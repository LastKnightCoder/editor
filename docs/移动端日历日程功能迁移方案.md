# 移动端日历日程功能迁移方案

> 状态：P0 已实施（2026-09-15）：Rust 数据层四模块 + 四页面 + 入口接线 + 番茄钟联动补齐；
> 评审修复：IANA 时区日界、周间隔、节假日顺延、跨域缓存及 UI 状态已接入自动化验证；
> 两端使用同一组规则契约数据，节假日请求失败使用旧缓存，无缓存时按周末顺延。
> 真机冒烟（四主题走查、返回手势全路径、两端互通）待验收。
> 定稿：主页 D 交互 + A 视觉；详情 A；编辑 A；管理 A。其他方案仅保留参考。
> 迁移源：桌面端 `apps/desktop` 日历模块（Calendar 页 + calendar/calendar-event/calendar-group 三表）。
> 迁移目标：`apps/mobile`（Tauri 2 + React 19 + 自研路由 + Tailwind 4 令牌）。
> 参考先例：`docs/移动端闪卡功能迁移方案.md`（P0→P1→P2 分期范式）。

## 1. 背景与目标

桌面端日历是一个成熟模块：四视图（月/周/日/议程）、事件 CRUD、日历分组管理、与待办/番茄钟深度联动。移动端已迁移大部分功能（卡片/文章/项目/知识库/待办/日记/番茄钟/闪卡/协作/搜索），唯独日历只有"数据被写入、没有 UI 消费"的状态——待办侧的 `todo_calendar_sync.rs` 已在移动端落地（待办的截止/计划/周期任务会物化成日历事件），但用户在移动端看不到任何日历视图。

本方案目标：

1. **看得见**：可折叠月历/周条 + 选中日列表（D 交互 + A 视觉）；两端共享表结构，整库同步完成后日程互通，并非跨设备即时可见。
2. **写得出**：用户日历上的日程完整 CRUD（新建/编辑/删除，含全天、跨天、颜色、数值、富文本详情只读）。
3. **联动闭环补齐**：移动端番茄钟完成会话时补写日历事件（当前缺失，会造成两端数据不一致，见 §5.4）。
4. **不破坏桌面数据**：系统日历（番茄钟/待办清单）事件在移动端 P0 只读展示；schema 零变更（所有表已存在于共享 db-schema，不触发 `db:schema:check` 联动）。

### 2.2 移动端已有基础（迁移目标环境）

- **共享 schema 零成本**：`src-tauri/src/database/migrator.rs` 以 `include_str!` 内编译 `packages/db-schema/schema/main.sql`，日历三表 + 映射表建库即存在。
- **待办联动已有接线**：`database/todo_calendar_sync.rs` 的 ensure、同步、删除与重新物化已落地，但日期和范围语义仍待对齐（§5.3）。
- **通用日期组件可复用**：`components/DateTimePickerSheet.tsx`（月历网格 + 时分步进 + 快捷胶囊），日程编辑直接复用。
- **富文本只读复用真实编辑器**：`@tau/editor/src` 的 `Editor readonly={true}`，日历不依赖闪卡 RichContent（§6.7）。
- **路由/浮层/返回手势**：`definePage` 自动注册、通用浮层内置返回拦截（规范见根 AGENTS.md「移动端浮层与返回手势规范」）。
- **入口范式**：首页 Bento 宫格（今日任务/番茄专注/闪卡复习大卡）+ AppDock 中央 FAB 弧形快捷创建（新卡片/新文章/写日记，角度 -135°/-90°/-45°）。

### 2.3 关键数据模型速览（与桌面共享，字段名两端一致）

```ts
// packages/db-schema/schema/main/50_learning.sql
calendar_group(id, name, is_system, order_index, create_time, update_time, parent_group_id)
calendar(id, title, color, description_content_id, archived, pinned, visible, order_index, group_id, …)
calendar_event(id, calendar_id, title, detail_content_id,
              start_date,            // 当天 00:00 本地时间戳
              end_date,              // 跨天事件的结束日期时间戳，可空
              start_time, end_time,  // 当天分钟数 0-1439，可空
              color,                 // 覆盖日历颜色，可空
              all_day, value, …)     // value: 可选数值（时间成本等）
todo_calendar_mapping(todo_item_id, calendar_event_id, sync_type, recurrence_date)
pomodoro_calendar_mapping(pomodoro_session_id, calendar_event_id)
```

要点：

- **时区语义**：IPC 传入 `timeZone`（IANA 名称），Rust 用 chrono-tz 按目标日期解析偏移；日历网格周一起始，周期规则周间隔采用周日起点，与既有待办规则一致。
- **无 RRULE**：日历事件本身不支持重复；周期性由待办 `todo_recurrence` 表达，查询时按可视范围物化为独立事件行（`recurrence_date` 映射回待办）。
- **17 色**：日历领域类型为 `CalendarColorName`、常量为 `CALENDAR_COLORS`。保留桌面 17 个字符串数据值及 light/dark 色值，不改库内颜色，不导入或别名化项目领域类型；历史来源见附录 A。
- **系统日历保护**：自身或父分组 `is_system` 的日历（番茄钟/待办清单下的截止·计划·周期）事件时间与归属锁定不可改——移动端 P0 直接整体只读。

## 3. 迁移范围与分期

### P0 —— 浏览 + 用户日程 CRUD + 联动补齐（本方案主体，一次交付）

1. Rust 数据层：`calendar*.rs` 模块（命令见 §5.1），范围查询接入周期任务物化（§5.3）。
2. 番茄钟→日历联动补齐（§5.4）：会话完成写事件、会话删除清事件。
3. 前端四页面：主页 D 交互 + A 视觉、详情 A、编辑 A、管理 A 基础版。
4. 入口接线：首页 Bento「今日日程」卡 + FAB 弧形菜单加「新日程」（3 项变 4 项，角度重新均分为 -157.5°/-112.5°/-67.5°/-22.5°）。
5. 可见性过滤：`visible` 字段消费 + 持久化（localStorage，对齐桌面 `selectedCalendarIds` 语义）。

### P1 —— 管理增强与编辑增强

1. 系统日历事件开放标题编辑（回写待办，语义对齐桌面 `syncFromCalendarEvent` 的 recurring-只回写-标题子集）。
2. 日历分组管理（新建/重命名/删除）、多选合并、拖动排序、置顶。
3. 详情富文本编辑（在 P0 真实编辑器只读基础上开放编辑和保存）。
4. 周日时间轴视图（3 日并排横滚 + 当前时间线，P0 不包含）。
5. 移动端存量番茄钟会话的一次性幂等迁移（扫描无 mapping 的会话补建事件，见 §9 决策点）。

### P2 —— 展望（依赖两端共建，不单端先行）

1. 事件提醒本地通知（桌面同样没有，需先定数据字段）。
2. 订阅日历（iCal/ICS）。
3. 桌面 MCP 查询工具结果的移动端渲染。

## 5. 数据层设计（Rust）

### 5.1 Tauri 命令清单（命名对齐移动端 snake_case 范式）

| 命令                               | 对应桌面 IPC                     | 说明                                                                  |
| ---------------------------------- | -------------------------------- | --------------------------------------------------------------------- |
| `calendar_get_all`                 | calendar:get-all                 | 全量日历（含分组、archived），带 `isInSystemGroup` 派生字段           |
| `calendar_create`                  | calendar:create                  | 新建日历（title/color/groupId…）                                      |
| `calendar_update`                  | calendar:update                  | 更新（P0 不含 merge/transfer）                                        |
| `calendar_delete`                  | calendar:delete                  | 删除（级联删事件+内容，事务）                                         |
| `calendar_group_get_all`           | calendar-group:get-all           | 分组列表（P0 只读展示）                                               |
| `calendar_event_get_by_id`         | calendar-event:get-by-id         | 详情（JOIN 日历 + detailContent）                                     |
| `calendar_event_get_by_date_range` | calendar-event:get-by-date-range | **核心查询**：可视范围事件 + 周期任务物化（§5.3）+ 按 start_date 排序 |
| `calendar_event_create`            | calendar-event:create            | 新建（P0 限非系统日历，Rust 侧校验）                                  |
| `calendar_event_update`            | calendar-event:update            | 更新（系统日历事件 P0 拒绝，错误码返回）                              |
| `calendar_event_delete`            | calendar-event:delete            | 删除（系统日历事件 P0 拒绝）                                          |

P0 不迁移的桌面通道及理由：`get-by-day/get-for-week/get-for-month`（桌面为视图做的优化通道，移动端一个范围查询覆盖）；`transfer-between-calendars`（P1 随管理增强）；`get-events-with-content`（AI 专用）；`calendar:merge`（P1）；`todo-calendar:*` / `pomodoro-calendar:*`（内部函数直调，无需独立命令）。

所有命令在 `lib.rs` `generate_handler!` 相邻位置注册；写命令事务包裹；operation 日志对齐桌面（`Operation.insertOperation` 同位逻辑，保持桌面热力图统计不缺移动端的写）。

### 5.2 模块拆分（对齐 pomodoro.rs / flashcard.rs facade 范式）

- `calendar_types.rs`：`CalendarRow` / `CalendarGroupRow` / `CalendarEventRow` / 出参 DTO（serde camelCase；`detailContent` 用 `serde_json::Value` 透传，Rust 不解析 Slate 结构——闪卡同款约定）。
- `calendar_calendars.rs`：`is_in_system_group` 派生判定（照抄桌面 `calendar.ts:52-75` 语义）、级联删除、内容引用计数清理（contents 表对齐桌面 deleteContent）。
- `calendar_events.rs`：CRUD + 范围查询。桌面普通事件按 start_date/start_time 排序，周期事件随后追加；展示层须定义稳定排序，不误称已有 all_day/id 排序。
- `calendar_pomodoro.rs`：§5.4。
- 单测：范围查询含跨天/全天/跨月事件边界、物化幂等、系统日历写保护、级联删除。以桌面行为快照做金标准（对齐闪卡 `flashcard_schedule.rs` 的做法）。

### 5.3 周期任务物化契约

1. 查询按请求范围物化；相同结果保留事件身份，规则或内容引用变化时清理范围内旧映射。`calendarIds` 缺省表示全部，空数组明确表示全不选。
2. 时间计算集中在 `calendar_time.rs`：日期采用本地日界，时刻采用墙钟分钟，不用固定 24 小时或当前偏移替代目标日期的 DST 规则。前端时间选择器也按本地小时设置。
3. 周期始终锚定 `startDate`，周间隔使用周数；月末、闰日钳制到当月末日。`maxOccurrences` 从规则起点按原始候选计数，而不是每个查询窗口重新计数。
4. 开启节假日排除时，将周末或节假日顺延到下一工作日，最多顺延 365 天；同日结果去重，顺延不改变后续规则节奏，也不越过结束日期。
5. 两端通过 HTTPS 获取 timor 年数据，使用条目的 `date` 和布尔 `holiday`，缓存 30 天；请求失败保留旧缓存，无缓存时仅顺延周末。移动端失败重试间隔 5 分钟，网络请求位于数据库事务之外。
6. 移动端范围物化任一环节失败即回滚整个查询事务，页面显示可重试错误。番茄会话与关联事件、映射一起提交，失败恢复活动会话以便重试。

桌面范围算法复用 `packages/shared/src/utils/calendarRecurrence.ts`；Rust 与桌面测试共同读取 `__fixtures__/calendar-recurrence.json`。上海、纽约时区分别运行桌面用例，Rust 覆盖所有时区用例。待办和番茄钟写入成功后，由 IPC 边界统一失效日历列表、范围和详情缓存。

验收仍需真机返回手势、四主题走查和实际数据库双端同步；自动化契约测试不替代这些验收。

### 5.4 番茄钟→日历联动补齐（P0 必做，两端一致性关键）

桌面语义（`modules/pomodoro.ts:507-530` + `createCalendarEventForSession`）：

- 会话完成（专注时长 ≥ 5 分钟）→ 找系统分组下「番茄钟」日历（不存在则创建，含系统分组 ensure）；
- 跨天会话按 `splitCrossDaySession` 切段，每段独立事件（标题 `🍅 预设名`）；
- 写 `pomodoro_calendar_mapping`（UNIQUE 兜底幂等）；
- 会话更新 → 删旧事件重建；会话删除 → 删事件+映射。

移动端落点：`calendar_pomodoro.rs` 提供同语义函数，在 `pomodoro.rs` / `pomodoro_history.rs` 的会话完成/删除/更新事务内调用。**不做此补齐的后果**：纯移动端完成的番茄钟会话永远没有日历事件，整库同步到桌面后桌面也不会补（桌面只在会话创建时写），两端统计口径永久分叉——这是 P0 范围内最高优先级的一致性项。

1. **首页 Bento 大卡「今日日程」**：与今日任务/番茄专注/闪卡复习并列，显示今日事件数 + 下一件日程摘要（如"14:00 周会 · 还有 2 件"），点击 push calendarHome。

3. **日程详情跳转源模块**（系统事件）：番茄钟事件详情提供「去番茄钟历史」、待办事件提供「去待办」入口（P0 顺带，增强联动感知）。

### 6.4 视图与交互设计（主页状态机）

- 状态：`calendarExpanded: boolean`（完整月历 / 选中周条两态）、`anchorMonth`、`selectedDate`、`calendarVisibleIds`（localStorage 持久化）。主页不采用 SnapSheet 三档。
- D 交互 + A 视觉：月份和把手使用语义 `button`，同步 `aria-expanded`、`aria-controls`、`title`；手机内无点击展开/折叠说明。收起保留选中周条，恢复不重置日期及列表位置。
- 数据：`calendar_event_get_by_date_range(月历可视 6 周范围)` 一次拉取，月历彩点与选中日列表/议程流同源派生，避免重复请求。
- 交互：点日期格 → 选中并过滤下方列表；「今天」按钮一键回位；月历左右滑切换月（对齐日记月历手势习惯）；长按空白格 → 新建（P1，P0 用"+"按钮）。
- 当前时间指示：列表视图内今日的"现在"分隔线（brand 细线 + 圆点），分钟级刷新（对齐桌面 WeekView 时间线逻辑的列表化简化）。

### 6.5 状态管理与数据流

- 读：TanStack Query（`usePageQuery` 带回前台刷新，key 参数化）；写：组件回调 → `services/tauri.ts` 强类型命令 → `invalidateQueries(["calendar"])`。
- 浮层态（日历选择/颜色/日期时间）局部 useState + 通用浮层组件，不入全局 store——与闪卡一致，无需新建 zustand 域 store。
- `useDatabaseChangeEffect` 联动：整库同步完成后失效日历查询（AppShell 统一刷新清单加 calendar 域）。

### 6.6 主题与颜色规范

- 页面结构色全部走令牌（bg-page/surface、ink、line、brand…），四主题自动适配，禁止硬编码色值。
- **事件/日历颜色例外**：17 个字符串数据值用 `CalendarColorName` 表达，取 `CALENDAR_COLORS` 的 light/dark 映射（随 `useMobileTheme().isDark` 切换），不以移植项目类型为最终设计；事件行使用色点/左竖条 + soft 底。
- 触控目标 ≥ 44px；月历格高 ≥ 56px（P0 固定 6 行网格，不做可变行高）。

### 6.7 富文本只读与 RichContent 去留

- 日历使用 `Editor`（`@tau/editor/src`），显式传 `readonly={true}`、`initValue`、当前 `theme`；沿用卡片 `mobileCardPreviewExtensions` 支持内容链接等扩展。完整详情不传 `previewBlocks`，不挂编辑工具栏或保存回调。
- 先例：`features/flashcard/FlashcardReviewPage.tsx:562` 参考资料用真实 Editor（readonly 默认 true）；`features/cards/CardItem.tsx:88`、`features/diary/DiaryCardItem.tsx:163` 显式只读。等数据就绪再挂载，验证切换事件、同步更新刷新，不把 `initValue` 当受控 value。
- **不能直接删除 RichContent**：`features/flashcard/ReviewCard.tsx` 一个导入、五个渲染位置，覆盖题干、填空输入/揭示、背面题干和详情，由 `FlashcardReviewPage` 正反面进入生产链路；另有 `CardEditPage` 与参考资料的说明性引用。
- 后续经明确授权可独立迁移：普通内容用真实 Editor 只读；填空需专用复习扩展保留 `blankProps` 输入、揭示与对错标记，不写题目 JSON、不提前泄露答案。现有 `FlashcardBlankExtension` 是编辑配置扩展，不能直接替代复习交互。回归通过、清除全部引用后才删除；本次不删组件、不改生产代码。

## 9. 风险与决策点

| #   | 风险/决策                          | 说明与建议                                                                                              |
| --- | ---------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 1   | **整库同步写冲突**                 | 两端同时改同一事件 → 最后写入者胜（整库文件同步的既有语义，非本方案新增）。闪卡已接受同等风险面，沿用。 |
| 2   | **日期/范围/节假日门槛**           | UTC 与本地日界、固定窗口、忽略节假日字段不可默认接受；先按 §5.3 验证一致性及存量修复策略。              |
| 3   | **存量移动端番茄钟会话无日历事件** | P0 只保证新会话补写；存量扫描补建（幂等判据：无 mapping 的会话）放 P1，避免 P0 同时动迁移与联动两条线。 |
| 4   | **月历性能**                       | 6 周 × 全量事件彩点渲染，事件量大时用范围查询收敛 + 彩点上限 3 个（超出折叠为"·N"），无需虚拟化。       |
| 5   | **系统事件写保护的错误路径**       | Rust 侧硬校验 + 前端隐藏入口双保险；错误码本地化为 toast（"系统日历日程不可在移动端编辑"）。            |
| 6   | **定稿交互落地**                   | D 交互 + A 视觉须验证月历/周条可逆切换、选中态与列表位置保持；生产动画/手势后续真机验收。               |

## 10. 验收标准（P0）

- `cargo test` / `vitest` / `tsc --noEmit` / `pnpm lint` 全绿。
- 桌面端创建的日程（含跨天/全天/带详情富文本）在移动端正确展示；移动端新建/编辑/删除后桌面端同步可见且字段无损。
- 移动端完成一次 ≥ 5 分钟番茄钟 → 日历出现对应事件；两端统计口径一致。
- 相同时区、规则和节假日输入下，两端同范围日期、时间、事件及映射一致；覆盖固定窗口外、夏令时、离线策略与存量修复，不豁免节假日差异。
- 系统日历事件在移动端不可编辑/删除；用户日历完整 CRUD。
- 返回手势全路径无死锁：主页→详情→编辑（未保存守卫）→返回逐层正确；所有浮层返回先关浮层。
- 四主题走查通过，无硬编码色值；玄夜主题下 17 数据色可辨识。
