## 2. 数据

**正文（唯一真相源）**

```ts
{ type: "check-list-item"; checked: boolean; taskId?: string; children: [Paragraph] | [Paragraph, CheckList] }
```

- `taskId` 由 `normalizeItem` 在缺失时补齐；同一文档内重复（回车拆分、粘贴、复制块）时后出现者重新分配。
- 连接正文的视图经列表包 `ITaskIdSource` 让内容来源接管身份；只读预览不补 id。内容层通过 `patchNodes` 在视图连接前及来源更新后补齐，有共享会话时只由所有者处理。已有 `taskId` 始终保留；缺失身份使用内容来源的稳定初始化键分配，离线分叉得到同一个值，不使用 `collabId`。初始化后定位与回写只认正文 `taskId`，不再依赖初始化键。
- 不经编辑器写入的正文（Markdown 导入、MCP / AI 写入）可能没有 `taskId`：索引时静默补 id 落回，这是常驻能力而非一次性迁移。
- 相对日期写回前的锚点和项目词归属提示都在正文节点，随正文同步；日期完成绝对化后清理临时锚点。用户直接改掉项目词时旧归属提示失效，胶囊或候选换项目时同时更新正文提示。

**索引库（派生，可整表重建）**

- `doc_tasks`（`packages/db-schema/schema/index/80_doc_tasks.sql`）：`content_id, task_id, title, text, checked, depth, parent_task_id, sort_index, group_id, group_token, date_hint, date_anchor, due_at`；主键 `(content_id, task_id)`。
- `doc_task_sources`：`content_id, update_time` —— 对账状态。
- `index_meta.doc_tasks_version=2`：首次升级强制对账存量正文；未补齐身份、日期或项目改名的正文不登记完成时间，持续重试。

**主库（用户选择，不能丢）**

- `doc_task_settings`（`main/50_learning.sql`）：`kind='excluded'`（`task_id` 空串）= 本文不收集；`kind='promoted'` + `todo_item_id` = 该项已转为独立待办。快照与状态条查询时按它过滤。原计划放索引库 / 复用 `todo_note_link`，改为主库独立表：索引库可整表重建会丢用户选择；`todo_note_link` 表达不了「整篇排除」，且一项转出时子项也要登记。
- `doc_task_group_names`：项目 id、项目创建时间、曾用名。创建时间隔离项目 id 重用；历史随主库同步，覆盖移动端或下载后检测到的改名。

## 3. 同步

- **正文 → 镜像**：后台模块 `src-electron/main/modules/doc-tasks/`（BACKGROUND）订阅 `onContentWritten`，按库合并一秒窗口内的文档写入，不因持续输入无限延期。初始化补对账已连接库；队列与 generation 按库隔离；单篇失败不阻断其他正文，失败及未完成规范化五秒后重试。连库先恢复改名记录，再按 `doc_task_sources.update_time` 对账；变化广播 `doc-tasks:changed`。
- **补 id**：缺失和重复都由内容层处理。关闭的本地正文不改 update_time、不记操作，但广播 `content:updated` 让预览和定位缓存拿到身份；不发正文写入事件。会话路径就地改属性，冻结时暂缓；视图自身不竞争补齐。
- **镜像 → 正文**：`ContentTable.patchNodes(db, contentId, patcher, { text? })` 是内容层唯一的按节点写入口：有编辑会话时 `patchSessionNodes` 在 Y.Doc 上逐元素 `setAttribute`、文本按 `minimalTextEdit` 只删改差异段（一次事务，元素原位、保留格式，与并发输入合并），否则改 JSON 落库并广播 `content:updated` + 写总线。共享内容拒绝写入 → `readonly`；找不到目标 → `not-found` 并重建该篇索引。doc-tasks 模块不 import 任何协作代码。
- **相对日期**：首次解析将锚点及带年份日期写到正文注记，安全时把日期词替换成绝对日期；有视图正在编辑时只补注记，避免抢先改写未完成输入。已存在的首次锚点不重新按今天计算；完成文字写回后镜像及胶囊直接消费绝对日期。只认完整日期词，普通词「明天见」「3号线」和非法日期不截取。
- **项目改名**：桌面改名先在同一事务保存旧名；连库及每篇增量重建也读取主库曾用名，先改正文再抽取归属。按完整段落 token 的最小文本补丁修改，支持跨格式及行内元素；不整篇覆盖。旧名被复用时按正文归属提示保护既有引用，新词按当前项目匹配。冻结或共享写入暂不可用时保持记录与待重试状态。
- **切库**：每个命令捕获库名，等待模块前后都校验；IPC 校验发起库与发送窗口，异步就绪后再复核连接对象。旧撤销闭包不能操作新库同号正文；项目缓存按库与请求修订隔离。

## 4. 界面

- **编辑器**（`src/editor-extensions/doc-tasks/`，只装在 content kit）：
  - 勾选项首段的 `#项目`、日期经扩展装饰（`DecorationSpec`，见下）渲染为胶囊：项目带色点；日期原文可见并在其后附相对说法（今天 / 周五），逾期红色。装饰不进文档。
  - 输入 `#` 弹项目候选（贴光标），回车 / Tab 补全完整项目名，可就地新建项目；Esc 关闭。
  - 相对日期词后按空格改写成带年份的绝对日期（整词是日期才改，「明天见」不动）。
  - 点胶囊弹小菜单：日期 = 今天 / 明天 / 下周一 / 清除；项目 = 换项目 / 移出项目。都是改文字，可撤销。
  - 项目能力由宿主经 `IDocTaskGroups` 服务注入（`src/services/docTaskGroups.ts`），扩展不依赖待办域；没注入时扩展不生效。
- **编辑器核心新增扩展装饰**（`@tau/editor/api` 的 `DecorationSpec`）：扩展声明 `decorations`，内核与宿主 `decorate` 合并执行，单个扩展出错只丢它的装饰并计入熔断（phase `decorate`）。
- **文档底部状态条**（`components/ContentEditor/DocTasksStatusBar.tsx`）：声明了编辑身份的正文、有未完成勾选项或已排除时出现；「在待办中查看」「本文不收集」/「恢复收集」。
- **待办页**：侧栏子项「文档中」= 参数 `id="docs"`，有文档条目时才出现；项目子项计数含该项目的文档条目。按日期 / 按项目议程把未完成文档条目排在每段待办之后，行尾来源可点开原文；摘要的今天 / 逾期计数含文档条目。抽屉（`DocTaskDrawer`）：只读标题 + 来源 / 日期 / 项目 + 原文上下文 + 打开原文定位 / 转为独立待办 / 本文不收集（Toast 撤销）。勾选乐观更新 + Toast 撤销。
- **转为独立待办**：读取内容层当前正文；项目取原文 `#项目`，没写用当前筛选或第一个有效项目。事务内检查已有登记，重复转出返回已有待办，先转子项再转父项复用子项；完成状态只写新项本身。日历操作与转出一起回滚，不缓存事务中生成的日历 id；提交后广播原库日程变化。转好后回到全部并打开待办。
- 装饰按段落计算完整 token Range，项目订阅及跨日使装饰失效；胶囊菜单校验 token 与 taskId，不以单片 DOM 文字确定修改范围。项目候选固定原输入 Range，异步提交接编辑器守卫；只读、停驻、换源后不恢复旧操作。
- 来源查询按批取标题、计数、更新时间及日记片段 id，不生成全文摘要；快照和状态条共用来源资格。已转出项在展开已完成时也隐藏，已完成条目可打开抽屉。
- **定位**：`EntityLocation` 增加 `{ taskId }`，`resolveLocationNode` 找嵌套项，打开原文后滚动到该项并闪烁。
- 数据层 `src/hooks/useDocTasks.ts`（待办页与编辑器状态条共用，不放在 features/todos）；日期文案 `src/utils/dayWords.ts`（待办 model 转出）。

## 5. 不做

- 双向实体同步（每个 checkbox 一条 todo_item）。
- 文档条目拖进日历、绑番茄、设周期——先转为独立待办。
- 待办页里改文档条目的日期 / 项目——在原文胶囊上改（DT-005 修订：少一条回写路径）。
