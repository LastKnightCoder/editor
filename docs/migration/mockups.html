批量导入 / 导出（迁入 · 迁出）—— 入口与交互

定位：低频、一次性、高风险（批量写库 / 批量产出文件）。原则是不占常驻视觉位，但在「想找它的时候」三步内能找到； 且所有入口汇入同一个向导，只实现一套扫描 → 预览 → 执行 → 报告的流程。

一、入口放哪里：三个方案

它们不互斥。推荐 A + B 为主、C 只做增强：命令面板给熟手，设置给「我要迁移笔记」的人去找，页面内只顺手做拖入和既有菜单项。

A · 命令面板命令 推荐·主入口

⌘K 输入「导入 / 导出 / import / obsidian / zip」即命中，零常驻占位；与现有 open-markdown、export-perf-snapshot 同类。
  • 零 UI 成本，对低频功能最合适
  • 可带上下文：在项目页唤起时默认「导出此项目」
  • 不知道有这功能的新迁入用户找不到

B · 设置 › 数据 › 导入与导出 推荐·兜底

与「同步」「资源存储」并列。用户找「迁移 / 备份」的心智本来就在设置的数据分组里。
  • 可发现性好，适合首次迁入
  • 能放「导入记录」与「撤销某批导入」
  • 设置是弹窗，向导需叠在其上（关设置再开向导即可）

C · 页面内情境入口 增强

卡片 / 文章页已有「导入」按钮 → 改为下拉加一项「导入文件夹…」；把文件夹拖进页面直达向导；项目 ⋯ 菜单的「整体导出」补上资源打包。
  • 不新增按钮，只扩充已有的
  • 目标已知（在卡片页就是导入为卡片），向导少一步
  • 入口分散，须保证全部汇入同一向导

不推荐：侧边栏新条目（违背低频定位）、Titlebar 图标、单独的「迁移」页面（definePage 承载一次性流程过重）。
