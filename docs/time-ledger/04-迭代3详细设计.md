# 迭代 3 · 拖动安排：详细设计

落地 TL-004（任务型只能从待办拖进日历）、TL-005（「计划任务」退役，存量转为关联事件）、TL-008（纠正走普通编辑、删除 Toast 撤销）、TL-009（日程页「待安排」面板）、TL-013（移动端最小改动）。路径默认相对 `apps/desktop/`，`M` = `apps/mobile`，`P` = `packages/db-schema`，`C` = `apps/cli`。

§12 列出需要用户拍板的点，拍板前不动代码。

## 2. 现状要点（2026-10-05 调研）

- 「计划任务」= `todo_item.type='planned'` + `start_at/due_at`，主进程 `todo-calendar-sync.ts` 物化到系统日历「待办清单 · 计划任务」，经 `todo_calendar_mapping` 关联；两端每次编辑都删除重建（移动端）或原地更新（桌面）。
- 物化事件的 `detail_content_id` **直接等于待办的 `description_content_id`**，未增加引用计数：桌面删除事件会对待办描述减一次引用，删除待办会减两次。转换时不能把它原样搬进用户日历，否则用户删掉这条安排就会删掉待办描述（现存隐患）。
- 现有日程块不能拖动 / 改时长（`TimedBlock` 只有 `onClick`，`onMouseDown` 被吞以免触发框选），新旧日历都没做过；只有空白处框选新建（`hooks/useTimeSlotDrag.ts`，mouse 事件）。
- 当日时间线是列表（`ledger.ts` 的 `buildDayTimeline`），行高与时长无关；周视图是比例网格（`CELL_HEIGHT=12` = 15 分钟）。
- 删除日程是 ConfirmDialog「删除后不可恢复」；主进程 `deleteEvent` 会连带删除备注 content。
- 勾选圈只认系统日历（`useEventDecor` 按 `kind==="todo"`），`getEventSources` 只 JOIN `todo_calendar_mapping`。
- 日程侧勾选完成只 `invalidateSchedule`，不发 todo mutation，待办页不会刷新。
- 提醒（`modules/todo-reminder.ts`）对 planned 按 `due_at - remind_before`（结束时刻）提醒；转为 normal 后不再提醒。
- AI 工具不能创建 planned；CLI `todo add --type planned` 直写 SQL 只写 `due_at`。
- 两端都没有「桌面已转换才能打开」的门槛；同步是整库快照。D-091：最后升级失败不放行，之后删除转换代码；不得靠改同一个版本号假装迁移完成。
- 首页今天的计划 / 截止 / 周期任务已在待办卡与日程卡各出现一次（现存，不在本迭代）。

## 3. 数据

### 3.1 新列与索引

- `calendar_event` 末尾追加 `todo_item_id INTEGER`（可空，不建外键）。
- 新增索引 `idx_calendar_event_todo_item ON calendar_event(todo_item_id)`：「已安排」按待办查事件、删除待办时级联，都按此列过滤；`calendar_event` 随番茄会话持续增长，不能全表扫。
- 索引写进 `P/schema/main/90_indexes.sql`，前提是**补列发生在 `MAIN_SCHEMA_SQL` 之前**（§4.1 的前置步骤负责），否则老库执行建索引会失败。`check-schema-parity.mjs` 的 `MAIN_INDEX_COUNT` 103 → 104。
- 同步 `database-schema.md` 的 `calendar_event` 小节；`pnpm db:schema:build / check / prepare`。
- 移动端：`main_upgrade.rs` 按新基线自动补列并按基线重建索引；Rust 写 `calendar_event` 全是显式列（无 `INSERT OR REPLACE`、无整表重建），不会抹掉新列。

### 3.2 语义

| 概念           | 判定                                          |
| -------------- | --------------------------------------------- |
| 任务型事件     | `todo_item_id IS NOT NULL` 且在用户日历       |
| 约定型事件     | 用户日历里 `todo_item_id IS NULL`             |
| 一条待办的安排 | 所有 `todo_item_id = 该待办` 的事件（可多条） |
| 已安排         | 存在开始时刻晚于现在的关联事件，取最早一条    |
| 上次安排       | 没有未来安排、存在过去的关联事件，取最近一条  |

## 4. 存量转换（TL-005）

### 4.1 前置步骤：`P/src/planned-retirement.ts`

做成 db-schema 包的前置步骤（与 `retireSubscriptions` / `retireFeatureTables` 同层），在三个入口都于 `MAIN_SCHEMA_SQL` **之前**调用：桌面 `database.ts` 的 `openDatabase`、桌面下载校验 `validate-downloaded-database`、CLI `DataAccess`。这样补列总在建索引之前，且 CLI / 下载副本走同一份转换。

```
retirePlannedTodos(db, dbPath):
  1. calendar_event 不存在（新库）→ 返回
  2. 补列 todo_item_id（PRAGMA 检查）
  3. 需转换判定按实际数据：EXISTS(todo_item.type='planned') 或「计划任务」系统日历 / 系统分组仍存在
     （兜住旧版移动端、旧版 CLI 同步回来的 planned）→ 否则返回
  4. VACUUM INTO <dbPath>.pre-planned-retirement-v1-<uuid>.bak
  5. BEGIN IMMEDIATE：
     a. 默认用户日历：首个「非系统分组、未归档」日历（与当日时间线补记同口径）；没有则建「日程」
     b. 对每条 planned 待办：
        - 有 planned mapping 的事件 → UPDATE 原事件行：calendar_id=默认日历、todo_item_id=待办、
          detail_content_id=0、title=待办标题（保留 event id，番茄 bound_event_id 继续有效）
        - 无 mapping（被移动端删了）且 start_at/due_at 可用 → 按 buildEventData 的 planned 口径新建事件
        - 都没有 → 不建事件（只是丢了时间，待办本身保留）
        - 删除其 planned mapping；todo_item.type='normal'，start_at=due_at=NULL，remind_before 见 Q5
     c. 删除「计划任务」系统日历中残余事件（无 mapping 的孤儿）、该日历本身、待办系统分组「计划任务」
     d. migration_meta 写 planned-retirement:v1 记账（转换条数）
  6. 任一步失败：ROLLBACK，抛 PLANNED_RETIREMENT_FAILED:，openDatabase 关闭连接不放行
```

- 不复用 `TodoCalendarSyncTable.upgradeTable`：它吞错，违背 D-091。
- 必须早于 `cleanupOrphanedEvents`（否则「待办日历里没有 mapping 的事件」会被提前删掉）——前置步骤天然满足。
- 不提升 `DATA_MODEL_VERSION`：转换按实际数据幂等重跑即可兜住旧客户端；提升会让旧版移动端拒库，代价大于收益（D-091 不靠版本号假装完成）。
- 按 D-091，后续版本拒绝 planned 并物理删除本步骤（记入 `05-桌面端清理调研.md` 的删除顺序表）。

### 4.2 待办系统分组

待办侧有一个系统分组「计划任务」（`todo-group.ts` 的 `ensureSystemGroups` 缺了会补建）。转换中删除，并从两端的系统分组清单里去掉，否则会被重建。

## 5. 主进程

### 5.1 日历事件

- `calendar-event.ts`：`parseCalendarEvent` 读 `todoItemId`；`createEvent` 可选写 `todo_item_id`；`updateEvent` **不写**该列（整行更新的旧调用方不会把关联清掉；改关联只走专门命令）。
- `CalendarEvent` 类型加 `todoItemId: number | null`。
- 新命令（读命令名不得以写动词开头，以免误触 `isScheduleWrite`；写命令须匹配其正则以广播 `schedule:changed`）：

| 命令                                | 作用                                                                                                                                              |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `calendar-event:create-for-todo`    | `{ todoItemId, startDate, startTime, endTime, calendarId? }` → 新建任务型事件：标题取待办标题、`detail_content_id=0`、日历缺省为默认用户日历      |
| `calendar-event:get-todo-schedules` | `{ todoItemIds, now }` → 每条待办 `{ next?: CalendarEvent; last?: CalendarEvent; count }`，用 `idx_calendar_event_todo_item` + 窗口查询，不全量拉 |

### 5.2 待办侧联动

| 场景                                                  | 处理                                                                                              |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 待办改标题                                            | 同步更新其关联事件的 `title`（一条 UPDATE）；任务型事件标题在日程表单里只读，提示「在待办中修改」 |
| 删除待办（`deleteItem` / `deleteItemsWithRelations`） | 见 Q4：推荐**删除未来的关联事件、过去的解除关联保留为记录**                                       |
| 归档 / 完成待办                                       | 不动关联事件（勾选圈显示完成态）                                                                  |
| `cleanupOrphanedEvents`                               | 追加：`todo_item_id` 指向不存在待办的事件解除关联（兜住旧客户端删除）                             |
| 快速添加识别出时段（原判 planned）                    | 见 Q6：推荐「建 normal 待办 + 建关联事件」，主进程一个事务（`todo:create-with-schedule`）         |

### 5.3 退役清理

- `todo-calendar-sync.ts`：`TODO_CALENDARS` / `TodoCalendars` / `getCalendarIdForType` / `buildEventData` / `syncFromCalendarEvent`（零调用，一并删）去掉 planned；`todo-item.ts` 的 `syncCalendar` 只处理 deadline；`cleanupOrphanedEvents` 的待办日历集合去掉 planned。
- `todo-reminder.ts`：只剩 deadline。
- `todo-group.ts`：系统分组清单去掉 planned。
- `TodoItemType` 去掉 `planned`；新写入 planned 一律拒绝（`createItem` / `updateItem` 校验）。

### 5.4 来源与番茄

- `getEventSources`：UNION「`calendar_event.todo_item_id` 关联」一段，`syncType` 新值 `"linked"`，`recurrence*` 为 null；`TodoCalendarSyncType` 收窄为 `deadline | recurring | linked`。
- `PomodoroSessionTable.resolveBinding`：反查待办先看 `calendar_event.todo_item_id`，再看 mapping。

## 6. 日程页

### 6.1 「待安排」面板（TL-009）

位置见 Q1。内容：

- 未完成的顶层待办（`useTodoSnapshot` + `openRoots(liveEntries)`，同番茄「专注于…」口径），排除周期任务（周期是标记）；按项目分组；顶部搜索。
- 每行：勾选圈（直接完成）、标题、淡色 meta：「已安排 · 周三 9:00」/「上次安排 · 周一」/ 截止日。meta 来自 `get-todo-schedules`。
- 行可拖：HTML5 DnD，`dataTransfer` MIME `application/x-tau-todo`，值为 todoId（常量放 `features/todos/model.ts`，与 `application/x-tau-question` 同约定）。
- 已安排的待办不从面板消失（一条可多次安排）。

### 6.2 拖入落点

| 目标                        | 落点                                                                                       | 结果                                            |
| --------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| 周视图日列                  | `round15((clientY - colRect.top) / CELL_HEIGHT * 15)`，悬停时用 `PendingRange` 预览 1 小时 | `create-for-todo`，时长 60 分钟（不越过 24:00） |
| 当日时间线「空档 / 补记」行 | 行的起点                                                                                   | 时长 = min(60, 空档长度)                        |
| 当日时间线其他位置 / 月视图 | 不接受（`dropEffect="none"`）                                                              | —                                               |

放下即建，不弹窗；新块出现即反馈，toast「已安排「标题」· 周三 9:00」带「撤销」（撤销 = 删除刚建的事件）。

### 6.3 周视图改时间 / 改时长（TL-008）

- 新 hook `src/hooks/useEventDrag.ts`（pointer 事件 + `setPointerCapture`，参照 `ResizeHandle` / Drawer 拖宽）：
  - 按下后移动 ≥4px 才进入拖拽，否则仍是点击（打开详情）。
  - 块体拖动 = 平移（可跨日列，按列 rect 判定 dayIndex），下边缘 6px 热区 = 改时长；15 分钟吸附，最短 15 分钟。
  - 拖动中块按乐观位置渲染；松手 `updateEvent`，失败回弹 + `toast.error`。
  - Esc：手势进行中用 capture 阶段 keydown 消费（取消并回原位，`stopPropagation` 防止同一次 Esc 关掉抽屉）。属于「进行中手势」的局部消费，不进 `useOverlayDismiss`；03 指南补记该约定。
- 可拖范围：用户日历事件（约定型 + 任务型）；系统日历（番茄、截止、周期）不可拖。统一用新 helper `isEditableEvent(event, calendars)`（= 非系统分组日历），表单与手势共用。
- 与列上的框选不冲突：块上 `pointerdown` 停止冒泡，列仍用 mousedown 框选。

### 6.4 删除改 Toast 撤销

- 详情抽屉与新建弹窗的删除去掉 ConfirmDialog：立即从视图隐藏，5 秒后落库，撤销即取消；离开页面立即落库（同待办页 / 番茄页的延迟删除模式）。
- 暂存的待删 id 放 schedule 域 `peekStore`（或新 `pendingDeleteStore`），DayColumn / WeekView / MonthView / AgendaView 渲染前过滤。
- 不采用「先删再重建」：`deleteEvent` 会删备注 content，重建会丢备注。

### 6.5 勾选圈与刷新

- `useEventDecor` / `useTodoEventSources`：来源判定改为「系统待办日历 或 `event.todoItemId != null`」；`EventTitle` 按是否有 source 画勾选圈。
- `useEventForm`：`isTodoEvent` 也包含任务型（锁标题，提示「在待办中修改」）；时间、日历、删除照常可用（任务型在用户日历）。
- `useToggleTodoEvent` 成功后补 `emitTodoMutation`，待办页与待安排面板随之刷新。
- `eventTone.ts`：`CalendarRole` 去掉 `planned`；待办清单分组下不认识的日历名不再兜底成时间块角色（按截止处理为标记）。

## 13. 实施偏差（2026-10-05）

- 转换步骤补列后，只在「确有遗留」（planned 行、「计划任务」系统日历或待办系统分组）时才备份并开事务；`migration_meta` 的 `planned-retirement:v1` 记累计转换条数。没有可用用户日历时新建的日历名为「日程」。
- 删除待办时「未来」按**开始时刻**判定：未开始的安排删除，已开始（含进行中）的解除关联保留为记录。
- 主进程删除了零调用的 `todo-calendar:sync-from-event`（`syncFromCalendarEvent`）及渲染端命令。
- 快速添加的时段跨零点时截到当天 23:59（安排只落在单日）。
- 待办系统日历下不认识的日历名按「截止」（标记）处理，不再兜底成时间块。
- 「安排」只读行对所有类型显示；截止 / 周期的同步说明文案保留。
- 本周负荷（HabitRail）去掉「计划」柱，暂不改为统计安排。
- 待安排面板的勾选直接复用待办域 `useTodoMutations().setCompleted`（含乐观更新与 todo mutation 事件）。
- 移动端：`TodoItemType` 保留 `planned` 成员仅为读取旧行，新增 `SELECTABLE_TODO_TYPES` 供类型选择器；`migration_tests` 的历史库升级用例补了 `todo_item_id`、番茄三列与新索引的断言。
- CLI 未改直写 SQL 的建待办逻辑（本就不同步日历），只收窄类型；开库经 `DataAccess` 自动执行转换。
