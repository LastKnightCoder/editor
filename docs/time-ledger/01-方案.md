# 时间账本：待办 · 日历 · 番茄联动方案

路径默认相对仓库根目录，`D` = `apps/desktop`，`M` = `apps/mobile`。决策编号 `TL-xxx`，已定 / 待定见 §8。

## 1. 为什么要做

三个模块已经连了一半，但全是「单向写日历」（2026-10-05 调研）：

| 联动        | 现状                                                                                                                                                            | 缺口                                                            |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 番茄 → 日历 | 会话结束且 ≥5 分钟，写系统「番茄钟」日历，标题 `🍅 预设名`（`D/src-electron/main/modules/pomodoro.ts`）                                                         | 只知道用了哪个预设，不知道在做什么                              |
| 待办 → 日历 | 截止 / 计划 / 周期任务物化到系统「待办清单」下三个日历；日历上可勾选完成（`tables/todo-calendar-sync.ts`、`calendar-event.ts` 的 `syncRecurringTasksForRange`） | 已完成 / 已打卡的仍照常显示（D-040 遗留）；日历上只读，不能安排 |
| 待办 ↔ 番茄 | 无。`pomodoro_sessions` 没有任务字段；D-045 把「关联待办」列为未做                                                                                              | 断掉的就是这一环                                                |

用户实际用法与模块设计定位有偏差：

| 模块 | 设计定位                       | 实际用法                              |
| ---- | ------------------------------ | ------------------------------------- |
| 待办 | 任务管理（截止 / 计划 / 周期） | **备忘**：别忘了这件事                |
| 日历 | 规划                           | **规划 + 记录**：每天什么时候做了什么 |
| 番茄 | 专注计时                       | 账本的自动记录器之一                  |

纠结点：

- 「计划任务」与日历事件重复——真要安排时间，直接在日历上建。
- 账本有一部分没有自动来源：会议、通勤、运动、线下阅读、忘开计时器的工作，番茄记不到。

旁证：旧「时间记录」模块（`time_records`）早已迁入 `calendar_event` 后删除（04-删除清单 schedule-4），记录本来就落在日历里，只是概念没立住。

## 2. 定位

> **日历是时间的唯一账本**：回答「这段时间我做了 / 要做什么」。其他模块往里写，不另立账本（TL-001）。

| 模块 | 回答的问题              | 与账本的关系                   |
| ---- | ----------------------- | ------------------------------ |
| 待办 | 我不想忘什么事          | 备忘池；拖进日历才有时间       |
| 日历 | 我的时间花在 / 将花在哪 | 账本本身                       |
| 番茄 | 我实际专注了多久        | 自动往账本写专注记录，只记专注 |

不打扰的三条检验标准，每个新交互都要过：

1. 能推断的不让用户填（不做预估番茄数、每日目标）。
2. 只在用户本来就会经过的地方露出（不弹窗、不推送、不加确认步骤）。
3. 联动都可以不用（开始专注不强制选任务，不选一切照旧）。

## 3. 核心规则

### 3.1 计划与记录：现在线区分（TL-002）

不加状态字段，不要求确认，按时间推断：

| 时段                   | 含义     | 视觉（纵向时间线：越早越靠上）     |
| ---------------------- | -------- | ---------------------------------- |
| 现在之后（现在线以下） | 计划     | 空心块：细描边、浅底               |
| 现在之前（现在线以上） | 记录     | 实心块：正常填充                   |
| 跨过现在               | 正在发生 | 在现在线处切开，上半实心、下半空心 |

- 计划随时间流逝自然变成记录，同一个块完成从规划到记录的转变。
- 过去的块默认就是记录（「推定发生」）。块内有番茄专注条的，自带「真的做了」的证据，差别自然可见，不另加标记。
- 纯渲染规则，零数据改动。

### 3.2 纠正：普通编辑（TL-008）

账本只反映真实发生的事，计划没兑现就改：

- 时间不对：拖到实际时段。
- 没做：删除。不二次确认，Toast 5 秒撤销（与待办删除手感一致）。
- 做了一部分：拖边缘改时长。

不设「没做但保留复盘」状态（YAGNI，等真要回看「计划 vs 实际」时再加）。

### 3.3 时间块与标记（TL-003）

日历上的东西分两类：

| 类别             | 内容                           | 显示                               |
| ---------------- | ------------------------------ | ---------------------------------- |
| 时间块（账本）   | 手动事件、安排进来的待办、番茄 | 时间轴上的块，适用 §3.1            |
| 标记（不占时间） | 待办截止日、周期打卡           | 当天顶部标记行，可勾选；完成后变淡 |

顺带解决 D-040 遗留「已完成 / 已打卡仍照常显示」。截止带具体时刻的，标记上显示时刻文字，但不进时间轴。

### 3.4 约定型与任务型（TL-004）

判别口径：**这个时间过了而事没做，你还会惦记它吗？**

| 类型   | 例子                   | 本质                   | 来源                   |
| ------ | ---------------------- | ---------------------- | ---------------------- |
| 约定型 | 会议、上课、约饭、看牙 | 时间本身；过了就过了   | 日历里直接新建         |
| 任务型 | 写报告、整理笔记       | 事情本身；时间只是安排 | **只能**从待办拖进日历 |

- 日历里新建的一律是约定型，不加「也加入待办」开关。顺序是「先记下事情，再给它时间」。
- 任务型 = 待办 + 一次时间安排，两样东西关联，而不是一个东西。生命周期不同：
  - 待办回答「做什么」，存在到完成为止；
  - 日历块回答「什么时候做」，时间过了变成记录。
- 安排时间过了但没做完：块成为记录（或被删），待办留在备忘池，可再拖一次。不自动顺延、不标红逾期。
- 一条待办可以有多次安排（周三两小时 + 周五一小时）。

### 3.5 待办退回备忘池，「计划任务」退役（TL-005）

- 待办保留：普通、截止（截止日是约束，不是安排）、周期打卡。
- 「计划任务」类型（`todo_item.type='planned'` + `start_at`/`due_at`）退役，存量一次性转换成「关联该待办的用户日历事件」（D-091：当前版本完成最后升级，之后拒绝旧格式）。
- 安排 = 把待办拖进日历时段，生成一个关联这条待办的**普通用户事件**（在用户日历里，可拖动、改时长、删除）。
- 任务型块显示勾选圈，勾选 = 完成待办；约定型块没有。
- 待办上显示安排信息（只读、淡色）：
  - 「已安排 · 周三 9:00」（有未来安排）
  - 「上次安排 · 周一」（安排都已过去且未完成）

### 3.6 番茄可选绑定（TL-006）

- 开始专注前可选「专注于…」，候选：今天的日历事件 + 待办（今日议程优先）。不选照旧。
- 绑定后：
  - 番茄写入日历的标题变成 `🍅 {事件或待办标题}`；
  - **绑定的是事件**，且专注时段落在事件时间范围内 → 当日时间线 / 周视图把番茄画成**事件块内的一条专注条**，不再单独叠块；落在范围外的仍单独成块；
  - **绑定的是待办**（没有对应安排）→ 单独成块，标题为待办标题；
  - 待办详情多一行只读「已投入 3 🍅 · 1h40m」；
  - 番茄账本查看单条时显示绑定对象，可跳转；
  - 周期待办配番茄 = 打卡 + 时长证据。
- 绑定任务型事件 = 同时归属它关联的待办，统计口径一致。
- 结束时**不做任何提示**（不问「完成了吗」、不弹「顺手完成」）。完成是待办自己的事。
- 番茄只记专注：会议、通勤等不应用番茄去记，否则污染「专注节律」与中断率统计。

### 3.7 空白槽：番茄记不到的部分（TL-007）

- 只在当日时间线的**过去时段**，把两条时间块之间的空隙画成淡虚线槽。
- 范围：当天第一个时间块的开始到最后一个时间块的结束之间（睡眠不算空白）；空隙 ≥15 分钟才显示。
- 点击 → 就地输入标题，起止时间已按空隙填好，回车即建（约定型事件，落默认日历）。
- 不推送、不红点、不计数；不看日历它就不存在。
- 纯渲染 + 复用现有新建事件命令。

## 4. 用户流程

```
备忘                    安排                      投入                      回看
──────────────        ─────────────────        ─────────────────        ─────────────────
待办（备忘池）  ──拖──▶ 日历空心块（计划）  ──▶  番茄绑定该块         ──▶  块变实心（记录）
  · 截止 → 标记行        任务型：带勾选圈          专注条画在块内           有专注条 = 有证据
  · 周期 → 标记行                                                         没做 → 删 / 拖到实际时段

                       日历直接新建（约定型）──────────────────────────▶ 时间过去即记录
                                                 番茄不绑定 ──────────▶ 单独的番茄块
                                                                         空隙 → 虚线槽 → 点一下补记
```

## 6. 数据与技术方案（草案，详细设计时验证）

### 6.1 安排关联（TL-005）

推荐 `calendar_event` 新增可空列 `todo_item_id`，而不是复用 `todo_calendar_mapping`（新增 `sync_type='scheduled'`）：

- mapping 表语义是「系统自动物化、随待办变化删除重建」，两端的同步逻辑在待办改类型 / 更新时都会按 todo 清理映射；复用就要改两端的清理条件，漏一处移动端编辑待办就会抹掉安排。
- 新列对旧版移动端透明：只要移动端写 `calendar_event` 用显式列 UPDATE，不会覆盖该列。**详细设计须核对 M 端 Rust 的写法与整库同步的合并方式。**
- 渲染侧「任务型」识别：`todo_item_id IS NOT NULL`。勾选完成复用 `useToggleTodoEvent` 的回写路径。

### 6.2 番茄绑定（TL-006）

`pomodoro_sessions` 新增可空列 `calendar_event_id`、`todo_item_id`（绑定事件时两者都填，后者取事件关联的待办，便于按待办聚合）。番茄自身写入「番茄钟」日历的事件保持不变（两端一致性、旧数据都依赖它），专注条是渲染层把番茄事件「收进」绑定事件的结果。

### 6.3 「计划任务」存量转换（TL-005）

主进程升级事务内：

1. 对每条 `type='planned'` 的待办，按 `start_at`/`due_at` 在默认用户日历新建事件，写 `todo_item_id`；
2. 删除其系统「计划任务」事件与 mapping；
3. 待办 `type` 改 `normal`，清空 `start_at`/`due_at`；
4. 系统「计划任务」日历退役。

失败不放行（D-091）。转换完成后桌面拒绝新写入 `planned`。

### 6.4 移动端（TL-013）

本期只保证数据兼容，交互不做。但移动端现在仍能新建「计划任务」，Rust 端 `todo_calendar_sync.rs` 也仍在物化它；整库同步后桌面会再次收到 `planned`。两个选项：

- (a) 移动端做最小改动：类型选择去掉「计划」，Rust 停止物化 planned。属于「数据兼容的必要改动」。
- (b) 桌面每次同步后再跑一遍转换。等于长期保留兼容层，违背 D-091。

已定 (a)，随迭代 3 实施。新增列都可空，旧版移动端读写不受影响。

### 6.5 纯渲染部分

TL-002 现在线、TL-003 标记行、TL-007 空白槽不改表，只改 `D/src/features/schedule/` 的 DayColumn、WeekView 渲染与 `eventTone.ts` 的来源判别。

### 6.6 联动约束

- Schema 变更按 AGENTS.md「数据库 Schema 维护规则」同步校验脚本、`database-schema.md`。
- 落地时在 DECISIONS.md 追加条目：推翻 D-040「日历上的待办只读」、D-045「不做关联待办」，并同步 03 指南日程 / 待办 / 番茄相关小节。

## 7. 不做

- 开始番茄强制选任务。
- 预估番茄数、每日目标、专注预算。
- 自动排程（把待办自动塞进空档）。
- 安排过期自动顺延、逾期标红。
- 番茄结束推送「下一件」或「完成了吗」。
- 待办列表每行常驻番茄计数徽章。
- 日历新建时「也加入待办」开关。
- 「没做但保留」状态与计划 vs 实际复盘视图（以后再议）。
- 移动端交互（本期只数据兼容）。
