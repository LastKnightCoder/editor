## 2. 现状要点（2026-10-05 调研）

- 会话只在主进程内存里（`modules/pomodoro.ts` 的 `activeSession`），结束且 ≥5 分钟才 `insertCompletedSession` 落库，再 `createCalendarEventForSession` 写「番茄钟」日历 + `pomodoro_calendar_mapping`。渲染端靠 `pomodoro:active-session-changed` / `pomodoro:tick` 镜像（`features/pomodoro/timerStore.ts`）。
- 所有开始入口（FocusRail ▶ / 右键、1–9 键、预设抽屉、小窗、沉浸窗）都直接 `pomodoroActions.start(preset)`，开始前无选择界面。
- 番茄日历标题有**三份**生成逻辑且已不一致：结束时 `🍅 预设名`（`pomodoro.ts`）；改时长重建时 `专注 预设名 N 分钟`（`tables/pomodoro-session.ts` 的 `updateSession`）；一次性历史迁移同后者。改时长后标题会变，是现存缺陷。
- 「当前选中预设」只在主进程内存、渲染端从未设置，不可作为默认预设来源。
- 移动端编辑待办会删除重建其日历事件（event id 不稳定）；桌面端周期事件原地更新、基本稳定。
- 整库同步是整文件替换；移动端打开库时按共享 `main.sql` 自动补可空列（`M/src-tauri/src/database/main_upgrade.rs`），Rust 写 `pomodoro_sessions` 全用显式列名。
- 跨域：`features/` 之间不得 import 彼此的 store；现有做法是 import 对方的 queries / 纯函数（今日页、SearchPalette）。`schedule/queries.ts` 的 `useCalendarEvents` 依赖日程页 uiStore，不可复用。

## 3. 数据

### 3.1 新列（`pomodoro_sessions` 末尾追加，均可空、无默认值）

| 列               | 类型      | 含义                                                                      |
| ---------------- | --------- | ------------------------------------------------------------------------- |
| `bound_event_id` | `INTEGER` | 绑定的日历事件（用户事件或待办来源事件）；不建外键                        |
| `bound_todo_id`  | `INTEGER` | 绑定的待办；绑定待办来源事件时由主进程经 `todo_calendar_mapping` 反查填入 |
| `bound_title`    | `TEXT`    | 绑定对象标题快照；日历标题与展示的兜底                                    |

- 三列命名区别于 `pomodoro_calendar_mapping`（那是番茄**自己生成**的日历事件）。
- 为什么要存 `bound_title` 快照：被绑定的事件 / 待办可能被删，移动端编辑待办会换掉事件 id；有快照则日历标题、账本展示、改时长重建都不依赖悬空 id。
- 周期待办的「哪一次」不另存：取会话开始日期。
- **不建索引**：老库执行 `MAIN_SCHEMA_SQL` 时列尚不存在，建索引会失败；按待办聚合的数据量小（单人番茄会话），全表按列过滤可接受。`check-schema-parity.mjs` 表 / 索引计数不变。

### 3.2 同步点

1. `packages/db-schema/schema/main/50_learning.sql` 建表语句追加三列 → `pnpm db:schema:build` / `check` / `prepare`。
2. `tables/pomodoro-session.ts` 的 `upgradeTable`：`PRAGMA table_info` 检查后 `ALTER TABLE ... ADD COLUMN`，**放在现有「番茄钟日历已存在就 return」之前**（参照 `tables/project.ts` 循环补列）。
3. `src/constants/internal-skills/database-schema.md` 的 `pomodoro_sessions` 小节追加三行（`database-schema.test.ts` 对账字段与顺序）。
4. 类型：`src/types/pomodoro.ts` 的 `PomodoroSession` 加 `boundEventId?: number; boundTodoId?: number; boundTitle?: string`；`tables/pomodoro-session.ts` 自有的 Row / `parse` 同步。

## 4. 主进程

### 4.1 绑定的解析：`resolveBinding(db, target)`

入参 `target = { eventId } | { todoId } | null`，返回 `{ boundEventId, boundTodoId, boundTitle } | null`：

- `eventId`：查 `calendar_event` 取标题；`TodoCalendarMappingTable.getTodoIdByEventId` 反查待办（有则填 `boundTodoId`）。事件不存在 → 报错（前端候选来自实时查询，正常不会发生）。
- `todoId`：查 `todo_item` 取标题，`boundEventId` 为空。
- 番茄来源的事件不可作为绑定对象（前端不提供；主进程按日历角色拒绝）。

### 4.2 RPC

| RPC                                      | 变化                                                                                                                                                                                                                                         |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pomodoro:start-session`                 | payload 改为 `{ presetId: number; expectedMs?: number; target?: BindTarget }`。预设始终由用户选（§12）；倒计时预设缺 `expectedMs` 时主进程按 `duration_min` 计算，跨域入口只传 `presetId`。`target` 经 `resolveBinding` 写进 `activeSession` |
| `pomodoro:update-binding`（新）          | payload `{ target: BindTarget \| null }`，修改 / 清除进行中会话的绑定，广播 `active-session-changed`；无活动会话报错                                                                                                                         |
| `pomodoro:stop-session`                  | 落库时写入三列；写日历前**重新解析一次标题**（对象仍在则取最新标题并更新快照，否则用快照）                                                                                                                                                   |
| `pomodoro:summary-by-todo`（新，ipc）    | 入参 `todoId`，返回 `{ count, focusMs }`（`WHERE bound_todo_id = ?`），供待办详情「已投入」                                                                                                                                                  |
| `pomodoro:get-event-bindings`（新，ipc） | 入参 `calendarEventIds`（番茄事件 id），经 `pomodoro_calendar_mapping` JOIN `pomodoro_sessions`，返回 `Record<番茄事件id, { sessionId, boundEventId, boundTodoId }>`，供日程画专注条                                                         |

`BindTarget = { kind: "event"; eventId: number } | { kind: "todo"; todoId: number }`，定义在 `src/types/pomodoro.ts`，两端共用。

### 4.3 标题统一

新增 `pomodoroEventTitle({ boundTitle, presetName })` = `` `🍅 ${boundTitle ?? presetName}` ``，放 `tables/pomodoro-session.ts` 导出；`createCalendarEventForSession` 与 `updateSession` 重建都用它（后者修复改时长后标题变成「专注 … 分钟」的现存缺陷）。一次性历史迁移不动（只对旧库执行一次）。`updateSession` 重建后补 `broadcastScheduleChange`，与结束写表一致。

### 4.4 渲染端命令（`src/commands/pomodoro.ts`）

- `startPomodoroSession(options: { presetId?; expectedMs?; target? })`（签名改为对象，调用方同步）。
- `updatePomodoroBinding(target | null)`、`summaryPomodoroByTodo(todoId)`、`getPomodoroEventBindings(ids)`。
- **跨域启动**（TL-010/011）走命令层而非 pomodoro 域的 store：日程 / 待办调用 `startPomodoroSession({ target })` 或 `updatePomodoroBinding(target)`，各窗口的 `timerStore` 由主进程广播自动镜像。符合「features 之间不 import store」。

## 5. 番茄页

### 5.1 「专注于…」选择器

- 位置：FocusRail 标题区（「开始专注」标题下方），一行可点的「专注于… 可选」；会话进行中移到 Player 内同位置，显示当前绑定，可改 / 清除。
- 交互：点开 `Popover`，顶部搜索框，下方两组候选，键盘上下选择、回车确定、Esc 关闭（`@tau/ui` Popover 自带 open 态 Esc 消费，焦点链 LIFO）：
  - **今天的日程**：今天的定时事件，排除番茄与标记（`isMarker`）；按「进行中 → 即将开始 → 已过去」排序。含待办来源的计划任务事件（带勾选圈图标）。
  - **待办**：未完成的顶层待办（`todos/model` 的 `openRoots` 口径），今天 / 逾期在前，最多 8 条，搜索时全量过滤。
  - 底部「不关联」。
- 开始前选中的绑定是**页面会话态**（`PomodoroView` 内 `useState`，随 Activity 保活），任何开始入口（▶、1–9、预设抽屉）都带上它；开始后清空。未选 = 不绑定，行为与现在完全一致。
- 数据（`features/pomodoro/queries.ts`）：
  - 今日事件：自建 `useQuery`，queryKey 以 `scheduleKeys` 同前缀 + 数据库名，随 `schedule:changed` 失效；queryFn 调 `@/commands/calendar` 的 `getEventsForDay`。日历角色用 `@/features/schedule/queries` 的 `useCalendarRoles`（不碰 uiStore）。
  - 待办：`@/features/todos/queries` 的 `useTodoSnapshot` + `@/features/todos/model` 纯函数（与今日页同口径）。

### 5.2 计时中显示

- Player（FocusRail）、MiniWindow、ImmersiveWindow：主标题显示 `boundTitle`，预设名降为副文字；无绑定时保持现状。
- `timerStore.sameSession` 比较项加入三列，否则进行中改绑定不刷新。

### 5.3 账本单条

`SessionPeekPopover` 的 `<dl>` 加一行「关联」：显示 `boundTitle`，可点跳转——有 `boundEventId` 且事件仍存在 → `navigator.push("schedule", { eventId })`；否则有 `boundTodoId` → `navigator.push("todos", { selectedId })`；都失效只显示文字。`DayDrawer` 行内在预设名后附 `· 绑定标题`（截断）。

## 6. 日程：专注条

### 6.1 纯函数（`features/schedule/ledger.ts`）

```ts
export function absorbFocus(
  blocks: CalendarEvent[], // 当天定时块（已排除标记）
  bindings: Record<number, { boundEventId?: number }>, // 番茄事件 id → 绑定
  roles: Map<number, CalendarRole>
): { blocks: CalendarEvent[]; focus: Map<number, { start: number; end: number }[]> };
```

- 番茄块若绑定了某个同在 `blocks` 里的事件，且专注时段**完整落在**该事件时间范围内（按绝对时刻，容差 0），则从 `blocks` 移除，并以分钟区间记入 `focus.get(事件id)`。
- 其余番茄块（未绑定、绑定待办无对应事件、超出范围、绑定事件不在当天）照旧独立成块，标题为 `🍅 绑定标题`（`displayTitle` 已去前缀）。
- 被收进的番茄不影响空隙计算（本来就在事件范围内）。

### 6.2 视图

- 数据：`schedule/queries.ts` 新增 `usePomodoroBindings(events)`（仿 `useTodoEventSources`：只对番茄角色事件取 id，queryKey 带数据库名，随 `schedule:changed` 失效）。
- **当日时间线**（列表形态）：事件卡片底部加一条 3px 细轨，按事件起止等比画出专注段（`bg-[var(--tau-...)]` 取番茄日历色），轨右侧小字「专注 1h20m」。无专注不画。
- **周视图**（网格形态）：块内右侧 4px 竖条，按分钟定位专注段。
- 专注段只画过去的部分（进行中的会话尚未落库，不画）。

## 13. 实施偏差（2026-10-05）

- `timerStore` 未改为复用 `useActivePomodoro` 的订阅：二者职责不同——timerStore 模块级常驻、跟每秒 tick 并推导结束结果；`useActivePomodoro` 只随组件挂载订阅会话变化，不收 tick。各自订阅同一通知，不会出现两份不一致的状态（都以主进程广播为准）。
- 主进程 `update-binding` 与 start 的 `resolveBinding` 都在 `tables/pomodoro-session.ts`；日历写入抽成 `writeCalendarEvents`，`modules/pomodoro.ts` 里的重复切段函数与 `createCalendarEventForSession` 已删除。「番茄钟」日历按系统根分组查找（原 `updateSession` 只按标题查）。
- 番茄写日历的标题刷新取最新标题时**待办优先于事件**（事件 id 可能被移动端重建换掉）。
- 跨域按钮为 `features/pomodoro/components/FocusStartButton.tsx`，日程与待办抽屉 import 该组件（不 import store）；待办「已投入」的查询 `useTodoFocusSummary` 在 `features/pomodoro/queries.ts`，随 `schedule:changed` 失效。
- 域外取当天日程新增 `schedule/queries.ts` 的 `useEventsOfDay`（不依赖日程页 uiStore），番茄事件绑定查询 `usePomodoroBindings` 同在该文件。
- 移动端：`cargo test --lib database::` 验证补列与读写（见 README）。
