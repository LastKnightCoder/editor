# 08 - 服务注入系统

## 8.1 架构概览

编辑器内核（`packages/editor`）是平台无关的，所有平台能力（文件对话框、资源上传、编译器、媒体内容源等）通过 **服务注册表（Service Registry）** 注入，整体分三层：

```
┌─────────────────────────────────────────────────────────┐
│ 宿主应用 (desktop / blog / mobile / browser-extension)   │
│  registry + config + extensions                           │
│  <EditorProvider ...>                                     │
├─────────────────────────────────────────────────────────┤
│ 编辑器内核 packages/editor/src/services/                  │
│  tokens.ts        服务 Token 定义                         │
│  registry.ts      注册表实现（惰性工厂 / 子注册表）         │
│  EditorProvider.tsx    统一运行环境 Context               │
│  slots.ts         UI 插槽类型                              │
│  defaultSlots.tsx 原生标签降级实现                          │
├─────────────────────────────────────────────────────────┤
│ 消费方                                                   │
│  React 组件: useService(token) / useOptionalService      │
│  Slate 插件: editor.getService(token) / tryGetService    │
│  平台组件: useEditorSlots()                               │
└─────────────────────────────────────────────────────────┘
```

**设计原则**：

- **Token 即依赖声明**：每个服务一个 `ServiceIdentifier`，类型层面互不兼容，消费方只依赖自己用到的服务（接口隔离）。
- **必选 / 可选语义显式化**：`useService` / `getService` 获取必选服务，未注册直接抛出包含服务 id 与注册指引的错误；`useOptionalService` / `tryGetService` 获取可选服务，未注册返回 `undefined`，由消费侧显式降级。
- **UI 组件不进服务**：平台专属 React 组件通过 **UI 插槽（EditorSlots）** 注入，带完整 props 类型，而非 `ComponentType<any>`。
- **惰性工厂**：`register(token, (registry) => impl)` 的工厂在首次 `get` 时才求值，注册顺序无关，服务之间可以互相依赖。

## 8.2 Token 一览

**文件位置**: `packages/editor/src/services/tokens.ts`

```typescript
// 必选服务
IResourceService; // 资源上传（返回可写入文档的地址字符串）/ 远程资源本地化 / CDN 地址解析
IFileService; // 文件对话框 / 读写 / 路径（webview 等宿主扩展消费）

// 可选服务（未注册时消费侧降级）
ICompilerService; // typst 编译 / tailwind 运行时
ICustomBlockService; // 自定义块模板列表（计划移除，待模板能力外置）

// 媒体 Provider（业务注入，未注册即无对应业务能力，见 8.8）
IMediaInsertSources; // slash 菜单二级的媒体插入入口
IVideoContentProviders; // 视频内容源解析渲染 Provider
IMediaActions; // 已有媒体内容的业务操作（工具条/右键菜单）
IMediaSelectors; // 已有媒体编辑 UI 的素材选择入口（如画廊加图）

// UI 插槽
IEditorSlots;
```

各服务的接口定义见 `packages/editor/src/types/services.ts`。

### EditorConfig 配置（替代设置/主题服务）

主题、外观默认值、Mermaid 设置、`openUrl`、PlantUML 服务器与暗色主题等**配置型**能力不经服务注入，
由内核规定规范（`EditorConfig` 类型）、宿主通过 `<EditorProvider config>` 提供取值：

```tsx
import { EditorProvider } from "@tau/editor/src";

<EditorProvider registry={editorRegistry} config={editorConfig}>
  <App />
</EditorProvider>;
```

React 侧经 `useEditorConfig()` 读取（配置变更自动重渲染）；命令式插件通过 `editor.getService()` 访问服务，配置型值应由宿主在闭包中传入。

### 宿主扩展注入

内核默认不含的能力（Markdown 粘贴导入、Webview 等宿主扩展）由 Provider 按编辑器树注入：

```tsx
import { EditorProvider, createMarkdownPasteImportExtension } from "@tau/editor/src";

<EditorProvider
  registry={editorRegistry}
  extensions={[
    createMarkdownPasteImportExtension(desktopImportFromMarkdown),
    new WebviewExtension(),
  ]}
>
  <App />
</EditorProvider>;
```

业务元素类型经 module augmentation 声明进 `ExternalElementMap`（见 desktop `editor-extensions/augmentations.d.ts`）。

## 8.3 宿主应用注册

以 desktop 为例（`apps/desktop/src/services/editorRegistry.ts` + `editorServiceImplementations.ts`）：

```typescript
import { createServiceRegistry, IFileService, IResourceService /* ... */ } from "@tau/editor/src";

export function createEditorRegistry(): ServiceRegistry {
  return createServiceRegistry(register => {
    // 必选服务
    register(IResourceService, desktopResourceService);
    register(IFileService, desktopFileService);
    // 可选服务
    register(ICompilerService, desktopCompilerService);
    // UI 插槽
    register(IEditorSlots, desktopEditorSlots);
    // 媒体 Provider（资源库 / 内容源 / 业务操作 / 选择器）
    // ...
  });
}
```

应用根部统一注入服务、配置和扩展：

```tsx
const editorRegistry = useMemo(() => createEditorRegistry(), []);
const editorConfig = useDesktopEditorConfig();
const editorExtensions = useMemo(() => createDesktopEditorExtensions(), []);

<EditorProvider registry={editorRegistry} config={editorConfig} extensions={editorExtensions}>
  <Router />
</EditorProvider>;
```

各平台工厂：

| 平台              | 注册入口                                                 | 说明                                                          |
| ----------------- | -------------------------------------------------------- | ------------------------------------------------------------- |
| desktop           | `apps/desktop/src/services/editorRegistry.ts`            | Electron 全功能，实现拆分在 `editorServiceImplementations.ts` |
| blog              | `apps/blog/src/services/editorRegistry.tsx`              | 只读渲染；不支持的能力注册为抛错实现，slots 用降级组件        |
| mobile            | `apps/mobile/src/services/editorRegistry.tsx`            | Tauri 能力                                                    |
| browser-extension | `apps/browser-extension/src/services/editorRegistry.tsx` | 重型服务经 WebSocket RPC 代理                                 |

无平台能力的场景可用 `createDefaultEditorSlots()`（基于原生 `img/video/audio` 标签）作为插槽基底。

## 8.4 消费方式

### React 组件内

```tsx
import {
  useService,
  useOptionalService,
  IResourceService,
  ICompilerService,
} from "@tau/editor/src";

const resource = useService(IResourceService); // 必选，缺失抛错
const compiler = useOptionalService(ICompilerService); // 可选，缺失为 undefined
```

### Slate 插件 / 非 React 代码

编辑器入口会把注册表挂到 editor 实例上（`packages/editor/src/index.tsx`）：

```typescript
const resource = editor.getService(IResourceService); // 必选
const compiler = editor.tryGetService(ICompilerService); // 可选
```

### UI 插槽

```tsx
import { useEditorSlots } from "@tau/editor/src";

const { Image, Video, Audio } = useEditorSlots();
```

三项插槽必选（宿主无平台能力时注入降级组件，可基于 `createDefaultEditorSlots()` 覆盖单项）。每个插槽的 props 类型定义在 `packages/editor/src/services/slots.ts`。

## 8.5 运行时覆盖（子注册表）

协同编辑等场景需要按上下文替换个别服务，使用 `createChildRegistry` —— get 时优先命中子级，未命中委托父级，覆盖粒度可到单个服务：

```tsx
const baseRegistry = useServiceRegistry();
const registry = useMemo(
  () =>
    createChildRegistry(baseRegistry, register => {
      register(IResourceService, {
        ...baseRegistry.get(IResourceService),
        upload: binding.uploadResource,
      });
      register(IEditorSlots, () => ({
        ...baseRegistry.get(IEditorSlots),
        Video: createAssetMedia(baseRegistry.get(IEditorSlots).Video, binding),
      }));
    }),
  [baseRegistry, binding]
);
return <EditorProvider registry={registry}>{children}</EditorProvider>;
```

参考实现：`apps/desktop/src/components/CollaborationEditor/index.tsx`、`apps/desktop/src/pages/SingleMarkdownEditor/index.tsx`。

## 8.6 注册表实现要点

**实现位置**: `packages/shared/service-registry.ts`（入口 `@tau/shared/service-registry`）。注册表实现已下沉到 `@tau/shared`，编辑器与白板共用同一套服务标识（`@tau/shared/service-contract`）与注册表，为应用级插件接口预留统一的能力注入方式；`packages/editor/src/services/registry.ts` 仅重导出，原导入路径与公共 API 不变。

- `createServiceRegistry(...registrations)`：接收若干注册回调。
- 注册值可以是实例，也可以是 `(registry) => impl` 工厂 —— 工厂惰性求值（首次 get 时调用），支持服务间依赖；注意：**注册值本身是函数时一律视为工厂**。
- 循环依赖在解析时检测并抛错。
- 注册空值（null/undefined）视为错误，保证 `get` 的返回值非空。

## 8.7 与旧机制（EditorServices）的对照

| 旧机制                                                  | 新机制                                  |
| ------------------------------------------------------- | --------------------------------------- |
| `EditorServices` 聚合接口 + 各 app 数百行巨型工厂       | 每服务独立 Token + 按平台组织的注册函数 |
| `useEditorServices()` 返回整个容器                      | `useService(token)` 只取所需服务        |
| `editor.services?.xxx?.yyy ?? fallback` 可选链          | 必选/可选语义显式，缺失时报清晰错误     |
| `components?: ComponentService`（`ComponentType<any>`） | `IEditorSlots` + 完整 props 类型        |
| 覆盖时 spread 整个 services 大对象                      | `createChildRegistry` 按服务粒度覆盖    |

## 8.8 媒体 Provider（内核纯度边界）

编辑器内核只理解"媒体元素 + 不透明业务数据"。所有内容源/生成/编辑类业务知识（视频平台解析、AI 生图、语音合成等）经四个正交协议注入，均为可选服务（未注册 = 无对应入口 / 默认渲染）：

| 协议                   | Token                    | 职责                                                                                                                                                                   | desktop 注册示例                                   |
| ---------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `MediaInsertSource`    | `IMediaInsertSources`    | 媒体元素空态面板的插入 Tab（内核固定提供 本地上传/网络地址 两个通用 Tab；含"资源库"在内的其余 Tab 全部来自宿主注册——内核只挂载注册的 Panel，点击后打开什么由宿主决定） | 资源库、bilibili/youtube 选择器、TTS 生成、AI 生图 |
| `VideoContentProvider` | `IVideoContentProviders` | 已有视频元素需平台解析后播放时的内容渲染（解析出地址后调用内核 `renderPlayback` 复用通用播放器）                                                                       | bilibili/youtube/remote 三个解析渲染器             |
| `MediaAction`          | `IMediaActions`          | 对已有媒体内容的业务操作（内核组装有图工具条按钮与右键菜单项，Modal 统一挂载）                                                                                         | AI 修图                                            |
| `MediaSelector`        | `IMediaSelectors`        | 已有媒体内容的编辑 UI 需要补充素材时（如画廊添加图片）的选择入口：内核只渲染入口按钮并调用 `select`，选择过程完全由宿主决定                                            | 资源库选择器                                       |

**数据契约**：`VideoElement.metaInfo` 为不透明透传（`{ type?: string } & Record<string, unknown>`），`metaInfo.type` 即内容源判别标识，由 Provider 的 `match` 消费——文档格式不随业务增减变化，零数据迁移。`match` 只做渲染接管判定；"网络地址"插入时对平台链接的拦截提示走独立的 `isSourceUrl`（仅平台页链接类 Provider 实现，普通直链 Provider 不参与）。

**纯度判定（换公司测试）**：内核可出现文档域名词（节点/选区/块/媒体/provider），不得出现业务名词（具体平台/AI 服务/数据库）。业务元素类型、markdown directive 解析同样外置——`importFromMarkdown` 经 `customDirectives` 参数注入宿主解析器（container/leaf/text 三种 directive 均支持，跨端共享实现在 `packages/shared` 的 `markdownCustomDirectives`）。

**分层归属速查**：

```
packages/editor（通用内核）     元素模型 / 编辑行为 / 通用渲染 / 服务协议与 Provider 协议 / EditorConfig 规范
apps/*（宿主）                 服务与 Provider 实现 / 业务扩展（editor-extensions）/ 业务面板（editor-providers）/ 全局配置取值
packages/shared（跨端共享）     通用 UI 原语 / 解析引擎 hooks（WithContext 注入依赖）
```
