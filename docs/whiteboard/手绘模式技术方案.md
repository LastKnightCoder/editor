# 白板手绘模式技术方案

> 状态：一期、二期均已实现（2026-10-05，D-107），实现与方案的差异见 §16、§17。方向为 mockup 方案 B「墨水」（`apps/desktop/mockups/whiteboard-sketch/`）。
> 范围：一期跑通主流程——页级「手绘 / 普通」两种模式 + 元素级细节覆盖 + 新渲染引擎，覆盖形状、连线、画框、分栏、文本、卡片、思维导图；二期覆盖媒体类元素、多选批量改笔触、内置手写字体与导出内嵌（§1.2、§9、§17）。不做存量数据升级（§10）。
> 代码路径均相对 `apps/desktop/src/components/WhiteBoard/`，另行注明的除外。

---

## 1. 目标与非目标

### 1.1 目标

1. **模式是页的属性，不是元素的特效。** 每页白板有「手绘 / 普通」两种模式，新建页默认普通。切到手绘后，页面上的元素线条与字体一起变化；用户不需要逐个元素去开。
2. **细节可覆盖。** 单个元素可以单独设置模式（在手绘页里保留一张普通图，或反过来）、笔触档位（工整 / 自然 / 潦草），也可以「换一笔」。
3. **参数说人话。** 笔触三档 + 填充四种，删掉 rough.js 的角度 / 间距 / 粗细滑杆，排线密度按尺寸与线宽自动计算。
4. **笔迹稳定。** 同一元素在拖动、缩放、撤销、重开、导出时都是同一笔。
5. **好看。** 变宽墨迹（起笔重、收笔轻）+ 马克笔淡涂，与现有「手写」工具使用同一个墨水引擎（perfect-freehand）。

### 1.2 元素覆盖范围

目标是所有元素都跟随手绘。按工作量分两期：一期覆盖「线条与文字」型元素（主流程），二期覆盖「媒体容器」型元素（只需要把外框换成墨迹）。

| 元素              | 一期 | 二期 | 手绘时的表现                                         |
| ----------------- | ---- | ---- | ---------------------------------------------------- |
| 形状              | ✓    |      | 墨迹轮廓 + 四种填充 + 文字手写字体                   |
| 连线              | ✓    |      | 墨迹线身 + 手绘端点 + 标签手写字体；虚线与流动保留   |
| 画框 / 分栏       | ✓    |      | 墨迹外框 + 标题手写字体                              |
| 文本              | ✓    |      | 手写字体；带底板样式时底板描边换成墨迹               |
| 卡片              | ✓    |      | 同文本（卡片复用 RichText 组件）                     |
| 思维导图          | ✓    |      | 节点墨迹外框 + 分支墨迹线 + 节点文字手写字体         |
| 手写              | —    | —    | 本来就是 perfect-freehand 墨迹，不变                 |
| 图片              |      | ✓    | 图片外加墨迹边框；图注底板描边换成墨迹、图注手写字体 |
| 视频 / 网页       |      | ✓    | 外框换成墨迹；内容区（播放器、网页）不变             |
| 音频 / 白板引用卡 |      | ✓    | 卡片外框换成墨迹、标题手写字体                       |

二期这批元素现在用 CSS `border` / `box-shadow` 画框（`ImageElement/index.tsx:213-285`、`VideoElement`、`WebviewElement`、`AudioElement`、`WhiteBoardCard/index.tsx:116-127`）。一期的引擎与 `useSketch` 就位后，每个元素只是「隐藏 CSS 边框 + 底层垫一个 `sketchFrame`」，约 0.5 天一个批次，不涉及新机制。

### 1.3 非目标

- 内置手写字体、多选批量改笔触：一期不做，二期已实现（§9、§17）。
- 存量数据升级：不做（§10）。
- 画布 chrome（选中框、控制点、连接点、参考线）永远普通（D-049）。
- 列表缩略图：缩略图是结构示意（`schematic/`），不受画风影响，维持现状。

## 3. 总体设计

```
页数据 data.sketch ──┐                              ┌─ 形状 / 连线 / 画框 / 分栏 / 导图 / 文本底板 ─→ utils/sketch 纯函数
                     ├─ Board.sketch ─ useSketch(el) ┤                                                → SketchPath[] → 声明式 <path>
元素 element.sketch ─┘   (set_sketch 进历史)         └─ 文本、卡片、标题、标签 ─→ 文字容器加 font-tau-hand
```

- **数据**：页级 `data.sketch` 是默认值，元素级 `element.sketch` 是可选覆盖，二者合成「生效画风」。
- **状态**：`Board` 持有页级 sketch，修改走新的 `set_sketch` Operation（可撤销、触发保存）。
- **渲染**：`utils/sketch/` 是一组纯函数，输入几何、样式与 seed，输出 `SketchPath[]`。组件内 `useMemo` 缓存后渲染为普通 `<path>`，不操作 DOM，不用 SVG filter 与 mix-blend-mode。
- **字体**：生效画风为手绘的元素，其文字容器加 `font-tau-hand` 类；字体栈由主题 token `--tau-font-hand` 提供。

## 4. 数据模型

### 4.1 类型

```ts
// types/sketch.ts（新增）
export type SketchMode = "sketch" | "normal";
export type SketchLevel = "neat" | "natural" | "loose";

/** 页级：这一页的默认画风，存在 WhiteBoardContent.data.sketch */
export interface PageSketch {
  mode: SketchMode;
  level: SketchLevel;
}

/** 元素级：可选覆盖；未设置的字段跟随页级 */
export interface ElementSketch {
  mode?: SketchMode;
  level?: SketchLevel;
  /** 「换一笔」写入；缺省时由元素 id 派生，见 4.3 */
  seed?: number;
}

export const DEFAULT_PAGE_SKETCH: PageSketch = { mode: "normal", level: "natural" };
```

### 4.2 字段落点

| 位置                                                      | 改动                                                                                                                           |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `src/types/white-board.ts:39-44` `WhiteBoardContent.data` | 新增 `sketch?: PageSketch`；缺省视为 `DEFAULT_PAGE_SKETCH`                                                                     |
| `plugins/CommonPlugin.ts` `CommonElement`                 | 新增 `sketch?: ElementSketch`。所有元素都可携带，是否生效由 4.4 的白名单决定                                                   |
| `plugins/GeometryPlugin.tsx:14-49` `GeometryElement`      | 删除 `sketchEnabled`、`sketchOptions` 类型定义；新增 `fillStyle?: "solid" \| "hatch" \| "cross" \| "scribble"`（缺省 `solid`） |
| `types/arrow.ts:35-52` `ArrowElement`                     | 删除 `sketchEnabled`、`roughness` 类型定义                                                                                     |
| 思维导图                                                  | 和 `themeId` 一样只在根节点存 `sketch`，整棵树共用（`types/mind.ts:30-33`）                                                    |

说明：

- **按页而不是按整块白板。** 一块白板有多页（`WhiteBoard.whiteBoardContentIds`），`Board` 实例按页创建，页数据整段 JSON 存在 `white_board_contents.data`（主进程不按字段解析，`white-board-content.ts:159, 212-227`）。挂在页上可以做到零表结构改动；复制页（`whiteboard.ts:353-363`）时自然带上画风。
- **普通模式下 `fillStyle` 一律按实色渲染**，并遵守 `fillOpacity`。这样填充样式与模式正交：切回普通不会丢失「斜线」设置，再切回手绘时仍是斜线。
- **「无填充」沿用现有语义**（`fill` 为空或 `none`），不进入 `fillStyle`。

### 4.3 seed：默认由 id 派生

```ts
const seedOf = (el: CommonElement) => el.sketch?.seed ?? hash32(el.id);
```

- 新建元素不需要写 seed，存量元素不需要补 seed；同一 id 永远同一笔。
- 「换一笔」写入 `sketch.seed`，进历史，可撤销。
- 复制粘贴产生新 id，笔迹随之不同，符合直觉。
- 取代现在 `SketchStyleSetterComponent` 里「useEffect 补 seed 再 onChange」的写法（:65-73），该写法会在打开面板时产生一次无意义的写入。

### 4.4 生效画风

```ts
// utils/sketch/resolve.ts
// 一期；二期追加 image / video / webview / audio / whiteboard
const SKETCHABLE = new Set([
  "geometry",
  "arrow",
  "frame",
  "column",
  "richtext",
  "card",
  "mind-node",
]);

export function resolveSketch(page: PageSketch, el: CommonElement, mindRoot?: CommonElement) {
  const own = (el.type === "mind-node" ? mindRoot?.sketch : el.sketch) ?? {};
  const enabled = SKETCHABLE.has(el.type) && (own.mode ?? page.mode) === "sketch";
  return { enabled, level: own.level ?? page.level, seed: seedOf(mindRoot ?? el) };
}
```

- `card` 复用 RichText 组件（`components/Card/index.tsx:67-78`），Card 把自己的 element 传给 RichText，`useSketch` 读到的是卡片元素本身，单独覆盖也能生效。
- `handwrite` 不在白名单：它本来就是 perfect-freehand 墨迹，两种模式下都不变。
- 白名单是渲染侧的开关，数据侧所有元素都能存 `sketch`。二期扩名单不需要改数据结构。

### 5.3 组件读取

```ts
// hooks/useSketch.ts
export function usePageSketch(): PageSketch {
  const board = useBoard();
  const subscribe = useMemoizedFn((cb: () => void) => {
    board.on("sketchChange", cb);
    return () => board.off("sketchChange", cb);
  });
  return useSyncExternalStore(subscribe, () => board.sketch);
}

export function useSketch(el: CommonElement) {
  const page = usePageSketch();
  const mindRoot = useMindRoot(el); // 新增：仅 mind-node 需要，沿父链找根节点
  return useMemo(() => resolveSketch(page, el, mindRoot), [page, el, mindRoot]);
}
```

- 范式与 `hooks/useReadonly.ts:5-19`（`readonlyChange` + `useSyncExternalStore`）一致。
- 元素组件都是 `memo`、只随 `element` 引用变化，所以页级变化必须由组件自己订阅，不能靠插件 `render()` 重新传参。

### 5.4 字体切换引起的尺寸回写

手写字体与正文字体的度量不同。切换模式后：

- 导图节点、文本、卡片由 ResizeObserver 回写尺寸（`MindNode/hooks/useHandleResize.ts:58-64`、`RichText/hooks/useHandleResize.ts:62`）；
- 形状是固定框，文字可能换行，但不回写。

回写发生在 `set_sketch` 之后 1 秒内，会被 `Board.apply` 的 1 秒合并窗口（`Board.tsx:529-541`）并入同一个撤销条目，撤销时连同尺寸一起还原。需要单测锁定这一行为（§12）。

## 6. 渲染引擎 `utils/sketch/`

全部是纯函数，不依赖 DOM，可以在 vitest 中直接测试。mockup 的 `sketch.js` 是同一套算法的原型。

### 6.1 模块

| 文件         | 职责                                                                                                                                                                                                                                    |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `random.ts`  | `rng(seed)`（mulberry32）、`hash32(id)`                                                                                                                                                                                                 |
| `path.ts`    | 把 SVG path 的 d 拆平为折线：支持 M/L/H/V/Q/C/A/Z（`ArrowUtil.getArrowPath` 的输出与几何 `paths` 用到的命令全部覆盖），不依赖 `getPointAtLength`                                                                                        |
| `outline.ts` | 形状轮廓采样：矩形含圆角（`extraInfo.cornerRadius`）、椭圆；其余几何类型对 `transformPath(path, w, h)` 的结果做 `path.ts` 拆平。输出闭合折线                                                                                            |
| `wobble.ts`  | 等距重采样 + 沿法线的低频摆动（两段正弦叠加，相位由 seed 决定）。摆动是弧长的连续函数，端点微移时线形连续变化，不会跳                                                                                                                   |
| `ink.ts`     | 调用 perfect-freehand 的 `getStroke`：压力曲线为起笔略重、行笔饱满、收笔变细；轮廓点转 path d                                                                                                                                           |
| `stroke.ts`  | 闭合描边：随机起点一笔绕一圈，末尾 6% 周长向外搭接（形成手绘的「收口」）                                                                                                                                                                |
| `fill.ts`    | 四种填充：`solid`（淡涂：轮廓外扩抖动后错位 3px，按 `fillOpacity` 半透明叠加）、`hatch`（-41° 排线，间距 `clamp(3.5+线宽×2.4, 5, 14)` 再按尺寸缩放）、`cross`（双向排线）、`scribble`（往复涂鸦一笔）。线类填充用 clipPath 限制在轮廓内 |
| `arrow.ts`   | 线身（一笔连续墨迹；虚线由遮罩切段，见 6.4）、5 种端点标记（见 6.3）                                                                                                                                                                    |
| `levels.ts`  | 三档参数：摆动幅度 0.55 / 1.3 / 2.6px，墨迹宽度 `线宽×1.3+0.5`                                                                                                                                                                          |
| `index.ts`   | `sketchShape(input): SketchPath[]`、`sketchArrow(input)`、`sketchFrame(input)`                                                                                                                                                          |

```ts
export interface SketchPath {
  d: string;
  fill?: string; // 墨迹与淡涂都是填充多边形
  stroke?: string; // 仅 clip 内的排线辅助
  opacity?: number;
  clip?: string; // 轮廓 d，组件里生成 <clipPath>
  dashMask?: {
    // 虚线遮罩，见 6.4
    d: string; // 中心线
    width: number;
    dash: number;
    gap: number;
  };
}
```

### 6.2 组件接入方式

```tsx
const paths = useMemo(
  () =>
    sketchShape({ outline, w, h, stroke, strokeWidth, fill, fillStyle, fillOpacity, level, seed }),
  [outlineKey, w, h, stroke, strokeWidth, fill, fillStyle, fillOpacity, level, seed]
);
return <SketchPaths paths={paths} />; // 纯声明式 <path>/<clipPath>
```

- 缓存键是几何与样式本身，平移（x/y 变化）不会重算。拖动时只有被拖元素相连的连线需要重算。
- 不按缩放退回普通渲染：输出已按几何与样式缓存，缩放不触发重算；若让每个元素订阅视口，平移缩放时全部元素都会重渲染，代价更大（§16）。
- 颜色：用户选的颜色原样使用；未指定颜色时，默认墨色取主题 `--tau-ink-1`，深色主题自动适配。

### 6.3 箭头端点

| `EMarkerType`          | 手绘表现                                                           |
| ---------------------- | ------------------------------------------------------------------ |
| `arrow` / `open-arrow` | 开口两翼一笔（左翼 → 尖 → 右翼），长度 `clamp(9+线宽×2.6, 10, 22)` |
| `closed-arrow`         | 闭合三角墨迹轮廓 + 同色淡涂                                        |
| `diamond` / `circle`   | 菱形 / 圆的闭合描边（复用 `stroke.ts`）                            |

方向取距端点约 14px 处的切线，避免曲线末端抖动带偏方向。

### 6.4 流动动画

流动动画用于架构图看流转方向，手绘模式下两种都保留，语义与普通模式一致。

难点：手绘墨迹是**填充多边形**，没有描边，不能直接用 `stroke-dasharray` / `stroke-dashoffset`。如果把虚线拆成一段段独立的短墨迹，每一帧都要重算，代价太高。

做法：**连续墨迹 × 虚线遮罩**。

```svg
<mask id="m1" maskUnits="userSpaceOnUse" x="-5000" y="-5000" width="10000" height="10000">
  <!-- 沿中心线描的粗虚线，宽度 = 墨迹宽度 × 3，圆头 -->
  <path d="中心线" stroke="#fff" stroke-width="…" stroke-linecap="round"
        stroke-dasharray="段长 间隔" class="sk-dash-flow" />
</mask>
<path d="连续墨迹" fill="墨色" mask="url(#m1)" />
```

- **虚线**：墨迹只算一次，虚线的切段交给遮罩。静止的虚线也走这条路，不再分段画墨迹。
- **虚线流动**：只给遮罩里那条中心线的 `stroke-dashoffset` 加 CSS 动画（与普通模式现有的 `dashFlow-${speed}` 同一手法，`Arrow/index.tsx:73-80, 212-233`）。墨迹不重算，段沿方向移动，段的两端保留墨迹本身的粗细变化。
- **实线流动**：沿中心线跑「流动点」，复用普通模式的 `animateMotion` 实现（`Arrow/index.tsx:82-175`）。手绘模式下，点改为「墨色实心点 + 一圈纸色描边」，不用辉光滤镜，这样点在同色墨线上也能看清，导出时也没有 filter。
- `animationSpeed` 的含义与普通模式一致。
- mockup 已验证：`board.html` 里「残差」虚线与 Value → 加权求和 实线开着流动；连线的浮动属性条「线型」弹层可以开关「流动」。

导出：`<mask>` 是静态 SVG 结构，snapdom 序列化时按导出那一刻的 dashoffset 定格，不影响导出。

## 9. 字体（二期，已实现）

> 二期已内置 **Shantell Sans（拉丁）+ 小赖 SC（中文）**（2026-10-05，用户在 `mockups/whiteboard-sketch/fonts.html` 九款候选中选定；Excalifont 用户不喜欢，未入选）。授权以各字体官方仓库的 OFL.txt 为准。

### 9.1 一期的系统回退为什么不够

一期用系统字体栈 `"Hannotate SC"（手札体）→ "HanziPen SC" → 楷体`：系统授权字体只能引用、不能随应用分发；Windows 没有手札体，退成楷体；macOS 部分字体要用户手动下载。所以二期改为内置。

### 9.2 选型

- **中文：小赖 SC**（[lxgw/kose-font](https://github.com/lxgw/kose-font)，OFL 1.1，未声明保留字体名，濑户字体派生）：通用规范 8105 字全含，手写感与白板最契合。备选霞鹜文楷 Lite 偏楷书、且保留字体名；清松手写体简体缺字；寒蝉 / 沐瑶 / 演示系列是作者声明式「免费商用」，子集化与嵌入软件没有原文授权，均排除。
- **拉丁：Shantell Sans**（[arrowtype/shantell-sans](https://github.com/arrowtype/shantell-sans)，OFL 1.1）：马克笔手写，x 高与小赖接近（0.50 / 0.47），1 / l / I、0 / O 可辨；可变字体，`INFM`（随性度）轴与笔触档位联动——工整 0、自然 40、潦草 90，字重统一 480（默认实例 300 偏细）。
- 对比页另含 Patrick Hand、Itim、Delius、Short Stack、悠哉、霞鹜文楷 GB Lite、系统回退作对照。

### 9.3 打包

- 产物：`apps/desktop/src/assets/fonts/hand/`（woff2 + `hand-font.css` + `hand-font.json` 清单 + 两份 OFL 许可），由 `apps/desktop/scripts/build-hand-font.py`（Python fontTools）生成并提交，构建期不重新切片。
- Shantell：只留 Basic Latin、Latin-1、常用标点与箭头，固定 BNCE / SPAC 两轴，保留 wght / INFM，135 KB。
- 小赖：通用规范 8105 字 + 中文标点、全角、数学与几何符号，按码位顺序每 220 字一片，共 43 片约 2.07 MiB。
- **每片独立 family**（`Tau Hand CJK 000`…`042`），字体栈由脚本生成为 `--tau-font-hand-faces`；desktop `base.css` 覆盖 `--tau-font-hand: var(--tau-font-hand-faces), "Hannotate SC", "KaiTi", var(--tau-font)`，`@tau/themes` 里的默认值仍是系统栈（移动端 / blog 不带字体）。独立 family 是为了导出（见 9.4）。
- 文字容器统一用 `handTextClass(sketch)`（`utils/sketch/handText.ts`）：`font-tau-hand` + 该档位的 `font-variation-settings`（Tailwind 静态任意值类）。
- 按需加载：`file://` 下实测一句中英混排只请求 5 个分片（共 44 个）。
- 安装包增量约 2.2 MiB，已记入 `06-安装包体积治理.md`。
- 授权义务：OFL 许可原文随包附在字体目录；「设置 · 关于与更新」增加「开源字体」组署名并链接仓库。

### 9.4 导出内嵌

实测 snapdom（2.24）在 `file://` 下 fetch 本地字体被拦截，导出产物不含字体。解决（`src/utils/bundled-font-embed.ts`，`captureBlobWithSnapdom` 统一调用）：

1. 从 `document.fonts` 取已加载的内置字体（unicode-range 按需加载，已加载的正是页面用到的字）；
2. 按「family + unicode-range 起始码位」对上构建期清单 `hand-font.json`（`file://` 下样式表 `cssRules` 不可读，不能现场解析 CSS），经 `import.meta.glob` 拿到打包后的分片地址；
3. 打包环境用 `readBinaryFile` 读成 data URL（开发服务器走 fetch），经 snapdom 的 `localFonts` 传入，snapdom 对 `data:` 不再 fetch；
4. snapdom 合并 CSS 时按 family + 字重去重，所以每片必须是独立 family，否则只会留下第一片。

实测：三行中英混排导出 SVG 内嵌 20 片（约 1.4 MB），放进不加载任何字体的空白页显示正确；通用规范字表外的生僻字回落系统字体。导出体积随用到的字数增长，约 30 KB/片；若将来需要压到最小，可改为导出时按实际字符做字形级子集化（Excalidraw 的 harfbuzz wasm 做法）。

### 9.5 风险

- 小赖作者自述补字与原版可能略有违和，个别字形不一定符合大陆规范，需在视觉验收时抽查常用字。
- 小赖只有一个字重，标题加粗靠浏览器合成粗体。
- 通用规范字表外的字（人名、古籍用字）回落系统手写体 / 楷体 / 正文字体，同一行里字体可能不一致。

## 10. 旧数据处理：不升级

- 渲染端不再读取旧字段 `sketchEnabled`、`sketchOptions`、`roughness`，类型定义中删除。

## 15. 评审结论（2026-10-05）

1. 画风按**页**存。
2. 新建白板 / 新建页默认「普通」。
3. 思维导图、卡片、文本都跟随手绘；目标是所有元素都跟随，媒体类放二期（§1.2）。
4. 填充收敛为 4 种（淡涂 / 斜线 / 交叉 / 涂鸦）+ 无填充。
5. 流动动画两种都保留：虚线用遮罩流动，实线用流动点（§6.4）。
6. 不做存量数据升级（§10）。
7. 字体放二期，一期用系统回退栈（§9）。

## 16. 实现与方案的差异（一期）

- **缩放降级未做**：见 §6.2，缓存已覆盖缩放场景，订阅视口反而让所有元素随平移重渲染。
- **思维导图「笔触」在任一节点都可改**：覆盖仍写在根节点上，与主题只在根节点显示不同，选中子节点时也能直接切。
- **文本 / 卡片底板**：只把 inset 发丝线换成墨迹框（`getTextSurface` 增加 `sketchEdge`，发丝线色太淡），底色仍是原底板；思维导图节点的底色改由墨迹框的不透明淡涂承担（`washAlpha = 1`，保文字对比度）。
- **分栏手绘线色**：发丝线色（ink 11%）太淡，手绘外框与标题分隔线改用 `--tau-ink-3`。
- **新建页**：不写入 `sketch`，缺省即普通；DSL 只读渲染没有页数据，始终普通。
- **共用件**：新增 `SketchRect` / `SketchStroke`（画框、分栏、文本底板、导图共用），`SketchTransforms.setPageSketch`（值未变不产生操作）。

### 回归清单（视觉验收）

- 状态栏切换手绘 / 普通、三档笔触；⌘Z 撤销切换（文本与导图尺寸随字体回写，一并撤销）。

## 17. 二期实现（2026-10-05）

- **媒体元素**：图片 / 视频 / 网页 / 音频 / 白板引用加入跟随类型。实现不是「隐藏 CSS 边框 + 底层垫框」，而是**在元素之上叠一层墨迹框**（`SketchRect`，`pointer-events: none`，颜色 `SKETCH_MEDIA_FRAME = --tau-ink-3`）：媒体内容不透明，垫在下面会被盖住。白板引用卡手绘时去掉 CSS 边框与投影（定位闪烁仍用普通高亮）；图注、音频标题、白板引用标题换手写字体。图片的图注边框是用户自选色、尺寸随内容（`w-fit`），保留 CSS 边框。
- **属性条**：视频 / 网页 / 音频 / 白板引用新增只有「笔触」的 `MediaSetter`；图片在 `ImageSetter` 末尾接入。
- **多选批量**：属性条覆盖全部选中元素（含连线），对齐 / 均分只在可对齐元素 ≥ 2 时出现；`MultiSketchPopover` 批量改画风 / 笔触 / 填充 / 换一笔（每个元素各换一笔），多选不一致时选项不高亮。写回不走多选平移路径，而是 `buildSketchOps` 直接生成只改 `sketch` / `fillStyle` 的 `set_node`，导图节点归到根节点去重，一次撤销（`utils/sketch/batch.ts`，单测覆盖）。
- **字体**：见 §9。
