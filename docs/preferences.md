# 个人偏好

> 这里记录长期协作方式与产品偏好。复杂需求先读「复杂需求的协作方式」，UI 设计动笔前先读「设计语言」与「交互」。评审产生的新结论先尝试并入已有条目，同类不另起行；确属新方向才加。只写结论本身，不带日期、原话与设计稿出处——过程记录留在评审时的任务文档里。

---

## 复杂需求的协作方式

适用于涉及架构调整、跨模块接口、数据模型变化，或需求范围尚不清楚且会影响设计的任务。范围明确的局部修改可按常规流程处理。

1. **先调研，与用户对齐需求。** 阅读真实代码、现有架构和调用方，找出当前入口、数据流、约束与可复用能力。把理解的目标、范围、用户可见结果和会影响设计的分歧讲清楚。方案阶段可以写设计文档，等用户确认需求理解和方案方向后再开始写实现代码。
2. **给出可评审的模块方案。** 说明现有架构、新增或调整的模块、各自职责和依赖，以及跨模块接口的输入、输出、调用时机和失败行为。复用仓库已有约定，只为当前需求中真实存在的职责划分模块。
3. **把复杂度留给真实业务。** 为新增抽象、回退或自动重试说明它对应的实际场景。失败能保持数据和状态一致，且用户可以安全重试时，给出明确的失败提示，交由用户重试即可。数据完整性、权限和正常使用中确实会发生的并发属于应处理的边界。
4. **用伪代码和流程图讲清主流程。** 伪代码写到模块调用、关键判断和结果即可。流程图画出入口、主要流程，以及会改变用户结果或系统状态的分支。用户主要评审目标、架构边界和系统行为，具体算法与实现细节由 Codex 选择并验证。

涉及存量业务边界调整时，可以参考正文迁移的调用盘点、行为对照、事务验证和分批交付步骤。 [现有业务的架构迁移](/docs/guides/dev-domain-migration.md)

## 设计语言

**总纲**：有个人特色的暖纸设计语言——奶油纸底、可可棕墨色、陶土橙 accent、柔和粉彩语义色（paper 主题，两端共用）。讨厌「一坨 antd」的通用后台脸、工程 README 脸和「贴上去的板子」；特色从排版、层次与组织里来，不从加颜色里来。可以参考外部产品的结构，皮必须换成我们的语言。宁可彻底重写，不在旧实现上缝补兼容。

### 层次与配色

- 「纸 + 墨」两个锚点拉开层次；表面阶梯单调有序、相邻档对比可辨，拒绝同色相糊成一坨的米黄与死档（如已退役的分组底——层次改靠描边与透明叠层）。
- 中性表面 + 单一 accent，色彩只表意（状态、语义）；同一处并列的用户色板必须是一个体系；一组可选配色从主题 token 推导，不手挑色板。
- 分组靠大平面、留白与投影，不靠 border 横线切割；同一屏多张碎卡片露底、每格一卡的「瓷砖」都是负样本。
- 承载纸白内容（PDF、画布）的阅读区不用深凹底，与纸同色，靠投影细边分层。

### 布局与组织

- 宽屏要利用：窄 max-width 只给正文阅读列；网格多列；详情页「正文 + 信息栏」双栏（空值写「空」、操作收进菜单，不照搬 Notion 常驻按钮）。
- 首页要有实质内容量（行动块 + 内容流 + 收集箱速览），不要空洞问候，也不要大数字仪表盘。
- 阅读/书写为主的页面是撑满的一整张纸：辅助信息拆进侧栏子项、浮层或纸缘，不开第二条侧栏、不做左卡右栏；管理页与编辑页同此。mockup 定稿的纸面结构落地时不退化。
- 页内的分组/筛选不与全局侧栏同层：进内容纸做 chips，或并入侧栏对应入口作子项；内容卡保持干净，不重复挂标签。
- 同一批数据给「浏览」与「检索」两种形态（如书架/列表），不为保存视图上重能力。
- 沉浸式专注界面主体居中（超高退化为滚动）；同一面板在不同数据量下都要撑满，不留大片空白。
- 中英混排的小节题不做 11px uppercase + 大字距；说明与示例上下排布，不做左右两列。
- 展示/档案页只写「看得见、点得着」的信息（长什么样、怎么用）；决策痕迹、运行元数据归任务与架构文档。
- 「顺便看看」的回顾类内容给一行带首句的入口，不占主位，也不只放无信息的图标。

### 内容要真

- 不造假数据，未接线就显示空态；数据必须真实（解码峰值的波形、从内容导出的缩略图），取不到就退简单形态，不画装饰假象。
- 无图封面用 id 派生的有彩渐变兜底；第三方平台里做的标记照原样呈现，不为统一改成中性。
- 列表行要能认出是哪一个：行名取内容本身，类型靠中性图标区分。
- AI 的结论连同理由和原始依据（问过的原话、涉及的笔记）一起摆出来，一条条展开成列表；不做轮播窄条，不藏进弹层。

## 交互

- **轻与稳**：悬停/激活只做底色、描边、文字色变化，至多加深一档投影——不上浮、不放大、不改变尺寸与布局（附属件占固定槽位或绝对定位叠放）；切换过渡平滑，标题栏与布局不跳。
- **悬浮层要么常驻不透明，要么完全收起**：不做半透明叠在内容上，也不做「淡到一半」。
- **控件归属明确**：控件只属于「选中」这个意图，路过什么都不出，每个按钮要有名字；高频工具的位置不折腾，换皮保留位置只换外观。
- **媒体**：控件放画面下方的纸色底栏，全屏才浮上画面；音频宁可多占一行也要真实波形（辨识度优先于省地方）；修图像相册式全屏、能力给全，原图永远保留。
- **输入与文案**：界面上已可见的状态不用文案复述；实时保存不设完成按钮，点击即入编辑的状态不在菜单里重复放入口；自动发生的事不加按钮；输入框常态与聚焦同底色，不用凹槽深底。
- **动作分派**：主动作进工具栏（新建为主按钮），不用右下角 FAB；列表加载用无限滚动；快速收集走命令面板，不单开小窗；轻点/按住按 250ms 区分，会录音的按钮按下即开录、不吞开头。
- **批注与历史不占阅读宽度**：页边留小标记、悬停浮出内容，浏览全部交给侧栏页签。
- **画布类**：属性控件浮在选中对象上方；辅助面板停靠进纸面，开关钉在面包屑；多画布切换用底部页签栏（单页不占位）；换皮只换界面，不动用户画的内容；库里的文档在画布上是文档形态（封面 + 标题 + 开头），展开原位长出、阅读 ⇄ 编辑无感切换。
- **学习类功能把过程留下来**：系统自动记事实、用户手动补思考，合在一条时间线，自动事件轻、手动记录重。
- **停靠优先于遮挡**：高频辅助面板（如 AI 对话）要与任何页面并排，空间不够先自适应收起，不砍入口。
- **对话里过程轻、结果重**：思考与工具调用是一行淡墨折叠，失败才默认展开。
- **AI 生成是后台任务**：配置完即关、条目即现，离开页面不停，过程看得见（流式产物或增长计数），完成即落库，不留「预览 → 保存」；大产物占正文、对话退停靠栏；同一产物的多轮生成按版本前后翻。
- **个人助手记忆默认无感知**：不展示逐条审核工作台，系统自动维护，开发工具只读检查。
- **分期与边界**：功能面大的模块先接功能后换皮；源头只读就做成只读，不假装可编辑；边缘形态能不做就不做。
- **平台分层**：桌面专属操作只在桌面渲染入口，Web 端不渲染而非置灰。

## 架构与工程文化

- 自动保存问题必须修复正常写入链路；不把用户自行备份或导出重导作为常规使用流程与验收条件。已发生事故的数据保全归内部排障。
- 声明式 API 的哲学贯穿一切子系统：defineXxx 一个文件声明全部（definePage、defineTheme）。
- 文件即注册单元（Vite glob 约定式收集），讨厌中心登记表。
- pure core + React shell（栈机纯函数、双注册表）。
- 渐进式升级而非大爆炸，升级进度必须可感知。
- 喜欢文档沉淀 + AGENTS.md 防腐化规则的工程文化。
- 键盘效率重要：命令面板直达、快捷键全，桌面惯例不缺（如后退/前进按钮）。
- 返回/关闭统一仲裁（移动端 LIFO + 退场缓冲），讨厌各处自行监听返回。
- 不使用 Electron 原生 dialog 承载确认、错误或导出，用应用内设计系统组件。
- 本机设置就地改、只留真正需要的：不把部署细节与运维能力摆给使用者。

## 命名与代码

- 统一产品域名：代码、默认配置与维护文档用产品域名，不写个人域名；自托管配置保留，不维护旧域名迁移链。
- 页面目录 PascalCase 统一。
