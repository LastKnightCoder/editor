# 桌面辅助窗口内存与首开延迟实测

2026-11-23 在同一台 Apple M3 Pro Mac（36 GiB，macOS 26.5.1，Electron 43.1.1） 上，将工作区改动前后的桌面生产构建分别启动三次。每次使用新的空资料库、独立 Electron 配置目录与本机端口。沿用仓库的生产测试隔离环境，真实运行数据库、IPC、WebSocket 与窗口管理，阻断外部联网和系统命令。样本没有用户安装的插件和本地向量模型。

## 内存

主窗口报告 `startup:shell-ready` 后等待 3.5 秒，枚举 Electron 主进程及全部后代，用 macOS `footprint -f bytes --noCategories` 读取每个 PID 的 `phys_footprint` 并求和，以 MiB 取整。第三轮每隔 15 秒重复一次，共 5 次。

| 场景                                                       |     改前 |     改后 |
| ---------------------------------------------------------- | -------: | -------: |
| 只打开主窗口，第三轮 5 次采样中位数                        | 1295 MiB |  816 MiB |
| 同一轮主窗口外预建的辅助窗口数                             |        4 |        0 |
| 使用过三个辅助窗口、随后隐藏，并播放背景音，三轮整组中位数 | 1708 MiB | 1374 MiB |
| 上述场景中，辅助窗口渲染进程之和，三轮中位数               |  457 MiB |  146 MiB |

第三轮按时间排列的整组足迹，改前为 1464 / 1422 / 1295 / 1161 / 1119 MiB，改后为 862 / 878 / 809 / 816 / 787 MiB。空闲中位数减少 479 MiB（37%）。整组数据包含共享 GPU 进程，系统合成和内存回收会引起波动。前次生产会话已运行约 14 小时，四个辅助渲染进程合计约 958 MiB；这次受控实验使用新资料库，两者分别代表长期使用和冷启动场景。

## 延迟

每轮从主窗口创建真实倒计时会话，依次打开小窗、沉浸窗、反馈窗口。每次先把焦点归回主窗口，等待 900 ms 让前一窗口的显示或全屏动画结束，再从相应 IPC 请求发起时开始计时。窗体可见、番茄暂停按钮或反馈文本框已经挂载，并经过两个动画帧后停止。隐藏窗口，用相同步骤再次打开。每格列三轮数据，括号内为中位数，单位 ms。

| 窗口       | 改前首次唤起（已预建） |           改后首次打开 |       改后再次打开 |
| ---------- | ---------------------: | ---------------------: | -----------------: |
| 番茄小窗   |     24 / 33 / 23（24） | 227 / 184 / 209（209） | 17 / 24 / 20（20） |
| 番茄沉浸窗 |     43 / 74 / 45（45） | 222 / 218 / 227（222） | 40 / 22 / 33（33） |
| 反馈       |     35 / 78 / 58（58） | 180 / 237 / 164（180） | 24 / 19 / 25（24） |

启动专注后从选择「小溪」到媒体元素触发 `playing`，改前三轮为 229 / 317 / 182 ms，改后为 239 / 235 / 217 ms。测试通过媒体时钟和事件确认播放，在极低音量下进行。它衡量应用侧可播放时间，声卡和蓝牙设备的输出延迟另计。

## 播放交接

同一轮中验证了一个主窗口与三个辅助窗口同时存在时只有一个播放者。依次销毁主窗口和剩余窗口后，先由番茄小窗接手，再由无可见界面的播放页在零个 BrowserWindow 时接手，媒体时钟延续。重新打开主窗口后，播放页释放，只有主窗口在播。交接涉及异步加载和解码，未测量音频波形的间隙。

以上时延来自单台 macOS 机器，包含本机窗口合成与应用负载。Windows、Linux 以及系统文件缓存完全冷却时的时延未涵盖。
