设计边界与三方案对比

核心承诺：卸载插件默认保留数据，用户在插件管理页随时能看见并按插件清除，不必重装。

真实数据事实（来自现有表结构，零假数据）

  • 集合来源：当前资料库 plugin_entities / plugin_records / plugin_kv / plugin_links / plugin_entity_kinds / plugin_ref_grants / plugin_create_receipts / plugin_operations（entity='plugin-entity'）与本机 plugin-secrets.sqlite 的 plugin_id 并集，减去当前已安装、待生效与坏包插件。
  • 名称降级：插件中心目录能查到的用目录名与彩色图标；离线或本地 ZIP 安装过查不到的诚实展示 pluginId 与中性图标，若有 plugin_entity_kinds 一并列出内容类型名。
  • 清晰边界：清除范围限于当前资料库 + 当前资料库的本机凭据；资料库内删除随云同步，已写入笔记的正文不受影响。
  • 卸载闭环：UninstallDialog 补一句「保留的数据可随时在『已卸载插件的数据』中查看和清除，不必重装」，点击本页顶栏「演示卸载闭环」即可完整体验。

三套方案取舍

方案承载方式优点取舍
A（推荐） 「已安装」页底部折叠区 + ⋯ 菜单定位 零新路由、零双层弹窗、复用餐桌搜索、一整张纸、不占顶栏 Tab 无数据时默认隐藏，靠 ⋯ 菜单进入空态查看
B 底部入口条 + ⋯ 菜单 → 600px 弹窗（内嵌确认步） 任意 Tab 随点随清、不拉长「已安装」页、单弹窗内步进无嵌套遮罩 插件很多或明细很长时宽度不如整页舒展
C 底部入口条 + ⋯ 菜单 → 二级子页（Page 栈） 宽屏最舒展、原生面包屑后退、零双层弹窗、每项明细并排最清晰 需增一条路由；数据少时多一次页面跳转
