# 长 Markdown 视口挂载与源码性能验证

日期：2026-11-15。验证范围为桌面 Markdown 文件窗口，包含默认渲染入口、文件完整性、剪贴板、拖选、无障碍树和源码性能。视觉验收由用户完成。

长文默认使用视口挂载，短文直接挂载。对照阶段的试用开关和只读首屏路径已退役。

## 已有基线

此前优化基线已保存为 `954464605`，增量投影等成果为 `99edc8a95`。参考文档实机开发版打开至完整正文就绪约 16.46 秒，单次完整 Markdown 解析约 2.18 秒；包含 2379 个顶层块、587 张表格、9778 个单元格和约十万个 DOM 节点。正文及格内输入中位延迟已分别降至 72ms、64ms。

现有 chunk 与 content-visibility 保留了屏外 React/DOM 节点，不能消除首次挂载成本。视口级挂载应改变渲染范围，完整文档、Y.Doc 和保存语义继续保留，不能把未挂载内容当成未加载正文。

只读首屏补充基线：相同文档三轮首屏帧代理约 4.14 秒、完整就绪观测约 17.77 秒，全文仍完整挂载。它缩短展示等待，没有消除全篇编辑器准备成本；与前述单轮基线的差异不作为视口方案收益，恢复实施时重新同口径复测。

## 渲染与交互

- 按现有长文判据启用。从同一份 Y.Doc 绑定完整 Slate 编辑器，只把当前窗口内的块渲染为真实可编辑 DOM。滚动时由视口观察器创建和回收块组件，保留位置与测得的高度。一个表格作为一个顶层块完整挂载。
- 光标、选区端点及嵌套输入框所在块保留。全选与源码跳转先挂载端点，目录复用屏外占位的几何位置。跨屏鼠标拖选用模型记录起点，滚动中接续可见终点。跨未挂载块的复制取完整 Slate 片段，生成可供外部应用使用的 HTML 与 Markdown 文本。
- Electron 报告辅助支持时，在当前会话挂载全文、取消屏外绘制跳过，并恢复当前选区。

```text
全文会话 = 读取并转换原文件()
开始编辑器(绑定全文会话, 首屏挂载范围)
当会话已连接且屏内块已提交时显示正文
滚动或定位时更新块的挂载范围
编辑、保存、撤销、导出均通过全文会话
```

测试使用临时 Electron 配置和文件副本。对照阶段在同一生产构建中切换路径。默认启用后，通过常规入口重复采样，并将保存结果与已记录的现行编辑器字节摘要比较。新窗口首屏与可写时刻使用同一套 DOM 和动画帧探针，首个输入由真实点击和键盘注入验证。实际文档只记录耗时、节点数和字节摘要。

## 压测结果

同机 Electron 生产构建复测历史样本（587 张表格）。时间从新窗口渲染页开始导航计算。首个 Markdown 窗口每种路径各测一次，预热后每种路径各测三次取中位数。

| 场景               | 现行首屏 | 原型首屏 | 现行可写 | 原型可写 |
| ------------------ | -------- | -------- | -------- | -------- |
| 首个 Markdown 窗口 | 397 ms   | 422 ms   | 6.65 s   | 422 ms   |
| 预热后打开         | 388 ms   | 422 ms   | 6.01 s   | 422 ms   |

原型首屏多用约 25–33 ms，首屏可见与可写在同一帧。典型可写时正文后代元素数由 87,272 降至 3,876。八份副本都在第一笔输入后使用保存快捷键，整份落盘字节与现行路径执行同一编辑的结果一致，原文件摘要保持一致。

- 1,800 段合成长文完成七次远距离滚动，界面挂载 18–30 个真实块。通过全文复制、剪切后保存空文件、粘贴后逐字节恢复、源码往返、撤销重做、屏外外部更新、目录跳转和切换文件前落盘。
- 首块巨表有 450 行数据。通过格内 20 轮输入与退格、Chromium 中文组合输入，以及校验除两处输入外全文逐字节相同。42 条输入到后续绘制帧的采样 P95 为 46 ms。

## 兼容性加验

- 原型此前会在跨屏拖选时丢失锚点。修复后分别正向和反向按住鼠标滚动五次，复制结果覆盖经过的全部段落，挂载量保持在测试预算内。
- macOS AppKit 通过独立原生剪贴板读取屏外的粗体、斜体、链接和表格。AppKit 导出的外部富文本可贴入原正文，也可替换全文选区，两条路径均验证了保存后的 Markdown。
- 模拟 Electron 启用辅助支持，验证当前光标和编辑会话保留，Chromium 无障碍树能遍历屏外标题和表格。辅助支持已开启时新建窗口也提供全文。

兼容性修复后的历史样本复测中，首个窗口的首屏为 438 → 413 ms，预热组三轮中位数为 389 → 405 ms。预热组可写中位数由 6.54 s 降至 405 ms，原型首屏与可写仍在同一帧。八份副本首次输入后立即保存的文件摘要一致，原文件摘要保持一致。巨表用例改用真实字形坐标点击并校验光标后重复三轮，全部通过，格内输入的各轮 P95 约 45–46 ms。

同一文件的源码压力测试中，源码首次聚焦由 4.52 s 降至 0.71 s。CodeMirror 从渲染 8,012 行降至约 36 行。逐键确认光标处内容的六个绘制代理样本从 5.30–5.78 s 降至 9–14 ms，保存后除指定输入外的整份文件逐字节一致。源码按其自身文件规模启用窗口化。

## 默认路径复测

- 历史样本通过正常入口打开四次。新进程首个 Markdown 窗口约 447 ms 可见并可写，预热组三次中位数为 389 ms。首次输入后立即保存的四份副本都与现行编辑器同一编辑的历史摘要一致。
- 验证覆盖源码输入、跨应用剪贴板、跨屏拖选、无障碍树、历史文件打开和保存、长文交换及巨表。巨表用例验证鼠标命中文字与落点一致，再执行 20 轮输入和退格及 Chromium 组合输入，正文保真断言通过。
- 默认构建的源码首次聚焦约 687 ms，渲染 36 行，六个输入代理样本中位数约 14 ms，最大值为 76 ms。

无障碍验证使用 Chromium 的树及 Electron 的辅助支持切换，未使用实际 VoiceOver 播报。跨应用富文本验证使用 macOS AppKit 的独立剪贴板。
