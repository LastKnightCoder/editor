# 明确下载覆盖的实现与验证

目标：日常同步继续合并；用户明确下载覆盖时，以远端为唯一基线，丢弃当前库的本地修改、缓存和草稿，恢复后仍可打开和编辑。

## 实现边界

新增独立只读下载入口和覆盖安装入口，不改变日常同步的 Yjs 合并路径。覆盖清空旧同步队列、JSON 转换意图、正文检查点、回执、历史与当前库的冲突材料，再安装远端主库和正文。设备身份和配对凭据保留，来源序号不倒退。

本机版本在主库安装事务中更新。移动编辑器按版本重新创建，缓存及视图按版本隔离；旧会话和旧提交不能写回新主库。物理缓存清理不是主库正确性的前置条件，安装后中断也不会重放旧缓存。旧备份不自动读取。

当前库覆盖与日常同步串行执行，在途操作完成后才安装；下载失败解除编辑门禁。附件按新快照引用补齐，不把本机未被引用的文件重新发送到远端。原有云端下载复用库替换流程，并补齐冷缓存、草稿及视图清理。

## 验证

| 场景 | 结果 |
| --- | --- |
| 正文与标签存在本地未确认修改后明确覆盖 | 当前库严格采用远端内容，本地旧字及标签不再出现 |
| 两端 SQL 适配器重复覆盖 | Node 30 次、真实 Rust 30 次通过 |
| 安装提交前后退出进程 | 各 6 次，重开得到完整原库或完整远端库，均能继续保存正文 |
| 无效远端数据 | 安装失败回滚，原库及本机版本保持一致 |
| 同基线旧缓存与旧会话 | 编辑器按新版本重建，旧字不重放；新会话可继续编辑 |
| 迟到的正文保存与提交 | 被本机版本守卫拒绝 |
| 下载断网 | 门禁解除，本机仍可使用 |
| 草稿、视图与其他库 | 当前库记录清除，其他库会话保留 |
| 日常同步回归 | 离线双端输入、重启、历史缺口、旧 JSON、防重复提交和图片双向同步通过 |

主库验证比较 98 张业务表。桌面使用真实 Electron SQLite，移动使用真实 Rust 存储与 HTTPS 代码；恢复调度和编辑器绑定由事件模拟及 React 行为测试验证，不等同于 iOS/Android 真机验收。复现命令见操作指南。

## 保留边界

这仍是实验接入，保持单桌面排序。64 MiB 快照请求、8 MiB 正文与 25 MiB 附件预算沿用现有模型；没有新增选主、跨表合并器或正文补偿协议。主库物理损坏、磁盘完全不可写与跨主库结构升级不属于本次覆盖路径的可用性证明。没有打包、安装到真机或执行视觉验收。
