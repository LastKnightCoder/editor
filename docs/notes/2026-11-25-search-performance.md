# 全局搜索真实资料库性能实测

结论：新增搜索不是零开销，但在当前真实资料库上未发现明显的本地查询性能问题；常见查询新增约 0.7–2.1 ms，18 条文档待办同时命中时新增约 5.9 ms。

## 数据和方法

- 日期：2026-11-25；硬件：Mac15,7，12 个物理核心，36 GiB 内存；Node.js 24.21.0。
- 使用当前设置指定的 data.db。通过 SQLite backup API 从只读连接制作主库及索引库副本，包含 WAL 中已提交数据；基准再次以 readonly + query_only 打开副本。未写入原库，未运行迁移或重建索引。
- 主库约 89 MiB，索引约 80 MiB：682 张卡片、79 篇文章、349 个项目条目、23 个项目、9 块白板、9 份 PDF、4 个数据库、51 张闪卡、275 条独立待办、2,130 条日程、260 个会话；文档待办索引 173 条。Notebook 为 0。
- 直接调用生产 FTSTable.searchHybridContent、CatalogSearchTable.search 和 queryTasks。全文基线关闭向量分支，不发起模型请求。文档转换在测试进程内运行真实转换器；没有计入跨进程传输。
- 3 个独立进程串行运行，每轮 10 个场景，每场景预热 3 次后测量 30 次。交替先测原搜索或合并搜索，减少执行顺序偏差。表内为三轮相应 P50/P95 的中位数，单位 ms。
- 基线是原正文搜索；新增是名称与文档待办两路的执行时间之和；合并列实测三路组合，不能用两个百分位数相减替代额外耗时。
- 真实标题只在内存中取样，不写入结果文件。报告及统计仅保留场景标签、数量和耗时。

## 结果

| 场景                      | 原搜索 P50 | 新增查询 P50 | 合并 P50 | 合并 P95 |
| ------------------------- | ---------: | -----------: | -------: | -------: |
| 2026年                    |       1.46 |         0.73 |     2.16 |     2.67 |
| 常见词（学习）            |       2.18 |         2.06 |     4.13 |     4.80 |
| 高频字（的）              |      11.88 |         3.25 |    15.28 |    16.54 |
| 英文缩写（AI）            |       2.70 |         1.04 |     3.76 |     4.17 |
| 完全不命中                |       0.08 |         0.69 |     0.78 |     0.98 |
| 真实待办标题片段          |       0.06 |         0.69 |     0.76 |     0.82 |
| 真实项目名称片段          |       3.52 |         0.74 |     4.25 |     4.91 |
| 真实闪卡题目片段          |       0.73 |         0.70 |     1.43 |     1.67 |
| 真实文档待办标题片段      |       3.89 |         1.35 |     5.20 |     5.84 |

所有场景都无文档待办查询警告。完全不命中的场景三路均为 0 条；标题命中和多条文档待办场景使用真实条目。

## 判断与边界

- 新增开销主要来自文档待办逐条读取原文与解析来源：18 条命中时约 4.98 ms；同一场景全部名称查询约 0.91 ms。当前 51 张闪卡的单独检索约 0.3 ms。
- 最重的合并场景是高频字：P50 15.28 ms，P95 16.54 ms，三轮最高单次 21.72 ms。新增查询自身最大单次约 7.86 ms；同步查询后零延时定时器的最高观测约 11.91 ms，包含调度噪声。
- 三个进程在正式预热前的第一次合并测量为 5.7–54.1 ms；这受模块与页缓存影响，单列观察，不混入稳态 P95，也不视为磁盘冷启动基线。
- 这证明当前数据规模下的本地查询成本可控，不能据此声称没有性能影响。未测渲染布局、跨进程队列拥塞、生产内容进程转换、远程向量模型网络延时或磁盘冷缓存；Notebook 只能覆盖空结果分支。
- 未因本轮实测修改生产实现。规模明显增长后应优先复测文档待办与闪卡 JSON 查询，再决定是否增加索引；不为当前亚毫秒名称查询预先引入缓存和索引维护。

## 复测入口

基准入口：[search-real-database.eval.test.ts](/apps/desktop/src-electron/eval/search-real-database.eval.test.ts)。显式使用 `vitest.eval.config.ts`；通过 `TAU_SEARCH_BENCH_DIR` 指定隔离副本目录，`TAU_SEARCH_BENCH_ROUNDS` 设置每场景次数，`TAU_SEARCH_BENCH_RUN` 为结果文件加轮次后缀。默认单测不收集该基准，不用耗时断言锁实现。
