# 白板编辑压力测试

在 Apple M3 Pro、macOS arm64 上从当前工作区重新构建 Electron 应用。桌面用例使用独立资料库与用户目录，打字、混合手写和 PDF 性能场景串行执行。输入法验证使用 Chromium 组合输入事件。未在 Intel Mac、实物数位笔或系统输入法驱动上测量。

## 正文、交互与保存

| 场景             | 负载与核对结果                                                                                                                                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 桌面打字         | 独立启动 3 次，每次 6 轮，每轮 24 个字符，共 432 个按键。每次另提交一次中文组合输入，离页重开后均读回。                                                                                                                                     |
| 连续编辑后冷启动 | 独立运行 3 次，每次在 4× 降速下连续编辑 40 批，每批输入字母、中文和 emoji，退格删除 emoji，再提交中文组合输入。每批核对完整文本，最终净增 830 个 Unicode 码点。退出 Electron 并启动新的主进程，三次读回的正文、其余元素和页面均与预期一致。 |
| 正文模型压力     | 8 个随机种子、2,640 次插入或删除，每次逐字符核对内容与粗体、斜体。局部路径命中 1,217 次，完整验证路径 1,423 次。208 组撤销与重做、48 次从编码状态重建模型均通过。                                                                           |
| PDF 和图形       | 972 个元素，包括 12 张真实 PDF 页卡。三轮正式平移的运动帧间隔 P95 为 9.1、9.0、9.2 ms。滚轮往返、定点缩放、拖动卡片及持久化坐标均通过，松开 PDF 卡到首帧为 12 ms。                                                                          |
| 共享与正文引用   | 生产 IPC 测试覆盖跨页移动、正文独立复制、重复提交、共享后重启与引用计数。SQLite 外键及 quick_check 通过。                                                                                                                                   |

### 打字性能

每个 CPU 档位有 9 轮。按键耗时取每轮 Chromium 外层 keypress 事件分发的 P95；第二帧指标从 keydown 量到第二次动画帧回调。慢帧按相邻动画帧间隔 ≥49.9 ms 计数。

| CPU 档位 | 按键 P95 的中位数（范围） | 第二帧 P95 的中位数 | 所有轮次最长帧 | 慢帧总数 |
| -------- | ------------------------- | ------------------: | -------------: | -------: |
| 正常     | 2.49 ms（2.19–4.01）      |             16.1 ms |        16.7 ms |        0 |
| 4× 降速  | 10.47 ms（10.16–12.62）   |             25.8 ms |        33.8 ms |        0 |

### 并发与异常恢复

- 两个 Agent 和一个用户并发修改，运行 20 组种子、1,000 轮。20,000 次尝试移动中接纳 18,000 次，200 个相互冲突的批次按预期拒绝。280 次重放没有重复执行，1,000 次用户修改均保留。
- 在删除前、中、后三种顺序下，32 个写入者各提交 8 批并重试，重开数据库后已删页面均未复活。
- 真实 WebSocket 加 100 ms 模拟往返延迟。断线后 1,000 次操作、100 批、100 次重试，重连后 731 ms 内对端 DOM 收齐。
- 在日志事务内、日志提交后、投影事务内、回执前四个切点分别强杀测试子进程 20 次。80 次恢复后重放原请求，修订与实际元素一致。

## 异常与复测

1. **一笔手写的点数不一致，原因未定位。** 混合白板有 800 条历史笔迹、480 个图形、240 段富文本、240 条箭头和 2 个画框。首轮冷启动读回时，一笔有 3 个采样点，输入观察器记录了 2 个。历史元素与另一页的比较此前已通过。三次额外记录原始及浏览器合并事件的复测、一次正式复跑，均通过 28 笔、2,832 个点的个数、坐标、压感及数据库投影核对。另做 140 笔短笔专项复测也通过。首次失败未记录逐点明细，无法区分采集差异和额外写入。已补充首个差异点的诊断，保留原判据。正式手写复跑的三轮仍有 10 个慢帧，最长 58.4 ms。
2. **索引启动超时与测试数据准备时机相关。** 在客户端启动后由测试驱动同步构造大白板，三次运行中均出现增量全文索引的内容执行进程启动超时。将相同场景提前至启动前构造后，两次对照和一次正式复跑均未出现该超时。这次调整仅涉及测试准备；真实机器在高负载时的索引服务仍需独立证据。
3. **退出期间的后台请求。** 一次连续编辑试验在「所有窗口已关闭」后记录了列表查询的 `No window found`。该次冷启动对账通过，随后两次相同试验也通过且未再记录此错误。生产 IPC 试验退出时另记录了索引服务关闭，数据库一致性检查通过。隔离运行还会阻止字体枚举子进程和外部插件目录请求。

常规复跑可使用仓库的 `whiteboard-typing-desktop.spec.ts`、`whiteboard-ink-desktop.spec.ts`、`whiteboard-pdf-pan.spec.ts` 和 `whiteboard-production.spec.ts`。本轮额外的随机编辑和短笔诊断使用临时用例。
