# 统一插件包协议验证

目标：以格式 4 分离包类型、支持平台与运行要求，同时保留已发布包的使用路径。

## 交付范围

- 格式 4 承载应用插件、独立 Skill、博客模板；桌面 Web 与本机后台共用包格式，后台仅声明桌面目标。
- 格式 1 的模板/独立 Skill、格式 2 的桌面后台与格式 3 的 Web 插件保留原始读取契约；不重新开放已退役的格式 1 可执行插件。
- 原始 ZIP、摘要、发行记录、安装目录、插件身份、私有数据与逐版本授权规则不改写。桌面读取历史 Web 包时，不追加手机发行权限校验。
- 中心按实际平台、版本、包格式与运行要求选最高兼容发行；旧客户端继续取得旧版。v1 明确限定桌面格式 1/2，不泄漏格式 4。
- 后台与 Skill 脚本沿用系统能力审核；门户移除“旧格式”标识，展示真实包类型和支持平台。
- SDK 候选版本为 0.61.0，模板构建器统一输出格式 4；UI 继续使用已发布的 0.6.0 原始包。

## 发布边界

没有上传插件、发布 npm 包、部署门户、执行远端数据库迁移、签名应用安装包或进行设备视觉验收。工作区中原有的未提交修改保持；模板子模块的构建器、作者文档和候选锁文件也保留在工作区，未创建提交。

发布时依次应用门户 0015 并部署中心、发布支持格式 4 的客户端、发布 SDK 0.61.0 与模板。模板锁文件的 SDK 摘要来自已验证候选，普通 registry 冻结安装须等对应版本正式发布；不得覆盖已发布的 0.60.0 或重新打包 UI 0.6.0 后冒用其发行身份。
