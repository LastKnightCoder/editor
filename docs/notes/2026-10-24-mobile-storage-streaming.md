# 移动存储流式传输验证快照

日期：2026-10-24（Asia/Shanghai）。分支 `codex/mobile-storage-plugins`，基于 `cbd998e38` 继续修正。

## 实现结果

- 桌面与移动复用宿主内部 fetch 桥接，响应头先返回，上传分块等待背压，响应按需读取；移动不再设 128 MiB 总量上限。Android IPC 每次最多编码 256 KiB，避免整文件 Base64、逐字节 JSON 与无界队列。
- 原生上传通道只排队一块；连接超时保留，上传进展重置响应头空闲计时，读取响应体也按空闲计时，不以整单 120/180 秒截断持续传输。取消涵盖响应头等待与响应体消费。
- 移动 arrayBuffer 消费先将网络响应写入私有临时文件，再按块填充一份最终 JS 数组；保留标准 bodyUsed、clone、流消费及错误行为。
- 数据库快照、同步资源不再读入整文件 Rust Vec。源/接收句柄按会话、方向、偏移和完成长度校验，下载成功后才改名，数据库还要校验、备份、替换；失败不发布版本、不覆盖现有文件。
- 编辑器与封面上传从 Blob 分块暂存，去除前端整文件编码与整图预解码；原生按尺寸和编码体积预算决定压缩，超预算原样上传。文件任务和图片处理共用原生内存许可，宿主新分配的独占上传字节不再复制。
- 临时文件为私有权限，正常完成与失败均释放；进程中断的暂存目录在下次会话首次使用时清理。七个现有作者插件和公开 API 均未修改。

## 原生内存观测

对当前 Rust 测试二进制分别执行单个测试，使用 macOS `/usr/bin/time -l` 记录进程最大驻留内存；每项输入为 129 MiB 级内容，不在测试端聚合整个 HTTP 文件。

| 独立原生测试       | 最大驻留内存              |
| ------------------ | ------------------------- |
| 双向 HTTP 流式传输 | 22,495,232 B，约 21.5 MiB |
| 文件句柄分块读写   | 17,825,792 B，17.0 MiB    |
| SQLite 大库快照    | 23,691,264 B，约 22.6 MiB |

证据为 `output/streaming-native-memory.json` 及 `output/streaming-memory-*.log`。这些数字只描述 Mac 原生单测进程，不含 WebView、插件或真机系统内存，不能当作整机预算。

## 实际边界

公开同步和上传接口仍是 Uint8Array，插件执行时至少需要一份完整文件字节；插件内部签名、JSON、Blob、显式 clone 或流聚合可能分配更多内存。此修正消除宿主可避免的整文件副本与编码，不承诺常量内存、任意文件大小、后台续传或进程终止后继续任务。

移动网络响应和提供方结果可能经过两份磁盘暂存，应留足磁盘空间；空间不足会失败并清理临时文件。版本 JSON 的 4 MiB 校验只用于元数据，不限制数据库、资源或 fetch 总量。

本轮没有推送、发布、视觉走查或 Android/iOS 真机峰值验收；原有发行候选与子模块本地提交保持原状。
