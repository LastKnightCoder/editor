# 白板增量更新复杂场景压测

本机 Apple M3 Pro，桌面生产构建，独立临时资料库。功能核对使用完整文档、另一份画布绑定、冷启动读回结果及 SQLite 页面投影。正式桌面用例使用 CDP 模拟压感笔。帧间隔来自前台窗口的 requestAnimationFrame，包括采集浏览器输入样本的开销。

## 手写与数据完整性

两个页面共预置 800 条笔迹（51,200 个历史点）、480 个图形、240 段富文本、240 条绑定箭头和两个画框。一个画框嵌套图形与富文本，另一页留作未编辑对照。每轮依次发送 2、63、64、65、128、129、257 个采样点的七笔，压力在笔划内变化。预热一轮、正式三轮，四轮全部参与数据核对。

## 并发、故障和恢复

| 压力条件                                   | 实测结果                                                                                                                                                       |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 两个 Agent 与用户并发，20 组种子、1,000 轮 | 尝试 20,000 次移动，接纳 18,000 次，200 个冲突批次按预期拒绝，280 次成功批次重放不重复写入，1,000 次用户修改保留。最终位置和页名与预期一致。                   |
| 真实 WebSocket，加 100 ms 模拟往返延迟     | 离线提交 100 个批次、1,000 次操作，每批重试一次。断线期间对端保持原状，重连后 722 ms 观测到对端 DOM 收齐，两个模型中的目标位置一致。                           |
| 删除与迟到保存                             | 32 个写入者各发 8 个批次。删除位于队首、中间、队末三种次序各执行并重放整批，重开后被删页没有复活，另一页写入保留。                                             |
| 四个提交切点强制终止进程                   | 日志事务内、日志提交后、投影事务内、回执前各 SIGKILL 20 次。重启后按原请求重试，80 次均恢复到预期修订，目标元素各出现一次。此项验证 Agent 写入所用的耐久路径。 |

## 972 元素的 PDF 交互对照

独立桌面场景载入 12 张真实 PDF 页卡、480 个图形、240 段富文本和 240 条箭头。使用相同主进程和相同输入，串行运行增量提交前保留的渲染构建与当前构建。计时断言采用 Playwright 的软断言以便一次运行覆盖后续动作；超出原门槛仍会使整项验收失败。

| 指标                                     |             上轮保留的渲染构建 |     当前构建完整复测 |
| ---------------------------------------- | -----------------------------: | -------------------: |
| 平移 P95 运动帧间隔，三轮                |         199.9、208.2、158.4 ms |     9.0、9.1、9.2 ms |
| 松开移动中的 PDF 卡到首帧                |                      13,765 ms |                20 ms |
| 平移、滚轮往返、定点缩放、拖卡、落盘位置 | 全部行为核对通过，性能门槛失败 | 行为与性能门槛均通过 |

当前构建首次执行同一场景时，一轮平移 P95 达到 100.1 ms，超过 25 ms 的已有门槛，当次运行失败。完整复测通过。主机负载和 GPU 调度没有锁定，首次慢帧的具体原因未定位。上述对照只更换渲染构建，不能单独归因到某一处优化。

### 样本边界

构造夹具时，模型按契约拒绝把箭头放入画框。正式样本将箭头放在根层，端点可绑定框内图形。另一次预检中，仅带标题且缺少样式字段的底层画框记录触发了渲染错误占位；错误发生在开始写入之前。正常画框创建工具会填充样式，正式用例采用完整样式，并显式检查渲染错误和占位节点。缺字段记录的兼容性是单独发现的问题。
