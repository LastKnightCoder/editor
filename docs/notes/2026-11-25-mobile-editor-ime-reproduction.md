# 移动编辑器双把手与键盘复现

## 环境与范围

初次复现使用 Android 16 真机，型号标识 2410DPN6CC，安装 Tau 0.5.1。通过用户授权的无线 adb 操作，新建了一篇 20:08 的无标题空文章；复现阶段未改已有正文、未覆盖安装应用、未改生产实现。系统列出的输入法只有小米搜狗，豆包输入法专属行为未验证。

## 已复现行为

1. 新建空文章，点击「编辑」后出现光标和配件栏；首次观察中键盘未弹出。
2. 点击空段落第一行，键盘显示，光标左侧出现灰色与黑色两个把手。
3. 用系统返回收起键盘，点击正文下方空白区域，键盘仍不显示。
4. 点击第一行，键盘重新显示。

步骤 3–4 连续重复三轮，系统 `dumpsys input_method` 每轮都分别报告 `mInputShown=false` 与 `mInputShown=true`。首次「编辑」按钮的未弹出行为没有单独做重复验证。

证据保存在本机 `output/mobile-editor-ime/`：`repeated-taps.json` 是三轮系统状态；`tap_first_line.png` 同时记录双把手与键盘；`tap_blank_again.png` 记录空白点击后的状态。截图用于故障复现取证，尚未进行修复后的视觉验收。

## 代码定位

- 灰色把手来自 `apps/mobile/src/features/cards/blockSelection/BlockHandle.tsx`，负责移动端选块与长按拖拽。
- 黑色把手来自 `packages/editor/src/core/components/BlockDrag/BlockDragHost.tsx` 的 `DragHandle`。该入口未检查 `IEditorInteraction.touch`，在移动宿主已经注册 `touch: true` 的情况下仍渲染桌面把手。`packages/editor/src/core/theme/editor.css` 的块悬停规则使其在点正文后可见，与移动端把手叠放。
- `apps/mobile/src/features/cards/ContentDetailPage.tsx` 将 `min-h-[45vh]` 放在外层包裹元素，实际 `Editor` 只有正文类，没有对应最小高度。编辑态的阅读手势处理直接返回，外层空白点击也没有聚焦转交。这与第一行可唤起、下方空白不能唤起的真机结果吻合；本轮未获得正式包 DOM 实测尺寸。
- 协作文档页面有相同的外层最小高度结构，尚未在协作文档上验证。

## 后续修复边界

触屏宿主保留移动端把手，内核遵循已有触屏交互服务停用桌面拖拽呈现。正文的可点击编辑范围应覆盖可见空白书写区域，继续保持阅读、块选择与交互节点各自的行为边界。修复后需要重跑相同真机步骤，另测「编辑」按钮首次唤起与面板切换；豆包输入法仍需装有它的环境验证。

## 修复与真机复测结果

内核已按触屏服务跳过桌面拖拽呈现，普通详情与协作详情把 45vh 最小高度移到实际 Editable。首次「编辑」在放好文末选区后复用同步 DOM 聚焦，避免 Slate 待处理选区操作导致延迟聚焦。两个详情页采用全屏背景与键盘内容外壳分离的结构，浮层挂在全屏根节点。

用户反馈键盘升起时页面位置不正确并露出下层页。复测发现按钮中心在 DOM 中为 y≈487 CSS px，而相同屏幕位置的实际触点变成 y≈733，样式按钮因此点不中。Android WebView 创建时增加原生滚动归零后，同一触点正确命中「样式」，面板与键盘可往返切换。前端内部滚动容器继续承担正文滚动。

独立诊断应用被系统拒绝安装；按用户要求改用 `pnpm dev:android`，使用与原版相同的证书成功覆盖安装 0.5.2 调试壳，保留数据。为排除共享工作区热更新干扰，最终复测由该调试壳加载固定的前端生产构建。开发预构建曾解析到旧版 lucide-react，已沿移动端现有 dedupe 配置统一版本。

真机复测结果：

- 三次进入编辑均显示键盘；收键盘后点击空白区连续三轮重新显示键盘。
- 编辑态桌面把手为 0，移动端把手为 1。
- 样式面板打开时键盘收起，返回键盘时正常显示；完成后回阅读，单击空白不进入编辑。
- 键盘与样式面板完整切换记录了 437 帧，页面层 top 始终为 0；DOM 命中检测未出现露出下层页的帧。
- 移动阅读/块选择行为测试 53 项、编辑器相关测试 7 项、官网测试 69 项及发行对账 5 项通过；mobile/editor 类型检查、前端生产构建与 Android 调试构建通过。

最终证据为本机 `output/mobile-editor-ime/phone-after-fix.json`、`layout-after.json`、`stable-build.log`。用户在修复后的手机上确认页面位置与底部遮挡「已正常」。豆包输入法与协作会话的真机复测尚未进行。
