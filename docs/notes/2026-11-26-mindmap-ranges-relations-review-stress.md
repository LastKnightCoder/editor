# 思维导图概要外框联系线审查与压测

审查日期：2026-11-26。对象为当前工作区的概要、外框、联系线及其依赖的布局、剪贴板、结构操作和协作链路。初次审查结论为 REQUEST_CHANGES，共确认 5 项问题（P1 四项、P2 一项）。用户确认后已修复，修复与最终验证见文末；以下问题描述和早期读数保留为修复前证据。之前的思维导图基础能力审查不能覆盖本批新增能力；本文是本批的独立审查快照。

## 修复前确认的问题

### P1 协作导图粘到节点下时复用身份并丢失区间

位置：[mind-clipboard.ts](/packages/whiteboard/src/utils/mind-clipboard.ts) 的 `fromTransfer`（第 33 行），以及 `MindUtil.cloneSubtree`。

`TransferElement` 原本有不同的 `id`，转换却统一写成空字符串。后续克隆的身份映射以原 id 为键，所有节点因此得到同一个新 id。5 节点（根、3 个分支、1 个概要）的真实 transfer 导出，转换并挂载后只剩 1 个唯一 id；概要的旧端点不能被映射，布局规范化后概要关系和外框均消失。

通过真实 `MindPlugin.getCapabilities().clipboard.pasteInto` 再验：调用抛出“白板身份不能复用”，模型保持操作前状态。因此已证明的是协作粘贴无法提交，以及中间树的身份和关系错误，未证明已保存文档被破坏。这是本批依赖链路里的存量缺陷，新增概要与外框进一步受其影响。

修复建议：转换时保留原身份，随后为整批子树一次性建立新身份映射，同时改写概要、外框和绑定引用；最后再提交。不要用随机 id 覆盖原身份后再尝试恢复区间。

### P1 嵌套外框包围盒存在指数级重复遍历

位置：[ranges.ts](/packages/whiteboard/src/utils/mind-layout/ranges.ts) 的 `subtreeRect`（第 52–66 行）。

计算一个节点时先递归所有子树，再计算其外框；外框又经 `rangeRect → subtreeRect` 遍历同一批子树。如果每层对唯一子节点添加外框，递推为 `T(d) = 2T(d-1) + O(1)`。这条路径直接被 `useMindRanges` 渲染使用，不只是导出或压测工具。

使用真实 `boundaryBox`，仅通过节点 x 的 getter 计数，不依赖机器速度：

| 嵌套深度 | 节点数 | 单个根外框计算的 x 读取次数 |
| -------- | -----: | --------------------------: |
| 4        |      5 |                          30 |
| 8        |      9 |                         510 |
| 12       |     13 |                        8190 |
| 16       |     17 |                      131070 |
| 20       |     21 |                     2097150 |

21 个节点远小于现有元素和深度预算；本机一次 `boundaryBox` 已约 193 ms，`subtreeBox` 同形态约 330 ms。继续增加深度将很快阻塞主线程，这是由确定性访问次数推断的风险，没有运行会长时间卡死的 64 层样本。

修复建议：一次布局或几何计算内，自底向上计算每个节点的可见子树包围盒并复用，外框从已计算的子树盒合并。缓存必须按当前布局、折叠与坐标版本失效。

### P1 协作导图跨父级拖拽仍按删旧建新提交

位置：[MindPlugin.tsx](/packages/whiteboard/src/plugins/MindPlugin.tsx) 的 `commitDrop`，同根分支第 1368 行及跨根分支。

真实协作模型中把根下的 a 拖成 b 的子节点，`diffNode` 产生复用 a 身份的创建/删除组合，模型抛出“白板身份不能复用”。普通三分支导图就能复现；带概要与联系线时同样失败。之前修复的 Shift+Tab 显式移动没有覆盖拖拽入口。这是相关结构链路的存量缺陷，不能归因为本批引入。

修复建议：拖拽提交先表达保留身份的 `move_node`，对移动后的结构只生成属性与区间补丁；同步处理因区间收缩而消失的概要。跨父级、跨根、Alt 拖出及单步撤销分别验证。

### P1 概要因移动消失后残留悬空联系线

位置：[MindPlugin.tsx](/packages/whiteboard/src/plugins/MindPlugin.tsx) 的 `commitDrop`，以及 [useMindNodeKeyboardNavigation.ts](/packages/whiteboard/src/components/MindNode/hooks/useMindNodeKeyboardNavigation.ts) 的 `commitRoot`（第 357–371 行）。

创建只括住 leaf 的概要 s，再从 s 连到另一节点。把 leaf 拖走或 Shift+Tab 升级时，区间清理会删除 s，但这些提交入口未对差集节点执行 `relationRemovals`。联系线仍保留已不存在的 s 为绑定端点。

本机真实 `commitDrop` 和协作模式真实键盘 hook 均复现：概要已不存在，箭头仍在。协作普通拖拽的身份错误会更早阻断，因此另用本机拖拽与协作升级分别证明联系线缺陷，避免把前一个错误当成清理验证结果。

修复建议：根据最终结构求实际删除节点差集，统一在同一批操作清理绑定联系线；移动但仍存活的节点不应删除其联系线。验证单步撤销能一起恢复概要和联系线。

### P2 同一区间重复添加概要导致正文完全重叠

位置：[MindUtil.ts](/packages/whiteboard/src/utils/MindUtil.ts) 的 `addSummary`（第 83–96 行），以及 [ranges.ts](/packages/whiteboard/src/utils/mind-layout/ranges.ts) 的 `placeSummary`（第 160 行）。

对 a、b 连续添加两次概要，入口允许新增两个概要；它们只按同一范围计算同一锚点，四种布局都得到完全相同的 x/y。重叠由几何相交断言复现，未进行截图或视觉走查。

修复建议：对相同范围再次操作时复用已有概要，或为多个概要安排独立空间；交叠、包含与相邻范围也需按确定规则处理。不要让第二次操作创建不可单独点选的重叠正文。

## 修复实现

五项问题均已修复，新增的边界验证也已合入默认回归。

- 协作剪贴板转换保留原节点 id；同批子树统一创建副本身份映射，概要、外框端点与外框自身 id 一起换新。框内外粘贴均通过真实能力入口验证，检查正文、标题、单步撤销重做与二进制重开；多选兄弟复制时，概要引用同批副本。
- 几何计算改为每批查询复用可见子树包围盒与父节点兄弟索引；范围规范化、外框间距也复用分组索引。查询批次不跨坐标与折叠变化存活，避免缓存陈旧。相同的 21 节点 `boundaryBox` 夹具从 2097150 次 x 读取降到 40 次，默认守护约束访问次数随节点规模线性增长，不用机器耗时断言。
- 同树换父、跨导图、拖出、整图合并均改用 `move_node`，移动后再生成布局与区间补丁。源节点、正文与仍存活联系线保持身份。修复过程中发现本机根拖动实时预览的坐标未被新移动历史恢复，现已在合并提交中补记预览前属性，原有两项根拖动撤销回归恢复通过。
- 升级和拖拽通过 `withMindRelationRemovals` 按最终结构差集清理联系线；先模拟操作取得最终箭头索引，避免删除根节点造成的下标移动。仍在文档中的移动节点不算删除。结构与连带删除属于一次提交和一次撤销；同父级排序保留范围，不按跨父级移走处理。
- 重复添加同一区间概要时复用已有节点，保留已有正文。两端并发生成重复概要时，保留第一个概要，其他总结投影为普通节点；两个节点的身份、正文均保留，不再完全重叠。真实两端并发合并和局部撤销已验证，不覆盖或删除另一端正文。

权威架构事实更新在 `packages/whiteboard/docs/architecture.md`，读者使用说明更新在 `apps/website/content/docs/whiteboard.md`。压测入口沉淀在 `docs/guides/development-quality.md`，不需要从临时目录恢复测试：

```sh
pnpm --filter @tau/whiteboard bench:mind
```

该命令显式开启 `WHITEBOARD_MIND_STRESS=1`，运行纯布局、嵌套几何与协作长会话。时间采样仅在门控套件打印，不成为默认单测的耗时门槛。原审查夹具重跑时，重复概要的断言更新为复用同一身份、仅保留一份概要正文，这是修复后的明确行为契约；其余原失败用例未删除或弱化。
