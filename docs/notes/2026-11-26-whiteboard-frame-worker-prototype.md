# 画框 Worker 隔离原型：正确性通过，当前版本不接入

隔离原型实现了真实 Worker 镜像、隔离候选和固定基线下的原子合入。复杂压力、实际保存与协作回归通过，但当前版本没有端到端收益。原型保留在性能夹具，生产入口和同步 API 未改变；全面 60 FPS 仍未达到。

## 原型边界

- Worker 只推进已确认镜像，在独立文档生成候选；复用完整契约、结构和容量校验，返回 V1 增量及初始化保护范围。每次准备也同步空文字根目录。
- 主线程在事务内检查许可、内容修订、根数量、待决依赖和事务状态；候选只能结算一次。合入标为本地事务，复用现有历史与保存监听，不能旁路保存。
- 沿用当前绑定的快照读取、投影和空闲预算准备，计时不会在 Yjs 合入后结束。尚未接入立即预览、依赖编辑队列或新对象的提交前编辑。

## 对照方法

同一生产构建夹具、1000 个带文字同屏元素，对比相同命令。结构同步组使用当前结构增量入口，纯几何同步组使用当前几何批次入口；后台组使用真实 Worker 返回增量合入。每组一轮预热、两轮正式，共 54 条采样、36 条正式样本。每轮使用新页面；Worker 在初始化后测首个候选，不能将进程预热解释为常驻 Worker 的长期热路径。同步复测完全不创建 Worker，先前共同初始化 Worker 再销毁的 54 条对照和 6 条试跑均保留。

这是一组模型事务原型，不含新建手势预览或拖动显示阶段调度，不应与上一轮完整交互基准直接作绝对值对比。读取 SVG 屏幕矩阵确认实际子元素位置，检查完整收纳/解散顺序、全部几何、1000 个 SVG 身份和单步撤销重做；计时后另用独立完整模型对账。所有样本保留首屏后 500ms，若空闲准备未执行则在采样内显式完成，不能把必要工作移出窗口。

## 4× 成本定位

| 阶段           | 收纳同步  | 收纳 Worker | 解散同步  | 解散 Worker |
| -------------- | --------- | ----------- | --------- | ----------- |
| 真实合入与历史 | 48.9–51.2 | 28.8–30.5   | 43.1–49.8 | 26.9–31.4   |
| 快照刷新与投影 | 27.2–27.7 | 90.4–92.4   | 31.0–36.5 | 88.2–91.0   |
| 后续预算准备   | 0.0       | 327.1–336.7 | 0.0       | 331.1–333.9 |

二进制候选被主线程视为外部写入：原结构快照与容量证明没有随候选交接，因此刷新重新打开既有富文本根，空闲准备又重复完整验证和索引准备。同步增量入口能沿用这些证明，后台组暂时失去这一优势。各阶段可能包含嵌套读取，不应再将 readMs 加到刷新时间上。

4× 合入本身仍约 20–31ms，超过一帧预算；即便消除后续重复读取，仍须验证真实合入、历史及密集绘制的下限。后台还复制并完整验证候选，准备延迟也进入首个结果显示时间。当前结果只否决这个返回二进制增量的原型版本，不能推导 Worker 或异步结算方向整体不可行。

## CPU 档位的限制

本次 1×/2×/4× 是页面主线程的 CDP 降速。Worker 收纳准备在三档下均约 231–242ms，没有按档位同倍增长；因此不构成所有线程一起降低 2×/4× 的验收。即便这个有利于 Worker 的条件下，首个结果显示仍退化。Chromium 的[页面设置入口](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/core/inspector/inspector_emulation_agent.cc)调用[主线程降速器](https://chromium.googlesource.com/chromium/src/+/99baeeafe29b54168bc18411791025d4a9419eea/third_party/blink/renderer/platform/scheduler/public/thread_cpu_throttler.h)。后续若出现收益，必须补全线程校准，再谈全面 4× 放行。

## 正确性与压力

- 4× 密集场景：1000 个带文字元素、5 轮、25 个历史批次、9010 次归属移动；混合场景：909 个元素、5 轮、27 个批次、8138 次归属移动。包括旧分栏升级、嵌套内容、箭头、批量几何和移出移入。
- 每一步执行完整副本接纳、逐步撤销重做及稳定元素/正文身份核对。每组 8 次取消、许可撤回、等待候选时 abort、循环移动、远端竞争、空根变化、重复结算和关闭准备器拒绝，失败零写入、零历史变化。完整 V1 保存重开一致，无页面异常。
- 实际 SQLite、自动保存监听和 WebSocket 定向回归 8 条通过；同一候选核心经真实保存/推送后，单步撤销保留远端内容，重做保留新标题，两端耐久状态重新接纳一致。浏览器真实 Worker 链路和 SQLite 核心路径分别覆盖，尚未接入生产端到端 Worker。
- 首次压力运行超过 10 分钟未完成而中断；该尝试不算通过，保留中断信息和日志。加入阶段记录后，以相同 5 轮和相同复杂度重新完整完成，没有缩小场景。
- 原型与夹具定向类型检查、白板边界和文档检查通过，lint 无错误。保存新增回归在最终测试辅助函数修改后又单独通过。正式性能采样功能结果、完整对账、撤销重做和实际屏幕坐标全部通过；没有做视觉验收。

## 后续门槛

下一步仍在隔离层验证“已验证写入计划、增量快照与容量证明”的交接，基线或观察者失配必须撤销证明并读取真实状态。先测主线程最低成本，再决定是否接入；若单事务和绘制仍超过预算，继续处理这些下限。现有同步 API、撤销归属、保存和远端竞争规则继续作为约束。
