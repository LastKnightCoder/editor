# 插件目录写入验证记录

本地工作树完成清单与日历目录的通用 create/update；没有执行 SDK、客户端或插件发布。创建沿用稳定 requestId，更新要求 expectedRevision。目录元数据 editable 与内容 writable 分开，系统目录不可编辑，归档用户目录改名不解除归档。

## 行为与升级

- SDK 全套 379 项通过；最后相关数据/中心用例复验 60 项通过，SDK、桌面、手机类型检查通过。
- 桌面相关 10 个文件、94 项通过，覆盖目录领域、数据变化、任务领域、适配通道及 AI Schema 对账。
- 手机 TS 数据与任务适配 15 项通过；项目 check:rust 的 fmt、Clippy 及 393 项 Rust 测试通过，沿用两个既有环境门控忽略项；最后目录 5 项及 Clippy 再验通过。
- 两端验证旧回执约束升级保留全部 todo/event 行及 retired 状态；后续初始化失败时旧结构、旧数据一起回滚。目录删除退役原请求。
- 同毫秒竞争、时钟回拨、过期版本、重试、更换参数/类型、不同插件请求隔离、归档及系统目录、元数据局部更新、清单曾用名和正文显式绑定均有相关行为验证。
- 创建和修改沿目录数据入口执行；目录改名不改写原任务/事件身份，不清空描述正文、分组、排序或置顶。手机日历操作日志记录真实日历 ID。

## 目录压力验证

入口为 apps/desktop/bench/plugin-directory.stress.ts，经专用配置显式运行，不进入默认单测。真实文件 SQLite 与实际目录写入入口运行，Electron 和视频索引队列仅在边界替换。

| 场景                   | 结果                                                                            |
| ---------------------- | ------------------------------------------------------------------------------- |
| 初始规模               | 1,000 个目录、10,000 个独立待办/日程、10,000 个正文待办                         |
| 全量期间改名与新增目录 | 426 页完成扫描/补偿，21,001 个身份与独立构造的预期集合逐项一致                  |
| 四连接竞争             | 1,200 个并发连接事务及 500 次宿主颜色修改，过期版本拒绝覆盖                     |
| 颜色、重试和无操作     | 颜色不产生全库正文通知；1,000 次创建重试和 500 次无操作更新不增加日志           |
| 回执写入失败           | 100 次故障回滚，目录、回执、日志无半提交                                        |
| 大量清单改名与裁剪     | 20 次改名后日志保留 100,000 条，旧游标明确重置；211 页重新核对全部身份          |
| 重开续读               | 检查点可继续，所有正文及原始任务/事件行摘要保持一致，目录重试返回当前名称与颜色 |
| 数据完整性             | integrity_check=ok，foreign_key_check 无记录                                    |

## 构建与文档

SDK 声明包生成 532 个声明文件，UI 生成 70 个。JSON 色板的类型依赖转成普通声明模块，作者无需从源码仓库导入 JSON。仓库外独立作者通过类型、构建、冻结安装、平台和包完整性检查，新目录方法及非法色板的类型拒绝均参与编译。报告 `/tmp/tau-directory-portable-author.json`，sdkSource 为 local-tarball；本地候选不表示 npm 上的包已更新。

桌面 Vite 生产构建通过；官网 69 项和发布清单行为 5 项通过。Schema build/check/prepare、数据库/插件进程/白板边界、AI Schema 对账、文档检查及 diff 检查通过。没有进行截图、视觉或真机验收，也没有实际连接外部待办/日历服务。

当前能力不包含目录删除、归档操作、合并、分组树编辑、多设备执行互斥和远端同步策略。压测结果只覆盖上述规模和场景，不构成任意规模与环境的无故障承诺。
