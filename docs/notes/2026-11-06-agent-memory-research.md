# 个人助手的 Agent 记忆系统调研

2026 年 11 月 6 日

**建议先在现有 Pi 聊天宿主旁增加本地记忆库。** 每轮只带一小份已确认的用户画像，按需查近期状态和历史证据。首版先做好「记住、查看、更正、忘记」，再让后台从对话中提炼候选。这样既能让新对话认识用户，也能避免把一句「我最近在学 Rust」永久当成现状。

## 代表性系统怎么做

| 系统                    | 怎样写入和召回                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | 适合借鉴什么                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| **Hermes Agent**        | 内置 `USER.md` 存用户画像，`MEMORY.md` 存工作约定和经验；默认分别限 1,375、2,200 字符。开会话时注入快照，Agent 可用工具增改删；会话原文另存 SQLite，用 `session_search` 全文检索。Mem0 等后端是可选扩展。[持久记忆](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory) · [会话检索](https://hermes-agent.nousresearch.com/docs/user-guide/sessions/#session-search-tool) · [可选后端](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory-providers) | 最常用的信息有固定预算；想不起细节时再查原文。快照可复用提示缓存，但会话内更正不会自动刷新这块提示。 |
| **OpenClaw v2026.11.1** | 工作区有画像 `USER.md`、精选长期记忆 `MEMORY.md`、日期笔记。长对话压缩前可静默写当天笔记，默认的 Dreaming 定期整理并提升长期条目。内置 SQLite 索引支持关键词与向量混检，Agent 可按需查笔记。[记忆总览](https://github.com/openclaw/openclaw/blob/v2026.11.1/docs/concepts/memory.md) · [压缩前写入](https://github.com/openclaw/openclaw/blob/v2026.11.1/extensions/memory-core/src/flush-plan.ts) · [内置检索](https://docs.openclaw.ai/concepts/memory-builtin)                          | 把日常观察和经过筛选的事实分层；积累足够多的观察后，再引入定期整理。                                 |
| **Mem0 v3**             | 接入现有 Agent 后，通过 `add` 抽取并追加独立事实，`search` 按用户等范围检索。托管版另有结构化画像，以及标记旧事实被替代、合并重复项的机制。[写入与版本变化](https://docs.mem0.ai/migration/oss-v2-to-v3) · [托管画像](https://docs.mem0.ai/platform/features/user-profiles) · [整理机制](https://docs.mem0.ai/platform/features/dream)                                                                                                                                                     | 想快速接上自动提炼和召回，可以试独立记忆服务；画像与事实检索仍应分开。                               |
| **Letta**               | 当前 SDK 用 Git 版本化的 Markdown 记忆库 MemFS：根文件常驻，深层文件按需读；可以显式要求记住，也可以由后台复盘整理。旧 SDK 常见的 `human` / `persona` 是另一套接口。[MemFS](https://docs.letta.com/concepts/memfs) · [后台整理](https://docs.letta.com/configuration/memory) · [旧版 SDK](https://docs.letta.com/v1-sdk)                                                                                                                                                                   | 让用户能检查 Agent 记下的内容；多 Agent 可共享明确授权的记忆，而各自的工作笔记仍可分开。             |
| **Zep / Graphiti**      | Graphiti 从对话或事件中抽取实体与关系，记录事实何时成立、何时失效，保留历史，并结合全文、语义和图检索。Zep 是使用 Graphiti 的托管服务。[Graphiti](https://help.getzep.com/graphiti/getting-started/overview) · [事实的时间模型](https://help.getzep.com/v4/facts)                                                                                                                                                                                                                          | 适合经常问「去年谁负责哪个项目」之类跨实体、跨时间的问题。个人画像和近期计划先用普通记录就能表达。   |

对个人助手影响最大的是两件事：**哪些信息值得跨会话保留，信息变了怎样停用旧值。** Markdown 最适合先验证手工维护的少量画像；本地结构化记录更容易做来源、期限和更正，适合这次需求；外接 Mem0 能减少抽取与检索开发，但数据归属和删除行为仍需由宿主定义。等确实有多跳关系查询，再评估图谱。

## 在现有聊天体系里怎么落地

[架构图：Pi 聊天与独立记忆库](./2026-11-06-agent-memory-architecture.html)

当前聊天原文已经由 **Pi v3 JSONL** 按库持久化，`chat_session` 只存目录和作用域。桌面 Pi 宿主有逐轮提示词装配位置，移动端公共运行时有具名提示段接口。现有 `chat-prompt` 向量索引服务「问了但没写」，只收主对话用户提问，不进入普通检索。可以复用会话读法和提示装配，保持原文与个人记忆的生命周期独立。[会话架构](/docs/architecture/desktop/ai-chat.md#pi-聊天运行时与工具审批) · [桌面提示装配](/apps/desktop/src-electron/main/modules/pi-session-host.ts#L1111) · [AI 公共核心](/packages/ai/README.md#airuntime-宿主接口) · [现有对话索引](/apps/desktop/src-electron/main/modules/chat-prompt-index.ts)

| 用户希望助手记住                   | 记什么                                                                   | 何时使用                                                                                                                    |
| ---------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 我是谁、做哪行、擅长什么、喜欢什么 | **稳定画像**。存用户明示的身份、领域、技能、爱好和沟通偏好。             | 少量高频条目常驻；细节按需读。                                                                                              |
| 我最近在忙什么、学什么             | **近期状态**。存项目或学习主题、当前状态和最近确认时间，支持结束或过期。 | 按主题、时间和状态检索。过期条目只作历史。                                                                                  |
| 我接下来打算做什么                 | **计划**。区分「考虑中」和「已决定」，可关联已有待办或日程。             | 回答计划类问题。用户要求提醒时，走待办或调度能力。[OpenClaw 的意图分层](https://docs.openclaw.ai/concepts/standing-intents) |
| 上次为什么这么决定                 | **会话证据**。通过会话和消息 ID 找回原文。                               | 需要查证时才查；查不到就说明不确定。                                                                                        |

记忆条目用本机独立 SQLite 保存，按库隔离，首版不加入库同步。记录只需包含类型、事实键和值、状态、来源、确认时间，以及可选的有效期；「什么时候说的」和「什么时候成立」分开。默认只在当前库的主对话使用，子 Agent 只接收任务所需的片段，资料对话和浏览器扩展默认不读写私人画像。记忆只作为背景数据参与回答，权限仍由宿主决定。

## 一条记忆如何生效

[流程图：从用户表达到下一轮召回](./2026-11-06-agent-memory-flow.html)

1. **先认来源。** 用户明确说「记住／改成／忘掉」时，提交后才确认成功。以后启用自动提炼时，只从本轮用户表达取证，助手生成的总结、网页和工具内容不能自行成为用户画像。一次性的请求只在本轮有效，敏感信息不自动入库，凭据不写入。
2. **用同一条规则处理更新。** 例如用户先说「我最近在学 Rust」，后来补充「Rust 先放下，现在主要学 Zig」。将 Rust 标为暂停并保留历史，将 Zig 设为当前；如果只是问了一次 Zig 语法，不更新学习状态。用户明确更正优先，含糊的冲突留待确认。
3. **按需取回。** 模型调用前加载预算内的稳定画像；遇到回忆、时间或计划问题，按范围、状态、日期和关键词找少量条目。需要证据时再查原文。忘记时同步移出索引和缓存，阻止同一来源在后台重建；是否同时删除原对话，交给用户单独选择。[OpenClaw 的来源与删除设计](https://docs.openclaw.ai/concepts/memory-provenance)

## 建议的实施顺序

1. **先验证用户能管理记忆。** 桌面主对话接入明确的记住、更正、忘记和记忆列表，接上画像及近期条目的有界召回。首版按关键词和时间筛选，专门试中文短词和中英混合查询。
2. **再验证自动提炼能帮上忙。** 对已提交的用户消息在轮后异步提取，按来源去重，切库或删改源消息后拒绝迟到写入。先让用户确认候选，再评估哪些能安全自动保存；补上按需查证旧对话。若同义表述的漏召回明显，再复用现有嵌入能力做混检。

验收可以从五个真实场景开始：新对话遵守已保存偏好；更正后只使用新值；问上个月时能区分历史与现状；忘记后不从旧对话重建；切库、私密场景或没有证据时不误用信息。可参考 [LongMemEval 的跨会话、时间、更新与无证据问题](https://arxiv.org/abs/2410.10813)，另外记录误写率、过期误用率和每轮新增延迟、提示词用量。
