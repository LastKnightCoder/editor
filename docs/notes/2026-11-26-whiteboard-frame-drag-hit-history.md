# 密集画框持续拖动的命中成本与撤销历史

对照从已接入稳定选区订阅和 iframe 保活的画布开始。场景为 1000 个同屏带文字的图形，整框原生指针沿 220 × 40 像素轨迹移动。正式长拖动计划八秒，发送 480 次输入，越过五像素起拖阈值后有 470 个应单独显示的位置。环境为 Apple M3 Pro（12 个逻辑核、36 GiB）、macOS 26.5.1、Chrome 158.0.8127.37。DevTools 只对页面主线程设置降速。

松手优化与 iframe 保活已在 `6852c1b46` 提交。本轮选择按两笔实际慢几何提交触发的策略，接入当前工作区。逐帧观测后触发的策略、单独开启增量裁剪的策略作为隔离对照。严格 60 FPS 目标尚未达到。[全部原始样本、输入、位移、过载记录与压力结果](2026-11-26-whiteboard-frame-drag-hit-history.raw.json.gz)

## 几何提交的重复工作

Yjs 将连续几何事务合并成一项撤销历史。白板的公共历史管理器随后按捕获时的作用域裁剪插入和删除区间。每次中途同步都会把本次手势已经检查过的所有历史区间再扫一遍。一次 4× 八秒试跑中，14 笔几何提交的候选历史时钟总数为 210210；复用已确认部分后实际重新裁剪 28028 个。这里的计数包括插入和删除，独立于最终保存的元素数量。

隔离原型仅在同一份禁止 GC 的文档、本地手势自己的历史和同一活动画框批次中复用。它按撤销项、作用域及字段保留私有区间副本，从当前事务的前后状态向量得到新增时钟，删除使用实际删除集。只有当 Yjs 合并结果和「上一份已裁剪范围与本次增量的并集」完全相等时才复用。首次捕获、作用域变更、改写历史、撤销重做或不满足条件时走完整裁剪。事务、初始化保护、保存、远端入口及单步历史语义保持原有契约。

## 命中降载

正常移动时仍将输入交给原来的画布。隔离原型在手势前 200ms 之后观察绘制时钟，连续输入期间，1.8 秒内出现三次超过 24ms 的帧间隔才启用画布表面的临时命中面。松手和取消都会移除命中面。起始时刻、触发次数、屏幕位置及发送端时钟随样本记录。强制产生慢帧仅用于中断压力，用于测性能的输入不注入人造阻塞。

另一项策略直接测本机整框手势的现有同步几何提交。只有同一手势连续两笔成功且隔离的提交各超过 12.5ms，才在剩余手势启用命中面和增量历史。阈值按 60 Hz 每帧的四分之三选取，给输入及绘制留下余量。健康手势只在定期提交前后读取时钟，无需添加逐帧监听。在正确性专用压力中，用真实同步观察者稳定触发该路径，并核对连续中途保存、取消和迟到松手。

## 正确性压力

4× 混合白板有 909 个元素、20 轮、121 个手势。千元素压力覆盖五轮收纳解散、12512 次前向归属移动、逐步撤销重做、独立模型及绘制顺序对账；1000 个 SVG 未重建，焦点、未提交输入及 iframe 文档保持，iframe 只加载了一次。拖动中远端更新全部几何、远端解散和迟到松手均通过；单独令临时命中面实际启用，再按 Escape 并松手，模型恢复且命中面清除。

真实双端 SQLite/WebSocket 回归 11 条通过。千子元素用例在一次手势中往返多个中间位置，每次等待远端收到，再用两个新开的只读 SQLite 连接分别读回状态，核对完整模型、1000 个坐标及非空正文。松手、单步撤销及重做后重复同一组检查，并验证真实运行过历史增量裁剪。

按提交耗时触发的原型另做了激活状态下的双端中断。在多笔几何已经广播并写盘时，对端写入文档标题，本机取消活动手势后收到迟到 pointerup。两端从磁盘读回的 1000 个坐标均恢复到手势前，保留远端标题，两个用户各自的撤销栈仍正确。临时命中面已释放。对同一作用域增量裁剪的直接实现，另用真实 Yjs 验证了作用域扩展、初始化保护及已截短历史项的回退。

## 采样与判定

## 正反序与拟接入实现复核

同轮、同相位且双方环境合格的 4× 外部时钟配对中，错过刷新分别为 20 → 4、149 → 34，输入 P95 为 30.3 → 24.4ms、49.3 → 34.2ms；屏幕独立显示位置分别为 433 → 452、324 → 429。4× 页面时钟的两对轨迹由 13.45 / 13.94 秒降为 8.38 / 8.82 秒。只裁剪历史的同组轨迹仍为 13.77 / 13.86 秒。绝对时间随主机状态波动，以上变化只在同轮比较。

低负载单看一个峰值不稳。用两份相同实现作对照，1× rAF 同一轮两份基线的峰值分别约 24ms、47ms，候选约 46ms。为排除原型包装影响，再把拟接入的类型化代码编入隔离构建，移除实例方法包装和专用计数器，用 DOM 属性变化独立记录是否启用命中面。1× 两种时钟的所有正式样本均未启用。第一次固定时钟配对的 P95 接近，但峰值从 23.3 / 23.2ms 升至 46.3 / 37.8ms；第二次峰值所在的位移间隔早于第一笔几何提交。交换顺序、增加相同基线后，4ms 相位的两份基线为 23.5 / 24.0ms，候选为 22.7ms；12ms 相位的两份基线为 46.4 / 20.7ms，候选为 14.4ms。反序候选两轮均显示全部 470 个有效点，拖动期间均未错过刷新。1× 类型化实现的 rAF 配对，基线 P95 两轮均约 17.8ms，候选为 17.8 / 17.7ms。接入判定是未观测到可重复的轻负载退化，所有较差记录仍在原始数据中。

4× 类型化构建的另两次固定时钟配对，实际启用命中面后，错过刷新从 142 / 153 降到 37 / 83，独立显示位置从 332 / 319 提高到 425 / 381。其中一条候选仍有约 175ms 输入峰值，对应约 164ms 实际位移间隙，该段没有几何模型提交与之重叠。这一结果不满足逐帧流畅要求。

## 同一块画布反复拖动

同板对照复用已加载的 1000 个编辑器及其 DOM。轮间真实撤销到同一初始模型，逐步重新水合独立模型核对，交换先后顺序。移除上一轮的事件监听器、模型计时包装和采样状态，避免探针累积。首次探针未完整解除方法包装，当场停止；记录其已返回的进度，不用于放行。限容量内的两组同板 1× 短组各产生一对双方负载合格的记录，均未启用命中面。一对基线与候选均单独显示 470 个位置，另一对为 468 → 470；输入 P95 分别为 18.3 → 19.0ms、19.5 → 17.6ms，峰值为 21.5 → 20.9ms、27.6 → 20.8ms。前述重新开页时较高的 1× 峰值仍保留，不能把它们从比较中删除。

较长的同板组包含每次拖动、中途多次写入、验收撤销、重做及下一轮复位。在禁止 GC 的 CRDT 中，这些操作持续增加真实持久化字节。第六次起保守容量证明不能覆盖下一批所有几何，基线也走了完整 submitChunks 预检。第八次出现无法复位到初始模型；该次夹具在先前功能步骤失败后仍尝试额外撤销，未留存完整末轮现场，因而不据此直接断定产品数据损坏。现已先保留失败行，跳过对失败手势的额外撤销，分别审计正常写入、撤销和重做。

## 文档容量边界

在两种实现中分别用真实的来回平移预填充历史。8,038,054 字节的种子可完成拖动和一次撤销。基线在 8,364,782 字节、新策略在 8,344,372 字节时，重做会超过 8 MiB 而被预检拒绝。拒绝前后的完整 V1 二进制、可见模型、撤销和重做栈的项身份及区间均一致。

更靠近上限的 8,238,262 字节种子揭示另一条路径。基线和新策略都已在拖动中发布了部分移动，下一笔几何被拒，随后回滚本身也超限。修正前两个方案均停在画框 x 约 159.9（起点 100），撤销和重做栈深度却都是 0。取消的清理逻辑在回滚失败时也清除了临时历史。单独验证的修正把仍在临时栈内的已提交记录移交给宿主历史，仍向调用方报告失败。两组原生指针复测均保留 1 个撤销项；再次尝试撤销仍被容量守卫拒绝，二进制、完整模型及两栈未发生写入。此边界不会通过加大额度或跳过校验来换取通过。容量拒绝仍然会中止手势，画面可停在已经对端确认的位置。本次原生复现中，被拒手势结束后原来的画框选区也没有恢复。

## 容量修正后的复核

在默认绑定中保留回滚受阻的手势历史，计时器同时报告提交和回滚错误。用 8,238,262 字节的原始状态再次测得，基线对照与慢提交方案停在对应的已同步位置，各保留 1 个撤销项，迟到松手未重放。再次撤销的容量拒绝在两臂均未改变 V1 字节、模型或两栈。真实双端 SQLite/WebSocket 用例还验证了已广播的部分坐标、两个用户各自的历史及磁盘重开一致。此修正不扩充值域和 8 MiB 总预算，容量不足时仍不能承诺撤销或重做可以执行。

最终 12 条真实保存和网络用例分别通过。合跑时千元素远端中断用例首次在等待对端恢复坐标的 4 秒上限超时，日志记录的写盘、对端应用及渲染累计超过 4 秒；该轮其余 11 条通过，包括近满容量。大型用例改为等待相同的坐标、模型和保存对账条件，单独重跑通过。普通用例的等待条件与预算未放宽。近满用例在首次打开大文档时也使用真实双端握手确认同步就绪。
