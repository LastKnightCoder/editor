# 子 Agent 压测记录

日期：2026-11-08。

## 范围与结论

本轮只修改主进程运行时、直接相关测试与文档，未修改 UI 源文件或跨进程接口字段。使用 Windows、本机 Node v24.4.1、pnpm 11.9.0、Vitest 3.2.7、pi SDK 0.87.1；所有模型请求来自本地替身或回环 HTTP 网关。

最终定向回归 13 个测试文件、114 个用例全部通过，包含启用的全部压力用例，测试总耗时 52.77 秒。类型检查、生产构建及插件进程边界检查通过。lint 无错误，测试夹具与已有宿主代码仍有非空断言等告警；构建保留上游扩展加载器的 import.meta/CJS 告警。

覆盖场景的执行状态、取消、等待、用户交互与通知行为通过；不代表任意规模、真实服务商限流策略或真实 UI 渲染负载均已验证。完整状态快照仍有主线程 I/O 增长成本。

## 复现并修复的问题

| 场景                   | 原行为                                               | 修复                                                           |
| ---------------------- | ---------------------------------------------------- | -------------------------------------------------------------- |
| 同一执行多个 wait      | 一个等待超时会释放另一个等待的占位，结果提前自动投递 | 按 runId 保存等待者集合，分别释放                              |
| 相同请求身份但不同载荷 | 静默返回旧任务                                       | 核对输入、模式、目标及标题，不一致拒绝                         |
| 停止代次保存失败       | 尚未发出取消信号便退出，运行继续                     | 本机代次先保证生效，持久化失败仍取消运行与队列                 |
| 取消排队任务时写盘失败 | 任务仍在可执行队列                                   | 转为明确保存故障终态，不再启动                                 |
| 观察者回调异常         | 已保存成功被误写为失败，可能重复终态消息             | 隔离观察通知与运行结果提交                                     |
| 大量任务来自一个父会话 | 其他父会话迟迟无法取得执行槽                         | 父会话轮转调度，合并调度并让出事件循环                         |
| 队首启动保存失败       | 后续任务可能不再取得调度机会                         | 失败处理后继续检查队列                                         |
| 普通对象异常           | 丢失明确的 message                                   | 直接读取已存在的字符串 message，不猜测分类                     |
| 审批期间父工具被停用   | 旧审批允许后仍写入文件                               | 等待审批前后复核工具有效性和取消信号                           |
| 可选状态 IPC 失败      | 子执行被误判失败                                     | 可选通知隔离；必要工具继承失败则释放半成品宿主                 |
| 多个父 prompt 同时争用 | 所有请求互相占位后全部拒绝                           | 新一轮同步取得独占准入；20 个并发请求接受 1 个，其余明确返回忙 |

同时补齐宿主并发测试的装配依赖与隔离临时目录；恢复测试按当前公共投影的「结果未知」语义更新旧期望，没有删除故障断言。

## 最终批量样本

每个并发档提交 480 次任务，12 个父会话、60 个子会话，每个子会话复用 8 次。每档结果均为完成 417、失败 34、取消 29；无重复启动、无重复终态投递，同一子会话没有并行执行。并发档位由测试注入，产品默认仍为 3。

| 并发档 | 实际峰值 | 提交耗时 | 总耗时  | 事件循环 P99 | 事件循环最长 | 编排记录 |
| ------ | -------- | -------- | ------- | ------------ | ------------ | -------- |
| 1      | 1        | 1144 ms  | 3416 ms | 96 ms        | 120 ms       | 347 KiB  |
| 3      | 3        | 1228 ms  | 3211 ms | 104 ms       | 114 ms       | 347 KiB  |
| 8      | 8        | 1451 ms  | 3063 ms | 128 ms       | 134 ms       | 347 KiB  |

5 个固定种子 7/19/42/137/777 各交错 200 次提交、完成、取消、停止和等待，共 1000 次操作。分别提交 74/76/82/71/80 个任务，实际启动 56/66/63/63/65 次，其余在启动前取消；并发峰值均为 3，结束后无活动执行遗留、无重复启动和重复通知。

240 个同时等待混合 80 次超时、80 次取消、80 次取得终态，各自独立收尾。交互管理器的 80 个会话合计 160 个提问/审批请求身份唯一；共享授权及 bypass 正确释放审批，但不回答问题；40 个问题由用户回答，40 个被取消，迟到操作拒绝。

## 本地 HTTP 故障

| 故障         | 实际失败消息                       | 结果                      |
| ------------ | ---------------------------------- | ------------------------- |
| HTTP 429     | 429 与网关返回的模拟错误正文       | failed；未自动重试        |
| HTTP 503     | 503 与网关返回的模拟错误正文       | failed；未自动重试        |
| SSE 连接中断 | terminated                         | failed；未自动重试        |
| 流提前结束   | Stream ended without finish_reason | failed；未自动重试        |
| 非法 JSON    | SDK 的 JSON 解析错误               | failed；未自动重试        |
| 响应持续挂起 | 用户取消                           | cancelled；流与执行槽释放 |

前五类故障在失败时均只有一次 HTTP 请求。父明确发送继续消息后，累计变为两次请求并完成；第二次请求体与持久历史都保留原任务上下文。挂起取消后也能向同一 agentId 提交下一次执行。

真实 pi 宿主另覆盖：同步工具调用、提问作答、审批中停用工具、提问/审批取消与迟到回传、子宿主释放后上下文恢复、父分支变更、跨窗口隔离、创建期间停止、工具桥继承失败恢复、异步完成唤醒及重复检查去重。

## 长历史与剩余性能风险

单父会话、8 个子会话、400 次较长输入复用，全部完成且无重复通知。最终样本：提交 3178 ms，总耗时 13822 ms，编排快照 4497 KiB，事件循环 P99 为 232 ms、最长 435 ms。

原全量复制版本在同类场景测得约 17.3 秒；采用局部 Immer 按修改复制后，样本在约 13.8–16.6 秒波动。该比较受 GC、缓存与本机其他工作影响，不作稳定加速比例结论。当前未变更新不写盘、候选在写盘成功后才发布，但磁盘仍完整重写 state.json，未消除历史增长带来的序列化与 I/O 成本。

因此，本轮确认功能覆盖通过，不能承诺极端批量任务下无 UI 卡顿。若后续要求大量长期复用仍保持低延迟，应单独设计增量编排持久化，并验证事务、崩溃恢复与旧记录升级；不把这一存储变更混入本轮故障修复。

## 未覆盖的边界

- 未对真实模型账户施加流量，不代表服务商实际配额与长期稳定性。
- 未测真实 WebContents 大量刷新和用户正在修改的 UI，不做视觉验收。
- 文件故障通过真实临时路径阻塞与故障注入模拟，未进行真实断电或损坏磁盘试验。
- 持久化始终不可用时，本机停止仍生效，但无法保证该停止决定跨进程保存；不会自动重放子任务。
- 堆变化受 GC 影响，本轮没有将它当作长期无内存泄漏的证明。
