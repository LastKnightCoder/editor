# Yjs 与 Markdown 增量投影：实现、保真验证与实际采样

日期：2026-10-23。目标是在不改变正文业务语义的前提下，减少局部输入时的全文快照与 Markdown 转换。

## 结果

已将 Markdown 文件的输入路径切换为独立只读的块投影，并只缓存明确声明的确定性转换。使用参考文档的固定磁盘副本，在实际 Electron 窗口运行了前后各 40 次输入/退格，以及同进程内 20 步全量与增量路径配对测量。

配对阶段中位数：Yjs 快照约 **22.35ms → 0.30ms**，Markdown 转换约 **9.55ms → 4.60ms**。20 步输出均与完整转换相同。整次输入中位延迟从 144ms 到 128ms，但长尾仍有波动，不能把局部收益解读为所有编辑卡顿已解决。

## 实现边界

### Yjs：独立快照与块级失效

`getContent()` 仍返回可修改的新副本，并加强为深复制，调用方不能通过嵌套属性改动 Y.Doc。新增 `getSnapshot()` 专供只读消费者：可安全冻结的 JSON 块深冻结，未变块复用；二进制等可变扩展值或不宜复用的对象图独立复制，不参与缓存。

深层事件使相关顶层块失效，根结构插入也使插入对象失效，覆盖撤销恢复、属性、远端更新及结构变化。转换仍使用原来的 `@slate-yjs/core` 和文本规范化，不重写 delta 合并规则。顶层直接文本、事务内读取或观察器重入期间回退为完整独立投影，避免在观察器尚未完成时读旧缓存。[Yjs 事务事件顺序](https://docs.yjs.dev/api/y.doc) 是该失效与发布顺序的依据。

投影不借用任何 Slate 编辑器的节点引用，不写入 Y.Doc，也不改变 CRDT 身份、origin、撤销分组或网络协议。代码位于 [contentProjection.ts](/packages/editor-collab/src/contentProjection.ts)，接口约定见 [包 README](/packages/editor-collab/README.md)。

### Markdown：保守复用与完整回退

默认 `getMarkdown()` 与位置映射 API 保留原来的完整转换行为。新增的会话级增量函数只缓存顶层不可变块，块与属性必须满足只读条件，参与的 codec 必须由调用方按原对象明确声明为确定性转换。Markdown 文件窗口只声明桌面自带 codec。

未声明的插件、文本 codec、可变属性与仅浅冻结的节点不使用输出缓存。回退时克隆整个块，保持父子/兄弟关系，允许插件操作独立副本，避免把冻结数据交给旧插件修改。序列化器判定沿用 Markdown 的 formatted 类型规则，带自有 text 字段的插件元素不会被误当成可缓存文本。

脚注会重新生成编号和定义，含脚注副作用的块不缓存输出；尾部分隔符每次重新组装，重排与删除不复用旧尾换行。插件快照换代使处理器和该会话的缓存一起重建。接口细节见 [Markdown README](/packages/markdown/README.md)；窗口接线在 [markdownDocument.ts](/apps/desktop/src/features/markdown-window/markdown/markdownDocument.ts)。

- 协作与本地投影：8 个文件、35 项测试通过。新增覆盖旧快照隔离、未变块引用、未知属性、二进制独立复制、结构/属性/文本、空文档、事务内读取、观察器重入、远端更新、双编辑器及 120 步混合差分。
- Markdown：12 个文件、94 项测试通过。新增覆盖变化块转换次数、重排、空输出、尾分隔、脚注、未知数据、父上下文、插件/文本 codec 的外部状态和浅冻结输入。
- 插件：43 个文件、232 项测试通过，含插件快照更换与卸载后的增量缓存失效。
- 目录与文件会话：9 个文件、26 项测试通过。混合正文使用实际链接/脚注 schema，验证表格对齐、代码块修改、结构移动、历史、外部版本、CRLF 原文格式与未知节点保真；已有源码切换、文件冲突、代码块控制器和关闭后迟到读取回归继续通过。
- 编辑器、Markdown 和桌面类型检查通过，修改文件 ESLint 无错误；桌面 Vite 的渲染端、主进程和 preload 生产构建通过，未执行发布。

实际文档副本额外完成 14 次快照/Markdown 全量核对，覆盖输入、退格、撤销、重做、外部版本和原文恢复；另用 CDP 模拟中文组合输入提交并撤销，两条路径输出一致，最终文件 SHA-256 与固定源副本相同。此检查不能替代所有操作系统输入法、插件组合或视觉验收，但覆盖了本次改变的数据链路。

## 实际采样方法

参考文档仅由应用和本地脚本处理，没有读取或输出正文。原文件复制到固定临时源，再为各轮建立副本窗口；修改只作用于副本，原文件最终 SHA-256 未变。有效原始数据不包含正文副本、截图或 DOM 快照。

两轮都使用 24 个绘制分块，在正文中部相同位置执行 20 组“输入 x → 退格”，共 40 次原生键盘编辑。Event Timing 按 interactionId 合并最大时长，durationThreshold 为 16ms；这是样本交互分布，不是完整页面标准 INP。

| 指标                               | 改动前  | 最终实现 |
| ---------------------------------- | ------- | -------- |
| 独立交互                           | 40      | 40       |
| 分块数                             | 24      | 24       |
| 文本节点字符长度（不含代码等属性） | 142258  | 142258   |
| 交互中位数                         | 144ms   | 128ms    |
| 交互 P95                           | 168ms   | 160ms    |
| 交互最大值                         | 168ms   | 216ms    |
| ScriptDuration 累计                | 4051ms  | 4639ms   |
| 样式重算累计                       | 48.7ms  | 43.3ms   |
| LayoutDuration 累计                | 112.3ms | 129.3ms  |
| TaskDuration 累计                  | 7605ms  | 7353ms   |

共享包变更曾触发开发服务器自动重启；失效的调试连接不计入数据，稳定后重新建立副本采样。跨轮渲染进程、JIT、GC 与后台状态并非严格相同。表中最大值、脚本累计未同步下降，说明不能宣称整个渲染线程全面提速；中间实现的多轮复测也显示尾延迟存在波动。

为直接验证目标路径，另在最终窗口内做 20 步配对实验：每步局部修改后，对同一份 Y.Doc 交替先后执行原全量读取/转换与增量读取/转换，比较输出相等，再记录阶段耗时。该实验在原生交互采样结束后单独进行，没有把双路径核对成本混入上表。

| 阶段中位数    | 全量路径 | 增量路径 |
| ------------- | -------- | -------- |
| Yjs 快照      | 22.35ms  | 0.30ms   |
| Markdown 转换 | 9.55ms   | 4.60ms   |

全量参考读取沿用原转换算法，没有额外计入新增公开副本的深复制成本。增量实验使用与产品相同的投影与缓存策略，先预热缓存；20 步输出全部一致。当前包含未声明插件的块仍完整转换，因此 Markdown 转换没有被完全消除。

## 剩余热点

CPU profile 中 readSnapshot 从原先首要业务热点退出，剩余主要开销集中到 React 提交、表格全局选区订阅及光标选区同步。此次没有修改这些业务交互。下一轮应围绕表格的精确选区订阅和大量 DOM 的提交成本定位，继续保留表格多格选区、行列手柄、拖动与输入法行为回归。

## 产物与清理

有效数据保存在被 Git 忽略的 `apps/desktop/output/perf/2026-10-23-incremental-projection/`：

- `projection-before.*`、`projection-after.*`：固定 40 次编辑的 metrics、CPU profile 和状态。

- `projection-stages.json`、`projection-stages-summary.json`：20 步配对耗时及相等结果。
- `projection-validation.json`、`projection-ime.json`：实际副本的功能与字节恢复验证。

临时副本、固定源副本、测试窗口和调试连接在收尾时清理，原文窗口保留。源代码、架构及包级接口文档同步更新，未提交或发布改动。
