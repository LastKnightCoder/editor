# 旧关联表统一为查询数据库验证

用户决定自动迁移，旧自建列与值不迁移；查询结果统一只读。升级由两端开库事务执行，旧来源表仅作升级输入，成功后删除，当前主库基线为 17。

保留数据库与表身份、名称、正文中的表引用、来源范围和源字段；保留可映射的列标题、宽度、隐藏、筛选、排序、分组及汇总。依赖已忽略字段的日历和看板回到表格视图。作者、上级、天气、心情补入统一目录；项目根目录与含子文档范围按树读取，年月范围由 today 与 year/month 动态计算。旧自建正文按既有规则延迟释放，源实体与源正文不改写。

旧关联读写、配置 UI、IPC 命令、共享类型与 Schema 均退役；三份仅验证旧合并或写回的测试随被测对象删除，由升级、只读和统一来源契约验证承接。

## 真实副本

仅以只读 SQLite online backup 从用户主库和索引取得私有副本。测试器再次克隆工作副本，在副本中附加卡片、文章、日记、项目根目录、项目含子文档五种旧关联定义，经正式开库与 IPC / Worker 链路执行升级。

最终 **79 / 79 场景通过**。五种迁移结果的行身份与独立 SQL 对账一致，旧行列清空，源业务记录逐表摘要不变；后续查询、只读拒绝、刷新、并发、预算、切库、重连和同名文件替换均正常。崩溃和未处理异常均为 0，SQLite quick_check 为 ok，外键异常 0。本轮批量变更使用 100 条，2,000 条压力证据属于独立的查询压力报告。

## 契约与检查

- 桌面直接相关 43 项通过，覆盖主库升级、查询、行补丁及 SQL 与 AI Schema 对账；最终迁移三项另行复核，包含共享手写夹具、重复开库和中途失败整体回滚。
- 核心与队列 16 项通过，增加日期年月跨界、调用方时区及 JSON 字符转义边界。

- 桌面类型检查、Vite 生产构建、数据库与启动及插件进程边界检查通过；官网文档 69 项及发布响应 5 项通过。

不连接真实云端执行上传下载，不进行截图或视觉验收。副本验证不对原库执行测试写入；用户资料库在使用新代码打开时自动升级。
