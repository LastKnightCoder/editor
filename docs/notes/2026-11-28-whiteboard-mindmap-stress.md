# 原生导图工具压力验证

日期：2026-11-28（Asia/Shanghai）。本机 Windows、v24.4.1、13th Gen Intel(R) Core(TM) i7-13700KF、24 个逻辑处理器。使用隔离临时资料库、本地协作服务、真实 SQLite 与保存队列；临时数据已按夹具生命周期清理。工作区包含并行改动，产物按每阶段构建摘要标识，不作为已发布安装包的兼容承诺。

## 结果

- 100、1000、5000 总元素完成改字批次、原请求重试、磁盘与重开核对。总元素与带正文节点不是同一额度。
- 1024 个富文本根和 64 层边界分别验证；8 MiB 文档预算前最后接纳 8155439 字节，继续新增整批拒绝，原状态不变。
- 20 个种子、每种子50轮，2200 个混合批次、200 次故意成环拒绝、160 次重放、100 次重开。概要、外框、联系线、笔记与复制身份参与独立对账。
- 三方竞争尝试 20000 次 Agent 操作，接纳 18000 次；200 个竞争批次按前提冲突拒绝，1000 次用户写入保留，280 次重放保持幂等。
- 四个提交切点各10次 OS 级进程终止，共 40 次；日志事务、日志提交后、投影事务、回复前均核对持久状态及原请求恢复，另覆盖日志/投影存储失败与过期视图。
- 真实双画布、100ms 模拟 RTT，64 个离线批次、65 次原请求重试和16次对端编辑完成合并，双方无重复或覆盖、用户选区和撤销来源保持。
- 优化后同一文档 1000 轮持续编辑、100 次用户写入、21 次旧请求重放、5 次重开通过。

## 发现与修复

批量正文修改逐次调用整页投影和索引，导致大图批次耗时随元素数放大。改为复用已绑定页索引并读取原生身份，保留跨页、已删除和本批新建节点校验。另将硬预算错误从建议重读的通用拒绝改为带额度的 LIMIT_EXCEEDED / fix_arguments。两个针对性回归及类型检查通过。

| 总元素 | 优化前256次改字单次样本 | 优化后三次样本中位数 | 本机相对降幅 |
| ------ | ----------------------- | -------------------- | ------------ |
| 1000   | 6.848 s                 | 0.640 s              | 90.7%        |
| 5000   | 25.280 s                | 1.801 s              | 92.9%        |

比较保持同样元素数、正文目标与批次负载。基线和优化后构建摘要分别保留在报告中；这是小样本本机比较，不是长期P95或画布帧率保证。已有基线矩阵未重复执行，修复后另行完成负载比较、千轮持续编辑及作用域和错误反馈回归。

## 复现与产物

运行方式见 /docs/guides/development-quality.md 的“原生导图工具压力与恢复”。完整入口为 pnpm --filter desktop test:mindmap-stress；比较入口为 --phase=batch-profile。原始报告、分阶段日志、环境、构建SHA256和汇总在 output/whiteboard-mindmap-stress/full/，summary.json 明确区分基线与修复后验证。分位数采用下经验分位数。网络重连数字包含一次重放确认与核验，离线批次数字不包含远端确认，不能当作纯网络时延。
