# Markdown 只读首屏：采样、交接与业务验证

日期：2026-10-23。范围：只做真实只读首屏；不做解析隔离和视口级挂载。

## 结果

同一参考文档副本，在实际 Electron/Vite 开发窗口前后各运行三轮，期间没有并行测试或构建。

| 指标                         | 改动前中位数 | 改动后中位数 |
| ---------------------------- | -----------: | -----------: |
| 首屏提交并经过两帧的代理时间 |       11.81s |        4.14s |
| 完整编辑器就绪的窗口观测时间 |       18.40s |       17.77s |
| 内部完整 DOM 就绪标记加两帧  |       11.81s |       13.86s |

主要收益是把首屏展示提前约 7.7 秒；完整可编辑时间仍约 18 秒，不能据此宣称整篇编辑初始化大幅提速。完整挂载阶段本身没有加速，新增了先绘制首屏、后台准备与交接的调度。

旧版本首屏代理为 11.65/11.81/12.64 秒；最终版本为 4.14/4.19/4.05 秒。完整就绪窗口观测分别为 18.40/18.10/19.04 秒与 17.92/17.77/17.72 秒。开发环境、缓存、JIT、GC 和布局会波动；当前基线与之前单轮约 16.5 秒的记录采用不同轮次，不能混用计算收益。

最终仍完整挂载 587 张表格和 9778 个单元格；DOM 数从 105838 到 105841，仅增加三个容器。预览交接后卸载，不把全文改为视口渲染。另做 40 次原生输入/退格，中位数 56ms、P95 64ms、最大 104ms，文本节点字符数恢复为 142258。本轮未对稳态输入重新做前后成对对照，因此不把它与历史输入结果的差异归因于首屏策略。

## 为什么看见后仍需要等待

首屏出现时，完整 Markdown 已解析并进入原文件会话，保存和历史的事实源已经包含全文。等待的主要部分是全篇 React/DOM 创建、布局及 Slate 编辑所需的 DOM/选区映射，约十万个 DOM 的准备成本没有被移走。

首屏是独立的只读展示副本，只有少量块，没有完整文档的编辑绑定和历史。它不能作为可写正文保存，否则会把片段误当成全文。真实编辑器准备好后原位接管；这次没有增加部分文档编辑的双向同步机制。

源码入口仍可提前使用完整原文；因此“富文本尚未就绪”不会阻止源码的真实编辑和保存。

## 实现

- 保持原 `createMarkdownDocument`、Y.Doc、归一化缓存、UndoManager 与 `useTextFileSession` 为唯一写入路径，预览不传文档绑定或写入回调。
- 长文只选取数据预算内的前若干完整块；巨大首块超预算时沿用原来的完整编辑路径，不截断复杂表格等结构制造交接重排。短文直接挂载原编辑器。
- 先让只读首屏绘制，再通过 transition 准备完整编辑器。准备区使用不可交互和不可见的独立容器，裁切高度避免屏外准备内容撑出可滚动空白。
- 以真实编辑器首尾节点 DOM 已连接、完整节点数量和帧调度为就绪检查，不把 `onInit` 回调当成全文 DOM 已提交。
- 正文容器稳定，交接按当前可见逻辑块的纵向锚点恢复位置；交接阶段临时关闭浏览器滚动锚定，恢复后重新开启，后续图片等内容仍沿用正常锚定。
- 拖选、非折叠选择和预览内部控件聚焦时延后交接；操作结束后自动继续。普通交接不调用 focus 或 select，不覆盖外部焦点。
- 提前返回富文本的主动光标恢复等待真实编辑器就绪，并检查焦点所有者；其它输入框或其它 CodeMirror 后来获得的焦点不会被覆盖。
- 预览上下文的键盘撤销重做委托完整文件历史；正常保存热键保留原来的冒泡顺序，让块内编辑器先提交草稿。
- 预览代码块使用独立运行时 uuid，真实文档和源码映射保留原 uuid。预览卸载不会删除真实代码块控制器，也不修改未知节点或持久化字段。

现状与接线见 [桌面架构](/docs/architecture/desktop.md)，实现位于 [MarkdownRichSurface](/apps/desktop/src/features/markdown-window/markdown/MarkdownRichSurface.tsx)、[首屏选择与身份隔离](/apps/desktop/src/features/markdown-window/markdown/firstScreen.ts) 和 MarkdownFileView/useSourceMode。

## 验证

- 编辑器：134 个文件、789 项测试通过。
- 本地与协作：8 个文件、37 项测试通过。
- 桌面目录和 Markdown：12 个文件、45 项测试通过。
- 共 871 项相关回归。新增覆盖先展示后准备、预览阶段保存和导出仍用全文、关闭取消、选字/拖选、外部更新、逻辑锚点、外部焦点、源码提前编辑保存及历史、返回时焦点保护、预览键盘历史，以及代码控制器卸载隔离。
- 严格桌面类型检查、修改文件 ESLint、渲染端/主进程/preload 生产构建通过。代码控制器回归等待真实就绪条件，避免以固定短超时替代生命周期断言。
- 实际副本在预览期间保存，完整正文与投影一致；拖选直到准备完毕仍保持预览，解除后交接锚点偏差为 0px，外部输入焦点保持。
- 实际副本提前进入源码，完成编辑、全文保存、撤销重做、恢复原文及返回，焦点保护和全文投影一致。
- 普通正文另做 14 次全量转换与投影核对，以及模拟中文组合输入提交和撤销，均通过；副本恢复后文件字节相同。
- 最终实际文档的 55 个代码块控制器全部存在，值与真实文档一致。

不做截图或视觉验收，视觉交接由用户确认。上述几何和焦点验证属于行为核对。

## 计时口径

打开计时与业务核对分开运行。对照临时恢复 `954464605` 的 MarkdownFileView，采样后恢复最终源码并做字节校验；其余已落地的增量投影等优化保持。原文仅由应用和本机脚本处理，没有读取或输出正文。

首屏代理：观察真实首屏或完整正文的 DOM 出现、可见条件成立，再记录两次 requestAnimationFrame 后的时间。它是 DOM/帧代理，不是截图确认的首像素，也不是标准 FCP。新窗口的绝对时钟校验与导航起点相差约 1–2ms。

完整就绪窗口观测：完整正文就绪条件成立后，等待窗口命令往返和两帧，包含主线程、布局及渲染的进一步占用。内部 DOM 标记加两帧会更早出现，不能把它当作用户已能即时编辑的承诺；因此保留两组数值而不相加。

功能核对轮包含主动选择、源码编辑、保存和撤销，其约几十秒的持续时间不计入普通打开对比。测试用外部输入框固定定位且 focus 使用 preventScroll，排除测试设施自身改变页面滚动的影响。初期并行构建、原型或设施调整轮不进入最终结果。
