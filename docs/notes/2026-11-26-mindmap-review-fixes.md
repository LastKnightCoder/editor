# 思维导图审查问题修复与压力验证

验证日期：2026-11-26。范围为概要、外框、联系线及其结构操作和协作链路。原审查确认的四项问题均已修复，原始七项功能复现原样通过；新增回归和最终压力运行无失败。本报告为修复后的验证快照，未将先前的阶段性通过当作最终结论。

## 修复结果

| 原问题               | 当前行为与验证                                                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 外框独立操作并发覆盖 | 独立新增、不同标题、同框不同字段分别合并；三端同步、局部撤销、复制及二进制重开保留内容                           |
| 联系线反复遍历整棵树 | 按不可变画布树共享节点和可见祖先索引；新投影树在发布前直接参与端点查询，折叠和位移不沿用旧坐标                   |
| 不同区间概要完全重叠 | 空间索引按真实概要子树包围盒向外避让；覆盖左右方向、包含、交叠、相邻、长正文和嵌套概要，括号向避让后的正文补连线 |
| 删除画框残留联系线   | 按实际删除的当前容器子树收集节点，连同框内及跨框联系线一次删除、撤销和重做，其他联系线保留                       |

外框的数组投影、正文和导入导出入口继续使用原接口。协作适配器通过 `recordProperties` 将数组差异编译为 `patch_records`；成员及属性进入元素已有的稳定 data 根，初始数组只作基值。这样不在旧文档首次并发编辑时争抢新共享根，也不重建节点或正文身份。具体协议事实已沉淀在 `packages/collaboration/README.md`，画布集成事实在 `packages/whiteboard/docs/architecture.md`。

补验期间发现并修正了修复实现中的两处撤销边界：同一记录被两端删除时，单个可见性布尔值不能表达独立删除；新增被撤销后，另一端留下的属性也不能当作非法孤立载荷。最终实现每次删除保留独立标记，撤销一端不会解除另一端删除；隐藏成员的属性保留，重做时重新合成。原失败证据在 `record-undo-edge-before.log`，九项记录回归最终全部通过，没有删断言换绿。

对应实现：[记录协作](/packages/collaboration/src/whiteboard-data-records.ts)、[联系线索引](/packages/whiteboard/src/utils/mindRelation.ts)、[概要避让](/packages/whiteboard/src/utils/mind-layout/summary-collisions.ts)、[删除入口](/packages/whiteboard/src/utils/SelectionActionUtil.ts)。

## 长会话与三端压力

- 两端长会话：80 轮、720 次编辑、1440 次撤销/重做；每次状态变更均做内存 Yjs 增量对账，8 次二进制重开。最终编码 455842 字节。
- 三端外框：40 轮、440 次编辑、240 次撤销/重做；覆盖并发独立新增和改标题、同框重复删除、只撤销一端删除、删除期间改字、撤销恢复远端新字；每轮同步对账，4 次二进制重开。最终编码 130293 字节。

上述字节数包含历史，不能作为堆内存或泄漏读数。三端场景走真实模型接收校验，但传输是内存状态更新，没有模拟真实弱网。

每条线执行一次联系线状态查询和两个绑定点查询。plain 组使用普通对象计时；首轮包含建立索引，后两轮复用同一快照。tracked 组使用 getter 统计身份访问次数，插桩时间不当作产品耗时。两组均不包含 React、文本、DOM 和路径渲染。
