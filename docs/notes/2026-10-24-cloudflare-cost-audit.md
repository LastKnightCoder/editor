# Cloudflare 费用风险审查与限流、熔断方案

审查日期：2026-10-24。源码基线：`9fbcefaa2`。目标：每月账户总费用尽量控制在 **20 美元**；触发保护时先暂停统计、评论和上传，尽量保留下载。

这是一次性审查快照与待实施方案，可以随时删除；不作为当前架构事实或已部署配置。检查范围为本地源码、正式部署配置、现有运维说明和本地行为复现。没有读取生产秘密、压测公网、修改生产规则或部署代码。未登录 Cloudflare 控制台，因此线上 WAF、缓存、预算提醒、实际套餐、存量容量和部署漂移仍需核对，不能把源码缺项直接认定为控制台缺项。

## 2. 风险与代码证据

### P1：插件公开下载反复读取完整 ZIP、计算摘要，没有入口限流

- `/v1/releases/:id/download`、`/v2/releases/:id/download` 均可匿名调用，共用 [releases.ts](/apps/plugin-portal/api/releases.ts) 的 `downloadPublishedRelease`（405–431 行）。
- 每次执行 `RELEASES.get`、完整 `arrayBuffer`、SHA-256、发布可见性复核；带有效匿名身份时还会查询身份并尝试写下载统计。
- [index.ts](/apps/plugin-portal/api/index.ts) 第 87 行对所有响应设置 `no-store`，没有发现内部对象缓存或通用 limiter。伪造 Origin 白名单、Referer 或不发送 Origin 都不能替代鉴权。
- 成本维度为 Worker 请求/计算、R2 Class B、D1 操作与内存压力。R2 出站流量免费并不消除这些费用。

处理：最先对全部下载尝试限流；再检查可见性；内部以 `releaseId + sha256` 为缓存键缓存已验证的 ZIP。保留每次响应前的撤回/禁用检查与外层 `no-store`，不能直接长时间公开缓存整个响应、破坏即时撤回。缓存未命中时保留摘要验证；不要把未验证内容放入缓存。缓存命中仍产生 Worker 调用和可见性查询，需单独控制。统计失败或统计熔断只跳过计数，不影响合法下载。

### P1：Analytics 下载 limiter 仅限制计数，未保护 R2

[downloads.ts](/apps/analytics/api/downloads.ts) 第 25 行先执行 R2 HEAD；第 31–39 行让 HEAD、Range、预取和机器人直接跳转；第 43 行才检查 limiter，拒绝时仍返回 302。格式合法但不存在的文件也会在 limiter 之前访问 R2。

处理：拆成“访问保护”和“统计采样”两道控制。访问保护置于 R2 HEAD 前，覆盖 GET、HEAD、Range、预取、机器人及不存在对象；计数仍按原口径排除这些情况。用发布清单白名单或短期存在性缓存减少 HEAD，成功缓存 60 秒、否定缓存 10 秒，限制缓存键数量。不要让随机文件名造成无限缓存增长；变化在下次发布时失效。

### P1：匿名统计请求放大 D1 写入，缺少全站事件额度

基线 `9fbcefaa2` 的 `apps/analytics/api/ingest.ts` 第 22–36、111–138 行允许每批最多 50 个匿名事件。UUID、安装 ID 和事件属性均由客户端提供，攻击者可以不断换新 ID；CORS 与客户端内置秘密不能证明请求可信。

[0002 投影触发器](/apps/analytics/infra/migrations/0002_versioned_projections.sql) 会为每个新事件更新 installations、sessions、daily_activity、daily_events，加上 events 本身共 5 次表记录变更。本地 SQLite 复现：一个 50 事件批次产生 **250 次记录变更**；这不是云端精确计费行数，索引维护还会增加 D1 写入计数。当前 limiter 的单位是请求，未限制整个账户的事件、写入行和容量。

处理：保留 IP 粗限流，增加安装 ID 软限流和全站事件配额；安装 ID 只作分摊标识，不作为可信身份。有效事件写入前原子预留事件数；统计达到预算首先停止写入。记录真实 D1 `meta.rows_written/rows_read`，包含索引和清理消耗，不能用 HTTP 请求数估算数据库账单。

### P1：反馈只有日字节熔断，不能限制请求数、R2 操作数和长期增长

已有保护应保留：[app-feedback.ts](/apps/plugin-portal/api/app-feedback.ts) 第 17–18、183–209 行实现全站附件 **1GiB/UTC 日**的原子预扣；[契约](/apps/plugin-portal/contracts/index.ts) 第 388–398 行限制每身份每天 5 条、每 IP 每天 20 次、请求 12MiB、最多 5 个附件。

缺口：

- 第 218 行完整读取、解析表单后，第 231 行才检查额度。已到限额或重复 clientRequestId 的请求仍可反复触发表单解析。
- 字节额度没有全站反馈数或附件操作数维度。无附件反馈不消耗字节；本地复现四字节 PNG 头也能通过当前魔数检查，消耗 4 字节额度却触发一次 R2 PUT。单身份/IP 额度仍生效，但多个身份/IP 的全站操作量没有对应硬额度。
- 第 432–439 行仅清理额度计数，记录和附件永久保留。每天允许新增 1GiB 并不限制总存量或以后月份的存储费用。

处理：正文读取前先做请求额度和已熔断检查；解析后再原子预留实际附件字节、附件个数和反馈条数。保持现有幂等和失败回收语义；永久保留规则下用“存量达到容量预算就拒收新增附件”控制费用。**不建议直接给整个反馈桶添加自动删除生命周期规则**，它会改变既有保留规则并留下失效数据库引用。以后若改变保留规则，需要单独设计 D1/R2 一致回收。

### P2：匿名身份、评论、喜欢和 OAuth 能持续消耗 D1

- [visitors.ts](/apps/plugin-portal/api/visitors.ts) 第 14–43 行：匿名申请先写 D1 限额桶，再写 visitors；目前每 IP 每小时 60 个新身份，无全站日/月额度；拒绝请求也需要访问数据库。
- [community.ts](/apps/plugin-portal/api/community.ts) 第 21–115 行：评论每身份每天 20 条，但可以申请新身份；喜欢可反复切换，读取会统计喜欢数。身份长期保留，不能指望两天限额桶清理自动删除身份。
- [auth.ts](/apps/plugin-portal/api/auth.ts) 第 97–126 行：未登录用户只需发起 GitHub 登录就会插入 oauth_states；不需要完成 OAuth。当前 scheduled 清理未覆盖过期 OAuth 状态/会话。

处理：在数据库之前粗限流；申请身份按成功新签发计数，已有身份复用不能误计为新增。评论/喜欢按操作次数全站限额并先暂停；补充过期 OAuth 状态和会话的有界清理，超期记录不参与鉴权但也不能无限堆积。

### P2：上传和 CI 有单账户限额，仍缺少原子总量和计算预算

- [uploads.ts](/apps/plugin-portal/api/uploads.ts) 第 105–128 行是先 COUNT 后 INSERT，100 次/发布者/天的检查存在并发越界窗口，没有全站上传字节/次数额度。单票内容上传的状态抢占已存在，不能误报为同票可无限覆盖。
- [package.ts](/apps/plugin-portal/api/package.ts) 已限制压缩包 16MiB、展开 32MiB、512 条目，并验证摘要；这些边界有价值，但不能限制大量合法重试的总计算成本。
- [ci.ts](/apps/plugin-portal/api/ci.ts) 第 111–136 行验证有效 GitHub OIDC 后，在第 118–119 行读取/检查 ZIP，再在第 125–132 行检查仓库绑定。未绑定仓库的真实公开 tag 工作流也能先消耗解压与校验；重跑同一 tag 会在幂等判断前重复检查包。

处理：网页和 CI 共用发布者及全站上传原子额度；在读包前，根据已验证的 OIDC `repository_id` 检查是否有登记仓库并预留计算/字节预算。认证后仍需要尝试次数和并发额度，不能只限制成功上传。先限制同时处理的包数；同版本重试优先查幂等状态，再进行必要的大小/摘要验证，保持“同版本不同内容必须拒绝”。

### P2：公开目录可能扫描大量元数据，分页不等于工作量有界

[center.ts](/apps/plugin-portal/api/center.ts) 第 141–301 行：v2 搜索在应用层过滤，不匹配时会继续翻批次；首屏 facets 遍历全站插件及版本；[releases.ts](/apps/plugin-portal/api/releases.ts) 第 168–186 行的 v1 分类统计读取所有已发布旧格式版本。每次只返回 20/30 条并不意味着只读取这些记录。POST `/v2/catalog/query` 是读接口，熔断不能简单按“所有 POST 都是写操作”分类。

处理：限制查询频率、标准化参数、缓存热门目录与 facets；增加每请求最大扫描页数/工作量，达到时按协议返回可继续分页或明确拒绝。随机查询词不能无限制造新缓存键。中期再考虑预计算目录，不必为本次费用保护先重做数据库。

### P2：直接 R2 域名和 Pages 首页是独立入口

- [域名说明](/docs/guides/ops-taunote-domains.md)、[updater.ts](/apps/desktop/src-electron/main/modules/updater.ts) 和 [FfmpegService.ts](/apps/desktop/src-electron/main/utils/FfmpegService.ts) 说明客户端直接使用公开下载域名。限制 Analytics 不会限制直链；旧下载域名仍有消费者，不能删除。
- [官网中间件](/apps/website/functions/_middleware.ts) 每次首页 GET 都执行函数、改写 HTML 并返回 no-store；两份清单读取**已有 60 秒缓存**，不能误报为每次一定新增两次 R2 读取。随机查询参数仍可能增加首页函数调用。
- [发布脚本](/scripts/publish-desktop.mjs) 第 343–357 行给版本产物一年缓存，但 latest YAML 使用 no-cache。需要检查实际 CDN 缓存命中、清单短 TTL、查询参数和不存在路径策略；大文件不能假定一定可缓存。

处理：新旧公开下载域名同步 WAF/缓存策略，保留正常 HEAD、Range、更新和 FFmpeg/模板下载；r2.dev 若启用则关闭，其他绑定域名也要纳入。官网若继续要求访问时更新版本，则保留当前清单缓存并加入口保护；若接受随发版更新，可在发布流水线更新构建快照、移除首页 Function，直接减少函数调用。仅修改响应 Cache-Control 不能据此保证不再执行 Pages Function。

## 3. 建议限流与业务配额

以下为 **20 美元、小规模项目的保守起始值**，不是已部署设置，也没有从生产流量计算出来。上线前先核对正常峰值，尤其是公司/NAT 共用 IP、桌面一次更新多个插件，以及官方插件批量发版；身份限额与 IP 限额同时存在，不能用可自行申请的身份绕过 IP 保护。

| ------------------ | -------------------------------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 统计采集           | 保留 IP 120 批/分；安装 ID 12 批/分                            | 5 万 / 100 万个事件，按事件数预留                                          | 停止统计入库；返回 503 与 Retry-After                          |
| 新签发匿名身份     | IP 3 次/分、10 次/小时；已有身份另设宽松复用限流               | 500 / 1 万个新身份                                                         | 拒绝新签发，已有身份继续用于下载                               |
| 评论、喜欢写入     | 评论每身份 3 次/分；喜欢每身份 10 次/分；IP 再设较宽保护       | 评论 1000 / 1 万次；喜欢 5000 / 5 万次尝试；保留评论每身份 20 条/日        | 暂停社区写入，继续读取                                         |

两套 Worker 正式配置目前没有 `limits.cpu_ms`。建议 Analytics 先以 100ms、门户以 1000ms 为评估起点，在本地/预发布用最大合法批次和 16MiB ZIP 测量后确定；门户包含同步解压，不能直接照搬 50ms。具体限制见 [Wrangler 官方配置](https://developers.cloudflare.com/workers/wrangler/configuration/#limits)。这限制单次计算，不能限制总调用数；子请求上限需对照目录和有界清理任务的实际最大调用数另行确定。

## 4. 配额与熔断如何落地

### 最小实现：复用现有 D1 原子配额，独立监控汇总账户费用

优先沿用反馈已采用的原子条件写入方式：在两套服务各自的 D1 中增加操作额度记录，包含日窗口、真实账单周期、操作尝试数、事件数、对象数、字节数和状态；每日/每周期均受限制。**禁止 COUNT 后再 INSERT 来承担硬额度**。额度校验与预扣必须在单条条件写入或正确事务中完成，业务操作只能在所有需要的预留成功后继续。

- 高成本写入先预留；外部存储结果未知时保守计费，不盲目退款。幂等命中可返回已完成结果，但不能通过重复传入客户端请求 ID 免费执行新操作。
- 额度服务或绑定缺失时，高成本写入口拒绝放行。不要像当前可选 limiter 一样在生产缺配置时自动无限放行。
- 已关闭的操作组在内存短期缓存关闭状态，减少拒绝请求对 D1 的反复访问；WAF 负责最终在执行前阻断。不要让每次下载都新增一次配额数据库写入。
- 两个 D1 的配额是分别分配的业务额度；由独立监控器汇总账户用量，不能把它们误认为一个原子的账户美元账本。若以后需要跨 Worker 共享的严格实时额度，再引入一个 Durable Object 统一预留；目前不必给所有下载请求额外调用 DO。
- Workers Rate Limiting binding 是每 Cloudflare 位置、近似计数；即使使用同一个 namespace 和固定 global key，也不是全球严格配额。[官方一致性与严格限额说明](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/#locality)

### 费用状态机

先核对账户固定订阅费、存量存储和其他服务。若仅有 Workers Paid 固定费约 5 美元，可暂按 **固定费 5 + 按量控制目标 12 + 缓冲 3 = 20 美元** 分配；税费、其他订阅和其他项目应先扣除，不能继续使用这套金额假设。

| 本账单周期按量费用估算            | 状态和自动动作                                                                                                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3 美元                            | 预警；检查哪项资源增长最快                                                                                                                                                 |
| 6 美元，或任一日/周期写入配额耗尽 | 暂停统计采集、下载计数、评论/喜欢、新身份、反馈和上传；保留下载、版本/撤回状态、安全管理与有界清理                                                                         |

### 独立监控器与边缘阻断

建议在已有 ECS 上部署一个独立 Node 脚本，由 systemd timer 每分钟执行；本次只提出方案，未创建任务或修改服务器。不要依赖正被攻击的业务 Worker 才能发出熔断指令。

1. 读取 Workers 调用数、CPU 总用量、D1 读写行和存储、各桶 R2 Class A/B 与存储，按真实账单周期累计；汇总所有相关 Worker、Pages Functions、四个 R2 桶和账户内其他按量服务。若某项 API 没有账单级实时数据，明确估算来源及时间水位，不用 P50 CPU × 请求数冒充真实 CPU 总量。
2. 用当前价目表和账户共享免费额度估算费用，同时观察 1–5 分钟增长速度；数据不全时不能重置为零。计入配额本身、失败请求、下载统计、触发器、清理、监控和日志的消耗。R2 新增字节还需要估算剩余周期的存储费用。
3. 读取操作组状态，触发阈值后原子锁定，再幂等开启对应 WAF Block 规则。记录动作、理由、时间和指标水位；多次运行不能重复发提醒。监控连续三轮失败时先关闭新增高成本写入并告警，下载保持既有保护。
4. 两阶段生效：应用内拒绝立即降低下游消耗；WAF 传播后在 Worker 前阻断，减少 Worker 请求费用。监控和规则传播都有延迟，预留在途请求/缓存状态的缓冲。
5. 令牌只授予读取所需指标和修改指定 Zone 规则的权限，存服务器秘密配置，不授予发布、删桶或 R2 对象写权限。自定义规则数量和 Rate Limiting 表达式按实际套餐核对；Workers Paid 不等于域名 Pro 套餐。

预先分两类规则：非必要写入口（统计、身份签发、评论/喜欢、反馈、网页上传、CI 上传）与昂贵读入口（搜索、目录）。按**方法 + 路径 + 域名**分类，不能误伤 POST 形式的版本查询。下载另建保护规则；历史下载入口如位于另一 Zone，同步配置与授权。不要删除 Worker Route 充当熔断，以免退化为直接访问源站或改变路由语义。

对默认 Pages 域名和预览入口同样核对：仅在自定义域名加 WAF 不能据此证明 pages.dev 已受保护。独立于源码核对三个私有桶没有额外公共域名、公开开发地址或泄漏的 S3 凭据入口。

### 缓存与存量容量

- `tau-plugin-releases` 保持私有；ZIP 内部缓存、逐请求验证撤回，不能为了省费用直接公开整个桶。支持 Cache API 的既有自定义域名可继续使用，具体参考 [官方 R2 缓存示例](https://developers.cloudflare.com/r2/examples/cache-api/)。
- `tau-release` 新旧公开域名给带版本文件长 TTL，清单短 TTL；对无业务含义的查询参数规范化，保留必须的签名/语义字段。不要假设所有文件都可缓存：Free/Pro/Business 通常单文件上限 512MB，大安装包需要单独核查。[R2 与 CDN 缓存边界](https://developers.cloudflare.com/cache/interaction-cloudflare-products/r2/)
- 反馈维持永久保留，建议从当前实际存量开始设置增长预算，新增 512MiB/账单周期，并在分配的绝对存储预算处关闭附件接收。绝对预算必须纳入桶内已有对象和其他公开发布产物，不能直接假定当前存量为零。
- 待审桶继续按现有 D1 引用与状态回收，不给整个桶配置按年龄自动删除。每日最多回收 1000 个对象，监控积压；历史安装包清理也必须先检查更新清单、blockmap 和旧客户端消费者。
