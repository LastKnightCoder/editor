# 白板结构增量处理与验证

本轮把新建容器收纳、移动、解散等操作，从「复制完整文档再校验、重读完整快照」改成「已验证基线上的独立结构草稿、一次真实事务、按变化重建快照」。不变更存储格式、同步协议或同步 API，不引入 Worker。**数据与原子性验证通过，全面 60 FPS 目标仍未完成。**

## 设计与安全边界

`WhiteboardStructure` 保存不可变快照、节点和父级索引、保留文字根与历史顺序身份。`WhiteboardStructureDraft` 只复制受影响的兄弟列表，在写入前检查父子准入、锚点、环、64 层深度和删除后的剩余子节点；草稿失败不改变真实文档。

根级新建的无正文容器在只含新节点、必要页面与契约的小候选中复用原创建校验和扩展资源校验，既有正文不复制。契约、命令及字段绑定不向候选泄露可变引用。容量在完整基线上作保守上界证明，不能证明则交回原完整候选精确判断；19 条预算测试覆盖接近 8MiB 时合法操作的退回和真超限零写入。

整批通过后使用原 Yjs 写入逻辑，在一个事务执行；比较实际写集、删除区间、时钟、修订和根数量。观察者附加写入使证明失效并重读真实数据。外部事务、撤销和重做不复用旧快照；恢复区、正文、任意属性以及不支持的创建方式仍走完整路径。

快照只重建变化节点及祖先，既有正文、样式与绑定引用保留。几何快照即时更新，索引日志按节点合并，在下一次结构操作前补齐，避免持续拖动中重复维护。路径命令复用一个写时复制游标，按删除后的目标路径定位移动结果。画布缓存稳定叶投影和布局，绑定销毁时清理缓存。

当前架构事实与流程见[协作包说明](/packages/collaboration/README.md#白板纯数据模型)及[白板架构](/packages/whiteboard/docs/architecture.md#画框与嵌套分栏)。

## 性能对照

基线为 `588356444` 后、增量改造前的工作区；沿用同一生产构建夹具、1000×700 视口、原生 CDP 指针输入和 500ms 收尾采样。CPU 降速不模拟 GPU、磁盘和网络减速。每档基线一次，改后两次，另作 4× 两次复核；以下报告最大 rAF 帧间隔，单位 ms。每次操作、撤销、重做均另用独立副本接纳增量并完整校验、读取，对账不计入操作采样。

| 场景                                   | 1× 改前 → 改后   | 2× 改前 → 改后  | 4× 改前 → 最后复核 |
| -------------------------------------- | ---------------- | --------------- | ------------------ |
| 背景 1000 个矩形，新建框圈住其中 30 个 | 183.3 → 16.8     | 350 → 16.8      | 800 → 66.7–116.6   |
| 从含 1000 个子元素的框拖出一个         | 66.7 → 16.8      | 150 → 16.8      | 350 → 33.3–33.4    |
| 含 1000 个子元素的框适应内容           | 16.7 → 16.8      | 33.4 → 16.8     | 83.3 → 16.8–33.3   |
| 解散含 1000 个子元素的框               | 83.3 → 16.7–33.4 | 233.3 → 49.9–50 | 516.6 → 100–116.6  |

4× 最后复核中，模型结构提交累计耗时：新建约 12.8–27.6ms、拖出约 5.1–5.7ms、解散约 57.1–66.8ms。这些是阶段计时，不能与其他嵌套阶段直接相加。原完整模型快照读取被稳定修订上的缓存读取替代，记录中不再出现整份快照扫描的几十毫秒成本。按最大帧间隔的较差复核值估算，新建改善约 85%、拖出约 90%、解散约 77%；样本量有限，不代表任意白板的固定加速比例。

额外测试了 **1000 个元素全部同屏、一次完整圈入新框**：1× / 4× 均实际收纳 1000 个，单次撤销和重做及独立模型对账正确。模型提交约 19.6 / 75.1ms，最大帧间隔约 116.6 / 550ms。这组没有对应改前样本，不作加速比比较，也说明大量可见节点更换父层级的渲染重建仍是瓶颈。

4×、1000 个带文字元素的整框拖动回归中，P95 仍约 16.8ms，但出现 33–50ms 帧或位移间隔、约 40–53ms 输入延迟，严格门控失败；失败数据保留。不能把结构更新变快解释成全面达到 60 FPS。

## 复杂场景与边界验证

- 909 个混合元素、嵌套分栏、旧契约升级、正文、连线、排序、移入移出、整框移动、撤销重做与 Esc 取消：4× 下 20 轮、121 次真实拖放通过。每轮将实际 Yjs 状态交给独立模型完整接纳、校验和读取，与增量快照比较；同时核对稳定记录、文字根、恢复区和撤销后的屏幕坐标。
- 模型状态测试逐批对账跨页创建、收纳、移动、删除和几何修改，覆盖正文与文字字段保留、64 层及第 65 层拒绝、环、非法锚点、非法末项零写入、候选回调重入、观察者额外写入和近容量退回。
- 白板定向行为测试 159 条通过（另 3 条环境门控），模型/历史/预算与增量对账 44 条通过，真实 SQLite 与 WebSocket 回归 7 条通过；两个包的类型检查、白板边界与文档检查通过，lint 无错误。

压测中曾在左上角起点命中缩放控制，现场确认启动的是 `resizing`，归属未变化符合该操作。夹具改用远离控制柄的起点，并强制断言实际启动目标拖动；原失败现场保留，未通过放宽归属断言换绿。另发现其他并行基准共享固定浏览器会话导致会话关闭，运行器现按进程隔离会话，该次运行不作性能样本。

## 复现

```bash
node apps/desktop/scripts/bench-whiteboard-frame.mjs --rounds=2 --rates=1,2,4 --raf-input --settle-ms=500 --verify --only=create:create:1000,exit,fit,dissolve --output=/tmp/frame-structure.json
node apps/desktop/scripts/bench-whiteboard-frame.mjs --rounds=1 --rates=1,4 --dense --raf-input --settle-ms=500 --verify --only=create:create:1000 --output=/tmp/frame-dense.json
node apps/desktop/scripts/bench-whiteboard-frame.mjs --stress --stress-rate=4 --output=/tmp/frame-mixed.json
```
