编辑历史 · 三份设计稿

现有实现是一个 920×620 的模态弹窗（左列表 + 右详情）。三份设计稿沿用同一套 paper 主题 token、同一份演示数据（16 个版本 / 本机 + 协作者 + AI / 含撤销、恢复、已撤销状态），只在「历史出现的位置」与「交互方式」上给出三种不同主张，可单独打开体验，也可混合取用。

2026-11-19 · 一次性方案对比产物 · 基于当前工作区实现（HistoryDialog / DocumentHistoryEntry）重设计

设计稿 A2 · 当前推荐

页边注 · 一张纸

针对 A 的反馈迭代：不再是「正文 + 侧栏」拼接，历史是同一张纸右缘的页边注——选中条目后虚线连接线从节点弯到正文标注块、两端序号一一对应；明细与操作收进条目自身展开区；↑/↓ 键在版本间移动；工具栏图标可收起页边注，纸张回宽只剩纯正文。

一体感
同底色同阴影同留白，边注与正文一体
操作
撤销/恢复/全文/确认都在条目展开区
联动
连接线 + 序号圆点，正文标注零翻译
代价
纸张加宽占空间；实现多一层连线层
设计稿 A

侧栏时间轴 · 正文联动

历史是正文的一部分，不是弹窗：右侧常驻面板 + 按天分组时间轴，选中条目后该次改动直接标注在左侧正文原位（绿增 / 红删 / 蓝移），边写边查互不打断。

位置
右侧 dock 面板（可开关）
入口
工具栏时钟图标常驻
适合
高频回看、写作中随手查
代价
占横向空间，小屏需降级
设计稿 B

版本工作台

保留模态的专注，重做信息架构：作者筛选、按天分组、改动量摘要、已撤销置灰、恢复前与当前正文逐块对照，底部常驻「历史只增不删」的教育文案——档案室式回溯。

位置
居中模态（沿用现有形态）
入口
不变（更多菜单 / 按钮）
适合
长历史、多成员协作场景
代价
打断写作；迁移成本最低
设计稿 C

沉浸式时间旅行

不再有独立面板：正文区接管为只读历史视图，顶部悬浮时间胶囊（节点颜色=作者，←/→ 键穿梭），diff inline 落在正文上——绿=恢复后会回来，红删除线=恢复后会失去。

位置
正文区本身（无面板）
入口
正文右上时钟 → 进入只读模式
适合
“看看文档当时长什么样”
代价
与写作互斥；筛选能力弱

三稿共通的约束（来自现状代码）

  • 数据模型不变：DocumentHistoryEntry{ sequence, actorId, actorName, time, kind: baseline|edit|undo|restore, target, source }，三稿的徽章、摘要、撤銷/恢复文案均由这些字段推导。
  • 动作语义不变：撤销=回退单次编辑（生成逆操作），恢复=整篇回到该版本；两者都会追加新历史记录，历史只增不删——A/B/C 都在确认文案里向用户传达这一点。
  • 权限模型不变：拥有者可恢复+撤销任意；成员只能撤销自己的编辑；已撤销与 baseline 条目不可再撤销。
  • 分页不变：每页 50 条、sequence 游标；三稿均保留「加载更早记录」。
  • 视觉全部取自 paper 主题 token（packages/themes/src/tokens.css），未引入新颜色；diff 删除沿用 danger，新增/恢复方向引入 ok、移动沿用 info。
