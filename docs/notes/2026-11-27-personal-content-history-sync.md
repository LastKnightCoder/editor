# 个人正文历史跨设备验证

验证对象是未开启文章共享的资料库。测试使用临时 SQLite 文件、实际 Yjs 正文模型、桌面存储代码和移动 Rust 存储代码。旧版桌面对照使用提交 `6cdad9870`。设备模拟器、应用商店安装包和线上个人资料库不在本次验证范围内。

| 场景                                          | 验收结果                                                                                                                       |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 两台桌面各自保存 160 笔独立编辑，再交换资料库 | 逐版还原的文字与独立生成的期望值一致。两边相同的本地序号分别指回各自基线。                                                     |
| 导入中断、磁盘事务失败、重复同步及重开        | 模拟一次首次导入失败，再做 24 轮旧库替换。每轮在指定版本制造写入失败，验证事务回滚后重试、随机版本正文及 SQLite 完整性和外键。 |
| 旧备份在一个未固定的编辑组中间分叉            | 从旧副本继续编辑后，可以分别还原原来的完整编辑组和旧副本的后续版本。超过 512 KiB 的中文和表情文本跨分片还原一致。              |
| 撤销与重做                                    | 按版本身份核对撤销目标，重送和切库后的旧预览无法误选另一版本；撤销后再次撤销该操作可以恢复文字。                               |
| 桌面 → 手机存储 → 旧桌面备份 → 新桌面         | 手机读取桌面版本并写入真实 Yjs 增量；旧版桌面执行开库迁移、写入和 SQLite 备份后，新桌面仍能还原两端文字。                      |
| 手机在写入过程中需要新的检查点                | 同一笔写入携带正确的冻结状态重试，新的输入进入下一版本。独立验证持久预算跨重开、满 1 MiB、满 128 条及已固定记录的合并竞争。    |
| 两窗口资料库换库回归                          | 100 轮换库、16 个并发读者、6,400 次读取、100 次写入，200 次过期请求被拒绝。                                                    |
| 正文历史模型                                  | 2,000 笔连续编辑的 80 个固定版本跨八次数据库重开核对；另有四个编辑者在千段正文上交错提交并回放。                               |

混合版本的边界沿用整库同步：旧客户端可以继续写正文并携带已下载的附加表。只有那台旧设备持有的编辑历史，在该设备升级后首次上传时补入。强制上传一份从未拉取新历史的旧库会替换云端文件，能够补回的版本取决于仍持有这些记录的设备或备份。

### 重跑两端交换

在仓库根目录设置 `TAU_HISTORY_EXCHANGE` 为一个新的临时目录。先以 `TAU_HISTORY_SYNC_STRESS=1` 运行 desktop 的 `src-electron/main/modules/content-runtime/library-history.stress.test.ts`，生成库文件与 Yjs 输入。然后执行 `cargo test --manifest-path apps/mobile/src-tauri/Cargo.toml --lib history_archive::tests -- --include-ignored`。最后将 `TAU_HISTORY_READ_MOBILE` 设置为返回文件所在目录，单跑上述桌面测试中的「手机导出的版本」。跨端命令必须共享同一批夹具。
