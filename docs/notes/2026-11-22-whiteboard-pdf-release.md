# PDF 卡松手延迟

Apple M3 Pro，短测使用 Chromium 153，桌面验收使用 Electron 43.1.1。两个指标都从真实 `pointerup` 的事件时间戳量到渲染进程下一次 `requestAnimationFrame`。桌面基线取自[上一次相同混合场景的验收](2026-11-21-whiteboard-interaction-acceptance.md)。

| 场景                            |                   修复前 |              交付版本 |
| ------------------------------- | -----------------------: | --------------------: |
| 短测，三次正式松手              | 137.4 / 131.5 / 137.2 ms | 16.3 / 15.7 / 15.4 ms |
| 短测中位数                      |                 137.2 ms |               15.7 ms |
| 桌面混合场景，拖动 PDF 卡后松手 |                   173 ms |                 17 ms |

短测连同构建和打开临时页面用时 4.5 秒。短测采用相同文档模型、Yjs 绑定、实际文档卡手势和解码后的 PDF 位图，省去了桌面服务启动和磁盘保存。计时过程中模型确实发生了位置变化。修复前完整模型提交的三轮中位数为 107.8 ms，内含候选复制 52.2 ms 和校验 53.6 ms，后者包含约 31 ms 的编码预算核算。提交之后，识别选中卡片支持的元素类型又触发了整板快照读取，中位数为 11.6 ms。

本机单张顶层文档卡复用经过校验的平移基线，保留撤销与正常 Yjs 增量。几何已在拖动末帧显示时只发布现有投影；获取元素类型时直接按 ID 查可见记录。其他写入、恢复与容量临界情况保留完整校验。快速路径在本次短测的同步模型提交耗时为 0.1–0.3 ms。

桌面混合场景包含 480 个图形、240 条绑定连线、240 个富文本框和 12 张已解码的真实 PDF 卡。生产构建加验收用时 22.2 秒。松手后另采样半秒，最长后续帧间隔为 10 ms。三轮画布平移的位置间隔 P95 为 9.1–9.7 ms，跨区滚动、定点缩放、卡片拖动均通过。独立租约重新读取已保存模型后，卡片位置与屏幕反算位置误差小于一个画布单位。自动化检查往返用时 517 ms，包含驱动等待，不能当作首帧或单独的落库耗时。

预算边界测试覆盖非法几何零写入、相邻上限的精确预检、空富文本根导致基线失效、撤销、同步和观察者附加写入。结果来自工作区的生产构建与隔离资料库。[短测和完整验收命令](/packages/whiteboard/src/utils/benchmarks/README.md)
