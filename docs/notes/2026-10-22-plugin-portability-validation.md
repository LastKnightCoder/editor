### 一个 SDK、一套模板、同一个插件身份

作者继续从 `@tau/plugins` 获取领域能力，从 `@tau/ui` 获取 UI，不另发“移动版 SDK”。SDK 区分公共能力、已适配的平台能力和桌面专属能力：生命周期、命令、私有存储、页面和基础编辑器契约尽量共用；业务数据/媒体等能力有实际宿主实现后才开放；Node、Shell 和外部程序保留桌面专属。能力声明决定能否安装/启用，不能伪造成功结果。现有宿主未提供环境时明确返回 unknown 与空能力，不让插件误判运行平台。

同一个模板仓库维护统一构建/发布流程，提供跨端页面、编辑器扩展、桌面增强等示例或选项；无需现在另造脚手架产品。普通插件默认使用公共能力，桌面增强需显式声明和检测。作者的公共业务逻辑、数据模型与节点类型不复制，界面差异大时可在同一个项目中拆桌面/移动组件。

一个插件 ID 对应同一个插件中心身份、作者与社区信息。当前最小验证采用同一版本同一 JS 包，证明可共用；这不是整个生态永久禁止平台入口/产物差异的裁决。未来 Node 后台与移动入口共存有真实消费者后，再定义多入口、产物与审核身份，不在本轮强推新格式。

### 页面和入口为什么分开

页面描述内容、参数与实例身份；入口描述用户如何发现和打开页面。任务管理可以有一个功能入口，却有列表、任务详情、设置等多个页面，因此注册页面不能自动增加侧栏条目。

`context.pages.register` 保持跨端页面语义；新语义入口 `context.navigation.registerEntry` 只引用本插件有效页面，由桌面映射侧栏、移动映射“我的 → 插件功能”。作者不操作宿主内部路由或“我的页”的实现。旧 `sidebar` 的分组、拖拽和子项仍是桌面专属，不能默默映射为移动已实现。

页面内部布局允许变化：桌面可列表/详情并排，手机可逐页进入；数据操作、任务 ID、参数与保存语义共用。优先响应式布局，差异大才分端视图。后续如果需要首页快捷入口，新增语义位置，首版不开放任意 UI 插入点。

### 环境与能力如何表达

SDK 由宿主注入平台（desktop/android/ios）、界面形态（compact/wide）、输入能力（touch/finePointer）和能力集合。平台不等于屏幕大小：iPad、外接键盘或触摸桌面不能只靠一个 isMobile 判断所有行为。插件不自行解析 User-Agent；适配宿主可以集中识别运行容器。

生命周期通过 `context.environment` 读取；React 渲染组件通过 `usePluginEnvironment()` 读取对应渲染宿主的环境。静态编辑器扩展、只读预览和博客不一定经过 activate，所以不能把激活 context 缓存在模块全局供 render 使用。能力表示 API 可用性，数据授权与可信执行边界是另外两件事。

本轮先实现会话环境快照；窗口尺寸/输入方式动态变化订阅属于后续完整宿主能力，不把静态快照宣称为已支持响应式环境事件。

### 编辑器的三层责任

| 层                                               | 共用原则                         | 责任       |
| ------------------------------------------------ | -------------------------------- | ---------- |
| 数据模型、codec、校验、业务动作                  | 同一节点类型与结构               | 插件作者   |
| 选中框、拖拽把手、块菜单、插入入口、标准源码容器 | 同一动作语义，不同平台交互       | 编辑器宿主 |
| 插件内部复杂操作界面                             | 可分桌面和移动组件，操作同一数据 | 插件作者   |

例如乐谱块声明编辑源码、导出、移动等能力，桌面宿主可用悬浮工具条/右键/拖拽把手，移动宿主用触摸按钮/底部菜单/上下移动。未来替换移动拖拽实现时，应主要改宿主，不能要求所有插件各写一遍长按与菜单。

图库排序、绘图工具面板等插件特有复杂交互允许作者分端实现；不得因此创建 abc-desktop/abc-mobile 两种正文节点。优先将 SourceBlockEditor、BlockToolbar 等标准组件做宿主适配，特殊交互才由插件接管。

### 支持状态不只一个布尔值

未来移动兼容声明至少区分“完整支持（插入/显示/编辑）”“只读展示”“不支持但保留原节点”。未适配编辑的插件不应因能渲染就获得插入/修改入口，也不能因为没用 Node 就自动被标为移动兼容。状态需要作者明确声明并验证；本轮不修改生产包格式，仅在验证证据中分别标记。

本轮计数器验证相同页面契约与不同入口；ABC 验证相同节点/codec/渲染器与不同源码交互。标准拖拽、复杂移动菜单、所有旧插件兼容、生产中心和商店审核不因这两个样本通过而自动完成。
