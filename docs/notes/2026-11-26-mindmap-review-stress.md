# 思维导图改动审查与压力验证

审查日期：2026-11-26。对象：当前未提交的思维导图第 1、2 批实现，以及共用的白板协作模型、投影和操作编译链路。数据库等并行改动不在本次审查范围。修复结论：本次确认的五项缺陷及两项直接相关的测试漂移均已修复。白板包仍有七项先前已复现的范围外失败，不能据此宣称全包通过。以下保留修复前的审查证据，修复与复验结果见文末。

## 修复前复现的问题（均已修复）

### P1：协作文档中的 Shift+Tab 升级无法提交

位置：`packages/whiteboard/src/components/MindNode/hooks/useMindNodeKeyboardNavigation.ts` 的 `handlePromote` / `commitRoot`，以及 `MindUtil.promote`。

本机模式的键盘验证能通过，但协作模式中，升级先构造新树再走 `BoardUtil.diffNode`。这个 diff 只在同一父节点内识别移动，跨父级的 `leaf0` 被编译成先 `insert_node` 再 `remove_node`，复用原节点身份。真实 `WhiteboardModel` 拒绝创建已有 ID，抛出“白板身份不能复用”，升级失败。

在独立的补充协作场景中，前两轮布局与复制以及第三轮 transfer 子树导入成功，第四轮第一次升级即失败，日志记录了原节点 `leaf0` 的 insert/remove 对。进一步移除前置操作，只对初始导图升级 `leaf0`，仍在第 0 轮报同一错误。建议用保留身份的显式 `move_node` 表达升级，布局变化只生成 patch；不能给移动节点换 ID 绕过校验，否则会破坏正文、引用和协作身份。

### P1：组织图拖拽预览与实际插入位置不一致

位置：`packages/whiteboard/src/plugins/MindPlugin.tsx:1160`。

候选预览经 `findNearestMindNode` 传入当前布局，松手时 `commitDrop` 重新调用 `calculateInsertPosition` 却未传布局，使用默认双向思维导图的纵向排序与方向分组。组织图的主分支应横向排序，逻辑图和树状图也应把两侧方向的孩子作为同一组。

复现：组织图根下有 `[a,b,c,drag]`，把 `drag` 放到 `b` 左边、与 `b` 中心同高。预览计算插入下标为 1；调用真实 `commitDrop` 后仍为 `[a,b,c,drag]`，预期 `[a,drag,b,c]`。复现运行断言失败。建议在松手计算时传入 `getMindLayout(targetRoot)`，并覆盖组织图横排和单向布局混合方向的排序契约。

### P1：2000 行以内的深层列表可导致导入栈溢出

位置：`packages/whiteboard/src/utils/mind-markdown.ts` 的 `markdownToOutline`，及 `packages/whiteboard/src/utils/MindUtil.ts:958` 的 `nodesFromOutline`。

解析仅限制总行数为 2000，没有限制嵌套深度。2000 行、每行比前一行多缩进一个空格的有效列表，会形成 2000 层树；调用实际节点构造和布局抛出 `RangeError: Maximum call stack size exceeded`。菜单路径的 `outlineDepth` 和后续递归也没有深度保护。该异常发生在正常的文档校验之前，无法得到可理解的拒绝提示。

建议在构建递归节点前检查深度，对协作文档按现有 64 层预算及目标父节点层级判断；超深输入明确拒绝并保留原文。不要只增加调用栈，也不要静默截断子树。

### P2：特殊未知布局值不能按承诺回落

位置：`packages/whiteboard/src/utils/mind-layout/index.ts:20`。

`value in LAYOUTS` 包含原型链。`__proto__`、`constructor`、`toString` 被当作已登记布局，随后读取 `layout.sides.length` 抛出 TypeError。普通未知值 `fishbone-v9` 的现有测试无法覆盖此边界。导入或协作文档携带这些字符串时可能无法打开。建议使用自有属性判断或无原型注册表。

### P2：Markdown 导出会删除正文中的反引号

位置：`packages/whiteboard/src/utils/mind-markdown.ts:36`。

行内代码导出调用 ``leaf.text.replace(/`/g, "")``。正文为 `a` + 反引号 + `b` 的代码叶子，导出再导入变成 `ab`，文字内容不可逆丢失。建议按正文中最长连续反引号选择更长的 Markdown 分隔符，同时让解析器识别这种代码跨度；round-trip 应保住原文。

## 修复与复验

- 升级节点以显式 `move_node` 提交，先在副本中应用移动，再对同一结构生成属性补丁；移动、重排与选区更新保持单批提交。新增四布局的真实快捷键协作测试，断言节点记录、正文绑定身份、单步撤销重做和远端一致。
- 拖拽松手计算插入位置时传入目标导图布局，补验组织图横排及逻辑图、树状图的混合方向兄弟排序。
- 大纲深度测量改为迭代；解析及节点构造前检查深度，目标粘贴按包含画框在内的实际路径扣除已用层级。超限提示并拒绝整次操作，文档和历史不变；补验画框内外的最后可用层及 2000 层输入。
- 布局注册表只判断自有属性；Markdown 行内代码使用匹配长度的反引号分隔符，保留反引号及首尾空格。
- 创建测试不再与旧构造整对象对比，改为验证已保存布局偏好会影响新导图；创建交互、清空选区及单步撤销的原有行为验证保留。官网使用文档与包内架构事实同步更新。
