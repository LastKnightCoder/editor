# 长文档 React、表格与打开性能：实现和实机采样

日期：2026-10-23。目标：减少实际 Markdown 正文编辑的 React 提交与表格更新成本，同时降低长文档打开等待，保持编辑、历史、源码和文件同步语义。

已有长文渲染、目录与增量投影成果先保存为提交 `99edc8a95`。本报告描述其后的改动与验证。

## 结果

使用相同参考文档的固定本地副本，在实际 Electron 窗口完成前后对比。正文输入、表格内输入各执行 20 组“输入 x → 退格”，每轮各 40 个独立交互。最终实现经过完整回归后重新采样，采样期间没有并行运行测试、类型检查或构建。

| 指标                         |      优化前 |  最终实现 |
| ---------------------------- | ----------: | --------: |
| 正文输入中位延迟             |       128ms |      72ms |
| 正文输入 P95 / 最大值        | 168 / 176ms | 80 / 96ms |
| 格内输入中位延迟             |       144ms |      64ms |
| 格内输入 P95 / 最大值        | 176 / 200ms | 80 / 96ms |
| 正文输入 ScriptDuration 累计 |      4587ms |    2157ms |
| 格内输入 ScriptDuration 累计 |      4657ms |    2020ms |
| 新窗口正文就绪               |      23.24s |    16.46s |
| 页面资源加载完成             |       0.87s |     0.84s |

两轮输入都保持 24 个 chunk、142258 个文本节点字符；文档为 2379 个顶层块、587 张表格、9778 个单元格。该字符统计不包含代码等属性，不等同于产品字数。

打开等待改善约 6.8 秒，仍然偏长；它没有下降到交互级延迟。表格和单元格均完整挂载，没有通过少显示正文取得收益。隐藏源码编辑器从首次打开时的 1 个变为 0 个，首次进入源码后才创建。

## 定位与实现

### 表格选区的广播提交

原 Table 使用 `useSlateSelection()`，每次选区变化都会让所有表格组件参与提交，即使输入发生在表外。这份文档的 587 张表格因此承担了无关渲染、React 元素创建、菜单与布局 effect 的成本。

Table 改为 `useSlateSelector()`，只返回属于本表的格选区矩形及行/列类型；值相同不提交。归属用当前 Slate 节点身份判断，不依赖尚未更新的渲染路径索引。内容、对齐、悬停、菜单和拖动依旧通过原来的状态更新，动作执行时仍实时取路径。

新增 80 张表格的 Profiler 回归：表外输入与光标移动时，无关表格提交数由 80 降为 0；跨表格选区只更新离开和进入的表格。既有表格复制、粘贴、格式、行列操作、拖动、只读与历史测试继续通过。

实际正文输入 CPU profile 中，Table 退出主要业务热点。React `commitRoot` 的包含采样时间约 2209→1421ms，格内输入约 2357→1336ms。采样时间反映调用栈归属，不能与子阶段相加，也不能当作每次交互的精确提交耗时。

### 初次规范化的全文脏路径变换

打开 profile 中，页面资源加载不到一秒，后续主要成本包含 Markdown GFM 解析、Slate 规范化、React 首次挂载和布局。Slate 初始规范化约产生 1278 次插入、1277 次属性修改与 2 次合并；大量插入是在行内元素两侧补空文本落点，每次结构操作又变换全文脏路径。

最初尝试在导入写入 Yjs 前补落点，实机没有获得相应收益。原因是 Yjs 不保存零长度文本，转换回来时这些落点会消失。因此最终准备发生在 **Yjs 转回 Slate 后、完整规范化前**。

本地文档新增可选 `prepareInitialContent(content, editor)`，Markdown 文件用已装配编辑器的实际 `isInline` / `isVoid` schema 补齐已声明行内节点的空文本落点。未知节点和 void 子树保持原样；不处理混杂非法子节点，交回原规范化修复。该准备仅改变编辑器独占投影，不写 Y.Doc，不新增撤销步骤；随后仍执行完整 Slate 规范化。正常结束或抛错都恢复原 `normalize` 方法，未配置选项时保持原连接路径。

实际文档同进程差分：原规范化 6851ms；准备约 17.2ms，后续完整规范化约 83.6ms，最终节点树深比较一致。实际打开 profile 中，本地连接的包含采样时间约 6044→135ms，规范化约 6094→172ms。后者还包含连接之外的正常规范化调用，并非独立阶段总和。

### 源码首次挂载与布局生命周期

源码编辑器首次进入时才挂载，此后保留同一个实例；双向光标映射、共享撤销、错误原文兜底及进入源码时同步最新正文继续保留。

实际副本往返发现：大纲列原来通过不同 JSX 分支排布，源码标题统计、标题删除恢复或宽度变化会重挂编辑器；旧 CodeMirror 清理还可能覆盖新实例引用，使撤销后源码显示未同步。最终使用同一组容器切换布局类，编辑器位置固定；CodeMirror 在同一个 effect 中配对登记和注销实例，回调变化后重新登记当前实例。

这部分增加回归，验证有标题文档的大纲开合、源码标题变化、撤销、首次光标映射和实例登记回调更换，正文与源码实例均保留。

## 采样口径与限制

参考文件只由本机应用与脚本处理，没有读取或输出正文，没有截图或视觉走查。原文件复制为固定源，每轮打开临时副本窗口；正文和格内输入在相同位置、同样键序列和等待间隔进行。

输入对照只恢复旧 Table 选区订阅实现，其余打开优化一致，减少无关变量。采样完成已恢复最终 Table 源码并做字节校验。Event Timing 按 interactionId 合并最大持续时间，durationThreshold 为 16ms；表中是固定 40 次交互的分布，不是标准页面 INP。窗口打开从导航开始，到完整正文挂载并经过两帧为止，包含解析、初始化、渲染与布局。

这是开发版 Electron/Vite 实机结果，不是正式安装包的绝对耗时承诺。跨轮渲染进程、JIT、GC、系统内存与后台状态会波动；最终另一轮打开约 17.01 秒，输入中位数约 64–72ms。有构建并发或功能修复前的中间采样不作为最终数据。

## 剩余成本与方案取舍

初次打开仍包含约两秒的 Markdown GFM 解析、大量 React 节点挂载和布局；编辑时剩余主要业务热点包括光标/DOM 选区同步、快照通知和未声明插件的 Markdown 转换。

| 后续方向                                   | 收益与成本                                                                                                                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 将解析移到隔离执行环境，按修订接收结果     | 可释放界面线程；需要保留插件上下文、未知数据及迟到结果仲裁，不能直接把现有同步解析塞进任意 worker。不能消除 React 首挂载成本。                                           |
| 先显示真实正文的只读首屏，再准备完整编辑器 | 可缩短“看见正文”的等待，但编辑就绪时间仍存在；需要明确只读阶段并保持焦点、滚动与关闭保存边界。                                                                           |
| 视口级挂载                                 | 可显著减少首次 React/DOM 数量；需要系统处理跨块选区、查找、拖动、滚动锚点、代码控制器和可访问性，实施及回归成本最高。现有 content-visibility 只省绘制，不省 React 挂载。 |

当前实现保留全文挂载与正常校验，没有引入视口卸载或只读占位阶段。
