# 白板拖动性能专项

原始问题来自桌面 0.65.2。11 月 21 日 21:34 的性能快照记录到 8–15 FPS 的连续掉帧及一次 704 ms 的 SVG 松手反馈。该快照没有区分每次拖动的手势、可见元素和绘制耗时。本次使用独立资料库与合成场景复现，对比基线为 `581b7c13b`。这些结果描述当前源码与基线的差异。

## 真实输入与屏幕更新

Apple M3 Pro，Chromium 153.0.8010.12，独立示例生产构建，窗口 1,000 × 700 CSS 像素。每个场景生成新页面，输入 48 步，每个版本预热一轮、正式三轮。表中耗时为一整段输入的渲染主线程任务耗时中位数。P95 帧间隔先按轮计算再取中位数。更新次数由 SVG 的位移与视图盒变更计数。缩放有固定步长限频，拖元素时视口保持原位。

| 场景                         | 主线程耗时，修复前 → 后 | P95 帧间隔，修复前 → 后 | 视口更新次数，修复前 → 后 |
| ---------------------------- | ----------------------: | ----------------------: | ------------------------: |
| 100 个图形，右键平移         |            140 → 153 ms |          16.8 → 16.8 ms |                   22 → 48 |
| 5,000 个图形，右键平移       |            223 → 181 ms |          16.7 → 16.8 ms |                   23 → 48 |
| 1,000 个富文本元素，右键平移 |            762 → 670 ms |          33.3 → 16.8 ms |                   21 → 48 |
| 5,000 个图形，滚轮平移       |            501 → 249 ms |          16.8 → 16.8 ms |                   48 → 48 |
| 1,000 个图形，定点缩放       |            191 → 164 ms |          16.8 → 16.8 ms |                   15 → 15 |
| 1,000 个图形，拖动元素       |            233 → 167 ms |          16.8 → 16.7 ms |                     0 → 0 |

小白板右键场景的总任务耗时增加 13 ms，同时画布更新次数从 22 增到 48。六个场景均检查了最终操作结果，以及实际屏幕变换矩阵与白板逻辑视口的对应关系。所有元素按固定网格分布，表中为整板元素数，同时在屏的元素取决于视口。

初次复现时同机负载较高，富文本场景三轮 P95 的中位数达到 116.7 ms。在仅修复订阅与元素扫描的中间版本，一次 48 步拖动的 Chromium 追踪仍记录到 49 次布局、109 次浏览器命中测试。后者累计约 883 ms，布局累计约 341 ms，事件可能嵌套。将格内位移移到合成层后，这批复测的富文本 P95 中位数为 16.8 ms。系统负载没有固定，因此以同口径复跑和实际更新次数共同判断收益。

## 受限 CPU 与桌面 PDF

Chromium 对渲染主线程启用 4 倍 CPU 降速，重复 1,000 个富文本、48 步右键拖动。三轮中位主线程耗时由 5,611 降至 2,632 ms，P95 帧间隔由 150.1 降至 66.7 ms，每轮 ≥50 ms 的帧从 48 降至 39。两版均完成全部位移。在这个压力档仍能感觉到卡顿。

Electron 43.1.1 的隔离窗口打开真实桌面白板与 12 张已解码的 PDF 卡，引用同一份现场生成的单页 PDF。两个渲染构建共用同一主进程、资料库和窗口，按「基线、修复、修复、基线」顺序加载。每次预热一次，采集三次 48 步拖动，两版各有六次正式样本。

| 指标                       |         修复前 |         修复后 |
| -------------------------- | -------------: | -------------: |
| 一次拖动的主线程耗时中位数 |         276 ms |         188 ms |
| 每轮 P95 帧间隔的中位数    |        69.6 ms |        55.2 ms |
| 每轮 ≥50 ms 帧数的中位数   |           19.5 |              3 |
| 两次进入窗口后的空闲 P95   | 38.3 / 45.4 ms | 38.9 / 45.4 ms |

这一组桌面复测的空闲帧间隔本身也偏长。其他独立启动中，空闲 P95 低到约 9 ms，此时旧版 48 步输入只有 8 次画布位移通知，并会丢失松手前最后一截位移。修复版在同一高刷新环境可以抵达完整的 120 像素落点。最终交付构建单独复核时，空闲 P95 为 9.2 ms，每轮 48 步实测位移通知的中位数为 47 次，三轮均完整移动 120 像素。PDF 场景验证了加载后的平移，首次解码大文件、多份不同 PDF 或用户原件的表现需要另外测量。

## 实现与行为边界

- 右键拖动绕过通用指针的 25 ms 限速，移除手势内部第二层 30 ms 限速。松手时使用最终指针坐标，微小移动仍能打开右键菜单。
- 画布按 100 屏幕像素分格，SVG 为格内移动预留绘制区域，用 CSS 位移跟随逻辑视口。跨格、缩放或尺寸变化时更新视图盒。导出保持精确的目标视口，鼠标命中、坐标换算和协作使用逻辑视口。
- 画布保持移动状态上下文的引用稳定，桌面文档卡单独订阅缩放。独自使用和只有远端光标时跳过用于对齐远端选框的全板索引。
- 三个图层独立保留可见集合，空箭头层不会清除文档卡的退出缓冲。嵌套容器比较可见后代，跨格进入视野的孙节点也会挂载。
- 大容器绘制时一次建立子树索引，按 ID 恢复子元素的可见后代，保留插件的过滤与顺序。

## 协作接收与长会话

原有三副本长会话在 15 分钟门限内未完成。同一压测进程的一段 6 秒 CPU 采样中，90% 的样本调用栈包含接收路径，57% 包含文档编码，51% 包含构造隔离候选，39% 包含预算检查。这些比例可以重叠。一次视口平移不会提交协作文档，本项影响持续改内容和接收增量。

模型继续在独立候选上执行修改、检查字节与结构预算、验证契约并核对远端身份。进程内复制改用 Yjs V2 编解码。接收期间复用同一私有候选已核算的 V1 字节长度。等待依赖时缓存已提交基线的编码，本机事务、取走暂存或释放模型时清理。检查历史位置引用时，每个元素的当前位置只解析一次。无待决依赖、无富文本根的重放使用 Yjs 快照确认结构和删除均被覆盖，然后只读校验当前契约、完整状态和精确字节预算。仅携带新删除的增量仍会实际应用。磁盘和网络数据格式沿用原协议。

三端长会话使用 8 页、128 个初始元素，执行 3,600 轮共 7,200 笔事务，含乱序与重复投递、双端删除与撤销，以及 30 次从二进制状态重开模型。原门限为 900 秒。

| 长会话指标                     |            基线 |       交付版本 |
| ------------------------------ | --------------: | -------------: |
| 3,600 轮总耗时                 | 1,194.5 s，超时 |  464.7 s，通过 |
| 每轮两笔本机提交 P50 / P95     | 66.2 / 122.2 ms | 30.3 / 47.5 ms |
| 每 300 轮采样的进程 RSS 最高值 |       328.1 MiB |      320.2 MiB |

基线在超时判定后仍输出了完整工作量的统计。交付版本在原门限内通过收敛、身份和历史检查。两次完整运行发生在同一台日常使用的机器上，后台负载随时间变化。总耗时差约 61%，不能仅凭这个数拆分代码优化与系统负载各自的贡献。RSS 包含测试进程、三个副本与历史。

三项独立容量测试同时通过。64 页、5,000 元素的完整模型接收耗时 159.6 ms。32 次移动提交 P95 为 134.8 ms，读取投影 P95 为 38.6 ms，大文档的内容写入仍可能超过单帧预算。1,024 个独立富文本根可完整接收。长文本接近 8 MiB 时拒绝了越界写入，保留了最后确认状态。模型重开不包含真实跨机器网络时延。

## 验证

- 白板内核、导出与演示共 133 项行为测试通过，桌面白板与阅读纸 20 项通过，纯协作模型 81 项通过，容量和长会话 4 项通过。
- 白板包、协作包、独立示例和桌面 TypeScript 检查通过。交付源码构建了桌面生产渲染包，并在隔离 Electron 资料库完成 PDF 交互验证。
- 白板与插件进程边界检查、文档检查、官网的 66 项 Vitest 测试与 5 项发布源测试通过。
- 用户的原始文档使用性能快照分析。前后对照使用合成白板、本地生成的 PDF 和隔离资料库。当前数据支持以上工作负载下的改善，其他文件内容、系统负载和显示器组合需单独解释。
