# 白板文本框输入性能

Apple M3 Pro，macOS arm64，Electron 生产构建，前台窗口和隔离资料库。页面预置 240 条各含 64 个点的笔迹、24 个图形、12 个文本框和 12 条箭头。通过白板工具栏进入文本模式，点击已有文本框，每轮以 70 ms 的驱动间隔输入 24 个字符，停笔后继续采样 700 ms。CPU 倍率只设置到编辑窗口的渲染进程。此场景未测展开的文档卡、Intel 硬件或真实输入法驱动。

| 运行顺序 | CPU 降速 | 按键同步处理 P95 | 按键至第二帧回调 P95 | 最长帧间隔 | ≥49.9 ms 帧数 |
| -------: | -------: | ---------------: | -------------------: | ---------: | ------------: |
|        1 |       1× |           4.1 ms |              14.9 ms |     9.4 ms |             0 |
|        2 |       4× |          12.4 ms |              29.3 ms |    25.1 ms |             0 |
|        3 |       4× |          12.4 ms |              29.2 ms |    25.0 ms |             0 |
|        4 |       1× |           2.6 ms |              15.4 ms |     9.3 ms |             0 |
|        5 |       1× |           2.6 ms |              16.3 ms |     9.4 ms |             0 |
|        6 |       4× |          11.3 ms |              25.9 ms |    32.5 ms |             0 |

同步处理取 Chromium trace 中每个字符的外层 keypress EventDispatch，包含其内嵌输入事件。按键至第二帧从 keydown 的事件时间戳量到连续两次 requestAnimationFrame 回调，是显示响应的近似值。最长帧单独取相邻回调的最大时间差。六轮完成后通过 CDP 提交一次中文组合输入，离页后向主进程重新申请租约，读回的正文包含全部 144 个字符和「中文输入」。

同机同规模的早期测量中，0.66.1 在 1× 和 4× 下的按键至第二帧 P95 三轮中位数分别为 423 ms、3,430 ms，手写优化后的构建为 76 ms、328 ms。本轮分别为 15.4 ms、29.2 ms。早期脚本通过点击和聚焦进入文本框，本轮显式使用文本工具，并打开 EventDispatch 采集，因此早期测量只用作同场景参考。4× 下的同步处理 P95 仍高于 10 ms。

从仓库根目录运行下列命令。计时期间单独运行此用例。

```sh
pnpm --filter desktop exec vite build --configLoader runner
WHITEBOARD_TYPING_DESKTOP=1 pnpm --filter desktop exec playwright test e2e/whiteboard-typing-desktop.spec.ts
```
