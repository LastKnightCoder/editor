# 画框后续性能瓶颈与四轮优化

已完成四轮局部优化及逐轮压力验证，数据一致性与操作契约通过；**全部操作在 4× 下达到 60 FPS 的目标仍未完成**。

## 瓶颈与修改

- 创建预览原先为每个高亮 ID 单独遍历整树，密集收纳存在二次复杂度；改为一次遍历读取全部目标，保留高亮顺序及缺失目标处理。收纳先按几何范围过滤，再查询收纳能力。
- 连续向同一顺序表相邻位置移动，改为一次 Y.Array 插入；位置属性仍按命令顺序写入，初始化保护覆盖整段引用。非连续和不具备结构证明的命令继续按原语义执行。诊断中顺序插入从 1000 次降到 1 次，两边均写入 1000 条引用。
- 空图形标签的整个 HTML 容器及编辑器延迟至出现文字或进入编辑才挂载。密集解散前标签容器从 1001 个降到 1 个（剩余画框标题）；解散后从 1000 个降到 0 个。
- CPU 采样发现批量组件卸载反复调用数组型事件容器的 removeListener/off。Board 的私有事件容器改为有序注册集合与回调索引，批量移除不再反复扫描其它监听；保留重复注册顺序、off 移除全部同回调、快照分发、once 重入、异常隔离与销毁清理。新用例先在原实现通过，再验证替换实现。

仍然存在跨 React 父级改变导致的组件重建：密集解散诊断中，1000 个已挂载图形 SVG，操作后保留原 DOM 实例 0 个。减少空标签并没有消除这条重建路径。模型仍需为每个变化节点同步写入位置属性，只有顺序引用能成段插入；不能用分批公开半成品或降低校验换帧率。

## 性能样本

使用同一生产夹具、1000×700 视口、原生指针、500ms 收尾；每次操作及撤销/重做另用独立副本完整接纳、校验与读取。以下单位为 ms。系统存在其他并行任务，负载随时间变化；所有样本及负载记录保留，不能据此宣称固定倍数加速。CPU profile/Tracing 另列为诊断，不作为帧率放行样本。

前两轮在固定旧源码 `7aa3113ee` 与当时工作区之间交替两次，4× 结果：

| 解散 1000 个：模型结构提交   | 82.8–86.4   | 62.9–79.1    |

## 正确性与压力验证

- 每轮优化后各跑一次 4× 混合压力：909 个元素、20 轮、121 次真实拖放，覆盖嵌套分栏、旧契约升级、排序、拖入拖出、整框移动、连线、撤销重做与 Esc 取消；每轮独立模型校验，无数据或运行异常。
- 第三轮与第四轮各跑一次 4× 密集压力：1000 个同屏元素，5 轮完整创建收纳与解散，每组累计 10000 次前向归属移动，另执行收纳和解散各自的撤销/重做。逐步核对完整快照、稳定记录、正文绑定、层级、顺序和恢复区，全部通过。
- 198 条白板行为测试通过，另 4 条环境门控；46 条模型、预算、历史与独立对账测试通过；25 条真实 SQLite/WebSocket 回归通过。两个包类型检查、白板边界、文档检查通过，生产代码 lint 无错误。
- 新增契约用例覆盖同目标重复移动、失效顺序引用后的锚点、父级切换、单步撤销重做、远端归属/文字并发及空图形第一次双击进入编辑；不将性能墙钟断言写入单测。

密集夹具首轮使用 Alt 中心创建，随后按框左边缘打开菜单时点击落在视口外，菜单定位超时。修正为普通创建、通过 API 转换屏幕坐标并检查视口范围后，整组重跑通过；保留原失败记录，未削弱完整收纳、顺序或快照断言。早期不完整源码覆盖器的探索样本不参与对照结论。

## 复现

```bash
node apps/desktop/scripts/bench-whiteboard-frame.mjs --stress --stress-rate=4 --output=/tmp/frame-mixed.json
node apps/desktop/scripts/bench-whiteboard-frame.mjs --stress-structure --stress-rate=4 --output=/tmp/frame-structure-cycles.json
node apps/desktop/scripts/bench-whiteboard-frame.mjs --rounds=1 --rates=1,2,4 --raf-input --settle-ms=500 --verify --only=create:create:1000,exit,fit,dissolve --output=/tmp/frame-final.json
node apps/desktop/scripts/bench-whiteboard-frame.mjs --source-ref=7aa3113ee --rounds=1 --rates=4 --dense --profile --trace --readable-profile --settle-ms=500 --verify --only=dissolve --output=/tmp/frame-reference-profile.json
node apps/desktop/scripts/bench-whiteboard-frame.mjs --source-ref=7aa3113ee --source-files=packages/whiteboard/src/Board.tsx --rounds=3 --warmup=1 --rates=4 --settle-ms=500 --verify --only=dissolve --output=/tmp/frame-event-reference.json
```

`--source-ref` 默认仅替换两个包的源码，继续使用当前夹具与依赖；构建会验证模型、画布与预览源码确已读取。`--source-files` 限制为指定文件，并验证这些文件实际进入构建，便于隔离单项变化。性能样本使用独立进程浏览器会话，压力失败和严格帧率失败均非零退出，不吞掉失败。[原始样本](./2026-11-26-whiteboard-frame-followup.json)。未做视觉验收，真实媒体解码、任意插件及完整桌面负载不在这组夹具的性能放行范围。
