# 插件第三期能力与验证记录

第三期实现通用待办业务能力，不接入特定服务。范围为重复规则创建与分段修改/停止、原子实例状态补丁、持久状态分页、正文待办单提醒/清单，以及正文任务的可靠变化流。

## 结果

- 插件可使用 `todos.create({ recurrence })`、`setRecurrence`、`setOccurrenceState`、`occurrenceStates.query`，修改沿用 expectedRevision。
- 实例按原始日期定位，改期与跳过不改变身份；停止保留历史。状态页只枚举有限持久状态，页间变化报冲突。
- 正文普通提醒使用绝对 at，重复提醒使用当日零点偏移，均限一条；清单写入复用正文任务绑定。
- changes 的 document/all 来源贯通 SDK、两端适配、SQL 身份目录与日志。初始化分批提交，可重启续建；格式错误保留旧身份并拒绝可见来源的完成检查点。
- 主库身份捕获涵盖整篇/分块、节点移动、正文身份变化、来源持有、排除/提升、恢复与目录资格。页面索引可独立重建。
- 规范化既有规则的兼容空字段及星期集合；原样重设不抖动版本，历史分段创建时间保留。公开身份对保留字符使用独立版本标记，原文 taskId 不改写，旧字面引用授权不会落到另一项任务。

## 验证中修复的问题

混合快照曾因 SQL 的公开 id 别名按字典序排序，数字续页位置因此漏项；改为稳定数字键并保留回归。手机正文规则准备和提交曾重复生成不同系列 ID，造成返回 revision 与落库不一致；改用稳定候选身份并返回实际持久状态。

同时补齐正文解析清单/日期参与版本、提交前复验、零时间戳完成状态、父项级联保护、旧停止任务的普通状态、未来规则的既有入口读取、计划停止后的兼容完成记录，以及未知/隐藏正文的变化边界。相邻测试的异步界面准备改为等待真实挂载，IPC 回滚测试核对实际注册的处理器，未弱化业务断言。

## 交付边界

候选 SDK 位于 `/tmp/tau-plugin-phase3-sdk`。模板依赖指向的候选版本尚未注册到 npm，直接安装曾返回 404；随后使用本地候选包在隔离目录完成类型、ZIP 构建和作者消费验证，没有为绕过问题更改工作区依赖版本或锁文件。
