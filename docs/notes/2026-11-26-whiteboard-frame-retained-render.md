# 画框实例保留、主线程长任务与进一步优化

本轮使千元素收纳和解散保留全部 SVG 实例、焦点、未提交输入及 iframe。4×、1000 个文字元素、四秒整框拖动的两次正式样本通过原严格门槛；八秒正式样本保留全部 470 次有效位移，但起落阶段仍约 33ms，输入延迟约 35–37ms，严格门控失败。**千元素结构事务与全部操作的 60 FPS 目标仍未完成。**

## 修改与语义

- `ElementLayer` 让根元素与画框直接子元素共享 React 所有权。非画框节点按 ID 复用 portal 容器；画框自身保留普通宿主和内容插槽，继续使用单个显示组位移。解散前先移动存活容器，再删除画框。分栏和脑图内部仍由插件渲染，导出及不支持状态保留移动的平台仍使用内联树。
- 优先使用浏览器的状态保留移动，避免普通重插导致焦点和 iframe 状态重置。原生压力对实际输入框焦点、未提交值、iframe 文档/窗口标记和加载次数作断言。[Chrome 的状态保留移动说明](https://developer.chrome.com/blog/movebefore-api)。
- 连续同一下标插入也合并成一次顺序写入：引用按最终物理顺序反向排列，位置属性仍按命令原顺序写入，重复目标、锚点、并发及历史契约保持。
- 本机合并手势先保存位移意图，提交期限、松手及结构操作前再生成整批几何；移动事件子树按需展开，并捕获发出时坐标。减少原先四秒内约 60 次整树几何分配；共享手势仍沿用 50ms 路径，公开查询仍为最新显示坐标，读操作不提交文档。
- 松手后分开模型提交、坐标归位和选区/控件显示，真实选择仍同步可读。删除中的画框不参与延后显示，下次指针交互前完成坐标归位。
- 画框属性面板和已显示过的缩放控件在拖动时隐藏保留，隐藏面板禁止修改。保活曾暴露画风 Hook 的全量快照订阅成本，现只订阅画风事件；文档投影先发布完整快照再发送画风通知，避免专属订阅读到旧值。
- 将命中索引准备纳入空闲准备，按元素版本失效；根元素 ID 直接查找。手势结束后也安排准备，避免下一次交互重新承受首次构建成本。

## 结构操作对照

只将 `BoardContent/index.tsx` 恢复为 `7aa3113ee` 中的递归渲染层，其余当前模型和优化均相同。两边同一生产夹具、原生输入、500ms 收尾，每组一次预热、两次正式采样。以下为 4× 最大 rAF 帧间隔，单位 ms：

| 场景                     | 恢复旧渲染层 | 当前渲染层 | 当前模型结构提交 |
| ------------------------ | ------------ | ---------- | ---------------- |
| 完整收纳 1000 个同屏元素 | 350.0–366.7  | 216.6      | 68.4–73.3        |
| 解散 1000 个同屏子元素   | 283.4–333.3  | 100.0      | 41.7–42.9        |

旧渲染层两类操作均未保留原 SVG；新层全部保留 1000 个。首屏就绪含夹具模型初始化和资源加载，旧样本 586.8–679.5ms，新样本 636.2–719.8ms；不是独立的 UI 冷启动基准，仍说明实例保留有初始容器准备成本。每次操作、撤销与重做均用独立模型完整接纳、验证和读取对账。

当前常规视口样本（每格一次）：

| 操作                         | 1×   | 2×   | 4×    |
| ---------------------------- | ---- | ---- | ----- |
| 新建收纳 30 个（背景 1000）  | 16.8 | 16.8 | 33.3  |
| 从 1000 子元素中拖出一个     | 16.8 | 16.8 | 16.8  |
| 1000 子元素自适应内容        | 16.7 | 16.7 | 16.8  |
| 解散 1000 子元素（常规视口） | 16.8 | 16.7 | 100.1 |

新建收纳的模型同步阶段仍约 68–73ms，密集解散约 42ms；逐节点归属移动和同步准备仍超出帧预算。不能把组件不重建等同于全部事务都已达到 60 FPS。

补充 CPU profile 与浏览器 tracing 的单次诊断中，模型准备及提交约 101/47ms，其中真实命令执行各约 12ms；热点还包含 React context 传播、连接点 owner 解析和逐容器移动。插桩样本最长帧达到 467/800ms，仅用于定位，不与正常计时比较；原始诊断同样保留。后台准备值得做隔离原型，但不能据此保证主线程合入及绘制已经符合帧预算。

## 拖动、输入校准与失败

控制组保持相同 DOM，用轻量处理仅移动画框显示组，固定节奏输入达到全部 235 次有效位移，最大帧/位移间隔约 16.8ms。证明应用工作确实会影响输入处理，不将失败全部归咎于驱动。

原固定节奏协议、屏幕同步原生输入、发送端时间戳试验全部保留。同步输入记录完整轨迹时长，真实子元素屏幕位移必须为 220/40，逐帧检查位置与最新已到达原生输入一致。应用延迟使用原生事件时间戳，发送端跨进程延迟单独列出；没有插值或虚构额外位移。预选是夹具准备，在计时前等待其布局完成；旧样本不删除。

4× 四秒两次正式样本：有效位移均 235/235，最大帧间隔 16.8ms，最大位移间隔 16.8ms，输入到画面最大延迟 32.3–34.0ms；门控通过。1×/2× 的前序采样也有全部位移且 16.8ms 的通过样本，所有不通过样本仍在原始数据中。

4× 八秒两次正式样本：有效位移均 470/470，最大位移间隔 16.8ms；最大 rAF 间隔 33.3–33.4ms，输入到画面最大延迟 35.3–36.6ms。逐帧最新输入位置均匹配，起落阶段仍有长帧，原严格门控失败，不能验收全面目标。

## 验证

- 每轮对应 4×、909 个混合元素、20 轮/121 次真实拖放及独立对账；再跑 1000 同屏元素、5 轮完整收纳/解散与撤销重做，每组 10000 次前向归属移动。
- 原生保活压力同样 5 轮/10000 次归属移动，检查全部 SVG 身份、绘制顺序、输入值/焦点及 iframe 文档和加载次数。包括坐标归位尚未结束便解散的重叠场景；全部通过，iframe 只加载一次。
- 217 条白板行为、画风与作者展示契约通过，另 4 条环境门控。46 条模型/容量/历史用例通过；真实 SQLite、WebSocket 及真实拖动跨画布回归 32 条通过。类型、边界和文档按最终改动检查。
- 新用例覆盖根层/跨画框/解散/撤销重做中的未提交编辑和实例保留、StrictMode effect 重放、事件只触发一次、位移快照不漂移、取消后的延迟写入、同步结束、意图未落地时解散、选择数据同步而显示控件分阶段、画风事件与完整快照一致。
