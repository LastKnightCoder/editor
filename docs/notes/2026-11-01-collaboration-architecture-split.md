日期：2026-11-01。目标：先修正已确认的行为问题，再明确正文、共享、白板与平台生命周期的边界。本轮没有搬迁管理器、改 CRDT 格式或改数据库 Schema；以下新增目录、接口与迁移批次均为待实施方案。

## 2. 拆分必须保持的事实

### 2.1 不能将几种确认合并成一个 saved

| 事实     | 含义                                         | 不代表什么                             |
| -------- | -------------------------------------------- | -------------------------------------- |
| 内存接纳 | 当前文档模型已接纳编辑                       | 未证明写入本机耐久存储                 |
| 本机耐久 | 增量或候选已进入可恢复日志/检查点            | 未证明主库投影完成，也未证明服务器确认 |
| 主库投影 | 正文、契约、关系或白板页已按对应修订提交主库 | 未证明远端接纳                         |
| 远端确认 | 当前操作取得匹配身份、基线和代次的提交确认   | 未证明本机投影已经追上                 |

桌面与移动的输入接纳时序可以不同，但接口必须说清返回的是哪一种事实。UI 的“已保存”和“已同步”从这些事实派生，不能由连接在线或一个 pending 布尔值推断。

### 2.2 保留现有数据权威边界

- 普通正文的主库存储、活跃会话和待投影材料各有既有职责；缓存重建不能覆盖主库后来写入的正文。
- 云端共享的房间基线、代次与成员权限由服务端裁决，本机缓存不能自行确认另一代次。
- 白板继续使用本机日志、主库检查点及网络操作回执。日志、投影和网络回执不因模块拆分合并为一张“保存表”。
- 原有资源、拒绝分支、输入草稿、终态回执及历史账本保全规则保持；仅更换代码位置不触发数据转换或清理。

### 2.3 身份要在接口上区分

| 身份                                  | 用途                                                   |
| ------------------------------------- | ------------------------------------------------------ |
| `librarySourceId + contentDocumentId` | 识别稳定的本机正文来源                                 |
| `databaseName + connectionGeneration` | 定位本机库槽位并拒绝旧连接的迟到写入；不能代替同源身份 |
| `serverOrigin + roomDocumentId`       | 定位服务器上的共享房间，不引入地址别名或凭据搬迁       |
| `baselineId + epoch + version`        | 核对当前 CRDT 基线及协议                               |
| `leaseId + sessionGeneration + owner` | 定位某个视图/窗口取得的使用权                          |
| `operationId + fingerprint`           | 追踪同一次发布、条件写入或退出的未知结果               |

这些身份不是都叫 documentId 的同一个字符串。迁移先在内部类型和适配边界明确命名，保留现有 wire 格式；不以全仓重命名作为前置任务。

## 3. 依赖方向

表中箭头表示源码允许依赖的方向。反向通知通过订阅或注入的有限端口完成，不能通过导入调用方实现。

| 上层                | 可依赖的下层                                         | 禁止反向依赖                                       |
| ------------------- | ---------------------------------------------------- | -------------------------------------------------- |
| 页面、React hooks   | 渲染端文档客户端、命令契约、只读状态投影             | 文档内核不得导入页面、store 或 React 生命周期      |
| Electron/Tauri 适配 | 应用用例、契约、平台 I/O                             | 用例与模型不得导入窗口管理、invoke 或页面          |
| 共享发布/关闭编排   | 正文服务端口、资源端口、共享 HTTP 端口、耐久操作记录 | 正文服务不得导入共享管理器                         |
| 正文服务            | 会话注册表、写入器、投影器、持有服务及存储端口       | 下层不得取得整个正文服务对象                       |
| 写入器/投影器       | 文档模型、有限会话句柄、存储或领域仓储端口           | 仓储不得回调网络或 UI                              |
| 共享连接池/文档通道 | Hocuspocus、票据端口、文档接纳及状态订阅端口         | 连接层不得导入正文表、资源上传 UI                  |
| Node/Worker 接入    | 共享纯规则、服务用例、各自存储适配                   | 共享业务规则不得依赖 Fastify、Durable Object 或 R2 |
| 协议与模型          | Yjs、稳定数据契约、纯校验                            | 不依赖 Electron、Tauri、React、业务实体仓储        |

组合根可以同时知道这些模块以完成装配，但组合根不持有第二份会话表、连接表或投影状态。业务互调经有限接口，不把原来的 `CollaborationManager` 整个对象作为依赖传下去。

## 5. 桌面主进程目标模块

以下路径为拟议目录。现有模块在对应消费者迁移完成后删除原方法；不维护双写与永久兼容实现。

### 5.1 正文服务 `modules/content-documents/`

| 模块            | 责任与公开能力                                                             | 状态归属                                                 | 从现有何处迁出                                                                 |
| --------------- | -------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `index.ts`      | 装配并暴露 open/apply/flush/read/release；通过既有 BACKGROUND 启动体系就绪 | 仅服务依赖引用                                           | collaboration 的正文入口与模块装配                                             |

| `writer.ts`     | 串行候选验证、耐久增量、输入草稿确认、候选安装；返回本机提交回执           | 单实例有界写队列、在途 flush；会话状态经受控方法更新     | NodeSessionUpdates、patchSessionNodes 与 replaceContentSnapshot 的本机安装部分 |
| `projection.ts` | 按已耐久检查点生成主库投影；原库事务复查来源和观察修订；合并投影排期       | 每正文在途投影、待投影修订、最后投影修订、重试状态       | project、projecting、projectionDirty、标题与正文投影编排                       |
| `retention.ts`  | 文档/历史/草稿持有的实体引用保全                                           | 持有记录的更新与读取协议                                 | retainNodeState、ContentRetention；复用原耐久记录                              |
| `storage.ts`    | 会话缓存、增量、草稿与本机视图数据；备份坏缓存并重建                       | SQLite 中对应记录                                        | local-store、content-local-state 的正文存储部分                                |

`session.ts` 不连接服务器、不写具体业务表；`writer.ts` 不触发关窗；`projection.ts` 不启动重连。普通正文和共享正文通过同一个正文用例入口执行本机写入准入，差别由装配的持久化/投影端口表达。

写队列由正文服务创建一次，按文档身份串行并共享总预算。整篇替换与节点补丁使用同一队列，不能每次操作创建新队列来绕开并发约束。只将异步计算放在队列外且持有观察修订；正式安装进入队列后重新核对身份和修订。

Awareness 的逻辑生命周期归正文会话；provider 使用同一份 Awareness。Hocuspocus 4.6 的最终 provider 销毁会连带销毁 Awareness，必须把二者纳入同一终态收尾路径：先让视图失效并解除绑定，再完成网络和文档资源释放。临时断线、资源等待与存盘失败都走暂停，不能任意 destroy。连接池只负责整条连接，文档通道只负责自己的路由和订阅。

原有 settings、身份、发布记录和白板安装记录共用一个缓存库并不意味着它们应共用一个巨型业务服务。可以先为现有 SQLite 连接提供窄仓储视图，保持文件、表和事务边界；不为拆模块新建多个数据库。

### 5.3 平台生命周期

| 模块                                     | 责任与状态                                                            | 依赖边界                                      |
| ---------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------- |
| `document-lifecycle`（沿用现有屏障协议） | 冻结请求、目标视图集合、等待回执、超时、取消与恢复；按 requestId 仲裁 | 依赖可排空的正文/白板端口，不读取模型内部结构 |
| 窗口生命周期适配                         | 将关窗、导航、崩溃、切库、退出映射到文档屏障                          | Electron → 屏障；正文服务不 import windows    |

冻结要避免死锁：先产生带 requestId 的门禁，允许本次目标视图排空已有输入；等待回执时不占用文档写队列；回执与在途写入全部确认后才进入关闭或切库提交。旧请求的取消只能释放自己的门禁，不能解冻更新的请求。

### 5.4 白板保留领域实现，只拆入口编排

沿用 [whiteboard-documents](/apps/desktop/src-electron/main/modules/whiteboard-documents/index.ts) 的 sessions、repository、journal、installation、transitions、publications、unshare、realtime 和 remote。优先从巨大的 init 拆出：

| 拟新增模块          | 接走的责任与状态                                                                        | 保留边界                                                           |
| ------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `ipc-controller.ts` | 类型化注册、参数和窗口/lease 校验                                                       | 不持有网络分支或安装任务                                           |
| `remote-runtime.ts` | remote 会话、remoteViews、remoteSyncs、remoteUsers、realtime 实例、分支隔离后的同步准入 | HTTP 确认与 WebSocket 实时收发仍分工；共用现有 DocumentSyncSession |
| `lifecycle.ts`      | 白板范围的 drain、waiters、打开屏障及取消                                               | 使用现有文档屏障协议，保留多视图保存确认                           |

`WhiteboardJournal` 继续独占本机增量和回执记录，`WhiteboardDocumentSessions` 继续独占模型和视图租约，`WhiteboardInstallation/Transitions` 继续独占跨存储提交阶段。正文和白板共享有限的排空/确认契约即可，不把两种会话硬合成一个带大量可选字段的基类。

## 6. 渲染端与移动端

| `hooks/useContentDocument.ts`          | 插件契约准备、EditorDocument 组装、同谱系换绑                 | 编辑器实例的谱系和准备代次                                             |
| 场景资源适配                           | 为 kit 注入当前文档的资源接口                                 | 不持有全局连接或上传事实                                               |

主进程 Y.Doc 与渲染副本属于不同进程，不能合并。渲染端 origin、选区和 UndoManager 属于视图；主进程不能为了“统一撤销”持有或恢复某个窗口的内存撤销栈。白板现有 IndexedDB outbox 仍由白板客户端拥有，不挪进普通正文 hook。

### 6.2 移动 WebView

在现有 `features/collaboration/core/` 内渐进拆分，不先建立跨端通用运行时：

| 模块                            | 责任                                              | 独占状态                                                    |
| ------------------------------- | ------------------------------------------------- | ----------------------------------------------------------- |
| `runtime.ts`                    | 按需启动、页面持有、前后台恢复、整体停止与装配    | refCount、idle timer、starting/desired、宿主事件注销句柄    |
| `rooms.ts`                      | 房间列表、成员、申请和后台关闭恢复调度            | 目录快照、refreshing、pendingJoins                          |
| `sessions.ts`                   | 唯一会话、打开去重、缓存与远端身份比对、替换/释放 | session 表、opening、Y.Doc、Awareness、视图借用代次         |
| `persistence.ts`                | Rust 缓存写入串行化、输入草稿确认、失败冻结与恢复 | 每会话 writeTail、pendingUpdates、draft sequence、saveError |
| `connections.ts`                | 服务器传输与本篇 provider 的有限操作              | 服务器池、事件连接、文档附着；与 sessions 的终态收尾配对    |
| `projection.ts`                 | 原来源正文的投影、修订核对和在途合并              | projection promise、下一轮待投影标记                        |
| `publication.ts` / `closure.ts` | 共享发布与结束的耐久操作流程                      | 候选、阶段和原操作身份；耐久记录由 Rust 仓储保存            |
| `resources.ts`                  | 地址映射与文档来源校验；调用 Rust 资源能力        | 来源注册、资源任务去重与排期；文件事实仍在 Rust             |
| `rest.ts`                       | Tauri 网络适配与结构化失败转换                    | 不拥有会话或页面生命周期                                    |

普通移动正文现有写入协调器与共享正文接线先保留各自入口；先统一身份、排空和提交结果口径，再判断哪些流程确实重复。WebView 编辑器直接使用会话 Y.Doc，不能复制桌面 IPC 同步客户端。

### 6.3 移动 Rust

将 [collaboration.rs](/apps/mobile/src-tauri/src/collaboration.rs) 的职责按原有函数边界迁入 `collaboration/identity.rs`、`http.rs`、`cache.rs`、`drafts.rs`、`views.rs`、`recovery.rs`，`mod.rs` 保留命令入口与装配。原 `database/collaboration.rs` 的主库绑定与投影继续属于数据库领域，`collaboration_assets.rs` 的文件资源保持独立。

文件身份、SQLite 事务、坏缓存备份、关闭恢复记录与并发锁仍由 Rust 拥有。WebView 不镜像一套“权威已提交”记录，也不因文件拆分复制多个缓存写锁。网络错误只在 Rust/TypeScript 适配边界转换，领域逻辑按错误码判断，不到处解析错误文本。

## 7. 服务端拆分

Node 与 Worker 继续各自提供 HTTP、WebSocket、存储和部署。先共享已经发生漂移的规则，再考虑共同的接纳用例。

| 模块                        | 责任                                                           | 状态归属                                |
| --------------------------- | -------------------------------------------------------------- | --------------------------------------- |
| routes / Hocuspocus hooks   | 解析请求、取得身份、调用用例、映射响应或推送                   | 仅请求与连接上下文                      |
| authorization               | 设备、成员、房间状态与票据复核                                 | 权威记录在各自 SQLite；不相信客户端角色 |
| document admission          | 文档队列内加载、候选验证、容量与修订条件复查、提交后安装运行态 | 每服务一份有界逐文档写队列              |
| protocol / operation ledger | 首次发布、当前基线、修订和幂等终态                             | 与正式正文共用同一 SQLite 事务          |
| Node repository             | better-sqlite3、快照/增量、文件资源                            | Node 的数据库与文件                     |
| Worker repository           | Durable Object SQLite、chunk、R2 资源                          | DO 的事务状态、R2 对象及持有记录        |
| presence / capacity 纯规则  | 活动优先级、新文档准入判据、状态预算                           | 无共享全局可变状态；额度数值由宿主配置  |

不建立吞掉两套存储差异的万能 Repository。公共接纳用例只依赖窄端口；正式增量、回执、修订及资产持有必须能在同一个同步事务中落地。任何 `await` 后再执行权限和基线复核，不跨网络等待持有 SQLite 事务。

连接计数、活动文档计数与编码内存预算分别拥有判据。已加载文档的成员重连不能消耗“新增文档”名额，20 份上限也不意味着 20 份最大文档都能驻留。

## 8. 状态唯一归属清单

| 现有状态/材料                                                     | 目标唯一拥有者                   | 其他模块如何使用                                         |
| ----------------------------------------------------------------- | -------------------------------- | -------------------------------------------------------- |
| 活跃 Y.Doc、基线、会话代次、Awareness                             | 正文/白板会话                    | 使用受控写入口或借用绑定，最终释放由同一会话生命周期协调 |
| 视图 origin、选区、UndoManager、源码句柄                          | 编辑器视图绑定                   | 会话不接管视图历史；换代时使旧绑定失效                   |
| 视图租约与当前 owner                                              | 会话；窗口到租约的查询由屏障适配 | IPC 校验租约，不接受裸 ID 绕过 owner                     |
| pendingUpdates、writeTail、本机提交错误                           | 本机写入/耐久组件                | 运行时读确认快照，不能由网络回调清除保存错误             |
| projectionDirty、projecting、projectionRevision                   | 投影器                           | 正文提交后标记待投影；网络不直接声明投影成功             |
| provider、是否附着、远端未确认计数                                | 文档通道                         | 视图读派生连接快照；本机保存不冒充远端回执               |
| transports、events、重连 timer                                    | 连接池                           | 文档取得和释放自己的通道，不能销毁整个池                 |
| rooms、members、requests、pendingJoins                            | 房间目录                         | UI 消费只读快照；目录不生成正文对象                      |
| publishing、close-attempted、close-confirmed、原修订              | 发布/关闭操作仓储与其协调器      | 未知结果按原身份续做，不由组件本地 loading 决定          |
| freezeWaiters、drainingViews、requestId                           | 文档屏障                         | 会话门禁持有对应 token；旧取消不影响新请求               |
| assetsPending、resourceGeneration、resourceTask、owner image 映射 | 资源服务                         | 通道根据资源就绪判据发送；UI 不维护第二份资产事实        |
| remote branches、receipts、白板 outbox                            | 各自耐久日志/客户端              | 保留不同故障边界，仅通过提交结果对账                     |
| 正文主库字段、关系账、标题归属                                    | 领域仓储与投影器                 | 协作客户端不直接更新业务表                               |
| start/stop、refCount、visibility 监听                             | 平台运行时适配                   | 页面只 acquire/release 自己的持有                        |
| 展示 label、tone、loading、toast 已消费                           | UI 快照与显示层                  | 不反写模型、成员或耐久状态                               |

`error` 不再由所有流程争抢一个字符串。先在各拥有者记录带阶段和 code 的错误，再由展示层按明确优先级合成当前提示。只读原因同样独立：保存失败、撤权、关闭结果未知、版本不支持不能互相清除。

生命周期只需小型判别联合，例如 opening、active、publishing、closing、close-unknown、retired；连接状态和保存状态保持正交。不引入覆盖所有组合的巨型状态机。

## 9. 关键流程怎样跨模块

### 9.1 打开、编辑与主库投影

1. 适配器提供固定库连接作用域和目标身份，正文服务经 registry 取得唯一会话。
2. 会话从既有权威检查点/可用缓存恢复；失败按既有保全和重建规则处理，核对来源后发放视图 lease。
3. 输入由视图模型接纳；本机写入器串行验证并耐久提交，返回 `LocalCommit`，然后广播该修订。
4. 投影器消费已提交检查点，资源就绪后在原库事务核对 observedRevision 并更新正文/关系。
5. 投影失败保留本机提交及待投影状态；关闭屏障等待所需投影结果，不允许把“内存有内容”当作保存成功。

桌面渲染副本的 IPC 回执与移动 Rust 缓存的异步回执均遵守这组结果语义；输入时序和进程划分继续保留平台差异。

### 9.2 断线、资源等待和保存失败

1. 连接池负责物理网络，文档通道负责自身的暂停、重新鉴权和状态向量交换。
2. 临时断线保留文档与视图历史；本机保存失败暂停该篇写入口和通道，原输入仍保留。
3. 本机耐久重试成功后，解除该保存失败原因，再恢复本篇通道；不清除撤权、关闭或版本原因。
4. 重连不能销毁其他房间的传输；缓存错误不能借销毁 provider 清空视图订阅。

### 9.3 条件写入、发布与结束共享

条件写入先固定观察修订、代次、候选和 operationId，耐久保存后再提交；请求期限消费服务端时间。结果未知先查询同一操作，不生成新 ID 重复执行。

结束共享由屏障冻结并排空输入，关闭协调器取得最终远端快照、等待资源持久副本和主库投影，再保存关闭记录并按原修订请求关闭。服务器成功后，跨存储安装/解绑继续使用固定候选；结果未知保持受控状态并续做，不能重新开放旧共享写入。

正文和白板可复用请求/确认的底层协议，但发布候选、资源安装、页面映射及关系账仍由各领域处理。

### 9.4 切库与终态释放

先废弃旧库连接代次与新写入资格，再排空对应文档；失败回滚本次屏障，成功后使旧 lease 失效。视图解绑后由拥有者释放通道、Awareness、模型和观察者，连接池仅在没有消费者或整体停止时释放。迟到结果必须携带原作用域，不能落入新库或新会话。

## 10. 最小接口草案

接口以用例和确认结果为中心；以下类型用于讨论边界，不要求按此名称原样实现。

```ts
interface LocalCommit {
  sessionGeneration: number;
  revision: string;
  durable: true;
}

interface ContentDocuments {
  open(target: ContentTarget): Promise<ContentLease>;
  apply(lease: ContentLease, update: Uint8Array): Promise<LocalCommit>;
  flush(lease: ContentLease): Promise<LocalCommit>;
  readCommitted(lease: ContentLease): CommittedContent;
  release(lease: ContentLease): Promise<void>;
}

interface ProjectionWriter {
  project(content: CommittedContent): Promise<ProjectionReceipt>;
  flush(target: ContentTarget): Promise<ProjectionReceipt>;
}

interface SharedDocumentChannel {
  resume(): Promise<void>;
  pause(): void;
  status(): RemoteStatus;
}
```

`ContentLease` 固定库连接、正文和会话代次；`CommittedContent` 只能由已耐久修订生成，并携带来源和观察修订。`RemoteStatus` 只表达传输及远端确认，不能通过它修改主库。没有“拿到整个管理器”“任意访问 SQL”或“把任何事务回调交给插件”的接口。

冻结屏障、资源与发布/关闭用例各有自己的有限端口，不把所有能力并入 `ContentDocuments`。模型/绑定的可信内部可使用 Y.Doc，业务调用方和普通插件不获得可变根。

每批先声明消费者和保留边界，移动后用 `rg` 复核原消费者清零，再删除原方法；不要让旧方法和新服务同时维护同一份状态。纯搬迁和行为变化分开审查。新增测试仅用于复杂状态迁移、已知严重回归或数据转换，其余优先复用相关现有测试、类型检查、边界与构建。

批次 B 的范围最大，可以在同一边界内再拆为“会话/写入”和“投影/持有”两个可独立验收的提交；每次提交仍须保持普通正文、共享编辑与退出可用。仅有新接口而消费者尚未接通，不算完成。
