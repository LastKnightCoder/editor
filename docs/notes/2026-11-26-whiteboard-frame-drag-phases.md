# 密集画框长拖动的输入、几何发布和松手归位

同屏 1000 个带正文的图形，预选整个画框，原生指针沿 220 × 40 像素轨迹连续移动。目标是八秒、480 次输入，包含起拖阈值、松手提交、坐标归位及控件恢复。Chrome 的档位只对页面主线程降速。逐帧读取画框及第一个子图形的屏幕变换，输入延迟量到 rAF 中能读到新位置，物理屏幕扫描输出另有延迟。

默认路径接入稳定选区订阅和画框宿主顺序修正。单一命中面仍只在隔离夹具中启用。固定八秒轨迹里，它在 4× 减少大量掉帧，但 1× 的合格样本连续出现更高的输入峰值。全面 60 FPS 尚未达标。[原始记录、逐帧坐标和全部失败样本](2026-11-26-whiteboard-frame-drag-phases.raw.json.gz)

## 为什么八秒变成十二秒

原夹具在页面每次 rAF 发送一个新输入。少一次刷新就少一次发送机会。历史上的 12.1 秒结束于最后一笔移动输入，发生在松手之前。本轮 4× 同构建、带轨迹的逐元素基线用时 12.23 秒，拖动区间错过约 255 个 60 Hz 刷新机会，折合 4.25 秒。下面的独立时钟对照在浏览器进程外按墙钟发送，单独记录发送完毕和浏览器确认耗时。

4× 同一次诊断中，页面对 480 次输入执行约 960 次原生命中测试。基线命中累计约 5.05 秒，给已接管的整框拖动提供单一命中面后约 0.16 秒。实际输入由 12.23 秒降至 8.06 秒，错过刷新机会由 255 降至 4。累计时间只用于定位，嵌套的浏览器事件不能相加。

## 哪些长帧与几何同步有关

长拖动中的本机发布依然将画框及每个子元素的绝对坐标放进同一笔 Yjs 事务。上述基线松手前有 18 笔，单笔 16.2–37.5ms。三个约 66.7ms 的 rAF 间隔中，有两个与几何提交重叠，一个发生在起拖、早于首笔提交。208 个约 33ms 的拖动间隔没有与几何提交重叠。仅在诊断夹具停掉中途发布，轨迹仍用 10.87 秒，错过约 174 次刷新，且丧失中途协作语义。此对照只用于归因。

## 松手后发生了什么

另一条 4× 轨迹中，最终几何模型批写约 19.5ms，整段结束手势约 23.9ms，首次 rAF 回调约 172.5ms。分阶段 CPU 采样在松手后捕获到 React 的上下文传播。四倍降速下，只给图形的正文编辑器套用 memo，松手仍有约 185ms 的原生事件分发长任务。把画布根与静态绘制层的选区改为稳定订阅，只有读取该选区的组件接收新值。三秒消融实验中，同样保留命中面时，环境合格的旧选区方案松手事件为 166.7ms，订阅原型两次为 34.6ms、36.6ms。后续坐标归位仍产生约 133ms 的长帧；首次回调与整次交互最长帧分开统计。

## 交错撤销时的 iframe 重载

两个画框与根层反复交错移动后，第 38 次检查对应一笔撤销。逐元素默认实现与拖动原型都保留了全部 SVG，但同一个 iframe 的加载次数从 1 变为 2，文档对象和窗口内标记均已更换。可读构建捕获到 React 在提交重排时对包含 iframe 的画框组执行普通 `appendChild`。随后再由元素层调整绘制顺序已经来不及保留这个文档。

隔离修正把 React 管理的画框宿主与其余 portal 分组，画框宿主的 React 相对顺序按稳定 ID 排列。实际 SVG 层叠顺序仍由元素层按模型顺序提交。这样避免 React 在普通子元素的归属或顺序变化时重插已有画框。压力逐步检查 DOM 顺序、焦点、输入值、iframe 文档和加载次数。

修正后的 4× 回归完成 5 轮整批收纳、解散和撤销重做，共 10000 次前向归属移动，再完成 2512 次交错移动、重排和归并。1000 个 SVG 全程保留，iframe 仅加载一次。原生拖动期间接纳远端几何更新和远端解散后再松手，两种冲突均验证了实际屏幕坐标、模型与独立副本一致。混合压力为 909 个元素、20 轮、121 个手势。

## 存储和协作

千子元素的真实双端测试使用两个 SQLite 文件、两个独立本地日志和回环 WebSocket。拖动中途先确认另一端看到了中间坐标，随后在松手、一步撤销和重做后，分别用新的只读 SQLite 连接读取两端的落盘字节，在独立模型里逐项比较 1000 个子元素的身份、坐标和正文（16 份非空）。本机仅有一个撤销项，远端没有产生本机撤销项。

早期压力暴露了源码环境缺少打包后的保存工作线程，以及富文本夹具缺少段落契约。最终测试在临时目录按桌面打包的相邻路径构建正式会话入口和保存 Worker，为非空测试正文安装实际契约。默认方案和注入拖动原型的真实保存、协作回归均为 11 条通过，选区、图层、画框和资源保留定向用例 34 条通过。压测中的输入延迟和超预算记录独立保留。

4× 四秒的配对剖析进一步分开了松手与归位。基线的松手首帧约 175ms，组合原型约 51ms。进入最终子树更新到选区恢复，两者仍分别用了约 350ms 和 359ms 的墙钟时间。该窗口的采样包括 React 子树协调、宿主属性写入和浏览器坐标读取；期间可以产生多个帧，并非单个 359ms 阻塞。基线松手后的 React 上下文传播约 138ms，组合原型的同一函数已退出最热项。此次带 profiler 的旧探针在停止追踪时仍采样，保存其原始尖峰但不用于帧率验收；已将探针停止点移到浏览器清理追踪之前。正式三档性能对照均关闭 profiler。

## 读数口径

最大实际位移间隔取相邻两次读到不同屏幕位置的墙钟时间差，原始数据同时保留对应的 rAF 时间戳间隔。输入 P95 与峰值从发送端开始，量到真实位置抵达或越过目标，覆盖合并输入。松手首帧从原生 pointerup 时间戳量到下一次 rAF 回调，包括排队。拖动错过刷新数按各段 rAF 间隔折算为 60 Hz 的刷新机会；全程最长帧还包含起拖前和松手归位。表中范围分别汇总各方案，不能把不同时刻的最差值相减当成一对样本。

首轮各档均对两个方案预热后交替测量；补测只按主机负载资格触发，保留超预算和负载不合格样本。另保留仅复用标签编辑器的中途结束采样，后续转向实际显示出松手收益的选区订阅。带分析器、早期并跑压力时的诊断以及去掉协作中间同步的消融均独立于正式对照。
