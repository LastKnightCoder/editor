## 一、总览与文件结构

以下相对路径均在 `packages/database/src/` 下；桌面宿主文件在 `apps/desktop/src/features/shared/database/`。

- 入口：`Database.tsx` —— 装配扩展（`extensions.ts` 的 `installDatabaseExtensions`）、创建 Zustand store、绑定键盘/列宽事件、渲染视图与 tabs。
- 状态：`DatabaseStore.ts` —— 单一数据源（columns/rows/views/viewConfig/history/selection/query/projection）。
- 插件：`plugins/*` —— 内置列类型实现、过滤/排序/分组/搜索策略、beforeSave/afterLoad；公式引擎在 `core/formula/*`。
- 视图：`views/TableView | GalleryView | CalendarView | KanbanView` —— 同源数据（store 内统一投影），不同呈现；类型元数据在 `views/registry.ts`，组件映射在 `views/components.ts`。
- 工具与 Hook：`hooks/*`（单元格编辑、列宽、可见列、键盘导航、校验、行详情开合）。
- 组件：`components/RowDetailModal`、`components/FormulaBuilder`、`ViewTabs`、`FilterPanel/GroupPanel/SortPanel`、`ViewTypeSelectModal` 等。
- 常量：`constants/select.ts` 提供多选/单选颜色配置（`SELECT_COLORS`，与 `@tau/ui` Tag 七色板对应）。
- 桌面宿主：`DesktopDatabase.tsx` 装配 `tau.desktop` 扩展（`desktopExtension.tsx`）并做切库保护；`plugins/*`（宿主侧）提供 image/attachment/rich-text 字段与 link 渲染覆盖；`viewAdapter.ts` 把持久化视图投影为通用视图协议。

## 二、数据模型与核心类型

### 2.1 Column / Row / DatabaseData

- `ColumnDef`：id/title/type/config/width/hidden/isPrimary/validation 等。`config` 由插件自定义（如日期格式、选择项）。
- `RowData`：`{ id: string; [columnId]: CellValue }`，行的自定义字段来自列 id。
- `CellValue`：插件决定具体形态，例如：
  - text/number: string | number | null
  - date: `{ start: number|null; end: number|null }`
  - select: `optionId:string`
  - multi-select: `Array<{id,name,color}>`
  - image: `ImageItem[]`

### 2.2 ViewConfig

`TableViewConfig`（从 @tau/shared）：

- `columnOrder`: string[] —— 列顺序；`columnWidths`: id→width
- `rowOrder`: string[] —— 行顺序
- `groupBy`: { fieldId, strategy }
- `sorts`: SortRule[]（priority + field + direction）
- `filters`: FilterGroup（树形条件）
- `footer`: id→FooterSpec —— 表尾汇总（单列聚合或以各列汇总为叶子的组合表达式，D-121）
- 扩展：`galleryConfig`（封面类型/图片列）、`calendarConfig`（日期列）、`kanbanConfig`（分组列/列顺序）

### 2.3 Selection/Editing

- `selectedCell`: { rowId, columnId } | null
- `editingCell`: { rowId, columnId } | null
- `query`: 会话查询（text 关键字 / filters / searchResults / grouping），经 `setQuery` 更新，不写入视图配置

## 三、状态管理与历史

### 3.1 createDatabaseStore 初始化

- 合并列宽：`mergedColumnWidths = viewConfig.columnWidths || col.width || 200`
- 行/列顺序回落：若 viewConfig 缺失则用初始数据顺序。
- 复制过滤器/配置：`cloneFilters` 深拷贝，gallery/calendar/kanban 配置浅拷贝。

### 3.2 操作类函数

- **updateCellValue**：写入前 `commitHistory`，仅替换目标 cell。
- **addRow/deleteRow/moveRow**：同步更新 `viewConfig.rowOrder`。
- **addColumn/deleteColumn/moveColumn**：同步 `viewConfig.columnOrder` 与 `columnWidths`（删除列还清理该列的表尾汇总配置）；删除列会遍历行删除字段，是纯数据操作——正文引用由主进程按差集维护（D-129），无插件清理钩子。
- **setGroupBy/setSorts/setFilters/setFooter**：写入 viewConfig，filters 深拷贝。
- **dispatch/setQuery**：外部变更（`rows.apply` 差量、`rows.receive` 确认快照、视图与列命令）与查询经 ref 进 store，source 为 "external" 时不触发保存回调。

### 3.3 历史与撤销

- `commitHistory`：最多 50 条；如果 redo 栈存在且有新操作，先截断 redo。
- `undo/redo`：恢复 columns/rows/viewConfig（基础字段），未包含 gallery/calendar/kanban？→ 在 setViewConfig 时会带上扩展配置，保证回放完整。
- 归并策略：无时间窗口，直接按调用顺序入栈；调用者需在批量更新前自行控制调用频率（例如 updateCellValue 内已 commit）。

## 四、插件体系详解（列类型）

### 4.1 CellPlugin 能力回顾

- `Renderer`（必需）+ `Editor`（可选，editable=true 时触发双击编辑）。
- `beforeSave/afterLoad`：格式归一化与容错。
- `getGroupKey`：分组键；`sort`：排序比较；`filters`：筛选操作符（可按列给出）；`search`：自定义搜索。
- `valueType/toScalar/formatScalar`：参与表尾汇总与公式的值口径（D-121）；未声明 `valueType` 的字段只能计数。
- `capabilities`：字段能力声明（date/singleOption/boolean/images），视图与面板经 `PluginManager.hasCapability` 查询，判定日历日期列、看板分组列、封面图片列等可用性。

### 4.2 内置插件要点

| 插件        | 值格式                         | 过滤/排序               | 特殊逻辑                                                      |
| ----------- | ------------------------------ | ----------------------- | ------------------------------------------------------------- |
| Text        | string                         | 包含/不包含/为空/不为空 | search 小写包含                                               |
| Number      | number                         | >= <= =                 | sort 按数值，过滤条件包含范围                                 |
| Date        | {start,end}                    | 多种比较（开始/结束）   | beforeSave/afterLoad 兼容 number/Date；isRange 切换 end=start |
| Select      | optionId                       | equals/not/null         | `getGroupKey` 用 optionId，看板依赖                           |
| MultiSelect | option[]                       | 包含/不包含/为空        | search 按名称包含，颜色来自 SELECT_COLORS                     |
| Checkbox    | boolean                        | is true/false/null      | search 按 bool                                                |
| Link        | {url,text}?                    |                         | Renderer 展示链接                                             |
| Star        | number                         | 数值排序                | 评分组件                                                      |
| Progress    | number                         | 范围过滤/排序           | 0-100 条形展示                                                |
| Formula     | {value,error?}（仅投影中派生） | 按结果类型              | 表达式存 `config`，可筛选/排序/搜索/分组（D-121）             |

> 桌面扩展（`tau.desktop`）另提供 Image（过滤空 url）、Attachment（清洗无效附件）、RichText（只读渲染）三个字段与 link 的渲染覆盖；包内 `builtInPlugins` 只含上表十项。

> 过滤操作符文本定义位于各插件 `filters` 字段，与 `FilterPanel` 下拉值一致。

### 4.3 PluginManager 行为

- 注册：`registerPlugin` 遇重复 type 报错，显式替换用 `replacePlugin`；内置插件与扩展贡献（`fieldTypes`/`fieldOverrides`）在装配扩展时统一注册（D-128）。字段插件没有 `onMount/onUnmount`，实例级启停由扩展 `activate()` 承担。
- 数据转换：`transformBeforeSave/transformAfterLoad` 包装 `beforeSave/afterLoad`。
- 搜索：若插件未实现，回落字符串包含。
- 能力查询：`hasCapability(type, capability)` 按插件 `capabilities` 判定，未注册类型或未声明该能力均返回 false；视图与面板不按列类型名特判。

## 五、视图渲染管线

### 5.1 表格视图 TableView

- 虚拟滚动：`@tanstack/react-virtual` 以行维度虚拟化；`estimateSize=40`，overscan 10。
- 头部：`ColumnHeader` 支持拖拽（react-dnd）、双击编辑、右键删除、列宽拖动；主列不可删。
- 行：`Row` 组件根据 `selectedCell/editingCell` 高亮；双击进入编辑（Editor 渲染）。
- 列顺序：`visibleColumnOrder` = `viewConfig.columnOrder` + 补全新列（并过滤 hidden）。
- 分组：投影（`core/projection.ts` 的 `projectDatabase`）返回 groups；若 grouped，则生成 header 行（插件 Renderer 渲染分组值）。
- 添加行：底部按钮（可禁用），默认调用 store.addRow；若传入 onRowAdd 使用外部逻辑。

### 5.2 画廊视图 GalleryView

- 响应式列数：ResizeObserver 计算容器宽度，最小 320px，1~6 列。
- 虚拟化维度：以「卡片行」为虚拟项；每行 cards=columnsPerRow；空分组仍渲染 AddCard。
- 分组头：使用插件 Renderer 渲染分组值 + 计数。
- 行新增：若当前分组非空，新增行默认带分组字段值。

### 5.3 日历视图 CalendarView

- 依赖声明 `capabilities.date` 的日期列（经 `hasCapability` 判定，视图类型元数据在 `views/registry.ts`）；`dateConfig.isRange` 决定 endDate 取值。
- 行映射为事件：`{id,title,startDate,endDate,color,rowData}`，title 取主列或“未命名”。
- 点击日期/拖拽区间：创建新行并设置日期列；可自定义 onRowAdd。

### 5.4 看板视图 KanbanView

- 依赖声明 `capabilities.singleOption` 的单选列；分组键为 optionId，未设置/未知选项归“未分类”。
- 列顺序：`kanbanConfig.columnOrder`；新选项会追加。
- 行拖拽排序/移动：更新 viewConfig.rowOrder 与行数据的分组字段。

### 5.5 视图公共组件

- `ViewTabs`：视图拖拽排序、重命名、删除、新建（所需列按字段能力校验）、筛选/分组/排序/搜索入口（搜索框写 `store.setQuery`，会话查询不写入视图配置）。
- `FilterPanel`：树状条件编辑；使用插件 `filters` 生成操作符与默认值；深拷贝保证撤销。
- `GroupPanel/SortPanel/ViewEditPanel`：对应设置 Popover（`@tau/ui`）。
- `ViewTypeSelectModal`：类型卡片与必填列校验由 `views/registry.ts` 元数据驱动。

## 六、交互与快捷操作

- **键盘导航**：`useKeyboardNavigation` 监听箭头/Enter/Space，按实例根节点仲裁（仅作用于事件目标所在实例，让位输入与输入法组合）；非编辑态时可进入编辑（若插件 editable）。
- **列宽调整**：`useColumnResize` 绑定 mousemove/up，最小宽 50，同步 `columnWidths` 和 `viewConfig.columnWidths`。
- **行/列拖拽**：表格行列使用 react-dnd；看板列顺序取决于 option 顺序。
- **右键/确认**：删除视图/行等确认弹窗为 `@tau/ui` 的 `ConfirmDialog` / `Dialog`；readonly 时禁用交互入口。
- **搜索与分组**：投影顺序（`projectDatabase`）为：公式派生 → 过滤 → 搜索 → 排序 → 分组/rowOrder 合并。

## 七、视图管理与持久化流程

1. **创建视图**：`ViewTabs.handleCreateView` 复制当前 config → 填充日历/看板特定配置 → 调用 `onCreateView` → 更新 store.views/activeViewId，并写入 store 中的配置（calendar/kanban）。
2. **删除视图**：确认后调用 `onDeleteView`，成功则替换 views 并更新 activeViewId。
3. **重命名/更新视图**：`handleUpdateView` 调用后端，成功后写入 store.views；若当前 active，同时更新 viewConfig 中的 gallery/calendar/kanbanConfig。
4. **排序视图**：`onReorderViews` 按拖拽顺序设置 order，传回外部。
5. **数据/配置上行**：`Database.tsx` 订阅 store，按 `lastChange`（source 为 "user"）在 dataChanged/viewChanged 时调用 `onDataChange/onViewConfigChange`；外部变更经 `ref.dispatch(command, "external")`，不触发保存回调。

## 八、行详情与富文本

- 入口：`RowDetailModal`（包内骨架：左正文、右属性栏）。打开来源：表格/画廊/看板的行点击，或外部回调（宿主传 `onRowDetailOpen` 时由宿主接管，如卡片库）。
- 富文本：正文由宿主插槽 `RowDetailBody` 提供（桌面为 ContentEditor 会话）；关闭与切换行前等待插槽 ref 的 `flush()`，卸载后补丁经 `onDetachedRowPatch` 提交（带原行预期值，迟到结果不能重建已删除行）。
- 正文落库：新建正文一律 `createPendingContent`（ref 0 + 待回收登记），保存进表时由主进程差集 retain；补丁被拒不硬删，无人引用时留给开库回收（D-129）。
- 属性编辑：支持在详情侧新增/编辑/删除列（受 readonly/allowDeleteColumn 控制）；属性与标题实时写回 store；删列是纯数据操作，正文引用由主进程数据层按差集维护（D-129）。
- 列排序：属性栏上移/下移（`store.moveColumn`），非拖拽。

---

## 九、性能与优化点

- **虚拟滚动**：表格/画廊采用 react-virtual；保证 `estimateSize` 接近期望高度，减小抖动。
- **投影条件重算**：store 的 `commit` 只在数据/视图/查询变化时重算 `projectDatabase`；大数据集时注意筛选条件树的深度与插件 filter 的单行成本。
- **列宽与可见列**：隐藏列不渲染，`useColumnVisibility` 管理 hidden 集合。
- **搜索/筛选**：投影按需短路（无条件时直接返回）；可为重型过滤器加 try-catch 防御。
- **历史长度**：默认 50，可调；频繁调用 commitHistory 会增大内存，占用需注意。
- **图片/附件清洗**：桌面字段的 beforeSave/afterLoad 过滤空 url，避免冗余数据。

## 十、扩展指南（列类型/视图/筛选）

### 10.1 新列类型

1. 新建 `plugins/MyPlugin/index.tsx`，实现 `CellPlugin`。
2. 提供 Renderer（必需）与 Editor（若 editable）。
3. 定义数据格式并在 `beforeSave/afterLoad` 归一化；提供 `sort/getGroupKey/filters/search`。
4. 如需作为日历日期列、看板分组列或封面图片列，声明 `capabilities`（视图按能力判定，不认列类型名）。
5. 在 `plugins/index.ts` 注册，或经扩展的 `fieldTypes` 贡献（D-128）。
6. 若需自定义筛选 UI，可在 `FilterPanel` 侧扩展操作符文本与初始值逻辑。

### 10.2 新视图类型（需同步 @tau/shared）

1. 扩展 `DataTableView.type` 与 `TableViewConfig`。
2. 新增视图组件（参考 Table/Gallery），透传 `pluginManager/theme/readonly` 与行/列回调。
3. 在 `views/registry.ts` 登记类型元数据（名称/图标/创建所需列/初始配置片段），在 `views/components.ts` 注册组件映射；渲染与创建弹窗均由注册表驱动，不再在 `ViewTabs`/`Database.tsx` 加分支（`constants/viewType.ts` 已删除，D-128）。
4. 持久化专属配置到 viewConfig，`onUpdateView` 回写并在 store 中设置。

### 10.3 筛选/排序扩展

1. 在插件 `filters` 添加操作符及 `getInitialValue`。
2. `FilterPanel` 会自动读取插件 filters；注意 operator 文本唯一。
3. 若需要全局排序策略，可在插件 `sort` 中加入优先级或自定义 compare。

## 十一、常见问题排查

- **筛选/排序不生效**：确认插件 filters/sort 实现；FilterGroup 的 operator 是否和插件一致；检查是否把外部变更误当 props 传入（外部更新必须经 `ref.dispatch`）。
- **看板/日历无法创建视图**：检查是否存在声明 `capabilities.singleOption`/`capabilities.date` 的列（经 `hasCapability` 判定，公式列结果为日期也不算），`views/registry.ts` 的元数据是否正确。
- **列删除后正文疑似泄漏**：删列直接走 `deleteColumn`，插件与组件均不做资源清理；富文本单元格 contentId 由主进程 `DataTableTable` 在每条写路径的事务内按新旧差集 `retain`/`releaseDeferred`，释放到 0 只登记 `content_pending_releases`，开库时回收超过 7 天宽限期且引用仍为 0 的正文（D-129）。排查时查该表登记与 `released_at`；宽限期内撤销、粘贴会重新引用并撤销登记。
- **行详情未保存**：正文在关闭/切换前经插槽 `flush()` 落库；确认 `createPendingContent` 成功并回写 `detailContentId`，卸载后补丁经 `onDetachedRowPatch` 是否被主进程拒绝（目标行已删除或旧值冲突）。
- **键盘导航失效**：检查 `useKeyboardNavigation` 监听是否被阻断（只读/编辑态）；键盘按实例根节点仲裁，焦点在其他实例或输入框上时不响应。
- **数据同步异常**：外部变更改 props 不会覆盖本地编辑（重渲染不覆盖）；确认外部更新是否经 `ref.dispatch(command, "external")` 下发。
- **虚拟滚动错位**：调整 `estimateSize`，确保 Row/卡片高度稳定；避免动态高度导致跳动。

## 附录：关键函数与调用关系

- 入口事件流：`Database.tsx` → 视图组件内部回调（单元格/列/行操作）→ store `commit` → `lastChange` → `onDataChange/onViewConfigChange`。
- 过滤管线：`core/projection.ts` 的 `projectDatabase`：公式派生 → filters → search → sorts → rowOrder 合并 → groupBy → 各视图按 `projection.rowIds/groups` 渲染（表格 flatItems、画廊虚拟卡片行）。
- 视图创建：`ViewTabs` → `Database.handleCreateView`（注册表 `createConfig` 追加专属配置）→ `onCreateView` → `dispatch({ type: "view.receive" }, "external")` → set\*Config。
- 列编辑：`ColumnEditModal` → `handleSaveColumn`（各视图内）→ store.editColumn/addColumn → commitHistory。
- 行详情：`RowDetailModal` → 属性实时写回（`updateCellValue` / 卸载后经 `DatabaseWriteContext` 的 `commitRowPatch`）→ 正文插槽 `flush()` → 宿主 `createPendingContent` + `onRowChange` 回写 `detailContentId`。
- 键盘导航：`useKeyboardNavigation` → `moveCellSelection` / `startEditing`。
- 列宽：`useColumnResize.startResize` → mousemove → store.resizeColumn → 写入 columnWidths + viewConfig。
