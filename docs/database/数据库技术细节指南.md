## 一、总览与文件结构

- 入口：`Database.tsx` —— 组装插件、创建 Zustand store、绑定键盘/列宽事件、渲染视图与 tabs。
- 状态：`DatabaseStore.ts` —— 单一数据源（columns/rows/viewConfig/history/selection）。
- 插件：`plugins/*` —— 列类型实现、过滤/排序/分组/搜索策略、beforeSave/afterLoad。
- 视图：`views/TableView | GalleryView | CalendarView | KanbanView` —— 同源数据，不同呈现。
- 工具与 Hook：`hooks/*`（过滤排序分组、列宽、可见列、键盘导航、校验）。
- 组件：`components/RowDetailModal`、`ViewTabs`、`FilterPanel/GroupPanel/SortPanel` 等。
- 常量：`constants/select.ts` 提供多选/单选颜色配置。

## 二、数据模型与核心类型

### 2.1 Column / Row / DatabaseData

- `ColumnDef`：id/title/type/config/width/hidden/isPrimary/validation 等。`config` 由插件自定义（如日期格式、选择项）。
- `RowData`：`{ id: string; [columnId]: CellValue }`，行的自定义字段来自列 id。
- `CellValue`：插件决定具体形态，例如：
  - text/number: string | number | null
  - date: `{ start: number|null; end: number|null }`
  - select: `optionId:string`
  - multi-select: `Array<{id,name,color}>`
  - image: `ImageItem[]`

### 2.2 ViewConfig

`TableViewConfig`（从 @tau/shared）：

- `columnOrder`: string[] —— 列顺序；`columnWidths`: id→width
- `rowOrder`: string[] —— 行顺序
- `groupBy`: { fieldId, strategy }
- `sorts`: SortRule[]（priority + field + direction）
- `filters`: FilterGroup（树形条件）
- 扩展：`galleryConfig`（封面类型/图片列）、`calendarConfig`（日期列）、`kanbanConfig`（分组列/列顺序）

### 2.3 Selection/Editing

- `selectedCell`: { rowId, columnId } | null
- `editingCell`: { rowId, columnId } | null
- `searchKeyword`: 全局搜索关键字

## 三、状态管理与历史

### 3.1 createDatabaseStore 初始化

- 合并列宽：`mergedColumnWidths = viewConfig.columnWidths || col.width || 200`
- 行/列顺序回落：若 viewConfig 缺失则用初始数据顺序。
- 复制过滤器/配置：`cloneFilters` 深拷贝，gallery/calendar/kanban 配置浅拷贝。

### 3.2 操作类函数

- **updateCellValue**：写入前 `commitHistory`，仅替换目标 cell。
- **addRow/deleteRow/moveRow**：同步更新 `viewConfig.rowOrder`。
- **addColumn/deleteColumn/moveColumn**：同步 `viewConfig.columnOrder` 与 `columnWidths`；删除列会遍历行删除字段。
- **deleteColumnWithCleanup**：先执行插件 `onColumnCleanup`，再删除列。
- **setGroupBy/setSorts/setFilters**：写入 viewConfig，filters 深拷贝。
- **syncExternalData**：与 props 比对（JSON 字符串），检测 columns/rows/viewConfig 变化后同步 state 和列宽。

### 3.3 历史与撤销

- `commitHistory`：最多 50 条；如果 redo 栈存在且有新操作，先截断 redo。
- `undo/redo`：恢复 columns/rows/viewConfig（基础字段），未包含 gallery/calendar/kanban？→ 在 setViewConfig 时会带上扩展配置，保证回放完整。
- 归并策略：无时间窗口，直接按调用顺序入栈；调用者需在批量更新前自行控制调用频率（例如 updateCellValue 内已 commit）。

## 四、插件体系详解（列类型）

### 4.1 CellPlugin 能力回顾

- `Renderer`（必需）+ `Editor`（可选，editable=true 时触发双击编辑）。
- `beforeSave/afterLoad`：格式归一化与容错。
- `getGroupKey`：分组键；`sort`：排序比较；`filters`：筛选操作符；`search`：自定义搜索。
- `onColumnCleanup`：删除列前回收资源。

### 4.2 内置插件要点

| 插件        | 值格式      | 过滤/排序               | 特殊逻辑                                                      |
| ----------- | ----------- | ----------------------- | ------------------------------------------------------------- |
| Text        | string      | 包含/不包含/为空/不为空 | search 小写包含                                               |
| Number      | number      | >= <= =                 | sort 按数值，过滤条件包含范围                                 |
| Date        | {start,end} | 多种比较（开始/结束）   | beforeSave/afterLoad 兼容 number/Date；isRange 切换 end=start |
| Select      | optionId    | equals/not/null         | `getGroupKey` 用 optionId，看板依赖                           |
| MultiSelect | option[]    | 包含/不包含/为空        | search 按名称包含，颜色来自 SELECT_COLORS                     |
| Checkbox    | boolean     | is true/false/null      | search 按 bool                                                |
| Link        | {url,text}? |                         | Renderer 展示链接                                             |
| Star        | number      | 数值排序                | 评分组件                                                      |
| Image       | ImageItem[] | 不参与搜索              | beforeSave/afterLoad 过滤空 url                               |
| Attachment  | 类似 Image  | 过滤无效附件            |
| Progress    | number      | 范围过滤/排序           | 0-100 条形展示                                                |
| RichText    | Slate desc? | 只读渲染                | 不可编辑（editable=false）                                    |

> 过滤操作符文本定义位于各插件 `filters` 字段，与 `FilterPanel` 下拉值一致。

### 4.3 PluginManager 行为

- 注册/加载：`registerPlugins` + `loadAllPlugins`（调用 onMount）；卸载对应 onUnmount。
- 数据转换：`transformBeforeSave/transformAfterLoad` 包装 `beforeSave/afterLoad`。
- 搜索：若插件未实现，回落字符串包含。
- 删除列：`executeColumnCleanup` 调用插件清理。

## 五、视图渲染管线

### 5.1 表格视图 TableView

- 虚拟滚动：`@tanstack/react-virtual` 以行维度虚拟化；`estimateSize=40`，overscan 10。
- 头部：`ColumnHeader` 支持拖拽（react-dnd）、双击编辑、右键删除、列宽拖动；主列不可删。
- 行：`Row` 组件根据 `selectedCell/editingCell` 高亮；双击进入编辑（Editor 渲染）。
- 列顺序：`visibleColumnOrder` = `viewConfig.columnOrder` + 补全新列（并过滤 hidden）。
- 分组：`useFilteredAndSortedRows` 返回 groupedRows；若 grouped，则生成 header 行（插件 Renderer 渲染分组值）。
- 添加行：底部按钮（可禁用），默认调用 store.addRow；若传入 onRowAdd 使用外部逻辑。

### 5.2 画廊视图 GalleryView

- 响应式列数：ResizeObserver 计算容器宽度，最小 320px，1~6 列。
- 虚拟化维度：以「卡片行」为虚拟项；每行 cards=columnsPerRow；空分组仍渲染 AddCard。
- 分组头：使用插件 Renderer 渲染分组值 + 计数。
- 行新增：若当前分组非空，新增行默认带分组字段值。

### 5.3 日历视图 CalendarView

- 依赖日期列（校验在 ViewTypeSelectModal）；`dateConfig.isRange` 决定 endDate 取值。
- 行映射为事件：`{id,title,startDate,endDate,color,rowData}`，title 取主列或“未命名”。
- 点击日期/拖拽区间：创建新行并设置日期列；可自定义 onRowAdd。

### 5.4 看板视图 KanbanView

- 依赖单选列；分组键为 optionId，未设置/未知选项归“未分类”。
- 列顺序：`kanbanConfig.columnOrder`；新选项会追加。
- 行拖拽排序/移动：更新 viewConfig.rowOrder 与行数据的分组字段。

### 5.5 视图公共组件

- `ViewTabs`：视图拖拽排序、重命名、删除、新建（校验日期/单选）、筛选/分组/排序/搜索入口。
- `FilterPanel`：树状条件编辑；使用插件 `filters` 生成操作符与默认值；深拷贝保证撤销。
- `GroupPanel/SortPanel/ViewEditPanel`：对应设置 Popover。
- `SearchInput`：更新 `searchKeyword`，进入 `useFilteredAndSortedRows` 搜索流程。

## 六、交互与快捷操作

- **键盘导航**：`useKeyboardNavigation` 监听箭头/Enter/Space；非编辑态时可进入编辑（若插件 editable）。
- **列宽调整**：`useColumnResize` 绑定 mousemove/up，最小宽 50，同步 `columnWidths` 和 `viewConfig.columnWidths`。
- **行/列拖拽**：表格行列使用 react-dnd；看板列顺序取决于 option 顺序。
- **右键/确认**：删除视图/列/行使用 antd Modal；readonly 时禁用交互入口。
- **搜索与分组**：`useFilteredAndSortedRows` 顺序为：过滤 → 搜索 → 排序 → 分组/rowOrder 合并。

---

## 七、视图管理与持久化流程

1. **创建视图**：`ViewTabs.handleCreateView` 复制当前 config → 填充日历/看板特定配置 → 调用 `onCreateView` → 更新 store.views/activeViewId，并写入 store 中的配置（calendar/kanban）。
2. **删除视图**：确认后调用 `onDeleteView`，成功则替换 views 并更新 activeViewId。
3. **重命名/更新视图**：`handleUpdateView` 调用后端，成功后写入 store.views；若当前 active，同时更新 viewConfig 中的 gallery/calendar/kanbanConfig。
4. **排序视图**：`onReorderViews` 按拖拽顺序设置 order，传回外部。
5. **数据/配置上行**：`Database.tsx` 订阅 store，深比较 columns+rows 或 viewConfig 变化后调用 `onDataChange/onViewConfigChange`。注意 JSON 比较的成本与顺序依赖。

## 八、行详情与富文本

- 入口：`RowDetailModal`。打开来源：表格/画廊/看板的行点击，或外部回调。
- 富文本：使用 `@tau/editor`，默认空文档；保存时若内容非空，调用 `createContent/updateContent`，将 `detailContentId` 回写行。
- 列编辑：支持在详情侧新增/编辑/删除列（受 readonly/allowDeleteColumn 控制）；删除列前执行插件清理。
- 拖拽：列在详情中可拖拽重排（react-dnd）。
- 关闭时写回：`onSave` 回调逐字段更新行（忽略 id）。

---

## 九、性能与优化点

- **虚拟滚动**：表格/画廊采用 react-virtual；保证 `estimateSize` 接近期望高度，减小抖动。
- **深比较成本**：订阅回调使用 `JSON.stringify`，大数据集时可考虑哈希/浅比较优化。
- **列宽与可见列**：隐藏列不渲染，`useColumnVisibility` 管理 hidden 集合。
- **搜索/筛选**：在 `useFilteredAndSortedRows` 中短路无条件时直接返回；可为重型过滤器加 try-catch 防御。
- **历史长度**：默认 50，可调；频繁调用 commitHistory 会增大内存，占用需注意。
- **图片/附件清洗**：beforeSave/afterLoad 过滤空 url，避免冗余数据。

## 十、扩展指南（列类型/视图/筛选）

### 10.1 新列类型

1. 新建 `plugins/MyPlugin/index.tsx`，实现 `CellPlugin`。
2. 提供 Renderer（必需）与 Editor（若 editable）。
3. 定义数据格式并在 `beforeSave/afterLoad` 归一化；提供 `sort/getGroupKey/filters/search`。
4. 如需资源清理，实现 `onColumnCleanup`。
5. 在 `plugins/index.ts` 注册，或通过 `Database` 的 `plugins` prop 注入。
6. 若需自定义筛选 UI，可在 `FilterPanel` 侧扩展操作符文本与初始值逻辑。

### 10.2 新视图类型（需同步 @tau/shared）

1. 扩展 `DataTableView.type` 与 `TableViewConfig`。
2. 新增视图组件（参考 Table/Gallery），透传 `pluginManager/theme/readonly` 与行/列回调。
3. 在 `ViewTabs` 新增视图按钮与创建校验；在 `Database.tsx` 渲染分支添加新视图。
4. 持久化专属配置到 viewConfig，`onUpdateView` 回写并在 store 中设置。

### 10.3 筛选/排序扩展

1. 在插件 `filters` 添加操作符及 `getInitialValue`。
2. `FilterPanel` 会自动读取插件 filters；注意 operator 文本唯一。
3. 若需要全局排序策略，可在插件 `sort` 中加入优先级或自定义 compare。

## 十一、常见问题排查

- **筛选/排序不生效**：确认插件 filters/sort 实现；FilterGroup 的 operator 是否和插件一致；检查 JSON 深比较导致的视图配置未更新。
- **看板/日历无法创建视图**：检查是否存在单选/日期列，`ViewTypeSelectModal` 的校验是否被覆盖。
- **列删除未清理资源**：确认插件实现 `onColumnCleanup`；`deleteColumnWithCleanup` 是否被调用而非 `deleteColumn`。
- **行详情未保存**：关闭弹窗时才写回；确认 `createContent/updateContent` 成功并回写 `detailContentId`。
- **键盘导航失效**：检查 `useKeyboardNavigation` 监听是否被阻断（只读/编辑态）；表格焦点是否在输入框上。
- **数据同步异常**：外部传入的 columns/rows/viewConfig 若引用变化，会触发 `syncExternalData` 覆盖本地；确保上层数据稳定或有节制地变更。
- **虚拟滚动错位**：调整 `estimateSize`，确保 Row/卡片高度稳定；避免动态高度导致跳动。

## 附录：关键函数与调用关系

- 入口事件流：`Database.tsx` → `useEventHandlers` (视图内部) → store 操作 → `onDataChange/onViewConfigChange`。
- 过滤管线：`useFilteredAndSortedRows`：filters → search → sorts → rowOrder 合并 → groupBy → 展平为 flatItems（表格）或虚拟行（画廊）。
- 视图创建：`ViewTabs.handleCreateView` → `onCreateView` → store.setState(views/activeViewId) → set\*Config。
- 列编辑：`ColumnEditModal` → `handleSaveColumn` → store.editColumn/addColumn → commitHistory。
- 行详情：`RowDetailModal` → 编辑 → 关闭时 create/updateContent → `onSave` → `updateCellValue`。
- 键盘导航：`useKeyboardNavigation` → `moveCellSelection` / `startEditing`。
- 列宽：`useColumnResize.startResize` → mousemove → store.resizeColumn → 写入 columnWidths + viewConfig。
