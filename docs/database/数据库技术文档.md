## 一、项目概述

### 1.1 技术栈

| 技术                    | 版本    | 作用                                                       |
| ----------------------- | ------- | ---------------------------------------------------------- |
| React                   | ^19.2.0 | UI 框架（peerDependency，宿主提供）                        |
| TypeScript              | ^5.x    | 类型安全                                                   |
| Zustand                 | ^4.3.8  | 状态管理与快照记录                                         |
| ahooks                  | ^3.7.8  | 高阶 Hook（useCreation/useMemoizedFn 等）                  |
| @tau/ui                 | -       | UI 组件（Dialog/ConfirmDialog/Menu/Popover/EditText 等）   |
| @tau/themes             | -       | 主题运行时与 Tailwind token（颜色只消费 `--tau-*` 语义类） |
| react-dnd               | ^16.x   | 列/视图拖拽排序（peerDependency，宿主提供 DndProvider）    |
| @tanstack/react-virtual | 3.13.x  | 表格/画廊虚拟滚动                                          |
| dayjs                   | ^1.11   | 日期处理（日历视图）                                       |
| uuid                    | ^9.x    | 行/列主键生成                                              |
| immer / lucide-react    | -       | store 不可变更新 / 图标                                    |

### 1.2 核心特性

1. **多视图**：表格 / 画廊 / 日历 / 看板四种视图共享同一数据与列定义。
2. **插件化列类型**：通过 `CellPlugin` 抽象列的渲染、编辑、排序、分组、筛选与搜索策略。
3. **视图配置持久化**：列顺序、宽度、行顺序、分组、排序、筛选、画廊/日历/看板专属配置均写入 `viewConfig`。
4. **虚拟化与键盘导航**：大列表虚拟滚动、列拖拽/宽度调整、单元格键盘导航与编辑。
5. **富文本详情**：行详情骨架在包内（左正文、右属性栏），正文、图片与画廊封面由宿主经扩展插槽提供（`RowDetailBody`/`Image`/`GalleryCover`）；桌面侧正文经 `createPendingContent` 创建，正文引用由主进程数据层按差集维护并延迟回收，组件不做资源清理（D-136）。
6. **可插拔扩展**：经 `extensions` 声明式装配字段类型、字段覆盖与插槽（D-135），外部另有视图增删改、行/列增删、自定义回调。桌面统一经 `features/shared/database/DesktopDatabase` 装配 `tau.desktop` 扩展。
7. **查询投影与公式**：筛选/搜索/排序/分组与公式列派生统一在 `core/projection.ts` 的 `projectDatabase` 中完成，四种视图与键盘导航共用；表尾汇总与公式共用一棵受限表达式树（D-121），公式值只在投影中派生、不落库。

## 二、核心架构

### 2.1 组件分层

- **入口**：`Database.tsx`（`packages/database/src/Database.tsx`）负责扩展装配（`installDatabaseExtensions`）、Zustand store 创建、主题合并、回调透传及视图选择。
- **上下文**：`DatabaseContext` 暴露 store，所有子组件通过 `useDatabaseStore` 读取/更新；`DatabaseHostContext` 提供扩展插槽，`DatabaseWriteContext` 提供卸载后的行补丁提交，`DatabaseFocusContext` 提供编辑器提交后的焦点归还。
- **插件管理**：`PluginManager` 负责注册/加载插件、执行 beforeSave/afterLoad、排序/分组/筛选/搜索策略。
- **视图容器**：`ViewTabs` 控制视图切换、新建/重命名/删除/排序等操作，主体视图经 `views/components.ts` 的组件映射由当前 active view 决定。
- **子视图**：`TableView`、`GalleryView`、`CalendarView`、`KanbanView` 共享相同数据层（store 内的统一投影），按视图配置差异化渲染。

### 2.2 数据模型（简化）

```ts
// packages/database/src/types.ts
export interface DatabaseProps {
  data: RowData[];
  columns: ColumnDef[];
  views: DatabaseView[];          // 通用视图协议：只有界面需要的标识/名称/类型/顺序/配置
  activeViewId: number;
  viewConfig: TableViewConfig;
  extensions?: readonly DatabaseExtension[]; // 声明式扩展（D-135），集合须引用稳定
  config?: DatabaseConfig;          // 开关：增/删行列
  onDataChange?: (data, change) => void;    // columns + rows，仅用户操作触发
  onViewConfigChange?: (config) => void;
  onActiveViewIdChange?: (viewId) => Promise<void>;
  // 视图 CRUD 回调（后端持久化）
  onCreateView?: (...) => Promise<DatabaseView | null>;
  onDeleteView?: (id) => Promise<number | null>;
  onRenameView?: (...args) => Promise<DatabaseView | null>;
  onUpdateView?: (...args) => Promise<DatabaseView | null>;
  onReorderViews?: (ids) => Promise<void>;
  // 行相关
  onRowDetailOpen?: (row) => void;
  onRowAdd?: (defaultData?) => void;
  onRowDelete?: (rowId) => Promise<void>;
  onRowCleanup?: (row) => void | Promise<void>;       // 删除前的行快照，宿主释放资源引用
  onDetachedRowPatch?: (rowId, patch, previousRow) => Promise<boolean>; // 卸载后的行补丁
  // 主题/只读
  theme?: "light" | "dark";
  readonly?: boolean;
  bare?: boolean;   // 铺在页面纸上：去掉卡片外壳
  className?: string;
}
```

### 2.3 Store 设计（Zustand）

`DatabaseStore.ts` 是核心单一数据源，记录 columns/rows/views/viewConfig/历史栈/选择态与查询投影等：

- **快照与历史**：`commitHistory` 每次数据写入前推入快照（最多 50 条）；`undo/redo` 恢复列/行/视图配置。
- **视图配置**：`columnOrder`、`rowOrder`、`columnWidths`、`groupBy`、`sorts`、`filters`、`footer`（表尾汇总），以及视图专属配置 `galleryConfig`、`calendarConfig`、`kanbanConfig`。
- **行列操作**：`addRow/deleteRow/addColumn/deleteColumn/moveRow/moveColumn`；删列是纯数据操作，正文引用由主进程按差集维护（D-136），删行经宿主 `onRowCleanup` 回调清理。
- **单元格状态**：`selectedCell`、`editingCell` 配合键盘导航；`moveCellSelection` 处理上下左右移动。
- **查询投影**：`setQuery` 更新会话查询（不写入视图配置）；`commit` 内在数据/视图/查询变化时经 `core/projection.ts` 的 `projectDatabase` 重算投影（含公式列派生），四种视图、键盘导航与拖拽共用。
- **外部同步**：挂载后的外部变更经 `DatabaseRef.dispatch(command, "external")`（`rows.apply` 提交字段差量、`rows.receive` 提交确认快照），不触发保存回调。

### 2.4 渲染与注入流程

1. `installDatabaseExtensions` 装配内置插件与 `extensions` 贡献的字段类型、字段覆盖与插槽；重复类型、缺失覆盖目标、重复插槽键均报错（D-135）。
2. 创建 `createDatabaseStore`，将 columns/data/viewConfig/views/activeViewId 初始化到 Zustand。
3. `useEffect` 订阅 store 变更：按 `lastChange`（source 为 "user"）分别触发 `onDataChange` 与 `onViewConfigChange`。
4. 绑定列宽拖拽（`useColumnResize`）与键盘导航（`useKeyboardNavigation`，按实例根节点仲裁，让位输入与输入法组合）。
5. 根据 `activeViewId` 经 `views/components.ts` 的 `getViewComponent` 渲染对应视图组件，统一透传插件管理器、主题、只读状态与行/列操作回调；插槽经 `DatabaseHostContext` 下发。

## 三、插件体系与列类型

### 3.1 CellPlugin 接口

```ts
// types.ts
export interface CellPlugin<T> {
  type: string; // 列类型标识
  name: string; // 在 UI 中展示的名称
  capabilities?: FieldCapabilities; // 字段能力声明（date/singleOption/boolean/images）
  Icon?: React.ComponentType<{ className?: string }>; // 列头图标
  Renderer: React.FC<{ value; column; theme; readonly; onCellValueChange }>;
  Editor?: React.FC<{
    value;
    column;
    onCellValueChange;
    onFinishEdit;
    onColumnChange;
    theme;
    readonly;
  }>;
  editable?: boolean; // 是否可进入编辑态
  getGroupKey?: (row, column, granularity?) => string;
  sort?: ({ a, b, direction, columnConfig, rowA, rowB }) => number;
  filters?: CellFilterDefinition<T>[] | ((column) => CellFilterDefinition<T>[]); // 可按列给出
  search?: (keyword, cellValue, column, row) => boolean;
  beforeSave?: (value, config) => CellValue; // 写入前转换
  afterLoad?: (value, config) => CellValue; // 读出后转换
  valueType?: ValueType | ((column) => ValueType | undefined); // 参与汇总与公式的值类型
  toScalar?: (value, column) => Scalar; // 存储值 → 参与运算的标量
  formatScalar?: (value, column) => string; // 数值汇总的展示文本
}
```

### 3.2 内置列类型

| 类型         | 主要特性                               | 关键点                                                                                  |
| ------------ | -------------------------------------- | --------------------------------------------------------------------------------------- |
| text         | 文本渲染/编辑，包含搜索、包含/为空筛选 | `filters` 定义四类字符串筛选                                                            |
| number       | 数字渲染/区间比较                      | 自定义排序，筛选支持范围                                                                |
| date         | 单/区间日期，格式归一化 `{start,end}`  | `beforeSave/afterLoad` 兼容旧数据；分组/排序字段可配置                                  |
| select       | 单选（含颜色配置）                     | `getGroupKey` 支持分组，看板依赖该类型                                                  |
| multi-select | 多选标签                               | 颜色配置/包含匹配                                                                       |
| checkbox     | 勾选布尔                               | 搜索/筛选基于布尔值                                                                     |
| link         | 链接渲染                               | 可搜索；桌面扩展覆盖其 Renderer 以支持应用内链接                                        |
| star         | 星级                                   | 可排序                                                                                  |
| progress     | 进度条                                 | 数值排序/筛选                                                                           |
| formula      | 公式列                                 | 表达式存 `config`，值只在投影中派生 `{ value, error? }`，可筛选/排序/搜索/分组（D-121） |

图片（image）、附件（attachment）与富文本（rich-text）字段不在包内：由桌面扩展 `tau.desktop`（`features/shared/database/desktopExtension.tsx`）经 `fieldTypes`/`fieldOverrides` 贡献，缺失插件的字段不可编辑并保留原值。

插件注册入口：`plugins/index.ts`，统一写入 `builtInPlugins`，在 `Database.tsx` 装配扩展时作为内置字段类型注册。

### 3.3 插件生命周期

- **注册**：`PluginManager.registerPlugin` 遇重复 type 报错，显式替换用 `replacePlugin`；外部字段类型与覆盖经 `extensions` 装配（D-135，详见 `packages/database/README.md`）。
- **实例挂载**：字段插件没有 `onMount/onUnmount`；扩展的 `activate()` 在每个实例挂载时启动，返回的清理函数在卸载时执行。
- **值转换**：单元格保存/加载时调用 `beforeSave/afterLoad`，保障存储格式一致（如日期、图片列表）。
- **能力与清理**：视图与面板只经 `PluginManager.hasCapability` 判定字段可用性（读取 `capabilities`，不按列类型名特判）；删列无插件清理钩子，正文引用由主进程按差集维护并延迟回收（D-136），删行清理走宿主 `onRowCleanup`。
- **搜索/筛选/排序/分组**：统一由 `PluginManager` 分发，视图逻辑只依赖通用接口。

## 四、视图系统

### 4.1 表格视图（TableView）

- 文件：`views/TableView/index.tsx`
- 特性：列拖拽排序、列宽调整、虚拟滚动（@tanstack/react-virtual）、行拖拽、单元格编辑/选择/键盘导航、行详情弹窗、列编辑弹窗、表尾汇总行（`FooterRow`，配置存 `viewConfig.footer`，按视图持久化，汇总输入是投影后的行）。
- 可配置：是否允许新增/删除列/行（`DatabaseConfig`），主列不可删除。
- 列头：`ColumnHeader` 支持拖拽、双击编辑、更多菜单删除，显示插件 Icon。
- 数据变更：`handleCellChange` 调用插件 `beforeSave` 再写入 store。

### 4.2 画廊视图（GalleryView）

- 文件：`views/GalleryView/index.tsx`
- 特性：卡片瀑布流 + 虚拟行，支持分组头、卡片数量展示，响应式列数（ResizeObserver）。
- 画廊配置：`viewConfig.galleryConfig` (`coverType: detail|image`、`coverImageColumnId`)；封面正文/资源预览由宿主 `GalleryCover` 插槽提供。
- 行新增：支持在分组下继承分组字段初始值。

### 4.3 日历视图（CalendarView）

- 文件：`views/CalendarView/index.tsx`
- 依赖：至少一个日期列（在 `ViewTypeSelectModal` 中验证）。
- 配置：`viewConfig.calendarConfig.dateColumnId`，日期列按字段能力判定（插件声明 `capabilities.date`，经 `hasCapability` 查询，不按类型名特判）。
- 事件：将行映射为 `{id,title,startDate,endDate}`，标题优先取主列。支持点击日期创建行（区间/单点）。

### 4.4 看板视图（KanbanView）

- 文件：`views/KanbanView/index.tsx`
- 依赖：声明 `capabilities.singleOption` 的列作为分组列（`kanbanConfig.groupColumnId`），列顺序可通过 `kanbanConfig.columnOrder` 持久化。
- 行分配：按单选值归类，缺失选项归入“未分类”。
- 支持拖拽行移动、行详情、列配置。

## 五、状态与数据流

### 5.1 数据同步

- **初始化**：`createDatabaseStore(columns, data, viewConfig, views, activeViewId)`；重渲染不覆盖本地编辑。
- **用户编辑**：`Database.tsx` 订阅 store，按 `lastChange`（source 为 "user"）触发 `onDataChange` / `onViewConfigChange`。
- **外部更新**：挂载后经 `DatabaseRef.dispatch(command, "external")`——`rows.apply` 提交字段差量、`rows.receive` 提交确认快照（保留其他本地草稿）；不触发保存回调。桌面适配（`DesktopDatabase`）在 tableId 数据变化时以 `rows.receive` 接回。

### 5.2 历史与撤销

- `commitHistory` 在每次写操作前记录快照（最大 50 条）。
- `undo/redo` 仅恢复 columns/rows/viewConfig 基础字段，附加配置（gallery/calendar/kanban）在写入 viewConfig 时已包含。

### 5.3 行/列生命周期

- **新增行**：缺省填充所有列为 `null`，写入 `viewConfig.rowOrder`。
- **删除行**：store 只调用宿主 `onRowCleanup`（接收删除前的行快照）；数据表的正文引用由主进程按差集释放并延迟回收（D-136）。
- **新增列**：生成列 id，附带默认宽度与行默认值。
- **删除列**：直接 `deleteColumn` 从列/行/列宽（及该列表尾汇总配置）中移除；富文本单元格正文引用由主进程数据层按差集维护，组件不做资源清理（D-136）。

### 5.4 键盘与选区

- `useKeyboardNavigation` 监听全局方向键/Enter/Space，驱动 `moveCellSelection` 和进入编辑态。
- 选区状态存储在 store，TableView/Row 组件按选区高亮。

## 六、筛选/排序/分组/搜索

- **筛选**：`FilterPanel.tsx` 以嵌套组的形式构建条件树（`FilterGroup`），叶子节点由插件 `filters` 定义操作符/初始值/是否需要值（读取统一经 `PluginManager.getFilterDefinitions(column)`）；`core/projection.ts` 的 `projectDatabase` 递归执行。
- **排序**：`viewConfig.sorts` 支持多字段 + priority，按插件 `sort` 实现比较；无排序时回落到 `rowOrder`。
- **分组**：`groupBy.fieldId` 需插件实现 `getGroupKey`；Table/Gallery 支持分组头，看板使用独立分组逻辑。
- **搜索**：`ViewTabs` 内的搜索框写入 `store.setQuery({ text })`（会话查询，不写入视图配置）；投影内 `PluginManager.executeSearch` 优先插件搜索，否则字符串包含。

---

## 七、视图管理与配置

- **视图切换与 CRUD**：`ViewTabs` 处理 active 状态、拖拽排序（react-dnd）、重命名（内联 `EditText`）、删除（`@tau/ui` `ConfirmDialog` 确认）、创建（`ViewTypeSelectModal`）。
- **视图创建校验**：视图类型元数据（名称/图标/创建所需列/初始配置片段）集中在 `views/registry.ts`，组件映射在 `views/components.ts`（`constants/viewType.ts` 已删除，D-135）；日历/看板所需列按字段能力判定，无候选列时不可创建；创建时复制当前视图配置并附加专属配置。
- **视图更新**：`handleUpdateView` 持久化后同步 store，若更新当前视图则写入 `galleryConfig`/`calendarConfig`/`kanbanConfig`。
- **配置入口**：`GroupPanel`、`SortPanel`、`FilterPanel`、`ViewEditPanel` 通过 `@tau/ui` 的 Popover/Menu 弹出。

## 八、行详情与富文本

- 文件：`components/RowDetailModal/index.tsx`（左正文、右属性栏，宽度不足 960 时退化为单栏，同一棵树只靠容器查询重排）。
- 正文：由宿主插槽 `RowDetailBody` 提供（桌面为 `features/shared/database/RowDetailBody.tsx`，编辑经 ContentEditor 会话）；关闭与切换行前等待插槽 ref 的 `flush()`，宿主把新建正文经 `createPendingContent`（ref 0 + 待回收登记）落库并经 `onRowChange` 回写 `detailContentId`；卸载后的补丁经 `onDetachedRowPatch` 提交（带原行预期值）。
- 列操作：详情侧可编辑/删除列（受只读与 `allowDeleteColumn` 限制），删除列直接更新本地行数据，正文引用由主进程数据层按差集维护（D-136）。
- 列排序：详情属性栏支持上移/下移（`store.moveColumn`），非拖拽。
- 上一条/下一条：按当前视图投影后的行序切换。

## 九、对外 API（Props/Ref/回调）

### 9.1 组件 Props（重点）

- `columns` / `data` / `viewConfig` / `views` / `activeViewId`: 必填数据源。
- `extensions`: 声明式扩展集合（`defineDatabaseExtension`，D-135），贡献字段类型、字段覆盖与插槽（含 hook 插槽 `useFormulaAssist`）；集合在实例内必须引用稳定，变更即报错。
- `config`: `{ allowAddColumn?, allowDeleteColumn?, allowAddRow?, allowDeleteRow? }` 控制交互开关。
- 视图事件：`onCreateView` / `onDeleteView` / `onRenameView` / `onUpdateView` / `onReorderViews` / `onActiveViewIdChange`。
- 数据事件：`onDataChange`（columns+rows，仅用户操作触发）与 `onViewConfigChange`（viewConfig）。
- 行事件：`onRowDetailOpen`（自定义详情打开）、`onRowAdd`、`onRowDelete`、`onRowCleanup`（删除前行快照）、`onDetachedRowPatch`（卸载后的行补丁）。
- 视觉：`theme`、`readonly`、`bare`、`className`。

### 9.2 暴露的 Ref

`DatabaseRef`（`forwardRef` 提供）：

- `deleteRow(rowId)`
- `addRow(rowData?)`
- `updateRow(rowId, data)`（忽略 id 字段）
- `getRows(): RowData[]`
- `dispatch(command, source?)`：外部变更入口（`rows.apply` 差量 / `rows.receive` 确认快照 / `column.configure` / `column.resize` / `view.receive` / `view.remove` / `views.reorder`）
- `setQuery(query)`：接入会话查询（text / filters / searchResults / grouping）

调用方式：

```tsx
const dbRef = useRef<DatabaseRef>(null);
<Database ref={dbRef} {...props} />;
dbRef.current?.addRow({ title: "新任务" });
```

## 十、扩展指南

### 10.1 新增列类型插件

1. 在 `packages/database/src/plugins` 下创建目录，导出 `CellPlugin` 对象；业务专属字段类型则放宿主扩展（如 `features/shared/database/plugins/`），经 `fieldTypes` 贡献，不必进包。
2. 实现 `Renderer`（必填）与 `Editor`（可选，需 `editable: true`），按需要补充 `sort/getGroupKey/filters/search`。
3. 在 `plugins/index.ts` 注册到 `builtInPlugins`，或经扩展的 `fieldTypes` 贡献（D-135）。
4. 若列需要持久化格式转换，提供 `beforeSave/afterLoad`；需要作为日历日期列、看板分组列或封面图片列时声明 `capabilities`。

### 10.2 新增视图类型（高级）

1. 定义新的视图组件（参考 `views/TableView` 入口），接受 `pluginManager/theme/readonly/...`。
2. 扩展 `DataTableView.type` 与 `TableViewConfig`（在 `@tau/shared`）；视图类型元数据（名称/图标/创建所需列/初始配置片段）在 `views/registry.ts` 登记，组件映射在 `views/components.ts` 注册（`constants/viewType.ts` 已删除，D-135）。
3. `ViewTypeSelectModal` 的类型卡片与必填列校验由注册表元数据驱动，所需列按字段能力（`requiredColumn.capability`）判定。
4. 确保 `onCreateView/onUpdateView` 透传新配置并在 store 中保存。

## 十一、性能与交互优化

- **虚拟滚动**：表格/画廊使用 `useVirtualizer`，保持 `estimateSize` 与真实高度一致可减少抖动。
- **列宽持久化**：`resizeColumn` 同步写入 `viewConfig.columnWidths`，避免刷新后丢失。
- **键盘导航**：`useKeyboardNavigation` 跳过输入类元素，防止冲突；选区存在且非编辑态时 Enter/Space 进入编辑。
- **分组/过滤**：投影（`core/projection.ts`）对无条件时直接短路返回，避免无条件遍历；必要时可缓存筛选结果。
- **历史栈**：超出 50 条自动丢弃旧记录，如需更长记录可在 `DatabaseStore` 调整。
- **主题**：主题运行时归 `@tau/themes`（`useThemeStore` 取系统主题），`theme` prop 可强制覆盖；弹窗为 `@tau/ui` 的 `Dialog` / `ConfirmDialog`，样式只消费 Tailwind 语义类与 `--tau-*` token。

## 十二、Bug 修复与调试建议

- **数据不同步**：用户编辑只经 `lastChange`（source 为 "user"）触发 `onDataChange`/`onViewConfigChange`；外部变更必须经 `ref.dispatch(command, "external")`，改 props 不会覆盖本地编辑。
- **列类型缺失/渲染异常**：检查是否在 `builtInPlugins` 或外部扩展的 `fieldTypes` 中注册（重复类型在装配扩展时报错）；确认 `column.type` 与插件 `type` 对齐。
- **筛选不生效**：确保插件 `filters` 定义的 `operator` 与 `FilterPanel` 下拉值一致，并处理 `requiresValue` 情况。
- **日历/看板无法创建视图**：检查是否至少一列的字段插件声明了 `capabilities.date`/`capabilities.singleOption`（经 `hasCapability` 判定，公式列结果为日期也不算）；`ViewTypeSelectModal` 已按注册表元数据做前置校验。
- **详情内容丢失**：确认宿主正文插槽（桌面 `RowDetailBody`）的 `flush()` 是否在关闭/切换行前完成、`createPendingContent` 是否成功及行对象中 `detailContentId` 是否回写；正文引用由主进程 `DataTableTable` 在写路径事务内按新旧差集维护，释放后进入 `content_pending_releases`，开库时回收超过 7 天宽限期且引用仍为 0 的正文（D-136），渲染端不直接 `deleteContent`。
- **虚拟滚动定位错误**：调整 `estimateSize` 或确保行高一致，避免动态高度导致跳动。
- **只读模式异常**：表格/画廊/看板的新增/删除/编辑入口需校验 `readonly` 与 `DatabaseConfig`；如出现可编辑，排查按钮的 `readonly` 判定。
