## 一、项目概述

### 1.1 技术栈

| 技术                    | 版本   | 作用                                      |
| ----------------------- | ------ | ----------------------------------------- |
| React                   | 19.1.0 | UI 框架                                   |
| TypeScript              | ^5.x   | 类型安全                                  |
| Zustand                 | ^4.3.8 | 状态管理与快照记录                        |
| ahooks                  | ^3.7.7 | 高阶 Hook（useCreation/useMemoizedFn 等） |
| antd                    | ^6.x   | 交互组件、Modal/Select 等                 |
| react-dnd               | ^16.x  | 列/视图拖拽排序                           |
| @tanstack/react-virtual | 3.13.x | 表格/画廊虚拟滚动                         |
| dayjs                   | ^1.11  | 日期处理（日历视图）                      |
| uuid                    | ^9.x   | 行/列主键生成                             |

### 1.2 核心特性

1. **多视图**：表格 / 画廊 / 日历 / 看板四种视图共享同一数据与列定义。
2. **插件化列类型**：通过 `CellPlugin` 抽象列的渲染、编辑、排序、分组、筛选与搜索策略。
3. **视图配置持久化**：列顺序、宽度、行顺序、分组、排序、筛选、画廊/日历/看板专属配置均写入 `viewConfig`。
4. **虚拟化与键盘导航**：大列表虚拟滚动、列拖拽/宽度调整、单元格键盘导航与编辑。
5. **富文本详情**：行可关联富文本内容（依赖 `@tau/editor`），支持创建/更新内容并清理关联。
6. **可插拔扩展**：外部注入列类型插件、视图增删改、行/列增删、自定义回调。

## 二、核心架构

### 2.1 组件分层

- **入口**：`Database.tsx` 负责插件注册、Zustand store 创建、主题合并、回调透传及视图选择。
- **上下文**：`DatabaseContext` 暴露 store，所有子组件通过 `useDatabaseStore` 读取/更新。
- **插件管理**：`PluginManager` 负责注册/加载插件、执行 beforeSave/afterLoad、排序/分组/筛选/搜索策略。
- **视图容器**：`ViewTabs` 控制视图切换、新建/重命名/删除/排序等操作，主体视图由当前 active view 决定。
- **子视图**：`TableView`、`GalleryView`、`CalendarView`、`KanbanView` 共享相同数据层，按视图配置差异化渲染。

### 2.2 数据模型（简化）

```ts
// apps/desktop/src/components/Database/types.ts
export interface DatabaseProps {
  data: RowData[];
  columns: ColumnDef[];
  views: DataTableView[];
  activeViewId: number;
  viewConfig: TableViewConfig;
  plugins?: CellPlugin[];
  config?: DatabaseConfig;          // 开关：增/删行列
  onDataChange?: (data) => void;    // columns + rows
  onViewConfigChange?: (config) => void;
  // 视图 CRUD 回调（后端持久化）
  onCreateView?: (...) => Promise<DataTableView | null>;
  onDeleteView?: (id) => Promise<number | null>;
  onRenameView?: (...args) => Promise<DataTableView | null>;
  onUpdateView?: (...args) => Promise<DataTableView | null>;
  onReorderViews?: (ids) => Promise<void>;
  // 行相关
  onRowDetailOpen?: (row) => void;
  onRowAdd?: (defaultData?) => void;
  onRowDelete?: (rowId) => Promise<void>;
  // 主题/只读
  theme?: "light" | "dark";
  readonly?: boolean;
}
```

### 2.3 Store 设计（Zustand）

`DatabaseStore.ts` 是核心单一数据源，记录 columns/rows/viewConfig/历史栈/选择态等：

- **快照与历史**：`commitHistory` 每次数据写入前推入快照（最多 50 条）；`undo/redo` 恢复列/行/视图配置。
- **视图配置**：`columnOrder`、`rowOrder`、`columnWidths`、`groupBy`、`sorts`、`filters`，以及视图专属配置 `galleryConfig`、`calendarConfig`、`kanbanConfig`。
- **行列操作**：`addRow/deleteRow/addColumn/deleteColumnWithCleanup/moveRow/moveColumn`，列删除前会调用插件的 `onColumnCleanup`。
- **单元格状态**：`selectedCell`、`editingCell` 配合键盘导航；`moveCellSelection` 处理上下左右移动。
- **外部同步**：`syncExternalData` 在 props 变化时比对 JSON，必要时更新本地状态与列宽。

### 2.4 渲染与注入流程

1. 创建 `PluginManager`，注册内置插件并加载外部传入的 `plugins`。
2. 创建 `createDatabaseStore`，将 columns/data/viewConfig/activeViewId 初始化到 Zustand。
3. `useEffect` 订阅 store 变更：检测 columns+rows 与 viewConfig 的 JSON 变化，分别触发 `onDataChange` 与 `onViewConfigChange`。
4. 绑定列宽拖拽（`useColumnResize`）与键盘导航（`useKeyboardNavigation`）。
5. 根据 `activeViewId` 渲染对应视图组件，统一透传插件管理器、主题、只读状态与行/列操作回调。

## 三、插件体系与列类型

### 3.1 CellPlugin 接口

```ts
// types.ts
export interface CellPlugin<T> {
  type: string; // 列类型标识
  name: string; // 在 UI 中展示的名称
  Icon?: React.FC; // 列头图标
  Renderer: React.FC<{ value; column; theme; readonly; onCellValueChange }>;
  Editor?: React.FC<{
    value;
    column;
    onCellValueChange;
    onFinishEdit;
    onColumnChange;
    theme;
    readonly;
  }>;
  editable?: boolean; // 是否可进入编辑态
  getGroupKey?: (row, column) => string;
  sort?: ({ a, b, direction, columnConfig, rowA, rowB }) => number;
  filters?: CellFilterDefinition<T>[];
  search?: (keyword, cellValue, column, row) => boolean;
  beforeSave?: (value, config) => CellValue; // 写入前转换
  afterLoad?: (value, config) => CellValue; // 读出后转换
  onColumnCleanup?: (columnData: CellValue[]) => void | Promise<void>;
}
```

### 3.2 内置列类型

| 类型         | 主要特性                               | 关键点                                                 |
| ------------ | -------------------------------------- | ------------------------------------------------------ |
| text         | 文本渲染/编辑，包含搜索、包含/为空筛选 | `filters` 定义四类字符串筛选                           |
| number       | 数字渲染/区间比较                      | 自定义排序，筛选支持范围                               |
| date         | 单/区间日期，格式归一化 `{start,end}`  | `beforeSave/afterLoad` 兼容旧数据；分组/排序字段可配置 |
| select       | 单选（含颜色配置）                     | `getGroupKey` 支持分组，看板依赖该类型                 |
| multi-select | 多选标签                               | 颜色配置/包含匹配                                      |
| checkbox     | 勾选布尔                               | 搜索/筛选基于布尔值                                    |
| link         | 链接渲染                               | 可搜索                                                 |
| star         | 星级                                   | 可排序                                                 |
| image        | 图片列表                               | `editable=false`，过滤空 URL                           |
| attachment   | 附件列表                               | 清洗无效附件                                           |
| progress     | 进度条                                 | 数值排序/筛选                                          |
| rich-text    | 富文本片段                             | 只读渲染，可用于卡片描述                               |

插件注册入口：`plugins/index.ts`，统一写入 `builtInPlugins`，在 `Database.tsx` 中自动注册并加载。

### 3.3 插件生命周期

- **注册与加载**：`PluginManager.registerPlugins` → `loadAllPlugins` 调用每个插件的 `onMount`。
- **值转换**：单元格保存/加载时调用 `beforeSave/afterLoad`，保障存储格式一致（如日期、图片列表）。
- **清理**：删除列时执行 `onColumnCleanup`，可用于回收外部资源。
- **搜索/筛选/排序/分组**：统一由 `PluginManager` 分发，视图逻辑只依赖通用接口。

## 四、视图系统

### 4.1 表格视图（TableView）

- 文件：`views/TableView/index.tsx`
- 特性：列拖拽排序、列宽调整、虚拟滚动（@tanstack/react-virtual）、行拖拽、单元格编辑/选择/键盘导航、行详情弹窗、列编辑弹窗。
- 可配置：是否允许新增/删除列/行（`DatabaseConfig`），主列不可删除。
- 列头：`ColumnHeader` 支持拖拽、双击编辑、更多菜单删除，显示插件 Icon。
- 数据变更：`handleCellChange` 调用插件 `beforeSave` 再写入 store。

### 4.2 画廊视图（GalleryView）

- 文件：`views/GalleryView/index.tsx`
- 特性：卡片瀑布流 + 虚拟行，支持分组头、卡片数量展示，响应式列数（ResizeObserver）。
- 画廊配置：`viewConfig.galleryConfig` (`coverType: detail|image`、`coverImageColumnId`)。
- 行新增：支持在分组下继承分组字段初始值。

### 4.3 日历视图（CalendarView）

- 文件：`views/CalendarView/index.tsx`
- 依赖：至少一个日期列（在 `ViewTypeSelectModal` 中验证）。
- 配置：`viewConfig.calendarConfig.dateColumnId`，日期列需为 `date` 类型。
- 事件：将行映射为 `{id,title,startDate,endDate}`，标题优先取主列。支持点击日期创建行（区间/单点）。

### 4.4 看板视图（KanbanView）

- 文件：`views/KanbanView/index.tsx`
- 依赖：单选列作为分组列（`kanbanConfig.groupColumnId`），列顺序可通过 `kanbanConfig.columnOrder` 持久化。
- 行分配：按单选值归类，缺失选项归入“未分类”。
- 支持拖拽行移动、行详情、列配置。

## 五、状态与数据流

### 5.1 数据同步

- **初始化**：`createDatabaseStore(columns, data, viewConfig, views, activeViewId)`。
- **外部更新**：`Database.tsx` 监听 store，JSON 比对后触发 `onDataChange` / `onViewConfigChange`。
- **props 变更**：`syncExternalData` 对 columns/rows/viewConfig 做深比较并更新 store（含列宽修正）。

### 5.2 历史与撤销

- `commitHistory` 在每次写操作前记录快照（最大 50 条）。
- `undo/redo` 仅恢复 columns/rows/viewConfig 基础字段，附加配置（gallery/calendar/kanban）在写入 viewConfig 时已包含。

### 5.3 行/列生命周期

- **新增行**：缺省填充所有列为 `null`，写入 `viewConfig.rowOrder`。
- **删除行**：若行存在 `detailContentId`，调用 `deleteContent` 清理关联。
- **新增列**：生成列 id，附带默认宽度与行默认值。
- **删除列**：优先执行插件 `onColumnCleanup`，再从列/行/列宽中移除。

### 5.4 键盘与选区

- `useKeyboardNavigation` 监听全局方向键/Enter/Space，驱动 `moveCellSelection` 和进入编辑态。
- 选区状态存储在 store，TableView/Row 组件按选区高亮。

## 六、筛选/排序/分组/搜索

- **筛选**：`FilterPanel.tsx` 以嵌套组的形式构建条件树（`FilterGroup`），叶子节点由插件 `filters` 定义操作符/初始值/是否需要值；`useFilteredAndSortedRows` 递归执行。
- **排序**：`viewConfig.sorts` 支持多字段 + priority，按插件 `sort` 实现比较；无排序时回落到 `rowOrder`。
- **分组**：`groupBy.fieldId` 需插件实现 `getGroupKey`；Table/Gallery 支持分组头，看板使用独立分组逻辑。
- **搜索**：`SearchInput` 调用 `setSearchKeyword`；`PluginManager.executeSearch` 优先插件搜索，否则字符串包含。

---

## 七、视图管理与配置

- **视图切换与 CRUD**：`ViewTabs` 处理 active 状态、拖拽排序（react-dnd）、重命名（内联 EditText）、删除（Modal 确认）、创建（`ViewTypeSelectModal`）。
- **视图创建校验**：日历需要日期列，看板需要单选列；创建时复制当前视图配置并附加专属配置。
- **视图更新**：`handleUpdateView` 持久化后同步 store，若更新当前视图则写入 `galleryConfig`/`calendarConfig`/`kanbanConfig`。
- **配置入口**：`GroupPanel`、`SortPanel`、`FilterPanel`、`ViewEditPanel` 通过 Popover/Dropdown 弹出。

---

## 八、行详情与富文本

- 文件：`components/RowDetailModal/index.tsx`
- 依赖：`@tau/editor` 作为详情富文本编辑器，默认内容 `[{type:"paragraph",children:[{type:"formatted",text:""}]}]`。
- 行保存：关闭弹窗时检测内容是否为空；如需创建/更新内容，调用 `createContent` / `updateContent`，并将返回的 `detailContentId` 回写行。
- 列操作：详情侧可编辑/删除列（受只读与 `allowDeleteColumn` 限制），删除列时调用插件清理并更新本地行数据。
- 行拖拽：详情弹窗内列支持拖拽排序（react-dnd）。

## 九、对外 API（Props/Ref/回调）

### 9.1 组件 Props（重点）

- `columns` / `data` / `viewConfig` / `views` / `activeViewId`: 必填数据源。
- `plugins`: 外部自定义列类型列表，注册后与内置插件一起加载。
- `config`: `{ allowAddColumn?, allowDeleteColumn?, allowAddRow?, allowDeleteRow? }` 控制交互开关。
- 视图事件：`onCreateView` / `onDeleteView` / `onRenameView` / `onUpdateView` / `onReorderViews`。
- 数据事件：`onDataChange`（columns+rows）与 `onViewConfigChange`（viewConfig）。
- 行事件：`onRowDetailOpen`（自定义详情打开）、`onRowAdd`、`onRowDelete`。
- 视觉：`theme`、`readonly`、`className`。

### 9.2 暴露的 Ref

`DatabaseRef`（`forwardRef` 提供）：

- `deleteRow(rowId)`
- `addRow(rowData?)`
- `updateRow(rowId, data)`（忽略 id 字段）
- `getRows(): RowData[]`

调用方式：

```tsx
const dbRef = useRef<DatabaseRef>(null);
<Database ref={dbRef} {...props} />;
dbRef.current?.addRow({ title: "新任务" });
```

## 十、扩展指南

### 10.1 新增列类型插件

1. 在 `apps/desktop/src/components/Database/plugins` 下创建目录，导出 `CellPlugin` 对象。
2. 实现 `Renderer`（必填）与 `Editor`（可选，需 `editable: true`），按需要补充 `sort/getGroupKey/filters/search`。
3. 在 `plugins/index.ts` 注册到 `builtInPlugins` 或从外部通过 `Database` 的 `plugins` prop 注入。
4. 若列需要持久化格式转换，提供 `beforeSave/afterLoad`；删除列需清理资源时实现 `onColumnCleanup`。

### 10.2 新增视图类型（高级）

1. 定义新的视图组件（参考 `views/TableView` 入口），接受 `pluginManager/theme/readonly/...`。
2. 扩展 `DataTableView.type` 与 `TableViewConfig`（在 `@tau/shared`），并在 `ViewTabs`/`Database.tsx` 的视图选择处增加分支。
3. 在 `ViewTypeSelectModal` 增加类型卡片与必填字段校验。
4. 确保 `onCreateView/onUpdateView` 透传新配置并在 store 中保存。

## 十一、性能与交互优化

- **虚拟滚动**：表格/画廊使用 `useVirtualizer`，保持 `estimateSize` 与真实高度一致可减少抖动。
- **列宽持久化**：`resizeColumn` 同步写入 `viewConfig.columnWidths`，避免刷新后丢失。
- **键盘导航**：`useKeyboardNavigation` 跳过输入类元素，防止冲突；选区存在且非编辑态时 Enter/Space 进入编辑。
- **分组/过滤**：在 `useFilteredAndSortedRows` 中按需短路，避免无条件遍历；必要时可缓存筛选结果。
- **历史栈**：超出 50 条自动丢弃旧记录，如需更长记录可在 `DatabaseStore` 调整。
- **主题**：`useTheme` + `App.useApp()` 统一主题与 antd Modal；可通过 `theme` prop 强制覆盖。

## 十二、Bug 修复与调试建议

- **数据不同步**：确认 `onDataChange`/`onViewConfigChange` 是否因 JSON 深比较失败（对象引用变化）。必要时手动调用 `syncExternalData` 或保证上层数据稳定。
- **列类型缺失/渲染异常**：检查是否在 `builtInPlugins` 或外部 `plugins` 中注册；确认 `column.type` 与插件 `type` 对齐。
- **筛选不生效**：确保插件 `filters` 定义的 `operator` 与 `FilterPanel` 下拉值一致，并处理 `requiresValue` 情况。
- **日历/看板无法创建视图**：检查是否存在至少一个日期列/单选列；`ViewTypeSelectModal` 已做前置校验。
- **详情内容丢失**：确认 `createContent/updateContent/deleteContent` 的调用是否成功，及行对象中 `detailContentId` 是否回写。
- **虚拟滚动定位错误**：调整 `estimateSize` 或确保行高一致，避免动态高度导致跳动。
- **只读模式异常**：表格/画廊/看板的新增/删除/编辑入口需校验 `readonly` 与 `DatabaseConfig`；如出现可编辑，排查按钮的 `readonly` 判定。
