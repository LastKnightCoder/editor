# 移动端闪卡功能迁移方案

> 状态：UI 风格已选定（风格 D 融合版，2026-09-14）
> 日期：2026-09-14
> 配套 UI Demo：`docs/flashcard-mobile-ui-demos/`（已选定 `style-d-blend.html`：A 杏子 Bento 视觉 × C 3D 翻面/滑动评分交互 + 五题型建卡流程）

---

## 1. 背景与目标

桌面端已有完整的"闪卡中心"：卡组管理、5 种题型卡片、自研间隔复习调度（间隔阶梯 + ease 因子）、AI 制卡与 AI 答案评判。移动端（Tauri 2 + React WebView）目前只有一个"即将上线"的占位入口（`apps/mobile/src/features/settings/SettingsPage.tsx:86`），但 **共享 db-schema 已包含全部 4 张闪卡表**，数据层天然就绪。

迁移目标：

1. **复习闭环优先**：移动端的核心价值是"随时随地复习"——桌面制卡，移动复习，数据经现有的整库同步（GitHub/S3/WebDAV/OSS）互通。
2. **调度算法与桌面完全一致**：同一张卡在两端复习，调度结果必须收敛，避免两套算法导致间隔混乱。
3. **遵循移动端全部既有规范**：自研路由（`definePage`）、返回手势仲裁（`apps/mobile/docs/移动端页面栈与返回策略.md`）、四主题设计令牌、通用浮层组件。

非目标（明确不做）：

- 不引入 FSRS/ts-fsrs 等第三方调度库（桌面就是自研，保持一致）。
- 不迁移 MCP 工具、右栏工作台等桌面专属形态。
- P0 不做 AI 能力（见 §3 分期）。

### 2.2 移动端已有基础（迁移目标环境）

- **技术栈**：Tauri 2 + React 19 + Vite 7 + Tailwind 4（CSS 变量令牌）+ zustand + TanStack Query + motion + 自研 touch 手势。WebView 方案意味着可以直接用 Slate/DOM，无需跨端妥协。
- **数据库**：Rust 侧 rusqlite 持有本地 SQLite，`src-tauri/src/database/migrator.rs` 直接 `include_str!` 共享 `packages/db-schema/schema/main.sql`——闪卡表建库即存在，**P0 无 schema 变更**（不触发 `db:schema:check` 联动，见根 AGENTS.md 数据库规则）。
- **Rust command 范式**：`database/pomodoro.rs` facade + 职责子模块 + `lib.rs` 的 `generate_handler!` 注册。闪卡照此办理。
- **路由范式**：`features/**/pages/*.page.tsx` 内 `export default definePage({...})`，`src/pages.ts` glob 自动收集，新增页面无需改登记表。
- **可复用组件**：`BottomSheet` / `ActionSheet` / `MobileConfirmDialog` / `PageHeader` / `GroupLabel` / `toast` / `VirtualContainerList`（均已内置返回手势拦截，业务零接线）。
- **富文本**：编辑复用 `@tau/editor`（经 `services/editorRegistry.tsx` 桥接移动端服务），列表摘要用 `src/utils/richTextText.ts`。
- **参考页面**：列表页对齐 `cardsLibrary` / `pomodoro`；沉浸页对齐 `pomodoroFocus`（`layer: "overlay"` + `useKeepScreenAwake` + 进度环 + 退出确认）。
- **设置页预留入口**：`SettingsPage.tsx:86` `key:"flashcard", soon:true`，实施时替换为真实跳转。

### 2.3 关键数据模型速览（与桌面共享）

- 题型 `FlashcardType`：`single-choice | multiple-choice | cloze | qa | boolean`（中文：单选/多选/填空/问答/判断）。
- 评分 `FlashcardReviewRating`：`easy | normal | struggle | hard`（轻松/一般/较难/困难）。
- 状态 `FlashcardStatus`：`new | learning | review | suspended`（UI 上新卡/学习中/巩固；suspended 桌面无入口，移动端同样不暴露）。
- `prompt` / `detail` 为 Slate `Descendant[]` JSON；cloze 的填空以行内 `flashcard-blank` 元素（`blankId/answer/alternativeAnswers/placeholder`）嵌在 prompt 内。
- 调度字段：`review_level`(0-9) / `due_time`(ms) / `ease_factor`(初始 2.5) / `review_count` / `status`。
- `references` 经 `flashcard_references` 表关联 `contents` 表（与全部内容实体打通）。

## 3. 迁移范围与分期

### P0 —— 复习闭环 + 建卡流程（本方案主体，一次交付）

1. Rust 数据层：12 个 command + 调度算法移植 + 单测。
2. 前端服务层：`services/tauri.ts` 封装 + 类型定义。
3. 闪卡主页：今日概览 + 卡组列表 + 卡组管理（新建/编辑/删除，BottomSheet 表单）。
4. 卡组详情页：状态筛选 chips + 卡片列表 + 单卡编辑/删除入口。
5. 复习页（全屏沉浸 overlay，风格 D 融合交互）：3D 翻面纸卡、5 种题型答题、本地判分、揭示解析、滑动手势评分 + 四档按钮、进度、退出确认、完成庆祝。
6. **建卡流程**：题型选择页 + 五种题型（单选/多选/填空/问答/判断）专属编辑表单；填空支持「选中文本设为填空」与 `{{blank:答案}}` 语法双入口、备选答案/占位符配置。
7. 入口接线：设置页占位项替换；闪卡主页可从设置页进入。

### P1 —— 制卡入口与统计

1. 内容详情页（卡片/文章/文档/项目）"加入闪卡"入口（自动携带参考资料 reference）。
2. 复习统计：主页概览扩展（今日已复习数、7 天趋势）；读取 `flashcard_reviews`。
3. 搜索接入：`search_all_content` 增加闪卡类型分发。
4. 卡片批量操作、卡组排序拖拽等管理增强。

### P2 —— AI 能力（依赖移动端 LLM 配置体系建设）

1. AI 批量制卡（流式生成 + 逐卡选择）。
2. QA 题答案 AI 评判（复习页"AI 点评"按钮，未配置时隐藏）。

### 5.1 Tauri 命令清单（命名对齐移动端 snake_case 范式）

| `flashcard_delete_card`      | `id: i64`                                                                         | `()`                                                                                     | delete-card                              |
| `flashcard_get_review_queue` | `deck_id: Option<i64>, limit: u32, statuses: Option<Vec<String>>`                 | `Vec<Flashcard>`                                                                         | get-review-queue                         |
| `flashcard_submit_review`    | `card_id, deck_id, rating, notes: Option<String>`                                 | `Flashcard`（更新后的卡片，前端用于乐观反馈）                                            | submit-review                            |
| `flashcard_get_stats`        | —                                                                                 | `FlashcardStats { due_total, due_by_deck: HashMap<i64,u32>, new_total, learning_total }` | （移动端新增，供主页概览，一次查询聚合） |

注意事项：

- `prompt/detail/data/tags/meta` 均为 JSON 列，Rust 侧用 `serde_json::Value` 透传，**不在 Rust 侧解析 Slate 结构**（判分在前端做，见 §6.4）。
- 时间戳全部 ms（i64），与桌面一致。
- `flashcard_list_cards` 的搜索过滤在 SQL `LIKE`（摘要列 `reference_summary` + 提取的纯文本缓存），全库搜索接入（P1）另行走 `search.rs` 的 jieba 索引。
- 桌面端 `flashcard.ts` 内的历史数据迁移（纯文本→Slate、references 旧结构）**不移植**：那是一次性升级逻辑，桌面端已消化；移动端打开的库要么是新建（直接新结构），要么是桌面同步来的（已迁移）。
- 卡组颜色 `cover_color` 存具体色值（桌面调色板 #2563eb 系）。移动端新建卡组提供移动端语义色系调色板（见 demo），存储仍是 hex，两端渲染各自兼容，不改数据。

### 5.3 调度算法移植（flashcard_schedule.rs，照抄桌面语义）

```
// 桌面源：apps/desktop/src-electron/main/modules/tables/flashcard.ts:61-86,947-1012
const REVIEW_INTERVALS_MS: [i64; 10] =
    [5*60_000, 30*60_000, 12*3_600_000, 86_400_000, 2*86_400_000,
     4*86_400_000, 7*86_400_000, 15*86_400_000, 30*86_400_000, 60*86_400_000];

fn rating_delta(rating) -> i32   // easy=+2, normal=+1, struggle=-1, hard=-2
fn ease_delta(rating) -> f64     // easy=+0.15, normal=0, struggle=-0.1, hard=-0.25
const EASE_RANGE: (f64, f64) = (1.3, 3.5);   // clamp；初始 2.5

fn calculate_schedule(review_level, ease_factor, review_count, rating, now_ms)
    -> (next_level, next_due_ms, next_ease, next_status)
{
    next_level = clamp(review_level + rating_delta(rating), 0, 9);
    next_ease  = clamp(ease_factor + ease_delta(rating), 1.3, 3.5);
    next_due   = now_ms + REVIEW_INTERVALS_MS[next_level] as f64
                 * (0.8 + next_ease * 0.2);
    next_status = if review_count + 1 >= 3 && rating != "hard" { "review" }
                  else { "learning" };
}
```

`submit_review` 事务：`SELECT 卡片 → calculate_schedule → UPDATE flashcards（level/due/ease/count/last_review_time/status）→ INSERT flashcard_reviews（rating/interval/level/ease/notes）`。

`get_review_queue` 排序：`due_time <= now` 优先，`ORDER BY (due_time > now), due_time ASC, review_level ASC`（对齐桌面 :900-945）。

**验收要点**：对同一输入序列，Rust 与桌面 TS 输出逐字段一致——单测用桌面行为快照做金标准（easy/normal/struggle/hard × 边界 level 0/9 × ease 上下限）。

### 6.2 路由与返回手势（遵循根 AGENTS.md 移动端浮层规范）

| key                 | layer       | match                                              | transition                 | 返回语义                                 |
| ------------------- | ----------- | -------------------------------------------------- | -------------------------- | ---------------------------------------- |
| `flashcardHome`     | screen      | single                                             | slideRight                 | 常规弹栈                                 |
| `flashcardDeck`     | screen      | params（getId=`d${deckId}`）                       | slideRight                 | 常规弹栈                                 |
| `flashcardReview`   | **overlay** | params（getId=`r${deckId ?? "all"}`）              | sheetUp/none（按所选风格） | 退出确认（§6.4）                         |
| `flashcardCreate`   | screen      | multi                                              | slideRight                 | 题型选择页（`usePageGuard` 未保存守卫）  |
| `flashcardCardEdit` | screen      | params（getId=`c${cardId}`；新建传 `deckId+type`） | slideRight                 | 未保存守卫；保存后 `finish` 回传刷新列表 |

建卡流程路由细节：

- 入口：闪卡主页 / 卡组详情的「＋」→ `flashcardCreate`（题型选择 + 归属卡组）→ `navigator.replace` 或 `push` 进入 `flashcardCardEdit`（携带 `deckId`、`type`，编辑态另带 `cardId`）。
- 编辑页未保存守卫用 `usePageGuard`（`canLeave`），与 quickCapture 的"先冲洗再放行"同构。
- 复习页 overlay 细节（对齐 `pomodoroFocus` 范式）：

- 主体面板 open 恒 true，关闭即 `goBack`。
- **退出保护用 `MobileConfirmDialog`**（"本次复习进度将不计入，确定退出？"——已答题目已实时落库，退出只是放弃未答部分）：MobileConfirmDialog 已内置返回=取消，页面本身不需要 `backDismiss={false}`；但若实现"返回先弹确认再退出"，则复习面板需 `backDismiss={false}` + `useBackHandler` 消费返回并弹确认框（参照 quickCapture 的"先冲洗再放行"模式）。**推荐后者**，防止误触丢状态。
- 复习期间 `useKeepScreenAwake(true)`。
- 队列快照进页面局部 state（对齐桌面 ReviewModal 的 `queueSnapshot` 防抖思路），评分后 `queryClient.invalidateQueries(["flashcard"])` 让列表数据收敛。

### 6.4 复习页交互状态机（核心 · 风格 D 融合交互）

```
[加载队列] → 逐卡循环（3D 纸卡：正面作答 / 背面揭示，堆叠余量显示剩余数）：
  ┌ 正面·答题态 ──「确认回答 · 翻面判分」──▶ 本地判分（checkAnswer）→ 自动翻面
  │      │ 单选/多选：选项点击；判断：✓/✕ 大按钮；
  │      │ 填空：blank 行内输入框（键盘避让 .mobile-kb-screen）；
  │      │ 问答：textarea + 或直接点卡翻面（自评模式）
  │      └─（任何题型）直接点卡翻面 = 跳过作答，走自评
  ▼
  背面·揭示态 ── 评分（滑动手势：卡片上左滑=吃力 / 右滑=轻松；
  │     横滑越半张卡或速度超阈值提交；其余两档用按钮）──▶ flashcard_submit_review → 下一张
  │     对错标记（单选/多选/判断/填空自动判分；问答引导自评）
  │     正确答案 + 解析 + 参考资料（可展开 BottomSheet 查看引用内容）
  │     四档按钮常驻兜底（吃力/一般/还行/轻松 + 间隔预览）
  ▼
  [队列空] → 完成庆祝（本次 N 张 · 用时 · 正确率）→ 自动 pop
```

- 判分逻辑 `reviewFlow.ts` 从桌面 `ReviewModal.tsx:123-157` 移植为纯函数：单选比 optionId、多选比集合、填空比 answer+alternativeAnswers（trim+lowercase）、判断比值、问答恒 true 自评。
- 四档评分 → 语义色映射（移动端令牌现成）：easy=`--sage`、normal=`--sky`、struggle=`--butter`、hard=`--rose`（详见所选 demo）。
- 每张卡评分实时落库（无批量提交），中途退出已复习部分不丢失。
- QA 题的 AI 评判按钮 P2 再加（移动端无 LLM 配置，隐藏入口）。

### 6.5 富文本渲染

- **题干/detail（复习页、卡片列表预览）**：
  - 列表摘要：`richTextPlainText`（既有工具）。
  - 复习页：新写 `FlashcardRenderer`——轻量递归渲染 `Descendant[]`（paragraph/heading/quote/code/list + formatted/bold/italic/code + 图片复用 `LocalImage`）。**不复用完整 Slate `Editable`**：复习页是只读+行内输入混合场景，完整编辑器过重（移动端 Slate 有 Android 光标补丁等包袱），轻量渲染器 ~150 行即可覆盖题干 95% 内容，且天然支持把 `flashcard-blank` 元素渲染为交互输入框（答题态）或高亮胶囊（揭示态）。
  - 未识别节点类型 fallback 为纯文本拼接（前向兼容桌面新增的节点类型）。
- **参考资料查看**：`references[].content.content` 同样走 `FlashcardRenderer`，在 BottomSheet 中展示。
- **编辑（P0 建卡流程）**：题干/详情/参考答案输入复用 `@tau/editor`（对齐 ContentDetailPage 的用法与 `editorRegistry` 桥接），并移植桌面 `flashcard-blank` 扩展（`apps/desktop/src/editor-extensions/flashcard-blank/`，@tau/editor 扩展机制两端同构）实现「选中文本 → 设为填空」；填空配置（答案/备选答案/占位符）为移动端表单卡（对应桌面 BlankConfigPopover 的 BottomSheet 化）；`{{blank:答案}}` 纯文本语法双入口（`parseTextWithBlanks` 从桌面 `utils/flashcard/index.ts` 移植）。

### 6.6 状态管理与数据流

- 全部走 TanStack Query（无 zustand 域 store，对齐 pomodoro 范式）：
  - `["flashcard", "decks"]`、`["flashcard", "stats"]`、`["flashcard", "cards", deckId, status, search]`、`["flashcard", "queue", deckId]`。
  - 写操作后 invalidate 对应 key；复习页持有队列快照，不受 invalidate 影响。
- 页面级查询用 `usePageQuery`（自带 refetchOnResume，库窗口/回前台刷新到期数）。
- IPC 封装进 `services/tauri.ts`（`trackedInvoke`，超时对齐卡片链路 8s）。

### 6.7 主题与 UI 规范

- 全部使用 `--bg-*/--ink-*/--brand*/六组语义色/--shadow-*` 令牌 + `rounded-card(20px)/rounded-bento(22px)/rounded-sheet(30px)`，禁止硬编码色值（cover_color 用户数据除外）。
- 四主题自动适配：风格 D 全部走令牌变量（复习纸卡底色固定为 `--bg-surface` 亦随主题），无独立固定色板；评分四档用语义色变量即天然四主题兼容；3D 翻面用 motion（rotateY 弹簧，`--ease-bounce`）。
- 列表页滚动留白遵循"外层承载"惯例（对齐近期 commit 的留白方案：`.dock-pad` / `--page-bottom-inset`）。

## 7. UI 风格选型（已定稿）

**选型结论（2026-09-14）：风格 D · 融合版**，见 `docs/flashcard-mobile-ui-demos/style-d-blend.html`：

- **视觉与列表体系 = 风格 A**：全面沿用杏子 Bento 令牌（奶油纸底、陶土橙主色、六组粉彩语义色、20px 圆角），四主题自动适配。
- **复习页交互 = 风格 C**：3D 翻面纸卡（卡组色顶边 + 背后错位堆叠显示队列余量）；正面作答 → 「确认回答 · 翻面判分」自动翻面（也可直接点卡翻面走自评模式）；背面揭示对错/解析后，滑动手势评分（卡片上左滑=吃力、右滑=轻松）+ 底部四档按钮兜底，热区避开左缘 28px 边缘返回区。
- **建卡流程纳入 P0**：题型选择页 + 五种题型专属编辑表单（单选/多选/填空/问答/判断），填空编辑采用「选中文本设为填空」+ `{{blank:答案}}` 语法双入口，与桌面端及 AI 制卡数据格式互通。

原始 A/B/C 三版 demo 保留在 `docs/flashcard-mobile-ui-demos/` 供回溯。三版要点对比：

|            | 风格 A · 杏子 Bento                       | 风格 B · 沉浸墨韵                            | 风格 C · 纸感卡堆                        |
| ---------- | ----------------------------------------- | -------------------------------------------- | ---------------------------------------- |

## 附录 C · 复习热力图实现要点（对应附录 B 设计稿）
