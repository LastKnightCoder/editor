# Notebook 演示文稿按页生成与续改

**目标**　让 Agent 分次写完一份 PPT，续改时只读写目标页。用户可以在 Notebook 里打开成稿、继续编辑，也可以下载一个移出工作目录后仍能播放的 HTML 文件。

**阶段**　2026-11-21 已确认方向，全部内置模板已接入分页工作区，旧稿按首次续改时的往返与播放检查结果迁移。下文记录整体方案，实测范围见文末。

## 现状与改动范围

改造前，生成弹窗与项目对话里的生成工具共用后台任务。当时有 17 个模板，所选模板约 45–77 KB；生成提示内含整个示例、基础 CSS 和风格说明。续改把整份原稿放入系统提示。虽然 Agent 可以多轮调用工具，任务最终只取最后一条回复，清理代码围栏、检查非空，再把整份 HTML 写进笔记。清理函数会接受缺少文件结尾的非空文本。阅读区与下载共用运行时注入。 [当前分页提示](/apps/desktop/src/constants/prompts/ppt-workspace.ts) · [任务执行与保存](/apps/desktop/src/features/vibe-learning/views/VibeLearningView/tasks/runner.ts) · [预览与下载](/apps/desktop/src/features/vibe-learning/views/VibeLearningView/stage/NoteEditorView.tsx)

本次保留项目资料检索、模板选择、后台任务、PPT 笔记身份与单文件 HTML 下载。需要调整 PPT 专属提示、生成结果的接收方式、任务进度、正文读写与预览入口。报告等其他任务继续按各自现有方式交付。模板外观验收由用户完成。

## 工作目录与模板

宿主按当前资料库、PPT 笔记和本次任务分配独立目录。编辑同一笔记的两次任务各有草稿。目录名及挂载目标由宿主生成。以下是 Agent 在一次任务中看到的逻辑结构。

```text
template/                         应用提供，只读，固定到所选版本
  layouts.md                      页型、适用场景、可用类名、对应示例路径
  examples/compare.html           一个页型一个示例，按需读取
  shell.html                      文档骨架、页容器和导航钩子
  theme.css                       模板共用样式
  decoration.js                   有专属装饰的模板才提供
draft/                            Agent 的工作目录
  deck.json                       文稿标题、模板版本和有序页清单
  slides/cover.html               一份 UTF-8 HTML 片段对应一页
  slides/method.html
  overrides.css                   需要整稿定制时才创建
build/                            宿主产出，只读
  deck.html                       当前候选稿的独立播放文件
```

- **模板按需读。** 生成提示只含任务目标、资料入口、文件契约和版式目录位置。Agent 读到“要比较两种方法”时再打开对比页示例。模板升级保留已发布版本，可按模板 ID 和版本取回原壳、样式与装饰脚本。翻页与全览继续复用应用的公共运行时。
- **素材按身份引用。** 资料沿用绑定项目的检索工具。需要插图的页面引用已经持久化的资源标识。导出时宿主解析并内联必需图片及其嵌套资源；预览和下载验证同一份已解析结果。在线字体可以使用模板约定的系统回退，缺失的内容图必须报出页 ID。
- **写权限绑定任务。** 现有一次性 Agent 支持传 cwd，但后台调用没有给 PPT 设置专属目录。实现时由宿主先创建目录，再提供根路径受限的列举、读取、写入和局部替换能力；校验真实路径，拒绝越界和符号链接逃逸。受限任务只装配必要工具，避免通用 shell 或文件写入绕开目录边界。宿主以本次生成或编辑授权限定草稿写入；需要额外授权时按后台模式返回明确错误。当前附加工具接线会将风险标为只读，实现时需显式传递实际工具权限。 [一次性 Agent](/apps/desktop/src/services/piAgentRunner.ts) · [目录解析](/apps/desktop/src-electron/main/modules/pi-workspace.ts) · [后台工具权限](/apps/desktop/src-electron/main/modules/pi-tool-permissions.ts)

## 页与正文如何保存

`deck.json` 中一条清单项形如 `{"id":"method","intent":"比较两种复习方法"}`。数组顺序决定播放顺序。ID 在首次写页时确定，限定为安全的单段标识，系统据此推导文件名。页号仅供用户定位。“第 7 页”在任务开始时解析成稳定 ID；换标题或移到第 3 页都沿用它。简短的 intent 只用于定位和撰写，大标题、数字和段落的权威内容在页面片段中。

每份片段恰有一个带 `.slide` 的根元素。HTML 保留模板支持的布局、SVG、数据动画和插图。宿主负责首页 active 状态、页码、样式装配及运行时；作者页不带外壳和脚本。局部样式限定到页根；涉及整份主题时才改覆盖样式。校验还应覆盖组合后跨页重复的 DOM ID，尤其是 SVG 渐变和图表引用。

**拟定落库方式**　沿用 PPT 笔记的 `contentId`。结构化正文的首个代码块以固定文件名 `deck.json` 和带格式标识、格式版本的清单识别，其余代码块的文件名与逻辑源文件对应，每个页面独占一个块，整稿样式如有则单独一块。使用编辑器已有的代码块、文件名和代码正文契约。资源走资料库的持久资源管理，模板随应用按版本供应。页面 ID 与编辑器分配的节点身份各自保留。读取时从正文节点解码，避免把普通代码围栏内的内容误判为整稿。未知格式版本提示需要支持该版本的客户端，保留正文。 [代码块类型](/packages/editor/src/extensions/code-block/src/types/code-block.ts) · [正文持久化](/docs/architecture/content-storage.md)

首版允许本地一次提交整组节点。续改用起始正文的修订调用既有 `replaceContent(contentId, { nodes }, expectedRevision)`，保留未改页的片段与可复用的节点身份。这解决的是模型读写量；数据库物理写入量另行度量。提交成功的正文是再次编辑、同步与重开时的唯一来源。整稿 HTML 可以按需重建，无须与页面文件双写。 [带修订的正文替换](/apps/desktop/src/commands/content.ts)

## 生成、续改与发布

```text
生成弹窗 / 对话生成 / 已有 PPT 的 AI 编辑
  → 宿主绑定原资料库、笔记和起始修订，准备任务目录
  → Agent 查资料、读版式目录，写大纲与页面（续改只打开相关页）
  → Agent 请求构建并检查实际导出文件
       有错误 → 返回文件、页和原因 → Agent 局部修正 → 再检查
       已通过 → 宿主冻结经验证的文件快照
                  修订匹配 → 提交结构化正文 → 预览、下载、再次打开
                  有冲突   → 保留已保存版本和本次草稿，提示基于最新稿重试
```

| 操作             | Agent 读取                                 | Agent 写入                                       | 用户看到的结果                                                                      |
| ---------------- | ------------------------------------------ | ------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 新建             | 已选资料、版式目录、实际用到的示例         | 先写短大纲和清单，再逐页或分小批写片段           | 后台显示已写好且通过页级检查的页数及页名，完整验证后自动发布                        |
| 改一页或局部文字 | 清单、目标页，必要时读取资料、相邻页或示例 | 目标页；意图变化时同步该清单项                   | 内容更新，未涉及页的源片段逐字保留                                                  |
| 重排、插页、删页 | 清单和涉及的页                             | 重排只改清单；插页新增片段与清单项；删页移除两者 | 页码按新顺序计算。模板内若有手写目录或交叉引用，校验报告受影响页，由 Agent 同步处理 |
| 调整全稿主题     | 模板说明、现有覆盖样式及受影响版式         | 整稿样式；确有结构变化才改涉及的页               | 用相同校验走完整文稿，检查主题变更对各页的影响                                      |

任务结束以已验证的草稿快照为输入，最后一条 assistant 回复只用于说明结果。工具成功只回页 ID、文件摘要、进度等短结果，避免每次写入都带回整稿。取消或验证失败保留原发布稿。失败草稿按任务保留到重试或主动放弃；成功提交后释放临时文件。重试先核对草稿所属资料库、原稿身份和起始修订，过期时从最新稿重新应用用户意图。

## 模型怎样自主验证成稿

宿主提供一个限定在本任务的“构建并检查”工具。模型在完成前主动调用它，读取诊断、修正对应片段再复查。检查输入是本次源文件快照，返回候选摘要、页数和可定位的问题，成功时附实际 HTML 文件。发布端只接受**同一份通过检查的快照**。检查后再改一个字也需要复查。模型说“已完成”或浏览器自动补齐了标签，都不足以作为通过依据。

| 检查层   | 放行依据                                                                                                                                                                                                   |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 源文件   | 清单可解析、版本可读、页数非零、ID 唯一、文件与清单一一对应。每个文件只有一个非空页根；缺页、孤立页、无效闭合、越界引用能定位到文件。                                                                      |
| 独立文件 | 壳有明确的 doctype、head、body 和结束标签。严格解析与实际 DOM 的页面数量、顺序和 ID 一致。必需样式、脚本和图片在导出的文件中可解析，无任务路径、失效 Blob 或临时 URL。                                     |
| 实际播放 | 在隔离的浏览器环境从生成文件打开，验证首页、下一页、上一页、总页数、单个活跃页及运行时错误；多页稿实际遍历到末页。断网检查必需资源，在线字体使用回退。只执行内置模板装饰与公共运行时。视觉效果由用户验收。 |
| 应用读取 | 保存后通过正文读取入口重开，恢复相同页序和片段；预览、下载共用同一编译及注入路径。把下载文件移到空目录后再打开。冲突、取消、缺素材、浏览器检查不可用均不得记作发布成功。                                   |

校验失败优先返回能改的原因，例如“method.html 中的插图缺失”，模型可以替换资源后复查。模板资产损坏或运行预算用完时，后台任务保留草稿并给出具体失败原因。检查器不能把“模型已修过一次”当作成功。

## 旧 PPT 的处理

1. **打开、演示、下载**沿用原 HTML 路径。读取端先识别结构化清单，其余现存 PPT 正文按原格式读取。打开旧稿不会触发数据库写入。
2. **首次续改**先在草稿目录试拆。根据解析后的 DOM 查找同一容器内的独立页根，记录字节区间，原样保留页外的标题、壳、样式、装饰和页间内容。为每页赋稳定 ID。把原稿自带的壳与样式随文稿作为只读快照保存，避免凭风格名猜测模板。
3. **验证无编辑的往返**。先用原片段重新组成 HTML，核对顺序、文本、资源及导航行为；仅允许明确列出的运行时注入差异。再按用户要求改页，带起始修订提交。旧稿带有无法可靠拆分的嵌套页、依赖页位置的脚本或旧导航类时，结束本次续改并保留原稿，仍可预览和下载。 [运行时注入及旧导航识别](/apps/desktop/src/utils/ppt-runtime-inject.ts)
4. **迁移按使用发生**。生产验收覆盖一个可拆旧稿和一个保留原路径的旧稿；两个样本都要分别验证保存前与重开后。报告继续使用原有 HTML 读取入口。

## 电影模板首批实装与验收

- Notebook 生成弹窗和项目对话的生成工具共用后台任务。电影模板把草稿写到本次任务的独立磁盘目录，模板文件只读。模型的最后一条回复只作说明；落库前必须取得离线播放检查通过的源文件快照。没有通过检查、取消或修订冲突时，不提交本次草稿。
- 正文使用现有 v2 代码块，文件名与页 ID 稳定，源文本存在 code-step 中。续改保留代码块 UUID；正文整篇替换仍由编辑器分配内部协作节点身份。首批的旧整稿与其他模板继续使用原入口，旧稿自动拆页属于后续迁移。

## 全部模板与旧稿迁移验收

- 17 套内置模板共用分页工作区，只给模型装配所选版本的版式目录与单页示例。电影稿继续使用原来的模板版本。统一批处理检查了 311 个示例片段的页根、闭合与资源约束。
