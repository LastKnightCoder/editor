# 白板 Yjs 协作与插件数据契约

状态：W1–W8 已按确认边界完成；W9 已执行本轮联合验收与发布准备核对，发布门禁未通过，任务保留。
创建日期：2026-10-24。
目标：保留现有白板内核，基于与编辑器统一的数据契约和 Yjs 基础设施，实现具有明确插件、并发和迁移边界的白板协作。

用户已选择现有白板 + Yjs 路线。当前授权为 W9 非 UI 兼容补齐：适配火柴人新白板契约，用隔离的本地候选 SDK 和服务端构建做组合验证；产品 UI 接线由另一会话负责。本轮不扩功能、不增加恢复包，不执行真实数据迁移、发布或部署。

本文是本任务唯一设计与实施进度入口；包含需求、已选路线、建议行为、接口、模型、冲突、迁移与验收，不依赖一次性调研报告。下面未另行标为已确认的细节均为本轮设计建议，不能视为用户逐项裁决或已实现能力。接口示例是拟议协议签名，不是当前 SDK 可编译代码。

## 1. 范围、分工与设计原则

### 1.1 交付范围

第一期在桌面现有白板内核上支持：整板多页协作、独立内容页协作、图形与连线、板内富文本、图片、手写、脑图与分栏、插件元素、离线恢复、选择性撤销、资源与外部引用。实施按功能门槛分批开放，不以简单图形原型替代全部完成。

第一期不包含：替换白板内核、每页单独权限、跨房间原子移动、任意插件后端在服务器执行、插件代码自动分发、移动端新增白板渲染宿主、评论/公开只读链接、自动跨库实体联邦。既有音视频能力保持原边界，接入资源声明不代表新增所有媒体上传支持。

正文内的白板节点仍引用原白板内容页；共享正文不自动共享被引用白板。白板中的文档卡同样只引用原文档，不自动复制或授权正文。第一期成员保持 owner/editor；若增加 viewer，必须将服务端授权和协议验收纳入范围，不能仅设置画布 readonly。

### 1.2 与编辑器节点契约任务统一

公共能力由编辑器节点契约任务归口；白板提供另一种文档适配器和字段投影，不另建契约摘要、身份或迁移状态机。编辑器任务已有并发移动问题复现及节点池候选，尚不能当作稳定可直接复用的引擎。

| 能力                                             | 公共归属                               | 白板职责                                                 |
| ------------------------------------------------ | -------------------------------------- | -------------------------------------------------------- |
| 契约规范化、摘要、版本分发、资源/引用声明        | 中立协作协议与 SDK；编辑器 T1/T2       | 增加白板结构描述和 data 字段投影，使用相同算法和错误语义 |
| 稳定内容身份、移动不复制内容、顺序引用及恢复投影 | 编辑器 T1 的并发模型验证；共享语义夹具 | 纯元素序列和页面适配；不要求复用 Slate 混排的物理序列    |
| 字符串/富文本绑定、修订依据、未确认编辑保全      | 编辑器 T4/T5 与公共绑定                | 将绑定挂到板内字段，跨页移动不换根                       |
| 来源/实体身份、关系账、本机保留及整库替换保全    | 编辑器 T1/T3/T6                        | 登记白板、页面、板内文本和外部引用消费者                 |
| protocol/epoch、操作回执、迁移屏障及安装回执     | 编辑器 T4/T7                           | 白板候选生成、各本地投影安装、旧快照转换                 |
| 白板交互、几何、容器、光标与渲染投影             | 本任务                                 | 不把白板行为放进正文或通用协议代码                       |

本任务自含地采用这些公共规则：契约纯数据且不可变；普通可选字段兼容新增不升数据版本；破坏性变化升版本；安装插件不迁移旧节点；外部引用带来源与实体稳定身份；本机状态和派生缓存不进入共享正文；旧 epoch 增量不能合入新代次；跨存储靠日志和回执续做，不宣称一个总事务。

首期公共对齐限于领域隔离、已有 textFields/资源声明、稳定引用和宿主条件替换。板内富文本复用编辑器已有文档根能力；不为此要求普通作者新增 richTextFields、mapFields 或任意 references 声明。通用 Map、投票 API、任意嵌套富文本与自定义引用槽暂缓，实际插件有需求后另行设计。编辑器的代码步骤按已确认方案改为稳定 code-step 子节点与 textFields，保留逐步源码身份和并发语义；structuredFields 随旧路径退役，不开放为白板作者能力。旧格式转换仍走明确升级边界。

### 1.3 当前事实与修改接缝

- 白板通过 initData + onChange 保存快照；Board.apply 是统一操作入口，仍以数组路径寻址，本地历史保存逆操作。
- WhiteboardAPI 已隔离快照，提供 submit/updateElement/captureSubmission；后者判断生命周期和目标存活，不提供分布式修订比较。
- 现有插件定义是 schemaVersion + migrate，加载或插入会自动转换；新格式必须改为与编辑器一致的 dataVersion + previousVersions + migrations。
- 富文本框使用本地 contentId，脑图 text、连线 description 等字段另存内容；需要按所有权逐项转换。
- 当前编辑器并发移动候选按稳定节点池保留内容，placement 只选择位置引用；白板采用同一语义，不把候选文件当作已验收公共 API。

### 2.2 一份白板一个共享文档

首版一个多页白板对应一个 Y.Doc、一个远端 documentId、一个权限对象。页目录、全部页内容、板内文本和契约在同一文档，支持同房间跨页移动及组合操作；仍受单文档容量上限约束，不宣称按页懒同步。

独立白板内容页可拥有单页文档。同一工作区的一个稳定页面只选择一个活动协作拥有者，不能同时向整板房间和另一个页房间写入；从整板中的页发起共享应打开整板共享入口，并明确共享范围。若旧数据一页被多个板引用，盘点后保留一个拥有者，其余为引用，无法确定时停止自动绑定。该约束由本机已确认绑定和库基线实施，不宣称现有按设备身份的服务已提供跨离线设备的全局唯一发布：两个独立设备重复发布可能形成不同房间分支，发现同一实体多绑定时保留分支并让用户选择，不能自动拼接 Y.Doc 或静默覆盖一个绑定。

同房间跨页移动保留 elementId、字段根和引用账；跨房间第一期只支持显式复制，分配新元素与字段身份，来源不自动删除。将单页文档并入另一白板、按页拆分 Y.Doc 属于后续受控迁移，不用普通拖拽隐式完成。

### 2.3 唯一状态源与确认层次

活跃会话以 Y.Doc 为内容事实源，Board 树和主库 JSON 均是投影。主进程持有耐久状态及已确认基线，渲染进程持有同一文档的编辑副本；副本不能各自重新从 JSON 初始化文档。无活跃会话的 AI/CLI/复制写入口也必须临时打开同一文档服务，不能绕回旧的整页 SQL 覆盖。

一次本地编辑依次经历：投影可见、主进程日志落盘、服务器接纳。UI 区分“待本机保存”“已保存在本机/待同步”“已同步”；provider 已连接或 state vector 交换结束不等于业务持久化成功。拟议提交回执标记 batchId、documentId、epoch 和服务端确认序号；重试同一 batchId 只接受同一请求摘要。

网络协议按房间保存 documentKind，不能由客户端在普通更新里更改。票据、握手、每次更新均关联 documentId/protocolVersion/epoch；旧代次在进入 Y.Doc 之前拒绝。类型、schemaVersion、dataVersion、epoch、服务端日志 generation 各有职责，不能混用。

同一逻辑元素 ID 不证明两个 Y.Doc 具有同一 CRDT 基线。每代次记录确认的初始化/安装回执及基线摘要，加入会话从该二进制基线和增量恢复，禁止各窗口从同一 JSON 独立建图后相互合并。并发写副本使用不同 clientID；恢复数据中的历史结构 ID 保留，新写入不能让两个活跃副本复用同一 clientID 时钟。主库快照下载/恢复后先核对房间、代次和基线，不能仅按更新时间把旧投影重新编码发往现房间。

### 2.4 白板内核的绑定接口

可编辑 WhiteBoard 接受 document 绑定，不再把 initData 与 onChange 作为另一个持久化通道。静态预览使用显式只读 snapshot 模式，不能与可写 document 同时提供；独立示例通过本地会话工厂创建绑定，不强迫建立远端房间。

```typescript
interface WhiteboardDocumentBinding {
  getSnapshot(): Readonly<WhiteboardDocumentSnapshot>;
  getState(): {
    mode: "local" | "shared";
    writable: boolean;
    frozen: boolean;
    connection: "offline" | "connecting" | "connected" | "error";
  };
  submit(commands: readonly WhiteboardCommandInput[]): EditReceipt;
  subscribe(listener: (change: WhiteboardDocumentChange) => void): () => void;
  undo(): EditReceipt;
  redo(): EditReceipt;
}
```

以上类型在白板公开合同中只描述不可变投影、身份命令、修改 ID 集合和会话状态，不出现 Y.Doc/Slate Editor/主进程对象。变更通知携带 changedPageIds/changedElementIds 及来源类别，绑定器复用未变元素引用，避免每次文字输入重建整板或重挂编辑器。来源字段用于防止事件回环，不是插件可伪造的授权信息。

生命周期顺序为：宿主解析稳定目标并取得会话 → 恢复耐久基线 → 绑定画布 → 接收命令与增量 → 视图解绑 → 最后一个持有者释放时耐久收尾。Activity 隐藏仅暂停手势和 Presence，不销毁文档；解绑不能丢弃已发生的文字编辑。关视图时保存失败要保留会话/恢复队列并可见地报告，不把失败吞掉后宣称已完成。

## 3. 数据模型

### 3.1 身份

| 身份               | 规则                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| 外部 EntityRef     | { sourceId, kind, entityId }；来源随合法库快照传播，数值主键仅用于本机解析                          |
| 文档 documentId    | 本地/共享会话逻辑身份与网络房间映射由宿主管理；复制是新身份，开启共享不得把内容复制成第二个活跃会话 |
| pageId / elementId | 文档内唯一、删除后不复用；转换时保留可证明唯一的现有 ID，缺失/冲突走隔离修复并改写内部引用          |
| 字段根 fieldRootId | 由宿主创建并稳定保存；与 elementId、字段和契约建立绑定，移动/换页不更换                             |
| placement token    | 每次位置变更创建的新位置引用身份；不是元素身份，不承载文字                                          |
| deletionId         | 一次逻辑删除的唯一标识，用于并发删除、选择性撤销和幂等重放                                          |

板内文字身份不能拼入当前 pageId 作为必须重建的存储地址，否则换页又会改变共享文字身份。同一 room 内跨页只改位置，外部实体引用始终维持原对象身份。

### 3.2 Y.Doc 的逻辑分区

下表规定逻辑模型；W1 冻结公共文字根和契约命名，白板物理分区由 W2 落实，见本任务 W2 实现记录。父级列表储存位置引用，不嵌入或复制完整元素。

| 分区         | 存储/内容                                 | 写入规则                                                                        |
| ------------ | ----------------------------------------- | ------------------------------------------------------------------------------- |
| meta         | 协议与身份摘要、标题、描述                | 标题为共享文本；权限/epoch 的权威值在服务器，不能凭 meta 自报切换               |
| contracts    | contractId → 不可变 JSON 契约             | 新增可；同 ID 不可改；同 domain/owner/type/dataVersion 不允许不同摘要           |
| pages        | pageId → 页属性、删除标记集合             | 页名共享文本；画风等按明确属性单元同步                                          |
| pageOrder    | 页位置引用序列 + 每页当前 placement       | 使用与元素相同的身份/位置分离语义                                               |
| elements     | elementId → 稳定 Y.Map 记录               | 记录与共享子对象一经建立不因普通更新而整体替换                                  |
| orders       | parentKey → Y.Array<{ elementId, token }> | 保留被当前 placement 选择的唯一位置；陈旧引用不产生重复元素                     |
| strings      | fieldRootId → Y.Text                      | 文本句柄更新；不得另存权威字符串副本                                            |
| richTexts    | fieldRootId → 公共富文本文档根            | 使用经验证的稳定节点池模型，包含自己的节点/位置；不是移动时 clone 的 Slate JSON |
| presentation | 演示序列、帧、元素引用                    | 序列/帧有稳定 ID，顺序引用；删除目标不销毁历史，播放时跳过不可见元素            |

元素记录至少包含：

```text
identity      = { type, contractId }                 // 创建后普通补丁不可改
placement     = { parent, token, fallbackPageId }    // 单个原子值
geometry      = { x, y, width, height, rotation }     // 单个原子值，页坐标
style         = 按属性共享的宿主样式
data          = 按属性共享的插件业务 JSON
fieldBindings = 字段名 → { mode, fieldRootId }        // 宿主管理
creation      = creationId                         // 同次初始子树共享，宿主管理
deletions     = deletionId → 独立删除标记
```

文档另有 creations 可见性登记：creationId → true。撤销创建移除该次登记，重做恢复登记；初始子树记录和文字根不移除。之后其他人新建的子节点拥有另一个 creationId，不随原创建的撤销隐藏。

其中 parent 是显式区分的 page 或 element 引用；不存在裸数字路径。children、selection、viewport、activeTool 和拖动标记不进入元素持久记录。投影可以为旧渲染代码计算这些字段，但读出的投影不是可写状态。

geometry 的尺寸有合法范围、数值必须有限；颜色、名称等独立属性不与 geometry 打包。同一几何整体竞争采用共享寄存器的确定性胜负，不承诺按墙上时钟“最后点击者获胜”。批量 Yjs 事务不等于多个独立键在并发合并时必然全胜或全败。

### 3.3 三种数据作用域

| 作用域   | 内容                                                                               | 保存/同步                            |
| -------- | ---------------------------------------------------------------------------------- | ------------------------------------ |
| 文档     | 用户内容、关系、图形、文字、手绘 seed、页面默认画风、作者设置的布局/折叠、演示顺序 | 耐久保存、CRDT 同步、可撤销          |
| Presence | cursor、pageId、selectedIds、编辑目标、拖动预览                                    | 限频、可丢弃、有过期清理；不进入历史 |
| 本机实例 | 视口/缩放、工具、悬停、弹窗、跟随状态、侧栏、测量/编译缓存                         | 临时状态或不参加库同步的本机存储     |

按语义分类，不使用字段名黑名单。column.collapsed 等若表达作者要共享的布局继续是文档属性；单人查看折叠须另走本机视图句柄。context.storage/IPluginStorage 可能随库同步，不是本机状态仓库，更不是房间共享状态。

### 3.4 白板文字与外部正文

富文本框、脑图主文字、图形描述、连线标签和框架标题均登记为字符串或富文本字段。板内富文本根与板在同一 Y.Doc，共用契约字典但使用独立根作用域；编辑器基础绑定需接受传入根，不能硬编码顶层 content。

文档卡、脑图关联笔记、白板引用等保持外部引用。旧 contentId 是否表示板内独占正文必须查持有关系：仅当前白板元素独占时可在基线转换中迁入板内根；存在其它业务持有时维持外部正文身份，不能偷偷复制后使两处各自修改。盘点不完整则保留外部引用或进入待恢复状态。释放旧正文必须先获得新根安装和关系账回执。

## 4. 契约与插件接口

### 4.1 同一契约格式，不要求同一 UI 外壳

公共契约信封在现有规范化器上扩展领域及结构，沿用其 format、owner、type、dataVersion、字段与 resources 语义，不另定义一套 contractFormatVersion/字段布局或摘要函数。domain 区分 editor-node 与 whiteboard-element；归属由宿主加载身份绑定，摘要不构成代码可信或权限证明。该差异已在 W1 收口为格式 2 与独立冻结样例，规范及验证见“W1-v1 冻结稿”；正式房间尚未切换。已持久化的契约不能补 domain 后原位重算摘要，改变格式要使用新契约格式/文档门禁及受控转换；仅未发行、未持久化的候选可在发布前统一重定。

字段解析统一面向“业务载荷”：编辑器为节点业务属性，白板为 element.data。作者声明 textFields: ["source"] 在白板中指 data.source，不必写 data.source；宿主外壳字段不允许通过该路径寻址。资源路径同样相对业务载荷，直接复用 ContentResourceSpec 的规则；不另造白板路径语言。内置外部引用由宿主已支持的固定槽写入契约，插件首期通过现有实体组件/引用命令操作这些槽，不能声明任意引用扫描回调或新的 references DSL。

默认普通字段逐顶层键合并；对象和数组是原子 JSON。字符串声明 textFields 后由 Y.Text 管理，不能与资源地址字段、宿主引用槽或身份属性重叠。板内富文本由宿主的已知文字槽映射到公共编辑器根，不给插件增加任意字段建模语言。资源/引用槽只描述如何发现数据，不自动下载、解析或授权目标；不认识槽规则的宿主不能猜测解释。

固定富文本/实体槽同样由相应扩展生成纯数据契约，缺插件时仍可解释；不能只藏在最新宿主 type→字段表里，或恢复业务类型黑名单。首期不向作者开放任意槽声明，不等于协作层可硬编码内置类型。

structure 保存宿主可解释的白板外壳能力：通用几何、是否允许收纳、允许的容器类别等纯数据。render、getBounds、move、schema JS 函数、菜单及插件发布版本不进入摘要。服务端不执行作者 Standard Schema 或迁移函数；只校验公共协议、字段存储类型、契约约束、资源/权限及预算。任意插件业务不变量不能假装由服务器担保。

### 4.2 元素声明与首期 API 范围

保留 defineWhiteboardExtension/defineElement 入口，版本规则直接采用编辑器的 dataVersion、previousVersions、migrations；当前 schemaVersion/migrate 的历史转换留在升级入口，新运行时不维护两套版本字段。首期协作声明只增加与编辑器一致的顶层字符串 textFields，资源使用同一 ContentResourceSpec。不是所有插件都必须为协作增加声明，只有确实需要字符串并发编辑的字段才声明。

```typescript
interface WhiteboardElementContractOptions {
  dataVersion: number;
  collaboration?: { textFields?: readonly string[] };
  resources?: readonly ContentResourceSpec[];
}
```

这是现有元素定义的增量片段；render、创建、schema 和展示贡献沿用原接口，历史版本与迁移复用编辑器公共类型，不再复制一套泛型递归定义。仅调整发布 SDK 的兼容版本不能自动转换已有元素。

previousVersions 只认当前定义直接列出的精确版本，同归属/领域/type/version 不得重复或对应不同契约；read/edit/none 的保护规则与编辑器一致。migrations 只允许明确旧版直接转当前版，来源必须登记；输入输出仅业务载荷，不含 ID、placement、geometry 或子树。函数必须纯数据、保留不主动删除的未知字段，不访问时间、网络、随机数和数据库。涉及结构的转换不能套用该属性迁移接口。

### 4.3 保留现有操作入口，增加必要的字段写入

继续使用 WhiteboardAPI.getElement/updateElement/subscribe；不另建 useWhiteboardElement、api.element 和每元素完整 store。updateElement 只接受允许的普通外壳 patch，geometry 由宿主编译成完整几何值；不能通过 data 整对象覆盖、type、children、契约引用或字段根绕过约束。

首期作者数据能力按 W1-v1 冻结稿和可编译类型夹具收口；下表概括入口，精确参数和返回值以冻结稿为准：

| 能力                                                    | 行为                                                                                                                      |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| updateElementData(id, patch, { unset?, historyGroup? }) | 只修改 element.data 中明确列出的普通属性；未知属性不丢失；unset 显式删除，不跨进程传 undefined；与 patch 同键冲突整批拒绝 |
| getTextBinding(id, field)                               | 返回与编辑器相同的公共文本绑定，按当前契约验证 textFields；不另定义白板 TextObservation 或自定义文本 CRDT                 |
| submit(身份命令数组, { historyGroup? })                 | 沿用批量提交概念，创建/移动/删除由稳定 ID 与锚点表示；不再公开数组路径和跳过历史/校验的 apply                             |

updateElementData 不得修改声明的文本、宿主引用、身份或结构字段；创建时缺失的文本初始化为空字符串，已有非字符串拒绝或进入显式转换，不能在加载时强制改值。数据句柄不暴露跨房间状态，也不把每次按键包装成作者要管理的网络回执。

普通同步方法只返回本机接纳结果或抛出公共错误，绝不承诺已落盘/已上传；耐久与远端确认由文档会话统一展示和 flush 等待。文本自定义输入直接采用编辑器 T1/T5 冻结的签名和观察版本规则，处理 IME、选择映射和过期输入；标准组件优先复用。实时输入不得积压成延迟整段 onChange，预览/编译可防抖。

例如源码图形声明 textFields: ["source"] 和 cover 资源槽：标题经 updateElementData 只改 title；输入组件取得 getTextBinding(id, "source")；封面先经宿主资源服务，再提交已处理引用。普通 updateElementData({source}) 拒绝。没有 mapFields，普通 votes 对象整字段更新也不承诺多人投票不丢计数；需要投票时另做实需设计，不能隐式退化上线。

### 4.4 批量、异步结果和条件替换

submit 接收同步构造的身份命令数组，先完整验证再一次提交，沿用现有批量结构，不额外引入通用事务回调 DSL。先校验权限、目标、版本、资源与预期结构；一个命令无效则零写入。Y.transact 不提供数据库式异常回滚，不能先改共享数据再靠抛错撤回。上传/AI/网络副作用在提交外执行；提交失败不得误释放其他成功引用的资源。

本地交互仍可产生 path 操作，但绑定器只能按操作生成时的当前投影修订立即解析为 ID；修订不匹配则重读/重建命令，不能把旧路径重新解释成新位置。beforeId/afterId 仅作为当前父序列锚点，两者互斥；锚点失效或已换父时拒绝本次提交，不能静默改成尾插。跨端已成立的位置由 CRDT 序列合并。

captureSubmission 仅表示生命周期和目标仍有效，不表示期间没有内容变化。AI/格式化/导入等整段替换由宿主公共替换入口接收基于旧输入的提案，首期只做已有语义明确的文本替换或受控布局命令，不开放任意读集合/任意条件写入 SDK。

共享条件操作必须在线：先冲刷并确认本机该文档待发送编辑，基于服务器已确认的 documentId、epoch 和单调文档修订读取输入，提交时服务器串行校验同一修订、权限和目标，再接纳正式增量。首期采用整文档修订，其他区域变化也可能导致保守冲突；不先建设逐字段版本索引、依赖追踪或通用 CAS 框架。纯本机会话由本机文档服务按相同条件串行裁决，不要求联网。

检查保护的是服务器已经接纳的基线，不承诺屏蔽其他端尚未上传的编辑：同 epoch 的合法离线增量后来仍按普通 CRDT 合并。替换等待期间调用端目标冻结为预览，不能积累新的同目标编辑又在成功后假装它们已被条件保护；用户取消/继续编辑先处理待决操作。要求清除全部旧增量的变化必须走 epoch 迁移，不能借普通条件替换实现。

条件操作的 operationId、请求指纹、PENDING/COMMITTED/ABORTED/EXPIRED 和未知结果处理复用宿主回执协议；相同 ID 不换候选，超时不代表失败，取消必须得到服务端终态。成功增量在发起编辑视图中按宿主保存的命令关联加入一次本地历史，其他视图视为远端；回执和同步消息无论谁先到、重复到达，都不重复应用或记历史。不能用客户端自报 origin 代替服务端鉴权。重启不恢复内存撤销栈时仍保存结果与操作回执，不伪造可撤销状态。

公共错误与编辑器一致，区分目标失效、只读/冻结、不支持契约、无效编辑、修订冲突、需联网、超限和回执未知。修订冲突/结果未知保留提案，不自动重新读当前内容替换原提案的基线，也不静默自动提交。

### 4.5 插件版本与缺失行为

| 场景                         | 行为                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------- |
| 发布版本不同、支持同一契约   | 正常协作                                                                               |
| 新插件支持旧版 edit          | 按旧契约编辑，不能用新版 schema 改写旧载荷                                             |
| 旧版 access=read             | 只读渲染；内部命令、normalize、后台写入均被宿主拦截                                    |
| 缺插件或无匹配契约           | 保留完整数据/字段根/子树，显示占位；可整体复制、移动、删除与撤销，不允许改内部业务字段 |
| 公共外壳可解释               | 允许通用平移；未知自定义几何不猜测缩放/布局，不能把其子节点拆开编辑                    |
| 宿主不认识协议或必需合并模式 | 拒绝可写会话，保全本机数据并提示升级                                                   |
| 卸载/回退插件                | 不删除数据，不回退数据版本，不自动安装代码                                             |

兼容保护是宿主 SDK 的正确性约束，不是“客户端必须安装某插件才有房间编辑权”的安全协议。当前同运行时插件没有完整沙箱；服务器仍从设备/成员身份授权，不能信任插件传来的 pluginId 或本地 origin 作为权限凭证。

## 5. 冲突处理协议

### 5.1 位置与内容分离

移动时只在目标父序列插入 {elementId, token}，并原子设置元素 placement；不删元素记录、不复制文字根。投影仅展示同时符合“token 等于当前 placement.token，parent 等于当前 placement.parent”的引用。因此两人移动同一元素只选出一个位置，原共享文字上的两端编辑仍存在。

同一父级不同节点插入由共享序列决定稳定顺序；同一元素位置竞争由 placement 寄存器选择一个完整值。一次移动产生的 token 唯一，同一 {elementId, token} 只能有一个位置引用；服务器拒绝复制该引用到两个位置，重复网络重放由 CRDT 结构 ID 幂等消除。普通更新不得替换整个父序列，无效的陈旧位置引用在当前 epoch 保留以支持撤销和迟到更新，不在观察器里各自删除。

与编辑器候选共用上述规则和夹具，白板纯元素顺序使用 Y.Array，编辑器可继续使用字符/节点混排序列。共享的是身份、选择和恢复语义，不把两种序列强行变成一个 UI 数据结构。

### 5.2 删除、恢复和循环

删除采用按 deletionId 区分的标记集合，而非物理删除元素池。一次“删除容器及内容”明确记录用户当时观察到的子树 ID 集合；集合内各元素增加同一删除标记。属性或位置更新不移除删除标记。两人都删除同一元素时，撤销一人的删除只移除其标记，另一人的删除仍有效。W1 本轮已在公共 NodeTree 候选中实现独立删除集合，编辑器删除命令提供观察到的子树 ID，removeNode 仍只表达删除指定节点；尚未接入白板 UI 或正式数据格式。

删除事务必须包含删除根和完整的已观察 ID 集合，集合由发起视图的同一修订快照产生并随命令记录；不在接收端按“现在的子树”重新扩张，否则迟到的新子元素也会被误删。deletionId 及观察集合不可复用为另一删除；撤销/重做只操纵该命令的可见性标记，不改变观察集合。

投影顺序固定如下：

1. 排除带有效删除标记的元素，保留原始记录及文字。
2. 根据当前 placement 选父关系，校验公共收纳规则；目标已删、缺失或不可收纳的节点进入恢复集合。
3. 在剩余父图上检测环；每个环按 elementId 的字节序选最小节点断开该父边，仅改变投影，不写回共享 placement。
4. 从有效页根和恢复根按确定性顺序遍历，超过公共逻辑层级上限时切断第一次越界父边并将整段子树作为恢复根，不仅限制 JSON 的物理嵌套深度；检测与遍历均受节点总量预算限制。
5. 正常子树按有效序列位置显示；恢复根按 ID 排序放到 fallbackPageId 页根的恢复分区。原页不存在/已删时放文档恢复区，不任意选另一业务页，也不自动创建持久页。元素的正常有效页从选定父链求出，不能把陈旧 fallbackPageId 当作跨页后的真实页归属。

恢复分区是原数据的派生入口，不复制元素；显示原因并提供显式恢复位置命令。普通客户端命令仍提前拒绝已知的环或非法收纳；服务器允许由合法并发产生且可按上述规则投影的环/悬挂，不因它们拒掉其中一端全部编辑。格式伪造、配额越界和未经授权的写入仍拒绝。

### 5.3 冲突矩阵

| 并发场景                      | 明确结果                                                                               |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| 同元素改颜色 / 移动           | style 与 geometry 独立，两者都保留                                                     |
| 同元素两个几何变化            | 选中一个完整 geometry；不拼成甲的 x 和乙的 y；可提示有人同时操作                       |
| 同元素双端换父/换页           | placement 只选一个位置；不出现两个相同 ID，内容身份不变                                |
| 移动 / 修改文字               | 位置按规则确定，文字按原根合并                                                         |
| 删除元素 / 修改属性或文字     | 删除在可见性上生效，更新留在保留记录；有效删除全部撤销后显示合并后的内容，不恢复旧快照 |
| 删除父子树 / 子元素移出       | 若子 ID 在该删除的观察集合内，仍删除；“已看见的内容随删除”优先于并发移出               |
| 删除父子树 / 新子元素同时插入 | 新 ID 不在观察集合内则保留，父不可用时进入恢复区；不能静默丢掉未被删除者看见的内容     |
| 两次删除 / 一人撤销           | 另一删除标记仍有效，不复活                                                             |
| 两节点互相移入                | 按确定性断环规则得到一个可见无环投影，各端相同，原数据保留                             |
| 同位置插入不同元素            | 共享序列保留两个 ID 并稳定排序                                                         |
| 删页 / 将元素移到该页         | 删除观察集合中的元素仍删；集合外落入不可用页的元素进入文档恢复区                       |
| 删除连线目标                  | 绑定原值保留，投影为悬空端点；显式重新绑定才改引用                                     |
| 异步插件结果 / 期间内容改变   | 条件提交冲突，保留草稿；不自动用过期结果覆盖                                           |
| 离线旧契约 / 新 epoch         | 拒绝旧增量进入新文档，保全后进入恢复流程                                               |

这是设计采用的产品语义，不承诺所有并发意图同时获胜。W1 必须把“父删子移”和恢复区行为做成明确夹具，若用户后续改变语义，回到模型阶段修改，不在 UI 中局部打补丁。

插件本地 schema 验证通过，不保证两个各自合法的字段修改合并后仍满足跨字段约束。例如 min/max 若必须成对合法，应作为一个普通 range 对象原子更新，或使用平台能够验证的条件命令；不能由各端在收到结果后擅自改值“修复”。不能识别的业务异常以只读错误展示保留数据，恢复动作必须显式提交；服务端只承诺其实际执行的规则。

### 5.4 几何、连线与布局

首版沿用页坐标，geometry 为每元素的用户几何输入。父子关系不隐式把 x/y 重新解释成局部坐标，换父本身不改变几何含义。移动自由容器时将观察到的子树位移编译为每元素 geometry 变化；同一 batch 是一次本地撤销步，但并发竞争仍逐元素裁决，不承诺整组几何冲突全胜全败。

连线两端各有一个原子绑定值，包含目标 ID、锚点和最后已提交的自由端点位置；目标不存在时显示该自由端点，目标恢复后可重新解析原绑定。路由、碰撞路径、吸附和指示线是派生结果，不在每个接收端写回文档。跨页端点第一期视为不可连接，保留数据并提示，不自动搬动目标。

column/脑图保存顺序、布局参数、手动尺寸等用户意图；由本机投影计算排布和包围盒，远端更新不能触发 relayout → board.apply → 再次广播。文本 DOM 高度、截图、预览和布局缓存移出持久元素。不同字体环境可能产生视觉测量差异，第一期承诺相同文档与布局规则，不承诺逐像素同尺寸；差异不得回写成持续争夺的共享几何。

从自动布局容器拖出时，将发起者当前可见几何作为一次明确的用户 geometry 提交；普通自动重排不写该值。插件自行请求自动排版时生成有修订依据的布局提案，经条件提交一次应用，其他端只接收结果。内置与官方元素需逐项列出“用户几何、派生布局、本机反馈”的字段归属并验收，不能用全局字段名过滤猜测。

### 5.5 撤销与手势

每个编辑视图一个本地 origin 与一条白板历史，包含所有页面、板内文本和内置/插件主动操作；同机另一个窗口是另一视图。origin 不用于网络鉴权，远端投影和缓存维护不入用户历史。首期不支持按任意字段/元素筛选旧历史，也不持久恢复进程重启前的撤销栈；这不减少内容和未确认编辑的耐久保存义务。

白板自有文字与画布共用该视图的唯一 UndoManager/历史协调器，按时间撤销最近一步，进入/退出文本、切页和手势结束显式分组。聚焦板内文本不跳过较新的画布历史去寻找旧文字步骤，也不创建第二个独立文本 UndoManager；外部文档卡的正文属于另一个文档，焦点在其编辑器时才路由到该文档历史。公共富文本绑定必须支持注入宿主 history/origin，当前每编辑器自行创建管理器的候选不能直接组合使用。

创建元素时的稳定元素池记录和文本根是初始化事实，不随用户撤销物理删除；创建的撤销移除该创建 ID 的可见性登记，重做恢复登记，保留之后的远端文字和属性。需要以宿主历史元数据协调初始化与可见性操作，不能让默认 UndoManager 把整个 Y.Map/Y.Text 从池里移除。创建撤销仍保留他人并发创建的子元素，按恢复投影规则处理。删除的撤销只撤回本次 deletionId，不移除别人的删除标记。

撤销本人旧位置/属性不覆盖已胜出的远端写入，恢复使用当前合并记录而非旧 JSON；redo 也不能盲目恢复已被别人改写的几何/位置。位置引用、可见性标记、文本创建及被跳过的撤销项必须有明确组边界；条件操作的成功增量按第 4.4 节关联一次历史。B07/B28 在通用 UndoManager 上无法满足时由宿主补命令历史逻辑，不以一个库名代替保证。

拖动使用本机覆盖层 + 合批 Presence 预览，结束提交最终几何。预览带 interactionId、目标 ID、序号和已观察基线；文档提交、取消、过期、删除或换页后清理，不能盖住新持久状态。普通多元素拖动仍按元素竞争，不承诺整组同时获胜。长笔迹以唯一笔迹 ID 和稳定段序列分段落盘，跨段归同一手势历史，笔迹定稿不替换已共享段根；崩溃最多损失未落盘尾段。

## 6. 服务器、资源和恢复

### 6.1 文档适配器与验证

正文/白板分别实现创建、候选校验、摘要、资源扫描和本机投影适配器；网络不再默认调用 readSharedContent。SourceBinding 扩为明确种类的正文/整板/独立页绑定，远端来源使用稳定实体身份，本机数值 ID 仅作映射。

服务器候选验证覆盖：固定文档种类、协议/epoch、契约摘要与不可变性、稳定 ID 唯一性、字段实际共享类型、位置引用完整性、外部引用结构、资源引用和大小预算。创建元素、契约登记、文字根初始化必须同批接纳，不发布缺半边的节点。JS schema 仅用于本机前置反馈，不能由不同插件版本对已接纳的远端数据各自修改或拒收。

普通更新还必须保留已存在元素记录和字段根的 CRDT 存储身份，不能仅保留 elementId/fieldRootId 字符串就用新 Y.Map/Y.Text 覆盖旧对象。否则远端继续编辑旧共享根时，内容仍会不可见。W1/W5 为此固定可验证的身份检查与夹具，存储根重建仅允许经过迁移屏障；JSON 投影相等不构成身份相同的证据。

接收端对“宿主理解协议、插件不理解业务数据”的状态保真投影；对协议本身不支持或损坏的状态终止可写连接并保全。服务端拒绝某个本地更新时，该副本可能已含被拒的 CRDT 结构：先耐久保留未确认副本/命令，再从已确认基线建立新会话副本。不能简单撤销一次 UI 操作后继续发送含被拒结构的增量。

普通增量还需经过因果完整性检查：若缺少它引用的先行结构，不能把尚未物化的候选当成“空改动、已校验成功”。缺依赖的消息只在有界待决队列中等待/请求补齐，不进入已确认基线、不返回业务成功；依赖齐备后对实际结果校验并耐久接纳。被拒、过期或错代次的祖先更新所依赖的后续增量也要隔离恢复，不能跳过失败批次继续污染现会话。B13/B32 覆盖乱序、缺依赖与补依赖后的非法字段。

### 6.2 资源、引用和保留

资产沿用 tau-collab-asset 引用、成员鉴权和私有 R2；上传、配额、内容摘要和回收仍由宿主负责。插件资源按元素所引用的精确契约扫描，未知插件也可处理。二进制不塞进 Y.Doc；本机引用不会被伪装成可共享资产。

关系账以文档身份、元素/富文本节点身份、引用槽和目标身份去重；同一提交多窗口重放只产生一次关系变化。板内根移动不增减关系；复制新元素产生新关系。共享关系、主库关系与本机恢复持有各自归属明确，本机持有不上传为其他设备的引用计数。

当前记录扫描不足以覆盖历史：例如把图片 A 替换成 B，活跃元素和文字根可能都已不再引用 A，但撤销仍需要 A。首期为每个代次维护宿主生成的历史资源保留清单，提交时根据已确认旧状态和新状态登记曾引用的资源；当前引用、删除/恢复记录和历史清单共同阻止回收。该清单是资源账务，不是插件可写文档字段，也不依赖仍有窗口在线。未上传成功的资源由本机未确认记录保全。

历史截断与资源自动回收不在本轮执行。新代次只安装校验通过的候选，旧日志不自动清理；当前与历史资源继续由已有持有账管理，不另建恢复包持有关系。

普通日志压缩不等于业务墓碑/陈旧序列可安全回收，也不提高 epoch；只有改变 CRDT 基线或历史语义时才走迁移屏障。隔离后的离线旧增量不能复活已回收对象；本轮不清理旧日志或历史资产，不承诺超出已有存储范围的恢复能力。

内容引用到已共享文章时独立鉴权；白板成员资格不传播。原文档标题/摘要快照若已存于元素，属于实际共享数据，开启共享前列入摘要确认；不能因目标未授权就假定已有快照未泄露，也不自动补抓更多内容。

### 6.3 同步与容量

当前 8MiB 单文档、12MiB 活跃编码状态总预算和 600 次/分钟/连接 Presence 限额作为现状约束，不直接增大。Presence 初始试验采用整条连接总计 5–8 次/秒并预留心跳余量；光标、选区、拖动合批。限额按连接而非画布分别使用，多房间复用连接时共用调度器。

服务器目前每次增量构造候选文档再校验落盘；需要对白板手势、笔迹、复杂文本和保留历史压测。W9 记录 100/1000/5000 元素、2/5/10 成员、多页、长会话及离线重放的 CPU、实际内存、消息字节、落盘耗时和恢复耗时，确定上线预算；这些是测试矩阵，不是性能承诺。到达容量阈值明确拒绝扩张并保留本地未确认内容。

## 7. 迁移边界

### 7.1 五类变化分别处理

| 变化                                           | 方法                                                                      | epoch / 权限                                           |
| ---------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------ |
| 首次把本地旧 JSON 转为新白板会话               | 本机基线转换；盘点正文/引用/资源/本机状态，先固定候选与原修订再安装       | 不涉及远端 epoch；本机跨存储日志必需                   |
| 新格式白板首次开启共享                         | 冻结并生成无旧历史的候选，准备私有房间/资产暂存，验证资源后激活并幂等绑定 | 新房间初始 epoch；用户发布授权，不自动因正文共享而触发 |
| 安装插件、兼容可选字段新增、插入新版本元素     | 正常读取/编辑，旧元素保持旧契约                                           | 不提高 epoch、不冻结整板                               |
| 同类型旧元素数据版本转换                       | 用户主动预览，宿主校验；第一期默认走共享迁移屏障                          | 共享所有者发起；改变字段语义/根身份时提高 epoch        |
| 存储模型变更、拆房间、历史截断或不兼容结构升级 | 专门宿主迁移，不通过插件普通 migrate                                      | 受控代次切换；无已验证流程则拒绝                       |

首版不建设通用“无 epoch 任意迁移”。可证明保持全部旧写入语义的特定转换才可在后续注册为条件转换；不能相信作者声称兼容。改样式、移动、普通可选字段和新增节点不是迁移。

### 7.2 旧白板基线转换

盘点所有白板入口：整板及页目录、独立内嵌页、创作模式页、正文白板引用、脑图笔记、插件元素、备份/导入、协作旧私有真身。不能只扫描 white_boards，漏掉没有对应板行的 white_board_contents。

同源旧库采用编辑器已确定的流程：选定完整库生成并发布含 sourceId/稳定实体身份的确认基线，其它设备在本机保全后采用该快照；独立离线升级的库先视为分支。页面归属、ID 修复和“正文迁入板内还是保持外部引用”的转换计划也随基线保存摘要/回执，不能让各设备按不同的本机缓存或 ref_count 各做不同裁决。独占证明需扫描正文关系、白板/其它实体持有、未投影任务及本机恢复记录；存在未知持有则暂不迁入/释放，裸计数为 1 不是证明。

1. 在隔离副本建立来源/实体身份与页面归属，校验重复元素 ID、连线、演示帧及外部引用；歧义记录候选，不按相同整数主键猜测。
2. 根据可验证历史定义建立旧数据契约，逐项提取内置字段；第三方未识别字段不按名称删除，缺插件使用当前协议的不透明契约保留。
3. children 转稳定元素池和位置引用，旧 schemaVersion 按明确映射转 dataVersion；未知版本不套用最新插件声明。不执行加载期自动 migrate。
4. 按持有关系处理 contentId：独占板内内容迁入字段根，共用/外部正文保留引用；文字、marks、插件节点、未知字段、资源逐项对账。
5. selection/viewPort、拖动反馈和可重建缓存按可靠定义迁到本机状态或重建；可重建性无法证明的作品数据原样保留，不能把仅存 SVG 当缓存删除。
6. 在现有迁移日志中保存候选与安装参数，安装新会话状态及主库投影，各库回执齐全后才开放新写入；失败保留原数据，禁止“尽力转换后继续保存”。

重复 ID 修复必须生成完整映射并更新所有内部引用；若一个旧 ID 对应多个候选、无法判断连线原目标，则保留歧义恢复记录，不武断指向第一个元素。ID 正常的元素不因基线转换随意换号。

### 7.3 首次发布与结束共享

首次发布的共享候选从用户确认的当前内容重新构建，保留可保留的页面/元素逻辑身份，但创建独立的共享 CRDT 基线。不能上传整个本地 Y.Doc 编码：其中可能含已删除内容、旧属性、恢复区和本地历史资源，清掉 UndoManager 也不等于删除这些数据。候选只含确认范围内的页面/元素、必要契约、板内文字和获准资源；恢复区或历史内容需单独明确选择，不自动加入。相同规则适用于关闭后再次发布。

步骤固定为：本机 flush 并暂停受影响写入 → 确认原日志已落盘并停止旧写入 → 固定发布范围和候选指纹 → 幂等准备仅创建者可访问的房间/资产暂存范围 → 上传并验证候选所需资产 → 服务端条件激活房间并保存回执 → 本机按回执绑定新基线 → 恢复编辑。正式成员加入、邀请及文档下载在激活前禁止；不能要求尚不存在的房间先完成成员鉴权上传。暂存超时/取消按操作终态回收，不误删已被激活房间引用的资产。

新共享基线不是复制出第二个可写业务实体：稳定来源/实体身份保留，本机旧状态仍留在原日志，旧活跃会话停止写入，旧撤销历史不跨发布边界。原本待发的本机二进制增量不得自动补发到新基线。发布窗口内的用户操作要么被阻止、要么明确保存在未提交草稿中；首期选择暂停写入，避免实现第二套发布队列。

服务端提交成功、本地安装失败时继续使用同一回执续装，不能再建一个房间；结果未知先查询或受控取消，同 operationId 不换候选。明确取消成功后才能恢复旧本机会话继续编辑；服务端已激活不能单端假装取消。首次发布也使用固定请求身份与持久终态，不能只给后续迁移提供这项保证。

首次发布不扩大外部实体权限，标题/预览快照作为实际数据纳入范围确认。结束共享、退出与被撤权不同：主动关闭时在权限仍有效期间保存已获准下载的状态和可用资产；被撤权后只能保全本机已有副本/未确认内容，不能继续下载服务器资产来完成“完整备份”。缺失资产明确记录，不伪造完整恢复。解除绑定后关闭旧连接与写队列，房间关闭和本机引用释放分别记账；再次发布使用新的分享实例，不复用旧房间身份来接纳迟到请求。

### 7.4 已共享数据的迁移状态机

与编辑器采用同一状态机和操作身份，不建立白板专用的第二套恢复协议。

| 本机阶段/服务端裁决                      | 必须成立的事实                                       | 恢复行为                                               |
| ---------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------ |
| PREPARED                                 | 原日志已落盘；候选、安装参数及指纹已在迁移日志中固定 | 未满足不得提交                                         |
| 服务端 PENDING                           | 已登记 operationId、发起者、旧 epoch、截止条件及屏障 | 等待、受控取消或到期裁决；客户端不自行假定失败         |
| 服务端 COMMITTED / 本机 SERVER_COMMITTED | 服务端同事务安装候选、新 epoch 和固定回执            | 响应丢失按 operationId 查询，不重做另一候选            |
| LOCAL_INSTALLED                          | 本机缓存、主库投影、本机状态和关系账按回执分别安装   | 从未完成存储续做，不能单端把旧 epoch 写回去            |
| COMPLETE                                 | 全部本机回执匹配、新格式可读、旧运行分支按清单清理   | 旧日志保持原样，不自动回收                             |
| 服务端 ABORTED / EXPIRED                 | 已持久化不可逆终态并释放屏障                         | 保留原数据；新尝试新 ID、新基线；迟到旧请求不能复活    |
| 查询无记录/网络失败/权限不明             | 无法证明远端未提交                                   | 继续保全和查询；可请求原子取消确认，不能清理或回滚猜测 |

迁移流程：所有者准备 → 在线端冲刷 → 最终写入屏障固定服务端修订 → 在受控客户端运行纯数据转换 → 服务端验证候选并条件提交 → 各端保全未确认内容后安装新代次。不会无限等待所有离线设备；离线设备回来的旧增量留在原日志/outbox；存在旧草稿时拒绝自动接入新基线。

同 operationId 不得换候选或目标；提交/取消/超时由同一服务端事务裁决，终态保留或压缩后仍永久拒绝旧请求。新 epoch 在进入文档前门禁，不仅靠收到新正文后的客户端检查。迁移以整个白板文档为代次单位，即使只转换一个元素，也要冻结/重绑该文档所有页、板内文字、缓存和连接，并清理这些视图的旧撤销历史；不能仅重绑可见页，让隐藏页继续发旧增量。外部被引用文章是另一文档，不随之冻结或清历史。普通兼容编辑不清空历史。

纯本机转换跳过远端阶段，但先保存本机提交决定与固定候选，再分别安装缓存、主库和本机状态；本地已提交不能改标取消，结果未知查本机日志。服务端 COMMITTED、本机未安装阶段继续暂停目标文档，不允许主库的旧 JSON 自动保存重新覆盖新状态；所有安装与引用账完成后才解除暂停。

插件仅转换业务载荷，保留不主动删除的未知属性；源码 source → code 必须检查目标字段不存在，转换文本内容并由宿主重建目标绑定。不能只改 JSON 键而保留旧根映射继续接收旧更新。作者没有权限指定 epoch 或绕过屏障。

以同一源码插件 v1 → v2 为迁移验收基线：v1 声明 source 为文本；v2 改名为 code，保留 v1 定义且 access=edit，登记 from=1 的直接转换。安装 v2 后旧元素继续使用 source，新建元素使用 code；所有者主动迁移时，宿主保留 elementId、placement 和 geometry，只转换业务载荷/契约及对应字段根，因旧文本增量不可安全套用而切换 epoch。输入已含 code 或来源不是字符串时整次转换失败。v1 客户端重连只能保护 v2 元素，不能凭旧类型名继续写 source；离线旧输入保留在原日志/outbox，不自动拼接到 code。

### 7.5 与旧 private blocks 转换的边界

旧正文里的白板真身可能在其他成员设备；白板任务不能绕过编辑器的“持有者明确提供、所有者明确公开”流程自动上传。正文任务恢复的是引用，白板任务处理实体自身的格式；两者用稳定实体身份和安装回执衔接，不要求一个跨库总事务。

来源只有占位或依赖实体缺失时，记录缺失状态，不假定实体已转换。整库替换沿用宿主已有安装入口及校验；白板本轮不增加替库恢复功能。

迁移完成后的正常运行时拒绝旧格式；历史解析器只留在独立升级发行路径，供跳过版本的设备执行明确升级。当前格式不透明元素和未来版本转换不是旧格式兼容层。未完成真实迁移的存储不得为了删码而假装已升级。

## 8. 存储、复制和导出

主库新增白板文档拥有者/页面映射及协作绑定的稳定身份字段，复用公共身份表时不重复建表；white_board_contents.data 保存带协议版本、内容/契约和投影修订的本页投影。完整契约字典与会话状态归文档拥有者，页投影可以引用字典，独立导出时补齐所需字典。W4 固定 whiteboard_documents / whiteboard_document_pages / whiteboard_entity_relations，旧数据转换由 W8 负责；不直接把白板 ID 塞入现有 collaboration_bindings.content_id。

主进程先耐久写 CRDT 更新与待投影记录，再在主库事务内更新页/板投影和关系账；缓存库与主库没有总事务，按 documentId/epoch/投影修订幂等续做。读取先确定匹配代次及较新耐久状态，不使用旧主库快照覆盖协作日志。切库、关页和 Activity 隐藏不清掉仍有持有者的会话。

内部复制/普通无损导出以用户选定的当前投影为范围，携带页面、元素、契约、字段内容和资源/引用清单，不直接搬运全部原始 Yjs 历史；复制分配新 ID 与新共享根，重写副本内部连线和演示引用，外部实体保持原引用且不自动授权。剪贴板与包内不得夹带本机视图、凭据或隐式本地路径。本轮不新增历史恢复导出。

跨房间复制资产与外部实体引用不同：源房间的 tau-collab-asset ID 不能直接写入目标房间并沿用源 ACL。宿主先以当前源权限读取或使用已合法保全的文件，再在目标权限下导入/登记资产并改写引用；底层按摘要去重不扩大读取权限。源不可读或目标上传失败时保持导入未完成、原节点不删，不生成声称完整但缺资源的副本。未知插件同样按携带契约扫描，不能依赖其运行代码。

PNG/SVG 是视觉导出，不承诺可编辑恢复；含未知插件且无法完整渲染时，默认报告不支持并停止“完整导出”，用户明确选择占位导出后才生成带缺失标记的结果。无损包不依赖插件渲染，始终保留原契约和载荷；不把旧数据送进仅支持新版的导出器。

### W1-v1 冻结稿

本节收口本轮此前未决的格式、签名与预算；覆盖前文仍写“待 W1 固定”的对应项。冻结的是公共基础能力和后续批次必须遵守的契约，不宣称白板协作产品、服务器准入或 SDK v2 已接线。若此后修改冻结内容，须显式修订 profile/格式/API 版本并同步夹具，不能用实现便利改变既定语义。

#### 多根与宿主历史

- 公共入口固定为 new NodeTree(doc, { rootId? })；省略 rootId 为 content，其它 ID 符合 [A-Za-z0-9][A-Za-z0-9._-]* 且长度不超过 128。拒绝空值、null、路径和冒号；宿主持久保存 UUID 或同规则 ID，不从页码、标题、字段显示名派生。
- 默认根使用 node-tree:nodes/root/creations；命名根使用 node-tree:roots:<rootId>:nodes/root/creations；全 Doc 共用 node-tree:contracts。当前编辑器拆并候选的 segments 也使用同一根前缀并纳入宿主历史作用域；本次冻结不把编辑器内部片段候选格式当作已发布的存储协议。不同根内可有同名节点，身份为文档/根/节点的组合，跨根不得按裸节点 ID 误查。
- createNodeTreeDocument(tree, { history? }) 与 withNodeTree 的 history 配置接收同一 NodeTreeHistory。宿主用首个根的 createUndoManager 创建，再由绑定 attach 其它根；每个编辑绑定独立 origin，跨根共享的是历史，不是一个 origin。
- 禁止跨 Y.Doc、裸 Y.UndoManager、整个 Y.Doc 作用域及已关闭历史；动态挂根不追溯纳入原本未追踪的编辑。初始化结构仍在同一网络事务中发布，并从历史时钟集合排除。
- disconnectNodeTree 是临时断开；disposeNodeTree 是最终释放，销毁自有历史但不销毁借用历史。NodeTree.dispose 只移除观察者/缓存，不删文档或其它根。宿主最终负责 history.destroy / doc.destroy；连接异常释放本次来源和订阅。视图集成在最终关闭时必须调用 disposeNodeTree，不能把临时断开冒充最终释放。
- 本地绑定 lineage 合并业务前缀、rootId、树实例与历史身份，不能通过相同业务前缀串根。根或历史变化时重建编辑绑定；同根同历史的配置更新可重连。二进制恢复不重新编码同一 JSON，跨页移动不更换 rootId。
- 逻辑深度以元素层数计：本地插入/移动在写入前拒绝超过 64；合法并发合成超深链时，按从根向下的确定性深度在首次越界处切投影父边，保留原数据并进入恢复投影。已验证 90 层并发链不丢 90 个节点，读取不写回共享关系。

#### 契约格式 2

规范化、摘要及验证只有 [content-contracts.ts](/packages/db-schema/content-contracts.ts) 一套实现。固定样例及 SHA-256 为 [whiteboard-w1-v1.json](/packages/db-schema/fixtures/whiteboard-w1-v1.json)，两个领域在同字典共存，由 domain/owner/type/dataVersion 共同确定版本身份。

| 字段                    | 冻结含义                                                                            |
| ----------------------- | ----------------------------------------------------------------------------------- |
| format                  | 固定为 2；格式 1 拒绝，不给旧条目原位补 domain 或重算摘要                           |
| domain                  | 宿主入口固定为 editor-node 或 whiteboard-element，作者不自报                        |
| owner/type/dataVersion  | 扩展归属、类型、正整数数据版本；同一组合不得对应不同契约                            |
| textFields              | 业务载荷的顶层字符串字段，去重、排序；编辑器载荷是节点属性，白板载荷是 element.data |
| structuredFields        | 正文继续保留并验证；白板必须为空，不新增 Map 等作者语言                             |
| resources               | 复用 ContentResourceSpec，资源顺序保留；重复路径、文本字段重叠或危险字段拒绝        |
| editor-node 结构        | kind 与 isVoid，既有正文规则不变                                                    |
| whiteboard-element 结构 | structure，所有字段归宿主；具体枚举见下表                                           |

白板 structure 的默认值与显式同义声明必须得到同一摘要；未知字段/枚举、null 冒充缺省值、重复 joins 均拒绝。

| 结构字段       | 值域                                      | 缺省 |
| -------------- | ----------------------------------------- | ---- |
| geometry       | rect / opaque                             | rect |
| container      | none / free / layout                      | none |
| canBeContained | boolean                                   | true |
| joins          | 空数组或 [layout]；不可收纳时只能为空     | []   |
| text           | none / plain / richtext，固定宿主 body 槽 | none |
| reference      | none / entity，固定宿主 entity 槽         | none |

固定宿主槽位仍随契约保存，不能由协作层按业务类型猜字段；原内置 title/description 等到 body 槽的转换由对应领域迁移/投影负责。普通作者不因此获得任意 richTextFields/references 声明。opaque 只允许宿主能安全解释的外壳/整体操作，不执行未知几何算法。资源路径相对白板 data，body/entity 宿主槽与 data 同名业务字段不是同一个位置。

格式版本、插件发布版本、节点 dataVersion、白板扩展 apiVersion 和房间 epoch 互不替代。当前白板 SDK 仍是旧运行时，新签名启用时须升级扩展 API 版本并设置最低宿主版本；具体发行版本在 W9 确定。格式 2 不自动改变正式协作协议版本，W5/T4 必须完成 documentKind/protocol/epoch 门禁后才能接入新文档。

#### 最小作者 API

精确可编译签名见 [whiteboard-api.fixture.ts](validation/whiteboard-api.fixture.ts)。该文件是 W1 规格夹具，不是已经发布的 SDK；W6 才替换真实 WhiteboardAPI，W2 不得以旧的路径写入口绕过冻结规则。保留现有工具/界面/订阅能力，数据入口固定如下：

| 入口                                                  | 冻结约定                                                                                                    |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| getSnapshot/getElement                                | 返回只读数据投影和当前 pageId；不暴露 Y.Doc、契约写入或原始 store                                           |
| updateElement(id, patch)                              | patch 只含 name、完整 geometry、按键 style；不得覆盖 id/type/children/data                                  |
| updateElementData(id, patch, {unset?, historyGroup?}) | 浅层业务属性补丁，unset 显式删除且与 patch 互斥；文本/身份字段拒绝，嵌套对象数组为原子 JSON                 |
| getTextBinding(id, field)                             | 使用同一个 EditorTextField 接口，字段必须由当前契约声明；不另造文本句柄                                     |
| submit(commands, {historyGroup?})                     | 同步本机批量接纳，先整体验证；返回 {createdIds}，按 create 命令顺序给出宿主分配的 ID，不是持久化/服务器回执 |

身份命令固定为 create、set_node、set_data、move_node、remove_nodes。create 指定元素类型、初始 data、完整 geometry 和目标父节点，宿主分配 ID 与当前契约；move 指定稳定 ID 与显式 page/element 父引用；beforeId/afterId 互斥，失效不静默尾插。remove_nodes 的 ids 是明确观察集合，不在远端扩张子树。首期不提供同批新建节点的临时引用 DSL；需要使用返回 ID 的后续动作另行提交，可用 historyGroup 组织撤销。原生粘贴/子树创建仍由宿主受控创建通道处理。

便捷单元素更新的 boolean 只表示本机是否接纳；不可提交返回 false，非法补丁/契约抛错。批量提交任一项无效时整体拒绝。真实实现需同步克隆输入再验证和提交，不能保留调用方可变对象引用。资源上传和外部实体鉴权独立执行，返回 ID 或 true 都不表示远端已确认。

版本声明采用 dataVersion/previousVersions/migrations，与编辑器同一语义；旧 schemaVersion/migrate 不能并存。类型夹具包含 v1/source → v2/code 示例、身份/路径/锚点/非 JSON 写入的负向断言。普通对象、数组不承诺深合并，votes 等字段不承诺并发计数；通用 Map、任意富文本槽和通用 CAS API 不进入首期。

文本 revision 是当前绑定的本机观察版本，不能当服务器修订。现有 EditorTextField.replace 的同步本机能力不等于共享条件替换：共享白板适配器必须拒绝将它直接用作异步整段覆盖，提示通过宿主异步条件提案流程；真实输入的 edit/editBatch 和主动选区替换按文本绑定处理。W5/W6 负责共享条件入口及结果状态，不以一个 void 返回掩盖待决或失败；本轮未实现该网络流程。

### W2 实现与 W1 的对应

本轮新增 WhiteboardModel、白板类型和无副作用的父图投影，放在 collaboration 包；现有白板 Board、画布、桌面保存流程和插件 WhiteboardAPI 均未替换。不把元素序列塞入富文本混排序列：元素顺序使用 Y.Array，正文仍复用 NodeTree，所有根共用 NodeTreeHistory 和初始化过滤机制。

| 对象 | 实现                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------- |
| 多页 | 稳定页记录池、独立共享页名、页位置 token；创建/换序/删除和撤销不物理删除页                     |
| 元素 | 稳定 Y.Map 记录，identity/fieldBindings 不可普通改写；原子 placement/geometry，按键 data/style |
| 文字 | textFields 与 plain body 为独立 Y.Text；richtext body 为公共 NodeTree 根，跨页保留根和相对位置 |
| 历史 | 同一宿主 NodeTreeHistory 覆盖页、元素和各富文本根；创建撤销只改可见性，删除只撤回本次标记      |
| 恢复 | 按收纳→断环→深度投影，恢复根按 ID 排序；原页失效进入文档恢复区，不创建持久恢复页、不借用另一页 |
| 批次 | 整批候选预检，拒绝零写入；返回本机新建 ID，不充当保存或远端回执                                |
| 入站 | 缺依赖有界暂存；补齐后验证整份候选，拒绝重复位置、契约改写和稳定根重建；排队请求也计入字节预算 |

候选物理键为 whiteboard:meta/title/pages/page-order/elements/orders/strings/creations。meta.profile 为 whiteboard-w1-v1，富文本和契约复用 W1 根命名；标记不代替 W4/W5 的 documentId、epoch、权限与耐久基线门禁。白板候选没有兼容读取旧 JSON 或运行真实迁移。

宿主命令增加页创建/换序/删除/页名编辑、文档标题编辑，并实现冻结的 create/set_node/set_data/move_node/remove_nodes 语义；宿主内部 create 接收已经解析的 contractId，不把选契约的权力交给插件。页删除同样携带 observedElementIds，不在接收端扩张。ID 由模型分配，锚点失效、已知环、非法收纳和超深移动均在真实写入前拒绝。

恢复根保持原 placement，显式 move_node 才改变它的位置。移动到恢复区容器时按有效父链取得可用页；文档恢复区中没有有效页的容器须先显式恢复。恢复根不能冒充正常序列锚点；非法锚点报错，不静默尾插或全局改写无关恢复记录。

### W2 预算与接纳边界

本轮按 W1 常量实际验证 64 页、5000 个保留元素、1024 个空富文本根、64 层、64 KiB 补丁、256 命令、512 KiB 批次和 8 MiB 编码状态边界。根/元素删除不释放额度；空公共根即便未进入二进制编码，也保留在本机候选预检中，避免预检通过后真实事务半途失败。普通字段多个小补丁累计可超过单补丁大小，不把 64 KiB 错当整个元素上限。150000 富文本节点继续由公共 NodeTree 与文档总量计数守门；各上限不能保证同时耗满。

submit 先克隆调用参数，再在隔离 Doc 中执行整批及校验，失败不碰当前文档/历史；预检继承原文档 clientID 与未编码根额度，真实提交保持同样的结构分配和字节计量。receive 使用独立候选、串行接收和修订复核，异步契约验证期间的本机变化不会被旧候选覆盖。

缺依赖增量返回 pending，现有文档保持不变；依赖齐备后才可能返回 applied。排队字节与待依赖材料合计受 8 MiB 上限约束，重复重放按 CRDT 身份幂等。补依赖后暴露非法字段仍整批拒绝；takePendingUpdate 显式交还未接纳材料，宿主保全后可以隔离失败分支。失败的当前输入仍由调用方保留。模型释放不代表材料已耐久，applied 也不代表已落盘或服务器确认。

两端分别合法但合并超额时，模型拒绝候选并保留两端现有内容，不裁剪数据来伪造收敛；正式房间的统一准入/失败分支恢复由 W4/W5 完成。内存模型不承担网络成员授权、资源 ACL、epoch 或持久日志。当前候选预检是完整编码复制，正确性证据不等于拖拽性能或长会话压测，W9 仍须测量。

原始 text/richText/Yjs 集合仅供可信宿主衔接；submit/receive 不是 Y.Doc 全局写防火墙。W3 必须把编辑器正文修改与撤销/重做接入宿主事务预算守门，不能经原始根绕过后声称已准入。该接线、画布手势、布局、结构共享缓存和 UI 均未在 W2 实现，也不在此提前展开。

### W3 预算、历史与失败边界

公共模型新增 preflight 与 preflightHistory；NodeTreeHistory 新增 beforeChange，撤销/重做在弹出真实栈之前先验证候选。输入预检回调仅执行稳定 NodeTree 意图，不携带 I/O/插件副作用；真实根随后执行同一意图。源码字段去掉本机 revision 后才编译为模型增量，避免把观察版本混入持久载荷。异步整段 replace 在白板与带准入的源码绑定中明确拒绝，等待 W5 的条件流程。

撤销预检不能只复制二进制内容：Yjs 编码可能合并原结构区间，而 redone 链只存在本机。候选先恢复引用区间边界、redone 链及历史时钟集合，再模拟动作；关闭候选 GC，以保留历史仍持有的已删内容，避免低估预算。用例覆盖连续多轮 undo/redo，以及撤销将编码状态推过 8 MiB 时“原文档和栈均不改变”。这不是持久历史协议。

Slate 拆段可能先产生本机叶拆分，再申请共享元素拆分。若后一步预算拒绝，编辑器恢复为当前 CRDT 投影，不能留下只存在于 Slate 的半个拆分；严格断言同时检查可见文字、层级、历史条数与完整二进制零写入。原 W1/W2 用例没有放宽。旧路径 set_node 中 null 表示删除，编译时转换为普通字段 unset；业务 data 中明确的 JSON null 仍保留原含义。

远端变化遇到未提交手势采用保守取消，不能在抬起时回写旧几何。updateHistory=false 不等于共享无历史写入通道：已纳入手势的预览随手势提交，普通测量/布局只更新本机投影。未来服务器条件结果仍须由 W5 关联发起来源、去重和耐久回执；本轮没有伪造服务器结果，也不将网络同步消息计入本地历史。

### W4 实现与边界

- 身份与主库：复用 library_identity 的 sourceId/baselineId，以及 ContentIdentityTable 的稳定实体映射；白板文档单独拥有 documentId/epoch，不能借用正文 contentId。新增 whiteboard_documents（检查点、契约、全板投影、创建幂等摘要）、whiteboard_document_pages（稳定页到本地 contentId 映射）、whiteboard_entity_relations（文档/根/节点/槽关系）。页删除只改变可见性，恢复仍使用原 contentId；相同创建请求重试不覆盖后续编辑。主库共 96 表、121 索引，bundle、数量断言和内部数据库说明同步维护。
- 写入与回执：逐文档有界队列验证候选；先在替换范围外的本机 journal.db 用 FULL/WAL 提交增量、完整状态和历史持有，再更新主进程模型并事务投影所有页、拥有者和关系差集，最后推进已投影修订。batchId 重试幂等、复用不同内容拒绝。revision 表示本机日志耐久接纳，projectedRevision 表示主库投影已确认，不混成远端确认。主库提交后回执写失败按相同修订/摘要续做，不重复引用计数。
- 引用与历史：白板实体槽使用公共 ContentEntityReference，正文引用按同一份内置节点 owner/type 契约识别；多富文本根的同名节点分开记账，跨页移动不重复计数。业务关系只来自可见投影（含可恢复区域）；已删除/曾替换的引用另在本机历史持有中累积，不污染同步 ref_count。未打开文档尚无本机持有时保守阻止实体回收；数据表/项目依赖正文的回收也保守保护。资源文件与跨房间授权的完整处理仍由 W5/W8 承担。
- 渲染端：同窗口同文档共享客户端，每画布独立历史；W3 绑定统一手势/富文本/跨页写入。每个本机增量立即复制到 IndexedDB outbox，后续输入不等待前一批 IPC 成功才入队；事务完成后发送，耐久回执后清除。远端投影不回写，处理中新增输入纳入同次 flush。Activity 隐藏不释放持有或历史，同文档切页不重建绑定；最后持有者仅在 flush/release 成功后销毁。
- 生命周期：窗口归属、库名与连接代次均在主进程复核。关闭/切库包括已开始的 open/create；冻结输入并排空所有相关持有者后才封租约。失败恢复编辑，晚到确认不得重新封住窗口；编辑器与白板共同关窗等待所有收尾结果后统一提交或回滚。受控退出在强制退出计时器启动前完成白板屏障，重复退出也拦截 Electron 默认关闭。
- 保全：日志失败不改会话/主库、不广播；投影失败保留日志、outbox 或内存输入并拒绝关闭/切库。真实进程终止后按摘要和来源基线恢复；主库旧快照、连接代次变化、日志损坏均拒绝覆盖且保留原材料。整库关闭/替换前，在替换目录外生成完整 SQLite 副本、摘要及 fsync 回执；备份或回执失败阻断后续覆盖。本机日志保留在原位置，副本包含本地实体依赖，不宣称包含未下载资源。

新格式创建只针对已有 library_identity 的资料库，旧白板打开路径不运行转换。新格式标题与页操作进入文档会话，旧快照与结构写口拒绝覆盖；完整业务类型/复制/资源/迁移继续属于后续批次。W4 没有启用远端房间、真实用户数据迁移或部署。尚未完成 IndexedDB 或主进程耐久提交的输入不承诺硬断电零丢失；正常关闭遇到保存失败会保留窗口和草稿。保留日志和恢复副本不自动 GC，代次退役属于 W8/W9。

### W5 实现与协议

白板业务数据仍使用冻结的 whiteboard-w1-v1；网络信封为协议 3，meta 固定 kind=whiteboard、documentId、baselineId、epoch，独立于正文协议 1/2。新适配器承担创建/候选校验/投影/资源扫描；白板各富文本根调用正文的 validateNodeTree，身份、契约、物理根、声明字段、位置和容量共同验证。已有记录、顺序及文字根不能被普通增量重建，文档种类不能通过增量或迁移偷偷互换。Node 与 Worker 同时接入发布、WebSocket beforeSync、HTTP 操作和迁移候选，不以 readSharedContent 读取白板。

公共 DocumentWriteQueue 串行验证同文档候选；持久化事务里重查成员资格、冻结、epoch 与基线，服务端不信任客户端 origin。候选缺少 pendingStructs/pendingDs 依赖时返回 MISSING_DEPENDENCIES，保留操作 PENDING，不安装、不推进确认序号；祖先补齐后用相同请求指纹重新校验。错误祖先被拒后，其后继不能假装空增量通过。协议票据和状态读取要求匹配文档版本；白板票据申请还必须提供本机 epoch 与 baselineId。普通更新禁止新增身份元数据写入，包括输掉 LWW 冲突的隐藏写入，防止旧缓存换到新票据后重放全量旧状态。旧票据和旧代次写入不能进入新基线。

公共 DocumentOperationLedger 沿用迁移账的 SQL 事务和终态语义，但普通条件提交不改变 epoch。新增服务表 collaboration_operations 保存操作指纹与终态，collaboration_sequences 保存单调序号；序号覆盖普通结构化更新及换代，重复增量不推进。接口为：

| 入口                                              | 语义                                                                                                           |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| GET documents/:id/protocol                        | 返回身份、完整 CRDT 摘要 revision 和单调 sequence                                                              |
| POST documents/:id/operations/:operationId        | 提交 version/epoch/baselineId/updateHash/expiresAt/update；条件提案同时传 expectedRevision 和 expectedSequence |
| GET documents/:id/operations/:operationId         | 查询已知 PENDING/COMMITTED/ABORTED/EXPIRED；null 只表示未登记，不能据此丢弃未知结果                            |
| POST documents/:id/operations/:operationId/cancel | 同指纹取消；取消先到保存终态，不被迟到提交复活                                                                 |

服务端回执与正文/白板更新同事务提交。操作 ID 不换候选、条件或截止时间；提交成功后重试返回原回执，回执写失败时文档与序号一并回滚，预先建立的恢复资源持有仍然保留。修订冲突、过期、取消不安装候选；服务端存储/活动文档/消息预算沿用既有限额，新增回执与资源历史占用计入存储配额。这里的“整文档条件”是对整份文档修订做比较，成功后安装保留身份的合法增量；重建整份 CRDT 基线仍走所有者迁移屏障、epoch 递增与回执，不借普通条件替换绕开。

### W5 本机接线与保全

DocumentSyncSession 复用于结构化文档：先将确认快照、操作 ID/摘要和原始增量持久化，再发送；结果未知不自行判失败。相同 ID 的本机暂存也幂等，不能复用 ID 修改候选。COMMITTED 回执及对应增量先保存再移出发送队列；重启查询服务端终态，既不重复提交，也不伪造重启前的撤销栈。

被拒祖先会连同后续未确认增量整体隔离，损坏增量也保留原始字节。换代即使没有待发送编辑，也先保全旧确认快照；隔离落盘失败时不清队列、不安装新状态。隔离后的副本阻止继续发送，调用方通过 restartFromConfirmed 明确获取确认快照建立新副本，恢复材料不删除。前序结果未知时不能越过它取消后继；取消已提交操作返回已提交状态，由调用方处理后续撤销。

桌面 WhiteboardRemoteJournal 复用 W4 FULL/WAL 日志，在 remote_branches 持久保存这些材料及摘要，按规范服务器地址/设备身份/文档身份隔离。CollaborationClient 复用设备鉴权与地址规范化，状态读取声明协议 3。主进程提供 remote-open/stage/sync/cancel，继续核对窗口租约及当前资料库；没有共享 meta 的本机白板拒绝隐式开启远端。remote-sync 排空提案并补交本机差异，接纳结果通过 W4 主进程日志/投影回到本机；网络等待期间新增本机修订标记 requiresSync。旧 epoch 或拒绝分支要求重绑，不把新基线合并回旧污染副本；打开新的干净副本也必须与确认快照一致。

画布宿主 beginConditional/receiveDocument/finishConditional 只处理首期文本与用户几何提案，冻结该视图写入口；同步先到时缓冲，回执成功后用该视图 origin 应用一次，再接收远端结果。重复回执不重复记历史，其它视图没有发起者历史。接口仅属宿主绑定，不发布插件通用 CAS、任意字段 Map 或事务 DSL，插件 SDK 接线留在 W6。
