# 个人助手记忆：从记得准到懂你

状态：进行中
目标：让个人助手对用户形成连贯、不碎片化、能跟进事项的理解，并真正送达主对话。

需求：

- 主对话的个人背景必须送达模型；系统提示在同一宿主会话内逐字稳定，不因后台归纳而变化，避免 provider 缓存失效。
- 修复对话摘要/遗留事项证据被判失效、使用节律画像不可见。
- 画像不因模型换 topic 名字而碎片化；存量碎片在全面复核时合并。
- 生成一份有依据的用户总述，作为开场背景的主体。
- 意图与遗留事项可被本人新自述关闭（完成/放弃），到期记为过期；只在用户提到相关话题时才带入开场背景。

方案：

- **背景注入**：宿主会话在第一次 `before_agent_start` 以该轮用户输入为 query 计算记忆背景并冻结；动态系统提示扩展每轮返回「渲染端 prompt + 冻结背景」，重试路径同源。宿主重建（空闲回收、重启）时重新计算，此时 provider 缓存本已过期。
- **摘要证据**：chat 来源的 `summary` 锚点在会话存在时有效。同一对话重新摘要时替换旧摘要；上一版遗留事项随输入给模型，明确已解决的转历史（outcome=done），原样保留的强化，其余不删。
- **节律画像**：`使用节律` 是唯一允许无经历依据的画像，召回校验单独放行。
- **画像合并**：归纳输入给出全部画像（上限 60）和近期状态；输出可带已有模型 `id`，按 id 原位更新（沿用原 topic，同 layer、同 kind，explicit 不被 supported 覆盖）。全面复核归纳后再调用一次合并，输出 `{keep, merge}`，只合并同 kind 的画像，explicit 不并入 supported；依据挂到保留项。
- **用户总述**：存 `meta.portrait`（行文本 + 引用的模型 id + 生成时间）。输入为有效画像与近期状态，每行必须引用本次输入的模型 id，无效行丢弃，有效行不足一半整份丢弃；600 字以内。引用模型被删除或更新后该行在简报中隐藏，并在距上次生成满一天后重建；全面复核后立即重建。开发诊断面板展示总述。
- **开场背景组成**：总述（无总述时退回画像列表）+ 与 query 相关、未被总述引用的画像最多 3 条 + 近期状态最多 3 条 + 与 query 相关的未关闭事项最多 2 条 + 最近会话摘要 + 当下状态。
- **事项闭环**：`memory.outcome`（done/dropped/expired，可空）。对账新增 `fulfill`：目标为 current 的 intention、非手动；候选为 chat/diary 本人当前自述且观测不早于目标；跨 kind 允许。对账召回额外取相关的当前 intention。到期的 intention 记 expired。

决策：

- 总述只在开发诊断面板展示，普通界面不提供。
- 未关闭事项只在与用户首条消息话题相关时带入，不主动逐条追问。
- `outcome` 列在打开记忆库时补齐，失败即拒绝打开，不留兼容分支。
