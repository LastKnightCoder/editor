# 移动端字号规范

状态：进行中
目标：把移动端字号从「散落的 30 多种像素值、整体偏小」收敛为一套 9 档字号阶梯，并让卡片列表与详情页正文字号一致。

视觉稿：`apps/mobile/mockups/typography-mobile/`，静态页，从仓库根起 HTTP 服务访问（`.claude/launch.json` 的 `mobile-sync-mock`，入口 `http://localhost:8835/apps/mobile/mockups/typography-mobile/`）。字号要在手机上看才准：在仓库根运行 `python3 -m http.server 8835 --bind 0.0.0.0` 后用同一局域网的手机打开，或用浏览器设备模式按 100% 缩放查看。

## 1. 现状与问题

- **根字号 14px**：`apps/mobile/src/styles.css` 的 `body { font-size: 14px }`，比 iOS 正文（17pt）和 Material 正文（16sp）都小，未声明字号的文字全部落在 14px。
- **字号散落**：`apps/mobile/src` 里 `text-[Npx]` 有 30 多种取值，出现最多的是 13 / 11.5 / 12.5 / 12 / 14 / 11px（各 60–100 处），还有 8.5 / 9 / 9.5 / 10.5 等半像素值；`@tau/themes` 的 `text-tau-*` 档位全目录只用了 2 处。
- **辅助文字过小**：时间、标签、分组标题、副标题集中在 11–12.5px，Dock 标签 10px，徽标 8.5px；中文在 12px 以下笔画会糊。
- **列表卡片与正文不一致**：详情页编辑器挂了 `.mobile-card-editor-content`（17px / 1.85）；卡片列表 `CardItem` 的只读编辑器没挂这个类，继承 body 的 14px。同一段内容，列表里 14px、点开 17px，标题块（`em` 相对字号）也跟着放大约 1.2 倍。
- **桌面档位不适用**：`packages/themes/src/scale.css` 的 `--tau-text-*` 是桌面密度（正文 13px），移动端直接用会更小，所以移动端一直在写字面值。

## 2. 专业产品的做法（mockup「0 调研」）

| 体系                           | 正文          | 列表主文本                      | 次要文字                    | 最小           | 要点                                                               |
| ------------------------------ | ------------- | ------------------------------- | --------------------------- | -------------- | ------------------------------------------------------------------ |
| iOS HIG（Dynamic Type 默认档） | Body 17       | Headline 17 / Body 17           | Subheadline 15、Footnote 13 | Caption2 11    | 11 档语义样式，用户可整体放大；中间档位间距 1–2pt，大标题 34       |
| Material 3                     | Body Large 16 | Title Medium 16 / Body Large 16 | Body Medium 14              | Label Small 11 | 15 档，按 Display / Headline / Title / Body / Label 五组各分大中小 |
| 系统备忘录类（Apple 备忘录）   | 17            | 标题 17 粗                      | 预览 15、时间 15 灰         | —              | 列表只给标题 + 一行预览，预览降一档、用灰色区分                    |
| 卡片流类（X、即刻、flomo 等）  | 约 15–17      | 与详情同字号                    | 13–14                       | —              | 列表就是内容本身，列表与详情**同字号**，靠截断行数控制密度         |

共识：

1. **正文 16–17**：CJK 字形占满字身框，同一像素值中文显得比拉丁文大，16px 中文 ≈ 17pt 英文的阅读感受；编辑器长文阅读可到 17。
2. **档位少而固定**：一款应用通常只用 6–9 档，档位之间至少差 1px，没有半像素；同一种角色只用一种字号。
3. **语义命名**：组件写「这是什么」（正文、说明、时间），而不是写像素值；全局放大只改档位表。
4. **最小值**：可读句子 ≥ 13，非句子标签（Dock、角标、计数）≥ 11，10 以下不用。
5. **层级靠字重和颜色，不靠缩字号**：副标题用灰色同档或降一档，而不是一路缩到 11px。
6. **列表与详情的关系二选一**：列表展示的就是内容本身（卡片流）→ 同字号；列表只是索引（备忘录、邮件）→ 标题同正文、预览降一档。

## 3. 方案

### 3.1 9 档字号阶梯（mockup「2 字号阶梯」）

沿用 `--tau-text-*` 的 9 个槽位，移动端在根上覆盖为移动端数值，不新增 token 词汇；`@tau/ui` 里已经用 `text-tau-*` 的组件（`SettingRow`、`FormRow`）随之自动变大。

| 槽位     | Tailwind 类         | 移动端值 | 行高 | 用途                                                         |
| -------- | ------------------- | -------- | ---- | ------------------------------------------------------------ |
| hero     | `text-tau-hero`     | 28px     | 1.25 | 详情页大标题、首页问候、统计大数字                           |
| title-lg | `text-tau-title-lg` | 22px     | 1.3  | 一级页大标题、空态标题                                       |
| title    | `text-tau-title`    | 17px     | 1.35 | 导航栏标题、区块标题（任务/最近）、弹层标题；配 600–700 字重 |
| body-lg  | `text-tau-body-lg`  | 17px     | 1.75 | 阅读正文：编辑器、卡片列表内容（与 title 同号，靠字重区分）  |
| body     | `text-tau-body`     | 16px     | 1.5  | UI 正文：列表行主文本、设置项、按钮、输入框、菜单项          |
| meta     | `text-tau-meta`     | 14px     | 1.45 | 次要说明：列表副标题、设置说明、空态说明、提示               |
| sm       | `text-tau-sm`       | 13px     | 1.4  | 时间、计数、分组标题、保存状态                               |
| micro    | `text-tau-micro`    | 12px     | 1.3  | 标签 chip、类型徽标、段控件                                  |
| tiny     | `text-tau-tiny`     | 11px     | 1.2  | 仅非句子：Dock 标签、角标、图表刻度                          |

- 只允许整数像素，禁止 `text-[Npx]`；计时器、日历大日期等数字展示（≥ 34px）是唯一例外，在组件内集中声明。
- 字重只用 400 / 500 / 600 / 700 四档（现有 550、750、800 收敛进来）。
- 输入框沿用 `--mobile-input-font-size: 16px`，与 body 档对齐（同时满足 iOS 不自动放大的阈值）。

### 3.2 列表卡片与详情同字号（mockup「3 卡片列表」）

- 推荐 **方案 A：同字号**。卡片列表渲染的就是正文本身（只读编辑器，所见即所得），与卡片流类产品同构：列表与详情都用 body-lg 17px / 1.75，标题块随之一致；密度靠截断控制（预览最多约 6 行，底部渐隐），不靠缩字号。
- 备选 **方案 B：降一档**。列表 16px / 1.65、详情 17px / 1.75，信息密度高约 15%，但列表点开会有轻微「放大跳变」，和本次要解决的问题方向相反。
- 落地：给 `CardItem` 的只读编辑器也挂 `.mobile-card-editor-content`，该类改为消费 body-lg 档位（`font-size: var(--tau-text-body-lg)`），正文行高从 1.85 收到 1.75。
- 卡片头部时间用 sm 13px，标签 chip 用 micro 12px；卡片内边距保持 16px。

### 3.3 迁移映射（mockup「5 迁移映射」）

| 现值                       | 新档位                                       |
| -------------------------- | -------------------------------------------- |
| 8.5–10.5px                 | tiny 11（只保留在非句子标签上，句子升到 sm） |
| 11 / 11.5px                | micro 12（标签类）或 sm 13（时间、说明类）   |
| 12 / 12.5px                | sm 13                                        |
| 13 / 13.5px                | meta 14                                      |
| 14 / 14.5 / 15 / 15.5px    | body 16                                      |
| 16 / 16.5 / 17 / 18px      | title 17                                     |
| 19–24px                    | title-lg 22                                  |
| 26–31px                    | hero 28                                      |
| `body { font-size: 14px }` | body 16                                      |

按页面域分批替换（壳层组件 → 卡片 → 首页 → 设置 → 其余），每批跑类型检查与测试；完成后加一条 ESLint 规则禁止移动端 `text-[Npx]`。

## 4. 决策

- 列表与详情：用户选定方案 A（同字号 17px）。
- 日记列表预览卡片同样算正文：与卡片列表一样挂 `.mobile-card-editor-content`（字号、行距、两端对齐、正文字体与详情页一致）。

待决策：

- 卡片列表长内容截断：按块截断（现为前 3 块）还是按行截断（约 6 行 + 渐隐）；按行截断会把图片块也裁掉，需先定图片卡片的处理。
- 是否同时提供「字号」设置（标准 / 大 / 特大，按档位等比放大 1 / 1.12 / 1.24）；本规范的档位表已支持，单独确认后再做。
