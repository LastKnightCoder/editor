# 正文完整验收

状态：待验收。目标是在正式容量、持续故障和实际设备上确认正文迁移的行为、性能与可恢复性。

正文架构实现已经交付。本任务接续完整验收，记录实际通过范围和退出条件。采用隔离资料库、冻结输入和已构建的真实宿主验证，各场景保存实际退出码、产物摘要、存储断言和失败重放入口。每一项分别核对成功路径与回滚、重开或断线后的结果。

## 已有证据

- 共享发布、解绑与整篇替换的未知回执已验证。在主库提交与后续日志安装之间实际终止 Electron，从同一存储恢复原房间或预存本机基线。重开按原操作 ID 对账。 [共享恢复证据](./evidence/README.md#共享恢复)
- 两组桌面与 Rust 使用同一 SQLite 文件完成 `3 → 2 → 3`。真实桌面白板协作、嵌入引用、任务写入、失效或缺失派生库的全文和关系索引重建通过。 [跨端与派生证据](./evidence/README.md#跨端与派生)
- 快速容量通过 12 组、最大 200 个 IPC 租约及单篇 1,000 次接纳。四个事务切点共 8 次实际强退通过。短烟测覆盖实际断线、重连与切库。用户要求缩短等待，正式长稳停止在预热及第一个正式样本之后。 [快速验证与中断证据](./evidence/README.md#快速验证)

## 完整自动验收

按以下顺序在固定候选和隔离环境执行，性能采集与构建及其他压测串行。容量、硬杀和长稳使用生产 Electron 主进程、本机测试服务及真实临时 SQLite 库。出现差异先定位业务不变量、恢复断点和输入，再决定修复与复跑范围。 [构建与执行命令](/docs/guides/dev-content-verification.md)

| 项目         | 通过条件                                                                                                                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 正文容量     | 保持 12 组文档与租约组合和 20 个固定种子，单篇累计接纳 10,000 次。每组格式、身份、关系、计数及外键无差异，超限拒绝可重开                                                                            |
| 反复崩溃     | 日志增量事务内外、主库投影事务内外各 20 次真实 `SIGKILL`。从文件核对耐久回执、修订、关系和计数。重复提交原增量只应用一次                                                                            |
| 真墙钟长稳   | 预热 5 分钟后连续 60 分钟混合编辑、断线与重开。每 5 分钟采样进程内存，每 10 分钟核对主库、服务端状态与关系。检查趋势、积压及排空退出                                                                |
| 冻结投影对照 | 14 个场景各跑三轮。与同机基准比较同场景 P95 中位数，阈值 `基线 × 1.20 + 5ms`。采样 RSS 或 heap 高于基线 20% 时定位原因。 [冻结输入与结果](./evidence/README.md#冻结投影基线)                        |
| 白板专项     | 独立时窗运行 `packages/collaboration` 的 `vitest run --config vitest.whiteboard-capacity.config.ts`。容量边界与三端 3,600 轮的内容、身份和上限核对均通过。Node 和本机 Worker 的真实网络用例各自留证 |

正式档位采用 20 个随机种子、80 次完整强退和 60 分钟采样。此次快速模式用于缩短等待，完整档位沿用这些参数。新结果按运行环境、实际覆盖和来源填写。

## 用户实际验收

使用独立测试库，保留桌面、iOS、Android 的系统与应用版本，以及每项的实际结果。

| 项目                    | 操作                                                                                                                                                               | 通过条件                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| iOS 和 Android 整库往返 | 分别用平时配置的同步提供方下载桌面测试库，打开一对共用正文的卡片和文章，再编辑共用正文及数据表行正文并同步回桌面                                                   | 两个业务入口仍指同一正文，原有行正文可打开。中文、粗斜体、源码、未知插件占位、正文链接和嵌入都保留，桌面能搜索更新内容 |
| 手机本机输入和生命周期  | 分别用中文输入法编辑正文。组合输入期间切前后台，完成输入后离开再开。保存后用系统结束应用，重开原库。另在一次编辑未确认时切到有同编号正文的另一测试库               | 重开结果与最后确认输入一致，输入法组合和恢复时的焦点符合操作预期，另一库同编号正文未被旧保存改写                       |

| 白板与正文互相嵌入      | 桌面编辑板内富文本，跨页移动后用中文输入和撤销。把板内正文复制成待引用正文，移除正文中的反向白板嵌入后重开原板。移动端查看相邻正文和白板占位，再同步回桌面打开嵌入 | 跨页移动保持内容、样式、光标及撤销行为。被其他入口持有的页面仍可打开。移动端显示占位且编辑相邻正文后不会破坏嵌入       |
| 待办与脉络回跳          | 在卡片或文章勾选和改名正文待办，从待办页回跳。打开脉络中的导航回链和白板嵌入                                                                                       | 待办状态、标题和正文一致，回跳聚焦正确块，原格式及无关节点保持，导航和嵌入显示正确                                     |
| 实际语义索引            | 在测试库使用已配置的嵌入模型或插件，编辑正文后触发索引重建，再做精确关键词与同义词查询                                                                             | 新词真实全文命中，同义词能按配置召回更新后的正文，旧内容不会在重建后继续顶替结果                                       |

记录每项为通过、失败或未覆盖。失败时附设备、库、前置状态、操作顺序和实际结果，以便按原场景重放。完整自动和实际验收都有结果后，按任务规则沉淀新增事实、退役本页并更新索引。
