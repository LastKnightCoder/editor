# 长文档视口级挂载

状态：暂缓，未排期。

目标：减少长文档屏外内容的首次 React 与 DOM 挂载成本，保持完整正文和业务功能。

## 用户决定

用户认可视口级方向，但近期时间有限，要求先记录，当前不实施、不安排自动跟进。只读首屏已完成并验证；解析隔离与视口级挂载继续暂缓。

## 已有基线

此前优化基线已保存为 `954464605`，增量投影等成果为 `99edc8a95`。参考文档实机开发版打开至完整正文就绪约 16.46 秒，单次完整 Markdown 解析约 2.18 秒；包含 2379 个顶层块、587 张表格、9778 个单元格和约十万个 DOM 节点。正文及格内输入中位延迟已分别降至 72ms、64ms。

现有 chunk 与 content-visibility 保留了屏外 React/DOM 节点，不能消除首次挂载成本。视口级挂载应改变渲染范围，完整文档、Y.Doc 和保存语义继续保留，不能把未挂载内容当成未加载正文。

只读首屏补充基线：相同文档三轮首屏帧代理约 4.14 秒、完整就绪观测约 17.77 秒，全文仍完整挂载。它缩短展示等待，没有消除全篇编辑器准备成本；与前述单轮基线的差异不作为视口方案收益，恢复实施时重新同口径复测。

## 恢复实施时的范围与判据

- 先复核正式构建与实际长文的首屏可见、可编辑时间、React 提交、布局及内存，明确收益基线。
- 先做独立原型，确定视口窗口、滚动锚点和高度估计；复杂表格和代码块按实际成本验证，不以顶层块数量代替渲染成本。
- 核对跨块选区、复制粘贴、全文查找、目录跳转、拖动、光标定位、输入法和可访问性。
- 保持撤销重做、源码往返、外部文件同步、关闭保存、未知节点、表格行列操作、代码块控制器及多编辑器行为。
- 用同文档副本比较并核对全量输出与原文件字节；视觉验收由用户完成。
