# 浏览器扩展重写：页内伴读

状态：待验收
目标：把浏览器扩展从「侧边栏」重写为「当前页内的悬浮伴读」——悬浮球入口，就地标注、写笔记、对网页提问，AI 能力借用已安装的 Tau 桌面应用；扩展与应用的连接必须经用户一次性授权。

## 需求

- 入口：页内悬浮球，不打开浏览器侧边栏（side panel）。
- 能力：①对页面做标注（高亮 + 批注）；②写页面笔记、摘录；③对整页 / 选区提问；④用 Tau 里配置好的模型聊天。
- 连接：扩展经 WebSocket 连本机 Tau；不是任何进程 / 网页都能连——首次连接由 Tau 弹窗让用户同意，同意一次长期有效，可撤销。
- 约束：旧扩展代码与数据不兼容、不迁移，从零重写（`apps/browser-extension` 整体替换）。
- 验收：mockup 评审定稿 → 实现 → 行为测试 + 构建通过；视觉由用户验收。

## 交互方案

### 一、悬浮球（贴边把手）

偏好里明确「讨厌右下角 FAB」，所以悬浮球不做右下角圆钮，而是**贴在视口右缘、垂直方向可拖**的把手：

- 常态：36px 圆形，一半嵌在视口外，只露出半圆 + τ 标识；**不做半透明**（偏好：悬浮控件要让位就完全收起，不淡到一半）。
- 悬停：整颗滑出，竖向展开 3 个快捷动作（问这页 / 标注 / 笔记），快捷动作占固定槽位，展开不改变球本身尺寸。
- 单击：打开面板（默认回到上次的页签）；再次单击或 Esc 关闭。快捷键 `⌥J` 开关面板。
- 拖拽：沿右缘上下拖动，松手吸附；拖过视口中线可换到左缘。位置按站点记忆。
- 角标：本页标注数（≥1 才显示）。
- 状态点：绿 = 已连接；琥珀 = 等待授权；灰 = 未连接（Tau 未运行）。灰态下点击面板顶部给出「打开 Tau」。
- 让位：右键 / ⋯ 菜单「在此网站隐藏」「本次隐藏」；全屏视频、页面进入打印时自动隐藏。

### 二、选区工具条（只属于「选中」意图）

选中文字后 150ms 在选区上方出现，悬停正文什么都不出：

```
[● ● ● ● ●]  │  批注  问 AI ▾  摘录  │  复制
```

- 五色高亮复用编辑器 `INLINE_PALETTE` 的 黄 / 绿 / 蓝 / 紫 / 红，存色相 id，导入 Tau 后和文档里的高亮是同一体系；渲染同为「同色相淡底 + 底线」。
- 批注：高亮并立即在选区下方展开批注输入框（⌘Enter 保存）。
- 问 AI ▾：解释 / 翻译 / 总结 / 自由提问；结果承载方式见第四节三选一。
- 摘录：把选区（带出处链接）追加进本页笔记。
- 点已有高亮：出同款小工具条（换色 / 批注 / 问 AI / 删除）。

### 三、页边批注标记（不占阅读宽度）

带批注的高亮在**正文右侧页边**留一枚 18px 小标记（与高亮同色），垂直对齐高亮首行；悬停浮出批注卡片，点击钉住。正文宽度不变；浏览全部、跳转交给面板「标注」页签。页边没有空间（正文贴满视口）时标记退到高亮行尾的上标圆点。

### 四、提问的三种承载方式（请选一个）

| | A 浮窗面板（推荐） | B 底部命令条 | C 原位气泡 |
| --- | --- | --- | --- |
| 形态 | 悬浮球旁展开 400×640 浮动面板，可拖可缩放，页签：对话 / 标注 / 笔记 | `⌥J` 在视口底部中央弹出命令条，回答向上展开成一张卡 | 回答直接贴在选区下方的气泡里，整页提问时气泡贴在球旁 |
| 长对话 | 好：完整会话与历史 | 中：卡片可滚，但多轮会挡正文 | 差：只适合一问一答 |
| 标注 / 笔记列表 | 同一面板内 | 另开面板 | 另开面板 |
| 对阅读的打扰 | 中：遮住右侧一块 | 低：用完即收 | 最低：就地出现 |
| 键盘效率 | 中 | 高 | 中 |

推荐 **A 为主容器 + C 的就地快答 + B 的快捷键**：解释 / 翻译这类短问在选区下就地气泡回答（气泡底部「在面板继续」接入 A）；整页提问、多轮对话、标注列表都在 A 面板里；`⌥J` 直接聚焦 A 面板输入框。原型右上角可分别切到纯 A / B / C 感受差异。

### 五、面板（方案 A）

- 头部：站点图标 + 页面标题（拖动把手）、连接状态、「固定」（切换标签页仍保持打开）、关闭。页签用文字标签 + 下划线，不用 Segmented。
- **对话**：
  - 上下文 chip：`本页 · 8,4xx 字`（默认带上，可点掉）、`选区`（有选区时自动出现）、`我的标注`（让 AI 参考本页高亮与批注）。
  - 模型来自 Tau：显示 Tau 当前默认模型，下拉可换 Tau 里已配置的其他模型；扩展自己不存任何 API Key。
  - 空态给 4 个建议问题（总结本页 / 列出要点 / 找出论证漏洞 / 和我的笔记有什么关联）。
  - **回答带证据**：回答里的 `[1]` 引用指向原文段落，点击滚动到原文并闪烁定位；回答下方操作「存为笔记」「复制」「重答」。
  - 会话按 URL 归档在 Tau 里，回到同一页可继续。
- **标注**：按页面顺序列出高亮（色条 + 原文 + 批注），顶部颜色 chips 过滤；点击滚动定位；底部一行同步状态。
- **笔记**：一张绑定当前 URL 的页面笔记（轻量 Markdown），摘录以引用块带出处追加；「保存到 Tau」后在 Tau 里成为一篇带来源的内容，之后两端编辑同一份。

### 六、连接与授权

见 [mockups/pairing.html](mockups/pairing.html)。用户视角：

1. 装好扩展后首次打开面板 → 显示「连接到 Tau」与一个 4 位校验码。
2. Tau 弹出应用内授权对话框：浏览器名称 + 系统 + 扩展标识、同一个校验码、申请的权限（模型对话 / 读写网页标注与笔记 / 搜索我的笔记〈可选，默认关〉）→ 拒绝 / 允许。
3. 允许后长期有效；在 Tau「设置 › 浏览器扩展」可看最近活动、调整权限、撤销。撤销后扩展立即断开并回到第 1 步。
4. 连续拒绝 3 次后该扩展实例 10 分钟内的请求静默丢弃，防弹窗轰炸；设置里可关闭「接受新的连接请求」。

## 技术方案

### 连接协议

```
扩展(background)                         Tau(主进程)
  │ ws://127.0.0.1:<port>/browser            │  只监听回环地址
  │ ── Origin: chrome-extension://<id> ───▶  │  ① Origin 必须是扩展 scheme，拒绝 http(s) 页面
  │                                          │
  │ 首次: pair.request{clientId, info, scopes, nonceE}
  │ ◀── pair.challenge{nonceA} ──────────────│
  │  双方算 SAS = H(nonceE‖nonceA) 的 4 位    │  ② 扩展与 Tau 弹窗显示同一校验码
  │                                          │  用户点「允许」
  │ ◀── pair.granted{token, scopes} ─────────│  ③ token 256 位随机；Tau 只存 SHA-256 + scopes
  │                                          │
  │ 之后: 首帧 hello{clientId, token}(3s 内) ─▶│  ④ 常量时间比较；失败即关闭
  │ ◀── ready{scopes, app, models} ──────────│
  │ ⇄ request / response / notification（流式回答走 notification）
```

- ① 挡住任意网页发起的跨站 WebSocket 劫持；网页无法伪造 Origin。本机进程能伪造 Origin，所以真正的门是 ③④ 的 token。
- ② 短认证串（SAS）保证用户批准的就是自己眼前这个扩展：恶意进程抢先发请求时，弹窗里的码与扩展里显示的不一致。
- Firefox 扩展 Origin 是每次安装随机的 `moz-extension://<uuid>`，按 scheme 放行，靠配对兜底。
- 每个方法按 scope 在主进程校验（`chat`、`annotations`、`notes`、`search`）；页面正文只在用户触发提问时才发送。
- token 存 `chrome.storage.local`（不进 sync，不跨设备漂移）；被撤销时 Tau 主动发 `revoked` 并关连接。
- 边界：已在本机运行、能读你文件的恶意程序不在防护范围内（它能直接读 token 和 Tau 数据库）；本方案防的是网页、其他扩展和未授权的本机进程。

### 扩展结构（MV3，WXT + React 19 + Tailwind + `@tau/themes`）

- **background service worker**：唯一持有 WebSocket 的地方（内容脚本里发起的连接 Origin 是网页，过不了①）；20s 心跳保活（Chrome 116+ WebSocket 活动可延长 SW 生命周期）；断线指数退避重连；离线时标注写入 IndexedDB 发件箱，连上后补发。
- **content script**：只在宿主元素 `<tau-companion>` 的 closed Shadow DOM 内渲染全部 UI，Tailwind 与 `--tau-*` token 注入 shadow root，不受页面 CSS 影响、也不污染页面；与 background 用 `runtime.Port` 通信，校验 `sender.id`。
- **高亮渲染**：CSS Custom Highlight API（`CSS.highlights`）——不改页面 DOM，不破坏 React/Vue 页面；按颜色分 5 个 `Highlight` 注册。
- **锚定**：每条标注存 W3C Web Annotation 选择器组合：`TextQuoteSelector`(exact + 前后 32 字) + `TextPositionSelector` + 最近块元素的 CSS 路径；加载时先精确匹配，失败再在块内模糊匹配；SPA 用 `MutationObserver` + URL 变化重锚，找不到的进「未定位」分组而非丢弃。
- **正文提取**：Mozilla Readability → Markdown，按段落编号，供 `[n]` 引用回链定位。
- **数据归属**：Tau 是真相源（标注 / 笔记 / 会话按规范化 URL 存）；扩展只缓存当前页。
- **AI**：复用桌面端 pi-session 宿主，扩展作为工具宿主提供 `readPage`、`getSelection`、`locateQuote`、`addHighlight` 等工具，模型列表与 Key 都在 Tau。

### Tau 端改动

- 主进程新增 `browser-pairing` 模块（BACKGROUND 层）：配对状态机、token 存储（新表 `browser_client`）、scope 校验。
- 现有 `browser-bridge` 重写为按新协议工作，挂到独立路径 `/browser`。
- 渲染端：应用内授权对话框（全局浮层，经壳层挂载与 `useOverlayDismiss`）、设置页「浏览器扩展」分区。
- 数据表：`web_annotation`、`web_page_note`（细节定稿后补，届时按 schema 维护规则同步校验脚本与 database-schema.md）。

## 决策

- 提问承载用推荐组合：A 浮窗为主容器；解释 / 翻译在选区下方气泡就地回答（「在面板继续」接入面板）；概括与自由提问进面板；`⌥J` 开关面板。
- 悬浮球默认贴右缘。
- 页面笔记「保存为卡片」：在 Tau 新建一张卡片，正文末尾附来源链接；草稿随即清空，面板里留已保存卡片的入口。
- 页面笔记用 Tau 编辑器的基础组件（扩展自己的页面以 iframe 嵌入），草稿存编辑器原生数据，保存直接交原生数据；摘录与「存为笔记」追加成对应的块。早先的 Markdown 草稿首次打开时转换一次。
- 扩展对话能用桌面对话的全部应用工具（笔记、待办、日程、Skill、MCP、插件工具），不给 pi 自带的读写文件与执行命令工具；作为可选权限「使用 Tau 里的工具」，授权弹窗里默认勾选。取代早先只放行 `search_knowledge` 的「搜索我的笔记」。
- 审批完全跟随桌面的工具权限模式，审批与作答在扩展面板里原地完成。
- 扩展的消息与工具渲染和桌面同一套 `@tau/chat-ui`；桌面专用卡片在扩展里退回通用工具行 +「在 Tau 中查看」（打开桌面只读的网页对话页）。
