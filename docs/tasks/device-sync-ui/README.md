# 局域网设备同步 UI 重设计

一句话目标：让首次使用者顺利完成配对，让已配对用户日常几乎不用管同步；桌面分协调电脑、连接电脑两种角色，手机只做连接端。

## 范围与约束

- 本阶段只产出可切换的高保真原型与本文档，等待选型；不改正式页面、同步协议、数据库、保存队列、覆盖守卫与配对凭据管理。
- 只重做设备同步，与云端存储同步分开呈现，不重做整个设置系统。
- 产品语义以 [设备同步架构](/docs/architecture/device-sync.md) 为准；界面只用「协调电脑、连接设备、自动补齐」三个概念。

## 原型

入口：[mockups/index.html](./mockups/index.html)，浏览器直接打开（file:// 即可）。

- 顶部深色条是原型控制区，不属于产品界面：切换方案 A/B/C、视角（桌面协调 / 桌面连接 / 手机）、状态、明暗，以及「现有接口 / 补充字段后」。
- 产品框内的按钮可以点：会在演示状态间流转（如 确认覆盖 → 进行中 → 重新打开 → 完成）。不调用任何真实接口，配对载荷标明「演示数据-不可用于配对」。
- 右侧说明栏逐状态列出：这一屏的设计、数据来源（现有接口字段）、依赖（需补充的能力）。
- 颜色直接引用 `packages/themes/src/tokens.css` 的 `--tau-*`，没有另造配色；当前为暖纸主题。
- 地址带状态，可直接分享，例如 `index.html#A/conn/offline/now`。

## 现状问题

入口：桌面 `features/settings/sections/DeviceSyncPanel.tsx`（挂在 `SyncSection` 云端页签上方），移动 `settings/sync/DeviceSyncSection.tsx`（挂在 `SyncCenterSection` 顶部）。

- 未开启时「作为协调电脑开启」和粘贴框同时出现，没有先回答「这台电脑是哪个角色」。
- 「下载协调电脑版本并覆盖本机」与「暂停」「立即补齐」都是同一档按钮并列，危险程度看不出来。
- 移动端覆盖按钮点了直接执行，没有确认；已配对后粘贴框仍常驻。
- 协调端文案「正在等待已配对设备连接 · N 台设备」把已配对数说成在线情况。
- 错误直接显示 `DEVICE_SYNC_*` 原文；冲突副本原因是「元数据事务已分叉」这类技术描述。
- 设备同步与云端同步在同一屏上下混排，没有分开。

## 接口能力（以代码为准）

桌面 IPC `device-sync:*`（`src-electron/main/modules/device-sync/index.ts`）：

| 动作 / 字段                             | 内容                                                                                                                                                                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`                                | `role`（coordinator / replica / unpaired）、`phase`（idle / syncing / synced / offline / error，仅连接端）、`enabled`、`database`、`peers: {id, name}[]`、`lastSync`、`error` 字符串、`pendingAssets`、`branches`、`noteCopies` |
| `enable` / `pause`                      | 协调端开启或暂停监听；连接端恢复或暂停自动连接                                                                                                                                                                                  |
| `pairing`                               | `{ code, expires, addresses }`，5 分钟、一次性；服务端只保留一份，重新生成即作废上一份                                                                                                                                          |
| `pair(code)`                            | 首次新建独立 `.db` 并登记切换；同源重配沿用本机副本                                                                                                                                                                             |
| `sync` / `download`                     | 立即补齐 / 下载协调电脑版本并覆盖（需已连接；旧库先备份，失败恢复原库）                                                                                                                                                         |
| `revoke(id)` / `copies` / `export-copy` | 解除配对；冲突副本列表 `{id, reason, kind}` 与另存                                                                                                                                                                              |

移动 `services/device-sync/runtime.ts`：状态只有 `phase / error / lastSync / pendingAssets / preservedCopies`；动作只有 `pairDevice(code)`、`wakeDeviceSync()`、`downloadDeviceLibrary()`。没有暂停、解除配对、设备列表与副本列表。

都没有：设备类型、在线状态、每台设备最近连接时间、任何进度百分比、下载分阶段事件。

## 三套方案

|            | A · 一张纸 · 状态句（推荐）            | B · 首次向导 · 安静摘要       | C · 关系图 · 弹窗配对     |
| ---------- | -------------------------------------- | ----------------------------- | ------------------------- |
| 与云端同步 | 独立页签「设备同步」                   | 同页上下并列两节              | 独立页签                  |
| 角色选择   | 同一张纸上并排两条路                   | 向导第一步单选                | 右侧两行选项              |
| 配对引导   | 就地展开在状态句下，完成自动收起       | 向导第二步（左侧进度轨）      | 应用内弹窗                |
| 多台设备   | 两列行式列表，每台一个 ⋯               | 折叠的「设备」段              | 关系图（超过 4 台需折叠） |
| 低频操作   | 状态句旁的 ⋯                           | 折进「高级与恢复」            | 节点菜单                  |
| 下载覆盖   | 留白隔开的「恢复」区，danger-soft 按钮 | 「高级与恢复」里，默认收起    | 协调电脑节点的 ⋯ 菜单     |
| 手机日常   | 状态卡 + 分组，覆盖在「恢复」组        | 一行状态 + 列表，覆盖进二级页 | 关系条，低频全进页头 ⋯    |

推荐 A：

- 日常只有一句状态 + 一个主操作，配对引导只在需要时展开，符合「一整张纸、分组靠留白」的偏好。
- 覆盖入口看得见又和日常操作隔开：位置（留白后的「恢复」区）、文案（「下载并覆盖…」）、音量（danger-soft）三处都和「立即补齐」不同，点开再确认一次。B 的覆盖最难误触也最难找到；C 收进节点菜单，可发现性最弱。
- 行式列表在现有接口下也成立（只需要名字）；C 的关系图在没有在线状态时信息量有限，设备多了会拥挤。
- 两套状态文案可以一一对应到现有 `phase`，桌面和手机用同一套说法。

方案 A 在原型里覆盖全部状态：配对过期 / 无效 / 重新生成、首次同步、同步失败与重试、暂停、图片待下载、冲突副本、覆盖确认 / 进行中 / 重新打开 / 完成 / 失败、解除配对确认、云端共享正文时不能开启。B、C 覆盖要求的最小集合。

## 能直接落地 / 需要补充的能力

现有接口可直接实现（方案 A 主体）：角色选择、开启 / 暂停 / 恢复、生成 / 复制 / 粘贴配对信息与过期倒计时、已配对设备列表与解除配对、日常 / 补齐中 / 离线 / 失败状态、图片待下载数量、冲突副本数量与另存、覆盖的一次确认与失败恢复。

只改渲染端（不动协议与存储）：

- 移动端覆盖补一次应用内确认（底部面板）。
- `DEVICE_SYNC_*` 前缀映射成人话 + 下一步（版本不一致、授权已撤销、过期、格式无效、云端共享冲突、离线）。
- 粘贴后本地解码配对信息，提前提示过期；剪贴板检测沿用加入协作页的 `clipboard.readText`。
- 协调端「对方已配对」由 `peers` 数量增加推断（现有 3 秒轮询）。

需要主进程或原生补字段（原型「补充字段后」展示效果）：

- `peers` 增加 `kind`、`lastSeen`：设备类型图标与「最近连接」。在此之前副标题只写「已配对」，不写在线。
- 连接端 `status` 返回协调电脑名称（`peer.json` 的地址里已有主机名）。
- 本机副本显示名：现在是 `device-<uuid>.db` / `device-<sha256>.db`，需配对时记录协调端资料库名。
- 手机上报系统设备名或允许改名：现在固定「我的手机」，多台手机会同名。
- 覆盖完成跨窗口重载的一次性通知，重载后才能给出完成提示。
- 冲突副本的原因码 + 笔记标题 + 发生时间。
- `status` 返回结构化错误码，替代解析字符串。

可选建议，均需新增能力，不在主方案：扫码配对、短码配对、局域网自动发现（当前无 mDNS）、精确进度（下载 / 校验 / 安装分阶段事件）、实时在线状态。

## 待你选择

1. 设备同步与云端存储：独立页签（A / C），还是同页上下并列（B）。
2. 配对引导：就地展开（A）、向导（B）、弹窗（C）。
3. 多台设备：行式列表（A）、默认折叠（B）、关系图（C）。
4. 下载覆盖入口：可见的「恢复」区（A）、折进高级（B）、节点菜单（C）。
5. 手机日常：状态卡 + 分组（A）、一行状态 + 二级页（B）、关系条 + 页头 ⋯（C）。
6. 「补充字段后」的依赖，哪些随本次 UI 一起做。

## 选型与实现

用户选定方案 A，并要求注意图标布局（原型里步骤序号被 `.m-step span` 规则拉成块级，数字贴左上，已修正）。实现只用现有接口，「补充字段后」的依赖本轮不做。

| 位置                                                       | 内容                                                                                                              |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `packages/collaboration/src/device-sync/messages.ts`       | 两端共用：`DEVICE_SYNC_*` → 标题 + 下一步；配对信息只解出有效期与主机名                                           |
| 桌面 `features/settings/sections/DeviceSyncPanel.tsx`      | 「设备同步」页签（默认页签）：角色选择、首次同步                                                                  |
| 桌面 `DeviceSyncCoordinator.tsx` / `DeviceSyncReplica.tsx` | 协调端（添加设备、就地配对引导、设备列表、解除确认、暂停）；连接端（状态句、⋯、恢复区覆盖确认、重新粘贴配对信息） |
| 桌面 `deviceSyncModel.ts` / `deviceSyncParts.tsx`          | react-query 数据层与覆盖后重载提示 `useDeviceDownloadNotice`（壳层挂载）；共用小件                                |
| 移动 `settings/sync/DeviceSyncSection.tsx`                 | 未配对（三步、剪贴板探测、粘贴预检）、日常、覆盖与重新配对底部面板；同步页下方加「云端存储同步」段头              |

与原型的差异：

- 手机同步页同时承载云端存储，固定在底部的拇指区按钮会盖住下方内容，改为卡片下方的满宽按钮。
- 没有不确定进度条（需要新增 keyframes 进主题包），进行中统一用旋转图标表达。
- 「协调电脑」名称、设备类型与最近连接时间不展示（无数据）；手机日常页只留本机资料库一行。
- 手机没有独立的「已配对」状态：以 `phase !== "idle"` 推断，冷启动首轮对账前会短暂显示未配对。
