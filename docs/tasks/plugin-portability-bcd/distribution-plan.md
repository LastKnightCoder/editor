# 跨端 SDK、清单与插件中心正式接入方案

目标：定稿一个 SDK、一套模板、同一插件身份的正式协议，明确桌面、移动端与网页中心的接入和旧插件兼容方式。

状态：本文件保留正式目标契约；中心 v2、格式 3 上传审核与网页已经上线，生产批准发布/平台分发和移动正式安装关闭。API 支持矩阵及客户端前向读取在本地继续完善，桌面格式 3 正式安装、外部 SDK/模板发行和 D 尚未完成。各批验证分别记录在 [逻辑交接](logic-handoff.md) 与 [API 契约收尾](api-contract.md)，不把目标契约全部标为已实现。

## 范围与决策

本方案同时列出已实现与剩余的接入目标；当前宿主能力以 [SDK 支持矩阵](/plugins/tau-plugin-template/docs/portability.md) 为准。公共 SDK、统一模板与调试宿主已经实现，中心接收格式 3 待审包但禁止批准发布，移动 release 拒绝安装和启用。Android/iOS 同包中心模拟器联调已通过，D 的真机和完整归档等验收未关闭。

- 一个 SDK、一套模板、同一插件 ID；第一版正式跨端发行采用一个版本对应一个不可变 ZIP，三端下载相同字节。平台差异写在包内组件和 targets 中，不建立三套 SDK 或插件身份。
- 第一版正式范围为 formatVersion 3、profile web-v1 的页面和正文扩展；不纳入 Node 后台或原生二进制加载。已有 backend、whiteboard、Skill、静态博客模板继续走原有桌面协议。web 环境只表示渲染上下文，网页插件中心不是插件运行宿主。
- 生产安装统一来自插件中心。开发 ZIP 与目录入口继续隔离；不把任意 URL 安装开放给普通用户。
- 可信模式保持不变：HTTPS 来源、审核、摘要和能力检查不是恶意代码沙箱。不新增作者证书或离线签名体系，也不声称现有摘要能独立证明发布者身份。
- 旧桌面格式继续被正式支持；不转换已发布 ZIP，不删除现有包、配置与数据。旧端通过既有协议获得旧格式，新端显式协商新格式。
- SDK 与分发协议先定稿；各端建设可与 D 并行，生产开放必须通过对应平台验收。npm、模板外部仓库更新、生产部署均不包含在本次文档任务中。

## SDK 与版本约束

作者业务能力仍从 @tau/plugins 获取，UI 从 @tau/ui 获取；这是一个插件 SDK 体系，UI 包不是第二套移动 SDK。host、rendering、environment-host 等内部装配入口不暴露给作者。正式 npm 使用现有发行包名与构建映射，不改作者源码导入方式。

| 版本字段                | 正式含义与变化规则                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| SDK npm 版本            | 作者编译时依赖；采用语义版本与变更日志，不能据此推断用户客户端已有能力。当前 0.36.0-dev.0 不是正式发布承诺。 |
| manifest.version        | 同一插件全平台共用的语义版本；pluginId + version 全局唯一，不按平台另存同版 ZIP。                            |
| formatVersion           | 包结构协议；旧格式 1/2 与跨端格式 3 分开校验，不把 3 偷换成 1 交给旧加载器执行。                             |
| apiVersion              | 保持 1；表示基础插件生命周期协议，不因新增可选能力递增。基础协议不兼容时须使用新的 apiVersion，旧宿主拒绝。  |
| profile                 | web-v1 定义模块、文件与运行边界；破坏性变更用新 profile，不静默改变 web-v1 含义。                            |
| 能力版本                | 如 pages.v1；新能力可增加，语义破坏时使用新的能力名/版本。required 缺失拒绝，optional 缺失降级。             |
| targets.*.minAppVersion | 分平台的最低客户端版本，由真实兼容验证决定；不得直接把实验模板的版本号当作正式最低版本。                     |

页面与入口分离：pages.register 声明页面；navigation.registerEntry 引用同次激活的页面。桌面映射侧栏，移动映射“我的 · 插件功能”；旧 sidebar 只在桌面有效。页面参数、身份、离开守卫、保存/取消语义共用；复杂布局允许拆分视图。

宿主显式提供 platform、layout、input、capabilities。作者按能力判 API、按布局和输入判交互，只有真正的平台差异才按 platform 分支。context.environment 是最新快照，usePluginEnvironment 订阅环境变化；静态正文组件不依赖 activate。会话内平台与能力固定，布局和输入可变化。

数据模型、节点 type 与 codec 跨端共用。标准源码容器、选区恢复、插入、块菜单、返回与提交保护由宿主适配；插件内部的特殊手势由作者适配。none 不装配，render 只读，edit 允许编辑；UI 与提交层同时执行等级。多个节点混在一个 extension 时保留现有保守投影，需要独立编辑入口时作者拆 extension，不改节点身份。

权限与能力分开：required/optional 只表示 API 可用性，permissions 仍走现有业务授权；宿主没有实现或授权的权限调用明确失败，不用“兼容”标签暗示数据访问已获准。第一版发布校验只允许各目标已接线的权限集合，不能为了通过校验给移动端虚报桌面权限。

清单读取规则：SDK 由 validatePortablePluginManifest 统一解析作者与消费方使用的发行结构，仅提取当前协议字段；validatePortableDistributionManifest 额外限制移动业务权限。宿主选版不使用能力名或节点等级，未知附加元信息不参与审核清单对账。新增业务 API 先接宿主与授权，再更新支持矩阵。

## 格式 3 清单与构建产物

保留已验证字段，不新增移动专用清单：

| 字段                                            | 约束                                                                                                 |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| id / name / description / version               | 身份和展示资料；沿用现有校验，中心 description 必填。ID 归属继续绑定同一发布者与源码仓库。           |
| formatVersion / apiVersion / platform / profile | 固定为 3 / 1 / portable / web-v1。                                                                   |
| format / main / styles                          | cjs、必需 JS 入口与可选 CSS；单入口打包，不能远程下载代码或带 Node/宿主私有依赖。                    |
| targets                                         | 至少一个 desktop/android/ios 目标；未声明的平台不支持，不用 UA 或“纯 JS”推断。                       |
| targets.*.minAppVersion / required / optional   | 各目标独立；required 必填，optional 默认空，二者无重复或交集。                                       |
| targets.*.elements                              | 含编辑器贡献时，每个目标列出全部实际节点 type，逐个标 none/render/edit；声明与求值结果必须完全对账。 |
| editor / permissions / categories / keywords    | 复用已验证语义；分类不是平台支持声明，permissions 不是能力列表。                                     |
| integrity                                       | 覆盖 main 与可选 styles；所有执行文件必须本地完整打包。README 等资料由整 ZIP 摘要覆盖。              |

格式 3 不接受顶层 minAppVersion、backend、whiteboard、skills、template 或 web target。旧静态模板继续按 template 字段区分包形态，并保留现有 formatVersion=1、apiVersion=1，不新增伪造的空格式号。schema/类型必须能表达旧代码包、旧静态包、跨端包三个分支，不能把 PackageManifest 定义为所有包都必有顶层 minAppVersion。

ZIP 继续为 <pluginId>/ 单层根目录，包含 manifest.json、main.js、可选 main.css、README.md、可选 CHANGELOG.md 与 LICENSE。沿用中心上限：ZIP 16 MiB、展开 32 MiB、512 条目、manifest 64 KiB、每份说明文档 128 KiB；SDK 构建器、上传校验和客户端读取器对齐，保留实际解压字节数校验。拒绝越界、链接、重复路径、加密条目、未声明文件、无效 UTF-8 说明文档及空入口。

统一模板提供页面和编辑器起点；跨端为默认路径，旧桌面模式仍在同一模板中显式选择。正式构建生成运行文件摘要与 ZIP 摘要，锁定正式 SDK/UI 输入；作者可按环境拆视图，但不生成不同平台同版本不同内容的 ZIP。正式产物不接受插件预发布版本或 build metadata，避免正式选版中的排序歧义；开发验证仍可用开发 SDK。存量已发布版本不重新打包或删除，保持原有语义版本比较规则。

第一版不提供多平台 backend 组合包、动态模块分片、热替换正文实例或博客格式 3 分发。需要这些能力时另行扩展协议，不在本次清单里预埋未实现字段。

## 分发协议

### 身份、来源与发布

复用现有插件 ID 归属、GitHub 登录与仓库绑定、OIDC 上传、草稿/审核状态机、不可变 Release、私有 R2 和摘要校验，不新建移动发布体系。作者提交的 manifest 与 README 是唯一资料来源，网页不能另外编辑平台声明。

发布记录绑定 releaseId、pluginId、version、ZIP size/sha256、完整清单、源码 commit 与审核记录；同一 ID/版本禁止覆盖或按平台补传不同包。包未发布前可依现有流程改草稿并重新审核；已发布后增加平台或改最低版本也必须发布新版本。源码 commit 是审核快照，不声称平台已复现该 commit 的构建。

格式 3 沿用既有上架规则。平台适配与测试由作者负责，审核者不承担平台测试，也不填写或确认验证记录；中心自动检查格式、完整性与兼容声明，不改写包内 targets。已绑定仓库中，具有审核权限的插件所有者本人推送 tag，经 OIDC 与包校验后可自动批准格式 3；普通作者和协作者进入待审，发布与平台分发开关继续生效。旧后台/脚本 Skill 的 systemReviewed 规则保持，不把它当作移动兼容认证。

可信来源为受配置约束的中心 HTTPS origin 与发布记录。安装命令接收 releaseId，由原生服务从中心取得下载地址、摘要与清单，不接受渲染端任意指定 URL/摘要充当正式来源。下载 URL 必须属于允许的中心 origin，不跟随未经验证的跳转；ZIP 摘要、包内文件摘要、身份/版本/完整清单都与发布记录核对。安装前与激活前各检查兼容，失败不执行 JS。

### 新旧 HTTP 边界

新增 /v2 公共分发协议，复用同一发布数据；/v1 作者登录、上传、提交、审核与社区接口继续使用，上传/审核契约扩展为清单联合类型。接口版本与 formatVersion 是不同维度。

| 接口                          | 输入与语义                                                                                                                                                                |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST /v2/catalog/query        | 只读查询：q、category、sort、limit、cursor、platform（desktop/android/ios/all），可选 host。返回每插件一项、分页游标和分类计数。POST 用于承载能力集合，不创建服务器状态。 |
| GET /v2/plugins/:id/releases  | platform 可选，返回公开版本历史与各版本目标声明；按版本排序，分页。不把历史列表当作推荐版本。                                                                             |
| POST /v2/plugins/:id/resolve  | 必填 host，可选 releaseId。无 releaseId 选最高兼容版本；指定时只校验该版本，不能偷偷换包。返回 release 或 null 及结构化原因。                                             |
| GET /v2/releases/:id          | 当前可公开发布记录、完整包资料与下载地址；包被撤回/插件禁用时不返回可安装记录。                                                                                           |
| GET /v2/releases/:id/download | 复用下载校验与计数，只有发布且未撤回/禁用的包可下载；所有目标使用同一 ZIP。                                                                                               |
| POST /v2/releases/status      | 只读批量查询，最多 100 个 releaseId；逐项返回 available/revoked/disabled/not_found 及公开处置原因，不泄漏未发布包资料。用于已安装包核验。                                 |

host 必须由宿主提供：platform、appVersion、apiVersions、formatVersions、profiles、capabilities；集合去重后排序，字段与长度受限，不能从插件参数或网页 UA 推断。platform=all 不接受 host；指定平台与 host.platform 必须一致。网页无真实 host 时返回 compatibility=unchecked、compatible=null，不能显示“当前设备可安装”。浏览器切换 Android 标签只表示查看该平台声明。

新目录项分别返回 latest（当前平台视图内最高公开声明版本）、compatible（host 下最高可安装版本或 null）、compatibility（unchecked/compatible/incompatible）、reasons。每个版本描述携带 formatVersion、apiVersion（静态模板同样沿用现有 1/1）、profile（旧格式为空）、targets 摘要、releaseId/version/size/sha256/downloadUrl。条目资料取自 latest，安装确认与权限提示必须取实际选中的 compatible 记录，并显示其确切版本。

platform=all 的 latest 是全体公开版本中最高者；各平台标签表示存在该平台的公开版本，不表示 latest 同时支持所有平台。平台筛选、搜索、分类计数与分页候选使用同一平台投影，防止先分页后剔除另一平台造成整页消失。游标及查询缓存绑定平台、完整规范化 host、搜索、分类、排序和统计日期；换条件从第一页开始。分页沿用现有上限和不冻结榜单口径，客户端按 pluginId 去重。

/v1 的公共目录、公开版本列表、详情、下载统一只暴露旧格式（含原有静态模板/Skill）；格式 3 不进入旧端 latest、compatible、搜索和分类计数。私有作者/审核接口仍能读取新提交。新网页和新客户端使用 /v2 浏览全部支持的格式，不让未升级消费者被新的清单结构击穿。/v1 服务端过滤不是把格式 3 降级转换成旧包。

### 兼容与版本选择

按以下顺序执行同一纯函数，SDK、中心选版与客户端复验共享规则；原生 ZIP 读写仍留在原生层：

1. 发布记录可用且平台发行开关开放；已撤回或禁用版本排除。
2. host 支持包结构、apiVersion 和 profile；移动仅允许格式 3，旧包只投影为 desktop。
3. 目标平台存在，宿主版本满足该目标最低版本，所有 required 都存在。optional 缺失记录降级，不拒绝。
4. 下载后对账 ZIP 与清单，在受控求值后对账节点清单；按 none/render/edit 装配并执行授权。
5. 候选按既有语义版本比较取最高兼容项；正式新发包不含预发布/build metadata。存量版本若比较相等，以 publishedAt、releaseId 稳定排序；其历史身份不变。

原因码至少包含 FORMAT_UNSUPPORTED、API_UNSUPPORTED、PROFILE_UNSUPPORTED、PLATFORM_UNSUPPORTED、APP_VERSION_TOO_LOW、CAPABILITY_MISSING、DISTRIBUTION_UNAVAILABLE、REVOKED、PLUGIN_DISABLED、NO_RELEASE；附带所需版本或缺失能力，不只给“安装失败”。无兼容包是成功查询返回 null；网络/鉴权/参数错误仍走既有错误信封，不能冒充“没有兼容包”。

安装或更新不得从 null 回退到 latest。更新只有候选版本高于已装版本才提示；新版本取消某个平台时，该平台保留仍有效的旧版，不自动降级、不删除数据。下载后若客户端条件或发布状态变化，重新核验，旧包保持可用，不留下半安装状态。

### 状态、撤回与存储

中心状态复用 draft → pending_review → approved 与 release pending/publishing/published/failed，撤回和插件禁用独立记录。客户端明确区分下载中、校验中、待生效、运行中、已停用、失败和已撤回；UI 状态不是新增服务端审核状态。

下载安装与更新仍走 staging → next/pending → 下一完整插件会话切换 current/backup；取消与失败不破坏旧包。启用意图属于设备，KV 属于当前工作区，同步正文或私有数据不自动下载、安装或授权代码。卸载保留正文及 KV，清当前库数据是独立确认操作。

格式 3 首期要求作者的数据变更保持旧版可读：采用兼容字段扩展，保留未知字段。中心不提供任意数据回滚器，不能从“有代码备份”推导“数据可回滚”；运行新代码并写数据后，只在明确验证旧版可读时允许手动代码回退，否则保留数据并要求修复版本。破坏性数据迁移不在首期支持范围。

用户启动插件会话、安装/更新/启用前，以及应用回到前台时，检查对应发布状态；断网时允许已验证且未被本机记录为撤回的安装继续使用，显示状态未刷新。已确认撤回/禁用后持久化拦截，不因离线或恢复 backup 重新启用；停止后续激活和编辑提交，在安全会话边界移除正文贡献、保留原文。同步死循环不能被当前可信 JS 运行时抢占。未知 ID 或网络失败不能直接视作审核撤回，但不能据此新装未经核验的包。

中心的 android/ios 发行开关与客户端 release 安装开关分别控制。开关关闭时仍可浏览目标声明和不开放原因，不能获得可安装推荐。商店分发路径与对应平台 D 验收是开放条件；本方案不声明已经通过应用商店审核。

## 各部分改动清单

实施按协议逻辑与 UI 两条工作线分工：主任务拥有契约、服务和数据适配，UI 专家拥有网站与移动展示层。具体文件所有权、混合文件交接和联调顺序统一见同任务的 [工作分工](work-split.md)。

| 部分与位置                                                                                            | 复用                                                         | 必须修改及验收                                                                                                                                                                                                                                                          |

移动 HTTP 经原生服务访问中心，不为适配 WebView 放宽浏览器 CORS。首期匿名浏览和安装无需 GitHub 登录；桌面已有匿名统计凭证不复制到移动。下载统计可先无身份使用（不计榜单），评论/喜欢不是安装闭环的前置项；后续如启用移动匿名互动，必须独立增加原生匿名身份契约和安全存储，不冒充 desktop 绕过现有 visitor-session 的来源检查。

网页下载 ZIP 仍是下载文件，不代表已安装到手机；首期不新增未经实现的“一键远程安装”。用户在应用内选择安装。网页中心支持 Android/iOS 展示，不等于格式 3 获得 web 应用激活资格。

## 旧插件兼容与作者迁移

| 组合                              | 结果                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------- |
| 旧桌面客户端 + 旧格式             | /v1 继续给出旧格式最高兼容版本，安装/升级不变。                              |
| 旧桌面客户端 + 同 ID 已发格式 3   | 仍看到旧格式版本，收不到格式 3 更新；纯格式 3 插件不出现在旧目录。           |
| 新桌面客户端 + 旧格式             | 走已有宿主；旧 sidebar、backend、Skill、模板/白板语义不变，不强制作者迁移。  |
| 新桌面客户端 + 格式 3             | 经 v2 选版与正式加载；与旧版共用插件 ID、KV 和正文节点，不同时装载两套实现。 |
| Android/iOS + 旧格式              | 不安装、不执行；同步来的未知节点保留原始数据，不能自动改清单后加载。         |
| Android/iOS + 格式 3              | 只有已声明平台、满足版本/能力、审核与发行条件的包可安装；节点等级逐个生效。  |
| 新格式取消某个平台 / 尚无移动适配 | 对应平台继续使用仍有效的旧兼容版本或提示无兼容版，不使用其他平台 ZIP。       |

旧作者可以不迁移，继续使用模板的 desktop 模式发旧包。需要跨端时保持 ID 与节点 type/字段，使用更高版本，移除非 web-v1 依赖，页面改语义入口，补 targets、能力与逐节点等级，再分别验收并重新提交。ABC 只改清单就跑通属于该插件复用了标准组件的验证结果，不作为所有旧插件自动兼容的承诺。

仍依赖 Node/backend/白板/Skill 的插件继续按桌面格式维护；不能把桌面系统能力塞进格式 3 optional。需保留同 ID 的桌面系统版与移动版时，可以在全局版本序列中分别发布旧格式桌面版本与格式 3 移动版本，按平台选最高兼容项，不能复用同一版本号；公共数据必须仍兼容。第一版不支持“同版本桌面有后台、移动无后台”的多产物发行。

旧安装的包、权限、配置和 KV 原样保留；升级到格式 3 只替换代码和经过确认的权限变化，新增权限不能继承旧授权。显式新版本迁移不属于“强制把所有旧包转格式 3”，也不触发客户端主数据库 schema 升级。客户端读取旧业务数据时仍遵循项目的数据保真与既有升级规则。
