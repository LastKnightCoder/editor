# 编辑器扩展实际移动适配

目标：补齐编辑器插件所需的移动宿主能力，以同一插件包完成桌面与移动安装、插入、编辑、保存和重启恢复。

## 需求与约定

- 用户明确要求继续实际移动适配，优先编辑器扩展；上一轮仅依赖升级，不作为本轮功能完成依据。
- 用户明确全部插件由本人维护且该功能未上线，允许统一升级：只保留一套稳定功能名，不维护旧能力标识、别名表或迁移版本门槛，SDK、宿主、模板、测试与作者插件同时修改。
- 中间方案的纠正检查只作临时门禁，纠正后删除；不长期保留针对旧 .v1 能力名的专门断言，测试只覆盖当前契约的行为与边界。
- 共用插件 ID、节点与源码，保持历史数据；不削减已有桌面 Skill、博客功能来换取移动声明。
- 当前 worktree 为 codex/mobile-plugin-spike；官方插件和模板统一在 plugins/ 子模块维护。外部升级目录保留已提交快照，不再作为维护源；固定提交与远端复现见 [子模块接入](submodules.md)。
- 先以 TikZ/Typst 梳理共性链路，再推进 HTML/自定义块/图册所需的样式与媒体交互。业务数据、AI、同步提供方等不因本轮被自动声明支持。
- iOS 正式签名继续等待；可进行模拟器行为验证。视觉、真机手感、最低系统等 D 待验收保留。
- 具体插件 ID、示例正文、CSS 选择器和测试步骤仅放 apps/mobile/validation，禁止进入生产 src；生产宿主只识别插件声明，不维护具体插件分支。正式构建必须检查不含验证样例与自动执行器。
- 应用源码使用 @/ 别名，验证入口使用 @validation/；TypeScript、Vite、Vitest 统一配置，禁止通过 ../../src 回跳。
- 用户已确认 [完整作者契约](author-contract-draft.md)，授权统一修改 SDK、模板、插件与宿主，完成仓库外构建和两端原生验证；不添加兼容层，先不发布。

## 实施协议

- 格式 3 增加可选 skills，沿用 skills/<id>/SKILL.md 和 integrity，只接纯 Markdown 文档，不允许脚本/任意附件；不新增移动 Skill 执行器，也不另设文件读取能力。构建器从 editor 自动推导 editor/editorCodecs，作者不重复声明。其他真实需求使用 sourceEditor、runtimeStyles、media 等稳定功能名，无独立能力版本。
- 桌面扫描读取原始格式 3 清单，继续按启停意图控制 Skill；移动只完整校验保存文档文件，不注册 Skill 或执行脚本。
- 博客 runtimeVersion 保持 1，包格式由 manifest.formatVersion 独立表达；增加格式 3 清单识别不改变加载、校验与静态渲染协议，因此不按包格式派生新的渲染协议版本。用户质疑这两个版本绑定后，已去掉对应分支。新加载器只求值静态编辑贡献，不激活插件；发布校验实际包身份和摘要，不把格式 3 改写成格式 1。旧博客加载器会明确拒绝格式 3，发行时仍需更新模板消费者。
- 新能力对应新 SDK 和客户端版本；本轮先在本地候选构建验证，不覆盖已发布版本、不自动部署中心或发 npm。发行前还需同步正式中心、SDK 与博客模板消费者。
