## 接口交接与并行顺序

1. 主任务先提供真实 TypeScript 契约、HTTP/原生适配入口和最小测试 fixture，列出已交付导出名、位置与状态。不把文档里的拟定接口误称为实现。
2. UI 可立即整理页面结构、组件、布局与状态矩阵；使用已有类型和测试专用 props/fixture，不创建一份独立 HTTP DTO 或兼容判定。未交付接口标记“待接线”，不接入生产路由造成半成品，也不伪造成功数据。
3. 契约交付后，UI 消费共享类型与主任务提供的 hooks/动作；主任务修改数据文件，UI 修改页面文件。接口变化由主任务统一更新，并列出受影响组件。
4. PluginManager 解耦交接后，UI 接入移动页面与入口；主任务验证真实服务路径，双方按组件/逻辑归属修复，不同时争用一个文件。
5. 合并检查旧流程、缺能力/无兼容版、网络失败、撤回、待生效更新与数据保真；主任务完成整体检查，用户做视觉和真机交互验收。

对 UI 的数据交付应覆盖：目录与游标、选中平台、latest/compatible/兼容原因、版本详情与逐平台声明、安装清单与待生效版本、操作进度/错误、动作允许状态及原因、平台发行状态、审核证据与 revision。动作应覆盖查询/重试/加载更多、下载、安装指定 releaseId、取消、启停、卸载、清当前库数据、恢复备份及审核提交。具体字段统一落入主任务维护的类型，不在本文件新建第二套命名协议。

UI 拥有搜索输入、选中 Tab、弹层开关等界面状态；主任务拥有数据请求、缓存失效和副作用。页面可以调用 hooks/回调，但不得以 useEffect+useState 另写数据同步或在渲染时执行安装。无权限、未开放、需升级、无兼容版本和网络错误应区别展示。没有真实 host 的网页不能推断当前机器可安装。

## 协作与验证

- 同一 worktree 下先查看 diff，禁止覆盖其他人的未提交修改。需要越界修改时记录路径、原因和所需接口，由文件所有者接手；这不是要求用户重复批准已授权工作。
- 仅使用隔离测试数据；显式 mock 只在开发或测试生效。生产失败不能回退 mock，不能向真实中心上传/审核测试包或开放移动 release 安装。
- 不并行执行会写同一 dist、锁文件或原生构建目录的命令。UI 负责网页与移动前端构建，主任务负责 SDK/原生/整体检查；最终全量验证由主任务串行安排。
- UI 完成相关组件测试、网页/移动类型检查和前端构建；不进行截图、浏览器视觉走查，视觉与真机手感由用户验收。使用 pnpm check:docs 检查文档。
- UI 交付列出具体页面、状态覆盖、改动文件、命令结果、待接线项；模拟结果与真实联调结果分开。不能把界面完成写成 D 完成或正式中心上线。
