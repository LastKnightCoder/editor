## 真机测试步骤

在 Android 开发构建（`pnpm --dir apps/mobile dev:android`）上执行；有条件再在 iOS（`dev:ios`）上执行一遍。点右下角路由面板按钮 → 「editor lab」进入实验页。每组做完点测量条的「复制报告」，粘贴回会话；做下一组前点「清空日志」。

1. **V1 键盘高度**：点「编辑」弹出键盘 → 切换到中文输入法、英文输入法、手写/语音（如有）→ 收起键盘。目测记录：键盘实际顶边是否与配件栏底边贴合（有缝或被遮挡各记一次）。
2. **V3 双击进入编辑**：在阅读态双击第二段中间某个字 → 看键盘是否弹出、光标是否落在双击处 → 点「完成」。测量条把「聚焦时机」切到 rAF 再做一次。另外在阅读态单击待办勾选框和链接各一次，记下是否生效。

## 调查结论

- 键盘高度：`useKeyboardViewport`（`apps/mobile/src/hooks/useKeyboardViewport.ts`）优先读 `window.__TAU_NATIVE_KB_HEIGHT`，但原生侧没有注入方（`gen/android` 不入库且无相关 Kotlin 代码），实际全部走 visualViewport 推算。`KeyboardViewportProvider` 把结果写入 `--kb-height` 与 `--kb-viewport-height`。
- 页面容器：编辑页用 `.mobile-kb-screen`（高度 = `--kb-viewport-height`）随键盘收缩。直接「blur 收键盘 + 显示面板」时，容器会先随键盘收起而变高，再被面板顶回，正文必然跳动。实验页因此由页面自己计算底部预留高度 = max(键盘高度, 面板预留高度)，切换期间保持不变。
- 编辑器：`Editor` 的 `readonly` 属性可动态切换（`CoreEditor` 透传给 Slate `Editable.readOnly`，并控制 HoveringToolbar / BlockPanel 挂载）；`EditorRef` 提供 `focus` / `getEditor` / `getEditableElement` / `isFocus`。
- 选区恢复：已有 `restoreSelectionAndFocus`（`features/cards/editorToolbar/toolbarActions.ts`），含 Android WebView 原生焦点残留的兜底，实验页直接复用。
- 页面注册：`features/**/pages/*.page.tsx` 由 Vite glob 收集，`definePage` 调用即注册；实验页用 `import.meta.env.DEV` 守卫，生产构建不注册。
