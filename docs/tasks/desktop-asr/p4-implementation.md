# P4：可选 AI 转录整理

> 后续裁决：本文记录实现时的验证结果。用户现已要求撤回所有新增宿主入口，当前只保留底层能力；界面位置待决定。

目标：复用现有模型配置整理最终转录，原文独立保留，失败回退，聊天仅写草稿。

## 范围与裁决

- 桌面复用 llmProviders、llmUsageSettings 和 piStreamText 无工具单发入口。新增用途 speechInputRefinement；未选模型即关闭，选用后生效，不增加另一套账号或额外启用开关。
- 仅输入本次最终转录，不附加聊天、搜索或整篇文档上下文；转录中的指令作为数据，不执行。默认轻度补标点与清理重复，可选适度分段及补充要求，仍须忠实原文。
- 原始 ASR 文本、分段及时间戳与整理结果分开；组件保留本次原始文本，供展开查看和复制恢复，不写日志或新增历史库。
- 整理错误、空结果、截断、无权威终态或 30 秒超时均回退原文并提示；用户取消整个会话不写入原文或整理结果。
- 整理中的临时结果只预览，最终通过现有提交守卫一次写入草稿。用户编辑、只读、离开页面或切换工作区后不覆盖新内容，冲突结果保留供复制。
- 移动端目前没有可复用的 LLM 模型配置与执行入口，本阶段只在桌面启用 AI 适配；共享组件在移动端继续原文模式，不凭空新增移动模型体系。Windows 原生、Whisper 听写和媒体整合仍为后续项。

## 接口

- `SpeechRefiner(text, { signal, onPreview }): Promise<string>`：宿主提供模型适配，纯 ASR 包不依赖模型 SDK。
- `refineSpeechInput(original, refiner?, options)`：返回 `{ original, text, status }`，status 为 original/refined/fallback；仅非取消失败降级。
- `SpeechHost.prepareRefinement()`：录音开始时固定所选模型身份及整理风格；后续配置变化不静默切换其他模型。
- `speechInput.refinement` 仅保存 style/instructions，经现有专用设置命令合并；模型引用仍只在 llmUsageSettings.speechInputRefinement。

## 使用与后续

在“设置 → 语音 → 语音输入 → AI 整理”选择已有模型，或在“大语言模型 → 功能分配 → 语音输入整理”分配同一用途；选择“不整理，使用原文”关闭。可保存轻度整理／适度分段及补充要求。原文仅保留在本次组件内存，可查看、复制；下一次录音、组件卸载或输入作用域重新激活时释放。
