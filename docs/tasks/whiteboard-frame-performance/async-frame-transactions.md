# 画框事务后台准备与异步完成方案

目标：让千元素收纳、解散等整批操作也能维持主线程帧预算，保留原子性、撤销、保存和远端竞争规则。

## 当前事实与约束

稳定渲染容器已经使千元素收纳、解散保留全部 SVG 实例、焦点和 iframe。相同代码下仅恢复旧渲染层的对照中，4× 密集收纳最大帧间隔约 350–367ms，当前约 217ms；密集解散从约 283–333ms 降到约 100ms。收纳的模型结构提交仍约 68–73ms，解散约 42ms。同步原子入口必须在返回之前完成这些工作，因而这些操作仍超过 16.7ms。

持续拖动通过位移意图、按需事件快照和绘制阶段拆分，4×、1000 文字元素的两次正式四秒样本达到全部 235 次有效位移、最大帧间隔约 16.8ms；八秒样本显示全部 470 次有效位移，但起落阶段仍有约 33ms 帧，严格门控未通过。所有失败数据保留，不把单次通过解释成全面达标。

当前同步 API 的实际契约：`submit`、`endGesture(true)` 返回后，主线程模型已包含本次修改。若改成后台准备及排队完成，需要明确区分即时显示结果与已提交模型结果。

## 用户确认的方向

- 内置画框交互可异步完成：画面先响应，模型提交和保存结算通过完成句柄通知；后续依赖这次修改的编辑按顺序排队。
- 先做隔离原型验证收益，有效才接入；每一步通过复杂压力测试，验证数据、保存、撤销和协作，比较 1×、2×、4× 性能。

隔离原型不改变生产入口和既有同步 API。原型必须把候选生成、真实合入、历史、快照及绘制的成本分别记录，不能只测 Worker 内的计算时间。

## 模块与边界

### 事务准备器

一个文档对应一个后台准备器，镜像已有的 V1 文档增量。只处理内置画框的创建、几何、归属、完整删除集合，不执行 UI 扩展工厂。自定义数据和资源许可仍由现有可信入口验证。

输入：基线修订、写许可代次、稳定元素身份、所见几何、创建容器数据和操作意图。输出：已完整验证的候选增量、容量结果、初始化保护范围、涉及身份与候选快照。准备失败不修改主线程文档。

准备器对镜像建立隔离候选，未确认的候选不推进镜像。主线程真正提交后才将相同增量回送镜像；过期响应按任务身份丢弃，不允许迟到写入。

### 编辑队列与完成句柄

为内置交互增加独立的异步入口，现有同步入口保留完成语义。新入口返回已分配的对象身份、即时视图及完成 Promise：

```ts
interface FrameEditHandle {
  id: string;
  createdIds: readonly string[];
  settled: Promise<FrameCommitReceipt>;
  cancel(): void;
}
```

同文档的依赖编辑串行结算。用户立即撤销未提交操作时，取消候选并移除视图意图；已经开始原子合入的操作先完成，再按同一个编辑身份撤销。一个完整手势仍只有一个撤销项。

内置画框入口及依赖它的后续编辑由宿主等待队列；旧同步入口在有待结算编辑时明确拒绝冲突调用，并返回可识别的“有待完成编辑”错误。没有待结算编辑时维持原同步语义。扩展若需要等待，显式使用完成句柄；不把异步行为藏进原同步接口。该边界随异步入口接入，隔离原型不改变生产交互。

### 即时视图与新对象编辑

公开画布查询返回包含待提交意图的当前视图，并提供可区分的已提交版本；模型的原始读取仍只返回已提交数据。命中、箭头和视口剔除共用同一视图，避免画面与交互位置不同。

新对象在提交前使用独立预览文本会话；若允许用户立即编辑标题，编辑增量在创建结算后按序应用，不能丢失、重复或写到未创建的正文根。写许可在入队及合入前各检查一次。

### 批次绘制容器

稳定元素容器继续按 ID 保存实例。另维护连续绘制批次：当整组元素从根层收进同一画框，或整框解散时，优先移动一个仍包含同序成员的批次组；只在部分成员进出或重排时拆分批次。避免每次对全部成员执行 DOM 归属移动。

绘制批次不改变逻辑父子树、节点身份或存储格式。画框的组位移、插件内部结构、选区、焦点、iframe、层级顺序与导出仍需使用已验证的边界。

## 提交流程

```text
接收画框意图
  → 分配编辑身份并发布即时视图
  → 后台按固定基线构造候选并完整验证
  → 主线程检查写许可、修订、根集合和队列身份
      基线过期/被取消 → 丢弃候选，撤回对应视图；不写文档
      验证失败       → 撤回视图并明确反馈；用户可重试
      仍有效         → 单个真实事务合入
                        → 核对实际写集及修订
                        → 交接一个撤销项，发布已提交结果
                        → 完成 settled，再执行依赖编辑
```

实际远端内容变化维持当前取消竞争手势的规则；无内容变化的回执不取消。后台响应不能直接写 Y.Doc。准备器给出的初始化保护区间在主线程真实事务内登记，原子合入仍归属本次编辑的历史项；观察者附加修改使增量证明失效，重新读取真实数据。

## 实现顺序与退出判据

1. 先以隔离原型测量后台准备后主线程的合入和历史开销；若仍超过预算，先报告下限，不能直接扩大到生产入口。
2. 引入内置画框的编辑句柄、顺序队列及取消；锁定即时查询、提交完成与同步旧入口的边界。
3. 实现连续绘制批次，验证整体和部分收纳、解散、嵌套分栏及排序。
4. 每一步通过 4× 混合、密集与原生保活压力，独立模型逐步对账，保留全部帧率失败。

验收覆盖：新建收纳 30/1000 元素、解散、移入移出、适应内容、连续及八秒拖动、即时撤销、取消、只读/隐藏、远端竞争、候选迟到、提交失败与保存重开。帧间隔、真实元素位置、输入延迟及完成延迟分开记录，不以空闲帧或延后到采样窗口外的工作换取通过。

## 隔离原型的接入门槛

原型先使用真实 Worker 镜像和独立候选，回传 V1 增量及初始化保护范围；主线程在真实事务内部核对许可、修订、共享根数量与事务状态，随后合入并标记本地编辑。它沿用原画布绑定的快照发布和空闲准备，不隐藏这些成本。

仅返回二进制增量会使当前模型将其视为外部写入，原增量快照和容量证明失效。接入前还须验证候选结果如何在基线匹配、观察者没有附加写入时交接这两类证明，并保留未变化正文与节点的引用。不能直接赋予外部快照可信身份；失配时须读取真实状态。即使交接成功，真实单事务合入、历史和绘制仍需分别满足预算，否则继续保留隔离原型。

## 证明交接原型

`WhiteboardModel.capturePreparedUpdate` 捕获当前已验证结构、容量上界和不可变操作意图，返回仅可信候选生产者可使用的一次性票据。真实合入前核对修订、根数量及事务状态；合入期间核对实际字段写集、所有客户端时钟和删除集，观察者附加修改使证明失效。

快照使用真实合入后的新节点载荷和几何，在原结构草稿中重放归属与删除，并对账受影响顺序根；不接纳外部整份快照。未变化正文和节点继续复用原引用。容量按原增量路径的保守命令余量检查，并用真实 V1 通知增量收紧上界；余量无法证明时不沿用容量证明。网络接纳与现有同步写入不自动使用该能力。

`forkPreparedBaseline` 只在有效基线上复制证明；候选 Y.Doc 与结构索引集合独立，不可变正文可共享。Worker 在原子结构路径返回隔离成功时沿用该证明，其余情况仍完整验证；主线程确认的增量才推进镜像，远端、撤销或未知写入使镜像旧证明失效。

```text
已验证基线 → 捕获交接票据 → Worker 独立候选
  → 主线程核对基线并原子合入 → 核对实际写集/时钟/根
      匹配：重建受影响快照 + 沿用增量预算 → 发布视图 → 同步已确认镜像
      失配：清除证明 → 读取真实状态
```
