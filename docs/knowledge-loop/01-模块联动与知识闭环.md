# 模块联动与知识闭环 · 产品文档

2026-10-01 与用户讨论后整理。**产品方向文档**：定义各模块如何联动成一个知识闭环，是后续迭代的依据。只定方向与边界，具体功能各自出需求文档（AI 洞见见 [../link-graph/ai-insights.md](../link-graph/ai-insights.md)，待按本文 §4.4 重写）。界面部分只给形态，落地前都要先出设计。技术方案见 [02-技术方案.md](02-技术方案.md)。

## 1. 背景

### 1.1 每个模块都能产出，但产出彼此不认识

产品里已经有剪藏、浏览器插件、微信读书、PDF、对话、卡片、文章、项目、Vibe Learning（下称 VL）、问题、闪卡等模块。每个都能单独用，但一样东西离开它的模块后，**既不记得自己从哪来，也看不到自己去了哪**：

- 插件侧栏生成的卡片不记来源 URL；闪卡只知道正文 id，不知道来自卡片还是文章。
- 只有卡片之间有反向链接。文章里引用了卡片，卡片那边看不到。
- 剪藏、PDF 标注、微信读书划线、插件划线都不进主库的向量索引，不能被引用，也不能当问题的材料。
- 已经写好的「这张卡被哪些问题用到」接口，没有界面调用。

完整的盘点见附录 A。

### 1.2 理想的生长方式和实际的写法对不上

最初的设想是知识**自下而上**生长：写卡片 → 卡片聚成主题 → 输出文章 → 多篇文章形成体系 → 整理成项目。

实际上经常是**自上而下**：学一个大主题时，拆不开，也不想拆，直接写了一篇文章；确定了一个方向，直接建项目不断完善。两种情况都绕过了卡片。

这不是使用者的问题。全面学习一个主题时，脑子里已经有结构，写成文章是最自然的。**产品不能要求单一的生长方向。**

## 2. 核心判断

### 2.1 知识的单元是「观点」，不是「卡片」

一张卡片是一个观点；文章、项目文档里的**一节**（一个标题下的内容），同样是一个观点，只是它住在一篇长文里。只要系统能**指向并索引到节**，文章里的观点就可以和卡片一样参与链接、图谱和 AI 洞见。

- **卡片**：独立存在的观点。
- **文章、项目文档的一节**：嵌在结构里的观点。不取单个段落，段落太碎、脱离上下文会丢失含义。

「指向哪里」（地址）与「什么算一个观点」（语义单元）是两件事，见 [02-技术方案.md](02-技术方案.md) §3.3 与 [04-决策记录.md](04-决策记录.md) KL-016、KL-017。

### 2.2 自上而下是引擎，自下而上是雷达

两种方向不是二选一的组织方式，它们**分工不同**：

|          | 自上而下                         | 自下而上                                 |
| -------- | -------------------------------- | ---------------------------------------- |
| 回答     | 我要弄清楚什么                   | 我实际积累了什么、哪里意外地连起来了     |
| 性质     | 主动、有方向、快                 | 被动、无方向、慢                         |
| 载体     | 项目、VL 项目、问题、文章大纲    | 图谱主题、AI 洞见                        |
| 时间尺度 | 一个课题，几周到几个月，有始有终 | 跨课题，几年，持续累积                   |
| 角色     | **引擎**：驱动收集材料、产出观点 | **雷达**：照见全貌，发现意外连接和空白   |

自下而上之所以让人觉得被动、生长慢，是因为它被当成了引擎。它天然依赖积累，本该是**一面镜子**：价值随时间和课题数量增长，不承担「推动学习」的职责。推动学习的始终是一个明确的方向，也就是项目的初衷。

另一个让图谱长得慢的原因：图谱只收卡片，而实际的主要产出在文章和项目里，图谱一直「吃不饱」。按 §2.1 让文章和项目文档的观点进入图谱，雷达才看得见真实的积累。

**两者是同一条流在不同时间尺度上的样子**：每一次自上而下的课题，都会留下一批观点；许多课题留下的观点，彼此连接，自下而上地聚成主题。项目是一次次远征，图谱是远征之后留下的版图。

### 2.3 两个方向的接口

融合不靠让用户在两种方式之间切换，而靠两个方向互相转换的动作：

**上 → 下：课题的产出进入版图**

- 项目、VL、文章里写下的观点**自动**进入图谱与 AI 洞见的范围，不要求手动抽成卡片（依赖 §2.1）。
- 在课题内部，「脉络」（§5）展示课题内容与**课题之外**旧知识的连接：「这一段和你两年前在另一个项目里写的观点呼应」。新课题由此接上旧体系。
- **回顾**：课题对版图的正式交付，按项目的两种形态（见下文「两种项目」）分为结项回顾与生长回顾。

**下 → 上：版图提示下一个方向**

- 雷达发现的空白、矛盾、追问，变成问题（§4.3）。
- **以此立项**：图谱里某个主题积累了很多观点却从未系统整理过，或某个问题攒了足够多的材料，提示「以此立项」，升级为项目或 VL 课题，带上已有的观点与材料。自下而上的积累由此变成下一次主动的方向。

```
     方向（问题 / 主题）──立项──▶ 课题（项目 / VL）──主动收集、产出观点
           ▲                                     │
           │ 空白、矛盾、成熟的主题                │ 观点自动进入版图；回顾        
           │                                     ▼
           └─────────────── 版图（图谱 + AI 洞见）◀┘
```

**两种项目**

项目有两种形态，同一个项目也可能从前者长成后者：

|          | 探索课题                       | 体系项目                                   |
| -------- | ------------------------------ | ------------------------------------------ |
| 是什么   | 弄清一个问题，探索完就结束     | 一个领域的知识体系，持续生长               |
| 终点     | 有：结项（即现有的归档）       | 没有                                       |
| 回顾     | **结项回顾**：一次性。产生了哪些核心观点（可选抽成卡片）、与已有体系连上了哪里、留下哪些没解决的问题（转入问题模块）、可以沉淀进哪个体系项目 | **生长回顾**：按变化量触发（不按日历）。最近长出了什么、新连上了哪里、结构里哪些部分还薄 |
| 与版图   | 交付一批观点后退场             | 版图中这个领域的**显式结构**，与图谱主题对齐 |

- **不在创建时选类型**：项目默认在生长；只有用户归档时才视为结项、触发结项回顾。不新增字段，归档沿用 `project.archived`。
- **探索课题汇入体系**：结项回顾可以建议「把这个课题的结论归入体系项目 X」，体系项目由此吸收一次次探索。
- **体系项目吸收散落的观点**：图谱里语义上属于这个体系、却散落在卡片或别的文章里的观点，提示为「可能属于这里」，由用户决定是否引用或归入。这是自下而上的积累反哺自上而下的结构。

### 2.4 知识体系由什么构成

知识体系 = 观点 + 两种结构 + 观点之间的连接。

- **两种结构并存**：项目目录与文章大纲是用户给的结构；图谱主题是涌现的结构。系统可以帮它们对齐，例如「图谱里这个主题的观点和项目 X 高度重合」。
- 不要求用户把涌现的主题「整理成」项目，也不要求项目内容「拆回」卡片；需要时由 §2.3 的两个动作转换。

### 2.5 卡片的角色：连接的枢纽，而不是唯一的入口

卡片仍然重要，但不再要求「先拆卡片再写文章」。**原子化渐进、事后、按需发生**：某一段观点有了跨文章、跨项目复用的价值时，才值得抽成卡片。触发时机：

- 在别处想引用文章的某一段；
- AI 发现这一段和另一个领域的内容有碰撞（相关、矛盾、呼应）；
- 写完一篇长文后，可选地请 AI 列出核心观点，挑几条抽出。

抽出的卡片通过谱系（§4.2）记住它来自哪篇文章的哪一段。

### 2.6 「我的思考」「外部材料」与「思考轨迹」

| 类别     | 包括                                           | 在体系中的位置                                 |
| -------- | ---------------------------------------------- | ---------------------------------------------- |
| 我的思考 | 卡片、文章、项目文档、日记、问题的答案         | 知识体系本身                                   |
| 外部材料 | 剪藏网页、书和划线、PDF 和标注、视频、插件划线 | 挂在体系边上，作为观点的来源与证据             |
| 思考轨迹 | 与 AI 的对话                                   | 不是节点，是方向信号与探究过程（见 §3.2）      |

文章是「我的思考」，**不是材料**。

### 2.7 疑问是闭环的发动机

学习会产生疑问，疑问长成课题，课题带来新材料和答案，答案回到体系，体系又暴露出新的空白。产品里已有的「问题」模块（待探究 → 探究中 → 已解答，可挂材料）应当成为这个闭环的**枢纽**，而不是一个孤立的列表。

## 3. 知识闭环

```
   外部材料 ──摘录──▶ 摘录 ──消化──▶ 我的思考 ──连接──▶ 知识体系
 (网页/书/PDF/视频)                (卡片/文章/项目)           │
       ▲                                                   │ 空白、矛盾、疑惑
       │                                                   ▼
       └── 收集资料 ◀── 探究（VL 课题）◀── 升级 ◀────── 疑问（问题）
                            │
                            └── 得出答案 ──▶ 回到我的思考
```

模块是这条线上的**地点**，不是阶段本身：

| 阶段 | 发生在哪些模块                                   | 产出                       |
| ---- | ------------------------------------------------ | -------------------------- |
| 摘录 | 剪藏、浏览器插件、微信读书、PDF 标注、视频笔记   | 带来源的一段原文           |
| 消化 | 对话、写卡片 / 文章 / 项目文档、VL 学习          | 观点                       |
| 连接 | 链接、引用、图谱、AI 洞见                        | 知识体系                   |
| 疑问 | 任何地方都可能产生                               | 问题                       |
| 探究 | 问题、VL 项目                                    | 答案、新的观点、新的材料   |

### 3.1 VL 在闭环里的位置

VL 项目是**一个课题的探究空间**：围绕一个疑问收集资料、在其中研究、沉淀产物。

- VL 项目**可以**由问题升级而来（带着问题已挂的材料进入），但不要求必须如此，也可以直接新建。
- VL 里产生的新疑问，回到问题模块。
- VL 的产物（笔记、大纲等）沉淀为卡片或文章，带谱系回到体系。
- VL 引用了主库里的笔记作为资料时，被引用的笔记那边要能看到「被哪个学习项目使用」。

### 3.2 对话在闭环里的位置

对话是第三类内容：**过程**，不是产物。一次对话里两种声音的性质不同：

- **我的提问 = 思考方向**。主动问 AI 的东西，就是此刻的疑问与关注点，是最直接的「意图信号」。
- **AI 的回答 = 一种外部材料**。它是另一个声音，不是我的思考；经我消化、写成卡片或文章，才进入体系。

因此对话不作为知识地图的节点，而在闭环里承担四个角色：

| 角色             | 怎么联动                                                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 疑问的显性化     | 一次对话可以关联到问题（问题的探究轨迹里出现这次对话），或一键从对话生成问题。问题模块的「探究中」由此有了真实的过程记录                       |
| 消化的场所       | 回答或自己的总结可以存为卡片 / 文章，谱系记到对话的那一条消息（§4.2）                                                                          |
| 方向信号（雷达） | 「问了但没写」：最近反复在对话里问某个主题，体系里却几乎没有相关的观点，提示写一张卡、建一个问题，或「以此立项」；对话里反复引用的卡片是「活跃知识」 |
| 从体系发起       | 从脉络、阅读时标记、知识地图点「继续聊」，对话带着当前上下文开始，并记住它从哪发起；该实体的脉络里出现「围绕它的对话」                         |

边界：

- 只把**我的提问**当作方向信号参与 AI 分析；AI 回答不参与雷达统计，避免 AI 自己的话被当成我的关注点。
- 浏览器插件的对话跟着网页走、不随库同步，归入该网页的摘录与来源，不进入雷达。
- 对话能被指向到**单条消息**（会话文件里每条消息已有 id），地址形如 `{kind: chat-session, id, messageId}`。

## 4. 四块共用的底层能力

联动不在每两个模块之间各打一个通道（N 个模块就是 N² 个通道），而是**所有模块共用同一套能力**。

### 4.1 统一引用：一切皆可被指向，最好能指到段落

- **目标**：任何实体都有统一地址，可以被链接、被聊天 `@`、被挂成问题的材料、被 VL 引用。长文要能指到段落。
- **现状**：内联引用、向量索引、聊天 `@` 只覆盖卡片、文章、项目文档、日记四类；没有通用的反向链接；主库向量按段落切块，但 `prefixed_id` 只到实体，没有块序号。
- **要补**：
  - 通用的反向链接（谁引用了我）；
  - 剪藏、划线、PDF 标注、VL 产物、问题纳入统一地址；
  - 段内地址：系统内部用引述锚点（引文 + 前后文）；只有用户主动「引用这一段」才生成独立的 `anchorId`，与协作层的 `collabId` 无关（KL-013、KL-017）。语义单元按「节」而不是段落（KL-016）。见 02 §3.3。

### 4.2 谱系：衍生物记得自己从哪来

- **目标**：每次衍生自动记一条「派生自」关系：摘录 → 卡片、文章段落 → 卡片、卡片 → 闪卡、对话回答 → 卡片、矛盾 → 问题、问题 → VL 项目、VL 产物 → 卡片。
- **价值**：这类连接是操作的副产品，**零成本、完全准确**，是「看到关联」里最直观的一种。
- **现状**：`cards` 没有来源字段；`flashcard_references` 只存正文 id；「转为卡片」各处各写一份，不记来源。
- **要补**：一份统一的派生关系（来源实体与位置、衍生实体、动作、时间），所有「转为 / 存为 / 生成」的入口都经它写入。

### 4.3 问题作为枢纽

- **任何地方都能一键「变成问题」并带上材料**：阅读时的疑惑、AI 发现的矛盾与空白、对话中的追问、测验或闪卡答错的题。
- **问题可以升级为 VL 课题**，材料随之带入。
- **答案回流**：已解答的问题，答案可以抽成卡片（已有 `buildCardFromContent`），带谱系。
- **反查**：任何实体都能看到自己是哪些问题的材料（接口 `listQuestionsByTarget` 已有，未接界面）。

### 4.4 语义连接：AI 洞见

前三块是**事实连接**（谁引用谁、谁来自谁），AI 洞见补上**意义连接**：

| 关系 | 说明                                       |
| ---- | ------------------------------------------ |
| 相关 | 在说相关的事，但还没有连接                 |
| 呼应 | 同一个道理，在完全不同的领域又出现了一次   |
| 矛盾 | 主张互相冲突                               |
| 追问 | 下了结论，但没写为什么、什么条件下不成立   |
| 空白 | 某个主题反复提到、却没有展开的概念         |

原则：

- **覆盖所有阅读与编辑的内容**：卡片、文章、项目文档、剪藏网页等。依赖 §4.1 的统一引用；长文按节作为语义单元，标记的定位用引述锚点。
- **目的是发现连接、激发思考、促成建立连接**，最终生长出知识体系。所以洞见的产出要**落到前三块**：变成一条链接、抽出一张卡片，或者变成一个问题。
- **默认给问题而不是答案**：提示用户去想，可以一键展开看 AI 的看法。
- **出现在阅读时**：读到某一段，旁边出现很淡的标记，点开就地展开（类似微信读书的想法），需要深入时到侧边栏对话。图谱上的主题级洞见放到最后做。
- **不打扰，可关闭**：落地前先出设计，回答「如何不打扰」（数量上限、出现时机、视觉强度）和「在哪关闭」（全局、按模块、单条忽略）。
- 卡片 AI 元信息（原 ai-insights §3）保留，是语义连接的基础，应扩展到所有「我的思考」类实体。

## 5. 看得见的联动：「脉络」面板

所有实体的详情页挂**同一个**组件，回答「这个东西和别的东西有什么关系」：

```
脉络
  来源   ← 摘自《XXX》第 3 章划线
  衍生   → 2 张闪卡 · 1 张卡片
  引用   ↔ 被 3 篇文档引用 · 引用了 2 张卡
  问题   ？ 是「为什么 X」的材料 · 被 VL 项目「Y」使用
  相关   ✦ 与《Z》第 2 段观点相反（AI，淡色，可关闭）
```

- 前四行来自 §4.1 到 §4.3，**不需要 AI**。
- 「相关」一行来自 §4.4。
- 长文里，脉络也可以按段落展开：当前段落的引用、来源与 AI 标记。
- 形态（侧栏、底部区、悬浮）待设计。

### 5.1 全局版图与局部关系

图谱是 §2.2 里的「雷达」，回答的是「我的整个知识积累长什么样」，属于**全局视角**，不应挂在卡片库下面。

- **全局：知识地图**是一个独立的大页面（`features/<域>/pages/` 下 definePage）。范围是所有「我的思考」类内容：卡片、文章、项目文档，后续是段落级观点；外部材料默认不作为节点。支持按类型、项目、标签筛选，「只看卡片」就是其中一个筛选。
- **入口在标题栏，不进侧边栏**：知识地图是卡片、文章、项目合起来的样子，比侧边栏条目高一层，范围也跨出了「知识」分组。入口与 AI 对话开关并列放在标题栏，和搜索、AI 一样是全局的。
  - **带上下文打开**：在某张卡或某篇文章里点击，地图以当前内容为中心打开（「我在版图的哪里」）；在没有具体内容的页面点击，打开全局。这是放在标题栏而不是侧边栏的主要理由，和 AI 对话会带上当前上下文是同一种逻辑。
  - 与 AI 对话不同，它打开的是页面而不是停靠栏：经 `navigator.push` 入栈，后退回到原处；地图在栈顶时按钮显示选中态。
  - Ctrl+K 命令面板里也能打开。
  - 落地时属于壳层行为变更，要在 DECISIONS.md 记录并同步 03 指南。
- **局部：脉络里的关系图**。某张卡、某篇文章的一跳、两跳邻居，作为「脉络」（§5）的一种展开形态，回答「这个东西周围有什么」。
- **卡片库**不再内嵌全局图谱，改为跳转到「知识地图（只看卡片）」或以某张卡为中心打开。
- **独立的时机**：图谱独立的同时，范围要扩展到文章与项目文档，否则只是换了个位置的卡片图谱。第一步按**整篇粒度**纳入：反向链接（§4.1）提供文章、项目文档之间的显式边，主库向量已经覆盖这几类内容，可以按实体聚合出语义近邻。段落级节点等第 6 步。
- 现状：图谱是卡片库里的一个区块（`apps/desktop/src/features/cards/components/CardGraphSection.tsx`），计算在 `apps/desktop/src/knowledge-map/` 与主进程 `knowledge-map-builder.ts`，结果表以 `card_id` 为主键，扩展范围要改节点身份。

## 7. 推进顺序

每一步单独就能让用户感到联动，后一步建立在前一步上：

1. **反向链接与「脉络」第一版**：补通用反向链接，接上问题反查，在卡片、文章、项目文档详情挂「脉络」（来源、引用、问题）。
2. **知识地图独立**：从卡片库摘出为全局页面，范围扩展到文章与项目文档（整篇粒度），见 §5.1。
3. **谱系**：统一的派生关系；所有「转为 / 存为 / 生成」入口改为经它写入；补齐已断的入口（回答存为卡片、对话生成闪卡）。
4. **摘录入库**：插件划线、微信读书划线、PDF 标注、剪藏网页变成可引用的行级数据，进入向量索引。这是 AI 洞见覆盖所有阅读内容的前提。
5. **问题枢纽与立项**：各处一键转为问题；问题或主题「以此立项」升级为项目 / VL 课题；答案回流成卡片。
6. **长文的节级观点与渐进原子化**：长文按节建语义单元；引述锚点；「抽成卡片」带谱系；知识地图细化到节级观点；用户主动的段落引用（`anchorId`）放在最后。
7. **AI 洞见**：元信息 → 阅读时的环境提示（先出设计）→「脉络」的「相关」行 → 结项回顾与生长回顾、体系项目的「可能属于这里」→ 知识地图上的主题级洞见与立项提示。

第 6 步可以与第 4、5 步并行做技术方案，因为它决定 AI 洞见与知识地图在长文上能做到多细。

## 8. 待讨论

- **抽出的卡片与原段落的关系**：复制 + 谱系（简单，之后两边各自演化），还是同一份内容的双向引用（一处改、处处变，复杂度高）。倾向先做前者。
- **图谱扩展到文章段落后如何呈现**：文章作为容器节点、段落作为子节点？规模会显著增加，需要按万级重新评估。
- **统一标签**：卡片、文章、项目文档、PDF、闪卡的标签各自独立，主题命名依赖标签，是否收敛为一套。
- **「脉络」面板的形态与位置**。
- **移动端**：谱系与反向链接涉及主库 schema，移动端至少要能容忍；是否在移动端展示「脉络」。
