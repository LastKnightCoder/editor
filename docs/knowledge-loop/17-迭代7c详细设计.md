## 0. 一句话与原则

**7b 是「这一篇在我的知识里的位置」，7c 是「我的知识整体长什么样、哪里意外地连着、哪里缺了」。** 同样是点一下 → AI 读（你看得见）→ 一处处画出来 → 一处一个气泡、最多两个按钮 → Esc 恢复。画的地方从正文换成了知识地图和项目树。

- **平时什么都不出现**：地图、项目树和现在一样；有还没看的发现时，只在按钮旁边一个很小的点（同 7b）。
- **唯一的主动落点是今日页一张「洞见」卡**，一次只说一件事。
- **AI 判断，本地只给宽候选**（ai-insights §5.1）。没配模型时入口不出现，不提供只靠向量的简化版。
- **产出只有连接与问题**（KL-052）：连接由你确认，落成卡片双向链接或 content-link；问题走命令面板记问题模式。不生成卡片、文章、闪卡。同一思路是观察，只有「知道了」，不产出（KL-068）。

## 2. 现状调研

### 2.1 知识地图（索引库，可重建）

- `knowledge_map_nodes(node_key, x, y, topic, subtopic, update_time)` + `knowledge_map_topics(id, parent, label, color_slot, size)`，两层：大主题（`parent = -1`）与子主题。`tables/knowledge-map.ts` 负责 IO，`knowledge-map-builder.ts` 在 worker 里整体重算。
- **主题编号每次整体重算按规模重排，不能当身份**；主题名来自 tag（项目文档无 tag 时用「项目 / 顶层文档」，KL-020），不是 AI 起的。
- **地图只在打开地图页时对账与重算**（`knowledge-map:get`）：新节点按近邻增量落位，漂移（增量放置 ∪ 编辑过的节点）超过 `REBUILD_DRIFT_RATIO` 或嵌入指纹变化才后台整体重算。用户不打开地图，主题就不更新。
- 渲染端 `features/knowledge-map/`（页面、筛选、生长动画里程碑）+ `components/LinkGraph/`（自研 canvas，`mapScene.ts` 把主题翻成簇、子主题标签在中等缩放下出现）。地图上没有 DOM 覆盖层，标记要画在地图上需要新增一层与相机同步的覆盖层。

### 2.2 元信息与 7b 可复用的部分

- 主库 `content_ai_meta.meta = { title, summary, concepts[], claims[] }`（7a）。**真实库还没有生成**，评估前要在副本上补（全库约 26 万 token / 千份）。

## 3. 交互全流程

### 3.1 知识地图的洞见视图

**入口**：地图页标题行右侧「✦ AI 洞见」（位置同 7b 的元信息行按钮）。有还没看的发现时按钮旁一个小点，不显示数字。槽没配时不出现。

**读**（概述都是新的时约 3–5 秒；第一次或有过时的主题时更久，见 §4.7）：

- 按钮变「正在读」并转圈；地图节点变浅，**一道淡光从左往右扫过地图**。
- 标题下一行说它此刻真实在做什么：「按主题读 1,298 条笔记的要点（读过的跳过），对照 19 个主题之间 24 组可能有关的笔记…」→「AI 正在判断哪些值得告诉你…」。不做假进度条。可以取消。

**点亮（全局层）**：

1. **报告卡**从地图右侧展开成一条 300px 的侧栏（2026-10-04 用户反馈：放在标题下太占地图高度）：版图两三句（多大、最近长在哪、哪里停了、AI 看到了几处什么）；数量签（呼应 2 · 问了没写 1 · 有发现的主题 3，类型签点击跳到第一处；「有发现的主题」点开是菜单，列出各主题还剩几处、按多到少排，选哪个飞进哪个）；逐条看按钮；下方一张**生长条**（每季度新写的笔记，最近四季着色）——「知识体系在怎样生长」最直接的图；≤ 1 个可以继续想的问题。
2. **地图上按顺序画出**（每处约 0.3 秒，全局层 ≤ 5 处）：
   - **呼应**：两个主题里各一个节点之间，一条蓝色弧线从一端画到另一端，两端节点亮起；
   - **问了但没写**：在它该属于的主题边上一个虚线圈「?」，轻轻呼吸。
   - 有主题层发现的主题，名字后一个小点。

**主题层**：点有小点的主题名 → 镜头飞进这个主题（其他主题降淡，子主题标签出现），报告卡淡入换成这个主题的：关注点变化（「早期写语法细节，最近一年转向运行时机制」）、反复使用的思路、生长条换成这个主题的、≤ 2 个问题；体量大却没有项目整理过的主题，报告里说一句（不给按钮，J11）。主题里画出（≤ 6 处）：

| 关系         | 画法                                 | 在哪                 |
| ------------ | ------------------------------------ | -------------------- |
| 重复         | 灰色点线                             | 两个节点之间         |
| 矛盾         | 红色波浪线                           | 两个节点之间         |
| 缺一环       | 几段实线串起一条链，中间一个虚线空位 | 链上的节点           |
| 同一思路     | 3–5 个节点各起一个淡紫色圈，依次出现 | 用了同一种思路的节点 |
| 还缺（空白） | 主题名下一行淡注「＋ 还缺：……」      | 主题标签下           |

报告卡顶部一行「全部主题 › JavaScript」，点「全部主题」飞回全局；还有别的有发现的主题时，主题名是同样的菜单，不回全局也能直接换主题。

**处理**：点标记 → 其余标记降淡，涉及的每篇笔记加一圈强调、旁边标出标题，镜头在它们不在视口里时拉远到都看得见（不拉近）；气泡开头一句直白说出这一处是什么（如「从《A》到《B》之间少了「X」」），下面一行 AI 的理由 + 对方是谁，最多两个按钮（悬停说明会做什么）：

| 关系       | 气泡里                                                 | 主按钮                                                                                 |
| ---------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 呼应、重复 | 两端并排：主题 › 标题 + 要点 / 片段                    | 两端都是卡片：**连接**（双向链接，弧线变成灰色实线）；有一端是长文：**去连接**（§3.4） |
| 矛盾       | 两端并排的两句主张                                     | **记为问题**                                                                           |
| 缺一环     | 链：调用栈 → 任务队列 → **？** → requestAnimationFrame | **记为问题**                                                                           |
| 同一思路   | 用在了哪几处                                           | **知道了**（观察，看见即可，不记问题；KL-068）                                         |
| 还缺       | 为什么说缺                                             | **记为问题**                                                                           |
| 问了但没写 | 你问过的几次（日期 + 原话）                            | **记为问题**（来源为那几次对话）                                                       |

都有 **不相关**：标记淡出，以后重算也不再出现。**逐条看**、数量签跳转、`↑↓ 回车 ⌫ Esc` 与 7b 完全一致。

**退出**：Esc 按层退：气泡 → 逐条看 → 主题层回到全局 → 退出视图（标记淡出、报告卡收起、镜头复位）。再点按钮也退出。视图里地图照常可拖动缩放，点普通节点在右侧 Drawer 预览，不退出视图；Esc 先关 Drawer。

### 3.2 今日页「洞见」卡

- 位置：「继续」段的第一块，一行高的卡：「✦ 洞见 · AI 从你的知识版图里看到的 · ‹ 1 / 4 ›」。**一次只说一件事**，关键的几个字下面画一道线（呼应蓝、问了没写黄、回顾 accent）。
- 两个按钮：**去看看**（呼应 / 问了没写 / 主题发现 → 打开地图并直接进入洞见视图，镜头对准那一处、画出来、弹出气泡；回顾 → 打开项目并展开回顾）、**不相关**（同气泡里的不相关；回顾条目叫「知道了」）。
- 内容：还没处理的发现，按「刚结项的回顾 > 呼应 > 问了没写 > 生长回顾 > 主题层发现」排，最多 5 条；什么都没有时整块不出现。
- 不推送通知，不在别处出现。

### 3.3 项目回顾

项目树上方，项目名右边「✦ 回顾」（归档的项目叫「结项回顾」），有还没看的回顾时带小点。点开：一道光从上往下扫过树 → 右侧当前文档上方展开报告卡（同 7b 的报告卡，右边是会长的小关系图：中间是这个项目，线是项目外连着的笔记）。

**生长回顾**（未归档）：

- 报告：自上次回顾以来长了什么、新连上了哪里、结构里哪些还薄；≤ 2 个问题。
- **可能属于这里**：项目外语义上属于某一支、却散在卡片库或别的文章里的笔记，以**虚线行**一行行长进树里那一支下面（≤ 3 行）。点开气泡：为什么属于这里 + 内容预览；按钮 **引用到这里**（在那一支下加引用型条目，虚线变实线、小图多一条线）/ 不相关。
- **还薄**：树里那一支下面一行淡注「＋ 这里还薄：……」，气泡里记为问题。

**结项回顾**（归档触发）：

- 归档后后台写回顾（约 5 秒），写好后今日卡出现一条，项目页按钮带小点。
- 报告：这个课题留下了哪几个核心观点（点标题打开）、和已有体系连上了哪里、**还没解决的问题**（每条悬停出「记为问题」，来源为本项目）、内容和哪个体系项目重合最多、可以归进去（一句话，项目名可点开；不替你移动或复制）。

### 3.4 主题层发现落到长文：「去连接」

呼应、重复有一端是文章或项目文档时，在地图上不能直接连（没有可以挂链接的那几个字）。分析时 AI 已经从那篇的命中节里选出原文片段（逐字校验，同 7b）：

- 点「去连接」→ 打开那篇、定位到那一节，**正文直接进入 7b 洞见视图，但只画这一处**并弹出同样的气泡（理由、对方、两段原文）；点「连接」把那几个字包成 content-link。处理结果回写到地图那一条。
- 片段校验没通过（正文已改）时按钮变成「打开看看」，不连。
- 这不是新形态，是 7b 视图的一个入口参数；文档本身的洞见结果（`content_ai_insights`）不动。

### 3.5 什么时候出现小点

| 位置              | 条件                                                           |
| ----------------- | -------------------------------------------------------------- |
| 地图「✦ AI 洞见」 | 全局层或任一主题层有还没处理、且你还没在视图里看过的发现       |
| 项目「✦ 回顾」    | 有还没打开过的回顾                                             |
| 今日卡            | 有还没处理的发现（看过但没处理的也算，处理或「不相关」后消失） |

## 4. 分析怎么做

### 4.1 本地与 AI 的分工（ai-insights §5.1 / §5.2）

| 洞见                    | 本地（不花 token，宽）                                                                                   | AI                                                                                |
| ----------------------- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 子主题概述、模式        | 成员元信息按创建时间排好，带月份；成员间已有的显式链接                                                   | 概述；关注点变化；同一思路；论证链与缺的一环                                      |
| 重复 / 矛盾             | 子主题内语义近邻对（高于随机块对 p95，不排除同项目），且至少一边有主张；每个子主题前 20 对               | 比较两边的要点与主张，判断重复 / 矛盾 / 都不是                                    |
| 还缺（空白）            | 不做本地统计（理由见 ai-insights §5.2）                                                                  | 读主题概述 + 各成员概念，判断缺了什么                                             |
| 呼应（桥接）            | 跨主题、没有连接、相似度高于阈值的笔记对，每两个主题最多 3 对，全库前 30 对；带两边命中节文字            | 读两个主题的概述 + 这几对，判断是否「同一个道理」、写一句理由，长文一侧给原文片段 |
| 问了但没写              | 用户提问向量：离所有笔记都不近（最近笔记块的相似度低于阈值）、彼此相近的成组；按组大小与最近程度前 15 组 | 判断是否真的没写、值不值得写，写成一个问题                                        |
| 生长                    | 每季度新写数（事实，直接画生长条）                                                                       | 用一句话说它在怎样长                                                              |
| 生长回顾 / 可能属于这里 | 自上次回顾以来新增 / 改过的文档；项目外笔记对项目各顶层分支的近邻（排除已在项目里或已连的），前 16 个    | 写回顾；判断哪些真的属于哪一支（≤ 3）                                             |
| 结项回顾                | 项目文档元信息、项目内外的已有连接、相关的未解决问题、与它重合最多的 3 个未归档项目                      | 写回顾：核心观点、连上了哪里、没解决的、可以归进哪里                              |

### 4.2 三层调用

| 子主题 | 成员元信息（≤ 80 份：有主张的、最近的、链接多的优先；超出只进候选对）+ 重复 / 矛盾候选对 + 成员间已有链接 | `overview`（≤ 150 字）、`shift`（关注点变化，可空）、`patterns`（同一思路 ≤ 1）、`chains`（缺一环 ≤ 1）、`pairs`（重复 / 矛盾 ≤ 3） | 72             |
| 主题   | 子主题概述 + 各成员概念 + 生长数字                                                                        | `overview`、`lead`（报告两三句）、`gaps`（≤ 2）、`asks`（≤ 2），并从子主题结果里挑出这一层要画的 ≤ 6 处                             | 19             |
| 全局   | 各主题概述 + 生长数字 + 呼应候选 + 问了没写候选                                                           | `lead`、`bridges`（≤ 3）、`asked`（≤ 2）、`asks`（≤ 1）                                                                             | 1              |

- 一律 `thinking: "off"`，输出逐条校验：节点必须在候选 / 成员里，长文片段逐字落在那一节（复用 `content-insights-prompt.ts` 的校验），不合格的丢弃；输出不是 JSON 时同样的请求再试一次（7b 已有）。
- 提示词写明「宁缺毋滥，没有值得说的就少给或不给」——mockup 里「CSS」「学习方法」都只有一两处。

### 4.3 主题身份与变化量

- **身份**：每个子主题 / 主题的结果行有自己的 id，存**成员快照**（`[contentId, 元信息指纹]`）。地图整体重算后，按成员 Jaccard 把新主题对到旧行：≥ 0.7 继承（当作一次成员变化）；拆分、合并、新出现的重写；对不上的删除（ai-insights §6.3）。
- **三档**（ai-insights §6.2）：变化量 = 新增、移除、元信息重新生成过的成员数 / 原成员数。< 10% 保留不动；10%–40% 增量改写（旧概述 + 变化部分）；≥ 40% 或已连续增量 3 次，从成员完整重写。子主题重写才往上传给主题；任一主题重写，全局最多每 6 小时重写一次。
- **已处理状态继承**：重算时按「类型 + 两端正文」继承 linked / questioned / dismissed；不相关的以后不再出现。主题拆并时随成员对应一起继承。

### 4.4 调度

- 主进程 BACKGROUND 模块 `topic-insights`（依赖 database、pi-ai、knowledge-map-builder、content-ai-queue）。串行、切库作废、输出解析失败重试 1 次（请求失败不重试）、连续 3 次失败停本轮（每次调用比元信息贵，见 §11）。
- **什么时候跑**：元信息队列空闲、且元信息覆盖率 ≥ 80% 时（概述读的是元信息，覆盖太低读出来是偏的）；连库后、元信息写入静置后、地图重算后检查一次变化量。地图过时的话它先请地图模块对账 / 重算（不再只在打开地图页时）。
- **用户在等时插队**：点「✦ AI 洞见」时，过时的主题先算；概述都新的话只跑全局一次（或直接读结果）。
- 结项回顾：归档即入队；生长回顾：项目文档的变化量 ≥ 30% 或新增 ≥ 5 篇、且距上次回顾 ≥ 7 天才自动写，第一次只在你点「回顾」时写。
- 问了但没写：随全局调用一起。

### 4.5 对话入索引（02 §5.5）

- 只取 `chat_session.scope = 'main-chat'` 会话里的**用户消息**，AI 回答、工具结果不入；太短的（< 6 个字）跳过。
- 写进索引库向量 `vec_documents`：`type = 'chat-prompt'`，`prefixed_id = chat-prompt:<sessionId>#<messageId>`，`content` 是消息原文。由主库向量编排按会话文件的修改时间对账（新增 / 删除会话），嵌入模型与笔记相同；嵌入指纹变化时一起重建。
- 不进全文搜索、不进脉络、不进知识地图（KL-006：对话不是节点）；命令面板与 `search_knowledge` 的类型白名单不变。
- 「记为问题」的来源：最近一次提问所在的对话 + 消息 id；其余几次的会话一并挂为探究对话（`question_chat`，需要把记问题来源扩成可带多个会话）。

### 4.6 可能属于这里的「引用到这里」

在那一支下加一个引用型条目（与在项目里手动添加已有卡片 / 文章同一条路径），不复制、不移动；卡片与文章都可以。项目文档（别的项目里的）不给这个动作，只能「打开看看」。

### 4.7 token 与等待

按元信息每份约 150 token 估算（7a 实测）：

| 项               | 真实库（1,298 节点 / 72 子主题）           | 重度库（2.3 万节点、约 1,000 子主题） |
| ---------------- | ------------------------------------------ | ------------------------------------- |
| 首轮（三层全部） | 输入约 30 万 / 输出约 5 万                 | 输入约 400 万 / 输出约 60 万          |
| 之后             | 多数编辑停在第 1 档；一个子主题增量约 3 千 | 同左                                  |
| 结项回顾         | 每个约 5 千                                | 同左                                  |
| 生长回顾         | 每个约 5 千，频率受 ≥ 7 天限制             | 同左                                  |

- 首轮与元信息首轮同一量级（7a 真实库约 83 万）。重度库首轮可能跑数小时，后台进行，进度在设置页那一行。
- 点按钮时：概述都新时只等一次全局调用（deepseek-flash 预计 3–5 秒）；有过时的主题时先算那几个，读的阶段说明会写「还有 3 个主题要重新读」。

## 11. 实现与设计的差异

- **对话提问的 id 是字符串**（第 2 步）：向量表的写入辅助原先只收数字 id，改为 `number | string`（`VecIndexParams`），检索路径只认白名单类型，不受影响；不限类型的向量检索与 `getAllVecDocumentResults` 显式排除 `chat-prompt`，否则提问会占掉近邻名额（结果虽然会被丢掉）。提问不进覆盖率统计，所以设置页的「索引覆盖」不变。
- **提问随向量队列补索引**：会话行在每轮结束时更新，`chat-session:update` / `delete` 进了索引写事件白名单；本地模型空闲 2 分钟后补，远程模型在连库 / 手动建索引时补（与笔记一致）。
- **元信息少于 3 份的子主题不单独调用**（第 3 步）：只计入主题的数量，免得为两三张卡花一次调用；主题内没有细分的成员归为「其他」组。
- **增量改写**：提示词里只放新增或改过的成员 + 上一次的概述与还开着的发现；上一次的发现两端都没变的原样保留，再与新发现合并去重（子主题最多 5 条）。变化很小（第 1 档）时不更新成员快照，变化量一直累计到上一次生成时。
- **主题层的标记是从子主题的发现里挑的副本**：处理状态记在主题行上（地图上看到的是主题行），不相关的身份带到以后，子主题重新生成后再被挑中也不出现。
- **地图后台也会更新**：`knowledge-map-builder.ensureFresh` 在主题洞见跑之前对账，过时就整体重算并等它算完（原来只在打开地图页时更新）。
- **调用失败**：后台一轮里连续 3 次失败停止本轮（设计写 5 次：这里每次调用都比元信息贵）；点按钮时第一次失败就报错。
- **结项回顾只自动补写最近 30 天内归档的项目**（第 4 步）：主进程没有归档事件，按「已归档、没有结项回顾、项目 30 天内改过」判断；功能刚开启时不给很久以前归档的项目补写一批（今日卡会被旧课题占满）。项目一改（`update-project` 写事件）半分钟后检查一次，归档后很快就能看到。
- **「归入」候选不按块阈值筛**：项目整体向量是很多篇的均值，和别的项目的相似度天然比单节之间低；取最接近的 3 个进行中项目（至少 3 份文档）交给模型判断。
- **「可能属于这里」只提卡片与文章**：别的项目里的文档不该被挪进来，也不给它们动作。
- **调度与 IPC 在 `knowledge-insights-module.ts`**：主题引擎 `topic-insights.ts` 与项目回顾 `project-review.ts` 共用助手函数，放在一起会循环引用。
- **地图覆盖层（第 6 步）**：LinkGraph 不碰业务，只加了 `overlay`（叠在画布上的宿主内容）与 `overlayRef`（`GraphOverlayApi`：每帧回调、按条目 key / 地图主题 id 换算画布坐标、飞到主题、飞回全图）；簇几何抽成 `core/clusterGeometry.ts`，渲染器与覆盖层共用。标记由知识地图页的 `insights/` 画，每帧（平移、缩放、飞行后）重新算一遍坐标；线条用 `pathLength="1"` 按比例画出，不依赖实际长度。
- **主题名的点击区按名字长度估算**：主题名是画布画的，覆盖层在名字位置放一个透明按钮（宽 ≈ 字数 × 15px），名字后是那个小点。
- **读的时候地图节点不变浅**（设计写了变浅）：只有一道光横扫地图与阶段说明。节点变浅要动画布渲染的状态，收益小。
- **卡片之间的「连接」走主进程**（`knowledge-insights:link-cards`）：一个事务写两张卡的双向链接，再广播 `card:updated` 并补发写事件；卡片域原有的连接逻辑在卡片域的 store 里，地图域不能引用。
- **「去连接」这一步先打开那篇、定位到那一节**；在那篇里只画这一处、就地连接放在第 7 步。
- **记问题的来源扩成多种**（原计划第 7 步，提前做）：多份材料（缺一环、重复与矛盾两端；同一思路后来改为「知道了」，KL-068）、多段对话（问了没写按会话合并，各挂成探究对话）、无来源（主题里还缺的那一块，来源 chip 显示主题名，建问题时不挂材料）。
- **问了没写画在它最接近的主题岛右上沿**；对不上地图上的主题时不画，逐条看与数量签仍能打开它。
- **呼应**：用户还没决定（17 §12.2 的三个选项），界面照现在的数据画，选项落地时只改数据来源或过滤。
- **「看过」（第 7 步）**：设计只说回顾「有还没打开过的」时带小点；实现为结果里的 `seenAt`（`knowledge-insights:seen`，不动生成时间，重新生成后清空）。打开回顾、今日卡点「知道了」都记为看过。
- **今日卡的数据由首页域自己取**（`features/home/insightQueries.ts`，与知识地图同一个缓存键）：首页域不引用地图域的数据钩子。
- **去连接经 `services/insight-focus.ts`**：地图登记「这一篇要画的那一处」再打开文档；详情页的洞见视图取走它，只画这一处、不显示报告卡；连接 / 不相关回写到地图那一条（记为问题不回写——问题本身就是处理）。长文那一端没有核对过的原文片段时，按钮叫「打开看看」，只打开不登记。
- **项目回顾没有逐条看**，「读」的时候也没有扫过文档树的光（报告卡位置先显示一行「正在读…」）：一个项目最多 3 + 2 处，逐条看用处不大。
- **刚归档、手里还是生长回顾时**，点「结项回顾」重新写成结项回顾（后台也会写，见到期判断）。
- **结项回顾里「还没解决」的问题记为问题时**，挂上核心观点那几篇作材料；没有核心观点时只记来源文字。
- **今日卡「打开回顾」**：项目详情页新增参数 `review=1`，打开即展开回顾；地图页新增参数 `insight`（`global:<标记>` / `topic:<主题>[:<标记>]`），打开即进入洞见视图并点亮那一处。
- **小关系图复用 7b 的 `MiniGraph`**（从 `features/insights/components/InsightsReport.tsx` 导出）。
- **vec0 按批读向量（第 8 步）**：见 §12.3；`noteVector`（逐个查）删除。
- **功能槽说明的 token 估算**按每份笔记约 300 token：第 5 步真实库实测（输入 34.6 万 + 输出 4.3 万）/ 1,297 份（设计时先按 230 估）。
