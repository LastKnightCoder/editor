## 0. 一句话与原则

**写一篇文章时，把相关资料摊在左边的白板上，右边写。进入时说一句想写什么，AI 从你的笔记里挑出一批、分好组摆上白板；写的过程中，和当前段落相关的资料在白板上轻轻亮起；写完点一下，AI 指出正文里哪些地方可以连到白板上的资料。**

- **白板是这篇文章的素材板**：一篇文章一块，跟着文章走，退出后原样保留，不出现在白板列表里。
- **AI 只摆资料、只提议连接**，不写正文，不自动插入连接。
- **正文里平时什么都不出现**（沿用 7b）。写作时的联动只发生在白板上。
- **一次一件事**：召集一次一句进度，连接一处一个气泡、最多两个按钮。

## 1. 用户决策

2026-10-09 已定：

- 白板是**真实白板，与文章 1:1 绑定**；**不出现在白板列表里**。
- **先只做文章**。项目文档也要做，但不在这一期；本期的数据与组件要让项目文档以后能直接接进来（§6.3）。
- **左右宽度可以调整**。

此前已定，本文沿用：连接由用户确认并落成 content-link（KL-058）；AI 必须参与判断，本地只负责宽候选；不要信息密集；零配置（配了模型即同意）；不做 AI 生成卡片 / 文章（04 待定）；新入口先单独问做不做。

## 2. 现状调研

### 2.1 白板的存储与可见性

- `white_board_contents` 是一页画布（`data` JSON、`ref_count`）；`white_boards` 是白板本体（标题、标签、`white_board_content_ids` 页序）。
- **项目里的白板条目没有 `white_boards` 行**：`project_item.white_board_content_id` 直接指向一页（`30_project.sql`），视图是 `WhiteBoardProjectItemView`。
- 所有列出白板的地方都读 `white_boards`：白板库 `useWhiteboards`、侧边栏白板标签、项目「引用白板」、`WhiteBoardSelectorModal`、编辑器嵌入白板选择、`entity-search.ts` 的 `SEARCH_SQL.white_board`（EntityPicker / @ 搜索）。命令面板、全文 / 向量索引、今日页最近编辑、知识地图都不收白板。
- 结论：**只建一页 `white_board_contents`、不建 `white_boards` 行，就天然不出现在任何白板列表里**，不需要加隐藏字段、不用在 6 处补过滤。这和项目白板条目是同一个先例。
- 例外是脉络「被使用」（`context-lineage.ts`）：它从索引库 `whiteboard_refs` 反查放了某篇笔记的页，再按「独立白板 / 项目条目 / 文档里嵌入」三种归属展示。素材板需要补一种归属（§5.3），否则放在素材板上的卡片在脉络里看不到「被使用」。
- 引用计数：页创建时 `ref_count = 1`，`WhiteBoardContentTable.deleteWhiteboard` 只减计数，启动时清理 ≤ 0 的页（保证撤销）。正文删除（`ContentTable.deleteContent` 引用归零）时会释放正文里嵌入的白板块，素材板在这里补一行释放即可。文档卡只存 `entityRef`，不计正文引用。
- 同步是整库快照，新表随库同步，无需单独处理（同步信封版本见 §8 C8）。

### 2.3 缺的

- 主进程 `findCandidates` 只按本文自己的节向量找近邻，**没有「指定一组候选」的入口**（§4.3 要加）。
- 白板**不支持把元素拖出画布**；编辑器**只接受系统文件拖入**，不接受实体拖入（§3.6）。
- 文档卡阅读纸的「居中 / 停靠右侧」是全局偏好（`readerStore.ts`），**宿主没法按场景禁用停靠**；创作模式右边是正文，停靠会盖住正文（§3.5）。
- 文章详情页没有分栏，正文是居中单栏（`ArticleDetailView`）。

## 3. 交互全流程

### 3.1 进入与退出

- 创作模式是**文章详情页的一种模式**，不是新页面：页面参数 `layout=compose`，`article-detail` 按 id 去重（`match: "params"`），切换参数是原位更新，编辑器不重新挂载、滚动位置不丢；原位更新不进历史，后退回到进入文章之前的页面。
- 元信息行「AI 洞见」旁一个开关按钮「创作模式」，进入后变成「退出创作模式」。用户只需要理解两种状态：普通编辑 / 创作模式（2026-10-09 用户反馈三态布局「只看正文 / 白板 + 正文 / 只看白板」不好理解，改为一个开关；想专心看白板时把正文栏拖窄即可）。
- 入口：① 文章详情的「创作模式」开关；② 新建文章菜单「在创作模式中新建」；命令面板不做（C1）。
- 退出：再点一次开关。素材板保留，下次进入原样恢复（视口、选中都在）。
- 素材板只在第一次进入时创建（懒创建），从没进过创作模式的文章没有素材板。

### 3.2 说出意图（第一次进入）

- 素材板还不存在时，左侧白板区域压暗，弹出一张卡：「这篇想写什么？」+ 一个输入框 + 来源类型勾选（卡片 / 文章 / 项目文档 / 日记，默认全选）+「开始找资料」/「跳过，空白白板」。
- 已有正文的文章，输入框预填「标题 + 首段前 120 字」，用户可以直接回车。
- 意图存下来（§5.1），**不在正文里常驻**（和写作本身无关，2026-10-09 用户反馈后去掉正文上方的意图条）；白板右上角「再找一些」左边一个铅笔图标，点开看 / 改。后面「再找一些」拿它作上下文。
- **已有文章先摆已关联的**：建板时先把文章已关联的资料（显式连接 + 正文里的引用，即脉络「连接」分区；显式在前、正文引用按出现顺序在后）摆成白板上的第一组，组名「已关联」；正文里引用了的卡片同时标「已引用」。这一组不记召集来源，删掉不算「不要」。新文章没有关联就没有这一组。之后正文里新加的连接不自动上白板，白板上的东西由用户和召集决定。
- 浮层经 `useOverlayDismiss` 接 Esc（D-003），Esc = 跳过。

### 3.3 召集资料

1. 白板区域上方一颗进度胶囊，真实阶段说明，不做假进度：「读你的写作意图…」→「在 1,298 份内容里粗筛出 64 份」（本地，毫秒到 1 秒）→「挑出 9 份，分成 4 组」（模型，约 5–10 秒）。白板区域一道淡光扫过。可以随时取消，取消后什么都不摆。
2. 结果回来后，每组一个 frame（标题是 AI 起的组名），组内是文档卡，**按组依次落下**（每张约 0.18 秒）。卡片底部印 AI 的一句「为什么相关」（≤ 24 字）。长文的卡定位到命中的那一节（展开时直接滚到那节）。
3. 胶囊变成「9 份资料已摆上白板 · 不要的直接移走 · 撤销全部」，数秒后收起。摆放是**一步历史**，Ctrl+Z 一次撤掉全部。
4. 不要的卡片直接删除即可；从 AI 摆上来的卡被删除时记为「不要」（§5.1），以后「再找一些」不再推荐。
5. 白板右上角常驻「✦ 再找一些」：用当前意图 + 正文已写的内容再找一轮，排除白板上已有的、不要的和已关联的，新的一组摆在现有内容右侧空白处，并把视口平移过去。
6. 摆放位置：第一次从画布原点开始按 2 列网格排；之后追加在已有内容包围盒右侧，不覆盖用户摆好的东西。

**摆什么**（本期）：只自动摆**四类正文实体**（卡片 / 文章 / 项目文档 / 日记），它们能被 content-link 连接，是 §3.8「标出可引用处」的对象。网页、视频、PDF 由用户用白板已有工具手动添加；摘录、PDF 标注、剪藏的自动召集以后再说（它们在白板上没有对应的元素形态）。

### 3.4 布局与宽度

- 左白板、右正文，中间 `ResizeHandle`；正文栏是固定宽的一侧，白板填满剩余。
- 正文栏默认 640px，最小 480，最大到「白板剩 360」；宽度存为全局偏好（不按文章记），双击分隔条恢复默认。
- 正文栏里的正文仍有版心（≤ 720px，窄时随栏宽），左右留白随栏宽收缩。
- 窗口太窄（放不下 360 + 480）时白板收起、只留正文，窗口放宽后自动回来；开关仍显示「退出创作模式」。

### 3.5 在白板里看资料、打草稿

- 白板就是普通白板，所有工具照常：便签、手绘、思维导图、frame、箭头、网页、视频、图片、手动添加文档（`EntityPicker`）。
- 文档卡展开阅读纸**只允许「居中」**（铺满白板区域，不盖正文），纸面上的「停靠右侧」按钮在创作模式下不出现。全局偏好不被改写，回到普通白板仍按用户上次的选择。
- 阅读纸里照常可编辑那篇资料（实时保存），「在详情页打开」照常可用。

### 3.6 白板 → 正文：把资料连进来

只有一条路（2026-10-09 用户反馈后去掉了拖拽），落下的是**行内连接（content-link）**，进入脉络「连接」与谱系：

- **点**：悬停文档卡时右上角出现一枚小签「❝ 引用」（悬停提示「在正文光标处插入指向它的链接」），插在正文当前光标处，没有光标时插到全文末尾。
- 引用后这枚小签常驻为「✓ 已引用」；悬停变成「✕ 取消引用」，点一下撤掉正文里指向它的全部链接（文字就是资料标题的整段删掉，包着正文原话的只解开、留下原话），toast 带「撤销」。正文里删掉这个连接，小签同样回到「引用」（按正文里的 content-link 实时算，不另存状态）。

mockup 里的「引述原文 / 嵌入卡片」两种落法本期不做，见 §8 C6。

### 3.7 正文 → 白板：写作时相关资料亮起

- 光标所在段落停笔约 2 秒、且这段有 ≥ 20 字的新改动时，用这一段的文字在**白板上已有的文档卡**里比相似度（§4.2）。
- 最相关的 1 张（超过阈值才算）轻轻亮起（描边 + 呼吸），下方一个按钮「连到此段」= 在光标处插入行内连接。
- 卡片在视口外时，白板边缘出现一个指向它的小箭头，点击平移过去。
- 光标离开这段、或 10 秒没操作，亮起淡出。**正文里什么都不出现。**
- 只比白板上的资料，不搜全库，不调模型；全库的判断留给 §3.8。

### 3.8 标出可引用处（复用 7b 洞见视图）

- 做的事：**AI 通读写好的正文，标出哪些话可以引用白板上的资料**，同时照 7b 指出重复、矛盾、可以展开的地方，并列出白板上还没用到的资料。原名「检查连接」用户反馈看不懂（「检查」像找错，「连接」是系统概念），2026-10-09 改名。
- 创作模式下，元信息行的「✦ AI 洞见」按钮改叫「✦ 标出可引用处」（悬停：AI 通读正文，标出哪些话可以引用白板上的资料，并列出还没用到的资料），打开后叫「收起标注」；行为与 7b 相同（读 → 报告卡 → 逐处画线 → 气泡 / 逐条看 → 退出），区别只有候选：**白板上的文档卡全部作为候选**，再加 7b 原有的本地近邻（§4.3）。
- 标记指向白板上的资料时，画线旁的编号与白板卡片左上角的角标一一对应；其余白板卡片降淡，退出时恢复。
- 指向白板外资料的标记，气泡里多一个「放到白板」（仍是最多两个主按钮：连接 / 不相关；「放到白板」是气泡里对方标题旁的小图标）。
- 报告卡开头一句（本地计算，不靠模型措辞）：「正文里有 N 处可以引用白板上的资料，还有 M 份没用到。」N = 指向白板资料的可连接 / 重复标记数，M = 白板上既没被正文引用、也没被标记指到的资料，点「M 份没用到」在白板上闪一下这几张；模型写的位置概述退为第二句。提醒漏掉的论据，不替你写。普通文章详情里仍叫「AI 洞见」、报告卡不变。
- 连接后：原文片段包成 content-link，对应卡片出现「✓ 已引用」。

## 4. 分析怎么做

### 4.1 召集：一次本地宽候选 + 一次模型调用

1. **本地候选**（不花 token，宽，取 60 份）：
   - 意图文字（召集）或「意图 + 正文最近写的 1500 字」（再找一些）做查询向量，节级 KNN（D-099）取前 150 节，按 contentId 合并；
   - 意图里的词与 `content_ai_meta.concepts` 匹配补召回；
   - 排除：本文自己与共用本文正文的身份、白板上已有的、标记为「不要」的、回收站里的；
   - 每份带：类型、标题 › 命中节、7a 要点与主张、命中节前 300 字。
2. **模型调用**（一次）：输入意图 + 本文已有正文的大纲（如有）+ 候选；输出 JSON：`groups[]`（3–4 组，组名 ≤ 10 字）、每组 `items[]`（候选编号、`why` ≤ 24 字、`section` 命中节），全部 8–12 份。提示词要求「宁缺毋滥：和意图无关的不要凑数；同一件事的多份只留最好的」。
3. **校验**：候选编号必须存在、不重复；不满足的丢弃；少于 3 份时不分组，直接排一列。
4. **用量**：输入约 60 × 250 + 600 ≈ 1.6 万 token、输出约 800（deepseek-flash 约 0.01 元）。只在用户点「开始找资料」或「再找一些」时调用。

功能槽：推荐复用「AI 洞见」`contentInsights`（与 7c 一样，零配置；§8 C4）。槽没配时：意图卡的「开始找资料」换成说明「配置『AI 洞见』模型后可以自动找资料」，「跳过」仍可用；「再找一些」不出现。

### 4.2 写作联动：只比白板上的资料

- 段落文字经当前嵌入模型生成一个向量（与索引同一模型），与白板上每张文档卡的**节向量**（索引库已有，长文只取命中节与相邻节）算余弦，取最大值。
- 阈值：用这块白板上「卡片节 × 随机正文段」的 p90 作动态阈值（同脉络「相关」的做法），白板卡片少于 3 张时用固定阈值。
- 白板通常 5–30 张卡，计算量可以忽略；嵌入一段文字是唯一的开销。嵌入模型是远程 API 时，会按停笔次数产生少量调用（§8 C5）。
- 不缓存结果、不存库。

### 4.3 标出可引用处：给 7b 加「指定候选」

- `findCandidates(mainDb, indexDb, self, opts?: { seed?: EntityRef[] })`：`seed` 里的实体全部进入候选（不受 15 份上限与 p95 阈值约束，最多 24 份；按命中本文的节向量选每份最相关的那一节带给模型），再与原有近邻合并去重，候选总数上限放到 30。
- 不加 `seed` 时行为与 7b 完全一致；7b 详情页不传。
- 结果照存 `content_ai_insights`（同一篇文章在详情页和创作模式里看到的是同一份结果），`result` 里每条 mark 带 `seeded: boolean` 供角标使用；`schema_ver` 不变（新字段可选）。
- 用量：比 7b 多约 50%（候选多），一篇长文约输入 1.2 万 / 输出 800。

## 5. 存储

### 5.1 新表 `compose_boards`（主库）

```sql
CREATE TABLE IF NOT EXISTS compose_boards (
  content_id   INTEGER PRIMARY KEY,         -- 正在写的那份正文
  page_id      INTEGER NOT NULL,            -- white_board_contents.id，素材板那一页
  intent       TEXT NOT NULL DEFAULT '',    -- 写作意图
  dismissed    TEXT NOT NULL DEFAULT '[]',  -- 「不要」的实体 key（entityRefKey）
  create_time  INTEGER NOT NULL,
  update_time  INTEGER NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_compose_boards_page ON compose_boards(page_id);
```

- 主库 71 → 72 表、114 → 115 索引；同步更新 `scripts/db/check-schema-parity.mjs` 常量、`database-schema.md`，执行 `pnpm db:schema:build` / `check`。
- 素材板页本身仍是一行普通 `white_board_contents`，`name` 记为「创作白板」；**不建 `white_boards` 行**，所以不进任何白板列表（§2.1）。
- AI 摆上来的卡片与组 frame 在元素上记 `composeOrigin: "gather"`（白板元素的宿主扩展字段，包内不解读），删除时据此写入 `dismissed`；用户手动加的不记。

### 5.2 为什么按 `content_id` 绑定

- 与 `content_ai_insights`、`content_links`（D-124）、协作绑定同口径：**同一份正文的不同身份共享同一块素材板**。文章转成 / 共用为项目文档时，素材板自然跟过去。
- **项目文档以后接入不需要任何数据改动**，只是在项目文档详情里多一个布局入口（§6.3）。
- 复制创建（新建正文）不带素材板。

### 5.3 生命周期与脉络

- 创建：第一次进入创作模式（确认意图或跳过）时，单事务建页（`ref_count = 1`）+ 写 `compose_boards`。
- 释放：`ContentTable.deleteContent` 引用归零时，与 `ContentAiInsightsTable.delete` 并列加 `ComposeBoardTable.releaseContent`：删行并对页 `deleteWhiteboard`（减计数，启动清理）。文章进回收站不释放，恢复后素材板还在。
- 脉络「被使用」：`context-lineage.ts` 的归属解析在「项目里的白板」之后加一支——页 id 命中 `compose_boards.page_id` 的，归属为「正在写它的那篇」，展示为「《标题》的创作白板」，打开 = 该文章详情 + `compose` 参数。这样一张卡片的脉络里能看到「它在哪几篇文章的素材板上」。

### 6.2 改动点

- **文章详情** `ArticleDetailView`：参数含 `compose` 时，把现有的正文纸包进 `ComposeLayout` 的 `editor` 插槽；`useInsightsView` 传 `seed`（白板上的文档卡）。标题栏加布局切换（`seg`，3 个图标按钮）。

### 6.3 项目文档以后怎么接

数据零改动（§5.2）。要做的只有：`EditProjectItem` 里同样把正文包进 `ComposeLayout`、`project-detail` 参数加 `compose`、标题栏加布局切换、`useInsightsView` 传 `seed`。`ComposeBoard` / `IntentCard` / 召集 / 联动都按 `contentId` 工作，不认宿主类型。召集时「排除本文」按 contentId 排除所有共用身份，项目文档同样适用。

## 7. 想过的其他方式

| 方式                                          | 为什么没选                                                                                        |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 建 `white_boards` 行 + 隐藏字段               | 要在 6 处列表 / 搜索补过滤，漏一处就露出来；还会带上标签、多页这些素材板用不上的东西              |
| 临时白板（写完即弃）                          | 整理好的资料与草稿白丢；用户已定真实白板                                                          |

| 素材板做成多页（SheetBar）                    | 一篇文章一个素材空间足够，分组用 frame；多页会让「白板上的资料」范围变模糊（§4.3 的 seed 取哪页） |

| 写作联动直接在正文里提示                      | 7b 已否决正文常驻提示                                                                             |
| 写作联动搜全库 + 调模型                       | 慢、花钱、打扰；全库判断交给用户主动点的「标出可引用处」                                          |
| 三态布局（只看正文 / 白板 + 正文 / 只看白板） | 把布局这个实现概念交给了用户；只看白板很少用，拖窄正文栏即可（用户 2026-10-09 否决）              |
| 召集只靠向量、不调模型                        | 用户偏好「AI 必须参与判断」；而且分组和「为什么相关」是素材板好用的关键                           |

## 11. 实现记录

### 11.1 实现与设计的差异

- 页面参数叫 `layout=compose`（不是 `compose`）；脉络「被使用」的打开目标带 `compose: true`，`openEntity` 据此打开到 `layout: "compose"`。
- 「创作模式」开关放在元信息行「AI 洞见」右边（与它同一种圆角按钮），不在壳层标题栏。
- §3.6「引用」：属性条与右键菜单是 `@tau/whiteboard` 内部的插件菜单，宿主加不进去；改为卡面右上角一枚小签（引用 / 已引用 · 取消引用），经 `DocumentHostContext.cardAccessory` 叠到卡面上，带 `CANVAS_OVERLAY_ATTR`。最初还有一个拖进正文的抓手（正文外包 `ComposeDropZone` 接 `application/x-tau-entity`），用户反馈两个纯图标按钮看不懂、误点后找不到撤销，2026-10-09 去掉拖拽、小签加文字并可取消引用（`insert.ts` 的 `removeEntityLinks`）。
- §6.2 白板包零改动：「只允许居中」与卡面叠加都在桌面端共享白板的 `DocumentHostContext`；元素上的 `composeOrigin` / `composeWhy` 白板原样保存。编辑器侧不改。
- 元信息行（`ArticleHero`）是 `@container/meta`：恒为一行：操作按钮不换行不收缩，信息组（编辑 · 字数 · 创建）固定一行高、溢出的项隐藏，按宽度依次让出创建时间、字数；创建时间始终可在「编辑」的悬停提示里看到。
- 脉络：素材板上的资料**不进脉络分区、不计入「N 处关联」**（它是写作时的工作区，不是内容关系；连接与素材板重合也就不需要去重），普通详情的脉络浮层末尾一行「创作白板 · N 份资料」作入口（`ContextBadge.extra` + `ComposeBoardEntry`，主进程 `compose-board:summary` 按实体去重数文档卡）；创作模式里不显示。
- §3.7 视口外的亮起：白板边缘箭头改为画布顶部一颗指路胶囊「与这段相关：《标题》」，点一下平移过去。阈值直接用脉络「相关」的随机块对分位（`ensureRelatedThreshold`），读不到时 0.6，不再按白板单独采样 p90。
- §3.8 编号只画在白板卡片上（蓝色圆角标），正文里的画线不加编号：画线已经是 7b 的样式，当前一处对应的那张卡片会描边；「放到白板」是气泡里对方标题右侧的小图标。
- §4.1 概念补召回：意图原文包含某条笔记的 7a 概念（≥ 2 字）即补入，最多 20 份，排在向量召回之后。查询嵌入失败（索引未建、模型缺失）时只靠概念补召回，不让整次召集失败。
- §4.1 召集在主进程排除已关联（`content_links` 两侧的全部身份 + 正文里的 content-link），即使用户把「已关联」那组从白板上删了也不再推荐。
- §4.3 `seed` 只对卡片 / 文章 / 项目文档生效（洞见本身只覆盖这三类），白板上的日记卡不进候选。
- §4.1 长度：提示词要求组名 ≤ 8 字、理由 ≤ 20 字，硬截断放宽到 16 / 40 字（评估第一轮模型常超出几个字，原来按 10 / 24 截断会截在半个词上）。
- §3.3 空白画布也从原点摆起；一次召集的所有 frame 是一次 `board.apply`，Ctrl+Z 一步撤掉；胶囊里「撤销全部」直接删掉这几个 frame（同时记为「不要」）。
