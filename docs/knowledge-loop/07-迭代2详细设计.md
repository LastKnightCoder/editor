# 07 · 迭代 2 详细设计：知识地图独立与泛化

2026-10-01。对应 [03-迭代计划.md](03-迭代计划.md) §迭代 2、[01](01-模块联动与知识闭环.md) §5.1、[02](02-技术方案.md) §5.3。路径相对仓库根目录，`D` = `apps/desktop`。

## 0. 目标与范围

**用户可见**：标题栏有一个「知识地图」入口，打开一个全局大页面。地图里除了卡片，还有文章和项目文档；在某篇内容里点入口，地图以它为中心打开。

**本迭代不做**：段落级节点（迭代 6）、AI 主题概述与洞见（迭代 7）、kNN 换近似近邻与力模拟改造（`docs/link-graph/scale-decisions.md` 两项，观察到变慢再做）。

## 2. 节点

### 2.1 范围

| 类型     | 纳入条件                                                            |
| -------- | ------------------------------------------------------------------- |
| 卡片     | 全部                                                                |
| 文章     | `is_delete = 0`                                                     |
| 项目文档 | `project_item_type = 'document'`，正文非空，且**不是引用型**（`ref_type` 不在 card / article / content） |

- 共用正文的身份只出一个节点（按 `content_id` 去重，优先级 卡片 > 文章 > 项目文档，即 `ENTITY_REF_PRIORITY`）。排除引用型项目文档就是为此。
- 日记、白板、网页条目等不纳入（01 KL-005：地图收「我的思考」中成形的观点；日记是流水，后续再议）。

### 2.2 身份：外部字符串键，内部数值下标

- **对外**（表、IPC 契约、渲染层的节点数据）用字符串键 `node_key = "kind:id"`，与 `entityRefKey` 一致。
- **对内**（`compute.ts`、`vectors.ts`、渲染场景）继续用数值：读输入时按 `node_key` 排序后分配稠密下标，计算完再映射回键。计算逻辑几乎不动，`compute.test.ts` 的「结果确定」继续成立。
- 改动点：`KnowledgeMapNode.cardId` → `key: string`；`KnowledgeMapCardInput` → `KnowledgeMapNodeInput { id: number(下标); key; tags; links: number[](下标) }`；`placeIncrementally` 的黄金角偏移用下标。

### 2.3 索引库表

`packages/db-schema/schema/index/40_knowledge_map.sql`：

```sql
CREATE TABLE IF NOT EXISTS knowledge_map_nodes (
  node_key TEXT PRIMARY KEY,   -- "card:12" / "article:3" / "project-item:5"
  x REAL NOT NULL, y REAL NOT NULL,
  topic INTEGER NOT NULL DEFAULT -1, subtopic INTEGER NOT NULL DEFAULT -1,
  update_time INTEGER NOT NULL
);
```

- 索引库没有版本机制。旧表有 `card_id` 列时，在 `initSchema` 之前 `DROP` 两张地图表（数据可重算），由下次打开地图时重建。写成幂等迁移，参照 `packages/db-schema/src/knowledge-index-migration.ts`。
- `knowledge_map_topics` 不变。

## 3. 边

- **显式边**：卡片 `cards.links` ∪ 索引库 `entity_refs`（迭代 1 的引用索引，覆盖全部类型之间的内联引用）。`entity_refs` 的来源是正文 id，经 `locateAll` 映射到节点；映射到被去重掉的身份时，归到代表节点。
- **语义边**：`vec_documents` 去掉 `type = 'card'` 的限制，读 card / article / project-item 三类；各节点的分块向量取平均后做 kNN（现状）。
- **长文的向量聚合**：长文分块多，取平均会把主旨抹平、漂向中心，可能变成到处都连的「假桥」。v1 先沿用平均，实现时在真实库上量两个指标再决定是否改（最大值 / 按块加权）：① 文章与项目文档节点的平均语义度数与卡片之比；② 被选作跨主题桥接的节点里长文的占比。结果记入 05。

## 4. 主题

### 4.1 分簇

不变：显式边 + 语义边上做 Louvain，规则与参数沿用。

### 4.2 增量与漂移

`reconcile`、`driftCount`、`neighborsOf`、`hasVectors`、`cardIds` 全部按三类节点改写（统一用 `node_key`）。`neighborsOf` 去掉 `type='card'` 限制，按 `prefixed_id` 聚合到节点。

### 4.3 命名：项目文档用项目路径代替 tag（建议，KL-020）

项目文档没有 tag，但它有更好的东西：**所在项目与上级文档**，这正是用户亲手搭的结构（01 §2.4「两种结构并存」）。命名时把项目文档的「标签路径」取为 `项目名 / 上级文档标题…`：

- 一群主要来自「前端体系」项目的文档聚成一团，主题名就是「前端体系」；子主题按上级文档分。
- 卡片照旧用分层 tag；文章用自己的 tag（扁平，当作一段路径）。
- 一个主题里卡片与项目文档混在一起时，仍按现有规则取多数，覆盖率不够就不命名。
- 只影响命名，不影响分簇。

## 5. 渲染

`D/src/components/LinkGraph/` 去卡片化：

- 输入从 `ICard[]` 改为 `GraphItem { key; kind; label; createdAt; tags; contentId; category? }`，由调用方组装。场景里的 `GraphNode.id` 仍为数值下标，另加 `key`、`kind`。
- 点击回调 `onClickNode(item)`；悬停预览按 `contentId` 读正文（`getContentById`），不再写死 `getCardById`。
- 说明行文案去掉「张卡片」，改为调用方传入（地图页：「卡片 674 · 文章 76 · 文档 554」之类）。
- **节点外观区分类型**（建议，KL-021）：卡片保持现状（实心圆，分类色）；文章、项目文档用**稍大的空心环**，颜色仍跟随主题色。理由：长文是「容器型」观点，环形在远景里能一眼和卡片区分，又不引入新颜色。先在 showcase 做出来给用户看，再定。
- 链接图谱回退模式（没有地图时按链接实时布局）、坐标缓存 `positionStore` 只服务卡片库旧入口；地图页不用它们。

## 6. 页面与入口

### 6.1 页面

新域 `D/src/features/knowledge-map/`：

```
features/knowledge-map/
  pages/knowledge-map.page.tsx   key "knowledge-map"，match "single"，params { focus?: string }
  views/KnowledgeMapView.tsx
  queries.ts                     useKnowledgeMap（从 features/cards/queries.ts 迁来）
  model.ts                       节点组装、筛选
  milestones.ts                  生长动画里程碑（从 features/cards/graphMilestones.ts 迁来）
```

- **筛选**：类型（卡片 / 文章 / 项目文档）、项目、标签。筛选只降淡未命中的节点（沿用 `filterCardIds` 的做法与「筛选保持主题色」的约定），不删节点。
- **focus**：带 `focus = "card:12"` 打开时，镜头对准该节点并高亮它的一跳邻居。
- 点击节点：经 `openEntity` 打开对应详情页（不再是卡片预览弹窗；预览弹窗只在卡片库里有）。
- 生长动画、里程碑邀请、说明行沿用卡片库的设计（用户记忆：入口是说明行、首次自动播）。

### 6.2 标题栏入口（壳层变更，D-095）

- `D/src/app/Titlebar.tsx`：搜索框右侧、AI 对话开关左侧放一个 `IconButton`（lucide `Map`）。
- 点击：当前页是卡片 / 文章 / 项目文档详情时，`navigator.push("knowledge-map", { focus })`；否则不带 focus。地图页在栈顶时按钮为选中态（同 AI 对话开关的选中语言），再点一次后退回原处。
- 命令面板：在 `D/src/features/search/searchMeta.ts` 的 `paletteCommands()` 手写一条页面命令「知识地图」，同时让最近访问能显示图标。
- 落地时在 `D/docs/redesign/DECISIONS.md` 加 D-095，同步 03 指南的壳层与页面小节。

### 6.3 卡片库（建议，KL-022）

卡片库的视图切换里现在有「图谱」。两种处理：

- **A（建议）**：保留「图谱」视图项，但它就是知识地图的「只看卡片」——选中后直接跳到地图页并预置类型筛选为卡片，卡片库自己不再渲染图谱。地图只有一份实现、一处入口逻辑。
- B：卡片库保留自己的图谱视图（只含卡片），地图页另有一份。两处维护、口径易分叉。
