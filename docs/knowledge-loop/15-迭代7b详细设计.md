## 0. 目标与范围

**一句话**：读一篇长文时，某一节和别处写过的内容在说相近的事、但还没有连接，就在这一节旁边给一个很淡的标记，点开就地看到是哪里、要点是什么，可以打开或忽略（KL-001：促成发现连接）。

01 §4.4 对「出现在阅读时」的要求：**先回答「如何不打扰」（数量上限、出现时机、视觉强度）与「在哪关闭」（全局、按模块、单条忽略）**。本文逐条给出推荐与数据。

**前提**：补 `<s>` 的嵌入修复 `ee7ab9fb3` 必须先进入日常运行的版本。本机现有索引是缺陷向量（14 §3.1），在它上面做标记没有意义；本文的数据都在按本分支管线重建的副本上测得。

## 1. 现状

- 7a 的「相关」是**整篇对整篇**（实体节向量均值查近邻），在浮层末尾、不计数、只在浮层打开时查（KL-057）。
- 节信息已经齐备：索引库 `content_sections` 有每节的标题路径、块范围、节文本；`vec_documents` 每节一条向量（`chunk_index`）。打开到块位置已有 `openEntity(ref, { at })`（KL-049）。
- 引述锚点已撤回（KL-052），**标记的定位只到节**（节的第一块），不到句子。
- 应用没有只读模式：卡片 / 文章 / 项目文档详情就是编辑器，「阅读」和「编辑」是同一个界面。

## 2. 标记从哪来（取数）

对**长文**（文章、项目文档，至少两节）的每一节：

1. 用这一节的向量查近邻（k = 200 块），按实体取最高相似度，记下对方命中的节（用于「› 某节」与打开定位）；
2. 排除已有关系：与「相关」同一套（自身与共用正文、卡片双向链接、引用了 / 被引用、谱系两端、同一问题的材料），**另加同一项目里的文档**（项目树本身是用户搭的结构，同项目互相推荐是噪音，见 §3）；
3. **只在有文字的节上出**：去掉代码、图片、链接网址后不足 80 字的节不出标记，也不作为目标（参考链接节、只有截图的节、代码节在数据里是主要噪音）；
4. 同一个目标只出现在相似度最高的那一节；
5. 相似度高于**随机块对 p99**（按当前库动态取，与「相关」的 p95 同一套抽样，存 `index_meta`）；
6. 每篇最多 3 处，按相似度取。

**卡片不出标记**（推荐，§9 D2）：卡片整张就是一节，它的标记就是「相关」的第一条，浮层里已经有了。

**不调 LLM**（推荐，§9 D3）：本地近邻能说的只是「这里讲的，别处也写过 / 在说相近的事」。01 §4.4 列的「呼应 / 矛盾 / 追问 / 空白」需要模型判断，留到以后（§8）。

## 3. 数据：会出几处、准不准

真实库副本（1425 个实体，本地 bge-m3 修复管线重建），270 篇 ≥ 3 节的长文（平均 8.6 节）。随机块对相似度分位：p95 0.643、p98 0.687、p99 0.721、p99.5 0.769。

**每篇长文的标记处数**（同一目标只算一次）：

| 口径 | 阈值 | 有标记的长文 | 每篇处数中位 / p90（不截断） | 截到 3 处后平均 |
| ---- | ---- | ------------ | --------------------------- | --------------- |
| 未过滤 | p99 | 92% | 6 / 35 | 2.51 |
| 文字 ≥ 80 字 | p99 | 89% | 5 / 31 | 2.33 |
| **文字 ≥ 80 字 + 同项目互不标记（推荐）** | **p99** | **69%** | **2 / 29** | **1.75** |
| 同上 | p99.5 | 42% | 0 / 5 | 0.83 |
| 同上 | p98 | 85% | 8 / 71 | 2.34 |

- 推荐口径下，**三成长文没有任何标记，有标记的平均不到 2 处**。p90 的 29 处说明少数长文（大型笔记集合）候选很多，上限 3 必须有。
- 取一篇长文的候选：本机平均 53–64 ms（每节一次 KNN）。重度库（4.4 万条向量）单次 KNN 约 78 ms（14 §4），一篇 9 节约 0.7 s、80 节的大文档约 6 s——**不能在打开时同步算**（§5）。

**抽查**（推荐口径、p99、每篇最多 3 处，`/tmp/kl7b-marks-eval-final.md`，待用户判断）：

- 过滤与同项目排除去掉了最明显的噪音：「参考」节互相推荐、只有截图的节、同一本书的各章、同一系列的版本记录。
- 剩下的标记**大多是「这里讲的东西，在别处也写过」**：如项目文档里「布尔值」一节 ↔ 讲假值的卡片、「字符串方法」里的常量 ↔ 同内容的卡片、端口被占用的卡 ↔ 「Windows 小技巧 › 杀死某个进程的端口」。对学习笔记为主的库，这类提示的价值是**把重复写过的地方连起来**，而不是发现跨领域的呼应。
- 仍有可疑的：相似度很高的代码节（渐变组件的 JSX ↔ 渐变语法）、主题相邻但无关（「同步」↔「Web Locks API › 死锁」）。

## 4. 形态（mockup 三选一）

| 方案 | 做法 | 优点 | 缺点 |
| ---- | ---- | ---- | ---- |
| **A 节首右侧细点（推荐）** | 节标题右侧页边一个 5px 淡点；悬停提示「和《X》› 某节相近」；点开在这一节末尾就地展开 | 位置精确到节；不占正文空间、不引起排版移动；余光可见 | 点小，可能被当成装饰；窗口窄、页边被收起时要退到 B |
| B 节末一行 | 这一节最后一段后面一行小字「这一节和《X》相近」，点开展开 | 出现在读完一节的停顿处，时机最自然；窄窗口也能放 | 占纵向空间；**编辑器里插入非正文行会让光标与排版跳动**，正在写的长文尤其明显 |
| C 只在浮层里 | 正文不加任何东西；「N 处关联」浮层的「相关」行加「← 某节」，悬停时正文该节淡淡高亮 | 零打扰，只给 7a 的「相关」补落点 | 不打开浮层就看不到，谈不上「阅读时」 |

推荐 A 的理由：本应用没有只读模式，标记出现在正在编辑的文档里。A 是页边浮层，不进入编辑区，打字、选区、滚动都不受影响；B 要在编辑器里插入装饰行，技术上可做（编辑器装饰层），但会改变正文高度。C 留作关闭标记后的退路（浮层里始终可以看到「相关」）。

**展开卡**（A / B 共用）：就地展开在这一节末尾，像微信读书的想法。每条：图标 + 标题 › 对方的节 + AI 要点（有元信息时）；行尾「忽略」；点击打开到对方的那一节（`at` 定位）。**不显示相似度**（同 KL-057）。长文与卡片之间不能「添加连接」（KL-018 只在卡片之间），所以展开卡里没有连接动作。

## 5. 时机与计算

- **出现时机**：打开文档后不立刻出现；正在输入时全部隐藏，停止输入约 2 秒后淡入（mockup「正在输入」状态）。
- **计算**：打开文档时异步请求，主进程逐节计算并让出事件循环，算完一次性显示（标记晚出现反而更不打扰）。结果按（实体, 正文 `update_time`, 嵌入指纹）缓存在索引库新表 `reading_marks`（派生数据，可重算，KL-009），再次打开直接读；正文改了、向量重建了就作废。**不做全库预计算**：重度库全库预计算是 4.4 万次 KNN、约 1 小时 CPU，而大部分长文不会被再次打开。
- 只对文字 ≥ 80 字的节查近邻，最多查 40 节（超长文档取前 40 个有文字的节），重度库最坏约 3 s，在后台完成。

## 6. 关闭（在哪关）

| 层级 | 推荐做法 | 存储 |
| ---- | -------- | ---- |
| 全局 | 设置「外观 / 阅读」里一个开关「阅读时显示相关标记」，默认开；关掉后正文不再出现标记，浮层「相关」不受影响 | 设置 `setting.json` |
| 按模块 | **不单独做**：标记只出现在文章与项目文档两处，再分模块开关意义不大 | — |
| 单条忽略 | 展开卡行尾「忽略」：这一节不再推荐这个目标（只针对这一对，不影响别处） | 主库新表 `insight_dismissals`（随库同步，换机器不复现）——**改主库 schema，需确认**（§9 D5） |

和「AI 功能零配置」不冲突：标记不调模型、不产生费用，开关管的是界面打扰，不是同意。

## 8. 不做 / 以后

- **LLM 判断关系类型**（呼应、矛盾、追问）：候选对用双方的 AI 要点与主张（7a 元信息，每对约 300–400 token）让模型分类，只保留「呼应 / 矛盾」。按重度库每篇长文 5 个候选估算约 1.5 万对、500–600 万 token。7b 先用本地「相近」验证打扰程度，用户觉得「相近」本身价值不够时再做。
- 卡片的标记、外部材料的标记、段落 / 句子级定位（需要锚点，KL-052 已撤回）。
