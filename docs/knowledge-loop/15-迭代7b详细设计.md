## 0. 一句话与原则

**点「✦ AI 洞见」，正文就地进入「洞见视图」：AI 先读一遍（你看得见它在读），然后正文里该连的、重复的、矛盾的、还没展开的地方一处处画出来，正文上方一张小报告告诉你这篇在你知识里的位置。处理完或按 Esc，正文恢复原样。**

- **平时什么都不出现**。只有你点了才有。
- **发生在原地**。洞见指向的就是正文里的那几个字，所以标记就画在那几个字上，不离开、不对照。
- **一处一件事，一件事最多两个按钮**。理由在气泡里，报告只有两三句话。
- **连接由你确认**，确认后那几个字直接变成 `content-link`。

## 1. 用户决策（2026-10-03）

- 文档内不主动出现洞见；连接、重复、矛盾等都在点了「AI 洞见」之后出现。
- 交互要直观、有效果：如正文里逐渐出现划线的动画标出推荐的连接点，再配一份分析报告；可以想更好的。
- 创作模式（左白板、右写作）不在这一期。
- 此前已定：连接由用户确认并生成 content-link；单独的功能槽「AI 洞见」；卡片也有；延伸可以带入 AI 的知识；模式梳理在 7c；没有迭代 8。

## 2. 交互全流程

### 2.1 入口

卡片、文章、项目文档详情的元信息行「✦ AI 洞见」（在「N 处关联」旁边）。分析过且还有未处理的，按钮右边一个很小的点，不显示数字。槽没配时按钮不出现。

### 2.2 读（第一次点，约 10–20 秒）

- 按钮变成「正在读」并转圈；正文变浅一点，**一道淡光从上往下扫过正文**。
- 元信息行下面一行说明它此刻真实在做什么：「对照你的 1,425 份笔记，找到 15 处可能相关…」（本地候选，毫秒级）→「AI 正在判断哪些值得告诉你…」（等模型）。不做假进度条。
- 读的过程中可以继续看正文、可以点按钮取消。

### 2.3 点亮

结果回来后同时发生两件事：

1. **报告卡**从元信息行下方展开（不进正文，§3）。
2. **标记按正文顺序一处处画出来**（每处约 0.25 秒，从左到右画线；一共不超过 6 处）。所有标记都画在正文的字上，不用页边装饰：

| 关系 | 标记 | 在哪 |
| ---- | ---- | ---- |
| 可连接 | 蓝色细实线从左到右画出 | 正文里 AI 指出的那几个字 |
| 重复 | 灰色点线 | 正文里 AI 指出的那一句（和对方说的是同一件事） |
| 矛盾 | 红色波浪线 | 正文里那句话 |
| 可以展开（空白） | 段尾一行淡注「＋ 这里可以展开：……」 | 那一节最后一段之后 |

动画只在点亮的那一刻播一次；之后再打开同一篇（分析过）直接点亮，不再读，标记照样按顺序画出。

### 2.4 处理

- **悬停或点标记 → 气泡**：一句理由；对方是谁（标题 › 节）和一小段原文预览；重复与矛盾时并排两段（这里 / 对方），一眼看出是「说的同一件事」还是「说法相反」。按钮最多两个：
  - 可连接：**连接**——那几个字的蓝线变成正式链接的样式（`content-link`），报告里的小关系图多出一条线、计数加一，提示「已连接 · 这篇现在连着 3 处」；
  - 重复：**连接**——和可连接一样，把这一句包成指向对方那一节的 content-link。重复的价值在于提醒你「这件事你写过两遍」，连上之后两处互相能看到，以后改一处时知道还有另一处；不提供合并或删除（那是改写你的正文）；
  - 矛盾 / 可以展开：**记为问题**（命令面板记问题模式，来源为本文，KL-043）；
  - 都有：**不相关**——标记淡出，以后重新分析也不再出现。
- **逐条看**：报告卡上的「逐条看」→ 其他标记降淡，当前这处居中并弹出气泡，底部出现一条操作条「1 / 5 · ↑↓ 切换 · 回车 处理 · ⌫ 不相关 · Esc 结束」。适合一次过完。
- 报告里的数量签（可连接 3 · 矛盾 1 …）点一下跳到该类第一处。

### 2.5 退出

再点按钮（此时叫「退出洞见」）、按 Esc、或点正文开始编辑：未处理的标记淡出，报告卡收起，正文恢复。已建立的连接留在正文里。洞见视图里正文只读——一边改一边看标记会错位，而这一刻你在「审视」，不在写。

## 3. 报告卡

一张浅底卡，左文右图，高度约 200px：

- **位置**（两三句）：「这是你『前端 · 渲染』主题里写得最完整的一篇，已经连着 2 处。AI 找到 3 处还没连上的笔记；『布局』一节和《前端体系》里的一段几乎重复；合成这一块是你写得最少的地方。」
- **数量签**：可连接 3 · 重复 1 · 矛盾 1 · 可以展开 1（点击跳转）。小关系图里的虚线（还可以连的）包括可连接与重复两类。
- **小关系图**（右侧 168 × 150）：中间是这篇，实线是已有连接，虚线空心点是还可以连的；每连上一处，一条虚线变实线并画出来——**让你看见这篇在长出连接**。
- **可以继续想**（≤ 2 个问题，悬停出「记为问题」）。
- 底部一行：分析时间与「读了 15 份候选，留下 6 处」、「重新分析」、「逐条看」。正文改动较大后这里提示「正文在分析后改动较大」，不自动重跑。

## 4. 实现要点

- **标记 = 编辑器装饰层**：AI 给出的是「节号 + 原文片段」，渲染时在该节的块里找到这几个字，作为 Slate decoration（不改文档内容）；找不到（正文已改）的标记直接不显示。画线动画用 `background-size` 0 → 100% 的过渡；点线与波浪线用 `text-decoration-color` 过渡；段尾淡注是按块 DOM 位置定位的浮层，不进编辑区。
- **连接** = 在那几个字的范围上执行 `wrapContentLink` 的选区包裹分支（与手动加链接同一条路径，协作、撤销都照常）。连接后结果里该条标为 `linked`。
- **只读**：洞见视图打开时编辑器 `readOnly`，退出恢复；Esc 经 `useOverlayDismiss` 接入页面浮层仲裁（D-003）。
- **报告卡**在编辑器之外、元信息行之下，是页面组件，不写进正文。
- 卡片同样：卡片正文短，通常 1–3 处，报告卡更短。

## 5. 分析怎么做

**一次分析 = 一次 AI 调用**（槽 `contentInsights`「AI 洞见」）：

1. 本地候选（不花 token，宽）：本文每个有文字的节（去掉代码、图片、链接后 ≥ 80 字）查向量近邻，排除已有关系（同「相关」），不排除同项目（重复与矛盾常在同项目里），随机块对 p95 以上，合并去重取前 15 个；每个带标题 › 节、7a 的要点与主张、命中节前 300 字。另带本文所属知识地图主题与相邻主题（写「位置」用）。
2. AI 输入：本文（标题 + 大纲 + 正文前约 6000 字，节编号）+ 候选 + 已有连接；输出 JSON：`lead`（≤ 120 字）、`marks`（≤ 6：类型、节号、原文片段、候选编号、理由 ≤ 60 字；矛盾另带双方各一句）、`asks`（≤ 2）。提示词要求「宁缺毋滥，没有值得说的就少给」。
3. 校验：原文片段必须是对应节里的原文（可连接的不能已在链接里），候选编号必须存在；不满足的丢弃。
4. 结果存主库 `content_ai_insights`（§6）。

**token**：一篇长文约输入 8000 / 输出 800，一张卡约 3000 / 400（deepseek-flash 下不到 1 分钱）。**只在你点按钮或「重新分析」时调用**，不做后台、不做全库。

**等待时间**：本地候选 < 0.5 秒（重度库约 1 秒）；模型调用 deepseek-flash 实测单份元信息约 3–4 秒，洞见输入大一倍，预计 8–15 秒——这就是 §2.2「读」要好看的原因。

## 6. 存储

主库新表 `content_ai_insights`（随库同步：换机器不重新花钱，「不相关」跟着走）：

```sql
CREATE TABLE IF NOT EXISTS content_ai_insights (
  content_id   INTEGER PRIMARY KEY,
  schema_ver   INTEGER NOT NULL,
  text_digest  TEXT NOT NULL,   -- 分析时的正文指纹
  result       TEXT NOT NULL,   -- JSON：lead、marks[]、asks[]，每条带 status（open / linked / questioned / dismissed）
  model        TEXT NOT NULL,
  create_time  INTEGER NOT NULL,
  update_time  INTEGER NOT NULL
);
```

重新分析时保留已处理的（按类型 + 目标 + 原文片段匹配），「不相关」的不再出现。删除与孤儿清理同 `content_ai_meta`。主库 66 → 67 表，索引不变；移动端不读写。

## 7. 想过的其他方式

| 方式 | 为什么没选 |
| ---- | ---------- |
| 正文里常驻淡点（v1） | 你没点它也在，算打扰；而且没有 AI 判断 |
| 侧栏列表（v2） | 一打开一屏字，要在列表和正文之间来回对照 |
| 独立的洞见页 / 关系图（v3） | 离开了正文，看不见「这件事发生在哪几个字上」；关系图作为报告卡里的小图保留 |
| 在对话里让 AI 讲 | 线性、慢，讲完还要自己回正文找位置、自己动手连 |
| **选中一段文字 → 问 AI 这段和我的哪些笔记有关** | 不冲突，是很好的**补充入口**（只看一段，更快、更准）。放进 §8 G6 由你决定这期做不做 |

在 v4 里额外加的两点：**逐条看**（一次把几处过完，不用一个个找）和**报告里的小图会长**（每连上一处多一条线），后者是「知识体系在生长」最直接的反馈。

### 11.1 第 3 步评估（2026-10-03，待用户抽查）

脚本 `D/src-electron/main/modules/__tests__/content-insights.eval.test.ts`（`KL_INSIGHTS_EVAL_MAIN` / `KL_INSIGHTS_EVAL_INDEX`，可 `KL_INSIGHTS_EVAL_REBUILD=local` 重建向量；只写副本）。模型 DeepSeek / deepseek-flash：「AI 洞见」槽未配置，回退到「笔记元信息」槽。向量按本分支修复管线重建（1425 个实体）。

| 项目 | 结果 |
| ---- | ---- |
| 样本 | 长文 10 篇（≥ 1000 字、≥ 3 节）、卡片 10 张（≥ 150 字），成功 20 / 20 |
| 标记 | 共 81 处，每篇平均 4.0：可连接 41、可以展开 35、重复 4、矛盾 1 |

初步观察（等用户逐条判断）：

- 「位置」一段基本准确，能说出所属系列、已连几处、哪一块写得少。
- 可以展开偏多（占 43%，有的长文 4 条），可能需要限制为每篇 ≤ 2 条。
- 矛盾很少（1 条，且更像「着眼点不同」）；重复集中在 Python 基础卡片与读书笔记的同一句话，命中准确。
- 可连接里有少量牵强的（如「割点」↔「有向图的环检测」、Set ↔ Map 的 API）。
- 一次分析只要约 3 秒，比设计估计的 8–15 秒快很多，「读」的过程会很短。

### 11.2 第二轮（提示词调整后，2026-10-03）

调整（用户要求「可以展开」≤ 2 条）：

- 「可以展开」每篇最多 2 条，提示词写明，解析时也强制截断；类型优先级写进提示词：矛盾、重复、可连接在前，可以展开放最后。
- 可连接收紧为「候选在讲同一个具体对象、机制或例子，读到这里翻过去确实有帮助；只是主题相近不算」；矛盾收紧为「互相冲突或一处说总是、另一处给了例外；侧重点不同不算」。
- 输出不是合法 JSON 时同样的请求再试一次（第二轮 20 篇里有 1 篇第一次就解析失败）。

同样 20 个样本（同一随机种子）、同一模型：

| 项目 | 第一轮 | 第二轮 |
| ---- | ------ | ------ |
| 成功 | 20 / 20 | 19 / 20（1 篇输出不是 JSON；重试已加，没有重跑） |
| 标记 | 81：可连接 41、可以展开 35、重复 4、矛盾 1 | 78：可连接 38、可以展开 33、重复 4、矛盾 3 |
| 每篇可以展开 | 最多 4 条 | **都 ≤ 2 条** |
| 每次用量（入 / 出） | 4,516 / 475 | 4,513 / 434 |

观察：可以展开已受限；可连接总数略降，「主世界地图」等设定类文档连得更具体，但仍有一些「同属一类」的连接（如「割点」↔「有向图的环检测」、二叉堆 ↔ 二分搜索树、冬夏季节 ↔ 相机与透镜）；新出的 3 条矛盾里有 2 条其实不是矛盾（欧拉回路的充要条件 ↔ 哈密尔顿回路没有充要条件；「错误留在上下文」↔ 学习方法的卡片）。deepseek-flash 对「不算」的边界把握偏松，「AI 洞见」槽配更强的模型可能明显改善——这正是 G7 单独一个槽的用意。
