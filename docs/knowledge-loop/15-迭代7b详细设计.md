## 0. 一句话与原则

**你点「AI 洞见」，进入一个新页面：左边一张关系图，右边是分析或你的正文，两边联动。** AI 站在你整个知识库的角度读这一篇，把能连的、重复的、矛盾的、还没写的摆在图上，用两三句话告诉你这篇处在什么位置。

- **正文里什么都不出现**。不弹提示、不加标记；只有你点进来才看到洞见。
- **少**。一页最多 5 条发现、2 个可以继续想的问题；每条一行字、一个动作，理由点开才看。
- **看图比读字快**。关系的类型用方位和线型区分，不用标签堆在文字里。
- **连接由你确认**。确认后在正文那几个字上生成 `content-link`。

## 1. 用户决策（2026-10-03）

- 文档内不主动出现任何洞见；连接推荐、重复、矛盾分析都在点了「AI 洞见」之后出现。
- 要新的交互形式与页面：图谱直观展示，旁边是分析，两边联动。

## 2. 页面

**入口**：卡片、文章、项目文档详情的元信息行「✦ AI 洞见」（不带数字，不进脉络浮层，不计入关联数）。打开新页面 `insights`（`features/insights/pages/insights.page.tsx`，参数 `ref`，`match: "params"`）。槽「AI 洞见」没配时按钮不出现。

**顶栏**：面包屑「文章 / 标题 / AI 洞见」；两个按钮「分析」「写作」（不用 Segmented）。

### 2.1 左：关系图

- 中间是这篇（或这张卡）。AI 确认过的关系按类型放在四个方向：**可连接**（右，实线）、**重复**（上，点线）、**矛盾**（下，红线 + ≠）、**空白**（左，虚线圈节点 = 你还没写过的概念；已有的问题用问号节点）。
- 已有的连接用灰色细线画在外圈，只作参照，让你看清这篇已经连着什么。
- 节点不超过约 12 个（发现 ≤ 5 + 空白 / 问题 + 已有连接）。布局按方位分扇区放置，不做力导向，打开就稳定、不抖动。
- **分析过程就是演示**：第一次分析时，先画出本地候选（很淡），AI 读完后成立的依次变实、不成立的淡出，顶部一行「AI 正在读 15 份候选…」。之后打开直接显示结果。
- 悬停节点：其他节点降淡（保持各自颜色，不刷成强调色），标签不消失。点击节点：一个小气泡，给一句理由、对方原文片段预览和最多三个按钮（主动作 / 打开 / 不相关）。

### 2.2 右：分析

- **位置**（两三句）：这篇属于哪个主题、已经连着几处、和谁覆盖范围相近、哪一块是你写得最少的。
- **发现**（≤ 5 条，一行一条）：「『强制同步布局』可以连到《列表滚动掉帧的排查》」「『布局』一节和《前端体系 › 渲染篇》几乎重复」「『只改 transform…』和《动画性能笔记》的说法不一致」「合成层怎么划分，全篇没写」。左边一个和图上同色的点；悬停时图上只亮对应节点、正文对应的字下划；点开才显示理由；行尾只有一个动作：连接 / 并排看 / 记为问题。
- **可以继续想**（≤ 2 个问题）：一键记为问题（来源为本文，KL-043）。
- 底部一行：分析时间、读了多少候选留下几条、「重新分析」。

### 2.3 右：写作（创作模式）

- 右边换成正文编辑器（同详情页的编辑器，可以接着写）。
- **光标所在的那一节决定左边亮哪些节点**；其他降淡。停下来时，左边按这一节重新找本地候选（淡节点，「可能相关」），想让 AI 判断就点图上的「看看这一节」。
- 点节点 →「连到光标处」：在光标处（或选中的文字上）生成 `content-link`；悬停节点时正文里 AI 指出的那几个字会下划。
- 不另开「白板」：左边就是这张关系图（是否允许把它「存为白板」见 §8 F6）。

### 2.4 联动

发现 ↔ 节点 ↔ 正文里那几个字，悬停任一处，三处同时高亮；在任一处建立连接或记为问题，三处同步变成「已连接 / 已处理」（图上那条线变成灰色已有连接）。

## 3. 分析怎么做

**一次分析 = 一次 AI 调用**（槽 `contentInsights`）：

1. 本地候选（不花 token，宽）：本文每个有文字的节查向量近邻，排除已有关系，不排除同项目（重复与矛盾常在同项目里），随机块对 p95 以上，合并去重取前 15 个；每个带标题 › 节、7a 的要点与主张、命中节前 300 字。另带本文所属知识地图主题的名字与相邻主题（用于「位置」那段）。
2. AI 输入：本文（标题 + 大纲 + 正文前约 6000 字，节编号）+ 候选 + 已有连接列表；输出 JSON：`lead`（≤ 120 字）、`finds`（≤ 5：类型、节号、原文片段、候选编号、一行文字、理由）、`gaps`（≤ 2 个未写的概念）、`asks`（≤ 2 个问题）。提示词要求「宁缺毋滥，没有值得说的就少给」。
3. 校验：原文片段必须是对应节里的原文，候选编号必须存在，可连接的片段不能已在链接里；不满足的丢弃。
4. 存主库 `content_ai_insights`（§4），带正文指纹与模型。

**token**：一篇长文约输入 8000 / 输出 900，一张卡约 3000 / 500（deepseek-flash 下不到 1 分钱）。只在你点「AI 洞见」或「重新分析」时调用；正文改动超过阈值（指纹相似度 < 0.7）后打开时提示「正文已改动，重新分析？」，不自动重跑。**不做后台分析、不做全库首轮**（用户主动才算）。

**写作模式**：当前节变化后停顿约 2 秒，用这一节的文字现嵌入一次（本地模型；远端嵌入按条计费很少）查近邻，只更新淡的「可能相关」节点，不调 AI；点「看看这一节」才对这一节做一次小分析（只针对这一节与它的候选，约 3000 token）。

## 4. 存储

主库新表 `content_ai_insights`（随库同步，换机器不重算、不重复花钱；「已连接 / 不相关」跟着走）：

```sql
CREATE TABLE IF NOT EXISTS content_ai_insights (
  content_id   INTEGER PRIMARY KEY,
  schema_ver   INTEGER NOT NULL,
  text_digest  TEXT NOT NULL,   -- 分析时的正文指纹
  result       TEXT NOT NULL,   -- JSON：lead、finds[]、gaps[]、asks[]，每条带 status（open / linked / questioned / dismissed）
  model        TEXT NOT NULL,
  create_time  INTEGER NOT NULL,
  update_time  INTEGER NOT NULL
);
```

重新分析时保留已处理的（按类型 + 目标 + 原文片段匹配），不让「不相关」的重新出现。删除与孤儿清理同 `content_ai_meta`。主库 66 → 67 表，索引不变；移动端不读写。
