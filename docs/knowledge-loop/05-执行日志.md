## 踩坑

### 工程与协作

- **测试里渲染死循环、vitest 一直不结束** → 回调参数每次渲染都是新函数，放进 effect 依赖后 effect 每次重跑，里面无条件 `setState({})` 又触发渲染 → 不稳定的回调用 ref 保住再包一层稳定的 `useCallback`；空结果用函数式 setState 判断后再写。
- **在本机索引上评估向量质量，结果比预期差得多** → 本分支的嵌入修复（补 `<s>`，`pipeline: 2`）不在 master，日常运行的应用写的是缺陷向量；指纹里没有 `pipeline` 字段即是缺陷向量 → 评估前先看 `vec_index_meta.main_content_embedding_fingerprint`；需要可信结果时用 `related.eval.test.ts` 的 `KL_RELATED_EVAL_REBUILD=local` 在副本上重建再测。
- **主进程测试里调真实模型报 `Connection error.`** → vitest 默认 jsdom 环境，jsdom 的 `AbortSignal` 不是 Node 的实例，undici `fetch` 拒绝该 signal（`RequestInit: Expected signal … to be an instance of AbortSignal`），openai SDK 包装成连接错误；内置目录加载也报 `AbortSignal.any is not a function` → 需要联网的评估脚本文件头加 `// @vitest-environment node`（`pi-*.test.ts` 已在配置里走 node）。
- **批量真实库校准有结果但 Vitest 报 onTaskUpdate 超时** → 单个测试长期同步计算阻塞 worker RPC → 样本间 setImmediate 让出事件循环，候选先做字符交集上界预筛，保留原判定口径。
- **代码节误被当作短节合并** → 代码存在节点 code 属性，Slate 文本叶子为空 → 用实际 Markdown 正文字数判断短节，补代码块回归。
- **图谱收敛 3 秒门槛在并行压测时偶发失败** → 同时运行多个 CPU 密集任务 → 性能测量独立运行，最终渲染全量限制 4 worker，不修改原测试门槛；保留首轮失败与重跑结果。

- **sqlite-vec INTEGER 元数据收到 FLOAT / NULL 时拒绝写入** → better-sqlite3 的 JS number 绑定为浮点，且新列不能省略 → `chunk_index` 用 `BigInt` 绑定；历史迁移夹具明确使用升级前的向量结构，不能直接套新模板。

- **嵌套 worktree 里 pre-commit 必挂** → `.claude/worktrees/*` 下 eslint 会同时加载 worktree 与主仓库的 `.eslintrc.cjs`，`react-refresh` 插件重复 → 在 `apps/desktop` 下手动跑 `npx eslint --no-eslintrc -c ../../.eslintrc.cjs <文件>`，再跑 tsc 与相关测试，全部通过后用 `--no-verify` 提交。
- **新 worktree 里 vitest 报找不到 `vitest-canvas-mock`** → worktree 没装依赖，解析到主仓库的 `node_modules` → 在 worktree 根目录执行 `pnpm install --frozen-lockfile`。合入 master 后依赖有变化，要再装一次。
- **任务分支的基线不一定是当前分支** → 用 spawn 开出的任务会话可能从 master 切出；直接合并会把整条 master 带进来（曾出现 31 个文件冲突，原因是移动端日历与闪卡迁移在两条线上各有一份 SHA 不同的版本） → 合并前先 `git merge-base` 确认基线；不是同一条线就只 cherry-pick 修复提交。
- **本会话限定在自己的 worktree** → git 命令不能指向其他 worktree（`git -C`、循环里的复杂 git 命令会被拒绝）；主仓库检出的分支（如 master）也无法从这里快进 → 拆成简单命令；需要动主仓库时，给用户命令让其执行。
- **判断向量 / 聚类质量要用客观指标，不凭截图**：用卡片的 tag 首段当参照，量「8 个近邻里同主题的比例」和「主题纯度」（把向量喂给真实的 `computeKnowledgeMap`）；旧向量基线可以从索引拆分前的主库备份里取。
- **node-llama-cpp 跑 bge-m3 不会自动补 `<s>`**（ugm 词表），CLS 池化会取错位置；新增其他本地嵌入模型时先确认分词器类型与池化方式。
- **改到的存量文件可能本来就没按 prettier 格式化**（如 `flashcard.ts`、`utils/card.ts`）→ 把 HEAD 版本经 stdin 交给 `npx prettier --check --stdin-filepath <文件>` 确认，原本就没格式化的不要整文件格式化。
- **`better-sqlite3` 的 ABI 会随最后一次编译变化**（2026-10-02 起是普通 Node ABI）→ 先看报错里的 `NODE_MODULE_VERSION`：137 用普通 Node（`npx vitest run src-electron`），148 用 Electron 内置 Node；不要自行重编译。
- **主进程测试报 `NODE_MODULE_VERSION 148 … requires 137`** → worktree 里启动过应用（或跑过 Electron 构建）后，`better-sqlite3` 被编译成 Electron ABI → 不要重编译（会影响正在用这个 worktree 跑的应用），改用 Electron 内置 Node 跑：在 `apps/desktop` 下 `ELECTRON_RUN_AS_NODE=1 npx electron ../../node_modules/vitest/vitest.mjs run <路径>`。
- **测试夹具插 `diary_entries` 时 `content_id` 不能填 0**（有外键），填 NULL 或真实正文。
- **会话隔离会拦截正文里含 git 字样的内联脚本** → 文档更新脚本先写成文件再执行。
- **`flashcard.ts` 原本就有大量未按 prettier 格式化的行** → 修改时不要整文件格式化，避免 diff 混入无关改动。

- **会话隔离对命令的限制（迭代 3 补充）**：同一条命令里 `cd` 到别处再跑 git、`for` 循环里调 `git show`、`sh -c` 或管道里间接出现 git、内联 python / heredoc 文本里出现 git 字样，都会被拒绝 → 每条命令只做一件事：先单独 `cd`，再单独跑 git；脚本用 Write 工具写成文件再执行。判断 HEAD 版本是否已按 prettier 格式化：`git show HEAD:apps/desktop/<文件> | npx prettier --check --stdin-filepath <文件>`（写成脚本逐个文件跑），原本没格式化的文件不要整文件格式化。
- **`vitest run src` 会连带跑 `src-electron`**（路径前缀匹配），主进程测试在普通 Node 下报 better-sqlite3 ABI 错 → 渲染端用 `npx vitest run src/`（带斜杠），主进程用 Electron 内置 Node 单独跑；`database-schema.test.ts` 也要用 Electron 跑。
- **`mcpCommandResolver` 测试偶发超时**（登录 shell 解析命令，负载高时超过 5 s）→ 单独重跑确认，与业务改动无关。
- **派生索引的解析规则一变就要升口径版本**：引用索引 `REF_INDEX_VERSION`（`entity-context/ref-indexer.ts`）、白板索引 `WHITEBOARD_REF_VERSION`（`whiteboard-indexer.ts`），存在索引库 `index_meta`。对账只比较 `update_time`，规则变了而正文没变的数据不会重解析。
- **自有 IPC 的模块写库收不到写事件**（如微信读书直接 `ipcMain.handle`，不经 `eventAndHandlers`）→ `onDatabaseWrite` 的订阅方（向量编排、脉络）感知不到 → 写完调 `databaseModule.notifyExternalWrite(事件名)` 补发；事件名要进对应白名单，脉络白名单的守卫测试要显式登记这类事件。
- **微信读书摘录的展开规则一变就要升 `WEREAD_EXCERPT_VERSION`**（`tables/weread-excerpts.ts`，存 `weread_config.excerpt_expand_version`）：保存时只在划线文本变化时重新展开，规则变了而缓存没变的书不会重算。
- **表模块新增对其他表的写入后，手写建表的旧测试会挂**（如 `weread-notebook-table.test.ts` 自建 `weread_notebook`、没有 `excerpt`）→ 夹具改用 `main.sql`。索引队列加了依赖模块（`material-index`）后，mock 了 `tables/*` 的旧测试（`index-recovery-yield`、`main-content-vec-index-status`）也要 mock 新模块。
- **Slate 文本叶子要带 `type: "formatted"`**：只写 `{ text }` 时 `getMarkdown` 会输出 `:tau-node[...]`，测试夹具与代码里构造正文都要按编辑器的形状写。
- **真实库副本做实测**：`entity-context/__tests__/context.eval.test.ts`（`KL_CONTEXT_EVAL_MAIN=/tmp/xxx.db`，会改动副本）、知识地图 `knowledge-map.eval.test.ts`。复制 `~/.editor/data.db` 时连同 `-wal` 一起复制，用完删除。

- **一个 `content_id` 可能对应多个实体**，`entity-search.ts` 的 `locate` 只返回第一个；`cards` / `articles` / `project_item` 的 `content_id` 没有索引。

- **向量 `prefixed_id` 是 `type:实体id`，多块共用，没有块序号**；`content_fts.chunk_index` 有列但从未写入；切块基于 Markdown，不保留与 Slate 块的对应。
