## 接手步骤

1. 读本文「当前状态」与 [03-迭代计划.md](03-迭代计划.md) 里第一个未完成的任务。
2. 读 [04-决策记录.md](04-决策记录.md) 的「已定」部分。**已定决策不要重新讨论**；要推翻，先在 04 记录理由并征得用户同意。
3. 涉及具体设计时读 [02-技术方案.md](02-技术方案.md) 对应小节；涉及产品意图时读 [01](01-模块联动与知识闭环.md)。
4. 动手前扫一遍 [05-执行日志.md](05-执行日志.md) 文末的「踩坑」。
5. 桌面端代码还要遵守根目录 AGENTS.md 与 `D/docs/redesign/03-架构实现指南.md`。

## 同步纪律

- **每次提交**：勾选 03 的任务；在 05 顶部追加一条日志（日期、迭代、做了什么、提交 hash、验证结果、遗留问题）；更新本文「当前状态」。
- **做出或推翻决策**：写进 04，并在 01 / 02 的对应位置同步。
- **踩坑**：写进 05 文末「踩坑」，格式为「现象 → 原因 → 解法」。
- **改到壳层、page 框架、主题或数据协议**：按 AGENTS.md 同步 `D/docs/redesign/03-架构实现指南.md`，必要时在 `D/docs/redesign/DECISIONS.md` 加条目（编号插顶部，合并前重查）。
- **主库 schema 变更**：按 AGENTS.md「数据库 Schema 维护规则」同步校验脚本、`database-schema.md` 与移动端。
