真实编辑按相似度分段的字符改动占比中位（LCS，长文截前 3000 字，只用于对照）：<0.5 段 0.83，0.5–0.7 段 0.36，0.7–0.8 段 0.22，0.8–0.9 段 0.12，≥0.9 段 0.01。0.5–0.7 段里改动占比最低 0.03 的样本是长文在 3000 字之后追加了内容（对照指标截断所致，不是指纹误判）。

**取值：0.7**（`DIGEST_RECOMPUTE_THRESHOLD`，`D/src/entity/text-digest.ts`）。理由：

- 用户要求「日常小改不能让标题跳变」，误重算是主要代价；0.7 比候选 0.8 的误重算少近一半（4.7% vs 8.6%），漏重算只多 1%（3 对，都是 ≥ 300 字长文里的整段改写或改写过半，而长文不用 AI 标题，只影响要点与概念）。
- ≥ 100 字的正文在 0.7 下小改误重算 ≤ 2.1%，大改漏重算 ≤ 3.3%。
- 真实编辑里 0.7–0.8 段的改动占比中位 0.22，多是长文的局部续写；不重算的话，核对时指纹仍保留生成时的版本（只记核对时间），继续累积改动后自然会跌破阈值。

**已知局限：短卡片（<100 字）**。bigram 集合小，改 3 个字就会拿掉 6 个、换上 6 个 bigram，真实 Jaccard 本身就低，不是 MinHash 估计误差；0.7 下仍有 19.9% 的小改会重算（主要是改 3 字、加一句）。短卡片重算成本很低，且其中「加一句」在短卡片里改动占比中位 0.28，本身接近实质修改。是否对短卡片另设规则（如按字数改用绝对改动量）需要用户判断，本迭代按 KL-054 只用单一阈值。

**诊断**（暴力全量比对，排除 KNN 实现问题）：

- 实体均值向量的随机对相似度 p50 0.42、p90 0.76、p95 0.80（只看卡片相近：0.41 / 0.75 / 0.79）；**有双向链接的卡片对相似度中位只有 0.51**，在全部实体里的排名中位 418。KNN 前 50 命中（22 / 60）与暴力排名前 50（20 / 60）一致。
- ai-insights §5.2 的实测（链接对中位 0.717、随机对中位 0.482、97% 落在前 50）是更早一版向量，与当前本机索引对不上。当前向量对「用户手动连接」的区分度很弱：随机对分布很宽，同类文档（版本号命名的项目文档、同一课程的各课）彼此相似度普遍高于真实链接。
- 抽查表里「相关」多是同类结构的文档（如 0.13.0 → 0.11.0 / 0.12.0 …、课程各课互相推荐），没有元信息时也没有要点。

结论：按 13 §5.3「评估达标就上，不达标再考虑 LLM 复核」，**当前不达标**。代码按设计实现并通过单测，是否上线、怎么改，等用户决定（见 05 本条遗留）。

### 3.1 根因：本机索引库是缺陷向量，补 `<s>` 的修复没有用上

- 本机索引库的嵌入指纹是 `{"providerType":"local_python",…,"runtime":"llama"}`，**没有 `pipeline: 2`**。补 `<s>` + 480 token 分窗的修复（`ee7ab9fb3`，05「修复：本地嵌入向量质量退化」）只在本分支，**master 不含**（`bd67379cc` 是把 master 合进本分支，不是反向）。日常运行的应用不带修复，索引一直是 9 月 9 日以来的缺陷向量；上面第一轮评估测的就是它。
- 用户 2026-10-03 要求重建后重测。评估脚本加了 `KL_RELATED_EVAL_REBUILD`：在新索引库副本上按主内容向量队列的口径（`splitSections` + `VecDocumentTable.indexContent`）重新嵌入卡片、文章、项目文档，本地 bge-m3 走本分支的修复管线（`/tmp/kl7-run-related.sh local …`）。
