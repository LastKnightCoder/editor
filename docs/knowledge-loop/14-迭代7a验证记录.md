```bash
  npx vitest run src-electron/main/modules/__tests__/text-digest.eval.test.ts
```

**样本**：

- 快照 47 个：`~/.editor/backup` 里最近 40 个版本 + 2025-05 到 2026-05 间隔取的 6 个 + 当前库，复制到 `/tmp/kl7-digest`。
- 人工改写 1806 对：从当前库的卡片、文章、项目文档里按长度分四层（<100 / 100–300 / 300–1000 / ≥1000 字）各取 60 份，每份做 8 种编辑。改 1 字、改 3 字、改 2% 的字、加一句、删一句、调换相邻段落标为「不该重算」；改写过半、整段改写（这一段占全文 ≥ 40%）标为「该重算」；占比不足 40% 的整段改写无标签。
- 真实编辑 145 对：相邻两个备份之间同一 `content_id` 的正文变化（128 对），以及隔 10 个备份的累积变化（17 对）。真实编辑以正在写的长文为主。

真实编辑按相似度分段的字符改动占比中位（LCS，长文截前 3000 字，只用于对照）：<0.5 段 0.83，0.5–0.7 段 0.36，0.7–0.8 段 0.22，0.8–0.9 段 0.12，≥0.9 段 0.01。0.5–0.7 段里改动占比最低 0.03 的样本是长文在 3000 字之后追加了内容（对照指标截断所致，不是指纹误判）。

**取值：0.7**（`DIGEST_RECOMPUTE_THRESHOLD`，`D/src/entity/text-digest.ts`）。理由：

- 用户要求「日常小改不能让标题跳变」，误重算是主要代价；0.7 比候选 0.8 的误重算少近一半（4.7% vs 8.6%），漏重算只多 1%（3 对，都是 ≥ 300 字长文里的整段改写或改写过半，而长文不用 AI 标题，只影响要点与概念）。
- ≥ 100 字的正文在 0.7 下小改误重算 ≤ 2.1%，大改漏重算 ≤ 3.3%。
- 真实编辑里 0.7–0.8 段的改动占比中位 0.22，多是长文的局部续写；不重算的话，核对时指纹仍保留生成时的版本（只记核对时间），继续累积改动后自然会跌破阈值。

**已知局限：短卡片（<100 字）**。bigram 集合小，改 3 个字就会拿掉 6 个、换上 6 个 bigram，真实 Jaccard 本身就低，不是 MinHash 估计误差；0.7 下仍有 19.9% 的小改会重算（主要是改 3 字、加一句）。短卡片重算成本很低，且其中「加一句」在短卡片里改动占比中位 0.28，本身接近实质修改。是否对短卡片另设规则（如按字数改用绝对改动量）需要用户判断，本迭代按 KL-054 只用单一阈值。

## 2. 标题与要点评估（第 3 步）

**脚本**：`D/src-electron/main/modules/__tests__/content-ai.eval.test.ts`（设 `KL_CONTENT_AI_EVAL_MAIN` 才跑；模型读 `~/.editor/setting.json` 的 `contentMetadata` 槽，没配就失败退出；只写副本）。

```bash
cp ~/.editor/data.db /tmp/kl7-eval.db
KL_CONTENT_AI_EVAL_MAIN=/tmp/kl7-eval.db KL_CONTENT_AI_EVAL_OUT=/tmp/kl7-content-ai-eval.md \
  npx vitest run src-electron/main/modules/__tests__/content-ai.eval.test.ts
```

**样本**：随机抽卡片 100 张、长文（≥ 1000 字的文章与非引用型项目文档）20 篇；模型 DeepSeek / deepseek-flash（用户 2026-10-03 指定），并发 4，每份只调一次（不重试）。

| 轮次 | 成功 | 卡片标题长度（显示宽度） | 卡片平均 token（入 / 出） | 长文平均 token（入 / 出） | 合计（入 / 出） |
| ---- | ---- | ------------------------ | ------------------------ | ------------------------ | --------------- |
| 第 1 轮（按字符数限 24 字） | 119 / 120 | 字符数中位 20、最长 45，超 24 字 33 个 | 406 / 147 | 1784 / 178 | 76253 / 18249 |
| 第 2 轮（按显示宽度限 24 字） | 120 / 120 | 中位 12、最长 23，超 24 字 0 个 | 424 / 146 | 1795 / 181 | 78341 / 18210 |

- 第 1 轮唯一的失败是模型把 JSON 的逗号写成分号；实际队列会再重试 2 次。
- **用户抽查第 1 轮：通过**。超长标题主要是英文术语按字符计长所致，用户裁决「按显示宽度计长」（英文单词、数字串各算 1 字），第 2 轮验证后全部在 24 以内。
- **首轮 token 推算**：本机库（范围内 1298 份正文：674 张卡、159 篇 ≥ 1000 字长文及其余短文）按新公式约 83 万（输入 + 输出）；重度口径 2 万张卡 + 3000 篇长文约输入 1390 万、输出 350 万。设置页估算公式按实测改为「正文字数（截 6000）× 0.6 + 每份 250」。
- 平均约 1.06 s / 份（并发 4）；串行时约 3–4 s / 份，本机库首轮约 1 小时，重度库约 1 天。
