# 白板保存故障恢复

仅供工程排障与处理已经受影响的数据。正常复制、粘贴、导入必须直接完成自动保存，不以用户备份、手动补齐或导出重导作为验收通过条件。

## 保全仍打开的窗口

1. 请用户保持窗口打开，不强制退出、不清缓存、不先更新重启。
2. 在画布空白处右键，选择「导出可编辑白板」，保存 `whiteboard.tau-board.json`。检查文件非空，保留原文件；共享资产不可读取时导出会失败，不把失败文件当作备份。
3. 若「重试保存」成功，重新核对各页内容后再关闭。若仍失败，保留导出文件和原窗口，由工程人员在隔离副本中使用同一套插件验证导入；不要先删除原白板或清理原草稿。
4. 复核所有页面、文字、容器子树、连线、媒体与缺插件占位，再保存、关闭、重开验证。导出重导会为复制内容分配新身份，不保留原白板的协作身份与撤销历史。
5. 不能导出时保留原窗口和当前日志，先核查资源不可读、容量预算、恢复区或插件错误；不得用截图代替可编辑数据备份，也不得承诺日志能重建正文。

## 窗口已经关闭

1. 在操作文件前备份资料库及其 WAL/SHM、`.editor/whiteboard-documents/` 日志目录，以及 Electron 用户数据目录中的 IndexedDB；用户数据目录按实际安装环境确认。不要删除 outbox 或手工编辑草稿身份。
2. 在隔离副本打开同一资料库。完整的同基线草稿会合并恢复并补发，确认主库投影和重开数据后再判定恢复成功。
3. 遇到另一基线草稿或「白板恢复草稿缺少依赖」时停止写入，保留原始文件；检查先前导出的可编辑白板或其它仍存活视图是否包含完整内容。
4. 若只有引用缺失结构的增量，创建数据既不在主库、日志、草稿，也没有完整导出或存活视图，不存在可验证的自动恢复材料。向用户说明已确认保存的修订与无法恢复的范围，不能将重试成功或打开旧画布当作内容完整恢复。

## 从日志定位

1. 搜索 `[whiteboard-edit]`，按相邻的文档/页身份核对粘贴、文件导入和复制页面的入口与完成记录。入口记录只能证明尝试，完成记录证明模型接纳，均不能代替保存回执。
2. 搜索 `[whiteboard-sync]`，按 `documentId`、`viewId`、`batchId`、`revision` 核对「本机耐久保存完成」「缺失依赖已进入草稿队列」与「本机保存未完成」。主库投影仍须对账 `projectedRevision`。
3. `MISSING_DEPENDENCIES` 表示当前增量引用的前置 Yjs 结构或删除记录不在保存端；不表示用户缺少软件依赖，也不能单凭这个错误推断为旧资料库、网络错误或多人协作。
4. 日志没有操作来源时，只能核对成功修订、第一次失败及后续重试；不能从更新字节数或截图断定点击菜单、键盘组合、具体正文或精确用户动作序列。

修复后的验证入口和判据见 [白板批量操作与草稿恢复](/docs/guides/dev-content-verification.md#白板批量操作与草稿恢复)。
