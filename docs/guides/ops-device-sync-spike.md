# 设备同步验证

架构与协议边界见 [个人设备同步](/docs/architecture/device-sync.md)。本手册适用于显式启用的实验入口，不使用真实资料库运行自动化验证。

## 自动化复现

前置：工作区依赖就绪，桌面 Electron 原生 SQLite 可加载，Rust 与平台构建工具可用。

```sh
cargo build --manifest-path apps/mobile/src-tauri/Cargo.toml --offline --features device-sync-spike --bin device-sync-peer
node scripts/spikes/database-sync/app-runner.mjs
node scripts/spikes/database-sync/app-runner.mjs --multi
(cd apps/mobile && TAU_DEVICE_SYNC_NATIVE=1 ../../node_modules/.bin/vitest run src/hooks/__tests__/useEditContent.native.test.tsx src/hooks/__tests__/useEditContent.test.tsx src/hooks/__tests__/useLocalContentDocument.test.tsx src/services/__tests__/content-metrics.test.ts)
```

程序使用临时 SQLite 文件，运行真实 Electron ABI 的 better-sqlite3、共享 Yjs 状态机及移动端 Rust 的存储、投影和 HTTPS 请求代码。最后输出验证结论与临时目录；其中桌面、手机库和冲突副本可独立检查。Rust 验证入口由 feature 控制，不进入默认移动运行路径。

通过判据：99 张商业表的行集合一致，同篇笔记包含两端输入且不重复；历史删除后使用 snapshot 补齐；旧 JSON 不覆盖 CRDT；删除后输入保存为笔记副本；元数据分叉保留两端完整材料；图片部分文件不冒充完成文件；证书不匹配、授权撤销及排序库回退均拒绝。

自动化生命周期使用事件模拟，不能替代 iOS/Android 的系统权限、挂起及进程终止验收。

`--multi` 使用一台 Electron SQLite 协调存储、两个生产桌面连接端及两个 Rust 手机副本，通过本机固定证书 HTTPS 验证。通过判据：六轮交错编辑后 99 张业务表一致、各端输入各出现一次；独立桌面子进程读取磁盘凭据及数据库后可用快照补齐离线输入；电脑和手机图片传至全部设备；同源重配保留本机修改，覆盖使旧队列及提交失效，新会话可继续编辑。桌面生产处理器回归在 `device-sync/__tests__/module.test.ts`，Electron 窗口与会话生命周期接口使用模拟，SQLite 和 HTTPS 使用真实实现。

## 故障与压力复现

```sh
node scripts/spikes/database-sync/app-runner.mjs --stress
TAU_SYNC_STRESS_SEED=11 node scripts/spikes/database-sync/app-runner.mjs --stress
TAU_SYNC_STRESS_SEED=73 node scripts/spikes/database-sync/app-runner.mjs --stress
```

使用临时库注入辅助 JSON、表结构、记录丢失、完整性封套及二进制损坏，并验证开库后继续保存正文。随机调度覆盖 9 个设备身份（包含真实 Rust 存储）、离线交错、响应丢失、进程重启及确认历史删除。独立子进程用 SIGKILL 验证事务提交前后恢复。测试还检查重复提交、迟到响应、失败事务回滚、附件损坏、真实写锁竞争、空间限制、一万行业务增量、大正文与日志折叠后的完整保全。

通过判据：正文输入各保留一次，99 张商业表最终一致；损坏材料被隔离，不清空业务资料；身份恢复仍需核对可信来源；失败保存不虚报成功，解除资源限制后能继续编辑。脚本输出耗时、宿主同步存储调用与测试进程内存，Rust CLI 启动及多个模拟设备在同一进程的成本不能当作单台真机指标。

不要手工删除主库、anchor、隔离表或库外设备身份来“修复同步”。正常损坏由存储入口处理；无法确认凭据时重新配对，仍不需要清空本机资料库。两个客户端都需更新到当前线协议版本。

## 客户端操作

1. 在资料最完整的电脑打开目标库，进入设置 → 同步 →「设备同步」页签。库中已有云端共享正文时先结束共享。
2. 点“开启并协调”，随即生成第一份配对信息；之后每台设备点“添加设备”生成一份。只向自己的设备传递，信息 5 分钟过期，重新生成会作废上一份。
3. 其他电脑或手机接入同一局域网：电脑在“设备同步”页签的“连接已有协调电脑”粘贴并配对，手机在设置 → 同步点“粘贴配对信息”再“配对”；手机允许系统局域网访问。首次建立独立本机副本，无关库保持原样；桌面配对成功后自动登记并切换到该副本。
4. 正常编辑后等待保存确认。连接电脑启动、恢复及窗口聚焦，手机启动、返回前台及重新联网均自动对账；不用手动上传、下载或选择资料库。协调电脑离线时各端仍可本机编辑，恢复后自动补齐。
5. 图片缺失时查看附件待补齐数量。源设备保留文件，网络恢复后继续校验和传输。

桌面暂停只停止局域网连接，耐久正文和待确认修改继续保留。解除某设备配对后，该设备不能继续提交；重新配对同一基线不会覆盖其未确认输入。

退出本轮协调：在协调端或暂停状态的 ⋯ 选择“退出本机协调…”，确认“保存并退出”。完成后当前库窗口重新加载，设备同步回到角色选择；本机普通正文和附件仍可使用，旧同步基线、待确认记录、设备授权和运行缓存不再加载。退出前完整资料库保存在 `backup/device-sync-exit-<UUID>/`，其中保留未处理的冲突材料供检查。

验证重新开启：再次点“开启并协调”，生成新配对信息；旧设备凭据不可继续连接。电脑和手机重新配对后进入独立新副本，旧副本及其尚未上传的修改保留在原设备上。同一轮同步内的普通重配仍复用原副本。

## 明确下载并覆盖

1. 在连接电脑“设备同步”页签的“恢复”区点“下载并覆盖…”，或在手机设置 → 同步的“恢复”组点“用电脑版本覆盖这台手机”。该动作会放弃当前库的本地修改、草稿、撤销记录及待同步事务；两端都在应用内确认一次影响后执行；离线或暂停自动连接时入口不可用。
2. 等待快照下载、校验和安装。此期间当前库编辑暂时停用；失败会解除门禁，不假报安装成功。
3. 完成后打开笔记并继续编辑。正文及标签以协调电脑为准，本地旧字、草稿和缓存不得再次出现；图片按新版本引用补齐。桌面将重新加载持有当前库的窗口，其他库窗口保持原样。

“立即补齐”仍保留并合并本地正文。历史不足自动使用快照也属于补齐，不等同于明确覆盖。

应用级验证入口同时包含 60 次双适配器覆盖、12 次安装中断恢复、旧会话与旧提交拒绝、同基线旧缓存隔离及覆盖后继续编辑。移动端 React 行为测试验证版本切换后的编辑器重建；不执行视觉验收。

原生定向回归将真实 `useEditContent` 节流与队列接入生产 `updateContent` 和 Rust SQLite，覆盖相同修订下旧输入、排队保存、失败重试的丢弃，以及覆盖失败后继续保存；分别走有耐久正文及普通 JSON 保存分支。应用级桥原样转发 generation，验证覆盖后导入正文的首次准备、准备期间覆盖的拒绝，以及两端本机版本表结构/记录异常的独立恢复、材料保全和只读/锁忙/空间限制失败。这些属于 React 调度与原生存储验证，完整页面导航、云端文件替换和真机生命周期仍按客户端步骤验收。

## 真机功能验收

| 场景         | 操作                                         | 通过判据                                             |
| ------------ | -------------------------------------------- | ---------------------------------------------------- |
| 首次配对     | 两端同网，首次允许局域网权限                 | 建立副本，笔记正文和图片能读取，无覆盖无关库         |
| 同篇离线     | 同步共同笔记后断网，两端分别写不同词，再联网 | 两端各词出现一次，全文和结构相同，无库选择弹窗       |
| 手机后台     | 保存确认后回桌面，电脑继续修改，再切回手机   | 自动补齐，已有输入仍保留                             |
| 手机冷启动   | 保存后终止进程，电脑继续修改，再启动手机     | 从 SQLite 恢复待确认状态并自动补齐                   |
| 图片双向     | 两端分别插入小于 25 MiB 的本机图片           | 对方可读取，正文存稳定引用，原始路径不作为接收端定位 |
| 大资料库     | 使用超过 64 MiB 的资料库配对、补齐与明确覆盖 | 文件收齐且完整校验后安装，原有合并与恢复语义保持     |
| 文件断传     | 大文件传输中断网后恢复并重试                 | 未完成文件不会安装，原库与待同步修改保留             |
| 图片断传     | 传图期间断网，恢复后重新进入前台             | 临时文件不展示为完成文件，完整校验后可用             |
| 约束连带     | 删除含数据表引用的正文块，再补齐             | 引用计数、正文待回收队列与两端商业表相同             |
| 元数据冲突   | 同步后离线在两端改同一标题或标签             | 正文仍合并；保留完整库副本，可在电脑同步设置导出检查 |
| 删除后的输入 | 手机离线编辑，电脑删除拥有者，再补齐         | 不复活被删对象，输入保留为笔记副本                   |
| 授权撤销     | 电脑解除手机配对，再尝试同步                 | 显示授权问题，本机已保存资料完整保留                 |

视觉验收由用户完成；自动检查不进行截图走查。

## 排查

- 设备不可达：确认两端同网、电脑应用运行、端口 24721 未被防火墙阻止。依赖系统本地主机名回连；名称解析失败且 IP 改变时重新生成配对信息。
- 配对过期或 TLS 失败：检查系统时钟、局域网授权和配对来源，重新生成信息。不要关闭证书验证或使用任意远端证书。
- 排序库回退：保留手机与电脑现状，检查原整库备份及同步设置中的保留副本，不删除库外排序头记录来强行覆盖手机。
- 结构不一致：先更新两端软件，使主库结构指纹一致；旧库保留，不尝试混合重放不同结构。
- 文件传输失败：确认两端均支持协议 4，保持同网后重试；缺块或摘要不符的文件不会安装。检查可用磁盘与内存，不删除原库或待确认数据。
- 请求超过上限：64 MiB 限制只适用于普通控制消息；快照和大同步批次已自动转为文件分块传输。更新两端软件后重试，不反复强制覆盖。

本协议不搬运聊天 JSONL、独立 PDF 原件、插件安装目录或设置账号。云端提供方的数据库与文件同步继续使用原入口。
