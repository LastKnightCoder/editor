# 代码风格规范

> 判据来自 2026-11 代码风格治理专项的实践提炼。每节先给**通用判据**（任何代码库成立），再以「本仓样板」一行指到仓库内的真实范例。工具怎么跑见 [代码检查与格式化](/docs/guides/development-quality.md)；裁决条目见 [decisions.md](/docs/decisions.md)「代码风格」节。

## 类型纪律

- **边界定型**：数据进出边界（存储、IPC、第三方库）处显式定型，不让 `any` 穿透到业务层。确需宽类型的边界必须标注理由——标注本身就是契约（下一个读者知道这是缺口而非偷懒）。
- **转换可验证**：类型转换的合法性要能被编译器检查——命名映射函数 > 目标断言 > 单断言；双断言（`as unknown as`）意味着两套类型从未对齐，是债不是写法。
- **失败尽早且显式**：理论上不可能为空的值，用显式 throw（带可读信息）守住，不用裸 `!` 把崩溃推迟到更难排查的地方。安全方向（超集→子集）可零拷贝直转；不安全方向先校验必填字段。

本仓样板：`SqliteRow`（`src-electron/main/types/table.ts`）；`packages/ai/src/session/convert.ts`（映射函数与安全/不安全方向分治）；`tables/whiteboard.ts` 事务内显式 throw。

## 规模与结构

- **拆分信号**：文件 >800 行、函数 >150 行、类 >400 行——是「该看一眼」的信号，不是机械红线。
- **行为等价优先**：重组织与抽象分开做。先拆（只移动不改写），真同构（每个实例参数化后逐行一致）才抽象；行为有分叉的模板保持独立。
- **等价要可证明**：拆分附机器校验（从 git 原文与新结构做归一化比对），不接受「看起来没改」。委托转发不得改变求值时机（如多一层 async 跳变 promise 时序）。
- **保住可测性**：跨方法调用走实例派发而非函数直连，测试的 spy/替换语义才不坏。
- **高风险先立护栏**：测试薄弱的核心模块，先补行为测试（锁状态机与时序契约）再动结构。

本仓样板：`collaboration/index.ts`（门面+域文件）、`ChatSidebar/hooks/`（组件域 hook 拆分 + `__tests__/ChatContainer.behavior.test.tsx` 护栏先行）、`host.ts` 的 `makeProviderRegister`（真同构才工厂）。

## 注释

- **信息量标准**：删掉这条注释，读者损失什么？损失「为什么/行为边界」→ 留；损失为零（代码自明）→ 删。
- **过程信息不属于代码**：方案对比、裁决、日期、任务编号、外部文档路径都会随任务退役变成悬空引用——它们归任务文档与 git 历史。
- 注释与代码同语言、随代码更新；过时注释比没注释更糟。

本仓基线：全仓注释/代码约 5%；契约文件可到 30%，业务文件 >15% 通常是 what 注释堆积。

## 命名

- **单一拼写事实**：每个专有词全仓一种拼法（含 camelCase 复合词全小写），新词入库先搜既有拼写。
- **一个概念一个动词**：同域内 create/new/build、fetch/get/load 各取其一；平行实现（跨端/跨层）共用词表，否则是各自造词的开始。
- **持久化 key 是对外 API**：改名即数据迁移——读路径兼容旧 key、写路径用新 key、挂靠自愈回写。运行时内存 key 改名无此约束，但要先确认它真的没被落盘。

本仓样板：`entity/whiteboard-refs.ts` 的 `migrateWhiteboardEmbedKeys`（读兼容迁移）；`Whiteboard` 拼写统一。

## 错误与日志

- **静默 = 把错误转嫁给未来的调试者**。降级可以，必须可观测（warn 留痕）；只有真正的预期路径（如首次运行无文件）允许静默。
- 「查询失败返回空列表」是最危险的降级——它把故障伪装成「没有数据」，调用方无从分辨。
- 错误对象收窄用语言机制（`instanceof`），不靠 `any` 后取字段。
- 日志走统一通道即写即落盘的，直接用；不要为「更正规」另起日志实例。

本仓约定：console 即 logger（两端已代理落盘）。

## 死代码

- **证明死亡的责任在删除者**：圈定（静态分析工具）→ 逐符号复核真实 import → 清零才删。同名不等于同源：别处的同名独立实现、注释提及、mock 字段都不构成消费者。
- **导出面即维护成本**：仅本文件使用的符号不导出；整文件删除前枚举其全部导出逐个验证。
- **不留平行实现**：新建公共实现后，旧副本当批回收——两份「差不多的」实现必然漂移。

本仓流程：`npx knip --include exports` 圈定；三类易漏的真实消费（namespace-spread 访问、按导出名分发的路由、barrel 死但直连活）见 [knip 台账](/docs/notes/2026-11-16-knip-unused-exports.md)。

## 重构验证纪律

- **基线先行**：动手前记录目标测试集的通过数，改后逐文件对比——「没变绿」和「本来就不绿」要分得开。
- **归因**：并行改动共存时按路径过滤区分错误归属；可疑失败用「单跑 + 对照基线」甄别是 flake 还是回归。
- **显式行为变化逐条列出**：「原来会崩溃 → 现在显式报错」属改善，但必须写出来让评审者看见。
- 大小写不敏感文件系统上改名文件走两步改名，提交后用 `git ls-files` 终检（stash 往返会写回旧名）。
