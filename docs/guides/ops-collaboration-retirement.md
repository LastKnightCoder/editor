# 编辑器与白板旧格式退役

本指南规定最后转换版本与下一个新格式版本的操作、删码范围和验收判据，仅覆盖编辑器、白板协作改造。协议与存储事实以[协作架构](/docs/architecture/collaboration.md)为准；正文转换步骤复用[正文转换与本机数据保全](/docs/guides/ops-editor-contract-upgrade.md)，发行组合复用[白板发布检查](./ops-whiteboard-release.md)。自动调度是一次性客户端升级代码，复用既有迁移账；不新建迁移数据库或逐篇转换界面。

本文是执行清单，不代表真实用户数据已完成转换或发行已放行。两个版本的实际版本号在发行时确定，不以仓库 package.json 或安装人数推断。

## 两个版本的职责

| 版本             | 必须完成                                                                                             | 不做什么                                                     | 放行判据                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| 最后转换版本     | 自动扫描并升级旧正文与旧白板；处理各设备本机遗留；完成纳入新版本支持范围的资料库、共享房间及配置转换 | 不静默丢弃异常或跳过保全；不将扫描结束当作全部转换成功       | 转换功能通过下述验收；切换下一版本前，存量数据和未完成转换已逐项核实 |
| 下一个新格式版本 | 拒绝旧格式输入；删除一次性转换、旧读取兜底及对应 UI、命令、导出和测试；保留当前格式功能              | 不在普通入口补回隐式转换；不清空未同步数据或自动删除保全材料 | 旧输入拒绝测试、当前功能回归、删码消费者检查全部通过                 |

安装新客户端后桌面后台自动保全并转换正文与白板，用户不逐篇确认；移动端不执行首次旧格式转换。安装本身不等于后台转换已经完成。本机缓存结构自动升级不能代替内容转换。使用现有入口和发行验收记录核对，不为此新增产品能力。

## 最后转换版本：执行与验收

1. 固定实际客户端、服务、SDK 和所用插件的发行组合，确认中心已发布 `LEGACY_PLUGIN_UPGRADE_VERSIONS` 对应版本。正式客户端先自动更新官方插件和补齐缺失的内容插件，再建立启动快照、转换正文与白板；验证断网自动重试、更新中断恢复，以及已达下限时离线启动。验证自动启动、连接补扫和中断续做可用。保留这个版本的可获取安装包及使用说明，供跳过升级的设备处理旧数据。
2. 核对要继续使用的资料库和共享房间，包括不常打开的正文、旧白板和仍被正文引用的隐藏页。确认后台扫描覆盖全部内容；共享正文由所有者客户端自动转换。打不开、转换失败或未确认的数据不能记为完成。
3. 在各持有设备核对旧私有真身、输入草稿、离线编辑和未确认队列。先完成现有保全，再接收新基线；不能仅凭服务器已有新正文，就清除其他设备的旧缓存。
4. 处理未完成转换：远端结果未知时查询原回执；已提交或主库已安装的操作续做，未安装且允许取消的操作走原取消流程。取消和过期终态不复活，不把日志删除当作转换成功。
5. 检查转换后的正文、契约、白板元素、附件与引用。未知插件及源码冲突保留下来的原始载荷继续保留；缺失附件明确记录，不宣称已完整取得。旧私有真身不得自动公开。
6. 确认旧资料库和旧备份的后续使用方式：下一个新格式版本拒绝旧输入，需先在最后转换版本或其配套工具中处理。不要求改写所有归档备份，也不自动删除它们。

切换下一版本前，在原发行验收记录中写明实际覆盖的资料库、共享房间和设备，以及未处理项。无法联系的旧设备不能视为已完成；它以后接入时仍须先处理本机旧数据。不要把“所有人安装了新版”作为数据验收结果。

| 场景                               | 必须观察到的结果                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 插件前置更新                       | 不要求手工更新插件或二次重启；新契约就绪后才转换；更新失败保留旧包和正文；既有停用意图不被覆盖         |
| 旧正文、旧白板转换                 | 普通界面没有逐篇确认，后台先保全再安装；转换后正文与契约对应，白板页面、连线、演示引用和隐藏页保持正确 |
| private blocks 与旧插件附件        | 本机真身及可取得附件保全；共享侧不公开私有内容；缺失资源明确列出                                       |
| 准备失败、安装中断、响应丢失与重启 | 原数据仍可用或已保全；按原操作续做；不重复记引用，不用旧候选覆盖转换后的输入                           |
| 本机旧白板取消与重试               | 主库未安装时可按既有规则取消；主库已安装时续做；旧的提前提交记录按既有修复路径处理                     |
| 取消、过期和远端已提交             | 终态不复活；远端已提交不能回退为取消；保全材料不随取消删除                                             |
| 移动端接收与迟到草稿回执           | 保全失败不覆盖；旧代次增量不混入新基线；迟到回执不清除较新的草稿                                       |

## 下一个新格式版本：删除清单

服务备份旧元数据兼容、旧端点和设备身份合并各有独立消费者，不因本次内容转换自动获得删除条件。若同批退役，先确认既有备份使用边界和身份迁移结果，再删除旧分支；当前备份恢复、回执与身份认证继续保留。不得把这次清单扩大为其他子系统的历史兼容清理。

## 不随本次退役删除

- 契约字典、正文层契约读取和转换边界、插件 `textFields/resources` 声明。
- 插件后续数据版本升级能力、精确版本渲染与导出。某个历史版本的实现只有在所支持数据与输入不再需要它时才可单独删除。
- 稳定节点与文本身份、同步代次和基线、操作回执、未确认队列、原事务及结果未知时的重试。
- 当前格式需要的保全、草稿确认、附件持有、引用计数和延迟回收。
- 已保存的保全材料、未知插件原始载荷和冲突原文。转换器退役不是删除这些数据的依据。

## 新格式版本验收

1. 用旧正文、旧白板、旧资料库、旧缓存和旧格式导入样本验证：入口明确拒绝并指向最后转换版本；不部分写入，不悄悄清空，不回退到旧解析。旧服务备份按已声明支持边界处理，不借缺失元数据绕过当前校验。
2. 服务端确认旧协议发布、更新和受控导入均不能重新引入旧文档；已有支持范围内的房间可由当前客户端继续读写。拒绝旧协议不依赖仅校验客户端安装版本。
3. 验证当前正文创建、保存、复制、日记、待办、摘录及索引入口，契约不重新传入无关业务层；原事务和复制契约仍在。验证 Markdown 代码块及 Magic Move 导入导出未因删转换器回归。
4. 运行现有并发、断网重连、取消/过期、回执丢失、退出保存、白板删除与引用计数回归；验证插件当前版本升级仍可执行，必要保全失败仍阻止覆盖。不重建已经删除的恢复包导入或独立资料库恢复 UI。
5. 用 `rg` 核查已删除符号的生产消费者为零；区分保留的拒绝测试与当前功能，不能仅按 `legacy`、`migration` 字样批量删除。运行受影响包的行为测试、类型检查和构建，以及已有边界检查。
6. 若实际修改主库表或索引，执行 `pnpm db:schema:build`、`pnpm db:schema:check`，同步 schema 数量断言与内部数据库字段文档；只改文档时不执行数据升级。
7. 同步协作架构、正文操作指南和白板发行检查中已经消失的旧入口，运行 `pnpm check:docs`。源码测试通过与真实数据转换结果分别记录，不互相替代；设备视觉验收仍由用户完成。

## 本指南退役

两个版本的工作完成、历史路径删除且现有操作指南不再依赖本流程后，将支持的新格式及旧输入拒绝边界留在协作架构，最后转换版本的获取与使用步骤留在对应操作指南；删除本指南并更新文档索引。此清单不成为常驻迁移机制。
