# 插件体系开发规范与验收

本规范补充仓库 AGENTS.md，不替代桌面、数据库和领域包的现行规则。每次提交同时交付行为、验证证据和文档更新。

## 实施规则

生产核心和协议使用 TS 并由桌面/测试共用；scripts 仅承担构建、启动、打包和验收编排，不发展第二套生命周期、存储或运行协议。插件与宿主同环境执行，不引入 OS 沙箱或进程隔离承诺；模块归属见 [packages/plugins](/packages/plugins/README.md)。

1. 先读直接依赖、类与属性上下文，再做小范围修改；避免按目录批量搬迁。
2. 每个公开能力必须有实际消费者、执行端实现、输入校验和失败语义；不先铺设未接线 SDK。
3. 插件不得依赖应用内部 store、私有路径或任意 IPC；宿主适配器可以调用内部实现，但不能把内部对象交给插件。
4. 导航框架和设计系统保持零业务依赖。框架新增机制必须通用且有测试；既有 Page 或主题约定变更同步桌面分篇与 decisions。
5. 服务依赖、用户权限、运行位置分别声明；不通过 TypeScript 的可见性模拟安全边界。
6. 动态注册归属插件作用域，失败按逆序回收，清理幂等，单个清理异常不阻断其他清理。
7. 数据和事件绑定工作区会话与实例代次；运行时校验不能只依赖调用方自律。
8. 原 ID、公共引用和数据版本保持可解释。迁移失败不放行，不能把删除旧数据当作清理完成。
9. 普通属性、日志、错误、构建和测试夹具均不得包含真实凭证。
10. 注释只解释代码事实；方案取舍与过程记录进入文档。
11. 面向作者的产品/领域 API 从 `@tau/plugins` 导入，UI 组件从 `@tau/ui` 导入；不要求作者导入内部编辑器包。宿主适配与内部业务不受此作者约定限制。

新增根导出时检查支持范围、命名冲突、类型声明和加载副作用；禁止一并导出 PluginHost、Node 文件适配器或内部 store。作者示例只消费上述两个 Tau 入口，不依赖私有 workspace 路径或未发布包。

编辑器插件只通过静态 editorExtensions/editorCodecs/editorMetrics 装配；验证只读、命令与菜单、序列化、未知节点保真及宿主内容快照的生效边界，不恢复运行期动态注册接口。

设置分区必须在真实设置承载中覆盖注册、保存、停用、重新启用与宿主重建；读写失败不能覆盖旧值或伪报成功。额外覆盖迟到请求、工作区隔离、相同局部 ID、单项注销、渲染错误、关态不挂载和 Portal 清理。当前采用即时保存，不将其验收扩大为草稿守卫或跨窗口同步保障。

统一管理的验收须通过实际管理按钮执行停用/重新启用，确认宿主详情及启用入口常驻；没有设置贡献的插件也可管理，打开管理详情不得自动激活。多个设置分组仅在插件详情内展示，旧 open 精确定位合同必须保留，不另建启停操作。

标准 fetch 必须验证 RequestInit/Response、非 2xx、bodyUsed/clone、Headers、多种 Body 格式、请求/响应流和 signal；通过真实 Electron IPC 验证，不能只有类型和模拟 Response。旧 nodeFetch 的消费者必须清零，不保留兼容层。测试区分本地网络、真实 Electron 与真实账号联调，未运行真实账号不得宣称远端已验证。

移除开发目录只解除登记并清理宿主托管的副本与缓存，不删除作者源码或构建目录；生产卸载只删除宿主托管的安装文件，不能把 manifest 路径当作任意删除目标。

## 验证矩阵

本表是最终需覆盖的范围，不是已有测试覆盖声明。独立进程不等于独立包，registerTrusted 不等于安装授权，unregister 不等于卸载，重新启用不等于代码重载。

新增插件能力必须用仓库外项目、实际 SDK 包产物和真实 Electron 加载验证，证明类型闭包、React 单例、UI/CSS/资源解析成立；覆盖异步挂起、旧代结果、持久启用意图、重启/切库和移除包；区分构建失败、替换失败与不可恢复副作用，检查完整产物、资源回收和模块缓存。每项保留对应复现命令，不以 mock、源码导入或历史测试替代新增链路验收。

| 类别       | 必须验证的行为                                                       |
| ---------- | -------------------------------------------------------------------- |
| 加载与身份 | 无效 manifest、冲突 ID、非法入口和不兼容版本被拒绝；受限端验证 owner |
| 权限       | 未声明、未授权、撤销后、间接命令与网络旁路不能越权（对外开放前）     |
| 生命周期   | 激活失败回收、重复停用、超时、旧回调、监听器残留                     |
| 工作区     | A 切 B、关闭重开同名库、切换期间迟到写入、窗口重复任务               |
| 数据       | 幂等、事务回滚、游标提交、分页、引用保留、迁移失败和恢复             |
| 页面       | 双注册表一致、实例退出、历史恢复、未保存守卫、设置卸载               |
| 编辑器     | 只读、撤销重做、协作、序列化、未知节点保真                           |
| 数据库产品 | 字段与视图缺失、计算错误、查询边界、操作历史                         |
| 白板       | 多实例、手势取消、隐藏与销毁、撤销重做、未知元素                     |
| 产物与重载 | 产物不完整、模块缓存、CSS 回收、资源定位、重载失败                   |
| 更新与分发 | 解包路径、发布身份、权限升级、数据降级拒绝、恢复与安全启动           |

安全测试必须包含直接绕过 SDK 的尝试，不能只测试包装方法返回拒绝。资源泄漏和重载测试检查监听器、任务及注册计数，不以「界面还能点」为通过依据。性能指标在对应工作开始前记录基线和环境，不凭空指定通用毫秒目标。

## 命令与执行记录

以下是仓库已有命令或调用方式，执行时按变更范围选择，记录实际退出码与范围：

```sh
git diff --check
pnpm check
pnpm --filter desktop exec vitest run <本次相关测试路径>
pnpm --filter desktop build
node scripts/check-database-boundaries.mjs
node scripts/check-whiteboard-boundaries.mjs
```

测试路径必须先从代码中确定，尖括号仅表示调用模板，不能原样执行。修改共享包时检查实际 package.json，追加该包及受影响端的类型、行为和构建命令，不假设所有包都有同名脚本。

桌面运行代码变更须完成类型检查、相关行为测试、构建和必要结构检查。完整 desktop build 包括原生打包步骤，环境或签名缺失导致未通过时必须准确说明，不能把仅前端构建写成完整桌面构建成功。必需门禁未完成不得标为可交付实现。

schema 变化另执行 `pnpm db:schema:build`、`pnpm db:schema:check`，必要时 `pnpm db:schema:prepare`，同步数量断言和内置数据库字段文档，并运行字段对账测试。迁移涉及共享模型时必须验证受影响客户端的读取和拒绝策略。

纯文档提交检查格式、链接、引用路径与 diff；不为文档运行无关业务构建，不把未执行的测试填成通过。视觉验收由用户进行，记录不阻断架构清理的外观问题。

## 提交流程

1. 检查工作区和已暂存内容，只纳入本工作单元的文件；保留用户其他修改。
2. 调查后定义本提交的可用行为、验证范围、恢复方式和消费者清理边界。
3. 实现并完成必需检查；新发现的阻断失败先修复，不用下一次提交补救。
4. 行为变化同步架构文档与相关指南，取舍变化更新 decisions。
5. 检查最终 diff，使用项目 conventional commit 风格提交，不跳过 hooks，不自动推送。
6. 核实提交后状态，向用户报告提交 ID、结果、验证限制与下一步。

## 恢复与数据保护

无持久化变化的提交应能通过 revert 恢复行为；持久化变化必须单独说明恢复前提、备份位置类别、兼容读写范围与必要的前向修复。不承诺所有 schema 变化都能靠代码回退恢复。

临时适配若确有必要，应记录消费者、退出条件和删除单元；每一步只保留一条有效写入链，不双写两套事实源。消费者清零后同批删除旧实现，不能用永久兼容层掩盖迁移未完成。

## 界面语言接入

1. 为插件维护独立的 JSON 词典，以 `defineI18n` 声明资源并赋给 `definePlugin` 的 `i18n`。宿主提供当前语言和运行时，插件负责自己的词条及回退语言。
2. 对支持翻译的声明字段使用 `messages.ref(key, values)`；动作标题、Notebook 输出标题/说明、侧栏固定菜单/动作标题、设置标题/说明和 Provider 表单的显示字段可按需接入。普通字符串沿原快照约定；不要靠反复注册、重连或执行动作刷新文字。
3. 自定义 React 界面使用插件的语言 Hook。将订阅留在显示组件，不让语言进入编辑器、请求、计时器或未保存草稿的重置依赖。
4. 用户创建的侧栏子项标题、AI plan、正文、ID、字段 key、选项 value 与默认值保持数据原意。设置标题目前还参与新建账号的默认名称；需要保持原默认命名的插件先保留该标题，逐步迁移纯展示字段。未知服务诊断不按文字猜译。
5. 静态模板在 `template.i18n` 中声明 `fallbackLocale` 和 `resources`（locale → 相对 `template.root` 的 `.json` 路径），字段标签/说明/占位与选项标签用 `{ "kind": "i18n", "key": "词条键" }`。把词典复制进根目录并纳入原完整性摘要；这些UI词典不作为站点资产导出。模板必须满足 SDK 的 `TEMPLATE_I18N_MIN_APP_VERSION`；客户端版本与 UI 库版本分别管理。完整文件示例见 [模板起步仓库](/plugins/tau-blog-template-starter/README.md)。

检查声明是否由实际 UI 解析，切换语言沿用原注册与用户值。普通文案迁移以类型/静态检查和构建为主，只有接口、状态或数据契约变化才维护针对性测试；不锁文案或样式。
