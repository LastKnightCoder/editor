# 面向读者的文档写法

适用于官网使用文档（`apps/website/content/docs/`）、插件开发文档（`plugins/tau-plugin-template/docs/`、模板 README）、插件 README（插件中心详情页）和更新日志。动笔前先确认读者是谁、他带着什么问题来。

## 读者

| 文档         | 读者                                           | 他们带着什么来                                                                                      |
| ------------ | ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 使用文档     | 第一次接触 Tau 的人                            | 想知道 Tau 能帮自己做什么；或者有具体目的（记读书笔记、管待办、写长文、做知识库、发博客）来查怎么做 |
| 插件开发文档 | 会 TypeScript/React、不了解 Tau 内部的插件作者 | 第一次做插件，要先跑通再知道下一步；或者带着任务查某个接口                                          |
| 插件 README  | 在插件中心挑插件的用户                         | 这个插件能干什么、怎么开始                                                                          |
| 更新日志     | 正在用 Tau 的用户                              | 这一版我能感受到什么变化                                                                            |

## 判据

- 每篇首段回答「这对我有什么用、什么时候用」，不罗列界面元素。
- 按读者的任务组织（想做 X → 这样做），不按界面从左到右巡览按钮。参考篇也可以用「你想做的 → 怎么做 / 可以这样说」的表。
- 开头给的例子贯穿全篇，后文接着用它，不要只出现一次。
- 篇末用一两句话指向下一步该读的篇目。
- 只写当前能力。不写版本号（「0.x 起支持」「需要较新版本」「最低版本」）、迁移、演进史、旧客户端兼容、「首期/后续/目前/暂时/尚未接线」。做不到的事直接说做不到，并给替代做法。
- 不写内部实现：宿主、主进程、同步协议、codec、R2、来源谱系、回调调度一类词不出现在读者文档里。插件作者文档里平台差异集中写在「多端适配」，其他篇最多一句话链接过去。
- 不写元叙述和报数：「本篇介绍」「下面按这个顺序」「有八种」「三个操作」都删掉，结构交给标题和列表。
- 用界面上的叫法。使用文档里技术名词（token、SSE、stdio、向量、TTS、Bucket）要么换成白话，要么第一次出现时用一句话解释它对读者意味着什么。
- 插件作者文档里的示例必须能照抄运行：import、权限、manifest 片段齐全，签名与当前 SDK 一致，遵守文档自己的规则（如 Tailwind 前缀、网络请求走 `context.network`）。先给最小示例，再展开参考细节。
- 同一个事实只在一篇里写全，其他篇放链接。

## 术语

| 用                                                                               | 不用                           |
| -------------------------------------------------------------------------------- | ------------------------------ |
| 资料库（装全部内容的那一份数据）                                                 | 笔记库、工作区、Tau 库、数据库 |
| 数据库（表格/看板/画廊视图的功能）                                               | 资料库                         |
| 待办的分组在待办篇里叫「待办项目」（界面按钮仍是「新建项目」），文档树叫「项目」 | 不加区分地都写「项目」         |
| 手机                                                                             | 移动端                         |
| Tau                                                                              | 宿主、应用（指代 Tau 时）      |
| 卡组（闪卡）                                                                     | 牌组                           |
| 《深度工作》                                                                     | Deep Work                      |

术语以界面为准：界面改名时同步改这张表和正文。

## 样板

- 使用文档：`diary.md`（一句话讲清何时用、用真实句子示范）、`notebook.md`（一个例子贯穿全篇）、`database.md`。
- 插件 README：`plugins/tau-plugin-weread/README.md`（一句话价值 → 三步开始 → 可以做什么）。

## 检查

- 使用文档：`pnpm --filter @tau/website test`（目录、示意、站内链接对账）。
- 插件开发文档：同上（`developers/manifest.test.ts` 对账目录、标题与链接），模板目录内 `pnpm check`、`pnpm build`。
