# 可复用子 Agent

## 身份与执行

桌面子 Agent 由主进程 `pi-subagents` 管理，执行复用 `PiSessionHost`，不另建模型协议或工具执行器。`agentId` 同时作为子会话的持久 pi ID；每次提交消息创建独立 `runId`，宿主登记 ID 在重建时变化。

`title` 是子 Agent 的职责名（如「校对」「调研员」），经 `pi-subagents:inherit-tools` 写入子会话工具上下文的 `agentTitle`，作为它改正文时的署名；身份色按职责名派生（`services/agent-identity`，`agent:<职责名>`），对话头像、正文修订痕迹、光标与在场头像同色。用户消息里「@职责名」时，父 Agent 把事情交给同名子 Agent：本对话已有同名的用 `send_agent` 继续，没有就以该名为 `title` 创建（规则写在 `spawn_agent` 的说明里）。

同一子会话串行处理消息，跨子会话共享三路并发。输入先作为队列记录保存，轮到执行时才交给 pi；后续任务不会提前进入当前任务上下文。失败、取消和中断保留会话与此前历史，后续 `send_agent` 建立新执行，旧终态不变。子会话使用父的模型、有效工具、工作目录和原数据库；工具定义变化时重建宿主并恢复同一份历史。

不同父会话按轮转取得执行机会，调度通过合并的事件循环任务让出主线程；队首提交失败不阻塞后续任务。重复请求身份只复用相同输入、模式与目标的执行，不同载荷明确拒绝。

## 工具契约

| 工具                                      | 调用者与行为                                                                                    |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `spawn_agent({title,message,mode})`       | 父创建子会话并提交第一条消息                                                                    |
| `send_agent({agentId,message,mode})`      | 所属父向原子会话提交新消息，忙时排队                                                            |
| `wait_agent({agentId,runId?,timeoutMs?})` | 所属父等待一次执行；缺省 runId 在入口固定为最新已接受的执行；缺省等待 30 秒，范围 0–300000 毫秒 |
| `cancel_agent({agentId,runId})`           | 所属父取消指定执行，不删除会话                                                                  |
| `send_parent({message})`                  | 子会话报告进度；收件人由宿主绑定                                                                |

`mode=sync` 等待终态，`mode=async` 立即返回身份。同步/异步属于一次执行，不属于会话。等待超时不取消执行。一次性、无持久会话的父入口只接受同步任务，避免入口释放后遗留无法续跑的父宿主；学习项目一次性生成提示显式采用同步模式。浏览器伴读的 hostToolsOnly 入口不装配子 Agent 工具。

父身份、数据库和授权不接受模型指定。子会话只装配 `send_parent`；操作入口还核验宿主的 childAgent 身份，重建和复用不会解除禁止继续派发的约束。

MCP 管理页与输入框快捷面板在「内置」分组展示「子 Agent」，目录包含四个父工具与标注「仅子会话」的 send_parent，并参与搜索与工具总数统计。该组沿用宿主工具常开只读语义，不经 MCP provider 开关改变运行。名称、说明、角色与参数 schema 的唯一来源为 `apps/desktop/src/agent/subagentToolCatalog.ts`，主进程装配与面板共同消费。

## 状态与错误

执行状态为 queued、running、completed、failed、cancelled、interrupted。`agent_settled` 仅表示结束，最终结果由 pi 最终消息、取消意图和宿主生命周期共同确定；单次工具报错不直接等于整个执行失败。

失败只提供实际 `error.message`，没有底层详情时明确说明，不生成错误分类、重试建议或等待时间。子会话关闭会话级自动重试，运行时不自行提交继续消息或重放工具；是否继续由父 Agent 调用 `send_agent` 决定。终态保存失败报告保存故障，不发布原执行成功；重新打开按持久未完成记录标记中断。

## 权限与用户交互

`PiPermissionScope` 共享父子会话级授权，键含工具名称、来源、执行身份、参数契约与风险。单次审批只作用于对应请求。子宿主释放不清掉父授权；父宿主释放会回收子宿主，重建与进程重启不恢复旧授权。执行时再次核验父工具仍然启用。

需要等待用户审批时，在等待前后都核验父工具的启用状态和取消信号，旧审批不能放行等待期间已停用的工具。必要工具桥继承失败会释放半成品子宿主，下一次明确发送重新建立；可选状态通知失败不改变执行终态。

`ask-question` 和权限审批由已有 `PiSessionInteractions` 持有请求、等待与用户响应，仅向 UI 发布快照；不写父消息收件箱、不触发父续跑、wait 不返回 needs_user。用户回答或审批后继续同一 runId；跳过工具审批不等于自动回答问题。

### 界面

- 任务卡：消息里同一工具组内连续的 `spawn_agent`（或 `send_agent`）合成一张卡，一行一个子 Agent（身份色头像、标题、耗时、状态、活动行）；待回答问题与待审批工具在行下直接作答，失败或中断显示 `error.message`；结果正文不在卡片上摘要，只在详情里按消息渲染。身份取工具输出，`mode=sync` 等待期间取工具发布的部分结果；拿不到身份或调用失败时仍是普通工具行。
- 对话顶部常驻入口：本会话有子 Agent 时显示汇总胶囊（待处理 / 工作中 / 已结束），点开按状态分组列出全部子 Agent，可定位到派发消息；列表只导航，不在其中作答。
- 详情：对话页为右侧非模态抽屉（左缘拖拽调宽，宽度本机持久保存），辅助栏为栏内下钻（「返回对话」或 Esc 返回）；两者共用正文（历史与当前响应、待处理交互、结果或错误、执行记录）与停止 / 取消排队按钮，Esc 经页面浮层仲裁。打开哪个子 Agent 按父会话记在 `focusStore`。
- 标题栏：本窗口任何子 Agent 有待处理项时显示「待你处理」，弹层内就地作答；对话不可见时另显示进行中的数量。
- 数据：对话容器经 `SubagentParentContext` 提供父对话身份（库名 + 对话 ID + 会话键），列表与详情查询带上它；父宿主已空闲回收或应用重启后，主进程从持久记录读取该对话的子 Agent（此时没有子宿主，只读）。列表视图带 `activity`（执行中子会话最近一次工具调用或模型输出，主进程按子会话事件更新并推送变更）；执行记录的 `startedAt` 是离开排队的时间，耗时从这里算起。读取使用 React Query；详情的流事件只在打开时触发有界刷新，不用组件挂载控制执行。

## 父消息与续跑

进度与终态先保存到父收件箱。进度只写入父上下文，不单独启动推理；异步终态可触发正常空闲父会话续跑。父运行中或等待用户交互时延后投递，在宿主空闲边界再次检查。

投递与用户 prompt 共用宿主在途操作门闩，父会话不并行运行。消息进入 pi 自定义消息（subagent-message），注明子任务来源，不伪装为用户指令。工具结果回执与自定义消息 ID 共同防止 wait 和自动通知重复投递；父上下文已有回执时只补编排确认。投递期间新结果到达会再次排空。

新一轮执行在进入异步准备前同步占位，避免多个请求互相占位后全部被拒绝；运行中插话仍走原操作入口。同一执行可以有多个等待者，超时或取消只释放该等待者自己的占位。状态观察回调失败不回滚已提交结果。

每次执行保存父分支锚点及任务代次。停止父任务或改历史推进代次并取消运行及排队任务，旧通知不得唤醒。取消一个排队任务不影响该子会话正在运行的其他任务。父有后台子任务时保留宿主与工具环境，但不因此将父显示为正在生成。

持久化暂时失败也必须中止本机活动执行，并使被取消的排队任务失去执行资格。停止代次保留在当前进程，后续成功提交一并落盘；写盘始终不可用时，不承诺跨进程保留这次停止决定。

## 持久化与宿主边界

本机 `subagents/<父身份摘要>/state.json` 保存子会话元数据、执行队列、最终结果摘要及投递记录，经临时文件、刷新和重命名提交；父身份由数据库与持久父会话 ID 组成。子历史为同目录 `<agentId>.jsonl`，保持 pi 原格式，不复制完整聊天正文。该本机目录不参加现有主聊天会话同步，不让其他设备自动接管运行。

候选状态用局部 Immer 实例按修改复制，写盘成功后才替换内存事实，未改变的更新不写盘；不改变应用其他 Immer 使用者的冻结策略。磁盘提交仍是完整快照，较大历史与批量提交会增加主进程 I/O 开销。

父对话删除时停止其子任务、释放子宿主并删除整个编排目录（含子会话历史）。应用重启把未完成执行标记为 interrupted，不自动执行排队任务；再次发送消息才启动新执行。窗口销毁或执行宿主失效会中断子任务，本实现不承诺关闭应用后继续执行。页面切换不影响执行。内存子宿主可空闲回收，再次使用从原历史加载。

普通业务工具仍在原执行环境，通过 `piToolBridge` 接收父工具上下文的快照；子会话单独持有该快照，页面注销不重新按名称查找后来注册的工具。会话释放注销对应快照和调用。

## 文件职责

- `apps/desktop/src-electron/main/modules/pi-subagents.ts`：BACKGROUND 装配与窗口归属校验的 UI IPC。
- 同级 `pi-subagents/service.ts`：身份、消息提交、队列、并发、等待、取消与父收件箱。
- `repository.ts`：按父身份持久保存编排记录与重启中断标记。
- `host.ts`：pi 宿主、工具继承、上下文复用、终态采集接线、投递与续跑。
- `state.ts`：实际运行结果归约；`tools.ts`：模型工具定义与参数校验。
- `pi-permission-scope.ts`：父子共享授权事实。
- `apps/desktop/src/types/subagent.ts`：跨进程契约；`commands/subagents.ts`：就绪保障与 IPC。
- `features/chat/subagentQueries.ts` 与 `features/chat/components/subagents/`：只读查询；任务卡（`SubagentToolGroup` / `SubagentTaskCard`，经 `MessageItem` 的 `renderToolGroup` 接入）、顶部入口与详情容器（`SubagentPanel`）、详情正文（`SubagentDetail`）、标题栏待处理（`SubagentAttention`）与交互复用（`SubagentInteractions`）。

旧 subagent_research 已移除执行注册、调度和渲染内存 store；保留历史结果的数据契约与只读渲染，不在历史查看时恢复执行。
