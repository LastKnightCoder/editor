# AI 会话与记忆

> pi 聊天运行时、工具审批、对话工作目录与个人助手记忆；子 Agent 见 [subagents.md](/docs/architecture/subagents.md)。

## 对话工作目录

可选目录只属于主对话（对话页 / 停靠栏），按对话记录在 `chat_session.cwd`。设置「工具权限 → 工作目录」的 `agentWorkspace.defaultCwd` 只决定新对话：草稿首轮登记时写入所选或当时默认目录，之后改默认不影响已有对话；目录为空的对话跟随默认。取值统一走 `useChatSessionStore` 的 `resolveChatCwd` / `useChatCwd`，ChatContainer 每轮传给 `ensureChatSession`（非主对话传空）；cwd 变化与模型变化一样按会话文件重建宿主，子代理经工具上下文的 `cwd` 继承。宿主请求带 `chatScope`，主进程 `pi-workspace.ts` 的 `resolveSessionCwd` 据此解析：学习项目对话固定在资料 Markdown 目录（`vibeLearningMarkdownDir`），其余空或不存在的目录落到应用数据目录（`~/.editor`）；`pi-session:workspace-info / workspace-branches / workspace-checkout` 提供仓库分支读取与切换。输入框上方的 `WorkspaceBar`（ChatContainer 的 `composerAccessory` 插槽，数据走 `features/chat/workspaceQueries.ts`）显示目录与分支，对话进行中禁用切换。浏览器扩展对话不传 cwd。

## pi 聊天运行时与工具审批

聊天操作区区分「重试」与「重新生成」：末尾用户问题尚无正文、工具调用时原位重试，复用原用户 entry（含附件与展示信息），不增加问题版本或分支。主进程重新核验当前投影，以隐藏的 `desktop-retry` 自定义消息触发 pi 完整运行与 settled 流程，空失败回答通过 context_edit 省略，系统提示仍取当前配置。上次在用户消息写入前失败则正常提交一次。已有正文、工具调用或后续追问时仍回退重发并保留旧版本；编辑重发不走失败重试。

项目视频笔记（`features/projects/components/ProjectView/VideoNoteView/`）是「左看右记」两栏：左栏 `MaterialColumn` 为播放器 + 跟随转录，右栏 `NotesStage` 笔记常驻（多篇用栏头胶囊切换，暴露 `insertQuote` 把转录摘录作为「引用块 + 时间戳」插到光标处）。对话默认收起，页面经 `useOwnAssist` 接管 Ctrl/⌘+J：条目区放得下「左栏最小 440 + 笔记最小 360 + 对话宽」时停成第三栏，否则作为抽屉盖在笔记栏上（Esc 退场），画面不让位；条目区收起文档树后仍放不下两栏时，经 `projectTreeStore.setAutoCollapse` 临时收起项目文档树（不写持久化偏好，期间用户点展开以用户为准）。转录划选弹工具条（摘到笔记 / 问 AI / 从这句播放 / 复制），问 AI 把原句作为引用带进对话输入框、不自动发送。笔记里的 `video-timestamp` / `video-screenshot` 节点经 `noteMarkers.ts` 扫出时间点（引用块内为「摘录」），作为 `VideoPlayer` 的 `markers` 刻度并给已摘录的转录句加底色，不另存数据。AI 章节由 `useVideoNoteChapters` 在转录就绪且配了「视频总结」模型位时自动生成，存 `video_notes.insights`（`{ version: 2, transcriptHash, chapters }`，hash 对不上即过期重生成，其他形态按无章节读），供进度条分段（`VideoPlayer` 的 `chapters`）与转录分组；未配模型时不生成也不提示。

视频笔记、视频学习资料与白板视频抽屉共用 `VideoNoteChatPanel`，经 `useScopedChat` 接入 pi 会话；旧独立总结入口已移除，总结由视频对话承载。视频检索只保留页面作用域工具，不恢复全局视频笔记 MCP 工具。转录优化与电子书重写统一消费 `useLLMConfig` 的 `provider/model`，缺少配置时经 `openLLMSettingsSection` 打开新设置分区。

两处视频笔记共用 `useVideoNoteTranscription`：空白在线视频笔记经 `useVideoNoteCaptions` 的 react-query 查询优先调用插件可选的 `getCaptions(ref, signal)`（毫秒时间戳、无字幕为 null），30 秒超时后保留手动转录；查询按库、笔记身份和来源引用隔离，取消后不写库。字幕读取与模型配置无关；结果经原库命令 `import-video-note-captions` 仅在笔记修订一致且仍为空时写入，复用转录字段和检索索引；重新打开不会替换已有内容。用户的「开始 / 重新转录」直接走音频识别，不再次优先取字幕。YouTube 消费通用 `videoExtractor.getCaptions`，经 plugin-services 的任务生命周期调用 yt-dlp，只下载一条受支持的字幕轨（JSON3 / WebVTT / SRT；人工优先、同类原语言优先，同一语言按 JSON3 → VTT → SRT 选格式），统一为纯文本与毫秒起止时间，沿用代理并在结束后清理任务目录；Bilibili 的认证和字幕 API 留在插件内。

纯聊天模型、归约器与运行协议经公共子入口 `@tau/shared/chat-core` 消费；该入口不加载 React/DOM，主进程可直接使用，ThinkingLevel 与 MentionRef 也归该层，不反向引用输入组件目录。调用方禁止导入 `@tau/shared/src/chat-core/*`，包内部文件布局由共享包自行维护。

跨端 AI 契约、模型配置与转换归 `@tau/ai/contracts` / `models`，桌面原类型入口只转导出。目录命中时容量、输入模态和推理能力取目录值，协议优先使用目录中宿主支持的 API，再取模型配置或服务商的兜底协议。桌面和移动按解析后的模型协议发送请求。自定义价格保留优先级，模型采样、headers、compat 与 stripThinkTags 沿用原语义。think 标签流转换从 `@tau/ai/think-stream` 消费，服务商协议仍交 pi-ai。

旧 Azure 服务商标识只在内置目录查询时映射到 `azure`，会话与功能分配仍用用户配置的 provider ID。Kimi Coding 目录命中时，旧官方 `/coding` 地址按新版协议发往 `/coding/v1`。OpenAI Chat Completions 在有工具历史且本轮无工具时默认省略 `tools`，要求空数组的模型可设置 `compat.requiresToolsWithToolHistory`。Anthropic 默认发送完整历史，桌面会话只在运行期间预热缓存。

`pi-session-transcript.ts` 转导出 `@tau/ai/session` 的公共投影，移动端也消费它。JSONL 原始消息保留签名与模型字段，展示仍是 ChatSessionMessage / assistant_blocks，完整展示路径与压缩后的模型上下文分开。会话交换使用 pi v3，公共层的格式约束由官方 SessionManager 双向读写与上下文差分测试守护。桌面首条消息即可落盘，旧会话没有文件时按空对话处理。source 的解析保留 mobile，手机写入的同格式记录可以经相同历史投影展示；设备缺失的工具不会因查看历史而被执行。具体公共接口见 [AI 公共核心](/packages/ai/README.md)。

会话键包含数据库身份，投影、树编辑和目录补丁显式携带创建时的库名。宿主在异步装配前占用文件租约；图片准备也是忙态，释放会话先取消并等待在途操作。删除后不得发布迟到的投影或标题。PDF / 学习项目工具的执行快照归会话持有，不依赖页面继续挂载；运行时 LRU 同时释放已打开投影。

云端提供方数据库同步搬运库文件：库文件与会话目录的 JSONL 文件分块上传到固定对象名，最后写版本文件；下载先复制旧库进 backup/，再在主进程替换库文件与会话目录。不做内容校验与格式门禁，版本冲突由设置页确认，自动上传遇到云端更新时跳过。协议与流程见 [宿主分块同步](/docs/architecture/storage-sync.md)。会话运行中拒绝同步，锁持有到维护重连完成。当前任务的跨存储提交仍使用原幂等记录；实体编号高水位不复用。

数据库同步的提供方由 `src/services/syncRequestRetry.ts` 按对象请求包装，会话编排不重放整个文件；资源同步不经该包装，保留主进程自身的重试策略。请求退避、进度计数与分块复用规则以[宿主分块同步](/docs/architecture/storage-sync.md)为准。

会话下载与上传共用 `commands/sync.ts` 的有限并发调度器；每轮读取完整对话索引，在本地比对内容摘要，未变会话不发逐文件远端校验请求。下载通过 `piSessionSyncFiles` 取得本地候选，`services/chunkedSync.ts` 经分块文件 IPC 提供可选本地字节来源，公共下载算法使用索引中的清单校验文件名，再按块校验并复用本地内容，临时目录全部完成后才进入原安装入口。本地候选不可读时回退为远端下载，不影响修复缺失会话。

桌面同步使用公共 Node 入口 `@tau/db-schema/sync` 的数据库锁。CLI已整体退役；数据库访问仍检查维护锁并保留必要的崩溃恢复，不允许并发写入正在维护的数据库。

同步存储插件只在渲染进程通过 `context.sync.register` 注册五方法提供方，沿用 main.js，不读取旧 manifest.sync 入口；新的显式 backend 独立声明与授权，不自动承载同步提供方。S3使用浏览器SDK构建，网络经已有context.fetch由宿主传输；主进程不执行同步插件代码。同步设置以 target 声明 form，由插件详情 › 设置统一渲染，应用级配置保留。数据库与用量流程直接调用渲染端提供方；资源扫描、计划、账本和重试仍在主进程，存储操作按任务转发给发起窗口。PluginSyncSessions只登记任务与归属并转发数据，任务期间阻止停用、卸载和更新；窗口断开时拒绝待响应请求、清理任务，不转移到Node执行。CLI同步命令、TUI入口、Provider及cli-sync协调接口已删除；通用数据库维护锁保留。S3旧包不再从安装包中自动替换；用户从中心选择新版后仍走原安装事务，配置与启用意图不变。OSS也已按同一渲染进程边界拆分，使用ali-oss官方浏览器构建和宿主fetch；配置和资源账本只使用当前插件格式。旧OSS同步Provider、资源Adapter及同步IPC已删除，资源上传/列桶及其共享凭据仍保留。WebDAV同步同样使用独立插件与官方浏览器客户端，通过SDK公开传输扩展绑定context.fetch；旧Provider/Adapter和exists/list同步IPC已删除。宿主upload/download仍服务资源上传下载。条件创建正确返回412失败，列举仅忽略404；所有插件资源调度统一使用现有插件参数，不按插件身份特判。WebDAV验收见 `docs/plugin-system/57-WebDAV渲染进程拆分.md`。GitHub同步也已通过context.fetch调用原Contents API，普通写入先取SHA，条件创建不传SHA；旧同步Provider/Adapter与同步专用工具已删除。四种同步方式现统一为插件，设置 › 同步只列出服务摘要与选用，连接配置在插件详情 › 设置，GitHub 资源按原始地址加载，不做 CDN 地址改写；桌面账号及博客查询工具已迁入发布插件，移动端仍有独立原生消费者。资源调度复用通用插件参数（并发配置5，经现有执行器上限收敛为3），无插件身份特判。GitHub验收见docs/plugin-system/58-GitHub渲染进程拆分.md。codec 的既有 Node 执行链已由 独立后台 M4 迁入独立内容渲染进程，现行边界与验证见插件专题 78。OSS实现与验收见 `docs/plugin-system/56-OSS渲染进程拆分.md`；执行边界见 `docs/plugin-system/55-插件渲染进程边界纠偏.md`。

同步与上传的渲染注册表实现统一归 @tau/plugins/provider-host，桌面只保留实例装配与 Electron 转发；作者 API 和桌面表单不变。移动迁入独立设置视图并消费相同配置属性，具体持久化与选用行为由各端宿主处理；两端账号配置都按插件独立保存，不做统一账号共享。

渲染端分块与数据库同步对象名使用 `@tau/db-schema/sync-protocol`，不得深路径导入 Node 包内部。锁的 5 秒心跳在独立线程运行，120 秒过期；同步 I/O 不会阻塞续租，失锁后拒绝旧租约。插件的 createFileIfAbsent 仍是提供方契约（S3/WebDAV 用 If-None-Match: *，GitHub 用不带 SHA 的创建请求，OSS 用防覆盖创建并检查桶版本控制），数据库同步不再使用。

工具清单与执行器在创建宿主前一次性捕获，不能在 await 创建后再查页面注册表，也不能在执行时按名称获取后来注册的工具。`ToolExecutionContext` 的 `databaseName/signal` 贯穿普通工具、作用域工具及子代理；业务调用用 `bindDatabaseCommands` 绑定命令封装，每次调用只捕获同步进入 `invoke` 的上下文，不能把异步业务函数当作命令绑定。命令内部若需异步准备正文，必须在入口同步捕获上下文并绑定最终调用的 `invoke` 或命令描述符，准备完成后仍向原库提交，取消时不提交。内容提案和检查点也须带库名。工具中止经 `pi-tool-cancel` 到渲染端，MCP 再传给 SDK；每次执行带独立 `executionId`，迟到结果、错误与进度不能认领重用同一 `toolCallId` 的新执行。失败使用 pi 工具拒绝语义，不把错误藏在成功结果 metadata 中。

MCP 连接配置的摘要进入工具定义身份，渲染层重载后也不能把旧来源的授权交给同名新来源。学习项目生成工具启动的后台任务，其占位、流式保存、最终正文、测验和播客记录都使用原库命令客户端；任务投影带库名，不能仅在工具入口绑定数据库。

`bindDatabaseCommands` 以可写副本承载代理，读取与调用仍委托原命令对象；禁止直接代理生产构建冻结的模块并替换函数返回值，否则会触发 Proxy 只读属性约束。回归测试须覆盖冻结导出、嵌套调用、异常恢复及取消后的数据库上下文隔离。

未知模型容量必须补齐后才能运行，不使用猜测窗口；Shell 兜底按平台处理，macOS/Linux 保留系统 shell。

上下文用量按 `providerId + modelId` 匹配，显示名不参与新数据身份判定；旧 `modelName` 兼容读取 ID 或名称。
用量取最近一次模型调用（不累加工具循环），输入包含 pi 独立报告的缓存读写 token，流式与会话投影保持一致。
内置模型的聊天容量从当前目录解析，已保存设置仅作兜底；K 按 1000 换算。
容量随 pi 目录升级，不在业务代码中按模型名称添加容量特判。

浏览器扩展复用 pi 宿主，页面会话的文件、运行归属与 RPC 契约见 [浏览器伴读架构](/docs/architecture/browser-companion.md)。

可复用子 Agent 由 BACKGROUND 模块 `pi-subagents` 管理，身份与单次执行分离；同步等待、异步创建、按 ID 等待、继续发送消息与父通知均经主进程原生工具。运行复用 pi 宿主，详细契约、持久化与文件职责见 [子 Agent 架构](/docs/architecture/subagents.md)。子任务持有父宿主时禁止空闲回收，但不把父标为正在生成。消息内任务卡、对话顶部常驻入口与壳层标题栏显示子会话状态和待用户处理入口（界面见同文档「界面」节）。

MCP 管理页和输入框 MCP 快捷面板的「内置」中展示常开的「子 Agent」目录；四个父工具与仅子会话可调用的 send_parent 共用主进程的工具元数据，搜索和数量统计包含该目录。

先恢复工具 turn 与续流监听，再开放按钮。订阅后复核宿主状态，补齐恢复间隙开始的回答快照或最终投影；
复核期间已收到新事件时以事件为准，迟到的空闲快照不能覆盖新一轮运行态。
父子会话经 `PiPermissionScope` 共享会话授权，授权绑定工具来源和执行身份；单次审批仍绑定具体请求。授权不写数据库，父宿主重建、空闲 30 分钟回收或主进程重启后失效，子宿主单独释放不撤销父授权；重开时悬挂的工具调用标为已中断。子 Agent 的 ask-question 与审批只更新用户交互 UI，不通知或唤醒父 Agent，用户处理后继续原执行。

## 个人助手记忆

桌面 `assistant-memory` 是 BACKGROUND 模块，目标是理解用户的经历、近期状态、目标、困难、偏好与兴趣，通用知识归知识库检索。分配「个人助手记忆」模型后自动运行，清空模型暂停后台与聊天召回；用量归属 `assistantMemory`。设置只保留原有模型功能分配，不提供逐条记忆、审核、更正、忘记或重试工作台。

- **准入与来源**：`extraction.ts` 接收主对话活动分支与日记中用户本人的明确表达或带不确定性的个人观察，必须包含 user 主体、当前／过去时态及逐字引文。知识讲解、粘贴文章、引用他人、假设案例、助手输出和原始卡片正文不提炼为个人事实；一次性要求不升格为长期偏好。待办和日程按已提交状态确定性整理，不以计划或日程经过证明实际执行。
- **日记内化**：日记以独立 `diary` 来源接入，来源 ID 为 `diary_segments.id`，通过日记条目与仍被引用的正文关联读取，不开放普通 `content` 的提炼。按片段提炼个人经历、观点、价值取向、反思、想法与明确情绪；观点保留主观归属，犹豫与探索保留不确定性，摘抄不自动视为本人立场。观测时间以日记归属日为准，同日保留片段创建时间，补写、修改不刷新经历日期。当天情绪在归属日结束时失效，未给明确期限的非稳定日记经历默认 30 天后转为历史；近期模型不超过支持经历的有效期。一时感想、情绪不升格性格或信念。日记本人表达与聊天自述共同支持长期理解，明确稳定观点可即时形成 fact 画像。启动分页补录，正文写入按所属日记片段防抖入队，日记增改删与导入触发对账；引文按同一片段、正文和归属日重新定位，改期、删除或原话失效后清理依据，遗忘后不因段落移动重新提炼。
- **提炼与对账**：形成经历分两阶段。提炼只看材料片段，不带已有记忆，避免复述旧认识或因“已有”漏记新细节。对账（`reconcile.ts`）为每条候选按 `topic + text` 分别召回同类经历（含历史态）及最多 8 条已有模型作参考：关键词走词级索引 `memory_words`（写入时经与 `searchTerms` 同口径的分词函数 `memory_segment` 由触发器维护，bm25 排序，命中超过 5% 经历且多于 64 条的通用词不参与），语义走 `MemoryVectorIndex.searchMany` 整批一次嵌入后逐条近邻；各 4 条按名次轮转合并，整批上限 24 条。一次批量调用判定操作：新增、强化（同一事实只追加证据并刷新时间，不改文本）、改写（同一事实更准确的表述，原位改文本，依赖模型失效后重新归纳）、取代（新自述推翻旧认识，旧经历转历史，新经历沿用旧 topic 防主题漂移）、了结（本人自述某个当前意图已完成或放弃，目标转历史并记 `outcome` 为 done/dropped，候选本身照常新增；召回额外取与候选相关的未关闭意图，可跨 kind）。没有相关经历时不调用模型。越权由代码降级：目标必须在本次提供范围内且同 kind（了结除外，其目标必须是非手动的当前意图，候选为不早于目标的本人自述）；改写和取代要求候选为 chat/diary 本人当前自述、目标非手动更正、候选观测时间不早于目标，不满足时改写退为强化、取代退为新增；同一目标只接受观测最新的候选。落库前核对目标未在等待期间变化，否则按新增；被遗忘的事实与引文不因强化或改写复活。对账不提供丢弃，是否值得记只由提炼决定；待办、日程、编辑活动和对话摘要不经对账。对话摘要证据锚点为 `summary`，会话存在即有效；同一对话重新摘要时替换旧摘要，上一版遗留事项随输入给模型，明确完成或放弃的按 done/dropped 关闭，其余保留。意图到期转历史时记 `outcome=expired`。对账失败按提炼失败退避重试。
- **活动证据**：`operation-events` 在业务操作流水提交路径发出通知；`LibraryMemorySources` 只从最近 30 天的正文 update 流水按正文和本地日期聚合编辑活动。insert、正文快照更新时间和批量导入不充当学习证据；没有接线的阅读行为不虚构。每项活动只保留有出处的编辑记录与资料标题，不总结资料知识。仅活动支持的近期模型要求至少两个日期，并使用「近期多次整理某主题资料」的受限措辞，不能据此推断喜好、能力或掌握程度。
- **分层存储**：每个本机库身份对应独立 SQLite，不参加资料库同步或自动跨库合并画像。L0 为原始消息、业务状态和编辑流水的引用与证据；L1 `memory/evidence` 保存个人经历。L2 近期状态、L3 长期画像存 `memory_model`，`memory_model_evidence` 关联支持经历，记录确定程度、观测时间与有效期。明确的稳定偏好、习惯、兴趣可即时形成画像：是否稳定只由提炼模型的 `horizon` 按含义判定，不做关键词过滤；升格的经历记 `memory.stable=1`（改写后清零，归并时保留），归纳生成明确画像时只认 stable 或手动更正的经历，一次性要求不能经归纳变成长期偏好；推断画像要求至少三个日期和独立的用户表达，不能只靠编辑活动。新明确自述可以更新先前认识，较弱推断不覆盖仍有效的明确自述，旧候选不能覆盖新认识。近期状态 30 天失效；推断画像 90 天失效；有效明确自述保留到被新证据替代或依据失效。
- **依赖与有效性**：模型只允许引用本次提供且提交时仍一致的经历。经历被删除、更正或状态变更时，数据库触发器退役依赖模型；重复经历归并时重挂依赖并保留证据。召回与简报再次核对来源，暂时不可用的来源只隐藏，不作为永久删除；真实删除或引文失效由后台复核清理。过去的自述不当作当前偏好或近期活动，观测时间不会被整理时间刷新。
- **自动维护**：新信息静默一分钟后有界归纳，连续归纳至少间隔五分钟。每 14 天按每页 48 条核对全部个人经历的来源，清理失效依据和过期模型，完成后重新归纳；断点和完成时间持久化，重启后续跑或补做错过的周期。模型输入优先近期经历与已有模型依据，有界反思只生成近期状态、长期画像及被明确新自述推翻的认识，经历层去重不在归纳内。归纳输入给出全部有效画像（上限 60）与近期状态（上限 24），输出带已有模型 id 时沿用其 topic 原位更新，避免换名即新条。全面复核归纳后再做一次画像合并（同层同类、明确自述不并入推断，依据挂到保留项），随后重建用户总述。用户总述存 `meta.portrait`，输入为依据仍成立的画像与近期状态，每行引用模型 id 并记录生成时的模型文本；引用无效的行丢弃，有效行不足一半整份不采用；画像累计变化 3 次且距上次满一天时重建，有效画像少于 3 条时清除。`使用节律` 由使用统计确定性生成，是唯一无经历依据的画像。全面复核每页先核对来源，再把页内经历与已有经历对账（每次 12 条），强化即合并重复并重挂模型依赖，取代即旧经历转历史；对账失败不推进断点。来源连续失败后按一小时退避自动重试，不要求用户恢复。前台 Agent 开始、模型切换或切库时中断后台，模型等待不持有数据库事务，迟到结果不能写回旧连接或覆盖新版本。
- **分层暴露**：个人背景在宿主会话第一次 `before_agent_start` 以该轮用户输入为 query 计算后冻结，动态系统提示每轮返回「渲染端提示 + 冻结背景」，重试同源；同一宿主内系统提示逐字稳定，后台归纳不改动它，宿主重建时才重新计算。`MemoryRetrieval.brief` 提供用户总述中依据仍成立的行；有总述时画像只补充与本轮话题相关、未被总述引用的最多 3 条，无总述时最多 6 条；近期状态最多 3 条；与话题相关的未关闭意图最多 2 条（不含待办、日程），提示只在话题自然相关时问进展；另附最近会话摘要与当下状态，按字符预算保留完整条目。开发诊断的概览展示总述各行及依据是否已变化。`memory_search` 默认返回模型概览和经历目录（ID、主题、时间），state/profile 选择模型层，episode 才展开经历，all 返回两者；`memory_get` 按层展开并核对证据。自然对话的新自述自动更新认识，不要求用户维护台账；明确要求更正或忘记时仍可走现有写权限链路。资料对话、浏览器扩展和子代理不取得个人记忆，无关问题不强行个性化。
- **向量召回**：`MemoryVectorIndex` 复用生效本地嵌入配置和 `embedding-service`，每批最多 8 条异步索引个人经历；不自动调用嵌入插件。`memory_vec/memory_embedding` 与事实同库，按模型指纹重建。检索先按个人准入、类别、状态、时间与输入版本限定允许的 ID，再做 vec0 近邻与关键词的 RRF 融合；模型排名结合相关经历。查询最多等待 3 秒，未就绪、未建完或失败时退回已有个人检索；不将任意知识库全文命中混入个人记忆。卡片知识仍使用知识库原有检索。

- **开发诊断**：开发悬浮球的「个人助手记忆 → 实时处理面板」打开可调宽的非模态 Drawer，普通设置不提供记忆台账。未打包的开发运行注册只读诊断 IPC，快照包含真实扫描、读取、提炼、归纳、全面复核、向量状态、暂停原因和处理时间；进度只统计当前接入的来源。每层有界读取最近更新的 40 项，数量另行统计，内存中最多保留 60 条过程事件；展开条目才读取并核对出处，不调用会执行过期整理的业务读取方法。主进程按窗口、库连接和独立订阅编号推送，100ms 合并连续事件；模型与列表按内容版本缓存，状态变化仍更新进度计数。前端用 react-query 缓存，初始读取与推送比较版本，开关面板或连接恢复时隔离会话；没有数据时呈现加载/错误状态，不解引用空快照。关闭、切库或窗口销毁解除订阅，没有定时请求或手动刷新；本地计时器只更新已运行秒数。诊断不发起提炼、索引重建、修改或删除，也不输出模型请求和密钥。

未发布版本产生的卡片知识摘要通过独立一次性脚本清理，产品不含旧数据分类迁移或兼容分支；操作见 [个人记忆清理](/docs/guides/ops-personal-memory-cleanup.md)。
