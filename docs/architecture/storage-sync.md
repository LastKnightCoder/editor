# 宿主分块同步

## 边界与事实源

数据库、资源和会话文件由宿主拆分与重组。插件仍提供普通对象的 uploadFile/downloadFile/fileExists/listFiles/createFileIfAbsent，不理解逻辑文件、版本发布、分块或平台差异。公网直链上传仍使用 context.upload，保持完整文件输入与真实 HTTP(S) URL。

线协议常量的唯一来源为 `/packages/db-schema/storage-protocol.json`。TypeScript 与 Rust 读取同一文件，交换格式由 `/packages/db-schema/fixtures/chunked-storage-v1.json` 及双向读写回归守护。纯 TypeScript 算法在 `packages/db-schema/src/chunked-storage.ts`；Node 文件装配在桌面 `services/chunked-sync.ts`，渲染端走分块文件 IPC；Rust 算法在移动 `chunked_sync.rs`。

## 对象布局

当前同步信封版本为 6，文件清单格式为 tau-chunked-file 版本 1，数据块最多 8 MiB，清单最多 4 MiB。最后一块可短于 8 MiB，空文件使用空分块列表。

| 对象                               | 命名                                                          |
| ---------------------------------- | ------------------------------------------------------------- |
| 数据库版本指针                     | `tau-sync-v1/databases/<库名 UTF-8 的 SHA-256>.json`          |
| 不可变版本后继                     | `<版本指针>.next-<父版本>`                                    |
| 数据库、会话文件清单及会话目录清单 | `tau-sync-v1/snapshots/<随机身份>.json`                       |
| 内容块                             | `tau-sync-v1/chunks/<SHA-256 前两位>/<其余位>.bin`            |
| 资源文件清单                       | `tau-sync-v1/resources/<文件名 SHA-256 前两位>/<其余位>.json` |

资源清单里保留逻辑文件名与大小；提供方返回物理对象列表后，宿主读取和验证清单，资源计划只展示逻辑文件，不把内部块当资源。分层哈希路径避免大量对象堆在一个目录。

文件清单包含 format、version、name、size、rootHash 与有序 chunks（每项 size/sha256）。块名从校验值推导，不接受清单给任意路径。块的 SHA-256 校验原字节；rootHash 校验 UTF-8 规范串：格式和版本、逻辑文件名、文件总长各占一行，随后每块一行 `size:sha256`，均以换行结束。两端验证分块长度、总长、顺序和根校验；文件名拒绝路径分隔符、控制字符及 `.`/`..`。

## 发布、恢复与重试

宿主每次只读一个内容块。已有同名内容块必须下载校验后才复用，损坏块重新上传；失败重试复用已经确认完整的内容块。所有块完成后才上传逻辑文件清单，数据库及全部会话清单完成后才争用不可变版本后继。指针仅用于加速，后继记录是提交事实；提交响应丢失按身份复验，竞争失败不推进本地版本。

下载先校验清单，每块验证后写入临时文件，完成前不替换正式文件。资源原子改名，数据库经 SQLite 校验及备份后与会话目录事务共同安装；日志支持中断恢复。会话采用 tau-session-directory 版本 1 的文件清单，每个 JSONL 文件独立分块，不生成整体 ZIP。会话结构校验逐行读取，并保留身份、父节点和目录引用校验。

桌面发布前校验数据库与本机会话目录引用完整。移动只沿用已下载快照的会话基底；数据库含非空会话但没有对应基底时，拒绝发布并提示从保有完整会话内容的客户端初始化，避免发布缺失会话文件的快照。

取消在分块边界和提交前检查，窗口或工作区失效拒绝迟到结果；资源列举失败不降级为成功空集。临时文件由既有会话和文件事务回收，未提交的远端内容块保留供重试复用；当前插件对象契约没有删除接口，不自动清理远端块。

提供方 SDK 绑定会释放不读取的写入控制响应及错误响应；桥接在无体响应和落盘消费完成时等待原生槽位释放，连续分块不会积累已完成的网络任务。

## 内存与磁盘

数据库及资源同步不把完整文件送入 JS，也不把完整数据库或会话目录经 IPC 编码。插件收到的是最多 8 MiB 的对象字节，编码、签名、Blob 和网络缓冲的内存随分块大小增长。移动 IPC 继续逐个 256 KiB 消息传输，原生文件许可与 JS 文件队列串行；同步对象网络响应额外按 16 MiB 预算拒绝异常内容，避免错误服务端响应在 JS 聚合。普通 fetch 和公网直链上传不受该同步预算约束。

桌面资源并发沿用宿主调度，最多三项，内存是少量分块的倍数。数据库快照、下载文件和事务备份需要与文件大小对应的磁盘空间；磁盘不足会失败并保留原数据。清单大小约束也约束单文件的分块条目数，不承诺无限对象数量。

## 首次使用与版本隔离

仅维护当前格式；不读取、转换或回退到原来的单体对象布局。两端和仓内插件统一升级，本地数据库及资源内容不变，首次从数据完整的本地库重新发布。原远端对象不参与当前同步，也不自动删除；仅有原远端单体对象且没有完整本地副本时，当前格式不提供恢复入口。

本地版本仅在数据库记录的 syncFormat 等于当前同步信封版本时有效，否则从零开始；成功上传或下载后写回版本与 syncFormat。移动会话基底保存在 chunkedSyncBases，资源账本采用 chunked-v1 名称空间。原计数、会话基底和账本不被解释为当前同步状态，避免跨格式误判新旧或覆盖已经发布的新数据。

所有客户端共同使用当前格式。账号配置及存储选择继续归各插件，改变远端对象布局不创建账号共享或改写原凭据。
