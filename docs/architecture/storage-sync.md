# 宿主分块同步

## 边界与事实源

数据库、资源和会话文件由宿主拆分与重组。插件提供普通对象的 uploadFile/downloadFile/fileExists/listFiles/createFileIfAbsent，不理解逻辑文件、分块或平台差异；数据库同步只用前三个。公网直链上传仍使用 context.upload，保持完整文件输入与真实 HTTP(S) URL。

线协议常量的唯一来源为 `/packages/db-schema/storage-protocol.json`。TypeScript 与 Rust 读取同一文件，交换格式由 `/packages/db-schema/fixtures/chunked-storage-v1.json` 及双向读写回归守护。纯 TypeScript 算法在 `packages/db-schema/src/chunked-storage.ts`，数据库同步的固定对象名与版本文件在 `database-sync.ts`；Node 文件装配在桌面 `services/chunked-sync.ts`，渲染端走分块文件 IPC；Rust 算法在移动 `chunked_sync.rs`。

## 对象布局

文件清单格式为 tau-chunked-file 版本 1，数据块最多 8 MiB，清单最多 4 MiB。最后一块可短于 8 MiB，空文件使用空分块列表。

| 对象             | 命名                                                          |
| ---------------- | ------------------------------------------------------------- |
| 数据库版本文件   | `tau-sync-v1/databases/<库名 UTF-8 的 SHA-256>/version.json`  |
| 数据库文件清单   | `tau-sync-v1/databases/<库名哈希>/data.db`                    |
| 对话记录清单     | `tau-sync-v1/databases/<库名哈希>/sessions.json`              |
| 单个对话文件清单 | `tau-sync-v1/databases/<库名哈希>/sessions/<文件名>`          |
| 内容块           | `tau-sync-v1/chunks/<SHA-256 前两位>/<其余位>.bin`            |
| 资源文件清单     | `tau-sync-v1/resources/<文件名 SHA-256 前两位>/<其余位>.json` |

数据库对象名固定，上传即按名覆盖。版本文件只含 `{version, updatedAt}`；对话记录清单为 `{files: [文件名]}`，桌面和移动端都读写。会话目录只包含当前库的应用对话，独立 browser-sessions 不参与同步。

资源清单里保留逻辑文件名与大小；提供方返回物理对象列表后，宿主读取和验证清单，资源计划只展示逻辑文件，不把内部块当资源。分层哈希路径避免大量对象堆在一个目录。

文件清单包含 format、version、name、size、rootHash 与有序 chunks（每项 size/sha256）。块名从校验值推导，不接受清单给任意路径。块的 SHA-256 校验原字节；rootHash 校验 UTF-8 规范串：格式和版本、逻辑文件名、文件总长各占一行，随后每块一行 `size:sha256`，均以换行结束。两端验证分块长度、总长、顺序和根校验；文件名拒绝路径分隔符、控制字符及 `.`/`..`。

## 数据库同步

数据库同步搬运 .db 文件及配套的会话文件，不校验数据库业务内容、不做格式门禁、不生成恢复包；资源文件走独立的资源同步。

- 上传：关库（编辑器缓存写回并合并 WAL；移动端用 `VACUUM INTO` 取快照）→ 上传库文件 → 上传对话记录与完整清单 → 最后写版本文件，版本号为 max(本机, 云端) + 1。中途失败时不发布新版本号。移动端上传前恢复会话事务并检查目录行对应文件，缺失正文不能被发布为空清单；文件名只接受安全 JSONL 文件名，不允许目录或符号链接。
- 桌面对话记录增量上传：成功上传后在 `sync-status/database-sessions-<同步目标哈希>.json` 记下写入的版本号与各对话文件的大小、修改时间（同步目标 = 插件、配置、库名）。下次上传时云端版本仍等于该版本号（期间无其他设备写入），才跳过大小与修改时间都未变的文件；记录缺失、损坏或版本不符时全量走分块流程。对话清单始终按本机完整文件列表重写。
- 桌面对话文件最多三个并发上传，单个文件失败按 1/2/4 秒退避重试三次，仍失败则整次上传失败。上传进度按库文件与待传对话文件的已处理字节计算，重试回退的字节不会让显示值倒退。
- 下载：云端版本为 0 时拒绝 → 下载库文件和清单所列会话到临时区域 → 关库并把旧库原样复制到 `backup/version-<本机版本>-<时间>-<库名>` → 丢弃该库的编辑器缓存会话（本地会话删除、共享会话解除来源）→ 改名替换库文件并删除 -wal/-shm → 安装配套会话目录 → 重置内容索引 → 维护重连（结构升级走正常开库流程）。桌面在远端有会话清单时替换会话目录；移动端使用下述成对安装规则。
- 版本冲突不在命令层拦截：手动覆盖较新一侧由界面确认（桌面 ConfirmDialog、移动整库覆盖面板警示）；桌面自动上传遇到云端更新时跳过并提示，启动时云端更新则自动下载。
- 桌面在 AI 会话忙时拒绝同步；取得数据库同步锁和会话目录维护权后回收该库空闲宿主，防止开库或写会话文件与替换并发。
- 移动端同步持有按库维护租约，模型准备、单发、会话运行、交互和提交收尾等忙态阻止同步；同步期间不能起新运行。上传和下载完成传输后回读远端版本，发现传输期间变化返回 SYNC_REMOTE_CHANGED。下载安装后增加库代次并撤销旧 AI 租约、原生 HTTP 上下文和提交暂存。
- 桌面同步设置的远程版本查询与数据库同步操作等待当前窗口的插件状态为 `active`；本地插件的已启用偏好只表示启用意图，不能作为就绪条件。激活期间显示「准备中」并禁用检查与上传，运行时通知激活完成后自动发起查询；激活失败显示「插件不可用」，真实查询失败仍保留错误与手动检查入口。

移动会话文件通过 `ai/sync.rs` 使用现有 PluginProvider 分块传输；对话清单完整写入，不套用桌面的 mtime 增量缓存。无清单、明确空清单与下载失败有不同语义：缺清单返回无远端会话集合，合法 `{files: []}` 表示明确空集，坏清单或任一列举文件失败都拒绝安装，不静默变为空集。

移动端的库文件与会话目录通过 `ai-installs/<库名>.json` 安装日志配对，原库与旧会话目录保存在 `backup/ai-installs/<事务 ID>/`。远端缺清单时也备份旧会话目录并创建空的活动目录，不能把旧库的同名文件当成新库历史；远端目录行缺正文时由 AI 读取接口报告缺失。安装失败或下次开库发现遗留日志时，恢复同一备份中的库和会话目录；不能只回滚其中一半。

版本文件最后写入只表示这一轮完成，不是远端多对象原子事务。固定对象在失败前可能已经被覆盖，远端版本回读也不构成分布式互斥；当前协议不合并多设备并发编辑。会话同步搬运文件字节，模型配置、凭据、运行授权和本机 HTTP 上下文不随它传输。

## 分块传输与重试

宿主每次只读一个内容块。已有同名内容块必须下载校验后才复用，损坏块重新上传；失败重试复用已经确认完整的内容块。所有块完成后才上传逻辑文件清单。下载先校验清单，每块验证后写入临时文件，完成前不替换正式文件；资源原子改名。

取消在分块边界和提交前检查，窗口或工作区失效拒绝迟到结果；资源列举失败不降级为成功空集。临时文件由既有会话和文件事务回收，未提交的远端内容块保留供重试复用；当前插件对象契约没有删除接口，不自动清理远端块。

提供方 SDK 绑定会释放不读取的写入控制响应及错误响应；桥接在无体响应和落盘消费完成时等待原生槽位释放，连续分块不会积累已完成的网络任务。

## 内存与磁盘

数据库及资源同步不把完整文件送入 JS，也不把完整数据库或会话目录经 IPC 编码。插件收到的是最多 8 MiB 的对象字节，编码、签名、Blob 和网络缓冲的内存随分块大小增长。移动 IPC 继续逐个 256 KiB 消息传输，原生文件许可与 JS 文件队列串行；同步对象网络响应额外按 16 MiB 预算拒绝异常内容，避免错误服务端响应在 JS 聚合。普通 fetch 和公网直链上传不受该同步预算约束。

桌面资源并发沿用宿主调度，最多三项，内存是少量分块的倍数。数据库快照、下载文件和事务备份需要与文件大小对应的磁盘空间；磁盘不足会失败并保留原数据。清单大小约束也约束单文件的分块条目数，不承诺无限对象数量。

## 首次使用

不读取、转换或回退到此前的快照布局（随机快照名、后继版本链、单体对象）；首次使用时从数据最全的设备上传一次，其他设备再下载。原远端对象不参与当前同步，也不自动删除。本机版本号只记录在设置的数据库条目 `version` 上。

账号配置及存储选择继续归各插件，改变远端对象布局不创建账号共享或改写原凭据。
