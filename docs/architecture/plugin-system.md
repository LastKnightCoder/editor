# 插件系统目标架构与能力

更新时间：2026-10-20。当前完成状态见 ](/docs/tasks/plugin-system-roadmap.md)，长期设想保留在 `历史方案`。

## 当前目标与结构

发布平台当前采用包资料模型：manifest提供名称/版本/简介，README提供介绍和使用说明，可选CHANGELOG提供版本记录；不维护第二份网页介绍、截图或外部反馈地址。上传与提交详情支持作者/审核者站内交流。此裁决直接替换开发期旧表单，没有运行时双模型兼容。

让作者独立编写桌面插件，让用户通过本地 ZIP 安装、使用和维护。本地闭环完成后，用户已恢复发布平台建设：先做上传与提交，再做审核发布、插件中心和在线升级，见 `C19`。权限隔离继续暂停。

- 作者使用 GitHub 模板、pnpm、TypeScript/React，输出 ZIP；从 `@tau/plugins`、`@tau/ui` 导入，npm alias 对应公开契约包。
- 主进程扫描固定目录 `~/.editor/plugins/<manifest.id>/`，读取并校验包；开发与正式构建均接入。
- 同一 TS 运行时负责实例、命令、页面、设置、侧边栏和清理。插件处于完整宿主环境，没有沙箱隔离。
- 启用意图是应用级偏好；私有数据按插件/工作区隔离，切库重建实例并撤销旧上下文。
- 页面复用既有导航，设置复用现有界面，侧边栏合并静态与插件贡献，图标支持作者 SVG 组件。

## 本轮：兼容与更新

2026-10-20 执行边界更新（PS-043）：普通 main.js 继续在浏览器环境执行；显式格式 2/backend 使用独立 utilityProcess，支持按需、应用/工作区就绪与常驻，必须获得精确版本授权。普通内容插件的转换移入无 Node/业务 preload 的独立内容渲染进程，主进程与 Node worker 不求值其代码。后台每个版本须人工重点审核，发布来源由 HTTPS 元数据和包摘要验证；插件 stdio MCP 复用声明、授权与进程监督。下述本地更新迭代的现行补充为：后台空闲后整包切换，新版重新授权，备份来源随旧版一起恢复。实现、证据及尚未完成的平台验收见 `78`，不提供 OS 沙箱或恶意同环境插件隔离保证。

manifest 增加可选 `minAppVersion`。已有未声明该字段的包仍可读，但无法表达额外最低版本要求；新模板明确填写。严格比较版本，预发布低于同号正式版本；新版客户端的检查无法追溯约束旧客户端。

本地安装/更新使用 ZIP 暂存、启动替换、上一版备份和事务记录。正在运行的代码不热替换，所有窗口在下次完整启动切换。安装中断回到旧包；新版启用失败可安排恢复上一版，再重启生效。尚未生效的更新可以取消。

恢复只替换代码与样式，不回滚私有数据；作者负责数据结构的兼容或迁移。不承诺远程检查、自动下载、任意数据回滚或恶意插件故障隔离。

## 后续与交付口径

后台能力的当前合同见 78；普通笔记、公共实体与组件能力另见 77。其他领域仍先选择真实插件，再补缺少的最小接口；不暴露内部 store、SQL 或桌面 feature。

安全隔离仍后置；发布平台已进入 C19，第一期仅 GitHub 登录、私有 R2 上传、D1 提交与作者查询，终点为待审核。旧 `23` 中的分档、签名和早期目录建议不能直接视为当前实现要求。

“完成”需要实际可安装产物和行为验证，而不只是类型声明。Agent 负责类型、构建和 Electron 行为验证，用户负责视觉与使用体验。公开文档只解释作者需要的接口和流程；阶段编号和内部测试保留在客户端仓库。
