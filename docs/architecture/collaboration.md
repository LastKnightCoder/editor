# 实时内容协作

## 服务与协议

正式协作入口为 `https://collab.taunote.app`，桌面端与移动端从共享协议包读取同一默认值。服务器为 `apps/collaboration-cloudflare`：Workers 接入请求，SQLite-backed Durable Object 统一管理设备、权限、文档与在线会话，附件和备份保存到私有 R2。

| 通道            | 协议与职责                                               |
| --------------- | -------------------------------------------------------- |
| `/v1/*`         | 设备身份、文档发布、协作码、审批、成员、短期票据和附件   |
| `/ws`           | Hocuspocus 4.6 二进制协议；同一连接可复用多个文档        |
| `/events`       | refresh、presence、revoked、closed 事件                  |
| `/health/ready` | 就绪状态、构建标记、正式实例、产品入口与受信任旧来源摘要 |

Worker 在边缘按来源 IP 限流，Durable Object 在连接和消息层继续限制资源；正式服务注册无需原型管理密钥。管理接口独立使用服务器 Secret，客户端不能调用导入、备份或维护接口。未验收激活的实例拒绝业务写入。

仓库内 Node 与 Worker 的 Presence 入口共用 `assertPresenceBudget`：状态 JSON 按 UTF-8 编码计量，最多 16384 字节和 16 个客户端状态；每连接每分钟最多 600 次。在线状态不写入文档及撤销历史。源码中的门禁不代表线上版本已更新。

## 文档与持久化

仓库中的桌面与移动正文编辑使用协议 2：稳定节点池、位置引用、正文片段与不可变契约字典，title 为 Y.Text。移动只调整位置，拆段/合段调整片段归属与边界，不复制文字身份；插件声明的 `textFields` 各自使用 Y.Text。`@tau/editor-collab` 负责 Slate 绑定、光标及源码输入，共享模型与校验位于 `packages/collaboration`。协议 1 的 Y.XmlText/fields 仅由隔离转换入口读取，普通编辑拒绝旧格式写入。

契约是节点数据版本的 JSON 说明，按内容摘要去重；节点保存契约引用。声明及完整 v1→v2 示例以[插件作者文档](/packages/plugins/docs/editor-collaboration.md)为准。普通属性默认同步，没有 `SOURCE_FIELDS`、字段名黑名单或 private blocks 同步开关；折叠、当前步骤等视图状态放本机记录，编译结果放可重建缓存。内置代码块的数据版本 2 用 `code-step` 子节点保存各步源码，复用同一 `textFields` 机制。源码字段服务 `IEditorTextFields` 由文档提供：节点树文档按 Y.Text 增量写入；本地 Y.Doc 文档（`createLocalYjsDocument`，如 Markdown 文件窗口）注册 `@tau/editor/api` 的 `slateTextFields`，字段是节点属性，经 Slate 操作整段写入后由 slate-yjs 同步，撤销走该文档的 UndoManager；无文档的临时编辑器由内核提供同样的本地字段。

主库 `contents` 与 `content_documents` 在同一事务保存正文、稳定正文身份、契约和投影修订。CRDT 的真实基线和 epoch 只属于协作缓存及服务端，不能从主库 JSON 冒充原基线；缓存缺失时建立新基线。活跃会话保持其正文及契约，主库接收带来源和观察修订的投影。正文准备、版本转换与校验归正文入口；业务元数据不解释契约，复合创建仍在原事务内携带正文。共用正文只增加原正文引用；独立复制生成新身份并保留来源契约。

外部实体引用由对应领域校验来源身份。`content_entity_relations` 记录正文的关系差集，与正文和目标引用数同事务更新；重复投影、窗口重连和同一正文的多个拥有者不重复记账。撤销及独立本机副本的持有记录不进入随库同步的引用数；回收须同时核查关系与本机持有，无法确认时延迟回收。

Markdown 按节点保存的版本选择导出器；缺少实现时保留携带契约的无损载荷。HTML/EPUB 缺少匹配实现时明确拒绝，不使用新版导出器猜旧字段。移动端外部 Markdown 导入保留契约，预览按精确版本只读渲染，落库复用原创建事务。索引仅消费正文入口提供的文本与分节，不接收契约字典。

Node 与 Worker 实现协议 2 的受控转换，桌面客户端先自动保全，再由所有者的后台升级执行。源码绑定在 Activity 隐藏时释放句柄，恢复时重新打开；旧订阅不能重连已释放句柄，原生源码输入的焦点不进入 Slate。仓库实现与本地验证不代表线上部署或已发行 SDK 已更新。

文档增量在 beforeSync 中完成同步 SQLite 事务后才继续协议处理。快照和增量以 512KiB 分块落盘，避开 SQL 单行限制；重连按状态向量交换缺失增量，压缩以事务替换快照。服务或 Worker 版本变化后从持久存储恢复，不以进程内 Y.Doc 作为持久化依据。

服务端元数据包含设备凭据摘要、文档、成员状态、邀请、审批、资源、审计与身份合并回执，以及文档协议、迁移终态和历史资产关系。设备只向客户端返回一次明文 secret，服务器只保留摘要；连接使用 60 秒签名票据，每条同步消息重新检查成员资格。

协议 2 的候选校验在有界的逐文档队列中执行，持久化前重查权限、冻结状态和代次。缺少先行依赖的增量不返回成功；非法契约、物理替换文字根、越过受控迁移的版本变化均拒绝。连接票据绑定文档代次与基线，协议 2 的票据请求要求 protocolVersion=2，状态读取要求 x-tau-document-version: 2，旧客户端不能取得不兼容快照。协议 3 的票据请求还必须声明匹配的 epoch/baselineId；普通更新同时禁止身份元数据的新写入，输掉 LWW 的旧身份记录也不能借新票据进入新基线。

HTTP 普通编辑在取得逐文档队列执行权后才加载完整文档，排队期间不持有全文副本。结构化文档的当前摘要随正文和序号同事务更新到既有协议记录，使用与落盘重载相同的 GC 编码；进程首次读取重新核验正文，随后未变化的摘要查询只读元数据。核验缓存绑定实际 SQL 记录值，回滚、迁移和导入不能沿用陈旧结果；旧协议仍从原正文读取。

所有者通过 `documents/:id/migrations/:operationId` 的 prepare/freeze/commit/cancel 操作迁移。冻结捕获最终修订；正文安装和 COMMITTED 回执共用 SQLite 事务。ABORTED/EXPIRED 不复活，重复提交返回原回执；取消先于首次请求到达时也保存终止记录。GET 操作回执返回 null 只表示没有记录，不等于可安全删除客户端恢复材料。

当前使用单个正式 Durable Object 保持权限、索引与文档更新的事务一致性。配置上限为 20 份活动文档、100 条连接、每设备 5 份共享、每文档 10 名成员、文档 8MiB、附件 25MiB、文档附件 200MiB和全站5GiB。活动文档另受12MiB编码状态内存预算约束，超出时拒绝继续加载或扩大，避免超出运行时内存。此上限属于背压，不承诺20份最大文档同时驻留。

## 白板文档与编辑回执

白板使用同一节点身份、删除标记、多富文本根、宿主历史和实体引用契约。仓库内的白板共享协议为 3，meta 固定 kind=whiteboard、documentId、baselineId、epoch；业务模型仍使用 whiteboard-w1-v1。`document-adapter` 按协议选择正文或白板候选校验、投影和资源扫描，不把白板解读为空正文。白板富文本根复用 `validateNodeTree`；普通增量不能修改种类、基线、契约或重建既有记录/文字根。Node 与 Worker 的发布、WebSocket 接纳、HTTP 编辑提交和受控迁移均通过此适配器，权限、冻结、epoch 与写队列复用公共实现。

普通编辑与整文档修订条件提交走 `/v1/documents/:id/operations/:operationId`，GET 查询终态、POST 提交，`/cancel` 受控取消。请求绑定 epoch/baselineId/version、增量摘要和截止时间；条件请求同时绑定 expectedRevision（完整 CRDT 摘要）与 expectedSequence（服务端单调修订）。`DocumentOperationLedger` 与迁移账共用 SQL 和 PENDING/COMMITTED/ABORTED/EXPIRED 语义，回执与正式增量在同一事务中提交。重复 ID 只能使用原指纹；缺依赖保留 PENDING 并返回 MISSING_DEPENDENCIES，不修改确认基线、不推进修订；取消、过期或修订冲突不安装候选。普通条件操作保留 epoch，重建整份 CRDT 基线才走迁移账，不允许正文与白板互换种类。

`DocumentSyncSession` 先把提案、确认快照和操作身份交给耐久日志，再调用服务端；连接失败属于结果未知，重启后查询回执。拒绝祖先时保全整条未确认分支及原字节，不跳过祖先发送后继；换代即使没有待发送编辑也保留旧确认快照。隔离完成前不清队列、不安装新基线；隔离后禁止继续使用旧副本，调用方显式获取确认快照重建，材料仍留在日志中。状态回退或摘要/序号不一致拒绝覆盖。桌面实现使用 W4 日志库中的 remote_branches，按规范服务地址、设备身份和文档身份隔离；损坏记录不自动删除。

普通增量取得 EXPIRED 终态后，只有确认仍为同一基线和代次才用新操作身份续传；条件替换、取消、未知结果和换代不走此路径。成功回执只保存幂等元数据，不逐次内嵌完整旧基线；未确认和被拒分支材料保持原样。白板渲染端将同一基线的全部 outbox 增量合并验证，补发批次按增量摘要确定身份，主进程耐久确认后才删除原记录，不按窗口 UUID 推断因果顺序。

桌面白板操作期限以最近 HTTP 响应的标准 Date 为依据，不使用客户端墙钟；缺失有效响应时间时停止提交。单次 flush 对同一待确认增量最多续投一次，再次过期返回可重试状态并释放串行队列。持续输入只能提前已有同步排期，不能推迟已安排的发送/轮询，也不绕过断网退避。

画布条件提案是宿主接口，只支持已定义的文本编辑和用户几何；等待结果期间冻结该视图写入口。同步先到时缓冲，确认后先用发起视图 origin 安装提案一次，再应用远端结果；重复回执不重记历史，其它视图不记录发起者历史。进程重启保留回执和内容，但不伪造已恢复的内存撤销栈。普通插件未新增通用 CAS 或任意事务接口。

本机日志、投影、关系账、多窗口与生命周期见 [桌面白板架构](/docs/architecture/desktop.md)。白板状态不写入正文 collaboration_bindings；主进程网络入口只打开已经带共享身份的白板，既有纯本机白板仍须经过独立首次发布流程。桌面协作状态以 `whiteboards` 单独列出白板房间（成员、角色、服务地址），协作码、加入审批与移除成员复用正文协作的接口与面板；白板内容的打开、同步与投影只走白板文档会话。成员打开已加入的白板时先在本机资料库落一份由远端确认快照创建的文档，再按同一流程同步。结束共享与退出复用 `/close`（带确认修订条件）与 `/leave`，本机副本在服务端完成后才换成不带共享身份的文档；再次共享建新房间，不复用旧房间。`DocumentSyncSession` 的传输层可提供 `peek` 读取确认摘要，远端未变化的刷新不下载完整状态。上述能力属于仓库实现与本地验证，不表示正式服务已经部署或旧白板已启用共享。

## 资源与私有节点

附件使用 `tau-collab-asset:<id>` 引用，R2 对象按内容摘要保存，读取必须通过文档成员鉴权。上传后重新校验权限并事务检查配额，指定资源 ID 支持幂等重试；相同摘要的上传与回收串行化，避免异步删除误伤新引用。

协议 1 的历史数据包含私有真身与共享占位符，当前普通编辑入口不再运行这种替换机制；旧格式仅供转换与恢复读取，转换前保全原始材料。格式 2 按节点契约声明共享文本及资源，外部实体引用在领域入口核对来源身份。本地视频、不可读取或超限资源使用仅本机引用。协议 1 未引用附件保留7天后由压缩回收；协议 2 另保存每代次曾引用的资产，历史关系仍持有的文件不按当前正文的缺失回收。关闭共享释放对应资源记录和无其他引用的R2对象。

协议 3 按精确契约扫描所有保留元素与富文本节点，包括未知插件和删除池；普通同名业务字段不误识别为资源。已接纳状态的资产并入各 epoch 的历史持有。未确认提案可能缺依赖，无法完整扫描，因此服务端保守持有该房间当时已上传的资产，取消/拒绝不会立即回收；持有和操作记录计入现有存储配额，退役须经恢复流程，不增加配额或提供自动历史清理。它不构成对未上传文件、外部 URL 或无权下载资产的完整恢复保证。

服务备份元数据格式 3 增加编辑回执与单调修订表，Node 导出和 Worker 备份/恢复一致；格式 1/2 的原正文恢复仍可读取，白板协议 3 的恢复要求携带格式 3 元数据，不能丢掉已确认操作后再接受重试。

## 客户端与端点升级

桌面端在 Electron 主进程维护本地协作缓存、Y.Doc、资源队列和多窗口视图同步；开发运行可通过 TAU_COLLAB_DEV_SERVER_URL 指向本地服务，发行版忽略此变量。业务编辑仍经过内容会话，不绕过版本校验与冻结协议直接写正文。

桌面及移动的正文缓存、节点视图、输入草稿、本机持有和转换日志复用各自的 `collaboration.db`，不随资料库同步；没有独立的 content-local-state 数据库。恢复副本保存在原库替换范围之外，逐文件校验后才登记成功回执。普通切库与重连只冲刷，真正覆盖主库时先保全；单文档副本只包含目标会话、草稿、视图、正文投影及所引用的本机资源，整库替换才包含对应主库及归属该库的缓存。资源未取得时明确记录，必要保全失败拒绝覆盖，不遍历整个资源目录兜底复制。 历史 `~\.editor\resources\…` 与 `~/.editor/resources/…` 按当前资料目录定位，跨平台转换仍将实际附件字节纳入保全。

桌面缓存格式 3 的恢复登记保存所属资料库，回收只检查该库的恢复清单；旧登记优先按已校验清单或原迁移/持有记录补归属，损坏且完全无法归属的旧记录继续保守阻止回收。重复会话保全同时核对正文投影、草稿、视图和附件字节，材料未变且原副本校验通过时复用回执。首次旧白板转换由后台队列在隔离库准备缺失身份，与白板候选一起事务安装，普通打开不隐式转换。

转换日志记录 operationId、预期版本、候选摘要、恢复材料与各存储安装回执。远端结果未知时查询原操作；已提交则幂等续做本地安装，不恢复旧候选覆盖后来输入。取消或过期不复活，也不删除恢复材料。旧私有真身只在持有设备保全；共享转换不自动公开它们。保全材料可校验和导出，没有恢复包导入、独立资料库恢复或来源选择界面。操作步骤见[正文转换与保全](/docs/guides/ops-editor-contract-upgrade.md)。

本机旧白板转换在主库事务安装成功后确认提交；重启或取消先核对主库候选身份与摘要，已安装的候选只续做。尚未安装且原库发生变化时，后台队列核对未安装后取消旧候选并重新准备；兼容修正此前“仅有本机决定、主库未安装”的记录，原材料仍保留。远端提交与首次远端发布的决定不可回退。旧元素换号时，唯一旧身份映射同时用于连线和演示引用；歧义继续保全并报告。

首次白板转换按目标和出现次数接管旧画布及内嵌正文的实体引用计数，在同一主库事务写入新关系账，不重复加计数；外部 contents 保留自己的关系账，不能抵扣新内嵌正文的持有。主库提交后重试只续做回执。只有折点的旧连线从折点派生矩形，分栏中的未知或外部正文节点保留原载荷和实体引用。

本机迁移表按文档建立索引，未完成记录使用部分索引；启动恢复先一次读取待恢复文档集合，避免每个已完成会话都扫描完整迁移历史。缓存打开时幂等建立这些索引，不改变迁移裁决或回执内容。

移动端在 WebView 复用会话 Y.Doc，REST 经 Rust 网关，WebSocket 直连；在线事件和回前台刷新负责恢复。首次旧格式或节点版本转换由桌面执行，移动端只保全本机输入、导出和接收新基线；旧代次增量不混入新基线，同代次也不得替换 baselineId。源码草稿仅在同次缓存写入成功且内容及序列仍匹配时确认，迟到回执不清除更新输入。页面卸载不立即销毁有活跃会话的运行时。

移动端本机与共享正文将未确认增量保留到缓存提交成功；写盘失败暂停编辑，冲刷或重连可合并祖先与后继重试，草稿先保存再随匹配的正文确认。保存恢复只解除本次保存错误的冻结，不解除远端换代冻结。活跃共享会话在列表刷新和重连前检查协议摘要，换代后保全旧副本、停止旧连接并提示采用新版本；普通同代次刷新不下载全文。

当前升级版本保留必要的旧格式读取与转换代码；下一基线版本移除这些历史路径并拒绝旧格式，跳过升级的设备须先使用最后升级版本。插件未来的数据版本转换与当前格式的保全继续存在；已保存恢复材料不因代码退役删除。分版本操作、删码范围与验收判据见[旧格式退役指南](/docs/guides/ops-collaboration-retirement.md)。

产品端点提供受信任来源的 SHA-256 摘要；客户端只向固定产品入口提交匹配来源的旧身份。不同来源身份的合并必须同时证明目标凭据和来源凭据，且合并回执支持安全重试。自托管凭据不外发；迁移失败保留原身份，远程操作等待重试，桌面本机内容编辑不因此被禁用。

旧房间 ID 与正文身份保持不变。桌面旧缓存通过端点解析访问新服务，移动端改写当前库中认可来源的绑定。历史域名不写入源码。ECS旧入口由Nginx返回410，不再兼容转发；旧业务容器停止并禁用自动重启，正式业务不依赖ECS。

## 运维与验证

正式发布、备份、数据导入与域名切换见 [操作指南](/docs/guides/ops-collaboration-deploy.md)。备份期间拒绝新的业务写入，未确认增量由客户端保留；R2 中只有具有完整 manifest 的备份可用于恢复，备份保留7天。

受控导入不能借旧版清单省略新协议要求的记录；恢复后的取消、过期与提交终态保持原语义。

`apps/collaboration-server` 保留为本机开发、自托管参考和旧库导出；其官方 Docker 发布入口已退役。原型与正式实例、桶、管理凭据隔离，独立验证见 [服务说明](/apps/collaboration-cloudflare/README.md)。

### 白板产品状态与传输

白板页面保存原子画风设置；演示使用 whiteboard:presentations 与 whiteboard:presentation-order，序列/帧记录带稳定身份、位置和公共删除标记，播放进度不共享。新增根和页面属性经过同一服务端候选验证，未知根仍拒绝；原契约摘要不原位重算。

位置引用是不可删除的排序事实，选择的位置可撤销；若远端竞争使原值无法恢复，公共历史保留现值而不是删除必需属性，一次历史操作不跳过冲突步骤去修改旧内容。大批复制在隔离候选按单批预算执行，完整验证后合入一个增量；新记录与文字根的初始化保护随增量转交，创建撤销只改变可见性。

完整白板包导出在存在文档级未归属恢复元素时明确拒绝，先确认页面归属再导出；不会把缺少这些元素、契约与资源的包当作完整结果。

whiteboard-transfer-v1 仅包含当前投影、契约、固定外部引用及资源清单，不携带原始共享历史、字段根和租约。可编辑文件最多 32 MiB，其中托管资源总量最多 16 MiB；最终 Y.Doc 仍遵守 8 MiB、页数、元素数及正文根预算。资源复制使用新目标资产身份，旧房间标识不是访问凭据。未知插件数据保留，禁止按同名字段猜测或改写其内部引用。

正文与白板的启动扫描、异常通知和切库调度见[桌面后台格式升级](./desktop.md#正文与白板的后台格式升级)。旧格式在转换期间只读预览，不要求逐篇确认。
