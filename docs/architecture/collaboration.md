# 实时内容协作

## 服务与协议

正式协作入口为 `https://collab.taunote.app`，桌面端与移动端从共享协议包读取同一默认值。服务器为 `apps/collaboration-cloudflare`：Workers 接入请求，SQLite-backed Durable Object 统一管理设备、权限、文档与在线会话，附件和备份保存到私有 R2。

| 通道            | 协议与职责                                             |
| --------------- | ------------------------------------------------------ |
| `/v1/*`         | 设备身份、文档发布、协作码、审批、成员、短期票据和附件 |
| `/ws`           | Hocuspocus 4.6 二进制协议；同一连接可复用多个文档      |
| `/events`       | refresh、presence、revoked、closed 事件                |
| `/health/ready` | 就绪状态、构建标记、正式实例、产品入口、支持的文档版本 |

Worker 在边缘按来源 IP 限流，Durable Object 在连接和消息层继续限制资源；正式服务注册无需原型管理密钥。管理接口独立使用服务器 Secret，客户端不能调用导入、备份或维护接口。未验收激活的实例拒绝业务写入。

仓库内 Node 与 Worker 的 Presence 入口共用 `assertPresenceBudget`：状态 JSON 按 UTF-8 编码计量，最多 16384 字节和 16 个客户端状态；每连接每分钟最多 600 次。在线状态不写入文档及撤销历史。源码中的门禁不代表线上版本已更新。

正文光标通过 Awareness 的 `nodeTreeSelection` 发送稳定选区，失焦或视图卸载时只清除本视图拥有的位置。焦点判断读取 Slate 当前状态，同时响应编辑器状态变化与原生焦点事件，覆盖 Android 输入法恢复焦点但不产生新 `focusin` 的路径。

## 文档与持久化

仓库中的桌面与移动正文编辑使用协议 2：稳定节点池、位置引用、正文片段与不可变契约字典，title 为 Y.Text。移动只调整位置，拆段/合段调整片段归属与边界，不复制文字身份；插件声明的 `textFields` 各自使用 Y.Text。`@tau/editor-collab` 负责 Slate 绑定、光标及源码输入，共享模型与校验位于 `packages/collaboration`。两端与服务端只接纳正文协议 2、白板协议 3；版本 1、缺失版本及未知版本在发布、读取、票据和导入入口明确拒绝，不转换原数据。文档协议与 `/v1` HTTP API 前缀、备份格式 5 相互独立。

契约是节点数据版本的 JSON 说明，按内容摘要去重；节点保存契约引用。声明及完整 v1→v2 示例以[插件作者文档](/plugins/tau-plugin-template/docs/editor-collaboration.md)为准。普通属性默认同步，没有 `SOURCE_FIELDS`、字段名黑名单或 private blocks 同步开关；折叠、当前步骤等视图状态放本机记录，编译结果放可重建缓存。内置代码块的数据版本 2 用 `code-step` 子节点保存各步源码，复用同一 `textFields` 机制。源码字段服务 `IEditorTextFields` 由文档提供：节点树文档按 Y.Text 增量写入；本地 Y.Doc 文档（`createLocalYjsDocument`，如 Markdown 文件窗口）注册 `@tau/editor/api` 的 `slateTextFields`，字段是节点属性，经 Slate 操作整段写入后由 slate-yjs 同步，撤销走该文档的 UndoManager；无文档的临时编辑器由内核提供同样的本地字段。

主库 `contents` 与 `content_documents` 在同一事务保存正文、稳定正文身份、契约和投影修订。CRDT 的真实基线和 epoch 只属于协作缓存及服务端，不能从主库 JSON 冒充原基线；缓存缺失时建立新基线。活跃会话保持其正文及契约，主库接收带来源和观察修订的投影。正文准备、版本转换与校验归正文入口；业务元数据不解释契约，复合创建仍在原事务内携带正文。共用正文只增加原正文引用；独立复制生成新身份并保留来源契约。

外部实体引用由对应领域校验来源身份。`content_entity_relations` 记录正文的关系差集，与正文和目标引用数同事务更新；重复投影、窗口重连和同一正文的多个拥有者不重复记账。撤销及独立本机副本的持有记录不进入随库同步的引用数；回收须同时核查关系与本机持有，无法确认时延迟回收。

Markdown 按节点保存的版本选择导出器；缺少实现时保留携带契约的无损载荷。处理器的节点声明来自宿主声明组（编辑器内置扩展 + 宿主节点持久化声明）加已装插件，不依赖场景编辑器 kit；codec 找不到对应节点声明时建处理器即报错，不静默退化为载荷。HTML/EPUB 缺少匹配实现时明确拒绝，不使用新版导出器猜旧字段。移动端外部 Markdown 导入保留契约，预览按精确版本只读渲染，落库复用原创建事务。索引仅消费正文入口提供的文本与分节，不接收契约字典。

客户端不再调用受控格式转换接口。源码绑定在 Activity 隐藏时释放句柄，恢复时重新打开；旧订阅不能重连已释放句柄，原生源码输入的焦点不进入 Slate。仓库实现与本地验证不代表线上部署或已发行 SDK 已更新。

文档增量在 beforeSync 中完成同步 SQLite 事务后才继续协议处理。快照和增量以 512KiB 分块落盘，避开 SQL 单行限制；重连按状态向量交换缺失增量，压缩以事务替换快照。服务或 Worker 版本变化后从持久存储恢复，不以进程内 Y.Doc 作为持久化依据。

服务端元数据包含设备凭据摘要、文档、成员状态、邀请、审批、资源、审计，以及文档协议、首次发布与普通编辑终态、历史资产关系。设备只向客户端返回一次明文 secret，服务器只保留摘要；连接使用 60 秒签名票据，每条同步消息重新检查成员资格。

协议 2 的候选校验在有界的逐文档队列中执行，持久化前重查权限和代次。缺少先行依赖的增量不返回成功；非法契约、物理替换文字根、普通编辑中的契约版本变化均拒绝。连接票据绑定文档代次与基线，协议 2 的票据请求要求 protocolVersion=2，状态读取要求 x-tau-document-version: 2，旧客户端不能取得不兼容快照。协议 3 的票据请求还必须声明匹配的 epoch/baselineId；普通更新同时禁止身份元数据的新写入，输掉 LWW 的旧身份记录也不能借新票据进入新基线。

HTTP 普通编辑在取得逐文档队列执行权后才加载完整文档，排队期间不持有全文副本。结构化文档的当前摘要随正文和序号同事务更新到既有协议记录，使用与落盘重载相同的 GC 编码；进程首次读取重新核验正文，随后未变化的摘要查询只读元数据。核验缓存绑定实际 SQL 记录值，回滚和导入不能沿用陈旧结果；缺少当前协议记录时直接拒绝，不从正文虚构基线或修订记录。

服务端不注册 `documents/:id/migrations/:operationId` 的 prepare/freeze/commit/cancel 接口，旧请求返回 404。`DocumentProtocolStore` 独立保存当前文档基线、首次发布身份和修订缓存，不创建格式迁移账本；普通编辑回执由 `DocumentOperationLedger` 保存。持久协议中仍带 `migrationId` 或 `frozen` 的旧记录明确拒绝读取，不自动过期、解冻或覆盖。

当前使用单个正式 Durable Object 保持权限、索引与文档更新的事务一致性。配置上限为 20 份活动文档、100 条连接、每设备 5 份共享、每文档 10 名成员、文档 8MiB、附件 25MiB、文档附件 200MiB和全站5GiB。活动文档另受12MiB编码状态内存预算约束，超出时拒绝继续加载或扩大，避免超出运行时内存。此上限属于背压，不承诺20份最大文档同时驻留。

## 白板文档与编辑回执

白板使用同一节点身份、删除标记、多富文本根、宿主历史和实体引用契约。仓库内的白板共享协议为 3，meta 固定 kind=whiteboard、documentId、baselineId、epoch；业务模型仍使用 whiteboard-w1-v1。`document-adapter` 按协议选择正文或白板候选校验、投影和资源扫描，不把白板解读为空正文。白板富文本根复用 `validateNodeTree`；普通增量不能修改种类、基线、契约或重建既有记录/文字根。Node 与 Worker 的发布、WebSocket 接纳和 HTTP 编辑提交均通过此适配器，权限、epoch 与写队列复用公共实现。

普通编辑与整文档修订条件提交走 `/v1/documents/:id/operations/:operationId`，GET 查询终态、POST 提交，`/cancel` 受控取消。请求绑定 epoch/baselineId/version、增量摘要和截止时间；条件请求同时绑定 expectedRevision（完整 CRDT 摘要）与 expectedSequence（服务端单调修订）。`DocumentOperationLedger` 使用 PENDING/COMMITTED/ABORTED/EXPIRED 终态语义，回执、协议修订与正式增量在同一事务中提交。重复 ID 只能使用原指纹；缺依赖保留 PENDING 并返回 MISSING_DEPENDENCIES，不修改确认基线、不推进修订；取消、过期或修订冲突不安装候选。普通条件操作保留 epoch；服务端不提供整份 CRDT 基线的格式升级入口，不允许正文与白板互换种类。

`DocumentSyncSession` 先把提案、确认快照和操作身份交给耐久日志，再调用服务端；连接失败属于结果未知，重启后查询回执。拒绝祖先时保全整条未确认分支及原字节，不跳过祖先发送后继；换代即使没有待发送编辑也保留旧确认快照。隔离完成前不清队列、不安装新基线；隔离后禁止继续使用旧副本，调用方显式获取确认快照重建，材料仍留在日志中。状态回退或摘要/序号不一致拒绝覆盖。桌面实现使用 W4 日志库中的 remote_branches，按规范服务地址、设备身份和文档身份隔离；损坏记录不自动删除。

普通增量取得 EXPIRED 终态后，只有确认仍为同一基线和代次才用新操作身份续传；条件替换、取消、未知结果和换代不走此路径。成功回执只保存幂等元数据，不逐次内嵌完整旧基线；桌面将终态回执按操作身份单独索引，与待确认队列移除原子提交，热同步状态不再反复克隆与写入完整回执历史；未确认和被拒分支材料保持原样。白板渲染端将同一基线的全部 outbox 增量合并验证，补发批次按增量摘要确定身份，主进程耐久确认后才删除原记录，不按窗口 UUID 推断因果顺序。

桌面白板操作期限以最近 HTTP 响应的标准 Date 为依据，不使用客户端墙钟；缺失有效响应时间时停止提交。单次 flush 对同一待确认增量最多续投一次，再次过期返回可重试状态并释放串行队列。持续输入只能提前已有同步排期，不能推迟已安排的发送/轮询，也不绕过断网退避。

画布条件提案是绑定层提供的宿主接口，当前桌面普通同步不接入该条件提案入口，桌面无消费者的 remote-stage/remote-cancel IPC 已删除；共享协议的条件提交与取消能力仍供模型和服务端使用。绑定层只支持已定义的文本编辑和用户几何；等待结果期间冻结该视图写入口。同步先到时缓冲，确认后先用发起视图 origin 安装提案一次，再应用远端结果；重复回执不重记历史，其它视图不记录发起者历史。进程重启保留回执和内容，但不伪造已恢复的内存撤销栈。普通插件未新增通用 CAS 或任意事务接口。

本机日志、投影、关系账、多窗口与生命周期见 [桌面白板架构](/docs/architecture/desktop.md)。白板状态不写入正文 collaboration_bindings；主进程网络入口只打开已经带共享身份的白板，既有纯本机白板仍须经过独立首次发布流程。桌面协作状态以 `whiteboards` 单独列出白板房间（成员、角色、服务地址），协作码、加入审批与移除成员复用正文协作的接口与面板；白板内容的打开、同步与投影只走白板文档会话。成员打开已加入的白板时先在本机资料库落一份由远端确认快照创建的文档，再按同一流程同步。结束共享与退出复用 `/close`（带确认修订条件）与 `/leave`，本机副本在服务端完成后才换成不带共享身份的文档；再次共享建新房间，不复用旧房间。`DocumentSyncSession` 的传输层可提供 `peek` 读取确认摘要，远端未变化的刷新不下载完整状态。上述能力属于仓库实现与本地验证，不表示正式服务已经部署或旧白板已启用共享。

## 资源与私有节点

附件使用 `tau-collab-asset:<id>` 引用，R2 对象按内容摘要保存，读取必须通过文档成员鉴权。上传后重新校验权限并事务检查配额，指定资源 ID 支持幂等重试；相同摘要的上传与回收串行化，避免异步删除误伤新引用。

正文资源只按节点契约中的声明扫描，不维护协议 1 的私有真身、共享占位符、源码字段名单或独立 resources 映射。外部实体引用在领域入口核对来源身份；本地视频、不可读取或超限资源使用不透明的仅本机引用。已被当前正文或历史关系持有的资产不按当前投影缺失回收；未被持有的上传资产仍按七天宽限期回收。关闭共享释放对应资源记录和无其他引用的 R2 对象。旧格式文档无法进入压缩和资源扫描，失败时原快照及资产保持。

协议 3 按精确契约扫描所有保留元素与富文本节点，包括未知插件和删除池；普通同名业务字段不误识别为资源。已接纳状态的资产并入各 epoch 的历史持有。未确认提案可能缺依赖，无法完整扫描，因此服务端保守持有该房间当时已上传的资产，取消/拒绝不会立即回收；持有和操作记录计入现有存储配额，退役须经恢复流程，不增加配额或提供自动历史清理。它不构成对未上传文件、外部 URL 或无权下载资产的完整恢复保证。

服务备份元数据只接受格式 5，Node 导出与 Worker 备份/恢复一致；必含文档协议、首次发布身份、普通编辑回执、单调修订与历史资产关系，不附带格式迁移或身份合并账本。旧格式清单、身份合并账本、缺失当前账本和带旧迁移标记的协议记录在导入写入前拒绝，不以补空表代替已确认记录。导出的活动文档与导入快照同样只接受正文 2 和白板 3，旧快照不能替换已导入的当前快照。

## 客户端与服务器身份

桌面端在 Electron 主进程维护本地协作缓存、Y.Doc、资源队列和多窗口视图同步；开发运行可通过 TAU_COLLAB_DEV_SERVER_URL 指向本地服务，发行版忽略此变量。业务编辑仍经过内容会话，不绕过版本校验与冻结协议直接写正文。

本地协作缓存是可重建缓存：元数据、快照摘要或格式不可读的缓存行把原始快照与增量写入 `collaboration/discarded/` 后删除，共享会话随后按远端确认快照重建，本机会话按主库正文重建；发布与结束共享遇到同身份的旧冷缓存同样备份后让位。刷新共享列表时单篇失败只跳过该篇并在状态里点名，其他文档、加入申请与撤权检测照常进行。正文仍绑定共享但服务器列表已不含该房间时，打开正文解除残留绑定并转为本机编辑。

整库同步下载按同步服务的文件替换协议执行；正文与白板不生成额外恢复副本。替换时内存会话与磁盘冷缓存一并释放，打开时发现本地缓存的来源身份与主库不一致即丢弃缓存、按当前主库重建，规则见[桌面架构](/docs/architecture/desktop.md)。

客户端不再执行正文与白板的格式转换、插件数据升级、备份或恢复。作者声明不再提供 `migrate` / `migrations`；`previousVersions` 仅保留精确版本读取与编辑。旧输入明确拒绝；已有备份文件保持原位。白板首次共享与退出协作保留必要的跨存储提交记录，用于确认当前操作是否完成，不提供历史内容恢复。

移动端通过 WebView 会话和 Rust 缓存保持普通增量与输入草稿的耐久提交；迟到回执不清除新输入。远端代次变化时停止旧连接，不提供保全、导出恢复包或采用新基线入口。页面卸载不立即销毁仍活跃的运行时。

客户端身份按规范化后的实际服务器地址保存：桌面在协作本机存储中按地址取身份，移动在应用私有 identity.json 中按地址取身份；缺失时仅向该地址注册。REST、WebSocket、事件和附件沿各自会话的服务器地址访问，不应用旧地址别名、不向产品入口复制其他地址的凭据，也不改写主库中的协作绑定。同一地址的并发注册去重、失败重试和服务端 Date 仍保留。

产品入口与自托管入口使用独立身份。服务端不注册设备身份合并接口，协议拥有者与操作回执按原始设备 ID 校验；Worker 不创建 identity_merges，已有非空旧合并账本在初始化写入前被拒绝，不自动修复或删除。健康检查不发布旧来源摘要，部署脚本不再配置该摘要。

旧本机身份、别名记录、绑定和缓存不主动删除；原地址不可达时不会改投另一个地址。ECS 旧入口仍由部署配置返回 410，正式业务不依赖它。

## 运维与验证

正式发布、备份、数据导入与域名切换见 [操作指南](/docs/guides/ops-collaboration-deploy.md)。备份期间拒绝新的业务写入，未确认增量由客户端保留；R2 中只有具有完整 manifest 的备份可用于恢复，备份保留7天。

受控导入不能借旧版清单省略新协议要求的记录；恢复后的取消、过期与提交终态保持原语义。

`apps/collaboration-server` 保留为本机开发、自托管参考和旧库导出；其官方 Docker 发布入口已退役。原型与正式实例、桶、管理凭据隔离，独立验证见 [服务说明](/apps/collaboration-cloudflare/README.md)。

### 白板产品状态与传输

白板页面保存原子画风设置；演示使用 whiteboard:presentations 与 whiteboard:presentation-order，序列/帧记录带稳定身份、位置和公共删除标记，播放进度不共享。新增根和页面属性经过同一服务端候选验证，未知根仍拒绝；原契约摘要不原位重算。

位置引用是不可删除的排序事实，选择的位置可撤销；若远端竞争使原值无法恢复，公共历史保留现值而不是删除必需属性，一次历史操作不跳过冲突步骤去修改旧内容。大批复制在隔离候选按单批预算执行，完整验证后合入一个增量；新记录与文字根的初始化保护随增量转交，创建撤销只改变可见性。

完整白板包导出在存在文档级未归属恢复元素时明确拒绝，先确认页面归属再导出；不会把缺少这些元素、契约与资源的包当作完整结果。

whiteboard-transfer-v1 仅包含当前投影、契约、固定外部引用及资源清单，不携带原始共享历史、字段根和租约。可编辑文件最多 32 MiB，其中托管资源总量最多 16 MiB；最终 Y.Doc 仍遵守 8 MiB、页数、元素数及正文根预算。资源复制使用新目标资产身份，旧房间标识不是访问凭据。未知插件数据保留，禁止按同名字段猜测或改写其内部引用。
