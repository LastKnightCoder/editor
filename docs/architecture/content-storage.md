# 正文持久化

## 存储边界

正文的 Yjs 协作协议为 2，与主库的存储布局独立。`content_documents.format_version` 的 2 表示整篇快照，3 表示按顶层块保存；两种布局都承载相同的正文节点与契约，较新的布局标记拒绝读取与改写。

主库 schema 基线为 13。资料库仍通过正常建表与指纹更新打开，不按旧版本标记拒绝已有数据；已有整篇正文不在启动时全库重写，在首次需要按块提交时同事务拆块。

| 位置                            | 职责                                                                                               |
| ------------------------------- | -------------------------------------------------------------------------------------------------- |
| `contents`                      | 稳定本地 ID、创建/修改时间、总字数、引用数；`content` 非空时持有整篇快照，为 NULL 时正文由块表持有 |
| `content_documents`             | 稳定正文身份、存储布局、不可变契约目录和投影修订                                                   |
| `content_document_blocks`       | 按顶层 `collabId` 保存块 JSON、顺序和块字数                                                        |
| `content_document_node_blocks`  | 元素节点到顶层块的归属；复合主键拒绝跨块重复节点身份                                               |
| `content_document_block_counts` | 块字数所用的声明规则，规则变化时重计一次已有块                                                     |
| `content_entity_relations`      | 可见实体关系，与正文块和目标引用数同事务更新                                                       |
| `content_snapshots`             | 完整正文的只读视图；字段与 `contents` 相同，优先返回整篇快照，否则按块顺序拼装 JSON 数组           |

正文读取统一走 `content_snapshots`，不能把 `contents.content` 的 NULL 当作空正文。桌面表、搜索与索引、插件、导出及移动端查询共用该视图；身份、引用数等写入仍作用于 `contents` 实表。

## 常规编辑

主进程的正文会话持有 `NodeTree` 投影缓存。已应用的 Yjs 事务提供触及节点和结构变化；同值属性及空文本增量不推进正文代次。保存捕获本轮代次，并据此定位可见顶层块，避免按物理文字源错误保存拆分或合并后的共享片段。同文档并发保存复用在途任务，等待实际提交后才返回。

非结构编辑只读取、资源本地化、序列化和计数受影响的块。`ContentDocumentBlocks.commit` 核对库、正文身份及观察修订，在单个 SQLite 事务里更新块、节点归属、总字数差量、关系差集、整篇结构预算和修订；正文变化才更新时间并记编辑操作。未修改块的正文载荷不重写，逐块编辑不能绕过整篇结构预算。修订是不透明的并发控制标记，消费者只比较，不自行按整篇 JSON 重算。

结构变化按当前可见根重建顺序，只写载荷、位置或字数实际变化的块。节点移动的关系先合并净变化，避免引用数短暂归零；重复身份、过时修订或任一步失败会回滚整批数据。字数规则及重计结果也处在同一事务内。

保存只确认本轮捕获的代次。资源转换等待期间收到的新输入保留节点代次，投影失败不清除待保存状态。共享作者补存图片导致本机资源地址变化时，重新投影可见块，原资源与持有边界保持不变。

首次建立或恢复会话时完整对账一次，保全冷缓存尚未投影的编辑；结构化 JSON 的键序和默认文本类型不算用户编辑。仅改标题不读取正文；仅补充契约更新文档元数据，不拆块、不更新时间。

## 整篇写入与跨端

`ContentDocumentTable.commit` 继续承载新建、整篇替换和修复，校验契约、身份与关系后原子提交整篇快照。`contents.content` 整篇更新的触发器清除旧块及字数规则，避免读取到旧分块；下一次局部编辑可以重新拆块。

移动端从同一视图读取块布局，整篇写回时核对稳定身份、来源和修订，并将布局更新为整篇快照；旧块、节点归属和块字数规则随同一事务失效。整库同步搬运快照与块表，不依赖本机协作缓存恢复正文。布局 3 的资料库需要配套更新正文读取客户端，不能使用仍直读 `contents.content` 的客户端编辑。

## 耐久日志与检查点

桌面未共享正文由 `local-content` 后台模块打开、编辑和恢复，写入 `local-content/content.db` 的 SQLite FULL/WAL 耐久日志。共享正文使用协作库。打开时以主库共享绑定路由，未共享正文的视图、日志和主库投影无需初始化共享运行时。编辑器节点和契约格式两边共用。

旧协作库中可读的本机会话、增量及草稿事务复制到本机正文库。旧文件保留。主库来源、正文身份、修订与日志基线一致时，重开先恢复未投影增量，再校验并合入未确认正文草稿。源码草稿只在字段原值与所记录的基线一致时合入，冲突副本保留。恢复增量和草稿确认同事务落盘，重复重开不重复输入。

自动保存每秒检查脏标记。主库按块投影，日志达到 128 条增量或 512 KiB 才压缩完整 Yjs 检查点。关窗、切库、退出和共享交接经统一保存屏障排空输入，未确认时保留视图。

缓存增量落盘失败时仍保留正文代次及待投影状态；重试先补存完整检查点，即使尚未达到普通压缩阈值，也不能先确认保存。正文块、日志和同步分支的原有冻结、退出及失败回滚边界继续适用。

## 成本边界

增量单位是顶层块，单个巨大段落或源码块仍需序列化该块。首次拆块、完整替换、结构变化、冷缓存对账、字数规则变化及检查点压缩仍可能处理完整正文。需要全文的索引、导出与读取仍承担全文成本；这些成本不能算作零开销的字符级持久化。

## 诊断日志

正文持久化诊断使用 `[content-save]` 前缀，写入既有主进程 session 日志，不另建文件。事件覆盖首次对账、布局切换、增量接纳失败与恢复、主库提交失败与恢复、缓存恢复及检查点完成。字段包括会话和稳定正文 ID、本地正文 ID、阶段、正文/契约代次、选中及写入块数、修订摘要、耗时、待保存状态和安全错误分类；不记录正文、标题、二进制载荷、服务凭据、原始错误消息或文件路径。

增量接纳与主库投影的故障状态分别关联，接纳恢复不等于主库已经投影。异常的 `journalSaved` 表示输入增量已进入耐久日志，`committed` 表示主库提交已完成，可区分回滚与后续通知失败。连续相同阶段与原因的失败、正常增量提交摘要按每会话 30 秒限频，100 毫秒以上的慢保存同样限频；恢复日志附带省略的重复故障次数，恢复后的新故障重新记录。日志输出异常不改变保存回执。

验证步骤与判据见[正文保存压力验证](/docs/guides/development-quality.md#正文保存压力验证)。
