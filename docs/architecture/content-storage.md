# 正文持久化

## 模型与接线

| 层次       | 现有实现与职责                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 正文模型   | `@tau/collaboration` 的 `NodeTree` 和正文校验承载节点、文本片段、标题、不可变契约与结构限制。编辑器把输入转换成 Yjs 增量，插件和 Agent 经过受控写入口              |
| 用例       | `content-ownership/` 编排新建、独立复制、共用、释放和整篇替换。卡片、文章和项目条目保留业务元信息与持有关系。会话接受增量、记录耐久进度、向主库投影并维护视图租约  |
| 存储适配   | `NodeSessionJournal` 负责日志提交，`ContentProjectionStore` 负责主库投影，`LocalContentSource` 负责绑定连接后的正文读取和打开准备。SQLite 适配器执行事务和来源复核 |
| 宿主与组装 | 桌面组合根在 `content-runtime/composition.ts`，共享管理器独立组装会话并接入网络。移动端经 Tauri 命令接入资料库事务，共用主库存储契约                               |

持久正文身份由资料库来源 `source_id` 和 `content_documents.document_id` 定位，主库 `contentId` 用于库内关联。写入按入口复核实际 SQLite 连接或移动端库代次、`contentId` 和创建时间。运行中的正文另有会话 ID、`baselineId`、`epoch`，共享绑定还包含服务器与房间。主库投影修订、Yjs 快照摘要和服务端操作序号分别用于各自的并发检查。复制生成独立正文和新节点，首次发布与解绑可更换运行中的基线而保留业务持有和稳定正文身份。

桌面输入经 IPC 到会话校验与日志接纳。实时视图使用已接纳增量，主库消费者使用提交后的正文快照，远端条件操作使用原操作回执。普通正文列表、导出和索引读取快照。编辑或需要打开修复的入口使用带作用域的会话。需要参与事务的持有、契约和引用更新在主库提交，索引等派生数据通过写入事件增量处理，并在连库时根据主库重新对账。

## 存储边界

正文的 Yjs 协作协议为 2，与主库的存储布局独立。`content_documents.format_version` 的 2 表示整篇快照，3 表示按顶层块保存；两种布局都承载相同的正文节点与契约，较新的布局标记拒绝读取与改写。

主库 schema 基线为 13。资料库仍通过正常建表与指纹更新打开，不按旧版本标记拒绝已有数据；已有整篇正文不在启动时全库重写，在首次需要按块提交时同事务拆块。

| 位置                            | 职责                                                                                               |
| ------------------------------- | -------------------------------------------------------------------------------------------------- |
| `contents`                      | 稳定本地 ID、创建/修改时间、总字数、引用数；`content` 非空时持有整篇快照，为 NULL 时正文由块表持有 |
| `content_documents`             | 稳定正文身份、存储布局、不可变契约目录和投影修订                                                   |
| `content_document_blocks`       | 按顶层 `collabId` 保存块 JSON、顺序和块字数                                                        |
| `content_document_node_blocks`  | 元素节点到顶层块的归属；复合主键拒绝跨块重复节点身份                                               |
| `content_document_block_counts` | 块字数所用的声明规则，规则变化时重计一次已有块                                                     |
| `content_entity_relations`      | 可见实体关系，与正文块和目标引用数同事务更新                                                       |
| `content_snapshots`             | 完整正文的只读视图；字段与 `contents` 相同，优先返回整篇快照，否则按块顺序拼装 JSON 数组           |

正文读取统一走 `content_snapshots`，不能把 `contents.content` 的 NULL 当作空正文。桌面表、搜索与索引、插件、导出及移动端查询共用该视图；身份、引用数等写入仍作用于 `contents` 实表。

## 新建与独立复制

`ContentCreation` 接收已经准备好的正文。带契约的新正文取得新的稳定文档 ID，递归重分配元素节点 ID，并在同一 SQLite 事务写入正文、契约、嵌入关系、初始引用和正文流水。普通卡片与文章在这笔事务中插入业务行和业务流水，初始正文引用为 1。待回收正文初始引用为 0，待回收登记和正文同时提交。创建用例完成后才发出创建事件，调用方存在外层事务时，订阅方沿用防抖重读。

插件 `copyOf` 按正文编号、创建时间和可寻址性定位来源，优先读取活跃会话。深拷贝节点和契约后完成异步转换，写入前核对目标库和连接。副本经同一新建流程生成独立身份，原文编辑与副本编辑各自持有自己的正文。

## 正文的业务持有

卡片、文章和项目条目通过各自的 `content_id` 持有正文。复用同一个项目条目时只改变目录挂载。删除被项目条目引用的卡片或文章时，清除该项目条目的原实体类型，项目条目继续持有正文。`content_links` 记录知识连接，正文最后一次持有释放并物理删除时才清除相应连接。

行内 `content-link` 是导航引用。嵌入白板页、数据表和项目卡片列表通过稳定实体引用记录于 `content_entity_relations`，其引用计数按目标实体的持有语义修改。本机日志中撤销、草稿等历史持有供安全回收判断，独立于随库同步的主库引用计数。

已有正文建文章和删除文章由 `ArticleContentOwnership` 确定事务边界。SQLite 表适配器在同一事务创建或删除文章行、登记业务流水及增减正文持有。重复构建复用已有的未删除文章。删除先查共享绑定，清理文章行、索引和项目引用类型，再按入口选择即时或延迟释放。普通删除只在最后持有释放时物理清除正文。可恢复的插件删除在计数归零时登记待回收，恢复时重新持有并取消该登记。

`CardContentOwnership` 管理卡片共用、项目派生和删除的同步事务。从已有正文构建时复用已有卡片，每次从项目条目派生则增加一张新卡片及一份持有。普通和限定资料库删除在同一事务清理卡片、索引、项目引用类型、流水和正文持有。即时释放经正文入口检查协作绑定，归零时物理删除。插件删除沿用延迟释放，模式卡片撤回沿用包括谱系和标记的外层事务。

`ProjectItemOwnership` 管理项目条目新建、目录挂载、解除和释放的同步事务。新条目建立一次正文持有，已有条目在多个位置共用只改变目录。普通解除根据实际项目根和父子边核对其余挂载，子树内的条目在最后一处解除时各释放一次。父条目可跨项目共享，同一父子边被移除时核对该父条目所在的所有项目。目录写入只更新结构字段和时间，用户明确改名继续经正文标题入口。插件从全部位置删除叶子条目时保存恢复位置并延迟释放，恢复时校验正文创建时间并重新持有一次。

跨项目移动按源和目标的实际目录边更新顺序、父关系与子树的项目归属。移动保留条目和正文身份。外部父边或项目根仍可达的子文档保留对应项目归属。子树按显式栈遍历，单次遍历对每个条目去重，移动和最后一次解除挂载均可处理深层目录。

整项目删除在同一 SQLite 事务内撤销目标项目的成员资格并释放独有条目，清理幸存条目的悬空目录关系。独立的无项目条目由显式清理入口处理。

项目条目改名及插件显式改名先提交主库业务行和操作流水，再向原活跃会话传播标题。传播前复核原会话、冻结状态和观察到的标题，后续标题投影继续同步共用正文的标题。

## 常规编辑

主进程的正文会话持有 `NodeTree` 投影缓存。已应用的 Yjs 事务提供触及节点和结构变化；同值属性及空文本增量不推进正文代次。保存捕获本轮代次，并据此定位可见顶层块，避免按物理文字源错误保存拆分或合并后的共享片段。同文档并发保存复用在途任务，等待实际提交后才返回。

会话在本地化资源前读取 `ContentProjectionStore` 的投影头并捕获预计修订。等待结束后复核数据库连接、会话和来源，以捕获的修订提交分块或整篇候选。若同一会话的任务助手先提交并推进观察修订，较早的候选仍使用原修订并被拒绝。正常晚到的输入留在待投影代次。

SQLite 适配器在同一同步事务内复核正文创建时间、资料库与正文身份、协作绑定及布局兼容性，再提交候选与正文编辑流水。任务助手的同步整篇写入使用同一适配器，已有相同内容的回执重放先判定无变化。会话提交后重新读取投影头、确认本轮代次并更新日志元数据，标题仍使用独立事务，正文实际变化时再通知消费者。

非结构编辑只读取、资源本地化、序列化和计数受影响的块。`ContentDocumentBlocks.commit` 核对库、正文身份及观察修订，在单个 SQLite 事务里更新块、节点归属、总字数差量、关系差集、整篇结构预算和修订；正文变化才更新时间并记编辑操作。未修改块的正文载荷不重写，逐块编辑不能绕过整篇结构预算。修订是不透明的并发控制标记，消费者只比较，不自行按整篇 JSON 重算。

结构变化按当前可见根重建顺序，只写载荷、位置或字数实际变化的块。节点移动的关系先合并净变化，避免引用数短暂归零；重复身份、过时修订或任一步失败会回滚整批数据。字数规则及重计结果也处在同一事务内。

保存只确认本轮捕获的代次。资源转换等待期间收到的新输入保留节点代次，投影失败不清除待保存状态。共享作者补存图片导致本机资源地址变化时，重新投影可见块，原资源与持有边界保持不变。

首次建立或恢复会话时完整对账一次，保全冷缓存尚未投影的编辑；结构化 JSON 的键序和默认文本类型不算用户编辑。仅改标题不读取正文；仅补充契约更新文档元数据，不拆块、不更新时间。

## 整篇写入与跨端

`ContentDocumentTable.commit` 承载新建、整篇替换和修复，校验契约、身份与关系后原子提交整篇快照。`contents.content` 整篇更新的触发器清除旧块及字数规则。下一次局部编辑可以重新拆块。

`ContentReplacement` 根据主库连接上的会话登记分派整篇替换。活跃会话核对 Yjs 修订、会话和连接，在资源准备后再次校验，经耐久日志接纳并投影。冷写通过 SQLite 适配器核对主库修订，将正文、契约、嵌入关系、目标引用计数和流水同步提交。裸 JSON 的更新与流水同属该事务，带修订的调用核对 `u:<update_time>`。关文档的日记、每日笔记与任务助手通过冷写入口。

插件正文写用例在异步转换前后核对连接、正文创建时间、修订和会话实例，复用整篇替换入口。冷写来源在同步 SQLite 写入时记录，活跃写待耐久日志接纳后标记投影来源。

移动端从同一视图读取块布局，整篇写回时核对稳定身份、来源和修订，并将布局更新为整篇快照；旧块、节点归属和块字数规则随同一事务失效。整库同步搬运快照与块表，不依赖本机协作缓存恢复正文。布局 3 的资料库需要配套更新正文读取客户端，不能使用仍直读 `contents.content` 的客户端编辑。

## 耐久日志与检查点

桌面未共享正文由 `local-content` 后台模块打开、编辑和恢复，写入 `local-content/content.db` 的 SQLite FULL/WAL 耐久日志。共享正文使用协作库。打开时以主库共享绑定路由，未共享正文的视图、日志和主库投影无需初始化共享运行时。编辑器节点和契约格式两边共用。

桌面组合根 `content-runtime/composition.ts` 打开本机日志库，初始化 Agent 建议与权限表，再组装运行时。`desktop-services.ts` 为每个运行时注入增量队列、持有查询、资源服务以及按连接创建正文读取和投影适配器的工厂。组合根在 IPC、保存屏障及窗口接线就绪后才发布本机运行时。启动注册失败会撤销本轮 IPC 及生命周期注册，释放本轮日志连接，允许后台模块重试。

本机 Agent 工厂由组合根提供，运行时在首次使用时把会话、保存、在场和共享操作注入同一个 Agent 服务。数据库命令装配直接登记 Agent 的范围编辑、建议、权限和在场处理器，各入口按需取得该服务。建议和权限与本机日志同库，共享运行时复用该 Agent，远端读写经当前共享桥接。受控退出先确认文档保存，再停止共享连接和本机后台任务，注销本机 IPC 与生命周期监听。

本机正文和共享正文分别组装 `ContentSessionRuntime`，各自维护会话、视图租约、增量日志、检查点和保存屏障。网络连接及交接归共享管理器，它通过 `LocalContentSharingAccess` 排空本机会话或接收退出后的正文。本机通过 `SharedContentBridge` 打开已绑定的正文和提交共享范围操作。两边的交接及回执归属见[实时内容协作](/docs/architecture/collaboration.md#桌面共享接线与交接)。

正文增量接纳通过 `NodeSessionJournal` 提交。本机与共享运行时分别接入各自日志库的 SQLite 适配器。适配器在同一同步事务中按候选持有、增量、可选条件操作回执的顺序写入，接纳队列随后才更新运行中的文档并确认草稿。候选与当前状态相同时，仍检查持有和检查点，有回执则单独提交回执。草稿通过独立端口确认，主库正文投影使用独立事务。

主库来源、正文身份、修订与日志基线一致时，重开先恢复未投影增量，再校验并合入未确认正文草稿。源码草稿只在字段原值与所记录的基线一致时合入，冲突副本保留。恢复增量和草稿确认同事务落盘，重复重开不重复输入。

`ContentSessionLifecycle` 按实际连接、窗口及正文编号合并重复打开，并按关窗、切库或退出的范围撤销在途打开。`LocalContentSource` 固定主库连接，独立读取来源、正文身份、创建时间和修订，建立新基线时才载入快照。等待自愈、草稿校验和资源准备后复核打开范围与正文身份。共享绑定出现时经共享入口继续处理。

自动保存每秒检查脏标记。主库按块投影，日志达到 128 条增量或 512 KiB 才压缩完整 Yjs 检查点。关窗、切库和退出先冻结命中会话，等视图回执后确认检查点和主库投影。已有投影若早于最后一批输入，屏障在原连接上补投末代。失败后恢复原视图，已耐久输入保留供重试。单窗口换库提交时撤销该窗口的旧租约，其他窗口继续使用原库会话。整库替换保持原会话冻结，交由原有释放及重连流程处理。共享交接继续经自身冻结与确认流程。

缓存增量落盘失败时仍保留正文代次及待投影状态；重试先补存完整检查点，即使尚未达到普通压缩阈值，也不能先确认保存。正文块、日志和同步分支的原有冻结、退出及失败回滚边界继续适用。

## 成本边界

增量单位是顶层块，单个巨大段落或源码块仍需序列化该块。首次拆块、完整替换、结构变化、冷缓存对账、字数规则变化及检查点压缩仍可能处理完整正文。需要全文的索引、导出与读取仍承担全文成本；这些成本不能算作零开销的字符级持久化。

## 正文编辑历史

桌面和手机在读取个人历史以及上传资料库时，按资料库来源和正文身份把可回放版本归入主库 `content_history_versions`。其中每条保存增量或完整检查点，按稳定身份关联前序版本和撤销目标。列表读取允许当前一组继续合并；预览固定所选版本，上传固定本轮携带的版本。每条历史沿自己的前序回放，其他设备先前独立形成的同号版本可以共存。替换资料库前在本机保全已接收的版本，恢复时只匹配同来源且仍存在的正文。两端以落盘版本计算快照间隔，自最近快照起满 128 条记录或累计回放增量达 1 MiB 时保存完整快照。旧客户端保留附加表，在旧设备上产生的本机历史待该设备升级后归集。

桌面活跃正文通过耐久日志事务保存编辑记录与 Yjs 增量。历史分片随历史清单独立于会话恢复日志的压缩。本机历史按资料库来源和稳定正文身份索引。关着正文的结构化写入在主库同时登记历史，打开正文时把这些提交合入本机历史，按操作 ID 去重。移动本机正文通过 Rust 会话缓存事务登记增量与历史，沿用相同的正文身份。共享历史的权威入口在协作服务器。

同一作者、同一来源的连续编辑写入时并入最新一条记录（`DocumentHistoryStore.append`，移动端为 `content_history::record` 的 `mergeInto`）：距上次编辑超过 5 分钟、从首次编辑起超过 30 分钟、作者或来源变化、最新记录已封口或为检查点时另起一条。撤销、恢复与基线不参与合并。合并后记录的增量为整段会话的合并增量，`startTime` 记首次编辑时间，`time` 记最后一次，操作 ID 换成最近一次写入的。合并容量按载荷的净增长与元数据余量检查，不重复计算被替换的旧载荷。

查看历史时先封口指定记录，再读取与回放；后续编辑不能改变已预览版本的撤销范围。查看旧记录不会封口较新的记录。桌面打开本机正文且没有其他视图时封口最新记录；移动端合并状态只在本次打开内有效，查看当前记录后同步清除内存合并状态。共享连接通过鉴权时只封口该设备的最新记录，重开与断线重连后的输入不并入之前的批次，其他成员连接不打断当前作者。关着正文的结构化写入与其导入的记录不合并，按操作 ID 去重仍然成立。历史不按保留期限抽稀。

每条记录保存版本号、操作 ID、编辑时间和来源，并指向最近的检查点。首次接纳前、正文基线变化和回放量达到阈值时保存完整检查点。桌面和服务端将二进制分为最多 512 KiB 的片段。查看历史在独立 Y.Doc 回放，主文档的渲染按原会话推进。历史预览可显示完整正文以及与上一版本的块和标题差异。

恢复版本以预览时的当前修订为前提，范围撤销复核目标文字、格式、节点和位置。文本范围可以沿现有锚点跟随后续不相交编辑。结构变化不满足反向变更前提时整组拒绝。恢复和撤销成功后各自提交新增量与历史记录。旧数据中已压缩清除的编辑从启用时的历史起点开始记录。

## 诊断日志

正文持久化诊断使用 `[content-save]` 前缀，写入既有主进程 session 日志，不另建文件。事件覆盖首次对账、布局切换、增量接纳失败与恢复、主库提交失败与恢复、缓存恢复及检查点完成。字段包括会话和稳定正文 ID、本地正文 ID、阶段、正文/契约代次、选中及写入块数、修订摘要、耗时、待保存状态和安全错误分类；不记录正文、标题、二进制载荷、服务凭据、原始错误消息或文件路径。

增量接纳与主库投影的故障状态分别关联，接纳恢复不等于主库已经投影。异常的 `journalSaved` 表示输入增量已进入耐久日志，`committed` 表示主库提交已完成，可区分回滚与后续通知失败。连续相同阶段与原因的失败、正常增量提交摘要按每会话 30 秒限频，100 毫秒以上的慢保存同样限频；恢复日志附带省略的重复故障次数，恢复后的新故障重新记录。日志输出异常不改变保存回执。

可重放的跨端、回执、故障和容量验证见 [正文回归与容量验证](/docs/guides/dev-content-verification.md)。日常保存诊断见 [正文保存故障排查](/docs/guides/development-quality.md#正文保存故障排查)。
