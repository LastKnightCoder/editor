# 局域网个人设备同步

## 范围与入口

桌面设置 → 同步 →「设备同步」页签与移动设置 → 同步顶部的「局域网设备同步」提供显式开启的实验入口，云端存储同步在其后单独呈现。同一资料库由一台电脑协调事务顺序，其他电脑和手机作为连接端独立配对、离线编辑并自动补齐。连接端不会因为暂停或恢复而提升为协调端，不自动选主。正文复用协议 2 的节点树 Yjs，标题、标签与其他主库数据走线性事务，无法证明安全的元数据分叉保留完整主库副本，日常同步不弹资料库选择框。

协议同步主库、正文二进制与正文声明的本机图片附件。聊天 JSONL、独立 PDF 原件、插件安装包、设置凭据及索引库不属于此传输。已有云端共享正文的库拒绝开启设备同步；配对库也拒绝新增云端正文共享，避免两套身份与权限同时接管同一正文。云端提供方整库搬运见 [宿主分块同步](./storage-sync.md)。

### 界面

- 未登记的库并排给出「由本机协调」与「连接已有协调电脑」（粘贴配对信息）；手机只有连接端。界面由 `status.role / enabled / phase` 驱动：已配对数取 `peers.length`，只表示授权数，不表示在线。
- 协调端：一句状态 +「添加设备」，配对信息就地展开（单行显示、复制、本地倒计时、过期后重新生成）；`peers` 新增一项即提示已配对并收起。设备两列行式列表，解除配对经确认；暂停收在 ⋯。
- 连接端：一句状态 +「立即补齐」，暂停与重新粘贴配对信息收在 ⋯（手机没有暂停接口，只写去协调电脑操作）。「下载协调电脑版本并覆盖本机」放在隔开的「恢复」区，经一次应用内确认；离线或暂停时不可用。
- 错误经 `@tau/collaboration/src/device-sync/messages` 把 `DEVICE_SYNC_*` 翻成说明与下一步，两端共用；配对信息在渲染端只解出有效期与主机名，不读密钥。
- 桌面覆盖成功或安装后失败都会重载持有该库的窗口，渲染端拿不到 IPC 返回：发起前在会话存储留标记，壳层重载后读一次状态给出结果提示。

## 合并补齐与明确覆盖

| 动作                                   | 当前库的安装语义                                                             |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| 日常增量、离线返回及历史缺口的快照补齐 | 同基线正文继续 Yjs 合并，本机多出的更新重新进入待确认队列                    |
| 连接端的“下载协调电脑版本并覆盖本机”   | 只读下载协调设备快照，以远端为唯一基线；不提交本机待同步数据，不合并本机正文 |

明确覆盖复用同一 SQLite 安装事务：业务表和正文检查点完整替换，清除本库旧日志、转换意图、回执、历史及冲突材料。保留本机设备身份、配对凭据与单调来源序号下界。`_tau_device_local.generation` 在同一事务内换新，正常同步不改变它；辅助状态重建不能移除该标识。

移动端覆盖入口串行等待本库在途操作，并暂时停止该库编辑及正常同步。旧会话和旧提交携带的版本不再有效。编辑缓存命名包含持久本机版本，撤销栈随旧编辑器销毁；旧缓存、输入草稿、视图状态与迁移记录按库清理。即使在主库提交后、清理缓存前中断，新版本也不会读取旧缓存；迟到的旧缓存写入只能落到旧命名空间。本机账号、其他资料库不参与重置。

移动正文输入产生时即固定资料库名、持久 generation 和内存覆盖版本；节流、串行保存、失败重试和 JSON 转换沿用该上下文，执行旧任务不能领取新版本。覆盖开始及结束都使旧页面队列失效，重新读取正文后才能建立新编辑上下文。原生 JSON 保存和耐久正文保存均在最终写入事务内核对 generation，资料库切换也拒绝旧库 JSON 请求。保存失败仍返回失败。

桌面现有云端下载沿用关闭、替换和重连流程，同时释放活动与冷正文缓存，并清理本库草稿及视图状态。移动云端下载使用相同编辑门禁，安装前校验候选文件，更新候选库的本机版本，再替换主库文件。备份与 discarded 目录仅供查看，不自动回放。附件按新快照引用补齐，未引用的旧文件不会再次上传；共享文件池不因覆盖单库而整体删除。

桌面连接端明确覆盖时先使旧排队对账失效，再只读下载协调端快照。持有既有资料库维护锁并关闭旧连接后，在独立候选文件中按原本机身份与单调序号下界安装快照、轮换 generation，校验成功后才替换主库。旧库先复制到 backup，正文/白板会话、冷缓存和草稿按库清理；随后重新连接并重新加载持有该库的窗口。窗口重新连接前不接受数据库命令，旧连接及已释放会话不能写回；失败同样恢复原库连接。主进程为本机资料库槽位签发命令上下文，明确覆盖关库时使旧上下文失效；渲染端在绑定命令和异步正文准备前固定该值，同一执行上下文再次绑定或重试仍沿用原值；显式库请求进入主进程时必须核对，因此其他仍存活窗口的旧任务也不能领取新库连接。普通关库及上传重连保留命令上下文。维护重连和覆盖后的窗口恢复只恢复原库绑定，不改变其他库的活动选择；按活动库运行的后台服务不随其他库的维护重连切换。其他库窗口、账号和配对凭据不参与重置。

## 模块归属

| 层             | 位置                                                   | 职责                                                 |
| -------------- | ------------------------------------------------------ | ---------------------------------------------------- |
| 共享模型       | `/packages/collaboration/src/device-sync/`             | 协议、正文候选校验、状态向量、回执与补齐状态机       |
| 共用元数据结构 | `/packages/db-schema/schema/device-sync.sql`           | 资料库内耐久状态、变更日志、正文检查点与副本         |
| 桌面宿主       | `/apps/desktop/src-electron/main/modules/device-sync/` | SQLite 事务、排序、证书配对、HTTPS、附件和冷状态保全 |
| 移动原生       | `/apps/mobile/src-tauri/src/device_sync/`              | SQLite 原子安装、固定证书请求、附件校验与落盘        |
| 移动编排       | `/apps/mobile/src/services/device-sync/`               | 前台调度、Yjs 编解码、旧 JSON 意图转换和附件补齐     |

桌面模块是 BACKGROUND，渲染端用 `withModule` 等待就绪。端口默认 24721，仅在用户开启后监听。初始化失败保留设置入口与错误信息；数据库重连后重新绑定实际连接对象，启动操作串行执行。

桌面 `server.ts` 仅承担协调端；`transport.ts` 负责私网地址与固定证书请求，`replica.ts` 负责独立副本和配对凭据，`client.ts` 负责串行补齐、退避及附件，`index.ts` 负责真实资料库、会话和 IPC 装配。四者复用现有共享引擎与存储，不新增同步协议或业务 Schema。首次桌面配对创建独立 `.db`，成功后登记并切换；同源重配复用本机副本并保留未确认修改。每个桌面安装当前保存一份上游连接记录，保存在设备私有目录，不进入主库。

桌面连接端在资料库连接后启动后台对账，正常约一秒一次，失败从两秒起退避，最长一分钟；应用恢复及窗口聚焦唤醒。网络等待不占用编辑事务，也不阻塞开库。明确覆盖及停止连接使旧队列版本失效，在途响应仍需通过存储身份、generation 和观察序号检查。下载在安装前失败时，只要原连接仍有效且未暂停，就恢复退避调度；旧下载任务不能重新启动已停止或已换代的连接。

## 耐久记录与所有权

`_tau_device_*` 是设备协议内部表，两端加载同一 SQL，不进入 99 张商业主表的结构契约。它们随 SQLite 文件保存，接收行变更和检查点时单独处理，不能作为普通业务行复制。

| 记录                       | 内容                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------- |
| `_tau_device_state`        | 资料库、结构指纹、来源、排序设备、epoch、确认头、单调修订及待快照标志              |
| `_tau_device_local`        | 本机安装版本；明确覆盖时轮换，日常同步及辅助重建保持不变                           |
| `_tau_device_anchor`       | 最近有效同步身份及本机序号下界，用于辅助状态损坏后的恢复                           |
| `_tau_device_documents`    | 正文 ID、真实 Yjs 基线、epoch、完整二进制、资源映射、纯数据统计规则与 SHA-256 校验 |
| `_tau_device_log`          | 有序行前后镜像、正文待确认标记、投影阶段及完整性封套                               |
| `_tau_device_json_intents` | JSON 写入发生前的二进制基线、目标正文及契约、条件提交令牌                          |
| `_tau_device_history`      | 排序后的事务记录与正文确认状态                                                     |
| `_tau_device_receipts`     | 来源序号、提交指纹和分叉保全结果                                                   |
| `_tau_device_branches`     | 无法重放的完整主库行集合及全部正文二进制                                           |
| `_tau_device_note_copies`  | 基线不兼容、删除后回来的输入或合并受限时的完整笔记                                 |

普通本机正文保留图床 URL 与本机资源地址；设备同步正文在资源入口转换为不透明标识，并由附件映射指向内容寻址文件。首次启用时从正文及有效缓存输入建立可传输新基线，原始本机地址及其历史不进入线协议；已建立的耐久基线继续使用原二进制，离线补齐不重新生成。

正文检查点是配对库的权威，`contents.content` 与 `content_documents` 是同事务提交的投影；协作缓存仍保存视图草稿、撤销持有与输入草稿。重启或快照补齐加载原始二进制，不从旧 JSON 重建一个相似文档冒充原基线。新正文尚无二进制时拒绝发布增量，避免两端各自初始化。

移动端首次准备导入或后台创建的正文时，在读取待准备记录前固定 generation，并显式随每次保存传给原生守卫；准备期间发生明确覆盖，旧准备结果不能落库，后续轮次按新基线重新准备。

正文修改的连带变化分成两个阶段：

- 本机阶段执行既有业务方法，维护离线可用的引用数、待回收记录与统计；通用触发器把这些变化标为投影，和用户显式元数据区分。
- 排序设备合并 Yjs 后调用既有桌面业务方法，在同一事务捕获实际派生行结果。接收端撤回自己的未确认行结果，重放确认行，再安装正文标量投影，不重复推导引用和统计。

因此不需要逐表写合并器，也不要求两种语言重新实现一套跨表合并规则。正文的 JSON、契约、计数与修订由正文状态机管理；其他关系和计数以确认事务的行结果为准。标题不由正文 Yjs 的 title 投影覆盖。本机会话将标题归属持久保存为 database，辅助状态丢失不会使旧正文标题重新获得覆盖权。

业务代码仍可带修订写正文 JSON；触发器先保存原 CRDT 与目标 JSON。转换器在原基线上生成节点操作、合并最新二进制，并以令牌和观察状态条件提交。未完成转换不能对外确认，转换与确认之间新增输入则重试。

## 增量、快照与保全

线协议版本为 2，与正文协议 2、历史独立原型的协议号分别校验。两端都必须支持恢复保全语义，旧线协议会被拒绝；配对信封和 HTTP 路径仍为 v1。SQL 表、字段与主键从实际结构读取；行序保留，SQLite 外键和约束在一个事务内验证，回放期间不重复执行已有持久业务触发器。整数使用十进制标记保存完整 i64，浮点与 BLOB 使用各自的值表示。

正文正常传输 Yjs 差量。接收状态未知时先交换所需文档的状态向量；进程首次恢复允许发送完整正文检查点。DeleteSet 仍随差量传播，不能只用状态向量相等判断没有变化。

来源发送确认头、当前本机序号、元数据变化和待确认正文。排序设备先封存本机变化，元数据仅在共同提交基线上重放；正文按自身基线合并。接纳前后及安装前都检查本机序号，校验、网络或维护等待期间的新输入不会被迟到响应确认。回执按完整正文摘要计算逻辑提交指纹，差量重发与重启后的完整重发具有同一身份。

历史缺口返回全库检查点。安装会从二进制重新生成正文投影，并合并本机仍有的同源正文；本机多出的二进制状态重新进入待确认队列。未知结果不清空待确认内容。排序头比移动端观察值旧时拒绝覆盖；桌面在库文件外原子保存已发布的 epoch、修订和头，恢复旧库不能继续发布旧检查点。

元数据分叉先要求来源提交完整主库快照，保全后继续共同库。完整副本保存所有商业行和正文基线；同一序号但不同材料使用不同指纹标识。正文不兼容时保留笔记副本。桌面设置可将保留库另存为独立 `.db`，或导出笔记原始材料供检查；没有自动切库步骤。

接收主库快照及元数据事务共用 AI 维护边界；忙态拒绝并自动重试。移动快照安装还进入插件工作区替换边界，回收旧租约后重建插件上下文。正文实时更新经会话广播，元数据提交后失效所属库的查询。桌面安装涉及白板表的增量、撤回行或全库快照前，复用白板排空屏障：先冻结相关库视图并确认输入已投影，再按原观察序号提交 SQLite 事务。排空产生了新输入时本轮安装重试；事务失败回滚屏障并恢复原租约，成功后释放旧租约，由现有客户端重新打开并按新主库重建模型和日志。未确认输入不能因刷新查询而丢弃。

## 历史与长期离线

确认历史最多保留 128 条且总载荷不超过 16 MiB；缺失历史靠主库检查点补齐。未确认的派生行与显式元数据各有 8 MiB 日志预算。派生记录超限后标记必须快照；元数据超限后也可折叠日志，但必须走完整副本保全后再安装快照，不能把日志清空当成确认。正文检查点仍保留。后台对账检查预算；正在进行的大事务在完成前仍可能暂时超过预算。

正文保持 `gc: false`。实体回收读取冷检查点中仍保留的历史引用，并保护对应正文；无法读取时保守保留。正文删除后回来的输入可存为单篇副本，不恢复已经删除的拥有者。没有按设备离线天数删除未确认输入、未解决副本或附件的规则。

## 辅助状态恢复边界

两端存储入口共用 `device-sync-health.sql` 检查辅助表结构、记录形状、待发送数量与日志封套，恢复模块只负责隔离、重建和标记重新对账，不承担业务合并。未登记资料库不安装通用变更捕获触发器。启动和后台准备会检查；读取损坏身份、正文二进制或本机正文缓存时也会进入对应恢复路径。业务触发器用 `CASE` 保护 JSON 读取，损坏的辅助 JSON 不应使普通业务写入报错。

本机版本表独立使用共享的 `device-sync-local.sql` 与 `device-sync-local-health.sql`，检查精确列结构、唯一记录和版本值；初始化、版本读取及移动云端下载候选库共用此边界。结构异常时仅在事务内归档并重建该表，正文检查点、业务行、转换意图和有效待确认日志保持原样。能确认唯一有效旧版本时保留它；版本缺失或无法确认时生成新的 UUID 命名空间，旧会话、任务及缓存随原版本失效。只有从未安装设备辅助表的库初次初始化允许沿用空版本。锁忙、只读、磁盘满及 I/O 错误直接返回，不当作结构损坏，不通过返回空版本伪造恢复成功。

恢复在事务内先移除设备触发器，把原辅助表改名保留到 `_tau_device_quarantine_*`，再建立当前结构。可读正文及副本继续保留；坏正文及待转换意图的原材料留在隔离表，重建优先使用通过校验且观察修订仍相符的活动会话，保留编辑中的原基线与输入；没有健康副本时，才从当前可读正文投影建立明确的新基线。主库业务表不作为可清空的辅助数据，健康的正文二进制也不是可任意删除的缓存。检查点的二进制及元数据按带 UTF-8 长度边界的字段计算 SHA-256；格式仍合法的单字段损坏也会被隔离。日志和确认历史保留完整性封套，删除日志必须同步维护预期数量，缺条目不会被当作已确认。

身份与本机序号下界优先从 anchor 恢复；恢复只折叠日志，不倒退来源序号。桌面还保留库外已发布状态，手机可通过已有固定证书及设备授权读取对端头，核对本机资料库来源并取回对端已确认的来源序号后恢复登记。无法确认来源时只停止设备连接，本机资料继续可读写，不自动信任新证书。恢复期间改变了读取基线时，本轮对账会重新读取，不能发出修复前的头和修复后的数据。恢复标记强制完整副本与快照，恢复头参与幂等标识，连续两次恢复不能错误复用同一份保全材料。

恢复和网络等待不持有业务事务。正常读取、编辑不等待网络补齐；移动端会话缓存损坏时，优先按健康耐久正文重建。隔离材料不参与业务约束、捕获、同步或自动回收。SQLite 主文件物理损坏、存储完全不可写及用户资料本身不可读不属于辅助重建能修复的范围；写入失败必须回滚并保留已保存状态，不能虚报保存成功。

## 配对与附件

协调电脑生成 5 分钟有效的一次性配对信息，包含候选局域网地址、证书与高熵秘密。连接电脑和移动端原生请求只信任配对证书，不使用公共信任根、重定向或代理；主机名经系统解析后仅连接私网地址，桌面还核对服务器叶证书与配对证书一致。重新配对同一基线保留本机未确认数据，无关目标文件保持原样。

成功配对换取独立设备 token，桌面只落盘摘要，移动端凭据保存在应用私有目录，不进入资料库或正文。服务拒绝浏览器 Origin，先校验已有 token 再读取大请求。暂停和撤销使在途提交失效，关闭连接后不能继续进入数据库事务。

资源只按节点声明收集。二进制引用使用不透明 ID，映射到 `~/.editor/resources/device-sync/<SHA-256>.<扩展名>`，不发送电脑绝对路径。正文可以先确认，图片缺失不阻断阅读与编辑；附件独立重试。

附件按 256 KiB 传输，每块和完整文件均检查 SHA-256，临时文件完整验证后原子改名。已验证文件按文件身份缓存，前台恢复重新检查；部分文件不能作为完成文件使用。公网地址保持原引用。

HTTPS 同时接纳最多两个请求，其余请求退避重试，避免并发堆积多个大正文请求。状态向量、SQL 语句与附件验证缓存均有容量限制；正文合并批次之间让出事件循环，事务内不插入网络或定时等待。后台安装争锁最多等待 25 毫秒，随后退避重试，并恢复业务连接原有设置；移动端 SQLite 与附件操作进入阻塞工作线程。

## 实验边界

- 一台电脑协调，其他电脑和手机主动连接；协调电脑不可达时各端仍可编辑，待重新连接后补齐，没有自动选主、设备级联或手机直连。
- 使用 IP 和系统本地主机名回连，没有自建 mDNS 服务发现。名称解析不可用且地址变化时需要刷新配对信息。
- 手机启动、浏览器恢复/联网事件和 Tauri `RunEvent::Resumed` 触发对账，隐藏时冲刷输入并暂停调度；操作系统挂起期间不承诺持续执行。
- 两端主库结构指纹必须一致。结构升级需对齐软件并建立一致基线，不自动分发安装包。
- 单个请求及检查点上限 64 MiB，正文沿用 8 MiB 模型预算，附件单文件 25 MiB。超出时拒绝并保留原数据，没有大库流式检查点安装。
- 正文当前以完整二进制检查点耐久保存；大量长文高频编辑的磁盘成本仍与正文大小有关。历史受预算限制，未解决副本与 CRDT 历史不自动物理清理。

复现、客户端操作和真机验收步骤见 [设备同步验证](/docs/guides/ops-device-sync-spike.md)。
