## 1. 现状事实

### 1.1 插件能力

- 上下文（`packages/plugins/src/contract.ts`）提供命令、生命周期、页面、设置分区、侧边栏（分组/图标）、`fetch`（主进程原生 fetch，不带 Cookie/CORS）、私有 `storage`（JSON 的 get/set/delete，按工作区 + 插件隔离）、开发场景编辑器扩展。
- 桌面私有存储是 `createBrowserStorage(window.localStorage)`（`app/plugins/PluginProvider.tsx`）；工作区与数据库一一对应（`plugin-local:workspace`）。
- 插件在渲染进程执行，只能 `require` 共享模块 `@tau/plugins`、`@tau/ui`、react 系列（`app/plugins/package-loader.ts`）。
- 测试夹具 `features/plugins/__tests__/fixtures/weread/` 已证明插件可经 `context.fetch` 调用微信读书网关并分页读取书单。
- 插件**没有**任何写入或引用 Tau 实体的能力。

### 1.2 现有微信读书实现

- 认证只有官方 API Key（`Authorization: Bearer`），存于全局 `setting.json` 的 `integration.weread`；无 Cookie、无扫码。网关唯一：`https://i.weread.qq.com/api/agent/gateway`，按 `api_name` 区分接口（`services/weread/index.ts`）。网络与解析全在渲染端，主进程只落库。
- 数据分两层：
  - 私有缓存：`weread_notebook`（主键为微信 `book_id`，含元数据、进度、同步游标、整本笔记 JSON）与 `weread_config`（`last_sync_time`、`excerpt_expand_version`）。全仓仅 `tables/weread-notebook.ts`、`tables/weread-config.ts` 读写。
  - 公共数据：`excerpt`，`source_type='weread'`、`source_key=bookId`、`external_id` 为 `bookId:bookmarkId` 或 `bookId:review:reviewId`。唯一索引 `(source_type, external_id)`。
- `ExcerptTable.syncSource` 按 external_id 合并：新增插入、变化原地更新、缺席软删除、重现复位，**external_id 不变则 `excerpt.id` 不变**。
- 下游全部只引用本地整数 `excerpt.id`：`question_link`（`target_type='excerpt'`）、`entity_lineage`（`src_kind='excerpt'`）、VL 资源 `refs`、向量/全文索引 `excerpt:<id>`、对话引用、全局搜索、移动端 `entity_context.rs`。
- "同步到 Tau"的现有含义：划线自动成为摘录并进入搜索/RAG；转卡片、转问题由用户在单书页触发。不自动生成文档或卡片。

### 1.3 摘录：通用存储，封闭的展示与跳转

`excerpt` 的存储语义与来源无关，已服务微信读书和浏览器插件网页划线（`excerpt:sync-web-page`）两个来源。但周边按来源写死：

| 位置                            | 封闭点                                                                                  |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| `entity/excerpt/types.ts`       | `EXCERPT_SOURCE_TYPES = ["weread","web"]`；`ExcerptAnchor` 为两种来源定位的联合类型     |
| `tables/material.ts`            | `excerptInfo` 按 `weread` 分支拼来源文案，并从 external_id 解析 `weread-book` 页面参数  |
| `entity/material.ts`            | `MaterialOpenTarget` 写死 `page: "weread-book"`                                         |
| 移动端 `entity_context.rs`      | `weread` 读 `anchor.chapterTitle`，其余来源一律显示「网页 · host」                      |
| `features/search/searchMeta.ts` | 摘录结果 `navKey: "weread"`                                                             |
| 变更事件                        | `weread:excerpts-changed` 与 `excerpt:sync-web-page` 各自被索引编排、上下文刷新分别订阅 |

结论：若只在这些分支里加一个插件分支，就是后门。C18 必须把它们改成按数据驱动。

## 2. 缺口

| 目标                                   | 现有能力 | 缺口                                       |
| -------------------------------------- | -------- | ------------------------------------------ |
| 配置连接、读取书架与笔记、页面与侧边栏 | 足够     | 无                                         |
| 启动后自动同步                         | 足够     | activate 中发起任务并绑定 `context.signal` |
| 同步到 Tau（写摘录）                   | 无       | 插件不能成为摘录来源                       |
| 保留数据与引用                         | 无       | 同上，且来源归属需交给插件                 |
| 从脉络/搜索/对话打开原处               | 无       | 打开目标写死内置页面                       |
| 转卡片、转问题                         | 无       | 客户端业务流程未对插件开放                 |

真正缺的只有一件事：**插件成为 Tau 外部摘录的提供方**。

## 3. 抽象层级与职责

| 层级                    | 例子                          | 判断                                                   |
| ----------------------- | ----------------------------- | ------------------------------------------------------ |
| 存储层（键值/SQL/实体） | 给插件一张表                  | 否：索引、引用、展示、移动端都无法理解插件数据         |
| 领域层：外部摘录提供方  | 来源 → 条目（引文/想法/位置） | 采用：阅读与划线类服务的共同形状，复用客户端全部消费方 |
| 业务层                  | `syncWeReadBook`              | 否：后门                                               |

公开 API 的名词是 Tau 领域概念（摘录、来源、材料），不是第三方服务或存储的概念。

- **插件负责**：API Key 输入与校验、网关调用与错误映射、限流重试、增量策略与游标、把服务数据转为摘录条目、书架/单书页面与偏好。
- **客户端负责**：摘录写入事务与合并语义、id 稳定、软删除/复位、写入后索引与上下文刷新、工作区绑定与停用拒写、材料展示与打开路由、插件未启用时降级、转卡片/转问题等材料动作、存量数据升级。
- **边界**：插件只描述"来源当前有哪些摘录"，不接触 id 分配、软删除实现和事务。

## 4. 公开 API（SDK 0.4）

```ts
// 写入侧：一个插件即一个摘录提供方
interface PluginExcerptSource {
  key: string; // 来源在本插件内的稳定标识：书 ID / URL / 文献 key
  title: string;
  url?: string; // 来源级外链，打开原处的兜底
}

interface PluginExcerptItem {
  externalId: string; // 本插件内唯一且稳定，其稳定性决定引用寿命
  quote: string;
  note?: string;
  location?: string; // 给人看的位置：「第 3 章 · 标题」「第 12 页」「位置 1234」
  url?: string; // 条目级深链，优先于来源 url
  anchor?: JsonValue; // 插件私有定位：宿主只存储、规范化后比较，从不解读
  color?: string;
  time?: number; // 在来源中的创建时间（毫秒）
}

interface PluginExcerptSyncResult {
  inserted: number;
  updated: number;
  deleted: number;
}

interface PluginExcerpts {
  /** 声明提供方；label 持久化，插件停用、卸载后及移动端仍可显示 */
  register(definition: {
    label: string;
    open?(target: { sourceKey: string; externalId: string }): void | Promise<void>;
  }): Disposable;
  /** 快照：以全集覆盖一个来源，缺席条目软删除；items 为空即整个来源下架 */
  replace(
    source: PluginExcerptSource,
    items: PluginExcerptItem[]
  ): Promise<PluginExcerptSyncResult>;
  /** 增量：只增改或软删除指定条目，适用于按游标拉取的服务 */
  patch(
    source: PluginExcerptSource,
    change: { upsert?: PluginExcerptItem[]; remove?: string[] }
  ): Promise<PluginExcerptSyncResult>;
  sources(): Promise<{ key: string; title: string; count: number }[]>;
  items(
    sourceKey: string
  ): Promise<{ ref: PluginMaterialRef; externalId: string; deleted: boolean }[]>;
}

// 消费侧：对所有材料通用
interface PluginMaterials {
  /** 客户端对该材料当前可执行的动作（转卡片、转问题……），新增动作插件自动获得 */
  actions(ref: PluginMaterialRef): Promise<{ id: string; label: string; run(): Promise<void> }[]>;
}
```

`PluginMaterialRef` 对插件是不透明值，结构与 `MaterialRef` 一致但插件不得依赖其字段。`context.excerpts`、`context.materials` 随实例回收。

契约：

- `source_type` 由宿主取插件 ID，插件不可见、不可传；插件只能读写自己的摘录。内置保留名 `web` 不得被插件 ID 占用。
- 摘录归用户：插件停用或卸载后照常可搜索、引用、展示；插件只能软删除。
- 幂等：内容不变的重复同步返回 `updated=0`；anchor 由宿主按键名规范化后比较。
- 打开原处：提供方已启用且注册 `open` → 交给插件；否则用条目或来源 `url` 外部打开；都没有则提示"需启用某插件"。
- 写入落到 `context.workspaceId` 对应的数据库，不随调用时的当前库漂移；实例 signal 中止后写入拒绝。
- `replace`/`patch` 须在本次激活内先 `register`，否则报错。
- 不提供：通用实体/SQL、凭证、后台任务、文档写入。凭证放插件私有存储。

## 5. 客户端改造

| 改造         | 内容                                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Schema       | `excerpt` 加 `location TEXT`、`url TEXT`；新增 `excerpt_provider(source_type PRIMARY KEY, label, updated_at)`                                                    |
| 存量升级     | 微信读书 `location ← json_extract(anchor,'$.chapterTitle')`、`url ←` 该书 `pc_url`；网页 `url ← source_key                                                       |     | '#tau-hl=' |     | external_id`；写入 `('weread','微信读书')`、`('web','网页')` |
| 类型         | `ExcerptSourceType` 改为开放字符串；`ExcerptAnchor` 改为不透明 JSON（网页 XPath 解析留在浏览器插件链路）                                                         |
| 材料解析     | `excerptInfo` 去掉来源分支，统一 `label · 《title》 · location`；打开目标为 `{ page: "excerpt-provider", sourceType, sourceKey, externalId }`，按第 4 节三级路由 |
| 移动端       | `entity_context.rs` 按列读 label/title/location，删除 `weread` 分支                                                                                              |
| 事件         | 合并为 `excerpt:changed`，索引编排与上下文刷新只订阅它                                                                                                           |
| 搜索         | 摘录结果直接打开原处，不跳固定入口                                                                                                                               |
| 内置网页来源 | 作为客户端内置提供方 `web`，走同一写入路径，无特例                                                                                                               |

数据规则：每个事实存放在所属层级；来源级字段沿用 `source_title` 已有的行内扁平化，本轮不做来源表规范化。

## 6. 通用性检验

| 来源              | 来源键 / externalId          | 位置      | 打开原处                 | 写入    |
| ----------------- | ---------------------------- | --------- | ------------------------ | ------- |
| 内置网页划线      | URL / 划线 uuid              | —         | `url` 深链               | replace |
| 微信读书          | bookId / `bookId:bookmarkId` | 章节名    | 插件页面，兜底网页阅读器 | replace |
| Kindle 剪贴文件   | 书名 / 内容哈希 + 位置       | 位置 1234 | 插件页面                 | replace |
| Readwise / Zotero | 文献 key / 远端 id           | 第 12 页  | `zotero://` 等深链       | patch   |

四者均无需客户端出现来源名。Kindle 的哈希 id 在用户编辑划线后变化：旧条目软删除并保留引文，属于契约内行为。

## 7. 迁移

已确认决策见 PS-035。

- 插件 ID 为 `weread`，等于现有 `source_type`：**摘录行不迁移、不改写**，归属自然成立。插件首次全量同步按 external_id 命中已有行，只会复位、更新或不变，不产生重复行和新 id。
- 插件必须保持 external_id 格式（`bookId:bookmarkId` / `bookId:review:reviewId`）、`source_key=bookId`，以及 `expandWeReadExcerpts` 的合并规则（同 range 想法并入划线；仅有想法时以 abstract 为原文）。现有 `expandWeReadExcerpts`、parser 测试用例搬入插件作为格式契约测试。
- 只在书单完整拉取成功后，才对本地有、远端没有的来源执行 `replace(source, [])`；软删除可逆，书重现时 id 复位。
- API Key 按工作区保存在插件存储，用户在插件设置中重填一次；宿主不搬运旧 Key，迁移版本清除 `integration.weread`。
- 接受仅存于旧缓存的数据丢失：已从账号删除的书、无原文的章节想法、整书书评、阅读进度快照；不提供导出。仍在账号内的书可由插件重新拉取。
- N 版本（C18 交付）：删除内置微信读书页面、侧边栏条目、启动校验、设置行、渲染端服务与写入 IPC、连库摘录回填；旧表保留但不读写。
- N+1 版本：删除 `weread_notebook`、`weread_config`，同步 `legacy-tables.json`、`scripts/db/check-schema-parity.mjs`、`database-schema.md`，清理移动端 `setting.rs` 残留默认值。不能只把表名加入守卫名单，否则旧库会被拒绝打开。
- 插件位于 monorepo `plugins/weread`，`pnpm-workspace.yaml` 增加 `plugins/*`；ESLint 限制其只能引用 `@tau/plugins`、`@tau/ui` 与 react。

## 10. 验收标准

- **引用保真**：迁移前快照全部 `(source_type, external_id) → id` 与 `question_link`、`entity_lineage`、VL 资源引用；插件全量同步后映射完全一致、引用全部可解析；新增行数等于远端真实新增划线数，无重复行。
- **幂等**：对未变化的库全量同步，结果 `updated=0`，不触发全量重新索引。
- **功能对等**：书架、单书、转卡片、转问题、复制、打开网页；从脉络、搜索、对话三处打开原处并定位到划线。
- **降级**：插件停用或卸载后摘录照常可搜索、引用、展示来源；打开原处退到网页阅读器链接；重新启用恢复插件页面。
- **通用性**：客户端与移动端代码不再出现按 `weread` 分支的展示或跳转逻辑；网页划线经同一提供方路径通过原有测试。
- **生命周期**：同步中停用则中止且不写入；同步中切库不写错库；重启后配置与偏好恢复。
- **工程**：类型检查、行为测试、完整构建、`pnpm db:schema:build`、`pnpm db:schema:check` 与 `database-schema.test.ts` 通过。视觉由用户验收，Agent 不做视觉走查。
