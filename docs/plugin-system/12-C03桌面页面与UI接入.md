# C03 桌面页面与公共 UI 接入

本阶段将 C02 底座接入真实桌面代码，用随开发构建提供的可信样本验证页面、命令、UI、本机偏好与生命周期。不是外部安装器，也没有开始 C04 编辑器扩展。

## 开发者入口

在本 worktree 启动 `pnpm dev`，进入「设置 → 插件」启用「页面与偏好示例」，再从开发台或命令面板执行「打开插件页面示例」。开发台提供「打开插件管理」跳转；C05 调整后不再单独提供启停控件。

样本使用真实偏好存储；「紧凑排布」保存成功后更新开关状态。条目 A/B 展示参数页面与实例去重，不创建业务记录。说明弹窗使用公共 Dialog/UiProvider。停用后命令消失，页面显示不可用提示；重新启用恢复访问，已有偏好仍保留。

样本每次工作区运行默认停用，不持久化启用状态。生产构建不显示开发台命令，也不加载示例插件。视觉与实机交互由用户后续验收，Agent 只做非视觉行为检查。

## 作者 API

| 入口         | 已提供能力                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| @tau/plugins | definePlugin、PluginContext、PluginPageDefinition、PluginPageHandle、PluginPageProps、PluginPageParams |
| @tau/ui      | 示例直接使用 Button、Panel、Switch、Dialog、DialogBody，不经 SDK 重导出                                |

页面在 activate(context) 中通过 `context.pages.register(definition)` 登记，返回的句柄有 `id`、`open(params?)` 和 `dispose()`。登记自动加入插件资源作用域，激活失败或停用时回收。

定义包含局部 id、title、component，以及可选的 match/getId。当前 match 支持 single 和 params；参数是字符串、有限数字、布尔值组成的对象，默认空对象。需要复杂业务对象时传稳定 ID 后查询，不把对象实例、函数或宿主连接塞进导航参数。

组件接收 `{ context, params }`；params 为当前页面实例的只读参数，context 属于创建时的插件/工作区。当前不公开内部导航器、PageProvider、QueryClient 单例或业务 store。无页面适配器的宿主调用注册会明确报错，纯 Node 插件不受影响。

可直接阅读 [样本定义](../../apps/desktop/src/features/plugins/example/notesPlugin.ts) 和 [UI 组件](../../apps/desktop/src/features/plugins/example/SamplePages.tsx)。SDK 并未替作者接管 React 本地状态或 react-query 使用方式；页面注册和组件渲染有不同生命周期，页面切换不等于停用插件。

## 宿主接线

- [运行时](../../apps/desktop/src/app/plugins/runtime.ts) 持有窗口/工作区的 PluginHost 和动态页面定义。
- [Provider](../../apps/desktop/src/app/plugins/PluginProvider.tsx) 随 AppShell 工作区挂载，开发样本懒加载，切库/卸载回收，取消后的导入结果不创建旧宿主。
- [承载 Page](../../apps/desktop/src/features/plugins/pages/plugin-page.page.tsx) 走已有文件注册和栈机。框架目录没有新增业务依赖或动态中心注册表。
- [页面视图](../../apps/desktop/src/features/plugins/views/PluginPageView.tsx) 解析本实例参数、注入 UI 上下文，处理不可用页与每代独立错误边界。
- [命令源](../../apps/desktop/src/features/search/searchMeta.ts) 将当前有效的插件命令投影成面板条目；SearchPalette 订阅运行时变化并通过宿主执行，不缓存已停用的命令。
- `createBrowserStorage` 由内部 host 入口提供，宿主注入 localStorage；每个偏好键包含工作区和插件身份，异常不静默清空。它是本机偏好适配器，不替代未来数据库服务。

页面定义冻结、参数复制和实例作用域用于防止正常代码误用，不是恶意代码沙箱。当前只有宿主显式登记的内置开发样本，第三方仍须后续完成安装、授权和运行档位接线。

## 停用和恢复

命令、页面句柄及存储均绑定旧上下文的取消信号。停用后旧回调不能继续操作；当前组件和 Portal 退出，后退/前进遇到旧条目显示不可用状态。再次启用生成新的组件代次，按历史参数恢复展示，不恢复已退出组件的瞬态状态。

页面自身渲染报错只影响该页面，支持重试；停用再启用会重建错误边界。当前样本没有未保存草稿，因此不引入虚假的离页守卫；后续编辑型页面必须单独完善保存/关闭协议。

本机偏好在切换回原工作区后可读，启用状态不随之恢复。跨窗口偏好的实时广播、库改名后的稳定身份、后台任务的多窗口仲裁均不在 C03 范围。

## 验证与后续

核心测试覆盖页面失败回收、手动注销和过期句柄、状态订阅、无页面宿主拒绝、标量参数以及浏览器存储分域。桌面测试使用真实 PageProvider/PageHost、开发台和样本，覆盖命令打开、参数去重、后退/前进、偏好保存、停用/恢复、隐藏页面以及切库。C02 的独立进程读写示例保留。

实施首次发现 react-query 不接受 undefined 查询结果，已将缺失偏好归一化为默认布尔值并复验。具体运行结果见执行日志；不把 jsdom 行为测试称为视觉或 Electron 实机验收。

下一步为 C04：继续以双入口接入编辑器扩展，验证节点、命令、codec、实例更新和缺失扩展保真。侧栏贡献、自定义设置分区和第三方 SDK 发布仍是后续能力，不因 C03 的页面样本完成而标记完成。
