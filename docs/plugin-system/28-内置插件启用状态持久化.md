# 内置插件启用状态持久化

日期：2026-10-15。承接 core.theme 内置插件，本单元补完整“启用一次，重启和切库自动恢复；停用后保持停用”的流程。安全和发布平台继续暂停。

## 状态归属

启用意图是本机应用偏好，不按工作区分开：A 工作区启用后，B 工作区也启用；B 停用后，返回 A 同样停用。每个工作区仍创建自己的插件实例，旧实例在切库时回收，不共享运行中的上下文。私有数据仍按既有工作区规则存储，主题选择仍是已有主题运行时的应用级偏好。

每个已装配内置插件使用独立 localStorage 键 `tau-builtin-plugin-enabled:v1:<pluginId>`，值为 `true` 或 `false` 字符串。不存在记录时默认停用；只恢复当前注册的内置 ID，不因磁盘上有未知记录就装载代码。不同插件写不同键，避免整张偏好表覆盖其他操作。

## 接线与失败处理

- [BuiltinPluginManager](../../apps/desktop/src/app/plugins/builtin-manager.ts) 持有启用意图、操作队列和错误，实际启停仍由同一个 TS PluginHost 执行。
- [Provider](../../apps/desktop/src/app/plugins/PluginProvider.tsx) 注册内置插件后恢复；同源其他窗口的 storage 事件按键重读，清空事件重新对账全部内置插件。
- [管理界面](../../apps/desktop/src/features/plugins/views/PluginManagerView.tsx) 对内置插件使用管理器启停。保存成功后才执行状态变化；保存失败明确显示错误，不能假装操作成功。恢复和用户操作按插件串行，忙态期间按钮不可重复提交。
- 切库、关闭和 StrictMode 清理只取消旧队列并销毁宿主，不调用持久化停用，不将保存的 true 改为 false；已取消队列不得在新工作区出现后再写旧意图。
- 读取失败或记录损坏显示错误并保留原记录；用户手动启用/停用可以重新保存该插件记录。某插件恢复失败不阻断其他插件。
- 激活失败保留启用意图与错误；管理界面可先停用取消自动恢复，再启用重试。已有生命周期错误处理沿用，不增加权限策略。

自动恢复不会主动执行插件命令。因此重启时只恢复主题插件的命令入口，不会自行轮换主题或改变用户明暗选择。

## 验证

```sh
pnpm --filter desktop exec vitest run src/features/plugins/__tests__/builtin-manager.test.ts src/features/plugins/__tests__/builtin-theme.test.tsx src/features/plugins/__tests__/desktop-plugins.test.tsx src/features/settings/__tests__/plugin-settings.test.tsx
node scripts/plugins/verify-builtin-persistence.mjs
pnpm --filter desktop build
```

34 项相关行为测试覆盖应用级恢复、主动停用、同 ID 串行、损坏/读写失败、激活失败重试、取消旧队列、跨窗口对账，以及正式 Provider 的管理点击和切库恢复。

真实 Electron 验证使用三个顺序执行的独立进程、同一临时 userData 与 HTML 地址：第一次启用实际 core.theme 并执行命令；第二次使用不同工作区身份，自动恢复后执行命令并停用；第三次确认保持停用。每次宿主清理后检查保存意图未被改写，窗口关闭前刷新浏览器存储。正式 TS 管理器、PluginHost 和主题插件直接复用，脚本只编译/启动，临时目录结束后删除。报告位于 `output/builtin-persistence-report.json`。

当前实测平台为 macOS arm64 / Electron 43.1.1，其他平台不扩张为已验收；不做视觉验收。跨进程验证是独立最小窗口，完整桌面构建与包内原生检查已通过，不把它称作完整业务应用端到端走查。

## 用户验收与后续

在设置 → 插件启用「主题切换」一次，重启或切换工作区后应保持启用且命令不重复；停用后再重启应保持停用。主题颜色不因恢复发生额外切换。外部开发目录的启用登记仍走原开发管理器，本次没有改变它的工作区归属。

内置插件启用状态恢复已补齐。后续仍是本地安装记录、导入、兼容和升级恢复，不推进安全或发布平台。
