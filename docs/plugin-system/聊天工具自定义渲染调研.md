## 工具身份与历史结果

### 工具名必须由宿主解析

[pluginMCP.ts](../../apps/desktop/src/tools/pluginMCP.ts) 的 `wrapTools()` 将声明转换为：

```text
source = plugin:<pluginId>:<mcpId>
hash = SHA256(JSON.stringify([source, originalToolName]))
toolName = plugin_<hash 前 16 位>_<原名替换非法字符后前 39 位>
```

相同插件 ID、MCP ID 和原始工具名生成稳定名称；激活及重连代次只影响 `executionIdentity`，不影响工具名。历史消息保存的是该全局名称，无法从摘要反解插件 ID 或原始工具名。

注册 API 应接收 `mcpId` 和原始 `toolName`，由桌面适配器调用同一个命名函数。不要让作者计算摘要，也不要改现有算法，否则已有聊天历史及逐工具开关会失配。建议从 `wrapTools()` 抽出唯一实现供执行与展示共用，并保留固定输入输出测试；摘要截短不能被描述为数学上绝无碰撞，仍需保留冲突拒绝。

### 成功结果已经有持久化通道

当前链路为：

```text
ToolExecutionResult.metadata
→ piToolBridge.toBridgeResult()
→ 主进程 pi-session-bridge.handleResult() 的 details
→ pi 会话文件中的工具结果
→ 实时 piChatEvents 或历史 pi-session-transcript
→ ToolCallExecutionState.metadata
→ ToolCallDisplay
```

证据：[渲染端桥](../../apps/desktop/src/services/piToolBridge.ts)、[主进程桥](../../apps/desktop/src-electron/main/modules/pi-session-bridge.ts)、[实时事件](../../apps/desktop/src/services/piChatEvents.ts)、[历史投影](../../apps/desktop/src-electron/main/modules/pi-session-transcript.ts)。无需新增聊天表、数据库 schema 或单独保存组件代码。

SDK 的 `copyJson()` 会复制整个工具返回对象，桌面本地工具适配目前也仅检查 `content` 后返回原对象，因此 JavaScript 作者携带额外 metadata 在部分路径上已经能贯通。但这没有公开类型、归属约束和版本约定，不能作为稳定作者接口。

两个行为边界必须在实现中明确：

1. 主进程 `handleResult()` 遇到 `isError` 会 reject，当前不会保留同一结果对象的展示 metadata。首期失败/取消使用通用错误展示，不承诺失败时仍有结构化卡片数据。
2. `piChatEvents` 的 `turn_end` 兜底分支没有复制 `toolResult.details`；通常由 `tool_execution_end` 提供 metadata。若承诺事件缺失时仍恢复展示数据，须同步补齐该分支并加回归。

### 展示与可执行性分开

渲染器属于插件激活生命周期，不依赖 MCP 当前是否连接或启用。即使 MCP 关闭、远端离线或工具从新列表消失，只要插件仍启用且该展示声明仍有效，历史消息仍可渲染。历史渲染不触发工具执行，也不授予旧消息重新调用工具的能力。

插件停用、卸载或切库时，组件应立即卸载并回到通用输入输出；重新启用后，现有消息应自动恢复自定义展示。新版本遇到不支持的数据版本，应主动调用 `renderDefault()`。插件更改自己的 ID、MCP ID 或工具名后，旧消息按未命中规则显示，不能靠模糊名称匹配交给另一工具。

## 作者契约

以下接口已在源码接通；全部通过 `@tau/plugins` 根入口导出，不要求作者引入 `@tau/chat-ui` 或内部模块。注册返回 Promise，以复用异步名称解析；激活函数必须 await，准备失败随激活报告。

```ts
interface PluginChat {
  registerToolRenderer(definition: {
    mcpId: string;
    toolName: string;
    component: ComponentType<PluginToolRendererProps>;
  }): Promise<Disposable>;
}

interface PluginMCPToolResult {
  content: string;
  render?: {
    version: number;
    data: JsonValue;
  };
}

interface PluginToolRendererProps {
  execution: Readonly<ToolCallExecutionState>;
  isDark: boolean;
  parsedInput: unknown | null;
  inputParseError?: string;
  data: JsonValue | null;
  dataVersion: number | null;
  renderDefault(): ReactNode;
}
```

`ComponentType`、`ReactNode` 来自已有 React 类型；`ToolCallExecutionState` 复用共享消息模型，经 SDK 转导出，避免另外维护一套状态枚举。SDK 打包时需核对传递类型依赖，作者只使用根入口即可。`render.version` 是展示数据版本，必须为正整数，与插件包版本、`apiVersion` 分开。

`content` 保持模型可读，也作为插件缺失时的默认结果。`render.data` 只携带有限 JSON 值，不接受 React 节点、函数或 DOM；继续使用 `copyJson()` 的复制与深度检查，不把字符串自动解释成可执行代码或资源加载指令。它会保存在会话中，作者应放展示所需的数据，不放凭证或临时大文件。

宿主将 `render` 转换成已有 `metadata.render`：`rendererKey` 固定为宿主计算的全局工具名，`version` 与 `payload` 来自已校验数据；作者不提供任意 rendererKey。对插件 MCP 返回的保留路由字段统一规范化，不能直接透传远端或未声明额外字段来选择内置渲染器。普通工具已有 metadata 路由保持原行为。

首期 transport 工具可按原始工具名注册组件，读取现有 `execution.output`；其标准 `structuredContent`、资源 `_meta`、MCP Apps 暂不作为已支持数据通道。当前 [customMCP](../../apps/desktop/src/tools/customMCP.ts) 和[主进程 MCP 返回类型](../../apps/desktop/src-electron/main/modules/mcp.ts)主要处理 content/isError，正式保留这些字段需要另行贯通类型、IPC 与解析，不能只修改 SDK 声明。

```tsx

function NoteResult({ execution, data, dataVersion, renderDefault }: PluginToolRendererProps) {
  if (
    execution.status !== "success" ||
    dataVersion !== 1 ||
    !data ||
    typeof data !== "object" ||
    Array.isArray(data) ||
    typeof data.title !== "string" ||
    !("note" in data)
  ) {
    return renderDefault();
  }
  return (
    <section className="rounded-tau-md bg-page text-ink-1 p-3">
      <strong>{data.title}</strong>
      <pre className="whitespace-pre-wrap">{JSON.stringify(data.note, null, 2)}</pre>
    </section>
  );
}

export default definePlugin({
  id: "example.notes",
  name: "笔记查询",
  version: "1.0.0",
  create: () => ({
    async activate(context) {
      if (!context.chat?.registerToolRenderer) {
        throw new Error("请升级到支持聊天工具自定义渲染的客户端");
      }
      context.mcp.register({
        id: "notes",
        name: "笔记工具",
        tools: [
          {
            name: "read_note",
            description: "按键读取本插件保存的笔记",
            inputSchema: {
              type: "object",
              properties: { key: { type: "string" } },
              required: ["key"],
              additionalProperties: false,
            },
            async execute(args, { signal }) {
              if (typeof args.key !== "string") throw new Error("笔记键必须为字符串");
              signal.throwIfAborted();
              const note = await context.storage.get(args.key);
              signal.throwIfAborted();
              return {
                content: note === undefined ? "未找到笔记" : JSON.stringify(note),
                render: { version: 1, data: { title: args.key, note: note ?? null } },
              };
            },
          },
        ],
      });
      await context.chat.registerToolRenderer({
        mcpId: "notes",
        toolName: "read_note",
        component: NoteResult,
      });
    },
  }),
});
```

组件使用已有 React 和 `@tau/ui`/主题词汇，不需要加入新的运行时共享模块。作者可在 activate 内通过闭包传入已有页面打开等动作，但组件渲染及挂载不能自动产生工具写入；按钮触发的动作仍遵循原有能力协议。`ctx.ai` 的文本生成接口不因此变成聊天工具执行接口。

## 宿主实现约束

1. **归属与事务提交**：新增 `ChatAdapter`，绑定真实 pluginId、workspaceId、激活代次和 signal。复用 MCP 的 `onActivated` 提交方式：激活期间只收集，全部成功才发布；失败逆序回收，不留半注册组件。局部重复目标拒绝，提前 dispose 后可重新注册。
2. **目标校验**：只能引用同一插件声明的 MCP。注册顺序可独立，在激活提交前统一核对；本地工具检查原名存在。远端工具允许列表尚未连接，保留声明，连接后对未发现名称给诊断，不因为离线导致整个插件激活失败。
3. **动态通知**：为共享注册表补 `subscribe/getSnapshot`，由真实工具行内部 `useSyncExternalStore` 订阅。当前父子组件有 memo，只改 Map 不保证重新渲染；既有测试通过重新传入 execution 对象触发，不能证明动态启停有效。
4. **清理身份**：插件路径使用带实例 token 的登记句柄，dispose 仅删除自己仍持有的条目。异步计算名称结束后再次检查 signal/代次。不能让旧实例清理删除新实例，同名内置注册的现有覆盖语义另保留。
5. **错误恢复**：错误边界按工具调用与登记代次重置；当前 `hasError` 一旦置位不会随组件替换恢复。插件卸载立即取消订阅及组件副作用，新代次可重新挂载。错误边界捕获组件渲染错误，不把事件回调和异步错误视为已被它兜底。
6. **状态与审批**：输入为空或 JSON 不完整时传 null 和解析错误，组件可回退；执行中按名称选择组件，不必等结果 metadata。审批继续由 `ToolCallBlock` 仲裁；旧 `codexItemType` 通用展示规则保留。
7. **工作区与窗口**：适配器每个桌面插件运行时独立装配；切库先使旧 signal 失效，再完成清理与新运行时创建。共享包只提供通用注册/展示能力，不引入桌面 store。多窗口各自登记，不持久化 React 实例。

当前插件运行在完整宿主环境。上述归属规则防止意外串用和生命周期错误，不构成恶意插件沙箱；本功能沿用现有信任模型，不以 iframe 隔离已实现作为前提或宣传。
