## 可用交付与阶段切分

C02-A 交付可运行的隔离命令样本及攻击性测试：宿主启动插件、绑定身份、执行声明命令、返回结果、停用并回收。此提交首先证明选定载体能满足基础安全门槛，不写业务数据库。

C02-B 在 A 通过后增加插件私有 KV 的持久化与配额，完成执行计数、退出进程、重启后继续读取的闭环。两插件交叉读取被拒绝，重载/撤权后的迟到提交被拒绝。存储目录由测试宿主创建并注入，不访问用户应用数据。

两个提交都通过独立开发测试入口使用，不在生产界面展示空插件管理页，也不改动微信读书、编辑器或主库。C02-B 完成后才标记 P2 完成；A 的网络或终止门槛失败，先记录并调整运行载体，不能用 B 的功能测试掩盖。

## 样本合同

样本 A 声明 `sample.echo`，收到有限 JSON 后返回有限 JSON。宿主只能调用该插件注册过的命令；插件不能借命令桥选择任意内部 channel。异常样本在 activate 注册部分内容后抛错，所有贡献必须被撤销。

样本 B 声明 `sample.counter`，通过自己命名空间下的原子更新操作增加计数，不能依靠并发不安全的 get/set 拼成自增。测试宿主让两个插件拥有相同 key，验证值隔离；不同工作区句柄、安装身份和授权集合都单独验证。

KV 数据只接受有限 JSON 与受限 key；用户不传文件路径。宿主按安装/工作区内部标识选择数据目录，串行提交并采用临时文件加原子替换，验证失败不覆盖旧值。C02 的 KV 是插件私有数据，不承诺与公共摘录跨库原子事务；公共领域提交留在 P3。

稳定错误至少区分：权限拒绝、无效请求、实例已失效、限额、超时、执行失败、版本不兼容；错误不回传宿主绝对路径、凭证和原始堆栈。requestId 与 generation 不复用，避免迟到响应命中新请求。

## 实施前准备

1. 复查分支与工作区，读取当前桌面 03 指南全文及相关 AGENTS 约束。
2. 当前新 worktree 尚无自身 node_modules。按仓库包管理及 native ABI 约定准备环境，记录锁文件实际 Electron 版本，不复用会被重建覆盖的其他工作区 native 产物。
3. 核实 Electron 43.1.1 对所需 API 的支持，禁止直接依赖在线 latest 文档中更高版本才出现的字段。
4. 明确所有测试只使用临时目录、本地探针和夹具，不访问用户凭证、真实微信读书 API 或生产数据库。
5. 原生测试保留 sandbox，不能为 CI 启动方便加 `--no-sandbox`；不具备运行条件时记录缺口，不能计为通过。

| ID  | 尝试或场景                                                             | 预期结果与证据                                                | 切片 |
| --- | ---------------------------------------------------------------------- | ------------------------------------------------------------- | ---- |
| A01 | 插件探测 require、process、window.electron 与通用 IPC                  | 无 Node/Electron 能力，无业务通道；只存在最小桥               | A    |
| A02 | payload 伪造 owner、runtimeId、工作区；来自子 frame 或未知 WebContents | 请求拒绝，另一个插件/工作区无变化；身份只来自宿主绑定         | A    |
| A03 | 重复 requestId、超大/过深 JSON、未知 operation、超并发                 | 稳定错误或终止实例，宿主队列和内存增长受限                    | A    |
| A04 | activate 半途抛错，重复停用，正常停用后发送请求                        | 注册和监听计数归零；后续请求失效                              | A    |
| A05 | 文件协议、ltoh、路径穿越、其他包资源、symlink 逃逸                     | 无应用文件泄漏，协议层拒绝                                    | A    |
| A06 | fetch/XHR、图片/CSS、WebSocket、表单、重定向、导航、新窗口、下载       | 外部探针零有效请求；被策略拒绝，不能仅依据前端 promise 失败   | A    |
| A07 | WebRTC 的 STUN/TURN/数据通道、DNS 预取、预连接、WebTransport           | 本地网络探针无未授权流量；只测 fetch 不算完成                 | A    |
| A08 | ServiceWorker、嵌套 frame/Worker、缓存后重启、另一个插件存储           | 无跨隔离边界或持久后台执行；清理后无旧资源复活                | A    |
| A09 | 摄像头、屏幕、剪贴板、文件选择等原生权限请求                           | 拒绝且不弹宿主授权框；权限检查与请求处理均覆盖                | A    |
| A10 | 插件无限循环、关闭超时、主动崩溃                                       | 外部监督能终止；宿主及另一插件仍响应；记录实际 PID 与退出原因 | A    |

| B02 | 停用/切工作区/同名工作区重开期间延迟写入                               | 旧句柄与代次拒绝，所有目标值可核对                            | B    |

A07 是载体选型的否决门槛，不是可延后的优化。若完整浏览器环境不能可靠封住已识别旁路，应提交调查结果并修订 PS-006，重新评估受限解释器等方案；不把“文档提醒插件不要联网”当修复。

A10 对内存只使用有界压力、载荷限额和外部监督；本轮不证明 OS 级硬内存配额。每个测试输出操作结果、探针计数、事件/注册计数与进程归属，不采集视觉截图。macOS 的通过不能代替 Windows/Linux 的运行证据。

## 构建与验证命令规划

新增脚本后拟使用以下命令；C02 实施时确认路径、脚本和实际支持平台后执行：

```sh
pnpm --filter desktop plugin-host:build-smoke
pnpm --filter desktop test:plugin-host
pnpm --filter desktop exec vitest run src-electron/main/plugin-host/__tests__
pnpm check
pnpm --filter desktop build
node scripts/check-database-boundaries.mjs
node scripts/check-whiteboard-boundaries.mjs
```

`test:plugin-host` 使用独立 Playwright 配置；不会将新用例混入已有协作 e2e 流程。纯测试宿主产物构建与正式 desktop build 分别记录，不能互相冒充。CI 若缺少可用 Electron 沙箱运行环境，所需实机验证仍未通过，不发布受限插件能力。

## 收尾与恢复

退出时关闭 WebContents、BaseWindow、IPC handler、session listener、网络探针和子进程，清理临时 userData；失败路径同样执行。除显式保留的诊断输出外，不留下长期进程或测试授权。

C02-A/B 通过前生产业务不依赖新运行时，代码可单独 revert；测试数据删除不影响应用数据。通过后更新现状、决策验证状态、运行限制、C03 的最小消费者和新的风险，不能只勾选“插件运行成功”。
