# C20 最小审核与批准发布

2026-10-16。承接已有提交门户，不另建管理站点。当前实现允许审核者批准、要求修改、拒绝，并自动发布批准的具体ZIP。客户端插件中心与在线升级不在本轮。

## 使用路径

使用REVIEWER_GITHUB_IDS中的GitHub账号登录 https://plugins.taunote.app → 进入审核管理 → 打开提交 → 查看README、源码快照并下载ZIP检查 → 填写意见 → 批准并发布 / 要求修改 / 拒绝 → 确认。

审核管理列出所有已提交记录，包含已处理项。要求修改和拒绝必须给原因；要求修改后作者能编辑重提，旧记录保留。批准后显示发布状态与下载链接，失败时审核者点击重试发布。拒绝新版本不影响旧版。

## 边界与事实源

- submission_reviews记录不可变的修订、上传ID、SHA-256、manifest、源码commit、审核者、意见和时间。
- releases按pluginId+version唯一，先pending/publishing，再published或failed；批准与发布分开，存储失败不抹掉审批记录。
- 待审桶tau-plugin-pending和发布桶tau-plugin-releases均私有。只有D1中published的记录通过Worker开放下载；没有公开整个桶。
- 发布前重新验证文件大小和SHA，发布重试采用相同确定性对象键；两分钟租约允许进程中断后重试，无后台自动审批。
- 普通作者不能审核、重试发布或查看别人的提交；维护者作为作者时可以审核自己的插件。
- 0003_review_release.sql保留现有提交和反馈，线上已有真实待审记录，禁止重置数据库或改写基线来跳过迁移。

## 验证

29项API测试、31项前端测试、类型检查及前后端构建通过。覆盖越权、过期修订、并发互斥、审核幂等、退回重提、历史快照、拒绝后的冻结、发布失败重试、过期租约恢复、摘要不符拒发、匿名下载和旧版本不受新版本拒绝影响。

本地workerd+D1+R2以真实ZIP完成批准/复制/匿名下载摘要比对，验证带已有记录的迁移；这些数据只在临时本地目录，未审批真实提交。上线后仍由用户自行审核真实插件。
