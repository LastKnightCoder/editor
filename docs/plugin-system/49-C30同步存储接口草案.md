## 作者侧对象接口

以下类型说明预期行为；名称可在M1按现有SDK命名统一，不代表当前已可调用。

```ts
interface TransferOptions {
  signal: AbortSignal;
  onProgress?: (progress: { transferred: number; total?: number }) => void;
}

interface ObjectInfo {
  key: string;
  size: number;
  modifiedAt?: number;
}

interface ObjectSource {
  size: number;
  // 每次调用从头读取，允许重试；由宿主管理底层快照的有效期。
  open(): ReadableStream<Uint8Array>;
}

interface StorageConnection {
  target: { identity: string; label: string };
  stat(key: string, options: TransferOptions): Promise<ObjectInfo | null>;
  read(
    key: string,
    options: TransferOptions
  ): Promise<{
    info: ObjectInfo;
    body: ReadableStream<Uint8Array>;
  } | null>;
  write(
    key: string,
    source: ObjectSource,
    options: TransferOptions & { mode: "replace" | "create-only" }
  ): Promise<{ status: "written" } | { status: "already-exists" }>;
  list(
    prefix: string,
    options: TransferOptions & { cursor?: string; limit: number }
  ): Promise<{ items: ObjectInfo[]; nextCursor: string | null }>;
  remove(key: string, options: TransferOptions): Promise<void>;
  dispose(): Promise<void>;
}
```

提供方的 `open(config, {signal})` 创建连接；配置由插件校验，结构可因服务不同而变化。open不隐式创建桶、仓库或改变服务配置。客户端对同一任务持有连接，结束后dispose；UI卸载不释放后台任务连接。

target.identity是远端命名空间的稳定非秘密标识，覆盖endpoint、bucket/仓库、根前缀等定位信息，不能仅用显示名称；凭证更新不会天然改变目标身份。宿主另持配置revision区分认证等配置变更，原任务固定其配置快照。对象key仅是目标根下的相对对象名，宿主验证合法路径，插件不能把根前缀混进list返回值。

read返回响应不等于完成下载：signal必须持续作用到body消费结束；读取错误通过流传播，客户端只在内容完整校验后安装。write成功表示整份对象完成远端写入；进度按字节报告，不用假的时间进度替代实际传输。

list按prefix列出对象，游标不透明；客户端消费至nextCursor为空。不承诺跨页快照，宿主按key去重。remove幂等，对确实不存在的对象成功；权限或网络故障必须失败。M2的remove用于提供方完整契约和隔离连接测试清理，不新增资源同步的自动删除策略。

## 条件写与错误

- create-only必须由远端原子实现；存在时返回already-exists，禁止先stat再replace。
- replace成功只返回written；上传来源可重开，提供方不能消费一次后在重试时上传空内容。
- 错误分类建议：unauthorized、forbidden、rate-limited、unavailable、unsupported、cancelled、invalid-config；限流可带retryAfterMs，不能携带凭证/签名URL。
- 请求异常不代表远端未写入。宿主保持现有快照提交身份校验，不能把网络异常当成已存在或直接覆盖。
- stat/read仅在确定对象不存在时返回null，列举失败抛错而非空数组。
- 遵守signal不等于撤销已经完成的远端写入。取消后的宿主仍依据提交状态处理，不直接宣称“远端没有变化”。

## 与现有同步引擎衔接

SnapshotPublicationProvider目前使用Uint8Array和boolean；M1提供唯一的宿主协议适配，将小型版本元数据转换为存储流，保留readSnapshotHead/publishSnapshot的算法与协议。业务层不再各写一份适配，插件不导入snapshot-publication。

数据库/会话包与资源文件走后台文件流，不能为了适配旧接口在渲染层整包转码。同步编排仍属于客户端；若接线需要改动数据库事务边界或锁释放顺序，须先停下来评估，不借存储插件化重写冲突算法。

## 注册与设置

- 后台入口：manifest新增可选sync入口；模板将作者src/sync.ts编为独立Node入口。具体字段与最低客户端版本在实现时统一校验，不仅更新模板。
- 后台声明包含providerId、名称、配置校验和open。提供方ID需属于插件命名空间，宿主目录验证重复和归属。
- 前端通过拟议的ctx.sync.registerSettings注册providerId对应的配置组件。它只挂载设置→同步的配置区域，不开放任意设置页插入能力。
- 组件接收宿主管理的config、saveConfig、testConnection；配置是本机应用级，原子保存并递增revision。保存成功后通知桌面查询；失败保留草稿。
- 凭据是插件目标配置的一部分，不新增通用密钥接口。公共状态仅包含配置是否就绪、目标名称和可公开错误；日志不包含完整配置。
- 同一插件设置入口可跳转到同步页的相同目标，不能维护第二份配置。
- 缺包、未启用、最低版本不符、后台模块加载失败必须显式报错，不能自动选择其他目标。

## 包校验与跨端

main入口仍承载UI，sync入口只包含Node可执行存储逻辑，不依赖React/Electron/页面store。两者由同一作者项目构建；所有后台产物必须进入manifest摘要、ZIP验证和安装事务。模板、SDK、桌面包读取器、门户包校验器和CLI加载器要同步，不提供未校验的开发路径兜底。

M2要求桌面与CLI执行同一后台入口。移动端现有Rust提供方维持原协议互通，不直接执行这个Node入口；不能因为支持同一远端协议就标记“任意同步插件支持移动端”。
