# 数据驱动博客模板与模板插件化方案（提案待评审）

> 状态：设计修订，2026-10-19 明确独立 Editor npm 包与模板起步仓库。宿主与官方模板已有本地原型，公开 Editor 包、模板起步仓库及无宿主源码的独立交付尚未完成；本次仅更新方案。宿主只负责数据、无界面搜索和插件产物协议，模板决定渲染、路由与预览，可选用公开 Editor 包。此前拆成多个 npm 包、将编辑器源码复制到模板的尝试均已撤回，不能作为正式接入路径。历史 spike 见第 9 节，本地实施证据与限制见第 66 号文档。

> 主线核对基线：2026-10-19 本地及远端 master 均为 `1842bb34231ebfd9729dc2c97989f8afc2b177da`（已合入 HTML 插件拆分），主线 SDK 为 0.17.0。本工作树原型来自较早的 `8914722c1`，不能据其旧扩展/服务清单发布 Editor；实施前按 M0 对齐当时最新 master。本次未合并分支、移动源码或发布 npm 包。

## 1. 背景与动机

改造前博客发布是"模板与数据混合"模式：官方预编译模板（`apps/blog`，六个固定页面入口 home/card/article/doc/quest/list）+ 发布器把数据内联注入模板 HTML。下表记录旧链路基线，不代表本分支改造后的现状；原 `apps/blog` 按要求保留不动。

| 耦合点 | 位置 | 现状 |
| --- | --- | --- |
| 页面类型固定 | `publish-site-generator.ts` `TEMPLATE_ENTRY_MAP` | 六种页型硬编码，模板作者不能增删页面形态 |
| 数据内联注入 | `publish-site-generator.ts` `injectData`（`DATA_PLACEHOLDER` → `window._INIT_DATA_`） | 数据 JSON 内联进每页 HTML，模板只能按 `IPublishInitData` schema 消费 |
| URL 结构固定 | 生成器各 `injectData` 调用点 | `articles/<id>.html` 等由宿主生成，本方案解除该限制 |
| 模板官方分发 | `publish-template-manager.ts`（R2 ZIP + `publish-template-latest.json`） | 无第三方模板入口，独立于插件中心的一套下载/校验/版本机制 |
| 资产路径改写 | `injectData` 的 `../../../assets/` 替换 | 宿主约定 |
| 内容链接预览 | `apps/blog/src/editorExtensions/contentLinkPreview.ts` | fetch 目标页 HTML 并解析内联 `_INIT_DATA_`，依赖内联数据 |

后果：模板无法由第三方提供；首页/列表形态、数据消费方式、样式主题全部由宿主规定，限制模板发挥。

## 2. 与既有能力的关系

- **C23 已提供内容插件产物与加载协议**：发布器按节点归属收集插件，清单提供产物位置、版本与 SHA-256 摘要，消费端按既有 CJS/依赖约定接入。本方案保留内容插件契约和包格式；模板自行选择渲染工具与插件接入方式，宿主不承载其组件树、界面资源或生命周期。
- **62/63 号文档的分发整改已确立硬边界**：客户端零内置插件（bundled-plugins 已退役）、正式插件全部从插件中心安装、移动端与浏览器扩展不感知插件。本方案不触碰这些边界——模板插件化只涉及桌面发布链路与**博客站点运行时**（站点产物在浏览器执行，与移动端/扩展端 App 无关）。
- **custom-block 拆分是体积层面的先例**：拆走后 `@babel/standalone`（2.9MB chunk）从博客构建消失（2026-10-18 重建实证，全站 33MB → 29MB）。

## 3. 目标与非目标

**目标**

1. 模板成为一种插件能力：任何作者可编写模板，经插件中心分发；客户端零模板资产。
2. 将数据与模板实现分开：宿主产出稳定内容标识、内容/聚合数据、搜索索引及插件产物；模板决定数据消费、正文渲染、插件接入、页面组织、URL、Router、样式和全部交互。
3. 官方模板迁移为插件中心里的普通模板插件，`PublishTemplateManager` 与 R2 模板 ZIP 链路退役。
4. 首版完整导出 home/card/article/doc/quest/list 所需的数据、引用关系、搜索和可选 CSS 资源；官方模板完成既有功能迁移，包括自身的渲染和内容预览，不以官方模板 UI 约束第三方模板。
5. 模板可提供单页或多个静态入口，使用 hash、query 或 History Router 等自身选择的 URL 方案；数据接口不以公开 URL 为输入或内容身份。不要求所有模板采用相同页面数量或路由结构。
6. 单独交付可选的通用 Editor 包，封装编辑器内核、默认扩展及自身 UI/资源；不理解博客发布协议。模板起步仓库提供 `PublishedContent` 等模板侧接入组件，封装发布资源与 C23 适配；作者只用公开接口，不需要理解内部包、组装 EditorKit 或复制编辑器源码，并可独立完成安装、类型检查、构建和模板打包。

**非目标**

- 不改内容插件（编辑器扩展）的作者契约、包格式与加载协议（C23 保持不变）。
- 不定义宿主业务路由、跨模板 URL 标准或路由声明语言；不根据内容类型批量生成公开入口。
- 不提供宿主正文组件、渲染挂载 API、预览 UI、界面资源管理或导航适配器；不规定模板必须使用的框架、渲染库和交互方式。
- 不做协议版本兼容层（已裁决：无存量用户，第一版）。
- 不涉及移动端与浏览器扩展的插件机制（63 号文档边界）。
- 不在本轮移除现有动态样式生成能力；宿主 Tailwind 编译明确列为后续删除项，不作为模板协议的永久能力。
- 不承诺整站原子发布、服务端渲染或自动适配所有托管环境的路由回退；不新增发布阶段执行模板生成代码的机制。
- 不把仓库内部编辑器、扩展、主题和工具模块逐个发布为 npm 包，不要求作者维护编辑器源码分叉。现有插件 SDK/UI 契约不改成站点渲染实现的容器；Editor 是另一个可选公共库，不是宿主阅读器服务。

## 4. 已裁决事项（评审时请确认）

以下为 2026-10-18～19 讨论修订后的实现约束；新增 Editor 包与起步仓库的具体公开接口见第 7.4～7.7 节，尚未作为已发布 API 交付：

1. **公开 URL 完全归模板**：路径、目录、slug、hash/query、列表地址和 Router 均由模板决定。宿主不规定文章、项目或其他内容的 URL，也不提供必须遵守的默认业务路由。`projects/<projectId>/…` 只能是某个模板自己的选择，不能成为数据或运行时契约。跨模板可共用稳定 key 和数据，切换模板时 URL 是否延续及如何迁移也由模板决定。
2. **模板走插件中心**：manifest 声明 `template` 对象，不使用 `template: true`。模板是静态资产能力，复用中心分发、安装、更新和卸载基础设施，不进入桌面插件的 `create/activate` 生命周期。官方模板同样从中心安装；客户端零模板资产。
3. **数据协议从第一版建立版本**：数据 version 与模板 template.protocolVersion 精确匹配；发布前检查，消费数据时再次校验。C23 的产物协议版本单独沿用，不把所有模板绑定到某个宿主渲染实现。不做旧数据适配层。
4. **辅助工具可选且无界面**：可随站点附带数据/查询辅助脚本 `tau-publish-data.js`，只提供读取、校验和搜索；类型定义挂现有 `@tau/plugins` SDK，不新开 npm 包。模板可以直接 fetch 和自行检索，无需引入辅助脚本；宿主不通过它提供组件、样式、正文挂载或预览。
5. **数据完整与官方模板迁移后退役旧链路**：宿主导出全部内容类型和引用数据；官方模板在自身实现中保留现有渲染、搜索与预览功能。第三方模板自行选择展示哪些内容及功能，不以“不展示某类型或预览”为由拒绝发布。
6. **模板提供入口，宿主复制产物**：模板包提供静态站点目录及入口 HTML；宿主只补充协议资源和启动路径，不按内容数量展开 HTML，不从地址栏推导内容。URL、Router、导航及部署方式归模板；宿主不操作 history、不监听 popstate，不承诺所有托管均无需 fallback。
7. **Tailwind 编译退出宿主是确定方向**：master 已完成 HTML 节点插件化，但仍通过通用 styleSources 生产动态 CSS；二者不是同一项完成状态。首版只保留既有样式生产者作为迁移桥接；替代方案验证后删除宿主源码扫描、Tailwind 编译及相关 worker 消息，不恢复 HTML 类型特判，也不把编译器包装成永久宿主 API。
8. **已插件化能力不回迁**：最新 master 中 HTML、TikZ、Typst、ABC 及 custom-block 已走独立插件；它们不进入 Editor 默认实现或资源包。仍内置的通用扩展按第 7.5 节收进 packages/editor；其他能力将来是否插件化另议，不因本次 npm 发布拆出更多包。
9. **搜索只有数据与查询契约**：发布数据包含配套搜索索引；可选辅助工具提供无界面查询接口，返回普通结果。模板决定输入框、结果、快捷键、高亮和导航，也可自行实现检索；宿主不提供搜索界面或规定检索库。
10. **运行环境与交付方式分开**：普通插件在 Tau 内运行，继续按现有约定使用 SDK/UI 类型并由 Tau 注入实现；模板发布后在独立浏览器运行，不能执行类型占位入口。选择公开 Editor 的模板在自身构建时将其可执行代码及资源打入静态产物，不依赖正在运行的 Tau 或宿主 checkout。
11. **只新增一个通用 Editor 公共包**：保留既有 `@tau/plugins`、`@tau/ui` 的宿主内插件边界；Editor 包内部封装所需内核、默认扩展及 UI 实现。本文用 `@tau/editor` 表示其消费入口，实际 registry 名称、别名和首发版本在交付前确定，不表示已发布。它不是模板准入依赖，数据协议不引入 React、Slate、EditorKit 或 DOM 类型；Editor 也不接收发布清单、业务 key、dataUrl、pluginRenderers 或 contentStyles。
12. **起步仓库是作者工具**：示范公开数据、Editor 和模板打包的最短路径；默认页面、Router、搜索展示和预览示例均可替换。宿主不安装或执行起步仓库的开发工具，不把示例框架、URL 或页面数量变成协议。
13. **源码收拢不破坏分层**：仍内置的通用功能收进 packages/editor 的 extensions，默认组合放 presets，对外 Editor 负责装配；core 不反向依赖具体扩展、默认组合或应用。业务扩展继续由应用/模板维护，内部目录不逐个成为 npm 包。

## 5. 方案总览

### 5.1 发布产物结构

```
site/
├── index.html                               # 示例模板自行提供的入口，非宿主页面约定
├── assets/…                                 # 示例模板自行组织的 JS/CSS/图片
├── …                                        # 模板包提供的其他公开文件/静态入口
├── _tau/client/<digest>/                     # 可选的数据/查询辅助脚本，不包含界面资产
│   └── tau-publish-data.js
├── data/                                    # 按文件内容摘要命名，不绑定整站批次
│   ├── site.<digest>.json                    # 内容数据清单，不含公开路由映射
│   ├── home.<digest>.json                    # 站点聚合数据，不代表模板必须有首页组件
│   ├── articles/<id>.<digest>.json
│   ├── cards/<id>.<digest>.json
│   ├── projects/<projectId>/<nodeId>.<digest>.json
│   ├── quests/<questionId>.<digest>.json
│   ├── lists/{articles,cards,projects,quests}.<digest>.json
│   ├── search.<digest>.json                   # 与本清单的内容 key 配套
│   └── styles/<digest>.css                   # 可选正文伴生 CSS，文件名只使用摘要
└── plugin-assets/<id>/<version>/             # C23 内容插件产物与摘要
```

数据、索引、CSS 与辅助脚本的 digest 为对应产物字节的 SHA-256，不在文件内重复写入自身摘要。先生成 CSS、内容 JSON 与搜索索引，再生成引用它们的清单，避免摘要循环；同一清单的搜索结果仅引用其中存在的内容 key。模板身份、模板版本和可选工具的构建摘要保留在发布记录中，不混入内容清单；相同数据可由不同模板复用。模板自行决定其资产文件名及指纹，宿主保留其目录结构。

data 目录是宿主数据资源的存储布局，不是模板业务路由；模板只通过清单或 API 读取，不从公开 URL 推断 JSON 路径。首版不引入整站 snapshot 字段、版本回溯或通用快照管理。单条内容修改只改变其实际影响的数据、聚合清单与启动元信息；无关正文 JSON 的字节和路径保持不变。稳定排序与序列化，`meta.publishTime` 等发布元数据仅在对应内容有效输入变化时更新，不能用当前时间改写所有数据。

### 5.2 发布流程

1. 冻结选中模板的 id/version/资产摘要、内容插件启用快照及发布数据；校验模板协议、资产完整性和包内路径。
2. 构造全部既有内容类型、首页/列表聚合数据及首版所需的可选正文 CSS；生成 key → 数据文件的清单，不生成公开 href。
3. 收集 C23 插件产物，保留固定版本与摘要；序列化数据时按数据文件位置计算插件和正文 CSS 的资源路径。
4. 保留模板静态站点目录结构，附带协议资源及可选数据辅助脚本；只对模板声明的入口 HTML 替换启动占位符，不生成业务路由，也不执行模板渲染代码。
5. 在本地完成包资源、数据引用、内容类型覆盖检查及上传 diff；缺少模板、插件、数据或资源时在任何上传前失败。不把任意 Router 的合法性改成宿主路径白名单。
6. 按依赖分阶段上传：先模板依赖文件、协议资源、内容 JSON、索引与清单，再模板入口 HTML。任一依赖上传失败则不更新入口；支持重试，不承诺多个入口的整站原子切换。

按摘要命名的文件可长缓存，模板入口和未指纹化的模板文件需要重验证缓存。首版保留当前及前一轮产物有变化的成功发布所需且可共存的依赖，无变化的重复发布不推进保留代次；同路径被模板覆盖的文件不承诺历史恢复。不维护无限历史或回滚 API，更早未引用文件可进入删除计划，失败时不提前清理上一轮依赖；撤下内容按第 12 节优先处理。同一内容插件 id/version 的资产不得换字节覆盖，摘要变化须使用新版本。

### 5.3 运行流程（浏览器时序，以文章页为例）

```
打开模板自己的 URL
 → 加载模板构建产物中的脚本、样式与所选渲染依赖（可包含公开 Editor）
 → 通过清单和内容 key 取数，可直接 fetch 或使用数据辅助工具
 → 模板侧接入组件按公开协议加载插件/样式并准备通用扩展
 → 模板自行渲染页面并处理链接、搜索结果与预览
```

### 5.4 可选 SPA 模板

模板可自行选择单页或多入口实现。数据协议只以 key 关联内容，不感知页面数量、渲染框架、路由或预览形式。

- **宿主边界**：复制模板静态产物，提供数据/索引/插件资源及必要校验。可选辅助工具只返回数据，不操作 DOM、样式、历史或界面生命周期。
- **模板边界**：模板自行解析路由、选择内容 key、生成公开链接；Router 与浏览器处理前进/后退、页面状态、加载/错误展示、标题、焦点、滚动和 query/hash。宿主不检查作者如何将 URL 映射到 key。
- **模板验证**：模板自行验证其部署方式下的导航、刷新、渲染和交互；官方模板的功能验收不转化为第三方模板必须采用的渲染架构或预览行为。
- **部署边界**：hash/query 路由或模板已有静态入口可直接用于普通静态托管；History Router 深链可能需要托管端 fallback，由模板选择与部署要求解决。宿主不伪造逐内容入口来规避该要求，也不在本方案新增服务端路由执行能力。
- **数据更新**：读取以清单 URL 和 key 为上下文，不随地址栏变化重解释；未知 key 返回数据错误，后续展示和导航归模板。

## 6. 接口契约（宿主 ↔ 模板，共三份）

### 契约一：模板插件包（作者提供）

manifest 的公共身份、最低客户端版本和分发元信息继续沿用插件中心。新增模板专用分支；下面只展示核心字段，摘要为示意值：

```jsonc
{
  "formatVersion": 1,
  "id": "example.blog-template",
  "name": "示例博客模板",
  "version": "1.0.0",
  "apiVersion": 1,
  "platform": "desktop",
  "minAppVersion": "<支持本协议的客户端版本>",
  "template": {
    "protocolVersion": 1,
    "root": "template/site",
    "entries": ["index.html"]
  },
  "integrity": {
    "template/site/index.html": "<sha256>",
    "template/site/assets/shell.js": "<sha256>",
    "template/site/assets/theme.css": "<sha256>"
  }
}
```

- **模板能力**：可独立声明静态模板，不要求 format/main/styles 或空脚本。若包同时声明既有代码能力，其代码字段仍按对应协议校验；发布器读取模板资源不触发代码能力激活。SDK、门户与客户端一致保留 template 对象，不用桌面代码入口约束模板的前端架构。
- **静态输出**：root 为包根相对的站点目录，其内部路径映射到发布站点根；entries 仅列出需替换协议资源路径的已有 HTML，路径相对 root，不是内容路由表。作者自行决定入口名和数量，无需每内容声明一个入口。首版复制作者已有输出，不执行内容驱动静态页面生成代码；如需该能力，另立生成协议。
- **资产清单**：允许 root 下的静态文件及现有说明文档；站点目录内每个文件均须出现在 integrity 中并逐字节验证 SHA-256，禁止缺失、未声明或重复资产。目录结构原样保留，不把包根或说明文档整个发布到网站。
- **路径边界**：root 与 entries 限制在声明目录内；禁止绝对文件路径、`.`/`..` 路径段、反斜杠、符号链接和目录逃逸，读取时核对 realpath。宿主保留 `_tau/`、`data/`、`plugin-assets/` 协议资源位置，包内文件不得覆盖实际生成的协议资源；其余静态文件路径由作者决定，这不是业务路由约定。
- **安装与生命周期**：安装器显式支持模板资产，不再套用当前仅 main/styles/文档的 ZIP 白名单。模板安装后即供发布选择，无桌面启停步骤、不执行模板 JS；包更新需按安装事务完成后才可选用，进行中的发布使用已冻结文件快照，不读取变化中的安装目录。
- **选择状态**：发布配置保存模板 id，生成时固定 version/摘要并记入发布记录，不写入内容数据。模板不存在、卸载、损坏或协议不匹配时拒绝发布并给出安装/更新入口，不静默换模板；安装更新不改变线上站点，重新发布才生效。
- **中心准入**：除占位符检查外，还需验证全资产、包大小和文件数量限制。本分支以完整模板约 12.3MiB、444 个资产为依据，将 ZIP 上限调整为 16MiB，解压 32MiB、512 项不变；限制由 SDK、门户、客户端共用。线上生效需另行发布门户 API，本轮只验证本地产物。

#### 入口启动信息与资源路径

宿主只在 entries 已存在的 HTML 中替换启动占位符，不按内容复制或生成入口，也不注入“当前页数据”。占位符为：

| 占位符 | 替换值 | 约束 |
| --- | --- | --- |
| `__TAU_MANIFEST__` | 包含部署 basePath 的清单路径，例如 `/notes/data/site.<digest>.json` | 作者自行读取该路径；不与当前业务 URL 或页面组件关联 |
| `__TAU_CLIENT__` | 可选数据辅助脚本的资源根，包含部署 basePath，带末尾 `/` | 仅在模板选择使用辅助工具时引用 |
| `__TAU_BASE__` | 部署根路径，例如 `/notes/`，带末尾 `/` | 作者可在入口中引用其自行组织的资产，不规定资产子目录 |

```html
<meta name="tau-manifest" content="__TAU_MANIFEST__" />
<link rel="stylesheet" href="__TAU_BASE__assets/theme.css" />
<script defer src="__TAU_CLIENT__tau-publish-data.js"></script>
<script defer src="__TAU_BASE__assets/shell.js"></script>
```

以上 meta 名称、目录与脚本引用只是示例，模板可自行选择 HTML 属性承载路径，也可以不使用辅助脚本。宿主替换已使用的占位符并按属性上下文编码，检查未替换 token、文件路径与可识别资源引用，不强制模板 DOM 结构或启动框架。首版不在任意 JS 字符串中替换 token，作者可从其 HTML 属性读取实际路径；base、脚本加载与路由部署由模板自行处理。

只有入口 HTML 接受展开，模板 JS/CSS 等资产字节不变。CSS 的 `url()` 相对该 CSS 文件，ESM 相对导入相对模块 URL；经典脚本中的 fetch/图片路径不能默认按脚本目录解析，应使用捕获的脚本 URL 或 SDK 返回的 URL 上下文。宿主不扫描并改写任意 JS/CSS 字符串；模板构建产物必须可重定位。

### 契约二：数据协议 v1（宿主产出、模板消费）

`data/site.<digest>.json`（数据清单，items 记录内容及聚合数据，不声明公开页面）：

```jsonc
{
  "version": 1,
  "site": { "title": "…", "description": "…", "basePath": "/notes/", "favicon": { "href": "…", "format": "…", "mimeType": "…" } },
  "search": { "data": "search.<digest>.json", "integrity": "<sha256>" },
  "items": [
    { "key": "home", "type": "home", "title": "首页数据", "data": "home.<digest>.json", "integrity": "<sha256>" },
    { "key": "article:1", "type": "article", "id": 1, "title": "数据与模板分离", "data": "articles/1.<digest>.json", "integrity": "<sha256>" },
    { "key": "card:7", "type": "card", "id": 7, "title": "关联卡片", "data": "cards/7.<digest>.json", "integrity": "<sha256>" },
    { "key": "list:article", "type": "list", "collectionType": "article", "title": "文章集合", "data": "lists/article.<digest>.json", "integrity": "<sha256>" },
    { "key": "doc:project:12:34", "type": "doc", "id": 34, "projectId": 12, "title": "项目说明", "data": "projects/12/34.<digest>.json", "integrity": "<sha256>" },
    { "key": "list:doc", "type": "list", "collectionType": "doc", "title": "项目集合", "data": "lists/doc.<digest>.json", "integrity": "<sha256>" }
    // card/quest 及其他数据同构；不声明作者的公开 href
  ]
}
```

内容 JSON 复用现有 buildXxxInitData 的业务构造，顶层补 version/key 和可选 contentStyles，不写入模板身份、整站批次或公开 URL。site 集中在清单，内容保留 content/meta/pluginRenderers；settings 仅作为可供模板选择消费的用户偏好，不强制其外观实现。SDK 定义六类明确数据类型，不能只返回任意记录对象。集合清单项提供 collectionType 业务分类，用于识别卡片、文章、项目文档或求索集合，不包含公开路径，也不要求模板拆解 key。

宿主不生成 navigation、激活项或分页 UI 状态。原 docCollections/sidebar 整理为纯 collections/tree 数据，面包屑、前后篇、列表、材料、contentLinkTargets 等站内关系统一使用 ContentRef：`{ key, type, id? }`。currentPath 等其他保存宿主业务路径的字段同样删除或改为内容身份，不只扫描字段名 href。用户正文中原存的普通 URL 保留原意，不按宿主路径猜测和改写。宿主配置的 favicon 放入 `_tau/site/<摘要>.<格式>`，通过 site.favicon 提供，不占用模板根目录文件名。

key 是模板可原样传递的稳定标识，不要求作者解析字符串结构。现有节点的 contentType/refId、搜索实体类型与清单 key，由宿主依据实体关系映射到同一身份，例如 project-item 引用和项目文档搜索项指向同一 doc key；不得通过历史 URL 反推。父项目、标题等已有业务元信息按类型提供，模板可用这些数据组织自己的 URL，而非解析 key 获取缺失信息。

#### ContentRef 与节点引用映射

ContentRef 的必需字段为 key/type，id 是对应实体的可选数字标识；type 使用清单数据类型，key 作为唯一查找依据，不由模板拼接。每份数据的可选 contentLinkTargets 是 `Record<string, ContentRef>`，用于把其正文节点中的引用身份映射到已发布目标。查找串为节点的原始 contentType、冒号和十进制 refId，例如 project-item:34；其他内容引用的身份由各类型 schema 明确，不从公开 URL 推断。

以下例子中的节点引用、目标清单条目与搜索文档指向同一个 key；来源数据可包含：

```jsonc
{
  "contentLinkTargets": {
    "project-item:34": { "key": "doc:project:12:34", "type": "doc", "id": 34 },
    "card:7": { "key": "card:7", "type": "card", "id": 7 }
  }
}
```

模板按映射读取目标数据即可，下面的读取过程不要求目标有公开页面，也不创建任何 UI：

```js
const source = await client.readData({ key: "article:1", signal });
const node = { contentType: "project-item", refId: 34 };
const identity = `${node.contentType}:${node.refId}`;
const target = source.data.contentLinkTargets?.[identity];
const targetItem = target
  ? await client.readData({ key: target.key, signal })
  : null;
```

映射缺失返回 null 只是本例模板代码的选择；宿主只约定该身份无可读取目标，是否提示、隐藏、展示原文或提供其他交互由模板决定。其他来源使用 ContentRef 的关系可直接传其 key，无需再经过节点身份映射。

清单按文件名摘要校验，内容与索引按其 integrity 校验，且摘要与文件名一致；内容 key/meta.type 与清单条目匹配。所有可用 ContentRef 及搜索命中的 key 须在该清单中存在。未发布引用保留原节点身份，但不加入可用 contentLinkTargets 映射；缺少映射表示目标不可读取，不伪造 key 或公开地址。多个清单可复用未变化的数据文件，不按公开 URL 或整站批次判断身份。

#### 搜索索引文件格式

清单 search.data 指向的文件采用以下最小公开格式，模板可以只读取 documents 自行检索：

```jsonc
{
  "version": 1,
  "documents": [
    {
      "key": "article:1",
      "type": "article",
      "id": 1,
      "title": "数据与模板分离",
      "summary": "按内容标识读取数据。",
      "content": "数据、搜索和内容引用通过稳定 key 关联。",
      "tags": ["架构"]
    },
    {
      "key": "doc:project:12:34",
      "type": "doc",
      "id": 34,
      "title": "项目说明",
      "summary": "项目的说明文档。",
      "content": "这是可供模板检索的文档纯文本。",
      "tags": []
    }
  ]
}
```

| 字段 | 公开类型与约束 |
| --- | --- |
| version | 固定为 1，表示该索引格式版本 |
| documents | SearchDocument 数组，空站点为 [] |
| key/type/id | key 唯一且在本清单存在；type 为 card/article/doc/quest，id 可省略，身份与清单一致 |
| title/summary/content | 必需的普通字符串，缺少对应文本时为空字符串；content 为可检索纯文本，不包含模板生成的 URL 或 UI |
| tags | 必需的字符串数组，没有标签时为 [] |

这些字段构成 SearchDocument。聚合项不重复进入正文搜索；未来索引若包含预计算优化字段，消费者可忽略，不能取代 documents。首版辅助工具须能仅凭该公开数组建立查询，不要求作者理解某个检索库的内部索引。排序、权重和分词可由自研检索实现选择，不要求所有模板返回相同排名。

#### 内容与聚合数据

| 数据类型 | 首版必须保留的业务信息，不规定模板组件 |
| --- | --- |
| home | 站点说明、时间线、统计、文档集合和发布偏好等聚合信息，不规定 hero 或导航组件 |
| card | 正文、标签层级、关联卡片和内容引用；当前标签/筛选状态由模板决定 |
| article | 标题、作者、时间、标签、正文和内容链接 |
| doc | 文档树、所属项目、父子/相邻关系、集合与正文元信息，不规定侧栏或面包屑 UI |
| quest | 描述、答案、材料引用、轨迹等现有完整结构及其中嵌套正文 |
| list | 内容集合、摘要、标签统计和数量等信息；是否分页及筛选交互由模板决定 |

模板可选择消费聚合数据，避免为摘要逐条拉取正文，也可组合多条数据绘制自己的页面。key 在站点内唯一；key → 数据位置由清单决定，key → 公开 URL 由模板决定。需要预览时，模板自行读取目标 key 对应的数据，不经公开页面 HTML 解析。

#### URL 基准与校验

| 字段/来源 | 解析基准 | 示例 |
| --- | --- | --- |
| 入口声明的清单路径 | 部署 origin + 含 basePath 的路径 | `/notes/data/site.<digest>.json` |
| items[].data、search.data | 清单文件 URL | `articles/1.<digest>.json`、`search.<digest>.json` |
| 站点 favicon.href | 站点根 URL，外部绝对地址保持原意 | 仅为资源引用，不是内容路由 |
| 业务导航/侧栏/内容链接/搜索命中 | ContentRef，无宿主 href | `{ key: "article:1", type: "article", id: 1 }` |
| pluginRenderers.entry/styles、contentStyles.href | 所属页面 JSON URL | `../../plugin-assets/<id>/<version>/main.js`（文章页数据示例） |
| 模板 CSS/模块内部的相对资源 | 对应 CSS/模块 URL | `./fonts/body.woff2` |

站点根 URL 由站点 origin 与规范化的 site.basePath 得到，basePath 为 `/` 或 `/notes/` 这样带首尾斜杠的部署路径。它是静态产物的部署位置，不是作者业务 Router 的协议。资源路径按本表解析，favicon 等外部绝对资源地址保留其语义；模板自己的路径、查询参数、hash、slug 和链接生成不经宿主规范化。

辅助工具按显式传入的 manifestUrl 解析数据资源，返回 dataUrl 等资源上下文，不读取地址栏来选内容。非法资源路径、重复 key、未知版本、身份不匹配或摘要失败返回数据错误；不校验业务链接、解析 hash/query 或归一化作者路由。

#### 正文伴生 CSS（首版保留，生产方式可替换）

contentStyles 是可选 CSS 资源数组，每项只提供 href 与 SHA-256 integrity，路径相对所属内容 JSON。CSS 文件名固定为最终字节的 64 位小写十六进制 SHA-256 加 .css，保存到 `data/styles/<digest>.css`；不把 key、实体名或作者 URL 拼入文件名，相同 CSS 字节可复用同一资源。文章数据中的引用例如 `../styles/<digest>.css`。

首版将编译器产出的 CSS 文件化；旧链路中绑定编辑器结构的选择器适配由官方模板自行处理，不作为通用数据协议。是否加载、如何应用、作用域和加载/释放时机都由模板决定，不引入宿主 DOM 属性、容器选择器或样式管理 API。

该字段只声明 CSS 资源，不声明 Tailwind 源码、编译选项或编译服务。模板 CSS、内容插件 manifest.styles 与页面伴生 CSS 分别管理；模板无需知道 CSS 如何生成。未来 HTML/动态样式全部由内容插件承担后，宿主不再生成此字段即可退出编译链路；可选 CSS 资源协议仍可消费其他生成方式。

### 契约三：C23 内容插件产物协议

`PublishedPluginRender` 形状、C23 `runtimeVersion: 1`、内容插件 main/styles 包格式、完整性摘要和共享模块名称集合保持现状。模板包新增静态资产分支不改变既有内容插件包的契约。

宿主按内容归属导出所需插件文件、版本、摘要与依赖声明，不代模板加载、求值、注入样式或执行界面生命周期。模板选择消费 C23 产物时，按既有协议提供插件需要的依赖与接入环境；采用什么渲染库、如何组织运行环境和管理界面状态均属模板实现。

模板可自行实现协议，也可复用起步仓库中的模板侧接入组件；该组件消费公开能力，把已准备的扩展交给通用 Editor。使用起步仓库的作者无需从零编写 CJS 求值、共享模块映射或内部服务组装。Editor 只接收正文及通用扩展，不接收发布协议；数据辅助工具仍只返回数据，不接管 DOM 和 UI。宿主不保证任意模板自动支持所有插件，不用官方渲染实现作为准入条件；模板接入层验证其声明支持的 C23 能力。

#### 插件产物最小接入说明（模板侧）

**公开入口现状与交付要求**：普通插件继续使用作者 SDK 的类型及宿主注入模块，不能在独立站点中执行其占位入口。数据类型/纯数据客户端按 M1 交付；通用 Editor 包与模板起步仓库中的 C23 接入层按 M2 分别交付，并用仓库外样例核对实际 npm 产物。仓库内部存在同名子入口不等于公开可执行，不得让作者 import apps/blog、应用私有文件或复制内部编辑器实现。下面记录底层协议的消费顺序，供起步仓库维护者和选择自行接入的模板使用，不是模板作者需要从零编写的代码。

1. 从已读取内容 data.pluginRenderers 获取 PublishedPluginRender 列表，保留这份内容的 dataUrl。检查 runtimeVersion 为 1，manifest 符合现有 C23 格式/API/编辑器声明，插件身份和节点归属不重复。
2. 用 `new URL(dependency.entry, dataUrl)` 读取实际脚本 URL；摘要字典的键是 manifest.main。样式同理使用 dependency.styles 作为资源地址、manifest.styles 作为摘要键；二者是否存在须一致。对响应的原始字节计算 SHA-256，匹配 manifest.integrity 后再解码，HTTP 失败、摘要失败均停止该次接入。不能把 manifest 文件名直接拼成资源地址，也不能以模板当前 URL 为基准。
3. 脚本是 CJS 产物，不能当作普通 script 直接执行。由模板接入层提供可执行共享模块映射，允许名称和定义契约沿用 [C23 文档](40-C23编辑器扩展与博客发布.md)。所需实现必须来自明确的公开可执行能力，不能把类型声明当成实现；缺少模块应明确失败，不回退到作者源码目录。通用 Editor 不因接收扩展而加载发布包，宿主也不建立站点模块装配服务。
4. 取得默认导出的插件定义后，核对其 id/name/version/apiVersion 与 manifest 一致，编辑器节点集合与 dependency.nodeTypes 一致；重复、缺失或多出的节点均作为产物不匹配处理。博客消费静态内容贡献，不调用插件的桌面 create/activate 生命周期。
5. 得到定义和已验证 CSS 后，模板接入层将贡献转为 Editor 的公开扩展，管理发布插件/伴生 CSS 的应用与释放；Editor 只管理编辑器自身实例、扩展和基础样式。模板决定挂载位置、容器、链接和预览 UI。它们都不是数据辅助工具或宿主的行为。

下面仅示意第 3 步的底层 CJS 求值，不是模板作者必须调用的公开 API，也不是完整校验器或宿主服务；输入 code 必须先完成第 1、2 步，sharedModules 仅包含 C23 允许的实际模块，第 4 步校验仍需执行：

```js
function evaluateDefinition(code, sharedModules) {
  const module = { exports: {} };
  const require = name => {
    if (!Object.hasOwn(sharedModules, name)) {
      throw new Error(`未提供插件依赖：${name}`);
    }
    return sharedModules[name];
  };
  const run = new Function("require", "module", "exports", '"use strict";\n' + code);
  run(require, module, module.exports);
  return module.exports.default;
}
```

对应的资源解析、摘要和身份校验可由模板的普通函数完成，无需数据客户端增加插件执行方法。若选择可选 SDK 工具，需验证其公开产物确有可执行出口；不以补齐工具为由重新引入宿主渲染、样式注入或预览服务。

## 7. 可选数据与查询辅助工具

`tau-publish-data.js` 只封装公开数据协议，提供数据读取、摘要校验和搜索。其产物不依赖渲染框架，不包含 DOM 组件、样式或内容插件执行环境。模板可直接 fetch/自行实现查询，是否使用该工具不影响发布资格。

```js
const client = TauPublish.createClient({ manifestUrl });
const manifest = await client.readManifest({ signal });
const item = await client.readData({ key, signal });
// item 固定返回 { data, dataUrl }，仅包含数据及其资源基准。
const hits = await client.search(query, { limit: 12, signal });
```

以上无界面 API 已在本分支实现；现有线上 npm SDK 尚未包含本轮新增类型，不能据此推定线上版本已可用。manifestUrl 由模板显式传入为绝对资源 URL；工具不读取 HTML meta、不依赖当前地址栏，也不根据 key 生成公开链接。client 只是绑定数据来源的查询对象，不管理模板状态或生命周期。数据类型随既有 SDK 发布，辅助脚本提供实际数据/查询实现；不能把当前作者 npm 包的类型入口当作该脚本。

#### 返回类型与初始化行为

| 调用 | 返回类型 | 返回值约定 |
| --- | --- | --- |
| createClient({ manifestUrl: string }) | PublishDataClient，同步返回 | 保存绝对清单 URL，不发起请求；无效 URL 同步抛 TypeError |
| client.readManifest({ signal? }) | Promise<DataManifest> | 直接返回第 6 节的清单 JSON：version/site/search/items，不增加隐藏上下文或界面对象；参数可省略 |
| client.readData({ key, signal? }) | Promise<DataResult> | 固定包含 data 与 dataUrl；data 为第 6 节六类 PublishedData 的判别联合，dataUrl 为解析其资源引用的绝对 JSON URL |
| client.search(query, { limit?, signal? }) | Promise<SearchHit[]> | 返回排序后的普通结果数组，无命中为 []；选项可省略，字段如下 |

```ts
interface DataResult {
  data: PublishedData;
  dataUrl: string;
}

interface SearchMatch {
  field: "title" | "summary" | "content" | "tags";
  text: string;
  ranges: [number, number][];
}

interface SearchHit {
  key: string;
  type: "card" | "article" | "doc" | "quest";
  id?: number;
  title: string;
  summary: string;
  tags: string[];
  matches?: SearchMatch[];
}
```

PublishedData 是 SDK 按 meta.type 区分的 home/card/article/doc/quest/list 数据联合，公共字段含 version/key/meta/content 及可选引用、插件和 CSS 资源；业务字段由第 6 节各类型 schema 定义。SearchDocument 与 SearchHit 共用身份和展示文本字段，SearchDocument 另有必需 content 纯文本，SearchHit 不复制该全文；命中范围引用 SearchMatch.text 本身，不假定它是截断后的 UI 摘要。模板可从 key 查清单中的额外实体元信息。

ranges 每项均为整数区间，满足 `0 <= start < end <= text.length`；field 为 tags 时，text 是该条命中的标签字符串。没有命中范围时可省略 matches，不能让模板依赖检索库的内部匹配对象。

作者不需要先调用 readManifest。readData 和非空 search 在需要时内部加载、校验绑定清单，再读取目标数据或索引；同一客户端复用该绝对 URL 对应的清单结果，不自动追踪站点后续发布。更换数据来源时由调用方以新 manifestUrl 创建客户端，不增加隐式刷新机制。空查询在正常情况下直接返回 []，清单和索引都不请求；已中止 signal 的调用返回 AbortError。加载失败不缓存为成功初始化，后续调用可重试；并发复用时取消一个调用不影响其他调用。

### 7.1 读取、校验与错误

- readManifest 读取指定清单；readData 以 key 查询清单，再读取对应 JSON，返回 data/dataUrl。资源 URL 按第 6 节解析；同一结果可供模板自行选择渲染、搜索后展示或预览。
- 内容引用先取得 ContentRef，再调用相同的 readData，无需预览专用数据 API；没有公开页面 URL 或目标 HTML 时也能读取已发布目标。不存在或未发布的 key 返回明确数据错误。
- 数据与索引均校验版本、身份和摘要；错误至少区分 PROTOCOL_MISMATCH、DATA_NOT_FOUND、INVALID_DATA、IDENTITY_MISMATCH、INTEGRITY_MISMATCH、RESOURCE_LOAD_FAILED，不伪装成空数据，不泄露本地安装路径。如何展示、重试或跳转由模板决定。
- 异步 I/O 接受 signal，取消返回 AbortError；不引入界面 dispose 或资源引用管理 API。实现可以按资源 URL 缓存查询结果；若复用进行中的请求，取消一个调用不能影响其他调用，失败允许重试即可，无需建设通用资源框架。
- 发布前检查模板声明的数据协议与最低客户端版本；消费端再次校验协议和产物。数据或插件格式不兼容需明确失败，不用某个宿主渲染实现作为兼容依据。

### 7.2 搜索接口

`client.search(query, { limit?, signal? }): Promise<SearchHit[]>` 只加载当前清单指定的索引并返回数据，不加载内容插件或界面库。

- **输入**：归一化 query 空白，空查询直接返回空数组，不请求索引；limit 为正整数，默认 12 条。索引按清单 search.data 解析、按 integrity 校验，与该清单的内容 key 配套；无需固定搜索索引 URL 或额外清单刷新机制。
- **结果**：SearchHit 提供 key/type/id 等内容身份及 title/summary/tags，不提供公开 href。可选 matches 是普通 `{ field, text, ranges }` 数据，field 为 title/summary/content/tags，ranges 为相对 text 的 UTF-16 左闭右开范围，不暴露检索库类型或预生成 UI。
- **实现**：首次非空查询再加载索引和检索代码，数据加载/取消/错误沿用第 7.1 节；不承诺中断检索库内部同步计算。模板也可使用索引中的普通搜索条目自行检索，不依赖辅助工具的具体算法。
- **展示与交互**：输入框、结果列表、摘要截取、高亮、防抖、历史记录、快捷键、过滤与点击后的 URL 均归模板。宿主不监听交互、不操作 DOM 或 history，不提供搜索后端或界面调度协议。

### 7.3 模板自行消费数据与插件

模板决定是否渲染正文、使用哪种渲染库、如何接入内容插件，以及如何管理界面状态和样式；宿主不提供统一挂载入口。模板需要预览时，根据 ContentRef 读取目标数据，再以自己的实现展示；可以弹窗、行内展开、单独页面，也可以完全不提供预览。宿主不规定预览数量、嵌套、关闭方式或内容截取规则。

官方模板保留现有页面、样式、内容链接和预览交互，将取数改为 key 查询，正文改为消费公开 Editor；不复制编辑器内核、内部 UI 或扩展源码来消除 link。不同模板无需共享页面组件、状态容器、样式体系或链接生成函数；也可以不使用 Editor，这些都不属于宿主作者契约。

### 7.4 Editor 包：通用编辑器公共依赖

新增一个 Editor npm 包，复用现有实现构建并维护，对模板提供稳定接口。编辑器内核、内部 UI、主题适配与默认扩展是该包的实现细节，不分别要求作者安装未公开的内部包。模板获得的是有版本的可执行 JS、类型、CSS 和必要资源，构建时与自身页面代码一起打进静态站点；“博客自带渲染能力”指这个构建结果，不是维护一份编辑器源码分叉。

打包范围为：输入/选区/节点变换/撤销重做/只读等编辑器内核、默认扩展、编辑器菜单/浮层/源码编辑预览等自身 UI，以及类型、已编译样式和必要静态资源。不包含桌面 IPC、数据库、上传、协作业务、发布资源加载、页面/Router/搜索界面或外部内容预览弹窗。

| 交付物 | 公开职责 | 不承担的职责 |
| --- | --- | --- |
| 既有 `@tau/plugins` | 普通插件类型/C23 契约；发布数据类型及可选纯数据客户端 | 不打入编辑器、UI、正文挂载、Router 或预览界面 |
| 既有 `@tau/ui` | 保持普通插件的现有 UI 类型与 Tau 注入约定 | 不新增站点阅读器，也不作为 Editor 在浏览器中执行时的类型占位替身 |
| 新增 Editor 包 | 通用编辑器内核、默认扩展、编辑器自身 UI、样式/资源及公开扩展接口 | 不认识博客发布协议，不加载发布插件或数据，不管理伴生 CSS，不决定页面、Router、搜索或预览 |
| 起步仓库中的模板接入层 | 用公开能力封装发布资源加载、C23 适配及发布样式生命周期；把正文和准备好的扩展传给 Editor | 不复制内部源码，不扩展宿主职责，不让普通作者从零组装接入逻辑 |

首版以 React 组件提供 Editor，这是模板选择该库时的依赖，不进入宿主的数据协议或模板准入条件。React/React DOM 等需要共享实例的依赖明确声明兼容版本/peerDependencies；模板接入层提供的扩展与 Editor 复用兼容实例。包内所需 UI 实现应随 Editor 交付，不能在浏览器运行时引用只有类型的 `@tau/ui` 根入口。所有其余依赖必须是包内闭包或可独立安装的公开 npm 依赖，不允许 workspace/link、本机路径或未发布私有包回退。

公开声明也须闭合。发布数据与 C23 产物元数据保持普通数据类型，不因引用插件定义而把 React、Slate 模块增强或 Editor 内部类型带入无界面客户端。Editor 可以在自身组件契约中使用 React 类型，不能要求模板补写内部模块声明、强制类型断言或私有路径别名才能通过检查。

Editor 包说明列出公开的编辑器/扩展契约及 React 兼容范围；模板接入层说明所支持的数据协议、C23 runtimeVersion 和经过验证的 Editor/SDK 版本组合。两者分别维护，不新增宿主的 Editor 版本协商字段。升级 Editor 只改变采用它的模板资产，不改变相同内容的数据 JSON、搜索索引或清单身份。

#### 最小公开入口与组件契约

以下为拟实施的首版设计，不表示已有同名 npm API；最终导出名与完整类型在 M2 对齐并验收，不借此公开整个内部模块树。

| 入口 | 首版内容 |
| --- | --- |
| `@tau/editor` | `Editor` 组件、`EditorProps`、通用正文类型、`EditorExtension` 及必要的通用扩展开发接口；默认扩展有可直接使用的组合 |
| `@tau/editor/api` | 明确的通用扩展开发入口，与主入口共享同一套内核、上下文和类型，不另打一份运行时 |
| `@tau/editor/styles.css` | 组件所需基础样式及可覆写的容器样式约定，内部资源按 CSS/模块 URL 解析 |

Editor 保留通用编辑与只读能力，沿用现有组件的基本形态；博客通过 readonly 使用它，不把公共包限定成博客阅读器。默认包含可用扩展组合，不要求调用方传 EditorKit、手动列全部默认扩展或注册桌面服务；模板可经公开扩展接口调整节点渲染。内容持久化、协作业务、桌面文件选择和上传不由该包承担，编辑时通过 onChange 把值交给调用方。

| Editor 参数 | 语义与边界 |
| --- | --- |
| `initValue` | 初始正文节点数组；不从 key、URL 或全局变量取数，不回写调用方的数据缓存。它不是隐式受控 value；换内容时由上层重新挂载对应实例 |
| `readonly` | 是否只读；默认行为与现有 Editor 对齐，博客显式开启只读，其他场景可编辑 |
| `onChange` | 编辑时向调用方返回正文值，不自动保存、上传或更新业务数据 |
| `extensions`，可选 | 按公开契约准备好的通用扩展；不传时有默认组合，不接受插件 URL、发布清单或 C23 包声明 |
| `className` / 主题等通用外观参数 | 调整本实例的容器与外观，不修改页面根主题，不要求 Tau 全局 Provider；具体名称对齐现有组件与公开扩展配置 |

最小类型轮廓如下；正文使用现有通用节点格式，Editor 公共类型与数据中的节点结构须兼容，但 Editor 不导入发布协议类型，数据 SDK 也不反向导入 Editor：

```ts
interface EditorProps {
  initValue: EditorNode[];
  readonly?: boolean;
  onChange?: (value: EditorNode[]) => void;
  extensions?: readonly EditorExtension[];
  className?: string;
}
```

不提供 `@tau/editor/published`、`loadPublishedResources` 或 `PublishedResources` 公共契约。Editor 的 props 不出现 dataUrl、pluginRenderers、contentStyles、文章 key 或发布清单；发布图片偏好、内容链接与预览等需求由模板适配为公开扩展/外观配置。节点或渲染错误按组件通常的错误边界处理，不建设博客专用错误层级。

组件内部负责自身需要的上下文、编辑器基础交互及菜单/源码编辑预览等 UI，不要求作者搭建内部 Provider/Portal 树。外部内容预览弹窗的打开、布局、层级和关闭仍归模板；Editor 不创建阅读器页面或预览容器。正文、引用答案和预览可同时挂载多个 Editor，每个实例分别创建节点、扩展注册状态和编辑器自身 UI，卸载回收自身资源；模板接入层另外回收发布资源。

现有 `CONTENT_ELEMENT_TYPES` 是跨端业务节点覆盖清单，不是内置扩展白名单。content-link、file-attachment、whiteboard、database，以及桌面的 doc-tasks、flashcard-blank、skill-ref、project-card-list 等业务扩展不因本次发布搬进 Editor 默认组合；桌面 store、服务注册、Markdown 文件/测高/描述输入等场景仍由应用维护。模板自己的链接与只读占位扩展也留在模板接入层。

#### 继续作为独立插件的能力

下列能力在 master 已迁出，Editor 包不得恢复旧实现、编译器、资源或节点专用回退。版本与摘要从迁移时的正式产物/固定夹具核对，不在本表另建版本源。

| 能力 | 既有插件 ID / 独立仓库 | 本方案的接入方式 |
| --- | --- | --- |
| HTML 块级与行内 | `tau.html` / `LastKnightCoder/tau-plugin-html` | 继续由同一 C23 插件提供两类 HTML 节点 |
| TikZ | `tau.tikz` / `LastKnightCoder/tau-plugin-tikz` | 编译器、字体和节点仍由插件提供 |
| Typst | `tau.typst` / `LastKnightCoder/tau-plugin-typst` | 节点与其现有编译/缓存策略沿用插件，不在 Editor 恢复原专用服务 |
| ABC 乐谱 | `tau.abc` / `LastKnightCoder/tau-plugin-abc` | 乐谱渲染、codec 和资源仍由插件提供 |
| 自定义组件块 | `tau.custom-block` / `LastKnightCoder/tau-plugin-custom-block` | 继续消费同一插件产物，不把其编译/渲染实现内置回来 |

博客的能力保留通过 PublishedContent 消费发布时收集的插件产物实现，不从 Editor 默认包偷偷补齐或自动下载安装。缺包时沿用现有缺失贡献检查、未知节点/源码保真规则，不丢原始数据；历史字段或类型名仍有消费者时可以保留，它们不构成回迁实现的理由。完整 HTML 文档、脚本、动态 CSS 和各插件交互须用真实包验证；若有缺口，在对应插件或公开接入适配中处理，不恢复旧内置实现。

默认组合是 Editor 这个可选库的能力，不是宿主固定的节点渲染清单。Editor 只按通用扩展契约处理覆盖与冲突，不识别 C23 包身份；模板接入层校验节点归属并适配贡献，不覆盖别的合法插件。后续还有其他内置能力迁为插件时继续使用同一通用扩展入口，不增加博客专用编辑器或永久内置回退。

CSS、字体、图标和编译器静态资源须随包或明确的公开依赖交付，并可重定位；既有在线渲染依赖要在包说明中明确。Editor 交付已编译的基础 CSS，限定在组件容器内，不向模板的 html/body 注入重置或主题规则；模板无需启用 Tailwind，也不扫描宿主或 Editor 源码/安装目录生成类名，不依赖 Tau 全局样式、主题状态或本机编译器。模板可自行选择样式工具；发布伴生 CSS 的加载、作用域及传入 HTML 子文档由模板接入层适配，不让 Editor 识别 contentStyles。首版不新增浏览器 Tailwind 编译服务，也不延长第 10.2 节的宿主编译退役计划。

### 7.6 模板侧 PublishedContent 与 C23 接入

起步仓库提供普通模板组件 `PublishedContent`，作为发布数据到通用 Editor 的适配层。它属于模板源码，不是 Editor 包的入口、宿主组件或额外 npm 包；作者可复用、修改或替换它，不需要在每个页面手动加载资源。

1. 接收已读取的数据及 `dataUrl`，取出当前场景的正文与发布资源声明，不创建博客专用正文结构。dataUrl 只在这一层作为 JSON 资源基准，不传给 Editor；不从公开路由或内容 key 猜资源地址。
2. 按第 6 节加载、校验 C23 脚本、插件 CSS 和伴生 CSS；取消、失败和过期结果在此处理。校验摘要后再求值，并校验插件身份/节点归属，不调用桌面 `create/activate` 或连接本地安装目录。
3. 用公开能力提供 C23 共享模块映射，把静态贡献适配为 `EditorExtension`。类型声明不是实现，实际模块来源必须逐项核对；存在缺口时先明确必要的公开能力，不得复制内部源码、引用私有模块或把发布加载器塞回 Editor 来绕过缺口。M2 必须用真实内容插件证明这条接入闭合。
4. 管理发布样式的作用域、HTML 子文档所需的样式适配和关闭清理；Editor 只消费通用扩展/配置，不读取 contentStyles。字节缓存可复用，正文节点、发布插件实例、样式所有权和组件状态分别归各实例。
5. 根据 `contentLinkTargets` 提供模板自己的内容链接扩展，再把正文和准备好的扩展交给 Editor。预览容器、Router、搜索、页面错误展示仍由模板组织。这里不建设通用 runtime manager、宿主挂载 API 或引用计数协议。

普通内容插件作者继续沿用一份 C23 入口，不需要编写“博客专用插件”。起步仓库维护者负责上述接入封装及真实插件测试；普通模板作者调用封装组件，不必从零编写 require 映射或编辑器服务组装。

拟议用法区分两层，名称仅为起步仓库中的示例，不是新增宿主契约：

```tsx
// 页面代码：模板自己的组件接收发布数据和资源基准。
const result = await client.readData({ key, signal });
<PublishedContent data={result.data} dataUrl={result.dataUrl} />;

// PublishedContent 内部：资源接入完成后，只传通用编辑器参数。
<Editor initValue={nodes} readonly extensions={extensions} />;
```

切换内容时，模板封装负责取消过期任务并重建对应 Editor 实例。预览是按目标 ContentRef 读取 JSON，再在模板自己的容器中挂载另一个 PublishedContent；不增加宿主预览接口，也不改变通用 Editor API。

### 7.7 模板作者起步仓库

另建独立的模板作者起步仓库，作用类似现有插件作者模板仓库；它不是原 apps/blog 的替身，也不是客户端内置模板。官方博客作为完整模板消费相同的公开依赖和打包契约，起步仓库保持最小可运行，不把官方博客的大量页面和布局变成作者起点。

- **包含**：固定公开依赖版本及锁文件；Vite + React 的通用 Editor 示例与模板侧 PublishedContent 封装；显式清单启动、按 key 取数、C23/伴生 CSS 接入、模板包 manifest/摘要/ZIP 构建；本地开发夹具和验证命令。示例展示直接 fetch 或数据客户端的消费边界，无宿主源码前置步骤。
- **示例而非协议**：Router、URL、页面结构、搜索展示、主题和预览 UI 均在模板源码中，作者可删除、替换或另选工具。展示一个链接/预览场景即可，不建设通用模板应用框架；React 只因示例选择 Editor 而存在。
- **不要求作者从零编写**：EditorKit/内部服务注册表组装、CJS require 映射或发布资源加载；这些由公开通用能力与起步仓库的模板封装分工完成。仓库不得包含编辑器/UI 源码副本、未公开私有包依赖、宿主路径别名、workspace/link、Git 子模块或依赖宿主 checkout 的样式扫描。开发服务器只提供明确的夹具资源，不把 mock 全局注入或私有本地服务带入正式站点。
- **分发**：仓库提供可克隆/生成的作者起点；构建后的模板 ZIP 仍通过插件中心分发。npm 包、起步仓库和站点模板包分别版本化并记录经过验证的依赖组合，不新增兼容协商平台。模板作者无须先克隆平台主仓库。
- **作者验收**：清空本地工作区外部依赖后，在只有该仓库的干净目录，从公共 npm registry 按锁文件安装、类型检查、构建和打包；随后用正式宿主消费产物。待发布 tgz 的预检与公共 registry 的最终验收分别记录，不能用前者代替公开交付完成。

#### 原 apps/blog 的处理边界

用户已明确后续博客发布改为插件，旧 `apps/blog` 不再需要兼容维护。其 master 中的 `../../../../editor-extensions/standard` 和旧 `@tau/editor-<功能>` 引用仅作历史参考，不要求迁移入口或维持旧工程安装、类型检查和构建，也不因此阻塞通用扩展收拢与顶层目录删除。

后续实施保留旧工程源码及历史工具/spike 供参考，不再将其作为正式发布来源或默认验证目标；必要时从活跃 workspace、根构建/CI 和依赖解析范围排除旧工程，避免其已失效的工作区依赖阻断全仓安装。该调整属于仓库接线清理，不是继续改造旧博客；不为它建立路径别名、源码副本、旧包名 npm 兼容包或转发层。本次只更新文档，不删除或修改旧工程。

正式验收覆盖宿主、公开 Editor、继续使用的应用/公共库及独立博客插件。旧博客及历史资料中的路径不要求字符串清零，但活跃配置不得继续解析到这些失效入口；报告明确区分历史引用与已迁移消费者。独立博客插件仍须保留既定样式和能力，并通过无宿主源码的安装、类型检查、构建及正式宿主发布验证。

#### B. 单一实现迁移与分层

1. 先建立 core 的稳定接口和明确依赖方向，再逐组迁入 23 个内置功能；每组保留节点 type、扩展/命令 id、原字段及序列化语义。现有内核行为归 core，功能节点归 extensions，不趁搬迁升级第三方依赖或改变插件协议。
2. 通用默认组合迁到 presets，外部 Editor 包装负责装配；应用保留自己的场景、业务扩展和服务接线。内置扩展只依赖 core 的稳定能力或通用支撑，不经外部 index/Editor 包装反向导入；Markdown/codec 使用独立通用入口，不从 UI 根入口取 codec。
3. 按 A 的清单核对所有继续使用的消费者，逐组更新工作区依赖、导入、类型增强、样式扫描/入口及测试路径，同组消费者和单一实现一起接替；未迁完的组暂留原位置，不复制保留两套实现，也不将旧包名逐个发布为 npm 兼容包。旧 apps/blog 按 A 作为历史工程处理，不参与入口迁移，不阻塞移动/删除。
4. 同步 `docs/editor-refactor/07-核心与扩展边界及推进约定.md`、相关决策、`scripts/check-editor-extension-boundaries.mjs` 及覆盖测试中的路径映射；边界规则仍检查“core 零具体功能/业务依赖”，不因目录集中就放宽。桌面、移动端与扩展不新增插件下载或加载机制，已迁出节点继续遵守各端既定规则。
5. 所有继续使用的消费者接替后，删除顶层 `editor-extensions/`、`standard.ts`、旧功能工作区包及临时旧入口，清理工作区/锁文件/配置引用。复核静态与动态导入、CSS 和声明解析，不依赖本机残留 node_modules 掩盖缺包；按消费者清单运行类型检查、相关行为测试及构建，补充顶层目录不存在、活跃配置无旧路径且 core 无功能依赖的结构检查。确认全仓安装及默认构建不再解析旧博客的失效依赖，不要求旧博客自身检查通过。`packages/editor-collab`、`packages/editor-source-view` 等仍有职责的公共库不因名称含 editor 而删除。

#### C. 生成一个独立可消费的 Editor 包

```text
npm 包/
├── package.json             # 显式 exports / dependencies / peerDependencies
├── dist/
│   ├── index.js             # 对外 Editor 与默认组合
│   ├── api.js               # 通用扩展接口，与主入口共享内核模块
│   ├── styles.css           # 已编译基础样式
│   ├── chunks/…             # 按需加载的内置能力
│   └── assets/…             # 本包需要的资源，不含已迁出插件引擎
├── types/…                  # 独立声明闭包
├── README.md
└── LICENSE / 许可说明
```

- 只发布一个 Editor 包，代码为可执行 ESM，不复用既有 SDK 类型包的占位入口作为运行实现。包名/别名/版本在实施时与注册表核对，不预占版本、覆盖已有版本或降级既有 SDK；现有两个 SDK/UI 包仅在契约确需更新时各自发版。
- 主入口、api 与需要保留的通用子入口共享同一套内核/上下文模块。React、React DOM 及其他必须共享实例的依赖整理为经过验证的 peer 范围，不照抄陈旧 workspace 配置，也不能每个入口各打出一份上下文。
- 内部 UI/shared/themes/Markdown/源码预览所需实现进入构建闭包或使用实际可安装的公开依赖。输出不得残留 workspace/link、宿主绝对路径、私有 @tau/* 导入或仅有类型的运行时替身；声明、模块相对引用及 CSS/资源同样可重定位。
- 发布白名单仅包含运行代码、类型、样式、资源和说明/许可，不包含应用源码、测试插件夹具、已迁出插件实现或本地调试配置。检查多入口依赖图、声明解析和最终 tarball 文件，不仅检查源码目录。

#### D. 候选包、公开发布与最终回读

1. 从当前主线收拢后的单一实现生成候选包，在无宿主源码的目录安装归档；分别验证普通编辑/只读、默认组合、自定义扩展及多实例，确认 Editor 完全不需要发布数据或业务 URL。
2. 起步仓库用该候选包和公开 SDK 接入正式 C23 插件，逐项核对共享模块的实际实现来源；验证 HTML/TikZ/Typst/ABC/custom-block 的真实贡献、资源和缺包行为。候选 Editor 的构建输入与产物不能包含它们的源码、引擎或测试夹具；协议/历史类型名保留不等于内置实现残留，不以清零字符串代替检查。
3. 分别记录 npm tarball、模板 ZIP、插件产物及整站体积，重新测量包限制和首次加载；不沿用旧分支的 vendor/字体尺寸或旧博客资源数证明新 Editor 的容量。

## 10. 体积实测与后续优化

历史基线：2026-10-18 重建旧版 `apps/blog`，全站 29MB。构成：tikzjax 6.6MB（TikZ/LaTeX wasm）、Shiki 全量语言/主题/oniguruma ≈9MB、mermaid 及传递依赖（elkjs 布局引擎、cytoscape 等）≈5MB、abcjs/KaTeX ≈2MB、CSS 4.6MB。master 后续已迁出多种实现，这些数字不代表当前 Editor 包、主线博客或未来模板体积。

spike 壳 32.1MB 是未 minify 的验证形态，不代表新方案正式体积。分别统计模板、可选数据工具、内容插件和整站产物；渲染依赖计入相应模板或插件，不能以“宿主辅助代码”名义重新捆绑。模板自行选择构建和分包方式，辅助工具只保留数据与查询依赖。

### 10.1 重型渲染器插件化

HTML、TikZ、Typst、ABC 和 custom-block 已完成相应迁出，不在本方案重复拆分或内置回来。仍保留的 Mermaid/PlantUML、math、code-highlight 等未来是否继续插件化另行评估，不是本次源码收拢或 npm 发布的前提。已有独立插件继续复用桌面与站点的同一产物，由发布器按内容归属收集；优化不在宿主新增渲染层，也不要求第三方模板采用相同工具。

### 10.2 HTML 已插件化后的宿主 Tailwind 编译退役

这是确定的后续架构方向，不以“模板可能需要”为由长期保留宿主编译器：

1. 首版沿用当前 master 的通用 styleSources 生产路径，将动态 CSS 保存为可选伴生资源；对齐旧分支时移除其 HTML 节点类型特判，不扩大宿主对模板源码或第三方框架的分析范围。
2. html-block/html-inline 的定义、渲染、codec、源码 UI 和样式源码声明已归 tau.html；不再安排其回迁或再次拆分。完整 HTML 文档及存量节点的行为由正式插件和模板接入层验证，不能把“已插件化”写成“动态样式已不依赖宿主编译”。
3. 模板与插件各自决定是否使用 Tailwind。静态类可在各自产物构建时生成 CSS；用户在插件安装后写入 HTML 的动态类不能靠插件构建期预编译覆盖。HTML 插件方案必须在删除宿主编译前选定并验证替代生产者：插件自行生成并保存内容所需的 CSS，或在站点运行时自带动态样式能力。具体插件数据/资产协议另立方案，本轮不新增“宿主执行插件代码产出样式”的生命周期或编译回调。
4. 删除范围同时覆盖发布和编辑/预览端：发布器源码遍历、`buildTailwindRuntimeCss`、编译缓存、相关主进程/worker 消息；SDK `styleSources` 与 `context.services.tailwind.compile`；编辑器 `IRuntimeStyleCompiler`、SourceBlockEditor 的 compiler 接线及 HTML 的宿主编译 hook；全部消费者迁移后再删除只为这些入口服务的模块和依赖。清理前需逐项列消费者，不能只删除发布 worker 就宣布宿主编译退役。
5. 同步更新 SDK/作者契约、重发受影响插件及客户端兼容约束；不留下空服务、静默忽略动态样式或永久旧编译回退。模板和插件自己的构建工具可以继续使用 Tailwind，退出的是宿主提供的运行期/发布期源码编译服务，不是禁止 Tailwind 作为构建依赖。
6. 退役验收：插件安装后新增/修改 HTML 类名，桌面编辑端及官方模板自身的正文/内容预览仍正确；样式产物离开宿主编译服务可消费。宿主不再扫描用户 HTML/插件源码，不提供上述编译服务。第三方模板自行决定如何展示 HTML，不以官方模板样式实现限制作者。

因此，`contentStyles` 表达的是可选 CSS 资源，Tailwind 只是首版过渡期的一种生产者。后续插件化可以改变生产者乃至不再输出该字段，无需让模板理解编译链路。

验收：Editor 在不提供任何发布清单/dataUrl 的普通编辑和只读场景下可独立使用，默认节点、扩展覆盖和 onChange 行为正确；core 不依赖功能扩展/preset，公开声明不依赖发布协议。Editor 产物不含已迁出插件实现。起步仓库的 PublishedContent 只用公开能力接入 master 对应的真实 C23 包，作者不导入 EditorKit/内部扩展或从零编写映射；适配层的摘要失败、取消/关闭回收、HTML 脚本/CSS 及同 key 多实例行为通过。按第 7.8 节分别记录候选包检查与公共 registry 冻结安装/构建；不用任何渲染库的摘要模板仍能消费同一数据协议。仓库迁移另按消费者清单验证继续使用的各端、公共库及工具链，完成顶层目录删除和活跃配置清理；旧博客自身的构建不在验收范围，公开包可用也不能替代其他活跃消费者的迁移验收。

### M3 模板包与插件中心安装闭环

- 门户、客户端 manifest 校验及 ZIP 安装器支持模板专用 root/entries 分支、完整资产摘要、目录白名单与资源保留位置，不以宿主业务路由限制作者目录。
- 实现模板分类、安装后导流、选择配置及无模板/损坏/不兼容状态；静态模板能力不依赖桌面激活或内容插件启用。
- 验证正式模板所需包限制，冻结发布时的模板版本和文件快照，处理安装更新、卸载与发布并发。

验收：真实模板 ZIP 经中心审核与安装后，作者静态目录和多个实际入口完整可读；篡改、漏声明资产、越界、重复项和协议不匹配均拒绝，不要求固定入口名或每内容一个 HTML；模板 JS 不在桌面安装/启动时执行。安装、更新、重启及卸载后的发布阻断均通过。

### M4 全内容类型数据与发布资源迁移

- 复用业务构造导出全内容类型与聚合数据，将生成的 href、currentPath 等路径改为内容身份；节点引用、材料与搜索指向相同 key，不生成公开路由。
- 实现协议路径占位符、模板目录复制、资源边界与逐文件摘要；索引与内容由同一清单引用，移除固定 search-index.json 的独立更新依赖。模板构建身份保留在发布记录，不污染内容数据。
- 动态 CSS 首版保存为 `data/styles/<digest>.css`，可按字节复用，不使用内容 key 作为文件名；保留过渡期生产者，样式使用和界面留给模板。favicon/偏好仍为数据，不新增统一渲染、插件执行链或导航协议。
- 接通发布 worker、冻结模板文件、增量 diff、依赖上传顺序、重试、当前及前一轮依赖的有限保留与缓存策略。

验收：正式生成/上传链路及构建通过；所有类型、关系、索引、CSS 和插件资源引用闭合。数据相同而模板不同，内容 JSON/索引/数据清单可复用；修改单条内容且共享输入未变时，不重传无关正文 JSON。发布前失败不上传，依赖失败不更新入口，重试及有限保留/撤下计划正确；不以模板能否绘制某种 UI 判断宿主数据是否合格。

### M5 官方模板迁移、完整验收与旧链路退役

- 官方博客基于原 apps/blog 的页面和样式在独立 tau-blog-template 工程迁移，消费公开数据 SDK、Editor 及插件产物；保留既有页面、样式、搜索、路由和内容预览。正文经模板侧 PublishedContent 接入公开 Editor，资源及模块映射集中在该适配层，不散落页面；移除宿主源码 link、私有导入、内部 Kit 组装与源码扫描，不复制编辑器内核或内部 UI，原 apps/blog 工程按用户要求保留不动。
- 官方模板按中心规则上架、安装和发布；官方模板与起步仓库分别做无宿主源码的独立安装/构建。再用正式宿主生成/上传链路消费其真实 ZIP，并用真实 C23 插件验证正文和预览交互。另用不提供预览/仅摘要模板验证准入自由，不为旧路径保留宿主路由层。
- 在新链路全项通过后，按仓库删除清单流程复核消费者，再退役宿主新链路中已被替代的 `PublishTemplateManager`、R2 模板 ZIP 获取链路、旧内联数据解析及旧发布脚本；替换为新的模板插件构建/分发流程。旧 apps/blog 内的脚本仅作历史参考，不继续维护或参与正式发布。
- 收口第 7.8 节的顶层目录删除检查：继续使用的各组消费者完成接替后，删除 editor-extensions 及旧工作区入口，确认旧博客不再进入活跃 workspace 依赖解析、默认构建与 CI。无需先迁移旧博客或为它保留旧入口，不以旧工程是否仍可构建阻塞删除。
- 同步 README、C23/分发文档、中心协议；涉及桌面数据协议与壳层行为时同步 03 架构实现指南及 DECISIONS.md。

验收：安装官方模板并发布，按其自身部署方式验证现有渲染、插件交互、搜索、导航及预览功能；真实产物的 Editor、默认扩展和资源完整，不以裁减能力规避包限制。这些模板行为不写成第三方作者硬约束。正式宿主与独立模板的旧固定路由、下载和内联解析消费者清零，独立模板与起步仓库无源码 link 或编辑器源码副本，客户端无模板 UI 资产或统一渲染服务；旧 apps/blog 及其工具只作历史参考，不作为发布来源或兼容验收对象，顶层目录删除及全仓安装/默认构建检查通过。历史 R2 文件可只读保留，客户端不再依赖。

## 12. 风险与开放问题（评审重点）

1. **宿主职责必须收口**：只提供数据、无界面查询及插件产物协议；辅助工具不能依赖官方模板组件或执行站点插件，不能承载渲染状态、样式和界面事件，也不能以“参考实现”名义成为必用模板框架。
2. **身份与数据闭合**：稳定 key 不随 URL、模板或展示形式变化；旧节点类型、搜索实体和清单身份的映射需实测。currentPath 等非 href 字段也要检查，预览所需目标数据不能藏在公开页面 HTML 中。
3. **搜索与内容配套**：清单引用固定摘要的索引和内容，避免搜索返回当前数据集合无法读取的 key。模板可用查询工具或自行检索；宿主不将结果改为链接或决定点击行为。
4. **内容插件兼容分层验证**：宿主检查文件、归属、依赖声明和摘要完整；Editor 维护者验证通用扩展契约，起步仓库维护者验证模板侧 C23 适配与公开模块来源，模板验证自己的依赖组合和交互。不宣称任意模板自动支持所有节点，不另建模板能力协商、强制组件或宿主准入渲染测试。
5. **Tailwind 退出有前置条件**：HTML 已在 master 插件化，首版仍提供通用生产者输出的过渡 CSS；退役前需证明动态输入的替代样式路径，再迁移全部源码扫描、公开编译服务和编辑器接线，不将“节点已迁出”当作“编译已删除”，也不留下永久兼容服务。
6. **部署能力范围**：复制作者静态产物，不执行模板生成代码或增加服务端路由。模板自行选择渲染、SPA、深链和 SEO 方案；这些能力不通过宿主隐式生成业务页面兜底，也不限制作者采用自己的工具。
7. **有限保留与撤下**：当前/前一轮依赖保留不优先于撤下内容；需清理关联旧数据、索引与派生摘要，删除源站文件不等于收回已有缓存。只换模板不删除当前数据，旧文件清理按实际文件引用处理，不识别作者路由语义。
8. **退出旧链路与范围控制**：官方模板功能迁移后再退役旧分发、固定路由生成和内联解析；实验双来源不进入正式兼容层。不增加 UI 管理框架、路由声明语言或历史回溯。静态生成执行能力若后续需要，另立协议，不能借此提前控制模板架构。
9. **公共交付不能由源码捷径替代**：新增 Editor 包必须有可用实现、类型和资源闭包；普通 SDK/UI 类型占位根入口继续按宿主内插件使用。既不将内部模块逐个发布，也不把复制源码、候选 tgz 安装或仅能运行已构建站点当成模板作者的独立交付验收。
10. **旧博客不再阻塞清理**：顶层 editor-extensions 最终完整删除，不留第二套扩展目录；后续发布由独立博客插件接替，旧 apps/blog 仅作历史参考，不维护兼容入口或要求继续可构建。按第 7.8 节清理其活跃 workspace/默认构建接线，避免历史依赖阻断全仓安装；宿主、Editor、继续使用的消费者及新模板仍须完整验收。
