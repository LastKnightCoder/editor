# 问题管理插件化与宿主能力开放：调研与方案

## 1. 背景与目标

问题管理（问题、分组、探究材料、探究对话、轨迹、独立答案）目前是桌面端内置模块。本方案调研把它抽成插件时 SDK 缺什么、宿主有哪些耦合，并借此补齐宿主能力的开放。

目标不是让问题插件跑起来，而是打下地基：之后其他模块转成插件时，能直接复用这些接口，不再为单个插件开专用口子。

产品尚未发布，接受部分功能丢失（见第 6 节）。

## 2. 判定标准

### 2.1 地基与补丁

判断问句：**把问题模块整个删掉，这个接口还说得通吗？**

- **地基**：宿主把自己的对象和自己的界面能力开放出去。接口用宿主的词汇（卡片、项目文档、Notebook、对话、侧栏、首页），与用到它的功能有多少无关。新建卡片弹窗、插入到项目、新建 Notebook，都是宿主本来就有的能力，所以都是地基。
- **补丁**：接口里藏着某个插件的概念或交互特例。比如 `seedQuestion`、只服务于「捕获成问题」的注册、识别「像问句」的命令面板提供方、专为问题写的脉络回调。

### 2.2 依赖方向

- 番茄钟、闪卡、漫步等都是核心功能。核心功能之间照常直接协作，不经插件扩展点；现有联动（待办详情里的「开始专注」、卡片详情里的「制作闪卡」、首页漫步）保持不变。
- 扩展点只给插件用。宿主在菜单、侧栏、首页留挂载点，内置项照旧写死，插件贡献的内容排在内置项之后。
- 本次只拆除指向问题模块的边：问题离开核心后，宿主里直接调用问题模块的地方，或者改由问题插件经挂载点挂入，或者删除。

### 2.3 能声明的不写回调

移动端、独立编辑器窗口不运行插件（插件运行时只挂在主窗口 `AppShell`），插件停用后也不运行。需要在这些地方生效的能力（脉络关联、类型外观）一律做成声明式数据，随笔记库保存；只有必须执行插件代码的行为才用运行时回调。

## 4. 地基设计

按宿主能力分五层，外加贯穿各层的统一正文输入。

### 4.1 统一正文输入

现状：读正文可以拿 `nodes`，写正文只能用 Markdown（`data.cards/articles.create`、`content.edit` 的 `append` / `prepend` / `replaceAll`）。77 第 5 节以「nodes 暴露 Slate 结构、须先声明 `nodeSchemaVersion`」为由推迟了 nodes 写入，但版本号一直没有实现。只收 Markdown 的代价：

- 格式丢失：高亮、颜色、白板嵌入、插件节点、文档待办的 taskId 都过不了 Markdown 往返，`replaceText` / `replaceAll` 已在注释里承认会简化格式。
- 问题插件直接受影响：描述与答案本身就是 `Descendant[]`，「答案存为卡片」在宿主里是无损复制，插件版若只能经 Markdown 中转就会丢格式。
- SDK 自身不一致：闪卡收 `string | Descendant[]`，`services.markdown.deserialize` 产出 `Descendant[]`。

统一为一个正文输入类型，所有写入口共用：

```ts
/** 新建与修改正文的统一输入；宿主在写入前按当前编辑器规范化 */
type PluginContentInput =
  | { markdown: string } // AI 输出、外部导入、简单插件
  | { nodes: Descendant[] } // 编辑器内部结构，无损
  | { copyOf: PluginContentRef }; // 宿主内部整份复制，插件不接触结构
```

- **`nodes`**：宿主在入口做结构校验并报出出错路径；未注册的元素类型按编辑器 ER-006 原样保留，不做类型白名单；文档待办的 taskId 由 doc-tasks 索引在写入后统一补齐（实施时细化，见任务清单）。SDK 导出 `EDITOR_NODE_SCHEMA_VERSION`，`content.read({ format: "nodes" })` 同时返回 `schemaVersion`，插件据此判断自己能否处理。
- **`copyOf`**：只需要目标的写权限，不需要来源的读权限，因为正文不离开用户的库，插件也拿不到内容。
- **使用范围**：`data.cards/articles.create`、`entities.create` 的初始正文，`content.edit` 的 `append` / `prepend` / `replaceAll`，第 4.3 节的界面动作。闪卡的生成素材不并入：`generate` 会把衍生草稿交回插件，接受 `copyOf` 会绕过读取授权（实施时裁决）。
- **实施进度**：见 [问题管理插件化任务清单](问题管理插件化任务清单.md)。

### 4.2 宿主对象：`ctx.data` 与统一引用

- **补齐数据接口**：
  - 白板、项目的增删改查；
  - 项目文档的新建、移动、删除（77 第 20.3 节已列为契约缺口）；
  - Notebook 及其资料（只读，实施时收窄为信息与资料清单，见任务清单 1.2d）；
  - 对话会话的读取与列表（只给会话信息，不含消息）；
  - 材料（摘录、PDF 标注、剪藏）的读取（不含剪藏正文）。
- **统一引用**：`PluginEntityKind` 补全为宿主全部可引用的类型，新增 `project`、`notebook`、`material`（外部材料统一一类，内部沿用 `MaterialRef`）、`chat-session`、`plugin-entity`。`pick`、`open` 同步支持。
- **引用解析**：
  - `app.describe(refs)`：返回 `ok`（最新标题）/ `missing` / `denied`（附所需权限）。用户亲手 pick 过的引用由宿主按插件记住，之后不需要权限；本插件自己的内容不需要权限；其余要对应类型的读取权限，不弹窗。只给标题，不含更新时间、字数等（实施时收窄，见任务清单 1.2a）。
  - `<EntityRef ref>` 组件：图标、类型名、标题、「已删除」状态都由宿主渲染，插件拿不到数据，复用宿主已有的 `useEntityKindMeta`。

### 4.3 宿主界面动作：`ctx.app.run` 与 `ctx.app.open`

规则：

- 宿主弹出界面、用户确认，确认即同意，不需要数据权限；
- 只能在用户操作后调用；
- 每个动作都有返回值，用户取消返回 `null`。

```ts
app.run("card.create", { content?: PluginContentInput, tags? })              → PluginEntityRef | null  // 宿主新建卡片弹窗
app.run("project.insertDocument", { content: PluginContentInput, title? })   → PluginEntityRef | null  // 宿主「插入到项目」弹窗
app.run("notebook.create", { title, description?, sources?: PluginEntityRef[], from?: PluginEntityRef })
                                                                             → PluginEntityRef | null
app.run("chat.start", { prompt?, context?: PluginEntityRef[], placement? })  → string | null           // 会话 ID
app.open(ref, { placement?: "page" | "dock" | "window", at?: string })
// 已有：content.export / content.present / content.share（返回值改为与上面一致的约定）
```

- `notebook.create` 的 `from` 由宿主记为通用的来源谱系（`upgraded_to`）。Notebook 页的「来源」按脉络的谱系解析统一展示，不再有 `SourceQuestionRow` 这类专门代码（实施见任务清单 1.3c）。
- `chat.start` 取代对话页的 `seedQuestion` 参数，`context` 中的引用作为对话上下文；会话本身可被引用、可被关联。
- `open` 的 `at` 对对话是消息 ID，对正文是位置，沿用 `ContentEditor` 的 `at`。
- 宿主现有 `ExtNoteInsertModal` 支持「复制」与「共用正文」两种插入方式。`project.insertDocument` 只开放复制；共用正文涉及插件实体与项目文档共享正文的生命周期，暂不开放。

### 4.4 宿主挂载点

第二期已实现（2026-10-22），下表为实际形状；与原方案不同之处见表后。

| 挂载点       | 形状                                                                                                                                                        | 说明                                                                                                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 侧栏         | `registerItem` 返回句柄 `update({ badge, children, action })`；子项 `{ id, title, params, tone?, count?, menu?, onDrop?: { type, run } }`；`dragType(type)` | 子项在条目页面显示时展开；`menu` 为右键菜单，`action` 为子项末尾的动作行（如「新建分组」）；拖放只接收本插件的拖拽类型                                                                              |
| 首页         | `home.registerPanel({ id, title, component, size? })`，`size` 为 `compact` / `wide`                                                                         | 内置与插件面板同一注册表，用户在编辑模式里拖动调整顺序、隐藏，布局随笔记库保存（桌面 D-182）                                                                                                        |
| 对象动作     | `actions.register({ id, title, icon?, targets, run })`，`run` 的参数随 `targets` 收窄                                                                       | `targets` 取 `card`、`article`、`document`、`material`、`chat-message`、`text`；宿主在对应对象的「⋯」菜单、PDF 标注工具条、对话消息动作行与命令面板「记录」组列出；用户点过的对象登记为选择过的引用 |
| 对象详情区块 | `views.registerEntityPanel({ id, kinds, component })`，组件收到 `{ context, target }`                                                                       | 卡片、文章、项目文档详情的正文上方（洞见报告之后）；宿主不加外框，读内容仍按权限                                                                                                                    |
| 脉络         | 声明式，由 4.5 的 `links` 提供                                                                                                                              | 不写回调                                                                                                                                                                                            |

「转为问题」只是问题插件注册的一个对象动作。命令面板里的「记为问题」是 `targets: ["text"]` 的动作，固定在「记录」组末尾，命令面板不再识别「像问句」的输入。

与原方案的差异（用户裁决，见任务清单第二期）：

- 首页不由宿主安排位置：固定插槽是按问题模块现状定的，插件声明所属段又会把易变的首页结构冻结成 API，改为统一面板布局交给用户。
- 侧栏子项增加 `count` 与 `menu`，末尾可放一个动作行：问题分组需要未解答数、编辑 / 删除分组与「新建分组」。
- 对象动作不做 `selection`：编辑器选区由插件的编辑器扩展负责（目前不开放选区工具条），PDF 选区暂不做。
- `context.materials.actions` 只给宿主自己的材料动作，不含其他插件的对象动作，插件之间互不依赖；宿主材料动作的「转为问题」已删除。
- 四类挂载点只在主窗口生效，独立编辑窗口不显示插件的菜单项、区块与面板。

### 4.5 插件自有数据

划分规则：用户能看见、能打开、能搜到的内容是**实体**；插件内部使用的数据是**记录**。

- **实体**（已有 `ctx.entities`）：
  - `registerKind` 增加可索引的 meta 字段声明；
  - `query` 支持按这些字段筛选，并按创建时间、更新时间或指定字段排序。
- **记录** `ctx.records`：

  ```ts
  records.registerCollection({ name, indexes: { field: "string" | "number" | "boolean" } });
  records.insert(name, data) / get / update(name, id, data, { expectedRevision }) / delete;
  records.query(name, { where, orderBy, limit, cursor }) / count(name, { where });
  ```

  随库同步；删除直接生效，不进「最近删除」（用户裁决：记录是插件内部数据，用户看不见也无从恢复）；卸载后与插件内容一样保留 7 天；发出 `record.*` 事件，只发给本插件。主库表 `plugin_records`。

- **原子提交** `ctx.transaction(async tx => { ... })`：跨实体、记录与关联，回调里的写入在回调结束后一次提交，任何一条失败全部不生效；新建立即拿到 ID，修改与删除的 `expectedRevision` 可省略。

- **关联** `ctx.links`：插件内容指向任意引用的有序有向边。

  ```ts
  links.add(from: string, to: PluginEntityRef, { role?, data? });
  links.list(from, { role }) / remove(id) / reorder(from, ids);
  ```

  - 边由宿主保存在 `plugin_links`。目标须是插件能看到的内容（规则同 `describe`）。卡片、文章、项目文档的脉络在「被关联」里列出关联了它的插件内容，外观取插件声明的类型名与图标，移动端也能读，不依赖插件运行。只做入边：插件内容本身没有宿主的脉络入口。
  - 目标被删时边保留，不级联删除，也不为目标保活；`list` 不返回目标是否已删除，由插件用 `describe` 或 `EntityRef` 取得。编号被复用时按目标创建时间判为不存在。来源被删时边随快照进「最近删除」，恢复后插回。

### 4.6 编辑器与页面

- `ContentEditor` 增加 `kit: "full" | "compact"`，对应宿主已有的精简编辑器套件（白板、驾驶舱实体弹窗、PDF 笔记卡共用 `getDescriptionKit`）。
- `pageContext` 增加「本页是否在栈顶」；SDK 开放浮层退场（Esc）统一处理，插件抽屉与弹窗按 LIFO 关闭，插件代码不自行监听 Esc。
- 事件补齐：
  - 白板、项目、Notebook、材料、对话会话的增删改事件；
  - 插件自有实体与记录的变更事件（同步下载、自己的 MCP 写入后刷新页面要用）。
