# C13-A 固定目录自动发现

日期：2026-10-16。当前开发版与正式版都使用约定的本地目录发现插件，普通管理不再要求选择目录。安全和发布平台继续暂停。

## 使用方式

```text
~/.editor/plugins/
└── example.external-counter/
    ├── manifest.json
    ├── main.js
    └── styles.css（如清单声明）
```

每个直接子目录是一份完整构建，目录名必须等于 manifest.id；将版本构建目录内的完整产物放进此子目录，不是放源码工程、ZIP 或 dist 的多版本父目录。扫描忽略隐藏目录和普通文件，不自动解压 ZIP。

1. 重启本次更新后的桌面应用，进入设置 → 插件。
2. 点击“打开插件目录”；目录不存在会自动创建。把解压后的构建放入同 ID 子目录。
3. 点击“刷新列表”，或下次启动时自动发现。新插件默认停用，启用时才执行。
4. 已启用插件在重启/切库后恢复；停用意图同样保存。内置主题插件随应用打包，不需要放在这个文件夹中。

真实目录由 PathUtil.getAppDir() 派生，默认位于用户主目录的 `.editor/plugins`。它属于应用数据目录，不在开发 worktree 中，也没有目录选择设置。

## 实现边界

| 部分         | 正式实现                                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 主进程能力   | `modules/plugin-local.ts`，BACKGROUND，客户端经 withModule 处理就绪竞态                                                        |
| 发现         | `services/plugin-discovery.ts`，创建根目录、逐个读取直接子目录，好包/坏包分别返回                                              |
| 包读取与加载 | 复用 plugin-package.ts，通用函数 readPluginPackage；渲染 package-loader.ts 延迟执行快照                                        |
| 身份         | plugin-workspaces.ts 共享既有登记器单例，只沿用工作区 UUID，不恢复旧目录列表                                                   |
| 状态         | activation-manager.ts 的 PluginActivationManager 被内置和本地管理共用，内置旧键不变；本地键为 tau-local-plugin-enabled:v1:<id> |
| 本地管理     | local-manager.ts 串行处理扫描、启停和状态恢复，Provider 关闭/切库取消迟到处理                                                  |
| 界面         | 现有 PluginManagerView 展示固定路径、打开目录、刷新列表、包错误与启停                                                          |

主进程接口不接受安装路径参数。实际扫描只读取清单、代码和样式；复用现有格式/API/平台/摘要检查，不新增权限策略。普通依赖仍由作者打包，React/UI 等共享依赖沿用 G1 合同。

原 builtin-manager 泛化为 activation-manager，原 development-loader 改为 package-loader；没有维护第二份生命周期、持久化逻辑或加载器。协议位于 src/types/plugin-local.ts，主进程不依赖渲染 app 层。

旧工作区映射仍位于 userData/plugin-development/registry.json，目的是保留已经分配的 UUID 和私有数据命名空间；新路径不使用里面的开发插件目录记录。旧目录不自动搬移、旧启用记录不作为新安装授权或状态；用户将产物复制到固定目录后首次手动启用。既有开发验证工具可显式使用旧管理器，普通界面不提供其目录选择入口。

## 刷新与失败行为

- 新增完整包：登记元信息，默认停用，不执行顶层代码。
- 同一包未变：保留实例，不重复注册命令、CSS 或设置。
- 删除目录：刷新回收对应实例/命令，保留启用偏好与私有数据；同 ID 包重新放回时可恢复原意图与数据。
- 无效包、目录 ID 不匹配、内置 ID 冲突：展示该项错误，好包继续发现；内置主题插件不会被覆盖。
- 已加载包的磁盘文件损坏：报告问题，保留当前窗口内已经校验的旧快照；新启动无法加载损坏包。
- 根目录扫描失败：显示错误并保留原列表，不把“读失败”当作“所有插件已删除”。
- 运行中包有变化：保持旧实例并提示重启，或停用后刷新加载新构建。当前不盲目热替换；完整升级事务/失败回滚仍是后续工作。
- 切库/关闭期间扫描返回：旧管理器拒绝登记或再次启用，不向新宿主注入旧结果。

只根据当前内存快照启停，不在运行中监听作者每一次文件写入；“刷新列表”是显式重新读取。未来更新回滚不得以重新扫描成功冒充已经完成。
