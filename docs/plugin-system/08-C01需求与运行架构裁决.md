# C01 多场景需求与运行架构裁决

本轮确定插件体系的技术边界和下一阶段实施合同，不实现运行时，也不宣称已经通过隔离测试。基线为 `192913382`，工作分支为 `codex/plugin-system`。目标是合理、可扩展、安全的应用插件体系，微信读书只检验其中的跨服务业务组合。

## 结论与适用范围

采用一个应用插件管理体系、两类明确的执行档位：受限插件通过独立 Chromium 沙箱与宿主能力代理工作；现有同步 React、Slate、数据库计算和白板手势扩展保留在受信任档。管理、身份、版本与能力命名可以共用，执行方式和安全承诺不能混同。

C02 选择专用 `WebContentsView` 作为受限载体，使用专用 preload、独立非持久化 session 和宿主控制的资源协议。其可用性、网络封锁及独立终止能力必须由真实 Electron 测试证明；失败时停止推进该载体，不退回主界面执行，也不降低隔离标准。

第三方原生执行不开放。是否允许用户主动安装受信任的第三方深度扩展，以及首期支持哪些平台，是产品策略选择，见文末；这两个选择不阻塞 C02 的本地开发验证。

## 运行载体比较

| 选择                       | 优点                                      | 主要问题                                                        | C01 选择                                       |
| -------------------------- | ----------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------- |
| 主界面直接加载模块         | 原生 React、低延迟、复用方便              | DOM、全局桥和数据暴露；无限循环可卡主界面                       | 仅受信任深度扩展                               |
| 主界面 iframe/Worker       | 轻量、可分离部分执行                      | 需另证来源、浏览器能力、进程及消息隔离，Worker 本身不是权限沙箱 | 不作为首个安全载体                             |
| Node utilityProcess        | 后台任务、可终止、易用 npm                | Node 环境带文件与网络能力，进程隔离不等于权限隔离               | 只运行宿主可信代理                             |
| 独立 WebContentsView       | Chromium 沙箱、独立 session、可扩展为页面 | 内存成本、浏览器网络面、进程共享与原生视图布局需要验证          | C02 首选验证载体                               |
| 嵌入解释器或 OS 级受限进程 | 可进一步限制客体 API 或资源               | 新依赖、兼容性、平台部署及 UI 能力成本高                        | 当前载体无法满足硬门槛时重新评估，不自动加依赖 |

依据 Electron 43.1.1 的 [WebPreferences](https://github.com/electron/electron/blob/v43.1.1/docs/api/structures/web-preferences.md)，显式设置 sandbox/contextIsolation，关闭 Node、子 frame Node、Worker Node、webview 和实验能力，不依赖默认值。隔离端不启用开发服务器、远程调试或 `--no-sandbox`。

`WebContentsView` 可由 `BaseWindow` 承载；C02 的独立测试宿主使用隐藏 BaseWindow，避免加入业务 BrowserWindow 工厂与广播。生产后台是否需要可见窗口之外的承载，以及隐藏时调度策略，在实际测试中验证。关闭 BaseWindow 不自动释放其 WebContents，宿主必须显式关闭。[Electron 43.1.1 BaseWindow](https://github.com/electron/electron/blob/v43.1.1/docs/api/base-window.md)

## 组件职责和信任流向

| 组件                    | 所在侧           | 责任与不能做的事                                                        |
| ----------------------- | ---------------- | ----------------------------------------------------------------------- |
| Plugin Manager          | 主进程           | 发现、版本、启停、安装身份及故障状态；不执行插件业务 JS                 |
| Runtime Supervisor      | 主进程           | 创建容器、绑定会话、超时及终止、收回通信和资源                          |
| Capability Broker       | 主进程           | 对每次请求验证身份、能力、资源范围、代次和载荷，再调用服务              |
| Domain Adapter          | 宿主可信侧       | 执行领域操作、事务、只读/协作检查；不能返回数据库或 Editor 对象         |
| UI Contribution Adapter | 应用界面         | 接收已授权贡献，调用既有 Page/菜单/浮层机制；不加载受限插件代码         |
| 专用 preload            | 插件容器隔离世界 | 最小桥与消息限制，不暴露 ipcRenderer、事件对象、任意 channel 或真实凭证 |
| 插件 runtime            | 沙箱界面世界     | 加载已批准本地产物、执行插件逻辑，通过桥提交数据请求                    |

宿主可以在主进程调用者之间复用服务；耗时网络与计算不能同步堵塞主进程。跨域业务流程留在插件，原子写入由宿主执行预定义操作，而不是接受任意 SQL 或脚本回调。

## 身份与作用域

安装身份为宿主确定的发行主体加插件 ID；升级延续该身份，来源变化按重新安装/授权处理。公共贡献 ID 由宿主加命名空间，插件不能注册其他 owner 的 ID。

每个工作区激活实例拥有 runtimeId、generation、workspaceSessionId 和授权版本。workspaceSessionId 是宿主给已就绪数据库连接发放的不可由插件指定的句柄；相同库名关闭重开、同步替换连接都会失效。库名仅用于显示和内部定位，不能作为持久身份的最终方案；工作区稳定 ID 与现有改名/同步规则在 P3 补充。

| 层级          | 生存期              | 拥有资源                                 |
| ------------- | ------------------- | ---------------------------------------- |
| 安装          | 安装至卸载          | 包、版本、授权记录、应用级偏好           |
| 工作区实例    | 连接就绪至失效/停用 | 同步任务、工作区服务句柄、工作区数据访问 |
| 窗口/页面实例 | 挂载至销毁          | UI 状态、页面引用、事件订阅              |
| 文档/领域实例 | 打开至关闭          | 只读状态、选区快照、领域操作目标         |
| 单个请求      | 接受至完成/取消     | deadline、请求 ID、事务提交资格          |

一个插件在同一工作区的后台实例由主进程协调，多窗口附着观察；窗口关闭不随意取消其他窗口使用的任务。跨工作区不共享可变业务状态；宿主基础服务可共享实现但不共享授权句柄。

## 通信与撤销

首版使用专用 preload 与原生 Electron 异步 IPC，外侧仅有固定的插件协议通道，不开放现有业务 channel。主进程根据注册过的 WebContents、精确主 frame、当前 URL 与 session 找到实例，忽略消息自报身份；子 frame 和未知 sender 直接拒绝。导航或 frame 重建先撤销实例，再决定是否重新握手。

消息为版本、requestId、operation、payload 的受限信封。请求/事件和返回值都校验 schema、深度与字节上限；拒绝重复 ID、超额并发和超时请求。权限在请求接受与异步写入提交前均复核，流和订阅同样可撤销。取消不撤销已经成功提交的事务，结果必须明确区分已提交、已取消和执行失败。

preload 在发往主进程前限制请求体与发送频率，Broker 再次校验；不能等巨大载荷进入主进程、完成结构化克隆后才限流。日志和事件也有长度、频率和订阅范围限制，插件不得借错误日志绕过消息配额。

首版不需要 MessagePort。后续若流式数据证明有必要，可换用宿主建立并绑定身份的端口，仍沿用同一授权/撤销语义；不能将可转交的端口当作永久授权。[Electron 消息端口](https://github.com/electron/electron/blob/v43.1.1/docs/tutorial/message-ports.md)

停用顺序：先置 stopping 并拒绝新工作，撤销提交资格，取消在途请求和订阅，通过宿主处理必要的未保存内容，限时调用 deactivate，最终清理贡献并关闭容器。强制撤权与正常停用区分：撤权不能被插件的未保存提示无限阻止；宿主保留可恢复草稿的能力需要单独授权和设计。

## 资源和网络策略

自定义 `tau-plugin` 协议只提供 manifest 文件清单中的安装包资源；协议注册在插件自己的 session。URL 使用宿主产生的运行实例标识，资源根不由插件传入。规范化、真实路径与 symlink 检查后再读取；拒绝跨包路径、目录遍历、查询串绕过及主应用 file/ltoh 资源。scheme 不开启 bypassCSP 或 ServiceWorker 权限。[Electron 协议作用域](https://github.com/electron/electron/blob/v43.1.1/docs/api/protocol.md)

session 按安装身份与工作区运行上下文隔离，使用非 persist 分区。重载前关闭旧容器、清理浏览器存储与缓存，再创建新代次；浏览器存储不是插件正式持久化渠道。不为每次重载无限分配新的 session，C02 验证反复启停后的资源回收。

默认只准加载自身本地资源，外部 HTTP/WS、file/ltoh、嵌套页面、导航、新窗口、下载和设备权限全部拒绝。将来授权联网时仍通过 Broker 的网络服务；渲染器不因获得 network 权限而直接解禁网络。Credential 服务仅向批准的目标注入密钥，不把原始密钥返给普通插件。

采用宿主生成的 CSP、session 出站拦截和权限处理器组合，所有策略由一个安全容器模块持有，避免后注册的 webRequest listener 覆盖先前策略。CSP 限定脚本与样式来自自身清单，关闭 connect、frame、worker、object、表单提交及未经批准的动态代码。动态 HTML、资源和 CSS 不能绕过清单策略。[WebRequest listener 规则](https://www.electronjs.org/docs/latest/api/web-request)

**尚需 C02 实证的硬门槛**：WebRTC/STUN/TURN、预连接、DNS 预取、WebTransport 等不能只依靠 fetch 拦截来判断。`disable_non_proxied_udp` 是 IP/UDP 策略，不是关闭全部 WebRTC 网络。对所选版本使用本地探针验证这些旁路，任何未被封住的通道都阻止受限载体通过验收；重新评估解释器或其他隔离载体，不能用删除 window 属性当安全修复。[Electron WebRTC 策略](https://github.com/electron/electron/blob/v43.1.1/docs/api/web-contents.md)

## 故障和可用性边界

监督器在插件容器外设置启动/请求/关闭期限、排队限额和错误归因；插件自己的计时器无法证明它没有卡死。C02 先采用单插件容器，检查进程 ID 不与宿主或其他活动插件共享，再授予能力；强制终止前重新检查。Electron 明确提醒 `forcefullyCrashRenderer()` 可能影响共享渲染进程，因此不能盲目调用。[Electron 渲染进程终止](https://github.com/electron/electron/blob/v43.1.1/docs/api/web-contents.md)

进程 ID 检查是运行门槛，不是对 Chromium 所有未来行为的形式证明；共享风险无法排除时拒绝启动该档位。进程、session 与来源是不同概念，不混用。

本阶段不承诺严格的操作系统内存/CPU 硬配额。采用请求限额、超时、有限数据与可终止执行控制常见故障；极端内存耗尽仍可能影响整个系统。C02 的压力测试必须有外部监督且使用有界载荷，不执行无限内存分配。P7 对外开放前审查这一残余风险和平台资源策略。

## 首个产物与 API 形态

首版受限插件入口采用浏览器 ESM：本地 `main.js` 导出 `activate(context)` 与可选 `deactivate()`，普通依赖打包，禁止 Node/Electron 导入、远程 import、顶层业务副作用和任意 eval。没有运行时 SDK import 的必要：开发期类型导入擦除，宿主传入有限上下文。preload 单独构建为沙箱支持的单文件产物，不能与插件入口混用。

manifest 最少包含固定格式版本、插件 ID、插件版本、支持的 host API 主版本、相对入口、资源清单和必需/可选能力；安装身份、实际执行档位、工作区和权限结果由宿主确定。首版只支持明确的 API 主版本兼容，不先实现复杂依赖求解。

隔离 UI 将来可自行打包 React；可信同界面扩展才要求宿主 React 单例。两种产物不能无标记混装，不能把所有插件都强制 external React。未知 manifest 版本和运行档位明确拒绝。
