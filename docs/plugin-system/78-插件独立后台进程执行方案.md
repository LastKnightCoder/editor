# 插件独立后台进程执行方案

日期：2026-10-20。状态：M1–M5 已完成代码与本地回归，M6 的独立作者 SDK、构建与真实 Electron 验证已完成，跨平台安装包验收待完成；尚未正式发布。用户已确认本期支持显式声明的独立后台、按需启动、应用启动激活与常驻；清理失效的旧 sync 特判，不把历史实现当作新架构约束。实施证据与剩余事项见阶段表及第十五节。

目标：同一个插件的界面继续使用渲染端 SDK，系统能力在独立后台进程执行。主进程只管理进程、路由与宿主服务，不执行插件代码；后台能力必须静态声明，进入重点审核，并经用户授权后运行。开机启动统一由 Tau 承载。

| 执行载体   | Electron utilityProcess，每个后台实例独立进程         |
| 启动方式   | 按需、应用就绪、工作区就绪                            |

| 前后台通信 | 请求响应、事件、取消、状态；限定本插件                |
| 系统能力   | Node 内置能力、可打包 JS 依赖、经宿主管理的外部工具   |

本期不包含跨平台 OS 沙箱、管理员提权、退出 Tau 后继续运行的系统服务、任意 npm 安装脚本、任意插件互调。原生模块和随包可执行文件须先完成具体平台的构建与签名验证，未验证的类型在包校验时明确拒绝，不做“先接受再运行失败”。普通 Node JS 后台和调用本机已有工具可以先形成完整闭环。

独立进程隔离事件循环、地址空间和普通进程崩溃，不保证恶意代码无法操作宿主文件或耗尽机器资源。完整 Node 环境中的系统用途声明是审核依据；不能把它宣传为强制系统权限白名单。当前渲染插件共享上下文，SDK 身份绑定也不等于插件间安全沙箱。

## 三 运行分层

### 主进程管理器

新增 PluginBackendManager，负责安装身份解析、授权检查、实例去重、启动停止、连接代次、任务租约、更新互斥及诊断。作为 BACKGROUND 模块注册，初始化仅建立服务；插件激活遵循清单及授权，不随模块初始化无条件启动。

主进程只启动宿主随应用发布的固定 bootstrap。bootstrap 在子进程中完成握手、验证入口后加载 backend 产物。主进程不得 import、require、eval 插件代码，也不通过执行 main.js 发现后台能力。

### 插件后台

后台运行于 utilityProcess，拥有独立 Node 运行环境。SDK 后台入口不依赖 React、DOM 或宿主内部模块。允许调用公开宿主服务，但不传数据库连接、窗口对象、Electron IPC 对象或内部 service 实例。

实例标识由宿主生成，包含安装身份、插件 ID、版本摘要、scope、工作区身份和 generation。相同实例的并发启动共享一个 Promise；新版本、新工作区代次和重启产生新 generation。

### 渲染端连接

现有 PluginHost 注入绑定当前插件的 ctx.backend。界面卸载只释放自身订阅，不自行结束常驻后台。后台和界面可各自先启动；界面注册失败不导致后台自动获得额外权限。

首期小消息经主进程异步路由，使用有界队列。大数据采用宿主签发的临时文件句柄或带流控的 MessagePort，不把大段内容无界转发。所有通道撤销、窗口失效与更新切换都由管理器处理。

## 四 清单与包协议

包含后台的新包使用 formatVersion 2；仅渲染的现有格式 1 保持可用。版本 2 的全新执行字段严格校验，不沿用业务描述字段的“忽略未知值”策略。旧客户端看到格式 2 必须拒绝整个包，不能只运行前端部分。

建议 backend 结构如下，示例是清单片段：

```json
{
  "backend": {
    "entry": "backend.js",
    "runtime": "node",
    "apiVersion": 1,
    "scope": "application",
    "activation": "app-ready",
    "lifetime": "persistent",
    "reason": "连接本机设备并向插件页面提供设备状态",
    "systemAccess": ["network", "filesystem"]
  }
}
```

| 字段         | 约束                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------ |
| entry        | 包内相对路径，首期为独立 CJS JS bundle；不得与 main 共用文件                               |
| runtime      | 首期仅 node，未知运行时拒绝                                                                |
| apiVersion   | 后台 RPC 与 SDK 协议版本，不复用插件市场版本                                               |
| scope        | application 或 workspace                                                                   |
| activation   | on-demand、app-ready、workspace-ready                                                      |
| lifetime     | idle 或 persistent                                                                         |
| reason       | 必填，展示系统能力的实际用途                                                               |
| systemAccess | 文件、网络、外部程序等固定分类，用于展示和审核，不承诺 OS 拦截                             |
| tools        | 可选的外部工具清单，最多 32 项；每项含 id、command、可选固定 args，须同时声明 process 用途 |

有效组合限定为 application × on-demand/app-ready、workspace × on-demand/workspace-ready；persistent 只常驻到所属作用域结束。应用级后台不自动获得活动工作区，也不能把用户切库当成自身可变的隐式数据库上下文。

安装器将 main、backend、样式和声明资源作为同一个不可变版本保存。包摘要必须覆盖清单语义与全部可执行产物；逐文件摘要使用原始字节。启动解析 realpath，拒绝越界、链接逃逸和未声明依赖，插件产物不得从宿主 node_modules 意外解析依赖。首期 JS 第三方依赖打包进 backend bundle，仅显式外置 Node 内置模块与后台 SDK。

目录扫描可以读取声明文件核验摘要，但不执行它们。没有 backend 就不探测约定文件。没有声明的额外可执行文件不成为入口，市场包按文件白名单拒绝。开发目录运行前生成固定快照，热重载只启动完成校验的新快照。

移除 sync 特判不等于重新支持 sync.js，也不承诺旧包可用。包若包含协议不接受的文件，走通用包校验报错，不再保留同步专属兼容分支。

## 五 作者接口与通信协议

前端提供 ctx.backend.call、subscribe、getState；后台通过 @tau/plugins/backend 定义 create、activate、deactivate，并注册 RPC 方法与事件。保持现有实例化和 Disposable 风格，模块顶层不得自动启动任务。

```ts
// 渲染端调用；身份由宿主绑定。
const devices = await ctx.backend.call("devices.list", {}, { signal });

// 后台激活时登记；入参与返回值都有运行时 Schema。
ctx.rpc.register("devices.list", schemas, async (_input, request) => {
  return enumerateDevices(request.signal);
});
```

协议实现应包含：

1. requestId、method、payload、generation、deadline；身份和工作区由连接赋值，不能信任 payload 的自报字段。
2. 双向运行时校验，拒绝未知方法、原型危险字段、不合法二进制引用和超限消息。
3. 超时、取消、错误码和稳定错误数据；不直接向界面暴露内部路径或完整敏感堆栈。
4. 每实例限流、并发上限、队列上限；事件按订阅有界发送，低优先级进度可合并。
5. 重启或撤销时拒绝所有旧请求，丢弃旧代次回包，不自动重放有副作用的调用。
6. 写操作由业务层传幂等 requestId；超时后结果可能未知，不能当成“未执行”盲目重试。
7. 后台需要业务数据时，走同一主进程领域服务与权限检查；应用级后台必须持有显式工作区会话，不能使用全局“当前库”。

建议初始默认值：启动握手 10 秒，普通 RPC 30 秒，小消息 1 MiB，每实例 16 个在途请求、128 个排队请求，空闲回收 60 秒。长任务显式使用任务租约和进度协议。以上集中配置并以真实场景校准，不承诺它们是系统资源硬限制。

## 六 授权与审核身份

后台执行授权和业务数据授权属于同一管理界面，但表达不同风险：前者允许运行本机 Node 代码，后者约束正规宿主 API 可访问哪些数据。声明后台不等于自动获准执行。

授权记录在宿主数据目录，与插件文件和插件私有 KV 分离。后台授权绑定发布者、安装身份、版本及整包摘要，并带 scope。临时授权由主进程按运行会话持有；停用、重载、工作区关闭或应用重启后失效，不能依赖某个页面内存。

首期采用明确的版本授权：每个后台新版本在前台确认后切换；旧版保持运行至切换，不能在后台自动扩大执行范围。后续若要允许“同权限已审核更新”自动继承，需另行定义发布者信任策略，本期不暗中继承。

自动激活仅消费已保存的持续授权。后台、系统登录启动及无窗口状态不弹询问框；需要新授权时进入 blocked 状态，托盘和插件详情页显示待处理。撤销先失效连接与后续业务提交，再终止进程；不能回滚已经发生的系统副作用。

开发包明确标识未经市场审核，授权绑定开发快照。市场审批是平台签发的状态，不接受包内自带 approved 字段。客户端核验发布渠道提供的审批信息与包摘要；离线可使用已验证且未过期的本地凭据，新安装不能靠自报信息绕过。撤回信息在联网时刷新，离线无法保证实时收到撤回。

## 七 启动 常驻与系统登录

### 激活与工作区

- app-ready：应用单例锁、设置、安装恢复、授权和管理器就绪后异步启动，不阻塞主窗口首屏。
- workspace-ready：数据库会话真正就绪后启动；库名存在不代表已经就绪。工作区切换先使旧代次失效，再启动新实例。
- on-demand：首次有效调用启动；无声明或未授权直接拒绝，不通过尝试执行探测能力。
- idle：无调用、订阅租约或运行任务后计时回收；事件订阅是否持有租约由 SDK 明确表达。
- persistent：不随页面关闭回收，随所属应用或工作区生命周期退出。

当前桌面以活动数据库切换为基础，不在本期另造多库后台调度器。登录后后台启动只自动激活 application 作用域；workspace 后台等待工作区按正常路径就绪，不为了激活插件遍历打开所有资料库。

### 托盘与关闭

用户可启用“关闭窗口后保持后台运行”。有需要保活的已授权任务时，关闭主窗口进入后台；重新打开只连接现有实例。保活不依赖隐藏主窗口或偷偷运行普通渲染插件。无后台任务且无保活意图时沿用正常退出策略。

显式点击退出永远结束整个应用。tray 必须提供打开主窗口、后台状态、暂停后台与退出；不支持托盘的环境必须有可发现的恢复和退出入口，不能留下不可见常驻程序。暂停后台在本次应用会话内禁止自动拉起，重启与恢复操作遵循清晰提示。

### 系统登录启动

应用级设置维护“登录系统后启动 Tau”和“登录后在后台运行”。默认不开启，插件安装和启用不得自行更改。启动参数在文件打开参数解析之前识别；第二次启动复用既有单例，用户主动打开文件时正常呈现窗口。

macOS、Windows 使用 Electron 对应平台的登录项能力，回读实际系统状态而不是把设置保存成功视为生效。Linux 若属于发布支持范围，使用用户级桌面自动启动集成；不安装 root daemon。系统策略禁止或用户在系统设置停用时，界面反映真实状态。

macOS 登录启动需要在正式签名、公证的安装包上验收，开发模式结果不能替代发布证据。具体配置按仓库锁定 Electron 版本文档实施，不依赖已删除或平台不支持的隐藏启动字段。

### 统一退出顺序

接入 app-quit-controller，沿用总退出预算，不给每个插件串行叠加等待时间：

1. 标记应用正在退出并设置全程期限；先登记窗口回执，再广播退出通知。
2. 在窗口收尾期限内保留已授权后台 RPC，包括收尾所需的按需启动，使退出同步能够完成；授权与版本检查不绕过。
3. 窗口回执完成或超时后标记 draining，拒绝新的后台调用，停止自动激活和重启。
4. 调用后台 deactivate，结束受管理的外部工具和业务会话；超时强制终止，再执行协作文档最终落盘与窗口、MCP 清理。
5. 在 finally 和全程超时路径强制回收后台及内容进程，完成应用退出。

当前代码最终使用 app.exit，因此不能只靠 will-quit 钩子。异常退出、主进程崩溃和系统注销另做孤儿进程测试；父连接断开即退出只能作为协作机制，受管理外部程序还需平台级进程组或 Job Object 等生命周期约束。

## 八 系统工具与故障监督

后台使用显式最小环境变量集合和独立工作目录；不默认继承宿主密钥、NODE_OPTIONS、调试参数或会话凭据。配置按插件归属传入，敏感值不进入日志和进程命令行。

外部工具经 ctx.process 启动，参数数组与 shell:false，登记工具身份、用途、参数约束、工作目录、输出上限和退出行为。默认禁止 detached。Windows、macOS、Linux 的进程树终止由平台适配器实现并验证，不能把 utilityProcess.kill 等同于整个子进程树已回收。

插件通过 SDK 提供的 MCP stdio 复用这套工具声明及启动授权。保留用户手动配置的 MCP 入口；`plugin:` 连接必须携带插件来源并绑定窗口，不能省略来源走手动连接分支。普通渲染插件仍与宿主共享执行环境，本期不能证明恶意代码无法跳过 SDK 直接访问原有 IPC；令牌和来源标记不构成安全沙箱。已有无声明的插件 stdio 在新规则生效后明确提示更新和授权，不静默继续执行。

状态包含 stopped、starting、running、draining、failed、blocked；同实例串行状态转换。崩溃时立即拒绝在途请求，常驻实例延迟 5 秒重试，5 分钟内失败 3 次后停止自动重启，手动恢复清除熔断。已停用、撤权、更新中和应用退出时不得重启。

心跳与期限由宿主外部监督；无限循环不能依赖插件主动汇报。管理页采集 CPU、内存、启动时长、RPC 超时和失败次数。原始 stdout/stderr 不进入宿主日志、不落日志文件，错误保留有界摘要；诊断计数只保留本次应用会话。资源指标用于诊断和手动停止，本期不设置 CPU/内存硬限额。

提供一次“暂停第三方后台”的恢复入口和启动参数，排查崩溃循环时无需先运行故障插件。不自动重放非幂等系统操作。

## 九 内容插件遗留迁移

### 必须保留的功能

内容插件的 codec 负责自定义节点与 Markdown 的转换；HTML serializer 等还参与发布。查询、全文回退搜索、分段、向量索引和博客生成依赖这些规则。不能删除注册后用基础 Markdown 转换悄悄兜底，否则自定义内容可能丢失。

### 推荐承载方式

将现有内容执行迁到宿主管理的独立内容渲染进程，保持浏览器环境。使用不展示界面的内容窗口承载 DOM 依赖，禁用 Node 集成、启用 sandbox 和 contextIsolation，只提供内容任务所需的最小桥，不使用普通业务 preload。它不运行插件 create/activate，不承担同步或 CLI 功能。

选择这个载体是因为 main.js 当前混合 React、编辑器和内容定义，直接放进 Node 后台会让所有内容插件获得本机代码执行能力，违反“必须声明”的目标；只依赖主窗口又无法覆盖主窗口销毁后的内容任务。内容载体可以使用现有 evaluatePluginPackage，但加载的是经过静态校验、当前启用的内容插件快照。

首期可由一个内容渲染进程承载同一快照，崩溃时整批未完成内容任务失败并有限重试；它与“每插件一个 Node 后台”是不同职责。不把这称为每插件安全隔离。以 HTML、ABC、TikZ、Typst 和白板等现有产物验证模块顶层、字体与 DOM 依赖；如某个依赖无法在此环境工作，先修该依赖边界，不回退到主进程执行。

### 迁移顺序

1. 建立 ContentExecutionClient：异步批量转换、快照版本、错误、取消、队列与缓存；输入输出可序列化，不传转换函数。
2. 为现有内容样本建立结果基线，覆盖节点到 Markdown、反向解析、HTML、分段、样式来源及插件版本选择。
3. 改造同步数据库查询消费者：查库同步返回不可变数据快照，在上层异步编排中请求转换；禁止主进程 Atomics.wait 或同步等待 IPC。
4. 索引 worker 接收已转换文本/分段，或经异步任务协议请求内容服务；保留批处理、修订校验和队列重试，避免每个节点一个 IPC。
5. 发布生成器消费同一版本快照的转换结果；固定插件版本、内容修订和发布任务身份。保持博客运行时产物、未知节点行为和输出语义。
6. 内容服务断开、插件缺失或版本不一致时明确失败或重试；不提交错误索引，不覆盖正确发布产物。
7. 消费者迁移并通过结果对照后，删除 acceptHeadlessPlugin、getHeadlessPluginArtifacts，以及两个 Node worker 的插件求值路径。

缓存键至少包含内容修订、输出类型和插件快照摘要；插件变更使旧缓存失效。发布保留其固定快照至任务结束，更新时按占用机制等待或取消，不能中途替换转换规则。

主进程/worker 的同步函数签名调整可能影响较多消费者，这一阶段必须逐个追踪调用方，不能批量替换函数名。范围包括 tables/card、article、project、diary、calendar-event、fts 及内容/资料/学习索引和发布，以上不是可替代全仓引用核查的封闭清单。

## 十 门户 审核与更新

复用现有 submissions、reviews、releases 流程。在包解析时提取后台摘要、启动策略、系统用途和与上一版本的差异；后端判定是否属于重点审核，不能仅依赖前端标签。

审核者必须能看到：后台源码与 bundle 的对应、源提交、依赖锁定、系统访问用途、外部工具、远端代码加载、原生文件、常驻行为、清理和更新测试。新增 backend、启动策略改变、作用域改变及系统用途扩张显著标记；每个后台版本重新审核。重点审核是原流程中的必需检查项，不因旧版通过而自动批准新版。

现有 CI 对审核者本人提交有自动批准路径；含后台或插件外部程序声明的包必须进入显式重点审核，不能因提交者具有审核身份而自动跳过。将该条件同时接入网页提交和 CI 提交的服务端判定，并增加绕过回归测试。

审批绑定不可变包摘要；审批后替换任何产物都使审批失效。复用现有 HTTPS 平台发布记录，以 Release ID、systemReviewed、插件身份、版本和 ZIP SHA-256 绑定已审核产物，审核记录保留审核者与源提交。客户端静态读包再次校验逐文件摘要，来源参与本机授权摘要。本期不引入离线签名或新密钥设施，不把 HTTPS 元数据称为数字签名。开发包走显式本地信任，不伪造市场凭据。

更新沿用现有暂存、校验、占用保护与原子切换事务：

1. 下载新包并校验，旧版继续服务。
2. 中心包必须已完成该版本审核；新版本不能继承旧版本的本机执行授权。
3. 有在途任务、订阅或插件 MCP 租约时拒绝切换，提示结束工作或显式撤销后台授权；进入更新临界区后阻止新启动。
4. 结束空闲旧后台和旧连接，原子切换整包指针；新版本等待用户在详情页授予本机授权，再按声明启动。此实现复用现有授权页，不另建暂存版本授权界面。
5. 新版启动失败标记失败并提供恢复；仅在旧版仍可用、已授权且不存在状态格式不兼容时允许退回。

不承诺更新回滚能撤销新版本已写入的插件数据或外部系统修改。开发者应保持私有状态向后可读或提供明确升级策略；本期不执行任意安装/迁移脚本。恢复磁盘事务也不得执行尚未授权的插件。

插件或版本撤回后禁止新启动，并终止对应运行实例，保留用户数据及诊断。客户端启动/调用时检查发布状态，查询缓存 60 秒，运行后台和外部 MCP 每分钟巡检；已知下架状态落盘，离线重启仍禁止，在线核对恢复可见的同一版本后才解除。离线不能获知尚未收到的远端撤回，不能承诺即时远程撤权。门户、客户端和 SDK 的发布顺序必须保证客户端只看到自己支持的包格式；新后台包使用明确的最低客户端版本。

- M3：已授权实例自动激活、暂停恢复、工作区切换、关窗保活、登录项与本机偏好、受控退出接线。自动激活合并为可等待任务，修复暂停后扫描仍创建目录的竞态；集成用例验证后台窗口/旧摘要无法授权、撤销后不复活。系统登录项测试使用模拟系统接口，没有修改测试机器的真实登录设置。
