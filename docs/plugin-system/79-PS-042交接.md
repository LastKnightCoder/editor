## 3. 必须遵守的工作方式（踩过的坑）

1. **工作区里有另一个会话的未提交改动**（插件独立后台进程，专题 78；以及反馈窗口），与本工作共用 `packages/plugins/src/{host,contract,index,package}.ts`、`apps/desktop/src/app/plugins/runtime.ts`、`PluginDetailView.tsx`、`module-config.ts`、`03 架构实现指南`、`API.md` 等文件。**只提交自己的 hunk**：做法是以 `git show HEAD:<file>` 为底拼出自己的改动，用 `git hash-object -w --stdin` + `git update-index --cacheinfo` 写入索引；绝不 `git add` 整个混合文件，绝不 stash/checkout 别人的改动。提交后用 `git diff` 确认对方的 hunk 仍在工作区。
2. **提交前在隔离树验证**：`git write-tree` → `git commit-tree` → `git worktree add --detach /tmp/xxx`，链接 `node_modules`（根目录软链，`packages/*`、`apps/desktop` 的 node_modules 用 `cp -a` 复制以保留 pnpm 相对链接），跑 SDK 与桌面 `tsc` 与相关 vitest，再真正提交。主工作区的 tsc 报错可能来自对方（如 `plugin-backend.worker.ts`、`vibe-learning-index-queue.ts`），不要去改。
3. **打包 SDK 只从 HEAD 的临时工作树打**：`node scripts/plugins/package-sdk.mjs /tmp/tau-sdk-pack`（工作区直接打会混入对方的后台接口）；node_modules 必须复制而非软链，否则包内依赖会出现 `@tau/shared` 等工作区名。插件更新 `vendor/` 中的 tgz 后需删掉 `pnpm-lock.yaml` 重新安装（校验值变化会被 pnpm 拒绝）。
4. **夹具更新**：`node scripts/plugins/pin-test-fixture.mjs <zip> <插件提交 SHA> https://github.com/LastKnightCoder/tau-plugin-weekly-review`，然后 `git rm` 旧版本目录（约定每个插件只保留一个版本）。夹具目录不参与格式化。
5. `packages/plugins/src/package.ts` 引入的文件会被 Node 以仅剥离类型模式直接加载：**不要用 TS 参数属性、enum、namespace**。
6. 测试里 mock 的 `@/electron` 不会追加 `{ toolDatabaseName }`；mock 的数据要带上 `revision`，否则 `copyJson` 拒绝 `undefined`。jsdom 没有 `navigator.userActivation`，代码里缺失时放行。
7. `app/plugins/*` 适配层不要静态引入导航与业务模块（会拖重插件宿主启动，`plugin-provider.test.tsx` 会失败），按需 `import()`。
8. 每次改 schema：`pnpm db:schema:build && pnpm db:schema:check`，同步 parity 常量与 `database-schema.md`。改壳层 / 数据协议同步 03 指南；每次提交同步 77 实施记录、06 日志、README 状态行。
9. Agent 不做视觉验证；文案按用户视角，不写内部实现。所有回答与文档用中文。

## 4. 已知事实与限制（设计时别再踩）

- 权限只约束 SDK 接口，插件与宿主同上下文、可直接访问 `window.electron`；界面与文档必须如实说明。
- 插件经主进程写入的正文**不进入编辑器撤销**（`Y.UndoManager` 只跟踪本地 origin）。
- 正文编辑的 replaceText / replaceAll 经 Markdown 重建整篇；append / prepend 只转换新内容。
- 实体 revision = 表的 `update_time`；正文 revision = 会话版本或 `u:修改时间`。
- 事件不携带数据；触发器在事务内执行，回滚写入也可能产生事件。
- `pick` / `open` 不需要数据权限，需要用户手势；`pick` 尚无真实插件消费者。
- 未做：项目文档新建 / 移动 / 删除，批量删除二次确认，`open` 的定位参数，事件 `fields`。

## 5. 下一步 M3：组件层与动作层（方案 77 第 6、7、11 节）

目标：插件作者一行 JSX 得到与卡片详情相同的编辑器（协作、内置与已安装扩展、文档待办全部生效）。

1. **调研先行**：读 `apps/desktop/src/components/ContentEditor/index.tsx`（15 处挂载，props 含 `contentId`、`source`、`editingContext`）、`hooks/useContentDocument.ts`、`useCollaborationKit`、`services/editorKit.ts` 的 `createDesktopKit`；参照 `packages/plugins/src/source-editor.ts` + `source-editor-host.tsx` 的「SDK 只导出占位、宿主注入实现」模式，以及 `PLUGIN_SHARED_MODULES` 与 `app/plugins/shared-modules.ts`。
2. **建议首批接口**（先只做有消费者的）：`<ContentEditor contentRef readonly? />`、`<ContentPreview contentRef maxLines? />`。宿主由 ContentRef 解码 contentId + createTime，`entity:locate` 反查实体补全 `source` / `editingContext`；挂载时校验权限：可编辑需所属实体 write，只读需 read，未授权渲染「请求访问」占位并调用 `permissions.request`。
3. **动作层** `ctx.app.run("content.export" | "content.present" | "content.share", { ref })`：复用宿主已有弹窗与组件（导出、演示 `PresentationMode`、协作 `ContentCollaborationControl`），只开放有消费者的动作。
4. **隔离档位**：组件层是同步 React，只能在同上下文执行；在 07 安全模型与 77 中标注。
5. **消费者**：可让「每周回顾」点开一张卡片时在侧栏内嵌 `<ContentEditor>`，或新建最小 Excalidraw 画布插件（同时成为 `pick` 的真实消费者）——开始前先问用户选哪个（用户记忆：新入口先确认做不做）。

## 6. 下一步 M4：插件实体与搜索 / @ / 反链（方案 77 第 5.4、14 节，裁决见 14.6）

1. **Schema**：`plugin_entities(id, plugin_id, kind, key, title, content_id, content_created_at, meta JSON, create_time, update_time)`，持有正文 ref_count；卸载插件进入 7 天宽限（复用 `content_pending_releases` / `releaseDeferred`）。同步 parity、`database-schema.md`。
2. **SDK**：`ctx.entities.registerKind({ kind, label, icon, open: { page, params }, mentionable? })`（`mentionable` 默认关闭）与 `ctx.entities.create/get/query/update/delete`；自有实体不需要业务权限。
3. **索引**：新增单一类型 `plugin-entity`，需同时改 `IndexType` / `CONTENT_TYPES`（`types/search.ts`、`features/search/searchMeta.ts`）、`search-details.ts`、全文队列（`main-content-fts-index-queue.ts` 的 `groups` 与增量 `entityTask`）、向量队列候选、`EntitySearchTable.locateAll`、`openEntity`。之后按 kind 交给注册表分发，不再为每个插件改宿主。
4. **点击**：宿主按声明式 `open` 推导 `navigator.push(PLUGIN_PAGE_KEY, …)` 并附 `at`；插件页把 `params.at` 交给 `<ContentEditor>`（依赖 M3）。插件停用时结果仍显示，点击打开宿主通用只读页。
5. **@ 与反链**：MentionPanel 收录 `mentionable` 的 kind；`ref-indexer` 识别 `plugin-entity` 并升 `REF_INDEX_VERSION`；插件读取反链 `ctx.data.refs.backlinks(ref)`。
6. **插件私有 KV 迁入主库** `plugin_kv`（裁决第 4 项）：一次性迁移 localStorage 后删除旧路径，不留兼容层（D-091）。
