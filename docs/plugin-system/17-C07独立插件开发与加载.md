# C07 独立插件开发、构建与桌面加载

基线 `4d60ba6e6`，2026-10-14。本单元打通仓库外作者项目到真实 Electron 的最小完整链路，包含原计划 C07-A/B 的 SDK 交付、实际管理入口、样式资源与双插件验证。微信读书后续工作保持暂停。

## 已实现与仍未实现

作者可在仓库外安装 `@tau/plugins` 和 `@tau/ui` 的开发压缩包，独立完成类型检查及构建；在桌面开发模式的「设置 → 插件」选择构建目录，查看默认停用的插件，启用后使用命令、页面与独立设置。宿主不再需要为每个外部开发插件修改源码导入列表。

C07 只保存本窗口当前工作区的登记快照。切库、关闭窗口或重启应用后需要重新选择目录；启用意图持久化、包记录恢复与移除开发包在 C08，读取新构建并替换旧版本在 C09。停用再启用会重新执行已登记的同一份代码快照，不重新读磁盘，不是热重载。开发包仍只接明确选择的可信代码，生产安装版拒绝此入口，没有实现第三方受限载体或高信任授权产品。

## 复现作者流程

在本仓库根目录准备开发 SDK 和独立项目：

```sh
node scripts/plugins/package-sdk.mjs
TAU_SOURCE="$PWD"
TAU_AUTHOR="$(mktemp -d "${TMPDIR:-/tmp/}tau-plugin-author.XXXXXX")"
cp -R "$TAU_SOURCE/scripts/plugins/template/." "$TAU_AUTHOR/"
cd "$TAU_AUTHOR"
npm install --ignore-scripts --no-audit --no-fund "$TAU_SOURCE/output/plugin-sdk/tau-plugins-0.1.0.tgz" "$TAU_SOURCE/output/plugin-sdk/tau-ui-0.1.0.tgz"
npm run build
```

输出为 `dist/1.0.0-<唯一标识>/`。启动 Tau 桌面开发构建（仓库根 `pnpm --filter desktop dev`），进入「设置 → 插件 → 选择开发插件目录」，选择该版本目录，确认元信息后点击启用。选择目录不执行插件模块；目录必须是已经构建完成的版本目录，不是源码目录或 dist 父目录。

启用后可在命令面板执行「打开独立计数插件」；页面用公共 Button/Panel/Dialog，点击「增加并保存」写入插件私有存储。管理详情的「计数设置」读取同一值；停用后管理仍在、设置组件退出，重新启用恢复已提交值。首次值为真实存储缺省值 0，不填充业务假数据。

作者拿到模板与两个压缩包即可开发，不需要 Tau 仓库、Vite 别名、workspace 链接或内部 editor/markdown/themes 包。源码中的 `contract-check.ts` 验证根入口的编辑器类型增强，以及内部宿主入口不能被导入；它不进入插件运行产物。需要外部 npm 网络下载公开生态依赖，未声称离线安装。

## SDK 与共享模块

工作区原有包保持 private 和源码 exports，不影响内置消费者。`scripts/plugins/package-sdk.mjs` 用 TypeScript 生成声明，沿实际声明引用收集闭包，将私有 workspace 引用改为包内相对路径，生成独立可安装的开发包：当前 plugins 138 个、ui 64 个声明文件。内部类型可以参与公开签名，内部包路径不成为作者依赖；声明目录不是内部运行时模块的导出承诺。

生成包只提供根入口，不导出 host/node 或内部编辑器路径。它们是开发契约包，运行 JS 明确提示需要宿主，不能当成普通独立网页 UI 库运行。构建必须 external 两个 Tau 入口；宿主提供真正实现。没有发布 npm，也没有承诺稳定 SDK 版本。

| 共享模块                                 | 当前约定                                                 |
| ---------------------------------------- | -------------------------------------------------------- |
| @tau/plugins、@tau/ui                    | 作者入口；生成包版本 0.1.0，宿主实现与声明随同一提交生成 |
| react、react-dom、react-dom/client       | 宿主单例，当前配套 19.2.0                                |
| react/jsx-runtime、react/jsx-dev-runtime | 与宿主 React 配套的 JSX runtime                          |
| 其他普通依赖                             | 打进插件入口，不运行安装脚本，不提供任意 Node require    |

UI 映射保留现有根导出的对象身份，主题/Portal 不建立第二套 Context；这是宿主适配器，不是业务发送通知的位置。桌面通知业务仍遵守 D-138，不由本轮增加插件通知服务或额外主进程能力。

模板使用 react-query 并在插件视图内创建自己的 QueryClientProvider，避免打包一份 query 库却依赖宿主另一份 Context。UI 基础样式由宿主提供；业务 CSS 自行预编译，SVG 示例通过 data URL 内联，不依赖宿主扫描外部 Tailwind 类或读取任意本地文件。当前没有外部资源 URL 服务；较大独立资源、分块与懒加载留给后续有需求的切片。

类型检查为 strict/noEmit，沿用仓库的 skipLibCheck。首次不跳过库声明时发现 Lucide 的 ReactSVG 和 Slate DOM 的 EditorWordOptions 与当前生态依赖组合不匹配；本轮没有升级这些依赖。声明生成器仍逐个解析/改写内部引用，仓库外源码检查覆盖实际 API、编辑器增强及私有入口拒绝，不将 skipLibCheck 宣称为所有第三方声明都通过严格校验。

## 产物合同与加载

构建使用 esbuild 的 browser/CJS 单入口。作者源码仍写标准 import/export，默认导出 definePlugin 定义；CJS 是构建产物格式，不要求作者写 require。格式能力参考 [esbuild 官方说明](https://esbuild.github.io/api/#format)。

真实 Electron 探针验证：同一 Blob ESM URL 在 revoke 后再次 import 仍返回缓存对象；裸 @tau/plugins 导入不能在现有页面直接解析。这不证明 ESM 不可用，但意味着还需模块映射及载体回收机制。当前选择模块工厂与有限 require 表，避免在首期引入第二套 ESM 模块注册表。只维护一种包格式；旧 C01 受限载体的 ESM 提案仍属未来隔离工作。

| manifest 字段             | 当前校验                                                                        |
| ------------------------- | ------------------------------------------------------------------------------- |
| formatVersion、apiVersion | 均只接受 1，不猜测未来版本兼容性                                                |
| id、name、version         | id 复用宿主标识校验，名称非空；版本为三段数字及可选预发布后缀                   |
| platform、format          | 仅 desktop、cjs                                                                 |
| main、styles              | main 必填 .js，styles 可选 .css；包内相对路径，拒绝绝对路径、空路径段和目录上跳 |
| integrity                 | 入口及声明样式的 SHA-256；读取时校验完整性，不作为作者身份或安全签名            |

模板从一个元信息来源生成入口定义与清单；宿主执行入口后复核 id/name/version/apiVersion 与登记值一致。读取时 realpath 校验拒绝指向目录外的符号链接，缺文件、空入口、摘要不一致拒绝登记。构建先写暂存目录，文件与摘要齐全后 rename 为新的唯一版本目录；失败不覆盖之前的产物，不把逐文件写入当作发布完成。

主进程 `plugin-development` 为 BACKGROUND，渲染端通过 withModule 等待。生产安装版或没有 VITE_DEV_SERVER_URL 的启动拒绝选择调用；开发模式由原生目录选择器授权读取指定目录。返回的是内存产物快照，无目录扫描守护进程、文件写入或删除。

加载器在用户启用时取得宿主共享模块，在渲染侧模块工厂中执行可信代码。require 仅解析共享表中的七个模块；未知模块报错。代码仍与应用共享 JS/DOM 环境，能造成任意同环境副作用，这不是沙箱，也不能以 require 表宣称完成权限控制。现有开发页面没有新增 CSP 放宽；未来受限载体不能直接复用这条路径。

CSS 随激活挂载、停用 signal 立即移除，并注册 dispose 兜底。加载/定义核对/激活失败保留管理记录，回收半注册贡献与样式；正常重新启用创建新实例。JS 错误带 tau-plugin 来源地址便于定位。后续 C08-A 已为异步挂起接入有界等待，超时或清理失败要求重启，见 [18](18-C08生命周期与管理收口.md)；同步失控及任意全局副作用仍无法确认回收，不声称强制卸载成功。

## 验证与恢复

完整复现：

```sh
node scripts/plugins/verify-external.mjs
```

该脚本创建临时仓库外项目，生成并安装压缩包，构建两个不同 ID 的真实插件，再使用实际 Electron、生产 preload、生产目录读取 IPC、加载器、管理组件、PageProvider/PageHost 和设置视图验证。原生目录对话框仅由测试替换为确定的选择结果，后续主进程文件读取、IPC 传输与渲染加载均为实际实现；不是自动化视觉走查，也不使用生产用户数据。临时项目与 profile 在退出时删除。

检查包括：选择后不执行代码、重复 ID 拒绝、React hooks/UI Portal、预编译 CSS 与内联 SVG、应用内导航、计数保存、停用/重启用恢复、双插件隔离和最终 CSS 回收。单测另覆盖清单/路径/缺文件/摘要、生产禁用、取消选择、未知 require、元信息不一致、入口/激活失败及加载期间取消。

类型、行为测试、完整桌面打包与结构检查的实际结果记入 [执行日志](06-执行日志与问题.md)。本机仅验证 macOS arm64 / Electron 43.1.1，Windows/Linux 尚未实证；视觉由用户验收。G1 的重启恢复、移除包和重载条目仍未完成。
