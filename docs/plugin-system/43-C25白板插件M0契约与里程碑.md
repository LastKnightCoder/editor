# C25 白板插件：M0 契约与里程碑

## 执行状态

- COMPLETE：Investigate/Triage/Understand the problem。核对公开 SDK、白板内部协议、静态图形消费者及跨端入口。
- COMPLETE：记录 M0 契约提案、数据格式、阶段验收和暂停条件；纠正调研文档中的旧数据兼容建议。
- 待用户验收：M0。本文件中的新增 API 均为设计，不代表已经发布或接线。
- 尚未开始：M1–M4。每阶段验收后等用户信号，再进入下一阶段。

## 硬约束

1. 火柴人未发布、无人使用。不保留 stickman 裸类型别名、顶层人物字段解析、兼容开关、转换脚本或迁移入口。不得自行清理用户本地开发数据。
2. 最终火柴人仅在独立插件中实现。内核只保留通用能力，默认分发不获得私有 API。
3. 作者只依赖公开 SDK 和普通 npm 包，禁止深引宿主源码、复制 CommonPlugin 或把白板整体打进 ZIP。
4. 不更换白板内核、历史系统或数据提交入口。共用一个 main.js，不新增 render.js 或宿主专用人物绘制器。
5. 暂不迁移其他插件仓库，不加入 submodule 或自动模板合并工具。

## 一、作者入口与装配

| 契约                                  | 设计                                                                                                                 | 归属/阶段              |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| PluginDefinition.whiteboardExtensions | 静态 WhiteboardExtension 数组，沿用现有白板协议并补齐静态元素定义；不新增另一套扩展引擎                              | SDK，M1                |
| manifest.whiteboard: true             | 声明白板静态贡献；与 editor 独立，可同时声明；缺声明或声明与实际贡献不一致时明确报错                                 | 包校验/作者构建器，M1  |
| @tau/plugins/whiteboard               | SDK 的白板作者子入口，提供经过收敛的定义函数、类型、公共组件与 hooks；构建时 external，由宿主提供共享实现            | SDK 打包/模块表，M1–M2 |
| WhiteboardExtension.elements          | 将元素定义提升为静态声明；create(api) 继续承载每个 Board 的交互贡献，不再返回第二份 elements                         | 白板协议，M1           |
| create(api)                           | 每个 Board 独立实例；返回 tools/inspectors/commands 等已有贡献；activate/dispose 继续沿用白板当前生命周期            | 复用，M1               |
| 启用快照                              | 复用现有内容插件的固定包快照、校验、CSS 与重启生效路径；内容贡献目录增加白板定义，不建立独立启用偏好或第二套包加载器 | 宿主，M1               |

新增子入口是同一个 npm SDK 的导出，不新增一套白板 npm 运行时依赖。子入口不得导出 Board 构造器、CommonPlugin、内部 transforms、任意 IPC 或内部 store；也不得直接重导出整个 @tau/whiteboard 根入口。

静态 elements 的必要性：白板列表的缩略图必须在没有创建 Board、没有调用 create/activate 时获取人物定义和纯投影。不能为每张卡片制造隐藏 Board，不能调用带假 API 的 create，也不能维护按元素类型硬编码的另一份登记表。

这是对白板内部协议的有意收敛：需要同步修改已有 workspace 中返回 elements 的定义和测试。白板内部现有通用 schemaVersion/migrate 机制不在本轮删改；火柴人不实现旧格式 migrate。若提升静态声明引发超出可控范围的消费者改造，必须暂停讨论，不能增加静态/动态双登记兼容层。

模块求值必须保持无浏览器副作用。混合声明编辑器与白板能力的插件仍须能在既有纯 codec 场景加载；不能用假实现或静默跳过导入解决跨环境问题。M1 用公开声明包和真实共享模块表验证这一边界。

## 二、最小公共能力表

以下字段为 M0 推荐命名；任何改变行为边界的调整都须讨论。已有 WhiteboardAPI 的提交、工具和事件协议继续使用，不再另造 ctx.whiteboard 的跨画布全局可变句柄。

| 能力         | 拟定入口                                         | 行为                                                                                                                                |
| ------------ | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 元素定义     | defineElement<TData>(definition)                 | 复用现有 schema、getBounds、isHit、move、create；声明在静态 elements 中                                                             |
| 数据提交     | api.submit / updateElement / captureSubmission   | 复用历史分组、只读与实例有效性检查，禁止直接改快照                                                                                  |
| 创建工具     | tools + element.create                           | 复用 click/drag 创建协议，不实现第二套鼠标监听                                                                                      |
| 属性栏       | inspectors                                       | 插件负责人物 UI，变更进入现有提交路径                                                                                               |
| 图层元信息   | element.presentation: { label, icon?, getName? } | getName 接收只读元素快照，用户手工 name 优先；未注册类型使用通用占位，不识别特定插件名称                                            |
| 框形元素交互 | element.interaction: { resize?, connect? }       | resize 描述角点/等比策略，connect 选用现有矩形连接规则；由内核统一呈现交互层和处理手势。火柴人声明角点等比缩放，不复制 CommonPlugin |
| 手绘能力     | element.sketch: true + useSketch(element)        | 静态声明是否跟随画风，已有页面/元素覆盖和 seed 规则不变；移除人物在类型白名单中的特殊项                                             |
| 纯缩略投影   | element.schematic(element, context)              | 返回现有 SchematicShape[]，context 只含主题等明确输入；无 Board/DOM/IPC、无修改、无随机副作用                                       |
| 公共 UI      | 白板作者子入口中的工具/属性原语与必要图形组件    | 基于现有 chrome/公共组件筛选，逐项用真实消费者验证，不批量暴露内部目录                                                              |
| 偏好         | 现有 PluginContext.storage                       | 人物最后选择属于插件；首次使用使用新默认值，不读取旧 localStorage 键                                                                |

M2 的交互适配须由现有内核逻辑提供。若现有缩放/连接实现无法被干净复用，需要先说明应如何抽取及影响范围，而不是把内部 Board 参数继续穿透给作者。不要为火柴人需要的矩形元素交互一次性设计全部多边形编辑 API。

### 画布与缩略图如何共享实现

火柴人插件保留一份姿态和笔画生成函数 buildStickStrokes。画布组件使用它生成完整人物，schematic 使用同一份笔画生成函数投影成既有简略线稿，二者均在插件同一个入口内。

当前缩略图本来就忽略文字、使用单色和细线，并不等同于完整画布截图。本轮保持这一既有表现，不强行引入新的矢量 DSL，也不把缩略图升级成全功能渲染器。图像导出则继续捕获实际画布，必须保留完整样式。通用投影失败时降级为明确占位；正式验收不能以占位冒充人物缩略图成功。

## 三、新插件数据格式

建议插件 ID / 扩展 ID 为 taunote.stickman，元素类型为 taunote.stickman.figure，工具 ID 为 taunote.stickman.create。采用完整插件前缀，避免占用 tau 内核命名空间；动态包装配时校验贡献归属和类型冲突。

```ts
type StickmanData = {
  pose: string;
  body: "classic" | "bean" | "glyph";
  tint: "mono" | "color";
  flip: boolean;
};

// 元素示例；x/y/width/height、sketch、name 属于白板通用字段。
const element = {
  id: "生成的唯一 ID",
  type: "taunote.stickman.figure",
  schemaVersion: 1,
  x: 0,
  y: 0,
  width: 132,
  height: 172,
  data: { pose: "有效姿态 ID", body: "classic", tint: "mono", flip: false },
};
```

创建器写入完整的 data，schema 负责校验。插件包版本与元素 schemaVersion 独立；此次新格式从 1 开始，没有从旧 stickman 格式升级的路径。

缺插件时保留新元素原始数据、尺寸和位置，并显示已有通用未知元素占位；不解析人物私有 data。相同插件重新安装后按声明恢复。缺包不能让保存操作删除未知节点，也不能静默导出成缺失的人物。这属于长期插件生命周期能力，与旧格式兼容无关。

| 博客               | 当前未接入 @tau/whiteboard/人物的完整画布展示                                                      | 不把本轮扩大为白板博客发布；若后续要求新增完整白板发布，单独评审运行环境和依赖携带机制 |

M3/M4 删除前须再次检索消费者，不能把本次清单当作永远不变的事实。发现新的真实消费者不能直接忽略。

## 五、里程碑验收与停止条件

| 阶段 | 交付                           | 必须通过                                                                                                                        |
| ---- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| M0   | 本契约与消费者清单             | 用户认可新增白板子入口、静态元素目录、无兼容策略及本轮跨端边界；不改生产代码                                                    |
| M1   | 最小外部白板元素完整接入       | 干净作者工程消费 SDK 声明包并构建；真实客户端 ZIP 加载、创建/属性/移动/历史/复制/保存重开；停用与缺包保留新数据；不增加常驻样本 |
| M2   | 通用交互、画风、元信息、缩略图 | 无内部 Board/CommonPlugin 深引，交互/历史/只读正确；列表不需要先打开画布，双 Board 无状态串扰                                   |
| M3   | 独立火柴人插件                 | 姿态/形体/配色/翻转/文字/手绘/缩放/箭头/图层/缩略图/导出等价；仅测试新格式；用户负责视觉验收                                    |
| M4   | 退役和分发交付                 | 生产源码中旧人物实现及专用分支清零，独立构建不依赖宿主源码；默认分发固定版本与摘要，SDK/模板/维护文档一致                       |

M1–M3 的内部临时分支允许保留原人物用于对照；测试样本使用不同类型，不建立数据双写或旧类型映射。M4 必须删除对照实现，未完成不能宣称抽离完成。

每阶段执行类型检查、相应行为测试和受影响构建，不把视觉问题冒充已验证。不调用真实付费服务，不自动发布 npm/GitHub 或改成 submodule；发布安排在阶段验收中明确。

以下情况暂停相关工作，向用户说明证据、方案、代价和推荐，再等决定：需要人物专用宿主分支；需要第二套内核或渲染实现；需要改变已有交互/导出表现；必须扩大跨端或格式转换范围；公共协议无法满足实际场景；分发构建必须依赖作者本机目录。不得以旁路、假 API、静默降级或兼容层绕过。
