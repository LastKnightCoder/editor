### M2 暂停点：缩放手势与历史

2026-10-17 用临时诊断夹具直接调用 CommonPlugin 的 onResizeStart → onResize → onResizeEnd：节点从 100×80 变为 200×160，board.undos.length 仍为 0，board.undo() 后仍为 200×160。报告保存在 `output/whiteboard-m2-audit/resize-history.json`。诊断夹具运行后已删除，避免把错误行为固化为长期通过的测试。

代码依据：CommonPlugin.onResize 使用 board.apply(..., false)；其 onResizeEnd 只处理父容器边界和吸附收尾，不提交自身缩放历史。useResize 自行注册 pointermove/up/cancel，清理函数只解除 pointerdown；ResizeCircle 另有节流回调。当前路径没有统一参与 InteractionManager 的失活/销毁仲裁。这里只复现了通用回调的历史问题；其他生命周期问题依据代码检查列为待验证，未宣称全部已复现。

该路径影响现有多个元素（ResizeCircle/useResize 的组件消费者约 11 个），FramePlugin 与 ColumnPlugin 还有独立的缩放覆盖。不能为了插件包装 CommonPlugin 后就宣称已满足撤销、只读和生命周期要求，也不能只给外部插件建立另一条长期缩放路径。

建议经用户确认后，将缩放纳入现有 InteractionManager：复用既有几何和吸附算法，将开始快照、预览、完成提交及取消统一管理；一次拖动一个撤销单元，父容器变化合并进同一单元；取消按开始快照恢复，删除/失活/只读切换时终止手势。现有手柄与插件生成的手柄进入同一条路径。先为既有矩形元素、Frame/Column 差异建立回归，再接插件 interaction 声明。范围限定在缩放，不重写移动、选择、箭头或整套白板内核。

### 画布与缩略图如何共享实现

火柴人插件保留一份姿态和笔画生成函数 buildStickStrokes。画布组件使用它生成完整人物，schematic 使用同一份笔画生成函数投影成既有简略线稿，二者均在插件同一个入口内。

当前缩略图本来就忽略文字、使用单色和细线，并不等同于完整画布截图。本轮保持这一既有表现，不强行引入新的矢量 DSL，也不把缩略图升级成全功能渲染器。图像导出则继续捕获实际画布，必须保留完整样式。通用投影失败时降级为明确占位；正式验收不能以占位冒充人物缩略图成功。

## 三、新插件数据格式

建议插件 ID / 扩展 ID 为 taunote.stickman，元素类型为 taunote.stickman.figure，工具 ID 为 taunote.stickman.create。采用完整插件前缀，避免占用 tau 内核命名空间；动态包装配时校验贡献归属和类型冲突。

```ts
type StickmanData = {
  pose: string;
  body: "classic" | "bean" | "glyph";
  tint: "mono" | "color";
  flip: boolean;
};

// 元素示例；x/y/width/height、sketch、name 属于白板通用字段。
const element = {
  id: "生成的唯一 ID",
  type: "taunote.stickman.figure",
  schemaVersion: 1,
  x: 0,
  y: 0,
  width: 132,
  height: 172,
  data: { pose: "有效姿态 ID", body: "classic", tint: "mono", flip: false },
};
```

创建器写入完整的 data，schema 负责校验。插件包版本与元素 schemaVersion 独立；此次新格式从 1 开始，没有从旧 stickman 格式升级的路径。

缺插件时保留新元素原始数据、尺寸和位置，并显示已有通用未知元素占位；不解析人物私有 data。相同插件重新安装后按声明恢复。缺包不能让保存操作删除未知节点，也不能静默导出成缺失的人物。这属于长期插件生命周期能力，与旧格式兼容无关。
