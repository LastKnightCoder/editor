# C10 · G1 独立开发闭环验收

日期：2026-10-15；基线 `3b032979a`。结论：**macOS arm64 / Electron 43.1.1 的可信桌面开发档，G1 行为验收通过**。G2 第三方生产开放、G3 生产领域扩展以及用户视觉验收不在此结论内。微信读书后续工作继续暂停。

本轮补充验证和报告，没有修改插件运行时协议、业务数据库或依赖版本。以下证据来自本轮实际执行，不以历史测试数量代替。

## 一条命令复现

在已准备好工作区依赖和原生构建环境的仓库根目录执行：

```sh
node scripts/plugins/verify-g1.mjs
```

该命令顺序执行 SDK 类型/测试/构建、桌面相关测试、仓库外作者工作流、完整桌面打包及编辑器/antd/数据库/白板边界检查，任一步失败返回非零。输出：

- `output/plugin-g1/report.json`：汇总状态、基线提交、运行前工作区是否有改动、每步命令/耗时/退出码，以及外部链路结果。
- `output/plugin-g1/external-report.json`：实际作者包版本与 15 个 Electron 进程的状态快照。
- 同目录各步骤 `.log`：详细诊断。再次运行会覆盖本机最新报告，不并发运行这一入口。

报告目录被 Git 忽略，不提交生成物。提交内保存验证脚本与本说明。临时作者项目、产物副本和 Electron profile 在结束后删除；故障场景只修改副本，不触碰调用方作者目录或生产数据。外部项目安装公开依赖需要网络，本轮不是离线安装验收。pnpm 沿用 `pnpm_config_verify_deps_before_run=warn`，没有自动重装工作区依赖。

仅重跑外部链路可执行 `node scripts/plugins/verify-external.mjs`，它仍输出 external-report.json，但不替代完整 G1 命令中的类型、单测、打包和结构门禁。

## 15 个独立进程场景

`initial` 覆盖正常流程、重载、监听与 A→B→A；其后顺序运行：`restore`、`disabled`、`skip`、`remove`、`removed`、`missing`、`recover-missing`、`incompatible`、`recover-incompatible`、`failed-install`、`failed-restart`、`timeout`、`cleanup`、`recover-cleanup`。所有场景通过。

报告中故障场景的 passed 表示观察到了预期的拒绝、隔离或恢复，不表示故障代码成功启用。每个场景收尾都检查样式清零。生产模式门禁由实际 handler 的单测验证，不把 Electron 隐藏窗口当成已打包应用的生产交互验收。

宿主验证器装配真实 PluginHost/DevelopmentPluginManager、主进程模块、preload、PageProvider/PageHost、管理与设置组件。原生对话框返回固定选择结果；服务由测试显式初始化，module-init 的就绪确认使用测试桩，不覆盖完整应用启动调度。插件通过真实磁盘产物执行，不由宿主源码导入插件定义。验证器不启动完整业务 App，也不操作真实 SQLite 数据库；这里的双工作区证据针对插件宿主、登记会话与私有存储隔离，不能替代业务数据库同步测试。视觉仍按项目规范交由用户。

## 后续与回退

G1 通过意味着作者可独立开发、构建、加载、管理和有限重载自己的可信插件。它不表示普通用户第三方框架首版已完成，更不代表默认受限执行、授权、生产安装/更新、供应链和生产领域扩展已完成。

后续应另行确定 G2/G3 的实施单元；不自动恢复微信读书主线，不自动发布 npm 或应用。回退 C10 仅撤销新增验证与文档，不改变 C09 运行行为、业务数据或登记格式。
