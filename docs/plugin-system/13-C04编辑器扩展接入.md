# C04 编辑器扩展接入

当前装配已按 D-152 调整：本文样本仅保留在 `features/plugins/__tests__/fixtures` 供回归显式装配，应用默认列表只保留主题切换；下文保留本阶段实现与验收记录。

本工作单元验证 P5 的编辑器子项：应用插件在桌面开发台注册节点、使用内置 UI、停用并重新启用。实现复用 `defineExtension`、`EditorKit`、命令分发、未知节点保护与 Markdown processor；未改写编辑器内核，也未接入生产正文、协作、数据库或白板。

## 作者入口

```ts
import { definePlugin, defineEditorExtension, defineEditorElement } from "@tau/plugins";
import { Button } from "@tau/ui";
```

作者 API 为 `context.editor.register({ scene: "workbench", extension, codecs? })`，返回 Disposable，并自动归属本次 activate。开发台是目前唯一接受的场景；不支持的场景或无适配器宿主明确拒绝。不存在尚未实现的 production/content 场景参数。

`defineEditorExtension` 适配现有编辑器声明，本次公开元素、命令、热键、元素菜单；元素定义复用原 ElementSpec。未公开原始 Slate 包装器和整套内部 API。节点渲染必须保留 attributes/children；UI 从 `@tau/ui` 导入，Slate/React 属于可声明的生态依赖。

编辑器命令归属具体编辑器实例，经已有 editor.commands 分发；不会自动注册成应用命令面板的全局命令。开发台从当前装配读取有标题的命令，渲染可执行按钮，不为提醒块硬编码宿主按钮。需要全局入口时仍使用 context.commands，并由将来的目标编辑器定位能力连接。

扩展 ID、节点 type、命令 ID、codec type 必须位于 `插件ID.` 命名空间，不自动改写持久化节点 type。节点类型通过 `@tau/plugins` 的 `EditorElementMap` 模块增强登记，行内类型同时增强 `EditorInlineElementMap`。核心接口仍由编辑器维护，SDK 负责门面与适配。

实际作者示例位于 `apps/desktop/src/features/plugins/__tests__/fixtures/example/editorPlugin.ts`、`Reminder.tsx` 和 `reminderCodec.ts`，只有上述两个 Tau 入口，无内部 store、kit 或 registry 导入。`packages/editor/contracts.ts` 是 SDK 内部使用的纯声明/定义入口，不是要求作者再安装的第三个入口；根 SDK 无 React/DOM 运行时依赖。

## 生命周期与会话

1. DesktopPluginProvider 在开发环境动态加载样本和装配器。样本默认停用，窗口/工作区创建独立宿主，切库/卸载回收。
2. activate 注册贡献，宿主先校验完整集合的类型、命令和 codec 冲突；激活成功后才对编辑场景可见。失败回收本次资源，不替换仍可用的编辑器。
3. 停用立即取消 signal，开发台立即撤销渲染、命令与 codec，不等待异步 deactivate 完成；随后逆序清理。手动 dispose 幂等，重新启用产生新的贡献实例。
4. PluginEditorSession 为每个实验文档保留独立正文、选区和 Slate history。贡献对象集合相同则保持实例；集合改变时从活跃编辑器获取最新原始快照，再重建实例并恢复历史/选区，避免依赖可能滞后的 onChange 保存。
5. 旧代次 onChange 不覆盖新会话；编辑器卸载按既有机制结束异步提交作用域。停用后未知节点沿用内核的只读占位和不规范化子树规则，再启用恢复渲染。其他段落仍可编辑。

这是有状态迁移的受控重建，不是原实例无缝热更新。块组件本地状态、DOM 焦点、输入法组合和在途异步操作不迁移。实验文档只存页面内存，页面关闭/切库/窗口关闭后清空；界面明确提示，不写生产数据库。Page Activity 保活仍受既有机制管理。

不能将此会话适配器直接套到 ContentEditor、Y.Doc、跨窗口协作或 external history；这些场景须另做绑定、事务、输入法、历史所有权与异步操作裁决。本次不因此新增全局编辑器重建机制。

## 编解码与数据保真

`reminderCodec.ts` 只导入类型，可在没有 DOM 的 Node 环境单独加载。开发台将启用贡献的 codec 与核心段落 codec 一起创建 processor；未向 Electron 主进程传 React/函数，也没有修改生产 Markdown 装配。

提醒块启用时输出易读 directive；停用时沿用已有未知节点封装保留原始字段与后代，缺失 codec 导入/导出同样可恢复。Markdown 普通语义不保留无意义空段落；启停快照因此绝不借助 Markdown 中转，而是直接复制原始节点和历史。未知节点测试额外包含未来私有字段。

异步编辑提交还没有作者 SDK API。本样本命令全部同步，宿主统一守卫只读与插件 signal。命令守卫不是沙箱，不能阻止恶意代码或作者持有原始 editor 后直接修改；受信任运行边界不变。

## 验证与手动入口

开发构建启动后：命令面板 → 插件开发台 → 打开插件管理 → 启用「编辑器提醒块示例」→ 返回应用 → 插入插件提醒 → 编辑正文/点击完成/撤销重做/切换只读。再进入统一管理停用，返回开发台查看未知节点与 Markdown，然后重新启用。管理设置是浮层，实验文档仍保留在开发台；页面样本的开关独立。

自动化覆盖真实 React/Slate 挂载、两个实例隔离、内容与历史/选区恢复、旧提交失效、只读命令、异步 deactivate 期间立即撤销、未知节点规范化与编解码、停用期间继续写段落、冲突失败、重新启用和宿主关闭。核心 SDK 同时回归失败回收、手动注销、旧上下文与无界面宿主；C02 跨进程磁盘样本继续运行。具体命令及结果见执行日志。

不做视觉验收或截图，界面外观由用户验收。示例构建仍依赖 workspace 源码，包的 ESM 验证产物不等于可发布 npm SDK；独立类型声明、共享 React/Slate 版本和宿主模块解析留给 P6。
