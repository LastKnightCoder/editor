## M0发现的架构前置问题（已确认纳入M1）

普通本地插件由 `PluginActivationManager` 通过 `Storage.getItem/setItem` 保存启用意图；`LocalPluginManager` 对普通插件沿用此路径。主进程 `ContentPluginPreferences` 目前只管理静态内容插件，落在 `.editor-enabled.json`。`plugin-local:content-enabled` 明确拒绝非内容插件。桌面PluginProvider随窗口/工作区创建和销毁，CLI无法独立读取普通插件的窗口启用偏好。

同步插件后台加载必须尊重用户的启用状态，不能仅凭“目录存在”或“同步目标已配置”就执行。否则用户在插件管理里停用后，CLI仍可能连接远端；多窗口与退出同步也可能出现不同判断。

不采用以下绕路：

- 为S3增加一份同步专用enabled状态，与插件管理并存。
- 将同步插件标记为editor/whiteboard内容插件以复用现有持久化路径。
- 依赖渲染窗口完成激活，再允许CLI或退出同步借用窗口实例。

**用户已确认把以下改造纳入M1：**

1. 所有已安装的本地插件共用主进程拥有的启用意图存储，窗口只订阅镜像；CLI通过同一Node持久化实现读取。
2. 保留实际运行语义：普通界面插件按既有生命周期启停；内容插件仍按现有启动快照和重启规则装配；后台同步实例由任务持有。
3. 增加通用的后台任务占用检查：有同步任务使用插件时，停用/卸载/替换先拒绝并提示结束任务。任务结束释放占用，不新增S3特判。
4. 迁移现有本地插件偏好时定义优先级、失败重试和完成标记；内容插件已有主进程值优先，普通本地插件从现有窗口偏好一次性转移。旧偏好清除只在新存储确认成功后进行。
5. 内置主题插件和旧开发台夹具不扩入此次改造；它们不作为可供CLI加载的已安装同步插件。后续如果也需要后台运行，必须进入同一协议。

这项改造触及已有插件管理，已在用户确认后开始；范围限于已安装本地插件启用意图，不重构整个插件系统。

曾比较过只收口后台/内容插件的较窄选择，但会保留按能力区分的两条持久化路径。用户选择统一全部已安装本地插件，需覆盖已有普通/内容插件的回归。

## 目标分工

客户端负责快照生成/校验、对象命名、版本链、同步锁、恢复、资源计划、用量合并、已有任务管理与用户确认。插件负责认证、目标路径映射、现有远端操作与配置表单。失败继续进入现有处理路径；不在本轮强推统一错误码全集。SDK不向提供方暴露数据库句柄或业务内容写入API。

同步目标配置由宿主在本机应用级持久化，不放在插件当前按工作区隔离的context.storage中。插件定义配置结构与表单；凭证属于配置，不新增通用凭证平台。宿主固定本次任务的配置，不要求插件额外实现target.identity或公开配置版本接口。配置、密钥、签名URL不进入日志。

后台模块不依赖React、Electron或窗口API，桌面后台和CLI可加载同一产物。前端仅贡献配置组件。提出manifest增加专用sync入口、模板编译src/sync.ts；必须同步包校验、摘要、ZIP上传检查、安装升级与模板，不能只让本地开发目录绕过校验运行。

接口草案见 [49-C30同步存储接口草案.md](./49-C30同步存储接口草案.md)。

### M1：宿主收口

1. 经确认后，收口本地插件启用意图和后台任务占用；为切库、多窗口、重启与CLI建立行为测试。

4. 后台提供方不依赖设置页生命周期；沿用当前字节传递、数据库锁和恢复模块，不在插件内复制同步引擎，不把整条大文件链路重写纳入本次前置条件。

验收以新旧行为对照为准：对象路径/内容、已有版本提交和响应丢失处理、配置切换、恢复与启停保持一致。已有冲突规则不能被静默放宽；发现旧实现本身的问题，单独列证据讨论，不改成新的插件准入认证。

其他提供方的旧源码可在尚未迁出时存在，但必须经统一协议接入，不新增另一套S3分支。每个提供方迁出后删除对应旧实现；不把长期双路径视作完成。

### M2：S3插件完整闭环

1. 专用后台入口及其完整包校验；同步配置组件在设置→同步的专用挂载点展示。
2. S3源码归独立作者项目，遵循现有业务插件独立仓库方向；不将业务源码塞进scripts。发布前只做本地作者项目与构建验证，创建GitHub仓库和SDK发布另记实际状态。
3. S3实现49中的五个方法；从已有S3行为迁移，签名、重试和条件写入差异按50单独核对。不强制新增stat/delete、公开分页、流或错误类型。普通npm依赖随插件打包。
4. 桌面数据库/会话、资源、用量及CLI使用同一插件实现。移除已被接管的旧S3同步Provider/Adapter；其他业务仍使用的S3上传/发布接口保留。
5. 同步专属配置一次性迁入宿主目标配置；共享integration凭证不删除，已有远端对象名和协议不变，不重新上传整个库。

验收：作者项目构建→ZIP校验→约定目录安装→启用→同步页配置→与旧实现对照上传/下载及CLI快照；覆盖已有失败恢复与启停，不将新增存储能力作为前置。界面视觉由用户验收。S3保持首个拆分对象，不自行更换提供方。
