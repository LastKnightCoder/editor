## 已遇到的问题与经验

### K07 浏览器网络探针与范围纠偏

- 已实测：Electron 43.1.1，独立 session、sandbox/contextIsolation、CSP connect-src none、webRequest 拒绝外联、权限拒绝及 disable_non_proxied_udp；本机对照探针收到 HTTP 1/TURN TCP 1/STUN UDP 4，受限配置收到 HTTP 0/TURN TCP 1/UDP 0。普通请求拦截不能证明完整浏览器客体禁止联网。
- 用户随后明确当前优先 API 与流程，不继续扩大安全实现。一次性网络探针源码已删除，仅保留此次观察；后续隔离阶段需重建可重复的验证，不将此记录当作已通过的门禁。
- 未引入 QuickJS 或其他引擎依赖；不以高信任档自动回退来宣称隔离完成。C02 改为明确可信的开发样本。

### K06 新 worktree 未生成 Husky 启动器

- 现象：首次提交没有触发钩子；检查发现 core.hooksPath 指向 `.husky/_`，但此工作区尚未生成该目录。补跑脚本时，antd/数据库/白板检查因找不到 TypeScript 失败。
- 原因：工作区未执行依赖准备，Git 忽略的启动器和各包 node_modules 不随 worktree 创建。
- 处理：用已有 Husky 生成本地启动器；仅为静态边界检查通过 NODE_PATH 解析原工作区已有 TypeScript，复验三项门禁通过。补齐本条后以同一文档提交 amend，重新经过原有 hooks；不修改 tracked hook、不跳过门禁。
- 防回归：C02 先完成独立依赖与 hook 初始化；此次工具借用不能证明新 worktree 可构建或运行原生测试。

### K05 新 worktree 的 pnpm 自动安装预检查

- 现象：为文档格式和提交门禁临时链接已有根依赖目录后，pnpm 11 的 exec 仍触发依赖状态检查，并尝试 install；非交互保护以 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` 中止。
- 原因：新 worktree 的依赖状态与原安装目录不一致，默认 verifyDepsBeforeRun 为 install，符号链接不是独立安装环境。
- 处理：文档格式直接调用现有 Prettier；提交门禁保留执行，仅将此次进程的 `pnpm_config_verify_deps_before_run` 设为 warn，避免自动重装。没有关闭 Git hooks，也没有完成依赖安装或原生重建；本轮结束删除临时链接。
- 防回归：C02 准备独立依赖环境，不能沿用此文档工具方案跑 native 测试或构建，不能设置 CI 强制清理共享依赖目录。

### K03 类型安全与注册表不等于权限安全

- 现象：项目已经有 RPC、服务依赖和注册表，容易误以为只需将其导出为插件 API。
- 原因：这些机制解决类型、装配和调用，没有绑定插件身份、资源范围与撤销语义。
- 处理：保留现有业务用途，新插件使用 Broker 显式允许的能力，不把所有 channel 整体桥接。
- 防回归：每个能力写明执行端授权位置，并直接尝试绕过 SDK。

### K04 在线文档版本高于仓库版本

- 现象：Electron latest 文档出现 43.7.0 等版本才增加的网络请求字段，而当前 desktop 声明为 43.1.1。
- 原因：在线 latest 会滚动更新。
- 处理：载体和关键 API 对照 Electron v43.1.1 标签文档，C02 还须核实锁文件及实装版本。
- 防回归：记录验证版本，不以 latest 页面中的新字段设计必需安全校验。

### K01 单一样本带偏体系目标

- 现象：初版路线以微信读书迁移为主线，并把隔离运行实现放在后期。

- 处理：按用户澄清重写目标，P1 比较多场景，P2 验证最小隔离运行；微信读书放回业务样本位置。
- 防回归：增加公开 API 时说明所属层、至少一个真实消费者及边界反例，阶段完成按体系验收判断。

### K02 历史文档混有过时链路
