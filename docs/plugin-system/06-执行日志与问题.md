## 已遇到的问题与经验

### K01 单一样本带偏体系目标

- 现象：初版路线以微信读书迁移为主线，并把隔离运行实现放在后期。
- 原因：将验证场景误当成最终架构目标。
- 处理：按用户澄清重写目标，P1 比较多场景，P2 验证最小隔离运行；微信读书放回业务样本位置。
- 防回归：增加公开 API 时说明所属层、至少一个真实消费者及边界反例，阶段完成按体系验收判断。

### K02 历史文档混有过时链路

- 现象：微信读书数据流文档保留旧页面、表格和 Slate 转换等说明，页首有部分更新。
- 原因：历史说明与当前投影混在同一文档。
- 处理：现状以源码索引为准，明确旧文档使用限制；本次不扩大为旧专题重写。
- 防回归：现状文件就地反映当前行为，过程进入日志，提案进入架构和决策，不在现状连续堆叠相互冲突的版本。

## 后续记录模板

每次新增条目写明：日期与工作单元、基线与提交定位、完整可用行为、涉及消费者、实际验证命令和结果、未解决问题及阻塞程度、恢复方式、下一步。测试失败保留首次失败原因与修复后的复验结果，不只记录最后一次成功。

安全或数据问题必须记录复现条件、影响范围、根因、修复、回归测试和当前状态。视觉问题单独标记为用户待验收，不能与行为门禁混淆。
