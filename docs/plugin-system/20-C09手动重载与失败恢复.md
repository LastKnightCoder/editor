# C09-A 手动重载与失败恢复

基线 `98bd4b3ed`，2026-10-15。本切片提供可信开发插件的手动整实例替换；后续 C09-B 已接完整发布监听，见 [21](21-C09自动监听完整构建.md)；G1 集成验收仍在 C10。微信读书继续暂停。

## 作者操作

修改仓库外插件源码，重新执行 `npm run build`。构建仍发布独立、完整的版本目录；在设置 → 插件找到已登记插件，点击「重载构建」并选择新目录。ID 必须保持不变，开发时允许同版本号的新构建，不提供插件数据迁移或版本降级保障。

取消选择、文件缺失、摘要不匹配、不同 ID 或不兼容清单都会在停止旧实例前返回。原插件运行中则新代也运行；原插件停用则只更换定义，不为检查构建而执行代码。当前文档只面向有明确来源的可信代码，不是沙箱。

## 替换与提交

主进程 prepare 读取新产物，返回一次性票据和代码快照。票据固定窗口会话，并保存旧登记和新清单；作者目录始终只读。

渲染端先将旧登记标为 starting，随后停用、注销旧定义，登记并按原运行状态启用新代。只有成功后才 commit 新目录、清单和启用状态。重载中进程退出时，成功提交前磁盘仍是旧登记及 starting，重启后跳过自动启动；成功提交后的重启恢复新版本。运行中仍使用内存快照，不在 activate 中读取变化的磁盘文件。

同插件管理操作串行，忙态在管理器中共享；切换列表/详情不会绕过忙态。关闭/切库使旧管理器失效，不继续创建旧作用域实例。票据在 finally 释放，连接失效时由整个会话回收。

## 失败恢复

- 新版本普通加载/激活失败：先回收新代，再使用旧内存快照创建旧版实例，恢复原运行状态并确认旧登记；界面仍报告此次重载失败及旧版恢复结果。
- 新版本登记提交失败：同样尝试恢复旧代码与旧登记。票据在事务结束前保留旧登记，提交响应异常后也能尝试写回旧版本。
- 旧代清理失败、新代激活超时或清理失败：沿用 C08-A 的 restart-required，不为恢复而运行另一个实例。
- 旧版再次激活或恢复提交也失败：停止插件，尝试写回旧登记并保留未完成标记；明确报告恢复失败。磁盘不可写时无法保证登记最终落点，必须检查登记文件，必要时使用 `TAU_DISABLE_DEV_PLUGINS=1` 跳过自动启动。

恢复的是代码与登记，不是数据事务。失败新版本已经写入的私有数据、网络/文件副作用不会回滚；旧版本若因此无法运行，会进入恢复失败状态。页面/设置依照既有 mountId 重挂载，已保存数据重新读取，未保存草稿、组件局部状态和焦点不迁移。现有即时保存样本适用，不宣称支持任意草稿类插件。

## 连续重载边界

模块工厂每次重新求值；宿主不建立全局插件模块缓存，不用不断变化的 ESM URL 累积模块。只保存当前产物、正在替换的候选和旧快照；资源仍由 signal/dispose 回收。

每窗口、每插件最多 20 次实际替换尝试，普通失败也计入，取消/校验失败不计入。达到上限时当前实例继续可用，需重启应用后再重载；计数跨切库保留。20 是保守开发策略，不是由堆阈值推导出的安全容量，更不能防止插件自行保留全局引用。

真实 Electron 验证成功重载、激活失败回退、ID 拒绝和后续连续 10 次重载：两插件的命令、设置、CSS 均保持 2 项；初次记录的粗粒度 usedJSHeapSize 前后均为 18,200,000 字节，仅作观察，不用于证明无泄漏。SDK/管理单测另验证 20 次边界，任意同步失控与全局副作用仍须重启。

## 复现与回退

`node scripts/plugins/verify-external.mjs` 在临时作者目录构建原版、第二插件、成功新版和激活失败新版，实际 Electron 通过管理按钮执行替换及回退，并用后续独立进程确认新登记恢复。单测覆盖提交失败、恢复失败、旧版清理失败、新版超时、停用插件、关闭竞态和登记快照。完整命令结果见 [执行日志](06-执行日志与问题.md)，视觉由用户验收。

登记格式没有新增版本字段，回退 C09-A 后 C08-B 仍能读取最后提交的目录和清单，但不再有重载按钮。插件自行改变的数据不随代码回退；作者目录不会被宿主删除。C09-B 已接自动监听，下一步为 C10 集成验收。
