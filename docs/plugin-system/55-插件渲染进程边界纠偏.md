## 执行边界

- 所有插件代码、同步提供方与自定义codec只在渲染进程执行。主进程、Node worker及CLI不得求值插件产物。
- 主进程保留宿主拥有的文件、数据库、网络、索引、发布和任务管理能力。插件通过明确的宿主API调用；复用context.fetch，不开放require、任意Node模块或代码执行。
- 普通插件仅通过main.js激活，新增context.sync.register用于五方法提供方注册。每轮任务固定配置，停用注销贡献；关闭设置页不影响任务。
- 数据库/用量同步复用原渲染端编排。资源任务仍由宿主管理扫描、账本、重试和进度；存储操作交发起任务的渲染进程，断开即失败并清理，不能转到Node执行。
- CLI完全移除同步命令、TUI和存储实现。不通过隐藏窗口或远程转发保留CLI同步。
- 内容扩展与codec保持同源。博客插件产物读取、摘要校验和复制不等于执行，可以由宿主完成；不得新增render.js、替代渲染器或改变文档/博客输出。
- 不新增存储能力声明、沙箱、发布平台、多文件Node依赖契约或数据格式。

## codec扩展影响：后续TODO，本轮不处理

主进程仍有以下调用：tables/card、article、project、diary、calendar-event中的正文查询转换；tables/fts全文回退搜索；search-core/main-content-adapter；main-content-fts-index-queue、main-content-vec-index-queue；material-index、vibe-learning-index-queue、vl-material-resource、content-sections；publish-search-index。

这些消费者不能在主进程同步等待渲染进程，否则会阻塞IPC与窗口。建议数据库查询维持同步，转换上移到既有异步请求/任务编排层，并在渲染端调用同一desktopMarkdown和splitSections实现。发布worker现有的主进程应答可以承接转换结果，但不得保留worker插件求值。没有渲染端就绪时显式等待/失败/重试，不能悄悄使用不含插件的codec生成不同结果。

这比仅移走两个worker更广。用户已决定后续单独处理，本轮不修改这些调用点、不改变文档和博客渲染行为。
