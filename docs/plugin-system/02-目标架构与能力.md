# 插件系统目标架构与能力

本文件是分阶段设计方向，接口名称用于表达职责，尚未承诺为稳定 SDK。技术取舍的状态见 [决策记录](05-决策记录.md)。C01 的具体运行载体、能力执行位置和范围见 [运行架构裁决](08-C01需求与运行架构裁决.md)。

当前已落地 API 以 [10](10-C02API与流程闭环.md) 和 packages/plugins 为准；本文件中的服务、页面和领域能力仍是逐步演进的方向，不预建空接口。

## 架构目标与多场景验证

体系必须让新增插件通常只增加插件包与声明，不要求在核心加入插件 ID 分支；权限有实际执行边界；停用、失败和升级不会破坏用户数据。微信读书用于检验跨服务组合，不能成为宿主 API 的业务模型。

| 验证样本                 | 主要检验边界               | 不能由其他样本替代的验收             |
| ------------------------ | -------------------------- | ------------------------------------ |
| 最小命令与私有存储插件   | 实例身份、授权、注册回收   | 越权拒绝、失败回收、重启可读         |
| 外部数据同步，如微信读书 | 网络、凭证、任务、公共数据 | 取消、切库、原子提交、幂等和来源定位 |
| 自定义页面与设置         | 界面隔离、导航、主题、表单 | 历史恢复、未保存守卫、浮层仲裁       |
| 编辑器节点与命令         | 同步行为、文档事务、协作   | 撤销重做、序列化、未知节点保真       |
| 数据库字段与视图         | 查询、计算、类型扩展       | 分页、计算失败隔离、缺失字段类型保真 |
| 白板元素与工具           | 手势、高频渲染、历史       | 实例隔离、取消手势、缺失元素保真     |

每次添加公共能力必须有当前消费者和反例；跨场景候选能力先用两类样本核实，领域专用能力则保持在领域接口中，不强行泛化。样本的实现可分阶段完成，需求边界必须在 P1 同时比较。

## 分层与依赖

### 面向插件作者的两个公共入口

用户已确认使用 `@tau/plugins` 与 `@tau/ui` 两个入口（PS-015）。页面、编辑器等产品 API 统一从 SDK 获取，通用组件从公共 UI 包获取；内部 `@tau/editor/api` 等拆分不要求作者直接依赖。

目标用法如下，页面 API 在 C03 接线，编辑器 API 在 C04 接线；不预先加入空导出：

```ts
import { definePlugin, type PluginContext } from "@tau/plugins";
import { Button } from "@tau/ui";
```

SDK 包含已支持的定义函数、产品 hooks 与公共类型，UI 包提供组件；实际服务通过插件上下文取得，如命令、存储和页面注册，不提供绕过实例作用域的全局服务单例。React 等生态依赖按公开 peer 约定使用。

公开名字按作者用途设计，避免多个领域都导出含义不同的 defineExtension/defineElement；例如可命名为 defineEditorExtension，内部仍复用原实现。不要将内部包 export * 后视为完整 SDK，也不为尚未实现的能力添加空类型或占位函数。

宿主实现和作者 API 分开：当前 `@tau/plugins/host`、`@tau/plugins/node` 只供宿主与测试使用，不进入根入口，也不属于外部作者契约。它们目前确实可被工作区解析，不能把这一约定说成访问控制；P6 发布前收回或移至内部宿主包。

两个公共入口与内部按需装配并存。C03 必须保持 SDK 根入口无 React/DOM 运行时依赖，UI 由渲染侧消费；内部绑定、构建解析及类型产物由宿主/SDK 承担，不把问题转嫁为作者安装内部包。

应用插件负责身份、版本、贡献、启停和授权；领域扩展负责某个编辑器、数据库或白板实例中的功能。一个插件可以贡献多个领域扩展，共用安装和生命周期机制。

公共契约不依赖桌面 feature、store、Electron 或 SQLite 实现。宿主适配器实现契约，并通过插件上下文注入；插件业务只消费统一作者入口。内部包的拆分随实际消费者决定，不改变作者导入路径。

受限插件与受信任的深度界面扩展使用明确不同的运行档位。当前 P2 先用可信开发样本验证 API，隔离样本推迟到第三方受限档开放前。身份由宿主发行与加载路径确定，manifest 不能自行声明可信；第三方使用高信任档须用户明确授权。

## 三个独立维度

| 维度     | 说明                                            |
| -------- | ----------------------------------------------- |
| 服务依赖 | requires/optional 表达宿主是否具备某项能力      |
| 能力授权 | 必需/可选权限表达插件能否访问特定资源或执行操作 |
| 执行环境 | 受信任界面、受限运行环境或明确授权的特权环境    |

同主界面执行任意 JS 时不能保证只使用申请过的权限。独立 Node 进程也不自动隔离文件和网络权限。后续开放第三方时再逐项验证隔离路径；P7 开放门槛通过之前，不开放公共第三方安装，也不宣称所有领域扩展都可在受限档运行。

受限插件所有宿主调用在执行边界验证身份、工作区句柄、实例代次、参数和授权；身份绑定通信端点，不相信请求里的 pluginId。网络限制必须覆盖重定向、图片等旁路，不能仅检查 SDK 的 fetch。

## 微信读书样本所需能力

| 能力         | 真实用途                       | 必须保留的语义                               |
| ------------ | ------------------------------ | -------------------------------------------- |
| 工作区上下文 | 连接完成、切库、缓存和任务归属 | 旧会话不能写当前库，关闭重开同名库也可区分   |
| 网络与凭证   | Key 校验、Agent Gateway 请求   | 取消、错误分类、目标范围、日志脱敏           |
| 设置与偏好   | 集成入口、书架布局和排序       | 设备级与工作区级分离；凭证不混入普通配置导出 |
| 插件存储     | 书籍、笔记、指纹、同步时间     | 分页、索引、批量写入、数据版本和配额         |
| 后台任务     | 增量及全量同步                 | 工作区级去重、进度、取消与失败可重试         |
| 页面与导航   | 书架、单书、划线定位           | 原匹配语义、参数、面包屑、页面保活           |
| 命令与 UI    | 同步、重新校验、状态提示       | 命名空间、可撤销贡献、主题及浮层仲裁         |
| 来源与摘录   | 同步公共摘录、打开原文         | 所有权、幂等、软删除、稳定外部 ID            |
| 受控事务     | 缓存和摘录一致提交             | 提交成功后才发变更通知，失败一起回滚         |
| 素材动作     | 转卡片、发起问题               | 走宿主领域协议，保持引用关系                 |
| 外链         | 打开授权页和原书               | 受控协议与目标校验                           |

微信读书首个闭环不要求原始编辑器、白板、任意 SQL、任意文件或主进程执行权限。网关分页、限流处理、指纹和响应解析属于插件，不新增一个包揽全部业务的宿主 `weread` API。

## 数据与凭证边界

1. 区分数据库产品扩展、插件私有存储、应用内部 SQLite，三者不能共用一个无边界的 database 对象。
2. 公共实体经领域操作写入，维护索引、引用、权限、通知和撤销规则，不暴露全局 SQL 连接。
3. 迁移现有业务时优先保持原表和 ID，通过宿主适配实现公开协议；通用插件存储按多场景需求设计，不由单个业务表结构决定。
4. 同库受控批量操作是微信读书保留现有事务语义的首选提案；若改独立库，必须补 outbox、重试和一致性修复，不能用两个调用假装原子提交。
5. 凭证接口与物理存储分开设计。更换存储前调查系统安全存储、导出、同步和无安全存储时的降级；不在普通依赖注入提交里顺带搬迁凭证。
6. 同步游标只在对应结果持久化成功后推进。网络请求不放进长数据库事务。
7. 插件卸载默认保留已生成文档、卡片和公共摘录；私有数据、缓存和凭证分别处理。

## 贡献与生命周期

宿主发现 manifest 时不执行插件代码；校验身份、版本、平台、依赖和权限后登记入口，再按需要激活。所有注册都返回清理句柄，并自动绑定 owner 和作用域；激活失败按逆序回收已完成的注册。

| 作用域         | 生命周期职责                                       |
| -------------- | -------------------------------------------------- |
| 插件实例       | activate/deactivate，持有实例代次和取消信号        |
| 工作区         | attach/detach，持有不依赖“当前库”的有效会话句柄    |
| 窗口           | UI 贡献的挂载与回收；不重复启动工作区后台任务      |
| 页面及领域实例 | 创建、显示/隐藏、销毁；Activity 隐藏不等于插件停用 |
| 数据版本       | 在授权和准备完成后迁移；不随普通重载重复迁移       |

停用时先拒绝新任务并取消在途工作，再通过宿主守卫处理未保存内容，销毁页面及领域实例，限时执行插件清理，最后由宿主兜底撤销注册与通信能力。异常或超时不允许阻止其他资源清理。必要的保存用宿主管理的有界收尾通道，不能让旧实例重新获得任意写权限。

同进程插件无法强制清理所有任意副作用；这种限制属于受信任模式边界。隔离模式可通过销毁运行环境完成更可靠的终止。

## 页面与领域扩展

继续使用 Page 栈，不另建插件 Router。动态注册需要原子管理 Page 元数据与组件定义，携带 owner，协调已打开页面、历史恢复和导航贡献。对现有静态 glob、侧栏单源约定的扩展必须先记录桌面裁决，再实现通用机制与适配器；导航内核保持零业务依赖。

设置先支持宿主 schema 表单，再按需要开放自定义视图。浮层仍由宿主仲裁 Esc，插件不能自行接管导航快捷键。

编辑器、数据库、白板公开受控操作，不能直接导出所有内部类型。扩展数据使用稳定命名空间和版本；插件缺失时保留原始数据、子节点和引用，提供降级展示。协作、导出和旧端读取必须考虑未知扩展。复杂同步 React 渲染器先归受信任档，不承诺透明迁入 RPC 沙箱。

## 构建与重载

开发期类型、运行期宿主实现分开。C01 选择受限入口采用浏览器 ESM 与 activate(context)，普通依赖打包，不要求运行时 SDK import；宿主 preload 单独构建。P6 完善面向开发者的构建和发布协议，不能等打包阶段才发现运行边界不兼容。

基本产物包括 manifest、入口 JS、预编译 CSS 和静态资源。安装不运行 npm 脚本；代码与数据目录分离。可信同界面渲染时 React 使用宿主单例并约束版本，隔离页面可自带 React；插件自行输出 CSS，不依赖宿主扫描安装后的 Tailwind 类，禁止向宿主注入全局 reset。

重载先做整插件实例替换：完整构建发布、校验、停止旧实例、回收、加载新实例、恢复可序列化 UI 状态。文件变化不是构建完成信号；使用最终发布的清单或版本目录。ESM 缓存不能仅靠不断添加查询参数实现无限重载。涉及数据迁移时，代码回滚不等于数据回滚。

## 后续分发约束

兼容性分别记录宿主 API、领域 API、插件数据版本及平台能力。升级新增权限重新授权；升级来源与发布者身份绑定，安全解包、完整性校验和原子替换不可省略。崩溃需按插件归因，连续失败可安全启动；签名和哈希不等于代码无恶意。
