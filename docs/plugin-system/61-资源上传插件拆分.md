# 资源上传插件拆分

## 当前范围

本轮拆分资源上传/图床，不重复拆分数据库与resources目录同步。默认使用已有本地落盘路径，GitHub、OSS、S3上传分别独立成插件；不创建WebDAV上传插件。已拆出的WebDAV同步插件不在退役范围。

## 设计边界

上传与同步契约分离：上传返回可供正文/博客直接引用的资源地址；不返回同步任务的boolean，也不增加内容读取、冲突处理或插件Node入口。插件仍只在渲染进程执行，网络复用context.fetch。

沿用插件注册和生命周期，只增加上传提供方的一次上传能力，输入为已处理的文件名、MIME类型与字节及本次固定配置，输出为资源URL。宿主继续负责图片压缩、唯一文件名、本地目录落盘、选择当前提供方、配置保存、错误提示与任务回收；不新增远程可用性探测、服务商能力声明或鉴权下载协议。

新用户和未配置远端的默认目标为本地。已有明确配置的GitHub/OSS/S3目标迁入相应插件，不默默改投另一个远端；选中插件不可用时明确失败，不暗中把文件改存到其他位置。默认本地目录复用copyFileToLocal，不引入新的目录选择体系。

## 删除与保留边界

- useUploadResource：移除具体服务商分支，保留公共压缩和本地落盘；上传插件经统一注册表调用。
- ResourceSection：保留本地与压缩设置，远端配置由上传插件贡献；不借同步设置承载上传配置。
- GitHub、OSS、S3账号与上传模块逐项搜索消费者，仍被博客发布等功能使用的工具不得直接删除；不将“上传插件化”扩大为博客发布重写。
- WebDAV图床：删除上传设置和分支；isWebDavResource、remoteResourceToLocal中的鉴权下载、LocalAudio特殊路径，以及webdav-upload/download IPC均在清单内。删除前需确认历史私有资源的处理方式，不能把已保存链接无提示变为不可访问。
- WebDAV共享账号设置是否有其他消费者需核实；WebDAV同步插件已经使用独立配置，不能因图床退役而删除同步插件配置或数据。

## 待确认的数据问题

用户确认没有需要保留的WebDAV历史资源，直接退役相关图床代码，不做历史资源迁移。当前未读取或迁移真实用户资源。

## 分发要求纠正

分发清理已完成，见63文档。上传插件独立发布到插件中心，不随客户端提供或自动安装；移动端和浏览器扩展不增加插件机制，博客保持发布时收集插件的流程。

## 跨窗口执行

独立卡片、文章、项目文档与Markdown窗口的远端上传，通过宿主IPC转发到主窗口现有渲染进程。主进程只转发数据，不求值插件、不创建隐藏窗口、不增加Node入口。主窗口插件宿主不可用时明确报错；窗口关闭、导航或宿主释放后拒绝等待中的请求，迟到回复不再交付。每次上传固定目标与配置快照。

本地上传保持原行为：普通正文写入应用resources目录，独立Markdown在本地模式写入.md同目录并返回相对文件名；导出包的assets目录属于导出流程，不改动。

多主窗口使用发起窗口自己的宿主；辅助窗口选择已连接的主窗口宿主。任务绑定本次宿主代次，另一主窗口的连接或关闭不会取消现有宿主的任务。
