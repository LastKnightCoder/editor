# 插件体系安全模型

## 当前设计入口

C12-B 的 Electron 监督、固定 WASM 资源布局、缺失/损坏拒绝与退出清理证据见 [25](25-C12-Electron监督与WASM打包.md)。它复用 C12-A 权限边界，没有增加客体能力；utilityProcess 的 Node 权限只属于可信 worker，不因此宣称 OS 沙箱。生产退出守卫、作者生命周期与数据提交仍需后续接线。

G2 的权限执行、供应链和安装升级设计见 [23](23-插件中心发布权限与安装方案.md)。当前发布平台暂停，先执行 [24 C12-A 最小权限边界](24-C12最小权限执行边界.md)：QuickJS/WASM 独立子进程候选实证，不是生产授权或完整安全审计。下文 C01/C02 载体是历史方案与威胁清单，不等于已经通过验收；未通过的网络封锁实验必须保留为反例。

生产权限要求：授权前不执行顶层代码；声明包含能力及范围；调用由宿主绑定的身份/工作区/代次验证；撤权在服务提交点生效。受限执行器必须封锁直接网络、文件和资源加载旁路并可终止。现有有限 require 和同 DOM CJS 不满足这些条件。任意 React/同步领域扩展建议留在高信任档，受限 UI 首期由宿主渲染受控数据，具体载体需 C12 实证。

发布批准绑定确切产物摘要与源 commit，生产安装执行不可变快照；本地来源不能通过自报 ID 继承官方授权。受限升级扩大权限须重新同意，高信任每个新摘要须重新授权。拒绝授权不能自动提权或执行候选；回滚代码不承诺回滚数据。详细失败处理和待评审产品取舍见 23。

## 历史模型与持续约束

本文件为 C01 更新后的威胁模型，不构成安全审计结论。[C01 裁决](08-C01需求与运行架构裁决.md) 已给出具体运行载体、信任流向和能力执行位置，[C02 合同](09-C02实施与攻击性验收.md) 给出攻击性测试。安全性通过运行约束证明，不能只由 manifest 或 TypeScript 类型声明。

当前优先级已由 PS-012 调整：先以可信样本跑通 API，隔离实现和此处的攻击性验收推迟到受限第三方开放前。下文 P2/C02 的安全门槛保留为原计划记录，不是当前 10 合同的完成条件；已有开发宿主不宣称提供这些保证。

## 保护目标与威胁主体

保护用户正文、数据库、附件、凭证、本机文件、系统能力及应用可用性；保持插件之间、工作区之间和实例代次之间的隔离。防范恶意插件、被篡改升级、意外越权、失控循环、故障清理及不可信导入数据。

操作系统已被完全控制、宿主二进制本身被替换不属于普通插件权限模型能独立解决的范围；发布链完整性仍需在 P7 管理。获准读取数据并联网的插件可以外传获准读取的数据，权限界面必须表达这一组合风险，不能声称域名授权等于数据不会外泄。

## 执行档位

| 档位           | 承诺                             | 限制                                             |
| -------------- | -------------------------------- | ------------------------------------------------ |
| 受限插件       | 仅通过绑定身份的通道使用获准能力 | 必须封锁环境旁路；开放范围以实际验收为准         |
| 受信任深度扩展 | 可承载必要的同步界面和领域行为   | 不承诺同环境内的细粒度强隔离，只接受明确可信来源 |
| 原生特权扩展   | 默认不提供                       | 将来必须单独决策授权、平台隔离和恢复方案         |

内置只是发行来源，不能替代能力声明；受信任也不能成为第三方 manifest 可自行选择的提权字段。仅允许外部代码运行在沙箱中，不意味着宿主的代理服务就安全，代理仍需最小权限校验。

用户已确认允许第三方经明确授权进入高信任档，默认仍为受限档（PS-010）；首期仅桌面（PS-011）。高信任授权必须由宿主记录并与安装身份和代码版本绑定，不得由插件自报或因沙箱失败自动回退。拒绝授权保持受限，撤销后阻止再次加载；对于已经执行的同环境代码，需要重启才能可靠清除的限制必须如实表达。

## 威胁与执行要求

| 攻击或故障                 | 执行要求                                                          | 验收证据                                      |
| -------------------------- | ----------------------------------------------------------------- | --------------------------------------------- |
| 伪造 pluginId 或跨插件读写 | 宿主把安装身份绑定通信端点与存储命名空间                          | 伪造消息、访问其他命名空间均拒绝              |
| 切库或重载后的迟到请求     | 工作区会话句柄与 generation 在提交端验证                          | 延迟请求无法污染新库或新实例                  |
| 任意 IPC、文件、进程访问   | 受限环境无通用桥、Node 权限或任意主进程执行入口                   | 绕过 SDK 的直接访问失败                       |
| 网络旁路、重定向及内网访问 | session/来源/网络策略配合代理；校验目标及跳转，约束本机与内网访问 | fetch、图片、导航、WebSocket 等按所选载体测试 |
| 凭证泄漏                   | 凭证归属、按目标注入、日志脱敏、不随普通数据导出                  | 错误、重定向、日志和导出夹具无凭证泄漏        |
| 恶意 RPC 参数或消息洪泛    | schema、载荷大小、并发与速率限制；返回稳定错误                    | 异常参数和大量请求不会扩大权限或拖垮宿主      |
| CPU 死循环或内存膨胀       | 可终止的运行载体，有限资源策略和故障归因                          | 有界测试终止故障插件，宿主可继续使用          |
| 恶意 CSS、DOM 或渲染回调   | 受限 UI 独立边界，可信渲染明示风险；禁止共享环境冒充沙箱          | 插件不能读取宿主 DOM 或覆盖其他界面           |
| 间接调用高权限命令         | 被调用动作自行检查调用身份和能力，避免宿主代为提权                | 低权限插件调用高权限动作被拒绝                |
| 包路径穿越、替换与依赖脚本 | 安全解包、路径和 symlink 策略、完整性、原子安装，不运行安装脚本   | 恶意包不能写出安装目录                        |
| 授权后升级偷加权限         | 权限差异检查与重新授权，发布身份绑定                              | 新增权限未批准时不可用                        |
| 卸载或崩溃损坏数据         | 关键回收由宿主负责，用户数据与安装目录分离                        | 不执行卸载钩子也可安全停用；原文仍可读        |

以上是要求，不是当前已具备的保证。执行位置已映射为 Supervisor、Broker、Domain/UI Adapter 和安全容器策略，见 08；不能以单元 mock 代替实际运行环境的隔离验证。

## C01 补充的高风险路径

- 默认会话的资源协议、主窗口 preload、本机服务及全窗口广播不进入插件容器；独立 session 不等于已封锁全部网络。
- custom-block 在可信界面执行正文 JS，文档写入必须阻断间接执行；包括嵌套、导入转换和宿主动作。
- WebRTC、预连接、DNS 等必须实测；只设置 CSP 或 disable_non_proxied_udp 不能宣称网络零旁路。
- WebContents 可能共享渲染进程。启用能力与强制终止前检查进程归属，无法排除误伤时拒绝启用该档位。
- C02 不承诺 OS 级硬 CPU/内存配额；载荷与队列限制、超时和可终止环境控制常见故障，极端资源耗尽作为 P7 前必须审查的残余风险。

## 数据与界面边界

私有存储的授权范围由宿主绑定，不由 SQL 表名前缀自行约定。公共实体写入检查插件拥有的来源、用户授予的资源范围和领域约束。参数合法不代表业务授权合法，事务也不能扩大授权范围。

插件页面向宿主发送的数据使用显式消息协议；React 函数、DOM 引用和可写内部对象不跨受限边界。同步渲染器是否进入可信档必须在安装或启用语义中明确，不能在性能优化时静默降低隔离级别。

第三方导入的富文本、HTML、URL、图片和资源路径都按不可信数据处理。现有 custom-block 等执行能力不是隔离证明；如果可由插件间接触达，必须纳入威胁模型和能力检查。

## 分阶段安全门槛

- P1：多场景资产、攻击路径和运行档位已裁决，未解决事项标记阻塞范围。
- P2：最小运行环境与跨插件访问、通用桥绕过、终止回收的真实测试通过。
- P3/P4：每个服务与 UI 贡献增加权限、数据归属及撤销测试。
- P5：明确每种领域扩展的运行档位，不能将受信任渲染器计入受限能力覆盖率。
- P6：包加载、路径、资源、开发模式和重载不绕过既有边界；开发授权与普通安装分开。
- P7：更新、权限升级、恢复和安全启动通过，记录测试平台与覆盖限制后才开放第三方分发。

开放前需针对实现进行安全审查；通过当前测试不意味着不存在未知漏洞。对外承诺必须精确到运行档位、平台和已开放能力。
