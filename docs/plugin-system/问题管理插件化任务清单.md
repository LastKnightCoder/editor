### 调查结论

- 写入链路：SDK `PluginHost`（`packages/plugins/src/host.ts`，参数校验与权限）→ 渲染端适配 `apps/desktop/src/app/plugins/data.ts` / `entities.ts`（ContentRef 解码）→ 主进程 `tables/plugin-data.ts` 的 `create` / `editContent`、`tables/plugin-entity.ts` 的 `create`。Markdown 由 `services/content-conversion.ts` 转换；装有内容插件时交给渲染进程内容执行器，主进程不加载插件代码。
- 文档待办身份：doc-tasks 索引在每次正文写入（`onContentWritten`）后调用 `ContentTable.ensureTaskIds`，补齐缺失或同文档内重复的 taskId；待办身份按「正文 ID + taskId」区分，跨文档相同的 taskId 不冲突。宿主已在所有写入上维护该不变量，正文输入无需另行重建。
- 未知节点：编辑器 ER-006 规定 kit 未注册的元素类型按 void 处理、数据原样保留（`packages/editor/src/core/kit/extensionGuard.ts`、`ElementGuard`）。已卸载插件的节点因此会留在正文里。
- 宿主现有的「复制正文」（插入到项目的 copy 模式）就是深拷贝节点后新建正文；`buildCardFromContent` 是共用正文（投影），不是复制。
- 依赖面：仓库内与 `../tau-plugin-*` 中没有插件调用卡片 / 文章新建或 `content.edit` 的 `markdown` 字段（每周回顾只用不带正文的 `entities.create`）；作者文档 `scripts/plugins/template/docs/user-data.md` 与夹具 `scripts/plugins/fixtures/author-contract-check.ts` 需同步。

### 决策

- **不按类型白名单拒绝节点**（偏离 81 第 4.1 节原文）：拒绝未注册类型会让「读 nodes → 写 nodes」在含已卸载插件节点的正文上失败，与 ER-006 的保真原则相反，也违背 `nodes` 无损的初衷。宿主只做结构校验：顶层为元素；元素有非空 `type` 与非空 `children`；文本节点有字符串 `text` 且没有 `children`；限制深度与总大小。未知类型按 ER-006 原样保留。
- **不单独重建 taskId**（细化 81 第 4.1 节）：由 doc-tasks 索引的 `ensureTaskIds` 统一处理，见调查结论。
- **闪卡不并入 `PluginContentInput`**（偏离 81 第 4.1 节原文）：闪卡的 `content` 是 AI 生成的素材，`generate` 会把由素材生成的草稿交回插件。若接受 `copyOf`，插件不经读取授权就能拿到他人正文的衍生内容，违背「copyOf 只需目标写权限」的前提（正文不离开用户的库）。闪卡保留 `string | Descendant[]`，引用正文继续走需要读取授权的 `references`。
- **字段命名**：新建接口的正文字段统一为 `content?: PluginContentInput`，替换原 `markdown`；`content.edit` 的 `append` / `prepend` / `replaceAll` 改为 `{ op, content }`。`replaceText` 是 Markdown 文本层面的查找替换，保留 `{ op, find, markdown }`。产品未发布，不保留旧字段（D-091）。
- **空正文**：新建与 `replaceAll` 允许空（得到一个空段落）；`append` / `prepend` 要求非空。
- **`copyOf` 来源范围**：来源须为卡片、文章、项目文档或任一插件实体的正文（与 `content.read` 可寻址的范围一致）；只核对目标写权限，不核对来源读权限（PS-046）。
