# 插件体系决策记录

使用 PS 编号保存背景、选择、理由、影响和验证。状态为已确认约束、待验证提案、已采用、已替代。用户确认目标不等于确认所有技术细节；提案进入实现前需补调查依据与验收，不为普通实现选择反复请求授权。

## PS-001 最终目标与验证样本

- 日期：2026-10-13。
- 状态：已确认约束，来自用户明确说明。
- 目标：设计架构合理、可扩展、安全的插件体系。
- 选择：微信读书只是验证例子，与编辑器、数据库、白板、页面和后台任务共同检验架构。
- 影响：不能将“微信读书迁移完成”等同于“插件体系完成”，不能按它的表结构和网关协议定义整个宿主 API。
- 验证：阶段计划包含多场景退出条件，公开能力有实际消费者和边界反例。

## PS-002 文档驱动与可用提交

- 日期：2026-10-13。
- 状态：已确认约束，来自用户的长期任务要求。
- 选择：保存现状、计划、决策、规范、执行过程和踩坑；逐步实施并依次本地提交，每次提交完整可用。
- 影响：代码与文档同批更新；近期精细拆分，远期只定依赖及验收。发布、推送和自动调度不包含在普通本地提交中。
- 验证：每次提交有可用行为、检查记录、遗留问题和恢复方法，不依赖后续提交修复已知阻断。

## PS-003 安全边界先于第三方开放

- 日期：2026-10-13。
- 状态：待验证提案；安全目标已确认，具体运行载体待 C01 裁决。
- 候选：全部同进程、全部隔离、多运行档位。
- 推荐：受限运行环境承担可代理能力，受信任档承担必要的同步深度界面扩展；两者共享能力语义，不伪装成相同安全保证。
- 理由：同环境任意 JS 可绕过门面；同步渲染、编辑行为和手势也不适合一律逐次 RPC。
- 影响：P2 必须有隔离样本和绕过测试；不把安全推迟到市场上线。
- 待验证：具体 Electron 承载、会话与来源策略、网络封锁、资源终止、各平台成本。

## PS-004 渐进契约与现有领域内核

- 日期：2026-10-13。
- 状态：待验证提案。
- 推荐：统一应用插件生命周期，复用现有编辑器、数据库、白板扩展协议，再按领域适配；服务通过上下文注入。
- 理由：已有领域机制承担文档和交互语义，另建三套内核会扩大风险。
- 影响：公开接口不直接等于内部接口全集，不一次创建无消费者 SDK。
- 验证：多个实例可独立运行；深层导入被禁止；不同领域退出后的数据均可保真。

## PS-005 数据身份与一致性

- 日期：2026-10-13。
- 状态：待验证提案，保持既有行为是实施约束。
- 推荐：业务迁移先改访问边界，保留原 ID 和事实源；通用私有存储单独设计；公共实体走领域服务。
- 理由：微信读书现有缓存与摘录共用事务，直接拆库会改变一致性。
- 影响：同库受控批量提交与独立库 outbox 在 P3 根据整体存储目标比较，不因单个样本强行选型。
- 验证：幂等、失败回滚、来源删除、引用保留、切库迟到写入和数据恢复。
