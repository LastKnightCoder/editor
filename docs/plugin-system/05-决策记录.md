## PS-007 身份和可撤销能力

- 日期：2026-10-13。
- 状态：后续隔离与宿主接线的设计方向。当前 C02 仅实现可信代码的插件/工作区作用域和 AbortSignal，未实现下述通信身份链。
- 选择：安装身份由宿主确定；运行实例绑定 WebContents、精确 frame、session、generation、工作区会话与授权版本。固定 IPC 信封只接受允许操作，不接受自报 owner 扩权。
- 理由：库名、窗口 ID、消息中的 pluginId 均不能独立代表当前授权；异步完成时身份可能已经失效。
- 影响：接受请求和提交写入时复核，正常停用、强制撤权、已提交结果分别处理；多窗口共享工作区后台实例。
- 验证：伪造身份、旧 frame、迟到结果、同名库重开、撤权和重复请求测试。存量工作区的持久 ID 映射留在 P3，不能把会话句柄直接持久化。

## PS-010 第三方默认受限并允许显式高信任授权

- 日期：2026-10-13。
- 状态：用户已明确确认，替代 C01 的“首期可信档仅内置”建议。
- 选择：第三方默认在受限档运行；用户明确授权后，可以进入高信任档。安装、声明能力或受限加载失败均不得自动提升信任等级。
- 授权语义：由宿主可信界面说明同环境代码不能被细粒度权限可靠约束；默认取消，不预选、不从插件提供的布尔值或 manifest 自行授予。拒绝后保持受限档；不支持受限档的功能明确不可用。
- 技术约束：授权绑定安装身份与具体代码版本/完整性摘要；换发布者或更新代码不能静默沿用旧版本高信任授权。授权记录与插件私有存储隔离，撤销后禁止再次启动；已执行的同环境代码可能需要重启宿主才能可靠清除，不声称撤销会回滚既有副作用。
- 范围：经 PS-012 调整，C02 只实现宿主显式登记的可信开发样本；高信任启用界面及第三方接线按后续领域/安装阶段实施，不存在从受限失败自动提权的入口。

## PS-016 编辑器贡献复用现有协议，首个消费者限定开发台

## PS-022 C08-A 有界生命周期与重启隔离

- 日期：2026-10-14；范围：可信宿主的异常生命周期收口，不改变作者 create/activate/deactivate/Disposable 契约。

## PS-041 视频提供方返回播放源描述

## PS-046 问题管理插件化：宿主能力开放的判定标准与统一正文输入

- 日期：2026-10-21。状态：已确认约束（标准与权限）+ 待验证提案（接口形状），方案见 81。
- 判定标准：宿主把自身对象与界面能力开放出去即为地基（新建卡片弹窗、插入到项目、新建 Notebook、发起对话等），与用到它的功能数量无关；接口中藏着某个插件概念或交互特例的为补丁，不进入 SDK。判断问句：删掉问题模块后接口是否仍说得通。
- 依赖方向：番茄钟、闪卡、漫步等核心功能之间照常直接协作，不经插件扩展点，也不用来给扩展点做自用检验；扩展点只给插件用，本次只拆除指向问题模块的依赖。
- 正文写入统一为 `PluginContentInput`：`markdown`、`nodes`（宿主规范化、重建身份字段、拒绝未注册类型，导出节点结构版本）、`copyOf`（宿主内部无损复制）。`copyOf` 只需要目标写权限，不需要来源读权限，因为正文不离开用户的库、插件拿不到内容。
- 接受功能丢失：发布站问题页、CLI 问题命令、命令面板自动识别问句、材料引用计数保活。
- 追加确认：实体与记录分为两个概念（用户可见可打开的为实体，插件内部数据为记录）；`project.insertDocument` 暂不开放共用正文；存量迁移前自动从插件中心安装并启用问题插件，失败不删旧表、下次启动重试，避免迁入数据被卸载宽限回收。

## PS-047 媒体资源与富块能力开放

- 日期：2026-10-21。状态：已确认约束（按通用能力设计）+ 待验证提案（接口形状），方案见 82。
- 起因是画廊插件化；判断问句沿用 PS-046：删掉画廊后接口是否仍说得通。
- 开放资源层（`useResource` / `useResourceUpload`，按编辑器作用域生效，遵守用户缓存设置，语义为解析文档资源引用而非任意路径读取）与默认媒体组件（`MediaImage` / `MediaVideo` / `MediaAudio`），作者可完全重写。
- 节点资源用 `ElementSpec.resources` 纯数据声明，宿主导出、灯箱、EPUB、协作、插件文档与 CLI 统一读取，删除按类型写死的分支。
- 编辑器提供通用 `useElement` 与 void 块外框，`useSourceBlock` / `useInlineSource` 改为其封装；不开放 slate、react-dnd。
- 不扩大改造范围：外框等新能力只给插件块用，内置块只补 `resources` 数据声明，本次只拆画廊；不加载插件的端沿用现有未知节点占位，文案不露出类型名。
- 追加确认：协作层只认 `resources` 声明，删除按字段名推断的 `RESOURCE_FIELDS`，资源字段由节点声明方负责；声明随协作文档元数据传递，并随库保存供主进程读取。协作包里写死的 `SOURCE_FIELDS` / `PRIVATE_BLOCKS` 属同类问题，另立条目。
- 实施调整（M1）：外观默认值不做编辑器根节点 CSS 变量（内核无该机制），改为 `useMediaAppearance()` + 编辑器服务 `IMediaAppearance`；桌面资源解析抽为共享的 `resolveMediaSource`，内置 LocalImage / LocalVideo / LocalAudio 与 `useResource` 共用；上传不带 `kind`。
- 实施调整（M2a）：声明与遍历工具放在最底层的 `@tau/db-schema/content-resources`（服务端、主进程、CLI 都依赖它，协作服务器不依赖编辑器）；声明增加 `preview` / `alt` / `caption` 同层字段；协作文档以 `resources` 映射携带声明，已有声明不覆盖；随库表 `plugin_element_resources`。
- 实施调整（M2b）：外框按键用 `keys`（键 → 命令 id）声明，不开放回调；媒体查看器为 `useMediaViewer(element)` hook；`useSourceBlock` 的 `update` 保持无守卫，只有 `useInlineSource` 改建在 `useElement` 上。
