# C08-B 开发插件持久管理

基线 `b5d1e6c4f`，2026-10-15。补齐开发包登记、启用意图、重启/切库恢复与移除；继续沿用 C08-A 的有界生命周期。仅可信桌面开发环境，微信读书继续暂停，代码重载归 C09。

## 身份与存储

现有数据库以本机名称定位文件，没有独立身份或改名入口。插件管理在 Electron userData 的 `plugin-development/registry.json` 中按去掉末尾 `.db` 的库名分配 UUID；包目录、静态 manifest、enabled 与 starting 按该工作区存储。工作区之间的登记与启用意图独立，不是生产全局安装目录。

UUID 是本机槽位身份。正常重启、重连与同名同步替换保持身份；开发构建通过设置页删除库前先解除映射，新建同名库得到新 UUID。应用外直接替换同名文件仍视为同一槽位，手动改名视为新槽位；不根据文件内容或 inode 猜测血缘，也不承诺跨设备同步插件配置。生产构建没有开发插件管理能力，本轮不为生产数据库删除增加开发登记处理。

私有偏好继续使用现有浏览器存储适配器，以 UUID 分域。已有 C07/C08-A 的库名偏好先复制全部至 UUID，已有目标值优先，复制成功后才删除旧键；写入失败保留源数据，可重试。移除插件不清除偏好；删除库解除管理映射也不删除旧 UUID 的插件偏好。

主进程串行读取、修改、写临时文件并 rename；拒绝损坏或不支持的登记格式，不覆盖它，也不返回成功。登记文件损坏需修复或备份移走该文件后重启，原作者目录与偏好不受影响。此机制面向单个应用主进程，不支持同时启动多个开发应用进程共享同一 userData 写入。

## 管理与恢复

1. 选择目录：原生目录选择器授权读取，清单/路径/摘要校验后保存，默认停用；内置 ID 和重复 ID 被拒绝。
2. 启用：先持久化 enabled=true、starting=true，再执行登记快照；成功后保存 starting=false。开始前落盘失败不执行代码；成功确认落盘失败则收回贡献，保留未完成标记。
3. 停用：先保存关闭意图，再走原宿主清理；清理失败仍遵守 restart-required，不能以切库/重新登记绕过当前窗口隔离。
4. 重启/切库：重新读取已登记目录，按原清单和摘要核对；缺文件、版本/身份或摘要变化保留不可用记录，不自动执行。starting=true 表示上次未完成启动，保留管理并跳过自动启用。
5. 移除登记：保存关闭意图、回收贡献、删除记录、注销定义。写入失败保留已停用记录以便重试。只解除本工作区的登记，保留作者目录、构建文件和私有数据。

停用再启用执行当前内存快照，不读取新代码。更新构建目前需要移除登记并重新选择；自动接受目录中的新内容不是恢复流程的一部分。

恢复启动可在仓库根执行：

```sh
TAU_DISABLE_DEV_PLUGINS=1 pnpm --filter desktop dev
```

这次启动只跳过外部开发包的自动启用，仍展示管理记录，可停用或移除故障包。它不清除已保存的启用意图；取消该变量后，正常记录仍按意图恢复。同步失控发生在激活期时，先落盘的 starting 可防止下次自动重演；激活成功后的任意同环境副作用仍需用恢复启动跳过。这里没有安全沙箱。

每个工作区只允许一个窗口管理开发包，第二个窗口保留正常应用但提示管理已被占用，需关闭占用窗口后重新进入工作区。主进程会话 token 绑定窗口与 UUID，关闭/切库后旧令牌失效；窗口销毁也释放占用。不是跨窗口后台任务单例框架。

## 分层

- `src/types/plugin-development.ts`：IPC 两端共用的纯数据契约，不放在渲染壳层。
- `src-electron/main/services/plugin-registry.ts`：登记文件、UUID 映射与恢复校验。
- `src-electron/main/modules/plugin-development.ts`：开发环境检查、窗口会话、目录选择与 IPC。
- `src/app/plugins/development-manager.ts`：持久意图与宿主启停的编排、旧偏好迁移。
- `PluginHost`：继续只管理实例/贡献，不知道文件目录与登记文件。

## 验证与恢复

单测覆盖串行写入、重启重读、库别名/隔离/退役、文件缺失及重新签摘要的内容变化、损坏登记、写入失败、启动标记、跳过启动、移除失败重试、旧会话拒绝和偏好迁移失败。

`node scripts/plugins/verify-external.mjs` 在临时仓库外构建两个插件，使用相同临时 profile 顺序启动四个独立 Electron 进程：首次加载和保存 → 重启自动恢复并从真实管理按钮移除/重新登记 → 再次重启确认停用意图 → 跳过自动启动。验证作者文件保留、原计数恢复和 CSS/贡献清理；只替换原生目录对话框的选择结果，不进行视觉走查。

实际类型、行为、构建与门禁结果见 [执行日志](06-执行日志与问题.md)。回退代码不会删除登记 JSON 与 UUID 偏好；回到 C08-A 后需重新选择目录，旧代码不认识新 UUID 偏好。需要完整回退偏好时应先备份当前 localStorage 并按登记文件映射回原库名，不能声称纯代码回退会自动恢复旧存储键。下一步 C09 手动重载与失败恢复，G1 整体验收仍在 C10。
