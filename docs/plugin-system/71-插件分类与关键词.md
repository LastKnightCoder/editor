# 插件分类与关键词

2026-10-19。为插件中心（门户网站与桌面「发现」页）增加按分类筛选和关键词搜索。决策见 PS-039，替代 [38](38-C21插件中心与已安装管理.md) 中「分类不展示」的约定。本文是设计稿，尚未实现。

## 现状

- manifest（`packages/plugins/src/package.ts`）没有分类、标签或关键词字段；`validatePluginManifest` 重建对象，未知字段会被丢弃。
- 门户 `/v1/catalog` 只支持 `q` 子串搜索（pluginId + name + description）和三种排序，没有筛选维度；`releases` 表无分类列。
- 桌面发现页请求时固定传空 `q`，在前端用 `matchesQuery` 过滤；目录单页最多 50 条，插件增多后前端过滤会漏结果。
- 桌面详情页已有运行时贡献清单（`PluginDetailView.tsx` 的 `contributions`：侧边栏入口、命令、设置分组），仅在插件激活时展示。
- 能力分两类：`PluginDefinition` 上的静态声明（editorExtensions、whiteboardExtensions、editorCodecs、skills、ai.features），以及 `activate(ctx)` 中的运行时注册（sync、upload、tts、images、mcp、chat、pages、sidebar、commands、settings 等）。博客模板在 `codex/blog-template-plugin` 分支，是带 `template` 字段的独立 manifest 变体（`TemplateManifest`）。

## 分类词表

分类按插件中心提供的扩展点划分，而不是预先设想的业务门类。一个分类可以涵盖多个扩展点；SDK 新增面向用户的扩展点时，在同一提交里扩充词表。

| ID              | 显示名   | 涵盖的扩展点                                                 | 当前插件                                  |
| --------------- | -------- | ------------------------------------------------------------ | ----------------------------------------- |
| `sync`          | 同步     | `ctx.sync`                                                   | S3、OSS、WebDAV、GitHub                   |
| `upload`        | 资源上传 | `ctx.upload`                                                 | 拆分中                                    |
| `editor`        | 编辑器   | `editorExtensions`、`editorCodecs`                           | TikZ、Typst、ABC、HTML、自定义组件块      |
| `whiteboard`    | 白板     | `whiteboardExtensions`                                       | 火柴人                                    |
| `blog-template` | 博客模板 | `template` manifest                                          | 待 blog-template 分支合入                 |
| `ai`            | AI       | `skills`、`ctx.mcp`、`ctx.chat`、`ai.features`、`ctx.images` | 图片生成与编辑，及附带 Skill 的编辑器插件 |
| `voice`         | 语音     | `ctx.tts`                                                    | 拆分中                                    |
| `page`          | 页面     | `ctx.pages`、`ctx.sidebar`                                   | 微信读书                                  |

不作为分类：

- 命令、设置项：只是功能入口，用户不会为找「提供命令的插件」而筛选；在详情页「此插件提供」中列出。以命令为主体的插件可以不选分类，通过「全部」和搜索触达；同类插件达到一定数量后再评估是否增设分类。
- `storage`、`fetch`、`services`、`register`：底层能力，详情页也不展示。

## Manifest 字段

```json
{
  "categories": ["editor", "ai"],
  "keywords": ["LaTeX", "绘图"]
}
```

- `categories`：可选，字符串数组，取值来自词表，去重，可多选也可不选。由作者填写；宿主不试跑、不对照实际注册做强制校验。
- `keywords`：可选，最多 5 个，每个 1–20 字，去重，只参与搜索匹配，不在界面上作为标签展示。
- 普通插件 manifest 与模板 manifest 使用同一对字段；模板作者填 `blog-template`。

校验分两档，避免新增分类时老客户端拒收新插件：

- 门户上传：严格校验，未知分类 ID 直接报错，便于作者发现拼写错误。
- 客户端 `validatePluginManifest`：未知分类 ID 静默丢弃，其余规则一致；目录展示以门户返回为准。

## 门户

- 数据：`releases` 增加 `categories`、`keywords` 两列（JSON 文本），上传时从 manifest 提取，与已有的 name/description 一致按版本存储；目录取最新发布版本的值。
- 审核：审核页展示作者填写的分类与关键词；不合适时用现有「要求修改」流程退回，不提供审核人直接改写。
- 接口：`GET /v1/catalog` 增加 `category` 参数（单值）；响应条目增加 `categories`；响应顶层增加各分类计数 `categoryCounts`（不受 `category` 参数影响，受 `q` 影响）。`q` 的匹配范围加入 `keywords`。
- 网站：列表页顶部按钮组展示有插件的分类及数量，选中写入 URL `?category=`；卡片显示全部分类，第一个为主分类。

## 桌面端

- 发现页：排序旁增加「分类」按钮 + Menu（不用 Segmented），一次单选，计数为 0 的分类隐藏；分类筛选与搜索改为服务端参数，不再前端过滤。
- 卡片：显示插件全部分类。
- 详情页「此插件提供」：继续按运行时实际注册统计，扩充为页面、侧边栏入口、命令、设置分组、同步方式、上传方式、语音、图片、MCP、Skill、编辑器节点、白板扩展；作者填写的分类与之无关，填错也不影响该清单的准确性。
- 功能处直达入口（另行确认范围后再做）：如同步设置的「更多同步方式」、博客模板选择处的「更多模板」，跳转插件中心并预选对应分类。

4. 现有 11 个官方插件补填 `categories`/`keywords` 并重新发布；blog-template 分支合入后为模板补填。
