# 裁决规则

跨任务长期有效的通用裁决，按主题分节、无编号；规则变化原地改写，被推翻即删。任务内的技术方案与过程决策跟任务走（见 [tasks/README.md](/docs/tasks/README.md)），不进本清单。

## 交互与反馈

- 破坏性操作优先「Toast 撤销」而非确认弹窗；确认框只留给不可撤销的高危动作。
- primary 实心按钮每屏至多一枚——层级是评审纪律，不进组件 API。
- 未知节点、未知数据原样保真，不静默丢弃或剥离；旧端读到按未知规则呈现，恢复能力后仍能解释原数据。
- AI 能力零配置：配置了模型即视为同意使用，不另设开关、预算或隐私提示。
- AI 生成的标题用户无感知，不提供手动改标题。
- 升级公告每版必备，升级前后都能看到。

## 主题与样式

- 桌面端与移动端共用 `@tau/themes` 一套主题（主题族 × 浅色/深色/跟随系统、同一取值、同一首帧脚本与偏好存储）；任何端不得另建主题或颜色变量，端差异只保留布局尺度（圆角、触控密度、字号）。
- 风格以桌面为准：主色纯色实底，不用渐变、彩色光晕阴影和全屏纹理；主色/标签实底上的文字用 `ink-inverse`，不写死白色。

## 数据语义

- 正文是唯一真相源；待办、索引等派生数据都是可重建的投影。
- 删除优先走「最近删除」可恢复（7 天宽限），而非硬删。
- 数据升级失败不放行；全部转换完成后的版本拒绝旧格式并删除历史转换代码，不长期保留兼容层。
- 列表展示按 LIMIT/窗口渐进拉取，不为展示全量拉大表。
- 桌面端与移动端都有的设置项在 setting.json 里用同一键名与同一语义；端上行为变化通过升级改写取值，不另起新键（为 setting.json 跨端同步留路）。

## 插件开放

- 插件使用一个 SDK、一套作者模板与同一个跨端身份；公共逻辑和数据模型共用，平台差异明显时允许独立视图，不以平台拆分正文节点类型。
- 同步文件的分块、清单、校验和重组属于宿主，两端共用格式；提供方只存取对象，公网直链上传保持完整资源语义。
- 同步与上传插件在桌面和移动使用同一套 API；作者只表达注册、保存与存储意图，持久化、选用和任务管理由宿主决定。两端可使用独立视图；账号分别归各插件配置，不做统一账号共享。
- 页面声明与功能入口分离：作者声明功能语义，宿主决定桌面侧栏或移动功能列表的呈现；桌面专属 API 不静默映射成移动支持。
- 插件环境由宿主显式提供，作者环境只表达平台与输入事实，布局由容器决定，API 兼容检查留在宿主加载链路；静态内容组件不依赖 activate 或全局缓存 context。
- 插件作者通过统一 API 注册实际功能；清单只声明身份、平台、最低版本和数据权限，不另列宿主能力、服务依赖或重复的正文/白板贡献。产品正式发布前的插件契约统一修改，不保留旧客户端、旧清单的适配分支或兼容空字段；宿主不得按具体插件 ID 实现业务分支。
- 编辑器标准交互由宿主适配，插件内部特殊交互由作者负责；显示、插入、编辑分别验证，只读展示不等于完整移动兼容。

- 文档声明的能力不得隐式授予代码执行权；执行类能力须显式声明与逐版本授权。
- 插件对业务数据与正文的读写经运行时授权（manifest 声明 + 调用时弹窗 + 详情页可撤销），这是 API 闸门不是安全隔离。
- 插件作者从两个入口获取能力：产品/领域 API 走 `@tau/plugins`，UI 组件走 `@tau/ui`。
- 插件内容的删除走可恢复快照，与宿主实体同体验；宿主核心功能之间不经插件扩展点。

## 工作方式

- Agent 不做视觉验证（截图对照、浏览器走查），视觉验收由用户完成；视觉问题记录后按 bug 修复，不阻塞架构工作。
- 每次提交保持应用完整可用，不以「未接线接口 / 等待后续修复」作为交付。
- 接口稳定前不发布公共 npm 包；发布与验收记录以实际验证为准。
