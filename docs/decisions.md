# 裁决规则

跨任务长期有效的通用裁决，按主题分节、无编号；规则变化原地改写，被推翻即删。任务内的技术方案与过程决策跟任务走（见 [tasks/README.md](/docs/tasks/README.md)），不进本清单。

## 交互与反馈

- 破坏性操作优先「Toast 撤销」而非确认弹窗；确认框只留给不可撤销的高危动作。
- primary 实心按钮每屏至多一枚——层级是评审纪律，不进组件 API。
- 未知节点、未知数据原样保真，不静默丢弃或剥离；旧端读到按未知规则呈现，恢复能力后仍能解释原数据。
- AI 能力零配置：配置了模型即视为同意使用，不另设开关、预算或隐私提示。
- AI 生成的标题用户无感知，不提供手动改标题。
- 升级公告每版必备，升级前后都能看到。

## 数据语义

- 正文是唯一真相源；待办、索引等派生数据都是可重建的投影。
- 删除优先走「最近删除」可恢复（7 天宽限），而非硬删。
- 数据升级失败不放行；全部转换完成后的版本拒绝旧格式并删除历史转换代码，不长期保留兼容层。
- 列表展示按 LIMIT/窗口渐进拉取，不为展示全量拉大表。

## 插件开放

- 文档声明的能力不得隐式授予代码执行权；执行类能力须显式声明与逐版本授权。
- 插件对业务数据与正文的读写经运行时授权（manifest 声明 + 调用时弹窗 + 详情页可撤销），这是 API 闸门不是安全隔离。
- 插件作者从两个入口获取能力：产品/领域 API 走 `@tau/plugins`，UI 组件走 `@tau/ui`。
- 插件内容的删除走可恢复快照，与宿主实体同体验；宿主核心功能之间不经插件扩展点。

## 工作方式

- Agent 不做视觉验证（截图对照、浏览器走查），视觉验收由用户完成；视觉问题记录后按 bug 修复，不阻塞架构工作。
- 每次提交保持应用完整可用，不以「未接线接口 / 等待后续修复」作为交付。
- 接口稳定前不发布公共 npm 包；发布与验收记录以实际验证为准。
