# 裁决规则

跨任务长期有效的通用裁决，按主题分节、无编号；规则变化原地改写，被推翻即删。条目一两句话，只写「必须遵守什么」——判据、正反例与实现细节归架构文档和对应指南，任务内的过程决策跟任务走（见 [tasks/README.md](/docs/tasks/README.md)）；AGENTS.md 已全文收录的领域细则不再重复收录。

## 交互与反馈

- 破坏性操作优先「Toast 撤销」而非确认弹窗；确认框只留给不可撤销的高危动作。
- 提示只有 `@tau/ui` 一套 toast：各端只挂宿主并选外观，不另写提示队列；移动端 `components/toast` 仅为保留调用形态的适配层。
- 会清除派生数据的选用与浏览分离：切换 Tab、展开、下载、配置都不改变当前选用，只有显式「设为当前」并确认后才写设置，没有默认选中。
- primary 实心按钮每屏至多一枚——层级是评审纪律，不进组件 API。
- 未知节点、未知数据原样保真，不静默丢弃；旧端按未知规则呈现，恢复能力后仍能解释原数据。
- AI 能力对用户无感运转：配置了模型即视为同意使用，不另设开关、预算或隐私提示；AI 生成的标题不提供手动修改。
- 升级公告每版必备，升级前后都能看到。
- 同一种编辑能力两端用同一实现，端差异只在承载方式（原地编辑或独立源码页），不为某一端另换编辑内核。
- Agent 改正文默认落成逐条建议：对话内展开、接受、撤销或继续修改，打开的正文同步显示修订痕迹；权限按「Agent × 正文」授只读 / 建议 / 直接改，直接改实时落地、人进入它正在改的块即让出、事后按次撤销。
- 伴随型工作面（浏览 + 对照 + 偶发动作，如编辑历史）用纸内「页边注」面板呈现，不做盖住正文的模态；模态只留给决策。

- 白板上方向键只用于移动选中元素；卡片级的翻页等动作用其他键（如 PDF 卡的 `[` `]`），不和移动抢方向键。

## 主题与样式

- 两端共用 `@tau/themes` 一套主题与颜色变量，端差异只保留布局尺度（圆角、触控密度、字号）；任何端不得另建主题。
- 正文字体只用于「内容」：文档正文、详情页标题区、卡片形态的标题与摘要；导航、Tab、按钮、设置、输入框、行式列表与元信息保持系统字体，不做全应用统一。
- 风格以桌面为准：主色纯色实底，不用渐变、彩色光晕阴影和全屏纹理；实底上的文字用 `ink-inverse`，不写死白色。
- 插件设置归宿主：设置组件放进宿主卡片、插件只写内容；需要校验或副作用的保存走草稿 + 宿主悬浮保存条，插件不自带 Panel、卡片边框或保存按钮。

## 数据语义

- 被持久引用的实体编号在正常新建时不得复用已提交后删除的编号；主库独立整数主键用 SQLite `AUTOINCREMENT`，不按 `MAX(id)+1` 分配。
- 个人助手记忆只承载关于用户本人的经历、近期状态、观点与偏好：日记中的本人表达属于记忆来源，摘抄与通用知识归资料库检索，一时情绪与探索想法不升格长期性格或信念。
- 「暂停」与「退出」语义分开：暂停保留会话以便继续；退出先保存用户资料、再清除可重建状态，重开从已保存资料重建，不静默延续旧故障状态。
- 已发布版本的数据结构与协议是基线：结构变更必须保留已发布用户的打开路径与数据升级，版本标记不得作为开库拒绝条件；不支持的数据明确拒绝，界面偏好回默认值。设置文件例外：读取永不阻断启动，先备份再剔除不合规字段补默认值。代码清理不自动删除开发数据或云端资产。
- 正文是唯一真相源；待办、索引等派生数据都是可重建的投影。
- 正文会话与快照预览分工：实时跟随原文用正文订阅，大量列表用轻量快照；会话就绪前统一 Loading，不用旧正文占位，不把预览模式并进编辑器。
- 协作协议与接口退役不删历史账本，备份完整携带；历史仅供保全，不提供旧身份合并或格式转换。
- 本机存储与共享传输分开：插图先按作者自己的存储与压缩设置保存，共享只上传结果；成员插图统一上协作服务器，作者保存持久副本成功后才允许结束共享。
- 正文字数由扩展声明统计字段、宿主统一计数；零字数不等于空文档，自动清理必须独立判断并保留未知或结构化内容。
- 删除优先走「最近删除」可恢复（7 天宽限），而非硬删。
- 正文与白板只编辑当前数据格式；编辑历史支持用当前格式恢复旧版或撤销单次编辑，作为新写入按当前权限校验。插件数据版本升级、白板手动恢复与旧格式恢复不提供入口。
- 不因格式问题让用户打不开正文或白板：打开前先备份原始字节，再按当前声明自愈补齐写回，未声明的节点原样保留；较新客户端写入的版本与身份基线错位不修复，照常报错。
- 可重建的本机缓存（协作缓存、白板本机日志、输入草稿等）损坏、版本不符或与主库对不上时，备份原始字节到 `discarded/` 后静默丢弃重建，不以「暂停写入 / 拒绝覆盖 / 只读 / 手动继续」让功能停摆；严格拒绝只留给主库与服务端的权威数据。
- 列表展示按 LIMIT / 窗口渐进拉取，不为展示全量拉大表。
- 两端都有的设置项在 setting.json 用同一键名与语义；行为变化通过升级改写取值，不另起新键。

## 本机通道

- 本机端口上的外部客户端（浏览器扩展等）逐实例授权：Origin 只挡网页，身份靠用户一次性确认签发的 token（宿主只存哈希）；方法按授予的权限分发，绝不外发模型密钥等配置。

## 插件开放

- 移动插件页面的系统安全区归宿主：滚动区外固定预留、键盘弹出时收缩，插件在可用容器内布局吸底、不重复加安全区。规范见[作者文档](/plugins/tau-plugin-template/docs/ui.md#手机页面的布局边界)。
- 插件只有一个 SDK、一套作者模板、同一跨端身份与两个入口：能力走 `@tau/plugins`，UI 走 `@tau/ui`；公共逻辑与数据模型共用，平台差异明显时允许独立视图，不以平台拆分正文节点类型。
- 插件经统一 API 注册实际功能；清单声明身份、包类型、平台、最低版本、运行要求与数据权限。包格式版本只控制解析，已发布协议的读取兼容限于包边界，安装与运行不按历史格式复制实现；已发布 ZIP 与摘要不改写。
- 宿主不按插件 ID 或插件专属取值（语言、mode、是否居中等）写业务分支，只提供对所有块一致的通用机制；确需区分的由作者经 SDK 声明，内置块同样经声明接入。
- 宿主核心功能之间不经插件扩展点；扩展点是否属于地基，用「把对应模块删掉，这个接口还说得通吗」检验——宿主自己的对象与界面能力是地基，藏着插件概念或交互特例的是补丁。
- 页面声明与功能入口分离：作者声明功能语义，宿主决定桌面侧栏或移动功能列表的呈现；桌面专属 API 不静默映射成移动支持。
- 插件环境由宿主显式提供：作者环境只表达平台与输入事实，布局由容器决定；静态内容组件不依赖 activate 或全局缓存。
- SDK 能力以实际插件需求为依据，没有实际消费者不保留接口；正文扩展统一静态声明。
- 工具的展示名、模型调用名与内部身份分开：界面按领域展示，模型用可读命名空间，内部稳定键承担偏好与历史绑定。
- 插件校验只服务于安全、数据正确性与实际资源预算：按协议提取字段、忽略无关属性，不为删掉的声明加禁止规则，不凭空限制文案或集合数量。
- 插件的平台适配与测试由作者负责：审核与发行不承担平台测试，依赖升级不等于可安装，批次结果不累加成「全部兼容」；编辑器标准交互由宿主适配，插件内部交互作者自负，只读展示不等于完整移动兼容。
- 声明式 form 只覆盖字段能表达的配置；字段表达不了的交互（扫码登录、连接状态校验）保留作者组件，不为它们扩 schema。
- 文档声明的能力不得隐式授予代码执行权；执行类能力须显式声明与逐版本授权。
- 插件对业务数据与正文的读写经运行时授权（manifest 声明 + 调用时弹窗 + 详情页可撤销），这是 API 闸门不是安全隔离。
- 插件内容的删除走可恢复快照，与宿主实体同体验。
- 内置功能迁移到插件时，存量数据破例按插件 ID 写入（先备份、单事务）；全部设备迁移完成后随清洁版删除该破例。
- 同步的分块、清单、校验与重组归宿主，两端共用同一套 API，提供方只存取对象；云端提供方的数据库同步直接搬运 .db 文件——固定对象名覆盖、覆盖前备份、不做内容门禁与恢复包，版本冲突交用户确认，资源文件独立同步；账号分别归各插件配置，不做统一账号共享。

## 日志与诊断

- 客户端日志统一 session 粒度：每次启动一个 `session-*.log`，保留 3 天、单文件 10MB 轮转；console 劫持后经宿主落盘（debug 不落盘），不为某一端另起日志框架或文件格式。

## 代码风格

- console 就是 logger：业务代码直接写 console.* 即进日志体系（electron-log / Tauri app_log），不另起日志实例；清理 console 调用前先确认不是运维日志。
- SQLite 行类型统一走 `SqliteRow`（`src-electron/main/types/table.ts`），表模块 parse 内逐字段断言；不写 `as any[]` 与 `parse(row: any)`。
- 列表 / 索引类查询失败不得静默返回空集合蒙混为「没有数据」：降级可以，必须 log.warn 留痕（首次运行无文件等预期路径除外）。
- 新建 shared / 公共实现后旧副本当批回收（消费者清零即删），不留平行实现漂移；公共 API 只导出有真实跨模块消费者的符号。
- 非空收窄优先于 `!` 断言；理论不可达路径写显式 throw（中文错误信息）。
- 跨层类型转换走命名映射函数（样板 `packages/ai/src/session/convert.ts`），不写 `as unknown as` 焊接；确需 any 的边界行内标注理由。
- 巨类拆分用门面 + 域文件，委托存根同步透传（禁 async 存根），跨方法调用经实例派发保测试 spy；拆分先于抽象，真同构才工厂化。
- 持久化 JSON key 改名必须读兼容旧 key 并靠自愈管线回写；文件名大小写改动走两步改名并在提交后 `git ls-files` 终检。
- oxlint 的 `no-explicit-any` 与 `no-non-null-assertion` 维持 warn 不升 error：生产源码已清零，剩余在测试与已标注边界；升 error 的前置是清掉测试存量。
- 判据与正反例详见 [代码风格规范](/docs/guides/dev-code-style.md)。

## 工作方式

- 启动流程变化必须同步更新生产验收判据：模块初始化、渲染提交与业务前置条件分别确认，捕获后的启动失败同样使验收失败。
- 每次提交保持应用完整可用，不以「未接线接口 / 等待后续修复」作为交付。
- 接口稳定前不发布公共 npm 包；发布与验收记录以实际验证为准。
- 技术验证与产品交付分开：不以原型或接口存在推断产品入口可用；平台兼容问题先复现、给方案、与用户商议，不自行扩张旧版本兼容范围。
