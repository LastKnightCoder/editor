# 裁决规则

跨任务长期有效的通用裁决，按主题分节、无编号；规则变化原地改写，被推翻即删。任务内的技术方案与过程决策跟任务走（见 [tasks/README.md](/docs/tasks/README.md)），不进本清单。

## 交互与反馈

- 破坏性操作优先「Toast 撤销」而非确认弹窗；确认框只留给不可撤销的高危动作。
- 提示只有一套实现：`@tau/ui` 的 toast。各端只挂 `ToastHost` 并选外观（桌面浅色、移动端 inverse 深色胶囊），不另写提示队列；移动端 `components/toast` 只是保留调用形态的适配层。插件与公共包调用 `@tau/ui` 的 toast 在各端都能显示。
- 会清除派生数据的选用（如切换嵌入模型会重建索引）与浏览分离：切换 Tab、展开、下载、配置都不改变当前选用，只有显式「设为当前」并确认后才写设置；没有默认选中。
- primary 实心按钮每屏至多一枚——层级是评审纪律，不进组件 API。
- 未知节点、未知数据原样保真，不静默丢弃或剥离；旧端读到按未知规则呈现，恢复能力后仍能解释原数据。
- AI 能力零配置：配置了模型即视为同意使用，不另设开关、预算或隐私提示。
- AI 生成的标题用户无感知，不提供手动改标题。
- 升级公告每版必备，升级前后都能看到。
- 编辑器里同一种编辑能力两端使用同一实现（如源码与代码的输入都用原生输入框 + Shiki 高亮），端差异只在承载方式（原地编辑或独立源码页），不为某一端另换编辑内核。
- Agent 改正文默认落成逐条建议，在发起对话逐条展开、接受、撤销或继续修改，已打开的对应正文随对话选中的条目显示修订痕迹；权限按「Agent × 正文」给只读 / 建议 / 直接改，直接改实时落地、人进入它正在改的块即让出，事后按次撤销。

## 主题与样式

- 桌面端与移动端共用 `@tau/themes` 一套主题（主题族 × 浅色/深色/跟随系统、同一取值、同一首帧脚本与偏好存储）；任何端不得另建主题或颜色变量，端差异只保留布局尺度（圆角、触控密度、字号）。
- 正文字体只用于「内容」：文档正文、详情页标题区、卡片形态的内容标题与摘要；导航栏、Tab、按钮、设置、输入框、行式列表（图标 + 标题的索引行）与时间字数等元信息保持系统字体，不做全应用统一。
- 风格以桌面为准：主色纯色实底，不用渐变、彩色光晕阴影和全屏纹理；主色/标签实底上的文字用 `ink-inverse`，不写死白色。
- 插件设置的保存入口归宿主：需要校验或有副作用的设置用草稿 + `useSettingsDraft`，由宿主画悬浮保存条并在离开前确认；插件不再自画保存按钮。简单偏好可即时保存，提供方 form 在自带「修改自动保存」语义的容器里用 autoSave。
- 插件设置的容器归宿主：两端都把插件设置组件放进宿主卡片，插件只写内容，不自带 Panel 或卡片边框；桌面插件详情是一整张纸，卡片用细描边，不叠阴影卡。

## 数据语义

- 个人助手记忆承载关于用户本人的经历、近期状态、观点、价值取向和长期偏好；日记中的本人表达属于个人记忆来源，摘抄与通用知识仍归资料库检索，不把保存、导入或编辑资料直接当作兴趣、能力或学习成果。一时情绪与探索中的想法保留时间和不确定性，不直接升格长期性格或信念。

- 同时提供「暂停」和「退出」的功能，两者语义必须分开：暂停保留会话以便继续，退出先保存用户资料，再清除可重建的会话状态；再次开启从已保存资料重新建立，不能静默延续旧故障状态。

- 产品正式发布前以当前数据结构与协议为基线；数据库结构变更须保留已有用户的正常打开路径，版本标记不得作为开库拒绝条件，实际结构变化须提供保留数据的升级。其他不支持的业务配置与数据明确拒绝，可丢弃的界面偏好使用当前默认值；设置文件例外：读取永不阻断启动，先备份原文件再剔除不合规字段并补默认值，严格校验只用于写入。代码清理不自动删除开发数据或云端资产。

- 正文是唯一真相源；待办、索引等派生数据都是可重建的投影。
- 正文会话与快照预览保持单一职责：需要实时跟随原文的阅读场景使用正文订阅，大量卡片列表使用轻量快照；正文会话就绪前统一显示 Loading，不用旧正文作加载占位，也不把快照预览模式并入正文编辑器。
- 协作协议与接口退役不删除历史账本；服务升级原地保留设备、权限、回执与资源，备份完整携带历史记录。历史仅供保全，不恢复旧身份合并或格式转换操作；现有活动正文仍按当前协议校验。
- 本机会话与共享传输分开：普通正文和共享作者插图遵守作者的存储与压缩设置，共享时仅将本地结果上传协作服务器，公网 URL 直接使用；成员插图统一上传协作服务器，作者接收后按自己的配置保存持久副本，保存成功后才允许结束共享。
- 正文字数由扩展声明统计字段、宿主统一计数；零字数不等于空文档，自动清理必须独立判断并保留未知或结构化内容。
- 删除优先走「最近删除」可恢复（7 天宽限），而非硬删。
- 正文与白板只编辑当前数据格式，不提供插件数据版本升级或手动恢复入口。正常编辑、保存、协作同步和撤销重做保留。
- 不因格式问题让用户打不开正文或白板：读取与打开前自愈，先备份原始字节再按当前声明补齐写回，当前没有声明的节点或元素原样保留。正文覆盖缺身份、缺或错契约、无文档记录；白板覆盖主库检查点摘要或字节损坏，以及读不出或与主库分叉的本机日志。较新客户端写入的格式版本、身份基线错位不修复，照常报错。节点身份与契约对业务代码透明。
- 本机缓存（协作缓存、白板本机日志、输入草稿等可由远端或主库重建的数据）坏了、版本不符或与主库/服务器对不上，一律备份原始字节到 `discarded/` 后丢弃重建，不以「暂停写入」「拒绝覆盖」「只读」或要求用户手动继续让功能停摆，重建保持静默不提示。缓存文件里与内容无关的设置（设备身份、共享绑定）能读出的迁进新库。严格拒绝只留给主库与服务端的权威数据。
- 列表展示按 LIMIT/窗口渐进拉取，不为展示全量拉大表。
- 桌面端与移动端都有的设置项在 setting.json 里用同一键名与同一语义；端上行为变化通过升级改写取值，不另起新键（为 setting.json 跨端同步留路）。

## 本机通道

- 本机端口上的外部客户端（浏览器扩展等）必须逐实例授权：Origin 只用来挡网页，身份靠用户一次性确认后签发的 token（宿主只存哈希）；方法按授予的权限分发，绝不外发模型密钥等配置。

## 插件开放

- 移动插件页面的系统安全区归宿主：在滚动区外固定预留，键盘弹出时收缩；插件默认在可用容器内布局与吸底，不重复添加安全区。页面布局规范见[作者文档](/plugins/tau-plugin-template/docs/ui.md#手机页面的布局边界)。
- SDK 能力以实际插件需求为依据；没有实际消费者时不保留动态编辑器注册接口。正文扩展统一静态声明，命令、菜单和节点交互随静态扩展提供。

- 工具的展示名、模型调用名与内部身份分开：界面按领域展示，模型使用可读命名空间并遵守接口字符限制；内部稳定键承担偏好与历史绑定，不将摘要默认作为用户或模型可见的前缀。

- 插件使用一个 SDK、一套作者模板与同一个跨端身份；公共逻辑和数据模型共用，平台差异明显时允许独立视图，不以平台拆分正文节点类型。
- 同步文件的分块、清单、校验和重组属于宿主，两端共用格式；提供方只存取对象，公网直链上传保持完整资源语义。
- 云端提供方的数据库同步搬运 .db 文件：固定对象名直接覆盖，覆盖本机前复制一份到 backup/，不做内容校验、格式门禁或恢复包；版本冲突交给用户确认，资源文件走独立同步。
- 同步与上传插件在桌面和移动使用同一套 API；作者只表达注册、保存与存储意图，持久化、选用和任务管理由宿主决定。两端可使用独立视图；账号分别归各插件配置，不做统一账号共享。
- 页面声明与功能入口分离：作者声明功能语义，宿主决定桌面侧栏或移动功能列表的呈现；桌面专属 API 不静默映射成移动支持。
- 插件环境由宿主显式提供，作者环境只表达平台与输入事实，布局由容器决定，API 兼容检查留在宿主加载链路；静态内容组件不依赖 activate 或全局缓存 context。
- 插件作者通过统一 API 注册实际功能；清单只声明身份、平台、最低版本和数据权限，不另列宿主能力、服务依赖或重复的正文/白板贡献。产品正式发布前的插件契约统一修改，不保留旧客户端、旧清单的适配分支或兼容空字段；宿主不得按具体插件 ID 实现业务分支，也不按插件专属的取值（语言、mode、是否居中等）预设或推断行为；宿主只提供对所有块一致的通用机制；确需区分时由作者经 SDK 声明，内置块同样经声明接入。
- 插件校验只服务于安全、数据正确性与实际资源预算；按协议提取字段，忽略无关属性，不为删掉的声明增加禁止规则，也不凭空限制文案或集合数量。公开扩展字段由宿主提取后再交给内核。
- 编辑器标准交互由宿主适配，插件内部特殊交互由作者负责；显示、插入、编辑分别验证，只读展示不等于完整移动兼容。

- 文档声明的能力不得隐式授予代码执行权；执行类能力须显式声明与逐版本授权。
- 插件对业务数据与正文的读写经运行时授权（manifest 声明 + 调用时弹窗 + 详情页可撤销），这是 API 闸门不是安全隔离。
- 插件作者从两个入口获取能力：产品/领域 API 走 `@tau/plugins`，UI 组件走 `@tau/ui`。
- 插件内容的删除走可恢复快照，与宿主实体同体验；宿主核心功能之间不经插件扩展点。

## 日志与诊断

- 客户端日志统一 session 粒度：每次启动一个 `session-*.log`，保留 3 天、单文件 10MB 轮转；前端 console 劫持后经宿主落盘（debug 不落盘），不为某一端另起日志框架或文件格式。

## 工作方式

- Agent 不做视觉验证（截图对照、浏览器走查），视觉验收由用户完成；视觉问题记录后按 bug 修复，不阻塞架构工作。
- 每次提交保持应用完整可用，不以「未接线接口 / 等待后续修复」作为交付。
- 接口稳定前不发布公共 npm 包；发布与验收记录以实际验证为准。
