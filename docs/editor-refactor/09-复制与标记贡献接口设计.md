## 2. 复制贡献：先选择最窄可用接口

已核对的规则只需要决定“保留当前包装”或“解包为处理后的子节点”，没有需要扩展任意创建、删除、替换内容的消费者。因此第一版不开放任意 Descendant[] 转换器，也不复用日常 normalize。

已在 `ElementSpec<E>` 增加 `copy`，类型通过 `@tau/editor/api` 提供：

```ts
type CopyDecision = "keep" | "unwrap";

interface CopyContext<E> {
  readonly element: Omit<DeepReadonly<E>, "children"> & {
    readonly children: readonly DeepReadonly<Descendant>[];
  };
  readonly fullySelected: boolean;
  readonly ancestorTypes: readonly string[];
}

// ElementSpec<E> 的可选字段，DeepReadonly 仅表示递归只读结构。
copy?: (context: CopyContext<E>) => CopyDecision;
```

- element 是已处理子节点的**片段节点**，不是可写的原文档节点；ancestorTypes 来自原节点的真实祖先，顺序从外到内，不含自身。
- 实施确认：解包后的 children 不一定满足原元素的完整文档 schema，所以保留 E 的其他字段，children 显式放宽为只读片段；不能把它谎称为完整 E。
- 不传 Editor、Transforms、原文档对象或可变路径。回调同步、无副作用，不允许 Promise；不需要任意 schema、额外全局登记或新的插件生命周期。
- `keep` 保留片段节点的所有字段与已处理 children；`unwrap` 只提升其 children。回调不能借返回值删除文本、清 checked 或丢私有字段。
- 没有 copy 声明的节点是保留边界：保留其原始片段子树，不递归进入。需要“保留外层且允许内层规则”的容器显式提供 `copy: () => "keep"`。这保持现有未托管容器行为，也保护未知扩展的内部结构。
- 第一版只在有子节点的块元素提供该策略；void、行内和文本原样保留，不为没有消费者的 void 源码复制增加特殊协议。

### 2.1 原节点与片段的对应关系

**对应关系在任何规则执行前固定；解包后不得按新下标重新查原路径。** 核心内部为选中树建立 trace，保存原路径、祖先类型、完整选中与原始片段快照；这些信息不写入文档字段、不加 uuid。

实现约束：

1. 在调用原 getFragment 前保存选区与文档根引用；若调用改变了文档或选区，保留其返回片段，不再尝试领域修复。
2. 依据当前 Slate 的选区切片语义建立候选 trace。已核查 Slate 0.126.2 的 Node.fragment 使用 Range.includes、反向遍历与首尾文本裁剪；不能用宽松的 Range.intersection 或仅比较数量代替。
3. 用同一选区的标准 Node.fragment 结果核对实际原 getFragment 返回值。未注册的受信任插件若改写了片段，且无法证明一一对应，则整体保留原返回值，不按相同 type 猜配对。该比较是安全退路，不新增外部 trace 注入协议。
4. trace 与裁剪结果必须在选中子树上保持单调对应；任何路径无效、类型/内容不一致或映射失败均跳过修复。涉及 Slate 版本变化时重跑边界选区测试。
5. 执行先子后父；父策略看到的是处理后 children，但 fullySelected、ancestorTypes 始终来自原 trace。

以上已实现为内部 CopyTrace：全片段数据与标准 Node.fragment 核对后，按 Range.includes 固定原路径/祖先/完整选中状态，再执行规则。只读快照按一次复制建立，结构共享重建，不在每一层重复深拷贝整个子树；不全量遍历未选中文档。没有 copy 贡献时不包装 getFragment，片段根没有可处理策略时直接保留原结果。

### 2.2 失败、冲突与注册

- 策略由当前有效 ElementSpec 的所有者提供，沿用元素冲突/override 的现有选择规则，不新增 copy 优先级。一个类型只有一个有效 copy 策略。
- ExtensionAssembly 收集 owner 与策略。替换 defaultPlugins 中的旧复制处理，在现有插件/schema 与文档 binding.install 完成后，对实例的最终 getFragment 包装一次并接既有 breaker；服务派生复用 assembly，协作 rebind 不重复挂载。当前协作与文档绑定源码未发现额外 getFragment 改写，仍须在集成测试中守护次序。
- 候选片段与原文档、原返回值隔离。传给策略的快照在运行时也递归冻结，按共享对象集合一次处理，不能仅依赖 TypeScript readonly。策略只返回决定，核心用受保护的候选节点应用结果，不接受回调原地修改的内容。
- 成功后返回普通可编辑的独立片段，冻结不泄漏给粘贴调用方。Date/Map 等无法通过 freeze 限制内部修改的非数据对象、克隆失败或路径不确定时整体保留原片段，不调用策略，不计扩展故障。
- 抛错、返回非法值、返回 Promise 等属于贡献失败。整次修复放弃候选结果，回退到原 getFragment 片段，防止父级继续解包失败子树；不影响下一次正常复制。
- 新增 `copy` 错误阶段，接现有 reporter/breaker；一次复制同一 owner 最多计一次。已熔断 owner 在当前片段被访问时同样触发整次修复回退，避免部分策略缺失造成祖先误判。
- 无贡献、映射不确定不是扩展错误，不计熔断。复制入口不自行监听键盘、不接管剪贴板传输。
- 这是受信任扩展的错误隔离，不宣称通过不传 Editor 就能阻止插件闭包访问宿主；第三方安全隔离不在本轮实现范围。

### 2.3 现有领域规则的逐项对应

| 所有者/节点                                     | copy 决策                                                                                         |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| list-item                                       | fullySelected 且（原祖先有 list-item，或处理后的子节点存在非 paragraph 元素）则 keep；否则 unwrap |
| bulleted-list / numbered-list                   | fullySelected，或非空 children 全为 list-item，则 keep；否则 unwrap                               |
| check-list-item                                 | fullySelected 则 keep，保留 checked；否则 unwrap                                                  |
| check-list                                      | fullySelected，或非空 children 全为 check-list-item，则 keep；否则 unwrap                         |
| table-cell                                      | fullySelected 则 keep，否则 unwrap                                                                |
| table-row / table                               | fullySelected，或非空 children 分别全为 table-cell / table-row，则 keep；否则 unwrap              |
| highlight-block / blockquote / callout / detail | fullySelected 则 keep，否则 unwrap                                                                |
| 未声明 copy 的节点                              | 保留整棵片段子树，不穿透                                                                          |

首次接线后，复制贡献已随列表/表格/容器迁入对应包。完整块菜单复制仍保留整节点；剪切只在剪贴板写成功后删除的保护未改变。

## 3. 标记渲染：字段所有权与渲染组合

已在 EditorExtension 增加 `marks`，沿用元素组件的 React 声明方式，不另造通用 UI DSL。一个声明可以拥有一组紧密协作的字段，不要求一字段一组件。

```ts
interface MarkRenderProps {
  readonly leaf: Readonly<EditorText>;
  children: ReactNode;
}

interface MarkSpec {
  id: string;
  keys: readonly string[];
  render: ComponentType<MarkRenderProps>;
}

// EditorExtension 的可选字段
marks?: readonly MarkSpec[];
```

上例 EditorText 是文档中的说明名称；实际使用 Slate Text（其 CustomTypes 对应 FormattedText），没有另建平行文本模型。纯类型增强入口与序列化归属已由 B3/B4 接线，见 §4。

### 3.1 组合与冲突

- 按宿主显式扩展数组顺序，再按扩展内部 marks 顺序组合：先声明的在内，后声明的在外。顺序是公开约定，不依赖模块加载先后，不另加 priority/before/after 排序系统。
- keys 的值存在且不是 undefined 时该声明参与渲染；false、0 和历史非法值交所有者解释，不由核心假定“truthy 才是标记”。
- 一个持久字段只有一个 owner；不同有效声明重复拥有 key 或 id，建 Kit 时明确报错，不能最后写入者静默胜出。`type`、`text` 是保留字段。
- 本期不增加 mark 专属 override。宿主替换格式实现时显式移除旧声明再装新声明；不借现有元素覆盖规则自动删掉其他 mark。现有项目没有 mark 协议消费者需要兼容这类覆盖。
- 实施保护：覆盖混合扩展的全部元素会连带移除 marks 时，建 Kit/extend 明确拒绝；按同一扩展 id 替换整个扩展则允许，不能只换元素 renderer 就静默丢掉格式。普通有效声明之间的 key/id 冲突仍拒绝。
- 基础文本格式首批作为一个 MarkSpec 拥有 bold、italic、underline、strikethrough、code、highlight、color、darkColor、textGradient。组合色/渐变的判断留在同一 owner，避免两个渲染器各自争夺 color。
- 不同扩展写不同字段，但可能产生相冲突的 CSS 效果；按明确包装顺序处理，宿主负责组合选择，不建立 CSS 属性仲裁引擎。

### 3.2 核心叶子承载与错误回退

核心最外层保留 Slate attributes/children 的承载节点，不把 attributes、contentEditable、ref 的所有权交给 mark。每层贡献只包装传入 children，禁止自行重建文本或丢 children；与 ElementRenderProps 一样，这是组件契约，需要测试守护，任意 React 组件不可能靠类型证明它一定渲染子树。

每个贡献独立 React 错误边界，失败回退到该层输入 children，不丢掉已成功的内层结果；上报既有 `render` 阶段，不因显示错误停用文档 schema。更新内容或替换 Kit 后可以按现有边界重置模式恢复，不在 render 中反复报告同一异常。

核心不因没有 marks 而清除文档字段；无格式扩展时仍显示文字，未知字段保留。基础格式模块接管样式、调色、CodeText、HighlightText；是否因核心承载多一层 span 改变布局，由实现时结构检查和用户视觉验收确认，不在设计阶段承诺 DOM 层数完全相同。

### 3.3 现有效果与交互必须一起迁移

现有效果基线：code 先包文字，highlight 再包 code，StyledText 最外层处理粗斜体、下划线＋删除线、颜色和渐变；渐变覆盖普通颜色，布尔 highlight 使用黄色，未知高亮色不画效果。不得将这些关系简单改成“每种 mark 任意拼一个 span”。

基础格式扩展还接管 paragraph 的 toolbar/inlineCode、六个 `tau.mark.*` 命令、清标记命令及其字段名单。命令 ID 保持不变，不新增命令旁路。Esc 的清标记继续受宿主浮层仲裁和现有热键次序约束，不增加全局监听。

实施修正（ER-029）：默认预设先于宿主追加，单靠预设排列不能保持旧优先级。已新增 EditorHotkey.fallback 布尔：Assembly 稳定划分普通/后备两段，基础格式在后备段，仍早于内核通用兜底。领域 mod+b/Esc 先消费或放行后再格式处理已测试；不按格式 id 特判，不引入数值排序或 before/after 系统。标记渲染本身仍严格按扩展/声明顺序。

宿主 decorate 添加的 Diff 等暂态属性不因此成为持久 mark。现有 DiffHighlightedEditor 改为新的叶子外观包装入口：接收核心已完成 mark 组合的 children，添加 Diff 视觉外壳，不再直接调用 FormattedText。核心保持 Slate 属性承载，取消 customRenderLeaf 对整条渲染链的替代能力；先迁唯一真实消费者及测试，再删除旧 prop/深引。具体宿主包装类型沿用 MarkRenderProps 的 children 约束，归宿主组件 API，不放扩展注册表。

B2 接线已完成：`leafWrapper?: ComponentType<MarkRenderProps>`；旧 prop、组件路径及 package export 已删除，消费者复核清零。标准格式由核心之外的 standardExtensions 显式组合，Arrow 单独安装同一扩展但仍仅三个元素。工具条使用原标记命令并以 source=toolbar 保留其折叠选区后继续带 mark 的旧语义；键盘保持折叠后清活动 mark。颜色写入经新增 tau.mark.set-text-color/set-gradient/set-highlight/clear-colors/apply-colors 命令，输入校验与只读保护接同一分发器。

## 4. Markdown 标记协议：同一个格式所有者，独立纯入口

渲染组件留扩展的 React 入口；同一扩展的 `/markdown` 提供纯标记 codec。`@tau/markdown` 不导入任何扩展，宿主把元素 codecs 与 textCodecs 显式组合一次，渲染进程和主进程复用。

已新增 `MarkdownProcessorOptions.textCodecs`，与元素 codecs 分开，禁止把 text mark 假装成一个带 children 的元素 codec：

```ts
interface MarkdownTextCodec {
  id: string;
  keys: readonly string[];
  importRules: readonly {
    nodeType: string;
    directive?: string;
    content: "children" | "value";
    readMarks(node: MarkdownImportNode): Readonly<Record<string, unknown>> | null;
  }[];
  exportWrap(leaf: Readonly<EditorText>): { prefix: string; suffix: string } | null;
}
```

readMarks 只返回自己 keys 的字段，不得返回 text/type；null 表示该精确规则不认领，空对象表示认领该语法但不附加 mark。content 决定由框架递归 children，还是把 value 作为文字；扩展不自建递归 walker。

同一 processor 的 key/id 重复、同一 nodeType＋directive 的规则重复在构建时报错。mark 规则与元素 importNode 之间保持明确优先级：先恢复保真载体，再走已声明文本规则，再走现有元素认领与普通文本回退；不得让宽泛元素认领抢走 strong 等已声明文本语法。

### 4.1 两条导入共用认领

已落地：两种入口共用遍历，普通入口不构建位置记录；历史零宽清理仅在载体之外生效。规则增加可选 position=self/inherit，以保留原强调与颜色指令各自的位置口径。value 模式保留内联代码的前后缀计算。重复认领/越权字段/异步认领明确拒绝。

普通导入与位置映射导入都调用同一个规则解析器；值与继承字段合并采用由外到内、内层同字段覆盖外层的顺序。包装规则递归处理文字与行内元素，不能把包裹链接的格式解析为第二种链接类型。

位置版只额外记录 mdast source range、前后缀和文本区间。inlineCode 的 value/多反引号边界沿用当前算法并补测试，不让格式扩展猜 DOM 或源码行号。已有两条导入路径若存在差异，先记录现状，再将修复与等价迁移分开，不以“统一实现”掩盖行为变化。

### 4.2 两条导出共用一个结构化结果

框架先取得文字并沿用当前零宽字符清理策略，再依序应用 exportWrap 的 prefix/suffix。普通导出读取同一结果的 output，位置版读取 prefixLength/suffixLength；禁止继续维护两个格式拼接函数。

第一版只支持保留内部文字的包裹，不开放任意改写 text 的序列化器。真实消费者全部可以表达：基础格式 owner 在内部按 **code → italic → strikethrough → bold → gradient 或 color → 字符串 highlight** 组合包裹。比如同时 bold/italic 时，prefix 为 `***`、suffix 为 `***`。内外 codec 的组合顺序与其显式列表一致。

已知兼容边界：当前 leaf 导出没有序列化 underline，布尔 highlight 也不导出，color 只有同时存在 darkColor 才导出。第一批将这些字段登记为基础 owner 已处理的历史语义，保留既有输出，不顺手修格式丢失；未来修复单独列行为变更。

### 4.3 未知标记不能沿用当前静默丢弃

实施状态：未知/失效文本现在经 tau-node 保存完整叶子 JSON，已完成普通/位置双入口恢复、转义与多行/emoji/零宽边界测试。原编码回调只拿独立冻结快照；失败回退不污染原文档。正常载体 sourceOffsets 精确对应 UTF-16 边界；非标准标签或物理多行载体用 opaque＋mdEnd 边界，JSON 仍为事实源。损坏文本载体保留原文，老元素载体及其反斜线/零宽数据回归通过。

兼容限制：旧版本只识别带 children 的元素载体，不能正确重存新文本载体。该新能力只承诺当前四端与新版处理器，禁止把旧版兼容范围说成无限；本轮没有部署。下面关于“当前缺口/目标方案”的段落保留设计起点语境，实际结果以本说明和 ER-030 为准。

设计起点的缺口：当时仅未知**元素**有 tau-node 保真兜底，leafToMarkdown 只读取已知字段。下述方案已由 B4 实现，当前未知文本字段也有保真载体；不能将此保证外推到旧版处理器。

目标方案：对存在无人拥有的持久字段、缺失 text codec 或 codec 失败的文本，使用已有行内 tau-node 载体保存完整 leaf JSON，恢复为文本，不伪造用户可见的元素插件。可复用现有可读 label 与 JSON 属性编码；当前 parseUnknownNode 只接受 children 元素，**需要明确新增文本载体解析分支**，不能直接调用旧函数声称支持。

这是保真协议的增补，必须先验证旧元素载体兼容、新文本载体恢复、恶意/损坏 JSON 作为普通文本退化、转义和多行位置映射。未知字段不能默认当临时装饰删除；处理器只接收持久文档数据，Diff decorate 产物不进入保存链。

不支持该增补的旧版本不能保证恢复新文本载体，需在启用前明确兼容范围。在增补未完成时，不得对外宣称可保存缺失插件的 mark；新 text codec 接口不能以“写成无格式文字”作为错误回退，失败应中止该次导出，保留原文档由调用方呈现错误。增补完成后才启用保真载体回退。

位置映射尤其不能仅给 JSON 外壳加 prefixLength：可读 label 有转义，换行也可能投影为空格。需为恢复的 leaf 建立转义字符与源码区间映射，对编码 JSON 区域采用明确的边界落点；已知格式语料保持原位置结果。不能把未知文本伪装成 void 元素来绕过文字映射。

文本载体标签及 JSON 属性中的竖线统一实体编码，避免 GFM 表格把扩展字段解释为新增列；标签偏移按编码后长度记录。普通段落与表格嵌套均需验证普通/位置双入口往返。

### 4.4 纯类型与旧入口

已落地：@tau/markdown/model 的 TextMarkMap 由格式扩展 types.ts 增强，框架不再声明标准格式字段。标准格式共享同一 key 清单，渐变预设已随领域迁出框架；旧 @tau/markdown/text-gradient 出口消费者清零后删除。leafToMarkdown/leafToMarkdownStructured 已成为 processor 方法，桌面转出绑定自身 processor；框架根不再提供固定格式的全局函数。四端显式 textCodecs 与 Node 行为护栏接线，无 DOM 类型检查也覆盖格式纯入口。

在现有纯模型侧提供可增强的 TextMarkMap（最终命名实施前确认），基础 Text 只拥有 type/text。基础格式的类型增强与纯 codec 同包提供；React 扩展入口和纯 `/markdown` 入口均引入对应类型登记，但后者不引 React。保留现有 FormattedText 名称及已有字段兼容，迁完再移除框架中的具体字段知识，不以 Record<string, any> 代替契约。

原全局固定格式的 `leafToMarkdown` / `leafToMarkdownStructured` 已改为 processor 绑定方法；桌面转出绑定本端处理器，没有全局可变 registry。普通和位置导出复用一个纯实现。

Node 验证必须使用显式 textCodecs。headless 框架不从 editor、text-formatting 根入口或 shared 根入口补默认格式；已有 Markdown 框架测试要显式使用纯夹具/实际 codec，避免测试绿了但应用漏装。
