# 01 · 目标架构

这里描述**终态**。各阶段怎么一步步到达，见 [02-阶段计划.md](02-阶段计划.md)。决策出处用 `ER-xxx` 编号，见 [03-决策记录.md](03-决策记录.md)。

## 1. 核心原则

1. **内核提供机制与基础段落/文本，领域功能归扩展。** 内置扩展和（将来的）第三方插件走同一套公开 API，不许走后门（ER-001 经 ER-026 修订）。具体约定见 [07-核心与扩展边界及推进约定.md](07-核心与扩展边界及推进约定.md)。
2. **依赖只能往下。** Editor 依赖契约（主题 token、服务接口），不依赖宿主实现。
3. **文档比插件活得久。** 插件缺失或出错时，它的节点必须能无损保存和往返（ER-006）。
4. **Token 是 API，类名不是 API。** 主题定制和插件取色都只走 CSS 变量和 ThemeService（ER-003）。

## 2. 分层与依赖方向

功能扩展已统一到根级 `editor-extensions/`，25 个完整功能独立成包，不按元素逐个建包（ER-027/044）。source-view 等共用支撑能力、chat-ui 和协作适配继续按自身职责归属，不强行套用元素扩展形态。

```
apps/desktop · blog · mobile · browser-extension     组装：选扩展、注册服务、注入主题
        ↓
平台层（desktop 的 editor-extensions / services 等）    服务实现、插槽（LocalImage…）、业务扩展
        ↓
功能扩展   editor-extensions/*（完整功能包）
共用支撑   editor-source-view │ editor-collab
        ↓
@tau/editor（内核）                                     机制 + 基础段落/文本（React / DOM）
        ↓
@tau/markdown（纯函数，无 DOM）   @tau/themes（主题契约，纯数据）   @tau/shared
```

`@tau/markdown` 和每个扩展的 `schema.ts` / `markdown.ts` 属于 **headless 层**：不依赖 React、DOM，可以在 Electron 主进程、Node 脚本、MCP 里直接用（见 §8）。

**headless 包的「Node 可直接加载」约束**（`@tau/themes` 根入口首先落地）：不经构建，Node 以包名原生加载 TS 源码（type stripping）。所以：相对导入写 `.ts` 扩展名；tsconfig 开 `allowImportingTsExtensions`、`erasableSyntaxOnly`、`verbatimModuleSyntax`，lib 不含 DOM；包内放一个 `node-import.test.ts`，用子进程真实加载。

硬约束：

- `@tau/editor` 不得 import 任何 `apps/*`。UI 直接用设计系统 `@tau/ui`（ER-018，推翻了原先「不得 import `@tau/ui`」的约束）。
- 扩展只能 import `@tau/editor` 的公开入口（终态为 `@tau/editor/api`），不得深引 `@tau/editor/src/...` 内部路径。P8 起用 ESLint `no-restricted-imports` 强制。
- P9 已拆出 `@tau/editor-custom-block` 与 `@tau/editor-diagram`（mermaid / plantuml / abc / tikz / typst），访问内核一律经公开 API，类型由公开映射增强登记。渲染声明只持有懒加载组件，模板执行器和图表专属渲染器不从内核或 shared 重导出；已删除的 chart / graphviz 等能力不恢复。
- `@tau/markdown` 不依赖 editor：框架拥有遍历、位置映射和未知数据载体，文本标记和渐变语义归 text-formatting 的纯 codec；textCodecs 由宿主显式组合。codec 与纯类型保持无 DOM 入口，不以加载渲染入口作为序列化的前提（ER-030/037）。
- 服务与 HTML 首批（ER-021）：`@tau/shared/service-contract` 拥有纯服务标识符，`/runtime-style` 拥有显式 `html | tsx` 样式契约；`@tau/editor-diagram/services` 拥有返回 HTML 的 Typst 契约。`@tau/editor/api/services` 只转出纯标识符与注册表类型，不加载渲染 API。注册表实现/作用域留内核，混合 CompilerService 已删除。HTML 两种元素、插入与 codec 归 `editor-html`；HTML 空态由扩展 `isEmpty` 声明，内核只分发。文件/资源/打开链接契约已归 shared/host-services，媒体契约已归 media/services（ER-035/036）。
- 源码视图与代码块（ER-022）：PreviewWithEditor、CodeMirror 模式/CSS、预览菜单归 `editor-source-view`；宿主只组合一次 `/menu` 的贡献扩展。代码块仍用 textarea＋Shiki，连同控制器、命令、插入与 codec 归 `editor-code-block`，纯 `/runtime` 只公开按 uuid 查询控制器。数学元素/codec/插入/规范化因预览依赖同批迁出；KaTeX 渲染归数学领域，emoji 和列表选择器分别归表情包与列表包，具体边界见 ER-023/040。内核只公开实际所需的导航/追加/删除/选区机制，不转出领域渲染器或控制器。
- `@tau/themes` 是主题的唯一归属，没有中间转出层。根入口只放数据和纯函数（token 词汇表、`defineTheme`、内置主题、偏好解析与首帧脚本生成），node 可跑；DOM 应用放 `@tau/themes/dom`，React 运行时（zustand store）放 `@tau/themes/react`；CSS 分为 `tokens.css`（变量）和 `tailwind.css`（语义类映射）。Editor 只用根入口的类型和 CSS 变量。

## 3. 内核（`@tau/editor`）负责什么

纠偏约束（ER-025）：扩展 API 不公开低级 EditorContextMenu 回调入口；局部菜单 UI 直接消费设计系统，内容编辑通过命令。列表选择器及 emoji-mart 依赖已归列表包，不归 emoji 元素包、不要求宿主额外注入。聊天与浮层已按 ER-023/024 收口，聊天后续治理不在本次范围。段落工具服务于固定基础模型，不提供任意 schema。

ER-026 已确认段落与文本归核心，不再为移走 paragraph 引入任意默认块 schema。现有迁移桥仍不自动纳入第三方稳定承诺；以下改为 API 评审条件，不再要求机械删除所有段落导出。

08-A 已落地纯 `@tau/editor/api/paragraph`（createParagraph、isParagraphElement、ParagraphElement），`/api` 同步转出。空初值、根规范化、追加、void 删除共用工厂。交互追加返回 Path/null，拒绝只读、陈旧身份与卸载目标，真实写入异常继续抛出；AddParagraph 仅插入成功回调。已验证纯入口 Node 运行加载，不据此宣称整个类型图无 DOM。选区空态查询已消费 isEmpty 贡献，图片提升已归媒体 codec（ER-032/033）。

| 过渡导出                                                                              | 当前消费者                          | 退出条件                                                                          |
| ------------------------------------------------------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------- |
| `AddParagraph` / `AddParagraphRef`                                                    | source-view、code-block             | 评审基础追加能力与 UI 耦合，验证落点/只读行为后稳定或替换；不直接承诺旧组件签名。 |
| `ParagraphElement`、`isAtParagraphStart`、`isParagraphAndEmpty`、`isParagraphElement` | custom-block、code-block 的段落行为 | 段落归核心，按最小公共能力评审类型与判断 API；快捷语法与特殊块聚焦规则仍归扩展。  |

聊天展示、工具 renderer 的登记和 React props 契约同属 `@tau/chat-ui`；`/renderers` 只加载登记逻辑，shared 的 `/chat-renderers` 只保留消息与纯展示归约。桌面自有展示继续通过默认项插槽复用同一登记链，不回流到 editor。

`OverlayBackDismiss` 与其 token/适配契约同属 editor。Layer 在当前编辑器的页面上下文只登记关闭回调；宿主继续拥有 Esc/返回仲裁。未注册服务或无 Page 上下文时保留浮层自身关闭入口，不新增监听。关闭、卸载和 Activity 隐藏注销，服务派生保持原作用域；仅用于当前源码全屏与行内公式，不扩展为通用浮层框架。

| 模块          | 职责                                                                              |
| ------------- | --------------------------------------------------------------------------------- |
| 文档模型      | 基础段落/文本、元素类型注册、结构校验、未知节点保护（ER-006/026）                 |
| 扩展宿主      | 扩展注册、冲突检测、按类型分发、错误隔离；activate/dispose 等远期能力本期不实现   |
| 命令与快捷键  | 命令注册表；快捷键只绑定命令 id                                                   |
| UI 挂载点     | BlockPanel、HoveringToolbar、右键菜单、拖拽手柄；**只提供挂载点**，条目由扩展贡献 |
| 服务注册表    | 保留 ServiceRegistry/注入与派生机制；宿主契约归 shared，媒体 token/插槽归 media   |
| 主题消费层    | `editor.css` 定义 `--ed-*` 组件 token；`ThemeService` 接口                        |
| 文档源        | `EditorDocument` 接口：普通值或 Yjs 绑定；文档源切换时无缝交接（§7）              |
| Markdown 接入 | 调用 `@tau/markdown` 做粘贴导入等；框架本身在 `@tau/markdown`（§8）               |

**不属于内核**：基础段落/文本之外的领域元素、具体格式效果、列表/表格/容器复制规则、领域转换名单，以及 mermaid、katex、shiki、codemirror、abcjs 等领域重依赖和平台能力实现。复制采用专用片段贡献，文本格式采用标记组合机制，转换沿用命令/菜单贡献；接口已落地，详见 07/09。

共用宿主资源、文件和打开链接契约已归 @tau/shared/host-services（ER-035）；核心只持有服务作用域和注入机制，不再转出这些 token。媒体专有 Provider/插槽与完整媒体实现已归 editor-extensions/media（ER-036），其余领域和旧扩展目录仍待后续。

## 4. EditorKit（替代 EditorProvider）

每个宿主创建一次，显式传给 `<Editor>`：

```ts
const kit = createEditorKit({
  extensions: [...diagramExtensions, customBlockExtension, ...desktopExtensions],
  services: [desktopServices],        // ServiceRegistration[]，沿用现有注册方式
  theme: desktopThemeService,         // ThemeService
});

<Editor kit={kit} initValue={value} onChange={...} />
```

- kit 创建时完成冲突检测和预计算（替代 `PluginOptimizer` 的缓存职责），同一个 kit 可给多个编辑器复用。
- **当前实现**：`createEditorKit` 仍补齐剩余内置扩展；diagram / custom-block / HTML / code-block / math 与预览菜单已由四端场景 Kit 显式追加。**目标（ER-026）**：仅内建段落/文本基础，其余功能由宿主显式选择；预设在核心外提供。两个 Kit 工厂的迁移方式待设计，四端场景能力保持不变；公共扩展实例不在组件 render 中新建。
- 嵌套编辑器（预览、白板卡片里的编辑器）默认继承父编辑器的 kit：用**内核私有**的 Context 传递，不对宿主暴露。
- 单个编辑器实例需要差异时用 `kit.extend({ extensions, services })` 派生，不做隐式合并。
- kit 按**场景**划分，一个场景一个，命名说场景不说程度（`getMarkdownFileKit()` / `getFlashcardKit()` / `getChatInputKit()`…），见 ER-016；每个 kit 只注册该场景需要的扩展，不要求全量覆盖，见 ER-017。各端 kit 可以不同（服务与组件实现有平台差异），但元素类型的覆盖要按内容实际会包含什么来补齐，否则同一份内容换端就渲染不出来。
- 现在 `EditorConfig` 里的字段去向（ER-004）：

| 现字段                                       | 去向                                                                        |
| -------------------------------------------- | --------------------------------------------------------------------------- |
| `theme.mode`                                 | `ThemeService.mode`                                                         |
| `theme.colors`（Tailwind 类名）              | **删除**，改用 `--ed-*` / `--tau-*`                                         |
| `appearance.image`                           | image 扩展参数：`createImageExtensions({ appearance })`                     |
| `openUrl`                                    | 服务 `IOpenerService`                                                       |
| `formatDate`                                 | **删除**，不设服务：没有宿主使用，也没有平台差异                            |
| `plantumlServer` / `plantumlDarkTheme`       | plantuml 扩展参数                                                           |
| `<Editor theme>` prop、`EditorContext.theme` | 删除，统一由 ThemeService；局部强制明暗用 `<EditorThemeOverride>`（ER-014） |
| `features.disableHeaderCollapse`             | header 扩展参数                                                             |

## 5. 扩展 API v2

复制贡献已落地（ER-028）：ElementSpec.copy 只返回 keep/unwrap，CopyContext 提供冻结片段、完整选中与原祖先类型；children 表达解包后的通用片段，而非完整领域 schema。ExtensionAssembly 按有效元素选择 owner/策略，核心在 binding.install 后包装一次 getFragment；核对标准切片并固定 trace 后先子后父执行，无贡献节点保留整棵子树。失败/非法异步返回按 copy 阶段隔离，整次回退原片段；核心不再持有列表/表格/容器复制类型名单。

标记显示贡献已落地（ER-029）：EditorExtension.marks 声明 id/keys/render，按显式顺序组合，重复 id/key 与保留字段在装配时拒绝；核心 LeafRenderer 持有 Slate 属性，逐贡献隔离显示错误，缺失/失败时保留文字和字段。text-formatting 负责标准格式、颜色工具条、inlineCode 与格式命令，暂留 editor 包内。EditorHotkey.fallback 保持领域热键先于格式后备；标记渲染顺序不受此标志影响。宿主仅以 leafWrapper 包装已组合结果，customRenderLeaf 与旧 FormattedText 组件出口已删除。默认 Kit 仍有格式，Arrow 显式安装；纯文本模型/Markdown 序列化留 B3。

### 5.1 形态

```ts
export default defineExtension({
  id: "tau.custom-block",          // 全局唯一；内置用 tau.*，第三方将来用作者命名空间
  apiVersion: 1,
  elements: [
    {
      type: "custom-block",        // 内置类型保持现有 type 名，不加前缀（兼容已有文档）
      kind: "block",               // block | inline
      isVoid: true,
      schema,                      // 校验函数；不合法时交给 normalize 修复
      render: lazy(() => import("./CustomBlock")),
      markdown: customBlockCodec,    // 来自 ./markdown.ts（纯函数文件）
      behaviors: { onKeyDown, deleteBackward, insertBreak, normalize, onPaste },
    },
  ],
  commands: [{ id: "tau.custom-block.insert", run }],
  hotkeys: [{ key: "mod+alt+c", command: "tau.custom-block.insert" }],
  menu: [...],
  blockPanel: [...],
  toolbar: [...],
  contextMenu: [...],
  services: { requires: [], optional: [IFileService] },
  activate(ctx) { return () => {} },   // 返回 dispose
});
```

- `ctx` 提供：`editor`（受限的编辑器 API）、`services`、`theme`（ThemeService）、`log`、`subscribe`。
- `behaviors` 只在选区或目标节点属于该类型时由宿主调用，不再全局改写 `editor.insertBreak`。
- **受信任层**：`plugins: Plugin[]`（原始 `(editor) => editor`）保留，只给内核内置扩展用。它在类型上标记为 `@internal`；将来开放第三方时不进公开 API。原因：少量能力（列表、表格的跨节点 normalize，协作）用声明式表达不了，硬塞进公开 API 会冻结内部实现（ER-005）。
- 当前只接受 v2 扩展：旧 `IExtension`、`Base`、`fromLegacyExtension()` 与 legacy 装配分支已删除（ER-019），不得恢复适配层。
- P8 落地的行为签名：`(editor, [node, path], ...args) => boolean`，从选区所在最内层元素往外找，返回 `true` 即停；在别的元素里触发、产出本元素的行为（快捷语法）用 `behaviorsFor: { paragraph: {...} }` 挂到目标类型上。已实现 `insertBreak` / `deleteBackward` / `insertText` / `normalize`。`commands` / `hotkeys` 已随命令注册表落地：`EditorCommand { id, title?, when?, run }` 与 `EditorHotkey { key, command }`，命令 id 重复建 kit 即抛错，执行带 enablement 与按扩展熔断，`editor.commands.execute(id, payload?, element?, path?)` 为统一程序化入口（菜单把目标元素与路径传进命令上下文）；`menu` 已随菜单贡献层落地（形状见 §5.4）；`onPaste` 由 ingest 声明化承接，`activate(ctx)` 远期。

### 5.2 隔离与容错

| 层面     | 机制                                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 渲染     | 每个元素外包 `ElementErrorBoundary`：出错显示「扩展 X 渲染失败」占位，保留 `attributes` / `children` 让 Slate 不丢选区，数据不动        |
| 行为     | 宿主调用每个 handler 时 try/catch，出错则回退默认行为并经 `IExtensionErrorReporter` 上报；同一扩展 10 秒内出错 3 次即停用其行为与快捷键 |
| 冲突     | 元素 type 在 kit 创建时检测，重复直接报错，显式 `override: true` 才允许替换（P6 已落地）；命令 id 与快捷键的检测随 P8 的命令注册表补齐  |
| 未知节点 | 找不到扩展的节点渲染为只读占位（显示类型名），序列化时原样保留（ER-006）                                                                |
| 性能     | `render` 和重依赖一律懒加载；首屏不因扩展数量变慢                                                                                       |
| 协作     | 元素数据必须可 JSON 序列化（schema 保证），这样才能走 yjs                                                                               |

命令 dispatcher 在执行谓词前先检查熔断，`when` 与同步动作统一隔离；异步动作须返回 Promise，由 dispatcher 捕获拒绝。`execute()` 返回 true 对异步命令表示已启动。剪切须先成功复制完整 Slate 片段，再按 pathRef 删除未被修改的原节点；纯文本降级不能作为删除依据。音频上传也按 pathRef 回填/清理，目标删除或变成其他类型后停止操作。

### 5.3 Markdown 归属

- 每个元素自带 Markdown 编解码（codec），但 codec 写在扩展的独立文件 `markdown.ts` 里，**不写在 `defineExtension` 的 UI 模块里**，否则主进程引入 codec 会连带引入 React 组件。`defineExtension` 只引用它。详见 §8。
- 未知节点兜底：没有 codec 的元素块级序列化为 `:::tau-node{type="x"}` 加 JSON 代码围栏、行内为 `:tau-node[正文]{type="x" json="…"}`，解析时还原，保证往返无损（ER-006）。
- 行内兜底标签仅供阅读，换行收敛为单行空格；JSON 保留原始换行和完整属性。渲染层的未知节点行内缓存跟随 `editor.children` 身份失效，跨父级移动或换绑复用旧节点时重新判断位置。

### 5.4 交互贡献点：菜单 / 拖拽 / 内容注入（2026-09-29 方案定稿，待落地）

命令是唯一动词层（§5.1 已落地 commands/hotkeys），其余交互面都是命令之上的视图或内核渲染的 affordance。插件作者的完整心智模型：**command（做什么）、hotkey（怎么触发）、drag/menu（在哪出现）、ingest（接什么进来）**，不需要知道 useDragAndDrop、React DnD、@scope CSS、EditorContextMenu 的实现。

- **菜单贡献点**（手柄菜单与右键菜单统一为一个贡献点，EditorContextMenu 已是通用渲染件，差的是数据来源）。已落地（2026-09-29）：

```ts
// defineExtension 增 menu（旧 IExtension 过渡字段叫 menuItems，迁移时搬过去）。
// 锚定规则：注册了元素的扩展，其条目默认只出现在自己的元素类型上（装配层统一过滤，
// 作者不必逐条目写 when）；不注册元素的扩展（内核默认菜单、preview 菜单）为全局条目，靠 when 限定范围
menu: [{
  id: "tau.callout.set-type",            // 顶层条目按 id 去重：后声明覆盖先声明（扩展可覆盖内核默认条目）
  title: "修改类型" | (ctx => "…"),       // 静态或打开菜单时求值（收起/展开这类动态标题）
  icon: <Palette /> | (ctx => <…/>),

  payload: { calloutType: "info" },       // 命令静态参数，与目标元素一起进 ctx（element + path）
  when: ctx => …,                         // false → 条目（连同 children）不出现：类型之外的额外适用条件（类型锚定已由装配层承担）
  disabled: ctx => …,                     // false 照常显示，true 灰显（enablement）
  group: "actions" | "transform" | "block" | string,  // 组序 actions（特有）→ transform → block，未知组随后；组间分隔线，组内按 order 与声明顺序
  order: 10,

  children: [...],                        // 子菜单（callout 五类、代码块语言表）

```

通用块菜单由产品显式安装 `tau.menu-defaults` 贡献：`block` 组包含上移 / 下移 / 剪切 / 复制 / 删除；删除对 void 块走「删后补空段落」语义（`deleteVoidBlock`）。`transform` 组由标题/列表/容器各自的 `menuFor` 按源类型贡献，`mergeChildren` 显式组合共享父菜单；原 `tau.transform.node` 只作兼容转发，不再持有类型名单或操作实现（ER-034）。特有条目仍由各扩展的 `menu` 限定于自身类型；预览类块的「编辑 / 全屏」由 `tau.preview-menu` 按 `previewActionsMap` 有无认领。菜单在手柄点击时对目标元素求值一次；求值错误按条目隔离。宿主 `extraMenuItemsBuilder` 过渡保留（追加在末尾）。菜单条目**只能**引用命令 id，不留内联函数后门。

- **拖拽声明化**（element 声明，内核渲染 chrome）。已落地（2026-09-30）：块组件只渲染内容，渲染链上的 `BlockDragHost`（挂在 ElementGuard 的错误边界内、扩展渲染外）成为手柄 / 插入线 / `ed-block` 类 / 半透明 / 手柄菜单的唯一渲染点。**自身与子级两个正交开关**（知识归属容器，孩子不认识父母——两处跨扩展感知硬编码已修：paragraph 的 normalize 写 `disableDrag` 进文档数据、内核 useDragAndDrop 硬编码两类型）：

```ts
// defineElement 增 drag（旧 IExtension 过渡字段叫 dragSpec，迁移时搬过去）
defineElement({
  type: "check-list-item",
  drag: {
    self: true,          // 自身可拖（显示手柄）；false 时本块仅作为放置目标
    children: false,     // 我内部的子内容不参与拖拽（更深的子块手柄都不显示）
    accepts?: (dragElement) => boolean,  // 放置谓词：拖动元素能否落到本块（含内部）；沿祖先链求值
    handleClassName?: "…" | (element) => "…",  // 手柄位置微调（标题让出折叠箭头、分割线抬高）；em 按 wrapper 字号算，随元素属性变化（标题级别）时传函数
  },
})
```

`drag: true` 是 `{ self: true, children: true }` 简写；**未声明的类型没有 chrome（DOM 与迁移前一致）**——需要拖拽的块显式声明，未接线的类型（list-item、表格行、行内元素）不凭空冒出手柄。canDrag 沿祖先链查 `children: false`；canDrop 沿祖先链求 `accepts`（check-list-item 的「只接受同类」由此声明，拖到其内部段落前后同样被管住）。`disableDrag` 字段已从类型与文档数据删除（旧存量数据里的值不再被读，正式剥离进 schema 迁移批次）。22 个接线点全部去接线（editor 包 17 + PreviewWithEditor + webview + VideoScreenshot + desktop 四扩展），useDragAndDrop / DragHandle / DropIndicator 降为内核私有（包根出口只留 `BLOCK_DRAG_GROUP` 类名常量）。

- **内容注入（ingest）**。已落地（2026-09-30）：drop 与 paste 归并为一条认领式管线（共同形状是 DataTransfer），取代旧病灶——内核 `withFileDrop` 硬编码 image/audio/video 三槽位（扩展 monkeypatch 挂载、无第三方路径）与各扩展链式改写 `insertData`（无隔离、顺序隐式、drop 与 paste 逻辑写两遍）。

```ts
// defineElement 增 ingest（旧 IExtension 过渡字段叫 ingestSpec，迁移时搬过去）
defineElement({
  type: "image",
  ingest: {
    files: {
      accept: "image/*",              // MIME 认领（type/* 前缀通配、精确、* 全收）；完全相同 accept 重复声明建 kit 抛错
      run: async (ctx) => {},         // ctx: { editor, files, data, point?, source: "drop" | "paste" }
    },
    text?: { when: (data) => boolean, run: (ctx) => {} },  // 粘贴文本侧认领（如 chart 认领 CSV），排在 markdown 导入之前
  },
})
```

管线（`plugins/withIngest.ts`，装配产物 `ingestSources` 驱动）：paste 侧改写 `insertData`——Slate 自有片段优先原样下传，files 按声明顺序分桶认领（每个文件只归第一个匹配的声明，任一桶认领即消费本次粘贴、未认领文件忽略），再试 text 谓词（第一个 `when` 为真的消费），都没认领才下传默认链（markdown 导入等宿主插件仍在其后）；drop 侧 `editor.handleDrop(dataTransfer, point)` 选中落点后分桶并行 run。每环按贡献扩展隔离、出错记入熔断（phase=ingest），熔断的声明视为不存在（文件留给后续声明）。ingest 不按元素类型锚定——认领对象是拖入/粘贴的内容而非元素。已收敛：image（drop/空段落粘贴插块图、非空段落插行内图——原 inline-image 插件的行为并入，占位按 uuid 回填）、audio、video（paste 失败清占位补空段落、drop 失败保留占位，沿用旧双插件差异）；六个 paste/drop 旧插件删除，`withFileDrop` 与 `editor.dropHandlers` 删除。宿主扩展声明 `accept: "application/pdf"` 即得附件拖入，内核不再加槽位。

- **落地顺序**（各自可提交）：菜单 → 拖拽 → ingest；与扩展 v2 迁移咬合（每迁一个扩展顺手带上它的 commands / hotkeys / menu / drag / ingest 声明）。drag 的悬停 / 拖拽观感与 React 合成键盘层归实机清单（jsdom 测不了 :hover）。

### 5.5 为第三方预留（本期不实现）

本期不做，但以下设计**不能被本期实现堵死**：

- 扩展以 `id + apiVersion` 标识，公开入口只有 `@tau/editor/api`。
- react、slate 等由宿主提供单例（将来作为 externals 注入），扩展包不能各自打包一份。
- 扩展不能直接访问 `window` 上的宿主对象，只能通过 `ctx.services` 访问。
- 扩展元数据（id、名称、版本、依赖服务）可以脱离代码读取，为将来的市场和授权清单留口。

## 7. 协作：文档源 + 协作扩展

### 7.1 现状与闪烁的根因

- desktop 所有内容编辑都经 `apps/desktop/src/components/ContentEditor`（12 个调用点）。**本机编辑也是 Yjs**：主进程为每篇内容建一个 `mode: "local"` 的协作会话，渲染进程经 IPC 订阅。
- 发起共享时，主进程用当前内容**新建**一个 Y.Doc（`createSharedDocument`），documentId 换成服务端 id。渲染进程这边接连发生三件事：
  1. `useCollaborationDocument` 在 documentId 变化时先把 binding 置空，ContentEditor 退回 fallback/转圈；
  2. 新 binding 就绪后，`<Editor key={contentId:documentId}>` 的 key 变了，整个编辑器卸载重建；
  3. 重建时所有块组件（mermaid、codemirror 等）重新初始化。
- 结束共享、移动端连接失败回落本地（`CollaborativeEditor` 返回 null 由宿主换成本地编辑器）也是同样的路径。
- 此外 `CollaborationServices` 靠嵌套 `EditorProvider` 覆盖资源服务和媒体插槽；内核里 `withCollaboration`、光标、私有块占位（SafeElement）都是 `collaboration` prop 的特判，内核因此硬依赖 yjs。

结论：闪烁不是渲染性能问题，而是**「换文档」和「换同步方式」被混成了一件事**。共享只改变了同步方式，内容并没变，不应该换文档。

### 7.2 模型

协作不是普通的内容扩展：它改变了内容的事实来源（Y.Doc 而不是 Slate value），接管了撤销历史，而且必须从第一帧就生效。所以拆成两部分：

- **文档源（EditorDocument）**：内核新增的一等概念，回答「内容从哪来、改动往哪去、谁管撤销」。普通值和 Yjs 绑定是两种实现。
- **协作扩展（`@tau/editor-collab`）**：协作光标、私有块占位、共享模式下的资源上传/解析服务。走扩展 API 的受信任层（ER-005）。

```ts
/** 内核接口（示意，P0 协作 spike 后定稿） */
interface EditorDocument {
  /** 内容谱系：同一篇内容在本机/共享之间切换时保持不变 */
  readonly lineage: string;
  /** "external" 表示由文档源自己管撤销（Yjs UndoManager），内核不装 withHistory */
  readonly history: "slate" | "external";
  /** 挂到编辑器上：同步初始内容、开始监听；返回卸载函数 */
  attach(editor: Editor): () => void;
  /** 该文档源需要覆盖的服务（如共享模式的资源上传），挂在本编辑器实例上 */
  readonly services?: ServiceRegistration;
  readonly readonly: boolean;
  subscribe(listener: () => void): () => void;
}

<Editor kit={kit} document={doc} />
```

落地形态（P6 定接口，P7 接入协作）：接口如上（另有 `initialValue`、可选 `onChange`），
`createValueDocument(initValue, onChange)` 由内核提供。`initValue` / `onChange` 仍是各宿主的
主路径，未改写为内部转文档源（见 02 P6 说明）。

- `createValueDocument(initValue, onChange)`：内核自带，给 blog、预览、只读场景。
- `createYjsDocument(binding, { lineage, cursors, onChange })`：`@tau/editor-collab` 提供。
- 内核不再有 `collaboration`、`collaborationCursors` prop，也不再依赖 yjs / slate-yjs。
- Slate 的挂载键、内容/选区快照、规范化与 `onInit` 均按 editor 实例管理：换文档或换 kit 导致实例重建时同步复位；同谱系换源复用实例。`cursors` 随换源更新，光标发送钩子只安装一次，避免重复连接叠加回调。

接管内容与撤销的文档源（目前只有协作）经 `document.binding` 改写编辑器，这是受信任层
（ER-005，标 `@internal`，不进公开 API）。内核在这几个点上让路，别处不认识协作：

| `EditorDocumentBinding`  | 内核何时调用               | 协作的实现                                                  |
| ------------------------ | -------------------------- | ----------------------------------------------------------- |
| `install(editor)`        | 创建编辑器时一次           | `withCollaboration`（withYjs + withYHistory + withCursors） |
| `connect` / `disconnect` | 挂载 / 卸载，换源时成对    | `YjsEditor.connect`；断开前 flush 未发出的本地改动          |
| `rebind(editor)`         | 同谱系换源（§7.3 第 3 层） | 换 sharedRoot、重建 UndoManager、结构共享                   |
| `renderElement`          | 每个元素渲染前             | 私有块：作者渲染真身，远端渲染占位                          |
| `renderOverlay`          | 编辑区之上                 | 协作光标层                                                  |
| `wrap`                   | 包住编辑器子树             | 提供 `useCollaboration` 的上下文                            |

`history: "external"` 时内核不装 `withHistory`；`binding` 存在时 `setEditorValue` 不接受整体覆盖
（内容归文档源管）。`renderOverlay` / `wrap` 用函数而不是组件：换源时组件类型一变，React 会重挂载整棵子树。

### 7.3 无缝切换的三层保证

1. **主进程：共享是会话升级，不是换文档（desktop）。** 发起共享时，把本机会话的 Y.Doc 状态发布到服务端，继续用**同一个 Y.Doc**；私有块转占位、资源 URL 改写、`meta.mode` 切换都作为这个 Y.Doc 上的普通编辑发生，经 IPC 像平常的更新一样同步到渲染进程。渲染进程订阅的是稳定的内容会话键，documentId 变化只在主进程内部映射。这一层做完，desktop 的发起/结束共享就根本不需要换文档。
2. **宿主：先准备好再切换，中间不出现转圈。** `useContentDocument(contentId)` 返回一个稳定句柄；底层文档源要换时，旧的继续显示和编辑，新的就绪后在同一帧切换。首次打开仍可用只读快照作占位（现有 `fallback` 的做法）。
3. **内核：同谱系的文档源切换不重建编辑器。** `document` 换了但 `lineage` 相同，就在同一个 Slate editor 上 detach 旧源、attach 新源；新内容与当前内容相同就保留现有节点对象，块组件不会重新挂载，选区也保留。`lineage` 不同才视为换了一篇文档。

第 3 层主要服务移动端「连接失败回落本地 → 恢复后接回协作」这类确实要换源的情况。

### 7.4 desktop 的 ContentEditor

保留一个薄的宿主组件是合理的（「编辑器 + 业务数据源」本来就是宿主的职责），但它只做一件事：

```tsx
function ContentEditor({ contentId, ...props }) {
  const document = useContentDocument(contentId); // 稳定句柄，内部处理会话、升级、回落
  return <Editor kit={desktopKit} document={document} {...props} />;
}
```

没有 key、没有嵌套 Provider、就绪前不换组件；只读、冻结、在线状态由文档源的 `readonly` 和 `subscribe` 提供。

### 7.5 已验证的可行性（P0 spike，2026-09-28）

- **会话升级（S1）可行**。在同一个 Y.Doc 上做最小编辑：私有块换成占位，删除 `LOCAL_FIELDS`，`meta.mode` 切为 shared，资源 URL 改写。结果如下：
  - 与私有块无关的块仍是同一个 `Y.XmlText`；
  - 读出的内容与新建共享文档一致，并通过 `validateDocument`；
  - 私有块数据（包括升级前 50 轮编辑的历史）和原本地资源路径都不会出现在编码状态里。
  - **前提是 Y.Doc 开启 gc**（Yjs 默认开启）。关掉 gc 后历史会残留，spike 里有对照用例。正式实现要在主进程加断言，或在发布前检查编码内容，把这条隐私边界锁死。
  - 升级必须是最小编辑。不能用 `replaceSharedContent` 整体替换正文，否则渲染端还是会整体重建节点。
  - 体积：50 轮编辑后，升级文档约 2.1 KB，新建文档约 1.2 KB，可以接受。
- **同谱系换源（S2）可行**。`rebind` 的步骤：disconnect → 改 `sharedRoot` → 重建 UndoManager → connect → 结构共享（新树中与旧树深度相等的子树换回旧对象）→ 恢复选区。结果如下：
  - 内容相同时元素组件零重挂载，选区保留；只有一段不同时只重建那一段；
  - 写入和远端更新都只走新文档，撤销只作用于新文档。
  - 对照组：不做结构共享时，所有元素都会重新挂载。这说明闪烁的根源在节点对象身份，而不在 `key`。
  - 正式实现还要处理（spike 没覆盖）：`withCursors` 的 awareness 切换、`withCollaboration` 的 fields 监听和 hydrate 重绑；结构共享要按 `collabId` 匹配而不是按位置，避免在差异段之后的段落上失效。

## 8. Markdown：headless 层

当前补充（ER-030）：标准标记不再由框架硬编码；宿主显式传 textCodecs，格式扩展拥有字段增强、渐变数据、语法认领与包裹。两种导入共用遍历，两种导出共用叶子结果；leafToMarkdown 方法绑定 processor。未知/失效文本用 tau-node JSON 保真，普通载体 sourceOffsets 精确映射，手改标签用 opaque 边界。旧版仅识别元素载体，不能正确重存新文本载体。下方早期实现描述保留历史上下文，当前以 09/ER-030 为准。

### 8.1 现状

同一件事现在有三份实现：

| 位置                                                                                                                | 内容                               | 使用方                                                          |
| ------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | --------------------------------------------------------------- |
| `apps/desktop/src/utils/markdown.ts` + `markdownSerializerRegistry.ts` + `markdown-helper.ts` + `positionMapper.ts` | 导入导出、双向位置映射，约 3800 行 | desktop 渲染进程、Electron 主进程（web-clip、search-core）、MCP |
| `packages/editor/src/utils/markdownImport.ts`                                                                       | 只有导入，约 1170 行               | editor 粘贴导入、mobile、browser-extension                      |
| `packages/slate-markdown`                                                                                           | 导出注册表，约 930 行              | **没有使用方**                                                  |

desktop 这份还硬编码了 desktop 自己的扩展类型（file-attachment），并由 `markdown-node-import.test.ts` 守护「无 DOM 环境可导入」。

### 8.2 目标

- 合并为一个包 `@tau/markdown`（沿用 `packages/slate-markdown` 目录改名），**headless**：只依赖 unified/remark 生态、`slate`（核心包本身不碰 DOM）和元素类型。
- 对外：

```ts
const md = createMarkdownProcessor({ codecs: desktopMarkdownCodecs });

md.importFromMarkdown(markdown, ignoreTypes?, { customDirectives? }); // → Descendant[]
md.importFromMarkdownWithPositions(markdown); // → { content, positionMap }
md.getMarkdown(value); // → string
md.getMarkdownWithPositions(value); // → { markdown, positionMap }
```

方法名沿用迁移前的 `importFromMarkdown` / `getMarkdown`，没有改成 `parse` / `stringify`。所有使用方经 `createMarkdownProcessor({ codecs })` 建处理器。P9 后四端组合剩余内置 codec、`diagramMarkdownCodecs`、`customBlockCodec` 与 webview，desktop 再追加业务 codec；渲染端与主进程共用 `utils/markdown.ts`，三端的 `services/editorMarkdown.ts` 同样可独立由 Node 加载。

- **codec 按扩展归属**：每个扩展的 `markdown.ts` 导出 codec（纯函数，只 import 类型和 `@tau/markdown`）。扩展包用独立的 headless 入口（如 `@tau/editor-diagram/markdown`）导出 codec 列表。宿主只定义一次 codec 列表，kit 和主进程共用，避免两边漂移。
  - P8 落地形态：`@tau/editor/markdown` 聚合内置扩展的 40 个 codec（`editorMarkdownCodecs`），webview 的在 `@tau/editor-webview/markdown`（独立包）。`@tau/markdown` 框架不带任何元素类型：`MarkdownCodec = { type, directives?, serializer?, isVoid?, inlineWrapperDirective? }`，directive 导入（callout / underline / video 等 directive 语法）、导出序列化器、void 表、行内包裹表全部由 codec 注入；包级默认处理器函数（`importFromMarkdown` 等）已删除，只剩 `createMarkdownProcessor({ codecs })`。宿主合成一次：desktop `[...editorMarkdownCodecs, webviewCodec, ...desktopMarkdownCodecs]`（kit 与主进程共用 `@/utils/markdown`），mobile / extension `[...editorMarkdownCodecs, webviewCodec]`。
  - 导入端去类型化（2026-09-29 用户裁决后落地）：**方言完全由 codec 声明，框架零元素类型知识**。codec 形状扩为 `{ type, directives?, fence?, importNode?, serializer?, isVoid?, inlineWrapperDirective?, normalize?, inlineForm?, fenceSourceProperty?, childSeparator? }`——`fence` 声明式认领围栏语言（```mermaid 等，同语言重复认领建处理器即抛错，插件作者加新围栏零函数）、`importNode` 通用 mdast 认领（按声明顺序首个认领生效，宽认领排后）、`normalize` 导入后规范化钩子（link 剥块级子节点、paragraph 单图提升与降级、divide-line 去重）、`inlineForm` 段落内行内形态（image→inline-image、html-block→html-inline）、`childSeparator` 取代导出端 isList/isTable 硬编码、`fenceSourceProperty` 声明 code 认领方的属性级映射。框架 walker 只剩机制：解析装配、递归与位置映射、formatted 文本标记层、directive 查询与退化兜底、RETIRED 过滤、tau-node 还原（ER-006）、脚注收集追加与 `addExportFootnote`、definition / footnoteDefinition 忽略、未知节点兜底。标准方言 = `@tau/editor/markdown` 的 codec 集合本身。
- **双向位置映射是框架能力**，不让每个 codec 各自实现：
  - 块级映射由框架根据 mdast `position` 自动生成；
  - 行内格式文本的字符级映射（前后缀长度）由框架统一处理；
  - void 元素的属性级映射（如 code-block 的 `code` 对应源码里哪一段）由 codec 通过上下文声明，不声明就只有块级映射；
  - 现有 `positionMapper.test.ts` 的用例全部迁移并保持通过。
- 未知节点兜底语法（ER-006）在这一层实现。

### 8.3 「不依赖 DOM」怎么强制

只靠约定守不住，用三道机制：

1. `packages/markdown/tsconfig.json` 的 `lib` 不含 `DOM`，用了 `document`、`window`、`HTMLElement` 直接编译不过；
2. 包内测试跑在 vitest `environment: "node"`；
3. ESLint 与依赖护栏禁止 headless 代码加载 React、DOM、编辑器运行时或图表渲染器。框架不再引用 editor 类型；外包纯类型走 `/types`，模块增强仅从渲染入口加载。
4. `node-import.test.ts`：子进程用 `node -e` 以包名加载并做一次往返，同时验证「Node 可直接加载」与「无 DOM」。
5. `check-editor-extension-boundaries.mjs` 检查源码 API、工作区运行时依赖方向与四端 Node codec 组合；`--bundle` 核对内核实际加载图。护栏已纳入 `check:editor-refactor`。

HTML 剪贴板转 Markdown 这类需要 `DOMParser` 的逻辑不进 `@tau/markdown`，留在编辑器粘贴扩展里。
