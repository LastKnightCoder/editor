# 核心与扩展边界及推进约定

日期：2026-10-19 更新。早期拆分依据 ER-026、ER-027；当前单包组织按博客模板方案 64 的已确认边界调整。

状态：内核仍只内建 paragraph；主线仍内置的 23 个通用功能已收进 `packages/editor/src/extensions/`，顶层 editor-extensions 已删除。默认组合在 presets，对外 Editor 组件装配默认能力，createEditorKit 仍保持显式装配。HTML、TikZ、Typst、ABC、custom-block 保持独立插件。旧阶段审计见 [11](11-完成审计与验证矩阵.md)，本轮构建、独立交付与验证状态见 [实施记录 66](../plugin-system/66-博客模板插件化实施记录.md)。

推进记录：段落公共能力、四端场景矩阵和三个 Kit 工厂的具体设计及分步状态见 [08-段落公共能力与显式装配设计.md](08-段落公共能力与显式装配设计.md)。用户确认 source-view 保留独立支撑包；聊天不属于本次编辑器拆分，既有成果保留，后续不扩大到聊天输入/展示归属治理。

## 1. 目标与取舍

实施状态：段落工厂/追加保护、copy、marks/textCodecs、Kit 显式装配、根 UI、空态/转换和导航边界贡献已接线。共用宿主契约独立，功能领域及其类型/操作/codec/样式已迁完整包。目录已归一，不能据此跳过外部示例和整体完成审计。

核心和扩展边界清晰，我们自己的扩展与未来外部插件使用同一套公开能力。内置扩展不能深引核心内部文件、使用内部 store 或要求核心新增专属类型分支。

编辑器定位为具有稳定基础文档模型的块式富文本编辑器，不追求适配任意文档模型。**核心内建段落与文本，扩展定义更丰富的文档语义。** 这是对早期“任何具体元素都离开核心”的修正；不会因此恢复一组享有内部 API 特权的基础扩展。

本阶段以公开 API 足以实现真实功能为目标，不同时实现第三方动态加载、市场、权限体系、任意 schema 或新的生命周期框架。

## 2. 包与目录组织

内核、仍内置的通用功能和默认组合在一个 `packages/editor` 源码包中维护，发布为一个可执行 Editor npm 包。完整功能仍按领域组织：table、table-row、table-cell 同目录，列表与列表项同目录；不再分别保留旧功能 workspace 包或发布一组兼容 npm 包。

同一包的独立 @tau/editor/renderer 入口提供 ContentRenderer 和 createClient，集中封装发布正文接入；通用 Editor 本体及其他入口的运行图不加载发布协议。模板不维护 C23 映射、CSS 校验或插件 render 替换。HTML 等已迁出能力仍使用实际插件，不新增 iframe 或实例资源接口，具体边界见方案 64 第 7.6 节。

当前结构如下，23 个功能及继续独立的插件清单见 [方案 64 第 7.5 节](../plugin-system/64-数据驱动博客模板与模板插件化方案.md#75-默认扩展与资源范围)：

```text
packages/
  editor/
    src/core/              内核、基础段落/文本与通用机制
    src/extensions/        仍内置的 23 个通用功能，非独立工作区包
    src/presets/           standard 与默认组合
    src/Editor.tsx         对外组件，装配默认扩展与浏览器基础 UI
    src/renderer/          发布正文接入，仅由 renderer.ts 公开入口使用
  markdown/                无 DOM 的转换框架
  ui/                      通用视觉原语
  themes/                  主题
  editor-source-view/      多个扩展共用的源码预览能力
  editor-collab/            编辑器与协作的适配能力
  chat-ui/                 独立聊天领域

```

依赖方向为对外组件 → presets → 功能扩展 → core 公开 API，core 不反向引用功能实现或默认组合。功能入口统一为 `@tau/editor/extensions/<功能>`，原扩展 ID、命令 ID、节点字段和序列化语义保持。应用自己的数据库、白板、任务等业务扩展留应用，不因源码收拢进入默认 Editor。

source-view 属于共用支撑能力，chat-ui 属于聊天领域，协作适配也不必伪装成元素扩展。媒体、图表暂按完整领域保留，不自动细拆。06 中“基础领域合成一个 editor-basic 包”的建议不再作为目标；其现状调查仍可参考。

迁移同步 workspace/依赖和锁文件、包出口、TS/Vite/测试解析、Tailwind 扫描、ESLint/边界脚本及 Node/headless 入口；standard 现在从 `@tau/editor/presets/standard` 消费。旧 apps/blog 作为历史参考退出活跃工作区，不保留其旧入口；正式博客由独立模板插件接替。下面 C7～C14 等旧阶段说明记录当时拆分过程，涉及旧包名时以此处现行入口为准。

## 3. paragraph：核心内建，职责保持最小

| 核心拥有                                           | 扩展拥有                               |
| -------------------------------------------------- | -------------------------------------- |
| 文本节点、paragraph 的基础结构与最小渲染           | 标题、列表、表格、媒体等领域节点与渲染 |
| 空文档补段落、删除最后一块后的输入落点             | 退出列表/容器的条件与领域处理          |
| 创建、识别、判断空段落与追加基础输入落点的公共能力 | 在领域规则需要时调用核心段落能力       |
| 通用选区、导航与正常文本编辑机制                   | `# `、列表语法、代码围栏等快捷转换     |
| 未知节点的保留与降级                               | 类型转换菜单、具体文本格式效果         |

paragraph 始终存在，不再提供另一份可选 paragraph 扩展与核心争夺所有权。移除基础段落、为每个插件配置任意默认块均不作为当前能力。是否开放最小渲染定制及其约束留具体接口设计，不能借此更换基础模型。

保留当前 `paragraph`、`formatted` 等存量数据字段；把格式效果迁到扩展不等于重写文本数据。段落的最小 Markdown codec 归核心的纯入口，其他领域 codec 随各扩展；`@tau/markdown` 框架不因此反向引用 editor。

现有 `ParagraphElement`、段落判断与 AddParagraph 曾标为迁移桥。现在不再要求为了“段落迁出核心”机械删除它们：逐项评审是否适合作为公开 API、是否包含 UI/领域耦合，再稳定或替换。**归属已定不等于这些现有函数签名全部已获第三方稳定承诺。**

## 4. 装配：核心基础始终存在，产品功能显式选择

目标是移除核心对 `startExtensions` 产品功能集合的自动装配。`createEditorKit()` 不传功能扩展时，应得到可正常输入段落的基础编辑器；列表、表格、媒体、文本格式等由宿主显式选择。

可提供核心之外的稳定扩展组合预设，宿主显式展开使用。预设只负责组合，不放宿主业务服务，不被核心反向导入，也不必为一个数组先建新包。

`createEditorKit()` 只内建段落，各端继续显式安装场景能力，Bare/FromRegistry 工厂不恢复。standardExtensions 从 `@tau/editor/presets/standard` 消费；默认对外 Editor 在未提供/继承 kit 时装配通用默认组合及浏览器基础 UI。显式 kit 或继承 kit 时不替换其服务与组合；场景能力、预览菜单、缓存、服务派生和协作换源保持原行为。

## 5. 复制：核心遍历，领域修复片段

采用专门的复制片段贡献点，与日常文档 `normalize` 区分。日常规范化保证文档合法，部分复制可能需要解包一个合法容器，不能混用触发语义。

核心负责从选区取得片段、建立原节点与片段对应关系、判断完整选中、遍历和错误隔离。列表、表格、容器扩展负责自己的包装保留/解包和父子结构约束。核心不持有 table-cell、list-item 等类型名单。

贡献点设计约束：

- 只处理复制结果，不修改原文档或原选区。
- 由节点对应的扩展处理，避免多个扩展无约束地竞争修改同一节点。
- 处理顺序确定为先子后父，嵌套复制行为已验证，接口见 09/ER-028。
- 没有贡献或处理失败时保留未破坏的原片段；错误进入既有隔离机制，不能吞内容。
- 参数形状、片段对应关系与解包决策已按 09/ER-028 落地，并由列表/表格用例验证。

## 6. 标记：核心承载文本，格式扩展贡献效果

核心控制 Slate 的 attributes、children、最外层结构与组合渲染。粗体、斜体、代码、高亮、颜色、渐变等具体效果，以及相应命令、工具条、快捷语法和序列化规则，归基础文本格式扩展；外部插件可贡献自己的标记并与基础格式组合。

扩展不得任意丢弃文本子树或破坏 Slate 属性。组合次序、同一标记重复声明/覆盖、互斥格式、异常回退要在接口设计中明确，不依赖偶然 import 顺序。缺少扩展时继续显示文字并保留未知标记数据；恢复扩展后仍能解释原数据。

格式渲染已通过 marks 贡献，Markdown 通过 textCodecs 组合；标准格式归 @tau/editor-text-formatting，核心不绑定旧 FormattedText 组件。未知字段保真和位置映射已验证，旧端与历史图片映射限制仍以 ER-030/033 为准。

## 7. 转换菜单：核心提供机制，扩展定义转换

C7 实施更新：文本格式、彩色下划线和样式文本已成为三个独立包；色板/渐变与面板由格式包提供公开子入口，CSS 数据块不再留在核心。工具条状态、子面板与紧凑分组使用通用声明，核心不保存格式按钮 id 名单，详见 ER-037。

C8 实施更新：链接/注释/批注/键盘标签/分割线/Front Matter 已各自拥有完整包，核心旧定义和出口清零。Markdown 的配对 HTML 标签由 codec 声明，框架不识别 kbd；类型、字段、命令 id 和批注通用保真语法保持。六包与四端、纯入口及行为验证详见 ER-038/04。

C9 实施更新：标题完整包落地，核心 ref 不再提供标题专有滚动；目录定位与折叠归标题扩展，具体迁移和真实测试修复见 ER-039/04。

C10 实施更新：列表系五种节点、图标选择器与共享行为同属 @tau/editor-list；核心列表定义/操作和 emoji-mart 临时例外删除，普通列表不要求上传服务。独立装配与只读/折叠/返回验证见 ER-040/04。

C11 实施更新：表格三节点及操作/拖拽/删除防护/codec 同属 @tau/editor-table，核心不再保留表格定义与操作出口。末格/删列落点、多表菜单隔离、失效拖拽与只读验证见 ER-041/04。

C12 实施更新：引用/Callout/详情/高亮块分别迁完整包，Callout 样式和资源归本包，核心仅保留通用容器退出与子节点修复。独立装配、只读/标题同步、缺失颜色和纯 codec 验证见 ER-042/04。

C13 实施更新：Tabs 完整包已迁出，核心内建元素仅段落。默认块导航按 isolateBlockNavigation 声明接管，不含 tabs 名单；只读切换、作用域拖拽、旧数据与保真见 ER-043/04。目录归一、外部示例和旧入口收回随后由 C14 至 C16 完成。

核心保留命令分发、菜单挂载、通用移动/复制/剪切/删除及基础段落操作。标题、列表、容器扩展分别定义可接受的源结构、目标构造、解包/包装规则和菜单适用条件。将节点改为 paragraph 的底层能力不负责猜测任意领域容器如何解包。

沿用已有 commands/menu 贡献体系，先移走核心里的转换源/容器名单；不另建覆盖所有元素两两转换的通用系统。跨域转换有需要时明确参与者及公开契约，不允许互相深引内部工具。

C4 已实施（ER-034）：menuFor 按源类型接线、mergeChildren 显式组合共同子菜单；标题/列表/容器自行提供命令与转换条件。旧 tau.transform.node 仅兼容转发，核心类型名单及转换实现已删除。合法菜单顺序与命令调用验证通过，规则已随 C9 至 C12 迁入领域包。

## 8. 后续推进与验收

下表是已执行的推进顺序与验收要求；四步实现与逐项自动化验收已完成，证据见 11。

| 步骤                  | 交付                                                              | 验收重点                                                                   |
| --------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 1. 接口与消费者设计   | 段落公共能力、装配迁移、复制/标记贡献的具体提案；四端场景矩阵     | 区分复用现有机制和真实新增缺口；函数名/签名、顺序、冲突和错误语义可审阅    |
| 2. 核心与贡献点实现   | 最小段落基础；显式功能装配；列表/表格复制与基础标记作为真实消费者 | 下方行为矩阵、类型、headless、错误隔离与场景覆盖；不为测试临时放宽内部导入 |
| 3. 扩展逐个完整归属   | 功能包及类型、命令、codec、样式、转换规则迁移；同步目录与工具链   | 完整功能不留半个实现于核心；核心不得反向依赖；跨端行为及必要生产资源检查   |
| 4. 外部开发者视角验证 | 示例扩展，仅依赖公开包，提供节点/命令/菜单/序列化并由宿主接线     | 核心无需新增类型分支；不得深引、复制私有实现或增加宿主专用后门             |

最低行为矩阵：

- 段落：空文档、删除最后一块、void 后追加、退出特殊块、只读、嵌套容器落点。
- 装配：基础编辑器可输入；四端现有场景覆盖不变；预览/测高匹配编辑处；服务派生与协作换源不重建。
- 复制：完整/部分列表项与单元格、跨块选区、嵌套列表/表格/容器、空选区、未知节点、贡献失败；原文档不变。
- 标记：多个效果组合、次序/冲突、缺失/异常贡献、未知标记保留、Markdown 往返与位置映射。
- 转换：段落到标题/列表、容器解包及嵌套转换、菜单可用条件与只读限制；既有命令 ID 不变。

视觉与实机由用户验收；类型、行为、依赖方向、无 DOM 入口及必要构建由 Agent 验证。测试通过不代替职责判断，目录迁完不等于插件能力已经可对外发布。
