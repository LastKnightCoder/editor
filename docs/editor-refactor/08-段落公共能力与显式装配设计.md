## 1. 设计起点调查与迁移结论（历史基线）

| 当前代码事实                                                                                                   | 设计结论                                                                                                    |
| -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| paragraph 扩展同时包含 renderer、drag、格式 toolbar、inlineCode 插件                                           | 最小段落保留结构、渲染和通用拖拽声明；toolbar 与反引号加 code 行为归文本格式扩展，不能整份内置              |

## 2. 四端场景矩阵

### 2.1 共用集合的准确含义

以下 B/X 是本文说明用缩写，不是要新增的全局配置或包。

- **B（原隐式底座，现为显式产品组合＋核心段落）**：`defaultMenuExtension`、paragraph、underline、header、image、inline-image、image-gallery、bulleted-list、check-list、check-list-item、numbered-list、list-item、tabs、tab-pane、detail、highlight-block、blockquote、callout、link、comment、divide-line、kbd、table、table-row、table-cell、styled-text、audio、video、front-matter、annotation。当前由 `editor-extensions/standard.ts` 保序组合，并显式安装文本格式和媒体 UI；paragraph 由核心提供。
- **X（当前四端显式共用扩展）**：五种 diagram、两种 HTML、previewMenuExtension、code-block、两种 math、emoji、custom-block。保留现有各端组合顺序；webview 等另列。
- **D（桌面静态追加）**：Markdown 粘贴导入、webview、设置订阅驱动的 image/image-gallery 覆盖。
- **M（移动静态追加）**：Markdown 粘贴导入、webview、移动设置驱动的 image/image-gallery 覆盖。

## 3. 最小核心段落的范围

保留现有文档形状：

```ts
{ type: "paragraph", children: [{ type: "formatted", text: "" }] }
```

paragraph 子节点仍允许已注册行内元素和文本，不缩窄为只有纯文字。不改存量标记字段，不在建空段落时继承相邻文本的 mark。工厂每次产生独立对象及 children，不能共享可变空节点。

| 现有位置                                                  | 归属与处理                                                                                  |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `extensions/paragraph/components/Paragraph`               | 核心最小渲染；保留 Slate 属性、子树、间距和现有聚焦行为，本轮不顺带改样式或全局焦点事件体系 |
| paragraph 的 `drag: true`                                 | 核心段落声明，继续使用通用拖拽机制                                                          |
| paragraph 的 `hovering-bar-configs`、`plugins/inlineCode` | 文本格式能力，拆离核心段落对象，显式装到现有场景                                            |
| `hotkeys/formattedText.ts`、`components/FormattedText`    | 格式领域后续一起接管；不要只搬 toolbar 留下隐藏格式功能                                     |
| `plugins/withNormalize`、`utils/normalizeEditorContent`   | 统一使用空段落创建函数；按 ER-047 不识别退役名单，旧数据清理由升级承担                      |
| `utils/nodeOperations.deleteVoidBlock`                    | 通用删除及补段落落点保留；不要与普通 `deleteNode` 混为一种规则                              |
| `extensions/paragraph/markdown.ts`                        | 基础导入/序列化归核心；图片提升特判迁给媒体，通用 `context.demote` 与空输入行为做往返对照   |

根 `Editor` 通过 ExtensionLayers 挂载声明的 UI；MediaUrlInputModal 等组件及其所有权、只读和释放逻辑已归媒体包。核心没有媒体 UI 专属挂载。

## 4. 段落公共 API 设计

以下接口已由 08-A/C2 实现，当前出口见 10；它们服务于既定基础模型，不承诺任意 schema。

### 4.1 纯数据与查询

| API                                                                                      | 语义与处理                                                                                            | 当前消费者 / 动机                                                   |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `createParagraph(): ParagraphElement`（新增）                                            | 返回全新空段落；不接受任意 schema/options，不操作 editor                                              | normalizeEditorContent、withNormalize、追加与 void 删除的重复构造   |
| `isParagraphElement(node: Node): node is ParagraphElement`（保留）                       | 对有效 Slate Node 做段落种类判断，先排除文本/Editor；不是外部 JSON 校验器                             | code-block/custom-block 及列表/容器规则                             |
| `isAtParagraphStart(editor: Editor): boolean`（保留）                                    | 折叠选区，最近块是 paragraph，且 anchor 在其起点；无选区/展开选区返回 false                           | 特殊块前聚焦、列表/容器退出与缩进                                   |
| `isEmptyParagraph(editor: Editor, paragraph: ParagraphElement): boolean`（新增明确目标） | 初期保持“仅一个子节点”的既有插入判断口径；空文本为 true，行内元素调用其 `isEmpty`，缺失或失败为 false | 替代含领域分支的空段落判断；避免字符串为空却含图片/公式时误删       |
| `isParagraphAndEmpty(editor: Editor): boolean`（兼容期保留）                             | 保持现有选区查询行为后委托上项，不增加“必须折叠”的隐式条件；新调用者优先传明确段落                    | 现有 insertElement、媒体 ingest、table/list/callout/code-block 行为 |

`isBlockElementEmpty` 对段落目前采用 every，而 `isParagraphAndEmpty` 要求一个子节点。二者不是同一个口径，不能为了 DRY 合并后改变行为；一般递归空态判断与“允许替换当前空段落”的判断应分开。

纯工厂、类型和种类判断建议从一个窄的 `@tau/editor/api/paragraph` 入口暴露，同时在渲染用 `/api` 重导出；该新入口不带 React/DOM。编辑器状态查询继续放 `/api`。这是为 Node/codec 与扩展共用基础模型的具体入口提案，不再建 paragraph 包。

迁移空态规则时，link/underline/styled-text/kbd/inline-image 要用已有 `ElementSpec.isEmpty` 表达原判断；不新增第二套注册表。缺扩展时保留节点，不能退化为按文字长度删节点。paragraph codec 的 image 特判同样是实施门槛：先确认媒体 codec 能保持导入提升和位置映射，再删除原分支，不在纯 factory 提取时顺手改它。

### 4.2 追加与 AddParagraph

保留 `insertParagraphAndFocus` 的概念，收紧为：

```ts
insertParagraphAndFocus(editor: Editor, target: Element): Path | null;
```

它是编辑器交互 API，不是 headless 数据工厂。语义如下：

1. 以目标元素身份解析当前路径，在其**同父级下一个位置**插入一个空段落并选中、聚焦；不自动跳出整个嵌套容器。
2. 只读返回 null，不写内容、不改焦点；读取现有 ReactEditor 的只读状态，UI 同时保留 useReadOnly 防护。
3. 目标已卸载、删除、替换时返回 null，不按陈旧 path 写到另一个节点；不把预期失效算成扩展故障。
4. 先验证目标再改选区/焦点；真实 transform 失败继续抛给现有错误处理，不把所有异常吞成 null。
5. 成功返回插入路径；现有 void 返回消费者可忽略结果，新增 UI 回调依此判定是否真正完成。已有写入成功但 DOM 聚焦不可用应单独验证，不能回滚已落文档或误报为未插入。

`AddParagraph` 继续留核心的编辑器专用 UI，经 `/api` 使用，不迁到通用 ui，也不新增包。保持 `element`、`onAddParagraph?`、ref 的 `addParagraph(): void` 形状；点击和 ref 复用上述动作，只有插入成功才触发回调。保留现有占位字符、间距和事件阻止语义。

真实消费者不仅是 source-view/code-block，还有 core 中的图片、音视频、图库、表格、tabs、detail、callout、blockquote、highlight-block，以及表格末尾退出路径。后续扩展迁移时都应转用同一公开入口。

目前追加函数先 focus 再 findPath，没有只读/失效保护；AddParagraph 在函数返回后无条件回调。这些收紧是明确的行为修复，需要单独测试，不冒充纯搬运。暂不增加平行命令体系或用 dispatcher 的 boolean 作为“已经插入”的证据：现有 dispatcher 返回 true 只表示命令已执行/启动，不保证有写入。

### 4.3 删除与退出不统一成万能操作

- `deleteVoidBlock` 当前在原位置补段落，不只是删除最后一个块才补；保留此语义并复用 createParagraph。
- 普通 `deleteNode` 当前在根仅剩一个节点时清内容，否则移除；不要在本轮改成总是替换 paragraph。
- 文档根被清空时由 normalize 保底；列表/表格/容器退出条件归对应扩展，调用核心基础操作即可。
- source-view 在有后续元素时先聚焦后续元素，无后续落点才追加；code-block 的追加也有自身触发条件。核心不接管这些领域判断。

## 5. 显式装配与工厂迁移

### 5.1 目标工厂只有一个公开正常入口

`createEditorKit(options)` 内建唯一的核心段落声明和必要机制；功能贡献仅来自 `options.extensions`。不传服务/功能扩展时应能运行基础段落编辑器（React 组件仍需遵循既有宿主挂载条件），不要求提供媒体 slots 或文件上传才能输入文字。

- 内部可继续用现有 ExtensionAssembly 表达段落，核心声明不再是供宿主手动安装的可选 paragraph 实例；不建第二套分发框架。
- `paragraph` 元素及核心 `tau.paragraph` 标识保留。通过 create/extend/per-instance extensions 覆盖它应拒绝，即使 `override: true`；对非核心图片/标题等的显式覆盖保持原有语义。
- 段落 renderer 定制暂不新增 API；现有仓内生产调用没有发现替换 paragraph，测试有替换断言，须明确改为保护核心段落，并用普通自定义元素继续测试 override 机制。
- `kit.extend({ services })` 继续复用 assembly；相同扩展实例集合派生的缓存、父子服务语义不变，不在本轮重写缓存键或 registry。

### 5.2 三个原工厂的迁移对照（已完成）

| 当前入口                      | 仓内证据                                                 | 推荐迁移                                                                                                                                |
| ----------------------------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `createEditorKit`             | 四端统一场景工厂使用                                     | 改为核心基础＋显式扩展；同批迁四端装配，禁止静默丢默认功能                                                                              |
| `createBareEditorKit`         | 生产调用只有桌面箭头；命令/拖拽/ingest/浮层等测试也使用  | 箭头改用主工厂＋inline-math/link＋显式格式能力；测试改用主工厂或直接测试底层 assembly；消费者清零后删除出口，不留第二种“无段落”产品模型 |
| `createEditorKitFromRegistry` | 在 packages/apps TS/TSX 中只发现定义及根转出，未发现调用 | 实施前复查消费者，清零则删定义/出口和 builtins 选项；不为无消费者能力引入新 overload                                                    |

上述消费者范围为当前仓内源码与测试，不代表已经调查任何外部发布使用者。本期未承诺外部兼容版本，首次对外发布前须确认最终公开面。

### 5.3 从隐式底座到显式组合

1. 先固定 §2 的场景集合、顺序、菜单/命令/格式能力基线，而非只比较 elementTypes。
2. 将当前 B 分成核心段落、通用块操作机制、文本格式贡献和其余领域扩展；默认转换菜单随领域，不能把整个 defaultMenu 当通用核心。
3. 各宿主保留自己的场景工厂与实例缓存，显式安装原先隐含的功能。源于同一功能的多个元素可导出稳定组，不让宿主手写内部组合细节。
4. 初期允许在迁移提交中用既有 named exports 过渡，但不新增核心汇总转出或新的共享“全功能 Kit”；扩展迁出后切为各包公开入口并删除过渡。跨步骤未清零时明确记录核心仍有领域依赖。
5. 当前 `<Editor extensions>` 的实例级追加仍保持非核心类型覆盖行为；基础 paragraph 保护同时覆盖该通道。独立公开预设如有需要在核心外提供，不能形成 core → preset → extension → core。
6. Arrow 场景不能因删除 paragraph 的 toolbar/inlineCode 而失去原有格式行为。补显式文本格式扩展，同时确保 elementTypes 仍仅三个；默认菜单以前未装的转换条目也不能意外加上。

取消隐式装配、纯化核心入口和扩展物理拆包是三个验收点，可以分提交完成，但不能把第一项通过当作后两项完成。

## 6. 分步实施建议

| 步骤                     | 具体范围                                                                                        | 完成条件                                                                           |

| C. 显式装配切换          | 同批处理四端底座、Arrow、两个额外桌面消费者、三个工厂及 paragraph 覆盖保护                      | 完整场景矩阵/命令/格式/codec 基线通过，缓存与服务派生不变                          |

这不是要求在设计轮完成全部实现。A 可先行，C 依赖 B 中影响最小核心的格式能力接线；复制接口本身在对应列表/表格迁出前完成即可，避免人为把所有后续工作绑成一个大提交。
