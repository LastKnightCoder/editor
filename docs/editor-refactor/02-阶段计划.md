# 02 · 阶段计划

每个阶段都要**独立可合并**：做完一个阶段，应用能正常运行，测试全绿，再开始下一个阶段。阶段内按任务粒度提交。

通用验证（每个阶段收尾都要跑）：

```bash
pnpm check                                   # desktop tsc
pnpm --filter @tau/ui check
pnpm --filter @tau/themes test          # P1 起
pnpm --filter @tau/editor test            # editor 单测
pnpm --filter @tau/collaboration test
pnpm --filter blog test
pnpm --filter mobile test
pnpm --filter browser-extension test
pnpm lint
pnpm check:editor-refactor               # 基线只许降；阶段完成后 --update 下调
```

涉及视觉的阶段还要在 desktop showcase（`pnpm showcase`）里做明暗 × 至少两套主题的截图对比，截图结论记进 04。

## P1 · 主题整体迁到 `@tau/themes`

目的：主题只有一个归属包。`@tau/ui` 不再有 `theme/` 目录，也不做转出；所有使用方直接从 `@tau/themes` 导入（ER-011）。

包结构（按依赖分层的子路径，根入口最纯）：

| 入口                       | 内容                                                                        | 允许的依赖                       |
| -------------------------- | --------------------------------------------------------------------------- | -------------------------------- |
| `@tau/themes`              | `tokenContract`、`defineTheme` 与注册表、内置主题、存储键常量               | 无（纯数据 + 纯函数，node 可跑） |
| `@tau/themes/dom`          | `applyThemeToDom`、`createThemeBootstrapScript`、`resolveThemePreference`   | DOM                              |
| `@tau/themes/react`        | `createThemeRuntime`、`useThemeStore`、`initThemeRuntime`、`nextAppearance` | DOM、react（peer）、zustand      |
| `@tau/themes/tokens.css`   | 尺度 `:root` + 各主题 `[data-theme][data-mode]` 数据块                      | —                                |
| `@tau/themes/tailwind.css` | `@theme inline` 语义类映射（`bg-page`、`text-ink-1`…）                      | Tailwind v4                      |

tokens.css 拆成两份，这样不用 Tailwind 的使用方（比如将来的第三方主题预览）也能只引变量。
