发布 · 站点设置抽屉重设计

三个方案都用的是海盐浅色 token，宽度和现在一样是 460px。字段都来自现在的 GitHub Pages 插件。抽屉里要放的东西分三类：发布目标（连接）、博客模板、站点信息。

现在的问题

  1. 所有字段平铺，字重一样，看不出「凭证 → 仓库 → 分支」这条依赖链，也看不出哪些是低频的高级项（提交者、Git Push、缓存目录）。
  2. 「读取仓库」「读取分支」做成了整行宽的按钮，看起来像分隔条，反而把字段和字段切开了。
  3. 按钮有三种：插件的「保存发布配置」、宿主的「测试连接」、底部的「完成」。用户不知道哪个才会保存。
  4. 「测试连接」是宿主追加在插件内容后面的，和插件最后一个按钮之间没有间距，连接结果也只用一个跟在后面的文字表示。
  5. 「管理发布插件」这个 ghost 按钮悬在两个分区中间，归属不清。

方案 A · 分组卡片 + 状态头 推荐

还是单页滚动，分成三个设置组卡片。连接状态和「测试连接」收进发布目标卡的头部。「读取」改成输入框尾部的内联动作。低频项折叠进「高级选项」。全部自动保存，底部只留「完成」。

结构

  • 抽屉只有三层：组标题 → 组卡片 → 行，组间距 14px，组内用细分隔线。
  • 卡片头部是状态条：连接状态、目标摘要、测试连接都在这里。失败时整条变成 danger 底色，出错的字段同时描红。
  • 「读取」挂在输入框尾部，分支读取后直接变成下拉，不再单独占一行。
  • 「保存发布配置」删掉，失焦时自动保存，底部「完成」只负责关闭。

代价

  • 插件要改：用宿主给的 SettingsGroup / SettingsRow 原语渲染行，并把「测试连接」交给宿主的状态头（插件暴露 checkConnection）。
  • 和「设置」页的分组视觉一致，学习成本最低，改动集中。

方案 B · 摘要首页 + 下钻子页

抽屉首页只放站点身份卡和三条摘要行，点进去在抽屉内切到子页编辑（类似 iOS 设置）。层级最清楚，代价是多一次点击。
