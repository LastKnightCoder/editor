# 升级公告

每个发布版本一个文件：`<版本号>.md`（如 `0.54.0.md`），写给用户看的更新说明。
开发流水仍记在根目录 `UPDATE_LOG.md`，两者不互相生成。

## 硬约束

- `pnpm publish:desktop` 发布前校验当前版本的公告文件存在且非空，缺失即拒绝发布。
- 公告随安装包打进应用（升级后展示），同时写进 OSS 上的 `latest*.yml`（升级前展示）。
- 发布后不要再改已发布版本的公告：已安装的客户端只认安装包里那一份。

## 用户在哪里看到

- 升级前：发现新版本的通知点「查看更新内容」；设置 → 关于与更新，应用卡下方直接展示。
- 升级后：首次启动弹出通知，点「查看更新内容」打开公告；关于页可随时查看本版内容。
- 跨版本升级（如 0.52 → 0.54）合并展示中间每个版本的公告，从新到旧排列。
- 官网「更新日志」（`/changelog/`）构建时读取本目录，发布后重新部署官网才会出现新版本。

## 写法

用 Markdown，不写版本号标题（界面会自动加）。按需使用以下分组，没有内容的分组省略：

```markdown
## 新功能

- **收集箱**：速记和网页剪藏先进收集箱，转成卡片后自动离开。

## 改进

- 表格支持从电子表格直接粘贴多行多列。

## 修复

- 修复了白板连线在缩放后错位的问题。
```

- 用用户能感知的语言描述变化，不写 commit 前缀、模块名、内部编号。
- 一条一句话，先说用户得到了什么，必要时再说怎么用。
- 移除或行为变化的功能务必写明，并告诉用户替代做法。
