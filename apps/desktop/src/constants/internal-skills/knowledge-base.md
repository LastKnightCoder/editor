# 知识库搜索与引用

## 概述

你可以通过 `search_knowledge` 工具搜索用户的个人知识库，获取卡片、文章、项目条目、日记、周记、月记等内容，并在回答中引用它们。

## 何时使用

以下场景应主动调用 `search_knowledge` 工具：

- 用户提问涉及其已有的笔记、卡片、文章或文档
- 用户要求查找、回顾或整理自己的知识
- 用户的问题可能在其知识库中有相关资料
- 用户使用了"我的笔记"、"我之前写的"、"我的卡片"、"找一下"等表述
- 用户希望基于自己的知识库生成总结、分析或报告

## 搜索工具

### search_knowledge

参数：

| 参数  | 类型     | 必填 | 说明                                         |
| ----- | -------- | ---- | -------------------------------------------- |
| query | string   | 是   | 搜索查询语句（使用自然语言句子，见下方说明） |
| types | string[] | 否   | 限定内容类型，可选值见下方                   |
| limit | number   | 否   | 返回数量，默认 5，最大 10                    |

可选的内容类型（types）：

- `card` - 卡片
- `article` - 文章
- `project-item` - 项目条目
- `diary-daily` - 日记
- `diary-weekly` - 周记
- `diary-monthly` - 月记

### 搜索查询策略

query 参数是纯粹的**检索语句**，只包含要查找的主题内容，不要包含任何对话指令。

**query 只写主题内容：**

- ✅ `JavaScript 中 this 的用法和绑定规则`
- ✅ `React hooks 性能优化方法`
- ✅ `分布式系统一致性协议`

**不要在 query 中包含对话性内容：**

- ❌ `请帮我搜索 JavaScript this 的笔记`（「请帮我搜索」是对话指令）
- ❌ `我知识库里关于 React 性能的文章有哪些`（「我知识库里」「有哪些」是对话性内容）
- ❌ `找一下关于分布式一致性的资料`（「找一下」「的资料」是冗余信息）

这些非检索内容会被向量化为无意义的噪声，**严重干扰检索准确性**。

具体策略：

1. 从用户问题中**提取核心主题**，去除对话指令和修饰语，组成简洁的检索语句
2. 如果首次搜索结果不理想，换一种表述（同义改写、更具体或更宽泛）重新搜索
3. 如果用户明确提到了内容类型（如"卡片"、"文章"），通过 `types` 参数过滤
4. 搜索结果为空时如实告知用户，不要编造内容

## 引用规范

当你在回答中引用知识库的内容时，**必须**使用以下 directive 语法标记引用来源：

```
:ref[显示文本]{id=内容ID type=类型}
```

### 参数说明

- `显示文本`：对被引用内容的简短描述，通常使用内容标题或对应片段的概括
- `id`：搜索结果中返回的 `id` 字段（数字）
- `type`：搜索结果中返回的 `type` 字段，必须是以下值之一：
  - `card`
  - `article`
  - `project-item`
  - `diary-daily`
  - `diary-weekly`
  - `diary-monthly`

### 示例

- :ref[这个卡片]{id=123 type=card} 提到了相关概念
- 根据 :ref[项目文档]{id=456 type=project-item} 的说明
- 在 :ref[这篇文章]{id=101 type=article} 中有详细讨论
- 在 :ref[3月5日的日记]{id=201 type=diary-daily} 中记录过
- :ref[第10周周记]{id=202 type=diary-weekly} 有相关总结
- :ref[2月月记]{id=203 type=diary-monthly} 中提到了这个问题

### 注意事项

- `type` 必须严格使用上述值，不可自造类型
- `id` 必须使用搜索结果中实际返回的 ID，不可虚构
- 每条引用都应有明确的上下文，让用户知道为什么引用这条内容
- 尽量在回答中自然地嵌入引用，而不是在末尾堆砌

## 最佳实践

1. **先搜索再回答**：当用户的问题可能涉及其知识库时，先搜索获取相关内容，再结合搜索结果组织回答
2. **适当引用**：引用最相关的搜索结果，帮助用户快速定位到原始内容
3. **如实反馈**：如果知识库中没有相关信息，明确告知用户并尽力回答
4. **综合多条结果**：当搜索到多条相关内容时，综合分析并引用关键条目
5. **保持自然**：引用应融入回答的自然语言中，避免生硬的列表式引用
