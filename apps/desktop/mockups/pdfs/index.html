PDF 列表页 · 方案与决策

现状：pages/PdfView/PdfListView 是 320px 宽的渐变文字卡网格，只显示文件名 + 「本地 / 远程」标签；右下角浮动 + 打开 antd 弹窗（本地 / 远程两个 Tab，单选文件）；卡片「⋮」里只有上传、删除。tags / category 字段存在但从未有 UI。这次只定列表页，详情页（阅读器 + 标注 + AI 对话）下一步单独出方案。

① 三套结构

三套共用同一套空态、添加对话框、拖入导入、条目菜单与删除确认（在方案 A 页用顶栏按钮切换查看）。

A 文档墙 + 列表切换 推荐

首页缩略图网格 + 「最近打开」续读行；右上角可切成行式列表。与微信读书书架同构。

识别度最高（论文 / 书一眼认出）；缩略图要生成与缓存。

B 纯列表

只有行式列表（= A 的列表排布），列头排序；无缩略图、无续读行。

最省工、密度高；像文件管理器，缺少「资料库」感。

C 列表 + 预览栏

左列表，右 360px 预览（缩略图 / 元信息 / 标注摘要），再点「打开」。

多一步；预览内容与详情页重复。

② 需要你拍板的点

高亮的是我的推荐。

1
页面结构
A 文档墙 + 列表切换与微信读书书架一致，心智统一
B 纯列表最省工
C 列表 + 预览栏先预览再打开
2
封面
首页缩略图首次打开 / 导入时渲染第 1 页并缓存成小图；远程文件未缓存前先用文字封面兜底
文字色块按文件名派生色，零成本；论文之间难区分
3
「最近打开」续读行
要Pdf 表新增 lastOpenTime / lastPage，详情页翻页时写回；打开直接跳到读到的页
不要排序用 updateTime 凑合，不改表
4
分类 / 标签
暂不做只按来源筛选 + 搜索；tags / category 字段保留不用（YAGNI）
标签挂侧栏子项同文章 / 白板口径；需要补标签编辑 UI
5
列表里露出 AI 检索状态
只在列表排布露出「可检索 / 索引中 / 失败」一列 + 菜单「建立 AI 索引」；封面墙不显示
不露出索引是后台细节，失败只在 AI 对话里提示
6
添加方式
对话框 + 整页拖入，支持多选本地 / 链接两个页签；链接自动推断文件名；「上传到云端」选项沿用本机偏好
保持现状单文件、远程需手填文件名

④ 落地分期（按推荐组合）

  1. 列表页：features/pdfs 新建 pdfs.page.tsx（definePage）+ queries（列表 + 聚合统计）；封面 / 列表两种排布、来源筛选、排序、搜索；添加对话框 + 拖入；条目菜单（重命名 / 上传 / 删除）。侧栏 app/navigation.ts 学习组加「PDF」。
  2. 缩略图：主进程或渲染端渲染第 1 页 → 缓存目录，列表按需取。
