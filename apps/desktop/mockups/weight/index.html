减重插件 · 页面设计方案

一个页面型插件（categories: ["page"]），覆盖你提的四件事：记录早晚体重、记录减肥行动和饮食、接入 AI 分析、用图表看趋势。三个方案共用同一份 90 天模拟数据（8/1 起，经历基线 → 饭后散步 → 16:8 断食 → 国庆 → 控碳水 + 散步五个阶段），用 cream / cocoa 两套主题的真实取值，右上角可切换明暗。图表悬停有提示，「记录今天」弹窗、范围切换、AI 流式输出都可以直接点。

二轮 · 记录为主，看见数字就能克制

你的反馈：方法只有两个，少吃、多动，用不上「实验」；页面主要是记录，让自己看到数字从而克制。据此重做了一个方案 D，一轮的 A/B/C 保留在下面作参考。

方案 D（二轮推荐）

减重记账本 · 体重 + 热量余额 + 运动，一屏记完看完

把「少吃」变成一个随时可见的数字：今天还能吃多少 kcal。吃之前在右上角写一句「奶茶一杯」，还没回车就能看到「≈ 380 kcal，记下后还能吃 N，相当于散步 95 分钟」，这一步就是克制发生的地方。少吃 / 多动不用手动打勾：摄入没超预算就算少吃，运动满 30 分钟就算多动，由记录自动判定。

✓ 顶部三张卡：今天晨重（早晚两个记录位）/ 热量余额环 / 运动进度 + 连续天数 ✓ 体重趋势和每日摄入柱上下对齐同一时间轴（不做双轴），超预算的日子一眼看出来，对得上后面的体重回升 ✓ 打卡格（8 周 × 7 天，两颗点 = 少吃 / 多动）和「做到了，第二天轻多少」四组对比，回答「少吃和多动哪个更管用」 ✓ AI 分「今天 / 本周」两段：今天提醒晚饭余量和还差多少运动，本周总结速率和破功规律 ✗ 依赖饮食记录完整：漏记一餐，余额和打卡都会偏乐观（缓解：晚饭时段若无记录，流水里显示「还没记」占位）
打开方案 D →
  • 删掉了：实验概念、阶段底带、行动标签库、单项行动排行。行动只剩两个，且自动判定；
  • 新增配置（插件设置里填一次）：每日热量预算（默认 1800）、运动目标（默认 30 分钟）、目标体重、身高；
  • 热量来源：一句话记录由 AI 估算，可点开修改；常吃的东西记住上次的数值，第二次不再调用 AI；
  • 称重弹窗只剩体重一项（起床 / 睡前），饮食和运动都走右上角一句话记录。

一轮 · 先想清楚：这个页面要帮你做什么决定

你说的核心诉求是「看什么样的方式减肥最有效」。所以页面的主线不是记账，而是一个反馈循环：

每天称重→记下当天做了什么、吃了什么→系统算出每种行动的效果→AI 解读、给出下一步→留下有效的，换掉无效的
  • 单日体重是噪声，趋势才是信号：一天之内水分、盐、胃容物能让读数差 1–2 kg。三个方案的主线都是 晨重的 7 日滑动均值，单日读数只作浅色散点。睡前体重单独保留，用来看日内波动和「吃多了」的即时反馈，但不参与趋势计算（早晚混算会让曲线锯齿化）；
  • 两种「效果」口径：
    ① 行动的短期效果 = 做了某行动的日子，第二天晨重的平均变化，减去没做的日子。能回答「聚餐让我涨多少」「睡够 7 小时有没有用」，但会被水分干扰，样本少于 8 天时标「样本少」并淡化；
    ② 阶段的长期效果 = 一段时间内 7 日均值的回归斜率（kg/周）。能回答「断食那三周和控碳水这三周哪个更有效」，更可靠，这是 「实验」 概念的来源；
  • 记录必须快：称完体重 5 秒内记完。弹窗打开即聚焦数字框、预填昨天读数，按早上 / 晚上自动选「起床 / 睡前」；行动是可点选的标签（可自定义），饮食是一句自然语言，AI 负责估热量，不做食物数据库；
  • AI 是解读者，不是计算器：所有数字由插件本地算好，AI 只拿到汇总后的结构化数据（每日体重、行动、饮食文字、阶段统计），负责解释原因、找规律、提建议，回答里引用的数字可点击定位到图表。

一轮 · 三个方案（参考）

方案 A

趋势仪表盘 · 一屏总览 + AI 常驻右栏

打开就是全局：今日体重 + 早晚两个记录位、四个关键指标（7 日均值 / 周速率 / 目标进度 / 预计到达）、90 天大趋势图（实验阶段作底带，下方是行动条带）、行动效果排行、每日变化热力图。右栏常驻 AI 分析卡、今日记录和当前实验。

✓ 信息最全，一眼能看到「在不在正轨上」；AI 结论常驻，不用点 ✗ 内容多，单项深度有限；每天打开只为记一个数时略重
打开方案 A →
方案 B

每日日志 · 时间线 + 单日详情

以「天」为单位：顶部是 45 天趋势条，左侧按周分组的日志流（每天的早晚体重、行动类别图标、次晨变化），右侧是选中那一天的完整记录：起床 / 睡前 / 次日晨重三格、行动标签、按餐的饮食和热量，以及 AI 对这一天的点评和「相似的日子」。

✓ 记录与回看最顺手，饮食细节最清楚；「这一天为什么涨了」最直观 ✗ 宏观对比弱，「哪种方式最有效」要靠 AI 和相似日推断，没有正式的对比视图
打开方案 B →
方案 C

减重实验室 · 实验索引 + 实验报告

把「找到最有效的方法」做成一等概念：每段时期是一个实验（假设 + 行动 + 起止日期），左侧列出所有实验和它们的周速率，右侧是选中实验的报告：结论四格（速率 / 相比基线倍数 / 区间变化 / 执行率）、带前后对照的趋势图、执行日历、和其他阶段的对比、单项行动排行；AI 写实验结论并建议下一个实验。

✓ 最贴合「量化哪种方式有效」：结论有对照、有执行率，不靠感觉；AI 能推荐下一个实验 ✗ 多一个「实验」概念要维护；只想随手记的日子要多走一步（左上角快捷记录缓解）
打开方案 C →

可以混搭

  • 推荐组合：以 C 为骨架做两个子视图 概览 | 实验（页内 segmented 切换）：「概览」= A 的仪表盘，「实验」= C 的报告；B 的单日详情做成点击趋势图某一天、或热力格子时弹出的侧抽屉；
  • A 的「今日卡早晚两个记录位」可以放进任意方案，也适合额外贡献一个首页卡片（home 扩展点），不用进插件页就能记体重；
  • C 的「AI 建议下一个实验」可以作为 A 右栏 AI 卡的固定一节。

三个方案共用的视觉与图表规范

  • 体重主线用 accent（赭橙）2px 线，单日读数为 ink-3 浅点，睡前为空心圈，目标为 ok 绿虚线。全页只有一条 accent 线，视线自然落在趋势上；
  • 行动类别色（数据色，不进主题词表）：饮食 运动 断食 作息 放纵。顺序固定，已用色盲校验脚本验过：浅色主题相邻对色盲 ΔE ≥ 8.2，深色主题 7.5，所以标签始终 图标 + 文字 一起出现，颜色只染小图标底；
  • 变化方向用发散色：蓝 = 变轻，红 = 变重，中点是中性米灰。不用「绿好红坏」，避免和类别色、状态色撞色；数字上的 −0.3 / +0.3 仍用 ok / danger 文字色，并带正负号，不只靠颜色；
  • 图表只有一根纵轴（kg），不做双轴；热量这类不同量纲的数据单独成图或只出现在列表；
  • 每个图表都有悬停提示（趋势图十字线 + 当天行动标签），后续实现补「表格视图」切换，满足无障碍与导出。

需要你拍板的问题（二轮）

  1. 热量预算：默认 1800 kcal 合适吗？还是按身高体重自动算（基础代谢 − 500）？
  2. 热量估算精度：一句话 + AI 估算够用吗？还是希望能选份量（小 / 中 / 大）微调？
  3. 运动的口径：「多动」按分钟（≥ 30 分钟）还是按步数？步数需要手动填或接手机数据，目前插件拿不到；
  4. 首页卡片：要不要在应用首页放「今天还能吃 N kcal」的快捷卡，不进插件页就能记一笔？
  5. 隐私：饮食和体重发给 AI，首次确认一次之后记住，可以吗？
