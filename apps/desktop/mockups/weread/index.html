微信读书页 · 方案与决策

现状：pages/WeRead 是一张只读数据库镜像（11 列 antd 风表格 + 自定义视图），点行后按需拉取划线 / 想法，用 Slate 编辑器渲染在全屏查看器里；顶部是连接状态 + 同步按钮。数据面不变（API Key → Agent Gateway → SQLite 缓存，详情按需拉取），这次只决定页面怎么组织与笔记怎么读。

定稿：A 的书架 + B 的列表排布（右上角切「封面 / 列表」，列表只做列头排序）· 划线还原原样式 · 书架分类放页面顶部 chips · 保留「在读」行 · 笔记只读（悬停只有「复制」）· 表格视图体系退役。见 方案 A（已按定稿更新）。

① 三套页面结构

三套共用同一份笔记渲染（书头 + 书评 + 按章节的划线 / 想法、悬停工具条、过滤条）和同一套空态 / 同步态，区别在「书目怎么排、笔记在哪儿看」。每页控制条都能切深浅、切「划线：还原 / 引文」。

A 书架 + 整页笔记 推荐

封面墙 + 「在读」续读行；点书进二级整页，目录停靠在纸内。分类挂侧栏子项。

最像读书；沉浸看笔记最好。舍弃表格多视图。

B 书目表 + 抽屉

保留现有保存视图（表格 / 画廊 / 分组）、筛选排序；点行滑出笔记抽屉，↑↓ 切书。

改动面最小、密度最高。像「管数据」。

C 分栏速览

纸内左栏书目、右栏笔记，↑↓ 切书即时刷新；书目栏可收起成整页。

翻多本最快。有「页内第二条导航」的风险。

③ 可以混搭

常见组合：A 的书架 + B 的「表格」作为第二种排布（书架右上角切「封面 / 列表」，列表只做排序不做保存视图）；或 A + C 的键盘切书（整页笔记里 ⌥↑ / ⌥↓ 直接跳上一本 / 下一本，不回书架）。笔记渲染三套通用，选哪套都不影响它。

④ 需要你拍板的点

高亮的是我的推荐。

1
页面结构
A 书架 + 整页笔记读书氛围 + 沉浸，贴合已有偏好
B 书目表 + 抽屉保留视图体系，最省工
C 分栏速览翻多本最快
2
划线呈现
还原微信读书样式保留用户划线时选的颜色与下划线 / 马克笔 / 波浪线（数据色，不是装饰色）
引文 + 色条统一宋体引文，颜色退到左侧 3px 色条，更安静
3
书架分类位置
全局侧栏子项同日记 / 白板的标签口径（A）
页内 chips / 列不动侧栏（B / C）
4
「在读」续读行
要书架顶部 3 张大卡：进度 + 读到的章节
不要只留封面墙，靠「在读」筛选
5
划线的编辑能力
保留现状改色 / 改样式 / 写想法 / 删除，只存本地；新增「复制」
只读与微信读书严格一致，去掉本地改动
6
现有表格视图
选 A / C 则退役useWeReadViews 与 weread-view 表进删除清单
保留为「列表」排布见「③ 混搭」
