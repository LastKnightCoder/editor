表格 · UI 与交互重设计

三个交互方向（02–04）× 三种视觉样式（05）可以独立组合。表格都能真的操作：点格子输入、跨格拖选、按 ⌫、用手柄 / 插入点 / 坐标栏增删移动行列。左侧块手柄 ⋮⋮ 是表格级菜单。

↑ 最后一行少了一格：跨行删除 / 删列失败后结构不再对齐。

  1. 聚焦时顶部挤出一条 2.5em 的工具栏，正文整体下跳；而且它在表格上方，其它块的操作都在左侧拖拽手柄菜单里，不一致。
  2. 菜单是「相对光标」的：「删除下一行 / 删除左一列」——先得把光标放进正确的格子，再心算方向；9 个条目 + 3 个标题要滚动。
  3. 12 个快捷键：⌘←→↑↓ 插入、⌘⇧←→↑↓ 删除。记不住，且 mac 上 ⌘← 本是「行首」、⌘⇧← 是「选到行首」，直接冲突。
  4. 没有「格选区」：跨格拖选得到的是文本选区，删除时被 deleteGuard 整个吞掉（什么都不发生）；全选删除后再补一个段落。这是 hack，不是语义。
  5. 结构不变式没人守：没有 normalize 保证「每行格数相同、至少 1×1」，增删行列是整表替换节点（撤销粒度粗、协同易冲突）→ 出现缺格。
  6. 视觉：斑马纹 + 首行加粗 + 1em / .75em 大内边距，信息密度低；行拖拽手柄塞在首格里，列不能拖；列对齐不支持（Markdown 导入时 :---: 被丢掉）。

01共同底座（与方向无关，选哪个都要做）

问题 4、5 是逻辑层的，换 UI 不能解决。下面这些是三个方向共用的模型与交互约定。

① 结构不变式交给 normalize

table → row → cell 三层严格；每行补齐 / 截断到同列数；至少 1×1；删到 0 行或 0 列 = 删除整张表、原位置回到空段落。任何操作出错都会被拉回合法形态，根治缺格。

② 细粒度变换，不再整表替换

插入 / 删除 / 移动行列改用 insertNodes / removeNodes / moveNodes：一次操作 = 一步撤销，协同时只冲突在真正改动的行列上。

③ 格选区是一等公民

拖过第二个格子即切换为格选区（矩形高亮，不再是文本选区）。⌫ = 清空所选格内容，结构不动；整行 / 整列被选中时 ⌫ = 删除行 / 列。⌘C 复制为 TSV + HTML 表格。取代 deleteGuard 吞键。

④ 表格级操作回到块手柄

复制表格、复制为 Markdown、删除表格放进左侧 ⋮⋮ 菜单，和其它块一致；表格上方不再有工具栏，聚焦不跳动。

⑤ 操作对象明确

菜单作用于「这一行 / 这一列 / 这块选区」，文案是「在上方插入行」「删除 2 行」，不再有「删除下一行」。

⑥ 快捷键收敛到 6 个

Tab/⇧Tab 左右格（末格 Tab 新增一行）、Enter 下一行同列、⇧Enter 格内换行、Esc 选中当前格（再按退出）、⌫ 见③。删掉全部 ⌘ 方向键。外加 GFM 列对齐首次接入。

★定稿 · 方向 A 边缘手柄 + 细框线 定稿

即方向 A：悬停格子时，该列顶边、该行左边各出现一个手柄。点手柄 = 选中整行 / 整列并弹出菜单，拖手柄 = 排序；右侧 / 底部「+」追加。不做插入点与选区浮条。

试试：悬停格子 → 点顶边手柄（列菜单，含对齐）/ 点左边手柄（行菜单）· 拖手柄排序 · 先跨格拖选几行再点左边手柄 → 「删除 n 行」· Enter 下一行 / ⇧Enter 格内换行 · 把下面的数据复制后粘贴进任意格（自动扩行扩列）

表格后面的段落，聚焦表格时它不会跳动。

02方向 A · 边缘手柄 推荐

悬停哪个格子，就在它这一列的顶边和这一行的左边各浮出一个小手柄。手柄 = 选中整行/整列 + 菜单 + 拖动排序，一个控件三件事。右边、下边贴一条细「+」用于追加。心智模型同 Notion / Craft。

试试：悬停格子 → 点顶边小手柄（列菜单，含对齐）· 点左边小手柄后按 ⌫ 删行 · 拖动手柄换行列顺序 · 右侧 / 底部「+」追加 · 跨格拖选后 ⌫ 只清内容

本周推进：

表格后面的段落，聚焦表格时它不会跳动。

  • 常驻零装饰：不悬停时就是一张干净的表；手柄只出现在当前行列，噪音最小。
  • 手柄同时承担选中 / 菜单 / 拖动，学一次就会；列也能拖了。
  • 整行整列选中 + ⌫ 删除，与格选区规则统一。
  • 「在中间某处插入」要两步（点手柄 → 在上方插入）；没有 B 那种一步到位的插入点。
  • 手柄跨在边框上，"细框线"以外的样式里需要靠阴影才看得清（已处理）。
菜单内容
  • 列：左侧插入 · 右侧插入 · 对齐（左/中/右）· 清空内容 · 删除列
  • 行：上方插入 · 下方插入 · 清空内容 · 删除行
  • 多选（拖选多格后再点手柄）时文案变「删除 2 行」，作用于选区覆盖的全部行。

03方向 B · 插入点 + 选区浮条

边框上就是插入点：鼠标在表头行附近，最近的列边界顶端出现「+」；在首列附近，最近的行边界左端出现「+」，悬停显示插入线，一点即插。其它一切操作都从格选区出发：拖选后上方浮出和文字浮动工具栏同族的操作条。

试试：鼠标移到表头行，沿顶边左右滑 · 移到首列，沿左边上下滑 · 点「+」插入 · 跨格拖选看浮条（对齐 / 插入 / 删除 n 行 / 删除 n 列）· ⇧+点击扩选 · 格内按 Esc 选中当前格

在读书单：

表格后面的段落。

  • 插入一步到位，而且位置所见即所得（插入线），中间插列最快。
  • 操作条与文字浮动工具栏同族，「选中 → 操作」的心智和正文一致。
  • 删行删列不必先精确选整行，选区碰到哪些行就删哪些。
  • 行列不能拖动排序（没有可抓的东西）；要排序得另加手柄，就回到 A 了。
  • 插入点只在表头行 / 首列附近出现，第一次不容易发现。
  • 浮条盖住选区上方一行的内容。

04方向 C · 坐标栏

表格获得焦点时，顶部和左侧淡入两条细「坐标栏」（电子表格的行号列标，去掉了字母数字）。点一段 = 选中整列/整行并弹菜单，在栏上拖 = 连选多列/多行，左上角 = 全选，栏尾「+」= 追加。

试试：点进任意格子 → 顶部 / 左侧出现坐标栏 · 点一段弹菜单（列菜单含对齐、左移右移）· 在栏上拖过几段连选 · 点左上角全选

方案对比：

表格后面的段落。

  • 所有行列的入口同时可见、位置固定，批量选多行多列最顺手（栏上一拖）。
  • 重度表格用户熟悉的电子表格心智；全选整表有明确入口。
  • 聚焦即出现两条栏，视觉存在感最强，和「笔记里的小表格」气质不太合。
  • 排序靠菜单里的上移 / 下移，不如拖动直接（也可以在栏上加拖动，成本更高）。
  • 栏占据表格外侧 17px，窄屏 / 嵌套容器里需要让位。

05视觉样式

与交互方向独立；顶部「细框线 / 只用横线 / 浮起卡片」开关会同时切换 02–04 的表格。共同点：去掉斑马纹，内边距收到 7px 12px，表头用底色或字号区分而不只是加粗。

① 细框线 推荐
圆角外框 + 浅内线，表头一层浅底。最像「表格」，结构最清楚，手柄跨在边框上也自然。
② 只用横线
无竖线、无外框，表头下一条深线。最轻、最"排版"，适合文字多的说明表；列多时对齐靠留白。
③ 浮起卡片
像一张嵌在文中的卡片，表头小字号沉底色。存在感强，与代码块 / 标注块的卡片质感一致。

06三个方向对比

「实现成本」只算交互层；01 的底座三者一样。

A 边缘手柄B 插入点 + 浮条C 坐标栏
常驻视觉噪音最低（只在当前行列）低（只在边缘附近）聚焦即两条栏
在中间插入两步（手柄 → 菜单）一步，带插入线两步（栏 → 菜单）

07需要你拍板的点

除了选方向和样式，下面几件会影响模型或范围。

1. 列宽要不要能拖？

GFM 没有列宽，要存就得在节点上加属性，导出 Markdown 时丢失；源码视图 / 协同也要跟着处理。

建议：不做，列宽按内容自适应（mockup 即如此）。

2. 表头行能否关掉？

GFM 表格必须有表头。允许关闭就只能"首行仍是表头、只是视觉上不突出"，导出后会和编辑器里看到的不一致。

建议：始终有表头；删除首行时下一行自动升为表头。

3. Enter 的语义

现在 Enter = 下一行、格内无法换行。新方案：Enter 下一行同列（末行则新增一行），⇧Enter 格内换行（序列化为 <br>）。

建议：按新方案；或者反过来（Enter 换行、Tab 走格），看你习惯。

4. 粘贴电子表格数据

从 Excel / Numbers / 网页复制一块区域粘进来：在正文里自动生成表格，在表格里则按格填充（必要时扩行扩列）。这是新入口。

要不要这一期一起做？

5. 格内内容范围

保持现状：只允许行内内容（文字、行内代码、链接、公式等），不支持格内列表 / 图片块。与 GFM 一致。

建议：保持。

6. 移动端

本 mockup 只覆盖桌面端。移动端表格可以只做"点格编辑 + 长按格子弹 ActionSheet（行列操作）"，按浮层规范接返回手势。
