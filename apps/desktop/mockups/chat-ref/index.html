聊天引用 · 设计稿

场景：和 AI 聊完有收获，用自己的话写进文章 / 卡片 / 日记，同时把出处指回那段对话。读的时候悬停就能看到原话，点一下在右侧停靠栏打开对话并定位到那一轮，可以接着聊。

正文里长什么样

两种形态。行内引用只标出处，摘录块把原话也留在正文里。

我的理解是：它把「难」和「记得多久」拆开了，难度还会自己慢慢回落，见 SM-2 与 FSRS 复习策略对比· 第 2 轮。

关键在于难度会均值回归：一次答错不会让卡片永远被判定为「难」，连续答对几次后 D 会回落，间隔增长随之恢复。

你的两个问题

要不要在对话里放一个「复制对话链接」按钮？ 要有入口，但不建议做成单独的「复制链接」。消息悬停操作里加一个「引用」按钮（排在复制后面），点开是小菜单：第一项「插入到〈当前文档〉」，停靠栏和正文并排时一步到位；第二项「复制引用链接」。复制链接是兜底通道：跨窗口、先存着稍后再贴、贴到 Markdown 窗口或外部应用。只给复制链接的话，最常见的「旁边就开着文档」场景要多走一步切窗口、找光标、粘贴。
正文里怎么插入？ 四个入口，最后落到同两种节点：
① 对话消息「引用」→ 插到当前文档光标处（行内引用，可选摘录块）；
② 选中回答里的一句 → 浮条「引用到正文」（摘录块，带原句定位）；
③ 正文里打 [[ → 现有引用面板加「对话」标签，搜标题 / 提问 / 回答，→ 展开到轮次；
④ 粘贴 tau://chat/… 链接 → 自动认成引用，给「粘贴为 行内引用 / 摘录块 / 普通链接」。

模块方案

做成内置插件 core.chat-ref（不可卸载、默认启用），但它需要的两个挂载点是通用的，内置与外部插件同一机制。

模块位置职责
编辑器扩展chat-ref 行内 void + chat-quote 块节点模型、渲染、悬停预览、粘贴识别、Markdown codec。结构照抄 editor-extensions/content-link
对话消息操作（新挂载点）MessageView.renderExtraActions 已有，缺插件接口注册「引用」按钮与选区浮条项；宿主告诉插件「当前有没有可插入的正文编辑器」
[[ 面板来源（新挂载点）MentionPanel 现在只搜内容面板支持多来源标签；对话来源提供搜索与「展开到轮次」
主进程查询pi 会话模块按 sessionId + entryId 取一轮（问 + 答 + 所在分支）；按关键词搜会话轮次
打开定位openChatInDock(sessionId) 加 entry停靠栏复用对话页现有的 entry 定位逻辑

数据与链接

// 行内：只存指针 + 显示用快照
interface ChatRefElement {
  type: "chat-ref";
  sessionId: string;   // pi 会话 id
  entryId?: string;    // 该轮用户消息的 entry；缺省 = 整个对话
  title: string;       // 插入时的会话标题，失效/协作时显示
  turn?: number;       // 第几轮，只用于显示
}

// 摘录块：原文是正文的一部分
interface ChatQuoteElement {
  type: "chat-quote";
  sessionId: string; entryId: string;
  text: string;                    // 引用原文
  prefix?: string; suffix?: string; // 前后各 ~32 字，跳转时找回这一句
  ask?: string;                    // 可选：连同提问一起摘
  title: string; model?: string; time: number;
}
// 链接：tau 协议已注册，正文内 / 外部都能打开
tau://chat/<sessionId>?entry=<entryId>

// 复制时剪贴板同时写三份
text/plain   → 链接
text/html    → <a href="tau://…">标题 · 第 2 轮</a>
application/x-tau-chat-ref → JSON（含选区原文/前后文）

流程

插入：对话「引用」/ 选区浮条 / [[ 面板 / 粘贴链接 → 生成 ChatRef 载荷 → 有正文编辑器在焦点链上？ 是 → 插到光标（行内或摘录块，一次撤销）；否 → 写剪贴板 + toast「已复制引用链接」
阅读：悬停 → 主进程取该轮 → 存在？ 是 → 预览卡；否 → 失效样式 · 点击 → 停靠栏打开会话 → 在当前分支？ 是 → 定位闪烁；否 → 提示切分支
