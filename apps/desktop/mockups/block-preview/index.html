块预览 · 设计方案

对话里模型产出的 HTML、思维导图、白板、图表等「块」如何打开、在哪里看、怎么边看边改。分两层裁决：① 容器——预览放在哪（三选一）；② 预览框 + 底层——不论选哪个容器都要做的统一 chrome、实时数据、渲染器协议与安全收口。

现状

新壳层里这块整体沿用 legacy，没有设计过。

入口现在怎么打开问题
对话页纸内 ResizablePanel 分栏 + BlockPreviewSidebar刚修掉「一点就崩」；预览框里仍是各渲染器自带的 antd 工具栏、英文文案、写死的灰色
停靠栏推入 block-preview 页，参数里塞整段 JSON拿的是冻结快照：生成中不更新；深色模式永远是浅色；没有标题行、没有错误边界
行内 AI / 视频笔记对话—点击卡片没有任何反应
块识别按代码围栏语言；id 用「消息分段序号」同一段里两个同语言的块 id 相同，会被当成同一个块
HTML 安全Electron webview 共用 persist:html-preview 分区；浏览器 iframe allow-scripts allow-same-origin所有生成页共享一份 localStorage / Cookie；浏览器端生成页脚本可以直接访问应用本身
PlantUML图的源码发到 plantuml.com 渲染离线不可用，内容外发

① 容器：预览放在哪

每个方案都给了「对话页」与「停靠栏」两种入口的样子（样板间顶部切换）。

A · 纸内分栏

现状形态 tau 化：对话页同一张纸左右分；停靠栏放不下，预览作为第二张纸从左侧伸出盖在正文上。

B · 预览上正文，对话退到停靠栏 推荐

一条规则：预览永远占正文、对话永远在右边。对话页点开时对话形变收进停靠栏；后退回到原处。

C · 覆盖式大预览

Quick Look：遮罩上居中大卡片，← → 切换本会话的块。最简单，但看预览时不能继续聊。

② 统一预览框

三个容器共用一个预览框，详见 统一预览框（各类型 × 就绪 / 源码 / 生成中 / 出错 / 移动端）。要点：

  • 头部一行固定骨架：图标 · 标题（类型 · 大小） · 版本 ‹ v2 / 3 › · 预览⇄源码 · 类型专属工具 · 复制 · 全屏 · 更多 · 关闭。渲染器只声明专属工具与更多菜单项，chrome 由框统一画。
  • 画布类（导图 / 白板 / Mermaid / PlantUML / TikZ / Typst）的缩放浮在右下角，不占头部。
  • 生成中：HTML 先看源码流式写入，写完自动切预览（不再半截 HTML 反复重载）；画布类保留上一次成功的渲染，头部显示进度。
  • 出错：接前面做的 ErrorState——保留上次成功渲染，给出行号与「查看源码 / 让 AI 修复」。
  • 版本：同一会话里同名同类型的块视为同一产物的多个版本（如「演示模板」v1→v3），卡片标 v3，预览里可前后翻。

③ 底层（与容器无关，都要做）

实时数据 + 稳定身份
  • 块身份改为 会话 id + 消息 id + 第几个围栏，修掉同段同语言撞 id。
  • 预览不再复制内容：useBlockPreviewStore（zustand，替掉只在对话页有的 Context）只记「打开的是哪个块」，内容从对话仓库实时派生——停靠栏、对话页、预览页看到的是同一份，生成中自动更新。
  • 任何对话面（停靠栏 / 行内 AI / 视频笔记）点击卡片都走同一个 openBlock()。
  • 预览页读 tau 主题（修掉 isDark 恒为浅色）。
安全收口
  • HTML 统一用 iframe srcdoc + sandbox="allow-scripts"（不给 same-origin，页面是不透明源，碰不到应用）；需要 Electron webview 时每个预览用非持久分区。
  • 生成页里的链接一律交给系统浏览器打开，禁止页内跳转与弹窗。
  • 合并掉 utils/html-preview.ts 与 11 处复制粘贴的 webview（VibeLearning 的 PPT / 报告预览一起受益）。
  • PlantUML 外发：先在更多菜单 / 首次渲染时说明「由 plantuml.com 渲染」，本地渲染另议。
渲染器协议：声明式、文件即注册

替掉 renderers/index.ts 中心登记表与 7 个渲染器各自的工具栏；renderers/*.block.tsx 由 glob 收集。

export default defineBlockRenderer({
  type: "mind-map",
  label: "思维导图", icon: Network,
  display: "card",        // card | inline（Mermaid / 白板在对话里直出 + 放大）
  canvas: true,           // 右下缩放浮控、点阵底
  streaming: "keep-last",  // source-first（HTML）| keep-last | live（白板）
  legacy: false,          // true：旧数据可看，不在任何提示词 / 技能里出现
  meta: content => ({ title: firstLine(content) }),
  Preview: MindMapPreview,
  more: [copyToWhiteboard, exportPng],
});
TikZ / Typst
  • 渲染器保留，标 legacy: true：老对话里的卡片照常可点、可看、可导出。
  • 新对话已无入口：生成它们的内置技能在 af766986b 已删；对话侧没有其它提示词再引导模型输出。
  • markdown 技能与「内容润色」提示词里仍列着 tikz / typst——那是编辑器文档的语法说明（文档里这两种代码块仍受支持），不属于对话块，保持不动。
  • 模型若自发输出 ```tikz 仍会出卡片（可渲染），不额外拦截。

需要你裁决的点

容器选 A / B / C？推荐 B；C 可作为 A / B 头部「全屏」按钮的实现。
要不要「版本」？同名同类型合并为版本，卡片标 v3、预览里前后翻。不要的话每个块各自独立。
Mermaid 与白板保持「对话里直接画出来」吗？现状如此；方案是保持直出，右上角加「放大」进统一预览框。也可以统一成卡片。
HTML 生成中先看源码、写完再切预览，可以吗？另一种是生成中每隔一段刷新一次预览（现状，会闪）。
PlantUML 外发渲染：只加说明，还是改为本地渲染 / 下线？

落地顺序（选定后）

  1. 底层：块身份 + useBlockPreviewStore 实时派生 + 全部对话面统一 openBlock()；HTML 沙箱收口。
  2. 统一预览框（tau 组件，零 antd）+ defineBlockRenderer 协议；7 个渲染器迁到新协议，删各自工具栏。
  3. 按裁决的容器接线（B：block-preview 页改为读 store + 标题行 + 形变；A：换 chrome；C：Dialog）。
  4. 版本、让 AI 修复等增量能力；删掉 legacy BlockPreviewContext / BlockPreviewPage / TabType.BlockPreview，登记 04 删除清单。
