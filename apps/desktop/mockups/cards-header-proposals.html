卡片库 · 顶部布局方案对比

同一场景：表格模式（头部堆叠最重的视图）· 尺寸按 CardsView.tsx / ViewTabs.tsx 实测还原 · hover 右侧改动点可在窗口中定位

现状基线 作为对照

CardsView.tsx 顶部两行 + Database ViewTabs 第三行
  • 1三行工具栏垂直堆叠：44 + 42 + 44px（含 py-5 的 20px 间距），到首行数据共 190px。
  • 2双搜索框同屏：外层语义搜索与表格内文本过滤同时出现，职责不同但视觉重复。
  • 3信息密度超载：第一行 5 组信息、第二行 7+ 组（每个 chip = 色点 + 名 + 计数），右上角两排控件零间距堆叠。
头部高度 190px，占 780px 视口的约 1/4；三行视觉权重相等，没有主次。

方案一 · 视觉减压 成本 低 · 半天

不动信息架构，只降每行密度
  • 1统计读数挪入底部状态栏："共 N 张 · N 字"是看一眼型信息，与已有的"N 组标签 · N 条链接"同族归位。
  • 2导入收进"新建"次级菜单：低频操作不占一等席位（图中为展开态示意）。
  • 3chips 瘦身：常态只有文字，色点与计数仅在选中 / hover 时出现。
  • 4两行中缝加 6px 呼吸感，去掉贴身堆叠。
高度基本不变（+6px），但每行信息组从 5/7 降到 3/4。缺点：表格模式三行堆叠的本质没动。

方案二 · 控件归位 推荐 成本 中 · 1~2 天

方案一全部内容 + 消灭两级工具栏的重复
  • 5砍掉表格内层搜索框：外层搜索已通过 searchResults 注入表格，内层是第二套过滤入口，语义打架。
  • 6表格视图 tab 轻量化：36px 圆胶囊改为 28px 轻胶囊，与外层视图切换同一视觉语言；py-5 收窄——三行从"三等重"变"两重一轻"。
头部 190 → 176px；语义上只剩一个搜索框、一套筛选入口（分类 chips）。这是收益 / 成本最优的组合，不动状态架构、不需要裁决记录。

方案三 · Notion 式单行 成本 高 · 行为变更

视图系统统一，头部只留一行
  • 1卡片墙 / 图谱 / 表格视图全部平级为 tab：视图切换即 setActiveViewId，不再有"页面级 + 表格级"两级工具栏。
  • 2分类筛选降为轻上下文条：无边影、无常态计数，保留三视图共用分类的语义。
  • 3统计由状态栏承担（同方案一）。
头部 190 → 118px，最彻底。代价：preferences.view 与 Database views 两套状态需统一（真值归一 / 类型扩展 / 存储迁移），是用户可感知的行为变更，按规范需先在 DECISIONS.md 裁决。留作视图系统演进方向。
