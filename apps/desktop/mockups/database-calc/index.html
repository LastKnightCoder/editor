数据库 · 汇总与公式 mockup

表尾汇总（列相加）+ 公式列（IF 判断）共用一套内部表达式结构（受限 JSON AST，只在存储与校验层，用户永远看不到）。用户面对的只有构造器和 AI 输入框；内嵌求值器是真跑的，改动后预览实时重算。

01表尾汇总 · 点一下就出数

每个列下方一格，默认空、悬停才显形。点开是 Notion 那个熟悉的清单：求和 / 平均 / 中位数 / 计数 / 非空 / 空值 / 去重 / 最小 / 最大。选中即算，不打开任何对话框——这是高频操作，一次点击要能完成。

语义（要拍板）
  • 汇总算的是筛选后的行——与 Notion 一致。改动筛选条件，表尾数字跟着变，不需要额外接线：求值输入就是 projection.rows。
  • 数字列默认右对齐、tabular-nums；汇总值继承该列的格式化配置（小数位 / 千分位 / 前后缀）。
  • 非数字列也能计数 / 非空 / 去重，不给「求和」——菜单按列类型收窄，不让用户选出必然出错的东西。

02公式列 · 小计与 IF 判断

公式列是一个新的 CellPlugin（type: "formula"），不新增任何跨层机制。上表的「小计」= 单价 × 数量，「优先级」= 嵌套 IF。它只读、不可编辑，值不写进 rows blob，是渲染期的派生覆盖层。

小计 公式列
两个数字列相乘。下游可排序、可筛选、可被别的公式引用——因为它在下推管线里长得和普通列一样。
优先级 公式列
嵌套 IF。改左侧任一槽位，右侧预览实时刷新。
为什么这里不需要 DSL
  • AST 是唯一事实源，没有解析器、没有词法层。构造器直接增删节点，不走「生成文本再解析回来」的往返。
  • 校验是静态的：保存时就报「文本列不能求和」，而不是运行时算出 NaN。
  • 求值是受限递归，白名单算子、无循环、无函数定义、无 eval——AI 生成的表达式也必须过同一个校验器。
  • 这东西要序列化进 data_tables.columns 的 JSON。树天然可序列化，文本语法还要额外的转义与版本规则。
仓里 ColumnDef.type 是裸 string、CellValue 带 | any、全仓零类型守卫。AST + 插件元数据的静态校验，正好补上这块最薄的地方。

03构造器 · 只有槽位和预览

左边是可点的槽位（列 / 算子 / 数值），右边是前几行的计算结果。用户看不到 JSON、代码或错误码：算不出来的格子显示「—」，悬停给一句人话原因。构造器每一处改动直接改内部树，不经过任何文本。

编辑「优先级」的 IF 条件
点任一 chip 换列 / 换算子，数字可直接改。错误会在预览里标出并指到具体行。
换根节点
根节点类型切换 = 换一棵树的骨架。构造器只暴露当前根允许的槽位。
「汇总」只能做根：行内求值拿不到整列，所以在公式列里选它是类型错误——构造器直接不列出来，而不是算完再报错。
同一个菜单里，可选项由静态类型推导给出，不是硬编码清单。插件没声明 valueType 的列（图片 / 附件 / 富文本 / 卡片链接）直接不入列表，天然不会被误用。

04AI 入口 · 说话，回填同一棵树

构造器顶部一个输入框。AI 的结果直接填进构造器的槽位供继续手改——不是另开一个黑盒窗口。按仓里「配了模型即同意」的约定，不另设开关或预算提示。

自然语言→ AI 生成→ 检查→ 回填构造器
AI 的输出绝不直接执行。它和用户手点出来的表达式走同一个静态校验器：列不存在、类型不匹配、引用成环、深度超限，一律拒绝并说明原因。受限 AST 的价值就在这里——没有代码执行面，模型乱写最多得到「检查不通过」，构造器保留用户原话并提示哪里不对。

05错误与边界 · 结构化，不炸整表

一行算错只让那格显示「—」，悬停看原因，不传染、不把整列清空。下表错误码只在内部用，用户看到的是右列的文案。

错误码
内部码 → 用户文案。
type列类型不参与运算，如文本 × 数字
div0除数为 0；返回空而不是 Infinity
missing-column引用的列已被删除
cycle公式列互引成环
depth嵌套超过上限（建议 16 层）
bad-ref节点结构非法（AI 幻觉 / 旧版本数据）
删除列时：引用它的公式列保留原样并转为空值 + missing-column，不静默改写表达式。改名同理——表达式按 columnId 引用，与标题解耦。

06两处入口 · 各自的位置

汇总走表尾就地菜单（高频、一次点击），公式列走新建列的列编辑弹窗（低频、需要完整构造器）。不共用一个面板——复杂度不同，不该互相拖累。

07已定

  1. 汇总算筛选后的行（Notion 同）。
  2. 公式列可排序 / 筛选 / 分组，委托给结果类型对应的字段。
  3. 公式值不落库，渲染时派生并做记忆化。
  4. 上限：嵌套 16 层、单表公式列 50 个，超限保存时拒绝。
  5. 文本不隐式转数字，文本列不出现在求和与四则的可选项中。
  6. 第一版不做日期运算、不做分组小计。
  7. 内部表达式结构不暴露给用户：没有公式文本框、JSON 视图或错误码。
