白板元素树重设计

元素树从「左上角按钮 + 浮层」改成画布纸面内的左栏：和项目文档树同构（同一张纸、右缘一条淡线、可拖宽），开关钉在标题栏面包屑最前面，收起 / 展开只换状态不跳位。三个方案共用这套骨架，只在行怎么长上不同。画布是上一轮的同一张可操作 mock：点行 = 选中并把元素带进视野，画布上选中也会同步到树。

可以试：面包屑 ▯ 开关 · 拖左栏右缘改宽 · 点行 / 右键行 / 双击改名 · 查找 · 右上「主题化元素」看缩略色跟着变

现状的问题

  • 全叫「文本」：元素没手动命名时，行名退回类型名——同一类元素一整屏同名同图标，树等于没有。三个方案都改成取内容当名字（文本首行、卡片标题、图形里的字、图片说明、箭头「起点 → 终点」），命名过的优先用名字。
  • 浮层盖画布：浮层压住画布左侧，开着就没法在那一块操作；入口是画布里的一颗悬浮按钮。
  • 信息太少：没有子元素数，看不出画框 / 导图里装了多少东西。

三个方案

A

中性图标 + 内容命名

行首保持中性墨色线性图标（比现在大一号、深一档），名字取内容，容器右侧挂子元素数。最克制，完全是「主题语言」那一路。

+ 最安静，和项目文档树一个样子− 区分只靠图标形状，扫一眼时类型感弱
打开方案 A → B

类型色块图标

图标放进 22px 圆角色块，按类型取主题的 tag 粉彩（图形蓝、文本赭、卡片紫、图片绿、导图陶土）；箭头 / 手写这类连线不上色、文字降一档，自动退到背景里；画框只描边。

+ 一眼分出类型，连线不再和内容抢− 多了一层颜色，色是「类型」而不是元素自己的色
打开方案 B → C

缩略预览（图层面板）

行首是元素自己的样子：图形按自己的形状和填充色画、图片用缩略图、卡片用自己的底色、箭头用自己的线色；两行式，第二行是类型 · 细节（卡片是正文首句，画框是「13 个元素」）。

+ 和画布一一对得上，颜色是用户数据不是装饰− 行高 40px，一屏装得少；实现要为每种元素写一个缩略画法
打开方案 C →

需要你定的

1. 选 A / B / C（或组合）

我倾向 C：你说「颜色没啥意思」——按类型配色确实是装饰，但元素自己的颜色是信息（蓝色的 Q、绿色的 K），C 用的是后者；图片也能直接认出是哪张。嫌行太高可以做「C 的缩略 + A 的单行」。

2. 展开元素树时全局侧栏要不要自动收成图标列？

项目详情进入时会收（文档树接替侧栏位置）。白板我倾向不自动收：元素树默认收起，打开是临时查找，不该连带改掉全局侧栏。

3. 默认展开还是收起，要不要记住？

倾向：默认收起，开关状态全局记住（同项目文档树，跨白板、跨重启）；宽度也记住。

4. 「按类型筛选」要不要做？

头部留了一个筛选按钮位（mock 未实现），元素多时可以只看「图片」或「卡片」。不需要就去掉。
