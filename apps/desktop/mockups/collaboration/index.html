领域判断 · 协作页到底服务什么

  • 编辑大多不发生在协作页：我发起的共享都有本地原内容（文章 / 卡片 / 项目文档），在原页面照常写就是协作；只有我加入的内容只存在于协作缓存里，协作页是它唯一的编辑位置。所以「协作页内嵌编辑器」对一半内容是必需的，对另一半是重复入口——三个方案的分歧主要就在这里；
  • 最有时效的是审批：申请会过期，对方在等。它已经通过 Notification（D-038）弹出，但协作页和侧栏入口仍然要能一眼看到剩余的待办；
  • 协作码是「发出去」的东西：作者最常做的是复制它，其次是轮换；它不需要被大字号展示在页面主位；
  • 数量很少：默认配额每设备 5 份共享、每份 10 人。页面不需要搜索、分页或批量操作，重点是状态清楚（谁在、同步了没、断没断）。

三个方案都修掉的 legacy 问题

  • 点「发起协作」就立刻共享：legacy 打开弹窗即冻结本地编辑、上传附件、发布并出码，用户还没看清就已经共享了。改为先说明（码 / 本地块不共享 / 随时可结束）再确认「发起共享」，发布过程三步可见；
  • 移除成员没有确认：工作台成员条上的移除按钮直接执行（分享弹窗里有确认，两处不一致）。统一走确认对话框——移除立即断开对方，不能撤销；
  • 协作码输入：一个裸输入框 → 三段 4 位，粘贴整段自动分段，回车提交，错误原位显示；
  • 「N 人正在编辑」把自己也算进去：只有自己时显示「1 人正在编辑」。改为只数他人：「2 人正在编辑 / 3 人在线 / 只有你在」；
  • 待审批的全局存在感：侧栏「协作」入口挂待审批计数（同番茄入口挂实时计时的口径），离开协作页也看得到；
  • 视觉：uppercase 小节题 → 中文 semibold + mono 副；横线切割 → 留白与底色；antd message / CustomModal → Toast / Dialog / Popover；成员、申请上的悬停操作占固定槽位原位淡入，不顶开布局；头像按 deviceId 派生色（tag-1…5 / accent，零新 token）。

方案 A

协作台 · 纸面目录 + 协作副本编辑面板（主从）

legacy 工作台的重做。左边 276px 是纸面上的会话目录：待审批（行内同意 / 拒绝）、我发起的、我加入的、已结束；每行是头像叠 + 标题 + 状态。右边是一整块协作副本编辑面板：顶栏放来源、在线成员（点开 Popover 管理成员、处理本条申请）、协作码 chip（点击复制）、「在文章中打开」和更多菜单；异常用内联横幅；底栏是状态与 ⌥↑↓ 切换提示。

✓ 与 legacy 心智最接近，迁移成本最低；在多份内容之间来回切着编辑最快；编辑区最大 ✗ 我发起的内容在这里和原页面各有一个编辑入口（重复）；成员与协作码收在 Popover，管理不直观

方案 C

协作名册 · 管理优先：名册大面板 + 就地加入 / 审批 / 身份

协作页不再是编辑器，而是「谁在、同步了没、码是多少」的名册。一整块面板按 我发起的 / 我加入的 / 已结束 分段，每行：标题 + 来源 · 更新、成员、状态、协作码（悬停复制）、「在原处打开」；点行在原位展开成员（可移除）| 协作码与本条申请。右栏纸面三段：加入协作（三段输入就地提交）、待审批、本机身份（昵称就地改、服务器 Popover、导出恢复）——协作设置弹窗随之取消。我加入的内容点 → 进整页协作副本编辑。

✓ 编辑入口不重复（我发起的回原页、我加入的进副本）；一屏看全所有状态和协作码；加入与设置零弹窗 ✗ 最「工具」、个性最弱；在协作页编辑参与内容要多一次进入；表格列在窄屏下要收

裁决记录（2026-09-25 一轮评审）

① 骨架选 A 协作台。但 A 的会话目录和全局侧栏并排，读起来像两条侧栏 → 二轮把目录拿掉，协作副本面板占满整宽，会话导航做成三种形态供对比（方案 A · 二轮，标题栏「会话导航」切换）：

　A1 会话条：页内工具栏下一行，按「我发起的 / 我加入的」排开标签（状态点 + 标题 + 申请数），选中项浮起；共享数少（配额 5 份）时一行放得下，多了横向滚动。
　A2 标题切换：不占任何空间，页头是「协作 / 当前内容 ▾」，点开 Popover 列出全部共享（头像、状态、申请数），⌥↑↓ 直接切。
　A3 侧栏嵌套：共享内容挂在全局侧栏「协作」下面作为子项（只在协作页展开），全局只剩一条侧栏；选中子项时父项降为「所在区」样式，不抢选中态。

三种形态共用：本条内容的加入申请直接显示在面板顶部行内处理；其它内容的申请由标签 / 子项 / 切换器上的计数和工具栏「N 个申请待处理」（Popover 批量处理、可跳转）承担。

② 我发起的内容在协作页也能直接编辑（保留「在文章中打开」作为跳转，不是唯一入口）。

③ 协作设置就地改，只剩昵称：工具栏右侧「头像 + 昵称」点击原位变输入框，回车 / 失焦保存、Esc 取消；铅笔图标占固定槽位淡入。服务器地址不暴露、不可改；身份导入 / 导出去掉；协作设置弹窗与齿轮入口取消；错误文案不再出现服务器域名。

④ 右侧小组件 CollaborationPanel 去掉。

⑤ 已结束的共享不保留在列表里（结束即消失；mock 数据中已删除该条）。

B 共享墙、C 协作名册为一轮留档，未按本轮裁决更新（C 右栏仍含服务器与身份导入导出）。

决策检查清单

① 骨架：A 协作台 / B 共享墙 / C 协作名册，或者混搭（例如「C 的名册 + A 的内嵌编辑」）。

② 我发起的内容，协作页要不要能直接编辑：要（A / B，两处入口）还是只跳回原页面（C）。

③ 协作设置放哪：协作页里就地（C）/ 协作页齿轮弹窗（A / B）/ 并入全局设置弹窗「协作」分区。

④ 右侧小组件 CollaborationPanel 是否退役：新壳层下侧栏入口计数 + Notification 已覆盖它的「一眼看到」职能，建议随本次迁移删除。

⑤ 内容页入口：底栏 Popover（本稿）还是保留居中对话框；「先说明再确认」的发起流程是否认可。

⑥ 已结束的共享：保留在列表里（可打开只读缓存 / 清理），还是结束即从列表消失、只在清理失败时出现。
