表格 画廊

三个方向

A侧边速览

从右侧滑出、不遮罩，表格还在、当前行高亮；点另一行就地切换，适合一边看表一边逐行补数据。Notion 的 Peek 就是这个形态。

适合
在表格里连续录入、快速过一遍
代价
只有 560 宽，长正文和视频局促；画廊、看板视图下会挡住不少卡片

B文档页

居中一张大纸，像打开一篇文档：横幅封面、大标题，属性用三列网格压成两三行，正文独占阅读列。

适合
正文是主角的库（影评、读书笔记）
代价
属性一多（十几个）网格会把正文推下去；滚到正文后属性就看不到了

C双栏推荐

同一张纸里左正文、右属性，右栏透明、不另起卡片，封面放在属性栏顶端。正文滚到哪里属性都在旁边，宽屏也不浪费。Linear 的 Issue 详情是这种排法。

适合
属性多、正文长，大多数库
代价
需要 ≥ 960 宽，窗口太窄时要退回 B 的单栏

三个方案都做的改动

看得见的

  • 去掉「行详情」通用标题，头部改为「库名 › 行标题」、第 N / M 条和上一条 / 下一条
  • 每行常驻的铅笔和垃圾桶收进属性名的点击菜单（编辑属性 / 删除属性）；拖拽手柄只在悬停时出现在左侧留好的位置，不挤动布局
  • 空值显示「空」，空属性默认折叠成「还有 N 个空属性」
  • 属性和正文之间不画分隔线，靠留白和字号区分
  • 正文里的视频沿用编辑器的纸色底栏，不压在画面上

实现时要动的

  • 插件 Renderer 自带表格单元格的 px-2 h-full，详情里需要紧凑形态（或由容器抵消），否则值和标签对不齐
  • 上一条 / 下一条：四个视图要把当前可见行序传给详情，现在只传单行；切换前先落库当前行（现在是关闭时一次性 onSave）
  • A 是非模态抽屉：Esc 走 useOverlayDismiss，点表格行要切换而不是关闭
  • 行没有创建 / 更新时间字段，所以不展示这类元信息
