现状：4px accent 圆角竖条 + italic + ink-2。五个方向在同一段正文里对比，最后给出推荐方案的完整形态、与 callout / 高亮块同屏的辨识度，以及落地规格。右上角可切主题与明暗。

00为什么现在「看不出是引用」

① 中文没有斜体字形，italic 让浏览器把苹方硬拧成伪斜体，笔画发虚，看起来像是渲染出错，而不是在表达引用； ② accent 左竖条和 callout 是同一套视觉语言（callout 同样是 border-l-[0.25em] 加彩色竖线），少了底色和标题，读者会把它当成「坏掉的 callout」或装饰线； ③ ink-2 只是让文字变淡，没有传达「这是别人说的话」； ④ 上下 0.75em 内边距加上 1.625 的行高，和正文 1.9 的节奏不一致，块看起来像是松散地飘在段落中间；嵌套引用也只是竖条叠竖条，分不清层级。

01五个方向

每个方向用同一段上下文加两种形态（单段 + 署名、嵌套引用），下面的「＋/－」是取舍。判断标准只有两条：扫一眼就知道是引用，不和 callout、高亮块混淆。

02第二轮 · 以 B 的大引号为基础

保留 B 的大引号（2.9em），专门解决 B 的两个问题：长引用读到结尾时分不清边界；嵌套时换回竖线，同一个块里有两套视觉语言。四张卡片内容相同，都是长内容：含标题前后文、列表、行内高亮和三层嵌套。

03同屏辨识度：引用 vs callout vs 高亮块 vs 代码块

放在同一篇笔记里时最容易混淆，这是关键测试。左边是现状，右边是 B1。

04落地规格（B1）

项取值说明
文字--ed-quote-text: var(--ed-text)，正体，行高继承正文；嵌套内层用 --ed-text-secondary去掉 italic；行高、段距与正文一致，不再单独设置 1.625
大引号Georgia 400，2.9em，--ed-quote-mark: var(--ed-accent)，不透明度 0.55，放在 2em 宽的左栏顶端必须用拉丁衬线字形（Georgia → Times New Roman → serif），苹方的全角「“」是方块状；contentEditable={false} + select-none
竖线尾迹2px，圆角，--ed-quote-bar: color-mix(in srgb, var(--tau-ink-1) 20%, transparent)，从 1.6em 起到块底，和引号的中轴对齐中性色，与 callout 的状态色竖线区分；无底色。长引用靠它交代结尾在哪
内边距左 2em（嵌套 1.1em），上下 0，外边距 1em去掉现在上下各 0.75em 的 padding，块和段落节奏一致
嵌套内层 blockquote 不渲染大引号，只有贴左的满高竖线内层竖线和外层的尾迹是同一种线，只剩一套视觉语言；可以用 CSS 后代选择器，也可以在组件里用 Editor.above 判断
拖拽手柄保持 -left-[1.25em] 在槽位里大引号在块内左栏，不和手柄重叠；原来「压窄让出竖线位置」的 handleClassName 可以回到默认宽度
主题可调三个 --ed-quote-* 进 editor.css主题作者可以调引号颜色、竖线深浅，不需要改组件
  • 不在本次范围：导出侧（html-serializers、公众号 wechat-styles、PDF）各有一套 blockquote 样式。编辑器定稿后再决定要不要统一。
  • 署名行（「—— 作者」右对齐、变小）只在 C 里演示过。它需要一条「以 —— 开头的末段」识别规则，属于新行为，建议单独立项，不和本次换样式放在一起。
