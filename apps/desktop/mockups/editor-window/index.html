独立编辑窗口 · 合并为一个「Editor Window」的 mockup

现状：卡片 / 文章 / 项目文档各自一个窗口页面（SingleCardEditor / SingleArticleEditor / SingleProjectItemEditor），内部都是同一个 ContentEditor，样式还是 legacy less。 方案：合并成一个窗口页面，按 kind（card / article / project-item）只切换「头部字段」和「数据适配器」；外壳（标题栏、纸面、FadeScroll、大纲、状态栏、源码模式）完全共用，且与主窗口同一套 token、同一 46px 标题栏、同一张「纸」。

① 外壳：纸面 vs 满铺② 文章 · 浅色③ 深色 + ⋯ 菜单④ 源码模式 ⑤ 卡片 / 项目文档⑥ 窄窗 + 查找⑦ Windows 标题栏⑧ 多开规则⑨ 功能清单⑩ 主进程重写⑪ 协作

①外壳选型：纸面托盘 vs 满铺纸面先定这个

A 纸面托盘：标题栏落在 page 底色上，正文是一张内缩 8px、圆角 12、card 阴影的「纸」——和主窗口 AppShell 右列完全一致，一眼看出是同一个 App。 B 满铺纸面：整窗都是 surface，标题栏下一根 1px 线分隔——更像 Typora/iA Writer 的纯写作窗口，正文多出 16px 宽度。

⑧多开规则

一个窗口 = 一篇文档。窗口身份键 kind:db:id：

  • 同一文档再次「新窗口打开」 → 聚焦已有窗口（闪一下 accent 描边），不重复开；
  • 不同文档 → 新窗口，相对当前焦点窗口级联偏移 28px；超出屏幕回绕到左上；
  • 尺寸 / 位置 / 大纲开关 / 源码模式 按 kind 记忆（下次打开卡片还是窄窗）；
  • 任一窗口与主窗口编辑同一文档 → 实时同步（沿用 content:updated 广播），状态栏显示「同步中」；
  • 切换数据库 / 文档被删除 → 编辑窗口显示空态「文档已不存在」并提供关闭，而不是白屏；
  • 主窗口全部关闭而编辑窗口还开着 → App 不退出（mac 语义）；Windows 下全部窗口关闭才退出。

⑩主进程重写思路（供对齐，不是 mockup）

现在 window-manager.ts 932 行：主窗口、番茄钟两种、背景音频、待办、快速卡片、四种编辑器窗口都堆在一个类里，getEditorRoute / getParamName / getEditorName 三个 switch 按类型分发，还有三个 createXxxEditorWindow 包装。建议拆成：

src-electron/main/windows/
├── createWindow.ts        # 唯一的 BrowserWindow 工厂：preset(基础配置/无边框/信号灯移出/preload) + loadRoute
├── windowRegistry.ts      # key → BrowserWindow；focusOrCreate(key, factory)；关闭自动注销
├── windowState.ts         # 按 key 前缀持久化 bounds（+ 级联偏移计算）
├── main-window.ts         # 主窗口（多实例）
├── editor-window.ts       # 编辑窗口：openEditorWindow({ kind, db, id }) → key = `editor:${kind}:${db}:${id}`
├── pomodoro-windows.ts    # 番茄钟 mini / 沉浸（单例，隐藏复用）
├── utility-windows.ts     # 待办 / 快速卡片 / 背景音频
└── ipc.ts                 # 窗口相关 IPC 一处注册（open / close / setAlwaysOnTop / setTitle）

渲染端：一个路由 /editor-window?kind=article&db=xxx&id=42
  EditorWindowPage → EditorWindowShell（标题栏/纸面/大纲/状态栏/源码切换）
                   → adapters[kind]（load / save / subscribe / 头部字段 / 额外扩展）
删除：SingleArticleEditor / SingleCardEditor / SingleProjectItemEditor 三个页面 + 各自 less

⑪协作（发起 / 进行中 / 切换 / 断线）

底层不用改：主进程协作模块按 窗口 登记文档订阅（views → windowId），ContentEditor 传入 source 后自动绑定共享 Y 文档；主窗口和编辑窗口同时打开同一篇共享文档时，两个窗口都能实时编辑。同一台设备按 deviceId 只算一个「我」。 这里要设计的是 入口 和几种 状态：

  • 发起：⋯ 菜单「发起协作」→ 在本窗口弹出现有「发起协作」对话框（说明 → 确认共享），不跳回主窗口；
  • 进行中：标题栏出现成员条（头像叠放 + 在线人数，待审批用红色数字角标），点开「成员与邀请」Popover（复用 ContentCollaborationControl 的 presence 模式）；正文显示远端光标；状态栏的「已保存」换成「协作中 · 已同步 / 连接中…」；⋯ 菜单文案变成「协作成员」；
  • 源码模式：共享期间源码 只读（可以看、可以复制）。切回富文本时会整篇替换，这会覆盖他人的并发编辑，所以不能编辑；分段控件上的「源码」项加锁图标并给出说明；
  • front-matter：共享期间 title 跟随共享文档（CollaborativeTitle），tags 仍是本地元数据，不共享；
  • 切换期（frozen）：发起 / 结束共享时，主进程要冻结文档，并等 所有窗口 的视图把本地改动刷完、回执 freeze-ack 才继续。所以编辑窗口必须登记视图、关窗时注销，否则切换会卡住。这段时间纸面顶部显示横幅「正在切换共享状态…」，正文只读，通常不到一秒；
  • 结束共享：编辑窗口打开的一定是本机实体（本机就是所有者），结束后自动回到本地编辑，toast 提示「共享已结束」，不需要额外操作；
  • 断线：不打断编辑，状态栏显示「离线 · 恢复后自动同步」，成员条头像变灰；
  • 访客文档（加入别人的共享、本机没有对应实体）：这次 不 支持弹出编辑窗口，仍在主窗口协作页编辑；以后需要时再加 kind: "shared" 适配器，外壳不用动。
