通知 · Notification 三方案

Toast 和 Notification 的分工：Toast 是「你刚做了什么」的回执，一句话、自动消失、不需要作答（已保存 / 已删除 · 撤销）。 Notification 是「不是你当下操作引发的事」，来自协作者、应用更新或后台任务，要有来源、标题、说明，常常需要你作答。 三个方案共用同一套内容和作答行为，差别在承载模型：通知出现在哪、停留多久、没来得及处理的通知去了哪里。

三案共用契约 content · behavior

  • 内容结构：来源行（中性图标 + 来源 + 相对时间 + 悬停才出现的 ×）→ 标题 13.5/600 → 说明 ink-2 → 最多 2 个动作，主按钮在最右。无图标头，不用色块。
  • 色彩只表意：语义色只落在来源图标上（发布成功 ok、发布失败 danger），卡片本体一律 surface + line-1 + shadow-float，与 Toast / Popover / Dialog 是同一浮层语言。
  • 停留：需作答的通知（加入申请、新版本、发布失败）常驻到有答案为止；纯告知的通知（发布完成）8 秒后消失，悬停时暂停计时。
  • 作答：点主按钮后转圈（aria-busy），完成后卡片收成一行结果（例如「已同意…」），1.6 秒后退场；失败时在卡内显示错误，不另弹 Toast。
  • 不抢焦点：role="status" + aria-live="polite"，出现时不移走输入焦点；通知不处理 Esc（它不阻断操作），只有展开的面板响应 Esc。
  • API 草案：notify({ source, title, body, tone, actions, sticky }) 返回 { update, resolve, dismiss }；异步作答可以直接写 actions: [{ label, onClick: () => promise }]，busy 和结果行由组件托管。

A · 通知卡栈

沿用现有「加入申请」卡片的做法，推广成全局组件：右上角直接弹出完整卡片，新的在上，最多展开 3 张，更多的层叠在后面。
位置
内容区右上，标题栏下方
多条
3 张展开 + 最多 2 层叠影，点击叠影展开全部
错过
需作答的一直留在栈里，没有历史记录
代价
常驻卡片长期压住右上角内容，打扰最大

B · 弹出一次 + 通知中心 推荐

通知从标题栏的铃铛下方弹出，停留 5 秒后缩回铃铛，未读数挂在铃铛上。点击铃铛打开通知中心，按「待处理 / 其他」两组列出，可以直接作答。
位置
标题栏右侧铃铛（全局唯一入口）
多条
只弹一张，新的来了旧的先缩回
错过
都在通知中心里，待处理的一直保留
代价
标题栏多一个常驻按钮，实现需要一个持久化的收件箱 store

C · 标题栏岛

不在内容区上方浮卡片。通知以胶囊形式长在标题栏正中，显示最新一条和计数；悬停或点击后，从胶囊下方展开完整卡片列表。
位置
标题栏正中（和壳层融为一体）
多条
胶囊显示最新一条和「+N」，展开后看全部
错过
待处理的一直留在胶囊里；纯告知的消失后找不回
代价
最安静但最容易被忽略；Toast 要从顶部中间移到底部中间，给胶囊让位
