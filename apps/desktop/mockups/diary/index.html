日记页设计探索 · 三方案 + 结合版 D

现状：legacy pages/DiaryView 是一条 800px 窄列时间线——左列「相对时间 + 日期」、中间竖线圆点、右边每条一张描边卡片，卡片里是常驻的 Slate 编辑器（误触即改）、12 色 antd 预设色标签 chip、天气 / 心情图标；顶部筛选条塞了日期预设、两个日期输入、标签多选和搜索框。新建一条只插入一张空卡片，要再点进去写。混用 --th-*、antd Dropdown / modal.confirm / message。

三个方案共用同一份 mock：35 条碎碎念（跨 2025 / 2026，今天 4 条），7 个标签，数据形状与 types/diary.ts 一致——一条 = 一个 DiarySegment（富文本 + 段级 tags + createTime），归属某天的 DiaryEntry，标签色来自 DiaryTagSetting。都能真的写：发布、# 联想打标签、点正文就地编辑、改标签 / 改色 / 清理标签、删除后撤销、筛选、搜索。标题栏虚线框是演示开关（正常 / 空态 / 外部定位到某天），右上角切 cream / cocoa。

二轮 · 方案 D（A 的流 + C 的输入）· ✅ 定稿（D-044，那年今日取「输入条上方」）

反馈：要 A 的 Feed 排版 + C 的 Chat 输入；做成一整张大纸，A 左边是卡片、右边不是，不够沉浸；那年今日不错，但不想做成右边一个列表。

方案 D

一整张纸 · 倒序 Feed + 纸内停靠输入条 + 那年今日织进今天

纸面撑满整个内容区，外面没有任何栏：A 的右栏拆掉了，标签按 C 的做法挂到全局侧栏「日记」下面；日历缩成工具栏的一个按钮，点开是热力月历浮层；纸的右边缘有一条按月的时间刻度，滚动时标出当前月，点一下就跳过去。输入条停在纸底部，与日期列对齐（左边「此刻 15:20」），↵ 发送，在页面上直接打字就进输入条，发出后回到顶部看到新的一条。那年今日（三轮）：不进流，只露一句预告——默认在输入条正上方一行（「一年前的今天 · 首句 · 还有 N 条」，可今天关掉），备选挂在今天日期下（演示开关切换）；点开从纸右侧滑出抽屉，按年份列出当天所有条目，「接着写」把某条引用进输入框，「在流里看」跳到那天；工具栏的历史图标是常驻入口。

✓ 沉浸：只有一张纸和一列内容；那年今日在写字的地方露一句，点开瞥一眼，还能直接回应 ✗ 输入在底部、最新在顶部，发出后要跳回顶部（演示开关里能切成输入条在顶部对比）

三个方案都修掉的 legacy 问题

  • 写一条要两步：legacy 点「新建」先插一张空卡片再点进去写。改为常驻输入框，写完 ⌘↵（C 是 ↵）直接发出；
  • 标签在写的时候打：输入 # 弹出联想（按使用次数排序，↑↓ 选、↵ 确认，没有就「创建」），也可以点「# 标签」按钮多选。发出后单条的标签照样能改；
  • 阅读态 / 编辑态分开：legacy 每条都是常驻编辑器。改为默认只读渲染，点正文进入就地编辑，失焦保存、Esc 放弃；
  • 删除不弹确认：立即消失 + Toast「撤销」（和待办页 D-040 一个口径），替换 antd modal.confirm；
  • 标签色：12 色 antd 预设（#1890ff…）→ Tag 七色板（D-021「点 + 软底」，与 ColorSwatch 同源），明暗主题各自跟随；标签管理（改色 / 清理）收进同一个浮层；
  • 补记：在过去的某天写下的条目会标注「补记于 …」（createTime 与归属日期不同天时），legacy 看不出来；
  • 视觉：去掉每条一张描边卡和贯穿竖线；分组靠留白和日期标题；悬停操作占固定槽位，原位淡入。

三个方案

方案 A

时间流 · 朋友圈式倒序流 + 纸面右栏

最接近「朋友圈」。一整块面板，顶部常驻「此刻」输入框（聚焦才展开工具条），下面按天倒序：左边是粘性的大号日期（今天 / 昨天 · 25 · 9月周五 · 4 条 149 字），右边是当天的条目，每条只有时间、正文、标签。右栏不加面板：本月热力日历（点一天只看那天，Shift 连选一段）、标签列表（按次数排序，点击多选筛选）、那年今日。

✓ 最符合「朋友圈 / 碎碎念」心智，打开就能写、往下刷就是回顾；右栏把日历、标签、那年今日一次摆全 ✗ 回顾很久以前要一直往下滚（靠日历 / 时间筛选跳）；结构最常规
打开方案 A →
方案 B

手账 · 整块月历 + 当天阅读列（主从）

以「日子」为主轴。左边是撑满的月历大面板（格内细线，不是瓷砖）：每格直接露出当天前三条的首行，前面的圆点是第一个标签的颜色；顶部一排标签 pill，点一个整个月历只剩这个标签。右边 430px 阅读列：大号日期 + 当天条目 + 输入框；选过去的某天写就是补记。搜索或 Shift 连选时右列变成结果列表，月历上匹配的字高亮。

✓ 桌面宽度用得最满；一眼看到哪天写了、写了什么，按标签看「这个月都在健身吗」最直观；补记最自然 ✗ 不像朋友圈，连续往下刷的阅读感弱（一次只读一天）；月历格里的首行在窄窗口下会很短
打开方案 B →
方案 C

对话流 · 给自己发消息 + 标签嵌进全局侧栏

写得最快。像聊天一样：最早在上、最新在下，输入条停靠在面板底部，↵ 就发（⇧↵ 换行），页面上随手打字会直接进输入条。日期是居中的粘性分隔胶囊，同一小时内的连续条目收紧、时间只在悬停时出现。标签不在页内做目录，而是像协作页 A3 那样嵌进全局侧栏「日记」下面（那年今日 / 各标签 / 无标签），点进去就是这个标签的频道，在里面发的自动带上这个标签。

✓ 记录成本最低（打字 → 回车）；标签即频道，按主题回看顺手；没有第二条侧栏 ✗ 倒着读回顾（向上滚），一天的全貌不如 A / B 清楚；标签多了侧栏会变长（需要折叠或只显示常用）

可以混搭的部件

  • C 的侧栏标签频道可以装到 A 上，替换 A 右栏的标签列表（右栏只留日历和那年今日）；
  • B 的月历可以做成 A 的第二种视图（工具栏 列表 / 月历 切换），两种阅读方式并存；
  • C 的 ↵ 直接发送和「页面上打字直接进输入框」可以用在任何方案——代价是多行内容要 ⇧↵；
  • A 的「那年今日」卡在三个方案里都能放（B 可放在阅读列空态里）。

待你拍板的几件事

  • 天气 / 心情：是 DiaryEntry（整天）级的旧字段，现在的 UI 已经没有编辑入口了，三个方案都没展示。要保留的话更适合放在「某一天」上（B 的日期头最自然），还是直接退役？
  • 图片：mock 里的图片块是占位色块，正文仍是 Slate 富文本（列表、引用、图片都支持）。碎碎念要不要限制成更轻的格式（纯文本 + 图片九宫格），还是保留完整编辑器？
  • Enter 行为：⌘↵ 发送（A / B）还是 ↵ 发送（C）？
