项目文档树 · 层级与文件夹区分方案

用户反馈：文件一多就分不清层级，文件夹和文件也难区分。四个方案都在同一棵 27 节点、4 层深的样例树上演示，可点击折叠箭头收起/展开，悬停行可看到操作按钮。右上角可切换深色主题，检查着色在深色下是否成立。

先看根因（来自 ProjectItem/index.tsx）

  1. 缩进比图标还窄：每层只缩进 pl-[16px]，而图标占位是 30px，子级图标落在父级图标中间，眼睛对不齐列，层级"糊"在一起。
  2. 没有展开状态：有子项一律显示 FolderOpen，收起时也是"打开的文件夹"，也没有折叠箭头；文件夹和文件只靠图标形状区分。
  3. 右侧操作列比层级更抢眼：每行常驻 … 和 +，形成两条整齐的竖列，视觉重心在右边，左侧的层级反而成了背景。
  4. 行高 38px + 间距 4px：一屏只放十几行，长树需要大量滚动，进一步削弱整体结构感。

另外要注意：这里的"文件夹"其实是带子文档的文档，点它会打开自身内容。这决定了"文件夹 vs 文件"的区分不必依赖图标，可以用箭头、字重、计数来表达，方案 D 就是沿这个思路。

推荐：A 作为基线，叠加 B 或 B2 的"仅顶层着色"

  • A 的四项改动解决的是根因（缩进对齐、折叠箭头、悬停才出操作、行高收紧），不论选哪个方案都应该做，成本也最低，只改 ProjectItem 一个组件的类名和结构。
  • 用户要的"颜色分层"可以采纳一半：只给顶层文件夹图标上色，第二层降饱和，更深层回到中性，三层以上不再细分颜色。颜色可以用灰蓝 --tau-info（B，和选中态天然分开），也可以用主题强调色（B2，随主题变化、更统一，但要靠背景块区分选中）。
  • C 适合"顶层就是章节"的项目，结构感最强，但侧栏里堆卡片会显得重，建议作为后续可选的视图样式，而不是默认。
  • D 最贴合数据语义，但收起状态只能靠计数徽标暗示，对"文件一多"的用户不如引导线直观。
  • 落地时层级色与引导线直接用现有语义色加 Tailwind 透明度修饰（如 text-accent-text/60、before:bg-accent/30），无需新增 token，各主题自动适配。
