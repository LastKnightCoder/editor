问题页设计探索 · 三方案

现状：legacy pages/QuestionWindow 是「左侧分组栏 + 问题列表 + 一串弹窗」——新建、编辑详情、写答案、选答案、看答案各自一个 antd Modal，答案在列表里只显示成「答案 #1024」。三个方案共用同一套 mock 数据（6 个分组、22 个问题、33 份材料，四种材料类型都覆盖），用 cream / cocoa 两个主题的真实 token 值。页面可以直接交互：快速收集、改状态、关联材料、写卡片 / 写答案、解除关联（可撤销）、右键菜单、拖拽都是真的能用，右上角切换明暗。

领域判断 · 问题不是待办，也不是文章

按你的用法，一个问题的完整生命周期是：

学习时冒出一个疑问→随手收集→带着问题去查资料→写卡片、写文章→从这些材料里拼出答案→已解答
  • 问题是学习的「入口」，卡片和文章是「产出」：问题页的价值不在列表本身，而在把一个问题和它催生出来的卡片、文章串起来。legacy 把答案藏在弹窗里，还只显示编号，这条链路几乎看不见；三个方案都把「材料」放到主视野里，并显示真实标题和摘要；
  • 收集必须零摩擦：冒出疑问的时候，你通常正在读书、写代码。legacy 新建要打开弹窗、填标题、再关弹窗；三个方案都改成一行输入、回车收集，用 #分组 顺手归类（不写就进当前分组）；
  • 三种状态其实是三个学习阶段：not_started / in_progress / resolved 的枚举不变，只把文案从「未开始 / 进行中 / 已解决」换成「待探究 / 探究中 / 已解答」，更贴近学习的语境；
  • 「答案」有两种：一种是可复用的材料（卡片、文章、项目文档），它们本来就在库里，问题只是引用它们；另一种是只属于这个问题的独立答案（legacy「写答案」产出的内容，不是卡片也不是文章）。三个方案都把后者叫「我的答案 / 结论」，前者叫「探究材料」，分开展示。

三个方案都修掉的 legacy 问题

  • 答案有标题了：卡片取首行、文章取标题、项目文档取文档名，并标出类型和摘要（legacy 的 answerTitles 固定写成 答案 #id）；
  • 弹窗链拆掉：详情、描述、状态、材料都在同一个视图里直接编辑；只有「写卡片 / 写答案」和「关联已有材料」这两个真正需要大编辑区或选择器的动作保留 Dialog；
  • 写卡片直接挂上去：新增「写一张卡片」动作——保存进卡片库，同时挂成这个问题的材料（组合现有的建卡命令和 addAnswer，不加字段）。这是你最常走的一步，legacy 里要先去卡片库写、再回来「选择答案」；
  • 挂上第一份材料时自动进入「探究中」（可撤销）；标为「已解答」时写入 resolvedTime，这个字段 legacy 有但界面从来没显示过——现在显示为「历时 N 天」；
  • 删除不弹确认：和待办页一样，直接删除，Toast 里可以撤销；解除材料关联同理，并明确告诉你「卡片仍保留在库中」；
  • 页内不做搜索框：统一走全局 ⌘K（legacy 工具栏的搜索只过滤当前分组）。

三个方案的共用基线

  • 状态环：待探究 = 虚线空圈，探究中 = 半满的 accent 圈，已解答 = ok 绿实心勾。颜色只用 accent 和 ok 这两个语义色，不新增 token；
  • 分组色是数据色：legacy 的颜色名映射到待办页那套 8 色板，只出现在小方点上，不用来给卡片、页头染色；
  • 材料行：中性墨色的类型图标（卡片 / 文章 / 项目文档 / 独立答案）+ 标题 + 两行摘要 + 「类型 · 字数 · 时间」。悬停时右上角出现「打开 / 解除关联」按钮，按钮是叠加上去的，不改变行的尺寸；
  • 视觉铁律照旧：不用横线分隔、面板靠 shadow-card 不描边、滚动区边缘渐隐、数字用 tabular-nums。

三个方案

方案 A

三栏清单 · 分组列 + 问题列表 + 常驻详情

最接近 legacy 的心智，但把弹窗全部收进右侧常驻详情。列表按「探究中 / 待探究 / 已解答」分三段，已解答默认折叠；顶部是快速收集输入。全键盘操作：↑↓ 切换、1/2/3 改状态、L 关联材料、⌫ 删除（可撤销）。把问题拖到左侧分组上就是移动分组。

✓ 迁移成本最低；详情不遮挡，边看列表边整理；键盘效率最高 ✗ 最「工具」、个性最弱；详情栏宽度有限，材料只能单列排

方案 B

探究看板 · 三条泳道 + 抽屉详情

把学习流程直接画出来：待探究 → 探究中 → 已解答三条泳道，放在同一块大面板里（不做碎卡片）。卡片上能看到最近的两份材料；已解答的卡片直接显示结论的开头和「历时 N 天」。悬停时出现下一步动作（开始探究 / 写答案 / 标为已解答），拖到另一条泳道就是改状态。分组做成顶部的 pills 筛选，详情从右侧抽屉滑出。

✓ 学习进度一眼可见，「探究中」堆太多时自己就能看出来；下一步动作最明确 ✗ 已解答会越积越多（只显示最近 4 个，其余折叠）；看详情要开抽屉，不能边看边改
打开方案 B →
方案 C

研究笔记 · 问题索引 + 问题即页面

把一个问题当成一篇研究笔记来展开：大标题是问题，下面依次是背景、结论、探究材料（两列卡片格）。右侧信息栏放状态、概览（材料数 / 字数 / 天数）和「探究轨迹」时间线，时间线由已有的时间字段推算。结论还空着时，会根据已有的材料数提示你「试着不看材料写下答案」。左侧索引按分组折叠，默认只显示未解答的问题。

✓ 最贴合「从材料构建答案」：结论和材料在同一页，材料可以宽排；个性最强 ✗ 一次只看一个问题，批量整理不如 A 快；待探究的问题正文区比较空

可以混搭的部件

  • C 的「结论 → 材料」正文布局可以直接替换 A 的常驻详情内容（详情栏放宽即可），也可以做成 B 抽屉的内容；
  • B 的「下一步」悬停动作（开始探究 / 写答案 / 标为已解答）可以放到 A、C 的列表行上；
  • C 的探究轨迹时间线和概览数字可以放进 A 详情的底部；
  • B 的泳道视图可以做成 A 的一个视图切换（列表 ⇄ 看板），数据和详情都不用变。

裁决记录（2026-09-25 一轮评审）

  • 方向：选 A 三栏清单。分组列和全局侧栏读起来像两条侧栏，二轮给出三个隔离变体（见下），最终定 A2；
  • 状态文案：改为「待探究 / 探究中 / 已解答」，枚举不变；
  • 不保留独立问题小窗。快速收集走现有搜索面板（Ctrl+K）里的一条「记一个问题」命令。面板本来就支持动作命令（「切换深浅主题」「打开设置」都是），加一条就行，不占新快捷键，也不和 Ctrl+K 冲突；
  • 首页放「探究中的问题」速览；
  • 写卡片不自动加标签；
  • 喜欢探究轨迹和过程数据，二轮把轨迹接进了 A 的详情；
  • 材料范围扩大：除了卡片、文章，还有项目文档、整个项目、白板。

二轮 · A 的分组列怎么和全局侧栏分开

问题出在层级上：旧版 A 的分组列和全局侧栏都直接落在纸色底上，样式也一样，读起来就是两条并排的侧栏。方案 A 页右上角可以切换三个变体：

变体做法好处代价
A1 板内分栏（推荐）分组列收进白色的列表板，成为板内左栏。全局侧栏在纸上，分组在板里层级一眼可分；分组仍然常驻，拖问题到分组上就能移动列表板变宽，窄窗口下详情栏会被压缩
A2 顶部切换分组变成列表板里收集框下面的一行 chips（和文章页 pills 同一套语言）页面只剩两块板，最干净，详情最宽分组多了要横向滚动；拖到分组的目标比较小
A3 侧栏嵌入分组成为全局侧栏「问题」下的子项只有一条侧栏，根本不存在「两条」的问题要改壳层导航协议（新增子项能力），而且只有问题页这么做，和其他页不一致

二轮 · 探究轨迹怎么记录

建议两者结合：过程事实由系统自动记，思考由你手动补。

  • 自动记录（不需要你操心）：提出问题、状态变化（包括「挂上第一份材料，自动进入探究中」）、关联 / 移除材料、从问题里直接新建材料。其中「写下卡片」「画了白板」和「关联了已有文章」分开记，因为前者才是这次探究真正产出的东西；
  • 手动「记一笔」：轨迹末尾有一个输入框，回车写入。记的是读到了什么、卡在哪、换了什么思路。这些系统推断不出来，却是回头看时最有价值的部分。视觉上手动记录比自动事件更重（accent 圆点、正文字号），自动事件只是轻量的背景；
  • 不做：不追踪材料被编辑的每一次（太吵）。以后需要的话，可以聚合成「这张卡片之后又改过 N 次」；
  • 存储：新增事件表 question_event(id, question_id, type, payload, create_time)。旧数据回填三类：提出（问题的 create_time）、材料（按 content 的创建时间推算，标为「推算」）、解答（resolved_time）。中间的状态变化和想法旧版没有记录，回填不出来。

二轮 · 材料可以是卡片、文章、项目文档、整个项目、白板

  • 现状的限制：questions.answers 是一个 content id 的 JSON 数组。卡片、文章、项目文档和独立答案都有 content id，但项目和白板没有（project、white_boards 都是自己的主键），所以现在存不进去；
  • 建议：新增关联表 question_link(id, question_id, target_type, target_id, sort_index, create_time)，target_type 取 card / article / project_item / project / white_board / answer，迁移时把 answers 数组逐条转成关联行。库里已有一张通用关联表 content_link（类型是自由文本，也有 create_time），可以复用，但它没有排序字段，语义上也是「内容引用网页剪藏」。所以更推荐单独建表；
  • 顺带修掉的 legacy 行为：① 旧版挂上第一个答案就把问题标为「已解决」，和新规则「第一份材料 → 探究中」冲突，要改掉；② 旧版删除答案会调用 deleteContent，新设计里「解除关联」只删关联，不能动卡片本身，迁移时要确认这一点；
  • 从问题里直接新建：详情里「新建 ▾」可以新建卡片、文章、白板、项目、独立答案，建完自动挂上并记入轨迹。「为了这个问题专门开一个项目」也就是一步操作；
  • mockup 里已经加上项目和白板材料（例如 CRDT 问题挂了一个 Vibe Learning 项目，B+ 树问题挂了一块白板），选择器也增加了「项目」「白板」两个分类。

裁决记录（2026-09-25 二轮评审）

  • ① 分组位置 = A2 顶部切换：分组做成列表板里的一行 chips，页面只剩列表板和详情板两块（方案 A 页默认显示 A2）；
  • ② 探究轨迹 = 自动记录 + 手动「记一笔」，存进新表 question_event；
  • ③ 材料关联 = 新建表 question_link，不复用 content_link；
  • ④ 快速收集 = 命令面板里的动作命令「记一个问题」。
