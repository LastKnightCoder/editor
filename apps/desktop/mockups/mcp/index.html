MCP 配置页 · 方案与决策

现状：MCP 管理是 MCPManagerModal（838 行老样式弹窗，只能从对话输入框 🔌 打开），分「内置 / 自定义」两个 tab；能力上只有服务器级开关、stdio / streamable-http 两种传输、JSON 导入。目标：和 Skill 管理一样升格为 AI 组下的独立页面，换新壳层样式，并借鉴成熟产品补齐工具级控制、错误诊断、低门槛添加三块短板。

② 页面布局：三选一

三套都已做成可点的样板间，添加弹窗、详情内容三者共用，区别只在「怎么排」。

A 列表 + 详情 推荐

左列服务器，右侧工具 / 配置 / 日志三个标签页。和 Skill 管理同一结构，服务器多了也清楚，查错最顺。

B 卡片库 + 抽屉

卡片网格 + 内嵌「常用服务器」目录，详情从右侧抽屉滑出。最好看、发现成本最低，但反复查看要开合抽屉。

C 单列展开

Cursor 式设置列表，行内展开工具芯片，编辑默认 JSON。实现最轻，但日志 / 确认策略放不下。

③ 需要你拍板的点

高亮的是我的推荐。

1
页面布局
A 列表 + 详情结构同 Skill 管理，扩展性最好
B 卡片库 + 抽屉更友好、更好看
C 单列展开最省工
2
导航位置
AI 组新增「MCP 服务器」与「Skill 管理」并列，失败数作徽标
合为「AI 能力」一页顶部 Skill / MCP 切换，侧栏少一项（见方案 C「合并导航」）
放进设置弹窗和 Claude / Cursor 一样，但与「Skill 独立成页」不一致
3
输入框 🔌 按钮
快捷浮层 + 跳页浮层只放开关，底部「管理 MCP 服务器」跳页（方案 A「输入框快捷」）
直接跳页最简单，但会打断对话
4
工具级控制（新能力）
一期：逐工具开关store 加 disabledTools，注册工具时过滤，改动小
二期：执行前确认写操作默认「每次询问」，需要对话流里加确认卡片，工作量大
都不做只换皮
5
添加方式
常用服务器 + 表单 + 粘贴 JSON常用清单内置静态数据，不做在线市场
表单 + JSON保持现有能力，只换样式
6
密钥存储
env / headers 值遮蔽显示一期只做 UI 遮蔽，仍存 localStorage
转存系统钥匙串Electron safeStorage，更安全，需迁移老数据
7
日志
做主进程已有连接 / 重连事件，补上 stderr 转发即可
不做只显示最后一条错误

④ 落地分期（按推荐组合）

  1. 一期 · 换页：features/mcp 新建页面（definePage key mcp），navigation.ts 的 AI 组加条目；复用 useMCPStore / customMCP.ts，表单与 JSON 导入逻辑从 MCPManagerModal 迁出；输入框 🔌 改为快捷浮层；删除老弹窗与 useMCPManagerModalStore（aiServer.ts 里的打开调用改为跳页）。
  2. 一期 · 补能力：逐工具开关、常用服务器清单、参数芯片 / 键值表编辑、密钥遮蔽、日志标签页、侧栏失败徽标。
  3. 二期：执行前确认（对话流内确认卡片 + 「始终允许」记忆）、密钥转存钥匙串、导出 mcp.json。
