项目详情页 · 全局侧栏 × 文档树 布局方案

问题：全局侧栏与项目文档树都是「竖排文字列表 + 同一底色」，并排时视觉权重相同，只能靠文档树右侧 1px 竖线区分，既违和又生硬。 下面 4 个方案都去掉这条竖线，改用 层级（底色/阴影/容器） 或 形态（图标轨/下钻/浮层） 来区分两者。

A纸面托盘推荐 · 改动最小

全局侧栏留在「桌面」底色上；文档树 + 正文装进同一张抬起的「纸」（圆角 + 柔阴影）。文档树在纸内用略深一档的 bg-group 底色，与正文靠色块分界，不需要竖线。 语义很清楚：纸外是 App 导航，纸内是这个项目。

⌂ 源核 ▾⇤ ＋
纸面边缘 = 分界，无竖线
＋ 只改容器样式，布局与交互不变；与现有 bg-surface / shadow-card 体系一致
＋ 其它详情页（白板、PDF、表格）可复用同一张「纸」
－ 横向仍占两栏宽度，窄屏需配合折叠

B侧栏换挡

进入项目详情时，全局侧栏自动收成 50px 图标轨（悬停弹出完整菜单），文档树顶替到「侧栏」位置并与侧栏共用桌面底色；正文是唯一抬起的纸面。 任一时刻只有一列文字侧栏，形态差异（图标 vs 文字树）天然可区分。

⌂ 源核 ▾⇤ ＋
离开项目后侧栏自动展开
＋ 正文区最宽；最接近 VS Code / Linear 的心智
＋ 侧栏折叠状态已有（« 按钮），可复用，只需按路由记忆状态
－ 进出项目时侧栏形态切换，需要动效过渡，否则会跳

C侧栏下钻

文档树直接「进入」全局侧栏：点项目后侧栏整体左滑切换成项目模式，顶部是「← 工作台」返回 + 项目卡片头，下方是文档树。像 Notion / 飞书知识库的层级导航。

← 返回导航
源核▾
＋ 彻底只有一列侧栏，最干净
－ 在项目内切到「今日 / 待办」要多一步；需要改侧栏架构（插槽/栈式导航）
－ 多个项目 Tab 并存时，侧栏内容要跟随 Tab 切换

D浮动目录

文档树默认隐藏，正文左侧留一条「目录刻度」（当前层级缩略）。鼠标移到纸面左缘或按快捷键时，文档树以浮层卡片滑出；可钉住，钉住后退化为方案 A。

⌂ 源核 ▾📌
悬停左缘滑出，可钉住
＋ 沉浸写作体验最好
－ 文档树可发现性差，频繁切换文档时多一次悬停

建议

  • A 作为默认：改动集中在 ProjectView/index.tsx 的容器（去掉 border-r border-line-1，外包一层 bg-surface rounded-tau-lg shadow-card，文档树改 bg-group），风险小。
  • 叠加 B 的自动收起作为设置项或窄屏（< 1200px）自动行为，解决两栏占宽问题。
  • C 改动大、D 牺牲可发现性，适合作为后续探索。
