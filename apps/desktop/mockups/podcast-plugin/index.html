播客插件化 · 结论与方案

现状：播客是宿主内置功能。podcasts 表在核心库，卡片 / 文章 / 项目文档 / Notebook 笔记四张表各有 podcast_id；生成逻辑全在 usePodcastGeneration（700 行）里，绑定弹窗生命周期，关弹窗即中断；Notebook 另有一份后台合成实现。入口散在四个详情页的「⋯」菜单。

结论：可行，但宿主要先补两项能力。页面、入口挂载、读原文、跳转、关联、事件、后台任务、FFmpeg 都已就绪；缺的是插件调用语音合成和插件保存音频文件。另需一次数据迁移，把现有播客搬进插件。

① 宿主能力对账

按播客插件要做的每件事逐项核对 packages/plugins/src。

② 宿主要补的两项（都是通用能力，不为播客单开口子）

参照已有的 speech:input（插件调用用户选好的语音输入）做对称设计。

新增形态为什么这样做
A 调用语音合成context.tts.getVoices() / synthesize(text, voiceId) / textInstructions，权限 tts:synthesize沿用用户在「设置 › 语音」里选的服务，内部复用 TTSProviderFactory；返回现有 TTSAudio。朗读、配音类插件以后都能用
B 保存资源文件非 hook 的 context.resources.upload(file) → url包装现有 desktopResourceService：本地模式写工作区 resources、远程模式走用户的上传配置，和正文资源一样同步、可被引用计数回收

模型不再由宿主管：「设置 › 模型」里的「播客生成」一行删除，宿主不再认识这个功能。

③ 插件结构（plugins/tau-plugin-podcast）

部分内容
实体 episodekey = 来源（如 article:123），标题由 AI 起；正文 = 带说话人的可读脚本；meta = audioUrl / duration / speakers / timeline[]（起点、时长、说话人）/ source / sourceGone。open 指向单期详情页
AI 功能ai: { features: [{ id: "script", name: "播客脚本", description: "把原文改写成多人对话脚本" }] }；生成前 ai.getStatus("script")，没配模型时对话框引导 ai.openSettings("script")
页面播客库（列表 + 迷你播放条）· 单期详情（播放器 + 跟读脚本 + 逐句重合成）· 审稿页
入口card / article / document 的「⋯ › 生成播客」；原文正文上方的实体面板（生成中进度 / 完成后播放条 / 失败续跑）；侧栏角标
任务队列activate 里起的单并发队列，与页面解耦；已合成的段落留在内存，失败从断点续；关窗后只保留脚本，重开从「合成语音」重来
从宿主搬过来脚本提示词与解析（services/podcast.ts）、逐句合成与拼接（Notebook 的 podcastAudio.ts 与 hook 里的两份合为一份）、说话人配色（PodcastPlayer/speakers.ts）

④ 设计稿

旧弹窗推翻重做：生成改成三问的轻对话框 + 后台任务；新增插件页管理全部播客。

插件页：播客库

列表露出原文并可跳转、点封面即播、迷你播放条；生成中 / 待审稿 / 失败任务置顶；单期详情含分色波形、跟读脚本、改句重合成；原文已删除与空态。

生成流程

⋯ 菜单入口 → 三问对话框（形式 / 谁来说 / 多长）→ 后台生成，进度在原文上方 → 可选审稿页 → 完成后原文上方播放条；无语音服务引导、失败续跑。

⑤ 需要你拍板的点

高亮的是我的推荐。

1
插件怎么到用户手里
内置插件，默认启用存量用户已有播客，迁移后必须立刻能看到；用户可在插件中心停用
插件中心自选安装更纯粹；但有存量播客的用户要先装才看得到
2
Notebook 里的「播客」生成
一并移交插件Notebook 生成类型里去掉播客；插件 action 增加 notebook 目标（宿主已有该实体类型），旧 Notebook 播客迁成插件实体
Notebook 保留自己的两套实现继续并存，宿主删不干净
3
一篇原文几期播客
一篇一期重新生成直接替换，新的成功后才删旧的；和现在一致
可以多期同一篇换风格各生成一期；面板要改成列表
4
合成前审稿
可选，默认不审对话框里一个勾选框，记住上次的选择；不审也能事后逐句改
总是先审和现在一样每次停在脚本编辑
5
新形式：单人讲述 / 圆桌
都加只是提示词与默认人数不同；单人需放开「至少 2 人」
只保留双人形式卡去掉，对话框更短
6
音色克隆入口
只留在设置 › 语音生成对话框里只放跳转链接；克隆是一次性配置，不该挤在每次生成里
对话框里保留和现在一样可折叠展开
