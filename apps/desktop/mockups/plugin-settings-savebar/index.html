插件设置：悬浮保存条 + 离开确认

以「体重」插件的「身体数据与目标」为样本。改任意字段，保存条从底部升起；点侧栏、其他 tab 或「模拟关闭窗口」看离开确认。

为什么不全改成即时生效

场景即时生效草稿 + 保存
开关、单选、主题等偏好合适，改完就看到效果多余的一步
API Key、地址、账号每敲一个字都去连一次服务；填一半就落盘成坏配置填完整、校验通过再写入，可附带「保存并测试」
互相约束的一组字段（身高+年份+目标→预算）中间态会让预算忽大忽小，甚至写入非法值整组校验，一次提交
有副作用的修改（记账删分类会迁移流水）误操作立即生效，无法反悔保存前可还原

所以两种都要：宿主表单（ProviderForm）已支持 autoSave，适合简单偏好；需要校验或有副作用的设置，用下面这套保存条。保存条由宿主统一画，插件只报告「有没有改动、怎么保存、怎么还原」。

「身体数据与目标」中的这些修改离开后会丢失：

    • 出现时机：草稿与已存值不同即升起，改回原值自动收起；不打扰没改动的浏览。
    • 位置：吸附在设置区可视底部（sticky），表单短时停在内容下方，长时贴住视口；永远在用户眼前。
    • 文案：说出改了几项；有校验错误时变红、「保存」点了会把页面滚到第一处错误并抖一下。
    • 保存中 / 成功 / 失败：保存中按钮转圈、字段不锁；成功后显示「已保存」1.2 秒收起；失败留在条上显示原因，可重试。
    • ⌘S 在设置页内触发保存；条上显示快捷键提示。
    • 离开确认：切 tab、侧栏导航、后退、切设置分组、关窗口都拦。三个出口：保存并离开（默认，回车）/ 继续编辑（Esc）/ 放弃修改；校验未过时「保存并离开」不可用。
    • tab 圆点：有未保存修改时「设置」tab 带一个强调色圆点，滚出视口也有提示。
    • 关闭窗口：Electron 主进程收到 close 时询问渲染端，有守卫才弹同一个对话框；应用退出、系统杀进程时不保证。
