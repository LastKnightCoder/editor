日程 · 日历页重设计方案

legacy 日历（src/pages/Calendar，约 5k 行）迁入新壳层的 schedule 入口。三个方案共用同一份数据模型（日历分组 / 日历 / 日程，无重复规则）和同一套主题语言：纸底 + surface 面板两层、面板靠 shadow-card 不描边、accent 只给「今天 / 现在 / 选中 / 主按钮」，日历色是数据色走 tag 1–5。下方窗口可切换方案、视图、交互状态与深浅色。

现状诊断 legacy

  • 通用后台脸：「今天」按钮带阴影、hover 阴影加深，头部整条 border-b 切开，侧栏和视图之间再加一条竖线——三处都是 PREFERENCES 的反例。
  • 双侧栏：新壳层已有全局侧栏，日历再套一个 240–400px 可拖宽侧栏，左边两列导航，视图只剩一半宽度。
  • 颜色没有语义纪律：17 色高饱和项目色板，月视图里所有日程都是实心色条 + 白字，深色模式另取更艳的值，和纸感主题正面冲突。
  • 表现与逻辑缠在一起：MonthView 单文件 1016 行；取色逻辑复制 8 处，跨行条的 span 计算复制 3 处；WeekView 在 map 里调 hook。
  • 既有缺陷：月视图行高写死 5 行（6 行月份错位）、议程丢掉全天与跨天日程、周标题是估算的「第 N 周」、新建默认日期用 UTC 可能差一天。
  • 交互只有「拖拽新建 + 点击编辑」：不能拖动改时间、不能拉伸、没有右键菜单与键盘；番茄钟与待办同步来的日程和普通日程长得一样。

三个方案

A · 纸 + 卡 · 经典三件套 第一版

信息架构与 legacy 一一对应：左列迷你月历 + 日历清单，右侧页头工具条 + 视图面板，点日程开 Dialog 编辑。只换皮不改交互模型，所有旧组件都有明确落点。
改动
侧栏去拖宽、去竖线，融进纸底；头部去横线；视图装进 surface 面板；Dialog 换 tau 家族
代价
仍是「双侧栏」，视图宽度受限

B · 周为主轴 · 右侧检查器

默认周视图。点日程不弹窗，右栏检查器就地编辑（标题 / 时间 / 日历 / 备注编辑器）；未选中时右栏是「今天 + 接下来」速览。拖拽建日程后直接在检查器里写标题。
收益
编辑不遮挡上下文，连续整理多条日程成本低；键盘可走完全流程
代价
需要 1280px 以上才舒展，窄窗检查器转抽屉

C · 月刊 · 月历 + 当日时间线 第二版 · 已选

去掉内层侧栏，日历筛选收成工具条 chips（管理进 Popover）。月历沿用 A 的整块大面板（格内细线，含邻月日期），右栏是选中日的时间线（含空档提示）+ 自然语言快速添加。
收益
最有个人特色、宽度利用最好，月视图和当日安排一屏可见
代价
日历多（>8 个）时 chips 会折行；快速添加需要写解析器
