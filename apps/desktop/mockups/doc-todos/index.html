文档 checkbox → 待办 · 交互与 UI

卡片、文章、日记、项目文档里的 - [ ] 自动汇总到待办页；在哪边勾都会同步到另一边。本页里的勾选框、标签页和抽屉都能点。

01数据归属：谁是真相源

这是最根本的问题，决定后面所有的同步和交互。推荐 C：正文才是真相源，待办页只做镜像，而且零配置——写了 checkbox 就会被收集，不需要额外标记。只有当用户想给某一项加周期、番茄或日程时，才把它转成独立待办，转换后这一项归待办表所有。

02编辑器一侧：几乎没有变化

checkbox 的样式和行为保持原样。新增两处：一是行内日期自动识别，解析器沿用 quickAdd 的自然语言规则，识别出的日期渲染成小胶囊，原文本身不改；二是文档底部一条收集状态条，可以把整篇文档排除在收集之外，适用于模板、读书笔记里的示例清单等。

02b正文内的项目与日期：沿用 quickAdd 的写法

项目和日期写在正文里，用的就是待办页快速添加的那套语法：#项目名 和「周五 / 明天 / 10月10日」。编辑器用装饰把它们渲染成胶囊，底层仍是纯文本，所以 markdown 导出、移动端、协作他人那边看到的都是原样文字。待办页对条目的项目和日期，就是读这段文字得来的。

04条目抽屉：只读原文 + 三个动作

文档条目的标题不能在待办页里改，要改就回原文改，这样可以避免双向编辑冲突。抽屉里展示条目在正文中的上下文（父项和前后各一行），并提供三个动作：打开原文定位、转为独立待办、本文不收集。

  • 转为独立待办：新建一条 todo_item，标题、日期、子项一起复制过去，挂进「工作」等项目，并自动通过 todo_note_link 关联原文。原 checkbox 保持不变。从此两者各自独立，避免一条事项出现两次，镜像里会把这一项标记为「已转」并隐藏。
  • 完成、撤销完成都是乐观更新，同时弹出 Toast「已在《Q4 发布准备》中勾选 · 撤销」。删除不在这里做，删除只能去正文删。

05同步边界与异常态

⟳
文档正被编辑
待办只调用内容层的 patchContentNode(contentId, { taskId }, { checked })。内容层自己决定怎么落地：有编辑会话就做一次属性级修改，和正在进行的输入合并；没有会话就改 JSON 后落库。待办模块不知道协作层的存在。
≠
该项已被删除
按 id 找不到就放弃写入，Toast 提示「原文中已没有这一项」，并重建这篇文档的索引。插行、移动、改文字都不影响定位。
🔒
只读 / 协作他人文档
勾选框禁用，悬停时提示「来自共享文档，只能在原文勾选」。
🗑
文档删除 / 进回收站
对应条目随之消失，不做额外提示；文档恢复后条目也恢复，因为索引可以重建。
∅
「文档中」空态
提示「在任意文档里输入 [] 加空格创建 checkbox，就会出现在这里」，不放演示数据。
✓
已完成项
默认隐藏，每组底部提供「显示 N 项已完成」。勾选后 1.2 秒再淡出，留给用户误点后撤销的时间。

06需要你拍板的点

  1. 数据归属选 A / B / C？C。镜像零成本，复杂的事交给「转为独立待办」，不做双向实体同步。
  2. 收集范围：默认收集全部，还是只收集带日期 / 带 #todo 的？默认全部收集，加上按文档「本文不收集」开关，符合零配置偏好。
  3. 没有日期的条目是否进「按日期」议程？不进，只在「文档中」里出现。
  4. 移动端是否首期就做？首期只做桌面端。数据在索引库，移动端二期复用同一份抽取函数。
  5. 块身份：check-list-item 自带 taskId，由 @tau/editor-list 规范化补齐（回车拆分、粘贴时去重），存量数据一次性升级补齐；不依赖协作层的 collabId。可以。字段归 checkbox 自己，协作层怎么改都不影响待办。
