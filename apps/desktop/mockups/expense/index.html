先说清楚：专业记账软件都在做什么

YNAB、Copilot Money、Monarch、MoneyWiz，国内的随手记、鲨鱼记账、钱迹，形态各异，但核心都是同一个循环：

花钱时 3 秒记一笔→自动归到分类→和预算比：还剩多少→月底看分布和变化→调整下个月预算
  • 记录要快，否则坚持不下去。这是所有记账软件流失的第一原因。专业软件的做法：数字键盘优先、分类记住上次选择、常用项一键重复、固定支出（房租、订阅）自动入账，以及银行账单导入。这里用一句话记账：「午饭 牛肉面 28」，本地规则识别金额和分类，认不出时让你点一下，记过一次后自动归类；
  • 预算比记录更能控制支出。只记账不设预算，月底只能看到一个已经发生的数字。YNAB 的核心是「每一块钱都有去处」，简化版就是分类预算（信封法）：给每个分类一个月额度，花之前就能看到这个信封还剩多少；
  • 拿时间进度做参照。29 号花了 90% 是正常的，10 号花了 60% 就该警惕。所以每个预算条上都有一根「今天的时间进度」竖线，花费超过竖线 10 个点就标「偏快」。本月累计图也是同一个思路：实线（实际累计）在虚线（均匀花完预算）上方，就是花快了；
  • 固定支出和可控支出分开看。房租、话费、订阅每月不变，混在一起会让日均、日历颜色、和上月比较都失真。三个方案里固定支出单独标注、不参与日历着色和日均计算；
  • 分布要和「平时」比才有意义。「餐饮 ¥2,837」本身说明不了什么，「比前 3 个月平均多 ¥200，多在夜宵」才能指导行动。分析一律以前 3 个月平均为基准；
  • AI 是解读者，不是计算器。所有金额由插件本地算好，AI 只拿到汇总后的结构化数据（分类合计、子分类、大额、周几分布），负责找原因和给可执行的建议，并估算能省多少。

方案 B

流水日历 · 记录与查找

经典记账软件的样子。左侧是月历，格子颜色深浅 = 当天可控支出多少，一眼看出哪几天花得多；点一天，下方显示当天的分类分布和每一笔。右侧是完整流水表：按天分组、搜索备注、按分类和账户筛选，筛选结果实时给出合计和分类分布条，可导出 CSV。

✓ 查账、改账、找某一笔最顺手；日历热度很直观 ✓ 筛选 = 临时报表：「10 月打车一共多少」一步得到 ✗ 对「还能花多少」只给一个数字，约束感弱

推荐组合

  • 插件页做三个子视图 预算 | 流水 | 分析（页内 segmented 切换），默认打开 A 预算：每天看它，记账也在这里；查账去 B，月底复盘去 C；
  • 点 A 的某个信封 → 跳到 B 并带上分类筛选；点 C 的某个月柱 / 分类 → 同样跳到 B 的对应筛选。三个视图共用一套筛选状态，数字永远对得上；
  • 首页卡片（home 扩展点）放「本月还能花 ¥346 · 今天 ¥56」+ 一句话输入框，不进插件页也能记一笔；
  • 月初第一次打开时，C 的 AI 复盘以「上月报告」形式出现在 A 顶部，一键采纳它建议的预算调整。

三个方案共用的视觉与图表规范

  • 分类色（数据色，不进主题词表），顺序固定：餐饮 购物 交通 娱乐 居住 人情 其他（中性灰）。已用色盲校验脚本验过：浅色主题相邻对色盲 ΔE ≥ 9.1，深色 ≥ 8.4。黄、青、粉在浅色背景上对比度低于 3:1，所以分类始终 图标 + 文字 一起出现，颜色只染小圆底；颜色跟着分类走，排序、筛选都不改色；
  • 金额一律等宽数字，支出写 −28；超支、比平均多用 danger 红，省下来用 ok 绿，且都带正负号，不只靠颜色；
  • 不用饼图：7 个分类、数值接近时饼图分不清大小。分布用横向排行条（能比大小）或 100% 堆叠条（看占比），段间留 2px 缝；
  • 日历热度用 accent 单色深浅（顺序色阶），不用红绿；固定支出用小圆点标出、不参与着色；
  • 图表只有一根纵轴（金额），每个图都有悬停提示，后续补「表格视图」满足无障碍和导出。

需要你拍板的问题

  1. 主视图：同意默认打开「预算」吗？还是你更习惯打开先看流水？
  2. 只记支出，还是也记收入？只记支出最简单；记收入就能算结余和储蓄率，但每月要多记几笔；
  3. 账户要不要？（微信 / 支付宝 / 信用卡）。不需要对账的话可以去掉，记账更快；
  4. 导入：要不要支持导入微信 / 支付宝导出的账单 CSV？能省掉大部分手动记录，但需要去重和分类映射；
  5. 分类：上面 7 个大类 + 子分类够用吗？有没有你特别想单独盯的（比如「咖啡奶茶」「打车」）可以设子预算；
  6. 大额一次性支出（旅行、电子产品）：放进月预算，还是单独设年度预算不占月额度？
