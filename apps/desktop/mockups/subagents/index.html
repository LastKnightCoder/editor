子 Agent · UI 设计方案

新运行时下，子 Agent 是可复用的子会话：主 Agent 用 spawn_agent 派发、send_agent 续派、wait_agent 等待、cancel_agent 取消；子 Agent 用 send_parent 报进度；问题与权限审批由用户直接回答。现在的 UI 只是对话顶部一排「标题 · 状态」按钮 + 一个 820px 对话框，信息量和操作入口都不够。下面三套方案共用同一套状态语言、交互卡和详情内容，差别在放在哪里、怎么组织。

定稿：方案 A · 内联任务卡 + 侧抽屉。对话开在右侧辅助栏时采用栏内下钻查看详情（场景 10）；B / C 仅留作对比参考。

三套方案

每个方案页顶部都能切 9 个场景、浅/深色；按 N 看方案说明，按 A 看标注。

A · 内联任务卡 + 侧抽屉 定稿

派发那条回复里出现任务卡，一行一个子 Agent，问题直接在卡里答；点行在右侧抽屉看子会话。贴近上下文、改动最小。

B · 任务坞 + 分屏

对话流只留轻标记；输入框上方常驻「任务坞」，待处理置顶；点子 Agent 在右侧分屏打开，可边看边聊。

C · 子 Agent 看板

对话头部切「对话 / 子 Agent」；看板按 等你处理 / 进行中 / 已结束 三列，卡片上作答，居中浮层看详情。适合子 Agent 多、跨轮复用。

场景对照

同一组数据（调研三家同步方案 + 一个汇总子 Agent），在三个方案里逐一对比。

场景要回答的问题打开
1 派发派了几个、各做什么、谁在排队（三路并发上限）
2 并行进行中每个子 Agent 此刻在干什么；先回来的结果怎么呈现
3 等你处理ask-question 与权限审批：在哪答、答完后怎样
4 完成回传结果如何回到主 Agent，主 Agent 续跑汇总
5 失败/中断/取消只展示真实 error.message；是否重试交给主 Agent
6 续用同一子 Agentsend_agent 续派：同一身份、第 2 次任务、保留历史
7 查看详情子会话全文：任务说明、工具、进度报告、结果、执行记录、停止
8 在别的页面离开对话后怎么知道有事要处理，能否就地答
9 同步派发mode=sync：主 Agent 在等，界面怎么表达「卡在子任务上」
10 侧边栏对话开在右侧辅助栏（360–560px）时怎么看子 Agent 详情：栏内下钻 / 向左外展（仅方案 A）A
11 顶部常驻入口对话头部汇总胶囊：本对话所有子 Agent 的分组列表 → 点一行进详情（页面与辅助栏都有）A

三方案共用的设计约定

  • 身份：每个子 Agent 一枚彩色首字头像（tag-1…5 循环），右下角状态点；同一个子 Agent 在流、抽屉、标题栏里颜色一致，续派时一眼认出是「老朋友」。
  • 状态语言：执行中 = accent 转圈 + 活动行文字流光；等你处理 = warn 色且呼吸点；完成 = ok；失败 = danger；排队/取消/中断 = ink-3 / warn，与现有 ToolCallRow 的语义色一致。
  • 活动行：用子会话最新一条工具调用或思考生成一句「正在…」（如「读取 docs.logseq.com…」），这是用户最想看的信息，现有 UI 完全没有。
  • 交互卡：问题 / 审批复用同一组件，数字键 1-3 选项、「自己写」「跳过」；审批「允许一次 / 本会话都允许 / 拒绝」，对应 PiPermissionScope 的共享授权。
  • 进度报告：send_parent 的进度以 info 色「↗ 报告给主 Agent」出现在子会话里，主对话不单独展示（它只进父上下文）。
  • 失败：只显示真实错误文本，不造分类与重试按钮；底部按钮是「让主 Agent 追问」，把决定权留给主 Agent，符合运行时契约。
  • 详情页底栏：明示「子 Agent 只接收主 Agent 的指令」，避免用户以为能直接给子 Agent 发消息。
