插件中心与已安装管理

目标：把「设置 → 插件」里的草稿版换成完整体验——在软件里发现、安装、更新插件，并管理已装插件的启停、设置、版本恢复与卸载。mockup 只使用门户与运行时今天就能拿到的字段：manifest（名称 / 版本 / 简介 / minAppVersion）、README、CHANGELOG、发布时间、包大小与 SHA-256；不展示下载量、评分、截图等不存在的数据。图标暂用名称首字 + 按 ID 取色。

已确认（2026-10-17）

  • 采用方案 B · 独立插件页：侧栏底部「插件」入口（徽标 = 可更新数）→ plugins 页（发现 / 已安装 / 更新），详情 push 为 plugin-detail 页；插件自己的设置并入详情页「设置」标签。
  • 设置弹窗保留跳转入口：「系统 → 插件」分节只剩一行概要和「打开插件页」，不再承载列表与插件设置。
  • 从插件中心安装后自动启用；本地 ZIP / 手动放入目录仍默认停用。
  • 发现页不做「刚刚上架」大卡，直接是全部插件网格。
  • 方案 A（设置内一体）、C（分栏管理器）未采用，见 git 历史。

交互约定

  • 安装与更新都是「下载 → 暂存 → 重启生效」（沿用 C17 事务）。页面顶部出现重启条，按钮变为「重启后生效 · 取消」，不假装热安装。
  • 从中心安装视为同意启用：重启后自动启用，免去"装完还得再去开关"；手动放入目录 / ZIP 安装仍默认停用。
  • 来源标签：插件中心 / 本地 ZIP / 内置 / 开发中。只有「插件中心」来源检查在线更新。
  • 如实的信任提示：当前插件在完整宿主环境运行，详情页与安装确认里写清楚"可访问你的笔记数据"，不暗示存在沙箱。
  • 不使用 Segmented；筛选与排序用按钮 + Menu；本地 ZIP / 打开目录 / 重新扫描收进 ⋯ 菜单，不占主操作位。
