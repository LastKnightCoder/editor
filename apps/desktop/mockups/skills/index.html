Skill 管理页 · 方案与决策

现状：pages/SkillManagement（895 行 legacy，antd + react-icons）是整个 skills 目录的一棵文件树 + 编辑器（md 用 Tau 编辑器、其它用 CodeMirror）；4 个内置 Skill 不在树里；没有逐 Skill 开关，所有 Skill 的描述无差别注入系统提示词；frontmatter 只解析 description，名字取文件夹名。目标：和 MCP 页（D-058）一样换新壳层，并借鉴主流平台补齐开关与调用方式、编写体验、跨工具复用三块。

② 相比现状要补的能力

三套布局都包含这些，区别只在「怎么排」。

逐 Skill 开关 + 调用方式自动（默认）/ 仅手动 / 常驻（可选）；仅手动与停用的不占系统提示词。
上下文预算显示自动 Skill 描述合计多少 tokens，描述过长 / 缺失标黄提醒。
输入框 / 手动调用斜杠菜单选 Skill，挂成芯片；AI 自动加载时回复顶部显示「已加载 Skill」。
单 Skill 编辑器文件树只显示这个 Skill；SKILL.md 上半截是表单（名称 / 标识 / 描述 + 字数与触发提示），下面是正文，可切源码。
四种添加方式新建（空白 / 模板）· 用 AI 创建 · 导入 .zip / 文件夹 / GitHub 链接 · 关联目录。
试一试 + 使用记录用未保存版本跑一轮验证；统计哪些对话加载过、自动触发占比。

③ 页面布局：三选一

三套都做成了可点的样板间，添加弹窗、编辑器、斜杠菜单三者共用。

A 列表 + 工作区

左列 Skill 清单，右侧概览 / 文件 / 设置 / 使用记录。最接近现有页面，切换查看最快；但编辑区偏窄、放不下「试一试」。

B 卡片库 + 编辑页 推荐

与 MCP 页同构（卡片 + 抽屉预览），编辑推入整页：文件树 + SKILL.md + 「试一试」三栏。浏览轻、编辑舒展，AI 组两页一套心智。

C 设置式单列

一行一个 Skill，调用方式下拉合并开关，展开看文件 / 工具。最轻最密，但看不到正文，与 MCP 页不一致。

④ 需要你拍板的点

高亮的是我的推荐。

1
页面布局
A 列表 + 工作区迁移最省，切换最快
B 卡片库 + 编辑页与 MCP 页一致；编辑有独立空间和「试一试」
C 设置式单列最轻，适合 Skill 很少的情况
2
调用方式
开关 + 自动 / 仅手动对齐 Claude Code 语义，仅手动写 disable-model-invocation
再加「常驻」Cursor Always 式，每次注入全文；费 tokens，易被滥用
只做开关最简单，但无法「只在我要时用」
3
手动调用入口
输入框 / 斜杠菜单主流做法；选中后以芯片挂在输入框
放进 ＋ 面板和 MCP 二级列表放一起，但多一步
两者都有＋ 面板里给 Skill 开关，/ 负责本条消息强制加载
4
添加方式
新建（模板）+ 导入 + 用 AI 创建AI 创建 = 内置一个 skill-creator Skill + 对话式起草

5
关联外部目录
做，只读~/.claude/skills 等只读挂载，想改就「复制为我的」
不做只管理应用自己的 skills 目录

可停用 + 可复制为我的原件只读随应用更新；同名时内置优先的规则不变
