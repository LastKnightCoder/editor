Agent 修改工具卡 · 改版方向

对象：对话里 Agent 调用修改工具后出现的卡片（SuggestionProposalCard + SuggestionCard）。

现在的问题

  • 内容藏在折叠后面。每条只显示「查看改动 · 原文前 40 字」，要逐条点开才知道改了什么；标题用的是原文开头，看不出改动点。
  • 状态说了三遍。头部「的 4 条建议已处理」、摘要「接受 4 条」、每行「已应用」，信息重复但没有一处讲清改了哪些字。
  • 差异读起来费劲。整段原文删除线 → 整段新文，长句里只改了两个字也要自己比对。
  • 按钮太多太散。展开一条就有 接受 / 退回 / 回复 / 在正文定位 / 继续修改 五个按钮，各自换行；批量按钮又在列表最下方。
  • 每条一个描边框，四条就是四个盒子叠在一个盒子里，视觉很碎。

三个方向

A 紧凑清单 推荐

一行一处改动，默认就显示前后文 + 词级差异；操作收成悬停图标；处理完自动收起成一行摘要。改动只在两个组件内，数据结构不变。

B 逐条审阅

一次聚焦一处，原句 / 新句上下对照，Y/N 键快速过；分段进度条。适合措辞类、需要读语感的改动，改动多时要按很多次。

C 摘要卡 + 文档内审

对话里只放规模摘要和全部接受；细审跳到正文，修订痕迹落在原位，底部悬浮审阅条。体验最好但要改编辑器标记层。

对比

A 紧凑清单B 逐条审阅C 摘要卡 + 文档内审
一眼看完全部改动能不能，只看当前一处对话里看规模，正文里看全部
上下文前后半句整句整篇原位
处理速度快（悬停 + 收尾一键）键盘最快，改动多时次数多全部接受最快；细审要切到文档
对话流占高中，完成后收起成一行固定最低
改动范围两个渲染组件 + 词级 diff 工具同 A，多一层当前项状态和快捷键A 的卡片 + 编辑器修订标记、气泡、审阅条

建议

  • 先做 A，把「看得见改了什么」和「操作不打扰」解决掉。
  • B 的键盘操作（↑↓ 切换、Y/N）可以作为 A 的焦点行快捷键，不必单独做一套界面。
  • C 等正文修订痕迹（agent-coedit 方案 A）落地后，再把「在文档里审阅」接上。
