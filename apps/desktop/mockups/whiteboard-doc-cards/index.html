白板 · 文章 / 项目文档卡片

双击卡片或选中后按 ↵ 展开 · Esc 收起 · 拖空白处平移 · ⌘/Ctrl + 滚轮缩放

A · 全屏展开

同类：Spatial、Milanote 文档、Apple Freeform 的便签放大

交互

  • 卡片从原位置「长」成一张居中的纸，画布压暗；Esc 或点纸外收回原位。
  • 纸宽 780，正文列 620（约 33 个汉字一行），和文章详情页的阅读宽度一致。
  • 画布上的原卡在展开期间隐藏，收起时纸「落回」原卡，编辑结果已经写进卡片。

评价

  • 注意力最集中，长文读写最舒服；空间连续感最好，像拿起一张纸凑近看。
  • 实现最简单：一层浮层，不改画布布局。
  • 编辑时看不到白板：不能边写边看别的卡片，也不能从正文往画布拖连线。
  • 在画布上「整理」（连续点开好几张）时，每次都要开合一遍。

B · 右侧面板

同类：Heptabase（白板卡片在右侧栏打开）、Obsidian Canvas 的侧边打开

交互

  • 卡片「飞」进右侧面板，原卡留在画布上标「编辑中」，打字实时同步回卡片。
  • 被面板挡住的卡片，画布会自动平移让它露出来。
  • 面板开着时单击画布上另一张文档卡，面板直接换成那一篇，不用先关。

评价

  • 适合对照写作：左边看素材、右边写；能看到修改落在白板上的位置。
  • 连续浏览多张卡片的成本最低。
  • 面板约 640px，在 1280 宽的窗口里画布只剩一半，左侧全局侧栏展开时更挤。
  • 从小卡飞到屏幕右侧，位移很远，「从卡片展开」的感觉比 A 弱。

C · 居中展开 + 可停靠推荐

同类：Heptabase（侧栏与全屏可切换）、Notion 的居中预览 / 侧边预览

交互

  • 默认按 A 居中展开；纸面右上角的「停靠到右侧」切成 B，「居中」再切回去。
  • 记住上一次的打开方式（按白板记），整理时停靠，写作时居中。
  • 停靠状态下单击别的文档卡就换内容，和 B 一样。

为什么推荐

  • 「读 / 写一篇」和「整理一片」都是白板里真实存在的场景，只选一种必然有一半人别扭。
  • 两种形态共用同一个阅读纸组件，只是摆放的位置不同；多出来的成本只有一个切换按钮和一次 View Transition。

卡片也是文档卡，和富文本分开

富文本属于白板自己的字，正文存在画布里。没有纸面，双击原地编辑，拖动边框就能改宽度，字号跟着缩放走。左下角那段就是富文本。
文档卡文章、项目文档、卡片三种，都是引用库里的实体。在画布上只看不编辑，双击展开编辑，删掉白板上的元素不会删掉原文。
卡片的差异版宽 460，比文章的 620 窄，缩小后的字更好认。没有标题，第一段加粗当标题，标签放在顶部，展开后是一张更小的居中纸（560 宽），不铺满整屏。
现状白板里的卡片现在复用富文本组件就地编辑，读代码看，正文改动没有写回卡片（saveCard 不带 content）。改成文档卡后统一走 ContentEditor，按 contentId 读写，这个问题会顺带消失。

通用设计输入（三个方案都适用）

触发单击只选中，双击、↵ 或选中后的「展开」胶囊才展开。白板上单击要承担拖动和框选，单击即展开会在拖动时误触发。Spatial 是单击即开，但它的卡片不承担连线、编组这类编辑操作。
卡片长相就是文档本身按 620 版宽排好再缩小（封面、标题、正文开头），底部渐隐。没有 banner 的文章用按 id 派生的粉彩封面。
低缩放缩放低于 45% 时只画标题和骨架线（试试缩小画布），沿用现有的 ContentSnapshotObserver 思路。
编辑展开后直接可编辑，实时保存，不设「完成」按钮；退出靠 Esc 或点纸外。
动画展开卡片时，阅读纸里那份文档从卡片的位置和缩放放大到 1，同时用 clip-path 把纸面从卡片大小揭开。文字不重排，全程只合成 transform，60fps，而且清晰。时长约 450ms，用临界阻尼弹簧曲线。
为何不用 View Transitions 做展开View Transitions 拿的是截图，文字从 0.39 倍放大时会糊；动画期间页面不能交互，也不能中途打断。所以只在停靠和居中之间切换时用它，和 page/morph.ts 一致。
减少动效系统开了「减少动效」时，改成 120ms 淡入淡出。
建议落地顺序：先做卡片元素和 C 的居中形态，形态稳定后再加停靠，停靠只是阅读纸换个摆放位置。
