导出图片 · 主题与弹窗重设计

对象：components/ContentExportModal（卡片 / 文章 / 项目 / 编辑器窗口的「导出图片」）。白板的导出弹窗是另一套（背景 / 倍数 / 边距），不在本稿范围，选定方向后可以再对齐。

配色是手挑的，和应用不成套16 组渐变各自取色，饱和度、明度没有统一口径（柠檬黄绿、薄荷绿蓝很跳）；文字只有纯黑 / 纯白，正文里的链接、引用、代码块仍按应用主题取色，跟背景不配套。
一个维度拆成了两层先选「深色 / 浅色」再从 8 个预设里挑，两边各记一个当前项，但只存在内存里，重开弹窗后另一侧的选择就丢了；宽度只有「移动端 / 桌面端」两档。
出口单一只能下载，文件名是时间戳，不能复制到剪贴板；看不到导出尺寸；导出按钮被刷成背景渐变，不像主操作；不能隐藏标题，也没有日期和署名。

一、配色方向

三个方向都从应用已有的 6 套主题推导，不再单独挑颜色
共同的底子：导出样式 = 应用主题（暖纸 / 海盐 / 薄荷 / 紫藤 / 樱花 / 水墨）× 浅 / 深，共 12 种。纸色、墨色、强调色、引用线、代码底都取该主题的 --tau-*，所以正文里的链接、引用、代码块和背景天然成套；对比度已由 theme-parity.test.ts 的 AA 断言兜住。以后新增一套应用主题，导出就自动多一种样式，零维护。

二、弹窗交互

三种布局，都可以点；上面选的配色方向会同步到这里
方案 A · 右侧设置栏推荐：保留现在「左预览、右设置」的骨架，但设置一屏看全、不用滚动。
  • 样式：6 个主题色块（色块就是缩小的纸 + 背景，所见即所得），右上角一个「深色」开关，代替现在「深色 / 浅色」+ 8 个预设的两层结构。默认跟随应用当前的主题和明暗，用户改过之后记住。
  • 尺寸：宽度、边距做成按钮 + 菜单（不用分段控件）；宽度从 2 档扩到 375 手机 / 600 标准 / 800 宽屏。
  • 显示：标题、日期、署名三个开关；署名是左下角的「Tau」小标，可以关掉。
  • 出口：「复制」和「保存图片」并列，保存用文档标题命名；底部常驻导出尺寸（如 600 × 1180 · @2x）。主按钮回到 accent 色，不再刷成背景渐变。
方案 B · 预览为主 + 底部工具条：弹窗几乎全给预览，所有设置收进底部一条工具条，参考 ray.so 这类「先看效果再微调」的工具。
  • 工具条从左到右：6 个主题圆点（悬停显示名字，选中后右边写出名字）、深色切换、宽度菜单、「选项」菜单（边距 + 标题 / 日期 / 署名）。
  • 复制 / 保存放到右上角标题栏，和关闭按钮挨着，⌘C 复制、⌘S 保存。
  • 代价：边距和显示开关藏进了菜单，第一次用的人要点开才看得到。
方案 C · 样式画廊：把 12 种样式（6 主题 × 浅 / 深）平铺在顶部一排，一眼看全，点哪个就是哪个，不需要「深色」开关。
  • 适合样式就是主要决策的情况；宽度、边距、显示开关收进右上角「选项」菜单。
  • 缩略图是骨架（标题条 + 正文线 + 引用 + 强调色），不是真实内容：12 份真实内容要渲染 12 个编辑器实例，长文时开销明显。
  • 代价：顶部条占掉约 140px 预览高度；以后应用主题变多，这一排会更长（横向滚动）。
