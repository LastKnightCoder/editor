白板列表页设计探索 · 三方案

现状：legacy pages/WhiteBoardView 是 antd 卡片网格加右下角悬浮「＋」。每张卡片上半是封面，没设封面时显示一张 CDN 占位图（离线会破图，所有白板都一样），五种随机主题色描边；下半是标题、「发表于」创建日期和两行描述。更多菜单要悬停才弹出（编辑 / 删除 / 换背景图），删除用 modal.confirm。卡片上看不到白板有几页、画了什么、最近什么时候改过。

三个方案共用同一份 mock：12 个白板，共 29 页，数据形状与 types/white-board.ts 一致。缩略图不是占位图，而是用每页的真实元素几何（图形、连线、卡片、文本、图片、思维导图、画框、手绘、视频）按「适应全部」的视角画出来的。列表接口 get-all-white-boards 本来就返回全部子白板和元素，所以实现时不需要额外取数。都能操作：新建、编辑信息、更换 / 移除封面、删除确认、排序、打开到指定页（mock 里用 Toast 表示跳转）。标题栏虚线框是演示开关（正常 / 空态），右上角切换 cream / cocoa。

方案 A · 二轮

画廊 · 标题过滤 + 侧栏标签 + 引用提示

标题过滤：工具栏右侧的过滤框（⌘F 聚焦，Esc 清空），边输入边筛，命中的字高亮，右侧显示「命中 / 总数」；没有命中时给出「清除过滤」。标签（日记同款）：标签不在页内另做目录，而是挂到全局侧栏「白板」下面作子项（各标签 + 无标签，带数量），点一下只看这个标签，工具栏标题旁出现可关闭的标签 chip；在某个标签下新建会自动带上它。卡片上以「点 + 软底」小 chip 显示标签，点 chip 也能切过去；「更多 → 标签…」打开和日记一样的勾选 / 新建浮层。演示开关可以隐藏卡片上的标签，对比只靠侧栏的效果。引用提示：删除确认里列出引用它的项目（主进程已有 get-project-item-by-ref，删除时本来就会 resetProjectItemRef），说明这些条目会解除关联。

✓ 标签复用日记的侧栏子项、Tag 七色和选择器，不新造交互 ✗ 待定：卡片上要不要显示标签（侧栏已经能筛选）

一轮 · 三个方案

方案 A

画廊 · 缩略图卡片网格 + 悬停扫页

和文章页、项目页的卡片网格是一家：一张卡片 = 画布缩略图 + 标题 + 一行描述 + 「4 页 · 30 个元素 · 2 小时前更新」，有演示序列的标「可演示」。多页白板在缩略图上横向移动鼠标就能翻页（左上角显示页名，底部是页码刻度），点下去打开的就是当前看到的那页。封面是可选的：设了就显示封面，悬停扫页时换成各页画布。右上角是「更多」，右键也能打开同一个菜单。演示开关里可以在网格末尾加一个「新建」格作对比。

✓ 最直观，一眼认出哪块板；和文章 / 项目网格同构，迁移成本最低 ✗ 页的结构藏在悬停里；白板多了之后描述和时间信息密度偏低

方案 B

胶片 · 一整张纸，每个白板一条页带

把「一块白板有很多页」直接摆出来。整块内容区是一张纸，每个白板占一条：左边标题、描述和统计，右边是全部页的横向胶片（页码 + 页名 + 元素数），点哪页就直接进哪页；上次停留的页（activeWhiteBoardContentId）会标出来。页多时带子左右渐隐，悬停出现翻页按钮；悬停时末尾出现「＋ 新页」，不用进白板就能加页。条与条之间只用留白分隔，不画线。

✓ 多页结构一目了然，直达某一页只要一次点击；一张纸，没有碎卡片 ✗ 纵向更长（一屏 4–5 个白板）；单页白板那一条右边比较空；不展示封面

方案 C

预览台 · 目录 + 大预览，同一张纸

像 Finder 的预览或 Keynote 的文稿选择器。左边是按时间分组的紧凑目录（今天 / 近 7 天 / 近 30 天 / 更早，按名称排序时不分组），右边是选中白板的大预览：16:9 大图、页带、更新 / 创建时间、演示序列数，以及元素构成（卡片 8 · 图形 6 · 手绘 5 …）。全键盘操作：↑↓ 选白板，←→ 翻页，↵ 打开；双击目录行也能直接打开。

✓ 信息最全（元素构成、演示）；键盘效率最高；扫一眼很多白板也不累 ✗ 每次只能大看一个；有「左目录右详情」的主从感，和「页内不再放第二条侧栏」的偏好有张力（这里目录与预览在同一张纸上，不另起面板）

三个方案都修掉的 legacy 问题

  • 悬浮球：新建移到工具栏右上角的主按钮「新建白板」，弹窗只填标题和可选描述，「创建并打开」直接进白板；
  • 占位图：CDN 默认图和五色随机描边退役。没设封面就用第一页的画布缩略图，空白板显示「空白画布」；
  • 信息：「发表于 + 创建时间」改为页数、元素数和相对更新时间（悬停看完整时间），有演示序列的标出来，菜单里可以「从头演示」；
  • 菜单：悬停弹出的 antd Dropdown 改为点「更多」或右键打开的 Menu：打开 / 在新窗口打开（Electron 专属）/ 从头演示 / 编辑信息 / 设置或更换封面 / 移除封面 / 删除；
  • 删除：确认弹窗里写明影响范围（「4 页、共 30 个元素会一起删除」），不再只问「确定删除该白板？」；
  • 排序：Segmented「最近更新 / 创建时间 / 名称」，默认最近更新（legacy 按数据库顺序）；
  • 视觉：tau token，悬停件都占固定槽位、原位淡入，不会顶开布局；缩略图底是点阵画布纸，明暗两套主题都有。

可以混搭的部件

  • A 的悬停扫页可以放进 C 的目录缩略图，也可以放进项目页里的白板条目；
  • B 的「＋ 新页」和「上次停留」可以搬到 C 的预览页带里；
  • C 的元素构成可以作为 A 卡片的悬停提示；
  • C 的时间分组（今天 / 近 7 天 …）可以给 A 的网格或 B 的纸面加小节题。

待你拍板的几件事

  • 封面：有了真实画布缩略图后，「自定义封面」还要保留吗？（B 已经不展示封面了。）保留的话，是否改为「选某一页作封面」，而不是上传图片？
  • tags：WhiteBoard.tags 字段存在，但 legacy 没有任何 UI。三个方案都没做标签筛选，是直接退役，还是像日记那样挂到侧栏？
  • 页内搜索：参照项目页 D-024 的口径，三个方案都没放搜索框（语义检索走全局 ⌘K）。白板多了之后要不要加标题过滤？
  • 被引用：项目条目可以引用白板（white_board_content_id）。删除确认要不要额外提示「被 N 个项目引用」？这需要主进程补一个查询。
  • 缩略图生成：mock 在渲染层实时画。真实数据里元素多了（图片、网页、视频），更稳的做法是保存时由主进程生成一个轻量摘要，还是直接复用画布的「导出图片」离屏渲染再缓存？
