图片 · 组件 UI 与编辑器交互升级

两部分：① 组件 UI——图片本身的加载 / 失败 / 上传 / 说明 / 外观，以及全屏预览（灯箱），编辑与只读都受益；② 编辑器交互——选中、工具条、缩放、裁剪编辑。需要选的地方各给 A / B 两个方向，末尾是与方向无关的通用细节。标 ▶ 的都可以直接点、拖、用键盘。

PART 1组件 UI

图片本身怎么呈现。这一部分大多是「补齐与规范」，只有灯箱需要选方向。

1.1状态与外观（统一方案）

首次加载成功后把原图宽高写进节点（新增 naturalWidth / naturalHeight），之后每次打开都能按真实比例预留位置，骨架淡出、图片淡入，正文不跳。

外观预设改用主题尺度
圆角对齐 rounded-tau（8 / 12 / 16），阴影对齐 shadow-card / lift / float——跟随主题明暗，不再写死 rgba。菜单里用缩略样片选择，而不是「小圆角 / 中阴影」这类文字。

1.2全屏预览（灯箱）▶

两者共同能力：滚轮 / 触控板缩放、放大后拖动平移、双击在「适应」与「200%」间切换、←→ 切换、+−0 缩放、Esc 关闭（经浮层仲裁），点图片本身不再关闭。点一下灯箱让它获得焦点再试键盘。

A 暗房
深色全屏，照片最出彩；顶栏张数 + 文件名 + 缩放与操作，底部缩略条（文档里的所有图片）。
B 纸面
主题纸色 + 模糊透出文档，右侧信息栏（说明、尺寸、格式、操作、缩略图）；和应用其他浮层同一语言。
  • A：看图体验最好，适合截图 / 照片类笔记；代价是与应用浅色主题反差大（但灯箱本来就是「离开页面」的时刻）。
  • B：更像应用的一部分，信息更全（尺寸、格式、原始路径）；代价是图片可视面积小约 25%，浅色纸底上看深色截图对比弱。
PART 2编辑器内的图片交互

共同原则：悬停不出任何控件（只有指针变化）；单击选中、双击预览；控件只在选中后出现，且不叠在图片上；每个按钮都有名字（文字或悬停提示 + 快捷键）。

2.1选中与工具条 ▶

点图片选中，试试工具条、「⋯」菜单、拖动四角 / 两侧缩放（靠近 50% / 75% / 100% 会吸附）、点下方说明直接编辑；双击跳到灯箱示例。

A 上方浮条
与视频块同款：选中后浮在图片上方，主操作带文字（裁剪 / AI 编辑），其余进「⋯」。说明就地写在图片下方。
B 下方停靠条
工具条停靠在图片下方、与说明输入合为一行：左边写说明，右边是图标操作。控件永远不遮图片，也不越过上一段正文。
  • A：和视频块一致（D-076 的属性条），用户学一次到处通用；主操作有文字、一眼能懂；代价是浮条压在上一段正文上方（文档顶部第一张图时翻到下方）。
  • B：说明与操作同一行，「给图片写说明」变成显眼的主动作；不遮任何内容；代价是和视频块的形态不一致，选中时图片下方多出一行，正文会下移约 44px（取消选中复位）。

2.2裁剪编辑（完全重写）▶

两者共同的数据策略：原图永远保留（url），裁剪参数记在节点（cropTransform），导出一张结果图给显示和导出链路用（previewUrl）——下游（博客、PDF、公众号导出）不需要改；按原格式输出（PNG 保持 PNG，不再一律 JPEG 丢透明）；再次裁剪从原图开始并恢复上次的框。

A 就地裁剪
不开弹窗，图片块原地进入裁剪态：框外压暗，拖八个把手或拖框移动；上方同位置换成裁剪条。Enter 完成、Esc 取消。
B 全屏编辑器
像相册的编辑：深色全屏，拖框裁剪、滚轮放大图片；底部拨盘微调角度（±45°，双击归零），比例、旋转、翻转一行排开。
  • A：最轻、所见即所得（直接在文档宽度里看裁完的效果），大多数场景是「切掉截图多余的边」，A 最快；代价是没有角度微调，大图细裁时画面较小。
  • B：能力最全（拉直歪照、放大细裁），操作手感像手机相册；代价是离开文档语境，简单的切边也要进出一次全屏。
