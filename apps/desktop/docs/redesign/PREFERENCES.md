# 偏好沉淀（PREFERENCES）

> 这份文档是"你的口味"的结构化沉淀：后续每一页 UI 设计动笔前先读它，评审后往里追加。
> 条目格式：**偏好/反偏好 · 场景 · 正例/反例 · 一句话理由**。宁可琐碎，不可丢失。
> 标注 ⭐ 的是从移动端重构与本次裁决推导的初始偏好，尚未逐条确认。

---

## 视觉

- ⭐ 喜欢**有个人特色的设计语言**，讨厌"一坨 antd"式的通用后台脸（反例：现状桌面端全部页面）。
- ⭐ 喜欢移动端"杏子 Bento"的**暖调纸感**：奶油纸底、可可棕墨色、陶土橙 accent、六组粉彩语义色、噪点纹理（正例：`apps/mobile/src/styles.css` apricot 主题）。
- ⭐ 认可"中性表面 + 单一 accent + 色彩只表意"的原则（现状 `theme-colors.css` 的设计注释，Raycast/Linear 谱系）。
- ⭐ **讨厌背历史包袱**（2026-09-14 裁决）：token 体系宁可彻底换新（旧 `--th-*` 不继承，旧页面样式失效也无所谓，反正每页都会完全重写）。反例：为省编辑器桥接成本而沿用旧前缀的思路被明确否决。
- ⭐ **讨厌横线切割**（2026-09-14，针对 A 初版的原话"太硬了，到处都是横线，切割得十分分明，不够柔和"）：分组靠底色容器与留白，不靠 border 分隔线；正例见 `direction-a-soft.html`（主布局零 border-bottom）。
- ⭐ **讨厌浪费桌面宽度**：宽屏下内容区要放开（窄 max-width 只允许出现在正文阅读列），网格多列利用横向空间；详情页用双栏（正文+信息栏）而非单窄列。
- ⭐ **首页不能空洞**：要有实质内容量（行动块+内容流+收集箱速览），不是一句问候加三个按钮；同时讨厌仪表盘式大数字堆砌——用行式数据与内容流填充。
- ⭐ **排版要柔和自然**：硬切/跳变是负样本（侧栏收起必须平滑过渡且标题栏不跳）；改进方向宁可直接重写也不在旧版上缝补。
- ⭐ **不造假数据**（2026-09-14）：模块清单按真实信息架构来（不发明"收集箱"这类不存在的模块）；数据未接线就显示空态，不用假数据撑演示。
- ⭐ **融合优先于分块**：侧栏/标题栏/内容/状态栏必须是一体感（同底色贯通、无横条截断、无缝隙），"贴上去的板子"是负样本。
- ⭐ **对"糊成一坨的米黄"零容忍**（2026-09-17，样板间 v6 动因）：暖纸底上如果所有层都是同一色相的近邻亮度（page / surface / group 三档挤在一起），层级就塌了——卡片、分组底、空态行全部读不出来（反例：v5 样板间的空态行与 Loading 演示底）。偏好"纸 + 墨"两个锚点拉开，而不是在同一色相里堆三四层微差。
- ⭐ **讨厌"工程 README 脸"**（2026-09-17）：11px uppercase + 大字距的小节题（`状态矩阵 · STATES`）在中英混排里只有英文受影响，产出的是一股文档工具味。正例：中文 semibold 主 + 英文 mono 副，靠字重与色阶分层。
- ⭐ **表面阶梯要单调有序、档间可辨**（2026-09-17，D-006）：底色 token 被夹在两个相邻档中间就一定是死档（反例：`bg-group` 夹在 page 与 surface 之间，对两侧都只有 1.06，怎么用都读不出来——下沉后仍被嫌脏，已于 D-034 整体退役）。判断标准不看"设计意图"，看实测对比度：相邻档 ≥1.10 才算一档。
- ⭐ **说明与示例上下排布，不做左右两列**（2026-09-17，样板间状态矩阵裁决）：左右两列里说明折行行数不一、标本高低参差，对齐读起来杂乱——「标签+说明」在上、示例在下的纵向从属关系更规整（正例：样板间 MatrixRow；反例：此前 280px 标签列 + 右侧标本区的两列 grid）。
- ⭐ **样板间只写"看得见、点得着"的组件信息**（2026-09-17，原话"样板间就是用来看组件的各个状态和写法，看组件写的对不对，样式对不对，不是加一些这种乱七八糟的东西的"）：档案页文案只回答两件事——组件长什么样（状态/样式取值）、怎么用（API/交互）；判断标准是**内容能否在本页靠眼睛或交互验证**。决策痕迹（裁决日期、"2026-09-17 裁决"这类过程记录、`D-0XX`/`§` 章节引用、M0/M1 里程碑与"明确不做"清单）、运行环境元数据（端口、纯浏览器入口）、z-index 台账、测试守护链都不算——它们归 DECISIONS.md 与 03 指南。反例：页脚「端口 6199（纯浏览器，不依赖客户端）· 层级 page → surface → 展品」、IconButton 档案「对照：button（Button 基础件待 §9 任务 2）」、Select 档案整段「表单控件家族口径（2026-09-17 裁决）…M0 明确不做：多选」。
- ⭐ **讨厌碎卡片漏底**（2026-09-24，待办页 B 议程流评审原话"卡片感觉零零碎碎的，然后是不是漏出背景，感觉不是很好看"）：同一屏里多张小 surface 卡（每个日期段一张、右栏每块一张）之间露出 page 底色，读起来零碎、没有整体感；分组应在**同一块大平面内**靠留白与段头完成，而不是每组各自成卡。反例：待办 mockup B 原版（6 张日期段卡 + 3 张右栏卡）。
- ⭐ **讨厌米灰「分组底」填充**（2026-09-24，原话"这个不好看的 token，我特别想将其删掉"）：Tag、面板空态、分段控件轨道、工具条上的 `bg-group` 灰米色块观感脏且处处复现；层次改靠描边（line-1）与透明叠层（bg-hover），不再引入介于 page 与 surface 之间的实底档。
- ⭐ **内容区背景别太深**（2026-09-29，PDF 阅读页评审）：承载纸白内容（PDF 页、画布）的阅读区不用 sunken 这类深凹底，深底会把纸白页面衬得刺眼、整屏发闷；默认和纸同色，页面只靠投影和细边区分，确需分层也只用比 sunken 浅得多的一档。反例：mockups/pdf-detail 初版 `.rd { background: var(--sunken) }`。
- ⭐ **批注不占阅读宽度，查找另给入口**（2026-09-29，PDF 阅读页边注评审原话「标注就始终按照窄的那种形式，显示在页内，hover 显示内容，这样不占据空间，又能看到标注内容，然后在侧边栏也始终存在标注这一列……方便查找跳转」）：附着在正文上的批注 / 笔记只在页边留一枚小标记，悬停浮出内容、点击钉住，不开常驻边注栏挤窄正文；「浏览全部批注、跳转」交给侧栏的列表页签。反例：mockups/pdf-detail 方案 B 初版 250px 边注栏。
- ⭐ **「有特色」≠ 加颜色，要用主题语言**（2026-09-24，设置重设计二轮原话"太花里胡哨了，我说 UI 不是乱加配色，要用我们的主题语言"）：反例是按分区硬配六组粉彩（导航徽标 / 页头渐变 / 随分区变色的氛围光）、渐变主按钮、700 字重，以及给账号卡配品牌色 logo。正例是「发布」页的语言：纸色加 surface 两层、面板靠 shadow-card 不描边、图标中性墨色、颜色只给 accent 与语义状态（状态点、失败数字），数据类图例才用 tag 色。特色要从排版、层次与组织里来，不从调色板里来。
- ⭐ **无图内容用派生色兜底，不用占位图**（2026-09-19，文章页评审原话"这个特别好，可以保持"）：内容没有 banner 时以 id 派生的粉彩渐变封面兜底，同一篇永远同一色、相邻内容错开取色；无图封面叠首段文字也要**有彩**——白色/米色寡淡封面是负样本（二轮反馈原话"要么白色，要么偏黄，不应该随机有自己的特色吗"）；反例：legacy 文章页的 CDN 默认占位图（离线破图、千篇一律）。

- ⭐ **沉浸式专注界面要居中**（2026-09-24，闪卡复习评审原话"沉浸式，但是得居中吧"）：侧栏收起后只剩一个主体（题卡 + 评分条）时，主体在剩余空间里水平、垂直都居中，不贴顶；内容超高时退化为顶对齐滚动。反例：mockups/flashcards 方案 A 初版题卡贴在顶部 3vh 处。

- ⭐ **月历用整块大面板，不要瓷砖分格**（2026-09-24，日程页评审）：月视图格子放在一张 surface 大卡片里、格内细线分隔；每格一块小卡片、间隙透出纸色的「瓷砖」形态被否（正例：mockups/calendar 方案 A / C 月视图）。
- ⭐ **切换视图后不能留大片空白**（2026-09-24，番茄专注方案 C 评审原话"我选择 7 天的时候，底下一大片空白，从视觉上看觉得不是很舒服"）：同一个面板在不同数据量（7 / 14 / 30 天）下都要撑满——行高随可用高度伸缩（数据少时变成更可读的放大形态），并用和主体同轴的合计 / 分布行收底；不用固定行高再把剩下的留给空白。

- ⭐ **沉浸 = 一整张纸，不要「左卡右栏」**（2026-09-25，日记页二轮原话"A 是左边是卡片，右边不是，感觉不够沉浸"）：以阅读 / 书写为主的页面，主体做成撑满内容区的一张 surface 大纸，辅助信息不另起纸面栏——拆进侧栏子项、工具栏浮层或纸缘刻度（正例：mockups/diary 方案 D；反例：方案 A 的纸面右栏）。
- ⭐ **回顾类内容是入口，不占主位，但要露一句**（2026-09-25，日记页三轮原话"不应该放到最上面，感觉只是一个入口……还是要一些简略信息，否则没有点开的欲望"）：那年今日这类「顺便看看」的内容，给一行带首句的预告（放在与其动作相关的位置——回应当年的自己 → 输入条上方），点开再用抽屉瞥一眼；不织进流顶、不做右栏列表、也不只放一个无信息的图标。

- ⭐ **页内不再放第二条侧栏**（2026-09-25，协作页方案 A 评审原话"A 的侧边栏和左侧的全局侧边栏，有两个，感觉有点怪"）：页面自己的条目目录与全局侧栏并排会读成两条侧栏；少量条目（个位数）优先嵌进全局侧栏对应入口之下作子项，页面只放主体内容（正例：协作页 A3 侧栏嵌套；反例：mockups/collaboration 方案 A 一轮的 276px 会话目录）。
- ⭐ **页内二级导航不能和全局侧栏同层**（2026-09-25，问题页 A 评审原话"左侧的组列表和全局的侧边栏，有两个侧边栏，这块感觉没有隔离开"）：页面自己的分组 / 筛选列如果也落在纸色底上、用和壳层侧栏一样的导航项样式，读起来就是两条并排侧栏。页内分组放进内容板里，做成 chips 行（正例：mockups/questions A2）；反例：问题页 A 初版纸面分组列。

- ⭐ **列表缩略图要是真内容，不是占位图**（2026-09-25，白板列表评审）：有真实内容可画时（白板画布），缩略图直接取自内容本身（复用导出图片），用户自定义封面优先；CDN 默认图、随机色描边这类「看不出是哪一个」的占位是负样本。
- ⭐ **标签的筛选入口统一放侧栏，卡片上不重复显示**（2026-09-25，白板列表二轮裁决「按侧边栏做」「卡片上不需要」）：页面的标签范围做成全局侧栏入口下的子项（日记、白板同款），卡片保持干净，不再挂标签 chip。

- ⭐ **同一批数据给「好看」和「好查」两种排布，而不是二选一**（2026-09-26，微信读书页「A 的书架 + B 的列表」）：以封面为主的书架是默认形态，右上角切「封面 / 列表」，列表只做列头排序；不为此引入保存视图这类数据库重能力。
- ⭐ **第三方数据保留原样式**（同上，「还原划线样式」）：用户在源平台做的标记（划线颜色、下划线 / 马克笔 / 波浪线）属于内容，照原样呈现，不为求统一改成中性引文。
- ⭐ **少量筛选维度可以放页面顶部 chips**（同上，书架分类裁决为「顶部」）：「标签入侧栏」不是铁律——分类数量少、只在本页有意义时，放在内容纸顶部的 chips 行就够了。
- ⭐ **管理页与编辑页也用「一整张纸」**（2026-09-26，Skill 页评审原话"希望和微信读书一样一张大卡片，以及在编辑的时候也是在大卡片里面"）：卡片库放进一张 surface 大纸（页头与筛选固定在纸顶、内容纸内滚动），纸内卡片改细描边不再叠阴影；编辑页同样一张纸，文件树是纸内透明左栏、开关在面包屑，元信息做成文档式标题 + 描述块，不套表单框。反例：Skill 页初版（卡片直接铺在页面底色上、编辑页头部是描边表单框）。

- ⭐ **mockup 里的纸面结构要原样落地**（2026-09-26，微信读书页实现评审原话"mockup 里面的 B 方案是整块都是大的卡片底色，现在没有了"）：定稿样板间是「整页一张 surface 纸、内容在纸内」，实现时不能退化成「内容直接铺在页面底色上、零散小卡片漏底」——列表 / 书架类页面同样适用「一整张纸」。

## 交互

- ⭐ 喜欢声明式 API：defineXxx 一个文件声明全部（"我觉得是很高级的设计"——原话）。**该哲学要贯穿一切子系统**：不止页面（definePage），主题也要 defineTheme 化（2026-09-14 用户主动提出，已落地）。
- ⭐ 喜欢返回/关闭的统一仲裁（移动端 LIFO + 退场缓冲那套），讨厌各处自行监听返回。
- ⭐ 键盘效率重要：命令面板直达、快捷键；高级能力可发现但不干扰高频输入（2026-09-14 你明确要求桌面补齐后退/前进按钮——桌面惯例要全，别拿移动端简化逻辑搪塞）。
- ⭐ **讨厌右下角悬浮球（FAB）**（2026-09-19，文章页评审）：新建等主动作进工具栏右上角（新建为主按钮、导入为图标按钮），不占悬浮层；反例：legacy 文章页的 hover FAB dock。
- ⭐ **列表加载用无限滚动**（2026-09-19，文章页评审）：触底自动加载（IntersectionObserver + 预加载阈值），不要手动"加载更多"按钮，也不要分页器。
- ⭐ **悬停不能改变元素尺寸**（2026-09-24，番茄专注方案 C 评审原话"hover 到预设的时候会把数字变为开始的 icon，但是会导致宽度跳变，我还蛮不喜欢的"）：悬停显隐的附属件（快捷键提示 ⇄ 播放图标、操作按钮）必须占固定槽位、原位交叉淡入或绝对定位叠放，不得用 display 切换或宽度过渡顶开布局。反例：mockups/pomodoro 方案 C 初版控制条 chip（kbd display:none + 图标 width 0→12）。
- ⭐ **悬停 / 激活不要夸张的位移和阴影**（2026-09-29，PDF 阅读页评审）：卡片、批注、列表项悬停或激活时，只做轻微的底色 / 描边 / 文字色变化，最多加深一档投影；不上浮（translateY）、不放大、不换成大面积浮起阴影。
- ⭐ **悬浮控件不要半透明叠在内容上**（2026-09-30，PDF 阅读页 HUD「滚动的时候会变透明，然后过了一会儿就恢复」，选「不变淡」）：底部 HUD 这类悬浮条常驻不透明；半透明时按钮和底下的正文混在一起，看着像渲染出错。要让位就完全收起，不做「淡到一半」。
- ⭐ **平台能力分层渲染**（2026-09-19，文章页评审）：「窗口打开」等 Electron 专属操作只在 Electron 渲染（现有 `isElectron` 判断），Web 端不渲染入口而非禁用置灰。

- ⭐ **界面上已经看得见的状态，不要再用文案复述**（2026-09-25，日记输入条原话"右下角根本不需要这个文案，因为在输入框已经有标签了，用户看的到"）：频道预置的标签已作为 chip 出现在输入条里，就不再加「会自动带上「X」」提示——复述的文案既冗余，又会在用户删掉 chip 后变成错的。

- ⭐ **输入框常态与聚焦态同底色，不用「凹槽」深底**（2026-09-25，日记输入条原话"输入框的背景太深了，我觉得聚焦的那个背景就是对的"）：纸面上的输入框常态就用 surface 底 + 1px 细线框出，聚焦只把线换成 accent + 焦点环；不用比纸更深的 page 色做「填充式输入框」，聚焦时底色跳变。

- ⭐ **不给已经自动发生的事再加按钮**（2026-09-25，日记就地编辑原话"右上角的完成是不是不需要，因为我记得是实时保存的……more 里面的编辑也不需要，因为一点击就会进入编辑"）：实时保存的编辑不设「完成 / 保存」按钮（退出靠失焦 / Esc / ⌘↵）；点击即可进入的状态不在菜单里重复放入口。
- ⭐ **阅读 ⇄ 编辑切换必须无感**（同上，"点击进入聚焦的时候，整个会闪一下，以及布局还会有抖动"）：切换时正文位置逐像素不动、不出现加载态；需要异步准备的编辑器，就绪前继续显示阅读态，光标落在点击处。

- ⭐ **多页切换用底部页签栏（XMind 式），只有一页时不显示、悬停才浮出**（2026-09-25，白板详情评审原话"类似于 XMind，底部的那种标签页""只有一页默认是不显示的，hover 的时候才显示"）：多个同级画布 / 工作表的切换放在内容纸面下缘的一整条页签栏，而不是浮动小条、侧栏子项或翻页器；只有一项时不占位置。
- ⭐ **能不做的形态就不做**（同上，原话"独立白板就一个就行了，不搞那么复杂"）：边缘形态（不属于任何白板的单页）保持最简，不为它补多页能力或额外控件。

- ⭐ **属性跟着对象走**（2026-09-25，白板画布换皮选方案 A）：画布类编辑器的属性控件做成浮在选中元素上方的小条（放不下翻到下方、拖动时隐去），不用固定在画布边缘的竖条，也不用常驻的检查器大面板——离操作对象最近、不和右侧抽屉抢位置。
- ⭐ **换皮不动用户内容**（同上，「元素默认样式单独再议」）：界面 chrome（工具条、选中框、控制点、网格、菜单）跟主题走；用户画出来的内容（元素默认填充 / 描边 / 箭头色 / 导图主题）不随换皮顺带改，要改单独立项。
- ⭐ **辅助面板停靠进纸面，开关放面包屑**（2026-09-25，白板元素树原话"我不喜欢这种浮动的，入口也不要左上角一个悬浮按钮，就是侧边这种……在面包屑那里和项目列表一样注册一个打开关闭的开关"）：目录 / 大纲类面板做成内容纸面里的左栏（同项目文档树），不做盖在内容上的浮层；开关统一钉在标题栏面包屑最前，不在画布里放悬浮按钮。
- ⭐ **列表行要能认出是哪一个**（同上，"太素了……至少需要图标区分"，评审选 A 中性图标）：行名取内容（文本首段、图形里的字），不要一屏同名的类型名；类型靠中性图标区分就够，不按类型上色。
- ⭐ **高频工具的位置不折腾**（同上，工具条「现状，可以」）：已形成肌肉记忆的入口（画布顶部居中工具条）换皮时保留位置，只换外观与分组；重复的入口可以合并（演示序列并入右下「演示」）。

- ⭐ **本机设置就地改、只留真正需要的**（2026-09-25，协作页裁决）：协作设置不开弹窗，在协作页工具栏就地改昵称；服务器地址不对用户暴露、不可修改，身份导入 / 导出不提供——不把部署细节与运维能力摆给使用者。
- ⭐ **喜欢把过程留下来**（2026-09-25，问题页评审原话"探究轨迹和探究过程的一些数据记录我觉得非常好"）：学习类功能除了结果，还要记录过程——系统自动记事实（状态变化、关联、新建），用户手动补思考（「记一笔」），两者合在一条时间线里；自动事件视觉上轻、手动记录重。
- ⭐ **快速收集走命令面板**（2026-09-25）：不为单个功能开独立小窗、也不另占全局快捷键，统一在 Ctrl+K 命令面板里加动作命令（反例：legacy 问题小窗 / 待办小窗）。
- ⭐ **高频辅助功能要能与任何页面并排，空间靠自适应换，不靠砍入口**（2026-09-25，AI 对话评审）：右侧 AI 快捷对话「使用频率还蛮高」，左侧改侧栏后也要保留右侧停靠形态（入口 A），不退化为遮挡内容的浮窗或需要先改导航框架的分屏；窗口窄时先自动收起左栏、再退化为覆盖浮层（正例：mockups/chat 入口 A；反例：入口 B 浮窗遮住右侧 440px）。
- ⭐ **迁移先接功能、后换皮**（2026-09-25，AI 对话原话「第一期我们不做样式的改造，先用原来的组件等把功能接进来」）：功能面大的模块分期——一期新写外壳 / 导航 / 布局，内部原样挂 legacy 组件；主题化与组件替换逐步进行。
- ⭐ **对话里过程信息要轻，结果才是主角**（2026-09-25，AI 对话二期按原型落地，待评审确认）：思考过程、工具调用是一行淡墨折叠（图标 + 名称 + 耗时），失败才默认展开；不做每个工具一张大卡片、不用彩色状态徽章。反例：legacy 工具调用卡（灰底描边卡 + 彩色实底 StatusBadge + ▼▶ 字符箭头）。
- ⭐ **可以参考外部产品的结构，但皮要换成我们的语言**（2026-09-25，对话输入框二轮原话「可以参考这样的设计，但是符合我们的设计语言，并且更加美观」）：借结构（左下一个 ＋ 收拢低频入口、右下 用量 · 模型 · 强度 · 发送、向上展开的同宽面板 + 键位提示页脚），不借皮（彩色应用图标、深灰实底、描边分隔线都不要）；次要入口宁可收进一个面板，也不要让工具行在窄栏里折成两行。

- ⭐ **大产物要大画面，对话退到旁边**（2026-09-26，块预览选方案 B）：模型生成的演示页 / 导图 / 图表打开后占正文，对话收进右侧停靠栏继续追问；不在一张纸里左右挤两半，也不用模态盖住整个窗口（看的时候还要能接着改）。
- ⭐ **同一个产物改了几轮要能前后翻**（同上，「要版本」）：同一会话里同名同类型的生成物视为一个产物的多个版本，而不是一串互不相干的卡片。
- ⭐ **AI 生成是后台任务，过程看得见**（2026-09-26，Vibe Learning 生成改造原话「点击配置好之后就会关掉，侧边栏就会有这个条目……点进入可以看到大模型的执行过程」「数字增在就在工作」）：配置完即关弹窗、条目立刻出现并标「生成中」，离开页面也不停；点进去看推理、工具调用、输出中间态，能直接渲染的产物（文档、导图）就看流式内容，不能的也要有持续增长的字数 / token 计数，而不是一句「正在生成…」加转圈。完成即落库，不留「预览 → 保存」这一步。

- ⭐ **做不到持久化的能力就不做**（2026-09-26，微信读书笔记）：源头接口只读时，本地不假装可编辑（legacy 的改色 / 写想法关掉就丢，属于负样本），直接做成只读，只留复制这类不改数据的操作。
