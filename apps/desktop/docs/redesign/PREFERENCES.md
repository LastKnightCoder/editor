# 偏好沉淀（PREFERENCES）

> 这份文档是"你的口味"的结构化沉淀：后续每一页 UI 设计动笔前先读它，评审后往里追加。
> 条目格式：**偏好/反偏好 · 场景 · 正例/反例 · 一句话理由**。宁可琐碎，不可丢失。
> 标注 ⭐ 的是从移动端重构与本次裁决推导的初始偏好，尚未逐条确认。

---

## 视觉

- ⭐ 喜欢**有个人特色的设计语言**，讨厌"一坨 antd"式的通用后台脸（反例：现状桌面端全部页面）。
- ⭐ 喜欢移动端"杏子 Bento"的**暖调纸感**：奶油纸底、可可棕墨色、陶土橙 accent、六组粉彩语义色、噪点纹理（正例：`apps/mobile/src/styles.css` apricot 主题）。
- ⭐ 认可"中性表面 + 单一 accent + 色彩只表意"的原则（现状 `theme-colors.css` 的设计注释，Raycast/Linear 谱系）。
- ⭐ **讨厌背历史包袱**（2026-09-14 裁决）：token 体系宁可彻底换新（旧 `--th-*` 不继承，旧页面样式失效也无所谓，反正每页都会完全重写）。反例：为省编辑器桥接成本而沿用旧前缀的思路被明确否决。
- ⭐ **讨厌横线切割**（2026-09-14，针对 A 初版的原话"太硬了，到处都是横线，切割得十分分明，不够柔和"）：分组靠底色容器与留白，不靠 border 分隔线；正例见 `direction-a-soft.html`（主布局零 border-bottom）。
- ⭐ **讨厌浪费桌面宽度**：宽屏下内容区要放开（窄 max-width 只允许出现在正文阅读列），网格多列利用横向空间；详情页用双栏（正文+信息栏）而非单窄列。
- ⭐ **首页不能空洞**：要有实质内容量（行动块+内容流+收集箱速览），不是一句问候加三个按钮；同时讨厌仪表盘式大数字堆砌——用行式数据与内容流填充。
- ⭐ **排版要柔和自然**：硬切/跳变是负样本（侧栏收起必须平滑过渡且标题栏不跳）；改进方向宁可直接重写也不在旧版上缝补。
- ⭐ **不造假数据**（2026-09-14）：模块清单按真实信息架构来（不发明"收集箱"这类不存在的模块）；数据未接线就显示空态，不用假数据撑演示。
- ⭐ **融合优先于分块**：侧栏/标题栏/内容/状态栏必须是一体感（同底色贯通、无横条截断、无缝隙），"贴上去的板子"是负样本。
- ⭐ **对"糊成一坨的米黄"零容忍**（2026-09-17，样板间 v6 动因）：暖纸底上如果所有层都是同一色相的近邻亮度（page / surface / group 三档挤在一起），层级就塌了——卡片、分组底、空态行全部读不出来（反例：v5 样板间的空态行与 Loading 演示底）。偏好"纸 + 墨"两个锚点拉开，而不是在同一色相里堆三四层微差。
- ⭐ **讨厌"工程 README 脸"**（2026-09-17）：11px uppercase + 大字距的小节题（`状态矩阵 · STATES`）在中英混排里只有英文受影响，产出的是一股文档工具味。正例：中文 semibold 主 + 英文 mono 副，靠字重与色阶分层。
- ⭐ **表面阶梯要单调有序、档间可辨**（2026-09-17，D-006）：底色 token 被夹在两个相邻档中间就一定是死档（反例：`bg-group` 夹在 page 与 surface 之间，对两侧都只有 1.06，怎么用都读不出来）。判断标准不看"设计意图"，看实测对比度：相邻档 ≥1.10 才算一档。
- ⭐ **说明与示例上下排布，不做左右两列**（2026-09-17，样板间状态矩阵裁决）：左右两列里说明折行行数不一、标本高低参差，对齐读起来杂乱——「标签+说明」在上、示例在下的纵向从属关系更规整（正例：样板间 MatrixRow；反例：此前 280px 标签列 + 右侧标本区的两列 grid）。
- ⭐ **样板间只写"看得见、点得着"的组件信息**（2026-09-17，原话"样板间就是用来看组件的各个状态和写法，看组件写的对不对，样式对不对，不是加一些这种乱七八糟的东西的"）：档案页文案只回答两件事——组件长什么样（状态/样式取值）、怎么用（API/交互）；判断标准是**内容能否在本页靠眼睛或交互验证**。决策痕迹（裁决日期、"2026-09-17 裁决"这类过程记录、`D-0XX`/`§` 章节引用、M0/M1 里程碑与"明确不做"清单）、运行环境元数据（端口、纯浏览器入口）、z-index 台账、测试守护链都不算——它们归 DECISIONS.md 与 03 指南。反例：页脚「端口 6199（纯浏览器，不依赖客户端）· 层级 page → surface → 展品」、IconButton 档案「对照：button（Button 基础件待 §9 任务 2）」、Select 档案整段「表单控件家族口径（2026-09-17 裁决）…M0 明确不做：多选」。
- ⭐ **无图内容用派生色兜底，不用占位图**（2026-09-19，文章页评审原话"这个特别好，可以保持"）：内容没有 banner 时以 id 派生的粉彩渐变封面兜底，同一篇永远同一色、相邻内容错开取色；无图封面叠首段文字也要**有彩**——白色/米色寡淡封面是负样本（二轮反馈原话"要么白色，要么偏黄，不应该随机有自己的特色吗"）；反例：legacy 文章页的 CDN 默认占位图（离线破图、千篇一律）。

## 交互

- ⭐ 喜欢声明式 API：defineXxx 一个文件声明全部（"我觉得是很高级的设计"——原话）。**该哲学要贯穿一切子系统**：不止页面（definePage），主题也要 defineTheme 化（2026-09-14 用户主动提出，已落地）。
- ⭐ 喜欢返回/关闭的统一仲裁（移动端 LIFO + 退场缓冲那套），讨厌各处自行监听返回。
- ⭐ 键盘效率重要：命令面板直达、快捷键；高级能力可发现但不干扰高频输入（2026-09-14 你明确要求桌面补齐后退/前进按钮——桌面惯例要全，别拿移动端简化逻辑搪塞）。
- ⭐ **讨厌右下角悬浮球（FAB）**（2026-09-19，文章页评审）：新建等主动作进工具栏右上角（新建为主按钮、导入为图标按钮），不占悬浮层；反例：legacy 文章页的 hover FAB dock。
- ⭐ **列表加载用无限滚动**（2026-09-19，文章页评审）：触底自动加载（IntersectionObserver + 预加载阈值），不要手动"加载更多"按钮，也不要分页器。
- ⭐ **平台能力分层渲染**（2026-09-19，文章页评审）：「窗口打开」等 Electron 专属操作只在 Electron 渲染（现有 `isElectron` 判断），Web 端不渲染入口而非禁用置灰。
