## 2.5 主进程模块就绪（跨进程能力）

主进程能力定义在 `src-electron/main/module-init/module-config.ts`，按 `layer` 分三档：
IMMEDIATE（窗口显示前）/ BACKGROUND（窗口显示后并行）/ ON_DEMAND（需调用方拉起）。

**铁律：新增模块一律 `BACKGROUND`。** ON_DEMAND 的初始化靠「窗口类型 → 模块组」隐式拉起，
一旦入口变化就静默失效——2026-09-15 主窗口换新壳层后 39 个模块的 handler 从未注册，
表现为 `updater:check` 报 "No handler registered"（详见 DECISIONS.md D-014）。

确需按需加载时，必须同时在渲染端用 `ensureModule` / `withModule`
（`src/commands/module-init.ts`）接入兜底；`module-init/__tests__/module-layering.test.ts`
守护这条约定，未接兜底的 ON_DEMAND 模块会让测试失败并列出模块名。

注：`@/electron` 的 `invoke` 已内置启动竞态重试（遇 "No handler registered" 每 500ms 重试、
上限 5s，收到过成功响应即停止），它只覆盖「注册晚于调用」的窗口期，**不覆盖「从未注册」**。

## 3. 三大协议（照抄即用）

**新增页面**（如卡片库）：

```tsx
// features/cards/pages/cards.page.tsx —— 文件即注册，无需改任何登记表
const schema = createPageSchema({ keyword: paramOptional(paramString()) });
type CardsParams = typeof schema.type;

export default definePage({
  key: "cards", // 与 navigation.ts 的 key 一致即接管侧边栏入口
  match: "single", // 功能页用 single；详情页用 "params" + getId: p => `card-${p.cardId}`
  label: "卡片库",
  status: "new",
  params: schema.schema,
  component: CardsView, // 视图组件放 ../views/
});
```

导航：`navigator.push("cards", { keyword: "..." })`；视图内读当前 params 用 `usePage().state`（后续可加 usePageParams 语法糖）。
`match: "single"/"params"` 的去重由栈机承担：重复 push 同 key 同参 = no-op、异参 = 原位更新，调用侧不要再做"是否已激活"判断。

**新增页面数据**（features/<域>/queries.ts，照抄 features/home 的形状）：

```ts
export function useXxxSnapshot() {
  const query = useQuery({
    queryKey: ["<域>", "snapshot"],
    queryFn: fetchXxxSnapshot, // 并行 Promise.allSettled + 单项降级，整体不 reject
    staleTime: 60_000,
    refetchOnWindowFocus: true, // 全局默认是关，"今日"类数据按页面开启
  });
  return {
    data: query.data ?? null,
    loading: query.isPending,
    refresh: () => void query.refetch(),
  };
}
```

禁止手写 useEffect+useState 拉取；列表展示 N 条禁止为此全量拉大表（用渐进窗口凑满即停，或主进程聚合命令——参考最近编辑 14→30→90→365 天的实现）。

**新增主题**：`ui/theme/themes/<name>.theme.ts` 用 defineTheme 声明（tokens 全键强制，漏键编译不过），在 `themes.ts` import 之，**并同步在 `tokens.css` 补 `[data-theme="<key>"]` 数据块**（取值运行时由该块级联，`theme-parity.test.ts` 守护两处一致；codegen 落地后改为生成）。派生逻辑写在 tokens() 里。

**主题模式与切换（已落地，02 §2.4）**：`ui/theme/themeStore.ts` 持有 `mode`（主题 key 或 `"system"`，localStorage `tau-theme` 持久化）与 `resolved`（实际生效 key，system 时按 `prefers-color-scheme` 解析并实时跟随）；DOM 应用走 `theme.ts` 的 `applyThemeToDom`（深色同步 `.dark` 类，供编辑器包 dark: 变体）。入口：Titlebar 主题按钮循环 浅色→深色→跟随系统（icon 实时反映）；完整外观设置留 M5 设置中心。**三处手工同步点**：新增主题时 ① `themeStore.ts` 的 `ThemeMode` 联合、② `index.html` 首帧脚本的白名单/默认 key、③ `theme.ts` 的 `DEFAULT_LIGHT_KEY`/`DEFAULT_DARK_KEY`（system 解析用），codegen 落地后统一。深色主题用户的首帧防闪白由 `base.css` 的 `html { background: var(--tau-bg-page, …) }` 兜底。**对比度**：`theme-parity.test.ts` 已含 02 §2.5 指标的 WCAG 断言（ink-1 ≥7:1、ink-2/accent 文字 ≥4.5:1，遍历注册表全主题），codegen 门禁前的手工守护。

**颜色与尺度消费（D-013 Tailwind 优先）**：组件样式一律 Tailwind 工具类。颜色写语义类（`bg-page / bg-surface / bg-group / text-ink-1 / text-ink-2 / text-ink-3 / hover:bg-hover / bg-accent-soft / text-accent / bg-ok-soft / text-warn …`）；尺度写 tau 命名空间词（`text-tau-body / text-tau-meta / rounded-tau-sm|md|lg / shadow-card / shadow-float / ease-tau-out / font-tau / font-tau-mono`，词表见 02 规范 §3/§4）。**禁止**：裸色值、antd token、内联十六进制、新增手写 CSS 类（白名单见 §4）。数据驱动的动态值（进度宽度/格子高度）允许 inline style，但色值仍走语义类；一次性展示字号用 `text-[24px]` 类任意值；热力图色阶这类"主题 accent 定稿值的 alpha 派生"暂以 arbitrary 注明出处。跨域复用的视觉模式收口 `ui/primitives/`（Panel/IconButton…），不要在多域重复同一段类串。

## 4. UI 风格铁律（A2 校准结论，评审对照）

> **视觉基准与样式载体（D-013，2026-09-15 起）**：视觉基准 = `mockups/direction-a-soft.html`（A2 柔和版）+ `mockups/home-final.html`（今日页定稿），**降级为参考物**（浏览器打开对照截图），不再是导出源；调视觉直接改组件里的 Tailwind 类。样式载体 = **Tailwind v4 工具类优先**，组件 className 语义化、就地可读；跨域视觉模式抽 `ui/primitives/` 组件。CSS 仅保留四类白名单（逐例裁决、默认不许）：① `app/base.css` 的 `.app` 作用域 reset（不波及 /legacy）；② `@keyframes`（经 `tokens.css` 的 `--animate-*` 消费）；③ `tokens.css` 主题数据块（D-012）；④ Tailwind 表达不了的复杂伪元素/全局状态（现存唯一实例：home.css 的 edge-fade mask + page 根高度链）。原"模板类名 1:1 / 禁手改 shell.css / 先改模板再导出"工作流已废弃（导出脚本从未入库，不可复现）；shell.css/stats.css 已删除，约 90 个无消费者的预置模板类不迁移，将来做对应页面时用 Tailwind 语义类重写。

1. **融合骨架**：侧栏透明融于 bg-page、整高贯通窗口；标题栏/状态栏只属于右列；不出现横贯全宽的条。
2. **零横线**：分组靠底色容器（bg-surface 圆角面板 + shadow-card）与留白；禁止用 border 分隔区块（border 只允许 ≤2px 控件级细节，如勾选圈）。
3. **宽度利用**：内容区 max-w 1680 宽容器；窄列只允许出现在正文阅读列（~72ch）；详情页用双栏（正文+信息栏）。
4. **反馈语言**：hover = bg-hover 淡墨底；激活（侧栏）= 淡墨底 + 左缘 3px accent 竖标；浮起（卡片）= shadow-card，hover 轻抬升；按钮无描边。
5. **圆角**：面板/卡片 var(--tau-radius-lg)=16，控件 md=12，小元素 sm=8。
6. **数字** tabular-nums；字号体系以模板为准（25/14/13.5/12.5/11.5）。
7. **滚动条**：不出现系统滚动条——4px 细墨条仅在「活跃」时显形（hover 滚动容器或滚动中；停止 700ms 且鼠标不在时隐藏，移出窗口立即隐藏）。实现 = `base.css` 的 `.app` 作用域样式（`scrollbar-live` 类控制 thumb）+ `app/scrollbarAutoHide.ts` 事件委托（AppShell 初始化一次，全部内部滚动区自动生效）。两个坑别踩：① 禁止改回 `:hover` 伪类驱动——Chromium 滚动条伪元素不随 `:hover` 重算，显形后会冻结不消失；② 覆盖 main.less 的全局滚动条样式时必须同时清零 `box-shadow`/`-webkit-box-shadow`（不同属性名互不覆盖，只盖 background 会留下内阴影残影、看似常显）。

## 5. 交互规范（已定案）

- 导航：栈 + forward buffer（push 清空 forward）；`Alt+←/→` 后退/前进；`Esc`=后退（浮层接入后改为先关浮层）；根页 Esc 无操作。
- 键盘仲裁收口在框架层（PageProvider/Titlebar 的全局监听），业务代码禁止自行监听这些键；两处都已让位编辑上下文（输入框/文本域/contentEditable，`page/dom.ts`）与输入法组合（`e.isComposing`）。
- 栈操作为 action 式 reducer（连续导航由 React 串行归约，不丢更新）；注册表（pageMeta/组件 registry/defineTheme）重复注册策略统一为 dev 覆盖+warn（HMR 兼容）、prod 抛错（真冲突）。
- 后退/前进按钮：**禁用而非隐藏**（面包屑旁，Titlebar）。
- 侧栏：拖宽（180–340，持久化）+ 折叠（58px 图标列；折叠按钮同位镜像反转 `»↔«`；双击拖宽条也可折叠）；**导航组头可点击折叠收纳**（chevron 旋转 + grid-rows 过渡 + 折叠处显条目数，`shellStore.navSectionCollapsed` 持久化，方案来源 mockups/sidebar-responsive 方案二；图标列态无组头不受影响）；导航列表滚动带**边缘渐隐**（`base.css` 的 `.edge-fade-scroll` 通用类 + `useEdgeFade` hook；home-scroll 的 mask 协议已抽通用）；Mac 红绿灯占位在侧栏头部（`isMac` 条件渲染，真实窗口为系统控件让位）；Windows/Linux 三键 `isWinOrLinux` 条件渲染。
- 拖拽区（`app-region-drag`，Titlebar/侧栏头部）内的一切可交互元素必须加 `app-region-no-drag`——Electron 会吞掉 drag 区的鼠标事件（侧栏折叠按钮曾因此点击失效）；页面级加载态统一用 `ui/primitives/Loading`（Spinner 可单独行内用）。
- 保活：`<Activity>`（React 已升级 19.2.3，无降级路径），LRU 上限 12；
- 图标：**lucide-react**（线性，stroke 1.75，`navigation.ts` 直接引用 LucideIcon 组件）；多色图标用 **react-icons**（桌面已有依赖）；
- legacy 占位层：侧边栏 18 个真实模块可导航到占位页（对齐老版全部一级入口——VibeLearning 学习项目由「项目」详情承载不设入口；2026-09-16 补齐+重分组：工作台/知识/学习/AI/工具）；
- tsc 全绿。挂载：主窗口 `/` 默认重定向 `/shell`（旧主界面在 `/legacy`，与 legacy 并行，M1 时删除重定向）。

## 6. 如何迁移一个 legacy 模块（标准流程）

1. `features/<域>/pages/<key>.page.tsx` 新建（key 与 navigation.ts 一致——真实注册自动覆盖 legacy.tsx 的占位）；
2. 视图组件按 §4/§5 风格重写（参考样板间与 HomeView，**不参考旧页面写法**）；
3. 数据接 `queries.ts`（契约类型先行，未就绪的字段返回 null + 空态）；
4. 从 `page/legacy.tsx` 的 LEGACY_PAGES 删除该行；
5. DECISIONS.md 的 Page 迁移清单勾选该行。

## 7. 今日页数据（已全部接线，features/home/queries.ts）

数据契约见 types.ts；来源与降级策略：

- reviewDueCount ← `listFlashcardDecks()` Σ stats.dueCount；
- todos / todoRemainingCount ← `listTodoItemsByType("all")` 未完成（逾期 > 今日到期排序，取 3）；
- events ← `getEventsForDay(Date.now())`（排序：非全天在前、按 startTime）；
- recentEdits ← `getCardsByDateRange` + `getArticlesByDateRange`（渐进窗口 14→30→90→365 天，凑满 12 条即停；Slate 正文提文本截断）+ 文档/项目全量轻表按窗口过滤 + 最新日记，混排取 12；
- focus ← `summaryPomodoroToday()`；weekly 叠加本周聚合；
- todayStats/weekly/trend ← `getAllStatistic` 全量快照差分（口径见 `utils/statistic.ts` 的 diffSeries，与统计页共用）；
- heatmap ← `getCalendarHeatmap(今年)` → 全年每日操作数（GitHub 式，HomeHeatmap 自绘）。
  并行 `Promise.allSettled`，单项失败降级为空值并 console.warn，不阻塞整页。
  新增区块时：types.ts 加字段 → queries.ts 分项函数 → HomeView 渲染。
