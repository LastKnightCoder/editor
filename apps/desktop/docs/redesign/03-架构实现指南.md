## 2.5 主进程模块就绪（跨进程能力）

主进程能力定义在 `src-electron/main/module-init/module-config.ts`，按 `layer` 分三档：
IMMEDIATE（窗口显示前）/ BACKGROUND（窗口显示后并行）/ ON_DEMAND（需调用方拉起）。

**铁律：新增模块一律 ****`BACKGROUND`****。** ON_DEMAND 的初始化靠「窗口类型 → 模块组」隐式拉起，
一旦入口变化就静默失效——2026-09-15 主窗口换新壳层后 39 个模块的 handler 从未注册，
表现为 `updater:check` 报 "No handler registered"（历史教训：主窗口换壳曾致 39 个模块 handler 未注册）。

确需按需加载时，必须同时在渲染端用 `ensureModule` / `withModule`
（`src/commands/module-init.ts`）接入兜底；`module-init/__tests__/module-layering.test.ts`
守护这条约定，未接兜底的 ON_DEMAND 模块会让测试失败并列出模块名。

注：`@/electron` 的 `invoke` 已内置启动竞态重试（遇 "No handler registered" 每 500ms 重试、
上限 5s，收到过成功响应即停止），它只覆盖「注册晚于调用」的窗口期，**不覆盖「从未注册」**。

## 3. 三大协议（照抄即用）

**新增页面**（如卡片库）：

```TSX
// features/cards/pages/cards.page.tsx —— 文件即注册，无需改任何登记表
const schema = createPageSchema({ keyword: paramOptional(paramString()) });
type CardsParams = typeof schema.type;

export default definePage({
  key: "cards", // 与 navigation.ts 的 key 一致即接管侧边栏入口
  match: "single", // 功能页用 single；详情页用 "params" + getId: p => `card-${p.cardId}`
  label: "卡片库",
  status: "new",
  params: schema.schema,
  component: CardsView, // 视图组件放 ../views/
});
```

导航：`navigator.push("cards", { keyword: "..." })`；视图内读当前 params 用 `usePage().state`（后续可加 usePageParams 语法糖）。
`match: "single"/"params"` 的去重由栈机承担：重复 push 同 key 同参 = no-op、异参 = 原位更新，调用侧不要再做"是否已激活"判断。

**新增页面数据**（features/<域>/queries.ts，照抄 features/home 的形状）：

```TypeScript
export function useXxxSnapshot() {
  const query = useQuery({
    queryKey: ["<域>", "snapshot"],
    queryFn: fetchXxxSnapshot, // 并行 Promise.allSettled + 单项降级，整体不 reject
    staleTime: 60_000,
    refetchOnWindowFocus: true, // 全局默认是关，"今日"类数据按页面开启
  });
  return {
    data: query.data ?? null,
    loading: query.isPending,
    refresh: () => void query.refetch(),
  };
}
```

禁止手写 useEffect+useState 拉取；列表展示 N 条禁止为此全量拉大表（用渐进窗口凑满即停，或主进程聚合命令——参考最近编辑 14→30→90→365 天的实现）。

**新增主题**：`packages/ui/src/theme/themes/<name>.theme.ts` 用 defineTheme 声明（tokens 全键强制，漏键编译不过），在 `themes.ts` import 之，**并同步在 ****`tokens.css`**** 补 ****`[data-theme="<key>"]`**** 数据块**（取值运行时由该块级联，`theme-parity.test.ts` 守护两处一致；codegen 落地后改为生成）。派生逻辑写在 tokens() 里。

**主题模式与切换**：`@tau/ui/theme/runtime` 提供 `createThemeRuntime` 和默认 `useThemeStore/initThemeRuntime`；mode 可以是已注册主题 key 或 system。AppShell 挂载运行时并在清理时释放系统监听，Titlebar 消费同一 store。DOM 应用由公共主题实现负责，业务代码不操作 data-theme。Vite 构建入口调用 `createThemeBootstrapScript()` 注入首帧脚本，新增主题只需注册定义并同步 CSS 数据块；公共包 theme-parity 测试检查 token 对齐与 AA 对比度。桌面侧栏、标题栏尺寸保留在 app/base.css，不作为公共主题尺度。

**共存期明暗判定（D-022）**：`data-theme` 的值是语义 key（cream/cocoa…），JS 里**禁止**比对 `dataset.theme === "dark"` 判暗——统一看 `<html>.dark` 类（`applyThemeToDom` 随主题 mode toggle，编辑器包与移动端同此口径）。旧设置 `setting.darkMode` 不再写 DOM，旧入口 `onDarkModeChange` 转发 `useThemeStore.setMode`；编辑器全局 config（`useDesktopEditorConfig`）的明暗从 themeStore `resolved` 派生。编辑器包 `.editor` 不自定义 `--th-*` 变量，由宿主 `:root` 级定义级联（桌面 `styles/theme-colors.css` 的 `:root`/`:root.dark`，移动端 `styles.css` 桥接块）——在组件局部定义同名变量会截断宿主的深色值。

**颜色与尺度消费（D-001 Tailwind 优先）**：组件样式一律 Tailwind 工具类。颜色写语义类（`bg-page / bg-surface / bg-group / text-ink-1 / text-ink-2 / text-ink-3 / hover:bg-hover / bg-accent-soft / text-accent / bg-ok-soft / text-warn …`）；尺度写 tau 命名空间词（`text-tau-body / text-tau-meta / rounded-tau-sm|md|lg / shadow-card / shadow-float / ease-tau-out / font-tau / font-tau-mono`，词表见 02 规范 §3/§4）。**禁止**：裸色值、antd token、内联十六进制、新增手写 CSS 类（白名单见 §4）。数据驱动的动态值（进度宽度/格子高度）允许 inline style，但色值仍走语义类；一次性展示字号用 `text-[24px]` 类任意值；热力图色阶这类"主题 accent 定稿值的 alpha 派生"暂以 arbitrary 注明出处。跨域复用的视觉模式收口 `packages/ui/src/primitives/`（Panel/IconButton…），不要在多域重复同一段类串。**bg-group 只用于小面积元素**（Tag 灰档、徽章、kbd 提示、次级按钮——D-009 口径）；容器与输入控件禁用——容器 = 透明底 + `border-line-1` 描边、输入控件 = `bg-surface` + 描边（D-007 表单家族），嵌套底色叠层是常见腐化点。

## 4. UI 风格铁律（A2 校准结论，评审对照）

> **视觉基准与样式载体（D-001，2026-09-15 起）**：视觉基准 = `mockups/direction-a-soft.html`（A2 柔和版）+ `mockups/home-final.html`（今日页定稿），**降级为参考物**（浏览器打开对照截图），不再是导出源；调视觉直接改组件里的 Tailwind 类。样式载体 = **Tailwind v4 工具类优先**，组件 className 语义化、就地可读；跨域视觉模式抽 `packages/ui/src/primitives/` 组件。CSS 仅保留四类白名单（逐例裁决、默认不许）：① `app/base.css` 的 `.app` 作用域 reset（不波及 /legacy）；② `@keyframes`（经 `tokens.css` 的 `--animate-*` 消费）；③ `tokens.css` 主题数据块；④ Tailwind 表达不了的复杂伪元素/全局状态（现存唯一实例：home.css 的 edge-fade mask + page 根高度链）。原"模板类名 1:1 / 禁手改 shell.css / 先改模板再导出"工作流已废弃（导出脚本从未入库，不可复现）；shell.css/stats.css 已删除，约 90 个无消费者的预置模板类不迁移，将来做对应页面时用 Tailwind 语义类重写。

1. **融合骨架**：侧栏透明融于 bg-page、整高贯通窗口；标题栏/状态栏只属于右列；不出现横贯全宽的条。
2. **零横线**：分组靠底色容器（bg-surface 圆角面板 + shadow-card）与留白；禁止用 border 分隔区块（border 只允许 ≤2px 控件级细节，如勾选圈）。
3. **宽度利用**：内容区 max-w 1680 宽容器；窄列只允许出现在正文阅读列（~72ch）；详情页用双栏（正文+信息栏）。
4. **反馈语言**：hover = bg-hover 淡墨底；**激活（侧栏）= bg-selected（accent 叠层）+ 左缘 3px accent 竖标**（2026-09-17 改，D-006：选中是状态、悬停是反馈，原先借用 5% 墨的 hover 底，对 page 只有 1.086、扫不出当前在哪一页）；浮起（卡片）= shadow-card，hover 轻抬升；按钮无描边。注意：`hover:` 变体已用 `@custom-variant hover (&:hover)` 去掉 v4 默认的 `@media (hover: hover)` 包裹（D-016，两个 CSS 入口同改）——否则触摸屏设备（hover:none 判定）会静默杀掉全应用 hover 反馈。
5. **圆角**：面板/卡片 var(--tau-radius-lg)=16，控件 md=12，小元素 sm=8。
6. **数字** tabular-nums；字号体系以模板为准（25/14/13.5/12.5/11.5）。
7. **滚动条**：不出现系统滚动条——4px 细墨条仅在「活跃」时显形（hover 滚动容器或滚动中；停止 700ms 且鼠标不在时隐藏，移出窗口立即隐藏）。实现 = `base.css` 的 `.app` 作用域样式（`scrollbar-live` 类控制 thumb）+ `app/scrollbarAutoHide.ts` 事件委托（AppShell 初始化一次，全部内部滚动区自动生效）。**位置**：细条画在滚动容器 border-box 的右缘，容器满宽时它就贴死窗口右缘——用 `-mr/pr` 借位把 border-box 撑进容器自身的右留白（内容盒右缘因此不动、与相邻列仍对齐），细条落进留白里；home-scroll 与样板间内容列同为 `-mr-6 pr-6`，离窗口右缘 16px。两个坑别踩：① 禁止改回 `:hover` 伪类驱动——Chromium 滚动条伪元素不随 `:hover` 重算，显形后会冻结不消失；② 覆盖 main.less 的全局滚动条样式时必须同时清零 `box-shadow`/`-webkit-box-shadow`（不同属性名互不覆盖，只盖 background 会留下内阴影残影、看似常显）。
8. **className 覆盖必须走 ****`cn()`****（D-008）**：组件默认样式要让调用方覆盖（`IconButton` 的 `size-[27px]`、样板间 `MatrixRow` 的 `trayClassName="items-center"`）时，合并一律用 `@tau/ui/cn` 的 `cn()` 而非裸 clsx——Tailwind 同属性工具类的胜负由生成顺序决定，clsx 的先后顺序无效，覆盖会静默失效。项目自有尺度词（`text-tau-*`/`rounded-tau-*`/`shadow-card`/`ease-tau-out` 等）已在 cn 内登记；新增尺度 token 必须同步登记（`packages/ui/src/__tests__/cn.test.ts` 守护与 `tokens.css` 一致）。

## 5. 交互规范（已定案）

- 页面级槽位注入（2026-09-19）：页面可向壳层注入标题栏面包屑与底部状态栏——
  `usePageBreadcrumb(key, node)` / `usePageStatusBar(key, node)`（PageProvider 槽位注册表，
  仅栈顶页的内容被显示；页面卸载自动清理）。**node 必须经 useMemo 稳定化**（每次渲染新建
  JSX 会造成 注册→context 变化→重渲染→再注册 的循环，usePageSlot JSDoc 有说明）；传 null

### Button 使用边界

- 变体六档是一个动作的全部音量（D-013，`mockups/button/` 方案 B）：primary（accent 实心，**每屏至多一枚**，层级是评审纪律不进 API）/ secondary（surface 亮底 + 描边，取消与表单的默认档，即原 ConfirmDialog 应答区皮）/ soft（accent-soft 平底，工具栏次级强调）/ ghost（无底 hover 淡墨，与 IconButton 同反馈语言）/ danger（确认位实心红）/ danger-soft（列表与工具栏位）；danger 两档对齐 D-011 危险分级。
- `loading` 是内建语义：aria-busy + Spinner + `loadingText` 文案切换 + 一并 disabled（原生属性封锁指针与 Tab 队列）；调用方不再手动拼 Spinner（ConfirmDialog 已迁移）。
- 图标仅左位 16px（`icon={Plus}`，lucide stroke 1.75）；icon-only 一律 IconButton，Button 不设该档；`block` 满宽给空态 CTA；type 默认 "button"，form 提交位显式传 submit。
- antd 迁移映射：type=primary → variant="primary"；type=default → "secondary"；type=text → "ghost"；danger 布尔 → "danger"/"danger-soft"（按确认位/列表位分档）；type=link 是文字链语义，不建变体。

### Menu / ContextMenu 使用边界

- Menu、子菜单与 ContextMenu 默认按内容自适应宽度，无固定最小宽度；上限为 320px 且不超过视口减去两侧各 8px，长标签省略。需要固定宽度时通过浮层 `className`（如 `w-[280px]`）覆盖。
- Menu 使用复合组件声明命令、开关、单选组和子菜单；命令项关闭整树，checkbox/radio 保持打开。`Menu.Submenu disabled` 禁止鼠标与键盘展开，已展开的头项再次点击收起并还焦父层。
- `Menu.className` 与 `ContextMenu.className` 都控制浮层；ContextMenu 的内容区采用 `display:contents` 包裹，宽度等布局类应放在 children 的真实元素上。
- `useMenuTree` 统一整树关闭、外点判定与跨实例互斥。Esc/左方向键按层收起；任意层 Tab/Shift+Tab 关闭整树，还焦触发位置后由浏览器继续移动焦点。子层键盘事件不会重复驱动父层。
- type-ahead 读取声明树中直接可见的文本，不解析自定义组件的渲染结果；需要按文本导航时应直接传文本标签。

### Dialog / ConfirmDialog 使用边界

- Dialog 是模态决策容器（三段固定：标题/徽标 + 正文 + 影响行/应答区），footer 按钮序列由调用方提供（主按钮恒在最右）；ConfirmDialog 是确认语义预设——`danger`（焦点落取消）与 `typeToConfirm`（输入解锁，只给真·不可逆）两档内建。家族分工（D-003）：Menu 不做确认，确认归 ConfirmDialog、撤销归 Toast。
- 关闭矩阵：`dismissible`（默认，×/Esc/遮罩可关）/ `critical`（无 ×、遮罩与 Esc 抖动拒绝）/ `locked`（异步 loading 封锁一切）。Esc 仅 open 态在卡片 DOM 消费（焦点链 LIFO，不进 D-003 注册表——同 Select/Menu 口径，ui 不反向依赖 page/）；打开即 Tab 圈闭、关闭归还触发元素焦点。
- Dialog 内通过公共 `PortalScope` 提供局部浮层挂载点，位于当前遮罩内部、正文滚动区外；Select/Menu/字段编辑器等继承该挂载点，避免被遮罩盖住或被正文裁切，业务无需自行提高 z-index。
- 初始焦点落卡片内 `data-autofocus` 元素（无则卡片自身）——表单放首输入框，danger 放取消按钮；ConfirmDialog 自动标记。Enter 默认应答只在 ConfirmDialog 内建（焦点在按钮上走原生）。
- `onAfterClose` 在退场完成、子树卸载后触发；需要清空内容或草稿时使用此回调，关闭请求只改变 open。退场期间重新打开会取消本轮关闭回调。
- `contentReady={false}` 可提前隐藏挂载异步内容，期间不接管焦点、不锁滚动、不可交互；内容就绪后设为 true，再显示完整弹窗。加载失败也必须放行展示错误，避免一直隐藏。
- 尺寸档 `sm 380 / md 440（默认）/ lg 560` 只改宽度；`width` 像素数覆盖档位（预设不是牢笼）。长内容正文区独立滚动（上限 78vh）+ `edge-fade-scroll` + `useEdgeFade`（壳层同款边缘渐隐）。遮罩 `bg-overlay + backdrop-blur-[4px]`，容器 z-[340]。
- 头部信息一处一责：标题讲动作、`context` 徽标记对象（surface 亮底 + 描边，D-009 口径）、正文讲事实、`impact` 念后果、按钮文案不带数量；阻断通知纯文字头部（无 icon）。
- 无 footer / impact 时，正文滚动区底部保留 16px 外间距，避开容器圆角；配合 6px 内边距维持内容原有的 22px 底部留白。

### Popover 使用边界

- Popover 是锚定式可交互内容浮层（非模态，D-014 方案 B 形制）：无标题栏内容卡，`Popover.Header`（头行随需，icon + 标题 + ghost ×，挂 aria-labelledby）/ `Popover.Body`（独立滚动上限 60vh + edge fade）/ `Popover.Footer`（应答区随需，按钮右对齐）复合声明，trigger 克隆注入（协议同 Tooltip/Menu：必须透传 props 与 ref）。
- 触发只有 click toggle（内建，不设 trigger props）：hover 说明归 Tooltip、右键归 ContextMenu——antd 存量 `trigger="hover"` 迁 Tooltip，placement 12 向同名直映（迁移口径见 D-014）。
- 关闭矩阵：点外 / Esc / × / Tab 移出皆可关；Esc 与 Tab 还焦触发器；非模态不圈闭焦点。Esc 仅 open 态消费（焦点链 LIFO，同 Select/Menu/Dialog 口径）。初始焦点落 `data-autofocus`（无则卡片自身）。
- 定位走 anchoredPosition 引擎全 placement 12 向（首个全表消费者）+ flip/shift，gap 8、宽随内容（180–340，`className` 覆盖）；浮层内开的 Menu/Select/二级 Popover 经 useLayerDismiss 嵌套链共存（点子层不误伤父层、Esc 逐层退场），开新顶层浮层自动收旧的。
- 浮层公共底盘（D-014 抽取，新浮层组件一律消费勿再手写）：`useAnchoredPosition`（定位生命周期）、`FloatingArrow`（菱形箭头，宿主标 `group/float` + `data-side`）、`mergeRefs`（触发器克隆的 ref 合并）、`useLayerDismiss`（外点/嵌套/互斥——MenuSurface 走 registerDismissLayer 直登）。

### 滚动区标准接法（手写三件套）

- 滚动区 = `edge-fade-scroll` 类 + `useEdgeFade(el)` + callback ref（el 经 state 触发挂载后接线），`overflow-y-auto` 自带写；滚动条样式走全局规则（4px 细墨条，hover/滚动中显形——scrollbarAutoHide 的 document 级委托），挂上类即生效，无组件侧接线（Scroller 收口曾于 D-012 引入、当日被用户裁决删除，勿再建）。
- 两类规则已全局化（原 .app 前缀盖不到 body 级 Portal，Dialog 曾因此显示 main.less 宽条）：`::-webkit-scrollbar` 系列与 `.edge-fade-scroll`；Home 的 home-scroll 是带自定义 padding 协议的历史变体。

## 6. 如何迁移一个 legacy 模块（标准流程）

1. `features/<域>/pages/<key>.page.tsx` 新建（key 与 navigation.ts 一致——真实注册自动覆盖 legacy.tsx 的占位）；
2. 视图组件按 §4/§5 风格重写（参考样板间与 HomeView，**不参考旧页面写法**）；
3. 数据接 `queries.ts`（契约类型先行，未就绪的字段返回 null + 空态）；
4. 从 `page/legacy.tsx` 的 LEGACY_PAGES 删除该行；
5. DECISIONS.md 的 Page 迁移清单勾选该行。

### 6.1 共存期组件复用（新页面引老组件 · 换皮不搬家）

legacy 退役前，老组件（`src/components/` 等）同时被 `/legacy` 与新体系消费（如 `ContentEditor`：8 处 legacy 消费者 + 新文章详情页）。**原则：不复制，就地换皮；位置归置跟删除锚点走。** 新页面需要一个老组件时，依次三问：

| 问                           | 判据                                               | 动作                                                                                                                                                                                   |
| ---------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 纯视觉模式？                 | 无业务逻辑，各域长得一样（面板/图标按钮/浮层底盘） | 不引老组件，用或抽 `packages/ui/src/primitives/`（§3 既有口径）                                                                                                                        |
| 行为不变、只换皮？（主场景） | 功能保留，仅样式/控件升级                          | **就地改造**：原地换 Tailwind 语义类与 `--tau-*` token、antd 控件换 tau 家族（顺带缩减 eslint 白名单）；新页面直接 `import @/components/...`，并在 04 清单该页「明确保留」表登记消费者 |
| 新旧行为分叉？               | 新页面交互模型变了，改老组件会破坏 legacy          | 唯一允许复制的场景：复制到 `features/<域>/components/`，老组件同时在 04 清单登记「legacy 消费者清零后删除」                                                                            |

- 换皮边界：只动样式层与控件替换，**对外 props 协议与导出符号保持兼容**——编译是硬约束（tsc 全绿覆盖 legacy 调用方），运行时表现不是；确需破坏性改签名，加新 props 默认兼容旧值，不直接改。
- **legacy 只保接口、不保表现**：换皮后组件在 `/legacy` 下的显示与交互**允许不对**（该侧随 G1/G2 整体删除），不为它做样式适配、兼容分支或回归验证；组件既有测试中断言行为（props/回调）的保留，断言 legacy 视觉的随换皮更新或删除。仅当它在 legacy 上下文抛异常白屏且顺手可修时才处理——任何情况下不阻塞新页面的开发、编译、调试。
- 分层红线：`features/` 可引 `@/components/`、`@/hooks/`、`@/utils/`，**禁止引 `@/pages/`**（页面级资产属 legacy，引了会被锚点删除绑架）；`@/components/` 反向禁止 import `features/`。
- 最终归置跟锚点（04 清单 G1/G2）：legacy 消费者清零后，按「消费者决定归属」纯搬家（`git mv` 不改代码、单独提交）——单域消费 → `features/<域>/components/`；仍跨域 → 留 `src/components/`（应用级共享层）；纯视觉 → 升 `packages/ui/primitives/`。
