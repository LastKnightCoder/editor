### 主题退出的建议顺序

不建议直接删除 `--th-*` 定义后逐屏补漏，也不建议仅把旧文件搬到新目录便视为主题升级完成。

推荐先统一明暗取值，再迁移 UI 消费者和 JS 色值，随后处理局部明暗及 Portal，最后删除旧变量源和设置字段。若需要逐批交付，可短期把旧变量改成 tau token 的别名，先消除“双配色源”；这种别名层必须登记消费者并设清零条件，否则只是换了一种兼容层。

绘图和文件数据要区别对待：PDF 标注保存的十六进制、白板用户设置的颜色、图谱数据色不是 UI 主题垃圾，不能统一替换为 accent。普通界面文字、底色、边框、控件状态才应遵守 tau 主题契约。

### 字体初始化可以先收尾

App.tsx 已全局调用 useSyncFont；AppShell、QuickCardWindow、EditorWindowPage、MarkdownWindowPage 又分别调用。当前顶层路由都由 App 承载，可保留全局一次调用，删除这些子入口的重复挂载及过期解释。

同时检查 `main.less` 的 body 自有 `--font/--font-size/--mono-font` 默认值与 useSyncFont 写入 html 的覆盖关系；子元素上的自有变量会遮蔽祖先变量，清理时应验证实际计算值，避免仅以“写到了 root”判定字体链路完成。字号词表在 `useSyncFont` 与 `packages/themes` 双写也应收口到既有尺度来源，或加一致性检查。

主题 runtime 与字体不同：不同窗口有固定明暗策略和 storage 同步，不能把所有 useThemeRuntime 调用机械删掉。应保持每个窗口显式初始化、释放监听的语义。
