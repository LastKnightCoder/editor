# 桌面端 UI 设计系统规范（v1）

> 本文档定义桌面端 UI 的基础设施：token 体系、多主题机制、排版/间距/动效、组件分层与 antd 替换映射。
> 视觉方向（配色/圆角/质感的具体取值）以样板间评审结果为准，三套方向的 palette 在各自 HTML 内嵌注释里——**本文档锁定的是结构与机制，方向定稿后把选中的取值回填到这里**。

---

## 1. 设计理念

审美基线 = PREFERENCES.md 的滚动沉淀（唯一事实源）：讨厌 antd 通用后台脸，讨厌营销页式装饰、夸张动效、抢占注意力的状态提示、仪表盘堆砌；喜欢有个人特色的设计语言。原 PRODUCT.md 为历史遗留，已删除，不再作为任何设计依据。

落地为五条视觉宪法（所有组件与页面评审对照这五条）：

1. **表面中性，色彩表意**：背景/面板/浮层全部中性色靠亮度分层；颜色只出现在 accent（选中/主按钮/焦点）与语义状态。绝不用颜色装饰。
2. **层级靠三个手段**：亮度（表面分层）、字重字号（排版层级）、留白（分组）——而不是线框和阴影堆砌。阴影只给"物理上浮起"的东西（浮层、拖拽物）。
3. **密度服务于判断与行动**：桌面是生产力工具，默认紧凑；每行只保留决策必需的信息，次要信息按需展开（hover/展开区）。
4. **反馈安静而确定**：操作反馈用轻量手段（160ms 过渡、状态色点、内联文案），不打断输入焦点，不用模态庆祝成功。
5. **键盘是一等公民**：所有交互可键盘到达，焦点环永远可见，Esc 逐层退场（与 surface 协议的 LIFO 仲裁一致）。

## 2. Token 体系：defineTheme 协议（全新，不继承旧 --th-*）

### 2.1 与旧 token 完全切割（D-008，已裁决）

- 旧 `--th-*`（`src/styles/theme-colors.css`）**不迁移、不复用、不兼容**，M1 换壳时整文件删除；
- 新体系前缀 **`--tau-*`**，词汇表与移动端对齐（`bg-page / ink-1 / line-1 / ok …`）——两端同词汇、各自取值，心智一致；
- 敢切的原因：旧页面样式靠 antd 自带体系 + less modules + 原子类，本就不依赖我们的语义 token，删旧 token 不影响 Legacy 兼容层里的旧页面继续跑；`packages/editor` 是自有包，直接改为消费 `--tau-*`（一次性改造）；移动端 `styles.css` 的 `--th-*` 桥接由移动端自己定义，与桌面无关；
- 尺度 token（字号/间距/圆角/动效）与主题正交，放全局 base 层；defineTheme 只声明**颜色语义 + 氛围**，密度走独立的 `[data-density]` 维度。

### 2.2 defineTheme：一个文件声明一个主题的全部

与 defineSurface 同构：主题不是手写 CSS 块的堆叠，而是**类型安全的数据 + 色板→语义的纯函数**。

```TypeScript
// ui/theme/tokenContract.ts —— 语义 token 单一事实源（词汇表 → TS 类型 / CSS 变量名 / 校验清单）
export const tokenContract = createTokenContract({
  surface: ["bg-page", "bg-surface", "bg-elevated", "bg-sunken"],
  interaction: ["bg-hover", "bg-press", "bg-selected"],
  ink: ["ink-1", "ink-2", "ink-3", "ink-inverse"],
  line: ["line-1", "line-2", "hairline"],
  accent: ["accent", "accent-hover", "accent-active", "accent-soft", "accent-text", "focus-ring"],
  status: ["ok", "ok-soft", "warn", "warn-soft", "danger", "danger-soft", "info", "info-soft"],
  tag: ["tag-1", "tag-1-soft", "tag-2", "tag-2-soft", "tag-3", "tag-3-soft", "tag-4", "tag-4-soft", "tag-5", "tag-5-soft"],
  float: ["overlay", "glass", "shadow-sm", "shadow-md", "shadow-lg"],
  ambiance: ["texture-noise"],
});
export type SemanticTokens = TokenShape<typeof tokenContract>; // 全键 Required——漏写一个 token，编译不过

// ui/themes/cream-light.theme.ts —— 一个文件 = 一个主题（Vite glob 收集，零登记表）
export default defineTheme({
  key: "cream-light",
  mode: "light",
  meta: { name: "暖纸 · 晨光" },
  palette: { paper: "#f6f1e7", ink: "#43392c", accentHcl: [0.62, 0.12, 28] },
  tokens: (p) => ({
    "bg-page": p.paper,
    "bg-surface": "#fffdf9",
    "ink-1": p.ink,
    "accent": oklch(...p.accentHcl),
    "accent-hover": oklch(p.accentHcl[0] - 0.06, p.accentHcl[1], p.accentHcl[2]), // 派生逻辑显式可见，不再藏在 CSS calc 里
    // …全部 token 由类型强制补齐
  }),
  ambiance: { texture: "noise-warm" },
});
```

要点：

1. **泛型只在边界**（definePage 同款手法）：`tokens(p)` 返回值被约束为全键 `SemanticTokens`，漏键 = 编译错误——从机制上杜绝"狂野补丁"（token 想加就加、漏了没人知道）的复发；
2. **派生显式化**：accent 的 hover/soft/active 派生从 CSS `calc` 里的隐式公式，变成映射函数里可读、可单测的代码；
3. **文件即注册单元**：`ui/themes/*.theme.ts` 经 Vite glob 收集，新增主题零登记表；
4. **编译期 codegen，运行时零成本**：构建脚本（`pnpm ui:themes`）把全部主题生成为 `themes.generated.css`（每主题一个 `[data-theme="key"]` 块）+ `themeRegistry.generated.ts`（key/mode/name 清单，供设置页与 themeStore 枚举）。切换仍走 `html[data-theme]` CSS variables，**零 JS 重渲染**；
5. **对比度门禁**：codegen 顺带跑 WCAG 断言（§2.5 指标），不过 AA 构建直接失败——主题质量不再靠人眼把关。

主题运行时只有很薄一层：`themeStore`（zustand + persist + 系统跟随 + index.html 首帧防闪）与 `useTheme()`。未来若要支持用户自定义主题，把 codegen 输出换成运行时注入即可，协议不变。

### 2.3 semantic token 词汇表（结构定稿；取值 = 样板间选中方向的变量表回填）

```CSS
[data-theme="cream-light"] {   /* 示意：每个主题一个块，由 codegen 生成，不手写 */
  /* 表面（亮度分层） */
  --tau-bg-page;        /* 窗口最底 */
  --tau-bg-surface;     /* 卡片/面板 */
  --tau-bg-elevated;    /* 浮层/菜单 */
  --tau-bg-sunken;      /* 凹陷区：代码块、输入框底、侧栏 */
  /* 交互态 */
  --tau-bg-hover; --tau-bg-press; --tau-bg-selected;   /* selected 通常是 accent-soft */
  /* 文字（4 级 + 反色；meta 行用 ink-2，不单设 meta-ink） */
  --tau-ink-1;          /* 正文 */
  --tau-ink-2;          /* 次要/meta */
  --tau-ink-3;          /* 占位/禁用 */
  --tau-ink-inverse;    /* accent 实底/深色胶囊上的文字 */
  /* 边线（3 级） */
  --tau-line-1;         /* 常规描边 */
  --tau-line-2;         /* 弱分隔（列表行间） */
  --tau-hairline;       /* 1px 发丝线（工具栏上下缘）；无描边风格的主题置 transparent */
  /* accent（派生关系写在 tokens() 映射函数里，不进 CSS calc） */
  --tau-accent; --tau-accent-hover; --tau-accent-active;
  --tau-accent-soft; --tau-accent-text; --tau-focus-ring;
  /* 语义状态（成对：前景 + 底色） */
  --tau-ok / --tau-ok-soft;  --tau-warn / --tau-warn-soft;
  --tau-danger / --tau-danger-soft;  --tau-info / --tau-info-soft;
  /* 标签/分类（前景 + 底色成对，组数按方向定稿，默认 5 组） */
  --tau-tag-1 / --tau-tag-1-soft; …
  /* 浮层氛围 */
  --tau-overlay;        /* 模态遮罩 */
  --tau-glass;          /* 毛玻璃表面（标题栏/浮层，可选） */
  --tau-shadow-sm; --tau-shadow-md; --tau-shadow-lg;   /* 只给浮起物 */
  /* 纹理（可选，方向定稿决定是否保留） */
  --tau-texture-noise;
}
```

消费规则：组件只允许消费 `--tau-*`（或经 Tailwind `@theme inline` 映射的语义类名 `bg-page / text-ink-1 / border-line-1`）；palette 原始输入不进组件；component 层变量（`--btn-*` 等）仅复杂组件自建、作用域私有。

### 2.4 主题机制

- **载体**：`html` 上的 `data-theme="<key>"`（codegen 生成的块）。CSS variables 切换，零 JS 重渲染；
- **跟随系统 + 手动覆盖**：`mode: "system" | "light" | "dark"` 存设置，`prefers-color-scheme` 监听（整套机制照搬 `apps/mobile/src/theme/themeStore.ts`，含首帧防闪：index.html 内联脚本先设 data-theme 再加载应用）；
- **扩展新主题 = 新增一个 ****`*.theme.ts`**** 文件**——比移动端"新增一个 CSS 块"更强：有类型完整性校验与对比度门禁兜底；
- **编辑器包**：`packages/editor` 直接改为消费 `--tau-*`（自有代码，一次性改造，随 M0 完成）；若改造期内需要并行，可在 `ui/theme/` 挂一个 `var(--tau-*)` → 旧名的临时桥接，M2 前拆除；
- **密度维度**：`[data-density="compact" | "comfortable"]`，控制行高/控件高度/页边距（桌面默认 compact，可全局切换），与主题正交。

### 2.5 对比度硬指标（codegen 门禁强制，不过 AA 构建失败）

- `--tau-ink-1` 对 `--tau-bg-page/surface` ≥ 7:1；`--tau-ink-2` ≥ 4.5:1；占位符与 meta 文字 ≥ 4.5:1（移动端踩过 ink-2 只有 3.9:1 的坑，桌面用门禁杜绝重犯）；
- accent 作为文字色时 ≥ 4.5:1，作为实底按钮时其上文字 ≥ 4.5:1（light/dark 分轨的派生公式写在 tokens() 里，主题作者可读可调）。

## 3. 排版系统

| 级       | Tailwind 词          | 字号/行高 | 用途                                      |
| -------- | -------------------- | --------- | ----------------------------------------- |
| hero     | `text-tau-hero`      | 25/1.3    | 首页 hero 日期、空状态大标题              |
| title-lg | `text-tau-title-lg`  | 20/–      | 页面标题                                  |
| title    | `text-tau-title`     | 14.5/–    | 卡片标题、面板标题、命令面板输入          |
| body-lg  | `text-tau-body-lg`   | 13.5/–    | 强调正文、阅读区正文                      |
| body     | `text-tau-body`      | 13/1.65   | 正文、列表主信息（壳层基准）              |
| meta     | `text-tau-meta`      | 12.5/–    | 时间戳、路径、面包屑                      |
| sm       | `text-tau-sm`        | 12/–      | 次级控件文字、窗口按钮                    |
| micro    | `text-tau-micro`     | 11.5/–    | 徽标、面板附注                            |
| tiny     | `text-tau-tiny`      | 11/–      | 导航分组标签、标签小字                    |
| mono     | `font-mono` + 上面档 | 12/–      | 代码、ID、快捷键提示（`--tau-font-mono`） |

- 取值为 A2 定稿（direction-a-soft.html）回填，词表经 `tokens.css` `@theme` 映射（D-013，`tau` 命名空间不覆盖默认刻度）；一次性展示字号（热力图轴标 9.5/10.5、统计大数字 19/21/24）允许 `text-[24px]` 类任意值，不进词表；
- 字体栈：系统栈（与移动端同源），数字一律 `font-variant-numeric: tabular-nums`（列表对齐、计时器必需）；
- 中文排版：中西文混排加 1/6 em 间距由系统字体处理，不手写空格；标题不使用全角标点悬挂；
- 字重只用 400 / 500 / 600 三档，700 及以上禁止（克制）。

## 4. 间距 / 圆角 / 动效

- **间距**：4px 基数刻度（4/8/12/16/20/24/32/48），语义间距别名：`--tau-space-page`（页边距，compact 20 / comfortable 28）、`--tau-space-card`（卡片内边距 16）、`--tau-space-stack`（同组元素间 8）；
- **圆角**：三档 `--tau-radius-sm: 6 / md: 10 / lg: 14`（具体值随方向定稿，如暖纸方向会整体加大）；输入框/按钮用 sm-md，卡片 md，浮层 lg；
- **动效**：时长四阶 `instant 80ms / fast 160ms / normal 240ms / slow 400ms`；缓动两根 `--tau-ease-standard: cubic-bezier(0.2, 0, 0, 1)`、`--tau-ease-bounce`（仅 drawer/dialog 进场用）；一切动效尊重 `prefers-reduced-motion`；**页面切换默认无动画**（桌面即时感），动效预算花在浮层和微交互上。

## 5. 组件体系（零 antd）

### 5.1 分层

```
ui/primitives/   单一职责的基础件（一个目录一个组件，含 __tests__）
  Button / IconButton / Input / Textarea / Select / Checkbox / Radio / Switch
  Segmented / Menu / Tooltip / Dialog / Drawer / Popover / Toast / Spinner
  Tag / Kbd / Avatar / Divider / VirtualList / ScrollArea
ui/patterns/     页面级模式（组合 primitives，体现交互范式）
  PageHeader / FilterBar / EmptyState / ListLayout / MasterDetail
  CommandPalette / SettingsShell / StatusBar / FormRow（Field 体系）
```

规则：primitives 不知道业务；patterns 不知道具体域（域内组件放 `features/*/components/`）。

### 5.2 antd → 自研替换映射（迁移对照表）

| antd                         | 自研                                                              | 迁移策略                    |
| ---------------------------- | ----------------------------------------------------------------- | --------------------------- |
| Button                       | `Button`（variant: solid/soft/ghost/danger × size: sm/md）        | 高频，M0 先建               |
| Input / Input.TextArea       | `Input` / `Textarea`（Field 体系包裹：Label/Help/Error）          | 高频，M0                    |
| Select                       | `Select`（listbox + 键盘导航，非 antd 弹层行为）                  | M0（先用受限版：单选+搜索） |
| Modal                        | `Dialog`（dialog surface 的默认容器）                             | M0                          |
| message / notification       | `Toast`（命令式 API + 视口角落）                                  | M0                          |
| Tooltip / Popover / Dropdown | `Tooltip` / `Popover` / `Menu`（共享一个浮层定位引擎）            | M0（引擎是关键投入）        |
| Table                        | **不建通用 Table**。列表用 `VirtualList` + 行组件；确需表格再评估 | 按需                        |
| Tabs                         | `Segmented`（内容切换不该用 Tab——那是导航的事，走 surface）       | M1                          |
| Checkbox/Radio/Switch        | 同名自研                                                          | M0                          |
| DatePicker                   | `DatePicker`（dialog surface 实现日历面板）                       | M2 前                       |
| Form                         | 不建——受控组件 + Field 体系 + zod 校验                            | —                           |
| @ant-design/icons            | **lucide-react**（线性 1.5px、风格统一、tree-shake）              | M0 引入                     |

浮层定位引擎（floating-ui 或自研锚点定位）是 primitives 里最重的一项投入，M0 专项做——Menu/Tooltip/Popover/Select/CommandPalette 全靠它。

### 5.3 组件 API 范式（一致性契约）

- 交互组件统一 `size: "sm" | "md"`、状态用 `data-state`（hover/press/selected/disabled）驱动 CSS，禁止 JS 切类名；
- 所有交互组件 `forwardRef`、可受控可非受控（`value` + `onValueChange` / `defaultValue`）、键盘可达、焦点环用 `--tau-focus-ring`；
- 触发浮层的组件统一 `open` / `onOpenChange` 命名（与 dialog/drawer surface 的 open 语义对齐）；
- Escape/外点关闭的仲裁一律走 surface 协议的 LIFO 链（`useEscapeDismiss`），业务组件不得自行监听 keydown Escape 关浮层。

### 5.4 样式写法（单轨制，D-013 细化）

- 唯一写法：**Tailwind v4 工具类 + `@theme` 语义映射**（tokens.css）：

  ```CSS
  @theme inline {
    --color-page: var(--tau-bg-page);
    --color-ink-1: var(--tau-ink-1);
    --radius-tau-md: var(--tau-radius-md);
    /* … */
  }
  ```

  组件里写 `bg-page text-ink-1 rounded-tau-md`——语义类名，主题无关；尺度词一律 `tau` 命名空间（不覆盖 legacy 在用的默认刻度），词表见 §3/§4；

- CSS 白名单仅四类（全局 reset / keyframes / 主题数据块 / 复杂伪元素，见 03 指南 §4）；`tailwind.css` 手写 utility 属 legacy 存量（`--th-*` 映射），只减不增，且不得与 tokenContract 语义词同名；
- 144 个 CSS Modules（.less）与 legacy 页面一起消亡：新代码禁增，迁移一页删一批；
- 禁止：内联 style 色值、`!important`（overlay.less 式补丁自此绝迹）、antd 的 `style` 透传。

### 5.5 窗口铬与平台适配（标题栏）

- **探测**：用 `packages/platform` 的 `platform.supports()` 决定平台分支；业务组件禁止嗅探 UA；
- **macOS**：红绿灯由系统绘制在左上，frameless 布局给左侧恒定 inset（内容起点约 76px / 控件高度 28px），标题栏整条为拖拽区（交互控件除外）；侧边栏折叠态也必须给红绿灯留位；
- **Windows**：自绘右侧三键（最小化/最大化/关闭），热区 34×26，关闭键 hover 用 danger 色；
- **导航控件**：标题栏左侧放后退/前进（对应 navigator.back()/forward()，Alt+←/→）；栈深不足时**禁用而非隐藏**——用户对"能否返回"要有稳定预期；
- 标题栏高度：macOS/Windows 统一 44px（compact 42px）。

## 6. 图标

- **lucide-react**，尺寸 16（inline/meta）/ 20（工具栏/按钮）/ 24（空状态），stroke 1.5；
- 同一动作全局同图标（新增=plus、删除=trash…），图标选用变化记入 PREFERENCES.md；
- 纯装饰禁用图标；每个图标操作必须有文字 tooltip（无障碍基线）。

## 7. 无障碍与键盘

- WCAG AA（§2.5 对比度已覆盖色彩面）；焦点环全局可见，禁止 `outline: none` 不给替代；
- 命中面积 ≥ 24×24（工具栏图标按钮用 padding 撑到 28×28）；
- 全局键盘骨架（与 surface 协议联动）：
  `Ctrl+K` 命令面板 · `Ctrl+N` 新建卡片 · `Ctrl+F` 页内搜索 · `Alt+←/→` 后退/前进 · `Esc` 逐层退场（LIFO）· `Ctrl+1..9` 切侧边栏入口 · `Ctrl+\` 分屏开关
- `prefers-reduced-motion` 全局降级为 instant。

## 8. 新增一个页面/组件的标准流程

1. 页面：`features/<域>/surfaces/xxx.surface.tsx` 声明（key/match/params/data/store/component），视图组件放 `views/`，props 驱动可单测；
2. 组件：先查 primitives/patterns 有没有——有则用，没有且跨域才进 `ui/`（域内组件不进 ui/）；进 `ui/` 必须带 `__tests__` + Storybook 式 demo 页（`ui/demo/` 可选建设）；
3. 评审五条视觉宪法（§1）+ PREFERENCES.md 对照——新页面不得引入 PREFERENCES 里记为反例的模式；
4. PR 描述里带 status 变更（legacy→new）与 CI 棘轮影响。
