Select 基础件 · 方案导览

待裁决：三份演示页视觉完全共皮（同一触发器 + listbox 弹层 + 键盘行为），分歧全在 API 形态——「结构写在哪里」：写在 JSX（复合组件 Select.Option）、写在数据（options prop）、还是写在调用方（无头 hook 自己分发 props）。定位引擎不在本轮议程：02 §5.2 已裁定 Select 与 Tooltip / Menu / Popover 共享 D-004 自研 mini 引擎（offset → flip → shift），弹层承载 = Portal + z-[250]。已定口径：listbox + 键盘导航（非 antd 弹层行为）、M0 受限版 = 单选 + 搜索、受控契约对齐 §5.3（value/onValueChange + 浮层 open/onOpenChange）。

三条 API 路线

方案 A · 复合组件

Select.Option 声明式 — 结构写在 JSX
<Select>
<Option 今日 />
<Option 本周 />
OptGroup
↘
选项即标签。antd / Radix 心智：<Select.Option> 里直接写 JSX，富内容（图标 + 双行 + 徽章）所见即所得；分组用 OptGroup。老代码从 antd JSX 写法迁移几乎零改动。
  • 富选项内容零成本——children 里随便写
  • antd Select.Option 老用法直接映射，迁移顺
  • 搜索过滤要遍历 children 提取文本——「可编程的数据」变「要解析的树」
  • 异步 / 虚拟化 / 大列表都要先把 JSX 数量化，绕一圈回到数组
  • value 类型推断弱（children 收集靠运行时），多选扩展动 API
适用：选项少而富（视图切换、语言选择）；调用方愿意写结构。

方案 B · 数据驱动 推荐

options prop 单组件 — 结构写在数据
[{value,label}…]
→
<Select options />
filter / 异步 / 分组
→
数据层解决
选项即数据。Linear / VS Code 心智：一个 options prop 吃下全部——搜索是一行 filter、分组是 group 字段、异步是换数组、M1 多选是 value: V[]、虚拟化是把列表区换成 VirtualList。API 面最小，扩展全在数据形状里平滑生长。
  • 实现最薄（单组件，无子组件收集）；M0 受限版 → M1 多选/搜索/虚拟化不破坏 API
  • TS 直接约束 options: SelectOption<V>[]，value 泛型推断完整
  • antd options 用法（绝大多数存量）字段直接映射
  • 富选项内容经 label: ReactNode + searchText 代理搜索，比 JSX 直写绕半步
  • 「表单里选项写死三五个」的场景，构造数组的仪式感略重（可后加语法糖）
适用：FilterBar / 设置页 / 命令面板内嵌筛选——桌面端 Select 的绝大多数真实场景。

方案 C · 无头 hook

useSelect + props 分发 — 结构写在调用方
useSelect(options)
↘
triggerProps → 自绘
menuProps → 自绘
state / getOptionProps
内核外露。React Aria 心智：hook 返回状态 + props 包，触发器和弹层的 DOM/样式全由调用方拼。自由度天花板（同一 hook 撑起标准下拉、行内迷你、图标触发三种形态），代价是每个使用点 20+ 行结构样板。
  • 形态自由度最大：变体（行内编辑 / ghost / 图标触发）不用组件开口子
  • 行为内核（键盘/aria/定位）与 UI 零耦合，单测最干净
  • 每个使用点重写一遍结构——与「视觉收口 primitives」铁律相悖，跨域必然漂移
  • 样板成本转嫁给全部调用方；文档负担最高（props 包契约要解释）
定位：不作为公共 API 竞选——它是 B 的实现策略（内部 = 无头内核 + 默认壳）与极端变体的逃生舱留档。

键盘与交互规范（三方案共通，进实现不动摇）

输入关闭时打开时
↑ / ↓打开并高亮当前值相邻项移动高亮（跳过 disabled），scrollIntoView(nearest)
Enter / Space打开选中高亮项 → 关闭 → 焦点归还触发器
Esc—关闭（焦点回触发器；接浮层退场 LIFO 链）
Home / End—高亮首 / 末项
可打印字符打开并跳匹配项type-ahead 跳匹配；searchable 时输入进搜索框并过滤
Tab—关闭并自然移出焦点
外点 / 滚出—关闭（外点 = pointerdown capture；弹层内滚动不关）

无障碍：触发器 role=combobox aria-haspopup=listbox aria-expanded；弹层 role=listbox + aria-activedescendant 指向高亮项；选项 role=option aria-selected。选中（当前值，bg-selected + Check）与高亮（键盘停留行，bg-hover）两态并存。aria-activedescendant 走 DOM id，实现时用 useId。视觉口径：触发器 surface 亮底（与未来 Input/Textarea 同族的「表单控件家族」；surface 卡片上同底靠描边显形、group 工具栏上浮起一档）、弹层 surface + shadow-float + radius-lg(16)、层级 z-[250]（命令面板 101 < Toast 200 < Select/Menu 250 < Tooltip 300）、动效 160ms ease-tau-out、md=34px / sm=28px、chevron 开合旋转 180°。

决策建议与 API 草案

怎么选

  1. 推荐方案 B（数据驱动）：M0 受限版（单选+搜索）到 M1（多选 / 虚拟化 / 异步）全部在数据形状里平滑生长，API 面不膨胀——这正是 antd Select 失控的反面；实现最薄（单组件、无子组件收集）；FilterBar / 设置页 / 命令面板内嵌筛选这些真实消费点全是 options 形态；antd 存量 options 用法字段直映（value/label/disabled 不改名）。
  2. A 的核心诉求（富选项）B 已覆盖：label: ReactNode 承载富行，searchText 代理富 label 的搜索匹配。若届时 JSX 心智诉求确实强，可在 B 之上加 <Select.Option> 语法糖（编译为 options）——先不做（YAGNI），加了语法糖就是 antd 双轨，两条路都要养。
  3. C 不是竞争者，是 B 的实现策略：无论选哪个，组件内部都写成「无头内核（键盘/aria/定位状态机）+ 默认壳」，演示页 plan-c 的 createSelectCore 即内核参考。useSelectCore 不作为公共 API 导出——视觉收口铁律（02 §5.1：primitives 不知道业务，patterns 不知道域）优先于极端自由度；真出现标准壳表达不了的形态，那是 primitives 该加变体，不是调用方该拿内核。
  4. 定位与承载直接复用 D-004：引擎中间件链 offset → flip → shift 照搬（GAP 收窄到 4，下拉贴触发器）；arrow 关闭。弹层 Portal 到 body、z-[250]，同宽策略 = min-width 取触发器宽、内容可撑开（matchTriggerWidth 默认 true）。Select 的 Esc 属于组件级浮层关闭（非全局浮层退场注册表），但同一时刻只应有一个下拉开着——实现时弹层打开即注册、关闭即注销，与命令面板的 LIFO 链相接。
  5. 定稿后的同步义务：DECISIONS.md 记条目（API 形态 + 表单控件家族视觉口径）；03 指南 §9 任务清单勾选；样板间加 SelectSection（含常显标本）；Input / Textarea 落地时沿用「surface 亮底 + line-1 描边 + radius-sm」的家族口径。

ui/primitives/Select API 草案（按 B 起草）

<Select                                    // 单组件，无复合子组件（A 语法糖可后加，YAGNI）
  options={viewOptions}                    // SelectOption<V>[]，字段名与 antd 对齐（value/label/disabled）
  value={view} onValueChange={setView}     // 受控 / defaultValue 非受控（§5.3 契约）
  placeholder="选择视图"                    // 空值占位（ink-3）
  searchable                               // M0 受限版内置本地过滤（label / searchText 做 includes）
/>

interface SelectOption<V = string> {
  value: V;
  label: ReactNode;            // string 直用；富行传 JSX（图标 + 双行 + 徽章）
  disabled?: boolean;
  group?: string;              // 分组键，按首次出现顺序分组（标签 tiny 600）
  searchText?: string;         // 富 label 的搜索代理字段（string label 免填）
}

interface SelectProps<V> {
  options: SelectOption<V>[];
  value?: V | null;  defaultValue?: V | null;  onValueChange?: (v: V) => void;  // M0 无清空路径，实现收窄为 V
  placeholder?: string;
  size?: "sm" | "md";          // 34px / 28px（§5.3 统一尺寸契约）
  searchable?: boolean;        // 弹层内嵌搜索框（30px，surface 底），自动聚焦
  filter?: (opt: SelectOption<V>, query: string) => boolean;   // 默认 includes
  emptyText?: string;          // 过滤空态，默认「无匹配项」
  matchTriggerWidth?: boolean; // 默认 true（min-width = 触发器）
  status?: "error";            // Field 体系错误态（danger 描边）
  disabled?: boolean;
  open?: boolean;  onOpenChange?: (open: boolean) => void;      // 浮层受控（§5.3）
  // renderOption?(opt, state: { selected, highlighted }): ReactNode  —— 逃生舱，M1 按需加
}
// 行为内建（不做成 props）：键盘全表（上表）· aria 接线 · 选中回填触发器 ·
// flip（D-004 引擎，GAP=4）· 外点关闭 · 焦点归还 · type-ahead 400ms 窗口
// 明确不做（M0）：多选/标签模式（M1 value: V[]）· 异步 loading prop（换数组即异步，
//   过渡态用 emptyText 表达）· 虚拟化（M1 列表区换 VirtualList，options 形状不变）
实现映射：三份演示页的触发器 + listbox CSS 可直接移植为 Tailwind 类（surface/selected/hover 语义类全在 tokens.css 词表内，零新增 token）；plan-b 页的 filter/分组/大列表即 M0 验收用例；plan-c 页的 createSelectCore 是内部内核参考实现。视觉与键盘行为不在本轮分歧内，用户裁决 API 后任一方案共用同一套皮。
