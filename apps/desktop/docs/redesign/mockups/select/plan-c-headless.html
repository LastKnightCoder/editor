Select 设计稿 · 方案 C

无头 hook · useSelect + props 分发 —— 结构写在调用方，同一内核撑起任意外壳

外壳一 · 标准壳（与 A / B 完全同皮）

// 调用方：内核 + 自己拼的标准结构（React 形态示意，~20 行） const sel = useSelect({ options: VIEWS, value, onValueChange: setView }) <button {...sel.triggerProps}> // role/aria-expanded/onKeyDown/onClick 全在包里 {sel.selected?.label ?? placeholder} <ChevronDown data-open={sel.open} /> </button> {sel.open && ( <div {...sel.menuProps}> // 定位/键盘/aria-activedescendant 在包里 {sel.visibleOptions.map(o => ( <div {...sel.getOptionProps(o)} key={o.value}>{o.label}</div> ))} </div> )}

内核签名 · createSelectCore（useSelect 的 vanilla 等价物）

interface SelectCore<V> { // 状态（订阅式，React 版即 hook 返回值） state: { open: boolean; highlightIndex: number; selectedValue: V | null }; // props 包：分发到调用方自己写的 DOM 上 triggerProps: { role; aria-haspopup; aria-expanded; onClick; onKeyDown }; menuProps: { role: "listbox"; aria-activedescendant; onKeyDown; style 定位结果 }; getOptionProps(opt): { role: "option"; aria-selected; data-state; onClick; onPointerEnter }; // 行为原语（键盘/开合/选中/flip 全内建——与 A/B 同一份代码） actions: { open(); close(); move(dir); pick(opt); setQuery(q) }; }
监视器（右上角）实时显示 state 与 props 包内容——「无头内核返回了什么」从抽象变可见。

暗账 · 公共 API 化的三张账单

① 样板转嫁：标准形态（占 90% 使用点）每个调用方都要写 20+ 行结构—— A/B 是 <Select options /> 一行。自由度只被 10% 的变体场景消费，账单却寄给所有人。
② 视觉漂移：结构与样式散落各域，02 §5.1「跨域复用的视觉模式收口 primitives」被绕开—— 三个月后出现五个太阳系（圆角 6/8/10 混用、间距各凭手感）。
③ 文档负担：props 包是隐式契约（triggerProps 里有哪些键？忘了 spread 就丢键盘）， 类型能兜一部分，心智成本兜不住。
结论（导览页口径）：C 不竞选公共 API——它是 B 的实现策略 （B 的内部 = 这颗内核 + 默认壳）与极端变体的逃生舱留档。真需要迷你壳这类形态时，primitives 加 variant="inline" 或独立 InlineSelect，内核复用、壳仍收口。
