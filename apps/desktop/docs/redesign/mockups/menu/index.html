Menu 基础件 · 方案导览

已定稿：方案 B · 现代产品（药丸行 + 控件式勾选 + kbd chip，2026-09-17 用户裁决，D-010）——A/C 留档对照。Menu 是动作触发的浮层命令面板——与 Select 的分界在语义：Select 选值即关， Menu 承载命令、开关（checkbox）、单选组（radio）、分隔、子菜单的异构序列，开关项触发不关闭。 技术底盘已定：定位复用 D-004 自研 mini 引擎（GAP=4 与 Select 同族），键盘导航按 D-007 预告从 Select/Menu 两例交集抽 listbox hook，Esc 同 Select 口径（焦点链 LIFO， 不进 D-003 注册表）。因此本页的开放决策只有一件事：视觉形态语言——三份演示页同内容、 同行为、共皮引擎，差异全在密度与形制，供综合选择。

三条形态路线

方案 A · 经典桌面

macOS 语感 — 图标列对齐 · glyph 勾选 · 纯文本快捷键
信任操作系统的三十年肌肉记忆。图标列 17px 强制占位（无图标留空位换文字列对齐）， 勾选 glyph（✓ / ●）画在图标列，快捷键右对齐纯文本。菜单是「命令清单」，不是「卡片」。
  • 零学习成本——从任何桌面应用过来的用户不需要适应
  • 无 chip、无控件装饰，视觉最安静；与系统菜单并排不违和
  • 图标列强制占位：全无图标菜单左松右挤，宽度下限 216px 最高
  • 纯文本快捷键在中英混排里基线/字宽要手调
适用：Titlebar 应用菜单、全局性命令面板语境——「这是个桌面应用」的身份感。

方案 B · 现代产品 已定稿

Linear 语感 — 药丸行 · 控件式勾选 · kbd chip
菜单是一件产品，不是一段系统 UI。行是浮起的药丸（34px + 行内 8px 圆角 + 2px 间隙）， 勾选用显式控件（方框/圆圈），快捷键穿 chip（D-009 亮底小药丸），danger hover 实心红。
  • 品牌感最强——与 Toast 卡片、命令面板同一浮层语言
  • 「开关是控件」语义最直白；danger 实心 hover 的后果感表达最强
  • 纵向开销：10 项比 A 高约 44px，长菜单更易进滚动态
  • kbd chip 三种背景下的显形 + danger×高亮第三态，测试矩阵涨一档
适用：卡片右键、分享/导出等产品语境——「这是个有设计的产品」的身份感。

方案 C · 密集工作台

IDE 语感 — 矮行 · 左缘指示条 · footer 描述条
footer 描述条随高亮联动
菜单是工具，为高频操作与长列表而生。26px 矮行 + 12.5px 字号换同屏密度； 键盘高亮带左缘 2px 指示条（IDE 活动行语感）；底部 footer 描述条随高亮念出每项说明。
  • 同屏多看 2–3 项；长菜单（移动到笔记本…）滚动压力最小
  • footer 条让长命令清单不用 hover 猜语义——desc 是信息密度的一部分
  • 菲茨定律账单：26px 行高点击容差小，触控板/偶尔用户门槛高
  • desc 内容税 + 指示条/✓ 双 accent 信号竞争，约束比 A/B 多一条
适用：批量操作、笔记本/标签选择器、排序视图——「这是专业工具」的身份感。

行为契约（三方案共用，随 D-004 / D-007 落地）

能力行为出处 / 备注
定位D-004 引擎：offset GAP=4、上下 flip、视口 padding 8px；右键菜单锚 = 鼠标点（虚拟 rect）与 Select 同族；子菜单锚 = 父项右缘
键盘↑↓ 高亮 · Enter 触发 · → 展开子菜单 · ← 收起 · Home/End 首末 · 敲字 type-ahead（400ms）· Esc 关栈顶导航 hook = Select/Menu 两例交集抽取（D-007 预告）
Esc 口径焦点链 LIFO：子菜单 → 主菜单 → 关闭还焦点给触发器；不进 D-003 注册表（同 Select D-007）仅 open 态在组件 DOM 消费（stopPropagation）
开关语义checkbox / radio 项触发不关闭菜单（连续操作）；命令项触发即关Menu 与 Select 的本质分界
ariarole=menu / menuitem / menuitemcheckbox / menuitemradio；aria-checked 双态；aria-haspopup + aria-expanded 在触发器右键菜单的触发器为虚拟锚，aria 挂内容区
关闭时机外点（pointerdown capture）/ Tab 失焦 / 命令触发 / resize（演示稿处理为全关）桌面语感：全局同时只开一棵菜单树
焦点归还关闭后焦点回触发器（右键菜单回内容区）键盘用户不断链
danger 二次确认Menu 不做确认——确认归 ConfirmDialog / 撤销归 Toast（D-003 家族分工）Menu 只负责触发，不承载决策

决策建议与 API 草案

怎么选

  1. 看产品主语境定身份：Tau 是知识管理工具（卡片 + 编辑为主战场），菜单的高频场景是 卡片右键与视图控制——若认同「菜单跟产品走」，B 的现代语言与 Toast/命令面板一脉；若认同 「桌面应用跟操作系统走」，A 最稳；若「效率工具优先」，C 的密度与 footer 信息量最贴重度用户。
  2. 两个可混、一个不可混：footer 描述条（C）与 kbd chip（B）可以嫁接到任何基底上（增量元素不破坏行制）； 但行高 / 勾选形态 / danger hover / 图标列策略四个维度必须整体三选一——它们共同定义「行的形制」，拼盘必割裂。
  3. 落地即收口：定稿后 Menu 进 ui/primitives/（03 指南 §9 任务 2 清单内），导航 hook 按 D-007 从 Select 抽交集（useListNavigation），定位直接传 gap: 4 复用 computeTooltipPosition； 实现提交同步 03 指南组件小节与 DECISIONS.md（编号顺延）。
  4. 内容契约同Select 口径：未接线的数据返回 null + 空态，菜单项不造假；长列表（笔记本选择器） 用 LIMIT/聚合命令，前端只渲染拉到的部分。

  <>
    <Menu.Item icon={<Open />} kbd="↩" onSelect={open}>打开</Menu.Item>
    <Menu.Submenu label="导出为" icon={<Export />}>      // 子菜单级联，→ / hover(260ms) 展开

    </Menu.Group>

interface MenuItemProps {
  icon?: ReactNode;        // A/C 占位对齐，B 随需
  kbd?: string;            // 快捷键提示（展示用，监听归全局注册表）
  desc?: string;           // footer 描述条（C 定稿则保留，A/B 定稿则砍）
  danger?: boolean;        // danger 色 + 专属 hover
  disabled?: boolean;
  onSelect?: () => void;   // 命令项：触发即关
}
// 内建行为（不做成 props）：键盘全表 · type-ahead · aria 双态 · 外点关闭
// · 焦点归还 · checkbox/radio 触发不关闭 · 子菜单 hover 延迟 260ms
// · Esc 焦点链 LIFO（同 D-007，不进 D-003 注册表）
// 注意：Menu 用复合组件而非 Select 的数据驱动——项是异构序列（命令/开关/单选/
// 分隔/子菜单），数据驱动要发明 DSL；D-007 的「数据驱动」裁决不外推到 Menu。
