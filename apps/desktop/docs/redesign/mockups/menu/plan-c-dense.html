radio 组（排序）与 checkbox 组（显示）都是「触发不关闭」——这是 Menu 与 Select 的本质分界： Select 选值即关，Menu 的开关项要连续操作。指示条=高亮、✓=选中，两个信号语义分离。

长列表滚动 · 同屏多看 2–3 项

同样 12 项：A 需滚 ~5 项、C 需滚 ~7 项可见（26px 行高的密度收益）； footer 条在滚动容器内 sticky 钉底。下方放不下 → 翻上方，定位 = D-004 引擎（GAP=4）。

暗账 · 本方案绕不开的三件事

① 菲茨定律的账单：26px 行高比 A/B 少 4–8px 的点击容差， 触控板与低精度指针场景误触率上升——「密集」是给熟练用户的礼物、给偶尔用户的门槛。
② footer 条的内容税：每菜单 +26px 纵向是小事，desc 要每项都写 才不显得断断续续——内容维护成本转嫁给菜单作者；不写则退化为常驻空条。
③ 两个 accent 信号的竞争：左缘指示条（高亮）与 ✓（选中）都在抢注意力， 「高亮了一个已选项」时左条与 ✓ 同行——语义上分得开（指向 vs 状态）， 视觉上要靠体量差（2px 条 vs 12px 勾）压住，设计约束比 A/B 多一条。
