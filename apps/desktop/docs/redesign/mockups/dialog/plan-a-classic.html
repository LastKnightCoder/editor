经典桌面 —— 无标题栏 · 无分隔线按钮栏 · 主按钮最右，跟操作系统的模态对话走

确认对话 · dismissible（× / Esc / 遮罩皆可关）

// 语义预设组件：确认类对话一句话接线（Dialog 的最薄封装） <ConfirmDialog open={archiving} onOpenChange={setArchiving} title="归档这张卡片？" description="归档后从列表移入档案，随时可恢复。" confirmText="归档" onConfirm={archive}/>
Enter 确认（默认应答） · Esc 取消 · Tab 圈闭 · 焦点落主按钮 · 关闭后焦点归还触发器

危险确认 · critical（无 × · 遮罩点击抖动 · 焦点落「取消」）

工作 · 重构 笔记本 · 24 张卡片
删除笔记本是不可逆操作（废纸篓保留 30 天）——critical 态不给 ×、遮罩点击只抖动， 强迫用户在按钮上显式二选一；焦点初始落「取消」，回车不会误删（macOS 危险对话的安全默认）。 后果在 risk-line 里量化（24 张卡片），不写「确定要删除吗？」这类空话。

表单对话 · 新建笔记本（Enter 提交 · 空值禁用主按钮）

// 通用容器：Body 自由排版，Footer 声明按钮序列（主按钮恒在右） <Dialog open={open} onOpenChange={setOpen} title="新建笔记本"> <Dialog.Body>…输入 / Select / 开关（D-007 控件口径）</Dialog.Body> <Dialog.Footer><Button onClick={close}>取消</Button> <Button variant="primary" disabled={!name} loading={busy}>创建</Button></Dialog.Footer> </Dialog>
首输入框自动聚焦全选；表单走 Enter 提交（dialog 承载 form 语义）； 名称为空时主按钮禁用——校验内联在按钮上，不做弹中弹的错误提示。

阻断通知 · 版本冲突（纯文字 · critical 二选一）

A 的 alert 不用 icon（macOS Ventura 起 alert 无图形，文字即信息）—— 冲突这种「必须二选一」的对话同样 critical：无 ×、不可遮罩关闭， 「保留我的」放主按钮位（安全侧），「重载他们的」是次按钮。

长内容滚动 · 头尾固定 · 尺寸档 sm / md / lg

正文区独立滚动，标题与按钮栏钉住不动；高度上限 78vh，超出才滚。 尺寸档只改宽度，不改变任何排版参数——档位是宽度词，不是密度词。

异步提交 · loading 期间一切关闭路径失效

主按钮进入 loading（spinner + 文案切换）后，Esc / 遮罩 / × 全部失效—— 半途关闭的导出是坏文件；完成后自动关闭并交 Toast 报告结果（D-003 家族分工：Dialog 管决策，Toast 管回执）。

暗账 · 本方案绕不开的三件事

① 层次全靠一层影子：无 hairline 分隔、无遮罩 blur，浮层的「浮」只剩 shadow-float—— cream 浅色主题下卡片与底色的明度差小，Dialog 存在感偏弱。
② 主按钮最右是 mac 记忆：Windows 用户三十年的记忆是主按钮在左 （WinUI ContentDialog 的 Primary 就在第一位），跨平台用户会有顺序迟疑。
③ 纯文字 alert 头轻脚重：无 icon 配重，信息稀疏的阻断通知视觉重心全压在按钮栏； 长描述时「一段灰字」的观感最素。
