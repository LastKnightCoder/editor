Dialog 基础件 · 方案导览

已定稿：方案 B · 现代产品（2026-09-18 用户裁决，D-011）——A/C 留档对照。 定稿在 B 基底上嫁接三件增量元素（不破坏形制）：上下文徽标（标题动作化、对象挂 chip）、 footer 影响行（后果贴决策点，信息一处一责）、edge fade（滚动渐隐对齐壳层 useEdgeFade 协议， 替代 C 的标题栏阴影）；尺寸档 sm/md/lg 之外允许 width 任意值覆盖；danger 两档—— 轻 danger 一步确认，真·不可逆才 type-to-confirm。 Dialog 是模态决策容器——系统有事要问、用户必须作答的地方（家族分工见 D-003： Menu 不做确认，确认归 ConfirmDialog、撤销归 Toast）。技术底盘已定：居中模态不需要 D-004 锚定引擎； 焦点圈闭/归还、滚动锁定、Enter 默认应答是标准件；Esc 属模态阻断浮层，走 D-003 useOverlayDismiss 注册表（命令面板同族——Select/Menu 的「焦点链 LIFO 自消费」是瞬态锚定浮层的口径，不外推）。 三份演示页同内容、同行为、共引擎，差异全在皮；plan-b 已更新为定稿口径。

三条形制路线

方案 A · 经典桌面

macOS 语感 — 体内标题 · 无分隔线按钮栏 · 主按钮最右
跟操作系统走的模态对话。无标题栏、无 hairline——按钮直接坐在描述下方 （mac alert 的克制）；主按钮最右、回车即默认应答；遮罩纯色不 blur——「系统变暗」而非「产品打光」。
  • 零学习成本——从任何桌面应用过来的用户不需要适应
  • 结构最薄：轻确认（归档）不背标题栏/影响行的框架，纵向开销小
  • 层次全靠 shadow-float 一层撑，cream 浅色主题下存在感偏弱
  • 主按钮最右是 mac 记忆，Windows 用户顺序相反
适用：系统级语境——版本冲突、同步失败、权限询问——「操作系统在问话」的身份感。

方案 B · 现代产品 已定稿

Linear 语感 — 体内大标题 · hairline 应答区 · type-to-confirm · + 嫁接件
对话框是产品的一部分，不是系统弹窗。体内大标题（16px）开门见山， hairline 划出应答区，blur 遮罩让世界后退；danger 走 type-to-confirm（输入名称解锁删除）， 按钮文案带数量——与 Menu B 药丸行、Toast 卡片同一浮层语言。
  • 与已定稿浮层（Menu B / Toast / 命令面板）语言连续性最强
  • danger 后果感表达最强：输入确认 + 实心红 + 数量入文案
  • blur 遮罩的 GPU 账单：大窗低端机连续开关有重绘成本
  • 16px 标题 + 34px 按钮最重，高频小确认显「隆重」
适用：产品语境——删除/导出/分享/表单——「这是个有设计的产品」的身份感。

方案 C · 密集工作台

WinUI / IDE 语感 — 标题栏横条 · 上下文徽标 · footer 影响行 · 主按钮在左
对话框是工作台的一块任务面板。标题栏横条挂标题 + 上下文徽标（操作对象是谁） + ×；footer 左念影响范围、右放按钮（主按钮在左，WinUI 顺序）；正文 12.5px 紧凑， 滚动时标题栏下渐显阴影。动效克制无缩放——工具不做戏。
  • 信息结构最强：对象徽标 + 影响行，批量/多开操作不迷路
  • 同屏信息量最大，长内容（更新说明）滚动体验最好
  • 主按钮在左是 Win 记忆，mac 用户相反（A 的暗账镜像）
  • 结构感在小对话里空转——轻确认没有影响行可念时框架大于内容
适用：批量操作、长内容、专业流——「这是专业工具」的身份感。

决策建议与 API 草案

怎么选

  1. 看浮层语言连续性定身份：已定稿的浮层家族全是现代产品语言——Menu B 药丸行（D-010）、 Toast 卡片、命令面板（D-003）。若认同「Dialog 跟产品走」，B 的连续性最强（blur 遮罩 + hairline 应答区 + 实心红 danger 一脉）；若认同「模态对话跟操作系统走」，A 最稳；若批量操作与长内容是 主战场，C 的信息结构（上下文徽标 + 影响行）最实用。
  2. 两个可嫁接、四个不可混：上下文徽标 / footer 影响行（C）与 type-to-confirm（B）是增量元素， 可嫁接到任何基底；但标题形制 / 按钮顺序 / footer 形制 / 遮罩材质四维必须整体三选一—— 它们共同定义「对话的形制」，拼盘必割裂。
  3. type-to-confirm 是档位不是装饰：只给真不可逆（删除笔记本、清空废纸篓）； 轻度危险（归档）永远一步确认，否则全线劝退。
  4. 落地即收口：定稿后 Dialog + ConfirmDialog 进 ui/primitives/（03 指南 §9 任务清单）， Esc 接 useOverlayDismiss（D-003），表单控件沿 D-007 surface 口径； 实现提交同步 03 指南组件小节与 DECISIONS.md（编号顺延）。

ui/primitives/Dialog API 草案

<Dialog open={open} onOpenChange={setOpen} title="新建笔记本" size="md">   // 通用容器
  <Dialog.Body>…输入 / Select / 开关（D-007 控件口径）…</Dialog.Body>
  <Dialog.Footer>                                                  // 按钮序列，主按钮语义位恒定
    <Button onClick={close}>取消</Button>
    <Button variant="primary" disabled={!name} loading={busy}>创建</Button>
  </Dialog.Footer>
</Dialog>

<ConfirmDialog                                                    // 语义预设：确认类一句话接线
  open={deleting} onOpenChange={setDeleting}
  title="删除笔记本" context="工作 · 重构"                         // C 定稿保留徽标，A/B 砍
  impact="24 张卡片 · 废纸篓保留 30 天"                            // C 定稿保留影响行
  confirmText="删除" cancelText="取消"
  danger typeToConfirm="工作 · 重构"                               // B 定稿保留输入确认
  critical focus="cancel" onConfirm={del} />

interface DialogProps {
  open: boolean; onOpenChange(v: boolean): void;
  title: string;
  critical?: boolean;            // 无 × + 遮罩/Esc 抖动拒绝——「必须作答」档
  size?: "sm" | "md" | "lg";     // 宽度词：380 / 440 / 560，不改排版
}
// 内建行为（不做成 props）：Esc（D-003 注册表 LIFO）· Tab 圈闭 · 焦点归还
// · Enter 默认应答（IME isComposing 让位）· 滚动锁定与 body 独立滚动
// · loading 封锁关闭 · 开合动效 · critical 抖动 · 底层滚动锁定
// ConfirmDialog = Dialog 的最薄预设：danger 自动 focus=cancel；
// 异步结果回执交 Toast（D-003 家族分工：Dialog 管决策，Toast 管回执）
实现映射：三份演示页的 mini dialog 引擎（开合动效、遮罩/Esc/× 关闭矩阵、critical 抖动、Tab 圈闭、焦点归还、Enter 应答、异步 loading 封锁、滚动阴影）可直接移植为 primitives 参考； 定稿方案的 CSS 皮即组件 Tailwind 类的蓝本。
