确认对话 · dismissible（× / Esc / 遮罩皆可关）

// 语义预设组件：确认类对话一句话接线（Dialog 的最薄封装） <ConfirmDialog open={archiving} onOpenChange={setArchiving} title="归档卡片" context="架构笔记" impact="可随时在档案中恢复" confirmText="归档" onConfirm={archive}/>
Enter 确认（默认应答 = Primary） · Esc 取消 · Tab 圈闭 · 焦点落主按钮 · 关闭后焦点归还触发器

危险确认 · critical（footer 影响行量化 · 无 × · 焦点落「取消」）

工作 · 重构 笔记本 · 24 张卡片
C 把后果念在 footer 影响行（任务对话框传统）：左侧红点 +「24 张卡片 · 废纸篓保留 30 天」， 右侧按钮作答——信息与动作同屏不换行。头部上下文徽标始终标明操作对象， 批量操作时多开不迷路。仍是 critical：无 ×、遮罩点击抖动、焦点落「取消」。

表单对话 · 新建笔记本（Enter 提交 · 空值禁用主按钮）

// 通用容器：Body 自由排版；Footer = 影响行 + 按钮序列（主按钮恒在左） <Dialog open={open} onOpenChange={setOpen} title="新建笔记本"> <Dialog.Body>…输入 / Select / 开关（D-007 控件口径）</Dialog.Body> <Dialog.Footer impact="创建在「收件箱」下"> <Button variant="primary" disabled={!name} loading={busy}>创建</Button> <Button onClick={close}>取消</Button></Dialog.Footer> </Dialog>
首输入框自动聚焦全选；表单走 Enter 提交（dialog 承载 form 语义）； 名称为空时主按钮禁用——校验内联在按钮上，不做弹中弹的错误提示。

阻断通知 · 版本冲突（标题内联 icon · 上下文徽标 · critical 二选一）

C 的 alert 用标题内联 icon（16px 线性，不做大圆底）+ 上下文徽标表明冲突对象； 影响行走灰字（非 danger）。冲突对话 critical 无 ×，「保留我的」是 Primary（在左第一位，安全侧）。

长内容滚动 · 头尾固定 · 滚动阴影渐显 · 尺寸档 sm / md / lg

正文区独立滚动，标题栏与 footer 钉住；向下滚动时标题栏下缘渐显阴影 （IDE 滚动语感，提示上方还有内容）。高度上限 78vh，超出才滚。尺寸档只改宽度，不是密度词。

异步提交 · loading 期间一切关闭路径失效

主按钮进入 loading（spinner + 文案切换）后，Esc / 遮罩 / × 全部失效—— 半途关闭的导出是坏文件；完成后自动关闭并交 Toast 报告结果（D-003 家族分工：Dialog 管决策，Toast 管回执）。

暗账 · 本方案绕不开的三件事

① 主按钮在左是 Win 记忆：macOS 用户三十年的肌肉记忆是主按钮最右、回车即应答—— 与 A 的暗账互为镜像，跨平台总有一半用户要重新适应。
② 28px 按钮的菲茨账单：点击容差三案最小，触控板轻点、高分屏缩放（125%/150% DPI）下 误触率上升；footer 行与按钮同高挤在一行时更紧。
③ 结构感在小对话里空转：轻确认（归档）没有影响行可念、没有上下文徽标可挂时， 标题栏横条 + footer 两道横线仍在——框架大于内容，小对话显「重」。
