三个方案

方案 A

卡片墙 · 瀑布流网格

延续旧版「一卡一世界」的卡片隐喻，废除单列虚拟列表改为多列瀑布流：置顶升格双列宽横卡，四分类色点 + 文献卡引用样式 + 链接计数入卡面；左侧层级标签树保留。图谱 / 表格视图给了完整示意（表格含四型视图 tabs）。

✓ 功能覆盖最全、卡片「作品感」最强、三视图示意完整✗ 密度最低（一屏 ~8 张），长文本卡片高度不齐
方案 B

卡片盒行 · 高密度列表

与今日页「继续编辑」、文章页 B 案同构的行式语言：时间分组 sticky 头 + 行首分类色条 + 摘要单行 + 标签/链接/字数列 + hover 平铺操作；↑↓ 键盘移动 + ↵ 预览。标签树改横向 pills（取舍点）。

✓ 密度最高（一屏 ~18 行）、键盘效率高、与首页基因连续✗ 无卡片形态感，长摘要看不全；标签层级横向展开较弱
方案 C

双栏工作台 · 列表 + 常驻预览

邮件客户端式三栏（标签树 / 紧凑列表 / 常驻预览）：预览弹窗升格为右栏工作面——正文可直接编辑、标签增删、链接卡片 chips 点击跳转、操作全部平铺；新建也在右栏完成（弹窗废除）。读卡 / 改卡 / 连卡不经弹层。

✓ 编辑动线最短（预览即编辑）、链接跳转闭环、键盘动线完整✗ 三栏挤占宽度（窄窗口需折叠），列表密度受中栏限宽

第二轮 · 融合方案 D2026-09-20 评审反馈

第一轮反馈（各方案吸引点）：A 的左侧标签树、B 的时间分组排序、C 的明确工作区；另裁决：页内不设搜索框（titlebar Ctrl K 全局搜索已覆盖，本页只做浏览与加工，A/B/C 已同步移除）。据此产出融合方案 D。

方案 D

融合工作台 · 第二轮 · 已被第三轮推翻，留档对照

三基因合一：左栏分类 + 层级标签树（A）· 中栏时间分组列表，分组头 sticky（B）· 右栏独立工作台大卡——预览即编辑、链接 chips 跳转、操作平铺、新建同区完成，更重阴影与左侧色脊强化「工作区与其他明确分开」（C）。无页内搜索，↑↓ 浏览 + ↵ 选中 + Ctrl ↵ 保存新建。

✓ 三个吸引点全部保留、浏览与加工同屏、键盘动线完整✗ 弃用：第三轮裁决回到卡片墙形态（用户更喜欢 A 的卡面呈现）
