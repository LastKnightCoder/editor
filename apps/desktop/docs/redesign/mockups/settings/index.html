同一信息架构（通用 / 数据 / AI 服务 / 扩展 / 支持 五组，14 子页归组），三种导航组织。 每页实做「外观 / 同步 / 大语言模型」三个代表子页（轻 / 中 / 重各一），可交互。

骨架之外的待裁决点

定稿前需要一并拍板（建议随骨架一起裁决）

  1. 保存模型：三稿统一演示即时保存（改了就生效，B 的 footer 状态条是其产品化表达）。 legacy 多为显式「保存」按钮。建议定即时保存并逐页清理显式保存；若某些子页（如同步目标切换）确需确认， 按页单独处理而不是全局回退。
  2. 设置搜索与命令面板的分工：B 的弹窗内搜索与已有 Ctrl+K 命令面板（D-003）能力重叠。 两条路：命令面板索引设置项后弹窗内不再做搜索（选 A/C 时自然回避）；或弹窗内保留轻量过滤作为「上下文内找」。 若选 B，建议命令面板跳转设置子页作为统一入口。
  3. 14 子页的再分组：三稿共用草案——「杂项」拆解并入通用；文字转语音 / 语音转录 / 白板录制 三页是否合并为「语音与转录」一组（或一页三段）；「发布」「集成」的去留按 M 系列迁移计划定。
  4. 承载与落地（架构约束）：D-002 规定 dialog/drawer 不经 Page 协议——设置弹窗应作为 feature 级浮层由壳层挂载（命令面板同族，D-003 模式），Esc 经 useOverlayDismiss 仲裁； 落地前需在 DECISIONS.md 追加条目（含左下角入口与 Ctrl+, 快捷键）。
  5. 尺寸策略：A 760 / B 920 / C 640 是预设值。设置弹窗跨 13~16 子页， 是否允许子页声明自己的尺寸偏好（预设不是牢笼，同 Dialog 的 width 覆盖口径）。
三案可嫁接：例如 A 的平铺导航 + C 的摘要列（导航行带当前值），或 B 的骨架 + A 的无 footer。 导览页鼓励综合裁决——定稿后 plan 页将更新为定稿口径（同 Dialog 工作流）。
