嵌入模型子页 · 设计探讨

legacy 嵌入模型子页是双 Tab（本地模型 / API 模型）。已落地的同步 / 资源 / 发布三子页都把 legacy 的提供商 Tab 溶解成了「Select + 字段网格」，但那三页 Tab 切的是同构内容的值（字段一样、换数据）； 嵌入模型这页切的是内容形态——本地是下载管理器、API 是 Provider 配置 + 模型表，字段完全不同， Select 溶解会让「切换后页面整个变」埋进下拉里。这是新设置弹窗里第一处真正需要内嵌 Tab的地方， 也是 02 规范 §5.2 裁决（antd Tabs → 自研 Segmented，M1）的第一个消费者。三案： 分段（形制后改定连体描边）/ 线轴下划线 / 来源溶解。功能严格对齐 legacy，只重做排版与主题语言； 「检索模型」节两态共享，常驻切换区之外。

功能盘点 · legacy 对照（三案共用，保证无遗漏）

嵌入模型 = 向量化检索的模型来源与管理；本地与 API 互斥（currentConfigId 单值）， 切换即后台重建向量索引（确认弹窗）。检索模型独立于来源，永远在本页。

案 1 · 分段 —— Segmented 控件（02 §5.2 裁决形态；2026-09-23 追记改定连体描边）

页题下一枚分段控件切换本地 / API 两种形态。追记：首版凹槽轨道（bg-sunken + surface 胶囊滑块）被用户否决深底，通用组件改定「连体描边」（Input 家族语言：hairline 容器 + 段间分割线，激活段 accent-soft 轻染 + accent-text，无轨道无滑块无投影——完整设计见 mockups/segmented/，D-029）。切换弹确认（后台重建索引）。 控件语义 = 单选（radiogroup，方向键移动即选择，D-026 同源），不是 tablist 导航。

✓ 优势

  • 就是 02 §5.2 裁决的 Segmented 形态——Tabs 的官定替代，不新增范式
  • 两个形态并列可见，「当前来源」一眼可读，切换因果最强
  • 连体描边是 Input 家族语言（与 Input/Select 触发器同皮），零深底零投影

⚠ 取舍

  • 比线轴多一层容器描边（换取「一枚控件」的明确边界）
  • 段数只适合 2–4 个——本页恰好两个，上限内
  • 需先落 Segmented 进 ui primitives（M1 计划内，本页提供首个消费者）

案 2 · 线轴分段 —— 下划线 Tab，最轻的切换语言

文字 + 2px accent 下划线 + 基线 hairline 贯穿右栏（浏览器 / VS Code 设置页的内嵌页签语言）。 视觉最轻、零底色，但基线横线是新的「横线切割」，且 Tab 隐喻与 02 §5.2 「内容切换不该用 Tab——那是导航的事」正面相撞。

案 3 · 来源溶解 —— 无内嵌切换器，「模型来源」Select 行

完全同构已落地三子页：第一行「模型来源」Select（本地模型 / API 模型），下方内容随值整块替换。 零新控件、零新范式，导航与行语言零改动——代价是「换一个值，页面整个变」的因果藏在下拉里。

  1. 建议以案 1 为定稿：它不是「又一个 Tab 方案」，而是 02 §5.2 已裁决的 Segmented 首次落地—— 本地 / API 的切换本质是 currentConfigId 单选，分段控件就是单选的皮肤，语义精确； 案 2 的下划线是 Tab 导航隐喻（踩裁决 + 新增横线切割），案 3 把形态开关埋进下拉（因果最弱）。
  2. Segmented 落地口径（2026-09-23 追记，已落地 packages/ui/primitives/Segmented.tsx）： 原生 input[type=radio] 承载语义——radiogroup、Tab 一次进组、方向键移动即选择全部白送； 复合组件 Segmented + Segmented.Item（label → aria-label、sm 28 / md 34、图标段与纯图标段）。 规格：hairline 容器（surface + line-1 · radius 8）+ 段间分割线，段高 26 + 描边 2 = 总高 28； 激活段 accent-soft 轻染 + accent-text 600；非激活 ink-2，hover 淡墨只落未选段；轻染淡入 160ms。
  3. 切换语义保留 legacy：本地 ↔ API、Provider 激活、模型启用三类切换都走 ConfirmDialog 确认（后台自动重建向量索引）；即时保存模型不变（无应答区）。
  4. 检索模型节在切换区外常驻：两态共享，避免切个来源把检索模型也藏了； 其下载源 / 设备策略行只影响本节模型。
  5. 不采纳案 3 的理由记录在案：若后续某子页 Tab 切的确实是同构值（如 LLM 多 Provider）， 仍优先溶解成 Select——「形态切换用分段、值切换用 Select」自此成为设置弹窗的分界口径。
