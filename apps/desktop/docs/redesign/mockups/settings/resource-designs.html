资源子页 · 设计探讨

资源域两件事，机制相互独立：上传目标（图床）——编辑器内上传图片/附件时「写时直达」所选存储 （本地 / GitHub / 阿里云 OSS / S3 / WebDAV，单选即生效）；资源目录同步——本地 resources 目录与云端「事后双向镜像」（本地多→上传、云端多→下载、同名跳过），远端与凭据跟随「同步」子页的 存储配置（与图床目标相互独立）。两块怎么组织成设置子页？三案：域闭环一页 / 生效卡 + 手风琴 / 拆三子页。功能严格对齐 legacy，只重做排版与主题语言。

功能盘点 · legacy 对照（三案共用，保证无遗漏）

上传目标 = 写时直达（五家单选 + 全局压缩开关，凭据在集成）；资源目录同步 = 事后镜像 （远端跟随同步子页，支持中断恢复 / 失败重试 / 黑名单 / 实时进度）。

案 1 · 域闭环 —— 一页两节（上传目标 + 目录同步）

资源的事一页说完：上节回答「新资源传到哪」，下节回答「resources 目录怎么和云端对齐」。 上节与同步子页完全同构（Select + 字段网格 + 凭据链接行），导航零改动。specimen 为弹窗右栏内容区全貌。

案 2 · 生效卡 + 手风琴 —— 目标全览，点选即生效

三案对比与建议

维度案 1 · 域闭环案 2 · 生效卡 + 手风琴案 3 · 三子页
导航改动无无数据分组 +1 子页（14→15）
页面长度~2 屏~1.5–2 屏（展开时）每页 ≤1 屏
图床 active 表达Select 隐式（与同步页同构）状态卡 + radio 显式，语义最准Select 隐式（同案 1）
五家配置全览否（逐家切换查看）是（摘要直读，legacy 无此体验）否
文件列表空间紧凑行（裁掉大小列）紧凑行完整表四列直读
与同步子页一致性最高中（新增手风琴语言）高（存储页同构）
落地成本低（复用 SyncSection 模式）中（新手风琴组件）中（新子页 + 导航 + IA 裁决）
  1. 建议以案 1 为基底：导航零改动（不破 D-028 十四子页对齐）、上节与同步子页完全同构 （Select + 字段网格 + 凭据链接行，落地直接复用 SyncSection 模式）、资源域一页闭环—— 「上传目标」与「目录同步」虽机制独立，但都是「资源放哪」的用户心智。
  2. 案 2 的增益可低成本吸收：五家配置全览不必靠手风琴——案 1 提供商 Select 的描述行可带出 已配置家的摘要（如「GitHub my-notes · 阿里云 OSS my-bucket · 其余未配置」），一行成本换大半增益； 手风琴本体作为独立形态仅在「配置摘要高频查看」时值得。
  3. 案 3 的完整文件表留作弹层：案 1 紧凑行若不够用，「查看问题 / 管理黑名单」走弹层 （D-002：浮层不经页面栈协议，ConfirmDialog/自定义弹窗承载），不为此扩导航。
  4. 防混提示是硬约束：资源目录同步的远端跟随「同步」子页（sync.active），与图床 active 相互 独立——同页并存（案 1/2）必须保留提示行「远端与凭据跟随 同步 · xx 的存储配置」，避免用户误以为 改图床即改同步远端。
  5. 压缩开关归属：legacy 是独立「压缩设置」Section；本稿并入「上传目标」节（它是上传管线的一环， 本地目标同样生效），少一个节标题、语义更聚。
  6. 落地锚点：替换 features/settings/sections 的 imageBed 占位；资源同步节消费既有 useResourceSync / useResourceSyncBlacklist 与主进程 resource-sync 命令；文件行 / 黑名单弹层新建。
