发布子页 · 设计探讨

发布是一次性静态站点生成：选中内容（卡片按标签树 / 文章 / 问题 / 项目 / 知识库）→ 模板渲染 → 增量推送或本地导出（内容哈希比对，只传变更）。三个发布目标（GitHub Pages / S3 静态托管 / 本地导出，凭据在集成子页），加上站点配置（标题 / 描述 / 公开 URL / favicon）、内容 选择器（legacy 里 min-h 24rem 的大组件）与发布操作（五阶段进度）。四段怎么装进 610px 弹窗右栏？三案：legacy 同构全内嵌 / 状态卡置顶 + 选择弹层 / 轻两节 + 紧凑内嵌。 功能严格对齐 legacy，只重做排版与主题语言。

功能盘点 · legacy 对照（三案共用，保证无遗漏）

案 1 · legacy 同构 —— 四节全内嵌

发布目标 → 站点配置 → 发布内容 → 发布操作四节自上而下，与 legacy 一一对应； 内容选择器完整内嵌（五 tab + 搜索 + 勾选树），无弹层。代价是页长 ~4 屏。

✓ 优点

  • 与同步 / 资源子页完全同构（状态卡 + 行流 + 凭据链接行），家族语言统一
  • 右栏一屏半可控；进度永远在置顶卡，发布中不滚出视野

案 3 · 轻两节 + 紧凑内嵌 —— 一屏发布流

目标与站点合并为一节（字段分组、开关内联），内容选择器紧凑内嵌（chips 切五类 + 固定高列表），发布动作就在内容节尾——整页 ~2 屏，配置到发布一条线，无弹层。

三案对比与建议

维度案 1 · legacy 同构案 2 · 状态卡 + 弹层案 3 · 轻两节内嵌
页面长度~4 屏（最长）~1.5 屏~2 屏
内容选择器完整内嵌（24rem+）摘要行 + 弹层（拿足空间）紧凑内嵌（180px 列表）
发布动作 / 进度页底操作节置顶状态卡（进度不滚出视野）内容节尾
与同步/资源一致性中（行流同构、无状态卡）最高（完全同构）低（合并节 + 无状态卡）
配置可发现性高（全部平铺）高（字段网格平铺）中（高级字段折叠）
勾选效率高（就地）中（弹层一步）高（就地，但列表矮）
落地成本低（PublishSelector 换皮直迁）中（选择器进弹层 + 状态卡）中高（选择器紧凑重排）
  1. 建议以案 2 为基底：与同步 / 资源子页完全同构（状态卡轻染置顶 + 行流 + 字段网格 + 凭据链接行），三个「数据」子页形成家族；右栏一屏半可控，进度永远可见；内容选择器在弹层 里拿足空间——legacy 的 min-h 24rem 大组件塞 610px 右栏本就是案 1 拥挤的根源。
  2. 弹层承载走 D-002 口径：内容选择弹层 = feature 级 Dialog（lg 560px 或更宽），内部即 legacy PublishSelector 换皮（五 tab chips + 搜索 + 勾选树 + 作用域），footer「完成 / 完成并发布」让选择到发布零往返；选择状态持续持久化，弹层只是编辑入口。
  3. 案 3 的「发布 18 项」可吸收：案 2 状态卡主按钮文案带计数（「发布 18 项」）， 动作语义自解释；「高级折叠」不建议（basePath 自动推导 / favicon 属低频但一眼可懂， 折叠反而伤可发现性）。
  4. 状态卡三态：云家就绪（ok 淡彩 + 目标摘要 + 上次发布 + 测试连接 / 发布）；发布中 （busy 旋转 + 五阶段 chips + 进度条 + 当前文件 + 取消）；未配置 / 凭据缺失（warn + 指路集成， 本地导出不受阻）。本地导出无测试连接，主按钮为「导出静态站点」（发布 = 选目录）。
  5. 发布语义注记：发布是一次性动作（非持续同步）——增量按内容哈希比对，不设自动发布 / 计划任务；「上次发布」时间来自发布历史（publish_history），首版若不展示历史可从结果 toast 回填状态卡。
  6. 落地锚点：替换 features/settings/sections 的 publish 占位；状态卡消费 executePublish / checkPublishConnection / downloadPublishTemplate 命令与 publish-progress WebSocket 通知；选择弹层换皮迁移 PublishSelector（@/pages 组件按分层红线在域内重建）。
