Button · 方案 C 密集工作台

按钮是工作台的一个命令位：一切为密度让路——md 30 / sm 24、padding 收窄、 反馈 100ms 即达。secondary 是透明底 + line-1 描边（IDE 的 outline 控件），排列再密也不打架； 无投影无位移，按压只是色变——工具不做戏。独有件：按钮内嵌 kbd 快捷键 （按钮即快捷键教练位，与 §7 全局键盘骨架配套）。danger 以 soft 档为主推，实心红只在确认位。 变体集与 A/B 完全相同，差异全在皮。

变体全谱 variants

六档覆盖一个动作的全部「音量」：primary 是唯一主角（每屏至多一枚）， secondary 应答，soft 是不打断阅读的强调，ghost 是语境动作，danger 两档对应 D-011 的危险分级。

disabled 统一 opacity 0.4 + 指针封锁（原生 disabled，不拦截焦点队列）； loading 封锁指针 + aria-busy，文案切换为进行时态——与 ConfirmDialog 现行行为一致（D-011）。

尺寸与图标 sizes × icons

两档高度：md 30（表单 / Dialog 应答区）、sm 24（命中面积下限，02 规范 §7—— 再无余量）。图标 15px stroke 1.75，仅左位；纯图标按钮走既有 IconButton，Button 不做 icon-only。 内嵌 kbd 是本方案独有件：挂在有全局快捷键的动作上（Ctrl+N / Ctrl+E…）。

kbd 在实心底上用 currentColor 半透明描边（不额外引入色）； 次级/soft 底上走 kbd 提示的 group 底口径（02 规范 §2 的既有组合）。 kbd 只在真有快捷键时出现——没有快捷键的动作不装裱。

④ 工具栏（密集排布 + sm 24 档 + danger-soft 主推位）

同一排放下四个动作（A/B 的 28px sm 档到此处已放不下 danger-soft）—— 密度是 C 的核心收益：工具栏塞得下完整动作组，危险动作不必藏进菜单。

行为契约 contract

三方案共用，定稿后随 ui/primitives/Button.tsx 落地； 与 02 规范 §5.3 一致（size sm/md、data-state 驱动、forwardRef、focus-ring 全局口径）。

Tab 焦点环（仅键盘导航显示） Enter 触发（form 内 = submit 语义，与 Dialog 默认应答协同） Space 按下即按压反馈

· loading：aria-busy + spinner + 文案切进行时态，指针封锁（ConfirmDialog 现行行为，D-011）
· disabled：原生属性（不出现在 Tab 队列），opacity 0.4，cursor default
· 动效 100ms ease-out（快于 A/B 的 140ms）；prefers-reduced-motion 下降级为纯色变
· 图标仅左位 15px；icon-only 一律走 IconButton，Button 不设该档
· kbd 位：shortcut="Ctrl N" 可选 prop，有全局快捷键才传
· antd 迁移映射：type=primary → variant=primary；type=default → secondary；type=text → ghost；danger 布尔 → danger 变体

暗账 costs

sm 24 贴着命中面积下限：02 规范 §7 要求 ≥24×24，本方案 sm 档恰好踩线无余量—— 触屏板 / 高 DPI 缩放场景下点击偏紧，密集排布里的误触率需要实测。
12px 字号在部分 Windows 屏上发糊：sm 档 12px 处于次像素渲染的劣势区， 高分屏正常、1080p 缩放 125% 时边缘发虚——密度的代价。
透明底 secondary 轮廓最弱：cream 纸面上它是「凹进的框」，与 Dialog B 的 surface 卡片 同屏时存在感低于 A 的 group 填充与 B 的 surface 亮底——密集收益换可指认性。
