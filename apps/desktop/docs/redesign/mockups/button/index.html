Button 基础件 · 方案导览

已定稿：方案 B · 现代产品（2026-09-18 用户裁决，D-013）——A/C 留档对照。 定稿即 B 原皮落地，无嫁接件：ConfirmDialog 应答区 BTN_BASE 收口偿还（注释里 「Button primitive 落地前在此收口，落地后迁移」的欠账），loading 上收为内建语义 （aria-busy + spinner + 文案切换 + disabled 一体，调用方不再手动拼 Spinner）； ghost 无底色，disabled 单独提到 0.55（0.45 在浅底上几乎不可辨，实机自检修正）。 C 的内嵌 kbd 是可嫁接件，真有带快捷键的按钮位再议（YAGNI，未嫁接）。 Button 是 M0 高频第一件（02 规范 §5.2）。API 面无分歧：变体集六档 × 尺寸 sm/md × 六状态，三份演示页同 API 同行为，差异全在皮：变体集（primary / secondary / soft / ghost / danger / danger-soft）、状态机（hover / press / focus-visible / disabled / loading）、尺寸档、语境样例（Dialog 应答区 / 表单 / 空态 CTA / 工具栏）三页完全一致。

共识：① 每屏至多一枚 primary（主按钮稀缺性是层级语义，不是装饰偏好）； ② 危险必须两档——实心红给确认位、soft 红给列表/工具栏位（对齐 D-011 的 danger 分级精神）； ③ 状态反馈只动 background / border / filter / transform 四类属性（GPU 友好）； ④ focus-visible 才显环（鼠标点击不显、Tab 才显），全局口径不因组件而异； ⑤ icon-only 是 IconButton 的领地，Button 不设该档（命中面积 ≥24×24 由 IconButton 承诺）。

三条形制路线

方案 A · 纸面凸版

Things 3 语感 — letterpress 暗边 · group 下沉次级 · 物理按压
letterpress · translateY
按钮是纸面上的一枚活字。accent 实心带底缘 letterpress 暗边，hover 微浮、 按压下沉 1px、暗边收紧——反馈是物理的。次级按钮不描线，用 group 下沉填充（02 规范 §2 点名的组合），纸的层次靠「沉浮」表达。
  • 手感最强：按压位移是三案里唯一有「按到了」物理确认的
  • 与暖纸视觉方向（direction-a-soft）同源走到尽头——纸感最纯
  • radius 8 / 高度 34 全在既有词表内，零 token 增补
  • 暗边是派生色（color-mix）——tokenContract 要增补或组件层收口
  • cocoa 下 group 次级是「洞」不是「纸」，密集表单里可指认性弱
适用：认同「这个应用是纸的」——写作、笔记、阅读语境的身份感。

方案 B · 现代产品 已定稿

Linear 语感 — accent 实心微投影 · surface 描边次级 · 光感反馈
brightness · shadow
按钮是产品表面的一件控件。primary 是 accent 实心 + 微投影（浮起 1px 的光感），hover 加深一档；secondary 是 surface 亮底 + line-1 描边；soft 是 accent-soft 平底。 反馈是「光」的（brightness / 阴影），无位移。
  • 语言连续性最强：ConfirmDialog BTN_BASE 就是这张皮，落地即替换零迁移
  • 与 Dialog B（D-011）、Menu B 药丸行（D-010）、Toast 卡片同一浮层家族
  • soft 档最正统：工具栏次级强调的中间音量
  • radius 10 是任意值（词表只有 8/12/16）——要么增补要么收敛
  • 无位移少一档手感；cocoa 上投影浮起感减弱需分主题调
适用：认同「Dialog 跟产品走」（D-011 的裁决逻辑顺延）——SaaS 产品语感的连续性。

方案 C · 密集工作台

VS Code 语感 — 透明底 outline 次级 · 内嵌 kbd · 密度优先
dense · 100ms · kbd
按钮是工作台的一个命令位。一切为密度让路：md 30 / sm 24、padding 收窄、 反馈 100ms 即达。secondary 是透明底 + line-1 描边（IDE outline 控件）；无投影无位移， 按压只是色变——工具不做戏。独有件：按钮内嵌 kbd 快捷键。
  • 密度收益：工具栏塞得下完整动作组（含 danger-soft，不必藏进菜单）
  • kbd 教练位与 §7 全局键盘骨架天然配套——可发现性最好
  • Dialog footer 纵向开销省 8px+，长表单收益累积
  • sm 24 贴命中面积下限无余量；12px 字在 1080p/125% 缩放下发糊
  • 透明底 secondary 轮廓最弱，与 Dialog B surface 卡片同屏时存在感低
适用：批量操作、复习队列、多按钮并排的主战场——「专业工具」的身份感。

决策建议与 API 草案

怎么选

  1. 看已定稿家族的连续性定身份：Dialog B（D-011）裁决时认定「对话跟产品走」，浮层家族 （Menu B / Toast / 命令面板）全是现代产品语言。若这条裁决逻辑顺延到控件层，B 的连续性最强 且 ConfirmDialog 零迁移；若认为「按钮是纸面的一部分、对话才是产品的」——纸感归控件、产品感归浮层， 则 A 成立（层与层两种身份，需接受这个张力）；若产品主战场是批量操作与复习队列，C 的密度与 kbd 可发现性最实用。
  2. 感受三案的手感差异再定：三份演示页的变体全谱区都可真实悬停/按压——A 的位移、 B 的光感、C 的快与密，是三种「按下去的感觉」。控件的手感会乘以使用频次，值得亲手试一遍。
  3. ConfirmDialog 换装成本要计入：选 B 是原样替换；选 A/C 则应答区皮随之换装 （结构不变，34→30 对 C 还省纵向空间）——不是阻塞项，但要在定稿提交里一并做掉，不留两套按钮并存。
  4. 落地即收口：定稿后 Button 进 ui/primitives/（03 指南 §9 任务清单）， ConfirmDialog / Dialog 的 BTN_BASE 同提交迁移；token 增补（accent-edge 或 radius 档）走 tokenContract + tokens.css 同步，theme-parity 守护；实现提交同步 03 指南组件小节与 DECISIONS.md（编号顺延）。

ui/primitives/Button API 草案

<Button variant="primary" size="md" icon={Plus} disabled={!name} loading={busy}>创建</Button>
<Button variant="secondary" onClick={close}>取消</Button>
<Button variant="danger-soft" size="sm" icon={Trash2}>删除所选</Button>
<Button variant="primary" block icon={Plus}>新建卡片</Button>              // 空态 CTA
<Button variant="primary" shortcut="Ctrl N">新建卡片</Button>               // C 独有件（可嫁接）

interface ButtonProps extends ComponentProps<"button"> {
  variant?: "primary" | "secondary" | "soft" | "ghost" | "danger" | "danger-soft";  // 默认 secondary
  size?: "sm" | "md";                // 默认 md
  icon?: LucideIcon;                 // 仅左位，16px；icon-only 走 IconButton
  block?: boolean;                   // 满宽（空态 CTA）
  shortcut?: string;                 // 内嵌 kbd 位——仅真有全局快捷键时传
  loading?: boolean;                 // aria-busy + spinner + 文案切换 + 指针封锁
  loadingText?: string;              // loading 时的文案（默认进行时态）
}
// antd 迁移映射：type=primary → variant="primary"；type=default → "secondary"；
//   type=text → "ghost"；danger 布尔 → "danger" / "danger-soft"（按位置分档）；
//   type=link → 文字链（不建 variant，行内动作走 link 语义，PREFERENCES 另记）
// 层级纪律由评审把关不进 API：每屏至多一枚 primary
实现映射：三份演示页的按钮 CSS 皮即组件 Tailwind 类的蓝本；状态矩阵与语境样例 直接移植为 ui/__tests__ 的守护用例（disabled/loading 行为、focus-visible 口径）。
