推荐与决策点

  1. 裁决记录 终选：2026-09-19 用户裁决取 A、B 两案结合，终选结合稿 II（点 + 软底），色点落为可选能力（showDot prop，默认开；gray 恒无点）；结合稿 I（彩描边）与 A/C 原案页保留为评审留档。下方 2–4 条为评审期论证，留档备查。
  2. 原推荐 A 为基线：与 D-017/018/019 三连定稿的「经典描边」语言连续——Tag 与 Input/Select/Checkbox 同皮，工具栏/过滤条/表单混排零违和；色感收进色点让 database 标签列密集排布不吵；零新 token、零 API 迁移。B 的扫读分色优势主要兑现在「状态列」这一窄场景，代价是全场景彩度与家族断裂；C 的密度优势兑现于「行内值」窄场景，代价是独立徽章位失效。
  3. 若 database 选项列体验优先，B 是合理选择（现实现语言的精修、零迁移）——接受值展示与控件分语言。
  4. 无论拍哪案：× 的热区 24 与 focus-ring、7 色板同源 ColorSwatch、truncate、单尺寸——已锁共识不变；antd 的 bordered/icon/Clickable/Checkable 一律不迁。
  5. ColorSwatch 联动：色板选择器（同文件下一件）沿用胜选形制的色语言——B 胜选则色板按钮同 soft 底，A/C 胜选则同 solid 点语言（swatch 用色块本身，不受影响）。
三页均双主题可交互（cream/cocoa 切换），含同一组真实场景（database 表格 / 文章元数据 / 过滤条件条）便于横向对比。
