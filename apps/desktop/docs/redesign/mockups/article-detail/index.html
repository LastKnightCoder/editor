第四轮 · A4 静 当前推荐

A4

静 · Quiet（四轮反馈的收敛形态）

单栏沉浸页 + 两个轻入口 · 零面板零工具条

撤掉右栏资料面板（第三轮反馈：太复杂），目录回到正文右缘 sticky 形态（此前认可）。速切器融入标题栏面包屑——当前标题即切换按钮（VS Code 面包屑下拉范式）。修订一：目录上方不放控件行（否决）。修订二（对齐 Notion/语雀）：元信息行尾模式文字链与 banner 内「更多」胶囊否决——改为内容区右上角固定动作区（语雀「编辑」+ Notion「Share/⋯」的共同范式）：「编辑/预览」ghost 文字钮 +「⋯」更多菜单；封面编辑改 Notion 式 hover 封面中央浮出「更换封面」。标签在正文末、播客操作在播客条、时间字数在 hero 元信息。

＋ 动作区位置与 Notion/语雀直觉一致；工具不进 banner、不混元信息；页面其余零显性控件 － 动作区与正文列右缘留白的对齐需窄窗适配（hero 变宽时避免重叠）

第三轮 · C2 精炼 留档

C2

精炼 · Refined（第一轮 C 基底 + 三轮反馈收敛）

零顶部工具条 · 就近收纳

核心裁决：整页没有任何顶部工具条。工具按「就近收纳」重排——编辑/预览 segmented 浮在正文右缘（贴着作用对象）；速切器（认可的 Switcher 思路）在右栏顶部，左栏列表退役；制卡/复制/源码/演示/沉浸/窗口收进右栏「动作」区；底部只留纯状态（已去 Esc 提示）；hero 与正文顶播客条保留（上轮认可形态）。

＋ 顶部彻底干净，工业感消除；C 的信息收纳 + 用户认可元素全部保留 － 右栏依赖宽屏（窄窗需折叠）；模式切换可发现性低于顶栏

第二轮 · A 系演进 留档

第一轮倾向 方案 A（hero 封面 + 文头部播客保留）。四点反馈：① 底部状态栏操作过多，应只显示状态；② 顶部滚动进度条删除（旧版遮丑方案）；③ 侧栏收起后无法展开、且正文不再水平居中；④ 左侧已有系统侧边栏，质疑文章列表是否必要。以下三版共同落实 ①②③，并就 ④「文章列表的形态」给出三种回答：

A1

聚焦 · Focus

无常驻列表 · Medium/Substack/Notion 页面范式

详情页只做单篇：浏览靠 Esc 返回列表页，连续阅读靠文末「上一篇/下一篇」卡。写作视野最大化，页面职责最纯粹。

＋ 最沉浸；页面栈语义最顺（列表页就是列表） － 多篇来回切换要进出两次；管理动作全部回列表页
A2

抽屉 · Drawer

列表按需唤出 · VS Code 侧栏范式

列表降为抽屉：默认收起、记忆状态，工具栏「列表」开关随时唤出/收起（160ms 推挤动画）；正文列恒居中，开合只平移版心。列表能力全量保留。

＋ 沉浸与效率兼得；旧版列表习惯零损失 － 多一层开关心智；唤出时正文平移半格
A3

速切 · Switcher

列表即浮层 · 书籍章节选择器/IDE 快速打开范式

无常驻列表，工具栏左侧「当前文章 ▾」速切器：点开浮层（搜索 + 置顶 + 按月分组，条目 ⋯ 承接置顶/导出/删除/窗口）。hero 做出血变体（960px 比正文列宽、同轴心）保留卷首气势。

＋ 切换最快（一次点击直达任意篇）；常驻成本归零 － 浮层一屏只见列表局部（无抽屉的扫视连续性）

第一轮三方案 留档对照

方案 A

卷首特辑 · Feature

旧版骨架的精修演进 · 工具留底部状态栏

封面 hero 保留并精修（21:9 + 墨色遮罩 + 标题左下），九宫工具带沉在底部状态栏按语义分组，右侧 sticky 目录。旧版肌肉记忆零成本平移。

＋ 封面仪式感最强，杂志卷首气质；迁移成本最低 － 底部图标带较密；封面占一屏首屏（阅读入口深一拍）
方案 B

纸页 · Paper

写作软件范式 · 工具上移为顶部文档工具栏

封面去 hero 化降为可选文首窄图，标题落纸面（墨字）；顶部工具栏按「模式/视图/提取/生成/场景」分组带文字标签，底部状态栏退化为纯状态（保存/进度/Esc）。

＋ 安静纸面、affordance 最好（图标+文字）；状态栏职责最清晰 － 封面叙事弱化；顶部工具栏常驻占一行竖向空间
方案 C

三栏工作台 · Studio

属性面板范式 · 辅助信息全部右栏收口

列表 | 正文 | 资料栏三栏。目录/信息（封面缩略图+更换）/标签/播客/动作（制卡·复制·源码）收进右栏，中央列只剩纯正文；封面从版面元素降为元数据。

＋ 信息密度最高、正文视野零干扰；资产管理动作一栏全见 － 与「文章是作品」的封面叙事冲突；宽屏依赖强（窄窗需折叠右栏）

裁决记录

第四轮反馈（2026-09-19）：C2 右栏（速切器+目录+详细信息面板）「太复杂」否决；目录用之前正文右缘 sticky 的形态；速切器思路仍认可 → 产出 A4 · 静（plan-a4-quiet.html）。修订一：目录上方不放控件行（否决）。修订二：元信息行尾「预览」文字链与 banner 内「更多」胶囊（否决：位置奇怪）→ 改 Notion/语雀式右上角动作区。修订三：取消只读态（不做预览/编辑切换；legacy readonly 参数若保留由页面 params 决定，无 UI 入口）；右上角只剩孤零零 ⋯（否决）→ 标题栏右端 ⋯。修订四：titlebar 心智是搜索+窗口管理，用户想不到（否决）→ 底部状态栏最右端：底栏是本页唯一被认可的固定状态区（字数/协作/阅读% 所在），右端入口是 VS Code/Office 状态栏通用惯例。修订五：三点 ⋯ 图标无自解释性（易读成省略号，否决）→ 改「更多 ⌃」文字按钮（VS Code 底栏「UTF-8」式文字语言），菜单向上弹出。修订六：「查看源码」移除（legacy debug 遗留功能，裁决不迁移）——提取组仅剩复制 Markdown / 复制公众号格式。封面编辑保持 Notion 式 hover 中央浮出。旧功能对照见该文件注释头。

第三轮反馈（2026-09-19）：Switcher 思路认可；A1/A2/A3 顶部按钮堆「太工业产品、不是面向用户的精致产品」；去掉状态栏 Esc 返回提示；在第一轮 C 基础上调整 → 产出 C2 · 精炼版（plan-c2-refined.html）。工具安置原则从「集中工具条」改为「就近收纳」：模式切换贴正文右缘、切换/生成/提取动作进右栏、状态沉底栏、导航留标题栏——页面顶部零工具条。

第二轮反馈（2026-09-19）：倾向方案 A（hero 封面与文头部播客保留）。① 底部状态栏应只显示状态（字数、协作人）——A1/A2/A3 已把工具全量上移顶部文档工具栏，底部只留「字数 · 协作 · 已保存 | 阅读% · Esc」；② 顶部滚动进度条删除（后续版本均已移除）；③ 侧栏收起后无法展开 + 正文不居中——根因是旧稿正文用 flex 组居中（正文+目录整体居中导致正文偏轴）且展开钮 absolute 定位错位，新版版心改为 grid [1fr 720px 1fr] 恒居中、目录独立贴正文右侧，列表开关固定在工具栏；④ 文章列表形态待裁决（见上三卡）。

关于「左侧已有系统侧边栏，还要不要文章列表」的参照系：双侧栏常驻见于「管理器型」应用（Obsidian 文件列表、VS Code 资源管理器、邮件客户端）——列表本身是主要工作对象时才值得常驻；「内容型」应用（Medium、Substack、Notion 页面、Bear）默认无常驻列表，靠返回 + 快速切换。文章详情页的工作对象是这一篇，列表的职责（浏览/筛选/管理）已由文章列表页（A3 月刊）承担——所以三版都取消了常驻列表，差异只在「要不要给切换留快捷通道、留哪种」。

共同基线（三版一致，评审不必重复比）：暖纸 token（tokens.css 真实取值）；标题栏后退/前进 + 面包屑「文章 / 标题」；Esc 返回列表（页面栈仲裁）；mock 数据与列表页 A3 同口径——当前文章即列表 mock 的 id=1「为什么写长文要先搭骨架」（3,482 字 · 写作/方法论 · banner 派生色 grad-0 · 置顶），封面/插图均为派生色示意（真实场景为 bannerBg 本地图）；播客条为「已生成播客」态示意；hero 封面 hover 换图、标题 hover 行内编辑、标签行、目录 sticky 高亮均保留。

编辑器本体（Slate 工具栏/行内格式）不在本轮范围：mock 正文为编辑器内容的静态投影，仅定版面；编辑器迁移时由 @tau/editor 接管（D-015）。
