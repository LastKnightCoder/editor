Toast 基础件 · 方案导览

三个设计维度：位置（顶部居中 / 右上 / 右下 / 底部居中，可配置）、类型（成功 / 错误 / 警告 / 信息 / 加载中）、样式流派。三份演示页共用 tau 双主题（cream / cocoa）与同一套语义色 token（ok / danger / warn / info），每份都是完整可操作的 playground——触发各类型、切换位置、堆叠、悬停暂停、加载中转成功（promise 形态）全部可玩。

业界参照

产品形态默认位置值得借鉴
Sonner（shadcn 生态默认）轻量胶囊右下（四角可配）悬停冻结倒计时；promise 形态（loading→成功/失败）；堆叠展开

Raycast居中 HUD窗口居中偏上单例替换、快速退场——与键盘操作绑定的「结果回声」

共识：① 位置必须可配置（不同场景的注意力位置不同）；② 类型语义色收敛在图标/色块，不做整块彩色底；③ 悬停暂停自动关闭是桌面端刚需（用户可能正想点动作按钮）。

三个方案

方案 A · 轻量内联胶囊

Compact Pill — Sonner / Linear 流派
轻确认不打断。36px 单行胶囊：图标（语义色）+ 一句话 + 可选动作 + 关闭。无标题无描述，一闪而过。
  • 注意力成本最低，四个位置都成立（居中/四角）
  • promise 形态天然支持（loading→成功）
  • 放不下解释和多个动作，复杂反馈表达不了
适用：已保存 / 已复制 / 网络异常一句话 / 命令执行确认。默认位置建议 底部居中或右下。

方案 B · 通知卡片

Notification Card — macOS / antd 流派
带上下文的小通知。344px 卡片：图标色块 + 标题 + 两行描述 + 动作按钮（次要/主要）+ 底部同色倒计时条。
  • 信息密度最高，可解释、可操作（重试/查看）
  • 倒计时进度条让「何时消失」可预期
  • 体量重，居中会遮挡内容，只适合右上/右下
适用：同步结果 / 剪藏失败可重试 / 协作冲突提示。默认位置建议 右上。

方案 C · 居中结果浮层

Center HUD — Raycast 流派
操作的结果回声。窗口居中偏上：大圆图标 + 居中短语，2.2s 快速退场，单例替换不堆叠，点击任意处关闭。
  • 阅读成本最低、退场最快，与键盘流/命令面板天然搭配
  • 单例语义免去堆叠管理，视觉永远干净
  • 不可堆叠、不适合决策类信息；频繁触发会闪烁替换
适用：已复制 / 已切换主题 / 已开始专注——命令面板与快捷操作的执行确认。

决策建议与 API 草案

怎么选

  1. 只做一个通用形态：选 A（轻量胶囊），默认底部居中或右下——覆盖 90% 场景，位置参数化后错误/通知也能用；后续需要重通知时再补 B。
  2. 双形态组合（推荐长期形态）：A 做全局默认（可配位置）+ C 补命令面板/快捷键回声（单例替换）——命令面板动作目前没有反馈通道，C 正好补位；B 留给「需要解释和操作」的通知场景（同步/冲突），可等具体功能出现时再引入。
  3. 信息密集场景先行（如即将做同步/冲突提示）：则 B 先行，默认右上。

ui/primitives/Toast API 草案（落选方案不入库）

toast.success("已保存", { description?, action?, position?, duration? })
toast.error / toast.warning / toast.info / toast.loading   // loading 返回 id，可 toast.resolve(id, "完成")
toast.promise(promise, { loading: "同步中…", success: "完成", error: "失败" })

position: "top-center" | "top-right" | "bottom-right" | "bottom-center"   // 全局默认可配，单条可覆写
// 语义色映射 token：ok / danger / warn / info（类型只落图标，与主题 AA 对比度由 token 保障）
// 通用行为：悬停冻结倒计时 · 上限 4 条 · Ctrl+K 面板打开时让位（面板 z 更高）
// 接入点：app 壳层挂载 ToastHost（同 SearchPalette 模式），Esc 不关 toast（浮层注册表只登记阻断后退的浮层）
实现映射：A/C 已验证的交互细节（悬停冻结的剩余时间计算、promise 转换、堆叠上限、纯 CSS 倒计时条）可直接从演示页 JS 移植；toast 属于 ui/primitives 基础件（03 指南 §9 任务 2 清单内），不涉及 DECISIONS 裁决。
