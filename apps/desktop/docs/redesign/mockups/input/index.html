Input 基础件 · 方案导览

待裁决：分歧在 框的形制语言 × 装备能力。已锁共识：受控 value/onChange + 原生 input 透传、尺寸 sm/md、错误态正源是原生 aria-invalid（直通换 danger 描边，无 status prop——判定/文案/touched 策略归表单层，Input 只内置视觉态）、placeholder 用 ink-3、数字 tabular-nums、focus 纪律遵循全局（--tau-focus-ring，除非形制本身主张更轻）。Input 只专注输入的基本能力——FormField 不在其中（label/描述/错误的包装是表单范式，归 ui/patterns 的 FormRow，02 §5.1 规划位；Input 靠原生透传天然配合）。A 是 2026-09-17「表单控件 = surface 亮底 + line-1 描边」裁决的完整演绎；B/C 是对这条裁决的两种不同态度（槽形 / 线形）；D 形制同 A、分歧在能力面（槽位 / addon / 特化形态）。

四条形制路线

方案 A · 经典描边

基线形 — plan-a-outline.html
surface 亮底
line-1 描边
focus: accent + 3px ring
lead icon · 清空 × · 计数器
↔
与 Select/DatePicker 触发器同皮
2026-09-17 裁决的标准演绎。输入框是浮起物：surface + line-1 + focus ring，与 Select / DatePicker 触发器同族同皮——表单里控件与触发器混排时视觉完全连续。六态矩阵 + 前后缀 + 清空 + 计数器 + NumberInput 校验齐备。
  • 与既有控件家族零形制差（混排无违和）
  • 白卡上同底靠描边显形（D-009 口径）
  • 错误/只读/禁用语义清晰（只读沉 group 底）
  • 大表单十几个字段排开时描边线噪偏高
适合：新建表单、对话框、与选择控件混排的一切场景——默认答案。

方案 B · 柔和填充

低线噪 — plan-b-filled.html
group 底（槽）
无描边
focus: 浮出为框
hover: 底加深一档
编辑 = 浮出，非编辑 = 沉底
输入框是「槽」不是「框」。平时 group 底无描边，focus 时浮出（accent 描边 + surface 底 + ring）。大表单线噪归零，层级全靠亮度——正合宪法第 2 条。
  • 设置页长表单的视觉最安静
  • 「编辑中」的存在感极强（唯一的框）
  • 与描边形的 Select/DatePicker 触发器混排形制不一致
  • 推翻 2026-09-17 裁决需记录 DECISIONS
适合：设置页（15 子页）这类纯字段流；若采纳需裁决「触发器是否同步改槽形」。
打开方案 B

方案 C · 下划线行内

最轻形 — plan-c-underline.html
一条 2px 发丝线
无框无底
focus: 线转 accent（无 ring）
h30 / h24 两档 · 行内编辑
点文本 → 变输入框
编辑既有值的最小侵入。无框无底只有一条线，focus 转线不弹 ring——就地编辑而非表单事件。主场是设置两栏流、数据库行内改值、属性面板。
  • 整页安静得像属性清单
  • 行内改值零仪式感（Enter/Esc 就地提交还原）
  • 不适合新建表单（空表单里线找不到输入边界）
  • 与控件家族形制差最大；无 ring 违反全局焦点纪律需裁决
适合：作为「表单用 A、清单用 C」的双轨补充，或整体放弃。

方案 D · 装备化

能力全集 — plan-d-equipped.html
形制同 A
lead 槽（icon/标签）
trail 槽（单位/kbd）
动作位：清空/显隐/步进 −+
addon：框外按钮连体
特化：Password / Number / 计数器
Input 是「输入容器」不是「一个框」。形制不变（同 A），把周围能挂什么做成完整拼装系统：槽位挂静默信息、动作独立成位（命中 ≥24×24）、addon 承担框外按钮——框不是工具栏。
  • FilterBar/搜索/数值调节一步到位（消费点真实存在）
  • 拼装纪律成文，避免各页面自由发挥
  • 能力面最大：每多一个槽位都是长期 API 维护面
  • 若 A+B 里已够用，D 的 addon/特化是超前投资
适合：与 A 合并采纳——A 定形制、D 定能力（形制无分歧，能力按需裁）。
打开方案 D

组合建议（供参考，裁决权在评审）

  1. A 定形制（与既有控件家族同皮，2026-09-17 裁决延续），D 定能力——两者不冲突：A/D 实为同一形制的基础档与装备档；
  2. B 的槽形若被采纳，需同步裁决 Select/DatePicker 触发器是否跟随改形（全族一致 vs 双轨语义），并记 DECISIONS；
  3. C 保留为行内编辑特化（variant="inline" 或独立 InlineField），仅用于设置流/数据库行内——不进默认表单；
  4. 能力按需裁：清空/计数器/lead icon 是刚需先落；addon 与 Password 特化等真实消费点出现再进。

裁决清单（定稿前需要拍板的点）

  1. 形制：A 描边（延续裁决）/ B 槽形（需裁决触发器跟随）/ 双轨（表单 A + 行内 C）；
  2. B/C 若涉及 focus 无 ring：C 的「线转色不弹 ring」违反全局焦点可见纪律（02 §7），需明确豁免范围；
  3. 装备 API 形态：槽位走 props（lead/trail）还是复合子组件（<Input.Leading>）——建议 props（Select 数据驱动同款心智）；
  4. Password / NumberInput 特化：Input.Password 复合命名 vs 独立 props（revealable）；
  5. addon 组合：进 Input 的 API 面（<InputAddon> 包装）还是留给调用方用 flex 拼；
  6. readonly 形：A 的「去描边沉 group 底」vs 保持描边只去 focus——与 B 的语义有交叠，需一并定；
  7. 计步器步长：NumberInput 的 step 默认值与精度规则（0.5 步长的展示格式）。
