三个方案

方案 A · 组件检查器

Inspector — Storybook 式双栏
一次审一个组件（深度优先）。左侧组件树按域分组；右侧「档案页」：职责 → 可交互画布（背景 4 档可切）→ 状态矩阵（锁定标本）→ API 备忘。
  • 单组件沉浸审阅最舒适，信息密度与结构最接近终态
  • 与未来真实落地（showcase 路由 / Storybook）信息架构一致，迁移成本最低
  • 全局概览弱：不知道「有什么」之前得先点树
  • 跨组件对照（如两个浮层的阴影/圆角一致性）要来回切
适用：逐个组件精审、写设计评注；未来演进为路由化 showcase 的骨架。

方案 B · 全景画廊

Gallery — 单页长滚动平铺
一页看全（广度优先）。所有组件 × 全状态平铺为「标本卡」网格：卡头状态名（mono）+ 锁定态标本 + 规格注记；顶栏锚点直达、标本底色全局四档。
  • 全局概览与跨组件对照最强，Ctrl+F 直接搜状态名
  • 滚动对照截图审阅方便；新增组件 = 追加一节，维护直观
  • 页面长，单组件沉浸感弱
  • 主题仍靠顶栏切换，对照要靠记忆
适用：快速纵览体系全貌、设计走查清单式核对、给新人当「体系地图」。

方案 C · 主题对照台

Split Lab — cream × cocoa 同屏
双主题同屏，不做切换。cream / cocoa 左右并排渲染同一组件；行头「验收」复选 + 顶部进度条，把样板间当双主题验收工作台。
  • 主题同构验证零记忆成本：反相配色 / 阴影档 / 透明交互底 / 硬编码色一眼现形
  • 已替你暴露真问题：YearHeatmap 陶土橙未随主题调整，两列同值即证
  • 单主题画布宽度减半，状态覆盖不如 A/B 全
  • 「主题」维度优先于「状态」维度，日常查状态不顺手
适用：新增/调整主题后的同构验收、AA 对比度走查、主题债清点。

  2. 落地第 2 步：已完成（2026-09-17，D-005）——独立 Vite MPA 落地：根目录执行 pnpm showcase 即在端口 6199 打开浏览器（纯浏览器、不依赖客户端），展品全部为 ui/primitives 真实现（零复刻漂移），代码在 apps/desktop/showcase.html + src/showcase/。本目录三份 HTML 降级为视觉定稿稿留档。
  3. 维护义务（防腐化）：与 03 指南文档保鲜同口径——新增/修改 primitives 或 token 时同一提交同步样板间对应档案；样板间与源码不一致视同文档腐化。

注意：HTML 内的组件为「复刻」（手写 CSS 对齐源码取值），存在漂移风险——静态稿用于定形态，第 2 步落地后即被真组件取代。

落地路径（定稿后）

HTML 定形态 → Vite 内真组件 → 演进为路由化 showcase

  1. 当下（本轮）：选定方案后，该 HTML 作为样板间 v1 留在 docs/redesign/mockups/showcase/，与其它 mockup 同规约（视觉参考，非导出源）。
  2. 短期（低成本，建议尽快）：在 apps/desktop 增设 showcase 入口（如仅开发构建暴露的路由页），直接 import ui/primitives/* 真组件渲染——复刻漂移归零，新组件自动纳管；主题切换直接复用 themeStore。锁定态可用极小 wrapper（如 className="is-hover" 注入或组件加 data-locked 支持）。
  3. 中期：若组件量大（>20）或需要独立部署/评审链接，再评估引入 Storybook/Ladle；当前 8 个档案规模，自建 showcase 页足够（YAGNI）。
  4. 维护义务（防腐化）：与 03 指南的文档保鲜同口径——新增/修改 primitives 或 token 时，同一提交同步样板间对应章节；样板间与源码不一致视同文档腐化。
