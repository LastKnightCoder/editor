DatePicker 设计稿 · 方案 B 范围主场

复合面板 · 预设 + 双月 + 底栏确认 —— 范围不是两个单日期的拼装，而是一次查询意图的表达

面板解剖 · 静态展开（范围形态）

  • 1预设列：业务高频一步到位（今天 / 本周 / 最近 30 天…），即选即定并关闭
  • 2双月并排：跨月范围不翻页——左 ‹ 右 › 承载翻月，中间以 line-2 弱分隔
  • 3悬停预览：点下起点后，鼠标扫过的区间打 accent-soft 底——选错在提交前就看得见
  • 4端点实底：起/止 accent 实底 + ink-inverse，中段只有 soft 底（色彩表意，不装饰）
  • 5底栏摘要：「9月12日 – 9月19日 · 共 8 天」——提交前最后一眼确认
  • 6显式确认：清空 / 确定两个动作；确定前 onValueChange 不触发（范围选错代价高）

单日期退化形态 · 同一结构收起两侧（B ⊃ A）

不传 presets、range 时：预设列与底栏收起、单月、恢复 即点即定——就是方案 A 的形态。也就是说 B 不是第二个组件，是同一结构的 「范围扩展态」；单日期 API 面与 A 完全一致。

复合面板（范围主场）

预设列 + 双月日历 + 底栏确认：手选范围走预览 → 摘要 → 确定三道闸， 预设与单日期退化态即点即定。presets 数据驱动（业务传入，组件不内置业务词表）。 代价：面板宽（约 640px）、结构最重——只有「范围」消费点才配这个重量， 单日期场景请让它退化。
试试：点一个起点后扫过区间看预览；点预设即选即定并联动统计； 退化形态点日期即提交；右上角切 cream / cocoa。
