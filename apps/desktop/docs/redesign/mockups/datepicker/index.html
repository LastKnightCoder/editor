DatePicker 基础件 · 方案导览

本轮已出方向：以方案 A 为基座（经典月历 · 即点即定 · 钻取导航），扩展能力走 prop——presets 预设行（日历下方、内容使用方决定）与 precision="minute"（底栏时刻区 + 15 分钟时刻网格 + 确定提交，取代 antd showTime）；按「值形状」拆两个导出 DatePicker / DateRangePicker（B 形态并入，共享日历引擎 / 弹层契约 / 触发器），时间与预设不另立组件。方案 A 演示页已升级为 A+（含全部扩展演示）。四页共用同一触发器家族与弹层三件套（surface 最亮 + shadow-float + radius-lg，D-004 mini 引擎定位）。已锁共识：02 §5.2 已定 DatePicker = 弹层日历面板（M2 前），API 契约走 §5.3（value/onValueChange + 浮层 open/onOpenChange），日期基座 dayjs（legacy 已在用）。

打字是第一通道。触发器即输入框，边输边解析；候选条实时投影解析结果；日历退居确认与兜底。词表白名单（相对日 / ±n 天 / 周X / 月日 / 绝对日期），不认识安静报 danger——不做自由 NLP，猜错的日期比报错贵。

已定向方案（2026-09-19 评审）与组合建议

  1. A 为基座并升级 A+（已定向）：即点即定 + 钻取保留；presets 预设行（日历下方、数据驱动、即点即定）与 precision="day" | "minute"（值格式与提交模型联动：day 即点即定，minute 时刻区 + 确定提交）走 prop，不另立组件；
  2. 按值形状拆两个导出：DatePicker（value: string | null）与 DateRangePicker（B 形态并入，value: [string, string]），共享日历引擎 / 弹层契约 / 触发器 / dayjs 值协议；可暴露 DatePicker.RangePicker 别名让 legacy codemod 零改动；
  3. C 的解析层作为 inputMode 候选增强：词表白名单先行（相对日/±n/周X/月日/绝对日期六类），范围输入 M1 再议——待行内输入消费点出现再裁；
  4. D 挂起，等行内改期消费点真实出现再裁——26px 命中临界设计需要真实使用数据背书；
  5. 纯时刻（TimeRecordView）暂缓：唯一独立值形状（HH:mm）但消费点仅一个；出现迁移需求时再立独立 TimePicker 原语，复用同一时刻网格。

裁决清单（定稿前需要拍板的点）

  1. 默认形态尺寸：A 的 276px / 32px 格，还是向 D 方向收紧一档（248px / 28px 格）？
  2. 范围承载：已定向——DateRangePicker 独立导出（B 形态并入，同引擎），不做 A 的 shift 点选扩展；
  3. 提交模型边界：已定向——单日期即点即定、手选范围显式确认、minute 精度显式确认（预设一律即选即定）；
  4. 输入通道：C 的词表是否进 M2？「下周三」按周一起始的语义（本周已过 → 下周）是否符合用户直觉？
  5. 时间输入（antd showTime 对应物）：已定向——precision="minute" + A+ 底栏时刻网格（15 分钟步长，timeStep 可调）；任意分钟键入随 inputMode 一并再议；
  6. 周起始确认：周一（dayjs zh-CN 现状）——涉及跨周预设语义，定稿后写进 03 指南。
  7. 界外日显隐：四方案均显示（ink-3 参与导航）；若嫌噪可改为仅相邻月补位。
  8. 禁用日期 API 名：isDateDisabled(d: string)（string 入参，业务侧零 dayjs 依赖）是否接受？
