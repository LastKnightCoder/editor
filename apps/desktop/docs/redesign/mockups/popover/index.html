Popover 基础件 · 方案导览

已定稿：方案 B · 现代产品（2026-09-18 用户裁决，D-013）——A/C 留档对照。 定稿实现已落地：ui/primitives/Popover.tsx（Header/Body/Footer 复合组件）， 公共底盘四件同提交抽取（anchoredPosition 更名 / useAnchoredPosition / FloatingArrow / mergeRefs / useLayerDismiss），样板间已有档案。 Popover 是锚定式可交互内容浮层——非模态、点击触发、内容任意（说明卡 / 过滤器组 / 色板 / 成员卡 / 卡片预览）。家族分工已经划好（D-003 / D-004 文件头口径）：Tooltip 管瞬态说明 （hover / focus、不可交互、无 Esc），Menu 管命令面板，Select 管表单值选择，Dialog 管 模态决策，Toast 管回执；Popover 收下中间最大的一块——「点了才出现、里面可以继续操作」 的锚定内容。技术底盘不是分歧点：定位复用 D-004 引擎（第四家）、Esc 走焦点链 LIFO 自消费（同 D-007/D-010/D-011）、触发 click 内建（不设 trigger props——hover 说明归 Tooltip， antd 的 trigger="hover" 是历史包袱，迁移语义不损失）。与 Tooltip 的公共底盘 抽离清单（见下节）已随实现兑现。三份演示页同内容、同行为、共引擎，差异全在皮。

共识：① 非模态是身份——不遮罩、不圈闭 Tab、light dismiss；② 箭头是指向性语言， 选了就要贯穿（A 短梯形 / B 菱形 / C 无箭头靠位移对齐）；③ 内容宽度自适应锚内容（不是下拉的 同宽默认）；④ 触发器语义 = click（hover 归 Tooltip、右键归 ContextMenu）； ⑤ antd 迁移面：title/content → 头行/正文、placement 12 向 → 同名直映、trigger hover → 用 Tooltip 重接。

公共底盘：Popover 与 Tooltip 能抽什么（本稿重点）

定位引擎早已公共（tooltipPosition.ts，Tooltip/Select/Menu 三家用，D-004）。 真正的账在定位引擎之外：跟随逻辑 / 箭头几何 / ref 合并在三个文件里各有一份近似实现， Popover 落地时会出现第四份——按「两例交集才抽」（D-007）的既有原则，这次是抽取窗口。

外点关闭 + 互斥useDismissableLayer（草案名） 两套：Select 手写单容器判定；useMenuTree 多容器登记 + 模块级互斥单例（Menu 语义） 从 useMenuTree 泛化：多容器登记照搬；互斥放宽为「顶层锚定浮层互斥、嵌套浮层共存」（popover 里开 Menu/Select/二级 popover 是常态）；Menu 特有语义留在 Menu
受控 open 契约 全家族既有口径（§5.3：open/onOpenChange，受控即接管时机） 直接沿用——这是 props 约定，无实现可抽

有意不抽的两件：① hover intent（450ms 进入 / 400ms 重开免延迟）——Tooltip 特有的 瞬态意图判定，Popover 是 click 语义，没有对应物；② 触发器事件注入（Tooltip 的 pass() 透传 / Menu 的 injected）——事件集不同（hover+focus vs click+键盘开合），强行合并会造出「参数选模式」的 复合体，违反 KISS；协议照 Menu 的注释文档化即可（元素必须透传 props 与 ref）。
抽取动作全部发生在 Popover 实现提交内（一处一提交原则）；三份演示页的 mini 引擎就是 useAnchoredPosition + FloatingArrow + 外点登记 的可直接移植参考。

三条形制路线

方案 A · 经典桌面

macOS NSPopover 语感 — 标题栏横条 · 短梯形箭头 · 面板身份
锚定浮层是一件小窗。标题栏横条（13px 标题 + ×）+ 内容 + 应答区， 短梯形箭头钉在锚点上——macOS 系统面板（账户 / 共享 / 输入源）的完整语感； 有头有关，长内容与多操作不迷路。
  • 结构最完整：标题栏让「这是什么浮层」始终可见，Esc 关闭有 × 兜底
  • 箭头最强：短梯形贴锚，指向性三案最明确
  • 一句话说明卡也背标题栏——轻内容显「隆重」（Dialog A 的暗账同款）
  • 标题栏 + 箭头 + 边框的框架成本，与「零横线」铁律需要小心调和
适用：系统级锚定面板——账户、同步状态、输入源——「操作系统的小窗」身份感。

方案 B · 现代产品 已定稿

Slack / Linear 语感 — 无标题栏内容卡 · 头行随需 · 菱形箭头
浮层是内容本身，不是容器。无标题栏；需要标题时用「头行」（16px 圆底 icon + 13.5px 标题 + 可选 ghost ×），随需出现、无内容不空转；8px 菱形箭头与 Tooltip 完全同几何 （抽 FloatingArrow 的直接理由），surface 底 + line-1 描边 + shadow-float。
  • 与已定稿浮层家族（Menu B 药丸行 / Toast 卡片 / Dialog B）语言连续性最强
  • 轻内容（一句话说明卡）零框架税，重内容（过滤器组）头行 + footer 撑得住
  • 无标题栏：长内容滚动时「我在哪」只剩头行一条线索（靠 edge fade 补）
  • 8px 箭头指向性弱于 A 的短梯形——远距离锚定时视觉关联偏含蓄
适用：产品内嵌浮层——过滤器、色板、成员卡、卡片预览——「这是产品的一部分」。

方案 C · 密集工作台

IDE inspector 语感 — 无箭头 · radius-md · 可 pin 驻留 · edge fade
锚定浮层是检查器，不是气泡。无箭头（贴齐 + 位移对齐表达归属）、 radius-md 12、12.5px 紧凑排版、行高收敛；可 pin——钉住后豁免 light dismiss， 变成驻留面板（Notion preview 的点击钉住同源）；长内容 edge fade。
  • 同屏信息量最大：属性面板 / 过滤器组一次展开不折行
  • pin 解决「边看边改」：浮层与底层内容并存工作，这是 A/B 都给不了的
  • 无箭头失去指向性——锚定关系全靠贴齐，多浮层同屏时归属易混
  • pin 是行为复杂度：钉住态的层级 / 互斥 / 关闭路径都要单独定义
适用：属性检查器、批量过滤器、快捷键表——「专业工具的附属面板」。

决策建议与 API 草案

怎么选

  1. 看浮层语言连续性定身份：已定稿家族全是现代产品语言（Menu B 药丸行 D-010、Toast 卡片、 Dialog B D-011）。Popover 的主战场是过滤器 / 色板 / 成员卡——B 的「内容即浮层」与这些场景 天然同构；A 的标题栏适合系统级面板但与「零横线」铁律相抵；C 的 pin 与密排版适合检查器场景， 但无箭头 + 行为复杂度把它推向「未来的 Inspector 容器」而非通用 Popover。
  2. pin 是唯一的行为级嫁接件：B 皮 + 图钉（钉住豁免 light dismiss）可嫁接不破形制； 箭头形制（短梯形 / 菱形 / 无）与标题形制不可混。
  3. antd 迁移面先想清楚：存量 Popover 的 trigger="hover" 用法迁 Tooltip、 trigger="focus" 逐例复核（focus-visible 显示归 Tooltip）；placement 12 向同名直映； title/content 二分对应头行 / 正文。04 删除清单随锚点事件补章节。
  4. 落地即抽公共底盘：定稿后同提交内完成 useAnchoredPosition / mergeRefs / FloatingArrow / useDismissableLayer 四件抽取（见公共底盘表），Tooltip / Menu / Select 改造为消费者—— 抽取不前置（没有第四消费者时不动存量），也不欠账（落地即还）。同步 03 指南 §9 组件清单与 DECISIONS.md（编号顺延）。

ui/primitives/Popover API 草案

<Popover trigger={<IconButton icon={Filter}/>} placement="bottom-start">   // 触发器克隆注入
  <Popover.Header icon={<SlidersHorizontal/>}>筛选</Popover.Header>    // 头行随需（B 定稿形制）
  <Popover.Body>                                                  // 内容任意：表单 / 色板 / 文本
    …chips / Select（D-007）/ 开关…
  </Popover.Body>
  <Popover.Footer>                                                // 应答区随需：无操作即无
    <Button onClick={reset}>重置</Button>
    <Button variant="primary" onClick={apply}>应用</Button>
  </Popover.Footer>
</Popover>

interface PopoverProps {
  trigger: ReactElement;                 // 协议同 Tooltip/Menu：必须透传 props 与 ref
  placement?: PopoverPlacement;          // 12 向全表，默认 "top"（同 Tooltip；antd 直映）
  open?: boolean;                        // 受控（§5.3；样板间常显标本）
  onOpenChange?: (open: boolean) => void;
  arrow?: boolean;                       // 定稿形制相关：B 菱形（A 短梯形 / C 无）
  className?: string;                    // 透传浮层（宽度控制如 w-[360px]）
  children: ReactNode;                   // Header/Body/Footer 复合声明（B）或裸内容
}
