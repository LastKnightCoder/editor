锚点
（点我开浮层）
flip：把锚点拖到窗口边缘再开——主轴放不下自动翻对侧；shift：交叉轴夹回视口。 引擎数学与 tooltipPosition.ts 同源（C 消费 gap 4 贴齐口径， 与 Menu/Select 一致）；本测试台就是实现期 useAnchoredPosition 抽取的验收台。

暗账 · 本方案绕不开的三件事

① 无箭头失去指向性：锚定关系全靠 gap 4 贴齐，多浮层同屏（尤其钉住一个再开一个） 时归属易混——B 的 8px 箭头在此有真实价值。
② pin 是行为复杂度：钉住态要单独定义层级（钉住的浮层 vs 新开浮层谁在上）、 互斥豁免（钉住不参与「开新关旧」）、关闭路径（× 与触发器仍可关）；每一条都是实现与 测试的账。
③ 密排版牺牲扫读性：12.5px / 1.6 在长文本（说明卡）上不如 B 的 13px / 1.65 舒展—— 检查器语感对「阅读型」内容是错配；通用 Popover 若定 C，说明卡场景要么提密要么接受降级。

C = 锚定浮层是检查器，不是气泡

无箭头（gap 4 贴齐，与 Menu/Select 同口径）、radius-md 12、12.5px 密排版、控件 28px； 可 pin——图钉钉住后豁免 light dismiss（外点 / Esc / 开新关旧都跳过）， 浮层变驻留面板，「边看边查 / 边改边看」成立（P1 钉住后点正文、P5 检查器是两个代表场景）。 footer 无 hairline 用留白分隔——零横线最彻底。
试试：P1 开浮层 → 点图钉 → 再点页面正文（不关）；P5 检查器同样可钉； P2 里开「高级选项…」看嵌套（Esc 先关二级）；P7 方位测试台切 12 向、拖窗口边缘看 flip； 右上角切 cocoa。
