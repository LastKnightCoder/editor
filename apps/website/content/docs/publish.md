发布可以把你选中的卡片、文章和项目文档生成一个静态网站，当作个人博客或公开的知识库。网站可以导出到本地文件夹自己部署，也可以一键发布到 GitHub Pages 或兼容 S3 的存储。

比如你写了一组《深度工作》的读书笔记，想分享给读书会的朋友：勾选这几篇文章和相关卡片，点「发布」，几十秒后就能把网址发出去。之后改了内容，再点一次发布即可更新。

## 准备工作

在侧边栏点击「发布」。第一次使用时，页面右侧会显示「开始之前」，按顺序完成：

1. **安装发布插件**：到 [插件](/docs/plugins/) 中心安装「GitHub Pages 发布」或「S3 静态托管发布」，账号在下一步的「站点设置」里填写。只想导出到本地文件夹的话，跳过这一步。
2. **安装博客模板**：模板决定网站长什么样，同样在插件中心安装，例如「Tau 博客」，它带文章、卡片、项目页和全文搜索，支持浅色和深色主题。
3. **设置站点**：点击「去设置」打开「站点设置」，选择发布目标和模板，填写站点标题。
4. **选择内容**：在左侧勾选要公开的内容。

完成之后，以后每次只需勾选内容、点「发布」。

## 站点设置

点击右下角的站点摘要，或在「开始之前」里点「去设置」，可以打开「站点设置」。修改会自动保存。

| 设置     | 说明                                                                             |
| -------- | -------------------------------------------------------------------------------- |
| 服务     | 发布到哪里：「本地导出」或已安装的发布插件                                       |
| 连接配置 | 选好发布插件后，它的账号和发布位置直接显示在服务下方，在这里填写即可             |
| 公开 URL | 网站的访问地址，页面顶部会显示它，点击即可打开。留空时使用发布目标给出的地址     |
| 标题     | 站点名称，显示在网站和浏览器标签上                                               |
| 图标     | 网站的 favicon，支持 SVG、PNG、ICO                                               |
| 模板     | 选择一个已安装的博客模板，下方会出现这个模板自己的设置，如「Tau 博客」的站点描述 |

选好发布插件后，站点设置会自动测试一次连接。之后改了配置，点「测试连接」再试一次。「发布目标」右上角的「管理发布插件」可以跳到插件页，安装或停用发布插件。

### 发布出去的网站是什么样

- **图片**：正文里的本地图片会随网站一起上传，读者打开网页就能看到，不依赖你电脑上的文件或外部图床。某张图片无法发布时，发布计划里会列出「几处图片无法发布」，不影响其他内容继续发布。
- **高亮**：正文里的背景高亮按「设置 › 外观 › 高亮」里选的笔触绘制，选了「平头荧光笔」「下半划线」或「干笔颗粒」，网站上也是同样的马克笔效果。改了笔触后重新发布即可更新。
- **主题和排版**：由博客模板决定，模板自己的设置（比如「Tau 博客」的站点描述）在站点设置的「博客模板」里填写。

### 发布到 GitHub Pages

在站点设置里选「GitHub Pages 发布」后填写：

- **Token**：需要对目标仓库有内容写入权限，点「创建 Token」可以去 GitHub 生成；
- **仓库**：填好 Token 后可以从你的仓库列表里选，也可以直接填 `owner/repo`；
- **部署分支**：网站文件提交到哪个分支，例如 `gh-pages`；分支不存在时会自动创建；
- **访问路径**：网站在域名下的路径。留空时，`你的名字.github.io` 仓库为 `/`，其他仓库为 `/仓库名/`。

「提交与推送」里可以设置提交者名称和邮箱，以及推送方式。默认用 Git Push 推送，需要电脑上装有 Git；关掉后改用 GitHub API 逐个上传文件。

发布后，还要在 GitHub 仓库的「Settings › Pages」里把来源设为这个分支，网站才能访问。

### 发布到 S3

「S3 静态托管发布」把网站放进一个对象存储（AWS S3，或 Cloudflare R2、MinIO 这类兼容 S3 的服务）。在站点设置里选它后填写：

- **账号**：服务商给你的 Access Key 和 Secret Key；
- **Bucket 和 Region**：存储桶的名字和它所在的地区，在服务商控制台里都能看到；
- **Endpoint**：用 AWS 以外的服务商时填写，服务商的文档里会给出这个地址。

:::detail{title="其他选项"}

- **访问路径**：网站放在子路径下时填写，比如 `/blog`；
- **对象前缀**：网站文件放进存储桶里的哪个文件夹；
- **URL 风格**：大多数服务保持默认的「路径风格」即可；服务商要求用 `存储桶名.域名` 这种地址时，改为「虚拟主机风格」。
:::

:::info{title="测试连接通过，不等于权限都够"}
测试连接只能确认账号能连上。如果发布时部分文件上传或删除失败，请检查账号是否有写入和删除的权限。
:::

### 使用自己的域名

Tau 没有单独的自定义域名设置，域名在托管服务那边绑定。以 GitHub Pages 为例：

1. 在仓库的「Settings › Pages」里填写你的域名，GitHub 会在部署分支里生成一个 `CNAME` 文件；
2. 在站点设置里把「访问路径」改为 `/`；
3. 在站点设置的「公开 URL」里填上 `https://你的域名`。

发布时 Tau 只更新它自己生成的文件，`CNAME` 等你手动放进分支的文件不会被删除。

## 发布

::demo{name="publish" caption="点「发布」看一次完整发布；再取消勾选一篇、重新发布，看计划里的删除和「跳过」"}

左侧按「卡片」「文章」「项目」分类列出你的内容。卡片按标签选，项目里勾选要公开的文档。可以搜索，也可以用「全部 / 已选 / 未选」筛选和「全选」。

勾选后，右侧「本次发布」会列出要上传的文件和要删除的文件。取消勾选的内容会从网站上删除。勾选变化后计划会提示过期，点「重新计算」刷新。

点击「发布」后，进度依次是准备、生成、推送、清理、完成。发布过程中请不要关闭 Tau。完成后可以点「访问站点」查看效果。

内容修改后点「重新发布」。Tau 会比对上一次发布的结果，只上传有变化的文件，没变的文件计为「跳过」。第一次发布到一个新目标时，会上传全部文件。

## 导出到本地

发布目标选「本地导出」时，按钮变为「导出」。点击后选择一个文件夹，Tau 会在里面生成完整的静态网站，你可以把它上传到任意静态托管服务，比如 Netlify、Cloudflare Pages 或自己的服务器。网站不在域名根目录时，在站点设置里改「访问路径」。

## 常见问题

:::detail{title="「发布」按钮是灰的"}
检查三件事：站点设置里是否选了发布目标，是否选了博客模板，左侧是否勾选了内容。「开始之前」会标出还差哪一步。
:::

:::detail{title="部分文件上传失败"}
完成卡片会列出失败的文件和原因。多数是网络中断或账号权限不足，处理后点「重新发布」，已经成功的文件会被跳过，只补传失败的。
:::

:::detail{title="网站打开后样式错乱或 404"}
通常是访问路径不对。网站放在 `https://example.com/blog/` 下时，访问路径应为 `/blog/`；放在域名根目录时为 `/`。改完后重新发布。
:::

想让别人不只是看，还能和你一起改，见 [协作](/docs/collaboration/)。
