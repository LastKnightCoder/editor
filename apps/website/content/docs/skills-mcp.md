Skill 和 MCP 是扩展 AI 的两种方式。Skill 是一份说明文档，告诉 AI 某件事该按什么步骤、什么格式来做；MCP 服务器是外部的程序或服务，让 AI 多出一批能调用的工具。两者都在侧边栏的「AI」分组里。

::demo{name="skills" caption="切换 Skill 的开关，看调用方式和常驻上下文的变化；打开「浏览器」服务器，看它从连接中变为可用"}

## Skill

同一类任务你总要交代一遍做法，比如读书卡片怎么写、周报按什么结构、会议纪要先写什么，就可以写成一个 Skill。之后只要提到这件事，AI 会自己翻出这份说明照着做。

### 添加 Skill

在侧边栏点击「Skill」，然后点击「添加 Skill」。有四种方式：

- **新建**：填写名称和描述，从空白、流程类、参考资料类或格式规范类模板开始写；
- **用 AI 创建**：描述你想让 AI 学会什么，也可以直接贴一段满意的对话，点「起草」生成初稿，改好后点「保存 Skill」；
- **导入**：选择 `.zip` / `.skill` 压缩包或一个文件夹，也可以粘贴 GitHub 仓库、目录或 SKILL.md 的链接；
- **关联目录**：关联电脑上已有的 skills 文件夹。Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）和通用 Agent Skills（`~/.agents/skills`）的目录已经列好，打开开关即可，也可以只启用其中几个。

:::warning{title="只导入信任的来源"}
Skill 里可以附带脚本，AI 会在你的电脑上运行它们。
:::

### Skill 的写法

一个 Skill 是一个文件夹，里面至少有一个 `SKILL.md`。文件开头用 `---` 包起来的部分写名称和描述，下面是正文：

```markdown
---
name: "周报"
description: "把一周的日记、已完成的待办和日程整理成周报。用户提到「周报」「本周总结」时使用。"
---

# 周报

## 步骤

1. 用 search_knowledge 找出本周的日记
2. 用 query_todos 查出本周完成的待办，按项目归类
3. 用 query_calendar_events 查出本周的会议和日程
4. 按下面的格式输出

## 输出格式

- **本周完成**：按项目列出，每项一句话
- **进行中**：还没完成的事和卡在哪里
- **下周计划**：最多三条

## 注意

- 只写有依据的内容，查不到的部分直接说明
- 语气简洁，不写客套话
```

开头的几个字段：

| 字段                       | 说明                                                       |
| -------------------------- | ---------------------------------------------------------- |
| `name`                     | 显示的名称                                                 |
| `description`              | 这个 Skill 做什么、什么时候用。AI 靠它判断要不要读这份说明 |
| `disable-model-invocation` | 写 `true` 时默认为「仅手动」，AI 不会自己加载              |

描述要写清「什么时候用」。编辑时如果描述里没有触发场景，Tau 会提示你补一句。

内容多的 Skill，可以把细节拆到其他文件里，`SKILL.md` 只放概要和索引，AI 需要时再去读：

```text
reading-card/
├── SKILL.md          必需：说明和索引
├── reference/
│   └── examples.md   参考资料、范例
└── scripts/
    └── extract.py    需要时运行的脚本
```

在 `SKILL.md` 里写明什么情况下运行哪个脚本，AI 会按说明执行。支持 `.py`（Python 3）、`.js` / `.mjs` / `.cjs`（Node）、`.sh`（Bash）和 `.ts`，其他文件需要有可执行权限。脚本在 Skill 文件夹里运行，单次最长 2 分钟。

:::detail{title="编辑 Skill"}
点击一个 Skill 打开详情，再点编辑进入整页编辑器。左侧是文件列表，可以新建文件和文件夹；正文可以在「编辑」和「源码」两种视图间切换。内置和关联目录里的 Skill 是只读的，想修改时点「复制为我的」，在副本上改。
:::

### 调用方式

每个 Skill 可以设为三种调用方式之一：

| 方式   | 什么时候生效                      | 占用上下文     |
| ------ | --------------------------------- | -------------- |
| 自动   | AI 根据描述，在需要时自己读取     | 名称和描述常驻 |
| 仅手动 | 只在你于输入框输入 `$` 点名时生效 | 不占用         |
| 停用   | AI 完全看不到                     | 不占用         |

设为「自动」的 Skill，名称和描述会放进每次对话，页面右上角的「常驻上下文」显示它们一共占了多少 token。描述偏长时卡片上会有提示，建议把细则挪到正文里。不常用的 Skill 设成「仅手动」，用时输入 `$` 选一下就行。

调用方式只保存在本机，不会改动 Skill 文件，内置和关联目录里的 Skill 也能设置。详情的「使用记录」里可以看到最近被加载的次数，以及其中多少次是 AI 自动加载的。

## MCP 服务器

MCP 服务器给 AI 接上 Tau 之外的工具，比如读写电脑上的文件、查询 GitHub、操作浏览器。很多工具和服务都提供了 MCP 服务器，在它们的说明里一般能找到配置方法。

### 添加服务器

在侧边栏点击「MCP 服务器」，然后点击「添加服务器」。可以手动填写，也可以粘贴 JSON：

- **本地进程 stdio**：在你的电脑上启动一个程序。填写命令（如 `npx`、`uvx`、`node` 或可执行文件的绝对路径）、参数、环境变量和工作目录；
- **远程 HTTP**：连接一个网络服务。填写 URL，需要登录的服务在请求头里加上 `Authorization`。

::demo{name="mcp-import" caption="改一改左侧的 JSON，看右侧识别出的服务器；点「导入」后看它们连接"}

「粘贴 JSON」和 Claude Desktop、Cursor 的 `mcpServers` 写法相同，也支持 VS Code 的 `servers` 写法，可以从别的工具直接复制过来。一次可以导入多个：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/you/Documents/notes"]
    },
    "github": {
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer <你的 GitHub Token>" }
    }
  }
}
```

名称里带 KEY、TOKEN、SECRET 等字样的环境变量和请求头，值会默认遮住。暂不支持 SSE 传输的服务器，导入时会标出来。点击页面上方的「导出为 JSON」，可以把你添加的全部服务器复制成同样的格式，方便备份或换到其他工具里用。

:::warning{title="请只添加可信的服务器"}
本地进程类的 MCP 服务器可以在你的电脑上执行命令，读写你的文件。
:::

### 管理和排查

每个服务器卡片底部显示当前状态：可用的工具数、「连接中…」、「连接失败」或「已停用」。侧边栏「MCP 服务器」旁的数字是连接失败的服务器数。

点击一个服务器打开详情：

- **工具**：列出它提供的全部工具，可以单独关掉不想让 AI 用的；
- **配置**：修改后点「保存并重连」；
- **日志**：查看最近 200 行输出，连接失败时先看这里。

改完配置或服务器卡住时，点击「重新连接」。

「内置」分组里是随 Tau 提供的工具，比如知识库搜索、内容编辑、待办与日程助理，部分常开不可关，具体能做什么见 [AI 对话与洞见](/docs/ai/)。

### 在对话中开关

在对话输入框里点击「+」，选择「MCP 服务器」，可以临时开关某个服务器，不用离开对话。这里的开关和 MCP 服务器页面是同一个开关。

:::tip{title="少开几个，AI 选得更准"}
每个打开的服务器都会把它的工具清单交给 AI。工具太多时，AI 更容易用错工具，也更费 token。不常用的服务器先关着，要用时在输入框里打开。
:::
