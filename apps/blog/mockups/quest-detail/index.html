求索录详情页 · 重设计

让读者看到「怎么得出」的，而不只是「得出了什么」

现状只有「问 → 解」。桌面端的问题其实已经记录了材料（question_link）、对话（question_chat）和轨迹（question_event），这些都没发布出去。三套方案在博客原有的朴素风格上补出「径（探索过程）」与「据（引用资料）」，区别在于过程与证据摆在哪里。示例问题相同，便于对比；右上角 ◐ 可切换明暗。

A · 论文式
脚注 + 参考文献

结论先行，探索过程和资料作为「方法」与「参考文献」附在后面。改动最小，最朴素。

问 → 解 → 径 → 据
B · 旁注式
资料贴在正文边上

资料以旁注形式与引用处对齐，顶部有研究概览，「径」是九天节奏图。证据感最强。

问 → 概览 → 解 ‖ 旁注 → 径 → 据
C · 研究日志
过程即正文

按天展开研究日志，资料作为引文卡嵌在发生的那一天，顶部给结论速览。最强调研究过程。

问 → 速览 → 径 → 解 → 据

我的推荐

以 A 为骨架、吸收 C 的两个元素：顶部「结论速览」和「弯路 / 想通了」笔记标记。理由：A 对内容质量没有要求（只有自动轨迹也不难看），可以作为所有问题的默认模板；C 的日志体验最好，但需要你在探究时勤写笔记，适合作为「轨迹足够丰富时」自动切换的形态，而不是默认。B 的旁注很漂亮，但要做避让排布和窄屏降级，性价比最低，可以以后再加。

需要你拍板的几个问题

  1. 正文里的 [n] 从哪来？答案正文目前没有「引用」这种节点。三个选项：① 自动——答案里已有的 content-link 若指向本问题的材料，就编号成引用；② 新增一个行内「引用」元素，在编辑器里从材料列表挑；③ 不在正文编号，只在文末列资料。我建议 ①，零额外操作，后续再考虑 ②。
  2. 未公开的资料怎么展示？现在的发布策略是「引用不等于公开」。我建议：已公开的卡片/文章 → 链接；划线、PDF 标注、剪藏本身就是摘录 → 直接展示原文 + 外部出处；未公开的卡片 → 只给标题和前一两句摘录，并标「未公开」。也可以做成发布时逐条勾选。
  3. AI 对话公开到什么程度？完整对话通常太长且涉及隐私。建议默认只显示「与 AI 讨论 N 次」，发布时可以手动挑选 1–3 条消息作为摘选（question_chat.message_ids 已经能记录具体消息）。
  4. 轨迹是否全部展示？自动事件（关联、状态变更）很密，建议发布时只保留：提出、里程碑（写卡片/文章）、手写笔记、解决；关联事件合并到当天一行。
  5. 「弯路」要不要成为正式类型？question_event 的 note 现在只有一种。如果给 note 加一个可选标记（弯路 / 想通了 / 疑问），研究过程的叙事性会强很多，桌面端也能用上。

其他建议

  1. 反向链接：卡片、文章详情页底部加「被这些求索引用」，资料与问题双向可达，博客会更像一张知识网。
  2. 列表页同步：求索录列表每行可以加一行灰字「9 天 · 7 份资料」，让读者知道哪些问题研究得深。
  3. 外链安全：剪藏等外部链接统一 rel="noopener nofollow" 并带 ↗ 标识，与站内跳转（→）区分。
  4. 进行中的问题：没有「解」时，C 方案的日志反而最合适——页面变成「正在研究的公开笔记」，比现在的「仍在路上」空态更有内容。
  5. 发布体积：资料只导出摘录（截断到 ~200 字），不内嵌完整卡片正文，避免页面膨胀，也与现有「引用不等于公开」的策略一致。
