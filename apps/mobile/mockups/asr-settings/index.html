问题清单

  1. ①桌面行式布局直接搬到手机。SettingRow 是“左标题 + 右控件”，手机上标题列和输入框挤在一行；输入框只有 34px 高，低于 44px 触控下限；原生 select 没有说明文字，用户不知道“按时长/按并发”差别。
  2. ②没有分组卡片。表单裸放在页面底色上，和移动端其它设置（同步、语音合成）的“灰底 + 白色圆角分组”不是一套语言。
  3. ③保存按钮像桌面次级按钮。小、靠左、不在拇指区；保存结果只是一行小字。
  4. ④兼容性提示放在表单末尾。和设置内容无关，像是表单的一部分。
  5. 更深一层：入口错位。ASR 是“语音输入”的服务账号，按 TTS 的先例应由宿主设置页承载（账号状态、测试、当前服务），插件只提供厂商字段。现在插件详情直接渲染表单，宿主的 asrConfig 上下文也没有入口。

结论

是的，应该在 @tau/ui 导出移动端组件，但不建议另起一套 @tau/ui/mobile。推荐“同名组件 + 密度上下文”：宿主用 UiProvider density="touch" 包住插件，同一个 SettingsGroup / SettingsField / ChoiceList 在桌面渲染行式、在手机渲染触控式。插件只写一份表单，详见第 4 页。

推荐：宿主承载“语音输入”页，插件只渲染厂商字段。和语音合成同一结构：宿主管理当前服务、测试和 AI 整理；豆包插件的表单用 @tau/ui 的触控密度组件写成，挂进宿主的账号页。入口位置（“我的 → 语音”分组）是建议，等你确认后再接线。

一份插件代码（豆包设置改写后）

import { SettingsGroup, SettingsField, SecretInput, ChoiceList,
         useProviderForm } from "@tau/ui";

function Settings({ asrConfig }: PluginSettingsProps) {
  const form = useProviderForm(asrConfig, parseConfig);   // 宿主负责保存/测试/错误
  return (
    <>
      <SettingsGroup title="账号">
        <SettingsField label="API Key" hint="在豆包语音控制台获取"
                       error={form.errors.apiKey}>
          <SecretInput {...form.bind("apiKey")} />
        </SettingsField>
      </SettingsGroup>
      <SettingsGroup title="计费资源">
        <ChoiceList {...form.bind("resourceId")} options={[
          { value: "…duration",   label: "按时长", description: "按识别音频时长计费" },
          { value: "…concurrent", label: "按并发", description: "按购买的并发路数计费" },
        ]} />
      </SettingsGroup>
    </>
  );
}

排版规则（宿主负责）

  • 分组：插件给了 groups 就按它分；没给时，宿主把 secret/text/url 归进“账号”，每个带说明的 choice 单独一组，其余归进“选项”。
  • 移动：每组一张卡，组标题在卡外；note 放在最后一组下方；link 放在导航栏右上。
  • 桌面：整个服务一个面板，组标题变成面板内小节头；note 和 link 放在面板标题行。
  • 保存与测试：宿主统一提供。parse 抛出 FieldError(key, 文案) 时，对应字段标红；其他错误显示在顶部横幅（移动）或操作区（桌面）。
  • 兜底：字段描述不够用（音色复刻、模型管理）时仍可注册 component，用 @tau/ui 的密度组件自己写。

与现状的关系

  • ConfigurationField（key / label / type / options / hint / loadOptions / reset）已经在同步、上传插件和 MiniMax 移动设置中使用。D 方案是把它扩成正式字段契约：补 secret、url、switch、number、choice 说明、default、optional，并让桌面也按字段渲染。
  • 字段契约放在 @tau/plugins（属于领域 API），两端渲染器放在宿主，共用的控件仍来自 @tau/ui。
  • 迁移后，豆包、MiniMax、Qwen 的设置代码都会变成纯声明，去掉现在的两份视图。
