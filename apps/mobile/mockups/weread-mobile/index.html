微信读书 · 移动端设计方案 v1插件 1.0.15 → 加 android / ios 目标 · 颜色取自 @tau/themes · 手机帧 360×760 · 划线与想法为示意文本，不是原书内容

桌面版是两整张纸：书架页把统计、搜索、同步、分类、状态 / 排序 / 排布三个下拉挤在一行；单书页左边常驻目录，右边按章节排划线，鼠标悬停才出现「转为卡片 / 复制」。手机上按「找到书 → 翻笔记 → 用一条划线」重排：书架只留一行工具和一行分类，三个下拉合成一个筛选面板；单书页目录收进底部面板，划线点一下出操作。插件仍是一份代码、一个 ZIP，按平台切界面：手机（含平板）用本稿，电脑用原来的双栏；状态与同步逻辑两端共用（同记账本插件）。数据、同步口径、摘录 externalId 全部不变。

1 · 入口换成跨端的 navigation

现在用 sidebar.registerItem 挂侧边栏，手机宿主没有侧边栏，激活时会直接抛「当前宿主不支持侧边栏」。改为 navigation.registerEntry：桌面仍在侧边栏「学习」组，手机出现在「我的」顶部功能宫格。命令面板在手机上没有，「打开 / 同步」两条命令保留注册但不承担入口。

2 · 书架两行工具

宿主顶栏只有返回和标题，插件不能往里加按钮，所以工具放在内容顶部：第一行「12 本 · 累计 60 小时 · 10 分钟前同步」+ 搜索 + 同步 + ⋯（同步面板）；第二行分类胶囊横滑 + 筛选按钮。往下滚时分类行吸顶，统计行滚走。

3 · 三个下拉合成一个面板

状态、排序、排布在手机上很少改，各占一个按钮太挤。合成一个「筛选与排列」底部面板；筛选或排序不是默认值时按钮上出一个点。不用 Segmented，状态用胶囊、排序和排布用单选行。

4 · 在读竖排、全部三列

「在读」是一张卡，竖排最近读过的 3 本，一行一本（缩略封面、书名、作者 · 最近阅读、右侧进度），不横滑；「全部」封面墙固定三列，列表排布改成一行一本（封面缩略 + 书名作者 + 进度和划线数），桌面列表的七列和点列头排序不搬到手机。

5 · 单书页：目录收进面板

书头（封面、书名、进度、阅读时长 / 划线 / 想法数）→ 两个按钮「在微信读书中打开」「重新拉取」+ ⋯ → 书评 → 吸顶过滤条。过滤条最右是目录按钮，滚动后按钮上显示当前章节名，点开是目录面板。

6 · 划线点一下出操作

手机没有悬停。点一条划线弹出底部面板：顶部是这条原文预览，下面「转为卡片 / 复制划线 / 复制划线和想法」。长按留给系统选字，可以只复制半句。

7 · 连接和同步口径不变

API Key、书架缓存、偏好仍在插件私有存储，按工作区分开；整库同步时随主库一起到手机，电脑上连过的话手机打开就是已连接状态。同步仍是增量 + 全量两种：书架上的「同步」是增量，全量在旁边 ⋯ 的同步面板里，和桌面「同步」旁的下拉箭头同一位置。

8 · 不做的

  • 不做手机专用插件，也不另起节点类型或摘录口径。
  • 不在手机上做阅读器、不做划线编辑：划线只来自微信读书。
  • 不做今天页卡片（见「待你决定」）。

你判断「移动端宿主能力已经满足」，我核对后不完全成立：页面、设置、存储、网络都有了，但插件的核心——把划线和想法写成 Tau 摘录——手机宿主还没有提供。依据是 apps/mobile/src/app/plugins/runtime.ts 给 PluginHost 的适配器里没有 excerpts / materials，@tau/plugins 的 host 在缺适配器时直接抛错；插件模板的 接口表 也把这两项标为仅桌面。所以现在给 manifest 加上 android / ios，插件在手机上激活即失败。

方案 A · 宿主补齐摘录与材料动作已定

  • 手机宿主实现 excerpts 全套与 materials.actions("card")，口径照搬桌面 tables/excerpt.ts 与 material-to-card.ts；脉络与引用里的摘录可点，交给提供方 open。
  • 插件只改入口注册和窄屏布局，两端功能一致，符合「列出平台 = 全部功能已适配」。
  • 代价：宿主侧工作量最大（Rust 读写与搜索索引、TS 适配器、脉络跳转、转卡片与谱系），之后网页摘录、其他摘录插件上手机也直接受益。

方案 B · 手机只读备选

  • 宿主只做 excerpts.sources / items 与 open，不做写入；插件在手机上隐藏「同步 / 重新拉取」，只看电脑同步过来的笔记。
  • 代价小，但新划线要等电脑同步一次再整库同步到手机才看得到；且只有部分功能，按规则不应列出手机平台，需要额外约定。

方案 C · 插件绕开摘录不推荐

  • 手机上把笔记存进插件私有存储自己画。
  • 单值 1 MiB 上限装不下大书架；划线不进搜索、不能引用、不能转卡片；两端事实源分裂，以后很难收回来。

两端都写摘录要先确认的事

  • 云端整库同步：后上传的整库覆盖，和其他数据一样，没有新问题。
  • 局域网设备同步按行合并：手机和电脑各自离线同步同一本书，会各插一行相同 (source_type, external_id)，撞 idx_excerpt_external 唯一索引。实现方案 A 前要先确认设备同步对唯一键冲突怎么处理。
  • API Key 在 plugin_kv：整库同步会带到手机；设备同步是否同步这张表（它不传「设置凭据」）也要确认，不同步时手机首次要再填一次。

1 · 宿主缺口怎么补（第 1 页）已定 A

  • 已定：方案 A，手机宿主补 excerpts 全套、摘录 open 跳转和 materials.actions，两端功能一致；宿主能力由另一路在补，补齐后再开始插件适配。
  • 选 A 时「转为卡片」走宿主材料动作，记谱系「摘自」，和桌面一样；如果想先少做一块，可以让插件在手机上改用已有的 app.run("card.create") 预填正文，代价是没有谱系、会弹出新建卡片窗口而不是直接建好。

2 · 划线怎么出操作（第 7 页）

  • 默认：点一下出底部面板，长按交给系统选字。界面最干净，划线本身就是按钮。
  • 备选：每条右上角常驻 ⋯（像桌面悬停按钮的位置），更好发现，但每条都多一个图标。

3 · 今天页要不要放「在读」卡片

  • 默认：不做，第一版只有「我的」宫格入口。
  • 要做的话：两列卡片中的一格，显示最近在读的一本（封面、书名、进度），点「继续读」打开微信读书 App 里的这本书、点卡片进单书页。需要插件注册 home 面板。

4 · 全量重新同步放哪已定

  • 已定：书架「同步」旁的 ⋯ 打开同步面板（第 5 页）：上次同步结果、全量重新同步、账号与连接。设置页不再放全量。
  • 桌面不变：仍是「同步」旁的下拉箭头。

5 · 其余我已按桌面定好的

  • 手机与平板都用本稿（内容最宽 720px 居中），电脑用原来的双栏，按平台切，同记账本插件。
  • 颜色、划线样式、封面兜底、空态文案全部沿用桌面；新增的只有筛选面板、目录面板、划线面板。
  • 数据与口径不变：摘录 externalId、同书想法并入划线、软删除与复位、私有存储键都不动；手机只加界面和 manifest 的 android / ios 目标。
  • 实施顺序：先宿主（能力 + 接口表 + 架构文档），再插件（入口、窄屏布局、目标平台），最后真机走一遍：安装、启用、连接、同步、转卡片、跳回、停用、杀进程重开。

6 · 实现前要在真机上确认

  • 手机浏览器能否直接登录微信读书获取页拿到 API Key（不能的话首次引导第一步改成在电脑上打开）。
  • 插件 WebView 里的 window.open 是否交给系统浏览器、能否唤起微信读书 App；navigator.clipboard 读写是否可用。
  • 局域网设备同步遇到两端各自写入的同一条摘录（同 externalId）怎么合并。
