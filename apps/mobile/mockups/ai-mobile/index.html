移动端 AI 能力接入 · 设计方案颜色取自 @tau/themes · 手机帧 360×760 · 模型、对话与笔记内容均为示意

移动端已有 MobileAiService（会话持久化、工具、MCP、原生网络桥）和语音输入的 refine 钩子，但没有任何产品入口，模型配置也只能读取。本方案分三层：一处配置服务商 → 按功能分配模型 → 各功能就近消费。配置结构直接沿用桌面端的 llmProviders + llmUsageSettings，功能键名与桌面一致（chat、speechInputRefinement），以后接入闪卡生成、标题总结时只是多一行分配，不用再改设置页结构。

三层结构

① 服务商（我的 › AI 模型）

DeepSeek / 通义 / OpenRouter / 自定义 OpenAI 兼容……每个服务商填一次 API Key 和地址，勾选要用的模型。

② 功能分配

「对话」→ DeepSeek V3；「语音输入整理」→ Qwen Turbo。一个功能一个模型，未分配的功能入口显示引导，不偷偷回落。

③ 功能消费

对话页、语音整理胶囊、以后的闪卡生成……只认分配结果，不关心服务商细节。

移动端设计原则

  • 拇指区优先：主动作（发送、按住说话、停止）都在屏幕下 1/3，顶部只放返回与历史。
  • 就近提问：在卡片、日记里选中文字就能问，问题自动带上引用，不用复制粘贴。
  • 语音是一等输入：对话里按住说话直接发送，复用现有按住说话手势（上滑取消）。
  • 结果能落地：每条回答都能一键「存为卡片 / 追加到日记」，AI 写入笔记前必须确认。
  • 可中断：切后台、断网、来电时生成暂停并提示，回来能继续，不丢已生成内容。

本稿覆盖范围

设置 服务商列表、添加服务商、服务商详情、功能分配选择器。

对话 4 种入口方案对比、全屏对话页、半屏对话、会话记录、写入确认。

交互 按住说话、长按消息、选中文字提问、@ 引用笔记、半屏/全屏切换。

语音 语音输入整理的开关、模型、整理风格与效果预览。

不覆盖：MCP 与技能管理、多模态生成、用量统计（建议后续单独出稿）。

入口放在「我的 › AI 模型」，与「语音输入」「朗读」同组。主页把功能分配放在最上面：用户来这里多半是想知道「对话用的是哪个模型」，服务商只是背后的账号。添加服务商走预设模板（填一个 Key 就能用），自定义 OpenAI 兼容地址作为兜底。API Key 只存本机，不进同步（与桌面一致，原生层读取后从不回传给页面）。
