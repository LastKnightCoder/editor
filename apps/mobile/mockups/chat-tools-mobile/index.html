现状问题

  1. 合并成胶囊：相邻调用收成一枚「A、B 等 · N 步」，看不出 AI 做了什么、做到哪一步；等待确认 / 失败的调用又被抽出来放到胶囊后面，顺序和真实执行不一致。
  2. 桌面密度直接搬来：FoldRow 行高 26px、图标 14px、点击区不到 30px；附注「· 212 毫秒」这种耗时信息对手机用户没有意义。
  3. 只有原始 JSON：手机端只注册了提问卡，搜索、读笔记、查询待办日程、SQL、新建 / 修改 / 删除都落到通用行，展开就是 12px 等宽字的输入输出；输出不格式化，长字符串挤成一坨。
  4. 确认条：参数也是 JSON；三个 28px 的小按钮挤一行，「本会话始终允许」和「允许」同等分量，容易误点。
  5. 图片生成看不到图：generate_image / edit_image 结果带 openai-image-result 展示键，但手机端没有注册这个展示，只剩一段地址 JSON。
  6. 插件工具：没有可读叫法时直接显示 bookmarks_search 这类英文名。
  7. 提问卡：选项行用桌面的 Radio / Checkbox 尺寸，「其他」是小输入框，提交按钮是 sm 号。

这次的思路

  • 不合并：每次调用一行，按真实顺序排，确认 / 失败就在它自己的位置。
  • 行里说人话：标题写「搜索笔记「同步」」，右边写结果「5 篇」，不写耗时。
  • 查询类轻、写入类重：查询只是一行，点开看底部面板；写入（新建 / 修改 / 删除）直接出结果卡，改了什么一眼可见。
  • 原始数据兜底：每个详情面板底部都有折叠的「原始数据」，排查问题时还看得到。

已定 A 时间线：每次调用单独一行，不再合并，按执行顺序和思考、正文穿插排列。标题是「动作 + 对象」（搜索笔记「同步」、读取「同步冲突策略」），右侧是结果（5 篇、2,140 字）而不是耗时，整行可点（40px）打开详情。左侧图标和 C 一样只有淡墨线条、不加圆底，按工具类别区分；细竖线在图标之间留空，把一串步骤连起来。
