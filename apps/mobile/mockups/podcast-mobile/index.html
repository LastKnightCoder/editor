桌面的播客有三处界面：播客库（列表 + 底部播放条）、单期详情（播放器 + 跟读脚本，可改句重合成）、原文上方的播客条，外加生成对话框和 Notebook 输出。手机上只做「找到一期 → 听 → 跟着脚本看」：从「我的」宫格进播客库，点一期进收听页。新建、审稿、改句、导出都留在电脑上。插件仍是一份代码、一个 ZIP，按平台切界面，播放逻辑（刚做的加载 / 缓冲 / 自动开播）两端共用。

1 · 播客随主库同步到手机

每期播客是插件内容（entities），跟着主库同步，手机打开就有。音频文件看存在哪：远端存储的地址手机第一次播时下载；本地资源库里的文件要先经资源同步到手机才能播（第 4 页）。

2 · 入口换成跨端的 navigation

现在用 sidebar.registerItem 挂侧边栏，手机宿主没有侧边栏，激活时直接抛「当前宿主不支持侧边栏」。手机上改用 navigation.registerEntry，出现在「我的」功能宫格；桌面仍用侧边栏，因为任务数角标只有侧边栏条目能更新。

3 · 收听页：播放器放到拇指区

桌面详情是「播放器固定在上、只滚脚本」。手机上标题和脚本一起滚，播放器吸底，大播放键在拇指够得到的地方；当前句高亮并自动跟随，点一句从这句播，翻走了给「回到当前句」。

4 · 手机是先下载再播

手机宿主解析远端音频时，先把整段下载进本地缓存（上限 500 MB），再交给播放器；桌面是边下边播。所以手机上「正在下载音频」是真实的一段时间：播放键转圈，下完自动开播，之后不用网也能听。

5 · 锁屏和离开页面要能继续听

通勤场景下，锁屏、切到别的 App、回到 Tau 去翻原文都不能停。页面里的 <audio> 撑不住这些（第 5 页），推荐由宿主提供原生播放，插件只给地址和标题、读进度。

6 · 不做的

  • 不在手机上新建播客，「⋯ › 生成播客」和 Notebook 输出只在电脑上注册。
  • 不审稿、不改句重合成、不导出音频、不按原文重新生成。
  • 生成中 / 待审 / 失败的任务不进手机列表，只给一行提示。
  • 不做原文上方的播客条（手机没有 views）；Notebook 来源只显示不能点开。
  • 不做定时关闭、倍速以外的音效设置。

只做收听，插件侧改动不大；卡住的是两件宿主的事：manifest 里的 tts:synthesize 会让整个包上不了手机，以及页面里的播放撑不住锁屏收听。依据：packages/plugins/src/portable.ts 的手机权限白名单（与原生 plugin_permissions.rs 一致）没有它，声明了 android / ios 的包会在构建和上架时被拒；@tau/plugins 的 host 在缺 sidebar / views / notebooks 适配器时直接抛错。

插件侧要改的

  • activate 按 context.environment 分两路：桌面照旧；手机只注册页面和功能入口。
  • 播客库页按容器宽度切窄屏布局（列表行、收听页、底部面板），宽屏仍是桌面版式。
  • 手机上隐藏新建、审稿、改句、导出、重新生成，保留改名、删除、打开原文。
  • manifest 加 android / ios 目标，minAppVersion 填宿主补齐后的版本。

和平台规则的冲突

接口表那篇写着「列出一个平台，表示插件的全部功能都已在这个平台上适配」。手机只收听不新建，严格按这条不能列手机。要么放宽规则（只要手机上出现的功能都可用、并在插件说明里写清楚），要么等手机能新建再上（待你决定 2）。

入口只有一个：「我的」顶部功能宫格的「播客」，图标沿用桌面的 Podcast。播客库把桌面六列表格收成一行一期：封面、标题（最多两行）、原文、时长和日期，右侧 ⋯。点封面就地播，点其余地方进收听页，和桌面一致。宿主顶栏只有返回和标题，插件放不进按钮，所以统计、搜索、筛选放在内容顶部。

脚本跟随播放高亮 · 点一句从这里播
B2脚本面板面板盖住播放器，暂停、跳转要先关面板。这是不推荐 B 的主要原因。

手机上播远端音频是先整段下载再播：宿主 components/editor/localMedia.ts 先调 remote_resource_to_local 把文件存进本地缓存（remote_resource_cache.rs，上限 500 MB），再读成地址交给播放器。所以这里的「正在下载」是真实的一段等待。宿主现在不报进度，插件只能转圈；宿主补上进度后可以显示百分比（待你决定 3）。下完自动开播，之后不用网也能听，直到缓存被挤掉。

D1正在下载（现在就能做）点了播放：播放键转圈，波形变淡，下方一行「正在下载音频…」。再点一次取消。插件现有的 loading 状态直接可用。
D2带进度（要宿主补）细进度条 + 百分比 + 已下 / 总大小。长音频要下几十 MB，有进度才知道要等多久。
D3下完自动开播不用再点；提示只在下完这一次出现几秒。以后再听这期直接走缓存，没有下载这一段。
D4本地资源库的音频还没同步音频地址是本地路径（不是 http）时就知道是这种情况，说清楚去哪同步；播放键置灰，同步后点重试。
D5远端下载失败没网或存储服务没响应。已经下过的那几期不受影响，照常离线播。
D6列表里点封面封面和播放条一起转圈，播放条写「正在下载音频…」，下完自动开播；失败时播放条写「音频加载失败」。

通勤收听要求三件事：锁屏继续播、锁屏 / 通知栏能控制、离开播客页还在播。现在的播放是页面里的一个 <audio>：播客页返回出栈就停；iOS 的 Info.plist 声明了后台音频，但 WebView 里的音频锁屏后能否继续没有验证；Android 只有录音用的前台服务，没有媒体播放的，后台随时可能被系统结束，也没有通知栏控件。推荐方案 B：宿主提供原生播放，和录音选原生是同一个理由。下面三帧是方案 B 的样子。

这几件会改变实现范围，按影响大小排。每条给了推荐，你定了之后再拆实现步骤。

1 · 后台与锁屏怎么播推荐 B

A 页面里的 <audio>：插件现在就能做，但播客页返回就停，锁屏不保证，没有锁屏控件。B 宿主原生播放：锁屏 / 通知栏控件、全局播放条、离开页面继续听，代价是两端原生 + SDK 接口 + 宿主发版。也可以先 A 上线、B 跟进，但 A 的体验和「通勤路上听」的说法对不上。

2 · 手机只收听，能不能列手机平台推荐放宽规则

现行规则要求列出的平台全部功能可用。推荐改成「手机上出现的功能都可用，没有的功能在插件说明里写清楚」，并把 tts:synthesize 加进手机白名单（插件在手机上不调用）。备选：等手机也能新建再上，范围大很多。

3 · 下载进度要不要推荐先转圈

先做 D1（只转圈，插件现在就能做）。要显示百分比，宿主的 useResource 得报下载进度（D2）。若选了决定 1 的 B，进度改由原生播放器报，不必再改 useResource。

4 · 记不记听到哪推荐做

通勤一段一段听，下次打开接着上次的位置；播客库顶部给「继续听」，列表标「剩 N 分钟 / 已听完」（第 2 页第 5 帧）。进度存插件存储，不动播客内容。桌面也一起受益。不做的话每次从头播。

5 · 原文详情里加不加「收听播客」倾向先不做

手机没有原文上方的播客条。可以在原文「⋯」菜单注册「收听播客」，但动作不能按是否有播客显示或隐藏，没有播客的原文点了只能提示「这篇还没有播客」。先只留宫格入口，用下来觉得不够再加。

实现前要在真机上确认

  • iOS WebView 里的 <audio> 锁屏后会不会停（决定方案 A 能走多远）。
  • 电脑本地资源库里的音频，资源同步到手机后路径能不能解析到。
  • 长音频在手机上走「整段读成 base64 → Blob」，二三十 MB 的内存占用和读取耗时，要不要改成文件地址直接播。
