移动端提醒与系统通知 · 设计方案颜色取自 @tau/themes · 手机帧 360×760 · 锁屏/系统弹窗由 OS 绘制，不随主题

结论：能用系统通知，而且应该用。移动端是 Tauri 2，官方 tauri-plugin-notification 在 iOS / Android 上支持预约本地通知（Schedule.at）：提醒交给系统排期，App 被划掉、手机锁屏也会准时弹，不需要推送服务器。现状是移动端待办详情里已经能选「15 分钟前」，但只是写进数据库，手机上从来不会响；日程（calendar_event）连提醒字段都没有。

必须处理的限制

  • iOS 最多排 64 条：只排最近的 N 条（按时间滚动），每次打开 App / 同步完 / 改动后重排。
  • Android 13+ 要通知权限，Android 12+ 准点提醒要「闹钟和提醒」权限；没有就会被系统延后几分钟。
  • 部分国产 ROM（小米/华为等）省电策略可能吞掉提醒，需要在设置页给出「去允许后台」的引导。
  • 别的设备改的提醒：桌面端新建的待办，要等手机同步后才会排进系统；没打开过 App 的这段时间不会响。
  • 「完成」按钮：iOS 后台改数据库要原生侧配合，首版点「完成」会先拉起 App 再勾选，体验上多一下动画。

需要你拍板的两件事

  • 一项能设几个提醒？你说的「前 15 分钟 + 前一天」是两个提醒。现在桌面端和数据库都只存一个（remind_before）。方案 A 不动数据结构；方案 B / C 要改成多个，桌面端一起改。
  • 桌面和手机会不会都响？默认两边都响（和系统日历一致），在任一端处理后另一端下次同步时撤销。也可以做成「只在手机响」的开关。

方案 A：每项只设一个提醒。沿用现在的「提醒」胶囊和单选面板，只做两件事：真正排进系统通知；日程编辑页加一行「提醒」。数据结构不变（待办用 remind_before，日程新增同名字段），改动最小，但「前 15 分钟 + 前一天」这种组合做不到。

推荐 B 的理由

  • 你举的例子本身就是两个提醒，A 满足不了，后面还得返工改数据。
  • 列表比格子多一行高度，但每行都能写出「11/03 18:00」，用户不用心算。
  • 日程表单逐行列出提醒，和系统日历的习惯一致。
