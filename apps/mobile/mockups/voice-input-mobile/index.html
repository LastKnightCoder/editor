底层已经齐了：createMobileSpeechInputService 负责麦克风采集、流式识别和 120 秒上限，onPreview 推送边说边出的文字，cancel() 保证不交付文字；@tau/asr 的 refineSpeechInput 做 AI 润色（流式 onPreview、30 秒超时、失败降级原文）。这一版组合：入口 = 配件栏固定 🎤；输入 = 按住后从底部升起沉浸区；文字流式写在正文插入点；配了 AI 润色时，松手后原地润色再落定。

设计原则

  1. 入口不打扰：配件栏一个固定 🎤，跟「Aa」「+」同一排。
  2. 输入要沉浸：按住时整块底部区域都是录音反馈，取消目标就在麦克风正上方，和微信「上滑取消」一致，只有一个手势。
  3. 看着正文说：文字直接流在插入点，浅灰无底色；用户始终知道落在哪。
  4. 润色在原地：不弹对比面板；流光表示「正在改」，改完直接替换，想要原文点一下。
  5. 一次撤销：语音 + 润色合并为一次插入，撤销一下全部回退。

备选 A：配件栏 🎤 → 键盘位置升起语音面板。沿用现有「Aa」「+」面板的顶替键盘机制（resolvePanelHeight），正文可视区不变；录音期间正文插入点变成红色标记并锁定。面板上半是预览区（流式文字），下半是控制区。停止后不立即写入，用户点「插入」才一次性落进正文，可选先「整理」。

建议结论

  1. 首期：配件栏 🎤（卡片、文章、日记、快速捕获的编辑态）+ 阅读态 🎤（追加到文末）；按住升起沉浸区，正文流式出字，松手写入，上滑取消；不做锁定，长段按住说，最长 2 分钟。
  2. AI 润色：配置后松手进入原地润色（流光 + 胶囊），完成后替换，可「用原文」「撤销」；移动端需先接 LLM 整理适配。
  3. 第二期：创建菜单按住「卡片 / 日记」直接说。
  4. 落地结构：useHoldToDictate（手势 + 会话状态：idle / connecting / holding / cancelling / polishing / committed）驱动装饰层预览与一次性插入；DictationOverlay 负责沉浸区；配件栏与阅读态按钮只是触发器。
