移动端编辑器体验 · 设计方案颜色直接取自 @tau/themes · 手机帧 360×760 · 键盘为系统绘制示意

桌面编辑器的三板斧（悬浮选区工具栏、hover 拖拽手柄、斜杠菜单）都依赖鼠标的「悬停 + 精确指向」，移动端没有悬停、手指遮挡视线、键盘吃掉近一半屏幕，还要和系统选区菜单抢位置。主流移动端编辑器的共识是：把工具放到拇指区（键盘上沿），把块操作从「拖」改成「选中后点」。

提炼出的 6 条设计原则

  1. 贴键盘，不悬浮：工具栏和键盘长成一体，跟着键盘升降；收起键盘即消失。
  2. 面板顶替键盘：二级面板（样式、插入）占用键盘的高度，正文可视区不缩、不跳。
  3. 上下文变形：同一条配件栏，按「选中文字 / 表格 / 代码块 / 插件块」切换内容，不堆按钮。
  4. 先选中，再操作：块移动、删除、转换走「选中块 → 底部操作栏」；拖拽是快捷方式，不是唯一入口。
  5. 不和系统抢：选中文字时不自绘气泡，系统的拷贝/粘贴菜单留在选区上方，我们只改配件栏。
  6. 触控尺寸 ≥ 40pt，高频项固定位置，低频项进面板，可横滑的只放「次常用」。

当前实现：MobileEditorBottomToolbar 是一条悬浮在键盘上方 12px 的横向滚动胶囊，4 组约 16 个 36px 按钮；标题、颜色、下划线是锚定在按钮上方的小 popover；插入走 ActionSheet。内核的块拖拽手柄只靠 hover 显示，移动端挂的是 HTML5Backend，触屏上实际拖不动，也没有块菜单入口。

问题清单（按影响排序）

  1. 没有块操作：手柄 hover 才出现、HTML5 拖拽不响应触摸，移动端无法移动 / 删除 / 转换一个块，只能剪切粘贴。
  2. 按钮平铺、靠横滑找：16 个按钮同权重，常用（列表、待办、缩进）和低频（下划线样式、样式文本）混排；36px 低于 40pt 触控下限。
  3. 二级是小 popover：锚在按钮上方，手指正好挡住；颜色面板 32px 色点易误触；和系统选区菜单可能重叠。
  4. 悬浮位置不稳：胶囊离键盘 12px，中间露出一条正文；键盘高度变化（切换输入法、候选栏）时会跳。
  5. 无上下文：光标在表格、代码块里时，工具栏仍是一样的格式按钮，行列操作、Tab/括号无处输入。
  6. 缺少的能力：没有缩进/反缩进、待办；没有阅读态，打开文档点哪都弹键盘（见 2.1）。
  7. 没有插件位：工具栏是硬编码数组 ROW_GROUPS，插件的 blockPanel、menu 贡献在移动端无处承接。

可复用的资产（不必推倒）

  • useMobileEditorToolbarController：聚焦、选区记忆与恢复、动作执行、激活态判断，直接作为新 UI 的大脑。
  • useKeyboardViewport / --kb-height：已有原生键盘高度，「面板顶替键盘」正好要用它。
  • 内核 EditorMenuEntry 块菜单（转换、剪切、复制、删除、上移、下移，带 when、group）：移动端块操作栏直接消费，与桌面同源。
  • 斜杠菜单 blockPanel 数据：插入面板直接消费，插件贡献的条目自动出现。

方案 A（推荐）：贴键盘配件栏 + 面板顶替键盘。一条 46px 的配件栏贴在键盘上沿：左端固定「+」，右端固定「收起键盘」，中间放 6～8 个高频项（可横滑、可自定义）。点「Aa」或「+」时收起键盘，在原键盘位置升起同高的面板，正文可视区不变；再点一次或点正文回到键盘。路线同 Apple 备忘录、飞书、Notion。

打开已有文档默认进入阅读态：没有光标、键盘和工具栏，整屏留给内容。单击只做「阅读里的交互」（打开链接、勾选待办、看大图、展开折叠块），双击正文或点顶栏「编辑」才进入编辑，光标落在双击的位置。收起键盘或点「完成」回到阅读态。这样能解决「点哪都弹键盘」的问题，也给高亮、批注这类不改正文结构的操作一个不必进入编辑的入口。

状态切换

  • 阅读 → 编辑：双击正文（光标落在该处）／ 点「编辑」（光标回到上次位置，没有则在末尾）。
  • 编辑 → 阅读：点「完成」／ 配件栏「收起键盘」。只滚动正文不退出编辑。
  • 编辑态打开 Aa / + 面板时键盘虽然收起，但仍算编辑态，「完成」照常显示。

实现要点

  • 页面持有 editing 状态，编辑器 readOnly = !editing；工具栏现有的 readonly 参数直接复用。
  • 只读下要单独放开待办勾选、链接点击：需要确认这些元素在只读时的点击逻辑。
  • 双击定位：caretPositionFromPoint 拿到 DOM 位置后转成 Slate 位置。

方案 B：保留悬浮胶囊，做减法 + 二级改底部抽屉。改动最小：胶囊只留 7 个固定按钮（不再横滑），按钮放大到 40px；二级从小 popover 改成从底部升起的 Sheet。代价是 Sheet 和键盘只能二选一：要么键盘保留、Sheet 叠在键盘上（正文只剩一条缝），要么收键盘（就变成了方案 A 的面板，只是外观不同）。

四个插件位与协议映射

位置插件提供现状
① 配件栏固定项commands（加 icon）需小扩展：命令可带图标
② 插入面板blockPanel已有 桌面斜杠菜单同源
③ 块「更多」菜单menu（EditorMenuEntry）已有 桌面手柄菜单同源
④ 上下文工具栏commands + when留位，暂不设计

移动端宿主的「工具栏项」统一成一个内部模型，内置动作和插件命令都转成它，UI 不区分来源：

// 宿主内部模型（示意，非插件协议）
type MobileToolbarItem = {
  id: string;            // "builtin:bold" | "plugin:mindmap.insert"
  title: string;
  icon: IconSource;      // 内置 lucide；插件给 svg 字符串
  slot: "accessory" | "insert" | "blockMenu" | "context";
  when?: string;         // 复用内核 when 表达式
  run(ctx): void;        // 内置走 toolbarActions；插件走 command
  source?: { pluginId: string; name: string };
};

插件协议这边只需一处增量：EditorCommand 允许带 icon（桌面也可以用来做命令面板图标）。其他三处都是现有字段。
