# 主题切换闪烁调试与渲染瓦片预算经验（2026-09）

## 问题现象

设置页 → 主题弹层内点击切换主题的瞬间，弹层下方的页面内容"闪现盖到弹层上"，
随即又被弹层遮住，肉眼观感为闪一下。任何主题间切换均触发（纯浅色互切也一样）。

## 根因结论

**不是层级（z-index）问题，是 Chromium 瓦片（tile）光栅化内存瞬时超限。**

证据链（全部来自 logcat，无需截图）：

1. 切换瞬间 logcat 稳定刷出：
   `E chromium: [ERROR:cc/tiles/tile_manager.cc:998] WARNING: tile memory limits exceeded, some content may not draw`
   单次切换 20~40 条，时间分布与点击精确对应；非切换时段零输出。
2. 对照实验：首页连续 8 次 fling 滚动（同样产生大量新瓦片需求）= **0 条**警告。
   说明瓦片预算并非常态紧张，问题出在主题切换特有的失效形态：
   换主题 = `html[data-theme]` 上的 CSS 自定义属性全部换值 = 所有层、所有可见元素
   的绘制属性同帧失效 → 全部瓦片同帧作废 → 新旧瓦片并存期瞬时占用翻倍 → 超预算
   → 部分已显示瓦片被驱逐/新瓦片拒画 → 弹层（mask/panel）区域短帧空白 → 底层
   页面内容裸露。滚动是增量光栅化（旧瓦片复用），没有这个"全量同帧翻新"形态。
3. 消融实验归因（单次切换警告数）：

   | 配置                           | ViewTransition | 警告/次 | 视觉       |
   | ------------------------------ | -------------- | ------- | ---------- |
   | 原始（dock blur + 分主题噪点） | 无             | 20~28   | 必现闪     |
   | 禁 dock blur + 禁噪点层        | 450ms 罩屏     | 2       | 不闪       |
   | 禁 dock blur + 分主题噪点      | 150ms 罩屏     | 4       | 偶现闪     |
   | 禁 dock blur + 共用噪点        | 无（直切）     | 33~39   | 必现明显闪 |

   两个结论：
   - AppDock 的 `backdrop-filter: blur(20px)` 是瓦片预算最大消耗者（约 85% 贡献）；
   - ViewTransition 罩屏期间 Chromium 对整树翻新的调度形态完全不同（警告数降一个
     量级），且旧状态快照罩屏是唯一被证实能消除裸露感的手段。直切路线被证伪。

## 为什么"给弹层加 transform: translateZ(0) + willChange: transform"无效且有害

- 合成器的层叠顺序由 paint 阶段按 z-index/DOM 顺序每帧重算，与层的创建时间无关，
  "全局重绘期间背景页反超弹层"的机制不存在；本 app 全部 z-index 是 JS 内联常量
  （router/zIndex.ts），主题切换根本不触碰它们。
- `translateZ(0)`/`willChange` 的语义恰是"让元素常驻独立合成层"，每层独占一套
  全屏瓦片内存——在预算紧张的场景是**加重**问题，不是缓解。
- 已撤除 BottomSheet / ActionSheet / MobileConfirmDialog 上的该组属性。

## 最终修复

1. `themeStore.ts`：主题 DOM 写入包进 `document.startViewTransition`，callback
   内 `await sleep(350)` 后 resolve——resolve 前旧状态快照持续罩屏，等可见区瓦片
   画完再交叉淡化。实测 150/250ms 仍偶现裸露、350ms 稳定、450ms 冗余。
   不支持 VT 或 `prefers-reduced-motion: reduce` 时回退直切。
2. `AppDock.tsx`：移除 dock 的 `backdrop-filter`（dock-bg 已 92% 不透明，视觉
   损失可忽略），这是瓦片预算的最大头。
3. `styles.css`：噪点/氛围光由 `body::before` + `body::after` 两个全屏伪元素合并
   为单伪元素多重背景；`--texture-noise` 跨主题共用 `:root` 一份（4% 透明度噪点
   的色调差异肉眼无感），主题切换时该层不再参与重光栅化。
4. `index.html`：修复首帧脚本使用已废弃主题 id `nocturne` 的问题（styles.css 已
   无该主题规则，且脚本不认识 `midnight`），对齐 themeStore 的存储格式。

## 渲染治理红线

- 禁止全屏元素的 `backdrop-filter`（含常驻弹层背景）；小面积需谨慎评估。
- 避免随主题切换而变化的全屏纹理/背景图（会加入"全量同帧翻新风暴"）。
- `translateZ(0)` / `will-change` 不作为层级问题或性能问题的默认手段——它换来的
  是瓦片内存占用。
- ViewTransition callback 未 resolve 期间页面输入会被挂起，罩屏窗口不要超过
  必要时长（本场景 350ms）。

## 调试方法论沉淀（release 构建无 CDP 时）

- **logcat 瓦片警告计数**是最有效的量化指标：`adb logcat | grep "tile memory
limits"`，按秒聚合即可与操作对齐；它同时是消融实验的观测量。
- **滚动对照**：用连续 fling 区分"预算常态紧张"与"特定操作全量失效风暴"。
- **消融实验**：逐项禁用候选层（纹理层/backdrop-filter/合成层提示），以警告数
  归因，比理论推断可靠。
- **uiautomator dump** 可替代截图做精确定位（无障碍树带 text + bounds，纯 XML），
  注意 WebView 内容整树是一行、节点属性顺序不定，需按 node 串解析。
- adb 在 Git Bash 下：远端路径必须整条命令加引号（`adb shell "cat /sdcard/x"`），
  否则 MSYS 会把 `/sdcard` 转成本地盘符；screenrecord 后台任务易被会话管理截断
  且文件缺 moov，本场景用警告计数代替录屏更高效。

## 遗留事项

- 罩屏窗口 350ms 是本机（WebView 143，渲染进程受厂商省电策略限速）的实验值，
  低端机可能需要更长；若后续报告仍偶现裸露，可上调至 450ms（已验证安全值）。
- VT 罩屏期间输入挂起属规范行为，主题连续快速切换会被 350ms 节流，属预期。
