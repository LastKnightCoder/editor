移动端编辑工具条 · 改版方案对比

背景：编辑器（Slate 富文本）的底部工具条目前是「撤销/重做 + 4 组格式按钮 + ⋯ 更多」的单行横向滚动胶囊， H1 / H2 各占一格，且没有图片入口——选图在移动端被 editorRegistry.tsx 显式拒绝。 要加图片、还要容纳更多新操作，单行空间已经不够。下面先复刻现状作对照，再给出 4 个可交互的改版方案， 每个手机里的按钮都能点，敲定方向后再写代码。

方案 0 · 现状复刻对照组

以下 4 个方案都包含两项共同改动，先在这里说明，后文不再重复。

当前布局的问题

  • H1、H2 各占一个独立按钮，占了 2 格却没有 H3（编辑器本身支持 1–6 级）
  • 没有图片 / 媒体入口，粘贴之外无法插图
  • 14 个操作平铺一行，高频低频混排，靠横向滚动找按钮
  • 「⋯ 更多」弹条已塞 5 项，继续加会越来越长

四个方案共同的基础改动（无论选哪个都包含）：

标题收纳：H1/H2 → 单个「H」按钮

点击弹出横条选择 正文 / H1 / H2 / H3，弹条内用真实字号做层级预览，当前级别高亮。腾出 1 格给图片。toggleHeaderBlock 扩展 level 3。

图片入口

上传链路 IResourceService.upload（tauri uploadResource）已可用；缺的是选图入口——需接 tauri 照片选择器或 WebView <input type="file"> 兜底，替换被拒绝的 IFileService.select。

新操作的去处（各方案差异点）

候选：拍照、视频、音频、表格、代码块、任务列表、日期、批注、关联内容……放哪里、怎么弹，就是下面 4 个方案要对比的核心。

试一试：H1/H2 可点击切换激活态；「⋯」可弹出更多菜单（现状交互）。

方案 A · 收纳弹条最小改动

保持现有「单行滚动 + 顶部弹条」的全部模式不变：H1/H2 收成「H」弹出，图片一步直达，新操作继续进「⋯」弹条（弹条可横向滚动变长）。

A · 收纳弹条

改动成本 ★☆☆☆☆　·　扩展性 ★★☆☆☆

思路：不引入任何新交互模式。主行净变化 = 「-H1 -H2 +H +图片」长度不变；所有长尾操作（现有的样式文本/代码/快捷键/批注/关联内容 + 未来的表格/日期…）都堆进「⋯」弹条，弹条横向滚动。

  • 实现最小：弹条完全复用「更多菜单」的 portal + calculateFloatingPosition 模式
  • 图片高频操作一步直达，不弹任何面板
  • 用户心智零变化，无学习成本
  • 「⋯」弹条会越长越长，10+ 项后回到「挤一行」的老问题
  • 低频操作两层深（⋯ → 目标），发现性一般
  • 没有给「插入类」操作建立独立心智，将来还得再改
改动小涉及 MobileEditorBottomToolbar.tsx / toolbarActions.ts无新组件

试一试：点「H」→ 弹出 正文/H1/H2/H3（会真实改变文章标题字号）；点「图片」→ 光标处插图 + toast；点「⋯」→ 弹出加长版更多菜单。

方案 B · 插入面板 +推荐

新增一个「+」按钮打开底部 ActionSheet（项目现成组件，六色语义图标），所有「插入类」操作收口进面板；图片因为高频，在主行保留直达按钮。

B · 插入面板 +（图片直达变体）

改动成本 ★★★☆☆　·　扩展性 ★★★★★

思路：把「格式」和「插入」两类操作分开——格式留在主行，插入（图片/拍照/视频/音频/表格/代码块/任务/日期/批注/关联内容…）全部进「+」面板。面板直接复用 ActionSheet，只是传一组 items 配置，零新 UI 组件。打开面板时键盘收起让位（demo 已模拟），选择后键盘回弹。

  • 容量近乎无限：加多少操作都只是一行配置，主行永远不膨胀
  • 「+」= 插入的心智非常清晰，和 Notion / Bear 等编辑器一致
  • ActionSheet 自带返回手势拦截、下拉关闭、退场缓冲，工程上零成本
  • 图片保留主行直达，高频操作不被面板拖慢
  • 「⋯ 更多」被「+」吸收合并，主行反而少一格
  • 除图片外的插入操作需要两步（+ → 目标）
  • 面板打开时键盘收起，节奏被打断一次（选择后自动回弹）
  • 插入项多了要分组（demo 已按 媒体/结构 分两卡）
扩展性最强复用 ActionSheet涉及 editorRegistry 选图链路

试一试：点「图片」→ 直达插图；点「+」→ 键盘收起、面板弹出 → 选任意项 → 光标处插入对应块、键盘回弹。

方案 C · 双行展开全可见

工具条尾部加「⌃」展开钮，向上展开第二行平铺所有插入操作；所有操作单次点击可见可达，代价是工具条高度翻倍。

C · 双行展开

改动成本 ★★★☆☆　·　扩展性 ★★★☆☆

思路：主行保持格式操作，尾部「⌃」切换第二行（图片/拍照/视频/音频/表格/代码块/任务/日期 平铺一行）。展开是临时态，收起恢复单行。占位高度变量 --mobile-editor-toolbar-occlusion 读的是实测 offsetHeight，天然兼容变高。

  • 所有插入操作一眼可见、单次点击直达
  • 不离开键盘上下文，不打断输入节奏（面板 B 会收键盘）
  • 第二行数量适中时（≤10）体验很好
  • 展开后工具条 ≈ 92px，键盘 + 工具条最多占到屏幕 55%，小屏设备遮挡明显
  • 顶部弹条（H、调色板）要重新处理与第二行的层叠关系
  • 第二行也塞不下太多，超过 10 个又回到滚动/分页问题
高度翻倍展开为临时态需处理弹条层叠

试一试：点尾部「⌃」→ 第二行滑出、按钮翻转 → 点「图片」等任一按钮直接插图；再点「⌄」收起。

方案 D · 分页工具条iOS 键盘风

单行高度不变，内容横向分成两页（格式页 / 插入页），scroll-snap 滑动切换 + 页点指示——iOS 原生键盘切表情/输入法的模式。

D · 分页工具条

改动成本 ★★★★☆　·　扩展性 ★★★☆☆

思路：第 1 页 = 高频格式（B/I/S/H/列表/引用/下划线/链接/颜色/高亮 + 撤销重做），第 2 页 = 插入与低频（图片/拍照/媒体/表格/代码块/任务/日期/批注/关联…）。页点在胶囊内底部，滑动或点页点切换。

  • 行高不变，视觉最克制，每页都不拥挤
  • 格式 / 插入两页分区清晰
  • 去掉「横向滚动无尽找按钮」的模糊感，改成分页的确定感
  • 第二页操作「藏」起来了，不滑动根本不知道存在——发现性最差
  • 跨页组合操作（先加粗再插图）要来回滑
  • 与现有横向滚动心智冲突，交互回归测试量最大
  • 页点占据约 10px 高度，按钮区实际变矮
发现性弱交互改动最大需两套页配置维护

试一试：左右滑动工具条或点页点切页；第 2 页点「图片」→ 光标处插图。

横向对比决策

方案主行长度新操作容量图片直达其他插入操作工具条高度实现成本
A · 收纳弹条不变（14）低（弹条滚动会变长）✓ 一步两步（⋯ → 目标）不变小
B · 插入面板 +减 1（13）近乎无限✓ 一步两步（+ → 面板）不变中（含选图链路）
C · 双行展开+1（15）中（第二行 ≤10）✓ 一步展开后一步展开时 ×2中
D · 分页工具条每页 ≤14中（两页各 ≤14）✓ 一步（第 2 页）切页后一步不变（页点 -10px）大（交互回归）

推荐：方案 B（插入面板 +，图片直达变体）

你的核心诉求是「还想加更多操作」——这是容量问题，A 治标、C/D 容量有上限，只有 B 把容量问题一次性解决： 插入项以后随便加（表格、日期、Callout、画板……），主行永远只有 13 个按钮。 图片作为最高频的操作保留直达按钮，不牺牲常用路径；面板复用现成 ActionSheet，唯一真正的工程量在选图链路（tauri 照片选择器）——这部分四个方案都躲不掉。 如果想更省，A 可以作为 B 的第一阶段先落地（先把 H 收纳 + 图片直达发出去，+ 面板二期再加），两者不冲突。
