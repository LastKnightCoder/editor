00现状还原（对照基准）

当前卡片详情头部为「7px 彩点 + 彩色分类名」一行，下接「时间 · 字数」meta 行；标签 chips 与关联折叠块沉在正文底部。 统一素材（一张「永久卡」笔记、3 个标签、3 条关联）贯穿全部方案，方便横向对比。

现状问题

平铺直叙，缺少层级锚点

  • 类型识别弱：7px 彩点 + 13px 文字在整页里几乎隐形，四种卡片类型长得一样。
  • 信息无分组：类型 / 时间 / 字数 / 标签 / 关联五类信息各自散落，没有视觉上的「归属」。
  • 底部太轻：标签和关联都是 bg-input 灰底块，与正文拉不开关系，像被遗忘的脚注。
  • 没有添加入口：标签、关联都只能去编辑态处理，阅读态看不到「这里可以加东西」的暗示。

A徽章行 · 定稿（可交互）

定稿方向：方案 A 徽章行头部 + 方案 D 的 surface 浮起胶囊标签 + 完整关联交互。下方样机为可交互 demo——点关联入口卡可展开列表；点「＋ 添加关联」呼出选择弹层，勾选内容后「完成」即写入；点「＋ 标签」可现场输入新标签。

定稿 · A 头部 × D 标签

方案 A · 徽章行

  • 类型：分类色 soft 胶囊徽章（zap / infinity / shapes / book-open 四色图标），一眼区分四类卡。
  • 时间 / 字数：与徽章同行右续，圆点分隔，tabular-nums 对齐。
  • 标签：方案 D 的 surface 浮起胶囊（shadow-card 微投影），与关联入口卡同层浮起；行尾虚线 chip 即添加入口，点按原位变输入框。

B索引卡头 · 元信息装进一张卡

头部信息装进一张 surface 浮起「索引卡」：左侧分类色竖条 + 分类图标块 + 两行元信息，字数以大数字右对齐成视觉锚点；标签与关联合并成底部「整理卡」，一张卡管住所有附加信息。

分区感 · 信息容器

方案 B · 索引卡头

  • 类型：4.5px 色条 + 图标块 + 名称，与列表卡片的卡片语言一致，最「有归属感」。
  • 时间 / 字数：时间入主行；字数大数字右对齐（1,248 比 12px 小字醒目但不吵）。
  • 标签 + 关联：合并「整理卡」——上标签下关联，hairline 分隔，关联直接展示前 2 条 + 「管理关联」。
  • 阅读动线：头部一张卡 → 正文一张「纸」 → 底部一张卡，三段式结构。
适合：希望元信息「有容器、成体系」，且关联需要常显（不只是折叠入口）的场景。

C编辑部风 · 纯排版，零容器

完全走排版气质：类型做成 overline（分类色短线 + 拉宽字距小字），正文后以对称细线分节；标签退为无底色纯文字，关联做成目录式列表（每条一行、类型点标身、可点击），列表下方常驻虚线「添加关联」。最像一本装帧好的书。

纸感 · 排版气质

方案 C · 编辑部 overline

  • 类型：短线 + 0.22em 字距 overline，杂志栏目标题的语言，安静但有身份。
  • 时间 / 字数：overline 下常规 meta 行，与正文拉开 8px 呼吸。
  • 标签：去掉 chip 底色，「#」用分类色，整行居中排在细线之间，轻到不像控件。
  • 关联：目录式两行（图标 + 标题 + 类型 + chevron），常显可点；底部虚线「＋ 添加关联」常驻。
适合：卡片内容以文字为主、追求「阅读器」气质；关联使用频率高、需要直达子卡的场景。

D沉浸色带头 · 颜色即身份

顶部一段分类色 soft 渐变色带，配一枚实底圆形分类图标做视觉锚点；类型、时间、字数都在色带里。四种卡片类型一进来就有完全不同的第一屏，记忆点最强。标签 chips 换 surface 浮起底，关联为横向入口卡。

氛围 · 类型即皮肤

方案 D · 沉浸色带头

  • 类型：soft 渐变色带 + 实底圆角图标块（带同色投影），头像级锚点，类型识别度四案最强。
  • 时间 / 字数：随图标右侧两行排布，沉浸但克制。
  • 标签：surface 浮起 chip（替代 bg-input），在色带下方形成第二层。
  • 关联：浮起入口卡 + 计数胶囊，同方案 A 的语言，全页一致。
适合：把「卡片类型」当产品核心概念、希望第一眼就传达分类身份的取向。注意深色主题下 soft 色带透明度需要校准。

05添加交互 · 标签输入态与关联选择弹层

四个方案共用同一套添加交互（与方案无关，可独立选用）：标签走「行尾虚线 chip → 内联输入」；关联走「添加入口 → SnapSheet 选择器」。 左卡为标签的两个状态；右卡为添加关联的底部弹层线框（搜索 + 最近内容 + 已选对勾）。

06通用详情页 · 文章 / 知识库 / 项目文档

把卡片详情定稿的语言（徽章行 · surface 胶囊标签 · 轻量「＋」行）推广到三个有标题的通用详情页，结构对齐知识库样机。 规则：有标题的内容，标题在上、类型文案进胶囊、并入标题下的 meta 行（卡片无标题所以徽章独占一行）；三个页面的 meta 统一为「时间 · 字数」，不再展示作者 / 阅读时长； 底部区块统一只设标签区（articles / document_items 均有 tags 列），知识库与项目文档另加「来源行」表达 ref 引用；均不设关联区。 项目文档的类型徽章直接复用项目内八种类型体系（itemTypeMeta）。

沉浸封面 + 标题

文章详情（对齐知识库结构）

  • 头部：沉浸封面不动；标题（就地编辑）之下，徽章行 =「文章」rose 胶囊（类型文案进胶囊，与卡片「永久卡」同一语言）+ 时间 · 字数——与知识库 meta 完全同构，单行放下。
  • 不再展示作者：文章 meta 去掉作者字段，信息与知识库严格一致。
  • 标签：articles.tags 有列——与卡片同一套 surface 胶囊 + 「＋ 标签」内联添加。
  • 不设关联区：正文之后到标签即收尾，与知识库同构。
改动：meta 行改为「胶囊 + 时间 · 字数」；正文后补标签区。

07选型总览

四案都基于现行设计令牌，不引入新颜色 / 新圆角体系；差异只在「元信息的容器化程度」与「类型的呈现强度」。

方案类型识别信息密度改动成本一句话定位
A · 徽章行中高（一行全装下）低 · 半天最稳的最小改版，先解决「看不见类型、没有入口」
B · 索引卡头中高高（头部卡 + 整理卡）中 · 1–2 天结构感最强，标签关联成体系，适合重度整理流
C · 编辑部风中（气质型）中中 · 1–2 天最像书，阅读体验最好，关联直达子卡
D · 沉浸色带最强中中高 · 2 天第一屏冲击力最大，类型即皮肤，需校准深色
组合建议：四案的头部 / 标签 / 关联三个区块可自由拼装。例如「B 的索引卡头 + C 的目录式关联」——头部有容器、关联可直达； 或「A 的徽章行 + B 的整理卡」——头部轻、底部重。定下方向后我再把选中组合落到 ContentDetailPage / TagChips / LinksDisclosure。
