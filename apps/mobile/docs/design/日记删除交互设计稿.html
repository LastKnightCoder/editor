日记删除交互 · 六案对比设计稿

针对日记卡片删除的重新设计。下方每个手机内都是真实可操作的交互原型（支持鼠标拖拽 / 长按 / 点按），视觉与动效完全按现有设计 token 还原（奶油纸、陶土橙、20px 卡片圆角、暖棕投影）。选定期方案后再落地到代码。

1滑动方向反直觉

现在是右滑露出左侧删除块。iOS / Android 主流习惯是左滑露出右侧操作，反向手势学习成本高、易误操作。

2删除按钮视觉过重

操作区固定 78px 宽、与卡片同高的整块渐变底色。日记卡片含正文预览本来就高，色块面积随卡片高度放大，越高越笨重。

3「N 个片段」无意义

片段是内部数据概念，用户不关心数量。DiaryCardItem.tsx:140 的这个标签建议直接移除，meta 行只留「N 字 + 心情」。本稿所有卡片均已移除。

✓二次确认已存在

代码里其实有确认弹窗（DiaryHomePage.tsx:340 MobileConfirmDialog）。若真机上点删除未弹窗，请先检查构建版本。新方案统一保留「确认弹窗 / 撤销 Toast」兜底。

方案 0

现状复现 · 右滑 + 全高色块

按线上实现 1:1 复现：向右滑卡片，露出左侧 78px 宽、与卡片等高的渐变删除块。注意卡片越高色块越显笨重——这是要修的问题基线。点击删除可体验现有二次确认。

9:41
👉 按住卡片向右滑
实现成本：零（现状）
方案 A

左滑 · 悬浮圆钮

把滑动方向改为左滑露右侧（符合主流习惯），同时把「全高色块」换成一枚 56px 圆形悬浮按钮：直径固定，视觉重量与卡片高度彻底解耦——卡片再高，按钮也只是卡片背后一枚小圆点，随滑动进度弹性浮现。SwipeActionRow 的互斥、阈值回弹、防误触机制全部沿用，仅反向 + 换视觉。

9:41·
👈 按住卡片向左滑
优点保留滑动手势习惯，改动最小（方向取反 + 删除按钮视觉）；圆钮轻量不喧宾夺主。
代价仍是手势入口，新用户可发现性弱；滑动与卡片内横向内容（未来若有）有冲突风险。
实现成本：低 · 半天内
方案 B

卡片「···」· 显式气泡菜单

不再依赖任何手势：卡片标题行右端放一枚极轻的 「···」按钮（ink-3 色、28px 圆形热区），点按弹出气泡菜单：置顶 / 分享 / 删除。零学习成本、入口永远可见，且天然承载未来的卡片级操作。「N 个片段」移除后 meta 行更干净。

9:41·
👆 点卡片右上角「···」
优点入口显式、可发现性最好；菜单可扩展（置顶、分享、移动分类…）；完全避开手势冲突。
代价卡片上常驻一个视觉元素（可做到极轻）；多一次点按才到删除。
实现成本：低 · 新增一个 Popover 组件
方案 C

长按卡片 · 底部操作面板

推荐主案

把整张卡片视为「对象」： 长按约 0.5s 触发（卡片轻微下沉反馈），从底部弹出操作面板（复用现有 SnapSheet / ActionSheet 语言：30px 圆角、grabber、条目式菜单）。卡片本身零视觉污染——没有任何常驻按钮，也没有任何方向性手势。这是 iOS 对富内容卡片的主流做法，且面板条目可无限扩展。

9:41·
🖐 按住任意卡片约半秒
优点卡片视觉最干净；无手势方向歧义；面板由现有 ActionSheet 改造，动效语言统一；扩展性最好。
代价长按有轻微学习门槛（但有系统级惯例背书）；需要长按与滚动的意图判定（8px 阈值即可，SwipeActionRow 已有同款逻辑）。
实现成本：中 · 复用 ActionSheet + 长按 hook
方案 D

整卡拖甩 · 飞出 + 撤销兜底

最爽快的一档：按住卡片直接向左拖，卡片实时跟手（不限于固定宽度），底下露出玫瑰色底板；拖过阈值（96px）底板「武装」变色，松手后卡片旋转飞出、列表收拢，底部 Toast 提供 5 秒撤销——用「事后撤销」替代「事前弹窗」，删除一步到位。适合高频删除的爽快派。

9:41·
👈 按住卡片用力向左拖，松手
优点一步完成、跟手物理反馈强、有「甩掉」的情绪价值；撤销比弹窗更不打断。
代价误删率最高，完全依赖撤销兜底（撤销 Toast 需要可靠的缓存恢复）；整卡拖拽与虚拟列表（react-virtual）配合要小心。
实现成本：中高 · SwipeActionRow 大改 + 撤销系统
方案 E

管理模式 · 多选批量删除

补充场景而非日常入口：顶栏「管理」进入编辑态，卡片左侧滑入选择圈，点卡片切换勾选；底部浮出毛玻璃工具条，「删除 (n)」随选择数激活，确认后所选卡片依次收拢。适合定期清理大批日记，日常单个删除仍走 A/B/C。

9:41·
👆 点右上角「管理」进入编辑态
优点批量删除效率碾压；确认一次删多篇；编辑态是成熟的列表模式。
代价日常单个删除路径太长，不能独立承担删除职责；列表需引入编辑态状态机。
实现成本：中 · 列表编辑态 + 工具条

我的推荐

1
C 长按面板 为主入口

富内容卡片的对象级交互惯例；卡片零视觉污染；直接复用现有 ActionSheet 与动效语言；未来加「置顶 / 分享 / 导出」零成本。

2
+ A 左滑圆钮 作为快捷双入口

保留滑动用户的肌肉记忆（方向修正为主流左滑），与 C 并存是 iOS 常见组合；A 本身改动极小，可以先行落地。

3
+ 全局「撤销」Toast 兜底

无论哪个入口删除，Toast 5 秒撤销作为弹窗之外的第二层保险，之后可逐步把高频场景的弹窗换成语境化撤销。
