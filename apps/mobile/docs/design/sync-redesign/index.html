数据与同步 · 三个重构方案

同一套功能、同一套杏子设计令牌，三种信息架构与交互模式。每份原型均为可点击交互稿，支持浅色（杏子）/ 深色（玄夜）主题预览。

现有设计的核心病灶

1. 单选被伪装成开关：4 个同步服务各挂一个 Switch，实际互斥——用户以为能多开，点第二个第一个会被关掉。

2. 平铺式长表单：同步分段一次堆 5 张大卡 + 4 份几乎相同的表单，每个 provider 还各配一个「保存配置」按钮，实际保存的是全局配置。

3. 危险操作无收口：整库上传/下载（会覆盖一端数据）与「刷新」平级混排在同一按钮网格，形状还不统一（圆角矩形 / 胶囊混用）。

4. 状态信息弱：本地 vs 远端版本只是两个裸数字，没有方向感（谁领先、差几个版本），用户需要心算。

方案对比

方案 A

状态中心 Status Hub

参考 iCloud 设置 / Obsidian Sync / Working Copy

  • 状态英雄卡：本地 ↔ 远端版本可视化 + 智能建议 + 单一主操作
  • 同步服务改 radio 单选卡，手风琴展开当前表单
  • 手动上传/下载降级为次级行，sheet 确认方向
  • 信息密度最高，适合「同步是高频操作」的定位
打开交互原型 →
方案 B

连接卡片 Connections

参考 Stripe / Linear 的 Integrations 页

  • 凭证 + 业务参数合并进同一张连接卡，消灭「集成」分段跳转
  • 连接三态徽章：未连接 → 已连接 → 使用中
  • 「设为同步服务」显式按钮表达单选
  • 状态压缩为顶部一行，点击展开；分段从 4 减到 2
打开交互原型 →
方案 C

极简分组 Grouped

参考 Apple 设置 / Wi-Fi 选择器的导航纪律

  • 主页只做选择：单选组 + checkmark，一屏放下全部入口
  • 所有细节（状态详情 / 服务配置 / 资源进度）push 子页
  • 整库覆盖独立成红色危险组，与日常操作物理隔离
  • 最克制、学习成本最低，改动量也最小
打开交互原型 →

落地说明

· 三案共用 app 现有设计令牌（--bg-surface / --brand / --sage / 圆角 / 阴影全部对应 styles.css），实现时按 Tailwind 工具类 1:1 映射，四套主题（杏子/玄夜/薄荷/海盐）自动生效。

· 数据流完全复用现有 SettingsPageProps 回调（onSwitchDatabase / onSyncUpload / onResourceSyncStart…），重构只动视图层，不碰业务逻辑。

· 可组合：例如「方案 A 的英雄状态卡 + 方案 B 的连接卡」可混合落地，确认方向后实现时按需取材。
