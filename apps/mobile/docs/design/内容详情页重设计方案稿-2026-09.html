内容详情页重设计

针对五类详情页的痛点：卡片顶部操作突兀、日记头身割裂、文章信息重复、项目与知识库层级混乱、整体字体偏小。 本稿只做设计提案，不动业务代码——每个方案都是静态高保真样机，等审阅通过后再落到 React 组件。

两个开关实时作用于下方所有样机
01

字体与字号

先回答「是字体的原因吗」——是，但字体只占一半

结论：三个原因，按影响排序

逐条修复后正文阅读体验会有质变，前两条零成本

  • 字号偏小：编辑器正文 15px、meta 信息 11–11.5px，手机上低于舒适阅读下限（正文 ≥16px）。正文提到 17px / 行高 1.85。
  • 次要文字对比度不足：大量 meta 用 --ink-3 #b9ac9a，在奶油底上只有约 1.9:1；--ink-2 也只有 3.9:1，均低于正文 4.5:1 标准。方案：meta 统一改用新令牌 --meta-ink #7a6c5a（5.0:1），ink-3 只留给装饰。
  • 字体本身：Windows 上没有 PingFang，回落到微软雅黑；雅黑只有 400/700 两档真实字重，界面里 500–650 的中间字重全是算法模拟，小字号发虚。方案 B 内置 MiSans（330/500/600/700 真字重，已在现有 font-stack 中，令牌无需改动，woff2 离线打包）。

落到代码时的公共规范

审阅通过后按这三条先行，再逐页改造

令牌新增（styles.css）

新增 --meta-ink（浅色 #7a6c5a / 深色 #a2aab8）替代 meta 场景的 ink-2/ink-3； 编辑器字号 .mobile-card-editor-content 15px → 17px、行高 1.85； 字体栈在方案 B 下把 "MiSans" 提到首位并随包内置 woff2。

组件级收敛

详情页顶栏统一为「返回 + 状态/留白 + ⋯」；危险操作（删除）一律进 ⋯ 菜单 + 确认弹窗，不在页面常驻； meta 行统一 12.5px / meta-ink / 「·」分隔 / tabular-nums； 列表分隔线虚线 → 实线（--line-1 1px）。

页面结构模板

内容型详情（日记 / 文章 / 卡片）＝「沉浸纸面」：无元信息卡，元数据一行化； 容器型详情（项目 / 知识库）＝「页头 → 路径栏 → 列表」三段式，标题一律在内容区、顶栏去重。 ContentDetailPage 的 props 预计收敛掉 pathLabel / showSaveState 等单页特化插槽。
