任务中心 × 任务详情 · 重设计方案对比

基于 TodoPage.tsx / TodoDetailPage.tsx / PageHeader.tsx 现状重设计。 视觉令牌与「杏子 Bento」浅色主题同源，以下所有方案均假设沿用现有令牌与组件（BottomSheet / ActionSheet / MobileConfirmDialog）。 方案内 chips / 分段控件可点击切换，用于感受交互态。

现状问题（阅读代码后确认）：
① 任务中心固定头部约 350px（统计大卡 ~110px + 分组 Tabs ~62px + 双行筛选卡 ~122px + 顶栏 56px），700px 屏内列表只剩 ~3 行；
② 筛选卡的「类型」行（普通/截止/计划/周期）与系统分组（systemType: all/normal/deadline/planned/recurring）功能完全重复，同一维度暴露了两个入口；
③ PageHeader 标题在 flex-1 区间内居中：左侧返回按钮恒占 40px、右侧 actions 为空时宽 0，标题视觉中心恒右偏 ~22px；
④ 任务详情没有「完成」主操作，必须回列表页勾选；属性六行平铺，无重点；
⑤ 描述编辑器不可用：Editor 的 key 含 syncVersion + descriptionContentId，自动保存回流 → key 变化 → Slate 整树重建 → 焦点丢失；新建描述敲第一个字符还会触发 contentId 落库 → 再次 remount。
三个方案共用的前置修复（无论选哪个方案都要做）：
① PageHeader 标题改为绝对定位居中（见下方演示），左右按钮正常流，长标题 max-width 收缩 + 省略；
② 描述编辑器 key 只保留 todoId，内容回流改走受控同步（不再用 key 强制重建）；新建描述首字符落库后不换 key；
③ 「类型」筛选与系统分组二选一保留（各方案内已注明取舍）。

方案 B3 · 大清单 + 底部操作栏 操作型实现成本中

  • 备注查看要一跳；信息折叠多一层
  • 新增全屏编辑路由/浮层，实现面最大
