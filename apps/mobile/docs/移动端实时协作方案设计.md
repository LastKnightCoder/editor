# 移动端实时协作方案设计

## 1. 背景与目标

Tau 的实时协作能力目前覆盖「协作服务器（**`apps/collaboration-server`**）+ 桌面端（Electron）」两端。协作服务器是协议中立的单体服务，桌面端通过 Hocuspocus 协议（y-websocket 兼容）+ REST + 事件流三通道接入。移动端（Tauri 2 + React 19）尚未接入协作。

本方案目标：

1. 移动端可作为**成员**加入协作房间，实时协同编辑（远端光标、在线状态、状态同步）；
2. 移动端可作为**发起者**把本地内容（卡片/文章正文）共享为协作房间，管理协作码、成员与加入审批；
3. 最大程度复用 `@tau/collaboration`（协议 + Slate⇄Yjs 投影）与 `@tau/editor` 的协作插件层，**协作服务器零改动**；
4. 遵循移动端现有架构约束：自研 router 页面栈、浮层返回拦截规范、`data-theme` 主题令牌、Android 已知问题清单（IPC 二进制、slate 光标补丁）。

`非目标（本期不做）：`

- 服务端任何协议/接口变更（包括 CORS，见 §5.2 的规避方式）；
- 离线长时间编辑与多设备合并（Yjs 天然支持短离线续传，但不做本地持久化缓存，见 §5.4）;
- 历史版本回溯（服务端无此 API）；
- 移动端私有块（白板/数据库/问答）的跨端渲染——与桌面一致，仅显示占位符。

## 2. 现状调研结论

### 2.1 协作服务端（apps/collaboration-server）

技术栈：Fastify 5 + `@fastify/websocket` + Hocuspocus 4.6（y-websocket 协议的服务端实现）+ better-sqlite3。默认部署 `https://collab.xiongtao.life`（`packages/collaboration/src/protocol.ts:2`），与 web-server 完全解耦、无中转。

**三通道：**

| 通道                | 端点      | 用途                                                                      |
| ------------------- | --------- | ------------------------------------------------------------------------- |
| WebSocket（二进制） | `/ws`     | Hocuspocus 标准协议：Yjs 文档同步 + awareness（光标/在线）                |
| WebSocket（JSON）   | `/events` | 服务端主动事件：`refresh` / `revoked` / `closed` / `presence`             |
| REST                | `/v1/*`   | 设备注册、文档列表/创建/发布、协作码、加入申请/审批、成员管理、票据、附件 |

`关键机制：`

- **无账号体系**：设备身份 `{id, secret}`（`POST /v1/devices` 注册，服务端只存 sha256 摘要）→ 每次连接前 `POST /v1/tickets` 换 60 秒 HMAC 短期票据（`apps/collaboration-server/src/store.ts:128-165`）→ WS 连接鉴权 + 每条消息再鉴权（撤权即断 4403）。
- **房间 = 共享文档**：documentId（UUID）为房间名；状态机 draft → active → closed；加入为**审批制**：12 位协作码（7 天有效、可轮换）→ `POST /v1/join-requests` → 作者批准 → 成员上限 10。
- **数据模型**：单一 `Y.Doc`：`meta` Y.Map（版本/模式/横幅）+ `title` Y.Text + `content` Y.XmlText（Slate 树，`@slate-yjs/core` 转换）+ `fields` Y.Map（代码/公式等重字段外置获得字符级合并）。私有块剥离为 `collaboration-placeholder`；附件以 `tau-collab-asset:<id>` 间接寻址。
- **presence**：awareness 的 `user` 字段被服务端强制覆写为 `{id, nickname, color}`；`activity` 白名单 `editing|viewing|background`；房间级成员列表（DB 成员 + 在线状态合并）经 `/events` 的 `presence` 事件推送。
- **限流/配额**：REST 300/min；连接数 100/设备；单文档 8MB；附件 25MB/文件。

### 2.2 桌面端（参考实现）

架构链路：**渲染进程（Slate 编辑器 + 视图级 Y.Doc 副本 + Awareness）⇄ IPC ⇄ Electron 主进程（会话编排 + 本地 collaboration.db + HocuspocusProvider）⇄ WSS ⇄ 协作服务器**。

| 关注点        | 桌面端实现                                                                                                        | 关键文件                                                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 连接管理      | 每服务器一条 `HocuspocusProviderWebsocket`（指数退避 1s→30s），每会话一个 `HocuspocusProvider`（票据 token 回调） | `apps/desktop/src-electron/main/modules/collaboration/index.ts:124-188`                   |
| REST 客户端   | 自动注册设备身份、Bearer 鉴权、身份按服务器 URL 缓存                                                              | 同上 `client.ts:5-108`                                                                    |
| 视图绑定 hook | 每视图 Y.Doc 副本 + Awareness，本地更新批量 merge 后 IPC 上送，1s 重试未送达更新                                  | `apps/desktop/src/hooks/useCollaborationDocument.ts`                                      |
| 编辑器接入    | `withCollaboration`（withYjs + withYHistory + withCursors + 字段投影/私有块拦截）                                 | `packages/editor/src/collaboration/withCollaboration.ts`                                  |
| 远端光标      | `Cursors.tsx`（光标竖线 + 姓名标签 + 选区底色，`memberColor` 12 色 oklch 色板）                                   | `packages/editor/src/collaboration/Cursors.tsx`                                           |
| 会话生命周期  | 发起（幂等键 → 创建 → publish → 绑定表）/ 加入（申请 → 审批 → refresh 发现）/ 退出（owner=close、member=leave）   | 主进程 `index.ts:567-889`                                                                 |
| 冲突防线      | 直写守卫（绑定协作后 contents 只能由投影写入）+ 乐观锁 revision + 绑定漂移检测 + 冻结协议 + generation 计数       | `content-sessions.ts` / `collaboration-guard.ts` / `content-repository.ts`                |
| 投影回写      | 每秒把 Y.Doc 物化回用户库 `contents` 表并同步标题                                                                 | 主进程 `index.ts:929-948`                                                                 |
| UI            | 协作中心（侧栏+编辑器）、右侧栏面板、内容页状态栏控制、加入申请通知卡、设置弹窗                                   | `apps/desktop/src/pages/CollaborationView/`、`components/ContentCollaborationControl/` 等 |

### 2.3 移动端现状与缺口

移动端是 **Tauri 2（Rust 壳 + 系统 WebView）+ React 19 + Vite 7 + Tailwind 4**，自研 router（`src/router/`，`definePage` glob 自动注册），zustand + TanStack Query，自研组件库（BottomSheet/ActionSheet/SnapSheet/MobileConfirmDialog 均内置返回拦截）。编辑器**深度复用 ****`@tau/editor`****（卡片详情页、快速记录、文章编辑均已接入），且 ****`@tau/editor`**** 内置协作插件层（****`withCollaboration`****/****`Cursors`****），只要提供 ****`EditorCollaborationBinding`****（Y.Doc + Awareness + 传输），编辑器侧协作即刻可用**。

现状关键约束（来自代码与已知问题文档）：

1. 前端 `src/` **零网络代码**，无 WebSocket/fetch 封装；网络全在 Rust 侧（reqwest）。
2. `@tau/collaboration` 仅 import 了纯函数子模块（`tabs-normalize`、类型），**刻意避免 yjs 进主 bundle**（`apps/mobile/src/features/cards/editorContentUtils.ts:3-5` 注释）。
3. Android WebView 下 Tauri IPC 二进制不可靠，Yjs update 走 invoke 需 base64（`services/tauri.ts:656-657` 注释）。
4. Android 下 slate-react 有光标补丁（`patches/` + `docs/slate-react-Android光标修复与补丁维护指南.md`），协作编辑器（withYjs 改变选区处理路径）落地时必须回归验证。
5. 页面栈 `<Activity>` 保活：页面压深时 effect 卸载，长连接/定时器必须挂全局或用 `usePageLifecycle`。
6. 数据库 schema 与桌面共享 `packages/db-schema`（Rust `include_str!` 内嵌），改表必须同步 `scripts/db/check-schema-parity.mjs`（AGENTS.md 规则）。

**缺口清单**（移动端需要新增的全部内容）：

- 传输层：HTTPS REST 客户端 + WSS 客户端 + 票据/重连；
- 身份层：设备注册、secret 安全存储、昵称；
- 会话层：会话管理器（对应桌面主进程）+ 视图绑定 hook（对应桌面渲染进程）+ zustand store；
- 数据层：`collaboration_bindings` 表、投影回写、（P1）本地缓存；
- UI：协作中心、加入流程、协作编辑页、成员管理、发起共享、设置模块（6 个页面，见 §6 与设计稿）。

## 3. 总体架构

### 3.1 架构选型对比

| 空          | 方案 A：WebView 直连（JS 全栈）                                                         | 方案 B：Rust WS 桥（帧转发）                                 | 方案 C：Rust 全栈（yrs）                                     |
| ----------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 思路        | 前端直接跑 `@hocuspocus/provider` + yjs + `@tau/collaboration`，WS/REST 由 WebView 发起 | Rust 侧 tokio WS 持连接，帧经 invoke/event 桥接；Yjs 仍在 JS | Rust 用 yrs 完整实现 CRDT 与投影，前端只收 JSON              |
| 复用度      | 桌面渲染进程逻辑近乎照搬（Electron renderer 本就是 Chromium）                           | 需自写 `WebSocketPolyfill` 适配层                            | 重写投影层/校验层，**放弃** `@tau/editor` 协作插件与实时光标 |
| 服务端改动  | 零（REST 走 Tauri http 插件规避 CORS，见下）                                            | 零                                                           | 零                                                           |
| 包体        | yjs+lib0+hocuspocus ≈ 50KB gz（动态 chunk 隔离，见 §5.1）                               | 同 A + Rust 依赖                                             | Rust 侧 yrs 体积                                             |
| 后台存活    | WebView 暂停即断线（重连恢复，awareness 天然掉线）                                      | Rust 连接可在后台存活                                        | 同 B                                                         |
| 复杂度/风险 | 低                                                                                      | 中：每帧过 IPC + base64 膨胀 33%、双端状态机割裂             | 极高：投影/私有块/校验逻辑全部重写且双实现漂移               |
| 结论        | **推荐**                                                                                | 不推荐（收益仅“后台存活”，但移动端协作本就是前台编辑场景）   | 否决                                                         |

**推荐方案 A**`，配套两点修正：`

1. **REST 不用 WebView fetch**（协作服务器未配 CORS，WebView fetch 会被预检拦截）：使用 Tauri 2 官方 `@tauri-apps/plugin-http`（Rust 侧发请求，无 CORS 语义，仅需在 `capabilities` 中授权作用域）。WebSocket 无同源策略约束，WebView 原生 `WebSocket` 直连即可。
2. **协作核心动态加载**：所有 yjs/hocuspocus/协作 UI 放入 `React.lazy` 动态 chunk，主 bundle 不变，首次进入协作功能时加载（保持 `editorContentUtils.ts` “yjs 不进主包”的既有决策）。

## 5. 模块详细设计

### 5.1 前端协作核心（新增 `src/features/collaboration/`）

```
features/collaboration/
├── core/                          # 动态 chunk 根：入口页 React.lazy 引用
│   ├── manager.ts                 # CollaborationManager 全局单例（会话表/事件流/票据）
│   ├── restClient.ts              # plugin-http 封装：设备注册/票据/文档/成员/审批
│   ├── identity.ts                # 身份读写（经 Rust 命令持久化）
│   └── eventsChannel.ts           # /events WS + 5s 重连（对应桌面 index.ts:449-484）
├── hooks/
│   ├── useCollaborationDocument.ts  # 视图级 Y.Doc + Awareness（移植桌面同名 hook）
│   └── useCollaborationPresence.ts  # activity 上报（editing/viewing/background）
├── store/useCollaborationStore.ts   # zustand：sessions/requests/connection（对应桌面同名）
├── components/                    # Avatar/AvatarStack/StatusDot/CollabCodeCard…
├── pages/
│   ├── collaborationCenter.page.tsx   # key: collaborationCenter, match: single
│   ├── collabEditor.page.tsx          # key: collabEditor, match: params(getId: documentId)
│   ├── joinSheet.page.tsx             # layer: overlay
│   ├── memberSheet.page.tsx           # layer: overlay
│   └── shareSheet.page.tsx            # layer: overlay
└── index.ts                       # createCollaborationApp()：懒加载装配器
```

**动态加载策略**：`manager.ts` 及其依赖（yjs/@hocuspocus/provider/@tau/collaboration 的 document.ts）全部经 `import()` 动态引入；`AppShell` 挂一个轻量 `CollaborationBootstrapper`（主 chunk，约 2KB），仅在「用户打开协作中心/协作编辑页/设置协作项」时才 `await import("./core")` 装配。`editorContentUtils.ts` 中“避免 yjs 进包”的注释同步更新为“仅经协作动态 chunk 引入”。

**会话生命周期**（与桌面语义对齐，实现从简）：

- 加入：输入协作码 → `POST /v1/join-requests` → 状态 `pending`（UI 显示等待作者批准，`/events` 收到 `refresh` 或轮询发现新文档）→ 拉取 `GET /v1/documents/:id/state` 建会话 → 进编辑页。
- 发起（P1）：从内容详情发起 → 幂等键（sha256(库+contentId+createTime+server+generation)，复用桌面算法）→ `POST /v1/documents` + `publish` → 写 `collaboration_bindings` → 返回协作码。
- 退出：member 走 `DELETE` leave（先冻结视图 drain 本地未送达更新，最多 10s）；owner 走 close（二次确认，服务端清数据）。
- 被动：`revoked`/`closed` 事件 → store 标记 → 编辑页顶横幅提示 + 自动退出到协作中心。

**轮询降频**：桌面 15s REST refresh 轮询在移动端放宽为 60s，仅在前台且已装配协作核心时运行；列表新鲜度主要靠 `/events` 推送。电量考量见 §5.9。

### 5.2 传输与鉴权

- **REST**：`@tauri-apps/plugin-http` 的 `fetch`（capabilities 配置 `https://*` 作用域或按配置服务器地址动态申请——Tauri 2 支持 runtime `permission` 扩展，最简做法是 capability 里放 `{ "identifier": "http:default", "allow": [{ "url": "https://*" }] }`，由 `normalizeServerUrl` 保证仅 HTTPS）。超时/重试沿用 `NetworkPolicy::standard()` 的 JS 等价配置（12s × 2 次）。
- **WS ********`/ws`**：`HocuspocusProvider` 默认浏览器 WebSocket；`token` 回调 = `POST /v1/tickets`（60s 票据）；重连参数沿用桌面（initialDelay 1s、maxDelay 30s，库内置指数退避）。
- **WS ********`/events`**：原生 `WebSocket`，连接后首条消息发 `{ticket}`；断开 5s 重连；票据在每次重连前重新获取。
- **每服务器单传输**：同一 serverUrl 复用一条 `HocuspocusProviderWebsocket`（与桌面一致），多房间共享。

### 5.3 身份与配置存储

- 身份 `DeviceIdentity {id, secret, nickname}` 按服务器 URL 隔离（与桌面 `identity:<url>` 键一致，便于未来导入导出互通）。
- 存储：P0 用 Rust 侧独立 JSON 文件（应用数据目录 `collaboration/identity.json`，0600 权限，新增 `collaboration_get_identity/put_identity` 两条命令）；P2 可选迁移 keyring。**secret 永不进 WebView localStorage、不进日志**。
- 昵称与服务器地址：进移动端设置（`SettingCompat` 增加 `collaboration.{serverUrl,nickname}` 字段，走既有 `read_setting_json/write_setting_json`，与桌面 setting.json 同构，见 §5.7）。

### 5.4 数据层

- **`collaboration_bindings`**** 表**（P1 发起侧需要，P0 仅需读判断）：与桌面同构（`content_id PK, content_created_at, server_url, document_id, source_type, source_id, source_title`）。落点二选一：

  - a) 进 `packages/db-schema/schema/main.sql`（全端共享，桌面已有自己的建表逻辑在 `content-repository.ts:11-32`，需确认桌面是否已把该表收进共享 schema——若未收，走 b）；
  - b) 移动端 Rust migrator 的私有迁移段（`src-tauri/src/database/migrator.rs` 追加）。
  - **推荐 b**：不动共享 schema，规避 `check-schema-parity.mjs` 联动与桌面回归；该表本就是端侧概念。

- **投影回写**：协作编辑期间，每 2s（比桌面 1s 放宽，减少移动端写放大）把 Y.Doc 物化回本地库：`readSharedContent` → contents 表 + 标题同步到对应业务表。回写走 Rust 命令 `collaboration_project_content`，入参为 JSON（Slate 树），避免 IPC 二进制。
- **直写守卫**：绑定协作的 content，常规 onChange 落库路径必须让位（桌面在 `tables/content.ts` 抛 `COLLABORATION_WRITE_REQUIRED`）。移动端为双层实现：**数据库层** `assert_content_local` 统一拒绝（`update_content`/`delete_card`/diary 直写等，错误码 `COLLABORATION_WRITE_REQUIRED`）+ **编辑器层** 详情页原地协作编辑时 `useEditContent` 以 `persistEnabled: false` 短路节流保存，本地库只接收投影管线写入。
- **P0 不做** `collaboration.db` 本地缓存（sessions/updates/resources 三表）：断网依赖 Yjs 内存态 + 重连自动交换；app 被杀则重新从服务端全量拉取。P1/P2 再评估（届时 Rust 侧新增 `collaboration.db`，结构对齐桌面 `local-store.ts:7-109`）。

### 相对本设计文档的实现偏差（调研后的优化）

1. **REST 通道改走 Rust 网关**，不再使用 `@tauri-apps/plugin-http`。移动端所有网络访问已统一收口在 Rust（reqwest + rustls），因此新增 Rust 命令 `collab_request` / `collab_get_identity` / `collab_update_nickname` 即完成 REST 与身份管理，无需新增插件依赖和 capabilities 权限，「协作服务器零改动」不变。WebSocket（`/ws`、`/events`）仍由 WebView 原生实现直连（WS 无同源限制）。
2. **会话模型简化为同进程共享 Y.Doc**。桌面端主进程与渲染进程分处两个 JS 环境，需要 Y.Doc 副本 + IPC 批量 merge + 重试队列；移动端协作运行时与编辑器同处一个 WebView，视图直接复用会话的 `Y.Doc` / `Awareness`，故删除了副本、批量转发与重试队列。
3. **运行时按需启动，不在 AppShell 常驻**。协作核心（yjs/hocuspocus）位于懒加载 chunk，`useCollaborationRuntime()` 在协作中心/加入/编辑/成员/协作设置页挂载时启动——未使用协作的用户不加载运行时，也不会在服务器上静默注册设备身份。
4. **绑定表复用既有 schema**：`packages/db-schema/schema/main.sql` 已存在 `collaboration_bindings`（与桌面同名字段），因此未改动任何 schema，规避 `check-schema-parity.mjs` 联动；绑定命令置于 `src-tauri/src/database/collaboration.rs`。

### Code Review 修复记录（2026-09-12 第二轮）

对首轮实现的全面 review 发现以下缺陷并已修复（均为架构级修复，非补丁）：

1. **写路径单一化**（原「已知限制 1」）：绑定协作的内容只允许投影管线写入。`update_content`/`delete_card`/diary 直写/三处 `decrement_or_delete_content` 级联删除统一接入 `assert_content_local` 守卫（对齐桌面 `tables/content.ts` 的 assertContentIsLocal）；投影走新增的 `collab_project_content` 命令，事务内校验 `create_time == content_created_at`，漂移（内容删除重建）自动解绑并跳过；详情页菜单「发起协作」在有绑定时切换为「查看协作」。（详情页的只读引导后续已由「原地协作编辑」取代，见下节。）
2. **发起方私有块数据丢失**：`createSharedDocument` 剥离的私有块真身此前被丢弃，投影回写会用占位符覆盖本地真身。现剥离结果并入会话 `privateNodes`，投影时经 `readSharedContent` 回填。
3. **owner 结束共享后绑定残留**：`leave`/`revoke` 统一调用 `clearLocalBindings`（解绑 + 清协作码缓存），投影漂移检测兜底清理孤儿绑定。
4. **重复发起不预检**：已绑定时 `shareContent` 直接返回现有房间（不重新发布、不轮换协作码——轮换会让已分发的旧码立即作废）。
5. **加入批准后自动进入**（2026-09-13 复核修复）：服务端 pending 响应补充返回 `documentId`（协议类型 `JoinRequestResult`），批准判定改为「该 `documentId` 出现在会话列表」精确匹配，替代原先「申请时会话基线 + 新会话出现」的模糊对比（原方案在多房间同时等待时会跳错房间）。`documentId` 仅为房间名、无凭据作用（所有访问仍经成员鉴权），持有有效协作码者本就知道文档存在，无泄露风险。
6. **会话建立竞态**：列表刷新与编辑页补建并发时 `openSession` 幂等（`opening` 表按 documentId 去重），不再覆盖出双份 Y.Doc。
7. **运行时生命周期闭环**：引用计数（`retain`/`release`）+ 空闲延迟停止（30s，有未同步改动时推迟）+ 设置开关关闭即停；`stop` 不再是死代码。
8. **启动并发切换服务器丢失**：`start` 以「目标配置 + 启动循环」实现，启动中切换服务器会被接续消费而非忽略。
9. **退出/被撤权后的导航**：编辑页统一监听「会话曾就绪后消失」自动退栈（覆盖主动退出、成员管理内退出、被撤权、被结束四种路径），替代原先 replace 造成的重复页 / overlay 残留。
10. **事件流断连兜底**：`/events` 连接失败（含取票失败）5s 定时重连（仅限当前配置的服务器），不再依赖 60s 轮询兜底。
11. **会话标题实时性**：`doc.on("update")` 维护 `info.title`，任何一端改名即时反映（对齐桌面 `restore()`）。
12. 其余：`flush` 超时对齐设计 10s，超时后仍有未同步改动则拒绝退出（`COLLAB_UNSYNCED`）；notices 原子消费防多实例重复 toast；附录 A 路由勘误（`/invitation`、`/decision`）。

### Code Review 修复记录（2026-09-12 第三轮，私有块生命周期专项）

第二轮复核发现「私有块真身仅存会话内存」存在系统性缺口，本轮补齐为三道防线：

1. **会话重建回填**（对齐桌面 `restorePrivateNodes`）：`createSession` 后 `restoreOwnerPrivateNodes` 从本地库内容恢复真身——本地带 collabId 标注按 id 恢复；无标注（首次投影未完成）按树位置与云端占位符对齐（`alignPrivateNodes`，数量 + label 逐位校验，云端结构已变即放弃）。
2. **投影防覆盖**：编辑页投影与 `shareContent` 首次投影统一守卫——物化结果仍含 `collaboration-placeholder`（真身缺位）时跳过写回并提示，绝不拿占位符覆盖本地真身。
3. **collabId 对应关系修复**：`shareContent` 复用/重试路径发现剥离 id 与云端占位符脱节（本地无标注）时，以云端为准按位置对齐恢复；对齐失败报 `COLLAB_PRIVATE_BLOCK_CONFLICT` 引导结束共享后重新发起。首次投影物化源改为云端文档 + 会话私有块，本地标注从此与云端一致。
4. 附带：`runStartLoop` 的 stop→start 交错残留目标自动接续启动（含 unhandled rejection 兜底）；owner close/leave 的 REST 失败保留会话与重试入口（云端房间不再悬空）。

已知残余限制（评审确认接受）：私有块真身恢复失败时编辑页显示占位符且投影暂停（保守正确，30s 空闲销毁会话后重进可再试恢复）；同型私有块被远端重排的对齐理论盲区（无标注窗口内，与桌面端同场景一致拒绝恢复）；投影失败静默重试无 UI 提示（数据不丢，自愈后补投）。

## 附录 D：详情页原地协作编辑（2026-09-13）

**动因**：原实现要求绑定协作的内容必须跳到协作编辑页才能编辑（详情页只读 + 引导横幅），对「作者本机发起共享」这一主场景体验割裂——作者的内容数据就在本地，理应原地编辑。

**方案**：详情页检测到协作绑定时，编辑器原地切换为 yjs 协同模式；协作编辑页保留给成员视角（协作码加入者本地无内容行，无法用详情页承载）与协作中心入口，双入口并存。

- **新增** `features/collaboration/CollaborativeEditor.tsx`：按需懒加载 chunk，内聚运行时挂载（`useCollaborationRuntime`）、Y.Doc 绑定（`useCollaborationDocument`）、owner 侧投影（`useCollabProjection`）、presence 上报与降级 UI。binding 就绪前回退为本地内容**只读**展示，杜绝用户在本地旧值上输入后被协作态覆盖。
- **抽出** `hooks/useCollabProjection.ts`：原 `CollabEditorPage` 的 2s 投影 effect（占位符防覆盖、漂移解绑提示、串行防乱序、失败回滚快照）原样迁移，两个页面共用。
- **新增** `features/collaboration/useContentCollabBinding.ts`：轻量绑定查询（不加载协作运行时），统一 5 个详情入口的接线——`contentDetail` 路由的卡片入口与 contentId 入口、`articleEditor`、`knowledgeNodeEditor`、`projectDocEditor`（后三者支持 `titleEditable`，其内容经卡片镜像同样可能被绑定）。
- **`ContentDetailPage`**：`collaboration` prop 语义由「只读 + 跳转引导」改为 `{ documentId }`；协作模式不接 `onChange` 落库（仅同步工具栏选区），`Editor` 用协作 binding 且 key 不含 `syncVersion`（yjs 模式禁止整体替换）；状态条替代原引导横幅（presence + 在线人数，点击打开共享与成员 Sheet——本页已能原地编辑，不再跳协作页；进协作编辑页保留在 ⋯ 菜单「查看协作」）。标题最终未接入协作：投影通道只回写正文，写 `title` Y.Text 会造成房间标题与业务表标题静默分叉（见下方第二轮记录）。
- **`useEditContent`**：新增 `persistEnabled`（默认 true）选项，协作模式下短路 `saveContent`/`flushNow`/重试，`saving` 恒 false；加载路径与 `contentSyncBus` 订阅保留（协作模式编辑器 key 不随 `syncVersion` 重建）。
- **异常表现（作者视角）**：会话 frozen/closed/被结束或连接断开时正文转只读 + 状态条提示，**不自动退出**（作者数据都在本地，投影持续落库，恢复连接后自动续传）；只读态（含 binding 就绪前的过渡期）底部编辑工具栏由 `CollaborativeEditor` 经 `onReadonlyChange` 上报后强制收起（只读编辑器仍可获得焦点，不能只依赖 persistent/isEditorFocused 判断）。成员视角的协作编辑页行为不变。
- **Rust 侧无改动**：`assert_content_local` 写守卫与 `collab_project_content` 投影通道原样复用，云端仍是唯一真相源。

**验证**：`npx tsc --noEmit` 通过；`apps/mobile` 235 个测试全通过（含新增「协作只读态收起工具栏」回归用例）；`packages/collaboration` 31 个测试全通过（含新增「整树替换读回」「整树替换保留私有块占位并回填真身」）。（`apps/collaboration-server` 测试当时在本机跑不起来，后于 2026-09-13 的腐化治理中修复：桌面传递依赖的 Electron 顶层单例改为测试桩、better-sqlite3 降级 12.10.1、根 postinstall 增加 Node ABI 恢复，详见 `docs/collaboration-code-review-2026-09.md`。）

**回归与修复**：改造中一度删掉非协作分支 `Editor` 的显式 `readonly={false}`，而编辑器 `readonly` 默认 `true`，导致所有普通详情页变只读（只读编辑器渲染为 `contentEditable=false` 无法聚焦，真正误显工具栏的是文章/知识库/项目文档页的 `persistentToolbar` 常驻路径）。已恢复显式放开，并为工具栏增加 `readonly` 属性（只读时强制收起 + 关闭已展开弹条），补回归测试覆盖。

### 追加：发起入口与作者侧断连兜底（2026-09-13 第二轮）

- **发起协作入口扩展到全部详情页**：新增共用菜单工厂 `collabMenuItems`（有绑定→「查看协作」进协作编辑页，否则→「发起协作」），卡片 / 文章 / 知识库节点 / 项目文档四处共用；`ShareContentSheet` 的 `content` 改为可选，缺省时按 `contentId` 现取正文（知识库/项目文档条目只带 `contentId`）。
- **作者侧会话建立失败不再只读**：`CollaborativeEditor` 上报 `onModeChange`（connecting / live / unavailable / ended），详情页据此在 `unavailable` 时改用本地编辑器继续编辑——改动经 `useEditContent` 的 `persistVia: "collabProjection"` 走 `collab_project_content` 通道落本地库（不改动服务端，云端单一写者约束不变），并写 localStorage 标记「有本地兜底改动待裁决」；连接迟迟不落地（8s 无错误也无会话）同样按失败处理。失败提示条提供「重试连接」。保存通道做双向兜底：绑定已解除时投影通道返回 `unbound` 则回退常规直写，常规直写被守卫拒绝（`COLLABORATION_WRITE_REQUIRED`）则回退投影通道，两种竞态都不会静默丢改动。
- **重连后由作者裁决**：会话恢复且存在待决标记时，暂停投影（收尾投影一并抑制，绝不让云端内容覆盖待决改动），弹 `MobileConfirmDialog`：

  - 「保留本机」：`manager.pushLocalContent` 经新增的 `replaceSharedContent`（packages/collaboration）把本地正文整树写回房间——CRDT 语义的整段删除+重新插入，远端成员看到一次替换而非静默状态覆盖；
  - 「采用云端」：清除标记、解除投影暂停，周期投影把云端内容写回本地。
    服务端 `publish` 仅对 draft 文档写快照（`store.ts`），已激活房间无法用发布覆盖，故必须走 CRDT 替换路径。

- **标题回退为纯本地**：此前协作模式下标题写 `title` Y.Text，但投影通道只回写正文、没有回写业务表的路径，会造成房间标题与文章/文档列表标题静默分叉（兜底模式下还会丢标题）。现标题一律走既有本地重命名路径（`articleUpdate`/`documentItemUpdate` 不在写守卫接线点内），协作房间标题维持发起时的值。
- **结束共享＝点击行为，结果直接回传**（最初误做成「靠订阅会话消失去推断」，已重做）：详情页横条改为 `navigator.pushForResult("memberSheet", …)`，成员 Sheet 内 `leave()` 成功后用 `navigator.finish("ended")` 回传；横条 await 到结果即通知宿主重查绑定，`collaboration` prop 归位、退回普通本地编辑。遮罩/返回关闭则 reject（`dismissed`），视为未结束共享。

  - 为什么不能靠页面生命周期：`screen` 与 `overlay` 是两条独立栈（`RouterProvider` 的 `screens`/`overlays`），详情页在 overlay 之下仍为 `active`，浮层关闭**不触发 ****`onResume`**，因此绑定增删无法被刷新信号捕获，必须由结束动作本身回传。
  - 按 AGENTS.md 浮层规范，用 `finish` 回传结果的 overlay 主面板必须传 `backDismiss={false}`（否则内置返回拦截吞掉弹栈请求、调用方拿不到结果）。成员 Sheet 的普通返回直接透传到路由出栈，`pushForResult` 自动按 `dismissed` 收尾；结束共享成功后才用 `finish("ended")` 回传结果。

- **`CollaborativeEditor`**** 的 ****`ended`**** 模式**：会话「曾就绪后消失」＝共享已结束/被撤权（远端结束共享、桌面端关闭等），直接退回本地编辑，不误报「连接失败」；会话建立失败才是 `unavailable`。二者由 `useCollaborationDocument` 的 `everReady` 事实区分。重新发起协作不受影响：绑定恢复后组件重新挂载，状态自然从零开始。
