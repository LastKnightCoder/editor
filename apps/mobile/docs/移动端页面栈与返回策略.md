# 移动端页面栈与返回策略

## 背景问题

- 旧实现以 `AppShell` 内多个分散状态控制页面显隐（`view`、`sidebarOpen`、`previewOpen` 等）。
- Android 物理返回键与手势返回未接入统一处理，导致存在可回退页面时仍直接退出 App。
- 设置页二级模块回退依赖局部状态，无法与系统返回链路统一。

## 目标

- 使用统一页面栈模型管理移动端导航，避免逐页面打补丁。
- 统一处理 `ui`、`android`、`popstate` 三类返回来源。
- 固化页面入栈/复用/替换策略，保证行为可预测。
- 将策略沉淀为文档，便于后续扩展和排障。

## 回退状态保留偏好（2026-02-13）

- 回退状态保留是强约束目标：同一运行期内，页面回退后应恢复到离开时的 UI 状态。
- 实现方式不做强绑定：可通过 KeepAlive、缓存层或其他架构手段达成，只要满足目标即可。
- 页面隔离问题（如设置页期间底层列表可滚动）必须通过架构或交互层修复，不能以卸载页面、丢失状态为代价换取隔离。
- 当动画策略与状态恢复冲突时，优先保证状态连续性。

## 状态模型

导航状态由 `zustand` store 统一管理：

- `screenStack`：屏幕级页面栈。
- `overlayStack`：覆盖层页面栈（抽屉、预览等）。
- `settingsModuleStack`：设置页模块栈（Phase 2 全局化）。
- `lastBackTs`：Android 根页面双击缩小应用时间戳。
- `toast`：导航层提示（例如 Android 场景“再按一次缩小应用”）。
- `historySyncToken`：历史同步变更计数。
- `isHistoryInitialized`：历史适配器是否已初始化。

核心类型位于 `apps/mobile/src/navigation/types.ts`。

## 页面策略矩阵

| page key               | 层级    | 复用策略 | 入栈策略   | 说明                   |
| ---------------------- | ------- | -------- | ---------- | ---------------------- |
| `main.home`            | screen  | single   | push       | 根页，不能被弹空       |
| `screen.search`        | screen  | single   | bringToTop | 搜索页单例复用         |
| `screen.settings`      | screen  | single   | bringToTop | 设置页单例复用         |
| `screen.about`         | screen  | single   | bringToTop | 关于页单例复用         |
| `screen.contentDetail` | screen  | multi    | push       | 内容详情页可多实例入栈 |
| `overlay.sidebar`      | overlay | single   | push       | 侧边栏抽屉             |
| `overlay.cardPreview`  | overlay | single   | replace    | 卡片预览仅保留一个实例 |

策略注册位于 `apps/mobile/src/navigation/pageRegistry.ts`。

## 返回分发顺序

统一入口：`dispatchBack(source)`，`source` 仅允许：

- `android`
- `popstate`
- `ui`

处理顺序：

1. 非 `popstate` 返回优先使用 `history.back()`，由历史快照恢复页面栈。
2. 若无可回退项，按平台策略处理：
   - Android：触发根页双击缩小应用策略（2 秒窗口）。
   - iOS：根页返回静默忽略，不主动退出或退后台。
3. `popstate` 仅负责读取历史快照并还原栈，不主动二次回退。

历史适配位于 `apps/mobile/src/navigation/historyAdapter.ts`。

## 生命周期定义

页面定义支持以下生命周期钩子（当前预留，按需启用）：

- `onEnter`
- `onLeave`
- `onResume`
- `onPause`
- `onDestroy`

钩子字段定义位于 `PageLifecycleHooks`，后续可用于埋点、资源清理、缓存管理。

## 扩展规则

- 新页面必须在 `pageRegistry` 注册 `layer/reuse/enterMode/backPolicy/defaultParams`。
- 覆盖层页面优先放入 `overlayStack`，避免与屏幕页混用。
- 任何新增返回来源必须接入 `dispatchBack`，禁止组件内部直接调用原生退出。
- 设置模块新增项需同时更新：
  - `SettingModule` 类型定义
  - `SETTING_MODULE_KEYS` 运行时校验列表
- 跨层跳转若需同时关闭 overlay 并进入 screen，优先使用 `navigate(..., { dismissOverlays })` 保证单次 history 快照写入。
- overlay 高频 UI 状态（如滚动位置）应通过 `replaceOverlayParams` 写回 params，避免 history 膨胀。
- 新增 screen 页面时，应验证该页面在“隐藏不卸载”场景下可安全恢复交互状态。

## 常见陷阱

- 在组件中直接 `setState` 控制页面显隐，绕过导航 store，会导致返回链路断裂。
- 调用 `dispatchBack` 后立即读取 store 判定“是否已回退”，可能因等待 `popstate` 尚未更新。
- 对 `single + bringToTop` 页面重复 `navigate` 不会新增实例，这是设计行为，不是缺陷。
- `overlay.cardPreview` 使用 `replace`，预览切换会替换实例而非叠加。

## 排障清单

- Android 双击返回未缩小应用：检查 `onBackButtonPress` 是否注册成功。
- iOS 根页返回无动作是预期行为：通过系统手势/Home 返回桌面。
- 浏览器调试返回异常：检查 `initializeHistory` 是否执行，以及 `history.state` 是否包含导航标记。
- 设置页返回不符合预期：检查 `settingsModuleStack` 与 `screenStack` 是否一致。
- 预览关闭后仍显示旧内容：检查 `previewRequestSeq` 取消逻辑与 `overlay.cardPreview` 回退链路。

## 附录

### 页面 key 命名规范

- 屏幕页：`screen.<domain>`，例如 `screen.search`。
- 根页：`main.home`。
- 覆盖层：`overlay.<domain>`，例如 `overlay.cardPreview`。

### 是否允许多实例判定准则

- 需要保留多份并行上下文时使用 `multi`（当前移动端默认不启用）。
- 大多数基础页面采用 `single`，避免历史栈污染与状态重复。

### `replace` 与 `bringToTop` 使用准则

- `replace`：同类页面切换参数但不希望堆叠实例，例如 `overlay.cardPreview`。
- `bringToTop`：再次访问已有页面时复用历史实例并恢复状态，例如 `screen.search`、`screen.settings`。
