# 移动端软键盘适配规范

## 背景与目标

移动端 WebView 中，软键盘弹出后常见问题包括：

- 输入框被键盘遮挡，用户无法继续输入。
- 页面高度不收缩，底部内容不可见。
- 抽屉/弹层与键盘叠加后出现跳动或错位。

本规范目标是提供一套统一、可复用、可降级的机制，覆盖 `apps/mobile` 全部输入场景，并支持局部禁用。

## 总体策略（稳兼容分层）

采用四层机制组合，而不是依赖单一能力：

1. 入口层：通过 viewport 元信息启用浏览器原生 resize 能力。
2. 状态层：使用 `VisualViewport` 计算键盘高度并输出统一状态。
3. 样式层：通过全局 CSS 变量和通用类统一页面/滚动容器行为。
4. 交互层：焦点变化时自动将输入控件滚动到可见区域。

## 关键约定

### 1. viewport 约定

`index.html` 必须保留：

```html
<meta
  name="viewport"
  content="width=device-width, initial-scale=1.0, viewport-fit=cover, interactive-widget=resizes-content"
/>
```

### 2. 键盘状态约定

统一计算（带基线修正）：

```ts
layoutViewportHeight = window.innerHeight;
previousBaseHeight = previous.viewportHeight + previous.keyboardHeight;
viewportBottom = visualViewport.height + visualViewport.offsetTop;
baseHeight = max(layoutViewportHeight, previousBaseHeight);

if (!hasKeyboardEditableFocus() && viewportBottom >= layoutViewportHeight) {
  baseHeight = layoutViewportHeight;
}

keyboardHeight = max(0, baseHeight - viewportBottom);
```

额外规则：

- `visualViewport.scale !== 1` 时，保持上一帧键盘高度，避免缩放误判。
- 需要读取深层 `activeElement`（含 shadowRoot）判断是否有可触发软键盘的输入焦点（`input/textarea/select/contenteditable`）。
- 仅在“无可编辑焦点且 viewport 已对齐 layout viewport”时回收基线，避免把普通窗口变化误判为键盘。
- 通过 `requestAnimationFrame` 合并 `resize/scroll/focusin/focusout/orientationchange`。
- Android WebView 若 `visualViewport` 不变化，必须启用 native IME Insets 回传：
  - `MainActivity` 监听 `WindowInsetsCompat.Type.ime()`。
  - 注入 `window.__TAU_NATIVE_KB_HEIGHT_RAW`（原生 px）与 `window.__TAU_NATIVE_KB_HEIGHT`（CSS px）。
  - 派发 `tau:native-kb-height` 事件触发前端重算。
- native 高度必须按 `devicePixelRatio` 换算成 CSS 像素，并在前端再做一次上限保护，避免把工具栏顶出屏幕。

### 3. CSS 变量约定

`KeyboardViewportProvider` 负责写入：

- `--kb-height`
- `--kb-viewport-height`

组件和页面不要自行写入这两个变量，避免状态冲突。

### 4. 自动滚动可见约定（Auto Reveal）

- `useKeyboardAutoReveal` 需要覆盖 `input/textarea/select/contenteditable`，不能只支持传统表单控件。
- 仅在 `focusin` 时 reveal 不够，必须在以下时机进行二次 reveal：
  - `visualViewport resize/scroll`
  - `tau:native-kb-height`（Android native 回传事件）
- reveal 建议采用“多次重试（0ms/120ms/260ms）+ 可视区校正”的策略，降低键盘动画期间遮挡概率。
- 继续遵守 `data-kb-optout="true"` / `.mobile-kb-optout`，避免与自定义滚动组件冲突。

## 类名使用规范

### `mobile-kb-screen`

作用：让全屏页面高度跟随键盘后可视区。

适用：`fixed inset-0` 的整屏页面根容器。  
示例：`SearchPage`、`SettingsPage`、`ContentDetailPage`、`AboutPage`。

### `mobile-kb-scroll`

作用：给可滚动容器自动追加 `safe-area + keyboard` 底部留白。

适用：

- 页面主滚动区（`flex-1 overflow-y-auto`）。
- 抽屉内容滚动区。
- 底部 Sheet 主内容区域。

### `mobile-fixed-footer-scroll`

作用：给滚动容器追加 `safe-area + keyboard + 底部固定栏 + 抽屉遮挡补偿` 留白。

适用：

- 抽屉内存在固定底栏（例如编辑器工具栏）时的主滚动区。
- 需要保证 `normal` 态底部内容可完整滚入视口的场景。

### `mobile-kb-optout` / `data-kb-optout="true"`

作用：局部关闭键盘避让与自动 reveal 逻辑。

适用场景：

- 该区域无需输入，不应因键盘改变布局。
- 组件有自定义定位/滚动算法，避免与全局机制叠加。
- 临时排障或灰度关闭。

## 何时只用 `mobile-kb-scroll`

满足以下条件时，只给滚动容器加 `mobile-kb-scroll`，无需 `mobile-kb-screen`：

- 当前不是整屏 `fixed inset-0` 页面根容器。
- 容器本身已经由父级控制高度。
- 只需要解决底部输入区被遮挡问题。

典型例子：

- `SnapSheet.Scroll` 内部滚动区。
- `ActionSheet` 的内容区。

## 接入模板

### 全屏页面模板

```tsx
<motion.div className="mobile-kb-screen fixed inset-0 flex flex-col">
  <header className="mobile-topbar topbar-immersive">...</header>
  <div className="mobile-kb-scroll flex-1 overflow-y-auto">...</div>
</motion.div>
```

### 抽屉内容模板

```tsx
<SnapSheet ...>
  <>
    <SnapSheet.Handle />
    <SnapSheet.Scroll>...</SnapSheet.Scroll>
    {/* 或有底部固定栏时使用 */}
    <SnapSheet.FixedFooterScroll>...</SnapSheet.FixedFooterScroll>
  </>
</SnapSheet>
```

### 局部禁用模板

```tsx
<section data-kb-optout="true">{/* 自定义键盘处理逻辑 */}</section>
```

## 新页面接入检查清单

- 页面是否是整屏容器：是则加 `mobile-kb-screen`。
- 是否存在主滚动区：加 `mobile-kb-scroll`。
- 是否包含输入控件：确认未被 `data-kb-optout` 误伤。
- 是否存在自定义滚动逻辑：评估是否需要局部 `optout`。
- 是否使用 `SnapSheet`：按是否有固定底栏选择 `Scroll` 或 `FixedFooterScroll`。

## 验收清单

- 键盘弹出后，焦点输入控件始终可见。
- 切换多个输入框时，不出现明显跳闪和抖动。
- 收起键盘后，页面高度与滚动位置恢复正常。
- 横竖屏切换后，抽屉和滚动区高度正确。
- iOS WKWebView 与 Android WebView 行为一致。

## 常见误用

- 只加 `mobile-kb-screen`，但滚动容器未加 `mobile-kb-scroll`。
- 在业务组件里手动写 `--kb-height` 覆盖全局变量。
- 对整页加 `data-kb-optout` 导致输入框再次被遮挡。
- 组件自行监听键盘并修改布局，和全局机制重复生效。
- 把 Android native IME 高度（物理像素）直接当 CSS 像素使用，导致底部工具栏被顶到屏幕外。
- 自动 reveal 只监听 `focusin`，未在键盘高度变化后做二次滚动校正。

## 备注

- 本规范当前仅适用于 `apps/mobile`。
- `packages/editor` 不在本次键盘机制覆盖范围内。
