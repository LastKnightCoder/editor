# 移动端软键盘适配规范

## 背景与目标

移动端 WebView 中，软键盘弹出后常见问题包括：

- 输入框被键盘遮挡，用户无法继续输入。
- 页面高度不收缩，底部内容不可见。
- 抽屉/弹层与键盘叠加后出现跳动或错位。

本规范目标是提供一套统一、可复用、可降级的机制，覆盖 `apps/mobile` 全部输入场景，并支持局部禁用。

## 总体策略（稳兼容分层）

采用四层机制组合，而不是依赖单一能力：

1. 入口层：通过 viewport 元信息启用浏览器原生 resize 能力。
2. 状态层：使用 `VisualViewport` 计算键盘高度并输出统一状态。
3. 样式层：通过全局 CSS 变量和通用类统一页面/滚动容器行为。
4. 交互层：焦点变化时自动将输入控件滚动到可见区域。

## 现有实现位置

- 入口配置：`apps/mobile/index.html`
- 键盘状态 Hook：`apps/mobile/src/hooks/useKeyboardViewport.ts`
- 自动可见 Hook：`apps/mobile/src/hooks/useKeyboardAutoReveal.ts`
- 全局 Provider：`apps/mobile/src/components/KeyboardViewportProvider.tsx`
- 全局样式契约：`apps/mobile/src/styles.css`
- 抽屉容器接入：`apps/mobile/src/components/PanContainer.tsx`

## 关键约定

### 1. viewport 约定

`index.html` 必须保留：

```html
<meta
  name="viewport"
  content="width=device-width, initial-scale=1.0, viewport-fit=cover, interactive-widget=resizes-content"
/>
```

### 2. 键盘状态约定

统一公式：

```ts
keyboardHeight = max(
  0,
  window.innerHeight - visualViewport.height - visualViewport.offsetTop,
);
```

额外规则：

- `visualViewport.scale !== 1` 时，保持上一帧键盘高度，避免缩放误判。
- 通过 `requestAnimationFrame` 合并 `resize/scroll/focusin/focusout/orientationchange`。

### 3. CSS 变量约定

`KeyboardViewportProvider` 负责写入：

- `--kb-height`
- `--kb-viewport-height`

组件和页面不要自行写入这两个变量，避免状态冲突。

## 类名使用规范

### `mobile-kb-screen`

作用：让全屏页面高度跟随键盘后可视区。

适用：`fixed inset-0` 的整屏页面根容器。  
示例：`SearchPage`、`SettingsPage`、`ContentDetailPage`、`AboutPage`。

### `mobile-kb-scroll`

作用：给可滚动容器自动追加 `safe-area + keyboard` 底部留白。

适用：

- 页面主滚动区（`flex-1 overflow-y-auto`）。
- 抽屉内容滚动区。
- 底部 Sheet 主内容区域。

### `mobile-kb-optout` / `data-kb-optout="true"`

作用：局部关闭键盘避让与自动 reveal 逻辑。

适用场景：

- 该区域无需输入，不应因键盘改变布局。
- 组件有自定义定位/滚动算法，避免与全局机制叠加。
- 临时排障或灰度关闭。

## 何时只用 `mobile-kb-scroll`

满足以下条件时，只给滚动容器加 `mobile-kb-scroll`，无需 `mobile-kb-screen`：

- 当前不是整屏 `fixed inset-0` 页面根容器。
- 容器本身已经由父级控制高度。
- 只需要解决底部输入区被遮挡问题。

典型例子：

- `PanContainer` 内部滚动区。
- `OptionBottomSheet` 的内容区。

## 接入模板

### 全屏页面模板

```tsx
<motion.div className="mobile-kb-screen fixed inset-0 flex flex-col">
  <header className="mobile-topbar topbar-immersive">...</header>
  <div className="mobile-kb-scroll flex-1 overflow-y-auto">...</div>
</motion.div>
```

### 抽屉内容模板

```tsx
<PanContainer ...>
  <div className="mobile-kb-scroll min-h-0 flex-1 overflow-y-auto">...</div>
</PanContainer>
```

### 局部禁用模板

```tsx
<section data-kb-optout="true">{/* 自定义键盘处理逻辑 */}</section>
```

## 新页面接入检查清单

- 页面是否是整屏容器：是则加 `mobile-kb-screen`。
- 是否存在主滚动区：加 `mobile-kb-scroll`。
- 是否包含输入控件：确认未被 `data-kb-optout` 误伤。
- 是否存在自定义滚动逻辑：评估是否需要局部 `optout`。
- 是否使用 `PanContainer`：确认抽屉高度会随 `viewportHeight` 重算。

## 验收清单

- 键盘弹出后，焦点输入控件始终可见。
- 切换多个输入框时，不出现明显跳闪和抖动。
- 收起键盘后，页面高度与滚动位置恢复正常。
- 横竖屏切换后，抽屉和滚动区高度正确。
- iOS WKWebView 与 Android WebView 行为一致。

## 常见误用

- 只加 `mobile-kb-screen`，但滚动容器未加 `mobile-kb-scroll`。
- 在业务组件里手动写 `--kb-height` 覆盖全局变量。
- 对整页加 `data-kb-optout` 导致输入框再次被遮挡。
- 组件自行监听键盘并修改布局，和全局机制重复生效。

## 备注

- 本规范当前仅适用于 `apps/mobile`。
- `packages/editor` 不在本次键盘机制覆盖范围内。
