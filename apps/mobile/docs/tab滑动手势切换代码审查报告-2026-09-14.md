## 一、架构评估（两轮一致认可的方面）

```
tabs.ts            顺序契约层：TAB_ORDER / resolveTabNeighbor / isTabRoot（纯数据+纯函数）
tabSwipeGesture.ts 输入检测层：方向锁、阈值、让位规则，只回调不渲染
PageHost.tsx       驱动层：surface 状态机 + controls 位移 + commit/cancel 补间 + 落定等栈确认
gesture.ts         既有边缘返回手势：underlayOffscreen 参数（tab-on-tab 全宽跟手）
AppDock.tsx        展示层：消费 TAB_ORDER + 邻居 tab 预热调度
```

1. **检测层与驱动层分离**，与既有 `useEdgeBackGesture` 同构（configRef、tracking/locked 状态机、document capture 监听），认知负担低；两手势按起点分流（≤28px 归边缘返回）互斥成立。
2. **顺序契约单一来源**（`TAB_ORDER`）同时供 dock 展示与手势邻居解析，消除两处顺序漂移。
3. **lift + push 预推入的统一驱动模型**：目标在栈内提层驱动既有实例（滚动位置保留），不在栈内立即 push 真实页面以 `gesture-target` 屏外挂载，手势全程驱动同一实例，落定零交接（不重播入场、不重初始化虚拟列表）。这是"落定重播动画"的正解。
4. **让位规则完备**：dock/FAB 遮罩/toast（`data-no-tab-swipe`）、可横向滚动祖先（chips 行）、左边缘 28px 返回手势区（与 `gesture.ts` 共享 `EDGE_START_WIDTH` 常量）。
5. 测试覆盖检测层全部关键分支（13 例 + 复审后补 1 例忙期拒绝）。

## 二、第一轮 Findings 与裁决

### 核心裁决：popTo 异步落定的时序耦合（三个 P0 的共同根因）

盲审 agent 发现、主审验证确认的关键事实：**`push` 是同步 `setScreens`，但 `pop/popTo` 走 `historyBack → history.go(-depth) → 异步 popstate → restoreStack`**（RouterProvider.tsx）。原实现的"发起 popTo 的同一批 setState 里清手势 + suppressExitIds 每次渲染整组清空"依赖了 React flush 与 popstate 两个任务的交错顺序——顺序不同结果不同，这正是作者自留 TODO「tab 滑动偶现落定重播动画」的根因：

- **lift commit**：渲染先于 popstate 时，卸载发生在抑制标记被清空之后的渲染 → origin 的 exit 从 -100% 反向横穿到 +100%，且 exiting 层 z=SCREEN_TOP 盖在新页之上，可见。
- **push cancel**：中间态把预推入层（栈顶）拉回屏内、把 origin 按错误方向播 leave，随后 popstate 才弹掉 target——用户看到"回弹→页面滑出→幽灵页滑出→页面滑回"。
- **夹层 lift commit**（目标在栈内非 underlay 位）：中间态把 target 按 deeper 计算（白屏一闪），栈落定后 `deeper→active` 重播 300ms 滑入。

**修复（统一机制，非逐案补丁）**：发起 popTo 后不立即清手势，记入 `pendingSettleRef`，**等栈顶回到期望 key 才清**（等待期 origin 冻结 active / target 保持 gesture-target，surface 机制不会制造中间态）；`SETTLE_TIMEOUT_MS=800` watchdog 兜底 popTo 被并发返回拒绝 / popstate 丢失的极端路径（按实时栈恢复视觉后强制清手势）。`suppressExitIds` 清空条件收紧为"只清已离栈的 id"，标记存活到真正卸载的那一帧，时序无关。

## 三、第二轮复审与收尾修复

第二轮独立复审（验证最终代码）结论 **APPROVE**，确认：popTo 等栈确认机制在"渲染先于/晚于 popstate、popTo 被拒（watchdog 兜底）"三类时序下均闭环；suppressExit 只清离栈 id 的语义精准；enabled 联动无窗口；z-index 安排无撞值且 < OVERLAY_SHEET(50)；预热与 TAB_KEYS→isTabRoot 收敛无行为差异；简化项无隐性破坏。

复审新发现并处置：

| #   | 级别 | 问题                                                                                                                                                                                            | 处置                                                                                                       |
| --- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1   | P2   | `settleSurface` 的 deeper 复位固定 set `"0%"` 打破存量隐式约定（deeper 层原停留在上次 underlay 离开时的视差位 -25%），后续 `deeper→underlay-parallax` 无处理分支 → 揭示转场边缘错位一个视差宽度 | ✅ 补 `deeper→underlay-*` 升层归位分支（揭示转场起始帧 set 固有几何，用户无感），deeper 复位值降级为临时值 |

| 3   | P3   | 测试头注释仍提已删除的"动画抑制窗口"                                                                                                                                                            | ✅ 更新                                                                                                    |

**遗留观察项（不阻塞，记录在案）**：

- watchdog 兜底路径 target 由 set 瞬跳（约一帧可见）：800ms 罕见路径，可后续改 `start` 动画；
- popstate 迟于 watchdog（>800ms，需主线程长阻塞）到达时 exit 抑制已失效；
- commit 补间 150ms 内并发程序 pop 弹掉 target 的 exit 未抑制（需导航仲裁层才能根治）；
- 多指触摸 `changedTouches[0]` 混用：与存量 gesture.ts 同模式；
- `router.integration.test.tsx` 的 popstate 相关用例存在**存量 flaky**（基线复跑对比确认与本次改动无关，失败集合随机漂移），建议另行排查；
- PageHost `enterMotion` 每渲染新引用导致 surface effect 重跑（被 `prev===surface` 早退，存量结构）。
