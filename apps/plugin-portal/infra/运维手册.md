## 2. 部署模型与源码位置

浏览器访问Pages静态前端；前端带Cookie调用Worker；Worker调用GitHub并读写D1/私有R2。不连接桌面数据库，不读取用户 `~/.editor/plugins`。

- `web/`：React页面、API客户端、交互与模拟模式；已完成设计，不擅自重做布局。
- `contracts/index.ts` + `docs/协议.md`：前后端共同契约；改字段/错误码须一起改消费者与测试。
- `api/`：Worker生产TS；`api/*.test.ts`与testing.ts是测试代码。
- `infra/wrangler.jsonc`：本地D1/R2模拟配置，含零值database_id，**不能拿来部署正式环境**。
- `infra/wrangler.production.jsonc`：正式资源、域名、非秘密变量，已纳入Git。
- `infra/migrations/`：独立D1迁移；不要修改桌面 `packages/db-schema` 来维护门户库。
- `infra/ops.mjs`：构建、部署和维护编排，不承载业务逻辑。

Pages是Direct Upload模式，没有GitHub自动构建。Git提交或push不会自动发布；Cloudflare面板里的VITE变量也不会自动注入本机构建。ops脚本显式设置真实API及 `VITE_MOCK_API=false`。

## 3. 新电脑 / 新agent接手

1. 使用用户指定的checkout，先看git status，不覆盖其他agent未提交内容。当前开发worktree为 `~/.codex/worktrees/plugin-system/editor`，不是唯一运行位置。
2. Node24+、pnpm11.9.0。门户单独安装可用 `pnpm install --filter @tau/plugin-portal... --frozen-lockfile --ignore-scripts`，避免无关Electron原生模块重建；如果仓库其他应用需要安装脚本，按它们的说明独立执行。
3. 在终端设置 `export pnpm_config_verify_deps_before_run=warn`。pnpm11默认依赖检查可能在执行普通命令时触发全仓install及原生构建；ops子进程已设置warn，但手动pnpm命令需要自行设置。warn不修复缺失依赖，仍应先完成明确的安装。
4. 登录Cloudflare：`pnpm --filter @tau/plugin-portal exec wrangler login`，再运行下方status检查账号。不要从旧机器复制Wrangler OAuth token。
5. 读协议、阶段计划和本文件，再决定本轮只部署代码、迁移数据库还是更新密钥。

本地开发：

```sh
pnpm --filter @tau/plugin-portal db:local
pnpm --filter @tau/plugin-portal dev:api
# 另一终端；用真实本地API时需配置开发OAuth App
pnpm --filter @tau/plugin-portal dev:web
# 或只看UI模拟模式
VITE_MOCK_API=true pnpm --filter @tau/plugin-portal dev:web
```

开发OAuth App与生产分开：Homepage `http://localhost:5173`，callback `http://localhost:8787/v1/auth/github/callback`。配置在 `infra/.dev.vars`，样例同目录，不能提交。生产Cookie为HttpOnly/Secure/SameSite=Lax；两个HTTPS子域同站，勿因跨域误改SameSite=None。pages.dev或localhost不能直接当作生产门户使用。

## 4. 标准脚本入口

```sh
node apps/plugin-portal/infra/ops.mjs help
node apps/plugin-portal/infra/ops.mjs status --execute
node apps/plugin-portal/infra/ops.mjs verify --execute
node apps/plugin-portal/infra/ops.mjs smoke --execute
```

所有动作默认只预览；省略 `--execute` 不访问云端、不构建、不改数据。`verify`只本地验证，`status`读云配置，`smoke`匿名读公网服务并做WSS握手，不登录、不上传数据，也不执行视觉检查。

成功执行后记录在仓库忽略的 `output/plugin-portal-ops/`：动作、时间、Git SHA和公开目标，不含密钥。这个记录不是云端版本记录；从status或Cloudflare控制台另记部署版本ID。脚本失败立即停止，没有自动回退或数据删除。

## 5. 发布代码

先检查当前分支并提交要发布的内容。脚本对deploy/migrate/rollback拒绝脏工作区；不自动commit、push、建分支或操作PR。

```sh
# 先预览，确认确实是正式资源
node apps/plugin-portal/infra/ops.mjs deploy-api
node apps/plugin-portal/infra/ops.mjs deploy-api --execute

node apps/plugin-portal/infra/ops.mjs deploy-web
node apps/plugin-portal/infra/ops.mjs deploy-web --execute
```

两者执行统一类型检查与前后端测试。API先dry-run再发布；web固定真实API构建后发布到经典Pages项目tau-plugin-portal的master生产环境。master是Pages环境标签，不要求当前Git分支叫master，不等于合并代码。

Wrangler4.151.1的Pages命令默认会尝试委托到新版Workers；脚本使用 `--force` 留在已经创建的经典Pages。升级Wrangler后需核对该行为，不能因为错误而误建第二个Worker站点。

API发布不自动应用数据库迁移、不改Secrets；web发布不改API或数据库。先部署向后兼容的新API，再部署消费者。非兼容协议变更必须单独安排切换与回退窗口。

发布后运行smoke；web还须检查 `/login`、`/submissions/<id>` 的SPA回退、静态资源、真实登录、上传、保存、提交及刷新恢复。mock成功、单测成功不能代替真实OAuth验收；视觉由用户验收。记录前后端部署ID、Git SHA、迁移编号及结果。

## 6. 数据库迁移与备份

```sh
node apps/plugin-portal/infra/ops.mjs backup --execute
node apps/plugin-portal/infra/ops.mjs migrate
node apps/plugin-portal/infra/ops.mjs migrate --execute
```

备份输出到 `~/.local/share/tau/plugin-portal/backups/<UTC时间>.sql`，目录0700、文件按umask077创建，默认不在Git内。备份含用户资料和加密会话，按私有数据保存。D1备份不包含R2文件，也不包含Worker Secrets；恢复环境需要三者对应。

migrate先导出D1，成功后才应用正式迁移。只新增带编号SQL，不重写已应用迁移。先在本地应用并测试，再执行线上迁移。数据库与旧代码必须在过渡期兼容：例如给表加列时，旧版无列名的INSERT可能直接失败，不能未经检查就迁移。

脚本不自动恢复SQL，不执行删除生产库/删桶。误删或破坏性变更优先在Cloudflare D1 Time Travel选择事故前时间，并核实将丢失哪些后续写入；保留事故现场备份，恢复后重核R2引用。恢复操作单独制定方案，不能把“回退Worker版本”说成“回退数据库”。

## 7. 密钥管理

| 项目                    | 来源与用途                                                                                                     |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| Cloudflare登录          | Wrangler OAuth，仅用于部署管理；当前环境DNS API无权限，可通过登录控制台维护DNS                                 |
| GITHUB_CLIENT_ID/SECRET | 当前用户.zshrc中的TAU_PLUGIN_GITHUB_CLIENT_ID/SECRET，部署时映射到Worker Secrets                               |
| TOKEN_ENCRYPTION_KEY    | `~/.config/tau/plugin-portal/token-encryption-key`，原始32字节base64，文件0600；用于解密D1会话中的GitHub token |

正常代码部署不需要重新上传密钥。首次配置或明确轮换GitHub secret时：

```sh
# 在自己的终端加载；不要打印变量，不把密钥放命令行参数
source ~/.zshrc
node apps/plugin-portal/infra/ops.mjs secrets
node apps/plugin-portal/infra/ops.mjs secrets --execute
```

脚本只读取已有加密密钥，不自动生成。换机器时用可信方式迁移原加密密钥或制定会话失效/重登录方案；禁止因文件不存在就生成新值覆盖线上Secret。GitHub回调固定 `https://plugins-api.taunote.app/v1/auth/github/callback`，Homepage为 `https://plugins.taunote.app`。不要在聊天、日志、截图或仓库暴露Client Secret。

## 8. 回滚

Worker：先status找出明确的旧版本，核对其API域名、Secrets/绑定和数据库兼容性，再执行：

```sh
node apps/plugin-portal/infra/ops.mjs rollback-api --version=<版本UUID>
node apps/plugin-portal/infra/ops.mjs rollback-api --version=<版本UUID> --execute
```

它立即切换Worker版本，**不回滚D1或R2**。不盲目使用“上一个版本”：旧版本可能含xiongtao.life配置或旧错误协议。必要时以当前配置重新构建修复版本，而不是回退不兼容配置。

Pages：Cloudflare → Workers & Pages → tau-plugin-portal → Deployments → 选择之前成功的production部署 → Rollback to this deployment。首次上线没有旧部署可回滚；preview部署不是有效回退目标。保留兼容的后端，回退后再验登录/上传。

## 9. 日常维护与排错

| 症状                   | 检查顺序                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------- |
| API不可达              | smoke → Worker部署/域名/证书 → 绑定存在性；不要直接重建桶或库                          |
| 登录跳转失败           | OAuth Client ID、callback精确匹配、新域名HTTPS、state Cookie；不要把GitHub授权码写日志 |
| 登录一段时间后提交失败 | 当前自动刷新未完成；重新登录；后续实现刷新后补并发/撤销回归                            |
| 401/403                | 先看会话、Origin、CSRF；禁止通过去掉认证或通配CORS来“修好”                             |
| 前端请求localhost      | 本机生产构建未注入VITE_API_BASE_URL；用deploy-web脚本重新构建                          |
| 409                    | 依据协议错误码区分旧revision、冻结、重复版本、归属、上传状态和过期；不统一重试         |
| 上传checking不结束     | 查询会将超过5分钟的处理标为invalid；重新申请上传，不覆盖ready对象                      |
| 图片不可预览           | 图片GET也需Cookie；桶保持私有，不通过公开待审桶解决                                    |
| 部署后表不存在         | 使用了错误的D1绑定或未应用迁移；查看正式配置与迁移清单                                 |

查看日志（在本包目录，先设置pnpm依赖检查warn）：`pnpm exec wrangler tail --config infra/wrangler.production.jsonc`。收集错误时间和requestId；当前后端返回requestId但未实现完整持久关联日志，不能承诺凭编号即可定位所有异常。

定期检查D1大小、R2对象增长、Cloudflare用量、OAuth失败和服务证书。**当前没有后台清理任务**。不得给整个待审桶套“按年龄删除”的生命周期规则：冻结提交可能长期引用这些文件。

无引用对象清理只检查submissions.package_upload_id（独立图标/截图上传已删除），先生成候选报告并设置宽限期，再在暂停新引用或事务保障下删除。仅凭旧created_at或一次SELECT结果直接删对象会与草稿保存竞态；首期不提供自动删除脚本。
