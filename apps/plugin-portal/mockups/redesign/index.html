插件门户重设计 · 三个方案

覆盖插件中心（含新的插件详情页）、我的提交、提交编辑、审核、评论管理。三套都只用接口已有的数据；需要后端配合的地方在每屏下方用 ● 协议 标出。颜色、圆角、字号取自 paper 主题的 --tau-* 变量，可切深色。

现在的页面差在哪

  • 插件中心：卡片里竖排两个整宽按钮，「评论与喜欢」在卡片内展开，把网格撑乱；统计口径说明直接铺在列表上方；没有插件详情页，但 /v1/releases/:id 已经返回了 README、更新说明和仓库。
  • 导航割裂：插件中心没有顶栏，登录区的顶栏 logo 指向「我的提交」；审核入口是标题下面的一个开关按钮，点完标题变成「审核管理」，评论管理只是一个浮着的链接。
  • 提交编辑：七个区块从上往下堆成一长条，原生文件选择框，主操作压在 README 下方；「要求修改」的意见要往下翻才看得到，审核意见和站内反馈分在两个区块。
  • 审核：没有待审队列，只能在列表里一条条点进去；决策是一个文本框加三个并排按钮，没有和上一发布版本的对比，看不出这次改了什么。
  • 评论管理：要手填两个 ID 精确匹配，每条评论下面都排着三个按钮，没有表格视图，也不能批量浏览同一身份的评论。

三个方案

A · 商店 + 工作台B · 收件箱C · 编辑式 + 时间线
整体结构统一顶栏；公开区是商店网格，登录区是带左侧栏的工作台左窄栏图标导航，每一页都是「列表 + 详情」双栏，不跳页单栏居中、留白多；提交与审核做成 PR 式的时间线
插件中心三列卡片网格 → 独立详情页（介绍 / 更新 / 版本 / 评论）左侧紧凑列表，右侧即时预览，评论在预览里看大搜索框 + 杂志式长行，详情页有统计条
提交（作者）双栏：左边上传与预览，右边吸顶「提交前检查」与操作三步向导：上传 → 核对展示内容 → 关联仓库并提交按插件分组的版本列表；详情是时间线 + 底部输入框
审核与提交同一版式，右栏换成决策卡；附上一版本对比三栏：队列 / 详情 / 底部决策条，J K 切换，A R X 快捷键时间线里直接回复；输入框带「批准 / 要求修改 / 拒绝」下拉
评论管理表格 + 行内 ⋯ 菜单，处理原因可选预设列表 + 详情，详情里列出同一身份的其他评论同 A
适合插件数在几十到几百，访客多于作者审核量大、审核者想一口气处理完作者与审核者来回沟通多，更看重过程记录
改动量中：新增详情页路由，提交页重排大：每页都要改成双栏，还要做键盘焦点管理中：时间线要合并审核记录与反馈两路数据

推荐 A：插件中心的读者主要是访客，商店网格 + 详情页最好认；作者与审核者共用一套编辑版式，维护成本最低。如果审核量上来了，可以只把 B 的「上一条 / 下一条 + 快捷键」搬进 A 的审核页（A 的审核页已经放了上一条 / 下一条）。
