## HTTP 约定

前缀 `/v1`。JSON 成功 `{data:T}`，失败见 ApiError；日期 ISO UTC，ID 不透明字符串。客户端不依赖 requestId 格式。HTTP 400 输入错误，401 未登录，403 无权，404 不存在，409 冲突，413 超限，422 包或图片无效，503 外部服务不可用。

所有请求 `credentials: include`。会话由 HttpOnly Cookie 保存，前端不保存 GitHub token。`GET /v1/session` 返回 Session，未登录也为 200。所有写操作（含上传和退出）带 `X-CSRF-Token`，取 session.csrfToken；服务端检查 Origin。开发仅允许 `http://localhost:5173`，生产仅配置的门户域名，禁止通配 CORS。401 回登录，403 显示错误；不能自动切 mock。

| 方法/路径                       | 请求                           | 响应 data / 行为                                                           |
| ------------------------------- | ------------------------------ | -------------------------------------------------------------------------- |
| GET /v1/auth/github             | 无                             | 顶层导航到该地址，302 GitHub；不要 fetch                                   |
| GET /v1/auth/github/callback    | code/state                     | 服务端回调，成功跳门户 `/submissions`；失败跳 `/login?error=oauth_failed`  |
| GET /v1/session                 | 无                             | Session                                                                    |
| POST /v1/logout                 | 无                             | `{loggedOut:true}`                                                         |
| POST /v1/uploads                | CreateUpload                   | 201 UploadTicket                                                           |
| PUT ticket.uploadUrl            | 原始 File 二进制               | Upload；XHR withCredentials=true 支持进度/abort，带 ticket.headers 和 CSRF |
| GET /v1/uploads/:id             | 无                             | Upload                                                                     |
| GET /v1/uploads/:id/content     | 无                             | 仅本人可读取 ready 图片，二进制；供图标/截图预览，包不提供此入口           |
| POST /v1/submissions            | `{clientRequestId: UUID}`      | 201 Submission；同一用户同一个请求 ID 重试返回同一草稿                     |
| GET /v1/submissions?cursor=...  | 不透明 cursor，可省略，URL编码 | SubmissionPage；每页20，按创建时间与ID倒序                                 |
| GET /v1/submissions/:id         | 无                             | Submission，仅本人；其他用户统一404                                        |
| PATCH /v1/submissions/:id       | SaveSubmission                 | Submission；全量替换草稿资料，revision 乐观锁，不接受任意状态字段          |
| POST /v1/submissions/:id/submit | `{revision:number}`            | Submission；待审记录重复调用返回原记录，不重复创建                         |

409 按错误码采取不同操作，不能统一重试或覆盖。所有草稿的上传引用必须是本人、ready 且 kind 匹配。上传和新建记录数量有服务端限额；具体文案取 message。

### 字段错误与冲突（2026-10-16交接补充）

`INVALID_INPUT` 的 `error.fields` 可按 Listing 原始字段名返回多项中文错误，例如 `{"summary":"简介不能超过160个字符","commit":"请填写完整的40位源码提交SHA"}`。前端保存和提交两个阶段均需显示字段错误；修改某字段后清除该字段的旧服务端错误。结构性错误或外部服务失败仍可只返回message。图标/截图字段错误可显示在上传区或总览提示中，不解析message推导字段。

| 错误码（均HTTP409）       | 前端行为                                                              |
| ------------------------- | --------------------------------------------------------------------- |
| REVISION_CONFLICT         | 读取最新草稿，保留本地输入，让用户比较后决定，不自动覆盖              |
| SUBMISSION_LOCKED         | 读取详情并切只读，不继续保存                                          |
| VERSION_ALREADY_SUBMITTED | 提示在“我的提交”查看已有版本，不将当前草稿误判为已提交                |
| PLUGIN_OWNERSHIP_CONFLICT | 提示更换包ID或联系维护者；重新读草稿不能解决归属问题                  |
| UPLOAD_STATE_CONFLICT     | GET上传记录核对；checking等待、ready成功、invalid失败，禁止覆盖原产物 |
| UPLOAD_EXPIRED            | 确定失败，重新申请ticket上传；不进入未知结果轮询                      |
| LIMIT_EXCEEDED            | 展示额度说明，不重试、不走版本冲突流程                                |

CONFLICT保留在类型中用于旧部署兼容，新服务端不再用于上述分支。状态码不作为前端业务分流的唯一依据。

当前生产门户与API均为HTTPS下的taunote.app子域，跨域但同站；Cookie保持HttpOnly、Secure、SameSite=Lax，不扩大Domain。OPTIONS允许GET/POST/PATCH/PUT与Content-Type、X-CSRF-Token；只允许明确的WEB_ORIGIN并允许credentials。pages.dev预览不直接连接生产API，使用模拟或独立配置的预览环境。

根命令 `check`、`test` 覆盖api和web；也可独立执行check:api/check:web/test:api/test:web。交互测试依赖jsdom与Testing Library已加入，DOM测试用文件级 `@vitest-environment jsdom`，现有纯逻辑测试仍在node环境执行。

## 状态与资料

Submission 持久状态仅 `draft`、`pending_review`。上传持久状态为 `awaiting_upload`、`checking`、`ready`、`invalid`。checking表示服务端正在接收/校验；页面根据上传进度显示上传中或校验中。提交中、网络失败是临时操作状态，不能写入审核状态。

PUT 处理包含校验，上传进度100%但响应未到时显示校验中。ready 表示静态格式与摘要校验通过，不是代码审核通过。取消请求后读取 Upload 核对是否已完成；invalid/不确定时可申请新 ticket，不原地覆盖 ready 对象。上传结果超时可 GET 查询；不得假定取消一定撤销服务端已接收的文件。

提交前必须保存。summary 1–160字、description 1–20000字、changelog 1–10000字；详细介绍是 Markdown，前端不渲染原始 HTML。repository 为 `https://github.com/owner/repo`；commit 必须40位十六进制 SHA；supportUrl 为 HTTPS。首期公开源码，提交时验证 GitHub 仓库管理权限与 commit 存在；第一期不声称源码与 ZIP 一致（尚无重建验证）。

图标必需，截图0–5张；只接受 PNG/JPEG/WebP，每张最多2 MiB。ZIP 最多8 MiB、解压总量32 MiB、512条目。来源 manifest 必须 minAppVersion，沿用 formatVersion/apiVersion=1，不为平台扩展宿主包格式。ZIP 单层 `<pluginId>/` 根，manifest/main/styles 与 integrity 一致，禁止路径穿越/链接。服务端不执行作者脚本。

包中的 id/name/version/minAppVersion 只读；修改这些值必须重新打包。同一插件 ID 首次提交暂时保留给经仓库验证的作者；首发最终归属由第二期审核确认。不同作者不能覆盖。一个 ID 的待审版本唯一；第二期引入驳回/修订后再放开同版本重提。待审内容全部冻结，第一期不做待审修改。

没有模板资料文件前，第一期直接填写表单；不假定 ZIP 已包含 listing.json，也不自动抓取 README。第二期再添加仓库资料导入，避免重复维护两个输入源。

## 范围与验收

前端页面 `/login`、`/submissions`、`/submissions/new`、`/submissions/:id`。新建页先创建并记住草稿 ID，可先上传再保存；刷新恢复详情，网络重试复用 clientRequestId。

第一期无批准/发布接口，无公开目录，无公开下载，无 GitHub Issue 自动评论。终点为“待审核”。已安装插件列表不会成为这里的数据源。

验收：真实登录 → ZIP进入私有R2 → 服务端解析 → 图片/介绍保存 → 验证仓库 → 提交 → 刷新后仍待审。未登录、越权访问、坏包、重复请求、旧 revision、并发提交均有行为测试。线上验收需要配置 GitHub/Cloudflare；本地测试不能冒充上线。
