# 发布门户协议：以插件包为资料来源

2026-10-16，当前唯一运行契约，类型见 `contracts/index.ts`。系统尚未有业务用户，直接删除旧Listing、图标/截图上传、supportUrl和CONFLICT兼容，不同时支持旧表单。

本页描述仓库接口契约。客户端与服务端共用 `@tau/plugins/center`；生产开关与最新部署信息见[运维手册](/apps/plugin-portal/infra/运维手册.md)。

## 跨端分发与审核（0012）

作者清单和格式 3 的 targets 只声明支持平台与 minAppVersion。requires、required、optional、节点等级和 editor/whiteboard 标记不再是发行字段；新上传严格拒绝这些重复声明。正文、Markdown 转换、白板及其他服务在插件代码中注册，宿主负责装配，不以声明列表再次限制 API 调用。permissions 继续约束用户数据授权。

PackageManifest 为旧 DistributionManifest 与 PortablePluginManifest 的联合；格式 3 固定 apiVersion=1、platform=portable、profile=web-v1，接受单个 CJS JS、可选 CSS 和纯 Markdown Skill，不支持后台与静态模板。移动业务数据授权尚未接入，包含移动目标且 permissions 非空时拒绝上传。版本按 SemVer 解析，接受预发布和 build metadata。中心选版依据平台、最低版本、格式、API、profile 和分发开关；新宿主不再发送能力列表参与选版。历史发布记录与 ZIP 原文保留，公开目标摘要投影各平台最低版本，不改写审计资料。产品正式发布前统一使用新协议，不保留旧客户端字段、空数组或历史能力选版适配。宿主信息提取 platform、appVersion、apiVersions、formatVersions、profiles，忽略无关属性。平台摘要仅返回 minAppVersion，选版结果只返回 status 与 reasons。

上传仍走 /v1/uploads 与同一 ZIP 校验器，不求值作者 JS；名称/说明/平台资料仍只来自包。格式 3 沿用既有上架规则：网页提交由审核者批准；已绑定公开仓库的 CI tag，OIDC 推送者 ID 与插件所有者一致且本人有审核权限、包不要求系统能力审核时自动批准。其他作者或协作者仍进入待审。平台适配与功能测试由作者负责；审核者决定是否上架，不承担逐平台测试，不填写或确认平台验证记录。审核 approve 请求：

```json
{
  "revision": 1,
  "decision": "approve",
  "comment": "允许上架"
}
```

平台声明只取包内 targets，不通过审核表单修改。批准不表示官方完成各平台功能测试。审核决定与 revision、ZIP sha256、manifest、源码 commit 绑定；修订或重试决定不一致返回 409 REVISION_CONFLICT。请求与回执不再提供 platformEvidence，旧客户端附带的该字段不参与批准条件，也不保存为新记录；既有数据库列仅保留历史值，不删除审计数据。包格式、摘要、权限、身份与发布开关校验继续执行，旧后台/脚本 Skill 的系统能力审核保持不变。

PORTABLE_PUBLISH_ENABLED 只有字符串 true 才允许批准/发布格式 3；默认关闭，拒绝时为 409 SUBMISSION_LOCKED，不消耗审核修订。PORTABLE_PLATFORMS 是允许推荐安装的平台逗号列表，默认空；关闭的平台仍能浏览声明，带 host 选版返回 DISTRIBUTION_UNAVAILABLE。两开关与移动客户端 release 安装门禁分别生效，不能互相替代。

0012 增加 releases 的格式/profile/targets 投影、release_targets 表及审核证据字段；旧发布回填 desktop，完整 content_json、ZIP 和外键保留。格式 3 的旧 min_app_version 列保持空串作为“不适用”，不作为兼容版本；客户端只读 targets。插入触发器从同一清单同步目标投影。

/v1 公共目录、版本列表、版本详情和下载只返回旧格式；旧评论管理查询保留。作者、审核和私有包下载仍复用既有 /v1 接口，能查看新格式。新网页部署必须在 /v2 API 后，真实失败不能回退模拟。

## 作者流程

GitHub登录 → 新建提交：上传ZIP并通过校验后才创建草稿 → 预览包资料 → 首次关联源码仓库 → 保存/提交 → 在提交详情站内反馈。已发布插件在「我的提交」对应行点「发布新版本」进入同一新建页，草稿预绑定该插件ID，上传的包必须是同一插件。草稿可删除，审核中的提交可撤回为草稿（见「草稿删除与撤回」）。

名称、版本、简介来自manifest；介绍、配置和使用说明来自README；更新说明来自可选CHANGELOG。网站只读展示，修改资料需重新打包。一个插件首次提交验证仓库管理权，后续上传该ID保存时复用已关联仓库。提交时自动读取默认分支SHA并保存为commit；这只是仓库快照，不声称已验证ZIP由该commit构建。

## ZIP要求

```text
<pluginId>/
  manifest.json     # 必须含 description；旧格式顶层 minAppVersion，格式 3 在 targets 逐平台声明
  main.js
  main.css          # 可选，manifest.styles指向它
  README.md         # 必需，非空UTF-8，最多128KiB，介绍及使用说明
  CHANGELOG.md      # 可选，非空UTF-8，最多128KiB
  LICENSE          # 模板默认携带
```

代码包只接受后台格式 2 与跨端格式 3，旧可执行格式 1 拒绝；apiVersion 保持 1；按运行文件 integrity 校验。静态模板包仍为格式 1，使用 template.protocolVersion=1、root 与 entries，校验全部静态资产摘要。纯模板无须 main、format、styles，不执行代码。ZIP 最多 16 MiB，展开总量 32 MiB、512 条目；拒绝穿越、重复路径、链接、未声明资源和加密条目。平台记录整个 ZIP 摘要并保存提取后的只读 content 快照。没有独立图片上传接口，默认插件图标；README 使用安全 Markdown 子集，不执行 HTML、不加载远程图片。

## HTTP与认证

前缀/v1。成功 `{data:T}`，错误 `{error:{code,message,fields?,requestId}}`。所有请求credentials:include；写操作带X-CSRF-Token，来自GET /session。Cookie HttpOnly/Secure/SameSite=Lax，生产两个HTTPS子域同站；CORS只放行配置的WEB_ORIGIN，OPTIONS允许GET/POST/PUT/PATCH、Content-Type和X-CSRF-Token。日期ISO UTC。

## 状态和错误

- Submission：draft → pending_review → approved / changes_requested / rejected；pending_review 可由作者撤回回到 draft。要求修改后作者可编辑并重提；已批准/拒绝的记录不可编辑。反馈在首次提交后一直可用，不改变版本和包。
- Upload：awaiting_upload/checking/ready/invalid。上传进度100%仍需等服务端校验结果；取消不保证服务端撤销，必须GET核对。ready不能覆盖。
- REVISION_CONFLICT：读最新记录，保留本地输入，用户确认后再保存。
- SUBMISSION_LOCKED：记录已冻结，切只读。
- VERSION_ALREADY_SUBMITTED：查看已有待审版本，不误判本草稿提交成功。
- PLUGIN_OWNERSHIP_CONFLICT：改ID或联系维护者。
- UPLOAD_STATE_CONFLICT：GET核对checking/ready/invalid。
- UPLOAD_EXPIRED：确定失败，重新申请上传，不轮询旧ticket。
- LIMIT_EXCEEDED：显示额度说明，不重试。
- 创建提交时，每位作者最多保留 100 条未完成提交（draft / pending_review / changes_requested）；approved / rejected 历史记录不占额度，归组列表保留全部历史摘要。达到上限时引导管理已有提交、删除允许删除的草稿或等待审核完成，不显示“重试创建”；同一请求编号的幂等重试仍返回原提交。
- INVALID_INPUT：输入问题，repository字段可返回fields，其余展示message。

反馈通过clientRequestId避免断网重发产生重复消息；修改反馈正文后必须使用新请求ID。列表与反馈分页游标必须URL编码。保存不支持正文/图标/截图字段，不存在旧模型转换路径。

## 审核与发布（0003）

后台能力审核扩展（迁移 0011）：格式 2 的 backend 包不能经 CI 自动批准。人工批准必须提交 `systemReviewConfirmed: true`；确认绑定当前 revision、ZIP 摘要与源码提交，写入审核记录和 Release 的 `systemReviewed`。批准接口及失败发布重试均在服务端校验，不接受包内自报审核状态。客户端从 HTTPS 发布记录取得该标记并与下载摘要一起保存为来源信息；它不是离线数字签名，普通本机包仍需明确的本机信任授权。上线顺序为 D1 迁移、API、网页；旧数据按未完成系统能力审核处理。

Skill 扩展（无迁移）：包内 Skill 是 `skills/<id>/` 目录，manifest 的 `skills` 列出目录 ID，目录内全部文件进入 integrity；每个 `skills/<id>/SKILL.md` 必须是 UTF-8 且在开头 front matter 中填写 description。没有 `main`、只声明 `skills` 的是独立 Skill 包，与模板一样共用插件 ID 命名空间、提交、审核、发布和目录，不另设类型字段，桌面端按安装后的 manifest 区分。带脚本的 Skill（`skills/<id>/scripts/` 下的文件，或 .js/.mjs/.cjs/.ts/.py/.sh 文件）与 backend 包同样按 `requiresSystemReview` 处理：不能 CI 自动批准，人工批准须确认系统审核，客户端下载与安装时核对 `systemReviewed`。分类词表增加 `skill`。

格式 3 的可选 skills 仅携带纯 Markdown 文档（每项必须包含 SKILL.md，其他文件也仅允许 .md，禁止 scripts 目录）。桌面读取并管理这些 Skill；移动校验和保存文件但不注册或执行 Skill，不额外要求作者声明文件读取能力。功能直接通过统一 API 注册，不另列能力清单。此扩展不允许后台或脚本，不改变审核者无需实测/填写验证记录的规则。

版本撤回扩展：审核者可 POST `/submissions/:id/revoke`，提交 `{ reason, clientRequestId }`。撤回保留包和审批记录，记录执行人及原因；Release 增加 `revokedAt`，目录、版本列表、详情和下载不再公开该版本，不影响同插件其他版本。客户端联网确认撤回后停止对应后台；离线无法保证即时获知平台变化。

审核管理与作者门户共用站点。scope=review列出所有已提交记录，包括已处理和发布失败项；待审队列用scope=review&status=pending_review，侧栏待审数取同一响应的counts.pending_review（任一review请求的counts相同）；仅REVIEWER_GITHUB_IDS中的账号有审核权限。作者不能通过传入reviewer或decision等额外字段自我提权；产品维护者同时是作者时允许审核自己的提交。

| GET /releases/:id/download    | 匿名下载已发布ZIP；未发布返回404                                                                                                                     |

审核事务同时写入决定和状态；绑定确切revision、uploadId、ZIP SHA-256、manifest及源码commit，修改版本不能沿用旧批准。相同审核请求重试返回原决定；已有不同决定或旧revision返回409。并发互斥审核只允许一个成功。要求修改时保留旧上传与审核证据，作者不能更换插件ID；同一未发布版本可替换包后重提。拒绝结束当前提交，作者可另建提交；拒绝新版本不影响旧发布。

批准会创建不可变Release（pluginId+version唯一），发布状态为pending/publishing/published/failed，独立于approved。服务端从PENDING取出已批准的确切包并复核大小/摘要，再复制到独立私有RELEASES桶。数据库确认published后才开放公共目录/下载；写桶失败、摘要不符或缺文件不会公开。

发布重试只处理同一Release；两分钟租约防并发，进程中断后可再次点击重试。R2键包含插件ID/版本/摘要，重试写同一内容，不覆盖其他版本。跨服务没有伪装成事务：先写R2后提交发布状态，异常残留对象保持私有。已发布版本不可编辑或覆盖；整个插件的下架由管理员禁用实现（见「插件禁用（0009）」），单个版本按上文「版本撤回扩展」处理。

0003_review_release.sql是保留现有数据的正式迁移，复制提交与反馈后扩展状态并新增审核/发布表。已有真实待审提交不可清空；新库执行0001和0003。旧0002历史记录保留。

## 插件分类与关键词（0008）

manifest 可选 `categories`（取值见 `@tau/plugins/package` 的 `PLUGIN_CATEGORIES`：sync/upload/editor/whiteboard/blog-template/blog-publish/ai/voice/video/page，可多选）与 `keywords`（非空文本，仅搜索）。上传校验实际分类值与关键词类型，未知分类或无效关键词返回422 INVALID_PACKAGE；重复值去重保序，不限制关键词长度或数量。作者自填，平台不对照插件实际注册校验，审核以「要求修改」纠正。0008在releases增加categories、keywords两列（JSON数组文本），批准时与content_json同源写入，并为已有记录从content_json回填。

## CI 发布（GitHub Actions OIDC）

`POST /v1/ci/releases`：请求体为插件 ZIP（`Content-Type: application/zip`，上限同上传），`Authorization: Bearer <GitHub Actions OIDC 令牌>`，令牌 audience 必须等于 API 源（`https://plugins-api.taunote.app`）。不使用 Cookie/CSRF，不需要任何密钥。返回 `CiRelease`（201）。

| 校验                                                                                  | 失败                                          |
| ------------------------------------------------------------------------------------- | --------------------------------------------- |
| RS256 签名（GitHub JWKS，未知 kid 每分钟最多刷新一次）、iss、aud、exp/nbf（容差60秒） | 401 UNAUTHENTICATED                           |
| ref_type=tag、repository_visibility=public                                            | 403 REPOSITORY_NOT_ALLOWED                    |
| 包按上传同一严格规则校验；tag 去掉 v 前缀后等于 manifest.version                      | 422 INVALID_PACKAGE / 400 INVALID_INPUT       |
| 插件 ID 已通过网页首次提交登记；令牌 repository_id 等于登记的仓库 ID                  | 404 NOT_FOUND / 409 PLUGIN_OWNERSHIP_CONFLICT |
| 同版本已有待审/已批准提交时，包摘要必须一致（重跑幂等）                               | 409 VERSION_ALREADY_SUBMITTED                 |

提交直接进入 pending_review，source_commit 取令牌中的 tag 提交 sha，仓库地址沿用登记值，计入发布者每日上传额度。仅当登记发布者在 REVIEWER_GITHUB_IDS 中**且**令牌 actor_id 等于该发布者时自动批准（审核记录 comment 为「CI 自动批准：推送者为审核者」，reviewer 为本人），随后与网页批准同路径生成并发布 Release；协作者推送的 tag 只进待审。待审中的同一版本由审核者本人重跑可补做自动批准。

## 下载统计与匿名身份（0005）

| 方法/路径                  | 契约                                                                                                                                                                                                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| POST /visitor-session      | 必须带 X-Tau-Visitor:1 与 JSON `{client:"web"\|"desktop"\|"mobile"}`。web 返回 visitorId，并通过 HttpOnly/Secure/SameSite=Lax Cookie 保存凭证；desktop/mobile 仅接受无 Origin 请求并额外返回 token。已有有效凭证复用身份，停用身份返回403。首次申请按来源 IP 的秘密摘要分小时限额60次，超限429。 |
| GET /catalog               | 保留 appVersion/q；sort 为 downloads7d（默认）、downloadsTotal、updated；limit 默认30，1～50；cursor 为服务端返回的不透明值。每项增加 downloadsTotal/downloads7d，结果增加 nextCursor 与 windowStart（近期统计起始 UTC 日期）。                                                                  |
| GET /plugins/:id/stats     | 返回 `{downloadsTotal,downloads7d,windowStart}`；无已发布版本返回404。                                                                                                                                                                                                                           |
| GET /releases/:id/download | 仍允许无身份下载。有有效 Cookie 或 Authorization:Bearer 凭证时，在读取完整 ZIP 并校验大小/摘要后计数。统计失败不阻断下载；不返回或记录凭证。                                                                                                                                                     |

计数口径：平台成功提供 ZIP，不代表安装成功或用户数。设备指匿名安装/浏览器身份，不采集硬件指纹；清除凭证后身份不能恢复或跨端认领。每个身份、每个版本、每个 UTC 日最多计一次，升级到不同版本分别计数；近7日含今日及前六个 UTC 日。GitHub、R2直链、自行复制安装与无有效身份请求不进榜单。累计量从上线时开始，无历史估算。

下载凭据唯一约束与 AFTER INSERT 触发器在同一数据库语句内更新日计数与累计数，并发/重试不重复增加，失败整体回滚。生产下载通过 Worker waitUntil 执行统计，不让统计查询延迟 ZIP 响应；可能少计，不因此阻断下载。每日03:00 UTC 清理超过两天的去重记录、旧申请限额桶和90天前的日计数；累计计数与匿名身份保留。清理不扣减累计计数。

排序先按对应下载量降序（updated 无下载量主键），再按插件最近一次发布时间倒序、pluginId升序；最近更新含补发旧版本。版本兼容继续按 SemVer 计算，不使用时间判断。SQL先分页候选插件，再只读取该页的版本资料。搜索按已发布资料筛候选、以最高版本资料做最终匹配，所以可能短页或空页但仍有 nextCursor。

游标绑定搜索、客户端版本、排序及 UTC 日，跨日或条件改变返回400并提示刷新。榜单不冻结快照，翻页期间变化可能影响位置，客户端按 pluginId 去重；刷新重取。两端查询缓存60秒，API保留 no-store，个人身份数据不混入公共目录。

桌面端凭证以0600权限保存在 userData/plugin-center 中按 API origin 区分的文件里，由主进程使用；不随工作区改变，也不经 IPC 返回。网站公开目录为 /plugins，浏览无需登录；下载自动建立匿名身份。审核区的已发布下载链接也经过同一路径，待审包下载不计数。评论与喜欢复用该匿名身份，见下节；没有星级接口。

## 插件评论与喜欢（C28）

### 管理员接口（C29）

入口 `/moderation`，使用现有GitHub会话，管理员由 `REVIEWER_GITHUB_IDS` 配置；服务端每次查询/写入检查角色，写入继续要求门户Origin与X-CSRF-Token。匿名凭证不能访问。普通发布者403，未登录401。

| 方法与路径                    | 参数                                                                               | 返回data                                |
| ----------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------- |
| GET `/v1/moderation/comments` | pluginId、visitorId精确筛选，可选status=visible/deleted/all（默认visible）、cursor | ModerationPage&lt;ModerationComment&gt; |
| GET `/v1/moderation/events`   | 可选cursor                                                                         | ModerationPage&lt;ModerationEvent&gt;   |
| POST `/v1/moderation/actions` | ModerationInput                                                                    | ModerationEvent                         |

列表按时间/id倒序，每页20条，nextCursor绑定筛选；删除不使游标失效。管理评论包含匿名身份ID、停用状态与visitorRevision，不包含token或token_hash。公开评论接口仍不返回身份ID。审计只记录管理员ID、评论ID、匿名身份ID、动作、原因、时间，不保存被删除正文。

ModerationInput包含commentId、action（delete_comment/suspend_visitor/restore_visitor）、reason（trim后1至1000字）、revision与clientRequestId（16至80位字母/数字/下划线/连字符，推荐UUID）。删除revision=0，仅允许尚未删除的评论；停用/恢复使用列表visitorRevision。成功更新与审计在D1同一事务，身份修改递增版本。目标已变化409 REVISION_CONFLICT，关闭确认框刷新后重新作决定。

同一管理员与clientRequestId重试返回原操作记录；同ID不同参数409。历史请求重试不重放状态更新，因此不能用旧停用请求覆盖后续恢复。删除清空正文且不可恢复；停用阻止继续评论/喜欢及下载计数，仍可匿名阅读和下载，不自动删除历史评论或喜欢。恢复只恢复写入能力，已删正文不恢复。用户可清除凭证再申请身份，此机制不是硬件封禁。

管理页面确认框保留失败原因与本次请求ID，同参数重试保持幂等；关闭框后需要重新确认。用户举报与自动审核不属于此版本。

仅对至少有一个published版本的插件开放，未发布返回404。与提交审核的feedback接口完全独立。以下返回值仍包装为 `{data: ...}`。

| 方法与路径                                         | 请求                           | 返回                                   |
| -------------------------------------------------- | ------------------------------ | -------------------------------------- |
| GET `/v1/plugins/:pluginId/community`              | 可选cursor，取上一页nextCursor | `{likes, liked, comments, nextCursor}` |
| PUT `/v1/plugins/:pluginId/like`                   | `{liked: boolean}`             | `{liked: boolean}`                     |
| POST `/v1/plugins/:pluginId/comments`              | `{message, clientRequestId}`   | PluginComment                          |
| DELETE `/v1/plugins/:pluginId/comments/:commentId` | 无正文                         | `{deleted: true}`                      |

PluginComment为 `{id, message, createdAt, canDelete, deleted}`。公开列表不含已删评论；不返回visitorId或凭证。liked/canDelete根据当前请求凭证计算，无凭证或已停用时为false。所有读取no-store，不能用共享缓存保存身份相关响应。

写入先POST `/v1/visitor-session`建立或恢复匿名身份，再携带Cookie或原生客户端（desktop/mobile）Bearer凭证与`X-Tau-Visitor: 1`。身份缺失/停用返回403，浏览器Origin必须匹配门户。CORS允许DELETE。匿名写入不依赖GitHub会话，不触发登录跳转；与下载不同，申请身份失败必须停止写入。

喜欢以pluginId+visitorId唯一，PUT设定状态，重复执行不重复计数。评论正文trim后长度1至2000个UTF-16代码单元，作为纯文本显示；请求ID须为16至80位字母、数字、下划线或连字符，推荐UUID。相同身份与请求ID重复提交返回原评论，内容或插件不一致返回409 `COMMENT_REQUEST_CONFLICT`。已删除请求ID重试返回deleted=true、空message，不恢复正文。

评论按createdAt/id倒序，每页最多20条，用最后一条id作为游标。游标绑定插件；删除游标对应评论仍能继续翻页。每个匿名身份跨所有插件每天（UTC）最多20条，检查与插入在同一SQL语句完成；达到限额返回429 `LIMIT_EXCEEDED`。删除正文不退还额度。删除只能操作自己的评论，未知或他人评论统一404，重复删除成功。

清除Cookie/客户端凭证会失去原身份，无法管理原评论与喜欢；不使用硬件指纹或声称跨设备唯一。前端失败保留评论草稿与当前请求ID，继续重试同一正文不重复发表；离开页面或标签会丢失内存草稿，请先确认结果。此阶段没有评论编辑、回复、举报、审核后台或喜欢排行。桌面消费入口在已发布插件详情的“评论与喜欢”标签，经主进程plugin-local调用同一接口，凭证不通过IPC返回；桌面安装与浏览器各有独立匿名身份。

## 草稿删除与撤回（0009）

草稿只在插件包校验通过后创建：`POST /submissions` 必带本人 ready 状态的 packageUploadId，服务端把包资料与（已登记时的）仓库地址一并写入新草稿，进入新建页但不上传不会留下记录。可选 pluginId 用于「发布新版本」：须是本人已登记的插件且等于包内 manifest.id，否则 404/400；草稿预绑定该 plugin_id，之后 PATCH 换包不能更换插件。普通「发布新插件」不传 pluginId，插件 ID 仍在首次提交时登记。

`DELETE /submissions/:id` 只删除本人 draft 且没有任何审核记录的提交（曾被要求修改过的记录属于审核证据，不可删），同事务删除其站内反馈；关联的上传记录与待审桶对象不随事务删除，失去提交引用后由每日清理在上传创建满7天时回收并把上传置为 invalid（UPLOAD_EXPIRED），与「取消上传不保证撤销」同口径。`POST /submissions/:id/withdraw` 把本人 pending_review 的提交退回 draft 并递增 revision；submitted_at、plugin_id、source_commit 保留，所以反馈线程继续可用、审核者在「全部」范围仍能看到这条已撤回的草稿，部分唯一索引不含 draft，版本号随即可被重新提交占用。撤回与审核决定同用 revision 乐观锁，只有一方成功。

## 插件禁用（0009）

管理员可对整个插件禁用/恢复；粒度是插件而非版本。`plugins` 新增 disabled_at/disabled_by/disabled_reason，审计表 plugin_moderation_events 与评论处置分开（后者外键要求评论与身份）。禁用只切断公开可见性：`GET /catalog`（含 q 搜索、categoryCounts）、`GET /releases`、`GET /releases/:id`（含 download）、`GET /plugins/:id/stats`、`/plugins/:id/community|like|comments` 对禁用插件一律当作不存在（列表排除、单条 404）。已发布 Release 的 state 不变，恢复后立即重新可见。作者不受限制：仍可为禁用插件提交新版本，审核照常批准并发布 Release（仍不可见）；原因对作者可见——`Submission.disabled`、`SubmissionGroup.disabled` 带 reason 与 at，用于整改。审核通过后由管理员在插件管理页手动恢复，批准不自动恢复。桌面端不需要改动：目录由服务端过滤，版本列表为空即无更新。

| 方法与路径                           | 参数                                                                               | 返回data                                                  |
| ------------------------------------ | ---------------------------------------------------------------------------------- | --------------------------------------------------------- |
| GET `/v1/moderation/plugins`         | q（匹配插件ID与任一已发布版本名称）、status=all/active/disabled（默认all）、cursor | ModerationPage&lt;ManagedPlugin&gt;，按插件ID升序每页20条 |
| POST `/v1/moderation/plugin-actions` | PluginModerationInput                                                              | PluginModerationEvent                                     |
| GET `/v1/moderation/plugin-events`   | 可选cursor                                                                         | ModerationPage&lt;PluginModerationEvent&gt;               |

ManagedPlugin 的 name/latestVersion 取最高已发布版本（SemVer），releaseCount 为已发布版本数，downloadsTotal 口径同目录。PluginModerationInput 的 reason trim 后 1 至 1000 字，clientRequestId 规则同评论处置；disable_plugin 要求当前未禁用，enable_plugin 要求当前已禁用，目标状态已变返回 409 REVISION_CONFLICT。同一管理员与 clientRequestId 重试返回原记录，同 ID 不同参数 409。仅 REVIEWER_GITHUB_IDS 中的账号可调用，其他登录用户 403。

## 桌面端用户反馈（0010）

桌面客户端的独立反馈窗口提交文字、截图与可选日志；管理员在工作台「用户反馈」页处理。正文与元数据存 D1，附件存私有 R2 桶 `tau-feedback`（绑定 FEEDBACK，不绑公开域名、不签发预签名链接），只能经管理员会话由 Worker 读出。

**提交** `POST /v1/app-feedback`：只接受桌面匿名身份——Bearer 凭证 + `X-Tau-Visitor: 1`，请求带 Origin（即浏览器）一律 403；身份缺失或已停用 403。正文为 `multipart/form-data`，整体不超过 12 MiB：

| 字段    | 内容                                                                                                                                                                                 |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `meta`  | AppFeedbackSubmit 的 JSON：kind（bug/idea/other）、message（trim 后 1 至 4000 字）、contact（可空，≤200 字）、context（可空）、clientRequestId（16 至 80 位字母/数字/下划线/连字符） |
| `image` | 可重复，最多 3 张，每张 ≤1.5 MiB；只认 PNG/JPEG/WebP 文件头魔数，不信 Content-Type，SVG 等拒收                                                                                       |
| `log`   | 可选，普通日志的 gzip，≤3 MiB                                                                                                                                                        |
| `perf`  | 可选，性能快照 JSON 的 gzip，≤3 MiB                                                                                                                                                  |

context 只接受 appVersion/platform/osVersion/arch/page/theme/locale 七个字符串键（各截断到 100 字），用户在客户端可整体关闭。返回 `AppFeedbackReceipt {id, createdAt}`。同一身份与 clientRequestId 重试返回原记录，不重复写对象；同 ID 不同正文 409 REVISION_CONFLICT。
