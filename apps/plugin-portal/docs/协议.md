# 发布门户协议：以插件包为资料来源

2026-10-16，当前唯一运行契约，类型见 `contracts/index.ts`。系统尚未有业务用户，直接删除旧Listing、图标/截图上传、supportUrl和CONFLICT兼容，不同时支持旧表单。

## 作者流程

GitHub登录 → 新建提交 → 上传ZIP → 预览包资料 → 首次关联源码仓库 → 保存/提交 → 在提交详情站内反馈。

名称、版本、简介来自manifest；介绍、配置和使用说明来自README；更新说明来自可选CHANGELOG。网站只读展示，修改资料需重新打包。一个插件首次提交验证仓库管理权，后续上传该ID保存时复用已关联仓库。提交时自动读取默认分支SHA并保存为commit；这只是仓库快照，不声称已验证ZIP由该commit构建。

## ZIP要求

```text
<pluginId>/
  manifest.json     # 必须含description（1–160字）及minAppVersion；可选categories/keywords
  main.js
  main.css          # 可选，manifest.styles指向它
  README.md         # 必需，非空UTF-8，最多128KiB，介绍及使用说明
  CHANGELOG.md      # 可选，非空UTF-8，最多128KiB
  LICENSE          # 模板默认携带
```

沿用formatVersion/apiVersion=1；代码包按运行文件integrity校验，静态模板包使用template.protocolVersion=1、root与entries，校验全部静态资产摘要。纯模板无须main、format、styles，不执行代码，也不规定业务URL、UI框架或预览能力。ZIP最多16MiB，展开总量32MiB、512条目；拒绝穿越、重复路径、链接、未声明资源和加密条目。官方完整博客模板实测约12.3MiB、444个资产，因此仅调整ZIP上限。平台记录整个ZIP摘要并保存提取后的只读content快照。没有独立图片上传接口，默认插件图标。README首期用安全Markdown子集显示，不执行HTML、不加载远程图片。本轮仅本地改动，线上限额在后续发布API后生效。

## HTTP与认证

前缀/v1。成功 `{data:T}`，错误 `{error:{code,message,fields?,requestId}}`。所有请求credentials:include；写操作带X-CSRF-Token，来自GET /session。Cookie HttpOnly/Secure/SameSite=Lax，生产两个HTTPS子域同站；CORS只放行配置的WEB_ORIGIN，OPTIONS允许GET/POST/PUT/PATCH、Content-Type和X-CSRF-Token。日期ISO UTC。

| 方法/路径                      | 输入                                  | data/行为                                                                                 |
| ------------------------------ | ------------------------------------- | ----------------------------------------------------------------------------------------- |
| GET /auth/github               | 无                                    | 顶层导航，跳GitHub                                                                        |
| GET /auth/github/callback      | code/state                            | 服务端回调到/submissions；失败到/login?error=oauth_failed                                 |
| GET /session                   | 无                                    | Session，包括user、csrfToken、reviewer；匿名200                                           |
| POST /logout                   | 无                                    | loggedOut                                                                                 |

| GET /uploads/:id               | 无                                    | 本人Upload，含content（manifest/readme/changelog）与校验结果                              |
| POST /submissions              | clientRequestId UUID                  | 幂等创建草稿                                                                              |

不存在上传图片GET content入口，也没有feedback URL输入框。审核者ID由后端REVIEWER_GITHUB_IDS配置（逗号分隔数字GitHub用户ID），前端不能自封身份。当前配置为产品所有者LastKnightCoder。站内反馈是提交级私有审核交流；最终用户公开问题入口随插件中心后续建设，不把提交审核讨论公开给任意账号。

## 状态和错误

- Submission：draft → pending_review → approved / changes_requested / rejected。要求修改后作者可编辑并重提；已批准/拒绝的记录不可编辑。反馈在首次提交后一直可用，不改变版本和包。
- Upload：awaiting_upload/checking/ready/invalid。上传进度100%仍需等服务端校验结果；取消不保证服务端撤销，必须GET核对。ready不能覆盖。
- REVISION_CONFLICT：读最新记录，保留本地输入，用户确认后再保存。
- SUBMISSION_LOCKED：记录已冻结，切只读。
- VERSION_ALREADY_SUBMITTED：查看已有待审版本，不误判本草稿提交成功。
- PLUGIN_OWNERSHIP_CONFLICT：改ID或联系维护者。
- UPLOAD_STATE_CONFLICT：GET核对checking/ready/invalid。
- UPLOAD_EXPIRED：确定失败，重新申请上传，不轮询旧ticket。
- LIMIT_EXCEEDED：显示额度说明，不重试。
- INVALID_INPUT：输入问题，repository字段可返回fields，其余展示message。

反馈通过clientRequestId避免断网重发产生重复消息；修改反馈正文后必须使用新请求ID。列表与反馈分页游标必须URL编码。保存不支持正文/图标/截图字段，不存在旧模型转换路径。

## 审核与发布（0003）

审核管理与作者门户共用站点。scope=review列出所有已提交记录，包括已处理和发布失败项；待审队列用scope=review&status=pending_review，侧栏待审数取同一响应的counts.pending_review（任一review请求的counts相同）；仅REVIEWER_GITHUB_IDS中的账号有审核权限。作者不能通过传入reviewer或decision等额外字段自我提权；产品维护者同时是作者时允许审核自己的提交。

| 方法/路径                     | 输入与行为                                                                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| GET /submissions/:id/reviews  | 作者/审核者读取最近50条不可变审核记录及release状态                                                                                          |
| GET /submissions/:id/package  | 作者/审核者下载当前关联ZIP，供实际审核；不等于公开下载                                                                                      |
| POST /submissions/:id/review  | `{revision,decision,comment}`；decision=approve/request_changes/reject；仅审核者，后两者必填原因                                            |
| POST /submissions/:id/publish | 仅审核者重试已批准包的发布，不再次审核、不接受新产物参数                                                                                    |
| GET /releases                 | 匿名分页查询已发布版本，pluginId和cursor可选；每页20条ReleasePage，项为ReleaseSummary（含manifest），按发布时间排序，不声称是兼容版本选择器 |
| GET /releases/:id             | 匿名读取已发布版本资料                                                                                                                      |
| GET /releases/:id/download    | 匿名下载已发布ZIP；未发布返回404                                                                                                            |

审核事务同时写入决定和状态；绑定确切revision、uploadId、ZIP SHA-256、manifest及源码commit，修改版本不能沿用旧批准。相同审核请求重试返回原决定；已有不同决定或旧revision返回409。并发互斥审核只允许一个成功。要求修改时保留旧上传与审核证据，作者不能更换插件ID；同一未发布版本可替换包后重提。拒绝结束当前提交，作者可另建提交；拒绝新版本不影响旧发布。

批准会创建不可变Release（pluginId+version唯一），发布状态为pending/publishing/published/failed，独立于approved。服务端从PENDING取出已批准的确切包并复核大小/摘要，再复制到独立私有RELEASES桶。数据库确认published后才开放公共目录/下载；写桶失败、摘要不符或缺文件不会公开。

发布重试只处理同一Release；两分钟租约防并发，进程中断后可再次点击重试。R2键包含插件ID/版本/摘要，重试写同一内容，不覆盖其他版本。跨服务没有伪装成事务：先写R2后提交发布状态，异常残留对象保持私有。已发布版本不可编辑或覆盖；撤回与安全撤销后续独立设计。

0003_review_release.sql是保留现有数据的正式迁移，复制提交与反馈后扩展状态并新增审核/发布表。已有真实待审提交不可清空；新库执行0001和0003。旧0002历史记录保留。

## 插件中心目录（0004）

客户端插件中心读取以下匿名接口，类型见 `Catalog`、`CatalogEntry`、`PublicRelease`。

| 方法/路径                   | 输入与行为                                                                                                                                                                                                                                      |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET /catalog?appVersion=&q= | appVersion必填，按插件包版本规则校验，无效返回400。每个pluginId一条：latest为最高已发布版本（按SemVer而非发布时间），compatible为minAppVersion不高于appVersion的最高版本，没有则null，不回退latest。q对插件ID/名称/简介做不区分大小写的包含匹配 |
| GET /releases/:id（扩展）   | 追加repository、commit（审核时的源码快照）与publisher `{login,avatarUrl}`                                                                                                                                                                       |

每项likes为plugin_likes现存行数，口径同GET /plugins/:id/community的likes，停用身份的历史喜欢不扣除；按当页pluginId一次GROUP BY查询。目录名称、简介、发布者、仓库取自latest；资料列由0004加在releases上，批准时与content_json同源写入，查询不解析含README的content_json。0005 起采用下述排序分页，新库顺序执行0001、0003、0004、0005。

## 插件分类与关键词（0008）

manifest 可选 `categories`（取值见 `@tau/plugins/package` 的 `PLUGIN_CATEGORIES`：sync/upload/editor/whiteboard/blog-template/ai/voice/page，可多选）与 `keywords`（最多5个，每个trim后1–20字，仅搜索）。上传以严格模式校验，未知分类或不合规关键词返回422 INVALID_PACKAGE；重复值去重保序。作者自填，平台不对照插件实际注册校验，审核以「要求修改」纠正。0008在releases增加categories、keywords两列（JSON数组文本），批准时与content_json同源写入，并为已有记录从content_json回填。

| 方法/路径    | 输入与行为                                                                                                                                                                                                                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET /catalog | 新增可选 `category`（单值，未知值400），游标绑定分类。每项增加 `categories` 与 `keywords`（取自latest，未填写为空数组；keywords 供客户端本地搜索，不作为标签展示）；q 的匹配范围加入keywords。结果增加 `categoryCounts`：各分类插件数，按latest的分类统计、受q影响、不受category影响；仅首页（无cursor）返回，翻页为null。 |

分类与搜索同样先按任一已发布版本筛候选，再以latest做最终匹配，可能短页。网站目录以 `?category=` 记录选中分类，分类条只显示计数大于0的分类。

## CI 发布（GitHub Actions OIDC）

`POST /v1/ci/releases`：请求体为插件 ZIP（`Content-Type: application/zip`，上限同上传），`Authorization: Bearer <GitHub Actions OIDC 令牌>`，令牌 audience 必须等于 API 源（`https://plugins-api.taunote.app`）。不使用 Cookie/CSRF，不需要任何密钥。返回 `CiRelease`（201）。

| 校验                                                                                  | 失败                                          |
| ------------------------------------------------------------------------------------- | --------------------------------------------- |
| RS256 签名（GitHub JWKS，未知 kid 每分钟最多刷新一次）、iss、aud、exp/nbf（容差60秒） | 401 UNAUTHENTICATED                           |
| ref_type=tag、repository_visibility=public                                            | 403 REPOSITORY_NOT_ALLOWED                    |
| 包按上传同一严格规则校验；tag 去掉 v 前缀后等于 manifest.version                      | 422 INVALID_PACKAGE / 400 INVALID_INPUT       |
| 插件 ID 已通过网页首次提交登记；令牌 repository_id 等于登记的仓库 ID                  | 404 NOT_FOUND / 409 PLUGIN_OWNERSHIP_CONFLICT |
| 同版本已有待审/已批准提交时，包摘要必须一致（重跑幂等）                               | 409 VERSION_ALREADY_SUBMITTED                 |

提交直接进入 pending_review，source_commit 取令牌中的 tag 提交 sha，仓库地址沿用登记值，计入发布者每日上传额度。仅当登记发布者在 REVIEWER_GITHUB_IDS 中**且**令牌 actor_id 等于该发布者时自动批准（审核记录 comment 为「CI 自动批准：推送者为审核者」，reviewer 为本人），随后与网页批准同路径生成并发布 Release；协作者推送的 tag 只进待审。待审中的同一版本由审核者本人重跑可补做自动批准。

## 下载统计与匿名身份（0005）

| 方法/路径                  | 契约                                                                                                                                                                                                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST /visitor-session      | 必须带 X-Tau-Visitor:1 与 JSON `{client:"web"\|"desktop"}`。web 返回 visitorId，并通过 HttpOnly/Secure/SameSite=Lax Cookie 保存凭证；desktop 仅接受无 Origin 请求并额外返回 token。已有有效凭证复用身份，停用身份返回403。首次申请按来源 IP 的秘密摘要分小时限额60次，超限429。 |
| GET /catalog               | 保留 appVersion/q；sort 为 downloads7d（默认）、downloadsTotal、updated；limit 默认30，1～50；cursor 为服务端返回的不透明值。每项增加 downloadsTotal/downloads7d，结果增加 nextCursor 与 windowStart（近期统计起始 UTC 日期）。                                                 |
| GET /plugins/:id/stats     | 返回 `{downloadsTotal,downloads7d,windowStart}`；无已发布版本返回404。                                                                                                                                                                                                          |
| GET /releases/:id/download | 仍允许无身份下载。有有效 Cookie 或 Authorization:Bearer 凭证时，在读取完整 ZIP 并校验大小/摘要后计数。统计失败不阻断下载；不返回或记录凭证。                                                                                                                                    |

计数口径：平台成功提供 ZIP，不代表安装成功或用户数。设备指匿名安装/浏览器身份，不采集硬件指纹；清除凭证后身份不能恢复或跨端认领。每个身份、每个版本、每个 UTC 日最多计一次，升级到不同版本分别计数；近7日含今日及前六个 UTC 日。GitHub、R2直链、自行复制安装与无有效身份请求不进榜单。累计量从上线时开始，无历史估算。

下载凭据唯一约束与 AFTER INSERT 触发器在同一数据库语句内更新日计数与累计数，并发/重试不重复增加，失败整体回滚。生产下载通过 Worker waitUntil 执行统计，不让统计查询延迟 ZIP 响应；可能少计，不因此阻断下载。每日03:00 UTC 清理超过两天的去重记录、旧申请限额桶和90天前的日计数；累计计数与匿名身份保留。清理不扣减累计计数。

排序先按对应下载量降序（updated 无下载量主键），再按插件最近一次发布时间倒序、pluginId升序；最近更新含补发旧版本。版本兼容继续按 SemVer 计算，不使用时间判断。SQL先分页候选插件，再只读取该页的版本资料。搜索按已发布资料筛候选、以最高版本资料做最终匹配，所以可能短页或空页但仍有 nextCursor。

游标绑定搜索、客户端版本、排序及 UTC 日，跨日或条件改变返回400并提示刷新。榜单不冻结快照，翻页期间变化可能影响位置，客户端按 pluginId 去重；刷新重取。两端查询缓存60秒，API保留 no-store，个人身份数据不混入公共目录。

桌面端凭证以0600权限保存在 userData/plugin-center 中按 API origin 区分的文件里，由主进程使用；不随工作区改变，也不经 IPC 返回。网站公开目录为 /plugins，浏览无需登录；下载自动建立匿名身份。审核区的已发布下载链接也经过同一路径，待审包下载不计数。评论与喜欢复用该匿名身份，见下节；没有星级接口。

## 插件评论与喜欢（C28）

### 管理员接口（C29）

入口 `/moderation`，使用现有GitHub会话，管理员由 `REVIEWER_GITHUB_IDS` 配置；服务端每次查询/写入检查角色，写入继续要求门户Origin与X-CSRF-Token。匿名凭证不能访问。普通发布者403，未登录401。

| 方法与路径                    | 参数                                                                               | 返回data                                |
| ----------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------- |
| GET `/v1/moderation/comments` | pluginId、visitorId精确筛选，可选status=visible/deleted/all（默认visible）、cursor | ModerationPage&lt;ModerationComment&gt; |
| GET `/v1/moderation/events`   | 可选cursor                                                                         | ModerationPage&lt;ModerationEvent&gt;   |
| POST `/v1/moderation/actions` | ModerationInput                                                                    | ModerationEvent                         |

列表按时间/id倒序，每页20条，nextCursor绑定筛选；删除不使游标失效。管理评论包含匿名身份ID、停用状态与visitorRevision，不包含token或token_hash。公开评论接口仍不返回身份ID。审计只记录管理员ID、评论ID、匿名身份ID、动作、原因、时间，不保存被删除正文。

ModerationInput包含commentId、action（delete_comment/suspend_visitor/restore_visitor）、reason（trim后1至1000字）、revision与clientRequestId（16至80位字母/数字/下划线/连字符，推荐UUID）。删除revision=0，仅允许尚未删除的评论；停用/恢复使用列表visitorRevision。成功更新与审计在D1同一事务，身份修改递增版本。目标已变化409 REVISION_CONFLICT，关闭确认框刷新后重新作决定。

同一管理员与clientRequestId重试返回原操作记录；同ID不同参数409。历史请求重试不重放状态更新，因此不能用旧停用请求覆盖后续恢复。删除清空正文且不可恢复；停用阻止继续评论/喜欢及下载计数，仍可匿名阅读和下载，不自动删除历史评论或喜欢。恢复只恢复写入能力，已删正文不恢复。用户可清除凭证再申请身份，此机制不是硬件封禁。

管理页面确认框保留失败原因与本次请求ID，同参数重试保持幂等；关闭框后需要重新确认。用户举报与自动审核不属于此版本。

仅对至少有一个published版本的插件开放，未发布返回404。与提交审核的feedback接口完全独立。以下返回值仍包装为 `{data: ...}`。

| 方法与路径                                         | 请求                           | 返回                                   |
| -------------------------------------------------- | ------------------------------ | -------------------------------------- |
| GET `/v1/plugins/:pluginId/community`              | 可选cursor，取上一页nextCursor | `{likes, liked, comments, nextCursor}` |
| PUT `/v1/plugins/:pluginId/like`                   | `{liked: boolean}`             | `{liked: boolean}`                     |
| POST `/v1/plugins/:pluginId/comments`              | `{message, clientRequestId}`   | PluginComment                          |
| DELETE `/v1/plugins/:pluginId/comments/:commentId` | 无正文                         | `{deleted: true}`                      |

PluginComment为 `{id, message, createdAt, canDelete, deleted}`。公开列表不含已删评论；不返回visitorId或凭证。liked/canDelete根据当前请求凭证计算，无凭证或已停用时为false。所有读取no-store，不能用共享缓存保存身份相关响应。

写入先POST `/v1/visitor-session`建立或恢复匿名身份，再携带Cookie或桌面Bearer凭证与`X-Tau-Visitor: 1`。身份缺失/停用返回403，浏览器Origin必须匹配门户。CORS允许DELETE。匿名写入不依赖GitHub会话，不触发登录跳转；与下载不同，申请身份失败必须停止写入。

喜欢以pluginId+visitorId唯一，PUT设定状态，重复执行不重复计数。评论正文trim后长度1至2000个UTF-16代码单元，作为纯文本显示；请求ID须为16至80位字母、数字、下划线或连字符，推荐UUID。相同身份与请求ID重复提交返回原评论，内容或插件不一致返回409 `COMMENT_REQUEST_CONFLICT`。已删除请求ID重试返回deleted=true、空message，不恢复正文。

评论按createdAt/id倒序，每页最多20条，用最后一条id作为游标。游标绑定插件；删除游标对应评论仍能继续翻页。每个匿名身份跨所有插件每天（UTC）最多20条，检查与插入在同一SQL语句完成；达到限额返回429 `LIMIT_EXCEEDED`。删除正文不退还额度。删除只能操作自己的评论，未知或他人评论统一404，重复删除成功。

清除Cookie/客户端凭证会失去原身份，无法管理原评论与喜欢；不使用硬件指纹或声称跨设备唯一。前端失败保留评论草稿与当前请求ID，继续重试同一正文不重复发表；离开页面或标签会丢失内存草稿，请先确认结果。此阶段没有评论编辑、回复、举报、审核后台或喜欢排行。桌面消费入口在已发布插件详情的“评论与喜欢”标签，经主进程plugin-local调用同一接口，凭证不通过IPC返回；桌面安装与浏览器各有独立匿名身份。
